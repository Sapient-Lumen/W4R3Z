## Authority, evidence and historical continuity

An observed current carrier is not proof of authentication, freshness, global
currentity, finalization provenance, lineage admission or publication. A verified
linked pair establishes the local relation between these exact two files. It
does not establish an independent custodian, a provider response, an experiment
window, a scientific settlement or permission to act on the external world.
Carried authority flags are declarations in admitted metadata; they do not
become effects of the present read-only invocation.

Datacube carries its current documentary project and C++ source. Historical
checkpoint identities are explicit addresses. A keeper retention declaration
and an exact address do not prove present or future archive availability or
independent custody. Ordinary continuation does not acquire that checkpoint or
replay ancestry. Deep audit and legacy execution require explicit checkpoint
acquisition and exact native verification. A legacy command may have its own
consequences; this bootstrap grants it no authority merely by listing the seam.

The native source is technical memory as well as the active implementation.
The current route registry identifies what the delivered thin runtime exposes;
the presence of a retained C++ organ does not make its legacy route active.
Read the current operative document and documentary docket named in `reentry`,
then use exact project/source reads or materialization for deeper work.

bootstrap_resolve_self() {
  invoked=$0
  case $invoked in
    */*) ;;
    *) invoked=$(command -v -- "$invoked") || bootstrap_refuse self-path 'cannot resolve invocation path' ;;
  esac
  [ ! -L "$invoked" ] || bootstrap_refuse self-symlink "$invoked"
  leaf=${invoked##*/}
  [ "$leaf" = "$DATACUBE_BOOTSTRAP_LEAF" ] || bootstrap_refuse self-leaf "$leaf"
  directory=${invoked%/*}
  [ "$directory" != "$invoked" ] || directory='.'
  DATACUBE_RELEASE_ROOT=$(CDPATH= cd -P -- "$directory" && pwd -P) || bootstrap_refuse self-root "$directory"
  DATACUBE_BINARY_PATH=$DATACUBE_RELEASE_ROOT/$DATACUBE_BINARY_LEAF
  [ -x "$DATACUBE_BINARY_PATH" ] && [ ! -L "$DATACUBE_BINARY_PATH" ] || bootstrap_refuse binary-posture "$DATACUBE_BINARY_PATH"
}

bootstrap_exec_linked() {
  bootstrap_resolve_self
  exec "$DATACUBE_BINARY_PATH" linked "$@"
}
