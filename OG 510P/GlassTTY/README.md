# GlassTTY

## Let a terminal and a visible browser speak without inventing an API

GlassTTY begins with a practical bridge: an operator has a real browser tab and wants it to participate in a local terminal workflow. The earlier design emphasizes a browser-agnostic core and site-specific adapters; the later supplied revision presents a ChatGPT-oriented command-line surface.

The bridge’s prose becomes most useful where it distinguishes what was requested from what the page actually did. Sending a draft, observing a response, attaching a file and cleaning up an interrupted operation each need their own account.

## Local does not mean no data leaves the machine

The later source says the browser remains the route to ChatGPT. Prompts and files still go to the service through that page. A local broker and absence of an extra upload server do not make a conversation purely local or erase the permissions needed for its contents.

The supplied account is Chromium/MV3-specific and does not claim Firefox support. Its adapters and site behavior are historical; no current browser compatibility claim follows from this introduction.

Read the first-flight findings and workflow limits before any installation decision. This edition installed no extension, opened no authenticated session and ran no archived handoff command.

Read beside [VHK](../VHK/README.md) for a desktop-level version of the problem, and [Sandcodex](../../guides/Sandcodex.md) for the separately maintained room in which an operator and agent may collaborate.
