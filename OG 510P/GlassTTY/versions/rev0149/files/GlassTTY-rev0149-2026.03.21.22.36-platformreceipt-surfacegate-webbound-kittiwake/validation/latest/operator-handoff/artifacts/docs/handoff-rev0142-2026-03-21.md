# Handoff rev0142 — promotion stability receipt and repeat-proof gate

## What changed

- added `CHATGPT-PROMOTION-STABILITY-RECEIPT.json` with a machine-readable repeatability gate for repeated ChatGPT proof windows
- integrated that new receipt into `refresh-truth-surfaces`, the ChatGPT first-proof kit, the ChatGPT candidate bundle, and the ChatGPT support record
- updated research notes and status/changelog material so the repo explicitly distinguishes one held-quality proof window from stronger repeatable support language

## Why this revision exists

rev0141 could now say whether one whole route/composer/submit proof window was coherent enough for a stronger held bundle. That still left one honest failure mode: a single good window could be mistaken for stable support truth.

rev0142 closes that gap by adding a separate repeatability gate. One coherent proof window may justify a held bundle; stronger support language now depends on repeated proof windows with distinct window tokens, stable benign readback, explicit auth posture, and replayable locator evidence.

## New behavior

- repeated proof windows can now be graded as `ready-for-provisional`, `ready-with-caution`, `hold-for-recapture`, `blocked`, `blocked-by-composer`, `blocked-by-route`, `planning-only`, or `stop`
- stronger ChatGPT support language no longer rides on one held-quality window alone; it now needs repeated windows that preserve stable readback and repeatability fields
- traces and locator replay notes are now treated as confidence-raising replay materials instead of optional narrative extras

## Remaining limits

- there is still no live official-surface ChatGPT repeated proof bundle in this archive
- the new stability receipt is only as good as the repeated proof windows and replay materials it is given

## Recommended next move

Capture one real route/composer/submit/proof-bundle window on ChatGPT, then capture a second distinct window on the same baseline lane with the same benign exact-match probe. Require both windows to clear the proof-bundle receipt, then require the promotion-stability receipt to say `ready-for-provisional` or `ready-with-caution` before widening the ChatGPT support story beyond one held bundle.
