# rev0091 handoff

## What changed

- deferred native-host broker ownership until the first browser message instead of deciding at host-process start
- added per-message broker intent handling in `daemon/src/glassttyd/native_host.py`
- made broker-server construction lazy so secondary one-shot helpers no longer instantiate the local broker unnecessarily
- marked persistent extension health pings as `broker_intent: owner_candidate` and one-shot `bridge.status` / probe health pings as `broker_intent: secondary_only` in `extension/src/background/main.ts`
- added focused native-host regressions proving that secondary-only status/health calls do not create `daemon.sock`, while owner-candidate health pings still claim the broker lazily

## Why this mattered

Chrome's native-messaging docs still distinguish `connectNative()` and `sendNativeMessage()` sharply: long-lived port versus fresh process per request. rev0090 stopped one-shot helpers from stealing an already-live broker, but it still allowed an early one-shot helper to become a transient owner. rev0091 closes that gap so the local broker remains a property of the persistent browser↔CLI bridge, not of opportunistic diagnostics.
