# rev0092 handoff

## What changed

- added `extension/src/shared/native-lane.ts` with a compact diagnosis model for native-lane state
- `extension/src/background/main.ts` now derives `nativeConnection.laneDiagnosis` whenever bridge state is patched
- explicit `bridge.status` / `bridge.probe` calls now opportunistically attempt a persistent reconnect when one-shot native diagnostics prove the host manifest is reachable
- probe-side error reporting now prefers the diagnosis summary/recommended action when native health is not confirmed
- added `extension/scripts/native-lane-check.mjs` as a focused proof for diagnosis cases

## Why this mattered

rev0091 made one-shot diagnostics truthful by keeping them secondary, but it still left operators waiting for alarm/backoff reconnect even when the browser had just proven the host was reachable. rev0092 closes that practical gap without collapsing the important distinction between one-shot helper reachability and a truly healthy persistent bridge.

## Honest validation here

- `npm run typecheck`

- `node extension/scripts/native-lane-check.mjs`
- package verification and archive audit for the new zip

No fresh live Chromium/native-host/browser round-trip was proven in this container.
