# Handoff — rev0144 (2026-03-21)

This revision adds a ChatGPT capability-profile receipt so repeated route-first proof can stay explicitly **text-only** unless the evidence also preserves tool, attachment, and model-profile boundaries.

## What changed

- added `CHATGPT-CAPABILITY-PROFILE-RECEIPT.json` and `scripts/chatgpt_capability_profile_receipt.py`
- added focused tests for planning, experimental, provisional, hold, and stop outcomes
- refreshed the ChatGPT first-proof kit, candidate bundle, support record, selector notes, support-source lock, and truth-refresh path

## Why it matters

The repo could already say whether route/composer/submit proof was coherent, repeatable, and lane-bound, but it still lacked a machine-readable way to keep a **plain text-only** baseline from being described as though it covered Search, uploads, data analysis, voice, image, or other tool modes that can live on the same ChatGPT surface.

## Recommended next move

Execute the route-first baseline, preserve explicit entry mode / tool visibility / attachment state per proof window, then require the capability-profile receipt before broadening support language beyond a text-only baseline.
