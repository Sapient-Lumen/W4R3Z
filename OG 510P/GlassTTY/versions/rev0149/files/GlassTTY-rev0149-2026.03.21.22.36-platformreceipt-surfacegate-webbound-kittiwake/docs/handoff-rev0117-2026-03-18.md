# Handoff — rev0117 (2026-03-18)

## What changed

- Added replayable smoke setup actions to `scripts/e2e-fixturelab.py`.
- Added `--ensure-playwright-channel-ready {never,if-needed,always}` so fixture-lab smoke can try to restore the supported Playwright channel lane before launch instead of merely diagnosing drift.
- Smoke now records the exact Playwright-recovery and native-host install commands it planned or executed, then writes a sibling `...setup-replay.sh` script beside the JSON report.
- `scripts/e2e_fixturelab_capture.py` now copies that replay script and exposes setup-action counts in the summarized capture output.
- Extension/package version markers are now `0.1.70`.

## Why this was the next move

The current Playwright docs still center extension automation on a persistent Chromium context and explicitly call out `channel="chromium"` for headless extension runs, while the current browser docs still treat browser install/alignment as a normal operational workflow. GlassTTY had already learned to diagnose cache drift and suggest a one-shot recovery command, but smoke still did not preserve whether it had actually used that command or which native-host install commands it ran. rev0117 turns that setup state into durable evidence and a replayable operator recipe.
