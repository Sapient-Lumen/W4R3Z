# rev0086 handoff — native-host outbound overflow becomes recoverable

Baseline used: `GlassTTY-rev0085-2026.03.17.09.05-playwrightrawtruth-gcowners-auditsignal-merlin.zip`

## What changed

- `daemon/src/glassttyd/native_host.py` now treats outbound native-messaging overflow as a recoverable condition instead of a host crash.
- Oversized outbound messages are spilled to `GLASSTTY_HOME/state/fixtures/oversized-host-outbound-*.json` with a matching summary in `GLASSTTY_HOME/state/latest/oversized-host-outbound.json`.
- `bridge.status` now exposes `last_oversized_host_message`, so the browser/CLI status lane can point at the saved overflow artifact.
- The browser receives a compact `error.report` that includes the original message type, measured size, host→extension limit, and saved artifact path.
- Extension/package version markers are aligned at `0.1.42`.

## Why this mattered

Chrome native messaging is asymmetric: the native host can only send 1 MB per message back to the browser, while browser→host messages can be much larger. GlassTTY already had offline budget tooling, but the live host still raised on overflow. That meant a rich fixture/debug payload could crash the bridge at exactly the moment the operator most needed diagnostics.
