# Handoff rev0127 — revision receipt, truth warning ledger, validation buckets

## What changed

- added `REVISION-RECEIPT.json` plus `check-revision-receipt` so the packaged archive can describe itself and lint that self-description against the manifest and current truth-surface counts
- added `truth-surface-warnings` so foreign-root / missing-current-root / non-citation-ready heads can be seen as one compact warning queue instead of only by reading the full truth register
- added `validation-artifact-inventory` so `validation/latest/` is summarized into stable bucket groups before pruning, handoff packing, or another capture family is added
- extended `control-plane-report`, `doctor`, `operator-handoff`, and `refresh-truth-surfaces` to expose or carry those new surfaces
- updated the opening/startup path so future operators read the revision receipt and can verify it immediately

## Why this was worth doing

The comparison datacubes suggested three real substrate lessons that still applied after rev0126:

1. the archive should have a compact self-description separate from changelog prose,
2. citation-head warnings should be compact and visible instead of buried inside a larger lineage object,
3. and large artifact trees should have a generated bucket summary instead of forcing file-by-file archaeology.

GlassTTY also had an internal reason to do this now: archive identity drift had already happened before, truth-surface lineage was available but not yet compactly warnable, and `validation/latest/` had become big enough that future sessions could waste time just re-finding the same capture families.

## Next good moves

1. backfill the first real Claude support bundle and freeze it under the stricter revision/warning surfaces
2. decide whether support bundles need a small candidate/published queue or whether the current support-record + snapshot model is still enough
3. keep the validation bucket taxonomy honest as more capture families appear instead of letting `other` silently become the largest bucket
