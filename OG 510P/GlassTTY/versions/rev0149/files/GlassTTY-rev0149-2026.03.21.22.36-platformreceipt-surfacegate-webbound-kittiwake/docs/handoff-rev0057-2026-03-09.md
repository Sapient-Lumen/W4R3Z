## Why it matters

rev0056 made receiver choice truer, but not yet transparent. A user or future LLM could still see a chosen receiver key without being able to tell whether that result came from deliberate policy or accidental row order. rev0057 closes that gap: the daemon now makes the same kind of choice every time for the same inventory, and it can explain that choice in saved JSON artifacts.
