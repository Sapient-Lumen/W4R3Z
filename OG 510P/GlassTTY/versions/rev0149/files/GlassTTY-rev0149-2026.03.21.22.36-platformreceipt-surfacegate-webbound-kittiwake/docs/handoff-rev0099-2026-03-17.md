# rev0099 handoff

## What changed

- added browser-family metadata to saved `glasstty-profile.json` launch records
- taught `scripts/profile_metadata.py` to distinguish strict relaunch readiness from an explicit discovered-browser fallback when the saved browser path is missing
- added `--allow-discovered-browser-fallback` to `scripts/reopen-profile.py` / `./scripts/glasstty-profile.sh reopen ...`
- exposed portable replay commands and saved-browser native-host follow-ups through profile summaries and doctor hints
- refreshed README/doctor/profile docs plus memory/worklog/handoff text for the new portability lane

## Why this was next

rev0098 made managed profiles replayable, but it still assumed the original browser path would exist forever. In practice, copied archives and multi-machine handoffs often lose that exact binary path first. rev0099 makes that failure mode explicit and recoverable without silently pretending a different browser family is the same thing.
