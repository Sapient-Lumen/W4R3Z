## Why it matters

rev0054 and rev0055 made the browser-side receiver model much more honest about instant navigation, but the shell-side resolver still had some older `frameId == 0` instincts. That created an operator mismatch: the extension could know a receiver was outermost while `glassttyd resolve-receiver --top-frame` and the human-facing label still treated the same receiver like a subframe. rev0056 closes that gap and gives shell automation a direct `--active-outermost` lane that mirrors Chrome's own guidance to combine outermost-frame identity with document lifecycle.
