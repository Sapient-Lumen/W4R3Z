## What changed

- `scripts/playwright_browsers.py` now reports first-class cache-alignment state for the Playwright persistent extension lane:
  - `channel_ready`
  - `cache_alignment_status`
  - `cache_alignment_reason`
  - `recommended_realign_command`
  - `recommended_repair_then_sync_command`
  - `recommended_channel_ready_command`
- `scripts/doctor.py` now turns drifted-cache detection into an explicit operator hint that explains why the official `channel="chromium"` path is blocked and how to recover it.
- `scripts/playwright-browsers.py inspect` now embeds the same extension launch plan directly, so cache-only archaeology does not have to rely on the doctor surface.
- The extension/package version markers are now `0.1.68`.

## Why this move

rev0114 made GlassTTY honest about cache alignment, but it still left operators with a soft diagnosis: a drifted cache would show up as `bundled-executable`, yet the recovery path back to the documented Playwright lane was implicit. rev0115 closes that loop. The project now says whether the persistent extension lane is actually channel-ready, why not, and which command should realign the cache before spending time on MV3 debugging under a fallback browser identity.
