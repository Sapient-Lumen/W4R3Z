# rev0093 handoff

## What changed

- added `extension/src/shared/persistent-history.ts` for bounded durable worker-boot/native-lane history
- background now writes `bridgePersistentHistory` in `chrome.storage.local` and derives a compact `runtimeHint`
- `bridge.status` and `bridge.probe` now return `persistentDiagnostics` alongside session bridge state
- side panel renders structured persistent diagnostics plus the raw mirrored local-history blob
- probe failures now include the durable runtime hint when native health is not confirmed

## Why this mattered

rev0092 made the current session's native-lane truth much better, but that truth still lived in `storage.session`, which Chrome clears on reload/update/browser restart. For MV3 restart debugging, GlassTTY needed a small cross-restart memory lane so future sessions could see whether the current worker boot had actually reclaimed the persistent port or only had one-shot reachability evidence.

## Honest validation here

- `npm run typecheck`
- `npm run build`
- `node extension/scripts/native-lane-check.mjs`
- `node extension/scripts/persistent-history-check.mjs`
- archive audit + package verification on the final zip

No fresh live Chromium/native-host/browser round-trip was proven in this container.

## Suggested next step

Capture one real browser run that deliberately forces a service-worker restart, preserves the before/after `bridgePersistentHistory` artifact, and proves the durable `runtimeHint` transitions from `restart_pending` or `current_boot_oneshot_only` back to `current_boot_connected` when GlassTTY successfully reseats the persistent lane.
