# Handoff rev0136 — ChatGPT posture matrix, search/home caution lane, and branch-shell classifier

## What changed

- added `CHATGPT-POSTURE-MATRIX.json` with a machine-readable classifier for the ChatGPT route-first baseline: plain guest home, authenticated home chat, search-capable home lane, Projects, Canvas, and GPT builder
- added `scripts/chatgpt-posture-matrix.py` / `scripts/chatgpt_posture_matrix.py` with report, capture, history, and rooted-output support
- integrated the new posture matrix into `refresh-truth-surfaces` so the rooted truth refresh now emits and roots the classifier automatically
- expanded `SUPPORT-SOURCE-LOCK.json` with current first-party OpenAI anchors for ChatGPT search and the web-only GPT builder workspace
- refreshed the ChatGPT candidate support bundle so it references the new posture matrix alongside the proof kit and brief
- refreshed adapter notes, support record, surface profile, research notes, status, changelog, and decision log around the new baseline-vs-branch discipline

## Why this matters

rev0135 made the first ChatGPT proof more executable once a session was already inside the page, but it still left an avoidable ambiguity: was the landed shell actually the plain baseline lane, or had the session drifted into a richer branch where the same selectors and evidence would mean something different?

rev0136 answers that with a machine-readable posture classifier. The repo can now distinguish:
- baseline-safe plain home chat
- a cautionary search-capable home lane that may still be acceptable for the first proof
- stop-and-preserve branches such as Projects, Canvas, and the GPT builder workspace

That makes the next real proof attempt more honest and more reusable.

## Concrete next step

Run the first ChatGPT baseline from the plain browser route, classify the landed shell with `CHATGPT-POSTURE-MATRIX.json`, preserve route/auth/overlay posture, then collect compose/submit/read-latest artifacts only if the shell still qualifies as the baseline lane.
