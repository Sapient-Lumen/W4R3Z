# Handoff — rev0118 (2026-03-19)

## What changed

- Added compact setup sidecars to `scripts/e2e-fixturelab.py`: `...setup-ledger.json` for machine-readable setup evidence and `...setup-summary.md` for a human-readable narrative beside the existing `...setup-replay.sh` recipe.
- `checkpoint_report(...)` now refreshes those setup sidecars while the smoke report evolves, so interrupted runs leave a smaller setup story instead of forcing future sessions into the large JSON.
- `scripts/e2e_fixturelab_capture.py` now copies the new setup sidecars and summarizes setup failures, failed action names, and last-setup state in capture bundles.
- `scripts/doctor.py` now points at the setup summary/ledger when the latest saved smoke run failed during setup.
- Extension/package version markers are now `0.1.71`.

## Why this was the next move

Current Playwright docs still focus debugging on saved traces and the supported extension lane on persistent Chromium contexts with `channel="chromium"`, while Chrome's remote-debugging hardening keeps more of the interesting failure surface in the *setup* stage before a useful browser trace even exists. rev0117 made setup replayable; rev0118 makes it explainable. The goal is that the next model/operator can answer “what setup did GlassTTY choose, what failed, and what did the command say?” from compact sidecars instead of spelunking the main smoke JSON.
