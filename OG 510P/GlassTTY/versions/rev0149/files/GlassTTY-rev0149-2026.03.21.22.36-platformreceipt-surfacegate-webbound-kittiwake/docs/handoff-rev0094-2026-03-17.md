# rev0094 handoff

## What changed

- added `scripts/mv3-worker-resume.py` and `scripts/mv3_worker_resume.py` as a dedicated MV3 restart-proof lane
- added reusable fixture-lab helpers for probe-page-only launches, browser-CDP worker termination, shared persistent-context launch, and before/after resume summarization
- expanded `tests/test_e2e_fixturelab.py` to cover probe-page-only URLs, probe opening without a fixture site, `Target.closeTarget` worker termination, and recovery-summary derivation
- preserved honest partial live restart attempts in `validation/rev0094-focused/live-mv3-resume-report*.json`

## Why this mattered

rev0093 improved GlassTTY's durable restart memory, but there was still no in-tree harness that forced an MV3 restart and checked whether the next probe really came back healthier. rev0094 closes that gap by making service-worker termination and before/after comparison a first-class artifact lane.

## Honest gap

No fresh full before/after browser restart proof completed in this container. The best live attempt got through extension build and native-host install and was then terminated by signal 15 before the Playwright browser phase finished.

## Suggested next step

Run the new harness on a machine that can keep Chromium alive long enough to reach `probe_after`, then compare the first successful `resume_proof` bundle against the partial rev0094 artifacts to see whether the remaining risk is browser startup, worker target discovery, or post-restart native-lane reseating.
