# Handoff rev0137 — ChatGPT witness-driven branch guard, history-search split, and route-stop evaluator

## What changed

- added `CHATGPT-BRANCH-GUARD.json` and `scripts/chatgpt-branch-guard.py`
- added a witness evaluator that classifies a concrete ChatGPT route witness into `continue`, `continue-with-caution`, `stop`, or `insufficient`
- taught the guard to distinguish sidebar chat-history search from main-lane web search so authenticated home chat is not misclassified on a weak single cue
- wired the guard into `refresh-truth-surfaces` so current-root truth refresh emits both rooted and `validation/latest/` branch-guard artifacts
- refreshed ChatGPT support docs, selector notes, candidate bundle refs, and research notes around the new route/auth/title/text witness boundary

## Why this revision exists

rev0136 named the posture families, but it still left future runs to decide by hand whether one concrete route/title/text/auth witness really meant “continue” or “stop.”

rev0137 closes that gap. The repo can now preserve one route witness and evaluate it with a machine-readable guard before spending proof budget on composer and submit logic.

## What to run next

1. Capture a ChatGPT route witness from the plain browser route.
2. Run that witness through `python scripts/chatgpt-branch-guard.py evaluate --witness path/to/route-witness.json --pretty`.
3. Continue the proof kit only when the decision remains `continue` or `continue-with-caution`.
4. If the decision is `stop`, preserve the branch evidence and relaunch from the plain chat lane instead of trying to salvage the run by force.

## Known limits

- The branch guard is still only as good as the witness quality; a sparse witness should lower confidence rather than create false certainty.
- No stronger live ChatGPT support claim is made here. This revision improves the route-first bring-up discipline, not the runtime evidence tier.
