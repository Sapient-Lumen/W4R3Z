# Handoff rev0138 — route witness receipt, proof readiness gate, and sparse-evidence discipline

## What changed

- added `CHATGPT-ROUTE-WITNESS-RECEIPT.json` with a machine-readable quality rubric for route witnesses and a proof-readiness decision that sits after branch classification
- added `scripts/chatgpt-route-witness-receipt.py` plus `scripts/chatgpt_route_witness_receipt.py` and focused tests for ready-vs-hold outcomes
- refreshed the ChatGPT candidate-bundle path so the first proof can now stop not only on the wrong branch, but also on a witness that is too thin to hand off honestly
- updated ChatGPT support and selector notes so future sessions preserve recapture work as useful evidence rather than as wasted setup

## Why this revision exists

rev0137 could classify a concrete witness into continue, continue-with-caution, or stop. That closed the branch ambiguity, but it still left one honest gap: a lucky single cue could still produce a seemingly confident answer even when the route witness was too sparse to support a durable proof bundle.

rev0138 closes that gap by separating **what shell the witness seems to describe** from **how complete the witness actually is**.

## What is now true

- ChatGPT route witnesses can now be graded as `strong`, `usable`, `sparse`, or `insufficient`
- proof continuation can now land on `ready`, `ready-with-caution`, `hold-for-recapture`, `insufficient`, or `stop`
- missing route/title/main-lane evidence now lowers effective confidence instead of riding the branch guard unchanged

## What is still not proved

- there is still no live official-surface ChatGPT compose/submit/readback bundle in this archive
- the witness receipt is only as good as the captured route/title/text evidence it is given
- richer ChatGPT branches still need dedicated follow-on proof paths rather than being folded into the first baseline

## Recommended next move

Capture one real ChatGPT route witness, classify it with the posture matrix and branch guard, grade it with the route-witness receipt, and only then spend proof budget on compose/submit/read-latest if the witness reaches `ready` or `ready-with-caution`.
