# rev0090 handoff

## What changed

- added explicit broker ownership leasing for the native host via `daemon/src/glassttyd/broker_lock.py`
- long-lived native-host instances now become broker `owner`; one-shot helper processes report `broker.role = secondary` and no longer start the broker server
- native-host `health.ping` and `bridge.status` payloads now include `host_identity` and `broker` metadata
- extension background now records persistent-host identity, compares one-shot status snapshots against it, and preserves `matches_persistent_host` in cached status snapshots
- `scripts/doctor.py` and `scripts/native-host-report.py` now surface live broker-owner runtime metadata

## Why this mattered

Chrome still documents `connectNative()` as a long-lived host/port lane and `sendNativeMessage()` as a fresh-process one-shot lane. GlassTTY was already using the one-shot lane for browser-visible local status snapshots, so it needed explicit broker ownership discipline to avoid letting helper processes contend for the broker socket.
