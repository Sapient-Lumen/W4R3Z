# Handoff — rev0017 — 2026-03-07

## What changed

- added `chrome.alarms` permission and an alarms-backed native reconnect backoff lane in the MV3 background
- `bridge.status` now includes `nativeConnection` state with timestamps, reconnect attempt count, and scheduled reconnect timing
- the side panel renders a dedicated Native bridge card so reconnect state is visible without digging through the mirrored session blob
- trace output now records reconnect scheduling and alarm firings
- upgraded versions to `0.1.7` and refreshed validation artifacts for packaging

## Why this matters

Chrome's own MV3 guidance says deferred work should use `chrome.alarms`, not service-worker timers, and native messaging disconnects should reconnect via `connectNative()` from `onDisconnect`. rev0017 combines those: immediate reconnect first, then alarms-backed backoff if the host is still unavailable.
