# Handoff — rev0146 — 2026-03-21

## What changed

rev0146 adds a machine-readable `CHATGPT-BROWSER-ENVELOPE-RECEIPT.json` plus `scripts/chatgpt_browser_envelope_receipt.py` so repeated route-first ChatGPT proof can stay bound to one explicit browser/project profile instead of silently broadening from `chromium-live` into Chrome, Edge, Firefox, WebKit, or mobile support.

## Why it matters

The repo already had separate guards for route, composer, submit, proof-window coherence, repeated-window stability, support-claim scope, capability profile, and auth/workspace scope. The next honest gap was browser scope: ChatGPT's own troubleshooting guidance says browser extensions, cache, private windows, VPNs, and trying a different browser can materially change behavior, and Playwright explicitly models different browsers/configurations as separate projects.

## Grounding imported this round

- OpenAI's current troubleshooting article still says ChatGPT web issues can depend on browser extensions, cache/cookies, VPNs, or trying a different browser/incognito window.
- Playwright's current browser and projects docs still treat Chromium, Firefox, WebKit, and branded-browser configs as separate browser/project targets.
- The existing ChatGPT home/capabilities/workspace docs still keep the route/tool/session story bounded, so the new browser envelope adds one more explicit scope axis rather than replacing the prior gates.
