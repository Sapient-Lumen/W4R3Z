# Handoff rev0131 — source lock, claim basis, and authority lane

## What changed

- added a rooted **approved-source lock** so first-party product surfaces, vendor runtime docs, and route/history references now live in a named machine-readable hierarchy instead of implicit prose assumptions
- added a **support-source baseline** surface so each official surface can show approved sources, cited bundle sources, and source-authority gaps
- hardened the **support publish gate** so a bundle now needs the required approved source refs for its surface in addition to live workflow evidence and clean publication blockers
- attached explicit `source_refs` to the held Claude bundle so future sessions can see the current authority basis without pretending the bundle is already publishable

## Why it was worth doing

The strongest remaining transferable pattern from the comparison cubes was not another queue state but a narrower authority chain: GlassTTY already knew whether evidence existed and whether publication was blocked, but it still lacked a first-class answer to *what approved authority basis this stronger claim would rest on*.

## Current honest posture

- GlassTTY still has **zero published support bundles**
- the Claude held bundle now cites an approved source basis and still remains **held** because live official-surface workflow proof is missing
- the new source-authority lane mainly exists to stop future sessions from mistaking repo evidence alone for sufficient publication authority

## Recommended next step

Capture one live logged-in Claude official-surface support bundle with route/history witness and before/after workflow evidence, then move that bundle toward `published-ready` with both a fresh publish guard and the current approved source basis instead of relying on the held bundle alone.
