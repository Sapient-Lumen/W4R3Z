# Specimen flow 102 — cross-cube lineage import without inherited status

## Scenario

A Harbor correction lineage now depends on fragments from neighboring cubes. SlopOS has a replayable `portal.net` append sequence showing a correction candidate crossed a membrane. Foundry has a classification pin and crosswalk witness. Steward has retry attempts and pushback budgets. Schell has retention and forgetting-ledger context. ViewFS has a volition card and consent fence. Ward has a stewardship charter, delegation warrant, and escalation handoff. Helm has repair attempts and intervention traces.

The attractive shortcut is to merge all of that into one status: if enough companion cubes are green, replayable, retained, delegated, or repaired, Harbor should be able to mark the derivative current. F102 rejects that shortcut. Every imported fragment must enter an import quarantine: material identity first, parent context second, scope translation third, authority quarantine fourth, local recheck before any Harbor status.

## Required packets

- foreign material packet;
- local observation / import clock packet;
- parent manifest / archive digest packet;
- native-scope to Harbor-scope translation packet;
- authority quarantine packet;
- cross-cube lineage bridge packet;
- sealed-evidence public-summary limit packet;
- multi-cube conflict / incomparable split packet;
- local recheck plan packet;
- public badge refusal packet;
- non-promotion packet.

## Expected accepted outcomes

Harbor may admit foreign material as scoped evidence only:

- SlopOS append history as an ordering witness;
- Foundry classification pins as label provenance;
- Steward retry history as attempt history;
- Schell retention context without deletion or repair proof;
- ViewFS volition cards as consent evidence only;
- Ward delegation warrants as route or escalation evidence only;
- Helm repair traces with Harbor-side scope recheck;
- multi-cube conflicts as incomparable split state;
- sealed packets by digest with public-summary limits;
- stale companion revisions as historical residue requiring recheck.

## Expected refusals

Harbor must reject:

- foreign green status inherited as Harbor status;
- replay availability as currentness;
- retention window as repair;
- foreign warning state as public badge;
- companion revision as freshness;
- foreign scope widened on import;
- foreign archive digest mismatch;
- copied fragment without parent manifest;
- cross-cube total order without a clock map;
- foreign policy majority vote;
- sealed evidence as public truth;
- foreign acknowledgement as consumer repair;
- callback success as authority;
- SlopOS append order as semantic supersession;
- Foundry classification pin as status truth;
- Steward retry exhaustion as compliance failure;
- Schell forgetting ledger as erasure proof;
- ViewFS volition card as consent outcome;
- Ward delegation warrant as authority transfer;
- Helm repair trace as completed repair.

## Why this matters to SlopOS and companions

SlopOS can bind portal-net request records, accepted append history, checkpoint/resume evidence, truncation and suffix rejection, and callbacks. Foundry, Steward, Schell, ViewFS, Ward, and Helm can each provide useful companion evidence. Harbor's job is not to trust or distrust the companion. Harbor's job is to import the fragment without letting the companion's native vocabulary become Harbor authority.

## Non-promotions

No cross-cube status inheritance, companion trust root, foreign compliance workflow, multi-cube conflict-resolution engine, global public badge workflow, consent/delegation authority transfer, repair-ledger import API, or final SlopOS datacube shape is promoted by this specimen.
