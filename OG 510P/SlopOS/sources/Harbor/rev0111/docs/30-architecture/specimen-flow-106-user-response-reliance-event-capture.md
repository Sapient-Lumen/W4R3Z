# Specimen flow 106 — user response and reliance-event capture

## Scenario

A Harbor user-visible explanation card has been shown for a revocation overlay.  The person, operator, browser, or agent then interacts with the explanation by inspecting evidence, requesting recheck, exporting a scope note, dismissing the card, starting an appeal, copying a share link, acknowledging receipt, focusing a status message, asking for sealed detail, requesting a generated follow-up, opting out of notices, acknowledging in a batch, or triggering an automated retry.

The specimen asks Harbor to preserve the interaction as useful evidence without converting it into comprehension, consent, reliance, repair, legal posture, compliance, all-recipient notice state, or currentness.

## Flow

1. Start from the F105 explanation bundle digest and a parent explanation case.
2. Record a response event with kind, clock, surface, minimal actor reference, and event digest.
3. Record capture context: scope-map carry-forward, localization scope, undo/escape posture, and whether delivery/focus/scroll are being overpromoted.
4. Record interpretation guards for comprehension, consent, reliance, repair, compliance, permission, read/application, recheck result, and currentness.
5. Record follow-up action separately from outcome.
6. Record privacy/retention posture and reject direct-person analytics or unbounded retention.
7. Preserve the explanation/overlay history trace.
8. Emit an accepted scoped-response verdict or a refused response-status-collapse verdict.

## Expected refusals

Harbor must refuse to say:

- the user understood because they clicked, scrolled, focused, or acknowledged;
- the user consented because a checkbox or acknowledgement exists without a consent basis;
- a third party relied because a scope note was exported;
- a warning was accepted because a card was dismissed;
- a repair occurred because an appeal or retry started;
- all recipients read because a share link was copied;
- compliance changed because someone acknowledged;
- a sealed request grants permission;
- a recheck passed because a request was scheduled;
- delivery receipt is a user action;
- a stale explanation response proves currentness;
- an agent-generated acknowledgement is user consent;
- response analytics may identify a person by default.

## Non-promotion

The specimen does not promote a consent receipt schema, reliance ledger, analytics product, identity registry, UI telemetry API, notification-read guarantee, legal/compliance workflow, accessibility conformance claim, or final SlopOS datacube shape.
