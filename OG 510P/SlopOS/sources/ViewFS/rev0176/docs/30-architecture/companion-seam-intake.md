Every borrowed seam must name what ViewFS adopts, what it refuses to collapse, and the first fixture or proof obligation it should pressure.

## Immediate intake decisions

1. The embedded `slopos/` directory has been advanced from `rev0655` to uploaded `rev0720` so ViewFS no longer evaluates against a stale companion snapshot.
2. ViewFS now has its own E1-style fixture lane instead of only importing SlopOS proof culture by reference.
3. Schell pressure is promoted into the core schema through `DerivedArtifact.retention`; derived artifacts are not retention roots by default.
4. Ward and trusted-path pressure stay separate: a delegation warrant may authorize a reviewer lane, but it does not by itself produce a user approval cut.
5. Foundry pressure is applied to registry/RFC hygiene immediately: duplicated IDs and duplicated RFC numbers now fail lint.

## Speculative next import

The next companion import should be a SlopOS-shaped portal grant replay corpus: accepted grants append to a small log, denied/duplicate requests do not create live authority, crash prefixes restore without minting authority, and checkpoint/lineage/append images replay to the same admitted grant state. That would give ViewFS its first serious bridge from JSON specimens to SlopOS-grade recovery evidence.

## Revision 156 intake decisions

1. SlopOS replay pressure is now represented by concrete portal grant fixtures: accepted grant redemption and spent-grant replay denial.
2. Schell retention pressure is now represented by explicit retention-root and receipt-only non-root sweep fixtures.
3. Steward retry/replay pressure is now represented by restore-token death-verdict denial and spent portal-grant replay denial.
4. Helm repair honesty is now represented by stale observed-base commit denial before any richer repair/merge lane is allowed.
5. Ward delegation pressure is now represented by a membrane-death/stale-brake fixture; warrant/escalation lanes remain future work.
6. Foundry code-drift pressure is now represented by proof-obligation coverage lint in addition to registry and RFC-number lint.

The revised intake rule is: a companion seam may enter ViewFS architecture prose as soon as it is useful, but it should not enter the core schema until it has at least one fixture or a named non-fixture proof obligation.
