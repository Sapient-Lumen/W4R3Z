# SlopOS boundary crosswalk v0

## Purpose
Keep Steward a companion to SlopOS rather than a parallel constitution.

Steward may make lifecycle truth easier to operate, explain, and verify, but it must not silently strengthen, rename, or fork SlopOS primitives.

## Ownership split
| Surface | SlopOS owns | Steward owns |
| --- | --- | --- |
| Native capability substrate | primitive authority, compatibility law, sealed object meaning | lifecycle use of selected primitives and explanatory receipts |
| D-SUPV pressure | constitutional supervision shape | component lifecycle product semantics |
| D-ACTIVATE pressure | activation primitive boundaries | CH-COMP, CH-ACTSET, activation receipts, activation witness cards |
| CH-COMP / CH-ACTSET | final native object compatibility, if SlopOS adopts them | v0 proof-slice profile and lifecycle-facing authoring rules |
| D-QUIESCE pressure | native operation semantics | operator-visible no-new-work and drain explanation |
| Readiness and health | native predicate discipline where defined | witness separation across spawn, activation, readiness, serving, probes, and verdicts |
| Request idempotency | canonical request/effect law | retry-attempt explanation and same-key mismatch rejection |
| Session or network resumption | transport/capability substrate | live-channel gap/duplicate ambiguity and retry linkage |

## Non-strengthening rule
Steward may carry SlopOS facts, host facts, and adapter facts as basis evidence. It may not turn weaker evidence into stronger native truth by relabeling.

Examples:

- SlopOS request idempotency pressure can inspire Steward same-key/canonical-intent checks, but Steward must not claim a global idempotency ledger.
- SlopOS network/session pressure can inspire live-channel ambiguity labels, but Steward must not claim transport continuity.
- SlopOS activation primitives can inspire CH-ACTSET receipts, but Steward must not claim raw handles are portable authority.

## Conflict rule
If SlopOS and Steward vocabulary disagree, the conflict is review-blocking. Steward may keep a local v0 profile only if it names the mismatch and avoids exporting it as final SlopOS law.

## Import rule
Steward may import a SlopOS primitive into the proof slice only when it can state:

1. what exact object or witness is imported;
2. what meaning remains owned by SlopOS;
3. what weaker lifecycle explanation Steward adds;
4. which corpus case prevents strengthening drift.

## Export rule
Steward may propose a primitive back to SlopOS only when it has:

- a posture doc;
- at least one proof or corpus artifact;
- a clear non-claim list;
- a sibling-boundary note.
