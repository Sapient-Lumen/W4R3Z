# Companion boundary map v0

## Purpose
Prevent Steward from absorbing every useful adjacent idea.

Steward's scope is lifecycle truth and activation explanation. Other cubes own neighboring domains.

## Steward owns
- component lifecycle posture;
- activation manifests and activation receipts;
- runtime-cycle stale fences;
- readiness, serving, quiesce, stop, restart, and retry witness separation;
- lifecycle-focused admin/inspection surfaces;
- witness cards that explain what a lifecycle fact does and does not prove.

## Companion ownership
| Companion | Owns | Steward may use only as |
| --- | --- | --- |
| SlopOS | native capability substrate and constitutional primitives | source of primitive pressure and final compatibility law |
| Schell | shell command intent, transcript semantics, prompt/input behavior | exact anchors and command evidence when needed for lifecycle actions |
| Helm | desktop surfaces, repair cards, intervention traces, operator UX | operator-facing lifecycle explanation and repair-gate presentation pressure |
| Harbor | boundary crossings, openings, callbacks, chooser detours, follow-on grants | activation/request detour evidence and callback restraint |
| Ward | trust material, delegation warrants, attestations, appraisal | issuer, custody, and authority-basis evidence for lifecycle witnesses |
| ViewFS | object references, package/state storage, trusted paths, consent fences | storage/object-reference pressure without path-freshness claims |
| Foundry | foreign-ground realization, classification pins, code/category drift | adapter-membrane and host-classification pressure |

## Scope rule
Steward keeps shell, desktop, storage, trust, or crossing semantics only when a lifecycle corpus or lifecycle witness needs them. Otherwise the concept should remain sibling-owned pressure.

## Examples of keep-versus-defer
Keep in Steward:

- exact lifecycle action targets;
- status barriers;
- start/stop/restart/quiesce receipts;
- runtime-cycle stale fences;
- activation-set digests;
- repair gates that block lifecycle mutation.

Defer to siblings:

- paste firewall semantics;
- generic repair-card UX;
- terminal media surfaces;
- broad workspace snapshots;
- chooser/open object algebra;
- trusted path and consent-cache families;
- delegation and attestation frameworks.

## Drift test
Before adding a new Steward doc, ask whether the doc changes lifecycle truth. If it only changes surface ergonomics or neighboring object behavior, it should usually be a sibling pressure note.

## Revision 190 boundary note — Ward versus Steward authorization

Ward remains the home for stewardship charters, delegation chains, standing, contests, remedy state, owner discovery, and durable governance policy. Steward owns only the lifecycle mutation gate. A Ward-derived warrant may appear as `ST-DELEGATE v0`, but Steward still requires operation-specific review, approval, and authorization-check evidence before the lifecycle surface may treat the request as allowed.

This is a membrane, not a takeover: Steward records enough governance evidence to avoid ambient admin authority while refusing to become the governance cube.
