# Helm-rev0102-2026.03.23.01.03-quarantineribbons-endorsementreceipts

Helm is a desktop shell/compositor product for SlopOS-style capability systems.

This revision continues the outside research and companion-cube evaluation,
but tightens the question again:
**what small shell law would keep foreign, risky, or ambiguous arrivals honest all the way from origin evidence to safe-open, endorsement, derivative export, and live authority?**

## Main gains in this revision

- re-read **SlopOS** as the main teacher for arrival seams, quarantined preview weakness, exact mediation, and the rule that foreign material should not quietly clear itself by merely being visible or reopened
- pulled **ViewFS** closer as a direct teacher for keeping **origin evidence, quarantine/risk state, safe-open session, explicit clear/trust decision, sanitized derivative, and live open/exec authority** on separate seams
- kept **Schell** nearby as a teacher for **object cards, exact reveal, safe-open honesty, and anti-spoof action ladders**
- kept **Steward** nearby as a teacher for **trusted chrome, label humility, and shell-owned blocked/allowed posture**
- harvested fresh outside pressure from **Apple Gatekeeper and runtime protection**, **Windows Attachment Manager / zone information**, **Microsoft Office Mark-of-the-Web macro blocking**, **Chrome Safe Browsing and dangerous-download warnings**, and **VS Code Workspace Trust / Restricted Mode**
- added a new pass on **quarantine ribbons** and **endorsement receipts**
- sharpened one especially good answer for arrival posture: Helm should be able to say **network / email / transfer / unknown origin**, **still quarantined**, **safe-open only**, **endorsement requested**, **endorsed exact object**, **fresh sanitized derivative**, or **live authority now** instead of flattening everything into one vague open/import story
