# Source basis note — 2026-03-25 (461)

This pass was an **evidence-interchange and profile-contract** pass.
It did not aim to prove that a brand-new top-ranked lane exists.
It aimed to check whether current Rust ecosystem signals justify making **versioned portable exchange contracts** a first-class planning layer for the current leaders.

## Facts imported directly

1. Rust users still report substantial pain around resource usage and debugging, while official online documentation remains the preferred canonical reference.
2. Official Rust debugging material explicitly emphasizes debugger / operating-system / version variance and async gaps.
3. crates.io now exposes stronger trust/publication/security surfaces including a Security tab and Trusted Publishing enhancements.
4. docs.rs hosts rustdoc JSON, warns consumers to inspect `format_version`, supports configurable docs.rs build metadata, and offers downloadable rustdoc ZIP archives with caveats.
5. Rust target tiers already distinguish bounded levels of support instead of one binary support claim.
6. Cargo/project-goals work continues around semver checks, libtest JSON, build analysis, namespaces, public/private dependency boundaries, and mirroring.
7. StableMIR explicitly aims to give tool developers a reliable interface that is insulated from compiler internals and published through crates.io.
8. The Rust Project Goals process is now annual for 2026 and currently tracks a large active slate.

## Main inferences from those facts

1. The archive still does **not** need a fresh umbrella frontier reset.
2. The current substrate increasingly rewards crates that can normalize many official surfaces into **portable, versioned, validated exchange bundles**.
3. The support-envelope ring is the cleanest first place to define a shared interchange doctrine.
4. The pathfinder / knowledge front door should increasingly import exchanged bundles instead of inventing bespoke packet formats.
5. The continuity/parity ring is the strongest next proof that the same contract can survive release and registry drift.
6. The archive itself benefits from one more machine-readable interchange memory layer.

## Open questions kept open

- Should the profile vocabulary (`explore`, `ci-minimal`, `enterprise-offline`, `safety-qualified`) be shared verbatim across all top lanes?
- When should a lane specialize verifier behavior rather than reuse the default bundle verifier?
- Is `interchange-profiles.json` enough as machine-readable memory, or should later passes add per-lane schema manifests and compatibility fixtures?
