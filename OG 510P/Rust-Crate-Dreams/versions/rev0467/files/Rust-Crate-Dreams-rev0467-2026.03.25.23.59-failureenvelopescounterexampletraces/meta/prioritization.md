# Prioritization rubric

This archive is intentionally broad. To decide what is **worth building**, score proposals across these axes (0–5 each), then discuss *why*.

## Scoring axes

1. **Impact** — If this exists, how many teams/projects does it unblock?
2. **Neglectedness** — Is there truly no good default crate/path today?
3. **Feasibility** — Can an MVP ship in 4–8 weeks with clear next steps?
4. **Adoptability** — Can it fit into existing stacks without rewrites?
5. **Sustainability** — Can it be maintained with a small team?
6. **Differentiation** — What is the sharp idea that makes this “the” crate?

## Guardrails (automatic downscore triggers)

- "We can just wrap 3 existing crates" with no new value
- unclear ownership/maintenance plan
- broad scope without a modular architecture
- "needs compiler changes" for MVP

## Output

Each proposal file should include:
- a **scorecard** (axes above)
- a **minimum lovable MVP**
- a **de-risk plan** (what to prototype first)
