# Entry 394 — projection/reborrow work deepened into a real smart-pointer semantics support lane

This pass stayed focused.
It did **not** add another big territory rerank.
Instead it deepened an older but still under-productized frontier:

**P-0440 Projection & Reborrow Semantics Kit**.

## Why this lane earned a serious refresh now

Fresh primary signals make the seam sharper than it used to be:

- the 2026 Rust flagships explicitly treat **field projections**, **reborrow traits**, and **in-place initialization** as part of the active “Beyond the `&`” frontier;
- the field-projections goal and the reborrow-traits goal make it clear that Rust still lacks ergonomic general-purpose language support for these patterns;
- the in-place-initialization goal explicitly points to real ecosystem experimentation such as `pin-init`, `moveit`, and Crubit-style constructors;
- current crates already prove demand for library-level substrate: `pin-project`, `pin-init`, `moveit`, `reborrow`, `relend`, and `reborrow-generic`;
- Miri remains the practical undefined-behavior detector for unsafe abstractions;
- and PinChecker’s 2025 results are a reminder that popular pinning APIs can still hide soundness bugs.

Together those signals say the missing value is no longer “someone should make pinning easier someday.”
The missing value is a stable crate-level handoff for:

1. projection authority,
2. borrow/reborrow mode coverage,
3. witness-basis honesty,
4. Miri-backed semantics evidence,
5. and portable support bundles.

## Main judgment after the refresh

**P-0440** is now stronger as a **receiver-facing semantics-support lane** than as a generic “projection testkit” idea.

That means the proposal should own:

- `projection-authority.receipt`,
- `borrow-semantics.matrix`,
- `semantics-witness.report`,
- and `projection-support-bundle.manifest`.

It should **not** try to own:

- the official language design,
- all unsafe reasoning,
- all in-place initialization semantics,
- or the full cross-language boundary contract.

## What should count as a worthy crate contribution in this lane now

A worthy projection/reborrow crate should hand other people:

1. **one authority receipt** that says which projection surface is actually being claimed,
2. **one mode matrix** that says which borrow/projection modes are supported or caveated,
3. **one witness report** that distinguishes ordinary tests, Miri, imported evidence, and manual-review gaps,
4. **one portable bundle** that another team can review later,
5. **one explicit uncertainty story** instead of fake soundness confidence.

If a candidate crate cannot do those things, the archive should usually treat it as a macro, helper crate, experiment, or local convention — not an epic semantics contribution.
