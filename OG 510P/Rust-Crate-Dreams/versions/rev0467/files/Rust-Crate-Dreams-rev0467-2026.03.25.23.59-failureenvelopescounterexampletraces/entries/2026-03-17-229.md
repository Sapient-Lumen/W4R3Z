# 2026-03-17 (229) — crate capability-contract productization pass

This pass did **not** add a new lane.
It sharpened **P-0510 Crate Capability Contract & Interop Profile Kit** into a more implementation-ready `0.1` shape.

## Main judgment

The missing value is still **not** another registry ranking feature, another whole-project support matrix, another item-level cfg matrix, or another slice-specific analyzer.
The sharper missing layer is a **maintainer-published support / interop contract** that records:

- which support profiles the crate is actually claiming,
- which facts are declared versus observed versus inferred,
- which hidden adoption obligations were actually observed,
- which public interop ecosystems are intentionally exposed,
- and how complete the advertised support story really is.

## Why this lane looks sharper now

- Rust’s current vision work explicitly argues that users need help navigating crates **and** that Rust needs smoother library interop.
- The 2025 State of Rust survey still says **online documentation** and **studying the code** are the main learning surfaces, which raises the value of structured support contracts over README prose alone.
- The Externally Implementable Items goal reinforces that library customization points are becoming more public and documentable, which strengthens the case for crate-authored support contracts.
- Cargo and docs.rs now provide enough substrate — `package.metadata`, `rust-version`, `build`, `links`, docs.rs metadata, rustdoc JSON, and `cargo metadata` — that the sharper missing value is the joined contract above them.
- crates.io is surfacing more decision-relevant information such as security advisories, which makes producer-side support truth more worth joining rather than less.

## Preferred proving grounds

- async crates using Tokio internally while advertising runtime-neutral public boundaries
- crates claiming `no_std` / `alloc` support while docs.rs or examples still lean on `std` overlays
- crates with proc macros, `build.rs`, or `links` that materially change downstream adoption cost
- crates where package metadata, workspace metadata, and docs.rs metadata can all influence the support story
- widely used crates whose public interop surface matters almost as much as their raw functionality
