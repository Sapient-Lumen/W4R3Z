# Entry 121 — foreign package ecosystems: Node/npm prebuild contracts and NuGet native interop shipkits

This pass broadened the archive deliberately. Instead of adding another Cargo-adjacent witness, it promoted two foreign-ecosystem seams the archive had been explicitly watching: **Rust→Node/npm native addon shipping** and **Rust→.NET/NuGet native interop packaging**.

First, it separated **Node-API package and prebuild contracts** from the already-existing Python-wheel and Apple-XCFramework work. Node.js already gives Rust a real ABI-stable substrate through Node-API, and napi-rs already offers a mature authoring/build stack with generated bindings and cross-platform prebuild workflows. But maintainers still cannot hand one another one compact artifact that says **which Node-API floor they promised, which `.node` binaries they actually published, how the JS loader resolves them, and whether Bun/Deno/local-build fallback claims are honest**.

Second, it separated **NuGet native interop shipping** from both generic FFI helper crates and mobile/desktop packaging. Microsoft already documents RID-aware native asset layout, probing rules, and Native AOT interop specifics, while csbindgen already smooths Rust→C# binding generation. But maintainers still cannot hand one another one compact artifact that says **which RIDs were actually packaged, whether managed binding names match native library names, what probing or resolver assumptions exist, and where Native AOT or single-file deployment changes the support story**.

New proposals:

- P-0498 Node-API Package & Prebuild Contract Kit
- P-0499 NuGet Native Interop ShipKit

Why these rose:

- **P-0498** rose because Rust’s Node ecosystem is no longer missing raw binding capability. The sharper gap is a **runtime contract / prebuild manifest / loader receipt / support-risk bundle** above Node-API and napi-rs.
- **P-0499** rose because Rust’s .NET ecosystem is no longer missing raw interop capability. The sharper gap is a **RID contract / binding receipt / native-load report / support-risk bundle** above NuGet native-file conventions and Rust-generated bindings.

What changed in archive judgment:

- The archive now draws a cleaner line between **producer-side package contracts** for Python, Apple, Node/npm, and NuGet rather than treating “foreign language integration” as one undifferentiated bucket.
- The archive now has a stronger pattern for crates that sit above **package-manager-specific runtime assets, loader logic, and downstream support promises** rather than above raw binding generation.

Archive hygiene added in this pass:

- Added an amnesia resistor warning future revisions not to confuse a binding generator or CLI scaffold with a boring package-manager-specific release contract.
- Added known-existing and frontier notes pushing future passes to distinguish **ABI substrate**, **artifact layout rules**, **loader/probing behavior**, and **consumer-support promises** whenever a foreign ecosystem is involved.
