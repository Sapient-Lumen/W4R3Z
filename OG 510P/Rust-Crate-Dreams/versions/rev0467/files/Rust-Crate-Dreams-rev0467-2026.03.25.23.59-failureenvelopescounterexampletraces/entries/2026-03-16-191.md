# Entry 191 — package review promoted into a fixture-first workspace-aware source-bundle lane

This pass did not add a new proposal.
It upgraded **P-0470 Cargo Package Review Kit** into a more implementation-shaped lane with schema files, scenario packs, and a sharper statement of what the crate should actually hand other people.

## Why this moved now

Several official Cargo signals now line up unusually well.

### 1. `cargo package` already defines a richer review contract than the archive was freezing

The docs do not just say “a tarball appears.”
They say Cargo rewrites and normalizes the manifest, removes `[patch]`, `[replace]`, and `[workspace]`, includes `Cargo.lock`, writes `.cargo_vcs_info.json`, flattens symlinks, rebuilds the extracted package, and checks that build scripts did not modify source files.

That is already enough substrate for a real review bundle.

### 2. Workspace packaging is more concrete now

The changelog says `-Zpackage-workspace` now supports packaging interdependent workspace crates and no longer requires those crates to publish to actual registries.
That makes “what exact package set did we review?” a real missing artifact boundary instead of a hypothetical future concern.

### 3. The canonical place for `.crate` review is clearer now

Rust release notes now tell users not to rely on `cargo publish` as the place `.crate` files persist as final artifacts.
That pushes this lane firmly toward **`cargo package` as the review anchor**.

### 4. External-file copy behavior is explicit enough to deserve review posture

The Cargo 1.90 development-cycle discussion made workspace-root license/readme copy questions explicit, rather than leaving them as invisible implementation trivia.
That means a worthy crate should preserve copy-in behavior and manual-review boundaries rather than pretending every packaged path came from the same include/exclude story.

## Current judgment

The worthy crate here is not:

- another registry client,
- another trusted-publishing wrapper,
- another provenance story,
- or another manual checklist pasted into CI.

The worthy crate is the boring shared layer that can hand other people:

1. a **workspace package-set report**,
2. a **manifest-normalization report**,
3. a **path explanation report**,
4. an **evidence-source receipt**,
5. and a **small diffable review bundle**.
