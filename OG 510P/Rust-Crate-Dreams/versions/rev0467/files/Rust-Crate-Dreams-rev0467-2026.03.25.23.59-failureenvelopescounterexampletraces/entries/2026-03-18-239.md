# Entry 239 — Rust Android Mobile Kit deepening around ABI coverage, load-doctor policy, and 16 KB page-size readiness

This pass did **not** promote a brand-new foreign-package lane.
It sharpened **P-0168 Rust Android Mobile Kit** into a more believable shipping crate.

## Why this moved now

The Android/Rust substrate is now strong enough that the missing value is no longer “compile Rust for Android somehow.”
The sharper missing layer is a **cargo-native shipping contract** above existing substrate:

- `cargo-ndk` already handles Android NDK env/target plumbing and `jniLibs`-shaped output layouts. citeturn709402search1turn458687view0
- UniFFI can generate Kotlin bindings, but that does **not** by itself solve Android AAR packaging or final native-library shipping workflow. citeturn709402search2turn458687view1
- `cargo-apk` and `cargo-mobile2` show real packaging/mobile workflow demand, but neither is the same thing as a small review-first contract for Android library shipping. citeturn388957view0turn388957view1
- Android’s own NDK guidance makes AAR-native-library packaging and collision risks concrete, especially around packaged JNI libraries and `libc++_shared.so`. citeturn709402search3turn458687view2
- Android now requires modern app submissions targeting Android 15+ devices to support **16 KB page sizes** on 64-bit devices, which turns native-library readiness into a more explicit release concern. citeturn559103search1turn458687view3
- Rust release notes now assume **Android NDK 25 or newer**, so long-lived project scripts already sit on moving toolchain assumptions. citeturn709402search0turn458687view5

## Main planning move

This pass kept the archive honest about what the crate should be.
The right `0.1` is **not** another full mobile framework, not another generic project generator, and not another wrapper that hides Android packaging realities.

The sharper missing crate is:

- a **cargo-native build/package/doctor/diff** workflow,
- scoped to **libraries and shared Rust cores shipped into Android apps or SDKs**,
- built on top of `cargo-ndk`, UniFFI, and standard Android packaging rules,
- with three first-class review objects that were previously still too implicit:
  1. **ABI coverage**
  2. **load-doctor / packaging-collision policy**
  3. **16 KB page-size readiness**

## Main judgment after the pass

A worthy Android shipping crate should now provide not only reproducible builds, but also:

- explicit **ABI coverage truth**,
- explicit **binding-mode honesty**,
- explicit **load-doctor / packaging-collision policy**,
- and explicit **16 KB page-size readiness receipts**.

That is a much sharper and more believable contribution than “yet another Android build wrapper.”
