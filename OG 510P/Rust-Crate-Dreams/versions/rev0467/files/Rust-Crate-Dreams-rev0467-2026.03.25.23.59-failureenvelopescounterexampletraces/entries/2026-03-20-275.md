# Entry 275 — crate upgrade support sharpened around summary-claim traceability and fallback refs

This pass came from noticing that the upgrade pack had become honest about source lineage, readiness, export posture, deviations, warnings, and freshness while still carrying one quiet bluff:

> the exported human summary could still sound more exact than the receipts beneath it.

## What moved this time

Three donor patterns kept surviving scrutiny:

- **Goldenrule** made the strongest case that compact public claims need a **claim register** rather than pure prose trust.
- **GlassTTY** made the strongest case that a release claim should stay traceable through state/evidence rather than becoming a standalone sentence.
- **Micromax + The Election Stack** made the strongest case that first-contact public surfaces need an explicit **fallback path** when a short sentence compresses more truth than a reader can safely act on.

## Main planning move

The previous passes already established:

- source lineage, source heads, native import truth, and hazard arbitration,
- fixup posture, package-scope truth, and active follow-through state,
- pack readiness, review queue, and cross-register consistency,
- export posture, exact publication surface, deviations, warnings,
- and revalidation/freshness/supersession.

This pass adds one sharper review object above them:

1. **summary-claim traceability** — every exported human summary claim can carry a stable id, claim class, audience, status, authoring mode, exact evidence refs, active warning/deviation links, and one fallback ref.

## Why this matters

Without **summary-claim traceability**, the lane still permits two ordinary lies:

- a polished bullet can sound like an exact native import when it is really a mixed maintainer synthesis across several receipts,
- and a downstream reader can treat one compressed sentence as the whole contract even when the sentence really needs to hand them into a recipe, warning, manual-boundary receipt, or review-queue item.

That is not cosmetic. It is the difference between a pack that is reviewable somewhere in the repository and a pack whose first-contact human summary is itself bounded and reconstructible.

## Main judgment after the pass

A worthy upgrade-support crate should now provide more than exact receipts plus one human summary.
It should also provide:

- one compact **summary-claim register** that says what the exported summary actually claims,
- one explicit **authoring-mode distinction** so mixed synthesis does not masquerade as native import,
- and one bounded **fallback ref** for any summary sentence that is too compressed to act on safely by itself.

That keeps the lane from quietly turning reviewable receipts into untracked prose authority.
