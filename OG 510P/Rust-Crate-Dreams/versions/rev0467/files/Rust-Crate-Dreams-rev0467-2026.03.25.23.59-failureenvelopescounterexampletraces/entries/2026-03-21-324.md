# Entry 324 — test-run artifacts deepened for run identity, selection basis, attempt topology, and share-safe bundles

This pass deepened **P-0106 Test Run Artifact Standard Kit** instead of opening another test runner, JUnit exporter, or flaky-test dashboard.

## Why this lane earned another serious pass

The archive already had the intuition that Rust test results are still too ephemeral.
What it lacked was a build-shaped answer for *which truths actually belong in one portable test-run contract*.

Current substrate is now strong enough to make that precise:

- `cargo test` still routes through libtest executables and forwarded selection arguments;
- Cargo explicitly says its JSON output does **not** control arbitrary tool output;
- the Rust project has an explicit goal around stabilizing machine-readable libtest JSON;
- nextest now records event streams, captured outputs, workspace metadata, attempt IDs, retries, stress iterations, and portable recordings;
- and nextest also explicitly warns that portable recordings may contain secrets or PII and are **not** auto-redacted.

That means a worthy crate here should not simply say “exports test results.”
It should say what run was captured, how it was selected, what attempt semantics shaped it, and whether the resulting bundle is actually safe to share.

## What moved this time

The main planning move was to stop treating all machine-readable test output as one kind of truth.

This pass elevated four review objects into first-class status for **P-0106**:

1. **run-identity truth** — which runner/harness/import route produced the artifact and how exact that identity is;
2. **selection-basis truth** — what package/target/filter/profile/platform basis actually defined the run;
3. **attempt-topology truth** — whether retries, fail-fast, stress loops, or process model changed the meaning of the verdict;
4. **bundle-sensitivity truth** — whether the artifact is merely portable, internally shareable, or actually safe to export.

## Why this matters now

The ecosystem evidence is no longer ambiguous:

- Cargo’s own JSON output stops at Cargo/rustc and does not standardize test-runner output.
- The libtest JSON goal proves stable machine-readable test output is a real unmet need.
- Nextest already captures a rich native recording surface, but that still does not magically become a cross-runner portable contract.
- Nextest portable recordings also come with an explicit sensitivity warning.
- `libtest-mimic` shows that custom harnesses can look like libtest while still needing explicit identity truth.

That means a worthy test-artifact crate should not let “we have logs / JSON / JUnit” quietly over-claim exactness, replayability, or share-safety.

## Main judgment after the pass

A worthy test-run artifact contribution should now provide more than a log export or a runner-specific recording.
It should also provide:

- one explicit **run-identity receipt**,
- one explicit **selection-basis receipt**,
- one explicit **attempt-topology report**,
- one explicit **bundle-sensitivity receipt**,
- and one conservative rule for when an artifact is portable but not exact or safe to share.
