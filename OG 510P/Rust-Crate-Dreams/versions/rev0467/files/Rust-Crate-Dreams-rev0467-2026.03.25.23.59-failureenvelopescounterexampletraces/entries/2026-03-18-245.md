# Entry 245 — Hex native NIF shipkit deepening around checksum residency, NIF-version windows, and fallback triggers

This pass did **not** invent a brand-new BEAM lane.
It sharpened **P-0502 Hex Native NIF ShipKit** into a more believable shipping-contract crate.

## Why this moved now

The Hex / Elixir / Erlang / Rust substrate is now real enough that the missing value is no longer just “please make Rust callable from the BEAM somehow.”
The sharper gap is a **boring package and support contract above already-working authoring tools**:

- `rustler_precompiled` now documents that precompilation happens in CI, that the Hex package should always include a checksum file, and that the checksum file is mandatory for the package to work.
- The current precompilation guide also makes NIF-version choice more explicit: NIF versions are more stable than OTP versions, older NIF minors can satisfy newer OTP releases within a compatible major, and the build matrix is intentionally target × NIF-version shaped rather than only OTP-version shaped.
- `rustler` now clearly lives in a features-first world for NIF version selection, and recent changelog history shows that build/no-artifacts and template/workspace details are still active substrate rather than frozen folklore.
- Erlang/OTP still makes `erlang:load_nif/2` and fallback stub implementations explicit, and its common caveats continue to warn that NIFs can degrade VM responsiveness if overused.
- Hex publishing and `hex_core` make tarball facts and outer checksums explicit enough that package receipt language can be concrete instead of hand-wavy.
- Real package changelogs now show the exact maintenance failures this archive cares about: missing checksum files inside Hex packages, artifact naming drift that breaks `rustler_precompiled`, local-build fallback when a target is unsupported, target-matrix expansion, and explicit NIF-version upgrades.

So the gap is not “there is no Rust BEAM tooling.”
The gap is that maintainers still rarely get one **reviewable Hex/NIF bundle** that says:

- whether the checksum file truly shipped inside the Hex tarball,
- what NIF-version / OTP window the release is really promising,
- when users get a precompiled NIF versus a forced local build,
- and how loader/path expectations relate to those claims.

## Main planning move

This pass kept the archive honest about what the crate should be.
The right `0.1` is **not** another NIF wrapper, not another CI action bundle, and not a generic Hex publisher.

The sharper missing crate is:

- a **cargo-native inspect/check/diff/bundle** workflow,
- scoped to **Rust-built NIFs published in Hex packages and consumed from Elixir/Erlang**,
- above today’s Hex tarballs, `rustler`, `rustler_precompiled`, and BEAM loading substrate,
- with three first-class review objects that were previously still too implicit:
  1. **checksum residency**
  2. **NIF-version window**
  3. **fallback trigger**

## Main judgment after the pass

A worthy Hex-native shipkit should now provide not only a package receipt, but also:

- explicit **checksum-residency truth** (`checksum_residency_ok`, `checksum_file_missing_from_tarball`, `checksum_asset_mismatch`, etc.),
- explicit **NIF-version-window truth** linking cargo features, Rustler config, and OTP claims,
- explicit **fallback-trigger truth** for target-not-covered, force-build, and toolchain-required paths,
- and a compact review bundle that another person can inspect without replaying Mix, GitHub releases, and local install behavior by hand.

That is a much sharper and more believable contribution than “yet another Rust-to-Elixir helper.”
