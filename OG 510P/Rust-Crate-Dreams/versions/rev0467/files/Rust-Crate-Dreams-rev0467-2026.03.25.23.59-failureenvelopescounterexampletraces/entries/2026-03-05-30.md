# 2026-03-05 (30): C2PA ShipKit + HTTP message signatures interop + RISC-V conformance runner

This entry adds three proposals that share a theme: **interop needs artifacts**. Each proposal centers on a portable “bundle” format that makes failures and reviews reproducible.

## Added proposals

- **P-0179** — `proposals/content-authenticity-c2pa-shipkit.md` — Content Authenticity (C2PA) ShipKit  
  Evidence: C2PA specification and the Rust `c2pa` SDK docs.  
- **P-0180** — `proposals/http-message-signatures-interop-kit.md` — HTTP Message Signatures Interop Kit  
  Evidence: RFC 9421 and ongoing ecosystem discussion of profiles for ActivityPub.  
- **P-0181** — `proposals/riscv-emulation-conformance-kit.md` — RISC-V Emulation & ISA Conformance Kit  
  Evidence: rvemu (Rust emulator) plus official RISC-V test suites (`riscv-tests`, `riscv-arch-test`).

## Notes

- The ShipKits are intentionally **thin** around existing primitives: the “missing crate” is mostly *workflow + fixtures + CI-grade evidence artifacts*.
- Bundle formats (`c2pabundle.zip`, `httpsigbundle.zip`, `riscvbundle.zip`) should remain semver-versioned schemas, not ad-hoc dumps.
