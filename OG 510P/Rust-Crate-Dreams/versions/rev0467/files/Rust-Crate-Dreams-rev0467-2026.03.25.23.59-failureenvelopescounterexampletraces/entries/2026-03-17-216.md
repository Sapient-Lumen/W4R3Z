# 2026-03-17 — Entry 216

Today’s pass did not promote a new crate lane.
It made **P-0472 Docs.rs Build Parity & Evidence Kit** more buildable.

## Main judgment

The docs.rs parity lane is now strong enough that the next useful move was **productization discipline**, not another neighboring proposal.

The sharper `0.1` shape is now:

- one compact profile file,
- one local capture path,
- one short human-first explanation renderer,
- one diff path,
- one hosted-build import path,
- one compact bundle/export path,
- and three artifacts that had previously been too implicit: **preflight fidelity**, **hosted-build import**, and **drift-cause classification**.

That matters because current official docs now say several awkward things very plainly:

- docs.rs uses nightly and publishes the current toolchain,
- `cargo docs-rs` is helpful but not a perfect replica,
- `docsrs` cfg only applies to the final rustdoc invocation,
- all non-`x86_64-unknown-linux-gnu` targets are cross-compiled,
- the source tree is mostly read-only,
- network access is blocked,
- build logs are capped,
- and target defaults can drift when metadata stays implicit.

So the missing value is not another docs runner.
It is the joined, reviewable contract that says what we tried, how close it was to hosted docs.rs, what limit/policy facts mattered, what we could import from hosted evidence, and which drift causes are plausible without pretending certainty.

## Why this was worth a pass

The official docs make the boundary clearer than before:

- docs.rs already publishes metadata knobs and sandbox constraints,
- docs.rs already points maintainers to `cargo docs-rs` in CI,
- docs.rs already offers builder-based local reproduction,
- docs.rs already exposes release/build summaries,
- docs.rs now hosts rustdoc JSON with explicit format-version caveats,
- and the 2025 default-target change proved that implicit docs posture can drift even when the crate code barely moved.

That means the missing value is increasingly not another wrapper around `cargo rustdoc`.
It is the explanation and handoff layer that records **fidelity**, **imported hosted facts**, and **drift causes** in a form ordinary maintainers can actually review.

## Working rule after this pass

Do not invent another nearby docs-support crate until **P-0472** proves too cramped to hold:

- metadata normalization,
- local preflight fidelity,
- hosted-build import,
- sandbox-limit interpretation,
- drift-cause summaries,
- release diffs,
- and compact downstream issue bundles.

If those still fit cleanly, the right move is to deepen **P-0472**, not split it prematurely.
