# 2026-03-06 (68) — OpenRTB / MAVLink / AS2 / ORC / BPMN-DMN frontier pass

This pass intentionally widened the search radius across **adtech, robotics, legacy enterprise messaging, data infrastructure, and process automation**.

## Added

- **P-0292** OpenRTB 2.6 + AdCOM Interop & Evidence Kit (`rtbbundle.zip`)
  - High salience: the spec now has ongoing 2.x monthly updates, 2.6 externalizes enums into AdCOM, and Rust mostly has schema crates rather than reproducible interop tooling.
- **P-0293** MAVLink Microservices Interop & Evidence Kit (`mavbundle.zip`)
  - High salience: Rust has protocol crates, but the pain lives in mission/parameter/file/signing microservice behavior over lossy links.
- **P-0294** AS2 + MDN Interop & Evidence ShipKit (`as2bundle.zip`)
  - Medium-High salience: old but still operationally critical; Rust lacks a cohesive partner-certification and incident-replay stack.
- **P-0295** ORC Interop & Canonicalization Kit (`orcbundle.zip`)
  - Medium salience: `orc-rust` is maturing well, so the gap is not “build ORC from scratch” but canonicalization, semantic diff, and bug bundles around it.
- **P-0296** BPMN 2.0 + DMN Conformance Workbench Kit (`processbundle.zip`)
  - Medium-High salience: merged the workflow/rules frontier into one bounded workbench because portability and replay matter more than yet another engine.

## Synthesis / pruning notes

- **Merged** BPMN and DMN into one workbench proposal instead of splitting them into two underpowered crates.
- **Downgraded** ORC from “epic missing engine” to “interop/canonicalization layer around a rising native implementation.”
- **Kept** OpenRTB and MAVLink near the top because both ecosystems are large, high-stakes, and unusually full of incident-driven compatibility pain.
