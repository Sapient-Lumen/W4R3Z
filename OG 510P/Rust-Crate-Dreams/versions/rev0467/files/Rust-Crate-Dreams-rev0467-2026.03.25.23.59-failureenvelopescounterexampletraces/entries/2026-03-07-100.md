# Entry 100 — Rust transition-adoption kits: Polonius witnesses, in-place initialization, ref-count migration, and evolving trait hierarchies

Added four proposals after another pass over places where Rust is clearly moving, but ordinary maintainers still lack a compact artifact layer that helps them adopt, compare, or review the change.

New proposals:

- P-0446 Polonius Borrowck Transition Witness Kit
- P-0447 In-Place Initialization Adoption Kit
- P-0448 Ergonomic Ref-Counting Migration Kit
- P-0449 Trait Hierarchy Evolution Migration Kit

Why these rose:

- **P-0446** rose because Polonius is no longer just a long-range theory project: the Rust project has an alpha analysis with real practical acceptance improvements and stabilization intent, but maintainers still lack a compact **old-borrowck/new-borrowck witness** above today’s compile-fail harnesses.
- **P-0447** rose because in-place initialization now has a concrete multi-domain motivation set — pinned values, C/C++ constructors, Linux-kernel out-ptrs, and async-in-dyn-trait futures — while today’s real substrate (`pin-init`, Crubit/Ctor, pin ergonomics) still lacks a shared **address-stability and fallible-init receipt layer**.
- **P-0448** rose because ergonomic ref-counting has now converged toward a `Share`-trait plus move-expression direction, but ordinary teams still lack a **capture audit / aliasing ledger / migration receipt** that helps them reason about today’s `Rc`/`Arc` boilerplate and tomorrow’s possible language path.
- **P-0449** rose because the Rust project is explicitly tackling evolvable trait hierarchies with motivating cases like `Receiver`/`Deref` and `tower::Service`, yet library maintainers still lack a **semver-aware trait-split planner** with impl-closure and receiver-capability receipts.

What changed in archive judgment:

- The archive now has a sharper pattern for crates that help ordinary users survive **language-transition adoption**, not just compiler-mode or package-surface transitions.
- A worthy crate contribution may be an **adoption kit**, **migration ledger**, or **hierarchy planner** sitting between today’s ecosystem practice and tomorrow’s upstream Rust feature.
- This pass also corrects a subtle failure mode: assuming that if upstream language design is still moving, there is nothing ecosystem authors can build yet. In many cases, the right crate is the thing that makes today’s pressure and tomorrow’s migration **reviewable now**.

Archive hygiene added in this pass:

- Added an amnesia resistor reminding future passes to look for crates that make upstream language pressure legible *before* stabilization, while staying honest about uncertainty.
- Added known-existing notes so future revisions do not mistake `pin-init`, compile-fail harnesses, `Receiver`, or the official ergonomic-RC goals for proof that the adoption-layer problem is already solved.
