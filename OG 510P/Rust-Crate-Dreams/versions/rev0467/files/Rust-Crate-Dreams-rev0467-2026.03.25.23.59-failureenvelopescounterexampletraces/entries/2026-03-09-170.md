# Entry 170 — text layout profiles and decision-origin receipts made explicit

This pass again avoided adding more proposal count.

The stronger move was to make **P-0197 Text Layout & Shaping Conformance Kit** more honest about what another maintainer actually needs when reading a text-layout diff.

## Main judgment

The next important missing value is **not** another text engine.
It is a compact contract for separating:

- the semantic case,
- the pinned interpretation profile,
- the backend capability surface,
- the origin of important decisions,
- and the fonts that actually resolved at runtime.

Without that separation, too many future diffs collapse into a fake story like “the backend changed text output”.

## Why these changes were the right ones

### 1. The proposal still under-specified comparability
The earlier pass made `P-0197` fixture-first.
That was good.
But it still did not cleanly answer a receiver-facing question:

> did this line-wrap diff come from a different text request, a different profile, a different backend capability surface, backend discretion, or a different font universe?

This pass makes that much more explicit.

### 2. Current ecosystem signals support profile-aware planning
Recent ecosystem signals make profile and discretion reporting more important, not less:

- Unicode 17.0 updates text-segmentation details.
- Parley continues to evolve on grapheme/line-break and emoji-presentation surfaces.
- COSMIC Text continues to evolve fallback and text-navigation behavior.
- WPT CSS Text remains a valuable import lane, but it carries browser-policy assumptions that should not be silently mistaken for raw Unicode-default behavior.

That means a strong Rust crate here should preserve policy provenance instead of burying it.

### 3. The archive needed a receiver-facing artifact split, not another text subproposal
The earlier stack note separated text *layers*.
This pass separates the **artifact contracts** that a downstream receiver reads.
That makes the archive smaller in practice because future revisions have a clearer place to put new details.

## New planning stance

For the next few passes, the archive should prefer:

- treating `layout-profile` as a first-class public artifact,
- demanding a `decision-origin` receipt whenever a run mixes pinned policy and backend discretion,
- demanding a `font-resolution` receipt whenever runtime font discovery can change the result,
- and using WPT or Unicode imports to strengthen profiles and cases rather than to smuggle unspoken policy assumptions into one giant layout blob.

The archive should **not** drift back into a single-file story where the case, profile, backend, and runtime font reality are all implied instead of stated.
