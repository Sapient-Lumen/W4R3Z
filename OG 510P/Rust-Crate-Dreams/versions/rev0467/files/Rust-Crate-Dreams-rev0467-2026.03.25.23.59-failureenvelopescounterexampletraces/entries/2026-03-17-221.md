# 2026-03-17 (221) — crate lifecycle-surface productization pass

This pass did **not** add a new lane.
It sharpened **P-0520 Crate Lifecycle Surface Pack Kit** into a more implementation-ready `0.1` shape.

## Main judgment

The missing value is still **not** another runtime, another structured-concurrency experiment, or another graceful-shutdown helper.
The sharper missing layer is a **maintainer-facing lifecycle contract** that records:

- what starts background work,
- what *kind* of start boundary that is,
- what stop verbs really do,
- and what evidence exists that teardown completed.

## Why this lane looks sharper now

- Tokio and tokio-util now make the signal / wait / detach / abort substrate concrete enough that the missing value is increasingly the review artifact above it;
- `spawn_blocking` and `JoinHandle` docs make it explicit that visible stop verbs do not always mean work actually stopped;
- Tokio’s I/O docs make `write`, `write_all`, `flush`, and `shutdown` materially different lifecycle surfaces;
- and graceful-shutdown / structured-concurrency crates remain useful substrate without becoming a receiver-facing per-crate contract by themselves.

## What to keep separate

- Keep **P-0520** separate from runtime failure handoff (**P-0513**).
- Keep **P-0520** separate from observability contracts (**P-0518**).
- Keep **P-0520** separate from authority posture (**P-0519**).
- Keep **P-0520** separate from graceful-shutdown frameworks and structured-concurrency substrate.

## Preferred proving grounds

- client crates with lazy reconnect or subscription workers
- stream / protocol crates with `flush` / `shutdown` obligations
- watcher crates with drop-versus-detach ambiguity
- blocking bridge crates where async abort is not enough
- service crates using `CancellationToken` + `TaskTracker` to prove drain completion
