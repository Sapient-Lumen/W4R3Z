# Entry 186 — Cargo SBOM precursor workbench promoted into a fixture-first supply-chain lane

This pass did not add a new proposal.
It upgraded **P-0125 Cargo SBOM Precursor Workbench Kit** into a more implementation-shaped lane with schema files, scenario packs, and a sharper statement of what the crate should actually hand other people.

## Why this moved now

Several official signals now line up unusually well.

### 1. Cargo SBOM support is now an explicit 2026 stabilization target

Rust’s 2026 goals explicitly call out **stabilizing Cargo SBOM precursor support**.
That makes this a current ecosystem seam rather than a speculative “someday maybe” idea.

### 2. Cargo already has real precursor substrate

Cargo’s unstable docs already define:

- how to enable `sbom`,
- the `*.cargo-sbom.json` naming convention,
- which outputs get precursor sidecars,
- `CARGO_SBOM_PATH`,
- and a starter JSON schema including package IDs, dependencies, features, and rustc provenance.

That means the missing crate is not “teach Cargo what an SBOM is”.
It is the reviewable layer above the precursor output.

### 3. Artifact association is real, but not yet boring

Cargo external-tools JSON already exposes the `compiler-artifact` stream.
That means a worthy crate can freeze how precursor files were associated with promoted artifacts instead of asking every downstream tool to rediscover those rules independently.

### 4. The precursor contract is still moving in ways that justify a compatibility / exactness layer

Cargo’s changelog recently tightened SBOM behavior by clarifying that package ID specifications in SBOMs are fully qualified.
That is a good sign for ecosystem progress, but also a reminder that downstream tools need explicit evidence-source and transform-loss receipts.

## Current judgment

The worthy crate here is not:

- just another CycloneDX or SPDX emitter,
- just another policy gate,
- or just another sidecar index.

The worthy crate is the boring shared layer that can hand other people:

1. a **precursor capture lock**,
2. a **precursor ingest report**,
3. a **normalized build graph**,
4. a **transform / loss receipt**,
5. and a **diffable review bundle**.
