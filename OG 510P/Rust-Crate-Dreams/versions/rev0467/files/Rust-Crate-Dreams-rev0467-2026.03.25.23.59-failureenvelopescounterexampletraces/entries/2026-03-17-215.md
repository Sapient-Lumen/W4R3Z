# 2026-03-17 — Entry 215

Today’s pass did not promote a new crate lane.
It made **P-0486 Debuggability Support Contract Kit** more buildable.

## Main judgment

The archive’s debug-support lane is now strong enough that the next useful move was **productization discipline**, not another neighboring proposal.

The sharper `0.1` shape is now:

- one compact policy file,
- one capture pass for observed artifact/debug posture,
- one local check pass,
- one human-first doctor renderer,
- one short summary renderer,
- one release/support diff,
- one bundle/export path,
- and three artifacts that had previously been too implicit: **support-class policy**, **artifact handoff**, and **source-lookup impact**.

That matters because debuggability drift now hides in boring places: Cargo and `rustc` can use different `split-debuginfo` defaults, disabling debuginfo can now implicitly imply `strip = "debuginfo"`, a build can stay “the same” while symbol sidecars get lost during copying or packaging, and path-hygiene improvements can quietly weaken debugger/source lookup expectations.

## Why this was worth a pass

The web scan made a useful boundary clearer:

- Cargo already exposes the main profile knobs,
- `rustc` already explains the major sidecar layouts and the real consequences of `strip = debuginfo`,
- stable `#[debugger_visualizer]` already gives Rust a real visualizer surface,
- path remapping/trimming are already real support/privacy knobs,
- and Build Dir Layout v2 makes it even clearer that artifact location churn is not the same thing as support truth.

That means the missing value is increasingly not another debugger or another binary-format crate.
It is the joined, reviewable contract that tells another maintainer what this build honestly supports, where the important sidecars are, whether the handoff preserved them, how source lookup expectations changed, and what drifted across releases.

## Working rule after this pass

Do not invent another nearby crate until **P-0486** proves too cramped to hold:

- support-class meaning,
- sidecar-handoff truth,
- source-lookup impact,
- visualizer presence,
- release/support diffs,
- and compact downstream summaries.

If those still fit cleanly, the right move is to deepen **P-0486**, not split it prematurely.
