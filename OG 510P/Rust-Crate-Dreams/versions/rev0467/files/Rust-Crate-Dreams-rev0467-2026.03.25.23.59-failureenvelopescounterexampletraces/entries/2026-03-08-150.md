# Entry 150 — compile-time-deps parity also needs coverage truth and workspace-invocation receipts

This pass again did **not** add another top-level proposal.

Instead, it sharpened **P-0494 Cargo Compile-Time-Deps Workflow Kit** where the archive still had the most leverage left: the crate now has a clearer plan for **selection-coverage reports and workspace-invocation receipts** above tool-only or check-like runs.

## Main judgment

The important missing crate is not another editor integration.
It is a **receiver-facing tool-workflow bundle** that can tell another person:

- which package scope and target classes were actually covered,
- whether dev-dependency or proc-macro lanes were omitted by selection,
- whether linked-project invocation ran `per_workspace` or `once`,
- whether startup behavior widened diagnostics beyond configured package scope,
- and whether the result should stay conservative or require manual review.
