# Entry 127 — Native build stack sharpening, fixture stubs, and incubation order

This pass intentionally did **not** add another top-level proposal.

Instead, it treated the archive’s strongest current `build.rs` / native-build ideas as a **stack** that deserves sharper planning.

## Main judgment

The best next native-build-adjacent frontier to make more buildable is:

- **P-0046 buildscript-ux-kit**
- **P-0059 buildscript-testkit**
- **P-0058 native-deps-kit**

The main archive judgment is that Rust already has a lot of native-build substrate, but still often lacks a **boring artifact that tells another human what the build script tried, what native contract was promised, and what action is suggested**.

## Why this pass focused on native builds / build scripts

- Cargo’s official docs still describe conservative rerun behavior, hidden warning behavior, and persistent `OUT_DIR` state that surprise users and maintainers.
- Cargo’s FAQ still says after-the-fact rebuild debugging is not easy yet.
- Cargo 1.84 added `cargo::error`, but live issues show build-script presentation is still noisy in practice.
- `system-deps` and `vcpkg` show that the substrate for a stronger native-dependency story already exists.
- The Rust project’s sandboxed-build-scripts goal explicitly treats `-sys` and native probing as a first-class use case, which reinforces that this area is foundational rather than niche.

## Incubation order after this pass

1. **P-0046 first** — best immediate value to users, CI, and IDE/tooling surfaces

## Archive-level lesson

The archive is healthier when it distinguishes:

- build-script **report/policy UX**,
- hermetic build-script **test fixtures**,
- and declarative native dependency **contracts**.

Those are adjacent, but they are not the same crate.
