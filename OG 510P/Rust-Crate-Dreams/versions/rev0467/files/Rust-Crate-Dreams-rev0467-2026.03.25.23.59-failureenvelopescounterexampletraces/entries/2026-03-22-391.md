# Entry 391 — broad territory rerank added compile iteration feedback as a new top-lane candidate

This pass chose to do two things at once:

1. run a broad frontier refresh across a wide variety of Rust use cases,
2. add exactly one sharply-bounded new proposal where the gap still looked real.

The new lane is **P-0537 Compile Iteration Feedback Kit**.

## Why this lane earned a new proposal now

Fresh official and primary-source signals line up unusually well:

- the March 2026 Rust challenges write-up treats compile performance as the **universal productivity tax**;
- that same write-up explicitly calls out GUI teams living with 8–10 second feedback loops and points to hot reloading plus faster linking as high-leverage mitigations;
- the 2025 compiler-performance survey still reports that small-change rebuild workflows are painful, while upstream “relink don’t rebuild” work remains experimental;
- Rust 1.90’s switch to LLD by default on `x86_64-unknown-linux-gnu` proves that link latency is important enough to change upstream defaults;
- Dioxus now documents both RSX hot reload and a `--hotpatch` lane for Rust code; `subsecond` makes runtime hotpatching and ThinLinking concrete; and Wild continues to pursue fast iterative linking.

Together those signals say something the archive had not yet named sharply enough:

The missing value is no longer only “make builds faster.”
It is a crate that helps other people inspect **which edits are live-updateable, which are only faster-to-relink, what state continuity is being claimed, and what restart fallback remains honest**.

## Main judgment after the rerank

The broad map still says the archive’s strongest work is usually a **support contract above real substrate**.
But this pass found that the local iteration loop was under-covered relative to its importance.

That is why the new ranked frontier now starts with:

1. **P-0537 Compile Iteration Feedback Kit**
2. **P-0509 Crate Ecosystem Pathfinder & Decision-Pack Kit**
3. **P-0535 Dependency Lifecycle Transition Kit**
4. **P-0536 Crate Knowledge Pack Kit**

## Why this beat nearby alternatives

It beat “just deepen build performance again” because the sharper missing seam was not only timings or regressions.
It was the boundary between:

- watch-loop routing,
- link-speed improvements,
- UI-only hot reload,
- runtime hotpatch eligibility,
- state continuity,
- and restart fallback.

It also beat adding multiple new lanes because the archive already has enough proposal count that curation and separation are more valuable than proliferation.

## What should count as a worthy crate contribution after this pass

A worthy “faster local loop” crate should now answer all of these cleanly:

1. **What edit happened?**
2. **What reload or patch lane was actually used?**
3. **Was the route only faster linking, or true live-update capability?**
4. **What state continuity is honestly being claimed?**
5. **What deterministic restart fallback remains?**
6. **Did the resulting loop meet the intended latency budget?**
7. **What portable bundle does another engineer receive?**

If a candidate crate cannot answer those questions, the archive should usually treat it as iteration folklore rather than a serious ecosystem contribution.
