# Entry 192 — compile-time-deps lane promoted with root-lane truth and optional imported-session evidence

This pass did not add a new proposal.
It upgraded **P-0494 Cargo Compile-Time-Deps Workflow Kit** into a more implementation-shaped lane by freezing the next missing receiver-facing layer: **root-lane truth and evidence provenance** above tool-only or check-like workflows.

## Why this moved now

Several official Rust/Cargo signals line up unusually well.

### 1. `target-dir` isolation is no longer the whole root story

The March 13, 2026 build-dir-layout-v2 call-for-testing explicitly asks teams to run tests, release processes, and anything else that may touch `build-dir` / `target-dir` with the new layout enabled.
It also says Cargo 1.91 already lets users separate intermediate build artifacts (`build-dir`) from final artifacts (still in `target-dir`).

That means a worthy tool-workflow crate should stop treating rust-analyzer’s `targetDir` knob as the only root fact that matters.

### 2. Cargo now has a more plausible optional session-import seam

Cargo’s unstable docs say `[build.analysis] enabled = true` is safe to leave in config even on stable because stable only emits an unknown-config warning.
Those docs also expose persisted session IDs plus `cargo report sessions`, `cargo report timings`, and `cargo report rebuilds`.

That creates a new possibility for **optional supporting evidence** in this lane: conservative linking between a tool-facing run and Cargo’s persisted session/report substrate.

### 3. The correctness boundary is still intentionally stronger than the tool boundary

RFC 3477 still keeps `cargo build` as the stronger guarantee line.
That means imported session IDs or nicer root receipts should not quietly erase the core value of **P-0494**: telling other people what a tool-facing run actually did and when a fuller build is still required.

## Current judgment

The worthy crate here is not:

- another rust-analyzer wrapper framework,
- another build profiler,
- another live lock-contention daemon,
- or another build-dir migration adapter.

The worthy crate is the boring coordination layer that can hand other people:

1. one **tool-build receipt**,
2. one **parity verdict**,
3. one **root-lane receipt**,
4. one **evidence-source receipt**,
5. and one **optional imported-session link**.
