# 2026-03-01 (18): identity + integration glue + untrusted document safety

This entry focuses on three themes that repeatedly show up as “missing golden paths” in Rust:

1) **Identity protocols that require tricky XML/crypto correctness** (SAML).
2) **New integration protocols growing fast** (MCP) where the missing pieces are security, auth, and operational guardrails.
3) **Untrusted document parsing** (PDF) where performance projects exist, but security posture + fuzzing/conformance are not standardized.

## Signals & sources

### Email security libraries exist, but operational tooling is fragmented
- `mail-auth` provides DKIM/ARC/SPF/DMARC in Rust and aims for correctness across major RFCs. https://github.com/stalwartlabs/mail-auth
- TLS reporting (RFC8460) parsing exists as a small library/utility (`tlsrpt-rs`). https://github.com/kravietz/tlsrpt-rs
- There are tools that probe many email-related DNS records (`mhost`), suggesting demand for “doctor”-style UX. https://crates.io/crates/mhost
**Gap:** a cohesive *transport security* kit (MTA-STS / TLS-RPT / DANE) with fixtures, “doctor” UX, and integration helpers.

### SAML support exists, but “battle-tested defaults” are still rare
- `samael` exists, but notes its signing/verifying support depends on xmlsec bindings via a modified `rust-xmlsec`. https://crates.io/crates/samael
- `saml-rs` explicitly defaults to strict parsing and strict crypto policy (rejecting DTD/entity expansion, etc.) and targets IdP use cases. https://github.com/terminaloutcomes/saml-rs
**Gap:** a pragmatic “SAML stack kit” with secure XML signature primitives, strict parsing defaults, and a conformance fixture suite.

### MCP has official SDKs, so the missing layer is security/ops glue
- There is an official Rust SDK repo for MCP (“rmcp”). https://github.com/modelcontextprotocol/rust-sdk
- The MCP docs describe building servers and transports; the core protocol layer is present. https://modelcontextprotocol.io/docs/develop/build-server
**Gap:** a security + policy layer on top of SDKs (auth, permissioning, redaction, logging, allowlists) plus a test harness for prompt-injection-adjacent failures.

### PDF parsing and extraction in Rust is growing, but “safe-by-default” posture isn’t standardized
- `lopdf` is actively maintained and is a general PDF manipulation crate. https://crates.io/crates/lopdf
- Newer PDF parsing efforts and wrappers (e.g., `pdf-rs`, `pdfium`) show active ecosystem work. https://crates.io/crates/pdf-rs and https://crates.io/crates/pdfium
- The rust-fuzz “trophy-case” highlights how fuzzing uncovers common Rust bugs (panic/OOM/DoS) — useful for parser security planning. https://github.com/rust-fuzz/trophy-case
**Gap:** a shared “PDF safety kit” with resource caps, streaming parse patterns, fuzz harness scaffolding, and a public corpus policy.

## Lessons
- **If a domain has RFCs + security footguns, the epic contribution is often fixtures + conformance + explainability**, not a new implementation.
- **Adapters beat monoliths:** keep a stable core + thin adapters over existing crates/projects.
- **Make “safe mode” the default** (bounds, timeouts, strict parsing), and require explicit opt-outs.
