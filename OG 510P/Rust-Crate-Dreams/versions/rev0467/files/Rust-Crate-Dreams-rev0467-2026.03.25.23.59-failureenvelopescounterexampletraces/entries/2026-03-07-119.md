# Entry 119 — tool-only compile surfaces and artifact-dependency adoption

This pass stayed disciplined by promoting two seams that sit **above real Cargo substrate** but still do not have a boring maintainer workflow.

First, it separated **tool-only compile surfaces** from both build-performance complaints and lock contention. Cargo now documents a permanently unstable `--compile-time-deps` mode intended for tools like rust-analyzer, while the accepted `cargo check` language-policy RFC is explicit that Rust’s ordinary stability guarantee is tied to `cargo build`. But maintainers still cannot hand one another one compact artifact that says **what that tool-only workflow actually built, what it skipped, and when it should fall back to a real build**.

Second, it separated **artifact-dependency adoption** from both final-artifact handoff and external-toolchain orchestration. Cargo now has documented unstable artifact-dependency substrate plus RFCs for binary dependencies and renamed multi-target artifact dependencies. But maintainers still cannot hand one another one compact artifact that says **which artifact contract, which host/target mapping, which env vars, and what stable fallback**.

New proposals:

- P-0494 Cargo Compile-Time-Deps Workflow Kit
- P-0495 Cargo Artifact Dependency Adoption Kit

Why these rose:

- **P-0494** rose because Cargo has now made the tool-only compile seam explicit enough that the sharper gap is no longer “faster editor builds” in the abstract. The sharper gap is a **tool-build / parity / fallback receipt** above `--compile-time-deps`, rust-analyzer config, and the `cargo check` versus `cargo build` policy boundary.
- **P-0495** rose because Cargo’s artifact-dependency substrate has become real enough that the sharper gap is no longer “could Cargo ever consume another package’s binary.” The sharper gap is an **artifact contract / target matrix / env-var receipt / stable fallback** layer above bindeps RFCs and unstable implementation.

What changed in archive judgment:

- The archive now draws a cleaner line between **lock contention**, **rebuild causality**, **tool-only compile surfaces**, and **final build guarantees**.
- The archive now draws a cleaner line between **final artifact handoff**, **artifact sidecars**, **external toolchain handshakes**, and **artifact-dependency adoption**.

Archive hygiene added in this pass:

- Added an amnesia resistor warning future revisions not to confuse documented `--compile-time-deps` substrate with an already-boring maintainer workflow for IDEs and wrappers.
- Added an amnesia resistor warning future revisions not to confuse Cargo artifact-dependency RFCs and unstable docs with an already-boring answer to “what artifact contract are we actually depending on?”
