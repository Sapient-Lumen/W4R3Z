# Entry 147 — vendored source parity needs source identity and coverage truth

This pass again did **not** add another top-level proposal.

Instead, it sharpened **P-0496 Cargo Vendor & Source Parity Kit** where the archive still had the most leverage left: the crate now has a clearer plan for **source-parity locks and coverage reports** around vendored/source-replaced builds.

## Main judgment

The important missing crate is not a better downloader.
It is a **receiver-facing source identity and coverage bundle** that can tell another person:

- which logical source IDs were in play,
- which replacement chains collapsed onto which physical roots,
- which dependencies still sit outside the vendored/offline boundary,
- and where the answer is exact versus manual-review-required.

- one frozen `source-parity.lock`,
- one `source-coverage.report.json`,
