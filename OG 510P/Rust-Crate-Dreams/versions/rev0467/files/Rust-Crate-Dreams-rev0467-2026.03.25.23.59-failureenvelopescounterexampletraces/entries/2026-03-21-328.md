
# Entry 328 — Async Replay Debugger Kit deepened for schedule basis, time basis, coverage truth, effect boundaries, and replay fidelity

This pass deepened **P-0073 Async Replay Debugger Kit** instead of adding another deterministic harness, another generic trace spec, or another run-artifact lane.

## Why this lane earned another serious pass

The archive already knew that async Rust bugs were hard to reproduce.
What it lacked was a build-shaped answer for *which truths actually belong in one reviewable async replay contract*.

Current substrate is now strong enough to make that precise:

- the Rust project’s February 2026 debugging-survey post explicitly says first-class support for debugging `async` code is still missing;
- `console-subscriber` and `tokio-console` show that live async runtime telemetry is practical today, but only when the runtime emits the right `tracing` data, and today that means Tokio-specific instrumentation;
- Tokio docs now make cooperative scheduling and paused/auto-advanced test time concrete enough to classify honestly rather than calling them generic replay;
- `tracing` plus `Instrument` / `in_current_span()` make span/task lineage a concrete coverage question;
- `loom` and `shuttle` prove schedule control and deterministic reproduction matter, but not every schedule artifact is a whole-incident replay;
- `sturgeon` proves narrow stream-timing replay is valuable, which helps sharpen the line between slice replay and whole-application replay.

That means a worthy crate here should not simply say “supports async replay”.
It should say what schedule authority exists, which clock is being replayed, how complete the instrumentation really is, which external effects were captured, and what replay fidelity another team can actually trust.

## What moved this time

The main planning move was to stop treating “async replay” as one blob.

This pass elevated five review objects into first-class status for **P-0073**:

1. **schedule-basis truth** — exhaustive model, recorded schedule, seeded scheduler, live trace only, or manual-review-only route;
2. **time-basis truth** — wall clock, paused Tokio time, synthetic timeline playback, imported timestamps, or manual review;
3. **instrumentation-coverage truth** — runtime telemetry source, span propagation posture, task coverage, effect-hook coverage, and blind spots;
4. **effect-boundary truth** — which nondeterministic effect classes were captured, stubbed, seeded, or left live;
5. **replay-fidelity truth** — inspection only, timeline reconstruction, slice replay, deterministic local replay, minimized schedule repro, or manual review.

## Why this matters now

The evidence is sharp enough that the missing layer is no longer vague:

- the Rust project now names async debugging as an open frontier rather than a solved tooling problem;
- Tokio console provides real operational value, but its current documentation still centers live telemetry rather than a stable offline replay contract;
- Tokio paused time is powerful for tests while still being explicitly narrower than wall-clock replay;
- `tracing` makes explicit instrumentation possible, which in turn makes missing lineage exportable rather than invisible;
- `shuttle` and `loom` prove that scheduling truth deserves first-class representation;
- `sturgeon` proves narrow effect replay is useful enough that it should be imported instead of hand-waved.

That means a worthy crate should not let “console trace”, “saved seed”, or “stream cassette” quietly over-claim whole-incident replay.

## Main judgment after the pass

A worthy async replay crate should now provide more than a trace viewer, a paused test clock, or a saved seed.
It should also provide:

- one explicit **schedule-basis receipt**,
- one explicit **time-basis receipt**,
- one explicit **instrumentation-coverage report**,
- one explicit **effect-boundary receipt**,
- one explicit **replay-fidelity report**,
- and one conservative rule for when a useful async debugging artifact is still too partial, too runtime-specific, or too effect-incomplete to bluff full replay support.
