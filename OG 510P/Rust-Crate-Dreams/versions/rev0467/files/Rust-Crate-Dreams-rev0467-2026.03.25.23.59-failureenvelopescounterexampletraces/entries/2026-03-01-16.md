# 2026-03-01: durable workflows + passkeys integration + BLE conformance + HTTP cassette standards

This entry captures four “missing-crate” territories where Rust has *pieces* but lacks a widely-adopted, low-friction **golden path**.

## Signals & gaps

### Durable execution / workflow engines
- Rust has multiple durable execution / workflow engine efforts (e.g. `durable`, `duroxide`, “Flawless”), plus broader industry writeups emphasizing deterministic replay + event logs.
- What’s missing is a **library-first, app-embedded workflow kit** with strong local dev UX, persistence adapters, and test/replay tooling — not a full platform.

Sources:
- https://github.com/iopsystems/durable
- https://docs.rs/duroxide
- https://restate.dev/blog/building-a-modern-durable-execution-engine-from-first-principles/

### Passkeys / WebAuthn are mature enough… but integration UX is still hard
- There are solid protocol crates (`webauthn-rs`, `passkey`/passkey-rs) and storage-agnostic server components (`passkey-server`), yet many teams still hand-roll end-to-end flows.
- What’s missing is an **opinionated integration kit** (framework adapters + session/cookie handling + attestation policy + migration guides).

Sources:
- https://crates.io/crates/passkey
- https://crates.io/crates/webauthn-rs
- https://lib.rs/crates/passkey-server

### Cross-platform BLE exists, but “works everywhere” remains elusive
- Cross-platform host libraries exist (`btleplug`, `bluest`) and there’s recurring commentary about dead crates/platform quirks.
- What’s missing is a **capability model + conformance suite + profile helpers** so apps can target a predictable surface and learn *why* something fails on a platform.

Sources:
- https://github.com/deviceplug/btleplug
- https://github.com/alexmoon/bluest
- https://nonpolynomial.com/2023/10/30/how-to-beg-borrow-steal-your-way-to-a-cross-platform-bluetooth-le-library/

### HTTP record/replay testing is fragmented by client
- There are multiple VCR-like crates tied to specific clients (`rvcr` for reqwest, `surf-vcr`, `http-client-vcr`).
- What’s missing is a **standard cassette format + redaction + match policy** plus adapters across popular stacks (reqwest/hyper/tower/http-client) so tooling isn’t siloed.

Sources:
- https://crates.io/crates/rvcr
- https://docs.rs/surf-vcr
- https://crates.io/crates/http-client-vcr
