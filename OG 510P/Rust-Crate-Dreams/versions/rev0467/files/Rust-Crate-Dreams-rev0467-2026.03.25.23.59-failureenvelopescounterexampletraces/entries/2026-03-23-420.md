# Entry 420 — crate-knowledge deepened around build-surface receipts, docs-build recipes, and conditioned availability witnesses

This pass chose to **deepen P-0536 Crate Knowledge Pack Kit** again instead of opening another docs portal, rustdoc renderer, or “crate chat” lane.

The sharper question was:

> once a knowledge pack has item witnesses and citation locators, how does it also say **which build recipe made an item/example/docs surface visible in the first place** and **under what feature/target/docs-build conditions that visibility claim is actually valid**?

## Why this deepening pass earned a full revision

Fresh sources made the next missing layer concrete:

- the March 2026 challenges write-up still says ecosystem navigation is fragmented and tacit-knowledge-heavy across domains;
- the 2025 State of Rust survey still says online documentation is the preferred canonical reference;
- docs.rs build docs say all hosted docs are built in a sandbox on nightly, that `cfg(docsrs)` only applies to the final rustdoc invocation, and that non-`x86_64-unknown-linux-gnu` targets are cross-compiled;
- docs.rs metadata docs show that features, `all-features`, `no-default-features`, `default-target`, `targets`, and extra rustdoc/rustc args all materially shape the hosted docs surface;
- docs.rs rustdoc JSON docs say the downloaded JSON may come from an older rustdoc and that consumers must check `format_version`;
- Cargo unstable docs show `doc-scrape-examples` remains recipe-bound and target-level, and that example scraping can be skipped when dev-dependency constraints are not met;
- `cargo-public-api` and `cargo-semver-checks` prove there is real value in rustdoc-JSON-driven API tooling, but both still operate on selected feature/target/toolchain conditions rather than exporting a receiver-facing bundle of conditioned availability truth.

That means the next worthy move for **P-0536** is not merely stronger item identity.
It is to make **build surface** and **conditioned availability** first-class review artifacts.

## Main judgment after this pass

The top frontier still begins:

1. **P-0537 Compile Iteration Feedback Kit**
2. **P-0509 Crate Ecosystem Pathfinder & Decision-Pack Kit**
3. **P-0535 Dependency Lifecycle Transition Kit**
4. **P-0536 Crate Knowledge Pack Kit**
5. **P-0538 Concurrency Contract Kit**

But **P-0536** is stronger now because the archive no longer stops at:

- material-basis receipts,
- export-policy receipts,
- excerpt-lineage reports,
- query-support matrices,
- citation locators,
- and item-witness / identity-fidelity reports.

It now has a clearer product shape for:

- **build-surface receipts**,
- **conditioned-availability reports**,
- **docsrs-cfg-scope honesty**,
- **feature/target/docs-build recipe witnesses**,
- and portable bundle inventory that keeps item identity separate from item availability.

## What should count as a worthy crate contribution in this lane now

A worthy crate-knowledge crate should provide other people:

1. **one build-surface receipt** that says which toolchain, features, cfgs, targets, and docs-hosting recipe produced a given visible surface;
2. **one conditioned-availability report** that says whether an item/example/docs claim is present, absent, target-bound, recipe-bound, or manual-review-only;
3. **one explicit separation between item identity and item availability** so “same item witness” is not over-read as “same visible support surface”;
4. **one docsrs-cfg-scope warning** so maintainers do not mistake `cfg(docsrs)` for a workspace-wide or dependency-wide visibility fact;
5. **one machine-surface recipe answer** so rustdoc JSON consumers know which format/toolchain window they are standing on;
6. **one portable bundle** that keeps build surface, conditioned availability, item witness, citation locator, and export-policy truth in distinct review lanes.

That is closer to an ecosystem-worthy crate than another crate-doc chatbot, renderer, or raw rustdoc-JSON wrapper.
