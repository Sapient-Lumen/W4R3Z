# Entry 106 — Cargo why-layers: resolver explanations and rebuild receipts

This pass stayed on the archive’s strongest current frontier: **Cargo-adjacent crates that explain what happened instead of merely exposing more raw output**.

New proposals:

- P-0468 Cargo Resolver Explanation Kit
- P-0469 Cargo Rebuild Explanation Kit

Why these rose:

- **P-0468** rose because Cargo now has real resolver substrate (`resolver` docs, `features` docs, `cargo tree`, and the plumbing-goal split between dependency lock and feature resolution), yet ordinary teams still do not have a **cause-chain artifact** saying why a feature is active, why a version was chosen, or why one package version built twice.
- **P-0469** rose because compile/rebuild pain is still a major Rust productivity complaint, while Cargo timing reports remain human-oriented and reuse failures still surface through folklore-heavy fingerprint/debug workflows rather than a **compact per-run rebuild receipt**.

What changed in archive judgment:

- The archive now treats **explainability above Cargo substrate** as a sharper missing seam than just adding more metadata snapshots or more performance dashboards.
- A worthy crate contribution here may be a **why-bundle**: a reviewable explanation of resolver choices, duplicate builds, fingerprint deltas, or cache-conflict facts.
- This pass also tightened the distinction between **historical analytics** and **shareable per-event explanation artifacts**.

Archive hygiene added in this pass:

- Added an amnesia resistor warning future revisions not to confuse `cargo tree`, timing HTML, debug logs, or new plumbing commands with a boring explanation workflow.
- Added known-existing notes for Cargo resolver docs, feature-unification substrate, build-dir/relink directions, and current timing/fingerprint surfaces so later passes do not rediscover the same false gap.
