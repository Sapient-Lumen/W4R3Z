# Entry 432 — concurrency-contract deepened around observer cursors, progress isolation, and slow-observer coupling honesty

This pass chose to **deepen P-0538 Concurrency Contract Kit** again instead of inventing another channel wrapper, actor helper, or “better subscriber API” crate.

The sharper question was:

> once a concurrency surface can already describe memory, pressure, audience, claim, acceptance, evidence, order, gaps, closure, and late-join posture, how does it also say **whether each observer advances its own cursor** and **whether one slow observer hurts only itself or changes everyone else’s story**?

## Why this deepening pass earned a full revision

Fresh primary sources made the next missing layer concrete:

- the March 2026 Rust challenges write-up still says async complexity remains part of the current Rust pain picture;
- Tokio `watch` docs explicitly say each `Receiver` independently tracks the last value seen by its caller;
- Tokio `broadcast` docs explicitly say a lagging receiver gets `RecvError::Lagged` and that receiver’s cursor is rebased to the oldest retained value;
- Tokio `broadcast` docs also make clear that lag is handled per receiver rather than by pretending all receivers remain equally caught up;
- Flume docs explicitly say cloning the receiver does **not** turn the channel into broadcast and that each message is still received by only a single receiver;
- `async-channel` docs explicitly say each message can be received by only one of all existing consumers;
- Tokio `mpsc` docs still define the surface as supporting only one `Receiver`;
- Tokio `Notify` docs explicitly say it does not carry any data, which makes cursor-style observer progress inapplicable there.

That means the next worthy move for **P-0538** is not just more “channel semantics.”
It is to make **observer cursor posture** and **observer progress isolation** first-class review artifacts.

## Main judgment after this pass

The top frontier still begins:

1. **P-0537 Compile Iteration Feedback Kit**
2. **P-0509 Crate Ecosystem Pathfinder & Decision-Pack Kit**
3. **P-0535 Dependency Lifecycle Transition Kit**
4. **P-0536 Crate Knowledge Pack Kit**
5. **P-0538 Concurrency Contract Kit**

But **P-0538** is stronger now because the archive no longer stops at:

- reentrancy scope,
- progress/fairness class,
- wait-cancellation behavior,
- execution-context legality,
- recovery posture,
- mobility/affinity,
- driver-liveness,
- delivery memory,
- backlog pressure / lag / loss posture,
- delivery audience,
- consumption-claim semantics,
- delivery acceptance,
- observation-evidence ceiling,
- delivery order,
- gap visibility,
- closure finality,
- post-close availability,
- late-joiner admission,
- join-start baseline.

It now has a clearer product shape for:

- **observer-cursor reports**,
- **observer-progress-isolation reports**,
- **independent seen-cursor versus shared work-pool honesty**,
- **per-receiver retained-history cursor versus single shared claim-pool honesty**,
- **self-lag rebase versus globally shared progress folklore**,
- **single-consumer fixed-cursor versus multi-observer applicability honesty**,
- and portable bundle inventory that keeps cursor/progress-isolation truth separate from audience, claim, order, gaps, join posture, memory, or closure semantics.

## What should count as a worthy crate contribution in this lane now

A worthy concurrency-contract crate should provide other people:

1. **one observer-cursor report** that says whether observers have independent seen-state cursors, per-receiver retained-history cursors, one shared competitive claim pool, one fixed single-consumer cursor, or no data cursor at all;
2. **one observer-progress-isolation report** that says whether a slow observer hurts only itself, self-lags with cursor rebase, competes for shared work, or makes multi-observer language inapplicable;
3. **one explicit separation between fanout / claim semantics and cursor ownership**;
4. **one explicit separation between “messages are single-delivery” and “receivers still have independent cursors”**;
5. **one portable bundle** that keeps observer cursor and progress-isolation semantics separate from memory, pressure, audience, claim, acceptance/evidence, order/gaps, closure/tail, fairness, cancellation, recovery, context, locality, and liveness.

That is closer to an ecosystem-worthy crate than another channel-comparison article because it tells adopters whether two observers advance one shared work frontier, keep separate observation cursors, or do not even live in the same observer topology.
