# Entry 174 — MSRV lanes sharpened + workspace boundary doctor added

This pass focused on two cross-cutting Cargo pain surfaces that are easy to underestimate because they are spread across docs, issue threads, and CI folklore instead of one obvious missing library:

- **P-0036 MSRV Workspace Lab**
- **P-0506 Cargo Workspace Boundary Doctor Kit**

## Why these moved now

The Rust safety-critical post made the MSRV lane look more strategic than before.
It does not treat dependency drift and compiler-floor coordination as niche complaints; it names them as real obstacles for serious adopters.
That made the old “binary-search a minimum compiler” framing feel too small.
The proposal now needs to own **policy receipts, resolver-lane diffs, blame reports, and adoption planning** for mixed workspaces.

At the same time, Cargo’s 1.94 notes made workspace/config discovery explicit enough to stop hand-waving.
The repo already had several Cargo diagnosis crates, but none owned the boundary problem cleanly:
which parent files were probed, which workspace root Cargo appeared to choose, whether cwd or `--manifest-path` caused the split, and whether the right answer is a local workaround or an upstream feature.
That gap looked worthy enough to justify a new proposal.

## Current judgment

The archive should keep rewarding crates that hand other people something *reviewable*:

- a support promise receipt,
- a blame report,
- a parent-probe trace,
- a membership diagnosis,
- or a short adoption plan.

Those are the places where Rust’s missing-crate frontier still feels more valuable than one more clever substrate library.
