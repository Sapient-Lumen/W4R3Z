# Entry 262 — crate performance support sharpened around execution intent, workload lineage, and profile identity

This pass did **not** add another benchmark runner, another profiler, another dashboard, or another CI perf service.
It sharpened **P-0517 Crate Performance Envelope Pack Kit** into a more implementation-ready support crate.

## Why this moved now

Rust’s performance story is no longer missing substrate.
That changes the shape of the missing value.

- The December 2025 Rust vision-doc work explicitly says crates need more **supportive interfaces**.
- The 2025 State of Rust survey still says online docs and code remain the main learning surfaces, and it still names resource usage as a recurring productivity problem.
- Cargo still makes `cargo bench` real, but it also makes profile identity matter: the default `bench` profile is not the whole story, and custom profiles are real.
- Criterion is still a strong stable-compatible wall-time framework, but its job is measurement, not receiver-facing contract authoring.
- Iai-Callgrind is still unusually useful for CI-friendly instruction-count evidence, but that does not automatically tell a downstream user which metric rules a release claim.
- Divan now makes throughput counters and allocation measurement easy to reach, but allocation profiling can itself distort timing and therefore needs explicit metric-authority truth.
- CodSpeed compatibility layers keep existing suites runnable, but they still distinguish environments where the suite ran from environments where real measurement happened.
- `cargo-nextest` now makes an especially important boundary explicit: Criterion benchmarks in **test mode** are useful to verify compilation and panic freedom, but they are not the same thing as trustworthy performance measurement.

That combination means the missing crate is no longer “Rust needs perf tools”.
The sharper missing crate is a **crate-authored performance contract** above benchmark frameworks, profiles, adapters, and CI services.

## Main planning move

This pass promoted five review objects to first-class status for **P-0517**:

1. **metric authority** — which number actually rules the scenario,
2. **execution intent** — whether a run was authoritative measurement, supporting measurement, smoke-only sanity, replay/imported evidence, or manual-review territory,
3. **workload lineage** — where the input shape came from and whether it was synthetic, fixture-backed, captured, seeded, or imported,
4. **profile identity** — which Cargo profile / harness / optimizer story the claim actually rode on,
5. **noise/trust class** — what kind of stability another team should assume from the evidence.

That move matters because the archive had already named the lane, but it had not yet made the boundary between **measurement** and **verification that a benchmark still runs** concrete enough.
This pass fixes that.

## Main judgment after the pass

A worthy performance-support crate contribution for Rust should now provide **more than benchmark outputs**.
It should provide:

- explicit **metric-authority truth**,
- explicit **execution-intent truth**,
- explicit **workload-lineage truth**,
- explicit **profile-identity / environment-fidelity truth**,
- explicit **noise-class truth**,
- and one compact **performance-envelope diff** another maintainer can inspect without reconstructing the story from runner flags, CI services, and README charts.

That is more believable and more ecosystem-multiplying than either:

- “just use Criterion”,
- “just use CodSpeed”,
- “just run `cargo bench`”,
- or “just check that benches still pass in CI” with no receiver-facing contract attached.
