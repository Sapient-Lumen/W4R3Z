# Entry 334 — Crash Artifact & Symbolication Workbench Kit deepened for capture truth, module identity, symbol routes, analysis coverage, replayability, and share-safe bundles

This pass deepened **P-0101 Crash Artifact & Symbolication Workbench Kit** instead of adding another crash collector, another hosted dashboard, or another debugger UI.

## Why this lane earned another serious pass

The archive already had better answers for:

- async incident replay,
- debugger support,
- evidence-bundle substrate,
- and desktop crash-pipeline handoff.

What it still lacked was a build-shaped answer for the postmortem crash question:

> “If you hand me this dump and this report, can I tell how it was captured, whether the symbols really matched, whether the report is replayable, and whether the bundle is safe to share?”

Current substrate is now strong enough to make that precise:

- `rust-minidump` is a mature minidump parsing/analysis stack with `minidump-processor` and `minidump-stackwalk` at the rich-analysis layer;
- `minidump-stackwalk` explicitly documents Breakpad symbol routes and Tecken-style symbol-server lookup, and recent releases add soft errors, direct symbol-file inputs, native-debuginfo support, and symbol stats;
- `wholesym` makes native symbol lookup across Windows, macOS, and Linux concrete;
- `symbolic` still provides broad multi-format symbolication substrate;
- `minidumper` and `minidump-writer` make out-of-process monitor capture concrete;
- Mozilla’s deployment and fuzzing notes make it clear that artifact discipline and reliability hardening matter as much as parsing.

That means a worthy crate here should not merely say “supports crash reports.”
It should say **how the crash was captured, which module identities were authoritative, which symbol routes were allowed, how complete/replayable the analysis really was, and what another team can safely receive**.

## What moved this time

The main planning move was to stop treating “symbolicated crash report” as one blob.

This pass elevated six review objects into first-class status for **P-0101**:

1. **capture basis** — in-process, external monitor, imported artifact, synthetic/test, or manual review;
2. **module identity** — module base/size/name plus debug-id, code-id, build-id, and confidence basis;
3. **symbol route** — bundled, local, native, server-backed, timeout, and offline/online lookup order;
4. **analysis coverage** — loaded, missing, corrupt, inline, unresolved, and soft-error posture;
5. **report determinism** — whether another team can replay the report from the bundle alone;
6. **share-safety** — memory, paths, usernames, symbol payloads, source locations, and redaction posture.

## Why this matters now

The ecosystem evidence is now sharp enough that the missing layer is no longer vague:

- capture-side crates do not answer symbol-route or share-safety truth;
- symbolication crates do not automatically answer replayability or share-safe bundle posture;
- a pretty stack trace can still hide missing symbols, code-id fallback, or live-network dependence;
- and a zipped dump + report can still be unusable or unsafe for another reviewer.

That means a worthy crate should not let one green “symbolicated” bit silently over-claim identity confidence, replayability, or share safety.

## Main judgment after the pass

A worthy crash-related contribution for Rust should now provide more than dump writing, stackwalking, or symbol fetching.
It should also provide:

- one explicit **capture-basis receipt**,
- one explicit **module-identity receipt**,
- one explicit **symbol-route receipt**,
- one explicit **analysis-coverage report**,
- one explicit **report-determinism receipt**,
- one explicit **share-safety receipt**,
- plus the already-needed summary/diff/support bundle surface.
