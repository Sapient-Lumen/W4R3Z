# Entry 452 — widen the territory scan, keep the control-plane frontier in front, and raise the bar for what counts as an epic missing crate

This pass again chose **deepen over append**.

But it also did something the archive needed:
- re-scan a very wide field of Rust use cases,
- compare missing-crate dreams against what each sector already has,
- tighten the definition of a **worthy** crate contribution,
- and add stronger archive memory so future passes do not keep re-inventing the same weak mega-lanes.

## Main judgment

The latest ecosystem scan does **not** point to one giant missing “web stack”, “GUI stack”, “ML stack”, or “enterprise platform crate”.
Those areas still contain pain and fragmentation, but the sharper missing contributions are usually either:

1. **horizontal control-plane crates** that help other people choose, qualify, ship, debug, and sustain crates responsibly; or
2. **narrow sector workbenches / evidence kits** that solve one credible seam with portable artifacts instead of promising to solve a whole domain.

That keeps the archive’s frontier where it has increasingly converged:

1. **P-0509** should stay the front door for decision-grade crate choice.
2. **P-0536** should sit beside it as the replayable knowledge substrate.
3. **P-0486 / P-0538 / P-0472 / P-0535 / P-0484 / P-0537 / P-0431** make up the strongest next control-plane ring.

So the broad territory pass ended up **confirming** the archive’s practical center more than overturning it.

## Why the broad scan still strengthens the control-plane frontier

The current official and community picture points in a consistent direction:
- Rust still reports crate choice, uneven domain maturity, debugging, and resource usage as recurring pain;
- 2026 project goals still emphasize async, supply chain/SBOM, Wasm/components, safety-critical work, and “building blocks” rather than one monolithic app framework;
- Cargo and docs.rs continue to expose more machine-consumable surfaces, which makes support/evidence/control-plane crates more realistic to build;
- several application sectors already have energetic community hubs (`Are We * Yet?`, GeoRust, embedded orgs, local-first projects), which means a worthy new crate in those sectors usually has to be **sharper** than “one more umbrella”.

The broad scan therefore raises the bar:

> a crate should count as epic only if it exports a durable artifact seam or a durable decision seam that many teams can reuse, not merely a fresh bundle of abstractions.

## Territory findings

### Strong frontier: horizontal/control-plane crates

The broadest need is still for crates that help teams answer questions like:
- what should we choose,
- what did we choose on,
- what docs/examples/API surfaces did we rely on,
- what debug/runtime/build/support posture is actually promised,
- what changed,
- and how do we carry decisions forward without folklore.

That is why **P-0509 + P-0536** now look even more like the archive’s clearest “epic contribution” pair.

### Worthy but sector-shaped opportunities

The territory scan still found good sector opportunities, but mostly in narrower shapes:
- embedded / edge qualification kits,
- safety-critical evidence and support kits,
- Wasm component/plugin packaging and policy kits,
- C++ / mixed-language integration and handoff kits,
- local-first / collaboration interop/evidence kits,
- industrial / robotics / geospatial workbenches,
- and offline / mirror / source-parity kits.

These should usually be promoted only when they export **portable evidence artifacts**, **transition artifacts**, or **interop artifacts**.

### Eliminate or defer for now

The broad scan argues against re-inflating these as top-priority archive lanes:
- a generic “one true web stack chooser”;
- a monolithic GUI salvation crate;
- an all-in-one ML supercrate;
- a generic local-first umbrella;
- a generic “enterprise Rust platform” meta-crate;
- a generic science/data mega-toolkit.

Those can still hide good sub-problems, but the worthy contribution is usually a **specific seam kit**, not the umbrella itself.

## What a worthy crate should provide other people

A proposed epic crate should be able to say, concretely:
1. **who receives value**;
2. **what recurring pain it removes**;
3. **which artifact it emits** or **which decision seam it stabilizes**;
4. **what competing crates or workflows it interoperates with**;
5. **what it refuses to do**;
6. **how another team adopts it incrementally**;
7. **what evidence or fixtures make its claims replayable**;
8. **what governance and change promises it can honestly keep**.

If a crate cannot answer those, it may still be a neat idea, but it is not yet archive-frontier material.

## Questions this pass wants future passes to ask first

Before opening another top-level lane, ask:
1. is the missing thing really a **durable artifact seam**?
2. is it really a **decision seam** that many teams repeat?
3. does the sector already have strong umbrella hubs and only lack one sharper interop/evidence kit?
4. can the first release be narrow, honest, and useful?
5. would another team understand what the crate provides without reading the archive?

If not, do not promote it yet.
