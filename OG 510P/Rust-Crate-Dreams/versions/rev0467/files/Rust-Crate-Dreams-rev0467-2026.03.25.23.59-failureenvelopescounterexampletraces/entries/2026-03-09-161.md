# Entry 161 — reproducibility evidence layering and fixture-first upgrade

This pass again chose **not** to add another narrow proposal.

The better move was to strengthen one of the archive’s broad top-tier bets that was still too essay-like relative to the repo’s newer fixture-first proposals.

## Main judgment

The repo needed a better answer to this question:

> when people say “Rust needs better reproducible-build tooling”, what exact crate layer is still missing?

The sharper answer is now:

1. a **build recipe**,
2. a **rebuild verdict**,
3. a **diff triage report**,
4. and one portable **repro build bundle** that carries those together.

That is stronger than “run diffoscope” and more local/operational than “wait for a hosted rebuild service”.

## Why these changes were the right ones

### 1. P-0242 needed to stop looking like “a Rust wrapper for diffoscope”

The external substrate is now good enough that the missing value is not just deep diffing.
The updated proposal now says more clearly that the crate should own:

- recipe capture,
- honest verdict vocabulary,
- small diff-triage summaries,
- and `*.reprobuildbundle.zip` artifacts.

That makes it much more plausible as a boring ecosystem multiplier.

### 2. The repo needed a better reproducibility layering note

The new meta note records one reusable rule:

- build recipe,
- rebuild verdict,
- diff triage,
- optional attestation/publication.

That should reduce future drift toward fuzzy “reproducibility result” language.

### 3. P-0242 needed fixture-first planning

The proposal now has small schema stubs and scenarios.
That matters because the archive is much more useful when a proposal can already answer:

- what artifact it hands another person,
- what states it classifies explicitly,
- and what kinds of drift it intends to treat as exact match, semantic match, mismatch, or manual review.

### 4. The repo itself benefited from one concrete hygiene cleanup

While touching this frontier, the pass also removed one concrete instance of ChatGPT UI citation markup that had leaked into archive content.
That keeps the repo closer to its own durability rules.

## New planning stance

For the next few passes, the archive should prefer:

- strengthening **P-0242** as a small recipe/verdict/triage stack,
- reusing **P-0256** for deterministic bundle substrate,
- and connecting reproducibility evidence upward to attestation/review lanes only when the boundary stays explicit.

It should **not** drift into:

- another generic signing/provenance crate,
- a diffoscope clone,
- or a fake all-in-one “reproducibility platform” that cannot distinguish recipe, verdict, and publication.
