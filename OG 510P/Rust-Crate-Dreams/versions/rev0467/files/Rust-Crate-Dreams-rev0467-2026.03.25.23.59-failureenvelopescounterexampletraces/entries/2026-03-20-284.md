# Entry 284 — crate upgrade support sharpened around config-basis truth and hidden Cargo override disclosure

This pass came from noticing that the upgrade pack had become exact about source lineage, capture context, lane selection, session honesty, replay bridges, export posture, public traceability, durable cues, freshness, and review provenance while still leaving one ordinary bluff available:

> a lane could still sound like ordinary reviewed Cargo behavior even when hidden config layers or override surfaces materially shaped what was resolved or built.

## What moved this time

One donor pattern kept surviving scrutiny:

- **The Election Stack + SlopOS** kept treating ambient hidden context as its own seam rather than burying it inside ordinary request or execution metadata.

## Main planning move

The previous passes already established:

- exact source/head/import truth,
- exact capture/scope/session/replay truth,
- and exact readiness/export/public-surface/traceability truth.

This pass adds one sharper review object above them:

1. **config-basis truth** — the pack can now say which Cargo config layers or override surfaces materially influenced the lane, whether they were checked into the repo, injected by CI, local to one user, or only present on an ephemeral command line.

## Why this matters

Without **config-basis truth**, the lane still permits an ordinary lie:

- a capture can honestly preserve package/feature/target scope,
- a replay bridge can honestly say how to get back to evidence,
- yet the bundle can still omit whether `[patch]`, source replacement, `CARGO_HOME` config, `--config`, or environment-variable overrides made that witness family non-default, nonportable, or less upstream-representative than it sounds.

That is not cosmetic.
It is the difference between “the command ran” and “the baseline this command represented is reviewably explicit.”

## Main judgment after the pass

A worthy upgrade-support crate should now provide more than exact scope, exact capture truth, and exact replay truth.
It should also provide:

- one compact **config-basis receipt** for which Cargo config layers or override surfaces materially shaped the lane,
- one explicit distinction between **repo-checked-in baseline**, **CI-injected baseline**, **user-local baseline**, and **ephemeral override**,
- and one consistency failure when a lane advertises default-like upgrade truth while omitting a hidden config or override basis.

That keeps the lane from quietly turning Cargo configuration hierarchy into another polished but ungrounded vibe.
