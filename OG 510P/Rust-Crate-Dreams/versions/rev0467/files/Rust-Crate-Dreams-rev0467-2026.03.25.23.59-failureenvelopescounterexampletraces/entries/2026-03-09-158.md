# Entry 158 — bundle substrate push, with deeper planning for evidence and verification

This pass again chose **not** to add another narrow proposal.

The higher-value move was to strengthen the archive’s shared substrate story.

## Main judgment

The repository now has enough `*.Xbundle.zip` proposals that the real risk is no longer “too few ideas”.
It is **bundle fragmentation**.

So this pass pushed harder on the idea that some of the most worthy Rust crates are not domain crates at all, but **coordination-substrate crates** that many other crates can reuse.

## What changed in the archive

Added:

- `meta/bundle-substrate-2026-03-09.md`

Updated:

- `proposals/evidence-bundle-core-kit.md`

## Why these changes were the right ones

### 1. P-0256 was more important than its old writeup made it look

The archive has accumulated many bundle-first ideas.
That means **P-0256 Evidence Bundle Core Kit** is not just another proposal.
It is increasingly a likely **substrate crate** for a whole family of later crates.

The updated proposal now has a much sharper plan around:

- deterministic packing,
- raw artifacts versus normalized projections,
- redaction receipts,
- DSSE/COSE-aware signing lanes,
- semantic diffing,
- and profile layering (`evidencekit`, `conformbundle`, `verifybundle`, `assurancepack`).

### 2. P-0485 needed to become more stack-aware

The verification-campaign idea was already strong, but it benefited from becoming more explicit about:

- obligation inventories,
- tool-semantic lanes,
- trust ledgers,
- drift reports,
- and `verifybundle` as a higher-layer profile instead of another private bundle grammar.

That makes it look more like a real ecosystem multiplier and less like a generic dashboard idea.

### 3. The repo itself needed a bundle-layer memory aid

The new meta note records a clean four-layer stack:

1. container substrate,
2. domain profile,
3. runner/suite layer,
4. review/assurance layer.

That should make future passes less likely to blur:

- P-0256,
- P-0264,
- P-0485,
- and P-0503.

### 4. The archive needed one more explicit hygiene rule

`meta/llm-hygiene.md` now says the quiet part out loud:

- do **not** paste ChatGPT UI citation markup into repo markdown,
- keep repo citations as raw URLs or ordinary markdown links,
- and treat tool/UI citation syntax as an interface artifact, not archive content.

## New planning stance

For the next few passes, the archive should prefer:

- strengthening **P-0256** as a bundle substrate,
- strengthening **P-0485** and **P-0503** as higher-layer evidence consumers,
- and only adding more bundle-first proposals when they clearly state which layer they own.

It should **not** drift into:

- every proposal inventing its own zip grammar,
- another evidence-ish crate that silently duplicates P-0256,
- or a review/assurance proposal that forgets it should import lower-layer artifacts rather than replace them.
