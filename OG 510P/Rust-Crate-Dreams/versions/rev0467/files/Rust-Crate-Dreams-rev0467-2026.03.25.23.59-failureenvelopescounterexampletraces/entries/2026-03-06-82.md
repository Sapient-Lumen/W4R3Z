# Entry 82 — frontier pass: AI model portability, IoT device-management profiles, hospital-message replay, trade-document releases, and compliance-package linkage

Added five proposals after a fresh pass focused on ecosystems where the standards surface is active or official, Rust now has at least some real substrate, and the real missing value still looks like the **boring middle layer**: lockfiles, semantic diffs, replay, validator normalization, and portable evidence bundles.

New proposals:

- P-0362 ONNX + ONNX Runtime + Backend Test Conformance & Replay Kit
- P-0363 OMA LwM2M 1.2 + OMNA Object Registry Conformance & Evidence Kit
- P-0364 HL7 v2.x + MLLP + Message Profile Conformance & Replay Kit
- P-0365 UN/EDIFACT Syntax + Directory Interop & Evidence Kit
- P-0366 OSCAL 1.1.x Component + SSP + Assessment Workbench Kit

Pass notes:

- **ONNX** rose because Rust already has parser/runtime substrate, while the missing crate is still a **model/opset/backend replay workbench** rather than another inference engine.
- **LwM2M** rose because the real pain sits at the **object-version / bootstrap / registration** seam, and Rust still lacks a boring default artifact for that failure mode.
- **HL7 v2 + MLLP** made the cut because hospital integrations still fail at the **profile ↔ ACK ↔ framing** boundary, while Rust now has enough parser/transport substrate to support an evidence-first workbench.
- **UN/EDIFACT** was promoted because release drift and partner overlays remain the actual B2B integration problem, not raw segment tokenization alone.
- **OSCAL** rose because Rust finally has meaningful model-building substrate, but still lacks a neutral artifact for **cross-document validation, linkage diffs, and audit-ready replay**.
