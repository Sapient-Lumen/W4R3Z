# Entry 312 — cargo-build-insights deepened for comparison-window truth, series splits, and exportable historical bundles

This pass deepened **P-0035 cargo-build-insights** rather than adding another adjacent Cargo performance lane.

## Why this lane earned another serious pass

The archive already had stronger answers for:

- one-run rebuild mysteries,
- resolver/feature cause chains,
- tool-workflow parity,
- and live lock/contention stories.

What still needed a more disciplined answer was the longitudinal question:

> “When did this start regressing, compared to which baseline, and are these runs even honestly comparable?”

Current upstream Cargo work now makes that question more actionable than it used to be.

## What moved this time

The key planning move was to stop treating “history across many runs” as merely “more rebuild explanation.”

This pass elevated three review objects more explicitly:

1. **comparison-window truth** — why this baseline/head or rolling window was chosen, and for which audience;
2. **series-split truth** — whether toolchain/profile/workspace changes require lane splits before any slowdown claim;
3. **exportable historical bundle truth** — what another reviewer can inspect without scraping unstable Cargo output directly.

## Main judgment after the pass

A worthy Cargo historical-build crate should not just import sessions and draw trend lines.
It should provide:

- one explicit **comparison-window receipt**,
- one honest **series-compatibility report**,
- one stable **session/summary schema**,
- and one exportable **regression explanation bundle** with exactness and provenance.
