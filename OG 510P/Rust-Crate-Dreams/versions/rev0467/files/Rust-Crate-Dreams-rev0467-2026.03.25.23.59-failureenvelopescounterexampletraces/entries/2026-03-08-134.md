# Entry 134 — Cargo lock contention witness implementation refresh

This pass again did **not** add another top-level proposal.

Instead, it upgraded **P-0490 Cargo Lock Contention Witness Kit** from a good abstract idea into a more implementation-ready crate plan.

## Main judgment

Cargo/rust-analyzer lock contention is now a cleaner frontier than it was when this proposal first landed.

The current upstream story already has:

- an explicit rust-analyzer FAQ warning that rust-analyzer and manual Cargo commands can block one another,
- a documented `rust-analyzer.cargo.targetDir` mitigation,
- official Cargo build-dir-layout work that names reduced lock contention as a goal,
- unstable `build-dir-new-layout` docs that repeat the locking/caching motivation,
- and Cargo cache-lock internals proving package/index cache coordination is real substrate.

So the missing value is not “show that Cargo has locks.”
It is the **receiver-facing witness bundle** above those surfaces.

## New planning stance

**P-0490** should now be read as a crate that hands other people:

- one cache-root manifest,
- one lock-wait receipt,
- one conservative collision diagnosis,
- one mitigation plan,
- optionally one process-role snapshot,
- and one diff for comparing witness bundles.

That is a much sharper contract than “Cargo IDE contention tooling.”

## Archive-level lesson

When upstream docs become clearer, a mature repo often benefits more from **shrinking the artifact contract** than from adding more idea count.
A worthy crate can get stronger by becoming smaller, more honest, and easier to hand to another person.
