# Entry 210 — crate example surfaces promoted as the adoption / quickstart-support lane

This pass added a new top-level proposal: **P-0524 Crate Example Surface Pack Kit**.
It also added the lane-boundary and fixture scaffolding needed to stop future passes from collapsing README examples, rustdoc snippets, `examples/` targets, docs.rs presentation, tutorial systems, and quickstart contracts into one vague “better docs” story.

## Why this moved now

Several current Rust and ecosystem signals line up unusually well.

### 1. The crate-supportiveness frontier still lacked a first-success lane

The archive already had stronger answers for:

- **task-first crate choice** via **P-0509**,
- **producer-side support / interop claims** via **P-0510**,
- **shared interop profiles** via **P-0511**,
- **compile-time / early-failure guidance** via **P-0512**,
- **runtime failure handoff** via **P-0513**,
- **release-to-release migration** via **P-0514**,
- **successor / off-ramp support** via **P-0515**,
- **setup/configuration scenarios** via **P-0516**,
- **performance envelopes** via **P-0517**,
- **observability surfaces** via **P-0518**,
- **authority surfaces** via **P-0519**,
- **lifecycle surfaces** via **P-0520**,
- **resource surfaces** via **P-0521**,
- **persistence surfaces** via **P-0522**,
- and **test surfaces** via **P-0523**.

But it still lacked a good answer to:

- “Once a team adopts a crate, what exactly is the smallest officially supported path from zero to first success?”

That left the archive with better answers for setup, telemetry, shutdown, storage, and testing than for the most ordinary adoption task of all: **getting started with the crate in a trustworthy way**.

### 2. Current substrate makes this a contract problem, not a primitives problem

Rust already has example targets, doctests, docs guidelines, scraped-example work, docs.rs metadata, executable example testing, UI tests, and markdown example tests.
That means the sharper question is no longer “can Rust host examples at all?” but “what portable artifact should sit above today’s tooling so a crate can tell downstream users which examples it actually stands behind?”

### 3. Current tools are useful but fragmented at the crate boundary

The ecosystem has many useful ingredients, but maintainers still assemble adoption guidance by hand.
What is still missing is the boring pack that can say:

- this is the official quickstart,
- these are official reference examples,
- these examples require only local files,
- these other ones require credentials or a board,
- this is what success should look like,
- and this is how the crate’s example surface changed across releases.

### 4. Rust’s current messaging makes example-support surfaces more plausible than before

The vision-doc work explicitly recommends more **supportive interfaces from crates**.
The 2025 survey says docs and code remain the main learning surfaces.
That combination makes example-surface packs feel like product-support artifacts rather than private maintainer notes.
