# Entry 350 — compile-time sandbox policy deepened around authority, actor scope, enforcement mode, exception ownership, and drift for P-0107

This pass deepened **P-0107 Cargo Sandbox & Capability Policy Kit** instead of adding another generic sandbox runtime, another static API scanner, or another build-script helper.

## Why this lane earned another pass now

Fresh official and primary-source signals line up unusually well:

- the Rust project goal for sandboxed build scripts explicitly treats file/network restriction and determinism as first-class design goals;
- the accepted compiler-team MCP says build-time execution should eventually have declared powers, a minimal API, and Cargo/rustc configuration;
- Cargo still documents a large build-time environment/config surface (`OUT_DIR`, `TARGET`, `HOST`, `DEP_*`, encoded flags, wrappers);
- Cargo unstable docs prove compile-time-only workflows are already real via `--compile-time-deps`;
- a newly accepted Cargo issue on wrapping host build target executions explicitly sits next to build-script allowlist mode, env sanitization, and sandbox experiments;
- `cackle` and `cargo-sandbox` now provide enough practical substrate to expose real support questions instead of hypothetical ones.

Together these make one conclusion stronger: a worthy ecosystem contribution here is not just “run builds in a sandbox”.
It is a crate that helps other people inspect **which policy source was authoritative, which actor got which powers, what mode actually enforced those powers, where exceptions were granted, and what drifted across releases**.

## Main judgment after the pass

The strongest near-term contribution in this lane is **not** another backend.
It is a **compile-time sandbox support contract layer** above `cackle`, `cargo-sandbox`, CI wrappers, and future Cargo-native sandbox substrate.

This pass promotes six P-0107 review objects into first-class status:

1. **policy-authority receipt** — where the effective policy came from;
2. **actor-capability matrix** — which build-time actor got which powers;
3. **enforcement-mode receipt** — whether the run was observe, audit, or enforce, and at what granularity;
4. **exception-ack record** — break-glass grants with owner and expiry;
5. **sandbox-policy drift diff** — what changed across revisions or policy overlays;
6. **sandbox support bundle manifest** — the portable review bundle joining those facts.

## Why these objects matter

Current compile-time sandbox substrate is finally specific enough that the archive should stop flattening it:

- a build can succeed while still being only **observe-mode**,
- a workspace overlay can quietly outrank the crate’s own manifest,
- a backend can isolate build scripts separately but only sandbox proc macros through a **shared lane**,
- and a new release can broaden network or filesystem power without changing whether the build goes green.

## New archive-level stance

For compile-time containment work, the archive should now prefer this layering:

1. **P-0107** for policy authority, actor scope, enforcement mode, exception ownership, and drift;
2. **P-0508** for delegated build-unit topology and output ownership;
3. **P-0040** for proc-macro migration/readiness toward future execution models;
4. **P-0519** for runtime crate authority;
5. lower-level sandbox/runtime proposals for OS mechanisms.

That keeps the portfolio from minting another crate that merely says “sandboxed build” without clarifying what policy actually existed.

## What should count as a worthy crate contribution after this pass

A worthy compile-time sandbox contribution should now be able to answer all of these cleanly:

1. **Which policy source was authoritative?**
2. **Which build-time actor got which powers?**
3. **Was the run observe-only, audit, or enforce?**
4. **Which exceptions were active and who owns them?**
5. **What changed across revisions or overlays that materially broadens trust?**

If a candidate crate cannot answer those questions, the archive should usually treat it as sandbox folklore rather than a serious support contract.
