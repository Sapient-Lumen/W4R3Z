# 2026-03-05 (60): PostgreSQL wire + S3 compatibility + OTLP evidence kits

Added three proposals aimed at **high-frequency, high-pain interoperability surfaces** where teams routinely debug “works on provider A but not B” issues and lack portable repro artifacts.

- **P-0268** PostgreSQL Wire Protocol Interop & Evidence Kit (`*.pgbundle.zip`) — canonical pgwire IR + capture/replay/diff for startup/auth, simple/extended query flows, and normalized error semantics.
  - Specs/refs: https://www.postgresql.org/docs/current/protocol.html ; https://www.postgresql.org/docs/current/protocol-message-formats.html ; https://www.postgresql.org/docs/current/protocol-message-types.html

- **P-0269** S3-Compatible Object Storage Interop & Evidence Kit (`*.s3bundle.zip`) — scenario DSL + canonical request/response IR + provider capability matrices; focuses on pagination, multipart, signing variants, and XML/error-shape drift.
  - Specs/refs: https://docs.aws.amazon.com/AmazonS3/latest/API/API_PutObject.html ; https://docs.aws.amazon.com/AmazonS3/latest/API/API_ListObjectsV2.html

- **P-0270** OTLP (OpenTelemetry Protocol) Interop & Evidence Kit (`*.otlpbundle.zip`) — capture/replay/diff for OTLP export requests/responses (HTTP/gRPC), including partial-success accounting and redaction-first bundles.
  - Specs/refs: https://opentelemetry.io/docs/specs/otlp/ ; https://opentelemetry.io/docs/specs/semconv/otel/sdk-metrics/

Also added fixture stubs under `fixtures/` for the three new bundle families and updated `INDEX.md` and meta files to include initial priority placements.
