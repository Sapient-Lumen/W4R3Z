# Entry 124 — Hex / BEAM native-package ship contracts, and a saturation rule for foreign package seams

This pass promoted one more foreign-package ecosystem seam, but it also added a stronger **stop rule** for future archive growth.

New proposal:

- P-0502 Hex Native NIF ShipKit

Why it rose:

- The archive already had a convincing package-contract pattern for Python wheels, Apple XCFrameworks, Node/npm prebuilds, NuGet native assets, JVM/JNI shipping, and RubyGems native extensions.
- The BEAM ecosystem now fits that pattern too, but with a meaningfully different package-manager truth surface.
- `rustler` and `rustler_precompiled` mean the raw NIF authoring and precompiled-download substrate already exists.
- Hex already has real package tarball and checksum vocabulary.
- Erlang/OTP already makes native-loading behavior explicit via `erlang:load_nif/2`.
- Real packages now expose the practical pain: target additions and drops, checksum discipline, source-build fallback, explicit NIF-version pinning, and naming/layout mismatches between artifacts and loader expectations.

What changed in archive judgment:

- The archive now treats **Rust-backed Hex packages with native NIFs** as another clear case where the missing crate is a **producer-side support contract**, not another binding layer.
- The especially distinctive facts here are:
  - Hex package tarball receipts and checksums,
  - checked-in checksum state for downloaded precompiled NIFs,
  - NIF loader/path/base-name expectations,
  - OTP / Elixir support windows,
  - and the operational difference between “precompiled for you” and “compile from source if anything goes wrong”.
- This pass also tightened the foreign-package frontier: future revisions should now assume this family is **mostly mapped**. New ecosystems should only be promoted when they bring genuinely different package-manager truths, not just another language binding story.

Archive hygiene added in this pass:

- Added a `known-existing` note so future passes do not mistake `rustler`, `rustler_precompiled`, or Hex packaging docs for an already-solved producer-side support contract.
- Added an `llm-hygiene` reminder that Hex tarball facts, checksum discipline, loader behavior, version support, and source-build fallback are all part of the real shipping contract.
- Extended `meta/foreign-package-contract-vocabulary.md` with Hex/BEAM-specific nouns.
- Added a third salience scan (`meta/frontier-salience-2026-03-08-3.md`) that promotes the new seam while also arguing for **slower growth** of this package-contract family.
