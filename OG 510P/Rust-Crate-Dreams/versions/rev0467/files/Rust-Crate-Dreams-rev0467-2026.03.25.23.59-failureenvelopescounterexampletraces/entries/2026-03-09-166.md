# Entry 166 — accessibility frontier split into doctor/gating and capture/interop lab

This pass again chose **not** to add another narrow proposal.

The better move was to clean up an important blurred frontier.
The archive already had two accessibility proposals with good instincts:

- **P-0087 UI Accessibility Kit**
- **P-0202 Cross-Platform Accessibility Interop & Conformance Kit**

But they were starting to overlap too much.
That overlap made both proposals less buildable.

## Main judgment

The sharper accessibility story in this archive is **not** one giant “a11y crate”.
It is at least two layers:

1. an **authoring-side doctor/gating layer** for emitted semantics and release truth,
2. an **observer-side capture/interop layer** for platform exposure, event streams, semantic diffs, and repro bundles.

That split maps much better to the current Rust ecosystem.
AccessKit is real substrate now.
So the next missing value is not “invent accessibility infra” but “freeze the boring workflows above it”.

## Why these changes were the right ones

### 1. AccessKit changed the shape of the missing value
The old text still smelled a little like “Rust needs accessibility infrastructure”.
That is too vague now.
AccessKit and related adapters mean the sharper missing crates are:

- **doctor/gating** above emitted semantics,
- and **capture/diff/bundle** above platform exposure.

### 2. The repo needed cleaner stack boundaries
Without this cleanup, future passes were likely to blur together:

- widget authoring semantics,
- CI gating,
- backend translation,
- platform capture,
- and compliance language.

That would make future proposals less honest.
The new note should help resist that drift.

### 3. Both proposals needed fixture-first planning
The strongest recent work in this repo has come from freezing receiver-facing artifacts.
This pass brings the accessibility frontier closer to that standard.

For **P-0087**, the missing surface is now much clearer:

- toolkit profile,
- doctor report,
- gate result.

For **P-0202**, the missing surface is now much clearer too:

- bundle manifest,
- tree snapshot,
- event stream,
- semantic diff report.

### 4. Compliance claims needed to be kept honest
A recurring trap in accessibility tooling is to slide from “useful diagnostics” into “automatic compliance oracle”.
The revised proposals now say more clearly that:

- WCAG/ARIA/ACT inform rules and severity,
- but emitted tree checks and capture bundles do not equal legal compliance,
- and `manual-review-required` remains a first-class, honest output.

## New planning stance

For the next few passes, the archive should prefer:

- treating **P-0087** as the authoring-side semantic doctor/gating story,
- treating **P-0202** as the observer-side capture/interop/bundle story,
- and using expected-vs-observed comparison as the clean seam between them.

It should **not** drift into:

- another GUI framework proposal,
- a fake compliance oracle,
- or one giant accessibility crate that owns semantics, capture, compliance, and platform abstraction all at once.
