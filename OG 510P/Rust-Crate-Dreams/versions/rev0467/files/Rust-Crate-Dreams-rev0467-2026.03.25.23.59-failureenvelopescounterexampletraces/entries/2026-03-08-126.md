# Entry 126 — Debug support stack sharpening, schema stubs, and incubation order

This pass intentionally did **not** add another top-level proposal.

Instead, it treated the archive's strongest current debugging-adjacent ideas as a **stack** that deserves sharper planning.

## Main judgment

The best next non-Cargo frontier to make more buildable is:

- **P-0486 Debuggability Support Contract Kit**
- **P-0493 Source Path Hygiene & Debug Source Kit**
- **P-0491 Debugger Visualizer Compatibility Kit**

The main archive judgment is that Rust already has a lot of debugging substrate, but still often lacks a **boring artifact that tells another human what a build actually promises**.

## Why this pass focused on debugging

- The 2025 State of Rust survey still leaves debugging as a significant productivity problem.
- The new 2026 debugging survey shows the project still explicitly cares about debugger support quality, visualizers, async debugging, and evaluator ergonomics.
- Cargo/rustc/rustup now expose enough substrate that the sharper missing layer is a **support/review contract**, not just a wishlist for new debuggers.

## Incubation order after this pass

1. **P-0486 first** — best direct value to release engineers and support teams
2. **P-0493 second** — strong narrower seam once broad support-posture vocabulary exists
3. **P-0491 third** — real, but narrower and best layered on top of the first two

## Archive-level lesson

The archive is healthier when it distinguishes:

- broad debug support posture,
- source-path/source-component lookup posture,
- and embedded visualizer compatibility.

Those are adjacent, but they are not the same crate.
