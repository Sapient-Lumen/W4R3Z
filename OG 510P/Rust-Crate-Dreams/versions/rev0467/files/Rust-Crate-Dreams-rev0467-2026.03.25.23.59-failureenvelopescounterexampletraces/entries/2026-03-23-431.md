# Entry 431 — concurrency-contract deepened around late-joiner admission, join-start baseline, and observer-horizon honesty

This pass chose to **deepen P-0538 Concurrency Contract Kit** again instead of inventing another channel wrapper, subscription helper, or “better observer API” crate.

The sharper question was:

> once a concurrency surface can already describe memory, pressure, audience, claim, acceptance, evidence, order, gaps, and closure, how does it also say **whether a new observer can join at all** and **what that observer starts with when it does**?

## Why this deepening pass earned a full revision

Fresh primary sources made the next missing layer concrete:

- the March 2026 Rust challenges write-up still says async complexity remains part of the current Rust pain picture;
- Tokio `broadcast` docs explicitly say new receivers are created by `Sender::subscribe()` and receive values sent **after** the call to `subscribe`;
- Tokio `broadcast::Receiver::resubscribe` explicitly says the new receiver starts from the **current tail** and does **not** include elements still queued for the current receiver;
- Tokio `watch` docs explicitly say new receivers can be created with `Sender::subscribe()` and that the **current value is considered seen** at creation time;
- Tokio `Notify::notify_one` explicitly says that if nobody is waiting, one permit is stored so the **next** `notified().await` completes immediately;
- Tokio `Notify::notify_waiters` explicitly says it only notifies **already registered waiters** and stores **no** permit for the next waiter;
- Tokio `mpsc` docs still define the surface as multi-producer, **single-consumer**, with separate sender and receiver handles returned by channel creation;
- Tokio `oneshot` docs still define the surface as a **Sender / Receiver pair** for a single transfer.

That means the next worthy move for **P-0538** is not just broader “subscription semantics.”
It is to make **late-joiner admission** and **join-start baseline** first-class review artifacts.

## Main judgment after this pass

The top frontier still begins:

1. **P-0537 Compile Iteration Feedback Kit**
2. **P-0509 Crate Ecosystem Pathfinder & Decision-Pack Kit**
3. **P-0535 Dependency Lifecycle Transition Kit**
4. **P-0536 Crate Knowledge Pack Kit**
5. **P-0538 Concurrency Contract Kit**

But **P-0538** is stronger now because the archive no longer stops at:

- reentrancy scope,
- progress/fairness class,
- wait-cancellation semantics,
- recovery posture,
- execution-context boundaries,
- mobility / affinity,
- driver-liveness,
- delivery memory,
- backlog pressure,
- delivery audience,
- consumption claim,
- delivery acceptance,
- observation-evidence ceilings,
- delivery order,
- gap visibility,
- closure finality,
- post-close availability.

It now has a clearer product shape for:

- **late-joiner-admission reports**,
- **join-start reports**,
- **future-only subscription versus current-snapshot entry honesty**,
- **stored-permit versus current-waiters-only wake honesty**,
- **fixed-cohort-only versus reopenable / resubscribable audience honesty**,
- and portable bundle inventory that keeps join truth separate from memory, pressure, audience, claim, acceptance/evidence, order/gaps, closure/tail semantics, fairness, cancellation, recovery, context, locality, or liveness.

## What should count as a worthy crate contribution in this lane now

A worthy concurrency-contract crate should provide other people:

1. **one late-joiner-admission report** that says whether a new observer can join at all, by which route, and under what preconditions;
2. **one join-start report** that says whether that observer starts with nothing, future sends only, a current snapshot already marked seen, a current tail baseline, or one stored permit;
3. **one explicit separation between “can join later” and “starts with current state”**;
4. **one explicit separation between “all current waiters are notified” and “future waiters inherit one stored wake”**;
5. **one portable bundle** that keeps late-joiner admission and join-start semantics separate from memory, pressure, audience, claim, acceptance/evidence, order/gaps, closure/tail, fairness, cancellation, recovery, context, locality, and liveness.

That is closer to an ecosystem-worthy crate than another channel-comparison article because it tells adopters whether “subscribe,” “clone,” or “wait later” actually gives a new observer access to the past, the present, the tail, or only the future.
