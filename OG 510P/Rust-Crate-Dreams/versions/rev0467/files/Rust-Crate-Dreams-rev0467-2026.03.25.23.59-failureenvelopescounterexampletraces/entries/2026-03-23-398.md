# Entry 398 — official quickstarts now need authority receipts, entrypoint-viability matrices, and hosted-visibility honesty

This pass stays inside an already-valuable documentation / onboarding lane.
It deepens:

**P-0524 Crate Example Surface Pack Kit**.

## Why this lane earned another serious refresh now

The archive already had the right instinct: crates need one honest answer to “where should I start, what does it require, and what proves it still works?”
What it still left too implicit was a harder review question:

> “Which start path is *actually* official, which entrypoints are really viable in each command / hosted surface, and which parts are merely visible rather than runnable?”

Current sources make that seam much sharper than before:

- the 2025 State of Rust survey still says online documentation is the preferred canonical reference, followed by studying the code itself;
- the December 2025 “what people love about Rust” write-up says crates still lack enough **supportive interfaces** and guidance;
- the API Guidelines still warn that example code is often copied verbatim by users;
- Cargo still gives `examples/` first-class target status and compiles them under `cargo test` by default to protect them from bit-rot, but examples are not *run* by default;
- Cargo target docs still say `required-features` can silently skip example targets;
- rustdoc scraped examples remain unstable;
- Cargo’s unstable scrape-examples docs still warn that example scraping can be suppressed by dev-dependency conditions unless a target opts in;
- and docs.rs still gives crates configurable features/targets while imposing a sandboxed, network-blocked, mostly read-only build environment.

Together those sources say the sharper missing crate is not another docs site, another transcript renderer, or another examples folder linter.
It is a **reviewable first-success contract** for:

- **official-start authority**,
- **entrypoint viability**,
- **hosted visibility**,
- and **portable quickstart bundles**.

## Main judgment after the refresh

**P-0524** is now stronger as an **official-start authority + entrypoint-viability honesty lane**.

That means a worthy crate in this lane should explicitly own:

- `quickstart-authority.receipt.json`,
- `entrypoint-viability.matrix.json`,
- `visibility-surface.report.json`,
- plus bundles that keep official quickstart claims, local command viability, rustdoc/docs.rs visibility, and success witnesses separate.

It should **not** try to own:

- docs.rs parity for all hosted build behavior,
- doctest extraction semantics,
- generic tutorial publishing,
- or a universal “examples are good” score.
