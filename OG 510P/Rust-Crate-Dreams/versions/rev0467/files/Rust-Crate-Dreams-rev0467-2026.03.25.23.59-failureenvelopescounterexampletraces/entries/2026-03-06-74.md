# Entry 74 — frontier pass: broadcast control, e-invoicing documents, official statistics, 3D manufacturing packages, and LTI launches

Added five proposals after a new pass focused on domains where Rust now has at least *some* substrate, but still lacks the **missing middle**: profile lockfiles, semantic diffs, conformance-suite adapters, replay, and portable evidence bundles.

New proposals:

- P-0322 AMWA NMOS Interop & Evidence Kit
- P-0323 UBL + EN16931 + Peppol/PINT Conformance & Evidence Kit
- P-0324 SDMX 3.0 Conformance & Canonicalization Kit
- P-0325 3MF Conformance & Packaging Evidence Kit
- P-0326 LTI 1.3 + LTI Advantage Conformance & Evidence Kit

Pass notes:

- **NMOS** rose because AMWA’s own testing surface makes it obvious that discovery/registration/connection behavior—not just API client code—is the operational pain seam.
- **UBL/EN16931/Peppol/PINT** rose because Rust is beginning to grow invoice-generation/validation substrate, but the hard problem is still profile pinning and explainable rule failures across jurisdiction overlays.
- **SDMX 3.0** was promoted because the standard now has machine-maintained specs and a TCK while public providers expose real SDMX 3.0 APIs; Rust’s gap is query/structure-aware reproducibility.
- **3MF** was promoted because official conformance suites now exist and Rust has real parser/writer momentum; the leverage point is package/extension validation rather than yet another raw reader.
- **LTI** rose because certification and launch/service replay are first-order problems in practice, and Rust now has enough LTI 1.3 substrate to justify a higher-level conformance/evidence layer.
