# Entry 426 — concurrency-contract deepened around delivery memory, backlog pressure, and lag/loss honesty

This pass chose to **deepen P-0538 Concurrency Contract Kit** again instead of opening another channel implementation, actor helper, or executor-adjacent abstraction.

The sharper question was:

> once a concurrency surface can describe reentrancy, fairness, cancellation, context legality, locality, liveness, and recovery posture, how does it also say **what a wake / value / message is allowed to remember when nobody is ready right now** and **what happens when backlog pressure rises**?

## Why this deepening pass earned a full revision

Fresh primary sources made the next missing layer concrete:

- the March 2026 Rust challenges write-up still says async complexity is part of the current Rust pain picture;
- community wish-list discussion still explicitly asks for better documentation around forward progress guarantees and reentrancy;
- Tokio `Notify` documents a stored-permit model with **at most one permit**, plus a separate `notify_waiters` path that stores **no** permit for future waiters;
- Tokio `watch` documents **latest-value-only** memory where intermediate values are dropped and receivers track seen/unseen state;
- Tokio `broadcast` documents bounded retained history with **lag detection** and explicit skip counts when a receiver falls behind;
- Tokio bounded `mpsc` documents FIFO buffering with sender backpressure instead of overwrite-on-lag semantics;
- `async-channel` documents bounded and unbounded MPMC channels where each message is received by only one consumer;
- `crossbeam-channel` documents bounded channels and an explicit **zero-capacity rendezvous** special case.

That means the next worthy move for **P-0538** is not just broader “channel behavior.”
It is to make **delivery-memory** and **backlog-pressure** first-class review artifacts.

## Main judgment after this pass

The top frontier still begins:

1. **P-0537 Compile Iteration Feedback Kit**
2. **P-0509 Crate Ecosystem Pathfinder & Decision-Pack Kit**
3. **P-0535 Dependency Lifecycle Transition Kit**
4. **P-0536 Crate Knowledge Pack Kit**
5. **P-0538 Concurrency Contract Kit**

But **P-0538** is stronger now because the archive no longer stops at:

- reentrancy scope,
- progress/fairness class,
- wait-cancellation semantics,
- recovery posture,
- execution-context boundaries,
- mobility / affinity,
- and driver-liveness.

It now has a clearer product shape for:

- **delivery-memory reports**,
- **backlog-pressure reports**,
- **coalesced wake versus queued backlog versus latest-value-only versus rendezvous honesty**,
- **lag / overwrite / drop / growth / block distinctions**,
- and portable bundle inventory that keeps memory semantics separate from fairness, cancellation, or context legality.

## What should count as a worthy crate contribution in this lane now

A worthy concurrency-contract crate should provide other people:

1. **one delivery-memory report** that says whether the surface remembers nothing, one coalesced wake, the latest value only, a bounded FIFO backlog, an unbounded FIFO backlog, or a per-receiver bounded broadcast history;
2. **one backlog-pressure report** that says whether pressure blocks senders, overwrites oldest history with lag signals, drops intermediate values, risks unbounded growth, or requires rendezvous;
3. **one explicit separation between “late receiver still observes something” and “every intermediate event/value is retained”**;
4. **one explicit separation between lag detection and no-loss delivery guarantees**;
5. **one portable bundle** that keeps delivery-memory and pressure semantics separate from cancellation, fairness, recovery, context, locality, and liveness.

That is closer to an ecosystem-worthy crate than another queue wrapper or “channel comparison” blog post.
