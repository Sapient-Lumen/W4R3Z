# 2026-03-17 (225) — crate authority-surface productization pass

This pass did **not** add a new lane.
It sharpened **P-0519 Crate Authority Surface Pack Kit** into a more implementation-ready `0.1` shape.

## Main judgment

The missing value is still **not** another sandbox runtime, another capability-based replacement library, or another static scanner that merely spots `std::fs` and `Command`.
The sharper missing layer is a **maintainer-facing authority contract** that records:

- which ambient powers a crate may exercise in each named profile,
- which of those powers are required versus optional or forbidden,
- which dependencies are truly injectable rather than ambient-only,
- which offline / deterministic / sandbox-ready claims were actually witnessed,
- and where a human still has to review the boundary manually.

## Why this lane looks sharper now

- the Rust vision-doc work keeps surfacing **supportive interfaces from crates** as part of the real product experience of Rust;
- the 2025 State of Rust survey says documentation and code remain the main learning surfaces, which means authority posture still too often lives in folklore rather than reviewable artifacts;
- the 2026 safety-critical post makes it clear that teams often use crates to move fast early, then explicitly harden, constrain, or replace them later in production-critical paths;
- the sandboxed build-script goal makes file/network/process authority and determinism pressure explicit at compile time, which reinforces the same boundary discipline at runtime;
- and `ambient-authority`, `cap-std`, `wasi-cap-std-sync`, and `getrandom` now make the substrate concrete enough that the missing value is increasingly the contract **above** those pieces, not another substrate crate beside them.

## What to keep separate

- Keep **P-0519** separate from **P-0509 Crate Ecosystem Pathfinder**.
- Keep **P-0519** separate from capability-oriented libraries such as `cap-std`.
- Keep **P-0519** separate from compile-time sandbox policy for build scripts or proc macros.
- Keep **P-0519** separate from generic static authority scanning.
- Keep **P-0519** separate from full sandbox/runtime host platforms.

## Preferred proving grounds

- parser or config crates that are mostly pure but hide env or `$HOME` convenience fallbacks
- SDK/client crates that claim an offline or deterministic mode while still touching caches, time, or randomness
- plugin/runtime helper crates with host-supplied capability handles and sharp ambient escape hatches
- WASI or capability-oriented crates where absolute-path assumptions can quietly bypass the intended profile
- regulated or safety-sensitive components where release-to-release authority drift matters as much as API drift
