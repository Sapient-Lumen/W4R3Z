# Entry 425 — compile-iteration deepened around coverage-scope receipts, claim-ceiling honesty, and route-support boundaries

This pass again chose to **deepen P-0537 Compile Iteration Feedback Kit** instead of opening another hot-reload helper, process supervisor, or framework-local wrapper.

The sharper question was:

> once a dev-loop bundle can describe surfaces, barriers, activation, stale-code risk, generations, drain, outcome, and degraded mode, how does it also say **what was actually under the live-update regime at all** instead of letting a few successful reloads masquerade as broad support?

## Why this deepening pass earned a full revision

Fresh primary sources made the next missing layer concrete:

- the March 2026 Rust challenges write-up still treats compile time as a universal productivity tax and explicitly names hot reloading and faster linking as important mitigation routes;
- Dioxus now documents three separate hot-reload families (RSX, assets, and experimental Rust hot-patching), plus tip-crate-only Rust hotpatch coverage;
- `subsecond` now documents tip-crate-only patch scope and route-local `call` / `HotFn` boundaries rather than whole-project coverage;
- Chaud says it updates `#[chaud::hot]` functions, and also says those macros are effectively no-ops unless the relevant feature is enabled;
- `hot-lib-reloader` requires code to live in a reloadable dylib and the wrapped module surface defines what is actually hot-reloadable, while generic functions remain unsupported;
- `bevy_simple_subsecond_system` only hotpatches annotated systems/observers, only considers functions that existed at launch, and explicitly excludes common workspace / `lib.rs` layouts.

That means the next worthy move for **P-0537** is not merely more patchability or cutover prose.
It is to make **coverage-scope receipts** and **coverage-ceiling reports** first-class review artifacts.

## Main judgment after this pass

The top frontier still begins:

1. **P-0537 Compile Iteration Feedback Kit**
2. **P-0509 Crate Ecosystem Pathfinder & Decision-Pack Kit**
3. **P-0535 Dependency Lifecycle Transition Kit**
4. **P-0536 Crate Knowledge Pack Kit**
5. **P-0538 Concurrency Contract Kit**

But **P-0537** is stronger now because the archive no longer stops at:

- reload surface,
- restart ceiling,
- latency budget,
- edit scope,
- fast-path barriers,
- state continuity,
- activation boundaries,
- stale-code residency,
- generation witnesses,
- mixed-generation risk,
- retirement boundaries,
- old-generation drain,
- live-update outcome,
- and degraded operating mode.

It now has a clearer product shape for:

- **coverage-scope receipts**,
- **coverage-ceiling reports**,
- **annotation / wrapper / tip-crate / preexisting-route honesty**,
- **framework-specific support boundaries that remain portable in one bundle**,
- and doctor checks that reject fake “reload worked somewhere so coverage is broad” stories.

## What should count as a worthy crate contribution in this lane now

A worthy compile-iteration crate should now provide other people:

1. **one coverage-scope receipt** that says what surfaces, crates, libraries, or routes are truly under live-update support;
2. **one coverage-ceiling report** that says what support claims are out of bounds because coverage is tip-crate-only, annotation-only, wrapper-only, launch-time-only, or manual-review-only;
3. **one distinction between a successful example route and broad support coverage**;
4. **one distinction between framework-local convenience claims and portable support-contract truth**;
5. **one distinction between route coverage and state / activation / drain / outcome truth**;
6. **one portable bundle** that keeps coverage scope and claim ceilings separate from edit scope, barriers, activation, generations, retirement, drain, outcome, and degraded mode.

That is closer to an ecosystem-worthy crate than another watch loop, patch engine, or framework-local “it works for my demo” story.
