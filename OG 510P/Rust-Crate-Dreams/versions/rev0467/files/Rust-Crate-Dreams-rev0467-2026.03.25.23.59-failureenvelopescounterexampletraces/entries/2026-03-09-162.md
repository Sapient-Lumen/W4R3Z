# Entry 162 — evidence bundle core gets fixture-first boundaries

This pass again chose **not** to add another narrow proposal.

The better move was to strengthen **P-0256 Evidence Bundle Core Kit** so that the archive’s bundle-first family inherits a cleaner shared substrate instead of proliferating private zip grammars.

## Main judgment

The repo needed a better answer to this question:

> when a Rust proposal says “signed evidence bundle”, what exact layer is the crate actually supposed to own?

The sharper answer is now:

1. a **core bundle substrate**,
2. one or more **embedded attestation/signature lanes**,
3. a **domain profile contract**,
4. and maybe an external **publication/transparency lane**.

Those are related, but they are not one blob.

## Why these changes were the right ones

### 1. P-0256 needed to stop looking like “a generic signed zip idea”

The external substrate is now good enough that the missing value is not another attempt to invent signatures, transparency, or canonicalization from scratch.

The updated proposal now says more clearly that the crate should own:

- deterministic packing,
- manifest vocabulary,
- redaction receipts,
- explainable verification,
- semantic diffing,
- and profile contracts.

That makes it much more plausible as a boring ecosystem multiplier.

### 2. The repo needed a memory aid for bundle boundaries

The new meta note records one reusable rule:

- bundle substrate,
- attestation lane,
- profile contract,
- publication lane.

That should reduce future drift toward vague “signed bundle platform” language.

### 3. P-0256 needed fixture-first planning

The proposal now has a small schema pack and two scenarios.
That matters because the archive is much more useful when a proposal can already answer:

- what artifact it hands another person,
- how a profile declares what it requires,
- how redaction is recorded,
- and how verification can fail honestly.

## New planning stance

For the next few passes, the archive should prefer:

- reusing **P-0256** as the portable bundle substrate,
- letting domain proposals mostly define **profile contracts** rather than private pack formats,
- and keeping Sigstore / DSSE / COSE / SCITT as imported lanes instead of collapsing them into the core.

It should **not** drift into:

- another private `*.zip` grammar for each proposal family,
- another fake universal attestation format,
- or a bundle substrate that quietly requires online publication infrastructure even for local support handoff.
