# Entry 90 — companion transforms, discovery channels, de-facto sidecars, and loss-aware evidence

Added five proposals after a pass aimed at ecosystems where the missing Rust value is **not another parser, SDK, or sender**, but a boring default for **lockfiles, semantic diffs, loss accounting, and portable receipts** above already-real standards or substrate.

New proposals:

- P-0402 OpenAPI Overlay + Arazzo Workflow Workbench Kit
- P-0403 CMSIS-SVD + IP-XACT Register Interop Workbench Kit
- P-0404 OpenPGP Discovery + WKD + Autocrypt Policy & Evidence Kit
- P-0405 ASAM MDF + A2L + DBC Interop Workbench Kit
- P-0406 Web Push + VAPID + HTTP ECE Interop & Evidence Kit

Pass notes:

- **OpenAPI Overlay + Arazzo** rose because the OAI is now clearly a **multi-specification stack**, while Rust still lacks a boring coordination artifact for deterministic transforms and workflow/source receipts.
- **CMSIS-SVD + IP-XACT** made the cut because Rust already has real SVD/PAC momentum, but still lacks an honest **register IR + loss-report layer** across firmware and IP flows.
- **OpenPGP discovery policy** rose because Sequoia has grown into serious RFC 9580 substrate, while discovery/trust support workflows still lack a compact, safe artifact.
- **ASAM MDF + A2L + DBC** made the cut because automotive measurement pipelines still suffer from **metadata drift** far more than from raw parser absence.
- **Web Push + VAPID + ECE** rose because Rust has enough sender/encryption substrate now that the sharper missing layer is **subscription/delivery evidence**, not one more request builder.

Archive hygiene added in this pass:

- Added a reminder that some of the most important crate opportunities sit between a **normative core** and one or more **companion transforms, drafts, or de-facto sidecars**.
- Strengthened the archive’s memory that **loss surfaces** must be stated explicitly whenever a proposal crosses document families, discovery channels, or partially standardized sidecars.
