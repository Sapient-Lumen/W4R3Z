# 2026-03-17 — Entry 214

Today’s pass did not promote a new crate lane.
It made **P-0484 Toolchain & Target Support Contract Kit** more buildable.

## Main judgment

The archive’s long-running toolchain/target support idea is now strong enough that the next useful move was **productization discipline**, not another neighboring proposal.

The sharper `0.1` shape is now:

- one compact contract file,
- one intent/environment capture pass,
- one local check pass,
- one human-first doctor renderer,
- one short summary renderer,
- one release diff,
- one bundle/export path,
- and three support artifacts that had previously been too implicit: **support-class policy**, **evidence provenance**, and **external prerequisites**.

That matters because ordinary Rust support drift hides in boring places: `path` toolchains silently nullify `components` and `targets`, docs.rs default targets can change what users see without a source diff, a Rust target can be installed while a linker or runner is still missing, and one green machine does not tell reviewers what class of support is actually being promised.

## Why this was worth a pass

The web scan made a useful boundary clearer:

- rustup already covers channels, profiles, components, targets, and path-toolchain caveats,
- Cargo already covers `rust-version`, resolver posture, hierarchical config, and target-specific linker/runner settings,
- docs.rs already covers metadata, default-target behavior, cross-compilation posture, and sandbox limits,
- and Rust’s target-tier policy already explains what Rust-the-project means by its own support tiers.

That means the missing value is increasingly not another installer or another narrow doctor tool.
It is the joined, reviewable contract that tells a contributor or downstream user which toolchains/targets are supported, what class of support that really means, what evidence backs the claim, what external prerequisites still apply, and how that support surface changed across releases.

## Working rule after this pass

Do not invent another nearby crate until **P-0484** proves too cramped to hold:

- support-class policy,
- evidence provenance,
- external prerequisites,
- docs target posture,
- bootstrap hints,
- and release diffs.

If those still fit cleanly, the right move is to deepen **P-0484**, not split it prematurely.
