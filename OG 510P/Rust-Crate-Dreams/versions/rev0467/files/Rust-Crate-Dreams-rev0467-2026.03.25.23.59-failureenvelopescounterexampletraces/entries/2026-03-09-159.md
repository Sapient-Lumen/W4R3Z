# Entry 159 — correctness-lab push for text layout and passkeys

This pass again chose **not** to add another narrow proposal.

The higher-value move was to strengthen two already-salient proposals that had real ecosystem substrate beneath them, but still needed much sharper planning above that substrate.

## Main judgment

The repo needed a better answer to this question:

> when Rust already has credible building blocks, what kind of missing crate is still actually worthy?

In both text/i18n correctness and passkeys/WebAuthn interop, the answer is increasingly:

- not another backend,
- not another generic SDK,
- but a **correctness lab** with scenarios, corpora, normalized outputs, and portable bundles.

## Why these changes were the right ones

### 1. P-0197 needed to stop looking like “a maybe-useful text stack note”

Rust now has enough text substrate that the missing value is no longer just shaping or bidi primitives.
The updated proposal now makes the sharper plan explicit:

- stable layout case models,
- backend adapters,
- semantic layout IR,
- conformance corpus imports,
- and `textlayoutbundle.zip` repro artifacts.

That makes it look much more like an ecosystem multiplier.

### 2. P-0200 needed to stop looking like “a better auth helper”

The WebAuthn/passkeys space already has meaningful Rust substrate and improving automation support.
The updated proposal now says much more clearly that the missing value is:

- scenario DSLs,
- normalized transcript IR,
- runner-lane honesty,
- redacted repro bundles,
- and compatibility reports.

That is a materially stronger and more honest crate target than “yet another Rust passkey library.”

### 3. These proposals needed fixture-first planning

Both proposals now have small schema stubs in `fixtures/`.
That matters because the archive is much more useful when a proposal can already answer:

- what artifact does it hand another person,
- what schema should that artifact roughly follow,
- and what parts of the workflow are meant to be deterministic.

### 4. The repo itself needed one more memory aid

The new meta note records a reusable pattern:

- mature substrate,
- moving backend/runner choices,
- missing correctness-lab layer.

That should help future passes avoid proposing another engine when the sharper value is the shared comparison and evidence surface.

## New planning stance

For the next few passes, the archive should prefer:

- strengthening **P-0197** and **P-0200** as artifact-first labs,
- connecting them upward to **P-0264** and **P-0256**,
- and only adding another backend-like proposal if the repo can show the substrate itself is still truly absent.

It should **not** drift into:

- engine count inflation,
- another generic auth helper crate,
- or hand-wavy “interop” ideas that cannot say what bundle or report they hand to someone else.
