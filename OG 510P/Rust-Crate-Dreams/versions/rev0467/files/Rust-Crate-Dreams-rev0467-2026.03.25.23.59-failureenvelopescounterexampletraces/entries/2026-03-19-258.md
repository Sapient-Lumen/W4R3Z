# Entry 258 — Crate lifecycle support sharpened around activation boundaries, stop verbs, blocking-work limits, and teardown evidence

This pass did **not** add another graceful-shutdown framework, another structured-concurrency runtime, or another general async helper.
It sharpened **P-0520 Crate Lifecycle Surface Pack Kit** into a more implementation-ready support crate.

## Why this moved now

The current Rust async/shutdown story is no longer empty.
That changes the shape of the missing value.

- The December 2025 Rust vision-doc work explicitly says crates need more **supportive interfaces**.
- The 2025 State of Rust survey still says online docs and code remain the main learning surfaces.
- Tokio’s graceful-shutdown guide already explains the three high-level shutdown phases.
- `CancellationToken` + `TaskTracker` already cover signal-and-wait substrate.
- Tokio now documents that dropping a `JoinHandle` detaches work, while dropping a `JoinSet` aborts tracked tasks.
- Tokio also documents that `JoinSet::shutdown()` aborts all tasks and then waits for them to finish shutting down.
- Tokio’s I/O docs distinguish cancel-safe `write`/`flush` from restart-hostile `write_all`, and separate `flush` from `shutdown`.
- `async_shutdown`, `tokio-graceful-shutdown`, `task_scope`, and `moro` prove ongoing demand for shutdown and structured-concurrency substrate.

That combination means the missing crate is no longer “Rust needs shutdown help.”
The sharper missing crate is a **crate-authored lifecycle contract** above today’s substrate.

## Main planning move

This pass promoted five review questions to first-class status for **P-0520**:

1. **activation boundary** — when background work really starts,
2. **stop-verb truth** — what `drop`, `abort`, `close`, `shutdown`, and `join` actually do,
3. **blocking-work limit** — where abort/cancel claims stop being trustworthy,
4. **teardown evidence** — what proves cleanup completed rather than only started,
5. **drain recipe** — what the supported graceful, timed, and hard-stop paths are.

That move matters because the archive had already named the lane, but it had not yet made the **review objects** and **scenario artifacts** concrete enough to survive real product planning.
This pass fixes that.

## Main judgment after the pass

A worthy lifecycle-support crate contribution for Rust should now provide **more than graceful-shutdown advice**.
It should provide:

- explicit **activation-boundary truth**,
- explicit **stop-verb truth**,
- explicit **blocking-work caveat truth**,
- explicit **teardown-evidence truth**,
- explicit **drain-recipe truth**,
- and one compact **lifecycle-surface diff** another maintainer or downstream user can inspect without reconstructing shutdown semantics from docs and issue threads.

That is more believable and more ecosystem-multiplying than either:

- “just use a cancellation token”,
- “just adopt a shutdown framework”,
- or “just mention graceful shutdown in the README” with no receiver-facing contract attached.
