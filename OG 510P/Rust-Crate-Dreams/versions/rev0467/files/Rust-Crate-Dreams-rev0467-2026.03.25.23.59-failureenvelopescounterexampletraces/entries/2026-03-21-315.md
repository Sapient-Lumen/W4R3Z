# Entry 315 — crate-health deepened for maintenance coverage, duty-map honesty, and invisible-work legibility

This pass deepened **P-0011 Crate Health Contract Kit** rather than opening another adjacent ranking, governance, or maintainer-funding lane.

## Why this lane earned another serious pass

The archive already had sharper answers for:

- broad declared health profile,
- maintenance windows,
- succession / backup posture,
- support intent,
- and conservative health checks that keep imported signals separate from maintainer promises.

What still needed a more disciplined answer was the coverage question:

> “Which kinds of maintenance work are actually covered, which are only best-effort, and which still have no visible owner?”

Current Rust ecosystem signals now make that question concrete enough to build around.

## What moved this time

The key planning move was to stop treating “reactively maintained”, “actively developed”, or “security tab present” as sufficient crate-health truth.

This pass elevated three review objects more explicitly:

1. **maintenance-coverage truth** — which kinds of keep-the-lights-on work and contributor-enabling work are explicitly covered, best-effort only, imported/inferred, or still unowned;
2. **duty-map honesty** — whether issue triage, CI breakage, security response, dependency upkeep, docs freshness, review bandwidth, refactoring capacity, and contributor enablement are all being flattened into one vague status word;
3. **visible-invisible-work balance** — whether a crate can honestly claim healthy stewardship even when it has feature momentum but weak janitorial or review coverage.

## Main judgment after the pass

A worthy crate-health contribution should not stop at support horizon, succession posture, or imported trust signals.
It should also provide:

- one explicit **maintenance-coverage report**,
- one honest split between **keep-the-lights-on** and **enable-evolution** work,
- and one conservative **duty-map gap** story when issue triage, CI, security response, docs upkeep, or review bandwidth are only implied rather than actually owned.
