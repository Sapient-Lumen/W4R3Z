# Exact plugin info rows keep a tiny state fallback when detail is blank

Rev589 is a tiny trust/legibility follow-up to the recent plugin command-bar cleanup. Micromax already kept rich exact plugin detail when a plugin had a description or a recorded load error, and recent revs taught broad plugin entry points plus exact `plugin reload NAME` rows to stay concrete about live plugin state. But one exact-inspection seam still lingered: a healthy plugin with no description could render `showplugin NAME` and `plugin info NAME` completion rows as `['name ', 'plugin', '[loaded]', '']`, which made the command bar look unfinished right at the moment it was supposed to be most precise. The fix stays intentionally small: exact `showplugin NAME` and exact `plugin info NAME` rows now reuse a tiny state fallback like `loaded plugin` or `available plugin` only when the richer detail column would otherwise be blank, while grouped plugin picker rows keep their older compact browse-oriented shape. Focused tests pin the loaded/no-description case so future cleanup does not drift back to blank exact rows.
