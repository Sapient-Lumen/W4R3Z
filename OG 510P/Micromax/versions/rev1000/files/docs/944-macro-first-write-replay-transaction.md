# Macro replay without eager workspace capture

Rev0987 removes the open-workspace text-copy multiplier from immediate macro
replay, keeps the pre-revision behavior as an executable differential oracle,
and fixes a nested history-suppression corruption found while auditing failure
control flow.

## Heart of the mission

Micromax is trying to become a calm editor whose automation is powerful without
being mysterious. A macro is one of the most ordinary forms of editor
automation: record a small action, replay it, and expect one understandable undo
step or an exact rollback. That lived loop should not become proportional to the
size of every unrelated file that happens to be open.

The design target is therefore not “more transaction machinery.” It is a smaller
ownership rule:

> preserve original text immediately before the first write to a buffer that the
> invocation actually touches; do not copy untouched documents merely because
> arbitrary automation *could* have touched them.

Rev0986 established that rule for `ed.with-undo`. Rev0987 applies the same proven
owner to immediate macro replay while retaining macro-specific authority,
history, navigation, feedback, and failure semantics.

## What had gone severely wrong

Before rev0987, `play_macro()` called `_macro_replay_snapshot()` before executing
its first step. That snapshot joined complete text for every open buffer. A
one-character macro in one buffer therefore copied all unrelated documents just
to own a possible rollback. A navigation-only macro did the same even though it
created no history row. A failed local macro copied the workspace and then
rebuilt only the touched state.

The retained history row was not the main problem. Rev0984 already compacted
aggregate rows to changed buffer identities. The waste was temporary rollback
ownership before the macro knew which buffer, if any, would change.

A permanent eight-buffer witness with 1,000,000 characters per buffer reproduces
the cliff:

| Replay case | Eager reference joins | Rev0987 joins | Eager median traced peak | Rev0987 median traced peak | Reduction |
| --- | ---: | ---: | ---: | ---: | ---: |
| one-character success | 9 / 9,000,001 chars | 2 / 2,000,001 chars | 9,036,532 B | 2,040,877 B | 77.415% peak |
| edit then failure | 8 / 8,000,000 chars | 1 / 1,000,000 chars | 20,891,005 B | 2,638,654 B | 87.369% peak |
| navigation only | 8 / 8,000,000 chars | 0 / 0 chars | 8,027,256 B | 34,573 B | 99.569% peak |

Median elapsed time in the same-runtime witness falls 43.499%, 81.581%, and
32.486% respectively. Python `tracemalloc` is not RSS, native-memory, or portable
latency evidence; the complete-string join count is the more direct ownership
witness.

Successful eager and first-write cases both retain exactly 2,000,001 logical
text bytes in one changed-buffer history charge. Rev0987 changes temporary
capture, not the final whole-generation representation of a touched aggregate
buffer.

## Shipped transaction shape

Macro replay now begins with `_first_write_buffer_transaction()`, the narrow
owner introduced for `ed.with-undo`:

1. Capture a text-free shell of buffer membership, identities, versions, paths,
   dirty/saved state, cursor and selection sidecars, local options, marks,
   recent files, saved cursors, search state, authority sidecars, input, and the
   current undo/redo snapshot.
2. Attach one one-shot pre-text-mutation observer to each buffer present at
   invocation start.
3. Immediately before a buffer's first actual write, join and retain its complete
   old text. If capture fails, the mutation does not occur and the observer stays
   armed.
4. Execute macro steps with their recorded runtime provenance. Eligible built-in
   action-only macros still suppress temporary per-step history; command,
   extension, Undo, and Redo steps retain the exact-history path.
5. Capture one text-free after shell. Restore the pre-invocation history before
   creating the one user-visible aggregate row.
6. If no text observer fired and the shells prove there was no durable change,
   finish immediately. Pure navigation therefore joins no document—not even the
   active one—and remains outside edit history.
7. Otherwise materialize complete old/new strings only for changed buffer
   identities and record one aggregate macro row when durable state changed.
8. On step failure or finalization failure, materialize only the old strings
   needed for rollback and restore exact editor state, history, and input.

New buffers need only after-text. Removed unchanged buffers can materialize their
old text from the still-reachable start object. Metadata-only changes may share
one current text string between before and after. Mark/register-only macros can
remain completely text-free.

The after shell is passed into finalization instead of being recaptured. Besides
avoiding duplicate sidecar work, this makes the navigation-only decision and the
materialized transaction refer to the same observed end state.

## Failure-control-flow audit: a real correctness bug

The allocation refactor exposed a separate history bug that predated rev0987.
For a safe action-only macro, playback enters `undo.suppress_recording()`. On
failure, the old control flow restored the saved macro snapshot *while still
inside that suppression context*.

That is harmless when the saved suppression depth is zero. It is wrong when
macro replay is nested inside an outer aggregate transaction:

1. outer owner has suppression depth 1;
2. macro's inner guard raises it to 2;
3. failed replay restores the saved depth 1 while the inner guard is still live;
4. the guard exits and decrements that restored 1 to 0;
5. the outer owner silently loses its suppression.

A later edit in the same `ed.with-undo` quotation could then record a stray
individual history row before the outer aggregate row. This is not only wasted
history; it breaks the promised single user action and can make nested rollback
reasoning false.

Rev0987 records the abort detail, exits the step-level `ExitStack`, and only then
restores the transaction snapshot. The saved nesting count is restored after the
inner guard has unwound. Regressions pin both one- and two-level suppression
counts and an end-to-end hostcall journey:

- a failed macro inside `ed.with-undo` restores its own edit;
- a following edit remains suppressed;
- the quotation commits exactly one outer row;
- undo and redo replay that row exactly; and
- suppression returns to zero only when the outer owner exits.

A source audit found no other macro rollback inside a live history-suppression
context. `ed.with-undo` already performs exception rollback after its suppression
context exits.

## Executable differential oracle

The eager pre-rev0987 control flow remains executable in
`tests/test_rev0987_macro_first_write_transactions.py` and
`tools/measure_macro_first_write.py`; it is not a shipped product mode.

The focused test module covers:

- forty seeded successful mixed action/command and multi-buffer replays;
- twenty seeded failed replays;
- exact return value, editor state, retained charge shape, undo, redo, and runtime
  authority against the eager oracle;
- untouched large buffers whose `get_text()` raises if accidentally joined;
- failed replay without untouched-buffer join or rebuild;
- navigation-only replay with `get_text()` forbidden on every buffer;
- register/mark-only replay with zero text joins and exact undo/redo;
- direct mutable-line-view mutation under observation;
- injected finalization failure after the row helper mutates history;
- script-origin macro authority;
- one- and two-level suppression restoration;
- failed replay nested in the real `ed.with-undo` hostcall; and
- the permanent measurement-tool schema and expected join counts.

This is deliberately stronger than comparing final text. Macro replay can affect
buffer membership, active/MRU state, cursors, selections, marks, recent files,
saved cursors, local options, dirty/saved metadata, history stacks, and authority
provenance. The oracle compares the complete in-process snapshot used by the
existing rollback contract.

## Online comparison and what it suggests

The implementation borrows narrow principles from mature editors and text
systems; none of these sources confer their guarantees on Micromax.

### Scintilla: document changes form history; navigation does not

Scintilla documents that it saves document-changing actions, does not save caret,
selection, or scrolling movement, compresses typing/deleting sequences, and can
nest `SCI_BEGINUNDOACTION`/`SCI_ENDUNDOACTION` groups. It separately notes a
memory cost when selection history is enabled:
<https://www.scintilla.org/ScintillaDoc.html#UndoAndRedo>.

Micromax already shared the user-facing rule that navigation-only macro replay is
not an undo event. Rev0987 makes the ownership cost match that rule: navigation
no longer pays for document rollback strings it can never need. Scintilla's
coalescing also reinforces that sustained typing—not another registry—is the
highest-value remaining history investigation.

### VS Code: explicit transactional edit and undo-stop policy

The VS Code extension API describes `TextEditorEdit` as a complex edit applied
in one transaction, and `TextEditor.edit` exposes explicit `undoStopBefore` and
`undoStopAfter` policy, defaulting to stops around the edit:
<https://code.visualstudio.com/api/references/vscode-api#TextEditor>.

The useful lesson is separation: constructing/applying an edit and deciding its
user-visible undo boundaries are related but explicit concerns. Micromax keeps
macro execution provenance and temporary step-history policy separate from the
first-write rollback owner and final aggregate row.

### Qt: nested edit blocks belong to the outermost user action

Qt's `QTextCursor.beginEditBlock()` groups operations into one undo/redo action;
nested blocks take their scope from the top-most pair:
<https://doc.qt.io/qt-6/qtextcursor.html#beginEditBlock>.

That is the exact user expectation endangered by the suppression-depth bug. The
rev0987 hostcall regression now proves nested macro failure cannot puncture the
outer grouping boundary.

### ProseMirror: internal transactions can be excluded from history

ProseMirror exposes `addToHistory=false` transaction metadata:
<https://prosemirror.net/docs/ref/#history>.

Micromax's eligible action-only replay similarly excludes temporary local rows
while retaining one outer invocation row. The comparison is conceptual only:
Micromax restores broad editor sidecars and recorded authority, not a
ProseMirror document transaction.

### Upstream micro: undo ownership is attached to the buffer

Upstream micro's `Buffer` contains both the text-bearing `LineArray` and the
undo/redo `EventHandler`:
<https://github.com/zyedidia/micro/blob/master/internal/buffer/buffer.go>.

Micromax has a global linear history because one macro or script quotation may
span buffers and editor registers. The inference is not to imitate micro's
structure wholesale, but to keep document text ownership local: a global
invocation should include only the buffer identities that actually participate.

## What is still missing or risky

Rev0987 retires one workspace-size multiplier and one nested-history corruption.
It does not finish macro, history, or transaction design.

- A touched aggregate buffer still retains complete old and new generations. A
  one-character macro in one huge buffer is no longer multiplied by unrelated
  files, but its eventual row is still whole-buffer-grained.
- The text-free shell still copies cursor/selection stacks, jump lists, local
  options, and global registers for every open buffer. Workspaces with enormous
  sidecar state need a separate measurement before making those fields lazy.
- Accepted query-replace remains a broad delayed session. Its answers cross time,
  visible prompt state, and generation validation; it should not be treated as an
  immediate macro merely because both eventually record one row.
- Simultaneous edit planning/replay and some specialized line plans still build
  complete result strings. One extremely long logical line remains an allocation
  and latency risk.
- A raw line-list alias retained before observation, private `_lines` mutation,
  concurrent writers, and hostile Python/native code are outside the owner
  contract.
- The journal is ordinary in-process memory. It is not crash-durable,
  thread-safe, independently persistent, or a substitute for save recovery.
- Messages and external effects—filesystem writes, processes, clipboard backend
  effects, network, native calls—are not rolled back by macro failure.
- Logical `undobytes` accounting does not count callback/dataclass objects,
  sidecars, metadata-only rows, allocator arenas, RSS, or native memory.
- Tiny typing rows remain uncoalesced, and the newest oversized row remains whole
  by explicit recovery policy.

## What should change next

The highest product risk is sustained typing history. Measure row count, object
and sidecar retention, pause/movement boundaries, and actual Undo feel in a long
editing journey. Only then add bounded coalescing semantics and an executable
oracle for grouping breaks.

The next transaction-specific measurement should be long accepted
query-replace sessions. Preserve its delayed interaction oracle while measuring
whether complete session snapshots cause a real cliff. Do not generalize the
first-write owner into a registry until a second delayed consumer proves the
same lifetime and failure boundary.

## What should not change yet

Do not add an undo tree, persistent in-memory journal, independent per-buffer
transaction graph, generic transaction/owner registry, rope or piece table,
background index, broker, watcher, or Wasm host on the strength of this result.
The landed change is valuable because it is narrow, measured, compatible, and
removes cost from a lived loop.
