# Worklist (rev1000)

## Landed: mission and trajectory audit

- Re-read the implementation, tests, evidence machinery, revision history, and
  living guidance as one datacube rather than treating rev0999 as the whole story.
- Named the durable mission: a calm, inhabitable editor whose automation is
  understandable, least-authority, attributable, bounded, recoverable, and
  observable without a renderer.
- Measured the imbalance between a strong trust laboratory and weak adoption,
  taste, flow, dogfood, and release-consumer evidence.
- Preserved the deep optimization record while moving it out of the product's
  first-contact path.

## Landed: evidence-state honesty

- `mxaudit` now reports release-suite presence, source/test currency, internal
  consistency, completeness, and pass state separately.
- A stale partial manifest can remain useful as a checkpoint, but its existence
  no longer reads like current release proof.
- Durable decision D51 makes evidence state a product fact rather than an audit
  implementation detail.

## Landed: first-contact product truth

- Package metadata, module documentation, CLI help, the tutorial, README, roadmap,
  repo map, and LLM handoff now describe a working editor with a headless product
  model and a reference curses renderer—not a future prototype.
- The Micromax language is positioned as the configuration, macro, and extension
  substrate for the editor rather than a competing product center.
- The revision index and machine-readable audit record this trajectory correction.

## Now: five bounded dogfood sessions

Use the editor for five real tasks: open and navigate a project, make a multi-file
change, search and replace, recover from a failed or interrupted action, and save
or inspect the result. For each session retain only:

1. the intended task and environment;
2. the first blocking or trust-breaking moment;
3. one compact headless witness where possible;
4. at most three fixes ranked by user impact.

Do not convert every observation into a framework. The goal is to learn whether
Trust enables Taste and Flow, not to grow another evidence language.

## In parallel: execute one current release-consumer journey

- Reset the carried full-suite manifest against the exact rev1000 source and keep
  partial status explicit until every batch passes.
- Execute the hosted exact-byte lane for this source, retain subjects and receipts,
  download them into an independent consumer environment, and verify provenance.
- Add Windows or macOS support claims only after equivalent executed receipts.
- Treat workflow configuration, a local partial run, and an attestation statement
  as three different facts.

## Then: one net-deletion ownership cut

The `Editor` coordinator has continued to grow despite repeated warnings. Choose
one resource family that already has duplicated capture, restore, retirement, and
cleanup policy. Extract one typed owner only when the change:

- deletes more coordination code than it adds;
- narrows lifecycle authority;
- preserves the compact headless model and focused journeys;
- does not create a generic registry or freeze internal Python surfaces.

No second extraction is authorized until the first demonstrates lower maintenance
cost in subsequent product fixes.

## Later, only from reproduced demand

- Define a small versioned extension world before considering process or Wasm
  isolation; imports, exports, lifecycle, budgets, and failure semantics come first.
- Specify grapheme and terminal-cell behavior when a second renderer or a concrete
  editing failure makes code-point semantics insufficient.
- Build filesystem and power-loss matrices from real supported targets.
- Resolve archive revision, package version, and host API compatibility policy.
- Select a public product name before broad distribution; “Micromax” has active
  technology-brand collisions and should not silently become release identity.

## Guardrails

- Product journeys outrank schema, runner, manifest, and audit expansion.
- Current, complete, and passing are never synonyms.
- Headless truth precedes renderer behavior; the TUI consumes shared semantics.
- Capabilities are application policy, not an operating-system sandbox.
- Add abstraction only after reproduced pressure, and prefer net deletion.
- Keep rollback, atomicity, portability, and release claims no broader than their
  exact witnesses.
