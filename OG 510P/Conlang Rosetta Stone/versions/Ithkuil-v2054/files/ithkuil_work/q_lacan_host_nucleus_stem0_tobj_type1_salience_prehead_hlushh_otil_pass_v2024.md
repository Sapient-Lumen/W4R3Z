## What this checkpoint now freezes

### 1. the next overt move should build the nominal core before solving the comparison morphology

The host nucleus has three burdens:

```text
T-OBJ       = broad demonstrative/object head
ŠH₃         = salience / prominence sharpening
SUR + CMP   = more-than-you comparison
```

The tempting move would be to attack `SUR + CMP:<2m>` first.
This pass rejects that order.

The comparison is semantically correct, but morphologically it depends on a stable nominal target.
If the archive tries to attach the Level machinery before deciding what exact noun-like unit carries it, it risks repeating the same scope instability that earlier passes worked to avoid.

So v2024 freezes the order of work:

1. first realize the headed nominal core,
2. then attach the `SUR` Level to that core,
3. then realize the `CMP:<2m>` than-term and the final object-case behavior.

This means the next improvement is not:

```text
<T-OBJ + ŠH₃>{LVL:SUR CMP:<2m>}  →  <T-OBJ + ŠH₃ + overt-SUR-CMP>
```

but:

```text
<T-OBJ + ŠH₃>  →  <hlušh-otil->
```

with the comparison still visibly parked on the resulting host pair.

### 2. the formal parent head remains `-T-` OBJ, not `-ŠH-`

The archive should not promote salience into the formal head.

If `ŠH₃` became the parent, the phrase would move toward:

> a salience/prominence that is more than you

rather than:

> a salient something that is more than you

That would be too much semantic narrowing.
The sentence needs a generic host because the source says **something**, not **a salience**, **a prominence**, or **a significant thing** in the ordinary lexical sense.

Therefore the parent head remains:

```text
-T- + OBJ specification
```

This keeps the host broad enough to mean the object/entity/situation/idea under discussion, while allowing the salience material to sharpen it without replacing it.

### 3. the `-T-` host should now be treated as **Stem 0**, not Stem 1/2/3

Until now the archive has written the head as `T-OBJ`, leaving stem-choice implicit.
For a final-ish surface path that is no longer good enough.

This pass freezes the parent head as:

```text
T₀-OBJ
```

Reason:

- **Stem 1** would pull the host toward “this one near/associated with the speaker.”
- **Stem 2** would pull the host toward “that one near/associated with the addressee.”
- **Stem 3** would pull the host toward “that yonder one,” away from both parties.

All three ordinary stems add a spatial/interpersonal deixis that the host does not yet need.
The line already has two explicit second-person relations nearby:

```text
<2m:ITP>      = through/in you
CMP:<2m>      = more than you / than-you term
```

If the host itself also became Stem 2, the archive would risk triple-marking the addressee association:

```text
through you + than you + that-one-associated-with-you
```

That is too heavy.
The host should remain a discourse-specified “something,” not a deictic “that thing of yours.”

Stem 0 is the cleanest official way to keep the raw root’s overall concept without forcing one of the three deictic stems.
So the head is now:

```text
T₀-OBJ = the discourse-specified object/entity/situation/idea under discussion
```

or, in the current English control phrase:

```text
a salient something
```

not:

```text
that salient thing associated with you
```

### 4. the parent-head core lead becomes `otil-`

Given the new Stem-0 decision, the parent head’s local core can now be stated more explicitly.

For the parent head:

```text
Slot II   VV = o     Stem 0 + PRC
Slot III  CR = t     General Demonstrative Root
Slot IV   VR = i     STA + OBJ + EXS
Slot VI   CA = l     default CSL/UPX/DEL/M/NRM
```

This yields the diagnostic parent-head core:

```text
otil-
```

This is not yet a whole word.
It is only the parent-head lead before:

- the `SUR` Level material,
- the final case/format material,
- and any stress-bearing decision for the full concatenated pair.

But it is a real gain over the old placeholder:

```text
T-OBJ  →  T₀-OBJ  →  otil-
```

### 5. the salience burden should be Type-1 concatenated, not Type-2 derivational

The archive has long wanted `ŠH₃` to sharpen the host without lexicalizing the whole expression too early.
That makes the concatenation type decisive.

A Type-2 derivational concatenation would push toward a new lexicalized gestalt:

```text
salience-object / prominent-thing / conspicuous-thing
```

That would violate the archive’s earlier caution against over-translating *objet petit a* into an ordinary common noun.

A Type-1 concatenation is safer.
It lets the salience formative function as a circumstantial/modifying prehead burden while the following parent remains the true head.

So v2024 freezes:

```text
ŠH₃ = Type-1 concatenated prehead
T₀-OBJ = parent head
```

not:

```text
T₀-OBJ = prehead
ŠH₃ = parent head
```

and not:

```text
ŠH₃ + T₀-OBJ = Type-2 lexicalized compound
```

### 6. the analytic salience prehead is `hušhal-`

If the salience prehead is written conservatively without the shortcut, its local diagnostic shape is:

```text
Slot I    CC = h-     Type-1 concatenated formative
Slot II   VV = u      Stem 3 + PRC
Slot III  CR = šh     IMPORTANCE / SIGNIFICANCE / PREVALENCE / CONSPICUOUSNESS / PROMINENCE
Slot IV   VR = a      STA + BSC + EXS
Slot VI   CA = l      default CSL/UPX/DEL/M/NRM
```

So the explicit analytic counterpart is:

```text
hušhal-
```

This is useful because it keeps visible the material that will be compressed in the running form:

```text
h- + u + šh + a + l
```

It also confirms the semantic path:

```text
Stem 3 BSC = salience / salient / prominent / conspicuous
```

### 7. the preferred running salience prehead is `hlušh-`

Because the salience prehead has default `VR = a` and default `CA = l`, it falls into the same official shortcut lane used earlier for `hleňf-`.

For a Type-1 concatenated formative, the default `a + l` bundle is carried by the shortcut-bearing Slot-I form:

```text
hl-
```

The overt `a + l` then disappears from Slots IV and VI.

Thus:

```text
hušhal-   = analytic expanded counterpart
hlušh-    = preferred running shortcut lead
```

This pass therefore freezes the salience prehead in the same style as the already-preferred middle-frame prehead `hleňf-`:

```text
preferred running form:       hlušh-
diagnostic expanded form:     hušhal-
```

### 8. the new local host-nucleus notation is `hlušh-otil-`

Putting the prehead and parent together, the old host placeholder now advances from:

```text

```

to:

```text

```

More explicitly:

```text
hlušh-        = Type-1 salience/prominence prehead
otil-         = Stem-0 demonstrative OBJ parent head
```

The hyphen is not decorative.
It marks the concatenated-pair relationship in the romanized archive line.

This is the first version of the host nucleus where the salience burden and the demonstrative head are both no longer mere symbolic placeholders.

### 9. the comparison still scopes over the parent-headed pair as a whole

The old packet was:

```text
<T-OBJ + ŠH₃>{LVL:SUR CMP:<2m>}
```

The new v2024 packet is:

```text
<hlušh-otil->{LVL:SUR CMP:<2m>}
```

This notation is intentional.
It does **not** mean:

```text
hlušh-{LVL:SUR CMP:<2m>}  otil-
```

That would say the salience itself is what exceeds the addressee.
Earlier passes rejected that reading.

It also does **not** mean:

```text
hlušh-  otil-{LVL:SUR CMP:<2m>}   with salience merely decorative
```

The comparison is still to be read against the whole stabilized nominal unit.
The parent remains `otil-`, but the pair as a pair is the comparison-bearing host.

So the control structure is:

```text
[Type-1 salience prehead + Stem-0 demonstrative OBJ parent]  +  SUR  +  CMP:<2m>
```

English-facing control:

> a salient something that is more than you

## Alternatives now rejected or demoted

### A. make `ŠH₃` the parent head

Rejected.
It would turn the object into a salience/prominence itself rather than a salient something.

### B. use Type-2 concatenation for `ŠH₃ + T₀-OBJ`

Rejected for now.
It would over-lexicalize the packet into a new “salient-object” gestalt, which conflicts with the archive’s caution around *objet petit a*.

### C. choose `T₂-OBJ` for the parent head

Demoted.
It is tempting because the object is found **in you**.
But the sentence already has explicit second-person marking in the middle frame and comparison term.
Stem 2 would over-index the addressee relation.

### D. leave `T-OBJ + ŠH₃` as a pure placeholder

Now demoted.
It was useful while the carrier work was live.
But after `esälu’u «objet petit a» hü` was stabilized, the host side needs to begin surfacing.
