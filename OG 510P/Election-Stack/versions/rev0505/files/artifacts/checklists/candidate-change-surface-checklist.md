# Candidate-change surface checklist

- Identify one authoritative public path for candidate-field changes and one authoritative help path.
- State the affected office or race clearly enough to avoid a false statewide or countywide answer.
- State the event type plainly: withdrawal, death, disqualification/ineligibility, nomination set-aside, replacement nomination, reopened filing window, write-in deadline change, or another bounded public event.
- State whether the affected candidate remains on any ballot, sample ballot, candidate list, guide, pamphlet, or cached/printed artifact, and which superseding notice now controls.
- Publish any replacement-nomination path, reopened filing window, supplemental candidate list, or write-in deadline change as an explicit public action item with its deadline semantics.
- Distinguish candidate-field-change facts from general calendar facts; do not force voters to infer “who is actually in this race now?” from a filing guide alone.
- Check parity across candidate lists, current-election pages, sample ballots, voters’ guides/pamphlets, FAQs, hotline/help scripts, and signed notices.
- Treat changed candidate fields, reopened filing windows, replacement nominations, and stale printed/cached materials as explicit superseding notices, not silent edits.
- Publish accessible and translated versions where required, plus a fallback contact path when the primary notice page fails.
- Do not publish internal challenge files, litigation work product, or copied ballot-access treatises when a bounded summary plus pointer will do.
- Record `last_verified_at` and the latest correction/advisory notice pointer.
