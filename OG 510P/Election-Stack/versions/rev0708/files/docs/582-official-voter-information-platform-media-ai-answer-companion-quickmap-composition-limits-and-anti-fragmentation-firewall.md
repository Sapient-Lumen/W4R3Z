## Why this exists (bounded)

The archive already made the right move by **not** forcing every AI-layer ambiguity back into `499`.
That kept pane state, thread carryover, answer language, provenance, answer outcome, safety controls, prompt inventory, transcript fit, transcript governance, remediation authority, and related questions from collapsing into one overburdened control.

But that success creates a second risk:
**once `562–581` exists, reviewers can start acting as if every closely related AI detail deserves one more numbered companion, one more packet tag, or one more paragraph of duplicate explanation.**

This document is the counterweight.
It says the AI-answer tail is now mature enough that most remaining work should be:
- choosing the right existing companion,
- keeping only the comparison-salient carried facts,
- tightening packet grammar,
- tightening neighbor boundaries,
- or deleting redundant prose.

Usually the missing move is **composition discipline**, not another numbered surface.
That now includes starter carry-profile selection, compression back toward an anchor-plus-one-modifier default, claim isolation, local-anchor/reset discipline, residue demotion, and the AI-tail **proof-budget firewall** with its named sentence-scope drift families.

## This is not another AI-answer surface

`582` does **not** define a new public route, new answer layer, new authority object, new packet tag family, or new evidence kind.

It exists only for one bounded question:
**when the same current media object already controls and the AI-answer boundary is already understood, how should maintainers choose among the existing `562–581` companions without fragmenting the archive further?**

If the real issue is still whether the player-native AI answer module exists as a bounded authority problem at all, use `499`.
If the real issue is still which platform-media boundary controls, use `523`.
If the real issue is packet shape, comparison, or citation scope after the doc choice is already made, use `527` and `530`.
Use `582` only when the problem is **neighbor choice and composition discipline inside the existing AI-answer companion family**.

## Composition ladder: decide in this order

When a same-object packet involves the platform-media AI layer, reviewers SHOULD decide questions in this order:

1. **Boundary + currentness**
   - Is this actually an AI-answer boundary over already-open media? → `499`
   - What packet currently controls? → `529`
   - What should later notes cite by default? → `530`

2. **Exposure / readiness / governing substrate**
   - Is the AI layer absent or visible because of rollout, entitlement, owner activation, account scope, or client environment? → `570`
   - Is the ordinary derivative still settling? → `561`
   - Did the content clear a published floor or fit rule? → `572`
   - Which transcript variant actually governed? → `573`
   - Did transcript language match the spoken source? → `575`
   - Did names/terms need bounded repair? → `576`
   - Who could enable or fix the same lane? → `581`

3. **Prompt / pane / thread framing**
   - Was the AI pane merely open, summary-focused, or answer-visible? → `562`
   - Was the answer fresh, follow-up-conditioned, or visibly reset? → `563`
   - What topical scope did the module claim? → `577`
   - What prompt inventory did the module offer before asking? → `580`

4. **Rendered answer properties**
   - What output language did the answer use? → `564`
   - What visible grounding cues appeared? → `565`
   - What source basis was disclosed? → `566`
   - Did the turn answer, fail narrowly, or no-answer? → `567`
   - Did the answer carry a visible warning/disclaimer? → `568`
   - Did the answer expose feedback/report controls? → `569`
   - Did the platform say the answer could use scenes/slides/objects beyond transcript text? → `574`
   - What task/output class was the answer performing? → `579`
   - What guardrails or safety-control posture were disclosed? → `578`

5. **Interaction-retention / minimization posture**
   - How did the platform say it stores, reviews, retains, improves from, or avoids training on the interaction? → `571`

Do **not** start in the middle.
Most false splits happen because maintainers choose an answer-property doc before they have settled whether the issue was really visibility, transcript governance, or thread conditioning.

That is not a truth ceiling.

The anti-fragmentation rule is simple:

## Why `527`'s AI spill order looks the way it does

`562`, `570`, `581`, `572`, `575`, `576`, `573`, `563`, `580`, `577`, `579`, `578`, `571`, `565`, `567`, `564`, `566`, `574`, `568`, `569`.

`582` is the rationale layer for that order.
It is intentionally **foundation-first**:
- start with whether the pane/answer lane is actually present as a same-object bounded surface (`562`),
- then prefer viewer-exposure / remediation / governing-substrate facts that explain why the lane exists, fails, or depends on a particular transcript footing (`570`, `581`, `572`, `575`, `576`, `573`),
- then preserve conversation framing (`563`, `580`, `577`),
- then preserve output-mode / guardrail / retention posture (`579`, `578`, `571`),
- and only then spend remaining budget on rendered-answer properties and softer wrapper residue (`565`, `567`, `564`, `566`, `574`, `568`, `569`).

That order is **not** a theory of importance in the abstract.
It is only a compact answer to one practical packet question:
**if several AI facts are simultaneously true and only a few can travel canonically, which ones most improve later reconstruction before prose begins to sprawl?**

## Pairwise tie-breakers before you carry two near-neighbor AI docs

When two AI companions from adjacent scopes are both true, reviewers SHOULD ask whether one of them already explains the comparison-salient ambiguity.
Usually the answer is yes.

| If both are true, carry... | Usually not both | Why |
|---|---|---|
| `570` when the claim is what this viewer could or could not see/use | `570` + `581` | visible/absent exposure is different from who could remediate it later |
| `581` when the claim is who had to enable, repair, or request repair | `581` + `570` | remediation authority is different from capture-scoped exposure |
| `572` when a published floor/fit rule explains why the lane or answer could not proceed | `572` + `561` | input sufficiency is different from ordinary derivative lag |
| `575` when the decisive issue is spoken-language / governing-transcript match or regeneration | `575` + `573` or `575` + `564` | language alignment is different from transcript precedence or visible output language |
| `563` when the answer was visibly conditioned by earlier turns or reset history | `563` + `580` | actual thread conditioning outranks merely offered prompt inventory |
| `580` when the inventory of suggested prompts is the thing being proven | `580` + `563` | prompt menu posture is different from what the chosen turn actually depended on |
| `577` when the decisive issue is whether the module stayed on-video or allowed related content | `577` + `566` | topical scope is different from disclosed source basis |
| `565` when the decisive issue is what support cues were visible on the answer | `565` + `566` | visible grounding cues are different from provenance claims |
| `566` when the decisive issue is what basis the platform said the answer drew on | `566` + `565` or `566` + `574` | provenance/source basis is different from visible cues or same-video visual-basis claims |
| `567` when the decisive issue is whether the turn answered at all | `567` + `568` or `567` + `569` | answer outcome outranks caution or feedback residue when one compact truth must win |
| `568` when the visible warning/caution posture itself changed and that is the disputed fact | `568` + `578` | answer-card warning state is different from product-level guardrail disclosure |
| `578` when the decisive issue is disclosed guardrail or filtering posture across the lane | `578` + `568` | guardrail posture is different from one card's visible warning label |
| `579` when the output class itself is what changes later reconstruction | `579` + `567` | task mode is different from whether the turn returned an answer |
| `569` only when helpfulness/report controls themselves matter for the claim | `569` + `567` | feedback/report residue rarely outranks answer outcome |

This is the operative anti-fragmentation default:
**before carrying two AI-tail docs from the same local neighborhood, make yourself explain why one would fail to preserve the actual disputed proposition.**
If you cannot do that clearly, carry one and keep the rest in short scoped prose.

## Starter carry profiles before you invent a custom AI bundle

When a packet seems to want four or five AI companions at once, reviewers SHOULD first ask which **claim shape** they are actually trying to preserve.
Usually one of these starter profiles already fits, which means the bundle can stay smaller than first impressions suggest.

### 1. Availability-first
Use this when the disputed proposition is mainly **could this viewer see/use the lane at all, and if not why not?**

Normal carried set:
- one of `570` or `581` as the anchor,
- plus `562` only if visible pane state itself must be shown,
- plus one of `572`, `575`, `576`, or `573` only when the claimed availability/remediation posture actually depends on that substrate fact.

### 2. Framing-first
Use this when the disputed proposition is mainly **what kind of question environment was the viewer in before or during the turn?**

Normal carried set:
- one of `563`, `580`, or `577` as the anchor,
- plus `579` only if the selected output class is part of the disputed proposition,
- plus `562` only if the pane/answer visibility posture itself is still needed for reconstruction.

### 3. Answer-proof-first
Use this when the disputed proposition is mainly **what one answer card or no-answer card actually showed.**

Normal carried set:
- `567` when answer-versus-no-answer disposition is the center of gravity,
- plus exactly one of `565`, `566`, `568`, `569`, `574`, `578`, or `579` when that second doc bears the specific card property being proved,
- with the head still cited separately for the controlling current route.

### 4. Repair-first
Use this when the disputed proposition is mainly **who could fix or re-enable the same lane, and what substrate issue made that repair path relevant.**

Normal carried set:
- `581` as the anchor,
- plus one of `572`, `573`, `575`, or `576` only when the cited repair path actually depends on floor/fit, governing-transcript, language-alignment, or terminology-repair posture,
- plus `570` only when the same note must also prove that the viewer-facing result was visible absence or bounded exposure.

If a capture cleanly fits one of these four profiles, start there before you reach for a custom four-doc AI bundle.
Only leave the starter profile when a second independently material proposition truly has to travel.

## Compression ladder when a custom AI bundle is still too big

Sometimes a maintainer already picked the right starter profile and the packet or sentence is **still** carrying too many co-true AI facts.
When that happens, compress by subtraction in a stable order instead of rebuilding the bundle from scratch.
The default is:

1. keep the **profile anchor**;
2. keep at most **one modifier** that bears the disputed proposition if the anchor alone would be too lossy;
3. treat every remaining co-true AI fact as presumptively demotable to short prose, `companions_overflow=`, or a scoped `528` note.

Use this profile-specific ladder before you improvise a custom reduction:

| Starter profile | Keep longest | Drop first | Keep this pair last before collapsing to one doc |
|---|---|---|---|
| `availability-first` | one of `570`/`581`, plus one governing-substrate modifier from `572`, `573`, `575`, or `576` when that substrate fact is what explains the visible result | `562` when pane visibility is already implicit; then whichever substrate modifier is merely explanatory residue rather than the disputed reason | anchor `570` or `581` + one decisive substrate modifier |
| `framing-first` | one of `563`/`580`/`577`, plus `579` only when output class is part of the claim | `562` first; then `580` before `563` when the real issue is actual follow-up conditioning rather than menu inventory; then `577` when scope bounds are not the disputed proposition | framing anchor + `579` only if task mode itself must survive |
| `answer-proof-first` | `567` when answer-versus-no-answer is central, plus exactly one card-property modifier from `565`, `566`, `568`, `569`, `574`, `578`, or `579` | `569` first unless feedback/report controls are the claim; then `568` when warning posture is only wrapper residue; then whichever of `565`/`566`/`574` is merely corroborative rather than the proposition being proved | `567` + one decisive card-property modifier |
| `repair-first` | `581`, plus one decisive substrate dependency from `572`, `573`, `575`, or `576` | `570` first unless the same note must also prove viewer-facing absence/exposure; then any second substrate fact that merely narrates the repair path without changing who could fix it | `581` + one decisive substrate dependency |

The practical default is therefore **anchor, one modifier, then stop**.
If the packet still feels incomplete after that compression, the likely problem is not missing companions but a missing short sentence that explains how the already-carried docs relate.

## Citation-side consequence

The same tie-breaker logic applies downstream in `530`.
If one sentence is proving one bounded proposition, cite the **single AI companion that actually bears that proposition** and keep other co-true AI facts in scoped prose unless they support a second independently material claim.
Do not cite two near-neighbor AI companions merely to recreate the whole answer card in citation form.
After a sentence is already proved, a follow-on sentence that only glosses the same proved proposition should default to short prose or scoped overflow rather than a second near-neighbor citation.

## Claim isolation before you add a second AI citation

When a sentence still seems to want three AI facts even after the starter-profile and compression-ladder steps, reviewers SHOULD first ask whether the prose is actually trying to prove **more than one bounded proposition at once**.
Usually it is.

Common smell:
- one clause proves **viewer exposure / who could repair it** (`570` or `581`),
- another proves **thread/prompt framing** (`563`, `577`, `580`),
- and a trailing clause proves one **answer-card property** (`565`, `566`, `567`, `568`, `569`, `574`, `578`, or `579`).

That is usually not one sentence that needs three AI citations.
It is usually two or three propositions wearing one sentence.

Use this rule:
1. pick the smallest honest starter profile;
2. compress to **anchor + at most one true modifier**;
3. if the sentence still wants another AI doc, split the prose before you add another citation.

Keep two AI citations in one sentence only when the second doc is genuinely a **modifier on the same bounded proposition** and splitting the sentence would lose the relation, timing, or comparative force.
Otherwise, split.

Compact examples:
- prove **viewer-facing absence because of gating** with `570`; put later owner repair authority in a second sentence under `581` only if that repair path matters too;
- prove **follow-up-conditioned answer** with `563`; put transcript-only basis in a second sentence under `566` only if provenance itself matters;
- prove **no-answer disposition** with `567`; put the visible warning label in a second sentence under `568` only if the caution posture is independently material;
- prove **remediation path depended on transcript repair** with `581` + one substrate modifier (`572`, `573`, `575`, or `576`) only when that dependency is the same proposition, not a second narrative fact.

This is the sentence-level version of the packet-budget rule:
**one bounded claim, one AI anchor, optional true modifier, then split.**

## Local anchor reuse and modifier reset after you split

Once claim isolation has turned one overloaded AI sentence into two or three smaller sentences, reviewers SHOULD avoid a second failure mode: acting as if the first AI citation now quietly covers the whole mini-paragraph.

Use this bounded local-cluster rule:
1. a split AI paragraph may keep one local anchor across **only the immediately adjacent sentence** when that sentence is still proving the same bounded proposition family and no new AI family has been introduced;
2. **modifiers do not inherit** — a second sentence that changes the decisive modifier (for example from `570` viewer exposure to `581` repair authority, or from `563` thread conditioning to `566` transcript-only basis) must restate/re-cite its own modifier or re-anchor completely;
3. when the paragraph crosses from one starter profile to another, **reset** — do not let a first-sentence `availability-first` anchor silently carry a later `repair-first`, `framing-first`, or `answer-proof-first` proposition;
4. two-sentence clusters are normal, three-sentence clusters need an explicit reason, and anything longer should usually re-anchor.

Compact examples:
- prove **viewer-facing absence because of gating** with `570`; if the next sentence is about who could enable the lane later, reset under `581` instead of letting exposure evidence silently carry remediation authority;
- prove **follow-up-conditioned answer** with `563`; if the next sentence is about transcript-only basis, reset under `566` instead of treating thread state as inherited provenance;
- prove **no-answer disposition** with `567`; if the next sentence is about a visible warning label, keep `568` separate unless the warning posture is truly the modifier on the same bounded proposition.

This is the paragraph-level companion to the sentence-splitting rule:
**a local anchor may travel one sentence; modifiers still reset when the proposition family changes.**


## Residue demotion before you re-cite the same AI neighborhood

After starter-profile selection, compression, claim isolation, and the local-anchor / modifier-reset rule, one more failure mode remains: **citation echo**.
That is when the first sentence already proved the bounded AI proposition, but the next sentence restates context, explanation, or contrast and gets a second same-neighbor citation mostly out of stylistic caution.

Use this default:
1. if sentence two adds **no new disputed AI proposition**, demote it to short prose or `companions_overflow=` rather than adding a fresh same-neighbor citation;
2. if sentence two only clarifies mechanism, chronology, or why the already-carried anchor mattered, keep the anchor in local memory and do not automatically cite again;
3. only re-cite when sentence two changes the bounded proposition, changes the decisive modifier, or would become contestable if separated from the first sentence.

Compact tests:
- **drop test** — if deleting the second citation leaves the sentence still honestly supported by the first sentence's carried anchor, drop the second citation;
- **contestability test** — if the second sentence would attract a real challenge on its own, re-anchor or re-cite it;
- **overflow test** — if the sentence is informative but not proposition-bearing, move the detail to scoped prose or `companions_overflow=` instead of rebuilding a citation cluster.

Compact examples:
- sentence one proves **viewer-facing absence because of gating** with `570`; sentence two says this likely reflected phased rollout language already visible in the same card — keep sentence two as prose unless it introduces a new disputed gating proposition;
- sentence one proves **follow-up-conditioned answer** with `563`; sentence two notes that the visible prompt strip looked short or guided — keep that as overflow unless prompt inventory itself is now material under `580`;
- sentence one proves **no-answer disposition** with `567`; sentence two says the surrounding card still looked polished or friendly — that is usually uncited residue unless disclaimer posture or safety controls are themselves being claimed under `568` or `578`.

This is the final anti-fragmentation backstop for the AI tail:
**after you split and reset correctly, demote explanatory residue before you re-cite the same neighborhood.**

## Connector discipline before you coordinate two AI propositions

After starter-profile selection, compression, claim isolation, local-anchor reset, and residue demotion, one last sentence-level failure mode remains: **connector smuggling**.
That is when a writer uses `but`, `while`, `although`, `still`, or a similar hinge so one sentence looks grammatically compact even though it is quietly asserting **two AI propositions that would point to different companions if written separately**.

Use this default:
1. treat a coordinated or contrastive clause that would want a different AI companion on its own as a **second bounded proposition**, not as harmless sentence glue;
2. if the second clause changes starter profile, companion family, or decisive modifier, split the sentence and re-anchor instead of letting the connector pretend one citation now covers both halves;
3. keep one sentence only when the second clause is a genuine **same-proposition modifier** and the comparative force would be lost by splitting.

Compact tests:
- **connector test** — if the clause after `but`/`while`/`although` would attract a different AI companion when written alone, split;
- **severability test** — if the second clause can stand as its own honest sentence, it is usually its own proposition;
- **modifier test** — keep one sentence only when the second clause merely narrows the first claim instead of adding a second claim-bearing fact.

Compact examples:
- prove **viewer-facing absence because of gating** with `570`; if the same sentence continues `but the owner could enable it later`, split and move that repair-authority fact under `581` only if it matters;
- prove **follow-up-conditioned answer** with `563`; if the sentence continues `while the platform said it used the transcript`, split and carry provenance under `566` only if provenance is itself disputed;
- prove **no-answer disposition** with `567`; if the sentence continues `although a warning label was visible`, split and carry `568` only when the warning posture is independently material;
- prove **repair path depended on transcript correction** with `581` + one substrate modifier; if the sentence also says the viewer still lacked access, decide the center of gravity or split rather than letting one conjunction make `581` and `570` look like one proposition.

This is the connector-level companion to claim isolation:
**if a hinge word would make a second companion seem necessary, treat that hinge as a likely split point first.**

## Parenthetical discipline before punctuation hides a second AI proposition

After connector discipline, one more sentence-level failure mode remains: **parenthetical smuggling**.
That is when a writer uses an em dash, parentheses, a comma-setoff appositive, or similar inline wrapper so the line still *looks* like one proposition even though the parenthetical clause would point to a different AI companion if it stood on its own.

Use this default:
1. if the parenthetical, dash-clause, or appositive would want a different AI companion when written as a sentence, treat it as a **second bounded proposition**, not as harmless inline gloss;
2. punctuation does **not** grant free inheritance — if the inline clause changes starter profile, companion family, or decisive modifier, split or re-anchor instead of letting punctuation widen one citation's scope;
3. keep one sentence only when the inline material is genuinely non-claim-bearing gloss or a true same-proposition modifier whose comparative force would be lost by splitting.

Compact tests:
- **lift test** — if the parenthetical can be lifted into an honest sentence that would call for a different AI companion, split;
- **punctuation-neutrality test** — changing dash / parentheses / comma-setoff punctuation into a period should not change the governing companion; if it does, split;
- **appositive test** — naming or identification gloss may stay inline, but claim-bearing remediation, provenance, gating, warning, or outcome facts do not get to piggyback as appositives.

Compact examples:
- prove **viewer-facing absence because of gating** with `570`; if the same line adds `(the owner can enable it later)`, split and carry that repair-authority fact under `581` only if it matters;
- prove **follow-up-conditioned answer** with `563`; if the line adds `— using transcript-only basis —`, split and carry provenance under `566` only if provenance is itself disputed;
- prove **no-answer disposition** with `567`; if the line adds `(with an informational warning visible)`, split and carry `568` only when the warning posture is independently material;
- prove **repair path depended on transcript correction** with `581` + one substrate modifier; if a comma-setoff tail also says the viewer still lacked access, either center the sentence on `570` or split rather than hiding viewer exposure inside an appositive.

This is the punctuation-level companion to the connector rule:
**punctuation does not make a second AI proposition free.**

## Comparative and exception discipline before one sentence claims both baseline and delta

After parenthetical discipline, one more sentence-level failure mode remains: **comparative compression**.
That is when a writer uses `not X but Y`, `rather than`, `instead`, `except`, `unless`, or similar phrasing so the line still *sounds* like one compact claim even though it is really asserting both a **baseline/carve-out proposition** and a **different decisive AI proposition** that would point to another companion if written separately.

Use this default:
1. if the comparison baseline, rejected alternative, or exception clause would want a different AI companion when written positively on its own, treat it as a **second bounded proposition**, not as free contrast residue;
2. if the comparative or exception clause changes starter profile, companion family, or decisive modifier, split or re-anchor instead of letting the comparison make one citation seem to cover both the delta and the baseline;
3. keep one sentence only when the comparison is genuinely operating on the **same bounded axis** and the baseline is only clarifying what the carried anchor already means.

Compact tests:
- **baseline test** — if the phrase after `rather than` / `instead of` / `not ... but ...` would attract a different AI companion when written as a positive sentence, split;
- **exception test** — if the phrase after `except` / `unless` / `only when` creates a second contestable AI fact instead of merely narrowing the first, split;
- **delta test** — keep one sentence only when the comparison changes degree on the same bounded proposition rather than asserting a second proposition family.

Compact examples:
- prove **viewer-facing absence because of gating** with `570`; if the same line says `rather than because the owner disabled or had not enabled the lane`, split and carry repair authority under `581` only if that second proposition matters;
- prove **follow-up-conditioned answer** with `563`; if the line says `instead of a pre-suggested prompt path`, split and carry prompt inventory under `580` only when the guided-prompt baseline is itself disputed;
- prove **no-answer disposition** with `567`; if the line says `but with an informational warning rather than a hard refusal`, split and carry `568` only when warning posture is independently material;
- prove **repair path depended on transcript correction** with `581` + one substrate modifier; if the same sentence says the viewer still lacked ordinary access `unless` the owner repaired the transcript, either center the sentence on `570` or split rather than letting the exception clause make exposure and remediation look like one proposition.

This is the comparison-level companion to the connector and punctuation rules:
**a baseline, rejected alternative, or exception clause does not make a second AI proposition free.**

## Cause-result discipline before one sentence claims both outcome and reason

After comparative discipline, one more sentence-level failure mode remains: **cause-result compression**.
That is when a writer uses `because`, `since`, `so`, `therefore`, `which meant`, `due to`, or similar phrasing so the line still *sounds* like one compact explanation even though it is really asserting both a **visible AI result** and a **different reason/trigger proposition** that would point to another companion if written separately.

Use this default:
1. if the stated cause, trigger, or consequence would want a different AI companion when written as its own sentence, treat it as a **second bounded proposition**, not as free explanatory glue;
2. if the reason/result phrasing changes starter profile, companion family, or decisive modifier, split or re-anchor instead of letting causal language make one citation seem to prove both the outcome and the reason;
3. keep one sentence only when the causal wording is genuinely operating inside the **same bounded proposition** and the second clause merely narrows degree or timing rather than adding an independently contestable AI fact.

Compact tests:
- **reason test** — if the phrase after `because` / `since` / `due to` would attract a different AI companion when written positively on its own, split;
- **result test** — if the phrase after `so` / `therefore` / `which meant` would attract a different AI companion when written as its own sentence, split;
- **dependency test** — keep one sentence only when the reason/result wording stays within the same carried proposition rather than asserting a second reason-bearing or outcome-bearing fact.

Compact examples:
- prove **no-answer disposition** with `567`; if the same line says `because the transcript floor was not met`, split and carry `572` only when the floor/fit reason is itself disputed;
- prove **viewer-facing absence because of gating** with `570`; if the same line says `because the owner had not enabled or repaired the lane`, split and carry `581` only when repair authority is itself material;
- prove **follow-up-conditioned answer** with `563`; if the line says `because the platform said it used transcript-only basis`, split and carry provenance under `566` only if provenance is independently contested;
- prove **repair path depended on transcript correction** with `581` + one substrate modifier; if the same sentence says this `therefore` prevented the viewer from using the lane, either center the sentence on `570` or split rather than letting causal phrasing make remediation and viewer exposure look like one proposition.

This is the cause/result-level companion to the connector, punctuation, comparison, and exception rules:
**a reason clause or consequence clause does not make a second AI proposition free.**


## Conditional and hypothetical discipline before one sentence claims both present state and contingent path

After cause-result discipline, one more sentence-level failure mode remains: **conditional or hypothetical compression**.
That is when a writer uses `if`, `when`, `once`, `only if`, `otherwise`, `would`, `could`, or similar phrasing so the line still *sounds* like one compact description even though it is really asserting both a **present AI state** and a **contingent recovery / enablement / alternate-path proposition** that would point to another companion if written separately.

Use this default:
1. if the condition, contingent path, or hypothetical recovery would want a different AI companion when written as its own sentence, treat it as a **second bounded proposition**, not as free planning or explanatory glue;
2. if the conditional or hypothetical clause changes starter profile, companion family, or decisive modifier, split or re-anchor instead of letting contingency language make one citation seem to prove both the present state and the contingent path;
3. keep one sentence only when the condition genuinely stays inside the **same bounded proposition** and merely narrows timing or degree rather than adding an independently contestable AI fact.

Compact tests:
- **condition test** — if the phrase after `if` / `when` / `once` / `only if` would attract a different AI companion when written positively on its own, split;
- **counterfactual test** — if the phrase with `would` / `could` / `otherwise` describes a different recovery, enablement, or alternate-path fact than the present state already carried, split;
- **present-state test** — keep one sentence only when the conditional wording merely narrows the already-carried proposition instead of asserting a second state-bearing or path-bearing fact.

Compact examples:
- prove **viewer-facing absence because of gating** with `570`; if the same line says the viewer `could` use it `once` the owner enabled or repaired it, split and carry `581` only when that contingent remediation path is itself material;
- prove **no-answer disposition** with `567`; if the line says an answer `would` appear `if` the transcript floor were met, split and carry `572` only when that threshold claim is independently disputed;
- prove **follow-up-conditioned answer** with `563`; if the same sentence says the answer `would` change `when` the platform switched from transcript-only basis to another basis, split and carry `566` only if that provenance shift is itself material;
- prove **repair path depended on transcript correction** with `581` + one substrate modifier; if the same sentence says the viewer would then regain ordinary access, either center the sentence on `570` or split rather than letting hypothetical recovery language make remediation and current exposure look like one proposition.

This extends the firewall's sentence-scope drift families into contingent and hypothetical clauses:
**a condition clause or hypothetical recovery path does not make a second AI proposition free.**

## Temporal and transition discipline before one sentence claims both current state and prior/later state

After conditional discipline, one more sentence-level failure mode remains: **temporal or transition compression**.
That is when a writer uses `before`, `after`, `then`, `until`, `already`, `still`, `no longer`, `yet`, or similar phrasing so the line still *sounds* like one compact state description even though it is really asserting both a **current AI state** and a **prior, later, or phase-change proposition** that would point to another companion if written separately.

Use this default:
1. if the earlier-state, later-state, or phase-change clause would want a different AI companion when written as its own sentence, treat it as a **second bounded proposition**, not as free timeline glue;
2. if the temporal or transition clause changes starter profile, companion family, or decisive modifier, split or re-anchor instead of letting sequence language make one citation seem to prove both the current state and the prior/later state;
3. keep one sentence only when the timing language genuinely stays inside the **same bounded proposition** and merely narrows recency, persistence, or observation window rather than adding an independently contestable transition fact.

Compact tests:
- **before/after test** — if the phrase after `before` / `after` / `then` would attract a different AI companion when written positively on its own, split;
- **persistence test** — if `still`, `already`, `yet`, or `no longer` is really asserting an earlier or later state that would need a different anchor, split;
- **window test** — keep one sentence only when the timing word merely narrows when the already-carried state was observed instead of asserting a second phase-change fact.

Compact examples:
- prove **viewer-facing absence because of gating** with `570`; if the same line says the lane appeared only **after** the owner enabled or repaired it, split and carry `581` only when that transition path is itself material;
- prove **no-answer disposition** with `567`; if the same sentence says the answer appeared **after** the transcript floor was met, split and carry `572` only when that threshold transition is independently disputed;
- prove **follow-up-conditioned answer** with `563`; if the same line says the thread looked different **before** the prompt basis switched, split and carry `566` only when that provenance transition is itself material;
- prove **warning/disclaimer visibility** with `568`; if the same sentence says the warning was **no longer** shown once the lane exited preview, split and carry the later task-mode or release-state fact only if that second phase-change proposition matters.

This extends the firewall's sentence-scope drift families into temporal and transition clauses:
**a prior-state or later-state clause does not make a second AI proposition free.**

## Attribution and reported-speech discipline before one sentence claims both observed state and declared basis

After temporal discipline, one more sentence-level failure mode remains: **attribution or reported-speech compression**.
That is when a writer uses `said`, `according to`, `described as`, `reported`, `labeled`, `called`, `presented as`, or similar phrasing so the line still *sounds* like one compact observation even though it is really asserting both a **viewer-observed AI state** and a **platform-declared explanation, basis, or characterization** that would point to another companion if written separately.

Use this default:
1. if the attributed clause would want a different AI companion when written as its own sentence, treat it as a **second bounded proposition**, not as free sourcing glue;
2. if the attribution changes starter profile, companion family, or decisive modifier, split or re-anchor instead of letting reported-speech phrasing make one citation seem to prove both the observed state and the declared explanation;
3. keep one sentence only when the attribution merely quotes or names the **same already-carried proposition** and does not add an independently contestable basis, label, warning, gating reason, or remediation fact.

Compact tests:
- **attribution test** — if the phrase after `said` / `according to` / `reported` would attract a different AI companion when written as its own sentence, split;
- **paraphrase test** — if removing the attribution and writing the declared point as a plain sentence changes the governing companion, split;
- **label test** — if the platform's own label, basis claim, or explanation would still matter even if the visible state were undisputed, re-anchor it.

Compact examples:
- prove **no-answer disposition** with `567`; if the same line says the platform `said` the transcript was not sufficient, split and carry `572` only when that floor/fit claim is independently disputed;
- prove **visible grounding cues** with `565`; if the same line says the platform `said` the answer drew on the transcript or the web, split and carry `566` only when the declared source basis is itself material;

## Quantifier and distribution discipline before one sentence claims both local observation and population scope

After attribution discipline, one more sentence-level failure mode remains: **quantifier or population-scope compression**.
That is when a writer uses `some`, `many`, `most`, `all`, `only`, `everyone`, `nobody`, `widely`, `generally`, or similar phrasing so the line still *sounds* like one compact observation even though it is really asserting both a **local viewer-observed AI state** and a **broader distribution / rollout / prevalence proposition** that would point to `570` or another companion if written separately.

Use this default:
1. if the quantifier or population-scope clause would attract a different AI companion or a materially different scope claim when written as its own sentence, treat it as a **second bounded proposition**, not as free prevalence glue;
2. if the sentence moves from one viewer/account/channel observation to a cross-viewer, cross-account, cross-channel, or rollout-wide claim, split or re-anchor instead of letting quantifier phrasing make one citation seem to prove both;
3. keep one sentence only when the quantifier merely narrows the already-carried proposition's explicit scope and does not add an independently contestable prevalence, rollout, or eligibility claim.

Compact tests:
- **population test** — if the phrase with `some` / `most` / `all` / `only` would still matter as its own challenged sentence, split;
- **scope-jump test** — if the line moves from “this viewer saw X” to “others generally could or could not see X,” split or re-anchor under `570`;
- **prevalence test** — keep one sentence only when the quantifier simply restates the already-declared capture scope instead of asserting a broader rollout or distribution fact.

Compact examples:
- prove **answer-visible for this viewer** with `562` or `567`; if the same line says **only some viewers** or **most accounts** saw that state, split and carry `570` only when the broader rollout claim is itself material;
- prove **viewer-facing absence because of gating** with `570`; if the same line says **everyone else** or **many other viewers** already had the lane, split unless that distribution claim is the disputed proposition;
- prove **owner/admin remediation path** with `581`; if the same line says **only some channels** or **all verified owners** could request repair, split and keep that wider authority-distribution claim separate unless it is the actual proposition at issue;

## Modal, permission, and recommendation discipline before one sentence claims both observed state and allowed/required path

## What should trigger another numbered AI-tail doc after `582`?

1. **The ambiguity is not already owned by `499`, `523`, `527`, `530`, or one of `561–581`.**
