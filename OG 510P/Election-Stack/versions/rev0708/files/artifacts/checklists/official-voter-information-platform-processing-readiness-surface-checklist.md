# Official voter-information platform processing-readiness surface checklist

Use this checklist when official voter-information media is publicly reachable before higher-quality renditions, replay derivatives, or transcript/caption sidecars are fully ready.

## Scope

- [ ] Reviewed the exact public media route that became reachable while processing was still underway.
- [ ] Distinguished processing/readiness state from the current written/help lane and from later steady-state playback/transcript behavior.
- [ ] Recorded which source pages, replay shells, or embeds were materially relied on during the processing window.

## Readiness-state review

- [ ] Verified whether higher-quality options were still processing when the public route first became available.
- [ ] Verified whether transcript/caption generation lagged the upload or replay publication.
- [ ] Checked whether the route showed a visible pending-processing or optimization state that could be mistaken for a finished publication.

## Currentness and fallback posture

- [ ] Verified the current written/help lane remained recoverable while media derivatives were still being processed.
- [ ] Verified action-changing instructions did not rely solely on qualities, captions, or transcript panes that were not ready yet.
- [ ] Verified the office did not treat ordinary URL reachability as proof that the reviewed steady-state media surface was already available.

## Recovery and closure

- [ ] Logged whether transcript generation had to be initiated manually or whether processing appeared stalled.
- [ ] Logged when the office considered the media route sufficiently ordinary to review as a stable public-answer surface.
- [ ] Verified the canonical office page or named office contact stayed visible until the processing window ended.

## Public proof posture

- [ ] Logged which readiness states were reviewed and when.
- [ ] Avoided publishing internal transcoding telemetry, individualized watch analytics, or private admin traces.
