# Official voter-information platform event-chrome surface checklist

Use this checklist when official voter-information media is surrounded by organizer-controlled event theming, branded player chrome, live-shell decoration, or state-visibility settings.

## Scope

- [ ] Reviewed the exact public route whose event chrome mattered, not just a backstage or admin console.
- [ ] Logged the route state reviewed there (pre-live, live, behind-live, ended, replay, or mixed/unclear).
- [ ] Logged which shell elements were customized there (for example: banner, logo, theme color, trailer, layout, latest-video substitution, or live-status-label state).

## Chrome/state review

- [ ] Verified whether the shell made it easy to tell if the route was pre-live, live, replay, or another state.
- [ ] Checked whether the same route looked materially different across native, embedded, attendee-facing, or copied/share paths.
- [ ] Checked whether any customized shell element could make a merely decorative change look like a newer authoritative answer.

## Authority-boundary review

- [ ] Verified the office did not let banners, logos, colors, layouts, trailers, or hidden live-status cues stand in for the current written/help lane.
- [ ] Verified the current written/help lane remained recoverable even when the shell looked polished or highly official.
- [ ] Verified the office did not treat shell customization alone as proof that the route was current, live, or superseding.

## Public proof posture

- [ ] Logged the reviewed route, route state, chrome state, and review time.
- [ ] Avoided publishing private backstage tools, operator controls, or non-public production artifacts beyond what the public route itself exposed.
