# Voter-ID requirements surface checklist

- Name one authoritative public path for voter-identification requirements and one authoritative help path.
- Publish context-specific requirement summaries, not one oversimplified “bring ID” sentence for every voter and voting mode.
- Publish the exact status vocabulary used for `id_required`, `id_may_be_required`, `no_additional_id_required`, and `state_specific` contexts where applicable.
- Publish accepted document classes and any bounded qualifiers that materially affect voter actionability.
- Publish the official fallback path when a voter lacks the listed document or needs case-specific help.
- Treat acceptable-document changes, qualifier changes, and fallback-path changes as explicit superseding notices, not silent edits.
- Check parity across website, downloadable handout/PDF, mailed instructions where applicable, hotline/help script packet, poll-worker quick-reference material, and signed notices.
- Publish accessible and translated versions where required, plus the fallback path when the primary ID-information page fails.
- Do not publish scanned IDs, uploaded-document logs, matching thresholds, fraud heuristics, or individualized decision records.
- Record `last_verified_at` and the latest correction notice pointer.
