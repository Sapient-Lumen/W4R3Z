# Official voter-information tabbed-answer surface checklist

Use this checklist for official voter-information routes that place answer-bearing content inside tabs where one panel is visible at a time.

## Scope and panel inventory

- [ ] Identify the official routes where tabs control which answer-bearing panel is currently visible.
- [ ] Record the tab sets whose panels contain deadlines, exceptions, next steps, or help/recovery instructions.
- [ ] Record which panel is default-visible and why that default is acceptable for the public route.

## Labels and visible state

- [ ] Tab labels are meaningful to voters and identify the substantive difference among panels.
- [ ] The active tab is visually and programmatically distinguishable from inactive tabs.
- [ ] The visible panel begins with the controlling answer, qualifier, or next step rather than forcing the user to infer it from surrounding chrome.

## Interaction and reveal continuity

- [ ] Keyboard users can move through the tablist and reveal the associated panel without ambiguity about focus versus selection.
- [ ] If manual activation is used, the route does not leave voters thinking the visible panel changed when only focus changed.
- [ ] Pointer/touch use does not leave decisive panels stranded behind tiny, crowded, or ambiguous tab targets.
- [ ] Routes that point users to a specific answer lane reveal the relevant panel directly or make that panel obvious to open.

## Hidden-panel findability and return paths

- [ ] Hidden panels are not treated as sufficient public delivery on their own.
- [ ] Reopened, revisited, or restored routes do not silently return to the wrong active panel without visible guidance.
- [ ] If search-in-page, copied links, or fragment-style navigation matter for the route, the office checked whether answer-bearing hidden panels can be revealed through an ordinary public path.
- [ ] There is a visible escape path back to help, overview, or contact information when the current tab is not the right answer lane.

## Evidence discipline

- [ ] The review records the relevant tab sets, default-visible panels, label posture, and active-panel findings.
- [ ] The review records when the check occurred and which route/version was observed.
- [ ] The archive does not retain named-user clickstreams, individualized panel histories, or unnecessary replay exhaust for this bounded surface.
