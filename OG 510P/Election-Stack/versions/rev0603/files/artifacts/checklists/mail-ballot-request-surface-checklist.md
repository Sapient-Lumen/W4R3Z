# Mail-ballot request surface checklist

- Identify one authoritative public path for requesting a mail ballot and one authoritative help path.
- Publish the exact public terminology in use and explain whether voters must request a ballot or receive one automatically.
- Publish each official request method separately and attach explicit deadline semantics to each one.
- Publish whether the path is no-excuse, excuse-required, special-population-only, or otherwise state-specific.
- Publish the official alternate path when the primary request portal or form is unavailable.
- Publish any distinct military/overseas or other special-population request path when it differs from the ordinary domestic path.
- Treat changed methods, deadlines, eligibility rules, and help routing as explicit superseding notices, not silent edits.
- Check parity across website, downloadable form/PDF, mailed instructions where applicable, hotline/help script packet, and signed notices.
- Publish accessible and translated versions where required, plus a fallback contact path when the primary request page fails.
- Do not publish per-voter request logs, signatures, uploaded documents, or internal anti-fraud heuristics.
- Record `last_verified_at` and the latest correction notice pointer.
