# Official voter-information file-delivery surface checklist

- Inventory each official voter-information download link, attachment wrapper page, embedded document/PDF viewer, and alternate-format fallback the public may encounter.
- Make the delivery role explicit: the handoff helps the voter retrieve the current official file or companion artifact; it does not become the rule source by itself.
- Tell users when a destination is a non-HTML file and, when practical, give file context before or at handoff.
- Keep the current official page/help route recoverable from the file wrapper, download lane, or embedded viewer.
- Prefer current accessible HTML when it can safely carry the answer; use detached files when a portable packet, printable artifact, or retained record is actually needed.
- Do not let an embedded viewer hide the file edition, election scope, direct-download path, or current official help path.
- Keep a visible accessible or HTML fallback when the file or viewer is unsupported, fails, or is not the safest route for the user.
- Keep wrapper pages, embedded viewers, and downloadable files aligned on the controlling current edition/state.
- Mark, withdraw, demote, or explicitly supersede stale files instead of leaving older versions reachable as if they still control.
- Do not let a stale cached viewer state silently outrank a newer signed notice or current page.
- Use a small result-state taxonomy so the handoff can distinguish current HTML-primary with file companion, current file-primary with HTML summary, superseded/withdrawn file state, and unsupported/accessibility fallback.
- Preserve a bounded file trace for action-changing outputs, including policy version, promoted file/object identifier, presented modality, file-type/wrapper context, result-state class, and timestamp.
- Do not retain detailed per-user download or viewer telemetry longer than the published policy requires.
- Do not turn file-open analytics into a shadow case-management or profiling surface.
- Keep the current office/help fallback visible, including phone/help routing when one exists.
- Re-check the file-delivery layer after edition changes, form replacements, deadline changes, location/hour changes, translation changes, viewer swaps, CMS migrations, or superseding notices.
- When material file or viewer behavior changes, publish an explicit update/superseding note instead of relying only on silent UI edits.
