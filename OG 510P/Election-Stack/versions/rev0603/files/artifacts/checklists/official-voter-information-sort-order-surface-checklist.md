# Official voter-information sort-order surface checklist

Use this checklist for official voter-information routes where **non-table answer-bearing items** can appear in different visible orders through a default order, a sort control, or a routine dynamic reorder.

## Default order and control clarity

- [ ] Record which official routes let the public change the visible order of answer-bearing items.
- [ ] Record the default ordering model for each route.
- [ ] Review whether the current order is visible without guesswork, including on compact/mobile layouts.
- [ ] Review whether sort labels are ordinary-language and specific enough that voters can tell what “newest,” “nearest,” “alphabetical,” or “recommended” means on the route.
- [ ] Review whether the control changes order only on explicit commit rather than on focus, highlight, or other intermediate movement.

## Ordering meaning and continuity

- [ ] Review whether the first visible item could be mistaken for a substantive official priority claim when it is only first because of the current order.
- [ ] Review whether separately featured or promoted items are labeled distinctly from the ordinary sorted set.
- [ ] Review whether changing sort reorders the same official set or also changes scope, and whether that boundary is visible.
- [ ] Review whether a voter can return to the default order or otherwise recover a predictable ordering without guesswork.
- [ ] Review whether a controlling item can be re-found after a routine reorder.

## Accessibility and dynamic updates

- [ ] Review whether headings, metadata, and link purpose still make sense when a different item becomes first after reorder.
- [ ] Review whether dynamic order changes are exposed as status updates without unnecessary focus movement.
- [ ] Review whether the route preserves logical focus behavior when resorting, especially for keyboard and magnifier users.
- [ ] Review the implemented route, not only isolated components, for compact/mobile layouts where the current order can disappear behind collapsed controls.
- [ ] Review that non-table routes do not rely on table/grid sort semantics as a substitute for visible order labeling.

## Evidence discipline

- [ ] Preserve a small public digest of default order, available orderings, current-order visibility, and verification time.
- [ ] Preserve bounded review evidence that order changes were checked for legibility and re-findability.
- [ ] Do not retain named-user sort histories, individualized click-order trails, session replay, or other interaction exhaust merely to prove a reorder existed.
