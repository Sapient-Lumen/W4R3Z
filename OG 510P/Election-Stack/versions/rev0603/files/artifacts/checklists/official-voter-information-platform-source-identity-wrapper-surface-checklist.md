# Official voter-information platform source-identity-wrapper surface checklist

Use this checklist when official voter-information media is presented with platform-native bylines, handles, profile names, profile photos, verification badges, creator URLs, uploader names, or profile-card identity cues.

## Scope

- [ ] Reviewed the exact public media route whose source-identity cues mattered, not just the channel settings view or a private admin console.
- [ ] Logged which platform and wrapper type was reviewed (native watch page, showcase, collection page, embed, SharePoint page, file card, or similar).
- [ ] Recorded which identity cues were materially relied on by the office or likely to matter to the public.

## Identity-cue review

- [ ] Verified which source cues were actually shown (for example: channel name, handle, profile photo, verification badge, creator URL, uploader/owner name, or profile card).
- [ ] Checked whether those cues matched the office’s current official-channel directory binding and recognizable jurisdiction identity.
- [ ] Checked whether channel-name, handle, badge, or profile-photo state could drift independently of the current written/help lane.

## Authority-boundary review

- [ ] Verified the office did not let a badge, byline, familiar handle, or uploader card stand in for currentness, legal effect, or the current written/help lane.
- [ ] Verified the current written/help lane remained recoverable even if the route looked official from identity cues alone.
- [ ] Verified legacy or successor account transitions remained recoverable where older handles, screenshots, or copied links could still circulate.

## Cross-wrapper review

- [ ] Checked whether source-identity cues differed across native, showcase, collection, embedded, mirrored, or file/page wrappers.
- [ ] Checked whether a partner wrapper or file/page presentation preserved some identity cues while dropping others.
- [ ] Logged any material mismatch between account identity cues and the route the office currently asks the public to trust.

## Public proof posture

- [ ] Logged the reviewed route, the identity cues shown there, and when the review occurred.
- [ ] Avoided publishing private account-management data, internal staff rosters, or unnecessary person-level telemetry beyond what the public route already exposed.
