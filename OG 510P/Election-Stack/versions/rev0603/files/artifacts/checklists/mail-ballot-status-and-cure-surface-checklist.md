# Mail-ballot status and cure surface checklist

- Name one authoritative public status-check path and one authoritative cure/help path.
- Publish the exact voter-facing status labels with plain-language explanations.
- Distinguish `received` from `accepted` and `needs_action` from final rejection.
- Publish effective dates/times and a freshness note for the current public answer surface.
- Publish accessible and translated versions where required, plus the fallback path when the primary portal fails.
- Treat cure-deadline or action-path changes as explicit superseding notices, not silent edits.
- Publish an outage/degraded-service notice if the status surface is unavailable or stale in a time-sensitive window.
- Check parity across website, state portal, hotline/help script packet, and signed notices.
- Do not publish per-voter histories, signature images, IDs, cure affidavits, or matching heuristics.
- Record `last_verified_at` and the latest correction notice pointer.
