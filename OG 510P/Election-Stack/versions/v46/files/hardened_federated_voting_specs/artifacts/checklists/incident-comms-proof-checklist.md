# Incident Communications + Proof Checklist

## Before publishing
- [ ] Identify relevant checkpoint(s): ID + hash
- [ ] Identify EPB hash and inclusion proof status
- [ ] Identify whether intake is active, degraded, or frozen
- [ ] Confirm whether the issue is integrity, availability, or both

## Publish (minimum)
- [ ] Signed public statement (what happened, what we know, what we don’t)
- [ ] Status page update + current checkpoint info
- [ ] If applicable: drift alert / fork proof / missed-deadline evidence

## Avoid
- [ ] No over-claims (“safe”, “secure”) without precise basis
- [ ] No PII disclosure
- [ ] No operational details that increase attacker advantage

## After publishing
- [ ] Preserve evidence bundle and record chain-of-custody
- [ ] Notify stakeholders (election officials, witnesses, trustees)
- [ ] Schedule update cadence and next statement time
