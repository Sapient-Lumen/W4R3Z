# 160. Generated canonical spec contract (no silent drift)

**Track:** Shared


This archive has multiple “views” of the system: prose specs, schemas, checklists, examples.
To prevent silent semantic drift (especially when LLMs are involved), we adopt a small set of
**single-source-of-truth** rules and generated artifacts.

Normative language uses BCP 14 (RFC 2119/RFC 8174) where appropriate.

## 160.1 What is generated in v33

1. **Schema catalog**
   - `schemas/SCHEMA_CATALOG.md` is generated by `scripts/gen_schema_catalog.py`.
2. **Archive manifest**
   - `MANIFEST.sha256` is generated by `scripts/build_manifest.py`.

## 160.2 Determinism requirement

Given identical inputs (file bytes) and tool versions, generators MUST produce
byte-for-byte identical output.

## 160.3 CI / review guidance (recommended)

A CI lane (or manual check) SHOULD enforce:
- `scripts/gen_schema_catalog.py` has been run and the output is committed.
- `scripts/build_manifest.py` has been run and the output is committed.
- `13-artifact-index.md` includes every numbered doc.
- lockfile entries are pinned (sha256 present) for all “must-follow” upstream sources.

## 160.4 Reviewer red flags

Treat as suspicious:
- editing generated outputs directly (catalog/manifest),
- adding normative wire semantics without updating a schema,
- changing receipts/proofs semantics without an ADR and version bump.
