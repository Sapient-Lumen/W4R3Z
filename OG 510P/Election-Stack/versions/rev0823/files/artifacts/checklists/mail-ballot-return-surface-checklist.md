# Mail-ballot return surface checklist

- Identify one authoritative public path for mail-ballot return instructions and one authoritative help path.
- Publish each lawful return method separately and attach explicit deadline semantics to each one.
- Publish the required return-envelope, declaration, signature, witness, notary, secrecy-envelope, and postage steps in bounded plain language.
- Distinguish request deadlines from return deadlines, and distinguish receipt, postmark, drop-box, and office-close semantics where those differ.
- Point to the current official drop-box directory or office-hours surface instead of burying directory data inside the return payload.
- Publish the official fallback path when the primary return method or location becomes unavailable.
- Publish a distinct specialized path when military/overseas or other legally different return methods apply.
- Treat changed return methods, envelope instructions, packet inserts, and deadline semantics as explicit superseding notices, not silent edits.
- Check parity across website, downloadable PDF instructions, mailed packet inserts, return-envelope text, hotline/help script packet, and signed notices.
- Publish accessible and translated versions where required, plus a fallback contact path when the primary return page fails.
- Do not publish per-voter return telemetry, signature images, witness identities, or internal acceptance heuristics.
- Record `last_verified_at` and the latest correction/advisory notice pointer.
