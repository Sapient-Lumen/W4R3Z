# Voting-issue reporting surface checklist

- Identify one authoritative public path for reporting or escalating voting problems.
- Publish issue-class routing explicitly rather than burying it in prose.
- Distinguish ordinary election help, formal state administrative complaint paths, civil-rights reporting, and emergency/law-enforcement escalation.
- Publish an explicit emergency rule for threats, violence, or intimidation rather than implying it.
- Publish the authoritative state administrative complaint path when one exists under HAVA.
- Publish the alternate official path when the primary office, hotline, or webform is unavailable.
- Treat changed hotline numbers, complaint forms, emergency instructions, and escalation routes as explicit superseding notices, not silent edits.
- Check parity across website, hotline scripts, PDFs, office directories, and signed notices.
- Publish accessible and translated reporting/help paths where required, plus relay or alternate communication methods when available.
- Do not publish complaint narratives, complainant details, investigative notes, or internal case-management identifiers.
- Record `last_verified_at` and the latest correction, outage, or escalation notice pointer.
