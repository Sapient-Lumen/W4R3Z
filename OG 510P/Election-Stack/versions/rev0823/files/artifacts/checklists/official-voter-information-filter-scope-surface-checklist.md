# Official voter-information filter-scope surface checklist

Use this checklist for official voter-information routes where **filters**, **facets**, **subset chips**, **scope toggles**, or similar controls decide which answer-bearing items are currently visible.

## Scope and route inventory

- [ ] Record which official routes narrow an answer-bearing set through filters/facets rather than showing the full set at once.
- [ ] Record whether the control model is single-select, multi-select, mixed by group, or otherwise specialized.
- [ ] Record which kinds of official items are being narrowed (locations, offices, FAQs, notices, deadlines, other).

## Group meaning and selection model

- [ ] Review whether each filter group has a clear label that says what question it is asking.
- [ ] Review whether the route makes clear when only one option may be selected versus many.
- [ ] Review whether selected choices remain visibly and programmatically exposed instead of depending on styling alone.

## Active subset visibility

- [ ] Review whether the route makes clear when the visible set is filtered rather than complete.
- [ ] Review whether zero-results states identify the active exclusions instead of implying the official answer does not exist.
- [ ] Review whether compact/mobile variants preserve the active-scope summary after filter controls collapse or close.

## Result updates and recovery

- [ ] Review whether meaningful result-set changes are announced without forcing a focus hunt.
- [ ] Review whether the route avoids disruptive auto-submission or otherwise explains immediate updates clearly.
- [ ] Review whether an ordinary clear/reset path returns the user to the broader official set.

## Evidence discipline

- [ ] Preserve a small public digest of the grouping model, active-scope visibility posture, result-update announcement posture, and clear/reset review.
- [ ] Do not retain individualized filter histories, clickstreams, replay exhaust, or person-level telemetry merely to prove the facet controls existed.
