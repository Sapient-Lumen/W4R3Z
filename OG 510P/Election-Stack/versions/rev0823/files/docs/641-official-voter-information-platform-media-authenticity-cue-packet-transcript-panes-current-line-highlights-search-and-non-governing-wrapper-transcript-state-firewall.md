## What this is for

Use `641` when a later packet preserves or reenacts a **visible wrapper transcript-state layer** around same-route detached derivatives:
- transcript side panels,
- `Show transcript` / `Transcript` posture,
- current-line highlights or follow-along scrolling,
- transcript-search boxes and filtered hit sets,
- transcript click-to-jump posture,
- `Return to current time` transcript posture,
- transcript-language or timestamp-visibility toggles,
- or similar later packet transcript foregrounding.

Those transcript surfaces are real packet facts and should be preserved honestly.
But they are still **later wrapper-added transcript-navigation / transcript-foregrounding posture**, not automatic proof of:
- a reviewed official transcript edition,
- source-native emphasis,
- source-native chronology,
- official translation,
- or the packet's governing member.

Current primary-source guidance is already enough to justify one bounded transcript-state bridge.
YouTube Help says viewers can click `Show transcript`, that the transcript scrolls to the current caption text while the video plays, that transcript lines can jump to specific parts of the video, and that some transcripts support keyword search.
Vimeo Help says viewers can open a transcript side panel, see the spoken words highlight and auto-scroll, click within the transcript to jump to timestamps, search for specific words, return to the current point in the video, change transcript language when multiple languages exist, and show or hide timestamps.
Microsoft Support says viewers can display or hide a video transcript, click transcript text to jump to that part of the video, and search transcript text for keywords and results.
That is enough for one bounded firewall here.
(xref: `youtube_view_video_transcripts_help_page`; xref: `vimeo_access_transcripts_video_page_help_page`; xref: `microsoft_video_transcripts_and_captions_help_page`)

`641` exists so maintainers can say:
**this packet preserved a later transcript pane/search/highlight layer around same-route detached derivatives, and that layer mattered for how later readers interpreted the packet, but the transcript layer itself does not silently prove a reviewed official transcript edition, source-native emphasis, source-native chronology, official translation, or the governing member.**

## Why this is distinct

`493` asks whether a later packet preserved **a transcript surface as a public-answer boundary around already-open media** — transcript panes, searchable transcripts, timestamp jumps, or downloadable/copyable transcript sidecars.

`557` asks whether the same current object preserved **transcript-pane state** — transcript open/closed posture, search-active posture, or current-line highlighting.

`573` asks whether translated or alternate visible transcript variants preserved **governing-transcript precedence** for the same AI answer.

`595` asks whether a later packet preserved **detached text extracts** — transcript lines, caption text, OCR text, or downloaded transcript text that survived outside the whole route.

`614` asks whether a later packet preserved **generic query posture** — search terms, find-hit lists, and result ordering.

`615` asks whether a later packet preserved **active selection/focus posture** — selected text ranges, active thumbnails, or active sidebar items.

`638` asks whether a later packet preserved **translation posture** — translated renderings, show-original posture, or language-pair badges.

`641` asks a different question:
**did a later packet add or preserve a visible transcript-navigation / transcript-foregrounding layer — transcript panes, current-line highlights, transcript search, transcript-language/timestamp toggles, or return-to-current-time posture — and did later readers start overreading that layer as if it proved a reviewed official transcript edition, source-native emphasis, source-native chronology, official translation, or the packet's governing member?**

If the real problem is transcript surfaces as current-route public-answer objects, use `493`.
If the real problem is same-object transcript-pane state, use `557`.
If the real problem is transcript-variant precedence for an AI answer, use `573`.
If the real problem is detached transcript text surviving outside the whole route, use `595`.
If the real problem is generic find/query posture, use `614`.
If the real problem is merely which transcript line or text range is active, use `615`.
If the real problem is transcript translation or show-original posture, use `638`.
Use `641` only when the missing distinction is **wrapper transcript-state posture itself**.

## Decision test

Use `641` when all three conditions hold:

1. later evidence preserves or reenacts a **visible transcript layer** around same-route detached derivatives — for example a transcript panel, current-line highlight, transcript-search hit list, `Show transcript` posture, `Return to current time` transcript state, or transcript-language/timestamp toggle;
2. that layer is **later wrapper-added transcript-navigation / transcript-foregrounding state**, not proof that the underlying source route itself officially published a reviewed transcript edition, officially privileged the highlighted lines, officially fixed chronology through transcript UI state, officially adopted a translated transcript, or officially made the packet governing; and
3. later readers are drifting toward treating that layer as if it proved **a reviewed official transcript edition, source-native emphasis, source-native chronology, official translation, or the governing member**.

If any condition fails, keep the packet under the narrower doc that already owns the real problem.
If the surviving packet is still mainly a transcript-boundary problem, same-object transcript-pane-state problem, governing-transcript-precedence problem, detached-text-derivative problem, query-state problem, selection-state problem, or translation-state problem with some visible transcript posture around it, keep transcript-surface authority in `493`, keep same-object transcript-pane state in `557`, keep governing-transcript precedence in `573`, keep detached text carry in `595`, keep generic query posture in `614`, keep active-focus posture in `615`, keep translation posture in `638`, and add one bounded `641` transcript-state note only if the visible transcript layer itself changed the reading.

## Keep transcript state, text carry, query state, selection state, and translation state separate

At minimum, keep these layers separate:
1. **current office control** — the current written/help lane and current media head (`194`, `529`, `530`);
2. **surviving detached derivative** — which `595–599` member, if any, the packet actually preserved;
3. **family routing** — whether the packet needed `600` because no single detached derivative dominated;
4. **transcript surface as current-route boundary** — transcript panes/search/jump/download posture on the already-open route (`493`);
5. **same-object transcript-pane state** — transcript open/closed, search-active, or current-line-highlight posture while the same object stayed current (`557`);
6. **governing transcript precedence** — which transcript variant actually governed an AI answer (`573`);
7. **detached text carry** — copied transcript/caption/OCR text that survived outside the whole route (`595`);
8. **wrapper-added query state** — search term, filtered hit set, or query framing (`614`);
9. **wrapper-added selection/focus state** — selected text range, active line, or active sidebar item (`615`);
10. **wrapper-added translation state** — transcript-language or translated-rendering posture (`638`);
11. **wrapper-added outline state** — transcript-related structure panes or chapter-like sidebars if that structure map itself matters (`640`);
12. **wrapper-added transcript state** — transcript panes, current-line highlights, transcript search, `Return to current time`, timestamp-visibility posture, or transcript-language toggles around detached derivatives (`641`);
13. **carrier wrapper** — slide deck, PDF memo, browser shell, doc shell, saved page, ticket, or email thread (`437`, `490`, `600`);
14. **assembly state** — whether later materials also fused several observations into one stronger-looking posture (`591`).

That separation matters because later packets can otherwise make two different mistakes:
- treating a visible transcript pane/search/highlight layer as if it proved the office actually published or reviewed that exact transcript posture as the controlling transcript edition; or
- letting a later transcript wrapper become evidence that the packet itself is governance-bearing, source-emphatic, source-chronological, or the governing member.

`641` exists so the archive can keep that later visible transcript layer **truthful but non-governing**.

## Minimal wrapper-transcript-state note grammar

When wrapper transcript state matters, reviewers SHOULD prefer one compact line in this shape:

`head=<current tuple|none>; governing_member=<595|596|597|598|599|600|none>; wrapper_transcript_kind=<transcript_panel|show_transcript|current_line_highlight|search_active|return_to_current_time|timestamp_toggle|language_toggle|mixed|unknown>; transcript_basis=<captions_backed|uploaded_transcript|auto_generated|meeting_transcript|mixed|unknown>; search_scope=<none|keyword_search|filtered_hits|jump_enabled|mixed|unknown>; source_transcript_edition_proved=<forbid>; source_emphasis_proved=<forbid>; source_chronology_proved=<forbid>; official_translation_proved=<forbid>; governing_member_from_transcript_state=<forbid>; carrier_wrapper=<browser_shell|doc_shell|pdf_shell|review_shell|slide_deck|saved_page|ticket|email_thread|none>; cite_default=<head|fallback anchor>; use_641_when=<transcript_state_changed_reading>; promote_wrapper_transcript_state=<no>; basis=<why the later transcript layer needed one bounded note>`

This is a note contract, not a new schema.
It exists so packets and summaries can say “this later packet also carried a transcript panel / current-line highlight / transcript-search posture” without minting a new detached-derivative member or silently rewriting transcript authority, source emphasis, source chronology, translation authority, or packet governance.

## Typical uses

1. **Transcript-search overread**
   A later packet shows transcript search results and later readers start retelling those hit lines as if the office officially foregrounded them rather than as a viewer-side query state.
2. **Current-line-highlight overread**
   A later packet shows one highlighted transcript line and later readers start treating that currently-followed line as if it were the office's chosen excerpt or definitive summary of the route.
3. **Transcript-language overread**
   A later packet shows a translated or switched-language transcript pane and later readers start treating that transcript-language choice as if it were the office's reviewed official translation rather than a later wrapper state.
4. **Transcript-pane-governance overread**
   A later packet shows `Show transcript`, a transcript side panel, or `Return to current time` transcript posture and later readers start treating that transcript shell as if it were the packet's governing member or a safer citation target than the head.

## When not to use this

Do **not** use `641` when:
- the decisive issue is still transcript panes/search/jumps as current-route public-answer surfaces (`493`),
- the decisive issue is still same-object transcript-pane state (`557`),
- the decisive issue is still governing transcript precedence for an AI answer (`573`),
- the decisive issue is still detached transcript/caption/OCR text (`595`),
- the decisive issue is still generic query framing or find-hit posture (`614`),
- the decisive issue is still merely which text line or sidebar item is active (`615`),
- the decisive issue is still transcript translation / show-original posture (`638`),
- the decisive issue is still a mixed detached-derivative packet with no dominant member (`600`),
- or the decisive issue is still cross-state composite assembly (`591`).

If deleting the visible transcript layer leaves an ordinary transcript-surface, same-object transcript-pane-state, detached-text, query-state, selection-state, or translation-state problem, use the narrower doc and omit `641`.
If deleting it would erase **why a later transcript panel / search / highlight / language toggle changed the way the packet was being read or retold**, `641` is probably right.

## Promotion rule

Future media additions should usually **not** be promoted just because a later packet carried transcript panes, current-line highlights, transcript search, transcript-language/timestamp toggles, `Show transcript`, or `Return to current time` posture.
Tighten `493`, `557`, `573`, `595`, `600`, `614`, `615`, `638`, or `641` first.
Only add another numbered doc when repeated wrapper-transcript-state mistakes still cannot be expressed as:
- one governing `595–599` member,
- or a mixed-packet routing note under `600`,
- plus one bounded wrapper-transcript-state note under `641`.
