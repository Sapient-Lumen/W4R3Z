# 645 — Official voter-information platform media authenticity-cue packet mute-volume restored-audibility and non-governing wrapper-audio-output-state firewall

**Track:** Shared / Public surfaces

**later packets can preserve mute toggles, low-volume posture, restored-volume state, visible volume sliders, or similar visible wrapper audio-output-state layers around same-route detached derivatives, and later readers can start mistaking that audio-output posture for source-native silence, source-native incompleteness, office-preferred audio redaction, an officially republished quiet edition, or the packet's governing member.**

## What this is for

Use `645` when a later packet preserves or reenacts a **visible wrapper audio-output-state layer** around same-route detached derivatives:
- muted playback or a visible mute icon,
- very low-volume playback or a visible reduced-volume slider,
- restored-audibility posture after a silent or quiet encounter,
- a volume popover or slider visibly foregrounded in the later packet,
- or similar later packet audibility foregrounding.

Those audibility surfaces are real packet facts and should be preserved honestly.
But they are still **later wrapper-added audio-output posture**, not automatic proof of:
- source-native silence or source-native incompleteness,
- office-preferred audio redaction,
- an officially republished quiet or muted edition,
- or the packet's governing member.

Current primary-source guidance is already enough to justify one bounded audio-output-state bridge.
YouTube Help says viewers can mute or unmute the video and increase or decrease volume from keyboard controls.
Vimeo Help says engaged players support volume up, volume down, and mute toggling from keyboard controls.
Microsoft Support says the Microsoft 365 web player supports mute or unmute, increasing volume, decreasing volume, and direct volume-slider changes during playback.
That is enough for one bounded firewall here.
(xref: `youtube_keyboard_shortcuts_help_page`; xref: `vimeo_player_keyboard_shortcuts_help_page`; xref: `microsoft_video_player_playback_experience_help_page`)

`645` exists so maintainers can say:
**this packet preserved a later mute/volume posture around same-route detached derivatives, and that posture mattered for how later readers interpreted the packet, but the audio-output layer itself does not silently prove source-native silence, source-native incompleteness, office-preferred audio redaction, an officially republished quiet edition, or the governing member.**

## Why this is distinct

`549` asks whether the same current media object preserved **selected audio-output state** — muted, effectively low-volume, or audibly restored — while the same object still controlled.

`596` asks whether later evidence preserved a **detached spoken-audio derivative** such as downloaded audio, audio-only export, or another spoken excerpt from the route.

`611` asks whether a later packet preserved **timing / motion wrapper posture** such as animation build order, autoplay, or transition timing around a derivative carrier.

`643` asks whether a later packet preserved **caption-display / caption-selection posture** such as captions-on/off, selected caption language, or caption appearance customization.

`644` asks whether a later packet preserved **playback-rate / scan posture** such as `1.25x`, `1.5x`, `2x`, `0.8x`, or speed-menu state.

`645` asks a different question:
**did a later packet add or preserve a visible mute / volume layer — muted playback, low-volume posture, restored audibility, volume-slider state, or similar audibility cues — and did later readers start overreading that layer as if it proved source-native silence, source-native incompleteness, office-preferred audio redaction, an officially republished quiet edition, or the packet's governing member?**

If the real problem is same-object selected audio-output state while the current head still controls, use `549`.
If the real problem is a detached spoken-audio derivative, use `596`.
If the real problem is wrapper timing, caption, or playback-rate posture, use `611`, `643`, or `644`.
Use `645` only when the missing distinction is **wrapper audio-output-state posture itself**.

## Decision test

Use `645` when all three conditions hold:

1. later evidence preserves or reenacts a **visible audio-output layer** around same-route detached derivatives — for example muted playback, very low-volume posture, restored audibility, a volume slider, or a visible mute icon;
2. that layer is **later wrapper-added audibility state**, not proof that the underlying source route itself officially published a silent or quiet edition, officially redacted audio, or officially made the packet governing; and
3. later readers are drifting toward treating that layer as if it proved **source-native silence, source-native incompleteness, office-preferred audio redaction, an officially republished quiet edition, or the governing member**.

If any condition fails, keep the packet under the narrower doc that already owns the real problem.
If the surviving packet is still mainly a same-object audio-output-state problem, detached spoken-audio problem, wrapper timing problem, caption-state problem, or playback-rate-state problem with some visible volume posture around it, keep same-object audio-output state in `549`, keep detached spoken-audio routing in `596`, keep wrapper timing in `611`, keep caption posture in `643`, keep playback-rate posture in `644`, and add one bounded `645` audio-output-state note only if the visible audibility layer itself changed the reading.

## Keep audio-output state, audio derivatives, timing, captions, and playback-rate separate

At minimum, keep these layers separate:
1. **current office control** — the current written/help lane and current media head (`194`, `529`, `530`);
2. **surviving detached derivative** — which `595–599` member, if any, the packet actually preserved;
3. **family routing** — whether the packet needed `600` because no single detached derivative dominated;
4. **same-object audio-output state** — muted, reduced-volume, or audibly restored playback while the same object still controlled (`549`);
5. **detached spoken-audio derivative** — downloaded or exported spoken-audio carry divorced from route cues (`596`);
6. **wrapper timing / motion state** — animation, autoplay, or timed build posture in the later packet (`611`);
7. **wrapper-added caption state** — CC on/off posture, selected caption language, auto-generated-caption inclusion, or caption-style posture (`643`);
8. **wrapper-added playback-rate state** — visible `1.25x` / `1.5x` / `2x` / `0.8x` or speed-menu posture (`644`);
9. **carrier wrapper** — slide deck, PDF memo, browser shell, doc shell, saved page, ticket, or email thread (`437`, `490`, `600`);
10. **assembly state** — whether later materials also fused several observations into one stronger-looking posture (`591`).

That separation matters because later packets can otherwise make two different mistakes:
- treating a visible mute/volume shell as if it proved the source itself was silent, incomplete, intentionally redacted, or officially republished in another audio form; or
- letting a later audibility wrapper become evidence that the packet itself is governance-bearing rather than just a later hearing layer around one preserved derivative.

`645` exists so the archive can keep that later visible audio-output layer **truthful but non-governing**.

## Minimal wrapper-audio-output-state note grammar

When wrapper audio-output state matters, reviewers SHOULD prefer one compact line in this shape:

`head=<current tuple|none>; governing_member=<595|596|597|598|599|600|none>; wrapper_audio_output_kind=<muted_playback|low_volume_posture|restored_audibility|volume_slider_open|mixed|unknown>; audibility_posture=<silent|reduced|ordinary|unknown>; selection_scope=<viewer_selected|session_persistent|platform_default|device_default|unknown>; source_native_silence_proved=<forbid>; official_audio_redaction_proved=<forbid>; republished_quiet_edition_proved=<forbid>; governing_member_from_audio_output_state=<forbid>; carrier_wrapper=<browser_shell|doc_shell|pdf_shell|review_shell|slide_deck|saved_page|ticket|email_thread|none>; cite_default=<head|fallback anchor>; use_645_when=<audio_output_state_changed_reading>; promote_wrapper_audio_output_state=<no>; basis=<why the later audibility layer needed one bounded note>`

This is a note contract, not a new schema.
It exists so packets and summaries can say “this later packet also carried a visible mute / volume posture” without minting a new detached-derivative member or silently rewriting source audibility, source completeness, source audio-redaction authority, or packet governance.

## Typical uses

1. **Visible mute overread**
   A later packet shows a visible mute icon and later readers start retelling the packet as if the office itself published a silent edition rather than a viewer-side audibility posture.
2. **Low-volume overread**
   A later packet preserves a visibly reduced volume slider and later readers start treating the packet as if the source itself was incomplete, barely audible, or intentionally quiet.
3. **Restored-audibility overread**
   A later packet captures mute or low-volume first and later restored audibility, and later readers start treating that restoration as if the office had republished, corrected, or officially disclosed a different edition.
4. **Audio-output plus detached derivative bundle**
   A later packet carries a still image, shared URL, copied metadata, or detached audio excerpt from the same route and also preserves a visible mute/volume cue; keep the detached derivative governing and use `645` only for the later audio-output-state drift.

## When not to use this

Do **not** use `645` when:
- the decisive issue is still same-object audio-output state (`549`),
- the decisive issue is still a detached spoken-audio derivative (`596`),
- the decisive issue is still wrapper timing / motion posture (`611`),
- the decisive issue is still caption posture (`643`),
- the decisive issue is still playback-rate posture (`644`),
- the decisive issue is still a mixed detached-derivative packet with no dominant member (`600`),
- or the decisive issue is still cross-state composite assembly (`591`).

If deleting the visible mute/volume layer leaves an ordinary same-object audio-output, detached spoken-audio, wrapper-timing, caption-state, or playback-rate-state problem, use the narrower doc and omit `645`.
If deleting it would erase **why a later audibility layer changed the way the packet was being read or retold**, `645` is probably right.

## Promotion rule

Future media additions should usually **not** be promoted just because a later packet carried mute, low-volume, restored-audibility, visible volume sliders, or similar audibility posture around same-route detached derivatives.
Tighten `549`, `596`, `600`, `611`, `643`, `644`, or `645` first.
Only add another numbered doc when repeated wrapper-audio-output-state mistakes still cannot be expressed as:
- one governing `595–599` member,
- or a mixed-packet routing note under `600`,
- plus one bounded wrapper-audio-output-state note under `645`.
