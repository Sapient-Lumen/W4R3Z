# 605 — Official voter-information platform media authenticity-cue packet ordering, page sequence, and non-governing wrapper-chronology firewall

**Track:** Shared / Public surfaces

This document defines a bounded control for **later packet-level ordering around same-route detached derivatives**:
reordered slides,
reordered PDF pages,
merged packet page sequences,
reordered deck sections,
or similar later wrapper-added arrangement that changes the order in which preserved detached derivatives are encountered without proving that the official source route itself used that chronology, priority, or narrative emphasis.

It does not create a new authenticity cue family.
It adds one narrow rule:
**when a later packet reorders same-route detached derivatives, the archive should preserve that wrapper-ordering fact honestly and should not quietly treat the later sequence as if it were source chronology, source priority, source-native narrative structure, or the packet's governing member.**

## Why this exists (bounded)

The archive already distinguishes detached stills (`597`), copied text (`595`), copied metadata (`598`), clipped observation windows (`594`), mixed detached-derivative packets (`600`), short wrapper labels (`601`), longer wrapper summaries (`602`), wrapper-added emphasis markup (`603`), and wrapper-added concealment (`604`).
Another small but real seam remains:
**a later packet can keep the same preserved detached derivatives but reorder them — by slide order, PDF page order, merged-page sequence, or similar wrapper arrangement — and later readers can start narrating that arrangement as if it were the source route's native chronology, source priority, or the packet's governing member.**

Current primary-source guidance is specific enough to justify one compact bridge here.
Google's current Slides guidance says slides can be reordered and skipped without being deleted.
Microsoft's current PowerPoint guidance says slides can be rearranged and sections moved.
Apple's current Preview guidance says PDF pages can be moved to new locations and dragged between PDFs.
(xref: `google_slides_add_delete_organize_slides_help_page`; xref: `microsoft_powerpoint_add_rearrange_duplicate_delete_slides_help_page`; xref: `microsoft_powerpoint_organize_slides_into_sections_help_page`; xref: `apple_preview_add_delete_move_pdf_pages_mac_help_page`)

That is enough to support one bounded maintainer rule:
**later packet order is still only later packet order.**
A reordered deck, resequenced PDF, or merged packet can honestly be the wrapper that later readers saw while still failing to prove that the official source route itself used that same chronology, priority, or narrative emphasis.
`605` exists so the archive can preserve that wrapper-ordering fact without quietly promoting packet sequence into source sequence.

## This is not the same thing as `594`, `600`, `601`, `602`, `603`, `604`, `591`, `437`, or `490`

`594` asks whether a later screenshot, crop, clipped embed, or other narrow observation window preserved only part of the route.

`600` asks how to route a mixed same-route packet when several detached derivatives coexist and no single `595–599` member clearly dominates.

`601` asks whether later packet titles, filenames, subject lines, memo headings, or similar short wrapper-added labels were mistaken for source metadata or for the governing member.

`602` asks whether later forwarding comments, share messages, speaker notes, memo-body summaries, or similar longer wrapper-added prose were mistaken for copied source language, copied metadata, or for the governing member.

`603` asks whether later wrapper-added markup or emphasis such as highlight boxes, arrows, circles, underlines, comment anchors, zoom callouts, or ink starts sounding like source-native emphasis or like the packet's governing member.

`604` asks whether later wrapper-added concealment such as redaction, crop-hide, hidden slides, or hidden objects starts sounding like source absence, source-native redaction, or like the packet's governing member.

`591` asks whether later materials fused observations from different routes, times, viewer conditions, or interaction states into one faux simultaneous posture.

`437` and `490` ask whether print/save/offline/web-archive carriers changed the authority or portability posture of the already-open route.

`605` asks a different question:
**did a later packet add its own ordering or sequence layer around same-route detached derivatives, and did later readers start overreading that arrangement as if it proved source chronology, source priority, source-native narrative structure, or the packet's governing member?**

If the real problem is the clipped observation window itself, use `594`.
If the real problem is mixed detached-derivative routing, use `600`.
If the real problem is a short wrapper-added label, use `601`.
If the real problem is wrapper-added summary prose, use `602`.
If the real problem is wrapper-added markup, use `603`.
If the real problem is wrapper-added concealment, use `604`.
If the real problem is later composite assembly across states, use `591`.
If the real problem is print/save/offline/web-archive authority or portability, use `437` or `490`.
Use `605` only when the decisive ambiguity is **wrapper-added ordering or sequence inside the packet** rather than copied source content.

## Default rule: classify the surviving derivative first; treat later wrapper ordering as descriptive unless provenance proves otherwise

By default, later notes SHOULD still cite the current controlling head under `530`, or the fallback anchor if the chain is headless.
A `605` note exists only to explain one bounded sequencing mistake around that head.

Use this triage order:
1. if the decisive issue is still copied source text, use `595`;
2. if the decisive issue is still a detached still-image derivative, use `597`;
3. if the decisive issue is still copied source metadata, use `598`;
4. if the decisive issue is still a mixed detached-derivative packet with no dominant member, use `600`;
5. if the decisive issue is still short wrapper-added labeling, use `601`;
6. if the decisive issue is still longer wrapper-added summary prose, use `602`;
7. if the decisive issue is still wrapper-added emphasis or annotation, use `603`;
8. if the decisive issue is still wrapper-added concealment or suppression, use `604`;
9. if the decisive issue is still cross-state composite assembly, use `591`;
10. if the decisive issue is still saved-page / print / offline portability or authority boundary, use `437` or `490`;
11. use `605` only when the decisive issue is that **a later wrapper reordering, page sequence, slide sequence, section move, or similar arrangement changed how the packet was encountered and later retellings started treating that arrangement as source fact.**

That means `605` is not a new citation lane.
It is a compact bridge for one bounded sentence saying that the packet carried later wrapper ordering and that this later sequence should not be silently upgraded into source chronology, source priority, source-native narrative structure, or governing-member proof.

## Keep source-derived content and wrapper-added ordering separate

At minimum, keep these layers separate:
1. **current office control** — the current written/help lane and current media head (`194`, `369`, `529`, `530`);
2. **surviving detached derivative** — which `595–599` member, if any, the packet actually preserved;
3. **family routing** — whether the packet needed `600` because no single detached derivative dominated;
4. **source-derived text** — transcript/caption/OCR or other copied route text (`595`);
5. **source-derived metadata** — labels copied from the official route itself (`598`);
6. **wrapper-added packet label** — filename, subject line, slide title, memo heading, or similar short later-added narrative (`601`);
7. **wrapper-added summary prose** — forwarding comments, share messages, speaker notes, memo-body summaries, or similar longer later packet narrative (`602`);
8. **wrapper-added markup/emphasis** — highlight boxes, circles, arrows, underlines, comment anchors, zoom lenses, ink, or similar later visual emphasis (`603`);
9. **wrapper-added concealment/suppression** — redactions, crop-hidden regions, hidden slides, hidden objects, or similar later visual withholding (`604`);
10. **wrapper-added ordering/sequence** — reordered slide order, reordered PDF page order, moved packet sections, merged-page sequence, or similar later arrangement (`605`);
11. **carrier wrapper** — slide deck, PDF memo, annotated screenshot, chat export, saved page, web archive, issue ticket, or other transport context (`437`, `490`, `600`);
12. **assembly state** — whether later materials also fused several observations into one stronger-looking posture (`591`).

That separation matters because later packets can otherwise make two different mistakes:
- treating wrapper-added order as if it proved source chronology, source priority, or source-native narrative sequence, or
- letting the ordering layer become the governing member instead of first classifying the surviving detached derivative.

`605` exists so the archive can keep that later sequencing layer **truthful but non-governing**.

## Minimal wrapper-ordering note grammar

When wrapper-ordering overread itself matters, reviewers SHOULD prefer one compact line in this shape:

`head=<current tuple|none>; governing_member=<595|596|597|598|599|600|none>; wrapper_order_kind=<slide_reorder|pdf_page_reorder|section_reorder|merged_packet_sequence|mixed|unknown>; wrapper_order_origin=<later_wrapper_added|copied_from_source|mixed|unknown>; treat_order_as_source_chronology=<forbid>; treat_order_as_source_priority=<forbid>; treat_order_as_source_narrative_structure=<forbid>; treat_order_as_governing_member=<forbid>; carrier_wrapper=<slide_deck|pdf_memo|annotated_screenshot|chat_export|saved_page|web_archive|ticket|email_thread|doc_comment_layer|none>; cite_default=<head|fallback anchor>; use_605_when=<wrapper_order_changed_encounter_sequence>; promote_wrapper_order=<no>; basis=<why the later sequence needed one bounded note>`

This is a note contract, not a new schema.
It exists so packets and summaries can say “this packet later reordered what it preserved” without minting a new detached-derivative member or silently rewriting source provenance.

## Typical uses

1. **Slide-order overread**
   A packet preserves several same-route detached derivatives but later reorders the slides, and later readers start retelling that slide order as if it were the source route's native chronology or importance order.
2. **PDF-page-sequence overread**
   A PDF packet preserves same-route text, stills, and copied metadata but later moves the pages, and later readers start treating the new page order as if it were the source route's intended sequence.
3. **Merged-packet sequence overread**
   A later packet merges pages from two preserved derivative slices of the same route and later readers start treating the merged sequence as if it were the source route's narrative structure.
4. **Section-order overread**
   A later presentation copy keeps the same slides but moves sections, and later readers start treating that packet arrangement as if it proved the office's own ordering or emphasis.
5. **Mixed ordering overread**
   A packet uses both slide reordering and PDF page resequencing, and later readers start treating the resulting visible order as if it were the source route's whole preserved derivative chronology.

## When not to use this

Do **not** use `605` when:
- the decisive issue is still copied source text (`595`),
- the decisive issue is still the detached still-image derivative itself (`597`),
- the decisive issue is still copied source metadata (`598`),
- the decisive issue is still a mixed detached-derivative packet with no dominant member (`600`),
- the decisive issue is still a short wrapper-added label (`601`),
- the decisive issue is still longer wrapper-added summary prose (`602`),
- the decisive issue is still wrapper-added emphasis or annotation (`603`),
- the decisive issue is still wrapper-added concealment or suppression (`604`),
- the decisive problem is still print/save/offline/web-archive authority or portability (`437`, `490`),
- or the decisive problem is still cross-state composite assembly (`591`).

If deleting the ordering layer leaves an ordinary text derivative, still-image derivative, metadata derivative, mixed packet, label problem, summary-prose problem, markup problem, concealment problem, saved-page issue, or composite-assembly claim, use the narrower doc and omit `605`.
If deleting it would erase **why a later reorder, page sequence, slide sequence, or section arrangement changed the way the packet was being routed or retold**, `605` is probably right.

## Promotion rule

Future media additions should usually **not** be promoted just because a later packet reordered slides, resequenced PDF pages, moved sections, or otherwise rearranged same-route detached derivatives.
Tighten `594`, `600`, `601`, `602`, `603`, `604`, or `605` first.
Only add another numbered doc when repeated ordering mistakes still cannot be expressed as:
- one governing `595–599` member,
- or a mixed-packet routing note under `600`,
- plus one bounded wrapper-label note under `601`,
- plus one bounded wrapper-summary note under `602`,
- plus one bounded wrapper-markup note under `603`,
- plus one bounded wrapper-concealment note under `604`,
- plus one bounded wrapper-ordering note under `605`.
