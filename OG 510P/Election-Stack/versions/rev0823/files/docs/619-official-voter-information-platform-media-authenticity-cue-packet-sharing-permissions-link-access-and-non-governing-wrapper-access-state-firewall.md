# 619 — Official voter-information platform media authenticity-cue packet sharing permissions, link access, and non-governing wrapper-access-state firewall

**Track:** Shared / Public surfaces

This document covers a narrow packet-wrapper problem:
**later packets can preserve share dialogs, manage-access panes, link-access scopes, role pickers, access-request notices, download/copy restrictions, expiration dates, or similar visible access-state layers around same-route detached derivatives, and later readers can start mistaking that wrapper access posture for source-route publicness, current official distribution scope, endorsed recipient scope, or the packet's governing member.**

## What this is for

Use `619` when a later packet preserves or reenacts a **visible wrapper access-state layer** around same-route detached derivatives:
- share dialogs,
- manage-access panes,
- “anyone with the link” / organization-only / invited-only link scopes,
- viewer/commenter/editor or review-only role matrices,
- can’t-download / copy-restricted settings,
- password-gated shared-link controls,
- expiration dates,
- access-request queues or approval notices,
- or similar later packet access posture.

Those access states are real packet facts and should be preserved honestly.
But they are still **later wrapper-added access posture**, not automatic proof of:
- current source-route publicness,
- the source route's current ordinary-public default,
- endorsed audience scope,
- safe actionability for the public,
- or the packet's governing member.

`619` exists so maintainers can say:
**this packet preserved a later access-state layer around a same-route detached derivative, and that layer mattered for how later readers interpreted the packet, but the access layer itself does not govern the packet and does not silently rewrite source-route publicness, audience scope, or current control.**

## Why this is distinct

`512` asks whether the public source route itself currently lands on an unavailable, private, age-gated, blocked, or restricted shell.

`535` asks whether one same-object chain currently has an ordinary-public head plus a **real audience-scoped current alias** for a defined subset.

`538` asks whether a same object is being reached through a watch page, direct player, embed, or other actual render alias whose access path still matters at route level.

`601` asks whether packet labels, filenames, or subject lines drift into governance or source-language territory.

`616`, `617`, and `618` ask whether later packets preserved wrapper review discourse, revision proposals, or history posture.

`595` and `598` ask whether the decisive surviving artifact is still copied source text or copied source metadata.

`619` asks a different question:
**did a later packet add or preserve a visible sharing/permissions layer — link-scope settings, role controls, access-request posture, or similar wrapper access state — and did later readers start overreading that layer as if it proved source-route publicness, current official audience scope, endorsed distribution, or the packet's governing member?**

If the real problem is the source route itself being blocked or private, use `512`.
If the real problem is a genuine audience-scoped current alias on the same object, use `535`.
If the real problem is an actual player/watch/embed route choice, use `538`.
If the real problem is still copied source text or metadata, use `595` or `598`.
Use `619` only when the missing distinction is **wrapper access-state posture itself**.

## Decision test

Use `619` when all three conditions hold:

1. later evidence preserves or reenacts a **visible sharing / permissions / access-state layer** around same-route detached derivatives — for example a share dialog, manage-access pane, “anyone with the link” state, invited-only state, role picker, request-access notice, password-protected link control, or expiration banner;
2. that layer is **later wrapper-added access posture**, not proof that the underlying source route itself had the same current publicness, alias status, or governing audience scope; and
3. later readers are drifting toward treating that layer as if it proved **ordinary-public access, endorsed recipient scope, source-route actionability, or the governing member**.

If any condition fails, keep the packet under the narrower doc that already owns the real problem.
If the surviving packet is still mainly copied source text or copied source metadata with some access-state posture around it, keep the detached derivative in `595–600`, keep any source-route restriction fact in `512`, keep any audience-scoped-alias fact in `535`, and add one bounded `619` wrapper-access-state note.

## Keep source-derived content, route-level access, and wrapper-added access state separate

At minimum, keep these layers separate:
1. **current office control** — the current written/help lane and current media head (`194`, `529`, `530`);
2. **surviving detached derivative** — which `595–599` member, if any, the packet actually preserved;
3. **family routing** — whether the packet needed `600` because no single detached derivative dominated;
4. **source-derived text** — transcript/caption/OCR or other copied route text (`595`);
5. **source-derived metadata** — labels copied from the official route itself (`598`);
6. **route-level public restriction** — whether the public source route itself was unavailable, private, blocked, or access-restricted (`512`);
7. **route-level scoped alias posture** — whether the same object also had a real current subset-only alias (`535`, `538`);
8. **wrapper-added summary prose** — forwarding comments, share messages, memo-body summaries, or similar later packet narrative (`602`);
9. **wrapper-added review discourse** — comment-thread bodies, replies, or similar later attached discussion (`616`);
10. **wrapper-added revision state** — tracked changes, suggestions, redlines, or similar proposal posture (`617`);
11. **wrapper-added history state** — version-history panes, named versions, restore candidates, or similar prior-version posture (`618`);
12. **wrapper-added access state** — link scopes, share roles, access-request posture, passwords, expiration dates, or similar later packet permissions (`619`);
13. **carrier wrapper** — slide deck, PDF memo, doc shell, saved page, web archive, issue ticket, or other transport context (`490`, `600`);
14. **assembly state** — whether later materials also fused several observations into one stronger-looking posture (`591`).

That separation matters because later packets can otherwise make two different mistakes:
- treating a packet's visible share/permissions UI as if it proved the source route was publicly reachable or officially distributed that way, or
- letting the existence of a share dialog / manage-access pane become evidence that the packet itself governs the source route.

`619` exists so the archive can keep that later visible access layer **truthful but non-governing**.

## Minimal wrapper-access-state note grammar

When wrapper access state matters, reviewers SHOULD prefer one compact line in this shape:

`head=<current tuple|none>; governing_member=<595|596|597|598|599|600|none>; wrapper_access_kind=<share_dialog|manage_access_panel|permission_sidebar|public_link_state|org_only_link_state|invited_only_state|role_matrix|request_access_notice|password_link_state|expiration_state|download_copy_restriction|mixed|unknown>; access_anchor_relation=<whole_member|member_link|attachment|slide|page|object|mixed|unknown>; wrapper_access_origin=<later_wrapper_added|storage_share_ui|collab_share_ui|imported_access_capture|mixed|unknown>; source_publicness_proved=<forbid>; source_alias_scope_proved=<forbid>; endorsed_recipient_scope_proved=<forbid>; treat_access_state_as_governing_member=<forbid>; carrier_wrapper=<share_dialog|doc_shell|slide_deck|pdf_memo|saved_page|web_archive|ticket|email_thread|none>; cite_default=<head|fallback anchor>; use_619_when=<access_state_changed_reading>; promote_wrapper_access_state=<no>; basis=<why the later visible access layer needed one bounded note>`

This is a note contract, not a new schema.
It exists so packets and summaries can say “this later packet also carried visible access-state posture” without minting a new detached-derivative member or silently rewriting source-route publicness, endorsed audience scope, or governance.

## Typical uses

1. **Anyone-with-link overread**
   A later packet shows “anyone with the link” and later readers start retelling the underlying source route as if it were necessarily ordinary-public and currently action-safe.
2. **Invited-only overread**
   A later packet shows invited-only or organization-only access and later readers start retelling that wrapper scope as if it proved the source route itself was subset-only.
3. **Role-matrix overread**
   A later packet shows viewer/commenter/editor or review-only permissions and later readers start treating those collaboration roles as if they described source authority, endorsement, or governing audience.
4. **Download/password overread**
   A later packet shows download-disabled or password-protected sharing posture and later readers start treating that wrapper control as if it proved source-route authenticity or current public distribution scope.
5. **Access-request overread**
   A later packet preserves access-request notices or approval queues and later readers start narrating those wrapper requests as if they proved the current public could or could not reach the source route itself.

## When not to use this

Do **not** use `619` when:
- the decisive issue is the source route itself being unavailable, private, blocked, or restricted (`512`),
- the decisive issue is a real audience-scoped current alias or route-level subset path (`535`, `538`),
- the decisive issue is still packet labels or filenames (`601`),
- the decisive issue is still wrapper-added summary prose (`602`),
- the decisive issue is still wrapper-added review discourse (`616`),
- the decisive issue is still wrapper-added revision-state posture (`617`),
- the decisive issue is still wrapper-added history-state posture (`618`),
- the decisive issue is still copied source text (`595`),
- the decisive issue is still copied source metadata (`598`),
- the decisive issue is still a mixed detached-derivative packet with no dominant member (`600`),
- the decisive problem is still print/save/offline/web-archive authority or portability (`490`),
- or the decisive problem is still cross-state composite assembly (`591`).

If deleting the visible access layer leaves an ordinary source-route restriction problem, audience-scoped-alias problem, summary problem, or mixed-packet problem, use the narrower doc and omit `619`.
If deleting it would erase **why a later share / permissions / manage-access layer changed the way the packet was being read or retold**, `619` is probably right.

## Promotion rule

Future media additions should usually **not** be promoted just because a later packet carried a share dialog, link-scope setting, role picker, password gate, expiration banner, or access-request posture.
Tighten `512`, `535`, `538`, `600`, or `619` first.
Only add another numbered doc when repeated wrapper-access-state mistakes still cannot be expressed as:
- one governing `595–599` member,
- or a mixed-packet routing note under `600`,
- plus one bounded wrapper-access-state note under `619`.
