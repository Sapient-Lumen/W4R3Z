# 606 — Official voter-information platform media authenticity-cue packet membership, imported slides, attachments, and non-governing wrapper-scope firewall

**Track:** Shared / Public surfaces

This document defines a bounded control for **later packet-level membership selection around same-route detached derivatives**:
imported slides,
selected PDF pages or merged PDFs,
chosen attachments,
forwarded subsets,
or similar later wrapper-added membership decisions that change **which members are present in the packet at all** without proving that the official source route itself natively had that same bundle, completeness boundary, or packet scope.

It does not create a new authenticity cue family.
It adds one narrow rule:
**when a later packet chooses, imports, appends, omits, or forwards only some same-route detached derivatives, the archive should preserve that wrapper-membership fact honestly and should not quietly treat the resulting included-member set as if it proved source-native completeness, source-native scope, or the packet's governing member.**

## Why this exists (bounded)

The archive already distinguishes detached stills (`597`), copied text (`595`), copied metadata (`598`), clipped observation windows (`594`), mixed detached-derivative packets (`600`), short wrapper labels (`601`), longer wrapper summaries (`602`), wrapper-added emphasis markup (`603`), wrapper-added concealment (`604`), and wrapper-added ordering (`605`).
A smaller but still important seam remains:
**a later packet can decide which same-route detached derivatives are present at all — by importing some slides, merging only some PDFs, attaching only some files, forwarding only some members, or similar wrapper-added membership selection — and later readers can start narrating that chosen member set as if it were the source route's native completeness boundary, native scope, or governing packet.**

Current primary-source guidance is specific enough to justify one compact bridge here.
Microsoft's current PowerPoint guidance says slides can be reused from another presentation and that one or all imported slides can be inserted into the destination presentation.
Apple's current Preview guidance says individual pages from one PDF can be added to another PDF or entire PDFs can be merged.
Gmail's current Drive-attachment guidance says senders can select the files they want to attach and then decide how to send them.
(xref: `microsoft_powerpoint_reuse_import_slides_help_page`; xref: `apple_preview_combine_pdfs_mac_help_page`; xref: `gmail_send_google_drive_attachments_help_page`)

That is enough to support one bounded maintainer rule:
**later packet membership selection is still only later packet membership selection.**
An imported-slide packet, combined-PDF packet, or chosen-attachment packet can honestly be the member set that later readers received while still failing to prove that the source route itself had that same completeness boundary, scope, or native packet composition.
`606` exists so the archive can preserve that membership fact without quietly promoting packet-level inclusion choice into source-native scope.

## This is not the same thing as `594`, `597`, `595`, `600`, `601`, `602`, `603`, `604`, `605`, `591`, `437`, or `490`

`594` asks whether a later screenshot, crop, clipped embed, or other narrow observation window preserved only part of the route.

`597` asks whether the decisive surviving artifact is the detached still-image derivative itself.

`595` asks whether the decisive surviving artifact is copied source text.

`600` asks how to route a mixed same-route packet when several detached derivatives coexist and no single `595–599` member clearly dominates.

`601` asks whether later packet titles, filenames, subject lines, memo headings, or similar short wrapper-added labels were mistaken for source metadata or for the governing member.

`602` asks whether later forwarding comments, share messages, speaker notes, memo-body summaries, or similar longer wrapper-added prose were mistaken for copied source language, copied metadata, or for the governing member.

`603` asks whether later wrapper-added markup or emphasis such as highlight boxes, arrows, circles, underlines, comment anchors, zoom callouts, or ink starts sounding like source-native emphasis or like the packet's governing member.

`604` asks whether later wrapper-added concealment such as redaction, crop-hide, hidden slides, or hidden objects starts sounding like source absence, source-native redaction, or like the packet's governing member.

`605` asks whether later wrapper-added ordering or sequence starts sounding like source chronology, source priority, source-native narrative structure, or like the packet's governing member.

`591` asks whether later materials fused observations from different routes, times, viewer conditions, or interaction states into one faux simultaneous posture.

`437` and `490` ask whether print/save/offline/web-archive carriers changed the authority or portability posture of the already-open route.

`606` asks a different question:
**did a later packet add its own membership boundary around same-route detached derivatives, and did later readers start overreading that included-member set as if it proved source-native completeness, source-native scope, or the packet's governing member?**

If the real problem is the clipped observation window itself, use `594`.
If the real problem is the detached still itself, use `597`.
If the real problem is copied source text, use `595`.
If the real problem is mixed detached-derivative routing, use `600`.
If the real problem is a short wrapper-added label, use `601`.
If the real problem is wrapper-added summary prose, use `602`.
If the real problem is wrapper-added emphasis, use `603`.
If the real problem is wrapper-added concealment, use `604`.
If the real problem is wrapper-added ordering, use `605`.
If the real problem is later composite assembly across states, use `591`.
If the real problem is print/save/offline/web-archive authority or portability, use `437` or `490`.
Use `606` only when the decisive ambiguity is **wrapper-added member inclusion or exclusion inside the packet** rather than copied source content.

## Default rule: classify the surviving derivative first; treat later wrapper membership as descriptive unless provenance proves otherwise

By default, later notes SHOULD still cite the current controlling head under `530`, or the fallback anchor if the chain is headless.
A `606` note exists only to explain one bounded membership mistake around that head.

Use this triage order:
1. if the decisive issue is still copied source text, use `595`;
2. if the decisive issue is still a detached still-image derivative, use `597`;
3. if the decisive issue is still copied source metadata, use `598`;
4. if the decisive issue is still a mixed detached-derivative packet with no dominant member, use `600`;
5. if the decisive issue is still short wrapper-added labeling, use `601`;
6. if the decisive issue is still longer wrapper-added summary prose, use `602`;
7. if the decisive issue is still wrapper-added emphasis or annotation, use `603`;
8. if the decisive issue is still wrapper-added concealment or suppression, use `604`;
9. if the decisive issue is still wrapper-added ordering or sequence, use `605`;
10. if the decisive issue is still cross-state composite assembly, use `591`;
11. if the decisive issue is still saved-page / print / offline portability or authority boundary, use `437` or `490`;
12. use `606` only when the decisive issue is that **a later wrapper import, attachment choice, merged-PDF selection, forwarded subset, or similar membership decision changed which members are present and later retellings started treating that packet membership as source fact.**

That means `606` is not a new citation lane.
It is a compact bridge for one bounded sentence saying that the packet carried later wrapper membership selection and that this selection should not be silently upgraded into source-native completeness, source-native scope, or governing-member proof.

## Keep source-derived content and wrapper-added membership separate

At minimum, keep these layers separate:
1. **current office control** — the current written/help lane and current media head (`194`, `369`, `529`, `530`);
2. **surviving detached derivative** — which `595–599` member, if any, the packet actually preserved;
3. **family routing** — whether the packet needed `600` because no single detached derivative dominated;
4. **source-derived text** — transcript/caption/OCR or other copied route text (`595`);
5. **source-derived metadata** — labels copied from the official route itself (`598`);
6. **wrapper-added packet label** — filename, subject line, slide title, memo heading, or similar short later-added narrative (`601`);
7. **wrapper-added summary prose** — forwarding comments, share messages, speaker notes, memo-body summaries, or similar longer later packet narrative (`602`);
8. **wrapper-added markup/emphasis** — highlight boxes, circles, arrows, underlines, comment anchors, zoom lenses, ink, or similar later visual emphasis (`603`);
9. **wrapper-added concealment/suppression** — redactions, crop-hidden regions, hidden slides, hidden objects, or similar later visual withholding (`604`);
10. **wrapper-added ordering/sequence** — reordered slide order, reordered PDF page order, moved packet sections, or similar later arrangement (`605`);
11. **wrapper-added membership/composition** — imported slides, merged-page subsets, chosen attachments, appended packet members, or similar later included-member selection (`606`);
12. **carrier wrapper** — slide deck, PDF memo, chat export, saved page, web archive, issue ticket, or other transport context (`437`, `490`, `600`);
13. **assembly state** — whether later materials also fused several observations into one stronger-looking posture (`591`).

That separation matters because later packets can otherwise make two different mistakes:
- treating wrapper-added membership as if it proved source-native completeness or source-native scope, or
- letting the membership layer become the governing member instead of first classifying the surviving detached derivative.

`606` exists so the archive can keep that later included-member layer **truthful but non-governing**.

## Minimal wrapper-membership note grammar

When wrapper-membership overread itself matters, reviewers SHOULD prefer one compact line in this shape:

`head=<current tuple|none>; governing_member=<595|596|597|598|599|600|none>; wrapper_membership_kind=<slide_import_selection|pdf_merge_selection|attachment_selection|forwarded_subset|packet_appendix_subset|mixed|unknown>; wrapper_membership_origin=<later_wrapper_added|copied_from_source|mixed|unknown>; treat_membership_as_source_completeness=<forbid>; treat_membership_as_source_scope=<forbid>; treat_membership_as_source_native_bundle=<forbid>; treat_membership_as_governing_member=<forbid>; carrier_wrapper=<slide_deck|pdf_memo|chat_export|saved_page|web_archive|ticket|email_thread|shared_link_message|none>; cite_default=<head|fallback anchor>; use_606_when=<wrapper_membership_changed_present_member_set>; promote_wrapper_membership=<no>; basis=<why the later membership choice needed one bounded note>`

This is a note contract, not a new schema.
It exists so packets and summaries can say “this packet later selected which members to include” without minting a new detached-derivative member or silently rewriting source provenance.

## Typical uses

1. **Slide-import subset overread**
   A packet imports one slide from another presentation and later readers start retelling that selected slide subset as if it were the source route's whole native packet.
2. **PDF-merge subset overread**
   A packet combines only some pages or only some PDFs, and later readers start treating that resulting PDF composition as if it were the source route's native completeness boundary.
3. **Attachment-selection overread**
   An email packet attaches only some files from the same route context, and later readers start treating that chosen attachment set as if it were the source route's full official bundle.
4. **Forwarded-subset overread**
   A later forward preserves only some derivative members, and later readers start treating the forwarded subset as if it were the source route's native scope.
5. **Mixed membership overread**
   A packet uses both imported slides and selective attachments, and later readers start treating the resulting member set as if it were the source route's whole preserved derivative record.

## When not to use this

Do **not** use `606` when:
- the decisive issue is still copied source text (`595`),
- the decisive issue is still the detached still-image derivative itself (`597`),
- the decisive issue is still copied source metadata (`598`),
- the decisive issue is still a mixed detached-derivative packet with no dominant member (`600`),
- the decisive issue is still a short wrapper-added label (`601`),
- the decisive issue is still longer wrapper-added summary prose (`602`),
- the decisive issue is still wrapper-added emphasis or annotation (`603`),
- the decisive issue is still wrapper-added concealment or suppression (`604`),
- the decisive issue is still wrapper-added ordering or sequence (`605`),
- the decisive problem is still print/save/offline/web-archive authority or portability (`437`, `490`),
- or the decisive problem is still cross-state composite assembly (`591`).

If deleting the membership layer leaves an ordinary text derivative, still-image derivative, metadata derivative, mixed packet, label problem, summary-prose problem, markup problem, concealment problem, ordering problem, saved-page issue, or composite-assembly claim, use the narrower doc and omit `606`.
If deleting it would erase **why a later import, attachment choice, PDF merge selection, or forwarded subset changed the way the packet was being routed or retold**, `606` is probably right.

## Promotion rule

Future media additions should usually **not** be promoted just because a later packet imported selected slides, merged selected PDFs, attached selected files, or otherwise changed which same-route detached derivatives were present.
Tighten `594`, `600`, `601`, `602`, `603`, `604`, `605`, or `606` first.
Only add another numbered doc when repeated membership mistakes still cannot be expressed as:
- one governing `595–599` member,
- or a mixed-packet routing note under `600`,
- plus one bounded wrapper-label note under `601`,
- plus one bounded wrapper-summary note under `602`,
- plus one bounded wrapper-markup note under `603`,
- plus one bounded wrapper-concealment note under `604`,
- plus one bounded wrapper-ordering note under `605`,
- plus one bounded wrapper-membership note under `606`.
