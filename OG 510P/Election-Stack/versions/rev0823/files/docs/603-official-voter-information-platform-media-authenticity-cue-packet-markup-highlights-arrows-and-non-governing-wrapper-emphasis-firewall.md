# 603 — Official voter-information platform media authenticity-cue packet markup, highlights, arrows, and non-governing wrapper-emphasis firewall

**Track:** Shared

This document defines a bounded control for **later packets or carrier wrappers that add their own visual markup or anchored annotation around same-route detached derivatives without proving that this emphasis lived on the official media route itself**:
highlight boxes,
arrows,
circles,
underlines,
zoom callouts,
comment anchors or margin balloons,
ink strokes,
textbox callouts,
or similar wrapper-added emphasis layered around preserved text/audio/still/metadata/locator derivatives.

It does not create a new authenticity cue family.
It does not create a new detached-derivative member.
It adds one narrow rule:
**when later evidence adds its own wrapper markup around same-route detached derivatives, the archive should preserve that markup fact honestly and should not quietly treat the emphasis layer as if it were copied source text, copied source metadata, source-native authenticity posture, or the governing detached-derivative member by itself.**

## Why this exists (bounded)

The archive already distinguishes detached still-image extracts (`597`), copied source metadata (`598`), mixed same-route detached-derivative packets (`600`), later wrapper labels (`601`), and later wrapper summary prose (`602`).
A smaller but still important seam remains:
**later packets often add their own visual emphasis layer around preserved same-route derivatives, and later readers start treating that wrapper markup as if it were source-native annotation, authenticity proof, or the packet's governing member.**

Current primary-source guidance is specific enough to justify one compact bridge here.
Google's current comments help says users can add comments to highlighted text, images, cells, slides, or scenes in Google files.
Apple's current Preview guidance says PDFs can be annotated with shapes, a highlight shape, a zoom lens, text, highlighted text, and notes.
Microsoft's current Office guidance says users can write, draw, or highlight text with ink, and its current private-annotations guidance says OneDrive can automatically create a private copy so the annotations are not affected by edits from other people.
That is enough to support one bounded maintainer rule:
**later wrapper emphasis is not automatically source-native emphasis just because it surrounds genuine same-route derivatives.**
(xref: `google_docs_use_comments_action_items_emoji_reactions_help_page`; xref: `apple_preview_annotate_pdf_mac_help_page`; xref: `microsoft_draw_and_write_with_ink_office_help_page`; xref: `microsoft_create_private_annotations_help_page`)

`603` exists so the archive can say, compactly and honestly, that a red box around a frame grab, a zoom lens over a copied metadata label, a comment anchor beside a transcript excerpt, or ink underlining across a saved packet may be **later wrapper emphasis** rather than copied source text, copied source metadata, or source-native authenticity posture — even when the packet also contains truthful same-route detached derivatives.

## This is not the same thing as `597`, `594`, `600`, `601`, `602`, `591`, `437`, or `490`

`597` asks whether later evidence preserved frame grabs, poster exports, thumbnail-like stills, or another detached still-image derivative from the route itself.

`594` asks whether a later screenshot, crop, clipped embed, or other narrow visual observation window preserved only part of the route.

`600` asks how to route a mixed same-route packet when several detached derivatives coexist and no single `595–599` member clearly dominates.

`601` asks whether later packet titles, filenames, subject lines, memo headings, or similar short wrapper-added labels were mistaken for source metadata or for the governing member.

`602` asks whether later forwarding comments, share messages, speaker notes, memo-body summaries, or similar longer wrapper-added prose were mistaken for copied source language, copied metadata, or for the governing member.

`591` asks whether later materials fused observations from different routes, times, viewer conditions, or interaction states into one faux simultaneous posture.

`437` and `490` ask whether print/save/offline/web-archive carriers changed the authority or portability posture of the already-open route.

`603` asks a different question:
**did a later packet add its own visual markup or anchored annotation around same-route detached derivatives, and did later readers start overreading that wrapper emphasis as if it were copied source content, source-native authenticity posture, or the packet's governing member?**

If the real problem is the detached still itself, use `597`.
If the real problem is the clipped observation window, use `594`.
If the real problem is mixed detached-derivative routing, use `600`.
If the real problem is a short wrapper-added label, use `601`.
If the real problem is wrapper-added summary prose, use `602`.
If the real problem is later composite assembly across states, use `591`.
If the real problem is print/save/offline/web-archive authority or portability, use `437` or `490`.
Use `603` only when the decisive ambiguity is **wrapper-added packet markup or emphasis** rather than copied source content.

## Default rule: classify the surviving derivative first; treat later wrapper markup as descriptive unless provenance proves otherwise

By default, later notes SHOULD still cite the current controlling head under `530`, or the fallback anchor if the chain is headless.
A `603` note exists only to explain one bounded markup mistake around that head.

Use this triage order:
1. if the decisive issue is still copied source text, use `595`;
2. if the decisive issue is still a detached still-image derivative, use `597`;
3. if the decisive issue is still copied source metadata, use `598`;
4. if the decisive issue is still a mixed detached-derivative packet with no dominant member, use `600`;
5. if the decisive issue is still a short wrapper-added label, use `601`;
6. if the decisive issue is still longer wrapper-added summary prose, use `602`;
7. if the decisive issue is still cross-state composite assembly, use `591`;
8. if the decisive issue is still saved-page / print / offline portability or authority boundary, use `437` or `490`;
9. use `603` only when the decisive issue is that **a later wrapper-added highlight, arrow, circle, underline, comment anchor, zoom callout, or ink layer changed how the packet looked, got routed, or got retold.**

That means `603` is not a new citation lane.
It is a compact bridge for one bounded sentence saying that the packet carried later wrapper markup and that this markup should not be silently upgraded into source-native proof or governing derivative proof.

## Keep source-derived content and wrapper-added markup separate

At minimum, keep these layers separate:
1. **current office control** — the current written/help lane and current media head (`194`, `369`, `529`, `530`);
2. **surviving detached derivative** — which `595–599` member, if any, the packet actually preserved;
3. **family routing** — whether the packet needed `600` because no single detached derivative dominated;
4. **source-derived text** — transcript/caption/OCR or other copied route text (`595`);
5. **source-derived metadata** — labels copied from the official route itself (`598`);
6. **wrapper-added packet label** — filename, subject line, slide title, memo heading, or similar short later-added narrative (`601`);
7. **wrapper-added summary prose** — forwarding comments, share messages, speaker notes, memo-body summaries, or similar longer later packet narrative (`602`);
8. **wrapper-added markup/emphasis** — highlight boxes, circles, arrows, underlines, comment anchors, zoom lenses, ink, or similar later visual emphasis (`603`);
9. **carrier wrapper** — slide deck, PDF memo, chat export, saved page, annotated screenshot, web archive, issue ticket, or other transport context (`437`, `490`, `600`);
10. **assembly state** — whether later materials also fused several observations into one stronger-looking posture (`591`).

That separation matters because later packets can otherwise make two opposite mistakes:
- treating wrapper-added markup as if it were source-native emphasis or authenticity proof, or
- letting the markup layer become the governing member instead of first classifying the surviving detached derivative.

`603` exists so the archive can keep that later emphasis layer **truthful but non-governing**.

## Minimal wrapper-markup note grammar

When wrapper-markup overread itself matters, reviewers SHOULD prefer one compact line in this shape:

`head=<current tuple|none>; governing_member=<595|596|597|598|599|600|none>; wrapper_markup_kind=<highlight|underline|circle|arrow|box|zoom_lens|comment_anchor|comment_balloon|ink|textbox_callout|mixed|unknown>; wrapper_markup_origin=<later_wrapper_added|copied_from_source|mixed|unknown>; treat_wrapper_markup_as_source_text=<forbid>; treat_wrapper_markup_as_source_metadata=<forbid>; treat_wrapper_markup_as_authenticity_cue=<forbid>; treat_wrapper_markup_as_governing_member=<forbid>; carrier_wrapper=<slide_deck|pdf_memo|annotated_screenshot|chat_export|saved_page|web_archive|ticket|email_thread|doc_comment_layer|none>; cite_default=<head|fallback anchor>; use_603_when=<wrapper_markup_changed_visual_emphasis_or_routing>; promote_wrapper_markup=<no>; basis=<why the later markup needed one bounded note>`

This is a note contract, not a new schema.
It exists so packets and summaries can say “this box / arrow / underline / comment anchor / zoom callout was later wrapper emphasis” without minting a new detached-derivative member or silently rewriting source provenance.

## Typical uses

1. **Highlight-box overread**
   A packet preserves a same-route frame grab, but a later red box is retold as if the official route itself highlighted that region.
2. **Circle-arrow overread**
   A later slide circles a copied metadata label and adds arrows, and later readers start treating that emphasis as if it were source-native UI or provenance posture.
3. **Comment-anchor overread**
   A shared document or slide comments on a transcript excerpt, and later readers start treating the comment anchor or margin balloon as if it were copied source wording.
4. **Zoom-callout overread**
   A PDF adds a zoom lens around one corner of a still-image derivative, and later readers start treating that magnified emphasis as if it were the route's own presentation layer.
5. **Private-annotation copy overread**
   A reviewer inks notes over a shared packet in a private copy, and later readers start treating those annotations as if they were part of the source packet rather than later wrapper emphasis.

## When not to use this

Do **not** use `603` when:
- the decisive issue is still copied source text (`595`),
- the decisive issue is still the detached still-image derivative itself (`597`),
- the decisive issue is still copied source metadata (`598`),
- the decisive issue is still a mixed detached-derivative packet with no dominant member (`600`),
- the decisive issue is still a short wrapper-added label (`601`),
- the decisive issue is still longer wrapper-added summary prose (`602`),
- the decisive problem is still print/save/offline/web-archive authority or portability (`437`, `490`),
- or the decisive problem is still cross-state composite assembly (`591`).

If deleting the wrapper markup leaves an ordinary text derivative, still-image derivative, metadata derivative, mixed packet, label problem, summary-prose problem, saved-page issue, or composite-assembly claim, use the narrower doc and omit `603`.
If deleting it would erase **why a later highlight, arrow, circle, comment anchor, or other emphasis layer changed the way the packet was being routed or retold**, `603` is probably right.

## Promotion rule

Future media additions should usually **not** be promoted just because a later packet used highlight boxes, arrows, circles, underlines, comment anchors, zoom callouts, or other wrapper-added markup around same-route detached derivatives.
Tighten `594`, `597`, `600`, `601`, `602`, or `603` first.
Only add another numbered doc when repeated wrapper-markup mistakes still cannot be expressed as:
- one governing `595–599` member,
- or a mixed-packet routing note under `600`,
- plus one bounded wrapper-label note under `601`,
- plus one bounded wrapper-summary note under `602`,
- plus one bounded wrapper-markup note under `603`.
