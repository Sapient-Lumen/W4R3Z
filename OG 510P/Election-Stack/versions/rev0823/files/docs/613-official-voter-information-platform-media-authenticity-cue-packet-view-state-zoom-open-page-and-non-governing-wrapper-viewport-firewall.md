# 613 — Official voter-information platform media authenticity-cue packet view state, zoom, open page, and non-governing wrapper-viewport firewall

**Track:** Shared / Public surfaces

This document defines a bounded control for **later packet-level view state around same-route detached derivatives**:
later-added initial view settings,
open-page or open-slide choices,
zoom or magnification,
fit-to-window or page-width posture,
restored last-view state,
reading-view style openings,
or similar wrapper-added viewport choices that change **what a viewer sees first or how large one preserved member appears** without proving that the official source route itself natively carried that same opening posture, focus, priority, or governing status.

It does not create a new authenticity cue family.
It adds one narrow rule:
**when a later packet opens, restores, or frames preserved same-route detached derivatives through its own view state, the archive should preserve that wrapper-viewport fact honestly and should not quietly treat the resulting zoom, open-page choice, or initial view as if it proved source-native focus, source-native default posture, source-native priority, or the packet's governing member.**

## Why this exists (bounded)

The archive already distinguishes clipped observation windows (`594`), mixed detached-derivative packets (`600`), short wrapper labels (`601`), longer wrapper summaries (`602`), wrapper-added emphasis markup (`603`), wrapper-added concealment (`604`), wrapper-added ordering (`605`), wrapper-added membership (`606`), wrapper-added repetition (`607`), wrapper-added layout (`608`), wrapper-added prominence (`609`), wrapper-added styling (`610`), wrapper-added timing (`611`), and wrapper-added navigation (`612`).
A smaller but still important seam remains:
**a later packet can open to one page or slide, restore a last-view position, or magnify one preserved same-route detached derivative, and later readers can start narrating that wrapper view state as if it proved source-native focus, source-native default posture, source-native priority, or the packet's governing member.**

Current primary-source guidance is specific enough to justify one compact bridge here.
Google Docs Editors Help says Slides supports changing zoom and view size.
Microsoft Support says PowerPoint supports Fit to Window and other zoom settings for a presentation.
Adobe Acrobat Help says PDF Page Display preferences can set page layout and zoom when a document is first opened, and that a document's Initial View can override those defaults.
(xref: `google_docs_zoom_change_document_view_help_page`; xref: `microsoft_office_zoom_document_presentation_worksheet_help_page`; xref: `adobe_acrobat_viewing_pdfs_preferences_help_page`)

That is enough to support one bounded maintainer rule:
**later packet view state is still only later packet view state.**
A PDF that opens at 200% on page 4, a deck that starts in one magnified posture, or a wrapper that restores a prior viewport can honestly be the first thing later readers saw while still failing to prove that the source route itself natively privileged that region, page, slide, or member.
`613` exists so the archive can preserve that opening-state fact without quietly promoting wrapper view state into source-native meaning.

## This is not the same thing as `594`, `608`, `609`, `611`, `612`, `546`, `600`, `597`, `595`, `598`, `437`, `490`, or `591`

`594` asks whether the preserved evidence is itself only a clipped capture or partial observation window.

`608` asks whether later wrapper-added spatial layout or placement starts sounding like source-native adjacency, source-native simultaneity, source priority, or like the packet's governing member.

`609` asks whether later wrapper-added size weighting or salience starts sounding like source-native emphasis, source-native priority, or like the packet's governing member.

`611` asks whether later wrapper-added motion, build order, or autoplay starts sounding like source-native chronology, source-native urgency, or like the packet's governing member.

`612` asks whether later wrapper-added hyperlinks, hotspots, internal jumps, or other click paths start sounding like source-native navigation, source-native hierarchy, source-native endorsement, or like the packet's governing member.

`546` asks whether the same current media object stayed current while the live player container or view state changed on the source route itself.

`600` asks how to route a mixed same-route packet when several detached derivatives coexist and no single `595–599` member clearly dominates.

`597`, `595`, and `598` ask whether the decisive surviving artifact is still the detached still-image derivative, copied source text, or copied source metadata themselves.

`437` and `490` ask whether print/save/offline/web-archive carriers changed the authority or portability posture of the already-open route.

`591` asks whether later materials fused observations from different routes, times, viewer conditions, or interaction states into one faux simultaneous posture.

`613` asks a different question:
**did a later packet open, zoom, restore, or fit one preserved same-route detached derivative in a way that later readers started overreading as if it proved source-native focus, source-native default posture, source-native priority, or the packet's governing member?**

If the real problem is a clipped capture, use `594`.
If the real problem is static layout, use `608`.
If the real problem is size weighting, use `609`.
If the real problem is motion or autoplay, use `611`.
If the real problem is click-path creation, use `612`.
If the real problem is a live same-object player-state alias on the source route, use `546`.
If the real problem is mixed-packet routing, use `600`.
Use `613` only when the remaining ambiguity is that **a later wrapper changed the packet's opening or viewport posture around already-preserved same-route detached derivatives and later retellings started treating that opening state as source fact.**

## Default rule: preserve wrapper view-state truth, but keep control with the head

When later packet view state matters, reviewers SHOULD preserve it as **descriptive packet posture** rather than as source proof.

Use a `613` note only when all of the following hold:

1. **The preserved member is already known.**
   The packet's governing detached derivative is already one of `595–599`, or the packet already truthfully needs `600` because no single member dominates.
2. **The remaining ambiguity is viewport or opening posture.**
   The real question is initial page/slide, zoom level, fit mode, restored last view, or similar opening-state framing.
3. **Treating the view state as source-native would mislead.**
   A reader could otherwise mistake one later opening state for the source route's own default focus, default page, or priority ordering.
4. **A better citation/control anchor still exists.**
   `530` can still point to the current media head or honest fallback anchor.
5. **Omitting the view state would lose useful truth.**
   The packet would otherwise hide the fact that the viewer first encountered one page, slide, or region through a later wrapper-set or later-restored viewport.

When those conditions hold, keep the current control in `194` / `530`, keep the surviving detached derivative in `595–600`, keep any clipped-window fact in `594`, keep any layout or prominence fact in `608` / `609`, and add one bounded `613` view-state note.
Do **not** silently promote the selected open page, zoom level, or restored viewport into the governing member.

## Keep source-derived content and wrapper-added view state separate

At minimum, keep these layers separate:
1. **current office control** — the current written/help lane and current media head (`194`, `369`, `529`, `530`);
2. **surviving detached derivative** — which `595–599` member, if any, the packet actually preserved;
3. **family routing** — whether the packet needed `600` because no single detached derivative dominated;
4. **source-derived text** — transcript/caption/OCR or other copied route text (`595`);
5. **source-derived metadata** — labels copied from the official route itself (`598`);
6. **source-derived locator** — watch URL, share URL, timestamp URL, embed URL, or similar copied route pointer (`599`);
7. **wrapper-added packet label** — filename, subject line, slide title, memo heading, or similar short later-added narrative (`601`);
8. **wrapper-added summary prose** — forwarding comments, share messages, speaker notes, memo-body summaries, or similar longer later packet narrative (`602`);
9. **wrapper-added markup/emphasis** — highlight boxes, circles, arrows, underlines, comment anchors, zoom lenses, ink, or similar later visual emphasis (`603`);
10. **wrapper-added concealment/suppression** — redactions, crop-hidden regions, hidden slides, hidden objects, or similar later visual withholding (`604`);
11. **wrapper-added ordering/sequence** — reordered slide order, reordered PDF page order, moved packet sections, or similar later arrangement (`605`);
12. **wrapper-added membership/composition** — imported slides, merged-page subsets, chosen attachments, appended packet members, or similar later included-member selection (`606`);
13. **wrapper-added repetition/multiplicity** — duplicated slides, repeated pages, repeated excerpts, repeated attachments, gallery-style repeats, or similar later same-member multiplication (`607`);
14. **wrapper-added layout/spatial relation** — side-by-side placement, inset-over-main placement, gallery rows, stacked columns, split-screen comparison framing, or similar later positioning (`608`);
15. **wrapper-added prominence/salience** — enlarged hero panels, thumbnail demotion, resized excerpt blocks, large-versus-small weighting, or similar later visual importance allocation (`609`);
16. **wrapper-added styling/tone** — later themes, palettes, fonts, background styles, grayscale/sepia effects, warning-color coding, or similar visual tone choices (`610`);
17. **wrapper-added motion/timing** — later object animations, build order, delays, autoplay, transition timing, reveal-after-previous settings, or similar temporal staging choices (`611`);
18. **wrapper-added navigation/interactivity** — later hyperlinks, linked shapes or images, action buttons, clickable hotspots, internal jumps, hover-triggered actions, or similar click-path choices (`612`);
19. **wrapper-added view state/viewport** — later initial view settings, open-page or open-slide choices, zoom level, fit mode, restored last-view state, or similar opening posture (`613`);
20. **carrier wrapper** — slide deck, PDF memo, chat export, saved page, web archive, issue ticket, or other transport context (`437`, `490`, `600`);
21. **assembly state** — whether later materials also fused several observations into one stronger-looking posture (`591`).

That separation matters because later packets can otherwise make two different mistakes:
- treating wrapper-added opening posture as if it proved the source route's own first-view default, focus, or priority, or
- letting a later zoomed/opened page become the governing member instead of first classifying the surviving detached derivative.

`613` exists so the archive can keep that later viewport layer **truthful but non-governing**.

## Minimal wrapper-view-state note grammar

When wrapper view state overread itself matters, reviewers SHOULD prefer one compact line in this shape:

`head=<current tuple|none>; governing_member=<595|596|597|598|599|600|none>; wrapper_view_state_kind=<initial_view|open_page|open_slide|zoom|fit_mode|restore_last_view|reading_view|mixed|unknown>; wrapper_focus_relation=<whole_member|subregion|page_first|slide_first|mixed|unknown>; wrapper_view_state_origin=<later_wrapper_added|viewer_restored|mixed|unknown>; treat_view_state_as_source_focus=<forbid>; treat_view_state_as_source_default=<forbid>; treat_view_state_as_source_priority=<forbid>; treat_view_state_as_governing_member=<forbid>; carrier_wrapper=<slide_deck|pdf_memo|saved_page|web_archive|ticket|email_thread|none>; cite_default=<head|fallback anchor>; use_613_when=<wrapper_opening_state_changed_first_impression>; promote_wrapper_view_state=<no>; basis=<why the later view state needed one bounded note>`

This is a note contract, not a new schema.
It exists so packets and summaries can say “this later packet opened or restored one preserved member in a particular viewport” without minting a new detached-derivative member or silently rewriting source focus, default, priority, or governance.

## Typical uses

1. **Initial-page PDF overread**
   A later PDF packet opens on page 4 at a chosen magnification and later readers start retelling that opening page as if the source route itself natively foregrounded that member first.
2. **Slide-zoom overread**
   A later deck or presentation opens with one preserved slide fitted, enlarged, or otherwise magnified and later readers start treating that viewport as if it proved source-native emphasis or priority.
3. **Restore-last-view overread**
   A later wrapper reopens at a previously viewed region or page and later readers start narrating that remembered state as if it were the source route's own current default.
4. **Fit-mode overread**
   A later packet opens in page-width, fit-to-window, actual-size, or similar view posture and later readers start treating that framing as if it were source-native layout or source-native scale.
5. **Reading-view overread**
   A later presentation opens in a simplified or reading-style view and later readers start treating that wrapper-only viewport as if it were the source route's native public default.

## When not to use this

Do **not** use `613` when:
- the decisive issue is still copied source text (`595`),
- the decisive issue is still the detached still-image derivative itself (`597`),
- the decisive issue is still copied source metadata (`598`),
- the decisive issue is still the copied source locator itself (`599`),
- the decisive issue is still a mixed detached-derivative packet with no dominant member (`600`),
- the decisive issue is still a short wrapper-added label (`601`),
- the decisive issue is still longer wrapper-added summary prose (`602`),
- the decisive issue is still wrapper-added emphasis or annotation (`603`),
- the decisive issue is still wrapper-added concealment or suppression (`604`),
- the decisive issue is still wrapper-added ordering or sequence (`605`),
- the decisive issue is still wrapper-added membership or composition of distinct members (`606`),
- the decisive issue is still wrapper-added same-member repetition or multiplicity (`607`),
- the decisive issue is still wrapper-added layout or spatial relation (`608`),
- the decisive issue is still wrapper-added prominence or size weighting (`609`),
- the decisive issue is still wrapper-added styling or visual tone (`610`),
- the decisive issue is still wrapper-added timing or motion (`611`),
- the decisive issue is still wrapper-added navigation or interactivity (`612`),
- the decisive problem is still live same-object player-view-state aliasing on the source route (`546`),
- the decisive problem is still print/save/offline/web-archive authority or portability (`437`, `490`),
- or the decisive problem is still cross-state composite assembly (`591`).

If deleting the view-state layer leaves an ordinary clipped-window problem, layout problem, prominence problem, timing problem, navigation problem, or mixed-packet problem, use the narrower doc and omit `613`.
If deleting it would erase **why a later opening page, zoom level, or restored viewport changed the way the packet was being read**, `613` is probably right.

## Promotion rule

Future media additions should usually **not** be promoted just because a later packet opened on one page, restored one viewport, or magnified one preserved same-route detached derivative.
Tighten `546`, `594`, `600`, `608`, `609`, `611`, `612`, or `613` first.
Only add another numbered doc when repeated view-state mistakes still cannot be expressed as:
- one governing `595–599` member,
- or a mixed-packet routing note under `600`,
- plus one bounded wrapper-view-state note under `613`.
