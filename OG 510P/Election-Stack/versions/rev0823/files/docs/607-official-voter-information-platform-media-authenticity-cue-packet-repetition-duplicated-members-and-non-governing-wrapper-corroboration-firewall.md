# 607 — Official voter-information platform media authenticity-cue packet repetition, duplicated members, and non-governing wrapper-corroboration firewall

**Track:** Shared / Public surfaces

This document gives the archive one compact rule for **later wrapper-added repetition of the same detached-derivative member**.

It exists because `601–606` now separate later packet labels, summaries, markup, concealment, ordering, and membership choice.
But one bounded ambiguity still remained:
**a later packet can repeat the same member more than once — as a duplicated slide, repeated page, copied excerpt, repeated attachment, contact-sheet tile, or gallery-style repeat — and later readers can start treating that repetition as if it proved several independent source members, stronger corroboration, or the packet's governing member.**

This document answers that narrow question.

## Why this exists (bounded)

Current primary-source guidance already shows that later packet tools can duplicate or repeat the same member without creating a new source lineage.
Google Slides and PowerPoint both support duplicating slides.
Preview supports duplicating a PDF or image, and Preview's page-management guidance also treats pages as movable packet members in thumbnails/contact-sheet views.
That means later evidence packets can honestly contain the **same member more than once** without that multiplicity proving several independent source members.
(xref: `google_slides_add_delete_organize_slides_help_page`; xref: `microsoft_powerpoint_add_rearrange_duplicate_delete_slides_help_page`; xref: `apple_preview_copy_pdfs_images_mac_help_page`; xref: `apple_preview_add_delete_move_pdf_pages_mac_help_page`)

That is enough for one bounded rule:
**later wrapper repetition is descriptive, not corroborative by default.**

## This is not the same thing as `603`, `605`, `606`, or `591`

`603` is about later wrapper-added **emphasis**.
A repeated member may be emphatic, but `607` is not about arrows, boxes, or annotation.

`605` is about later wrapper-added **sequence**.
A repeated member may appear earlier or later in the packet, but `607` is not about order.

`606` is about later wrapper-added **membership choice**:
which distinct members got included at all.
`607` is different.
It asks what happens when a packet already includes a member and then **repeats that same member again**.

`591` is about later **multi-state assembly** across routes, times, or viewer conditions.
`607` is different.
It applies when later repetition risks making one same-member record look like several independent corroborating records.

Use `607` only when the decisive ambiguity is **wrapper-added repetition of the same member** rather than copied source content, later membership choice, or cross-state assembly.

## Default rule: classify the surviving derivative first; treat later wrapper repetition as descriptive unless provenance proves otherwise

By default, later notes SHOULD still cite the current controlling head under `530`, or the fallback anchor if the chain is headless.
A `607` note exists only to explain one bounded repetition mistake around that head.

Use this triage order:
1. if the decisive issue is still copied source text, use `595`;
2. if the decisive issue is still a detached still-image derivative, use `597`;
3. if the decisive issue is still copied source metadata, use `598`;
4. if the decisive issue is still a mixed detached-derivative packet with no dominant member, use `600`;
5. if the decisive issue is still short wrapper-added labeling, use `601`;
6. if the decisive issue is still longer wrapper-added summary prose, use `602`;
7. if the decisive issue is still wrapper-added emphasis or annotation, use `603`;
8. if the decisive issue is still wrapper-added concealment or suppression, use `604`;
9. if the decisive issue is still wrapper-added ordering or sequence, use `605`;
10. if the decisive issue is still wrapper-added inclusion or exclusion of distinct members, use `606`;
11. if the decisive issue is still cross-state composite assembly, use `591`;
12. if the decisive issue is still saved-page / print / offline portability or authority boundary, use `437` or `490`;
13. use `607` only when the decisive issue is that **a later packet repeated the same member — as a duplicate slide/page, repeated excerpt, repeated attachment, gallery tile, or similar wrapper multiplicity — and later retellings started treating that repetition as independent corroboration, source-native multiplicity, or governing-member proof.**

That means `607` is not a new citation lane.
It is a compact bridge for one bounded sentence saying that the packet repeated one same-member derivative and that this repetition should not be silently upgraded into several independent members, several independent observations, or a new governing member.

## Keep source-derived content and wrapper-added repetition separate

At minimum, keep these layers separate:
1. **current office control** — the current written/help lane and current media head (`194`, `369`, `529`, `530`);
2. **surviving detached derivative** — which `595–599` member, if any, the packet actually preserved;
3. **family routing** — whether the packet needed `600` because no single detached derivative dominated;
4. **source-derived text** — transcript/caption/OCR or other copied route text (`595`);
5. **source-derived metadata** — labels copied from the official route itself (`598`);
6. **wrapper-added packet label** — filename, subject line, slide title, memo heading, or similar short later-added narrative (`601`);
7. **wrapper-added summary prose** — forwarding comments, share messages, speaker notes, memo-body summaries, or similar longer later packet narrative (`602`);
8. **wrapper-added markup/emphasis** — highlight boxes, circles, arrows, underlines, comment anchors, zoom lenses, ink, or similar later visual emphasis (`603`);
9. **wrapper-added concealment/suppression** — redactions, crop-hidden regions, hidden slides, hidden objects, or similar later visual withholding (`604`);
10. **wrapper-added ordering/sequence** — reordered slide order, reordered PDF page order, moved packet sections, or similar later arrangement (`605`);
11. **wrapper-added membership/composition** — imported slides, merged-page subsets, chosen attachments, appended packet members, or similar later included-member selection (`606`);
12. **wrapper-added repetition/multiplicity** — duplicated slides, repeated pages, repeated excerpts, repeated attachments, gallery-style repeats, or similar later same-member multiplication (`607`);
13. **carrier wrapper** — slide deck, PDF memo, chat export, saved page, web archive, issue ticket, or other transport context (`437`, `490`, `600`);
14. **assembly state** — whether later materials also fused several observations into one stronger-looking posture (`591`).

That separation matters because later packets can otherwise make two different mistakes:
- treating wrapper-added repetition as if it proved independent corroboration or source-native multiplicity, or
- letting the repetition layer become the governing member instead of first classifying the surviving detached derivative.

`607` exists so the archive can keep that later repeated-member layer **truthful but non-governing**.

## Minimal wrapper-repetition note grammar

When wrapper-repetition overread itself matters, reviewers SHOULD prefer one compact line in this shape:

`head=<current tuple|none>; governing_member=<595|596|597|598|599|600|none>; wrapper_repetition_kind=<duplicate_slide|duplicate_page|repeated_excerpt|repeated_attachment|gallery_repeat|contact_sheet_repeat|mixed|unknown>; repeated_member_relation=<same_member|same_member_likely|mixed|unknown>; wrapper_repetition_origin=<later_wrapper_added|copied_from_source|mixed|unknown>; treat_repetition_as_independent_corroboration=<forbid>; treat_repetition_as_source_native_multiplicity=<forbid>; treat_repetition_as_additional_member=<forbid>; treat_repetition_as_governing_member=<forbid>; carrier_wrapper=<slide_deck|pdf_memo|chat_export|saved_page|web_archive|ticket|email_thread|shared_link_message|none>; cite_default=<head|fallback anchor>; use_607_when=<same_member_repeated_without_new_distinct_member>; promote_wrapper_repetition=<no>; basis=<why the later repetition needed one bounded note>`

This is a note contract, not a new schema.
It exists so packets and summaries can say “this packet repeated one same-member derivative” without minting a new detached-derivative member or silently rewriting corroboration weight.

## Typical uses

1. **Duplicate-slide overread**
   A packet duplicates one slide containing the same detached still, transcript excerpt, or copied label, and later readers start retelling the repeated slide count as if it proved several independent source members.
2. **Repeated-page overread**
   A packet repeats one page or screenshot page in a PDF and later readers start treating that page count as if it reflected several independent captured pages from the source route.
3. **Repeated-excerpt overread**
   A packet quotes or screenshots the same detached text or still several times in different packet positions and later readers start treating that repetition as if it were several independently corroborating extracts.
4. **Repeated-attachment overread**
   A later wrapper carries the same file or same screenshot more than once, and later readers start treating the repeated attachment count as if it were the source route's native multiplicity.
5. **Gallery/contact-sheet overread**
   A later wrapper renders the same member as thumbnails, contact-sheet items, or other repeated tiles, and later readers start treating that gallery multiplicity as if it were several distinct members.

## When not to use this

Do **not** use `607` when:
- the decisive issue is still copied source text (`595`),
- the decisive issue is still the detached still-image derivative itself (`597`),
- the decisive issue is still copied source metadata (`598`),
- the decisive issue is still a mixed detached-derivative packet with no dominant member (`600`),
- the decisive issue is still a short wrapper-added label (`601`),
- the decisive issue is still longer wrapper-added summary prose (`602`),
- the decisive issue is still wrapper-added emphasis or annotation (`603`),
- the decisive issue is still wrapper-added concealment or suppression (`604`),
- the decisive issue is still wrapper-added ordering or sequence (`605`),
- the decisive issue is still wrapper-added membership or composition of distinct members (`606`),
- the decisive problem is still print/save/offline/web-archive authority or portability (`437`, `490`),
- or the decisive problem is still cross-state composite assembly (`591`).

If deleting the repetition layer leaves an ordinary text derivative, still-image derivative, metadata derivative, mixed packet, label problem, summary-prose problem, markup problem, concealment problem, ordering problem, membership problem, saved-page issue, or composite-assembly claim, use the narrower doc and omit `607`.
If deleting it would erase **why a later duplicate slide/page/excerpt/attachment changed the way the packet was being retold or weighted**, `607` is probably right.

## Promotion rule

Future media additions should usually **not** be promoted just because a later packet duplicated slides, repeated pages, copied the same excerpt twice, or otherwise repeated one same-route detached derivative member.
Tighten `594`, `600`, `601`, `602`, `603`, `604`, `605`, `606`, or `607` first.
Only add another numbered doc when repeated repetition mistakes still cannot be expressed as:
- one governing `595–599` member,
- or a mixed-packet routing note under `600`,
- plus one bounded wrapper-label note under `601`,
- plus one bounded wrapper-summary note under `602`,
- plus one bounded wrapper-markup note under `603`,
- plus one bounded wrapper-concealment note under `604`,
- plus one bounded wrapper-ordering note under `605`,
- plus one bounded wrapper-membership note under `606`,
- plus one bounded wrapper-repetition note under `607`.
