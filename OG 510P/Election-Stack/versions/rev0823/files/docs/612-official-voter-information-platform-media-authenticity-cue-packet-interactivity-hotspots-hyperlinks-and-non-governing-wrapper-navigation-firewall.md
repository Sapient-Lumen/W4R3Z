# 612 — Official voter-information platform media authenticity-cue packet interactivity, hotspots, hyperlinks, and non-governing wrapper-navigation firewall

**Track:** Shared / Public surfaces

This document defines a bounded control for **later packet-level interactivity and navigation around same-route detached derivatives**:
later-added hyperlinks,
linked text, images, or shapes,
clickable hotspots,
action buttons,
internal page or slide jumps,
hover-triggered actions,
or similar wrapper-added navigation choices that change **where a viewer can go next or which preserved member looks like the packet's preferred path** without proving that the official source route itself natively carried that same click path, hierarchy, endorsement, or governing status.

It does not create a new authenticity cue family.
It adds one narrow rule:
**when a later packet adds its own click path or interactive navigation around preserved same-route detached derivatives, the archive should preserve that wrapper-navigation fact honestly and should not quietly treat the resulting hotspots, internal jumps, or external links as if they proved source-native navigation, source-native hierarchy, source-native endorsement, or the packet's governing member.**

## Why this exists (bounded)

The archive already distinguishes detached stills (`597`), copied text (`595`), copied metadata (`598`), copied locators (`599`), clipped observation windows (`594`), mixed detached-derivative packets (`600`), short wrapper labels (`601`), longer wrapper summaries (`602`), wrapper-added emphasis markup (`603`), wrapper-added concealment (`604`), wrapper-added ordering (`605`), wrapper-added membership (`606`), wrapper-added repetition (`607`), wrapper-added layout (`608`), wrapper-added prominence (`609`), wrapper-added styling (`610`), and wrapper-added timing (`611`).
A smaller but still important seam remains:
**a later packet can make one same-route detached derivative newly clickable, add a hotspot over it, or create a packet-specific jump path to another member or outside destination, and later readers can start narrating that wrapper navigation as if it proved source-native pathing, source-native hierarchy, source-native endorsement, or the packet's governing member.**

Current primary-source guidance is specific enough to justify one compact bridge here.
Google Docs Editors Help says links can be added, updated, or removed in Google Slides.
Microsoft's current support says PowerPoint action buttons or pictures can trigger hyperlinks to the next slide, previous slide, another presentation, another file, or another action on mouse click or mouse over.
Adobe's current Acrobat guidance says PDFs can add links that go to a page view, open a file, open a web page, or run another custom action.
(xref: `google_docs_work_with_links_bookmarks_help_page`; xref: `microsoft_powerpoint_action_buttons_help_page`; xref: `adobe_acrobat_add_links_pdfs_help_page`)

That is enough to support one bounded maintainer rule:
**later packet navigation is still only later packet navigation.**
A hotspot deck, linked PDF, click-through memo, or hover-action packet can honestly be the interactive experience later readers encountered while still failing to prove that the source route itself natively carried that same path, priority, recommendation, or governing status.
`612` exists so the archive can preserve that navigation fact without quietly promoting wrapper interactivity into source-native meaning.

## Keep source-derived content and wrapper-added navigation separate

At minimum, keep these layers separate:
1. **current office control** — the current written/help lane and current media head (`194`, `369`, `529`, `530`);
2. **surviving detached derivative** — which `595–599` member, if any, the packet actually preserved;
3. **family routing** — whether the packet needed `600` because no single detached derivative dominated;
4. **source-derived text** — transcript/caption/OCR or other copied route text (`595`);
5. **source-derived metadata** — labels copied from the official route itself (`598`);
6. **source-derived locator** — watch URL, share URL, timestamp URL, embed URL, or similar copied route pointer (`599`);
7. **wrapper-added packet label** — filename, subject line, slide title, memo heading, or similar short later-added narrative (`601`);
8. **wrapper-added summary prose** — forwarding comments, share messages, speaker notes, memo-body summaries, or similar longer later packet narrative (`602`);
9. **wrapper-added markup/emphasis** — highlight boxes, circles, arrows, underlines, comment anchors, zoom lenses, ink, or similar later visual emphasis (`603`);
10. **wrapper-added concealment/suppression** — redactions, crop-hidden regions, hidden slides, hidden objects, or similar later visual withholding (`604`);
11. **wrapper-added ordering/sequence** — reordered slide order, reordered PDF page order, moved packet sections, or similar later arrangement (`605`);
12. **wrapper-added membership/composition** — imported slides, merged-page subsets, chosen attachments, appended packet members, or similar later included-member selection (`606`);
13. **wrapper-added repetition/multiplicity** — duplicated slides, repeated pages, repeated excerpts, repeated attachments, gallery-style repeats, or similar later same-member multiplication (`607`);
14. **wrapper-added layout/spatial relation** — side-by-side placement, inset-over-main placement, gallery rows, stacked columns, split-screen comparison framing, or similar later positioning (`608`);
15. **wrapper-added prominence/salience** — enlarged hero panels, thumbnail demotion, resized excerpt blocks, large-versus-small weighting, or similar later visual importance allocation (`609`);
16. **wrapper-added styling/tone** — later themes, palettes, fonts, background styles, grayscale/sepia effects, warning-color coding, or similar visual tone choices (`610`);
17. **wrapper-added motion/timing** — later object animations, build order, delays, autoplay, transition timing, reveal-after-previous settings, or similar temporal staging choices (`611`);
18. **wrapper-added navigation/interactivity** — later hyperlinks, linked shapes or images, action buttons, clickable hotspots, internal jumps, hover-triggered actions, or similar click-path choices (`612`);
19. **carrier wrapper** — slide deck, PDF memo, chat export, saved page, web archive, issue ticket, or other transport context (`437`, `490`, `600`);
20. **assembly state** — whether later materials also fused several observations into one stronger-looking posture (`591`).

That separation matters because later packets can otherwise make two different mistakes:
- treating wrapper-added interactivity as if it proved source-native next-step logic, source-native hierarchy, or source-native endorsement, or
- letting a later clickable overlay or jump button become the governing member instead of first classifying the surviving detached derivative.

`612` exists so the archive can keep that later navigation layer **truthful but non-governing**.

## Minimal wrapper-navigation note grammar

When wrapper-navigation overread itself matters, reviewers SHOULD prefer one compact line in this shape:

`head=<current tuple|none>; governing_member=<595|596|597|598|599|600|none>; wrapper_navigation_kind=<hyperlink|internal_jump|action_button|hotspot|hover_action|file_link|external_link|mixed|unknown>; navigation_relation=<same_packet_member_link|same_route_derivative_link|external_handoff|mixed|unknown>; wrapper_navigation_origin=<later_wrapper_added|copied_from_source|mixed|unknown>; treat_navigation_as_source_path=<forbid>; treat_navigation_as_source_hierarchy=<forbid>; treat_navigation_as_source_endorsement=<forbid>; treat_navigation_as_governing_member=<forbid>; carrier_wrapper=<slide_deck|powerpoint_show|pdf_memo|chat_export|saved_page|web_archive|ticket|email_thread|shared_link_message|none>; cite_default=<head|fallback anchor>; use_612_when=<wrapper_navigation_changed_perceived_path>; promote_wrapper_navigation=<no>; basis=<why the later interactivity needed one bounded note>`

This is a note contract, not a new schema.
It exists so packets and summaries can say “this packet later created its own click path around the preserved members” without minting a new detached-derivative member or silently rewriting navigation, hierarchy, endorsement, or governance.

## Typical uses

1. **Linked-image overread**
   A packet makes one preserved still, excerpt block, or title clickable and later readers start retelling that click path as if the source route itself natively treated that member as the preferred next step.
2. **Hotspot-overread**
   A packet places an invisible or shape-based hotspot over one preserved member and later readers start treating that hotspot as if it proved source-native hierarchy or source-native recommendation.
3. **Internal-jump overread**
   A packet adds slide-to-slide or page-to-page jumps and later readers start narrating that wrapper path as if the source route itself natively sequenced or grouped those members that way.
4. **External-link overread**
   A packet adds a later exit to a website, file, or other resource and later readers start treating that wrapper-added destination as if it were source-native endorsement or source-native routing.
5. **Hover-action overread**
   A packet uses mouse-over or similar interactive triggers and later readers start treating that wrapper-only behavior as if the source route itself natively revealed, recommended, or prioritized the linked member.
