# 545 — Official voter-information platform media text-track selection states, caption/subtitle language picks, and head/default retention discipline

**Track:** Shared

This document gives the recent platform-media chain layer one more compact rule.

It exists because the archive already knows how to separate:
- the underlying media object itself (`369` and `528–529`),
- browser- or platform-generated caption/translation overlays (`492`),
- transcript panes and searchable transcript jumps (`493`),
- alternate audio / dubbed-audio surface-boundary behavior (`501`),
- selected spoken-audio track state inside the same object (`552`),
- explicit same-object offset routes (`539`),
- app-launch/container shifts (`542`),
- remembered resume (`543`),
- and player-internal moment jumps such as transcript clicks or chapter picks (`544`).

A smaller ambiguity still remains:
**what should the archive do when the same media object stays current, but the viewer turns captions on, switches subtitle language, selects auto-translate, or lands in an embed that defaulted a particular text track — and that text-track state starts to look like a new current route, a new official edition, or a safer citation target than the controlling head?**

This document answers that narrow question.

## Why this exists (bounded)

Current official platform help already shows that the same media object can stay current while the **visible text-track state** changes inside the player.
YouTube says viewers can turn captions on or off, select a language, and use Auto-translate when a desired language is not directly listed.
Vimeo says viewers can turn captions or subtitles on/off and choose among available tracks, and that embeds can default a specific text track or autogenerated captions while viewers still retain the ability to switch or turn tracks off.
Microsoft says viewers can turn captions on or off, choose the available caption language, and that caption-display customizations last only for the browser session.
(xref: `youtube_manage_caption_settings_help_page`; xref: `vimeo_viewing_captions_subtitles_help_page`; xref: `vimeo_embed_default_texttrack_help_page`; xref: `microsoft_video_transcripts_and_captions_help_page`)

That means one same-object chain can truthfully contain all of the following at once:
- one current controlling head,
- one caption/subtitle track state that materially changed what the viewer saw,
- one provenance difference such as creator-supplied, autogenerated, or translated text,
- and no new office-published route at all.

Without a compact rule here, reviewers tend to make one of four mistakes:
- they treat a selected caption/subtitle language as if the office published a new current route,
- they collapse text-track state into `492` even when the decisive fact is player-native track selection rather than browser-generated overlay behavior,
- they let an embed-default text track or remembered caption default quietly become the citation-safe present-tense default,
- or they leave the text-track fact out entirely and later cannot explain why the visible wording, language, or apparent scope differed while the same object still controlled.

This document fixes that bounded ambiguity.
It standardizes one small note for **same-object text-track state + head/default retention**.

## This is not the same thing as `377`, `492`, `493`, `501`, `539`, `544`, or `552`

`377` governs official language selectors, locale fallback, and machine-translation boundaries on the surrounding answer route.

`492` governs browser- or platform-generated live captions, subtitle translation, and transcript-like overlays that are not simply the player's own selected text track.

`493` governs transcript panes, searchable transcripts, and transcript-derived jump surfaces around already-open media.

`501` governs whether alternate spoken-audio tracks such as dubbed audio, commentary, or descriptive audio have become an authority-boundary problem in the first place.

`552` governs selected spoken-audio track state inside an already-governed same-object chain.

`539` governs explicit copied or encoded same-object offset routes such as `Start at` or current-time links.

`544` governs transcript clicks, chapter picks, table-of-contents picks, and similar player-internal moment selections.

`545` is different.
It says that sometimes one same-object chain should keep:
- one full-object current head or fallback anchor,
- plus one or more **text-track state notes** such as captions-on, subtitle-language-selected, auto-translate-selected, or embed-default texttrack,
- while recording that those states changed the visible text rendering **without** creating a new published route, a new head, or a safer citation target than the controlling head.

If the decisive issue is the official multilingual route outside the player, use `377`.
If the decisive issue is browser-generated captioning or translation, use `492`.
If the decisive issue is transcript search/jump behavior, use `493` or `544`.
If the decisive issue is what the viewer heard through another audio track inside the same current object, use `552`.
If the decisive issue is whether alternate spoken audio has become an authority-boundary problem at all, use `501`.
Use `545` only when the surface is already understood but the archive still needs to classify the **same-object selected text-track state** inside an already-governed media chain.

## Default rule: preserve text-track truth, but keep control with the head

Inside one `528` same-object chain, reviewers MAY keep a compact **text-track state note** when all of the following hold:

1. **The underlying object is still the same.**
   The playback stayed within the same office-controlled event, recording, or published media answer.
2. **The practical difference is player text-track state, not a new publication.**
   The decisive fact is that captions were enabled/disabled, a subtitle language was selected, auto-translate was chosen, or an embed loaded with a particular text-track default.
3. **Treating the state as a new route would mislead.**
   A reader could mistake a transient or viewer-specific text-track choice for a new current head, a reviewed translated edition, or an explicit route alias.
4. **A better present-tense default still exists or the chain is honestly headless.**
   `529` and `530` can still name the current head, or `533` can honestly say no public media head exists and point to the best fallback anchor instead.
5. **The text-track fact still matters.**
   The archive would lose useful truth if it omitted what caption/subtitle state the viewer actually saw, whether the wording was autogenerated or translated, or why the visible text did not match another viewer's rendering.

When those conditions hold, keep the head/default under `529–530`, keep any multilingual-route fact under `377`, keep any browser-generated overlay fact under `492`, keep any spoken-track boundary fact under `501`, keep any selected spoken-track fact under `552`, and add one `545` text-track state note.
Do **not** silently promote the selected track into the chain's current head.

## Minimal text-track grammar

When a same-object chain has a current head or fallback anchor plus a meaningful selected caption/subtitle state, reviewers SHOULD prefer one line in this shape:

`chain=<stable object label>; head=<current tuple|none>; texttrack_aliases=<route family>; texttrack_class=<captions_on|captions_off|subtitle_language_selected|caption_language_selected|auto_translate_selected|embed_default_texttrack|autogenerated_texttrack_default>; track_provenance=<creator_uploaded|auto_generated|translated|unknown>; selection_scope=<viewer_selected|embed_default|account_default|browser_session_default>; cite_default=<head|fallback anchor>; cite_texttrack_when=<visible-wording, language-rendering, or selected-track claim>; promote_texttrack=<no>; basis=<why the selected text track mattered without becoming the public default>`

This is a compact note contract, not a new schema field.
It exists so packet notes can preserve **which visible text layer the viewer actually used** without making every caption toggle or subtitle-language choice sound like a fresh publication or a safer citation target than the head.

## When to use a text-track note

Typical uses include:

1. **Same recording, different subtitle language**
   The current head still controls, but a selected subtitle/caption language matters because the visible wording or the viewer's apparent understanding depended on that chosen track.
2. **Embed defaulted captions or a specific text track**
   The same object is still current, but the embedded player loaded a particular text track by default and that first-view state matters for reproduction or visible-wording claims.
3. **Same object with auto-generated or auto-translated text**
   The same head controls, but the archive needs to preserve that the viewer relied on autogenerated or translated text rather than a creator-reviewed subtitle file.
4. **Text-track state intertwined with app launch, explicit offset, remembered resume, or in-player jump**
   The archive may need `545` plus `542`, `539`, `543`, or `544` when the same object both launched in-app, resumed from memory, landed at an offset, or jumped within the player while also showing a particular caption/subtitle state. Keep those facts separate instead of letting one note absorb the others.

## Citation rule

By default, later notes SHOULD still cite the **current controlling head** under `530`, or the fallback anchor if the chain is headless under `533`.
A `545` text-track state note SHOULD be cited only when the later claim is specifically about:
- which caption/subtitle language or track the viewer saw,
- whether the visible wording depended on autogenerated, translated, or creator-supplied text,
- whether an embed or session default preselected a text track,
- or why the archive refused to let a selected text track outrank the head-first citation rule.

That means `545` preserves one honest text-rendering exception to head-first citation without letting player state quietly become the archive's present-tense authority object.

## When not to use this

Do **not** use `545` when:
- the decisive issue is the surrounding multilingual route, locale fallback, or machine-translation boundary outside the player — use `377`,
- the decisive issue is browser- or platform-generated live captions/subtitle translation over the page or media rather than the selected player text track — use `492`,
- the decisive issue is the transcript pane, transcript search, or transcript-derived jump surface — use `493`,
- the decisive issue is the spoken track or dubbed-audio selection inside the same current object — use `552`,
- the decisive issue is whether alternate spoken audio became an authority-boundary problem at all — use `501`,
- the decisive issue is an explicit copied/encoded `Start at` or current-time route — use `539`,
- the decisive issue is a transcript click, chapter pick, or other in-player moment jump — use `544`,
- or the archive is trying to preserve fine-grained personal subtitle-preference telemetry beyond what bounded reconstruction requires.

If deleting the text-track fact would erase **which visible text layer the viewer actually used**, `545` is probably the right companion.
If deleting that fact would erase the whole publication or routing story, the problem probably belongs elsewhere.

## Tie-breaker when reviewers ask “if viewers read that subtitle track, why isn't that the head?”

Ask three questions:
- does the selected text track prove **how the same object was rendered to the viewer** rather than **what the archive says controls for the ordinary public now**,
- would a head-first summary become less accurate if it defaulted to a viewer-selected or embed-default text track,
- and is the missing fact really about the selected player track rather than about the multilingual route, a browser-generated overlay, a spoken-audio track, or an explicit route alias?

If yes, keep current control under `529–530`, preserve any multilingual or browser-generated text-layer fact under `377` or `492`, preserve any spoken-track boundary fact under `501`, preserve any selected spoken-track fact under `552`, and record the selected text-track state under `545`.
Do **not** let the text-track state absorb chain control.

## Promotion rule

Future media additions should usually **not** be promoted just because the same object exposed another caption toggle, subtitle-language pick, or embed-default text-track parameter.
Tighten `545` first.
Only add another numbered surface when the ambiguity is really about a new route class, a new public surface, or a new authority object rather than about **selected caption/subtitle state inside an already-governed same-object media chain**.
