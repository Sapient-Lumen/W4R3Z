# Election calendar surface checklist

- Identify one authoritative public calendar path and one authoritative help path for the election scope.
- Publish only dates and deadlines that materially change voter or observer actionability.
- Distinguish legal deadlines from recommended early-action dates.
- Distinguish dates from hours windows and identify the controlling timezone.
- For each calendar entry, point to the more-specific detailed surface that governs exceptions or full instructions.
- Treat changed dates, changed hours windows, and changed deadline semantics as explicit superseding notices, not silent edits.
- Publish bounded advisories for emergency, court-order, outage, or mailing-disruption changes that affect the calendar surface.
- Check parity across website, downloadable calendar/PDF, hotline/help scripts, and signed notices.
- Publish accessible and translated versions where required, plus a fallback contact path when the primary calendar page fails.
- Do not publish per-voter reminders, internal staffing calendars, or copied legal text when a bounded summary plus a pointer to the detailed surface will do.
- Record `last_verified_at`, the controlling timezone, and the latest correction/advisory notice pointer.
