# Official voter-information platform upcoming-event-surface checklist

Use this checklist when an election office needs the **current answer/help lane to remain reconstructible even if official voter-information media is exposed through a public upcoming-event page, Premiere watch page, waiting-room shell, or pre-live countdown surface before the media actually starts**.

## Scope and boundary review

- [ ] Record which public event pages, Premiere watch pages, waiting-room shells, or pre-live player states were reviewed.
- [ ] Distinguish this surface from follow/reminder state, interaction layers, collection pages, and the finished recording/livestream lane.
- [ ] Keep “the event shell is public before start” separate from “the shell itself is the complete current official answer.”

## Before-start discoverability review

- [ ] Review whether the event shell can be shared, embedded, or discovered before the event starts.
- [ ] Review whether platform search, recommendations, copied links, or channel surfaces can let the voter meet the shell before the current written route.
- [ ] Do not let discoverability before start silently turn the shell into the primary current-answer lane.

## Countdown / waiting-room / trailer review

- [ ] Review whether countdowns, trailers, recurring-schedule overlays, or “hasn’t started yet” messages overstate currentness or urgency.
- [ ] Review whether delay, reschedule, or cancellation states remain truthful on the shell itself.
- [ ] Keep visual imminence cues from standing in for explicit current written/help recovery.

## Interaction-before-start review

- [ ] Review whether comments, chat, Q&A, or similar interaction can appear before the media starts.
- [ ] Review whether organizer or moderator presence on the event shell makes the shell feel like the office's settled help desk.
- [ ] Keep pre-start conversation subordinate to the current written/help lane rather than the only visible current answer path.

## Recovery and current-state review

- [ ] Keep the current written page, notice, FAQ/help entry, or named office contact recoverable from the pre-start shell.
- [ ] Re-review event shells that may remain public after delays, reschedules, cancellations, or election-cycle turnover.
- [ ] Keep recurring or reused event shells from silently carrying last cycle's authority into the next one.

## Authority-boundary review

- [ ] Treat upcoming-event pages and pre-live shells as scheduling/discovery surfaces rather than proof that the controlling operational answer already lives there.
- [ ] Preserve a small public digest of reviewed shell states, countdown/trailer posture, recovery anchors, and last review time rather than private analytics or viewer traces.
- [ ] Keep the finished recording/livestream publication distinct from the not-yet-started event shell that preceded it.
