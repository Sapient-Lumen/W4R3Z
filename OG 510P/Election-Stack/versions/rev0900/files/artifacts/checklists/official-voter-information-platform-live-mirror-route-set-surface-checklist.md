# Official voter-information platform live mirror / route-set surface checklist

Use this checklist when the same official voter-information live event is intentionally exposed through more than one public route or continuation handoff.

## Scope

- [ ] Reviewed the exact public route set, not just the primary admin console or one preferred platform.
- [ ] Distinguished same-event mirror routes from ordinary copied links, post-event replays, and unrelated partner reposts.
- [ ] Recorded which platforms, embeds, and continuation handoffs were materially relied on.

## Route-set review

- [ ] Verified whether one route was primary and whether any others were mirrors or fallbacks.
- [ ] Verified whether the office exposed a redirect or continuation handoff between official routes.
- [ ] Verified whether the office kept the current written/help lane recoverable from each route in the set.

## Feature-difference review

- [ ] Checked whether captions, chat/Q&A, sign-in posture, delay, or embed context differed materially across official routes.
- [ ] Verified the office did not treat “all official routes are live” as equivalent to “all official routes provide the same public-help posture.”
- [ ] Logged any route-specific limitations that could affect voter understanding or accessibility.

## Failure and fallback posture

- [ ] Verified the office had a legible fallback order when one mirror failed, lagged, or exposed fewer features.
- [ ] Verified redirect destinations remained inside the intended official route set and were legible as route changes.
- [ ] Logged whether route-set behavior differed across platform-native and embedded contexts.

## Public proof posture

- [ ] Logged which routes were official, which route was primary (if any), and when the route-set review occurred.
- [ ] Avoided publishing stream keys, individualized path telemetry, or private platform-admin traces.
