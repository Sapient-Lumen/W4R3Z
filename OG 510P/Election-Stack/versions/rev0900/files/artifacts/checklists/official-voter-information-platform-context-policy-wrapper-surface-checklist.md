# Official voter-information platform context/policy-wrapper surface checklist

Use this checklist when official voter-information media is accompanied by platform-added context panels, information boxes, disclosure labels, ratings, classification cues, or protection banners.

## Scope

- [ ] Reviewed the exact public media route whose context/policy wrapper mattered, not just a private admin or uploader console.
- [ ] Logged which wrapper type was reviewed (for example: context panel, election information panel, AI-generated label, content rating, sensitivity label, or protection banner).
- [ ] Logged which route form was reviewed (native watch page, embed, shared file flow, page wrapper, or similar).

## Wrapper-state review

- [ ] Verified the exact wrapper text or cue shown there and whether it appeared office-authored, platform-authored, policy-generated, or third-party-sourced.
- [ ] Checked whether the same media showed materially different wrapper state across native, embedded, file-sharing, or copied routes.
- [ ] Checked whether wrapper presence or absence could be conditional on election cycle, region, policy, title visibility, or route type.

## Authority-boundary review

- [ ] Verified the office did not let a context panel, label, rating, sensitivity cue, or protection banner stand in for the current written/help lane.
- [ ] Verified the current written/help lane remained recoverable even if the wrapper looked explanatory or cautionary on its own.
- [ ] Verified the office did not treat wrapper presence or absence as the whole proof that the route was current, official, or lawfully dispositive.

## Public proof posture

- [ ] Logged the reviewed route, the wrapper state shown there, and when the review occurred.
- [ ] Avoided publishing private moderation histories, internal admin settings, partner telemetry, or other non-public control-plane data beyond what the public route itself exposed.
