# Official voter-information data-table surface checklist

Use this checklist for official voter-information routes that place answer-bearing facts inside tables, comparison grids, schedules, or directory-style row/column views.

## Scope and table inventory

- [ ] Identify the official routes where tables carry deadlines, exceptions, office routing, schedules, or next-step instructions.
- [ ] Record which tables are decisive enough that a voter must find the right row, column, or cell to learn what controls.
- [ ] Record whether the route uses ordinary table, responsive stacked table, horizontal overflow, expandable rows, sort controls, or filters.

## Headers and row/cell meaning

- [ ] Row and column headers are meaningful to voters and preserve the meaning of each visible value.
- [ ] Complex multi-level or irregular headers were reviewed deliberately rather than assumed to stay understandable.
- [ ] Mobile/stacked variants keep enough header context that each value still says what it means.
- [ ] The table does not depend on decorative abbreviations, icons, or clipped labels to carry the controlling distinction.

## Responsive overflow and visible state

- [ ] Narrow-screen and zoomed views were checked so decisive columns do not disappear into unnoticed horizontal overflow.
- [ ] If horizontal scrolling remains necessary, the route still makes it obvious that more answer-bearing columns exist.
- [ ] Expandable-row or stacked-card variants keep the controlling row/cell meaning intact rather than dropping the governing label.
- [ ] Print/save views were checked when the route expects people to keep a record of a table-based answer.

## Sort, filter, and row findability

- [ ] Sortable columns expose the current sort state visibly and programmatically.
- [ ] Default sorting/grouping does not quietly imply the wrong priority or authority.
- [ ] Search/filter controls do not hide decisive rows without making the active filter state obvious.
- [ ] Routes that direct users to a specific row, office, date, or site preserve an ordinary way to re-find that row after reopen, revisit, or share.
- [ ] There is a visible help or overview escape path when the table alone does not resolve the case.

## Evidence discipline

- [ ] The review records which tables were checked, which responsive mode was observed, and whether sorting/filtering was part of the answer lane.
- [ ] The review records when the check occurred and which route/version was observed.
- [ ] The archive does not retain named-user table searches, individualized interaction traces, or unnecessary replay exhaust for this bounded surface.
