# 610 — Official voter-information platform media authenticity-cue packet styling, themes, color coding, and non-governing wrapper-tone firewall

**Track:** Shared / Public surfaces

This document defines a bounded control for **later packet-level styling around same-route detached derivatives**:
later-applied themes,
background palettes,
font schemes,
warning-color coding,
brand-template restyling,
or similar wrapper-added visual tone choices that change **how urgent, official-looking, neutral, or severe one preserved member appears** without proving that the official source route itself natively carried the same palette, typography, background treatment, or implied urgency.

It does not create a new authenticity cue family.
It adds one narrow rule:
**when a later packet changes the styling or visual tone around preserved same-route detached derivatives, the archive should preserve that wrapper-styling fact honestly and should not quietly treat the resulting color, font, theme, or background choice as if it proved source-native urgency, source-native officiality, source-native sentiment, or the packet's governing member.**

## Why this exists (bounded)

The archive already distinguishes detached stills (`597`), copied text (`595`), copied metadata (`598`), clipped observation windows (`594`), mixed detached-derivative packets (`600`), short wrapper labels (`601`), longer wrapper summaries (`602`), wrapper-added emphasis markup (`603`), wrapper-added concealment (`604`), wrapper-added ordering (`605`), wrapper-added membership (`606`), wrapper-added repetition (`607`), wrapper-added layout (`608`), and wrapper-added prominence (`609`).
A smaller but still important seam remains:
**a later packet can restyle one same-route detached derivative or the packet around it with warning colors, campaign-like palettes, official-looking templates, or font/background choices, and later readers can start narrating that wrapper styling as if it proved source-native urgency, source-native officiality, source-native sentiment, or the packet's governing member.**

Current primary-source guidance is specific enough to justify one compact bridge here.
Google Slides' current help says a theme is a preset group of colors, fonts, backgrounds, and layouts, and that theme colors can be edited.
Microsoft's current support says PowerPoint themes can change colors, fonts, effects, and background styles.
Apple's current Preview guidance says note color, text style, border color, and fill color can be changed for annotations.
(xref: `google_slides_change_theme_background_layout_help_page`; xref: `microsoft_add_color_design_slides_themes_help_page`; xref: `apple_preview_annotate_pdf_mac_help_page`)

That is enough to support one bounded maintainer rule:
**later packet styling is still only later packet styling.**
A red-alert palette packet, official-blue template packet, grayscale-muted packet, or font-restyled packet can honestly be the tone later readers encountered while still failing to prove that the source route itself natively carried that same urgency, branding, neutrality, or governing status.
`610` exists so the archive can preserve that tone fact without quietly promoting wrapper styling into source-native meaning.

## Keep source-derived content and wrapper-added styling separate

At minimum, keep these layers separate:
1. **current office control** — the current written/help lane and current media head (`194`, `369`, `529`, `530`);
2. **surviving detached derivative** — which `595–599` member, if any, the packet actually preserved;
3. **family routing** — whether the packet needed `600` because no single detached derivative dominated;
4. **source-derived text** — transcript/caption/OCR or other copied route text (`595`);
5. **source-derived metadata** — labels copied from the official route itself (`598`);
6. **wrapper-added packet label** — filename, subject line, slide title, memo heading, or similar short later-added narrative (`601`);
7. **wrapper-added summary prose** — forwarding comments, share messages, speaker notes, memo-body summaries, or similar longer later packet narrative (`602`);
8. **wrapper-added markup/emphasis** — highlight boxes, circles, arrows, underlines, comment anchors, zoom lenses, ink, or similar later visual emphasis (`603`);
9. **wrapper-added concealment/suppression** — redactions, crop-hidden regions, hidden slides, hidden objects, or similar later visual withholding (`604`);
10. **wrapper-added ordering/sequence** — reordered slide order, reordered PDF page order, moved packet sections, or similar later arrangement (`605`);
11. **wrapper-added membership/composition** — imported slides, merged-page subsets, chosen attachments, appended packet members, or similar later included-member selection (`606`);
12. **wrapper-added repetition/multiplicity** — duplicated slides, repeated pages, repeated excerpts, repeated attachments, gallery-style repeats, or similar later same-member multiplication (`607`);
13. **wrapper-added layout/spatial relation** — side-by-side placement, inset-over-main placement, gallery rows, stacked columns, split-screen comparison framing, or similar later positioning (`608`);
14. **wrapper-added prominence/salience** — enlarged hero panels, thumbnail demotion, resized excerpt blocks, large-versus-small weighting, or similar later visual importance allocation (`609`);
15. **wrapper-added styling/tone** — later themes, palettes, fonts, background styles, grayscale/sepia effects, warning-color coding, or similar visual tone choices (`610`);
16. **carrier wrapper** — slide deck, PDF memo, chat export, saved page, web archive, issue ticket, or other transport context (`437`, `490`, `600`);
17. **assembly state** — whether later materials also fused several observations into one stronger-looking posture (`591`).

That separation matters because later packets can otherwise make two different mistakes:
- treating wrapper-added styling as if it proved source-native urgency, source-native officiality, or source-native sentiment, or
- letting an official-looking or warning-colored wrapper become the governing member instead of first classifying the surviving detached derivative.

`610` exists so the archive can keep that later styling layer **truthful but non-governing**.

When wrapper-styling overread itself matters, reviewers SHOULD prefer one compact line in this shape:

`head=<current tuple|none>; governing_member=<595|596|597|598|599|600|none>; wrapper_style_kind=<theme|background_palette|font_scheme|color_coding|background_effect|mixed|unknown>; style_relation=<same_route_packet_restyling|same_route_member_restyling|mixed|unknown>; wrapper_style_origin=<later_wrapper_added|copied_from_source|mixed|unknown>; treat_style_as_source_urgency=<forbid>; treat_style_as_source_officiality=<forbid>; treat_style_as_governing_member=<forbid>; carrier_wrapper=<slide_deck|pdf_memo|chat_export|saved_page|web_archive|ticket|email_thread|shared_link_message|none>; cite_default=<head|fallback anchor>; use_610_when=<wrapper_styling_changed_perceived_tone>; promote_wrapper_style=<no>; basis=<why the later styling needed one bounded note>`

This is a note contract, not a new schema.
It exists so packets and summaries can say “this packet later made the material look urgent, official, or subdued through styling” without minting a new detached-derivative member or silently rewriting provenance, urgency, or governance.

## Typical uses

1. **Warning-palette overread**
   A packet wraps a same-route detached derivative in red, orange, or other alert-like colors and later readers start retelling that palette as if the source route itself signaled emergency or elevated severity.
2. **Official-template overread**
   A packet applies office-looking branding, fonts, or slide theme choices around preserved members and later readers start treating that wrapper template as if it proved source-native officiality or currentness.
3. **Muted/grayscale overread**
   A packet converts preserved members to grayscale, sepia, or another subdued look and later readers start retelling that tone as if the source route itself visually demoted or historicized the material.
4. **Font-tone overread**
   A packet changes typography so one preserved member reads like a warning banner, formal notice, or casual aside and later readers start treating the font choice as if it came from the source route itself.
5. **Background-style overread**
   A packet changes background styles around preserved members so strongly that later readers start treating the surrounding visual tone rather than provenance as the reason one member governs.
