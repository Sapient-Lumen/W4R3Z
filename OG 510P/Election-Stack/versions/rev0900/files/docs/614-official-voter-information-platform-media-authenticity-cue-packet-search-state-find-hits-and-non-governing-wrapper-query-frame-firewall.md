# 614 — Official voter-information platform media authenticity-cue packet search state, find hits, and non-governing wrapper-query-frame firewall

**Track:** Shared / Public surfaces

This document defines a bounded control for **later packet-level search or find state around same-route detached derivatives**:
later-entered search queries,
find-in-file or find-in-page state,
hit highlighting,
next/previous-match stepping,
search-results panes or sidebars,
search-rank ordering,
or similar wrapper-added query framing that changes **which preserved member, phrase, or region is foregrounded by a viewer's search posture** without proving that the official source route itself natively foregrounded those hits, guaranteed that result set as complete, or made the search-conditioned member the packet's governing member.

It does not create a new authenticity cue family.
It adds one narrow rule:
**when a later packet carries its own query-conditioned search frame around preserved same-route detached derivatives, the archive should preserve that wrapper-query fact honestly and should not quietly treat highlighted hits, search-result panes, or stepped matches as if they proved source-native emphasis, source-native completeness, or the packet's governing member.**

## Why this exists (bounded)

The archive already distinguishes copied source text (`595`), detached stills (`597`), copied source metadata (`598`), mixed detached-derivative packets (`600`), wrapper-added labels (`601`), wrapper-added summaries (`602`), wrapper-added markup (`603`), wrapper-added concealment (`604`), wrapper-added ordering (`605`), wrapper-added membership (`606`), wrapper-added repetition (`607`), wrapper-added layout (`608`), wrapper-added prominence (`609`), wrapper-added styling (`610`), wrapper-added timing (`611`), wrapper-added navigation (`612`), and wrapper-added view state (`613`).
A smaller but still important seam remains:
**a later packet can be opened under a search query or find state that highlights one phrase, ranks one set of hits, or steps the viewer through one narrowed subset of the preserved material, and later readers can start narrating that query-conditioned view as if it proved source-native emphasis, source-native completeness, or the packet's governing member.**

Current primary-source guidance is specific enough to justify one compact bridge here.
Google Docs Editors Help says Docs and Slides support Find and replace, with next/previous navigation and optional narrowing.
Microsoft Support says PowerPoint supports Find and Replace and Find Next within a presentation.
Adobe Acrobat says PDF searches can use the Search window or Find toolbar, highlight matching results in the PDF, and search across multiple PDFs.
Apple Preview says PDF search can show results, move next/previous, and sort matches by search rank or page order.
(xref: `google_docs_search_find_replace_help_page`; xref: `microsoft_powerpoint_find_replace_text_help_page`; xref: `adobe_acrobat_searching_pdfs_help_page`; xref: `apple_preview_find_text_pdfs_help_page`)

That is enough to support one bounded maintainer rule:
**later packet query framing is still only later packet query framing.**
A searched slide deck, highlighted PDF hit list, query-conditioned saved page, or stepped-through packet can honestly be the experience later readers encountered while still failing to prove that the source route itself natively foregrounded those hits, guaranteed that narrowed result set as complete, or made the hit-bearing member govern the packet.
`614` exists so the archive can preserve that query-conditioned posture without quietly promoting wrapper search state into source-native meaning.

## This is not the same thing as `557`, `595`, `603`, `613`, `600`, `597`, `598`, `594`, `490`, or `591`

`557` asks whether the same current object merely had its native transcript pane opened, searched, or left highlighting one line inside the live route itself.

`595` asks whether the decisive surviving artifact is still copied source text itself.

`603` asks whether later packet emphasis or annotation was manually added as markup.

`613` asks whether later packet opening posture, zoom, fit mode, or restored viewport changed the first view.

`600` asks how to route a mixed same-route packet when several detached derivatives coexist and no single `595–599` member clearly dominates.

`597` and `598` ask whether the decisive surviving artifact is still the detached still-image derivative or copied source metadata themselves.

`594` asks whether later evidence preserved only a clipped observation window.

`490` asks whether saved-page / offline / web-archive carriage changed authority or portability posture.

`591` asks whether later materials fused observations from different routes, times, viewer conditions, or interaction states into one faux simultaneous posture.

`614` asks a different question:
**did a later packet add or preserve its own search query, find state, hit highlighting, or search-result ordering around same-route detached derivatives, and did later readers start overreading that wrapper query frame as if it proved source-native emphasis, source-native completeness, or the packet's governing member?**

If the real problem is native transcript-pane search on the live route, use `557`.
If the real problem is copied source text, use `595`.
If the real problem is manual markup or annotation, use `603`.
If the real problem is only opening posture or zoom, use `613`.
If the real problem is a balanced mixed packet, use `600`.
If the real problem is clipping, use `594`.
If the real problem is saved-page/web-archive authority boundary, use `490`.
If the real problem is cross-state assembly, use `591`.
Use `614` only when the missing distinction is **query-conditioned packet search state itself**.

## Decision test

Use `614` when all three conditions hold:

1. later evidence preserves or reenacts a **search / find posture** around same-route detached derivatives — for example a query string, hit-highlighting, result pane, next/previous stepping, search-rank sort, or page-order hit list;
2. that search posture is **later packet state or later viewer query state**, not the source route's own reviewed text, metadata, or ordinary live transcript-pane search behavior;
3. later readers are starting to treat the query-conditioned hits as if they proved source-native emphasis, source-native completeness, or that the hit-bearing member governs the packet.

When those conditions hold, keep the current control in `194` / `530`, keep the surviving detached derivative in `595–600`, keep any clipped-window fact in `594`, keep any manual markup fact in `603`, keep any view-state fact in `613`, and add one bounded `614` query-state note.

## Keep source-derived content and wrapper-added query framing separate

At minimum, keep these layers separate:
1. **current office control** — the current written/help lane and current media head (`194`, `369`, `529`, `530`);
2. **surviving detached derivative** — which `595–599` member, if any, the packet actually preserved;
3. **family routing** — whether the packet needed `600` because no single detached derivative dominated;
4. **source-derived text** — transcript/caption/OCR or other copied route text (`595`);
5. **source-derived metadata** — labels copied from the official route itself (`598`);
6. **native route search state** — transcript-pane or same-route native search posture (`557`);
7. **wrapper-added packet label** — filename, subject line, slide title, memo heading, or similar short later-added narrative (`601`);
8. **wrapper-added summary prose** — forwarding comments, share messages, speaker notes, memo-body summaries, or similar longer later packet narrative (`602`);
9. **wrapper-added markup/emphasis** — highlight boxes, circles, arrows, underlines, comment anchors, zoom lenses, ink, or similar later visual emphasis (`603`);
10. **wrapper-added concealment/suppression** — redactions, crop-hidden regions, hidden slides, hidden objects, or similar later visual withholding (`604`);
11. **wrapper-added ordering/sequence** — reordered slide order, reordered PDF page order, moved packet sections, or similar later arrangement (`605`);
12. **wrapper-added membership/composition** — imported slides, merged-page subsets, chosen attachments, appended packet members, or similar later included-member selection (`606`);
13. **wrapper-added repetition/multiplicity** — duplicated slides, repeated pages, repeated excerpts, repeated attachments, gallery-style repeats, or similar later same-member multiplication (`607`);
14. **wrapper-added layout/spatial relation** — side-by-side placement, inset-over-main placement, gallery rows, stacked columns, split-screen comparison framing, or similar later positioning (`608`);
15. **wrapper-added prominence/salience** — enlarged hero panels, thumbnail demotion, resized excerpt blocks, large-versus-small weighting, or similar later visual importance allocation (`609`);
16. **wrapper-added styling/tone** — later themes, palettes, fonts, background styles, warning-color coding, or similar visual tone choices (`610`);
17. **wrapper-added motion/timing** — later object animations, build order, delays, autoplay, transition timing, or similar temporal staging choices (`611`);
18. **wrapper-added navigation/interactivity** — later hyperlinks, linked shapes or images, action buttons, clickable hotspots, internal jumps, or similar click-path choices (`612`);
19. **wrapper-added view state/viewport** — later initial-view settings, open-page/open-slide choices, zoom level, fit mode, restored last-view state, or similar opening posture (`613`);
20. **wrapper-added query frame/search state** — later search terms, hit highlighting, next/previous match stepping, result-pane ordering, page-order sorting, or similar query-conditioned visibility (`614`);
21. **carrier wrapper** — slide deck, PDF memo, chat export, saved page, web archive, issue ticket, or other transport context (`437`, `490`, `600`);
22. **assembly state** — whether later materials also fused several observations into one stronger-looking posture (`591`).

That separation matters because later packets can otherwise make two different mistakes:
- treating query hits or ranked matches as if they proved the source route itself naturally emphasized those words or regions, or
- letting a searched packet become the governing member instead of first classifying the surviving detached derivative.

`614` exists so the archive can keep that later query-conditioned layer **truthful but non-governing**.

## Minimal wrapper-query note grammar

When wrapper query-state overread itself matters, reviewers SHOULD prefer one compact line in this shape:

`head=<current tuple|none>; governing_member=<595|596|597|598|599|600|none>; wrapper_query_kind=<find_text|find_next_prev|search_hits|search_sidebar|search_rank|page_order_hits|cross_file_search|query_highlights|mixed|unknown>; query_scope_relation=<whole_member|hit_subset|cross_member|cross_file|mixed|unknown>; wrapper_query_origin=<later_wrapper_added|viewer_entered_query|mixed|unknown>; treat_hits_as_source_emphasis=<forbid>; treat_hit_set_as_source_completeness=<forbid>; treat_query_frame_as_governing_member=<forbid>; carrier_wrapper=<slide_deck|pdf_memo|saved_page|web_archive|ticket|email_thread|none>; cite_default=<head|fallback anchor>; use_614_when=<query_conditioned_view_changed_reading>; promote_wrapper_query=<no>; basis=<why the later query state needed one bounded note>`

This is a note contract, not a new schema.
It exists so packets and summaries can say “this later packet was being read through a search or find state” without minting a new detached-derivative member or silently rewriting source emphasis, completeness, or governance.

## Typical uses

1. **PDF hit-highlight overread**
   A later PDF packet shows highlighted matches for one phrase and later readers start treating those hits as if the source route itself visibly emphasized only those passages.
2. **Slide find-state overread**
   A later slide deck is advanced with Find Next through one search term and later readers start retelling the stepped hits as if the source route natively prioritized those slides.
3. **Cross-file search overread**
   A later packet or workspace search reports hits across several preserved packet members and later readers start treating that narrowed hit list as if it proved source-native completeness of the packet's relevant material.
4. **Saved-page find-in-page overread**
   A later saved page or web archive is read through find-in-page and later readers start narrating the visible hit positions as if they were source-native highlighting or source-native issue structure.
5. **Search-rank overread**
   A later packet shows matches sorted by search rank or page order and later readers start treating that ordering as if it proved source-native priority, chronology, or the packet's governing member.

## When not to use this

Do **not** use `614` when:
- the decisive issue is still native transcript-pane search/focus on the live route (`557`),
- the decisive issue is still copied source text (`595`),
- the decisive issue is still the detached still-image derivative itself (`597`),
- the decisive issue is still copied source metadata (`598`),
- the decisive issue is still a mixed detached-derivative packet with no dominant member (`600`),
- the decisive issue is still a short wrapper-added label (`601`),
- the decisive issue is still longer wrapper-added summary prose (`602`),
- the decisive issue is still wrapper-added emphasis or annotation (`603`),
- the decisive issue is still wrapper-added concealment or suppression (`604`),
- the decisive issue is still wrapper-added ordering or sequence (`605`),
- the decisive issue is still wrapper-added membership or composition of distinct members (`606`),
- the decisive issue is still wrapper-added same-member repetition or multiplicity (`607`),
- the decisive issue is still wrapper-added layout or spatial relation (`608`),
- the decisive issue is still wrapper-added prominence or size weighting (`609`),
- the decisive issue is still wrapper-added styling or visual tone (`610`),
- the decisive issue is still wrapper-added timing or motion (`611`),
- the decisive issue is still wrapper-added navigation or interactivity (`612`),
- the decisive issue is still wrapper-added view state or opening posture (`613`),
- the decisive problem is still print/save/offline/web-archive authority or portability (`437`, `490`),
- or the decisive problem is still cross-state composite assembly (`591`).

If deleting the query layer leaves an ordinary text-derivative problem, markup problem, view-state problem, mixed-packet problem, or clipped-window problem, use the narrower doc and omit `614`.
If deleting it would erase **why a later search term, hit list, or next/previous match state changed the way the packet was being read**, `614` is probably right.

## Promotion rule

Future media additions should usually **not** be promoted just because a later packet was read through a find box, search-results pane, hit-highlighting state, or cross-file search posture.
Tighten `557`, `594`, `600`, `603`, `613`, or `614` first.
Only add another numbered doc when repeated query-state mistakes still cannot be expressed as:
- one governing `595–599` member,
- or a mixed-packet routing note under `600`,
- plus one bounded wrapper-query note under `614`.
