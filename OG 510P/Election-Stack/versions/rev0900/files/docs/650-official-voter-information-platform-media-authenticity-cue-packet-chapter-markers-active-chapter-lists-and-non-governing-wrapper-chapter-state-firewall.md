# 650 — Official voter-information platform media authenticity-cue packet chapter markers active chapter lists and non-governing wrapper-chapter-state firewall

**Track:** Shared / Public surfaces

**later packets can preserve chapter markers, active chapter highlights, chapter-list panes, chapter-title previews, or similar visible wrapper chapter-state layers around same-route detached derivatives, and later readers can start mistaking that chapter posture for source-native structure, an officially endorsed excerpt boundary, a governing quoted section, or the packet's governing member.**

## What this is for

Use `650` when a later packet preserves or reenacts a **visible wrapper chapter-state layer** around same-route detached derivatives:
- chapter markers on the seek bar,
- an active chapter highlight,
- a chapter list or chapter pane left open,
- a chapter-title preview,
- a visible current-chapter selection,
- or similar chapter-state posture added by the later wrapper.

Those chapter surfaces are real packet facts and should be preserved honestly.
But they are still **later wrapper-added chapter posture**, not automatic proof of:
- source-native structure,
- an officially endorsed excerpt boundary,
- a governing quoted section,
- or the packet's governing member.

Current primary-source guidance is already enough to justify one bounded chapter-state bridge.
YouTube says videos can have chapters, that viewers can navigate by selecting different chapters, and that chapters break the video into sections with their own previews.
Vimeo says chapters let viewers navigate to relevant segments in the same video.
Microsoft says chapter markers can appear on the seek bar, viewers can open a chapter list to the right of the video, and selecting a chapter title jumps playback to that timecode.
(xref: `youtube_video_chapters_help_page`; xref: `youtube_timeline_chapter_seeking_features_help_page`; xref: `vimeo_use_chapters_help_page`; xref: `microsoft_clipchamp_video_chapters_help_page`)

`650` exists so maintainers can say:
**this packet preserved a later chapter-marker / active-chapter / chapter-list posture around same-route detached derivatives, and that posture mattered for how later readers interpreted the packet, but the chapter-state layer itself does not silently prove source-native structure, an officially endorsed excerpt boundary, a governing quoted section, or the packet's governing member.**

## Why this is distinct

`494` asks whether chapter markers, key moments, or chapter lists became the **authority-boundary** problem on the public surface in the first place.

`544` asks whether a viewer used transcript clicks, chapter picks, or table-of-contents jumps to move inside the same current object while control stayed with the same head.

`598` asks whether later materials preserved copied chapter lists or other metadata-like labels without preserving the route-level authenticity posture around them.

`599` asks whether a locator derivative such as a shared link, timestamp link, or other route pointer carried only a bounded route-location claim.

`641` asks whether the later wrapper foregrounded transcript state rather than chapter state.

`649` asks whether the later wrapper foregrounded a *next-object* or successor layer rather than the currently selected section inside the same object.

`650` asks a different question:
**did a later packet add or preserve a visible chapter-state layer — chapter markers, active chapter highlight, chapter list pane, chapter-title preview, or similar same-object sectioning posture — and did later readers start overreading that layer as if it proved source-native structure, an officially endorsed excerpt boundary, a governing quoted section, or the packet's governing member?**

If the real problem is chapter markers or key moments as a voter-facing authority boundary, use `494`.
If the real problem is a same-object player-internal jump or chapter pick, use `544`.
If the real problem is a copied chapter list or metadata-only extract, use `598`.
If the real problem is a shared chapter/timestamp locator, use `599`.
If the real problem is transcript-pane foregrounding, use `641`.
If the real problem is next-object succession, use `649`.
Use `650` only when the missing distinction is **wrapper chapter-state posture itself** around a later detached-derivative packet.

## Decision test

Use `650` when all three conditions hold:

1. later evidence preserves or reenacts a **visible chapter-state layer** around same-route detached derivatives — for example chapter markers, an active chapter highlight, a chapter list pane, a chapter-title preview, or a visible current-chapter selection;
2. that layer is **later wrapper-added chapter posture**, not proof that the underlying source itself natively fixed that section boundary as the governing quote, the governing excerpt, or the present-tense citation target; and
3. later readers are drifting toward treating that layer as if it proved **source-native structure, an officially endorsed excerpt boundary, a governing quoted section, or the governing member**.

If any condition fails, keep the packet under the narrower doc that already owns the real problem.
If the surviving packet is still mainly an authority-boundary problem, same-object jump problem, metadata-extract problem, locator problem, transcript-state problem, or successor-state problem with some visible chapter posture around it, keep authority-boundary in `494`, keep same-object jump state in `544`, keep metadata extracts in `598`, keep locator-only claims in `599`, keep transcript posture in `641`, keep successor posture in `649`, and add one bounded `650` chapter-state note only if the visible chapter layer itself changed the reading.

## Keep chapter state, chapter picks, metadata extracts, locators, transcript state, and successor state separate

At minimum, keep these layers separate:
1. **current office control** — the current written/help lane and current media head (`194`, `529`, `530`);
2. **surviving detached derivative** — which `595–599` member, if any, the packet actually preserved;
3. **family routing** — whether the packet needed `600` because no single detached derivative dominated;
4. **chapter-surface authority / same-object jump class** — whether chapter surfaces already became the decisive public-surface problem (`494`) or the issue was merely a same-object player-internal chapter pick (`544`);
5. **metadata / locator carry** — whether the packet mainly preserved copied chapter labels (`598`) or a route pointer to a chapter/time (`599`);
6. **adjacent wrapper state** — whether the real drift is transcript-state or successor-state posture instead (`641`, `649`);
7. **carrier wrapper** — slide deck, PDF memo, browser shell, doc shell, saved page, ticket, or email thread (`437`, `490`, `600`);
8. **assembly state** — whether later materials also fused several observations into one stronger-looking posture (`591`).

That separation matters because later packets can otherwise make two different mistakes:
- treating a visible chapter marker, active chapter highlight, or chapter list pane as if it proved that the source itself officially privileged that section as the governing excerpt; or
- letting a later chapter-state overlay become evidence that the packet itself is governance-bearing rather than just a later sectioning layer around one preserved derivative.

`650` exists so the archive can keep that later visible chapter-state layer **truthful but non-governing**.

## Minimal wrapper-chapter-state note grammar

When wrapper chapter state matters, reviewers SHOULD prefer one compact line in this shape:

`head=<current tuple|none>; governing_member=<595|596|597|598|599|600|none>; wrapper_chapter_kind=<chapter_markers|active_chapter_highlight|chapter_list_pane|chapter_title_preview|current_chapter_selected|mixed|unknown>; chapter_scope=<markers_visible|chapter_selected|chapter_list_open|preview_visible|section_foregrounded|unknown>; source_native_structure_proved=<forbid>; official_excerpt_boundary_proved=<forbid>; governing_quote_section_proved=<forbid>; governing_member_from_chapter_state=<forbid>; carrier_wrapper=<browser_shell|doc_shell|pdf_shell|review_shell|slide_deck|saved_page|ticket|email_thread|none>; cite_default=<head|fallback anchor>; use_650_when=<chapter_state_changed_reading>; promote_wrapper_chapter_state=<no>; basis=<why the later chapter layer needed one bounded note>`

This is a note contract, not a new schema.
It exists so packets and summaries can say “this later packet also carried a visible chapter-state layer” without minting a new detached-derivative member or silently rewriting structure, excerpt boundaries, quoted-section governance, or packet control.

## Typical uses

1. **Active chapter overread**
   A later packet preserves an active chapter highlight or a selected chapter row and later readers start retelling that foregrounded section as if the source itself officially privileged it as the governing excerpt.
2. **Chapter-list overread**
   A later packet leaves a chapter list pane open around a preserved derivative and later readers start treating that chapter-state as if it proved source-native structure rather than later wrapper sectioning.
3. **Marker-preview overread**
   A later packet preserves chapter markers or chapter-title previews on the seek bar and later readers start overreading those visible markers as if they were governance-bearing boundaries rather than packet-visible navigation aids.
4. **Chapter-state versus locator split**
   A later packet preserves a current-chapter highlight that mattered for interpretation, but there is no need to imply a copied chapter link or encoded offset route; keep `599` for locator claims and use `650` only for the later chapter-state drift.

## When not to use this

Do **not** use `650` when:
- the decisive issue is still chapter markers / key moments / chapter lists as a voter-facing authority boundary (`494`),
- the decisive issue is still a same-object player-internal chapter pick or transcript/chapter jump (`544`),
- the decisive issue is still a copied chapter list or metadata-only extract (`598`),
- the decisive issue is still a timestamp/chapter locator or shared link (`599`),
- the decisive issue is still transcript-state foregrounding (`641`),
- the decisive issue is still next-object succession (`649`),
- the decisive issue is still a mixed detached-derivative packet with no dominant member (`600`),
- or the decisive issue is still cross-state composite assembly (`591`).

If deleting the visible chapter layer leaves an ordinary chapter-authority, same-object jump, metadata-extract, locator-only, transcript-state, successor-state, mixed-packet, or cross-state problem, use the narrower doc and omit `650`.
If deleting it would erase **why a later chapter-state layer changed the way the packet was being read or retold**, `650` is probably right.

## Promotion rule

Future media additions should usually **not** be promoted just because a later packet carried chapter markers, an active chapter highlight, a chapter list pane, chapter-title previews, or similar visible sectioning posture around same-route detached derivatives.
Tighten `494`, `544`, `598`, `599`, `600`, `641`, `649`, or `650` first.
Only add another numbered doc when repeated wrapper-chapter-state mistakes still cannot be expressed as:
- one governing `595–599` member,
- or a mixed-packet routing note under `600`,
- plus one bounded wrapper-chapter-state note under `650`.
