## What this is for

Use `623` when a later packet preserves or reenacts a **visible wrapper organization-state layer** around same-route detached derivatives:
- starred or favorited status,
- recent-file or recently-used lists,
- pinned recent entries,
- “Add shortcut” / “Add shortcut to My files” posture,
- favorites / quick-access placement,
- moved-folder or moved-location posture,
- folder-color or local organization cues,
- or similar later packet organization/curation state.

Those organization states are real packet facts and should be preserved honestly.
But they are still **later wrapper-added organization posture**, not automatic proof of:
- current official prominence,
- current official priority,
- endorsed retention,
- canonical route placement,
- or the packet's governing member.

`623` exists so maintainers can say:
**this packet preserved a later organization-state layer around a same-route detached derivative, and that layer mattered for how later readers interpreted the packet, but the organization layer itself does not govern the packet and does not silently rewrite prominence, currentness, or control.**

## Why this is distinct

`609` asks whether a later packet changed visual size weighting or salience inside the packet.

`615` asks whether a later packet changed active focus or selection state.

`619` asks whether a later packet preserved sharing or permissions posture.

`620` asks whether a later packet preserved notification or activity posture.

`621` asks whether a later packet preserved delete/recovery posture.

`622` asks whether a later packet preserved offline/sync/conflict posture.

`623` asks a different question:
**did a later packet add or preserve a visible organization / curation layer — starred, recent, pinned, shortcut, favorite, quick-access, or moved-location posture — and did later readers start overreading that layer as if it proved official prominence, currentness, endorsed retention, or the packet's governing member?**

If the real problem is visual salience inside the packet, use `609`.
If the real problem is active selection, use `615`.
If the real problem is access, event, lifecycle, or sync posture, use `619–622`.
If the real problem is still copied source text or metadata, use `595` or `598`.
Use `623` only when the missing distinction is **wrapper organization-state posture itself**.

## Decision test

Use `623` when all three conditions hold:

1. later evidence preserves or reenacts a **visible organization / curation layer** around same-route detached derivatives — for example starred status, a recent-files list, a pinned recent entry, a shortcut-to-My-files placement, a favorites/quick-access placement, a moved-folder location, or a folder-color cue;
2. that layer is **later wrapper-added organization posture**, not proof that the underlying source route itself was officially prioritized, currently endorsed, or canonically located there; and
3. later readers are drifting toward treating that layer as if it proved **official prominence, currentness, endorsed retention, or the governing member**.

If any condition fails, keep the packet under the narrower doc that already owns the real problem.
If the surviving packet is still mainly copied source text or copied source metadata with some organization-state posture around it, keep the detached derivative in `595–600`, keep any salience question in `609`, keep any active-focus question in `615`, keep any access/event/lifecycle/sync question in `619–622`, and add one bounded `623` wrapper-organization-state note.

## Keep source-derived content, packet salience, and wrapper-added organization state separate

At minimum, keep these layers separate:
1. **current office control** — the current written/help lane and current media head (`194`, `529`, `530`);
2. **surviving detached derivative** — which `595–599` member, if any, the packet actually preserved;
3. **family routing** — whether the packet needed `600` because no single detached derivative dominated;
4. **source-derived text** — transcript/caption/OCR or other copied route text (`595`);
5. **source-derived metadata** — labels copied from the official route itself (`598`);
6. **wrapper-added labels** — filenames, subject lines, and packet titles (`601`);
7. **wrapper-added packet salience** — hero panels, thumbnail demotion, or other size weighting (`609`);
8. **wrapper-added active focus** — selected thumbnails, selected objects, or similar current selection posture (`615`);
9. **wrapper-added access state** — link scopes, roles, or request-access posture (`619`);
10. **wrapper-added event state** — notifications or activity posture (`620`);
11. **wrapper-added lifecycle state** — Trash/Recycling/delete-restore posture (`621`);
12. **wrapper-added sync state** — offline/local/pending/conflict posture (`622`);
13. **wrapper-added organization state** — starred, recent, pinned, shortcut, favorite, quick-access, moved-location, or folder-color posture (`623`);
14. **carrier wrapper** — slide deck, PDF memo, doc shell, saved page, web archive, issue ticket, or other transport context (`490`, `600`);
15. **assembly state** — whether later materials also fused several observations into one stronger-looking posture (`591`).

That separation matters because later packets can otherwise make two different mistakes:
- treating a visible recent/starred/shortcut/favorite state as if it proved the source route was newly official, currently preferred, or canonically settled there, or
- letting a file-manager or library placement cue become evidence that the packet itself governs the source route.

`623` exists so the archive can keep that later visible organization layer **truthful but non-governing**.

## Minimal wrapper-organization-state note grammar

When wrapper organization state matters, reviewers SHOULD prefer one compact line in this shape:

`head=<current tuple|none>; governing_member=<595|596|597|598|599|600|none>; wrapper_organization_kind=<starred|recent_list|pinned_recent|shortcut|favorite_or_quick_access|moved_location|folder_color|shared_list|mixed|unknown>; organization_anchor_relation=<whole_member|member_link|attachment|slide|page|object|message|mixed|unknown>; wrapper_organization_origin=<later_wrapper_added|file_manager_ui|recent_list_ui|shortcut_ui|favorites_ui|folder_browser_ui|mixed|unknown>; source_prominence_proved=<forbid>; source_currentness_proved=<forbid>; endorsed_retention_proved=<forbid>; canonical_location_proved=<forbid>; treat_organization_state_as_governing_member=<forbid>; carrier_wrapper=<doc_shell|file_manager|desktop_client|slide_deck|pdf_memo|saved_page|web_archive|ticket|email_thread|none>; cite_default=<head|fallback anchor>; use_623_when=<organization_state_changed_reading>; promote_wrapper_organization_state=<no>; basis=<why the later visible organization layer needed one bounded note>`

This is a note contract, not a new schema.
It exists so packets and summaries can say “this later packet also carried visible organization-state posture” without minting a new detached-derivative member or silently rewriting official prominence, currentness, retention, or governance.

## Typical uses

1. **Starred-overread**
   A later packet shows a file or folder as starred/favorited and later readers start retelling that wrapper cue as if it proved current official priority or endorsement.
2. **Recents-overread**
   A later packet shows the derivative in a recent-files list and later readers start treating that resurfacing as if it proved current official publication or active control.
3. **Pinned-list overread**
   A later packet shows an item pinned in a recent-files list and later readers start treating that wrapper persistence as if it proved durable official priority.
4. **Shortcut/favorite overread**
   A later packet shows “Add shortcut,” “shortcut to My files,” favorites, or quick-access placement and later readers start treating that wrapper convenience path as if it proved canonical route placement or endorsed distribution.
5. **Moved-location overread**
   A later packet shows a moved folder, chosen destination, or local organization cue and later readers start narrating that wrapper location as if it proved canonical archival placement or governing-member status.

## When not to use this

Do **not** use `623` when:
- the decisive issue is still packet salience or size weighting (`609`),
- the decisive issue is still packet active-focus or selection state (`615`),
- the decisive issue is still wrapper access-state posture (`619`),
- the decisive issue is still wrapper event-state posture (`620`),
- the decisive issue is still wrapper lifecycle-state posture (`621`),
- the decisive issue is still wrapper sync-state posture (`622`),
- the decisive issue is still copied source text (`595`),
- the decisive issue is still copied source metadata (`598`),
- the decisive issue is still a mixed detached-derivative packet with no dominant member (`600`),
- the decisive problem is still watch-history / continue-watching / remembered-resume posture on the source route itself (`506`),
- the decisive problem is still print/save/offline/web-archive authority or portability (`490`),
- or the decisive problem is still cross-state composite assembly (`591`).

If deleting the visible organization layer leaves an ordinary salience problem, selection problem, access/event/lifecycle/sync problem, route-memory problem, or mixed-packet problem, use the narrower doc and omit `623`.
If deleting it would erase **why a later starred / recent / pinned / shortcut / favorite / moved-location layer changed the way the packet was being read or retold**, `623` is probably right.

## Promotion rule

Future media additions should usually **not** be promoted just because a later packet carried starred status, recent-list placement, a pinned recent entry, shortcut/favorite placement, or moved-folder posture.
Tighten `609`, `615`, `619–623`, or `600` first.
Only add another numbered doc when repeated wrapper-organization-state mistakes still cannot be expressed as:
- one governing `595–599` member,
- or a mixed-packet routing note under `600`,
- plus one bounded wrapper-organization-state note under `623`.
