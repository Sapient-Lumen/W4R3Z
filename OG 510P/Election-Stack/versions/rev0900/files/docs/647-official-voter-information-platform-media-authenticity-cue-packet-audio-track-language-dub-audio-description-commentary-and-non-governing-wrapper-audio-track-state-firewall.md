# 647 — Official voter-information platform media authenticity-cue packet audio-track language dub audio description commentary and non-governing wrapper-audio-track-state firewall

**Track:** Shared / Public surfaces

This document covers a narrow packet-wrapper problem:
**later packets can preserve selected spoken-audio-track posture — original audio, dubbed language, automatic dub, audio-description, commentary, audio-track menu state, or similar visible wrapper audio-track-state layers — around same-route detached derivatives, and later readers can start mistaking that audio-track posture for source-native language, a reviewed official translation, an officially adopted accessibility/commentary edition, or the packet's governing member.**

## What this is for

Use `647` when a later packet preserves or reenacts a **visible wrapper audio-track-state layer** around same-route detached derivatives:
- original audio selected,
- a dubbed language selected,
- an automatic dub selected,
- audio-description selected,
- commentary selected,
- an audio-track menu or label foregrounded in the later packet,
- or similar later packet spoken-track foregrounding.

Those spoken-track surfaces are real packet facts and should be preserved honestly.
But they are still **later wrapper-added audio-track posture**, not automatic proof of:
- source-native language,
- a reviewed official translation,
- an officially adopted accessibility or commentary edition,
- or the packet's governing member.

Current primary-source guidance is already enough to justify one bounded audio-track-state bridge.
YouTube Help says viewers can set preferred languages for audio, titles, and descriptions, switch a specific video's audio track from player settings, and switch between original and dubbed tracks for videos with automatic dubbing.
Vimeo Help says viewers can choose a different audio track in the player for another language, audio description, or commentary, while creators classify tracks by type.
Microsoft Support says viewers can change tracks with the player’s **Audio tracks** button, while owners can upload language-specific audio files and mark them as descriptive tracks so the player labels both language and audio-description posture.
That is enough for one bounded firewall here.
(xref: `youtube_watch_preferred_language_help_page`; xref: `youtube_automatic_dubbing_help_page`; xref: `vimeo_change_audio_track_help_page`; xref: `vimeo_multiple_audio_tracks_help_page`; xref: `microsoft_alternative_audio_tracks_help_page`)

`647` exists so maintainers can say:
**this packet preserved a later spoken-audio-track posture around same-route detached derivatives, and that posture mattered for how later readers interpreted the packet, but the audio-track layer itself does not silently prove source-native language, a reviewed official translation, an officially adopted accessibility/commentary edition, or the governing member.**

## Why this is distinct

`501` asks whether alternate spoken audio, dubbed audio, or audio description became an **authority-boundary** problem on the public surface in the first place.

`552` asks whether the same current media object preserved **selected spoken-audio state** — original audio, dubbed language, auto-dub, audio-description, commentary, or similar — while the same object still controlled.

`596` asks whether later evidence preserved a **detached spoken-audio derivative** such as downloaded audio, audio-only export, or another spoken excerpt from the route.

`638` asks whether a later packet preserved **translated renderings / show-original posture** as visible translation state.

`643` asks whether a later packet preserved **caption-display / caption-selection posture** such as captions-on/off, selected caption language, or caption appearance customization.

`645` asks whether a later packet preserved **audibility posture** such as mute, low volume, restored audibility, or visible volume-slider state.

`647` asks a different question:
**did a later packet add or preserve a visible spoken-audio-track layer — original audio selected, dubbed language selected, automatic dub selected, audio-description selected, commentary selected, or similar audio-track menu posture — and did later readers start overreading that layer as if it proved source-native language, a reviewed official translation, an officially adopted accessibility/commentary edition, or the packet's governing member?**

If the real problem is alternate-audio authority boundary on the live public surface, use `501`.
If the real problem is same-object selected spoken-track state while the current head still controls, use `552`.
If the real problem is a detached spoken-audio derivative, use `596`.
If the real problem is wrapper translation, caption, or audio-output posture, use `638`, `643`, or `645`.
Use `647` only when the missing distinction is **wrapper audio-track-state posture itself**.

## Decision test

Use `647` when all three conditions hold:

1. later evidence preserves or reenacts a **visible spoken-audio-track layer** around same-route detached derivatives — for example original-audio-selected, dubbed-language-selected, auto-dub-selected, descriptive-audio-selected, commentary-selected, or an audio-track menu/label;
2. that layer is **later wrapper-added spoken-track state**, not proof that the underlying source route itself officially published a new native language, officially reviewed the translated wording, officially adopted one accessibility/commentary edition as controlling, or officially made the packet governing; and
3. later readers are drifting toward treating that layer as if it proved **source-native language, a reviewed official translation, an officially adopted accessibility/commentary edition, or the governing member**.

If any condition fails, keep the packet under the narrower doc that already owns the real problem.
If the surviving packet is still mainly a same-object spoken-track-state problem, detached spoken-audio problem, wrapper translation problem, wrapper caption problem, or wrapper audio-output problem with some visible audio-track posture around it, keep same-object spoken-track state in `552`, keep detached spoken-audio routing in `596`, keep wrapper translation in `638`, keep caption posture in `643`, keep audibility posture in `645`, and add one bounded `647` audio-track-state note only if the visible spoken-track layer itself changed the reading.

## Keep audio-track state, audio derivatives, translation, captions, and audibility separate

At minimum, keep these layers separate:
1. **current office control** — the current written/help lane and current media head (`194`, `529`, `530`);
2. **surviving detached derivative** — which `595–599` member, if any, the packet actually preserved;
3. **family routing** — whether the packet needed `600` because no single detached derivative dominated;
4. **authority-boundary exposure of alternate audio** — whether multi-audio / dubbed / descriptive tracks were themselves a public-surface authority problem (`501`);
5. **same-object spoken-track state** — original audio, dubbed language, auto-dub, audio-description, commentary, or similar while the same object still controlled (`552`);
6. **detached spoken-audio derivative** — downloaded or exported spoken-audio carry divorced from route cues (`596`);
7. **wrapper-added translation state** — translated renderings, show-original posture, or similar visible translation state (`638`);
8. **wrapper-added caption state** — captions-on/off posture, selected caption language, or caption-style posture (`643`);
9. **wrapper-added audio-output state** — mute / low-volume / restored-audibility / visible volume posture (`645`);
10. **carrier wrapper** — slide deck, PDF memo, browser shell, doc shell, saved page, ticket, or email thread (`437`, `490`, `600`);
11. **assembly state** — whether later materials also fused several observations into one stronger-looking posture (`591`).

That separation matters because later packets can otherwise make two different mistakes:
- treating a selected or foregrounded audio track as if it proved the source itself natively spoke that language, officially reviewed that translated wording, officially adopted one accessibility/commentary edition as controlling, or quietly republished the governing answer in another spoken layer; or
- letting a later spoken-track wrapper become evidence that the packet itself is governance-bearing rather than just a later hearing layer around one preserved derivative.

`647` exists so the archive can keep that later visible audio-track layer **truthful but non-governing**.

## Minimal wrapper-audio-track-state note grammar

When wrapper audio-track state matters, reviewers SHOULD prefer one compact line in this shape:

`head=<current tuple|none>; governing_member=<595|596|597|598|599|600|none>; wrapper_audio_track_kind=<original_audio_selected|dubbed_language_selected|auto_dub_selected|descriptive_audio_selected|commentary_track_selected|mixed|unknown>; track_provenance=<original|creator_uploaded|auto_generated|audio_description|commentary|unknown>; language_rendering=<source_language|translated_language|descriptive|commentary|mixed|unknown>; selection_scope=<viewer_selected|preferred_language_default|session_persistent|platform_default|player_default|unknown>; source_native_language_proved=<forbid>; reviewed_translation_proved=<forbid>; official_accessibility_or_commentary_edition_proved=<forbid>; governing_member_from_audio_track_state=<forbid>; carrier_wrapper=<browser_shell|doc_shell|pdf_shell|review_shell|slide_deck|saved_page|ticket|email_thread|none>; cite_default=<head|fallback anchor>; use_647_when=<audio_track_state_changed_reading>; promote_wrapper_audio_track_state=<no>; basis=<why the later spoken-track layer needed one bounded note>`

This is a note contract, not a new schema.
It exists so packets and summaries can say “this later packet also carried a visible spoken-audio-track posture” without minting a new detached-derivative member or silently rewriting source language, translation-review posture, accessibility adoption, commentary authority, or packet governance.

## Typical uses

1. **Dub-language overread**
   A later packet shows an audio-track menu set to a dubbed language and later readers start retelling the packet as if the office itself natively published that language as the governing spoken answer.
2. **Auto-dub overread**
   A later packet foregrounds an automatically dubbed track and later readers start treating that visible selection as if it proved a reviewed official translation rather than a later player-side spoken-track posture.
3. **Audio-description overread**
   A later packet preserves descriptive-audio selection and later readers start treating that accessibility layer as if it were the source's native spoken wording or the office's controlling edition.
4. **Commentary-track overread**
   A later packet preserves commentary-track selection and later readers start treating that commentary layer as if it were the source's own official narration or the governing member.
5. **Audio-track plus detached derivative bundle**
   A later packet carries a still image, shared URL, copied metadata, transcript excerpt, or detached audio excerpt from the same route and also preserves a visible audio-track cue; keep the detached derivative governing and use `647` only for the later audio-track-state drift.

## When not to use this

Do **not** use `647` when:
- the decisive issue is still alternate-audio authority boundary (`501`),
- the decisive issue is still same-object spoken-track state (`552`),
- the decisive issue is still a detached spoken-audio derivative (`596`),
- the decisive issue is still wrapper translation state (`638`),
- the decisive issue is still wrapper caption state (`643`),
- the decisive issue is still wrapper audio-output state (`645`),
- the decisive issue is still a mixed detached-derivative packet with no dominant member (`600`),
- or the decisive issue is still cross-state composite assembly (`591`).

If deleting the visible spoken-audio-track layer leaves an ordinary alternate-audio-boundary, same-object spoken-track-state, detached spoken-audio, wrapper-translation, wrapper-caption, or wrapper-audio-output problem, use the narrower doc and omit `647`.
If deleting it would erase **why a later spoken-track layer changed the way the packet was being read or retold**, `647` is probably right.

## Promotion rule

Future media additions should usually **not** be promoted just because a later packet carried original-audio selection, dubbed-language selection, automatic dubbing, descriptive-audio selection, commentary-track posture, or similar spoken-track state around same-route detached derivatives.
Tighten `501`, `552`, `596`, `638`, `643`, `645`, or `647` first.
Only add another numbered doc when repeated wrapper-audio-track-state mistakes still cannot be expressed as:
- one governing `595–599` member,
- or a mixed-packet routing note under `600`,
- plus one bounded wrapper-audio-track-state note under `647`.
