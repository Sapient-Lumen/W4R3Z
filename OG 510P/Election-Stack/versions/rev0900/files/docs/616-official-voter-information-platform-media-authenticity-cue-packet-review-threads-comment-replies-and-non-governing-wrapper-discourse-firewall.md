# 616 — Official voter-information platform media authenticity-cue packet review threads, comment replies, and non-governing wrapper-discourse firewall

**Track:** Shared / Public surfaces

This document defines a bounded control for **later packet-level review discourse around same-route detached derivatives**:
comment-thread bodies,
reply chains,
review notes attached to slides/pages/regions,
action-item or task-like review comments,
resolved or reopened comment state,
comment reactions,
review-pane conversation lists,
or similar wrapper-added discussion that changes **how preserved members are being discussed or interpreted by later reviewers** without proving that the official source route itself published that discussion, endorsed those statements, or made the discussed member the packet's governing member.

It does not create a new authenticity cue family.
It adds one narrow rule:
**when a later packet carries its own review-thread discourse around preserved same-route detached derivatives, the archive should preserve that wrapper-discourse fact honestly and should not quietly treat comment bodies, replies, task assignments, or resolution state as if they proved source-native wording, source-native endorsement, or the packet's governing member.**

## Why this exists (bounded)

The archive already distinguishes wrapper-added labels (`601`), wrapper-added summaries (`602`), wrapper-added markup (`603`), wrapper-added concealment (`604`), wrapper-added ordering (`605`), wrapper-added membership (`606`), wrapper-added repetition (`607`), wrapper-added layout (`608`), wrapper-added prominence (`609`), wrapper-added styling (`610`), wrapper-added timing (`611`), wrapper-added navigation (`612`), wrapper-added view state (`613`), wrapper-added search state (`614`), and wrapper-added active selection (`615`).
A smaller but still important seam remains:
**a later packet can also carry review-thread discourse — attached comments, replies, task assignments, resolution history, or note sidebars — and later readers can start narrating that discussion as if it were official source wording, official endorsement, or governing-member proof.**

Current primary-source guidance is specific enough to justify one compact bridge here.
Google Docs Editors Help says comments can attach to highlighted text, images, slides, or scenes; users can reply, resolve, reopen, and assign action items.
Microsoft Support says comments in PowerPoint live in the Comments pane, can attach to objects or whole slides, can receive replies, and are stored in the file.
Adobe Acrobat Help says shared review PDFs support adding comments, replies, emoji reactions, and comment-pane management.
Apple Support says Preview can add notes and speech bubbles to a PDF, display all notes in a sidebar, and print notes.
(xref: `google_docs_use_comments_action_items_emoji_reactions_help_page`; xref: `microsoft_add_change_hide_delete_comments_presentation_help_page`; xref: `adobe_acrobat_add_manage_comments_help_page`; xref: `apple_preview_add_notes_speech_bubbles_pdf_help_page`)

That is enough to support one bounded maintainer rule:
**later packet review discourse is still only later packet review discourse.**
A comment thread on a frame grab, a resolved reply chain beside a copied metadata label, a task-like review note attached to a slide, or a Preview note sidebar can honestly be the later packet reviewers encountered while still failing to prove that the official source route itself published that discussion, adopted its language, endorsed its claims, or made the discussed member govern the packet.
`616` exists so the archive can preserve that review-discourse posture without quietly promoting wrapper discussion into source-native meaning.

## This is not the same thing as `602`, `603`, `614`, `615`, `600`, `595`, `598`, `594`, `490`, or `591`

`602` asks whether later forwarding comments, share messages, speaker notes, memo-body summaries, or similar wrapper-added synopsis prose was mistaken for copied source language, copied metadata, or the governing member.

`603` asks whether later wrapper emphasis or annotation changed how the packet looked — highlight boxes, arrows, circles, underlines, comment anchors, zoom lenses, or similar markup.

`614` asks whether later search or find state foregrounded hits through a query-conditioned posture.

`615` asks whether later selected thumbnails, objects, or ranges changed how the packet was being actively focused.

`600` asks how to route a mixed same-route packet when several detached derivatives coexist and no single `595–599` member clearly dominates.

`595` and `598` ask whether the decisive surviving artifact is still copied source text or copied source metadata themselves.

`594` asks whether later evidence preserved only a clipped observation window.

`490` asks whether saved-page / offline / web-archive carriage changed authority or portability posture.

`591` asks whether later materials fused observations from different routes, times, viewer conditions, or interaction states into one faux simultaneous posture.

`616` asks a different question:
**did a later packet add or preserve its own attached review-thread discourse around same-route detached derivatives, and did later readers start overreading that wrapper discussion as if it proved source-native wording, source-native endorsement, or the packet's governing member?**

If the real problem is a packet synopsis or forwarding cover text, use `602`.
If the real problem is only comment anchors, highlight boxes, or other markup, use `603`.
If the real problem is search posture, use `614`.
If the real problem is selection posture, use `615`.
If the real problem is a mixed packet, use `600`.
If the real problem is clipped observation, use `594`.
If the real problem is saved-page/web-archive authority boundary, use `490`.
If the real problem is cross-state assembly, use `591`.
Use `616` only when the missing distinction is **review-thread discourse itself**.

## Decision test

Use `616` when all three conditions hold:

1. later evidence preserves or reenacts an attached **review-discourse layer** around same-route detached derivatives — for example comment bodies, replies, assigned tasks, resolved-comment history, note sidebars, or similar review conversation;
2. that discourse is **later packet state or wrapper-added review material**, not source-native route text or source-native public notice language; and
3. later readers are drifting toward treating that discourse as if it proved **source wording, source endorsement, source resolution, or the governing member**.

If any condition fails, keep the packet under the narrower doc that already owns the real problem.
If the surviving packet is still mainly copied source text or copied source metadata with some later discussion around it, keep the detached derivative in `595–600`, keep any markup fact in `603`, keep any summary-prose fact in `602`, and add one bounded `616` review-discourse note.

## Keep source-derived content and wrapper-added review discourse separate

At minimum, keep these layers separate:
1. **current office control** — the current written/help lane and current media head (`194`, `369`, `529`, `530`);
2. **surviving detached derivative** — which `595–599` member, if any, the packet actually preserved;
3. **family routing** — whether the packet needed `600` because no single detached derivative dominated;
4. **source-derived text** — transcript/caption/OCR or other copied route text (`595`);
5. **source-derived metadata** — labels copied from the official route itself (`598`);
6. **native route search/focus state** — transcript-pane or same-route native focus posture (`557`);
7. **wrapper-added summary prose** — forwarding comments, share messages, speaker notes, memo-body summaries, or similar longer later packet narrative (`602`);
8. **wrapper-added markup/emphasis** — highlight boxes, circles, arrows, underlines, comment anchors, zoom lenses, ink, or similar later visual emphasis (`603`);
9. **wrapper-added view state / query / selection** — later opening posture, search posture, or active selection (`613`, `614`, `615`);
10. **wrapper-added review discourse** — comment-thread bodies, replies, task assignments, resolution history, note-sidebar text, or similar later attached discussion (`616`);
11. **carrier wrapper** — slide deck, PDF memo, chat export, saved page, web archive, issue ticket, or other transport context (`437`, `490`, `600`);
12. **assembly state** — whether later materials also fused several observations into one stronger-looking posture (`591`).

That separation matters because later packets can otherwise make two different mistakes:
- treating reviewer discussion as if it were source language or office endorsement, or
- letting a discussed page, slide, or object become the governing member just because the review thread is attached to it.

`616` exists so the archive can keep that later attached discussion layer **truthful but non-governing**.

## Minimal wrapper-discourse note grammar

When wrapper review discourse overread itself matters, reviewers SHOULD prefer one compact line in this shape:

`head=<current tuple|none>; governing_member=<595|596|597|598|599|600|none>; wrapper_discourse_kind=<comment_thread|reply_chain|assigned_action_item|resolved_comment|note_sidebar|review_comment|reaction_thread|mixed|unknown>; discourse_anchor_relation=<whole_member|member_region|slide|page|object|text_range|mixed|unknown>; wrapper_discourse_origin=<later_wrapper_added|reviewer_added|editor_added|mixed|unknown>; treat_discourse_as_source_text=<forbid>; treat_discourse_as_source_endorsement=<forbid>; treat_discourse_as_source_resolution=<forbid>; treat_discourse_as_governing_member=<forbid>; carrier_wrapper=<slide_deck|pdf_memo|doc_comment_layer|saved_page|web_archive|ticket|email_thread|none>; cite_default=<head|fallback anchor>; use_616_when=<attached_review_discourse_changed_reading>; promote_wrapper_discourse=<no>; basis=<why the later attached discussion needed one bounded note>`

This is a note contract, not a new schema.
It exists so packets and summaries can say “this later packet also carried an attached review thread / comment discourse layer” without minting a new detached-derivative member or silently rewriting source provenance, endorsement, or governance.

## Typical uses

1. **Comment-thread overread**
   A later slide deck or PDF packet carries an attached comment thread on one preserved member and later readers start retelling that thread as if it were official source wording.
2. **Reply-chain overread**
   A later packet preserves replies under one review note and later readers start treating that conversation as if it were office endorsement or official correction text.
3. **Assigned-action-item overread**
   A later comment assigns a task or reviewer and later readers start treating that assignment as if it proved source-native workflow, official approval, or source disposition.
4. **Resolved-comment overread**
   A later packet shows a comment thread as resolved/reopened and later readers start narrating that status as if it proved the source route officially settled the underlying claim.
5. **Note-sidebar overread**
   A Preview note or similar sidebar commentary rides with a preserved derivative and later readers start treating that note text as if it were copied source language or the governing member.

## When not to use this

Do **not** use `616` when:
- the decisive issue is still packet synopsis or forwarding summary prose (`602`),
- the decisive issue is still wrapper-added emphasis or annotation (`603`),
- the decisive issue is still wrapper-added view state or opening posture (`613`),
- the decisive issue is still wrapper-added query state or search posture (`614`),
- the decisive issue is still wrapper-added active-focus selection (`615`),
- the decisive issue is still copied source text (`595`),
- the decisive issue is still copied source metadata (`598`),
- the decisive issue is still a mixed detached-derivative packet with no dominant member (`600`),
- the decisive problem is still print/save/offline/web-archive authority or portability (`437`, `490`),
- or the decisive problem is still cross-state composite assembly (`591`).

If deleting the discussion layer leaves an ordinary summary-prose problem, markup problem, query-state problem, selection problem, or mixed-packet problem, use the narrower doc and omit `616`.
If deleting it would erase **why a later review-thread or comment-layer discourse changed the way the packet was being read or retold**, `616` is probably right.

## Promotion rule

Future media additions should usually **not** be promoted just because a later packet carried comment threads, replies, task assignments, resolution history, or note-sidebar discourse.
Tighten `602`, `603`, `600`, `614`, `615`, or `616` first.
Only add another numbered doc when repeated review-discourse mistakes still cannot be expressed as:
- one governing `595–599` member,
- or a mixed-packet routing note under `600`,
- plus one bounded wrapper-discourse note under `616`.
