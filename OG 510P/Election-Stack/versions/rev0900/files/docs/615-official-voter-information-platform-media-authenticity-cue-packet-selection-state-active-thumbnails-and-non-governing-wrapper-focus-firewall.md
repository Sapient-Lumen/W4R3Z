# 615 — Official voter-information platform media authenticity-cue packet selection state, active thumbnails, and non-governing wrapper-focus firewall

**Track:** Shared / Public surfaces

This document defines a bounded control for **later packet-level selection or active-focus state around same-route detached derivatives**:
selected slide thumbnails,
selected PDF page thumbnails,
selected objects with handles or bounding boxes,
selected text ranges,
selected page subsets queued for print/export/move,
active sidebar items,
or similar wrapper-added focus state that changes **which preserved member, object, or region is currently selected** without proving that the official source route itself natively selected that item, privileged it, or made it the packet's governing member.

It does not create a new authenticity cue family.
It adds one narrow rule:
**when a later packet carries its own active-selection posture around preserved same-route detached derivatives, the archive should preserve that wrapper-focus fact honestly and should not quietly treat selected thumbnails, selected objects, or selected subsets as if they proved source-native emphasis, source-native scope, or the packet's governing member.**

## Why this exists (bounded)

The archive already distinguishes copied source text (`595`), detached stills (`597`), copied source metadata (`598`), mixed detached-derivative packets (`600`), wrapper-added labels (`601`), wrapper-added summaries (`602`), wrapper-added markup (`603`), wrapper-added concealment (`604`), wrapper-added ordering (`605`), wrapper-added membership (`606`), wrapper-added repetition (`607`), wrapper-added layout (`608`), wrapper-added prominence (`609`), wrapper-added styling (`610`), wrapper-added timing (`611`), wrapper-added navigation (`612`), wrapper-added view state (`613`), and wrapper-added query state (`614`).
A smaller but still important seam remains:
**a later packet can show one slide, page, object, or text range as selected, with handles, active thumbnails, or selected subsets, and later readers can start narrating that active-focus posture as if it proved source-native emphasis, source-native scope, or the packet's governing member.**

Current primary-source guidance is specific enough to justify one compact bridge here.
Google Docs Editors Help says Slides lets reviewers select slides and apply actions to the selected subset.
Microsoft Support says the Selection Pane can select and multi-select objects, including hidden or stacked ones.
Adobe Acrobat says page thumbnails can be selected singly or in groups before moving or copying pages.
Apple Preview says viewers can Command-click thumbnails to select specific pages for printing.
(xref: `google_slides_add_delete_organize_slides_help_page`; xref: `microsoft_selection_pane_manage_objects_help_page`; xref: `adobe_acrobat_move_copy_pages_help_page`; xref: `apple_preview_print_selected_pages_mac_help_page`)

That is enough to support one bounded maintainer rule:
**later packet active selection is still only later packet active selection.**
A slide deck with one selected thumbnail, a PDF with selected page thumbnails, a packet with one selected object and resize handles, or a preview window with selected pages queued for print can honestly be the state later readers encountered while still failing to prove that the source route itself natively privileged that member, guaranteed that selected subset as the authoritative scope, or made the selected item govern the packet.
`615` exists so the archive can preserve that active-focus posture without quietly promoting wrapper selection state into source-native meaning.

## This is not the same thing as `557`, `603`, `613`, `614`, `600`, `605`, `606`, `608`, `609`, `612`, `594`, or `591`

`557` asks whether the same current object merely had its native transcript pane opened, searched, or left focusing one line inside the live route itself.

`603` asks whether later packet emphasis or annotation was manually added as markup.

`613` asks whether later packet opening posture, zoom, fit mode, or restored viewport changed the first view.

`614` asks whether later packet search terms, hit-highlighting, or result panes created a query-conditioned reading posture.

`600` asks how to route a mixed same-route packet when several detached derivatives coexist and no single `595–599` member clearly dominates.

`605` asks whether later sequence or page order was rearranged.

`606` asks whether later member choice changed which distinct slides, pages, or attachments were included at all.

`608` and `609` ask whether later spatial placement or size weighting changed adjacency or salience.

`612` asks whether later click paths or hotspots changed navigation.

`594` asks whether later evidence preserved only a clipped observation window.

`591` asks whether later materials fused observations from different routes, times, viewer conditions, or interaction states into one faux simultaneous posture.

`615` asks a different question:
**did a later packet add or preserve its own active selection state around same-route detached derivatives, and did later readers start overreading that wrapper focus as if it proved source-native emphasis, source-native scope, or the packet's governing member?**

If the real problem is native transcript-pane focus on the live route, use `557`.
If the real problem is manual markup or annotation, use `603`.
If the real problem is only opening posture or zoom, use `613`.
If the real problem is query-conditioned search state, use `614`.
If the real problem is a balanced mixed packet, use `600`.
If the real problem is reordering, use `605`.
If the real problem is changed packet membership, use `606`.
If the real problem is layout or prominence, use `608` or `609`.
If the real problem is navigation, use `612`.
Use `615` only when the missing distinction is **active selection state itself**.

## Decision test

Use `615` when all three conditions hold:

1. later evidence preserves or reenacts an **active-selection posture** around same-route detached derivatives — for example a selected slide thumbnail, selected PDF page thumbnails, selected object handles, selected text range, or selected subset queued for a later action;
2. that selection posture is **later packet/editor/viewer state**, not the source route's own reviewed text, metadata, or ordinary live-route focus behavior;
3. later readers are starting to treat the selected member, object, or subset as if it proved source-native emphasis, source-native scope, or that the selected item governs the packet.

When those conditions hold, keep the current control in `194` / `530`, keep the surviving detached derivative in `595–600`, keep any clipped-window fact in `594`, keep any markup fact in `603`, keep any view-state fact in `613`, keep any query-state fact in `614`, and add one bounded `615` selection-state note.

## Keep source-derived content and wrapper-added selection state separate

At minimum, keep these layers separate:
1. **current office control** — the current written/help lane and current media head (`194`, `369`, `529`, `530`);
2. **surviving detached derivative** — which `595–599` member, if any, the packet actually preserved;
3. **family routing** — whether the packet needed `600` because no single detached derivative dominated;
4. **source-derived text** — transcript/caption/OCR or other copied route text (`595`);
5. **source-derived metadata** — labels copied from the official route itself (`598`);
6. **native route search/focus state** — transcript-pane or same-route native focus posture (`557`);
7. **wrapper-added packet label** — filename, subject line, slide title, memo heading, or similar short later-added narrative (`601`);
8. **wrapper-added summary prose** — forwarding comments, share messages, speaker notes, memo-body summaries, or similar longer later packet narrative (`602`);
9. **wrapper-added markup/emphasis** — highlight boxes, circles, arrows, underlines, comment anchors, zoom lenses, ink, or similar later visual emphasis (`603`);
10. **wrapper-added concealment/suppression** — redactions, crop-hidden regions, hidden slides, hidden objects, or similar later visual withholding (`604`);
11. **wrapper-added ordering/sequence** — reordered slide order, reordered PDF page order, moved packet sections, or similar later arrangement (`605`);
12. **wrapper-added membership/composition** — imported slides, merged-page subsets, chosen attachments, appended packet members, or similar later included-member selection (`606`);
13. **wrapper-added repetition/multiplicity** — duplicated slides, repeated pages, repeated excerpts, repeated attachments, gallery-style repeats, or similar later same-member multiplication (`607`);
14. **wrapper-added layout/spatial relation** — side-by-side placement, inset-over-main placement, gallery rows, stacked columns, split-screen comparison framing, or similar later positioning (`608`);
15. **wrapper-added prominence/salience** — enlarged hero panels, thumbnail demotion, resized excerpt blocks, large-versus-small weighting, or similar later visual importance allocation (`609`);
16. **wrapper-added styling/tone** — later themes, palettes, fonts, background styles, warning-color coding, or similar visual tone choices (`610`);
17. **wrapper-added motion/timing** — later object animations, build order, delays, autoplay, transition timing, or similar temporal staging choices (`611`);
18. **wrapper-added navigation/interactivity** — later hyperlinks, linked shapes or images, action buttons, clickable hotspots, internal jumps, or similar click-path choices (`612`);
19. **wrapper-added view state/viewport** — later initial-view settings, open-page/open-slide choices, zoom level, fit mode, restored last-view state, or similar opening posture (`613`);
20. **wrapper-added query frame/search state** — later search terms, hit highlighting, next/previous match stepping, result-pane ordering, page-order sorting, or similar query-conditioned visibility (`614`);
21. **wrapper-added active selection/focus** — later selected thumbnails, selected objects, selected text ranges, active sidebar items, or selected page subsets (`615`);
22. **carrier wrapper** — slide deck, PDF memo, chat export, saved page, web archive, issue ticket, or other transport context (`437`, `490`, `600`);
23. **assembly state** — whether later materials also fused several observations into one stronger-looking posture (`591`).

That separation matters because later packets can otherwise make two different mistakes:
- treating selected members or selected subsets as if the source route itself had natively privileged them, or
- letting a selected page, slide, object, or subset become the governing member instead of first classifying the surviving detached derivative.

`615` exists so the archive can keep that later active-selection layer **truthful but non-governing**.

## Minimal wrapper-selection note grammar

When wrapper selection-state overread itself matters, reviewers SHOULD prefer one compact line in this shape:

`head=<current tuple|none>; governing_member=<595|596|597|598|599|600|none>; wrapper_selection_kind=<selected_slide|selected_page_thumbnail|selected_object|selected_text_range|multi_select_subset|active_sidebar_item|mixed|unknown>; selection_scope_relation=<whole_member|member_subset|object_within_member|cross_member|mixed|unknown>; wrapper_selection_origin=<later_wrapper_added|viewer_selected|editor_selected|mixed|unknown>; treat_selection_as_source_emphasis=<forbid>; treat_selected_subset_as_source_scope=<forbid>; treat_selected_item_as_governing_member=<forbid>; carrier_wrapper=<slide_deck|pdf_memo|saved_page|web_archive|ticket|email_thread|none>; cite_default=<head|fallback anchor>; use_615_when=<active_selection_changed_reading>; promote_wrapper_selection=<no>; basis=<why the later selection state needed one bounded note>`

This is a note contract, not a new schema.
It exists so packets and summaries can say “this later packet was being read with one member/object/subset actively selected” without minting a new detached-derivative member or silently rewriting source emphasis, source scope, or governance.

## Typical uses

1. **Selected slide overread**
   A later deck shows one slide thumbnail selected and later readers start treating that active slide as if the source route itself natively privileged it over the rest of the preserved packet.
2. **Selected PDF page subset overread**
   A later PDF workspace or print dialog preserves several page thumbnails selected for action and later readers start treating that selected subset as if it proved source-native scope or completeness.
3. **Selected object overread**
   A later packet screenshot shows one text box or image selected with handles and later readers start retelling that active object as if it were source-native emphasis rather than later editor/viewer posture.
4. **Selected text-range overread**
   A later packet preserves one text range selected for copy/search/annotation and later readers start treating that active selection as if it were source-native highlighting or reviewed official excerpting.
5. **Active sidebar-item overread**
   A later PDF or deck shows one sidebar item active and later readers start treating that active item as if it proved source-native priority, scope, or packet governance.

## When not to use this

Do **not** use `615` when:
- the decisive issue is still native transcript-pane search/focus on the live route (`557`),
- the decisive issue is still copied source text (`595`),
- the decisive issue is still the detached still-image derivative itself (`597`),
- the decisive issue is still copied source metadata (`598`),
- the decisive issue is still a mixed detached-derivative packet with no dominant member (`600`),
- the decisive issue is still a short wrapper-added label (`601`),
- the decisive issue is still longer wrapper-added summary prose (`602`),
- the decisive issue is still wrapper-added emphasis or annotation (`603`),
- the decisive issue is still wrapper-added concealment or suppression (`604`),
- the decisive issue is still wrapper-added ordering or sequence (`605`),
- the decisive issue is still wrapper-added membership or composition of distinct members (`606`),
- the decisive issue is still wrapper-added same-member repetition or multiplicity (`607`),
- the decisive issue is still wrapper-added layout or spatial relation (`608`),
- the decisive issue is still wrapper-added prominence or size weighting (`609`),
- the decisive issue is still wrapper-added styling or visual tone (`610`),
- the decisive issue is still wrapper-added timing or motion (`611`),
- the decisive issue is still wrapper-added navigation or interactivity (`612`),
- the decisive issue is still wrapper-added view state or opening posture (`613`),
- the decisive issue is still wrapper-added query state or search posture (`614`),
- the decisive problem is still print/save/offline/web-archive authority or portability (`437`, `490`),
- or the decisive problem is still cross-state composite assembly (`591`).

If deleting the selection layer leaves an ordinary query-state problem, markup problem, view-state problem, mixed-packet problem, or clipped-window problem, use the narrower doc and omit `615`.
If deleting it would erase **why a later active selection changed the way the packet was being read**, `615` is probably right.

## Promotion rule

Future media additions should usually **not** be promoted just because a later packet preserved selected thumbnails, selected objects, selected text ranges, or other active-focus state.
Tighten `557`, `594`, `600`, `603`, `613`, `614`, or `615` first.
Only add another numbered doc when repeated selection-state mistakes still cannot be expressed as:
- one governing `595–599` member,
- or a mixed-packet routing note under `600`,
- plus one bounded wrapper-selection note under `615`.
