# Beneficial ownership, public registry, and privacy-burden routing

## Question in one sentence

When a tax or AML system requires beneficial ownership, trust, company, real-estate, or registry disclosures, how should the archive protect transparency without creating privacy dragnet, small-entity burden, or shell immunity?[S526][S527][S528][S529][S530]

Route: ownership transparency is a capacity tool, not an all-purpose public dossier. The archive prefers adequate, accurate, up-to-date information available to competent authorities with risk-based access, verification, correction, privacy controls, and proportionate small-entity support.[S528][S529]

## Core rule

A registry fails in two opposite ways: it can expose ordinary owners, survivors, small entities, or family arrangements to avoidable privacy risk; or it can exempt the entities most useful for hiding control. The moral target is real control, not indiscriminate publication.

## Routing table

| Signal | Start here | Default output |
|---|---|---|
| anonymous shell or nominee chain | control gate | verified BOI, tax use, and cross-border exchange. |
| small entity has simple ownership | burden gate | simplified filing, assistance, and correction before penalty. |
| registry access is public by default | privacy gate | tiered access and masking for safety risks. |
| domestic class exemption creates gap | gap gate | alternative data source or high-risk trigger.[S526][S527] |
| trust/legal arrangement hides control | arrangement gate | settlor/trustee/protector/beneficiary information with safeguards.[S529] |

## Anti-patterns

- **privacy dragnet** — ordinary ownership data is broadly exposed without purpose or safety screen.
- **shell immunity** — formal exemptions recreate anonymous control.
- **paper-owner finality** — registry name is mistaken for real control.
- **small-entity penalty mill** — minor BOI errors become automatic fines.
