# Datacube lifecycle and policy-evaluation rules should not be turned into prose sprawl or stale doctrine

## Claim

The archive now needs a rule for its own growth. A new route is justified only when it makes future cases easier to classify, adds a distinct axis combination, or compresses recurring disputes. Otherwise the editor should add a golden case, merge a family, refresh sources, or retire stale doctrine.[S59][S594]

## Why it matters

Moral tax design fails when it becomes either slogans or bureaucracy. The datacube was added to prevent that: facts should route through stable axes, not through endless bespoke notes. The same evaluation discipline applied to tax expenditures and public programs should apply to the archive's own route lifecycle.[S59][S594]

## Route

Use [`../docs/10-framework/cube-lifecycle-pruning-route-retirement-and-axis-hygiene-routing.md`](../docs/10-framework/cube-lifecycle-pruning-route-retirement-and-axis-hygiene-routing.md) and [`../docs/20-calibration/cube-lifecycle-pruning-route-retirement-and-evidence-refresh-ladder.md`](../docs/20-calibration/cube-lifecycle-pruning-route-retirement-and-evidence-refresh-ladder.md). The compact rule is: add axes only when they improve routing; refresh evidence when facts move; retire prose when cases no longer need it.

## Anti-patterns

- **prose sprawl** — another memo repeats the existing pattern.
- **stale doctrine** — dated source facts silently govern current cases.
- **axis bloat** — synonym inflation makes the cube harder to query.
- **permanent frontier** — open calibration hardens into unreviewed rule.
