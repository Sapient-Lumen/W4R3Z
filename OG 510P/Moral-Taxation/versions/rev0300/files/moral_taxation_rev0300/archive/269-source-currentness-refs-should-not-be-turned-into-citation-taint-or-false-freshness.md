# 269 — Source-currentness refs should not be turned into citation taint or false freshness

A source-currentness reference is not a trophy citation. It is a release-critical dependency: the route is promising that if the source changes, the answer may need to change.

The archive should therefore keep three layers separate:

1. **ordinary source citation** — supports background, mechanism, or analogy;
2. **primary/load-bearing source** — supports a core route claim; and
3. **source-currentness ref** — supports a volatile legal, operational, litigation, implementation, quarterly, filing-season, AI-governance, or official projection claim that must be refreshed.

Rev0287 repairs a false-freshness pattern where a valid AI-energy source was promoted into currentness metadata for routes whose answer did not depend on that source. The fix is not source deletion. The fix is source-role discipline.

## Anti-patterns

- **currentness taint** — a broad source cluster makes unrelated routes look live or volatile.
- **citation laundering** — a route borrows the freshness of a recent source even though the source does not support the operative claim.
- **dangling registry entry** — a volatile source is tracked in the registry but no route actually depends on it.
- **false stability** — a legal or operational source is cited as background when the route should refresh on rulemaking, litigation, quarterly factors, filing-season changes, or implementation dates.

## Operational rule

Every currentness ref must have a local claim and review reason. If the claim cannot be stated, the source remains an ordinary citation rather than currentness metadata.
