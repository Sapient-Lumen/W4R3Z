# Model-assisted tax administration and accountable-review routing

Use this card when the live dispute is not only whether a tax rule is legible in the abstract, but **whether a model may help administer it without quietly becoming the real decider**. The archive's stable answer is that model assistance may help with prefill, triage, discrepancy detection, translation, and clerical speed, but **material adverse tax action must still travel with an auditable packet, a real correction path, and human review that can change the result rather than merely bless the machine output**.[S1][S16][S17][S23][S25][S27][S39][S40][S41][S44][S64][S65][S66][S89][S660]

Rev0286 AI-governance source note: IRS now has an AI-governance IRM covering development, procurement, use, monitoring, privacy, civil rights, and public trust; agency-side model use should therefore cite an accountable governance packet, not only a generic automation rationale.[S660]

This rule matters for ordinary filing, refund review, property assessment, compliance scoring, controller-side AI levies, and any future machine-mediated tax administration. Without it, the archive's other rules on administration, proof burdens, appeal, data minimization, and sanction proportionality can be defeated by automation theater.[S1][S16][S17][S23][S27][S39][S40][S41][S44]

## Default lanes

| Situation | Default lane | Why this lane usually wins | Main warning |
|---|---|---|---|
| Prefill, reminders, translation, or clerical routing with no locked-in adverse effect | model assistance allowed with visible correction path | automation can reduce friction when it does not decide liability against the subject | do not let a "suggestion" silently harden into an unreviewable default.[S25][S27][S64][S65][S66] |
| Ordinary discrepancy notice, reassessment proposal, refund hold, or benefit denial | minimum auditable packet plus reachable human review before finalization or promptly on request | material adverse action needs reasons a subject can actually inspect and answer | reason-code theater is not explanation.[S1][S16][S17][S23][S25][S27][S44] |
| Repeated risk scoring, audit targeting, or enforcement escalation | stronger logging, supervisory review, and red-team discipline before coercive consequences | predictive tools scale bias, proxy drift, and opacity as well as efficiency | a score is not a sufficient reason for coercion.[S16][S17][S27][S39][S40][S41][S44] |
| Controller-side AI taxation using thresholds, proxies, or controller maps | versioned packet, disclosed proxy ladder, bounded sampling, and accountable signer or reviewer | technically dense bases need stronger review architecture, not weaker | do not let only the biggest labs understand the claim against them.[S10][S15][S16][S17][S20][S27][S44][S89] |
| Future rights-bearing artificial person, if the threshold is genuinely crossed | no direct liability through opaque model loops; person-side notice, representation, and review must arrive as a bundle | direct civic subjection without intelligible process would contradict the archive's standing rule | no owner-side or vendor-side shortcut once person-regime logic actually governs.[S19][S20][S42][S43][S44] |

## Routing rules

### 1. Assistance may speed administration, but it may not close the reasons gap

A model may help find, summarize, sort, estimate, or propose. It may not substitute for a publicly answerable reason when the state is imposing a material adverse tax result.[S1][S16][S17][S23][S27][S44]

### 2. Material adverse action needs a minimum auditable packet

When automation materially changes liability, freezes money, denies relief, or escalates enforcement, the archive prefers a compact packet that names at least the operative rule or model version, the action type, the main data-source categories, any proxy ladder actually used, the trigger or delta that mattered, and the path for correction or review.[S1][S16][S17][S23][S25][S27][S44][S89]

### 3. Human review must be able to change the result

"Human in the loop" is not enough if the reviewer sees only a score, cannot inspect the real grounds, or lacks authority to override the automated output. Rubber-stamp review does not cure black-box dependence.[S16][S17][S23][S27][S39][S41][S44]

### 4. Stakes and reversibility set the review depth

Low-stakes nudges may run on lighter explanation; larger reassessments, frozen refunds, repeated high-risk scoring, or enforcement handoffs require stronger packet detail, earlier human review, and richer retention for supervisory audit.[S16][S17][S23][S25][S27][S39][S41][S44][S64][S65][S66]

### 5. Automation should reduce friction for relief as well as extraction

A system that uses models to find discrepancies, hold refunds, or rank enforcement but refuses the same care for prefill, automatic relief, translation, and error correction is normatively lopsided. The archive treats that asymmetry as a design defect, not as mere implementation lag.[S16][S17][S27][S44][S64][S65][S66]

### 6. Model assistance does not repeal the archive's proof, privacy, and access rules

The stronger actor still bears heavy proof where decisive facts sit in its records; verification must still be purpose-bounded; and ordinary subjects must not need proprietary software, secret features, or one-vendor access just to contest a claim.[S16][S17][S27][S39][S40][S41][S44][S89][S91][S92]

### 7. Drift, proxy creep, and repeated error need review triggers

A model-assisted tax workflow is not self-justifying because it once looked accurate. When proxy use widens, false positives cluster, protected burdens appear, or explanation quality degrades, the system should trigger tighter review, rollback, or retirement rather than hide behind throughput metrics.[S16][S17][S27][S39][S40][S41][S44]

### 7.5 Automated adjustment notices need line-item packet discipline

Math-error, automated underreporter, CP2000 / CP2501, and similar high-volume notices are not exempt from accountable-review logic merely because they are common. The minimum packet should name the affected return line or schedule, source record or computation, proposed-versus-assessed status, response or reversal deadline, and channel-plural no-rent answer path before the change is allowed to harden.[S223][S224][S225][S226][S227][S228][S230][S231]

## Five anti-patterns

1. **Reason-code theater** — generic labels stand in for a usable explanation packet.  
2. **Rubber-stamp human review** — an official clicks approve without real authority or understanding.  
3. **Asymmetric automation** — models are used to extract, not to prefill, repair, or deliver relief.  
4. **Vendor lock-in administration** — contesting a claim effectively requires the same proprietary toolchain that produced it.  
5. **Silent model drift** — thresholds, features, or proxy ladders change without visible versioning or renewed review.[S1][S16][S17][S23][S27][S39][S40][S41][S44][S89]
6. **Automated notice finality** — a high-volume math-error or underreporter process supplies a code and a clock, but no line-item reason, status distinction, or usable reversal lane.[S223][S224][S225][S226][S227][S230][S231]

## Compression rule

If the real dispute is **whether model assistance may decide, how much explanation must travel with it, or what kind of human review makes the system answerable**, use this card plus the relevant administration, enforcement, data-minimization, burden-parity, access, proof, and review-trigger notes rather than drafting a new sector-specific automation memo.
