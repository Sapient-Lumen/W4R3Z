# Calibration memo format

The archive's narrow waist is now mostly closed. Most future growth should therefore arrive as **small calibration memos**, not as new constitutional routing notes.

Use this format when the rule already exists and the live question is **where to set a threshold, how to weight a split, how strong a disclosure rule must be, what proxy ladder to allow, how much bonding to require, or what delivery / appeal standard is enough**.

## Use a calibration memo when

- the archive already has a routing rule for the problem,
- the live dispute is mainly about parameter choice or operating standard,
- the output can stay small and comparative,
- and the work does not need to reopen personhood, incidence, scale, subjecthood, review architecture, or other closed waist questions.

If the work is really about a missing routing rule, a material reversal, or a genuine compression win, use the admission rule in [`../10-framework/waist-closure-and-calibration-frontier.md`](../10-framework/waist-closure-and-calibration-frontier.md) instead.

## Preferred size

Aim for **one short note**, usually closer to a dense memo than a mini-paper. The archive should learn from the memo, not warehouse the whole literature around it.

## Default skeleton

Every calibration memo should try to answer these blocks in order:

1. **Question in one sentence.** What parameter or operating choice is actually live?
2. **Closed rule invoked.** Which narrow-waist note already settles the constitutional part?
3. **Why calibration is still needed.** What remains genuinely open after the rule is fixed?
4. **Small option set.** Usually two to four options or ladders, not a giant menu.
5. **Provisional recommendation.** What is the narrowest workable setting now?
6. **What would change the recommendation.** What evidence, trigger, or failure pattern reopens it?
7. **Source IDs only.** Cite the archive's source registry compactly rather than reproducing long source summaries.

## Default output shapes

Prefer the smallest shape that fits the question:

- a **threshold ladder**,
- a **claim-splitting table**,
- a **proxy hierarchy**,
- a **bonding / reserve ladder**,
- a **delivery / appeal decision table**,
- or a **trigger-and-review matrix**.

If a memo needs more than one of those, the question may still be too broad.

## Red lines

Do not use a calibration memo to:

- restate the whole archive,
- reopen a closed routing rule without saying so,
- smuggle in a new tax base by example,
- paste large source summaries,
- or hide a normative reversal inside a supposedly technical parameter tweak.

## Naming consequence

When possible, title the memo for the **live parameter** rather than the whole policy domain. Example: not `ai-taxes.md`, but something like `automation-dividend-trigger-ladder.md`.

## Practical consequence

When the frontier map says a problem should become "one calibration memo," this note is the default format it means. Future archive growth should increasingly look like this template plus a small amount of evidence, not another round of waist proliferation.
