# Compute wager protocol

This file operationalizes the original seed's test-time-compute idea without embedding the seed itself.

## Working thesis

Poetry generation is cheap; selection is the bottleneck. Extra samples help only when the cube can reject obvious failures mechanically or statistically before asking taste to decide. Therefore the project should spend early effort on verifiers, receipts, and selection architecture before spending large generation budgets.

## Shell/core split

- **Shell**: constraints kept, source claims checked, quote-search clear, banlist/fingerprint acceptable, metadata present, no prohibited concealment, no known specimen imitation.
- **Core**: the live poetic question: pressure, music, surprise, necessity, disclosure survival, memorability, reread value.

Compute can improve shell compliance. It cannot prove the core. The cube must not let a strong shell impersonate a living poem.

## Verifier-first funnel

1. Metadata gate: poem record exists before drafting.
2. Research gate: turn pulse exists; poem-specific source pulse exists if documentary.
3. Mechanical gate: counted/lettered constraints checked by tool or explicit receipt.
4. Banlist/fingerprint gate: obvious LLMPoetry and Fable-contamination tells scanned.
5. Novelty/quote gate: title and strongest phrases searched before evidence status.
6. Cold taste gate: no same-turn judgment; pairwise/order-swapped criteria first.
7. Disclosure gate: external-facing test must disclose machine role after blind rating.

## First compute posture

For P0001, use a small budget: one planned form, a few branches, no best-of-N charisma contest. The first goal is to test whether records and validators catch enough failures to make larger compute ethical and informative.
