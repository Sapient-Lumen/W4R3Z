
# Datacube design

The cube is not a folder of poems. It is a set of coordinates and receipts for poetic work.

## Core axes

- **Turn/time**: revision, turn, phase, draft lineage, and cold-judgment boundary.
- **Research pulse**: query/source, role, source-health state, entropy value, and effect on the turn.
- **Generation**: model/operator, prompt, parameters when known, source pulse, and human intervention regime.
- **Form**: form family, constraint stack, whether verification is mechanical, manual, or absent.
- **Quarry**: source IDs, facts harvested, facts used, source quality, currentness, and copyright/ethics status.
- **Failure**: banlist hits, end-word patterns, cliché structures, generic closures, imitation risk, and corpus fingerprints.
- **Evaluation**: judge, standards, pairwise target, order swap, position consistency, verdict band, disclosure result.
- **Revision**: edit operator, knowledge delta, what new pressure entered the poem, and what was cut.
- **Status**: template, draft, graveyard, anthology candidate, evidence candidate, admitted, withdrawn.
- **Proof**: fact gate, quote-search gate, constraint gate, external/human judge, disclosure survival.

A poem becomes a datacube entity only when these coordinates are recorded in `poems/P####/metadata.json` and the registries point to it.
