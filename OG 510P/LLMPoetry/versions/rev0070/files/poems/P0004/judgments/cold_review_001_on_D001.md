**Verdict:** `revise_not_promote`  
**Temporal status:** later-turn review of the exact rev0067 draft, packet, OCI spec, receipt, index, layout, and rendered surfaces.  
**Successor:** P0004-D002 is created in this revision and remains same-turn unjudged.

## Decision

D001 proves the mechanism it claims, but its page is too close to a verification receipt. The lower objection appears; the upper layer names that exact objection in an explicit whiteout; the merged view reports both paths missing; the manifest reports both layers required. Full disclosure confirms the diagram rather than opening a second reading. The work therefore risks ending at the instant a technically informed reader solves the whiteout rule.

Its strongest fact should be preserved: deletion and deletion-marker both disappear while the immutable layer blobs remain structurally required. The revision should not ornament that fact. It should make the administrative act less enumerable and create a surviving contradiction inside the same layer that performs the deletion.

## Criterion-first read

- **Form integrity — B.** The image layout is actual, but the page repeats its receipt.
- **Specificity density — B-.** Paths and byte count are exact; `I OBJECT TO THIS RECORD` is generic.
- **Closure risk — B-.** Manifest retention leaves residue, but disclosure resolves almost everything else.
- **Diction risk — B.** Filesystem diction is severe; the objection is placeholder legal language.
- **Disclosure survival — C+/B-.** Explanation verifies more than it deepens.
- **Need test — B.** The layers matter, but much of the page can still be paraphrased without them.

## Revision action

D002 must use several lower appeal files and one opaque whiteout, so the deletion does not name each suppressed record. The upper layer must also add `NO APPEAL ON FILE`. The opaque marker is intentionally placed after that status in tar order: a correct OCI application hides only lower children and retains same-layer additions regardless of encounter order.

That requirement exposed a real defect in the incoming simulator, which processed opaque markers sequentially and could wrongly erase same-layer files that appeared earlier in the tar. The refactor applies all whiteouts to the pre-layer state first, then applies non-whiteout entries. It also requires the poem layout's blob directory to be closed-world, preventing unreferenced content from hiding beside the committed image.

This review is not evidence, admission, publication clearance, or a reader response. D002 is not judged here.
