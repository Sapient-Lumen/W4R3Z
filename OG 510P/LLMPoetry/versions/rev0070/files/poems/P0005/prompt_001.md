# P0005-P001 — false presence without deletion

Open a machine-native family that does not depend on vacancy, whiteouts, hidden history, or another bureaucratic erasure.

Build an actual insertion-only Bloom filter with a synthetic exact ledger. The non-member query must return `POSSIBLY PRESENT` because each of its three set bits was contributed by a different inserted record. No inserted record may own more than one of the query's bits. Commit the binary filter, ledger, query, rendered surface, deterministic builder, and independent checker.

Keep the body short. Do not invent a real case, person, institution, adverse action, or false-positive rate. Disclose the mechanism and the exact-ledger contradiction. Preserve all earlier candidate bytes and the zero-response reader log. Same-turn judgment is prohibited.
