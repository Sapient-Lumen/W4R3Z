# Trajectory map

## Current priorities

### T1. Preserve the teacher as the accountable instructional adult

The archive currently treats AI as strongest when it expands teacher reach and judgment rather than replacing them. See [`docs/10-core/reference-model.md`](../10-core/reference-model.md) and [`docs/20-governance/evidence-and-procurement.md`](../20-governance/evidence-and-procurement.md).

Linked open questions: `OQ-0002`, `OQ-0004`.

### T2. Shift from assignment completion to proof of learning

The archive's sharpest substantive claim is now backed by a compact default bundle grammar and subject-family templates. The next issue is institutional plausibility: how much richer evidence can schools demand without creating intolerable labor costs or surveillance? See [`docs/40-assessment/authentic-assessment-and-proof-of-learning.md`](../40-assessment/authentic-assessment-and-proof-of-learning.md) and [`docs/40-assessment/proof-of-learning-bundles.md`](../40-assessment/proof-of-learning-bundles.md).

Linked open questions: `OQ-0003`, `OQ-0005`.

### T3. Raise the procurement and evidence bar

The archive now has a clearer minimum evidence package by stake level, but the boundary between promising pilots and scale-worthy interventions still needs refinement. See [`docs/20-governance/evidence-and-procurement.md`](../20-governance/evidence-and-procurement.md).

Linked open questions: `OQ-0004`, `OQ-0006`.

### T4. Build AI literacy as a curricular strand with progression

The archive now has a minimal spine, an exemplar kernel, a small course-level grammar, and a two-channel rule for separating pedagogical disclosure from protected access-support routing. The next implementation problem is narrower: which access-support categories can be standardized safely across institutions, and which still need local override because the construct being assessed differs too much by discipline, age, or sector? See [`docs/10-core/minimal-ai-literacy-spine.md`](../10-core/minimal-ai-literacy-spine.md), [`docs/30-operations/subject-embedded-exemplar-kernel.md`](../30-operations/subject-embedded-exemplar-kernel.md), [`docs/30-operations/course-level-ai-use-grammar.md`](../30-operations/course-level-ai-use-grammar.md), and [`docs/20-governance/accommodation-aware-disclosure-and-accessibility.md`](../20-governance/accommodation-aware-disclosure-and-accessibility.md).

Linked open questions: `OQ-0001`, `OQ-0005`.

### T5. Extend the archive beyond course shells into lifelong public learning routes

The archive now has a public-stack model, a minimum handoff standard, a typed packet, sector-specific recognition defaults, a governance rule for standing-equivalency lists, a tiny publication profile with family-specific recency windows, a bounded exception grammar for partial equivalencies and local overrides, a privacy-light maintenance rule for learning from appeals and false matches through aggregate signals, a thin public maintenance-history profile that publishes state, date, scope, reason family, and action hint without raw counts, a default partner-consumption / grandfathering rule that makes most changes future-use only unless integrity, authority, fraud, or legal invalidity are at stake, a dedicated in-flight protection grammar that prefers teach-out, successor substitution, challenge access, or construct-close equivalents over hard restart when learners already relied in good faith, and a compact evidence-and-burden rule for deciding when stronger protection is owed rather than merely preferred. The next problem is narrower still: when a system-caused rule change still requires a bridge, challenge, or substitute-equivalent step, which fees and support costs must the system absorb rather than offload back onto the learner. See [`docs/30-operations/lifelong-public-ai-learning-stack.md`](../30-operations/lifelong-public-ai-learning-stack.md), [`docs/30-operations/portable-public-learning-packet-and-recognition-profile.md`](../30-operations/portable-public-learning-packet-and-recognition-profile.md), [`docs/30-operations/sector-defaults-for-public-ai-learning-recognition.md`](../30-operations/sector-defaults-for-public-ai-learning-recognition.md), [`docs/30-operations/standing-equivalency-lists-and-review-governance.md`](../30-operations/standing-equivalency-lists-and-review-governance.md), [`docs/30-operations/standing-list-publication-profile-and-recency-windows.md`](../30-operations/standing-list-publication-profile-and-recency-windows.md), [`docs/30-operations/standing-recognition-exception-profile-and-local-overrides.md`](../30-operations/standing-recognition-exception-profile-and-local-overrides.md), [`docs/30-operations/appeal-feedback-and-standing-list-maintenance.md`](../30-operations/appeal-feedback-and-standing-list-maintenance.md), [`docs/30-operations/public-maintenance-history-and-trust-signals.md`](../30-operations/public-maintenance-history-and-trust-signals.md), [`docs/30-operations/partner-consumption-and-grandfathering-rules.md`](../30-operations/partner-consumption-and-grandfathering-rules.md), [`docs/30-operations/in-flight-teach-out-and-substitute-equivalent-rules.md`](../30-operations/in-flight-teach-out-and-substitute-equivalent-rules.md), and [`docs/30-operations/documented-reliance-and-burden-thresholds.md`](../30-operations/documented-reliance-and-burden-thresholds.md).
