# First activation route-stability operation and deconflict-exit defaults for hot-exam recipient followup shells

The archive can now publish one still smaller layer for the hottest exam-like learner-request routes.

It can already say:

- when a retired route reappears, a replacement route activates, a decommissioned residue gains a current owner, or no-active-route residue exposes a current path;
- when the first activated cycle exposes route-choice drift between revived routes, replacement routes, source/search/archive surfaces, recipient portals, protected routes, proof objects, or clocks;
- when the same route-choice conflict repeats after first-cycle resolution, split, or minimization; and
- when that repeat conflict crosses a named route-stability threshold without turning every first conflict into a standing watch or treating repeated owner-side ambiguity as learner fault.

That is still not enough.

A threshold is only truthful if the shell can say what the threshold actually opens. It might open a bounded watch. It might require owner reconciliation. It might send one route pair to redesign. It might split public, protected, recipient, archive, or official-record paths. It might retire the revived route again. It might retain dual-route recognition for one recipient cycle. It might expose no-active-route residue. Or it might close because current proof shows that the apparent repeat conflict was only ordinary search/cache/archive lag.

This document adds one thing only:

- a **tiny activation route-stability operation / deconflict-exit field set** for hot-exam recipient followup shells after `YQ0-YQ4` has already found a repeat activation-cycle conflict threshold, but before the archive claims that a bounded watch, reconciliation, redesign, split, retired-route posture, or no-active-route residue is operating or has exited.

That means the archive now asks a different question than before. It no longer asks only **when repeated route-choice conflict crosses a threshold**. It now asks **what the opened threshold may do, what current proof can deconflict it, what learner-safe action applies while owners reconcile, and how the deconflict memory exits learner-facing publication — without creating permanent activation surveillance, public route-pair stigma, automatic duplicate learner filing, or an all-surface replacement-failure certificate**.

Current official signals support a deliberately narrow answer. Google Search Console's Removals tool is property-owner, exact-URL, current/expired-history, temporary-removal, cancellation, about-six-month, Google-Search-only, and source-side-permanent-method based rather than a global route-pair operating authority. Google's Refresh Outdated Content route is exact page/image URL, changed/gone-content, queue/status, additional-URL, and 180-day-expiry based rather than an automatic recipient-route deconfliction monitor. Google's personal-content and site-owner removal surfaces keep Search removal, source-page removal, screenshot proof, notifications, new-result handling, and sensitive proof separate. WiscWeb separates local WiscWeb source edits, emergency edits, primary-contact support, redirection, caching, campus search/lookahead/directory behavior, and major-search-engine non-control. Princeton separates local deletion, document/media cleanup, access control, cache behavior, Google/Bing/custom-search exclusion, and Wayback persistence. Rowan separates CMS ownership, Web Services support, Siteimprove/accessibility monitoring, contributor training, content-audit/redesign work, support tickets, and accommodation routing. Internet Archive asks for URL, time-period, control-period, and review context before exclusion. Bing distinguishes temporary block, up-to-90-day expiry, cached/outdated-content handling, exact URL submission, extension or permanent-removal prerequisites, and source-side methods such as 404/410 or noindex. Together those signals support a tighter archive rule: **the next truthful portability gain here is one tiny operating layer for threshold run-state, deconflict scope, owner proof, learner-safe action, exit disposition, minimization, and reopen triggers — but not one permanent activation dashboard, one public route-pair proof vault, one duplicate-filing duty, one all-engine replacement-failure certificate, or one no-memory reset.** See `B262`.

## Small field set for activation route-stability operation and deconflict exit

| Code | Meaning | Default archive action |
|---|---|---|
| `YO0-NO-PERMANENT-ACTIVATION-SURVEILLANCE-ROUTE-PAIR-STIGMA-DUPLICATE-FILING-OR-REPLACEMENT-FAILURE-CERTIFICATE` | a threshold can open bounded work, but it does not automatically create a permanent watch, public instability label, duplicate learner-filing duty, or all-surface replacement failure | require a current named operation state, affected scope, owner, learner action-now truth, and exit basis before the shell widens beyond `YQ0-YQ4` threshold publication |
| `YO1-PUBLISH-OPERATION-RUN-STATE-SCOPE-OWNER-AND-CADENCE-LIMIT` | an opened threshold must say what is actually running and how bounded it is | publish whether the threshold opened bounded watch, owner reconciliation, route redesign, route split, recipient confirmation, protected-route handling, retired-route posture, no-active-route residue, ordinary lag review, or no operation; name affected route pair, surface, owner, cadence or event trigger, and what is out of scope |
| `YO2-PUBLISH-DECONFLICT-PROOF-AND-PRECEDENCE-BASIS` | deconfliction requires current proof, not owner assertion, stale screenshot, or platform lag alone | publish current replacement proof, revived-route proof, reciprocal owner confirmation, recipient-of-record confirmation, protected-route authority, source-owner update, search/archive status, official-record proof, route-native clock proof, or `precedence unresolved` with age and scope |
| `YO3-SEPARATE-LEARNER-SAFE-ACTION-FROM-OWNER-DECONFLICTION-WORK` | owner-side route instability should not force duplicate filings or adverse wrong-route risk on the learner | publish learner action only when current proof requires it; otherwise publish no action now, submit once with dual-route recognition, use the more protective route, use the longer current window, wait for owner confirmation, protected local-only handling, manual support, or owner-only action |
| `YO4-PUBLISH-DECONFLICT-EXIT-MINIMIZATION-AND-REOPEN-TRIGGERS` | route-stability operations must end, split, hand back, minimize, or reopen on named facts instead of lingering as public dashboards | publish ordinary activation restored, route pair reconciled, replacement controls, revived route controls, dual-route recognition retained, route split retained, route redesign handoff, retired-route residue, no-active-route residue, operation extended, operation closed, minimized memory, or reopen only on material route, owner, proof, clock, recipient, protected-route, search, archive, or official-record facts |

## Field values that now travel together

When this layer is used, the shell should publish only six concrete fields:

1. `activation_stability_operation_state_token` — `none`, `threshold met but no operation opened`, `bounded activation watch`, `owner reconciliation opened`, `route redesign opened`, `route split operation`, `recipient confirmation operation`, `protected route handling`, `retired route posture`, `no active route residue`, `ordinary lag review`, `operation closed`, `none inherited`, or `not published`;
2. `activation_deconflict_scope_token` — `revived and replacement route pair`, `replacement route only`, `revived route only`, `recipient portal`, `official record`, `protected accommodation or accessibility route`, `source page`, `Google result family`, `Bing or partner-search family`, `custom search`, `image result`, `archive capture or mirror`, `proof object`, `clock or deadline`, `prerequisite requirement`, `multiple affected scopes`, `none inherited`, or `not published`;
3. `deconflict_owner_and_proof_token` — `replacement owner proof current`, `revived route owner proof current`, `reciprocal owners confirmed`, `recipient of record confirmed`, `official record owner confirmed`, `protected owner confirmed`, `source owner updated`, `search status current only`, `archive status current only`, `clock precedence proof current`, `proof still stale`, `proof mismatched`, `precedence unresolved`, `no active owner`, `none inherited`, or `not published`;
4. `learner_safe_action_during_operation_token` — `none current`, `wait for owner confirmation`, `use replacement route`, `use revived route`, `submit once with dual-route recognition`, `do not duplicate filing`, `use more protective route until resolved`, `use longer current window until resolved`, `protected local-only submission`, `manual local support only`, `owner-only action`, `information-only notice`, `none inherited`, or `not published`;
5. `deconflict_exit_disposition_token` — `ordinary activation restored`, `route pair reconciled`, `replacement route controls`, `revived route controls`, `dual-route recognition retained`, `route split retained`, `protected route retained`, `recipient path controls`, `route redesign handoff`, `retired route residue`, `no active route residue`, `ordinary lag only`, `operation extended`, `operation closed without learner action`, `none inherited`, or `not published`;
6. `deconflict_memory_and_reopen_token` — `minimized public memory`, `local-only proof retained`, `recipient proof retained`, `protected proof sealed`, `old route proof superseded`, `threshold memory expired`, `reopen on material route reappearance`, `reopen on owner change`, `reopen on proof mismatch`, `reopen on clock conflict`, `reopen on recipient conflict`, `reopen on protected-route conflict`, `reopen on source search archive split`, `no reopen trigger`, `none inherited`, or `not published`.

## Practical deconflict-operation defaults

| Situation | Minimal publication | Why |
|---|---|---|
| repeated revived-vs-replacement conflict crosses a threshold | `bounded activation watch` or `owner reconciliation opened`, affected route pair, current owners, `submit once with dual-route recognition` or `use more protective route until resolved`, and explicit exit condition | threshold status can require owners to reconcile, but it should not create duplicate learner filing or public route-pair stigma |
| recipient portal repeatedly accepts the retired route after replacement activation | `recipient confirmation operation`, recipient-of-record owner, last current replacement proof, `submit once with dual-route recognition`, and whether recipient path controls or splits | recipient dependency can govern live learner action even when a source route has migrated; the shell should protect timely action while owners deconflict |
| protected accommodation or accessibility route repeatedly conflicts with public replacement route | `protected route handling`, protected owner proof, `protected local-only submission`, and `protected route retained` or `route split retained` | protected proof should not become public merely because the public route pair is unstable |
| search, image, custom-search, or archive surfaces keep showing the retired route while source and recipient agree on the replacement | `ordinary lag review` or `retired route residue`, source / recipient proof, `no learner action now`, and minimized memory | search/cache/archive lag can be real evidence but does not by itself make the old route current or the replacement route failed |
| two clocks recur after a route pair was reconciled once | `owner reconciliation opened`, `clock or deadline`, clock-precedence proof or `precedence unresolved`, `use longer current window until resolved`, and clean exit only after conflict-aware notice | adverse clocks should not attach until a current owner publishes the controlling route-native window |
| route redesign is needed because repeated conflict comes from the same route instructions | `route redesign opened`, redesign owner, proof objects in scope, `owner-only action` unless learner proof is currently needed, and `route redesign handoff` | redesign is owner work, not proof that every learner must refile or that every old conflict stays public |
| no owner can currently reconcile the route pair | `no active route residue`, affected scope, last current proof, `manual local support only` or `no action now`, and material reopen triggers | absence of a current owner should be published as residue, not fictional approval, denial, closure, or learner abandonment |
| operation closes after one clean cycle | `operation closed`, current controlling path, `ordinary activation restored`, minimization state, and reopen triggers | clean exit restores ordinary handling without erasing proof that mattered during the unstable window |

## What this layer now makes portable

Hot-exam recipient followup shells may now publish one tiny `YO0-YO4` layer after `YQ0-YQ4` when the archive needs to say not merely that **repeat route-choice conflict crossed a threshold**, but that **a bounded deconflict operation is now running, what proof can close it, what learner-safe action applies while it runs, and how its memory exits publication**.

That means a shell may now truthfully say things like:

- `repeat route-choice conflict met the threshold; owners are reconciling, submit once, and no adverse clock runs until conflict-aware notice names the controlling route`;
- `recipient confirmation is live because the portal still accepts the retired path; timely action through either named path is preserved while the recipient owner confirms`;
- `the public replacement path controls, but protected accommodation proof remains local-only and the protected route stays split`;
- `the old route appears only in a search or archive surface; keep retired-route residue time-slice-specific and do not reopen learner action`; or
- `the operation closed after one clean route-choice cycle; minimize public conflict proof and reopen only on material route, owner, clock, recipient, protected-route, search, archive, or official-record facts`.

It still may not pretend:

- that threshold status creates permanent activation surveillance;
- that a route pair deserves a public instability label forever;
- that repeated owner disagreement is learner fault;
- that learners must duplicate filings while owners deconflict;
- that a search result, archive capture, or screenshot makes the old route current by itself;
- that owner assertion alone proves repair, reconciliation, or redesign;
- that protected or sensitive proof must become public to deconflict a public route; or
- that one surface's deconflict result is an all-surface replacement-failure or all-surface restoration certificate.

## Why this matters for the larger archive

The archive's education-with-AI program is not only about identifying instability. It is also about making the repair state legible enough that learners are not made responsible for owner-side ambiguity.

This layer matters because a threshold can otherwise become a silent status trap. One bad default says repeated route-choice conflict automatically proves the replacement failed and all learners should refile, reprove, or restart. Another bad default says a threshold is only an internal owner concern and learners can safely ignore it even while two official-looking paths keep publishing different clocks or prerequisites. Both are wrong. The portable answer is narrower: publish **what operation is actually running**, **which route pair or surface is affected**, **who owns deconfliction**, **what current proof controls or remains unresolved**, **what the learner can safely do without wrong-route risk**, **what clock posture applies**, **how protected or sensitive proof stays bounded**, and **how the route pair exits, splits, hands back, redesigns, retires, minimizes, or reopens**.

## Boundary conditions

This layer should not be used when only one of the following is true:

- `YQ0-YQ4` has not found a repeat activation-cycle conflict threshold;
- the visible difference is ordinary search/cache/crawl/archive lag with no learner-facing route-choice, owner, proof, clock, recipient, protected-route, or live dependency effect;
- the route-native process already names the operating owner, deconflict proof, learner-safe action, clock, exit state, and reopen rule;
- the only signal is an unrelated mirror, screenshot, archive capture, expired history row, or downstream copy with no current owner or learner dependency;
- a protected accommodation, privacy, safety, legal, records, appeal, or recipient-of-record process already controls proof handling and should stay local-only;
- no operation is open and the threshold was closed as non-material lag; or
- a current rule expressly requires a different local conflict-resolution, duplicate-filing, precedence, or appeal posture.

In those cases, publish `no operation opened`, `ordinary lag only`, `route-native rule controls`, `protected local-only route`, `no learner action now`, `no active owner`, `threshold closed`, or `none inherited` rather than creating a portable deconflict operation.

## What this closes

This closes `FT-0148`.

The archive no longer stops at "repeat route-choice conflict crossed a threshold". It can now publish a minimal activation route-stability operation / deconflict-exit layer: operation run-state, affected scope, owner, cadence limit, deconflict proof, learner-safe action, exit disposition, minimization, and reopen triggers when a revived route, replacement route, recipient portal, protected route, source/search/archive surface, proof object, official record, or clock repeatedly conflicts after activation.

It also opens one narrower seam.

After a deconflict operation exits, splits, hands back, redesigns, retires a route, restores ordinary activation, or becomes no-active-route residue, the archive may still need a tiny post-deconflict relapse / route-pair memory layer for cases where the same route pair later relapses, old deconflict proof ages, minimized memory must be recalled, or a learner again sees two official-looking paths — without making every later recurrence an automatic re-watch, permanent route-pair stigma, or total fresh-start amnesia.
