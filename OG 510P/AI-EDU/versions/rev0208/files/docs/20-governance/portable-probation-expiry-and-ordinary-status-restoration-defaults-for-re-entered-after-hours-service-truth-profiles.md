# Portable probation-expiry and ordinary-status restoration defaults for re-entered after-hours service-truth profiles

This document closes the archive's next after-hours governance gap: **once a callback-only after-hours branch has already repeat-retreated, regained portable callback publication under one shared local-repair / fresh-republication package, and then survived its first watched returned cycle cleanly, can that clean watched cycle itself carry one shared probation-expiry / ordinary-status restoration package, or should the meaning of "ordinary again" still remain local even after portable re-entry has already survived one monitored reuse?**

The archive's answer is narrower again:

> only branches whose **end-of-probation callback truth** remains stable across the reuse scope should carry one shared probation-expiry / ordinary-status restoration package. In the starter canon, only some low-consequence callback-only `ST-HE-TEACHOUT` and `ST-LIB-CIVIC-FIRST` branches usually carry one shared restoration package; aid / credit, public-route, licensure-sensitive, and protected-support branches should keep restoration-to-ordinary trust local.

The point is to avoid three opposite errors at once:

- **premature normalization** — a service treats any clean watched returned cycle as automatic proof that ordinary callback trust has returned, even where the real meaning of "ordinary again" still depends on owner-specific caution, queue review, or consequence checks;
- **shadow-restoration drift** — a service publishes one watched returned-cycle package but then restores ordinary callback status only through unpublished owner-local discretion, hidden residue checks, or opaque approvals;
- **permanent probation** — a callback-only branch whose clean watched returned cycle really does mean the same thing across the tiny reuse scope never earns one portable restoration rule and therefore remains artificially probationary forever.

Current public signals support this thinner move. HLC's current teach-out policy still treats communications, applicability periods, credit treatment, fees, and records as governed student-facing commitments. OIA's current good-practice materials still expect providers to tell students what they must do to preserve position while matters remain live and to issue Completion of Procedures Letters once internal processes actually end. Federal Student Aid still says a school's aid offer is the best source of truth rather than earlier estimates. ALA still frames civic/library access as low-barrier public access infrastructure rather than downstream decision ownership. SAMHSA still treats 988 as a genuinely live 24/7 crisis route. Together those signals support a small archive rule: **a clean watched returned callback cycle may sometimes end special callback probation, but only inside a very small callback-only reuse scope and never by elapsed time alone or hidden owner forgiveness.** See `B192`.

## Three restoration portability tiers

The archive now distinguishes three probation-expiry / ordinary-status restoration portability tiers.

| Tier | Meaning | What travels | What stays local |
|---|---|---|---|
| `AOS-BOTH` | the watched re-entered branch carries one shared probation-expiry floor and one shared ordinary-status restoration rule | the minimum clean watched returned-cycle condition that ends special callback probation and the minimum fact that the next eligible callback cycle returns to ordinary portable status | any stricter local sign-off, any extra local checkpoint, and any stronger local warning or challenge route |
| `AOS-EXPIRY` | the branch carries only one shared probation-expiry floor | the minimum fact that a clean watched returned cycle can end special callback probation | the actual rule for when ordinary status is restored and what lingering local residue still matters |
| `AOS-LOCAL` | the branch carries no shared restoration package | only the earlier promotion, quantitative, miss, retreat, re-entry, and watched-cycle tiers | both probation-expiry and ordinary-status restoration |

The archive is deliberately asymmetric again:

> restoration portability is harder to earn than watched-cycle portability. A branch can carry one shared `PW-CB1BD-1RETURN + RC-CB1BD-LOCAL` package while the truth about becoming **ordinary again** still remains owner-local.

## Five tests for whether end-of-probation callback truth really travels

A watched re-entered callback-only after-hours branch may harden above `AOS-LOCAL` only when all five tests hold.

1. **same-clean-watch-meaning test** — a clean watched returned cycle really means the same thing across the reuse scope rather than one owner treating it as a bounded callback-shell pass while another treats it only as provisional evidence pending local approval.
2. **same-probation-expiry boundary test** — the exact point at which special callback probation ends can be described in one reusable way rather than depending on local queue review, local callback closure rituals, or owner-specific caution residue.
3. **same-ordinary-status meaning test** — saying that the next eligible cycle is now ordinary again means the same thing across the reuse scope: no special watched-cycle warning remains, and the path falls back to the ordinary portable callback package rather than to unpublished shadow probation.
4. **no-shadow-restoration test** — the shared restoration package does not conceal local shadow review, unpublished holdbacks, or stronger owner-specific evidence burdens that still materially determine whether ordinary callback trust has actually returned.
5. **same-post-restoration inheritance test** — once ordinary status is restored, the callback path really inherits the same baseline after-hours canon across the proposed scope rather than diverging immediately through local recent-repair sensitivity, queue-protection residue, or hidden accelerated re-cooling rules.

Failing the second, third, fourth, or fifth test keeps the branch at `AOS-LOCAL`. Failing only the third may eventually point to `AOS-EXPIRY`, but the starter canon does not yet use that middle tier.

## The starter probation-expiry / ordinary-status restoration package

The archive now names one shared probation-expiry floor and one shared ordinary-status restoration rule.

| Code | Meaning |
|---|---|
| `WE-CB1BD-CLEAN` | a **clean watched returned cycle** closes special callback probation only if the published `PW-CB1BD-1RETURN + RC-CB1BD-LOCAL` package completed without a missed callback against the republished band, fresh owner-window inflation, new queue / rights / protected-route consequence, or unresolved owner-scarcity relapse |
| `OR-CB1BD-RETURN` | once `WE-CB1BD-CLEAN` is satisfied, the next eligible cycle returns to the branch's ordinary portable callback status rather than carrying watched re-entry again, while still inheriting all ordinary callback-band, missed-window, retreat, and future re-entry rules |

The archive does **not** yet create a richer restoration ladder. The starter canon is deliberately small:

- no watched re-entered after-hours branch currently restores ordinary status before the watched cycle closes cleanly;
- no watched re-entered after-hours branch currently restores ordinary status by elapsed time alone;
- where the archive refuses a shared restoration package, services must still publish a **local** end-of-probation / restoration rule, or say plainly that renewed callback portability remains under owner-local caution even after a clean watched returned cycle.

## The archive's starter restoration answers

### `ST-HE-TEACHOUT` may sometimes harden as `AOS-BOTH` with `WE-CB1BD-CLEAN + OR-CB1BD-RETURN`

Some low-consequence callback-only teach-out branches may usually carry **both** one shared probation-expiry floor and one shared ordinary-status restoration rule across the tiny reuse scope that already survived `ARP-BOTH` and `RWP-BOTH`.

Why the archive allows this:

- low-consequence teach-out callback re-entry usually means the same thing across that reuse scope: a comparison or low-stakes continuity callback shell cooled locally, returned under fresh republication, and then survived one fully published watched cycle without fresh miss, owner-window inflation, or consequence drift;
- the point at which special callback probation ends is usually describable in one reusable way too: once that watched returned cycle closes cleanly under the already-published package, there is no extra hidden owner step that changes whether the branch is still special or ordinary;
- the meaning of "ordinary again" is relatively thin and therefore portable here: the path does **not** become exempt from ordinary callback-band, miss, retreat, or later relapse rules, but it does stop carrying the special watched-return flag.

The starter default is therefore:

> when a low-consequence callback-only `ST-HE-TEACHOUT` branch has already earned `OV1`, `AQT-CALLBACK`, `ABP-BOTH`, `RFP-BOTH`, `ARP-BOTH`, and `RWP-BOTH`, and then completes its watched returned cycle cleanly under `PW-CB1BD-1RETURN + RC-CB1BD-LOCAL`, it may usually also inherit `AOS-BOTH` with `WE-CB1BD-CLEAN + OR-CB1BD-RETURN`.

What this means in practice:

1. after a re-entered teach-out callback branch survives the watched returned cycle cleanly, the special re-entry probation ends at cycle close;
2. the next eligible callback cycle does **not** need to republish the watched-cycle flag or carry a hidden restoration review;
3. ordinary portable callback status returns, but only the ordinary portable status already defined elsewhere — callback-band, missed-window, repeat-failure, and future re-entry rules still govern the path;
4. any later miss, owner-window inflation, or consequence drift is handled by the ordinary after-hours canon rather than by pretending the branch is forever stuck in returned-cycle probation.

### `ST-LIB-CIVIC-FIRST` may sometimes harden as `AOS-BOTH`

Some callback-only civic/library first-contact branches may usually carry the same shared restoration package.

Why the archive allows this:

- the ordinary meaning of a clean watched returned cycle is similarly thin here: a low-stakes callback shell for civic first-contact has returned, stayed within the published callback band for one watched cycle, and has not drifted into downstream decision ownership;
- restoring ordinary status does not convert the library or civic front door into a downstream aid, complaint, or licensure owner; it only ends the temporary watched-return caution for the thin callback shell.

The archive therefore usually allows the same `AOS-BOTH` starter package here once the branch has already truthfully carried the same thin portability chain.

### `ST-HE-AID-CREDIT` stays `AOS-LOCAL`

Aid / credit branches should currently keep probation-expiry and ordinary-status restoration local.

Why the archive does **not** promote a shared restoration package here:

- even where an aid / credit branch could truthfully publish a returned callback band and one watched returned cycle, the meaning of "ordinary again" still varies materially with school-specific aid review, credit-treatment residue, and queue / rights effects;
- a shared restoration package would therefore overstate how comparable the end-of-probation boundary really is.

### `ST-WF-PUBLIC-ROUTE` stays `AOS-LOCAL`

Public-route branches should also keep restoration-to-ordinary trust local.

Why:

- restoring ordinary callback status in a public-route context can still change how preserved place, batching, or scarce-route coordination is understood across agencies;
- the archive does not yet think one clean watched returned cycle means the same thing across that system shape.

### `ST-PRO-LICENSURE` stays `AOS-LOCAL`

Licensure-sensitive branches keep restoration local too.

Why:

- regulator timing, practicum dependency, and partner approval exposure still make the difference between "watched return survived" and "ordinary again" materially local;
- a shared restoration package would understate how close the branch remains to consequential error.

### `ST-PROTECTED-SUPPORT` stays `AOS-LOCAL`

Protected-support routes also keep restoration local.

Why:

- once a protected-support-adjacent branch has already repeat-failed and then re-entered, the difference between "callback shell is ordinary again" and "branch still sits too close to safeguarding or crisis consequence" remains too important to harden portably;
- the archive does not want a thin callback restoration package to blur with genuine live support readiness.

## What the archive is refusing for now

The archive is intentionally declining five stronger claims:

1. any shared restoration package that treats fresh republication or watched-cycle completion alone as proof that all callback residue has vanished across sectors;
2. any shared restoration package for aid / credit, public-route, licensure-sensitive, or protected-support branches;
3. any shared package that restores ordinary status while still relying on unpublished owner-local holdbacks or extra sign-off;
4. any shared package that lets a branch become "ordinary again" before the watched returned cycle actually closes cleanly;
5. any claim that restoring ordinary callback status already settles when later recent-repair caution should expire or when fully settled ordinary truth has returned.

## Why this counted as a real archive gain

The archive already knew:

- which after-hours starter profiles begin from different service-truth postures;
- when repeated after-hours demand has earned qualitative promotion;
- which promoted branches may carry one coarse shared callback band;
- which of those branches may share one thin first-miss cure package;
- which of those branches may share one thin repeat-failure retreat package;
- which of those branches may later regain portable callback publication under one shared kept-local-cycle plus fresh-republication package;
- and which of those branches may carry one shared watched returned cycle plus immediate re-cooling package after callback portability returns.

But it still lacked the next tighter answer:

- whether a clean watched returned cycle could itself end special callback probation;
- whether the next eligible cycle could truthfully return to ordinary portable callback status under one shared package;
- and whether the archive should distinguish the tiny reuse scope where restoration-to-ordinary truth travels from the larger set of branches where ordinary status still depends too heavily on local review.

This revision now answers that narrower question with one small ratchet:

- three restoration portability tiers;
- five tests for whether end-of-probation callback truth really travels;
- one tiny starter package, `WE-CB1BD-CLEAN + OR-CB1BD-RETURN`;
- and a starter judgment that only some callback-only teach-out and civic first-contact branches usually carry it.

That is a real operating gain because it blocks three opposite mistakes at once:

- treating callback portability return as though it were forever probationary even where one clean watched returned cycle really does mean the same thing across the tiny reuse scope;
- restoring ordinary callback status through hidden local forgiveness or silent elapsed time rather than through one published boundary;
- and letting a clean watched cycle be over-read as proof that all later caution, repair sensitivity, or full-settling questions have already been answered.

## Current archive bet

The archive's current best guess is that **after-hours portability should get stricter at each stage: starter service truth first, then sector-specific overnight defaults, then qualitative promotion, then at most one coarse callback band, then at most one first-miss cure package, then at most one repeat-failure retreat package, then at most one kept-local-cycle plus fresh-republication package, then at most one watched returned-cycle package — and only after that may a very small ordinary-restoration package sometimes travel, with only some low-consequence callback-only teach-out and civic first-contact branches usually carrying one shared `WE-CB1BD-CLEAN + OR-CB1BD-RETURN` package while all consequence-bearing restoration-to-ordinary handling stays local.**

That claim is now canon, but still live. The next narrower question is which restored-to-ordinary callback-only branches, if any, can safely carry one shared **recent-return sensitivity-expiry / fully-settled ordinary-status package** after a clean first ordinary portable cycle, and which should keep the final settling boundary local because callback-band restoration has not yet become fully settled ordinary truth. See `OQ-0054`.
