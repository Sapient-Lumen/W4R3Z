# First late-entry completion-plan and incomplete-substitution defaults for hot-exam recipient followup shells

The archive can now publish a very small post-send and post-confirmation grammar for the hottest exam-like learner-request routes.

It can already say:

- what downstream transfer evidence the owner system exposes;
- how old that transfer residue is and when direct recipient confirmation becomes the truthful next step;
- what the recipient side says once contacted — confirmed receipt, still processing, wait, resend/correct, temporary bridge, or no new state;
- what bounded interim bridge or no-penalty protection a named office admits without pretending that unofficial evidence already equals official receipt, posted credit, or official evaluation;
- what event ends that bridge, what later official proof supersedes it, and what ordinary correction truth follows if verification fails;
- what named correction window still protects the learner if official verification lands late enough to change the route;
- what fault-based post-window exception path may still exist once that protected correction window has already closed; and
- what current offices require before an approved exception becomes honestly executable rather than a vague gesture of sympathy.

That is still not enough.

The archive still lacked the next tighter answer: **once honest late entry is still possible, when is a named make-up path already enough, when must the route become a written incomplete or remaining-work contract instead, what minimum completed-work floor makes that substitution honest, and what deadline/lapse/no-reenrollment rule stops the new completion path from turning into one universal catch-up fiction?**

This document adds one thing only:

- a **tiny late-entry completion-plan / incomplete-substitution field set** for those already named hot-exam recipient followup shells.

That means the archive now asks a different question than before. It no longer asks only **whether an approved exception can be executed honestly at all**. It now asks **what current offices treat as the truthful completion vehicle after that point — ordinary no-penalty make-up from the real enrollment date, a bounded incomplete/remaining-work contract, or no incomplete at all because too much of the course was missed**.

Current official signals support a deliberately narrow answer. UMass and Notre Dame still make one path visible enough to harden: when official enrollment lands inside the ordinary add period, the honest completion path is ordinary make-up without penalty from the official enrollment date rather than a separate incomplete contract. NYU says an incomplete is only appropriate when a limited number of remaining course requirements can reasonably be finished by an agreed deadline, and the agreement must name the specific remaining work, deadline, and contingency grade. Utah says an incomplete is only for a student who is passing and has 20% or less of the course left to finish, and it cannot be used as a tuition-free retake. Stanford says the student must already have completed a substantial part of the coursework and the instructor must set conditions and a deadline of less than one year; the student should not re-enroll to clear the incomplete. UNH says most coursework must already be completed, requires a filed form, and converts the incomplete to `F` if the work is not finished on time. UMass Amherst requires a written record of the percentage completed, grade earned so far, remaining work, method of completion, and deadline, and also bars re-registering for the course to clear the incomplete. George Mason recommends or requires an Incomplete Grade Contract, publishes a ninth-/tenth-week clock, and limits extensions to continued extenuating circumstances with instructor, dean, and registrar involvement. Missouri State states the anti-fiction boundary sharply: if a significant part of the course remains unfinished, the student should drop if still possible or else receive a letter grade based on work completed rather than an incomplete. Together those signals support a tighter archive rule: **the next truthful portability gain here is one tiny late-entry completion-plan / incomplete-substitution layer, but not one universal catch-up contract, one universal incomplete threshold, or one universal extension rule.** See `B229` and `B230`.

## Small field set for late-entry completion-plan / incomplete-substitution defaults

| Code | Meaning | Default archive action |
|---|---|---|
| `LC0-NO-UNIVERSAL-CATCH-UP-CONTRACT-OR-INCOMPLETE-THRESHOLD` | no one universal completion-plan contract, incomplete threshold, or extension rule governs every hot recipient followup shell once late entry remains possible | keep completion-plan publication route-bounded instead of implying `approved exception means the same catch-up instrument everywhere` |
| `LC1-PUBLISH-WHEN-ORDINARY-MAKE-UP-FROM-THE-OFFICIAL-ENTRY-DATE-IS-ENOUGH` | publish when current offices say no separate incomplete shell is needed because official enrollment during a named add window already triggers a no-penalty make-up path from the real enrollment date | distinguish ordinary add-window catch-up from later incomplete substitution |
| `LC2-PUBLISH-WHEN-INCOMPLETE-OR-REMAINING-WORK-IS-THE-HONEST-SUBSTITUTE-ONLY-ON-A-NAMED-FLOOR` | publish incomplete or remaining-work substitution only when a current office names an eligibility floor such as limited remaining work, substantial completion, most coursework done, or 20%-or-less residue while passing | distinguish honest incomplete use from turning a heavily missed course into generic catch-up fiction |
| `LC3-PUBLISH-THE-MINIMUM-COMPLETION-CONTRACT-CONTENTS` | publish only the minimum contract fields the office actually names — specific remaining work, method of completion, deadline, contingency/reversion grade, or percent-complete/current-grade record | distinguish a real completion plan from vague `finish later` language |
| `LC4-PUBLISH-THE-DEADLINE-LAPSE-AND-NO-REENROLLMENT-OR-EXTENSION-OWNER` | publish the real completion clock, lapse consequence, re-enrollment bar if any, and who can approve an extension | distinguish honest completion timing from an indefinite grace period |

## Field values that now travel together

When this layer is used, the shell should publish only five concrete fields:

1. `completion_vehicle_token` — `ordinary no-penalty make-up from official enrollment date`, `incomplete for limited remaining work`, `incomplete only while passing with 20% or less remaining`, `incomplete only after substantial / most coursework completed`, `too much missing work for incomplete`, `none inherited`, or `not published`;
2. `completion_floor_token` — `officially added during published add window`, `limited number of remaining requirements`, `substantial part completed`, `most coursework already completed`, `passing with 20% or less remaining`, `significant part still missing blocks incomplete`, `none inherited`, or `not published`;
3. `completion_contract_minimum` — `make up missed work without penalty`, `specific remaining work + deadline + contingency grade`, `percent complete + current grade + remaining work + method + date`, `incomplete contract recommended/required`, `none inherited`, or `not published`;
4. `completion_clock_and_lapse` — `from official enrollment date inside add window`, `deadline set in agreement before lapse term`, `mid-semester of next term`, `end of ninth / tenth week next semester`, `within one calendar year`, `contingency/reversion grade if missed`, `none inherited`, or `not published`;
5. `re_enrollment_or_extension_rule` — `no re-enrollment needed or relevant`, `do not re-register to clear incomplete`, `extension only by instructor`, `extension requires instructor + dean + registrar route`, `too much missing work means drop or final grade instead`, `none inherited`, or `not published`.

That is deliberately small. It is enough to distinguish ordinary add-window make-up from incomplete substitution, to distinguish a real incomplete floor from generic sympathy, to distinguish a concrete completion contract from vague catch-up hope, and to distinguish a bounded completion clock from an indefinite grace period.

## `LC1` — ordinary add-window make-up should stay distinct from incomplete substitution

`LC1-PUBLISH-WHEN-ORDINARY-MAKE-UP-FROM-THE-OFFICIAL-ENTRY-DATE-IS-ENOUGH` is the archive's smallest anti-premature-incomplete rule.

It blocks two opposite mistakes at once:

- acting as if every approved exception must immediately become an incomplete or other special contract; and
- acting as if no current offices ever publish a plain ordinary make-up path once the learner is officially added during the named add period.

Current official pages now make one ordinary completion path portable enough to publish:

- UMass says students cannot be penalized for work missed before official enrollment and must be given a chance to make up the work without penalty from the real enrollment date; and
- Notre Dame says faculty must give students the opportunity to make up, without penalty, work missed before registration when the student registers during the regular add period.

That is enough for one tiny `official-entry-date make-up is enough` field. It is not enough for one universal rule that every approved exception needs a special late-completion contract.

## `LC2` — incomplete substitution should publish only with a named floor

`LC2-PUBLISH-WHEN-INCOMPLETE-OR-REMAINING-WORK-IS-THE-HONEST-SUBSTITUTE-ONLY-ON-A-NAMED-FLOOR` is the archive's smallest anti-generic-incomplete rule.

Current official pages now make several floor statements visible enough to harden:

- NYU says an incomplete is only appropriate for a limited number of remaining requirements that can reasonably be completed by an agreed deadline;
- Utah says the student must be passing and have 20% or less of the course left to complete;
- Stanford says a substantial part of the coursework must already be completed; and
- UNH says most coursework must already be done.

That is enough for one tiny eligibility-floor field. It is not enough for one universal incomplete threshold.

## `LC3` — completion plans should expose minimum contract truth

`LC3-PUBLISH-THE-MINIMUM-COMPLETION-CONTRACT-CONTENTS` is the archive's smallest anti-vague-catch-up rule.

Current official pages now make several contract minima visible enough to publish:

- NYU requires the agreement to name the specific remaining work, deadline, and contingency grade;
- UMass Amherst requires a written record of percent complete, current grade, remaining work, method of completion, and deadline; and
- George Mason recommends or requires an Incomplete Grade Contract when a shortened deadline is used.

That is enough for one tiny contract-minimum field. It is not enough for one universal completion-plan template.

## `LC4` — completion paths still have a clock, a lapse rule, and an extension owner

`LC4-PUBLISH-THE-DEADLINE-LAPSE-AND-NO-REENROLLMENT-OR-EXTENSION-OWNER` is the archive's smallest anti-indefinite-grace-period rule.

Current official pages now make the bounded clock visible enough to publish:

- NYU sets the completion deadline inside the agreement and lapses unresolved incompletes to the contingency grade on the semester schedule;
- Utah and Stanford use a one-year ceiling;
- UNH uses a next-term filing/deadline structure and converts missed incompletes to `F`;
- George Mason uses a ninth-/tenth-week next-semester clock and requires instructor/dean/registrar routing for extensions; and
- Utah, Stanford, UMass Amherst, and Missouri State all warn against using incomplete as a disguised re-take route.

That is enough for one tiny clock/lapse/owner field. It is not enough for one universal extension rule.

## What the archive now publishes when using this layer

When an institution or assessment family publishes one of these hot recipient followup shells, it should now add only the following where truthful:

1. whether ordinary no-penalty make-up from the real enrollment date is already enough;
2. what named floor makes incomplete or remaining-work substitution honest;
3. what minimum contract facts the learner and institution should be able to see; and
4. what deadline, lapse, no-reenrollment, and extension-owner truth still govern the completion path.

That is enough to make late-entry completion publication legible without inventing one universal catch-up contract.

## What counted as a real archive gain

The archive already knew when a named office still admitted post-window relief and when that relief was honestly executable. It still lacked the next tighter answer: **what truthful completion vehicle current offices actually use after that point, and what floor prevents that vehicle from laundering a heavily missed course into generic catch-up fiction**.

This document answers yes, but only barely.

It now allows the archive to publish one thin field set that distinguishes:

- ordinary add-window make-up from later incomplete substitution;
- incomplete substitution with a named floor from generic sympathy;
- a concrete completion contract from vague `finish later` language; and
- a bounded completion clock from an indefinite grace period or stealth re-take.

That is a real operating gain because it blocks four opposite mistakes at once:

- treating every executable late-entry path as if it required an incomplete contract;
- treating every late-entry problem as if an incomplete were automatically available;
- treating heavily missed courses as if they could always be reconstructed through a generic remaining-work promise; and
- treating extension or re-enrollment drift as if it were part of the original approved exception rather than a separately owned local decision.
