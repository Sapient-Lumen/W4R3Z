# Portable recent-return-sensitivity expiry and fully settled ordinary-status defaults for restored ordinary after-hours service-truth profiles

This document closes the archive's next after-hours governance gap: **once a callback-only after-hours branch has already repeat-retreated, regained portable callback publication under one shared local-repair / fresh-republication package, survived its watched returned cycle, restored ordinary portable callback status, and then completed its first restored ordinary portable cycle cleanly, can that clean first ordinary cycle itself carry one shared recent-return-sensitivity-expiry / fully settled ordinary-status package, or should the final settling boundary still remain local even after the archive has already allowed callback portability to become ordinary again?**

The archive's answer is narrower again:

> only branches whose **final recent-return settling truth** remains stable across the reuse scope should carry one shared recent-return-sensitivity-expiry / fully settled ordinary-status package. In the starter canon, only some low-consequence callback-only `ST-HE-TEACHOUT` and `ST-LIB-CIVIC-FIRST` branches usually carry one shared final-settling package; aid / credit, public-route, licensure-sensitive, and protected-support branches should keep that last settling boundary local.

The point is to avoid three opposite errors at once:

- **premature full settlement** — a service treats one clean restored ordinary callback cycle as automatic proof that recent-return caution has expired everywhere, even where the meaning of “fully settled ordinary again” still depends on owner-local queue review, consequence residue, or renewed scarcity checks;
- **shadow-settling drift** — a service publishes one restoration-to-ordinary package but then clears or preserves its residual caution only through unpublished owner-local judgment, hidden callback review, or opaque confidence thresholds;
- **permanent recent-return stigma** — a callback-only branch whose clean first ordinary portable cycle really does end recent-return sensitivity in the same way across the tiny reuse scope never earns one shared final-settling package and therefore has to restate the same already-proven caution locally forever.

Current public signals support this thinner move. HLC's current teach-out policy still treats communications, applicability periods, credit treatment, fees, and records as governed student-facing commitments. OIA's current good-practice materials still expect providers to tell students what they must do to preserve position while matters remain live and to issue Completion of Procedures Letters once internal processes actually end. Federal Student Aid still says a school's aid offer is the best source of truth rather than earlier estimates. ALA still frames civic/library access as low-barrier public access infrastructure rather than downstream decision ownership. SAMHSA still treats 988 as a genuinely live 24/7 crisis route. Together those signals support a small archive rule: **a clean first ordinary portable callback cycle may sometimes end special recent-return caution, but only inside a very small callback-only reuse scope and never by elapsed time alone or hidden owner forgiveness.** See `B193`.

## Three final-settling portability tiers

The archive now distinguishes three recent-return final-settling portability tiers.

| Tier | Meaning | What travels | What stays local |
|---|---|---|---|
| `AFS-BOTH` | the restored ordinary callback branch carries one shared recent-return-sensitivity-expiry floor and one shared fully settled ordinary-status rule | the minimum fact that a clean first restored ordinary portable cycle ends special recent-return sensitivity and the minimum fact that the next eligible cycle is now fully settled ordinary portable status | any stricter local sign-off, any extra local checkpoint, and any stronger local warning, disclosure, or challenge route |
| `AFS-EXPIRY` | the branch carries only one shared recent-return-sensitivity-expiry floor | the minimum fact that a clean first ordinary portable cycle can end the special recent-return-sensitive state | the actual rule for when the path is treated as fully settled ordinary again and any owner-local residual caution |
| `AFS-LOCAL` | the branch carries no shared final-settling package | only the earlier promotion, quantitative, miss, retreat, re-entry, watched-cycle, and restoration tiers | both recent-return-sensitivity expiry and fully settled ordinary-status restoration |

The archive is deliberately asymmetric again:

> final-settling portability is harder to earn than restoration-to-ordinary portability. A branch can carry one shared `WE-CB1BD-CLEAN + OR-CB1BD-RETURN` package while the truth about becoming **fully settled ordinary again** still remains owner-local.

## Five tests for whether final-settling callback truth really travels

A restored ordinary callback-only after-hours branch may harden above `AFS-LOCAL` only when all five tests hold.

1. **same-clean-first-ordinary meaning test** — a clean first restored ordinary portable cycle really means the same thing across the reuse scope rather than one owner treating it as full closure while another treats it only as provisional evidence pending hidden scarcity or queue review.
2. **same-expiry boundary test** — the exact point at which special recent-return sensitivity expires can be described in one reusable way rather than depending on local callback closure rituals, owner-specific caution residue, or quiet queue-health review.
3. **same-fully-settled meaning test** — saying that the next eligible cycle is now fully settled ordinary again means the same thing across the reuse scope: no special recent-return caution remains, and later failures are now handled by the ordinary promoted / miss / retreat canon rather than by hidden fast-collapse logic.
4. **no-shadow-settling test** — the shared settling package does not conceal owner-specific shadow review, unpublished confidence checks, or hidden caution holdbacks that still materially determine whether fully settled ordinary status has actually returned.
5. **same-late-relapse inheritance test** — once fully settled ordinary status is restored, the callback path really inherits the same ordinary promoted after-hours canon across the proposed scope rather than diverging immediately through owner-specific “recently repaired” exceptions or unpublished quick-collapse rules.

Failing the second, third, fourth, or fifth test keeps the branch at `AFS-LOCAL`. Failing only the third may eventually point to `AFS-EXPIRY`, but the starter canon does not yet use that middle tier.

## The starter recent-return-sensitivity-expiry / fully settled package

The archive now names one shared recent-return-sensitivity-expiry floor and one shared fully settled ordinary-status rule.

| Code | Meaning |
|---|---|
| `RRX-CB1BD-CLEAN-1ORDINARY` | a **clean first restored ordinary portable callback cycle** ends the special post-restoration recent-return sensitivity only if that cycle closes without a missed callback against the ordinary portable band, fresh owner-window inflation, new queue / rights / protected-route consequence, or unresolved owner-scarcity relapse |
| `FS-CB1BD-SETTLED` | once `RRX-CB1BD-CLEAN-1ORDINARY` is satisfied, the next eligible cycle returns to **fully settled ordinary portable callback status** rather than carrying any special recent-return caution package, while still inheriting the ordinary callback-band, missed-window, retreat, and future re-entry canon |

The archive does **not** yet create a richer settling ladder. The starter canon is deliberately small:

- no restored ordinary callback-only after-hours branch currently becomes fully settled by elapsed time alone;
- no restored ordinary callback-only after-hours branch currently carries one shared “two clean ordinary portable cycles before settlement” rule;
- where the archive refuses a shared final-settling package, services must still publish a **local** rule for when post-restoration recent-return caution truly clears, or say plainly that fully settled ordinary status remains owner-local even after a clean first ordinary portable cycle.

## The archive's starter final-settling answers

### Restored ordinary callback-only `ST-HE-TEACHOUT` usually hardens as `AFS-BOTH` with `RRX-CB1BD-CLEAN-1ORDINARY + FS-CB1BD-SETTLED`

Restored ordinary callback-only teach-out branches may usually carry **both** one shared recent-return-sensitivity-expiry floor and one shared fully settled ordinary-status rule across the thin callback-only reuse scope.

Why the archive allows this:

- the meaning of a clean first restored ordinary callback cycle is usually stable enough here: the branch already cooled, repaired locally, republished explicitly, survived its watched returned cycle, restored ordinary portable callback status, and then completed one ordinary callback cycle without new miss, inflation, or rights-bearing drift;
- the minimal settling boundary is usually stable too: once that first ordinary callback cycle closes cleanly, the portable story no longer needs a special recent-return overlay and can fall back to the ordinary portable callback canon honestly;
- teach-out callback publication still sits inside governed student-protection communication rather than casual promotional support wording, which makes “fully settled ordinary again” easier to specify without hiding downstream owner-local discretion.

The starter default is therefore:

> when callback-only `ST-HE-TEACHOUT` has already earned `OV1`, `AQT-CALLBACK`, `ABP-BOTH`, `RFP-BOTH`, `ARP-BOTH`, `RWP-BOTH`, and `AOS-BOTH`, it may usually also inherit `AFS-BOTH` with `RRX-CB1BD-CLEAN-1ORDINARY + FS-CB1BD-SETTLED`.

What this means in practice:

1. a clean first restored ordinary callback cycle ends the special recent-return caution package;
2. the next eligible callback cycle is treated as fully settled ordinary portable callback status rather than as “ordinary, but still recently repaired”;
3. any later miss or callback drift is handled through the ordinary promoted callback-band, cure, retreat, and re-entry canon rather than through a permanent shadow recent-return layer.

What still collapses `AFS-BOTH` immediately:

- any missed callback, owner-window inflation, queue/rights/protected-route consequence, or unresolved owner-scarcity relapse during the caution-marked first ordinary cycle;
- any attempt to treat the path as fully settled before that first ordinary cycle has actually closed cleanly;
- any effort to smuggle owner-specific shadow caution or unpublished fast-collapse logic underneath the shared settling package.

### Restored ordinary callback-only `ST-LIB-CIVIC-FIRST` usually hardens as `AFS-BOTH` with `RRX-CB1BD-CLEAN-1ORDINARY + FS-CB1BD-SETTLED`

Restored ordinary callback-only civic/library first-contact branches may also usually carry the same tiny final-settling package.

Why:

- the branch remains low-consequence, callback-only, and non-owner for downstream consequential decisions;
- a clean first restored ordinary callback cycle usually means the same thing across the tiny reuse scope: the civic branch is back to ordinary low-barrier first-contact callback publication without hidden queue-rights residue;
- once the first ordinary callback cycle closes cleanly, keeping a separate recent-return caution layer would often add no truthful public distinction.

### Restored ordinary callback-only `ST-HE-AID-CREDIT` stays `AFS-LOCAL`

Aid / credit callback branches should keep recent-return-sensitivity expiry and fully settled ordinary-status boundaries local.

Why:

- even after ordinary callback status returns, the meaning of “recent-return caution has truly cleared” still depends too much on school-specific aid timing, credit treatment, document dependency, and queue effects;
- a shared fully settled rule would therefore overstate how comparable the final settling boundary really is across aid / credit regimes.

### Restored ordinary callback-only `ST-WF-PUBLIC-ROUTE` stays `AFS-LOCAL`

Public-route routing branches also keep final settling local.

Why:

- route inventory, partner capacity, and downstream scarcity remain too variable even after callback portability has already been restored;
- the point at which recent-return caution truly disappears therefore varies too much to travel honestly.

### Restored ordinary callback-only `ST-PRO-LICENSURE` stays `AFS-LOCAL`

Licensure-sensitive callback branches remain fully local after a clean first ordinary portable cycle.

Why:

- licensure windows, regulator dependence, and consequence-bearing timing still vary too much;
- a shared final-settling package would risk hiding meaningful differences in when recent-return residue is considered fully cleared.

### Restored ordinary callback-only `ST-PROTECTED-SUPPORT` stays `AFS-LOCAL`

Protected-support branches also remain fully local after a clean first ordinary cycle.

Why:

- these routes remain too tied to genuinely live support separation, protected evidence handling, or urgent transfer semantics for one shared final-settling callback package to stay truthful.

## What the archive is refusing for now

The archive is intentionally declining four stronger claims:

1. any shared final-settling package that says a clean first restored ordinary callback cycle always clears recent-return sensitivity across all after-hours callback branches;
2. any shared final-settling package for aid / credit, public-route, licensure-sensitive, or protected-support callback branches;
3. any shared package that lets a callback branch appear fully settled while unpublished owner-local caution still materially governs the next cycle;
4. any claim that fully settled ordinary callback status still needs a second permanent “recently repaired” layer after `AFS-BOTH` is earned.

## Why this counted as a real archive gain

The archive already knew which after-hours branches can begin from different honest overnight postures, when repeated overnight use can promote into a published callback-slot promise, which promoted branches can carry one coarse portable callback band, which of those can share one missed-window cure package, which can share one repeat-failure retreat package, which can later regain portable callback publication under one shared re-entry package, which first returned cycle can carry one shared watched package, and which clean watched returned cycle can restore ordinary portable callback status. But it still lacked the next tighter answer:

- whether a clean first restored ordinary callback cycle can end recent-return sensitivity in one shared way at all;
- and whether the archive should distinguish branches where that final settling truth travels from branches where it still depends too heavily on local queue, scarcity, rights, or consequence residue.

This revision now answers that narrower question with one small ratchet:

- three final-settling portability tiers;
- five tests for whether final-settling callback truth really travels;
- one tiny starter package, `RRX-CB1BD-CLEAN-1ORDINARY + FS-CB1BD-SETTLED`;
- and a starter judgment that only low-consequence callback-only teach-out and civic first-contact branches usually carry it.

That is a real operating gain because it blocks three opposite mistakes at once:

- treating a clean first restored ordinary callback cycle as automatic full settlement for every after-hours callback branch;
- making low-consequence callback-only teach-out and civic first-contact branches permanently residually local even when their final settling boundary is actually stable enough to travel;
- and using a restoration-to-ordinary portable story to conceal shadow-settling or unpublished residue review at the exact point when fully settled ordinary status is being claimed.

## Current archive bet

The archive's current best guess is that **after-hours callback portability should become harder at each stage: qualitative promotion travels first, then at most one coarse callback-slot band, then at most one thin first-miss cure package, then at most one thin repeat-failure retreat package, then at most one shared repair-to-portability package, then at most one watched returned-cycle package, then at most one restoration-to-ordinary package, and only after that may a very small final-settling package sometimes travel — with only low-consequence callback-only teach-out and civic first-contact branches usually carrying one shared `RRX-CB1BD-CLEAN-1ORDINARY + FS-CB1BD-SETTLED` package while aid / credit, public-route, licensure-sensitive, and protected-support branches keep final settling local.**

That claim is now canon, but no longer stands alone: the archive now answers the next question too in [`late-relapse-and-ordinary-reset-defaults-for-fully-settled-after-hours-service-truth-profiles.md`](late-relapse-and-ordinary-reset-defaults-for-fully-settled-after-hours-service-truth-profiles.md), which refuses any distinct post-settlement relapse layer once a callback path has truthfully rejoined fully settled ordinary portable status.
