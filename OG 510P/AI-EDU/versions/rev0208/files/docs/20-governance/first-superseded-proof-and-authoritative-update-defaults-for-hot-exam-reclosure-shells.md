# First superseded-proof and authoritative-update defaults for hot-exam reclosure shells

This document closes the archive's next narrower governance gap after **proof-precedence and reclosure defaults**.

Three overclaims matter here:

- **coequal stale-proof display** — once ordinary closure truth has returned, the archive keeps earlier non-submitted statuses, earlier room-count mismatch notes, or earlier partial-closure statements on screen as if they were still parallel live truth;
- **history-in-every-shell fantasy** — the archive treats every ordinary learner-facing closure update as if it must carry a full audit trail or universal incident log; and
- **authoritative-update silence** — the archive fixes the route internally but leaves no clear current owner-of-record update, so learners and staff are forced to infer which proof is now operative.

Current official signals support a tighter answer. Bluebook's current in-school testing page says coordinators should check Bluebook if Test Day Toolkit seems stale, because Toolkit status can be out of date; if answers were submitted, the exam appears on the **Past** tab with **“Your answers have been submitted!”**; and for unresolved AP submissions, schools should protect the original device and tell students to sign back in and click **Submit Answers** rather than using device swap. Bluebook's current AP answer-resolution page repeats that ordinary digital closure is re-established on the same device when the student reaches the **Congratulations** page after submit or sees the exam on **Past** with the submitted message. Current hybrid digital AP pages say the scored artifact is the paper free-response booklet, that students place an **AP ID label** on that booklet, and that schools receive and return those booklets as secure exam materials; the current AP key-dates page then fixes **June 1, 2026** as the deadline by which exam materials must be received by the AP Program. Current AP Research and AP Capstone pages keep the portfolio route's update legs explicit again: students submit the paper as final in the AP Digital Portfolio by **April 30, 2026, 11:59 p.m. ET**; once submitted as final, students cannot change the file unless the teacher sends it back; AP coordinators check final-submission status and teacher-scoring status in the AP Digital Portfolio; teachers submit presentation scores and checkpoint affirmations by **May 10, 2026, 11:59 p.m. ET**; and final student work submitted by deadline is automatically sent onward for scoring so long as an exam was ordered. Together those signals support a narrower archive rule: **the hot-exam reclosure shells may now share one tiny superseded-proof / authoritative-update publication layer, but they still do not justify one universal audit log, one universal always-visible stale-proof panel, or one universal retention/display rule for every earlier status artifact.** See `B213`.

This document adds one thing only:

- a **tiny superseded-proof / authoritative-update publication layer** for those already named reclosure shells.

That means the archive now asks a different question than before. It no longer asks only **which signal governs and what re-closes the shell**. It now asks **what the ordinary shell should publish once closure truth has returned, which earlier proof may remain visible only as superseded, and when stale proof should disappear from the ordinary shell altogether rather than linger beside current truth**.

## Small grammar for superseded-proof / authoritative-update defaults

| Code | Meaning | Default archive action |
|---|---|---|
| `AU0-NO-UNIVERSAL-AUDIT-LOG` | no one universal history panel or universal stale-proof log travels across these hot shells | keep retained incident history route-local or upstream rather than forcing every ordinary shell to display it |
| `AU1-PUBLISH-CURRENT-OWNER-OF-RECORD-UPDATE` | when closure truth returns, the ordinary shell should publish the current owner-of-record state as the live status | replace ambiguous mismatch-era display with one current authoritative update |
| `AU2-LABEL-SUPERSEDED-PROOF-IF-RETAINED` | if earlier proof must remain visible, it must be visibly marked superseded rather than left as coequal live truth | retain stale proof only with a superseded label, not as a parallel current state |
| `AU3-WITHDRAW-SUPERSEDED-PROOF-WHEN-NO-LIVE-ACTION-DEPENDS` | stale proof should disappear from the ordinary shell once no current action, appeal, or review depends on it | do not keep old nonmatch or partial-closure states on the main learner-facing shell by default |
| `AU4-KEEP-ROUTE-SPECIFIC-HISTORY-OUTSIDE-ORDINARY-SHELL` | route-specific deeper history may remain in coordinator, secure-return, or portfolio systems, but not as the ordinary public shell | separate current truth publication from deeper incident history |

## `AU1` — the ordinary shell should publish current authoritative state, not unresolved history residue

`AU1-PUBLISH-CURRENT-OWNER-OF-RECORD-UPDATE` is the archive's smallest anti-residue rule.

Its point is not that every route has the same current status words. Its point is that once ordinary closure truth has returned, the ordinary shell should again show the current owner-of-record state:

- a same-device Bluebook submitted state for digital AP submission;
- an identified AP-ID-linked booklet back in counted secure custody / return-for-scoring truth for hybrid digital routes; or
- the currently governing AP Digital Portfolio / teacher-score / checkpoint state for portfolio-plus-local-record continuity.

So `AU1` restores one current truthful shell without pretending deeper incident history never existed.

## `AU2` — retained stale proof must be visibly superseded, not quietly coequal

`AU2-LABEL-SUPERSEDED-PROOF-IF-RETAINED` is the archive's smallest anti-double-truth rule.

If a stale proof item still needs to remain visible for a time, the shell must label it as superseded rather than leaving it to compete with the current update:

- a Toolkit snapshot that no longer matches current Bluebook truth;
- an earlier booklet discrepancy note after the identified booklet has re-entered ordinary custody; or
- an earlier partial-closure or returned-for-correction portfolio status after the governing leg has moved forward.

So `AU2` does not require all earlier proof to vanish instantly. It requires the archive to stop presenting it as a parallel current state.

## `AU3` — stale proof should disappear from the ordinary shell when nothing live depends on it

`AU3-WITHDRAW-SUPERSEDED-PROOF-WHEN-NO-LIVE-ACTION-DEPENDS` is deliberately modest.

It prevents the opposite excess from `AU2`: once no current action, appeal, or live review depends on the stale item, the ordinary shell should stop showing it.

That means:

- no permanent learner-facing non-submitted badge beside a reclosed submitted Bluebook state;
- no permanent public mismatch banner beside an ordinary identified booklet custody state; and
- no permanent ordinary-shell partial-closure badge once the portfolio-side official legs have actually closed.

So `AU3` keeps ordinary shells current rather than turning them into mini incident archives.

## `AU4` — deeper history may exist, but it belongs outside the ordinary shell

`AU4-KEEP-ROUTE-SPECIFIC-HISTORY-OUTSIDE-ORDINARY-SHELL` is the archive's smallest anti-overpublication rule.

Some deeper history may still matter:

- coordinators may still need incident handling records for unresolved or recently resolved digital AP submission problems;
- secure-return chains may still keep booklet-handling history; and
- AP Digital Portfolio / local course systems may still keep return, correction, scoring, or checkpoint history.

But the archive now draws the boundary more cleanly: those route-specific historical materials may remain in the route's deeper system of record or support review on request; they do **not** automatically belong on the ordinary closure shell once current truth is restored.

## What the archive now publishes when using this layer

When an institution or assessment family publishes one of the hot exam reclosure shells, it should now add only the following where truthful:

1. the shell-specific notice minimum from `RC1-RC3`;
2. the applicable `SV`, `ER`, `HF`, `MR`, and `PR` fields, if any;
3. the current `AU1` owner-of-record update once ordinary closure truth returns;
4. any `AU2` superseded label for stale proof still temporarily visible; and
5. any `AU3` / `AU4` rule that removes stale proof from the ordinary shell while leaving deeper history route-local or upstream.

That is enough to make post-reclosure publication legible without inventing one universal audit log.

## What counted as a real archive gain

The archive already knew how to reopen a shell, how to decide which signal temporarily governs, and what token actually re-closes the shell. It still lacked the next tighter answer: **what should remain visible after truthful closure returns, what earlier proof may survive only as superseded, and when stale proof should disappear from the ordinary shell altogether.**

This document answers yes, but only barely.

It now allows the archive to publish a small shared layer for:

- a current authoritative owner-of-record update after reclosure;
- explicit superseded labels for stale proof that must remain visible briefly;
- withdrawal of stale proof from the ordinary shell once no live action depends on it; and
- separation between ordinary current-shell publication and deeper route-specific history.

That is a real operating gain because it blocks four opposite mistakes at once:

- leaving mismatch-era proof on screen as if it were still coequal live truth;
- forcing every ordinary shell to become a miniature audit log;
- silently fixing the route without a clear current authoritative update; and
- overpublishing stale incident residue long after ordinary closure truth has returned.
