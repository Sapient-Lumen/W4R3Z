# First post-deconflict relapse and route-pair memory defaults for hot-exam recipient followup shells

The archive can now publish one still smaller layer for the hottest exam-like learner-request routes.

It can already say:

- when a revived or replacement route first activates and exposes route-choice conflict;
- when that same conflict repeats and crosses a named stability threshold;
- when the threshold opens bounded deconflict work, owner reconciliation, route redesign, route split, protected-route handling, recipient confirmation, retired-route posture, or no-active-route residue; and
- how that operation publishes run-state, affected scope, owner, current proof, learner-safe action, exit disposition, minimization, and reopen triggers.

That is still not enough.

An exited deconflict operation can leave behind a fragile truth. It might have restored ordinary activation. It might have reconciled the route pair. It might have retained a route split or dual-route recognition. It might have handed a route pair to redesign. It might have retired the revived route again. It might have become no-active-route residue. Or it might have closed because current proof showed that the apparent conflict was only ordinary search, cache, portal, archive, or clock lag.

Later, a learner may again see two official-looking paths. A recipient portal may again accept the old route. A search or archive copy may reappear. The replacement route may change a prerequisite. A protected route may publish a different proof instruction. The old deconflict proof may age. The operation's memory may have been minimized, and the shell may need to know whether it can recall that memory without publishing a permanent dossier.

This document adds one thing only:

- a **tiny post-deconflict relapse / route-pair memory field set** for hot-exam recipient followup shells after `YO0-YO4` has exited, minimized, split, handed back, redesigned, retired, or become residue, but before the archive treats a later recurrence as a fresh first-cycle conflict, a repeat-conflict threshold, a reopened deconflict operation, a redesign failure, or ordinary lag.

That means the archive now asks a narrower question than before. It no longer asks only **how a route-stability operation runs and exits**. It now asks **what happens after exit if the same route pair or affected surface relapses, if old proof has aged, if minimized memory must be recalled, or if a learner again sees two official-looking paths — without making every recurrence an automatic re-watch, permanent route-pair stigma, duplicate filing duty, or total fresh-start amnesia**.

Current official signals support a deliberately narrow answer. Google Search Console's Removals tool exposes property-owner, exact-URL, current/expired-history, temporary-removal, cancellation, about-six-month, Google-Search-only, and source-side-permanent-method boundaries rather than a durable all-surface route-pair certificate. Google's Refresh Outdated Content route is exact page/image URL, changed/gone-content, queue/status, and 180-day-expiry based rather than a standing relapse monitor. Google's personal-content routes keep Search removal, source-page removal, screenshot proof, notifications, new-result handling, and sensitive proof separate. WiscWeb separates local WiscWeb source edits, emergency edits, primary-contact follow-up, campus-search / lookahead ownership, redirection, caching, and major-search-engine non-control. Princeton separates local deletion, document/media cleanup, access control, cache behavior, Google/Bing/custom-search handling, and Wayback persistence. Rowan separates CMS ownership, Web Services support, Siteimprove/accessibility monitoring, contributor training, content-audit/redesign work, support tickets, and accommodation routing. Internet Archive asks for URL, time-period, control-period, and review context before exclusion. Bing distinguishes temporary block, up-to-90-day expiry, cached/outdated-content handling, exact URL submission, extension or permanent-removal prerequisites, and source-side methods such as 404/410 or noindex. Together those signals support a tighter archive rule: **the next truthful portability gain here is one tiny memory-and-relapse layer for relapse materiality, prior exit scope, recall authority, current proof age, learner-safe action, disposition, reminimization, and reopen triggers — but not one automatic re-watch, one public route-pair memory vault, one duplicate-filing duty, one all-engine replacement-failure certificate, or one no-memory reset.** See `B263`.

## Small field set for post-deconflict relapse and route-pair memory

| Code | Meaning | Default archive action |
|---|---|---|
| `YN0-NO-AUTOMATIC-REWATCH-PERMANENT-ROUTE-PAIR-STIGMA-DUPLICATE-FILING-OR-FRESH-START-AMNESIA` | a later recurrence after deconflict exit can matter, but it does not automatically reopen watch, publish stigma, force duplicate filing, or erase prior memory | require a current relapse signal, prior exit state, affected scope, recall authority, current proof age, and learner action-now truth before the shell widens beyond ordinary post-exit publication |
| `YN1-PUBLISH-RELAPSE-MATERIALITY-PRIOR-EXIT-AND-ROUTE-PAIR-SCOPE` | the shell must say whether the later event is the same route-pair problem, a new surface, or ordinary lag | publish the current relapse signal, the prior `YO0-YO4` exit disposition, affected route pair or surface, and why the event is material or non-material |
| `YN2-RECALL-MINIMIZED-DECONFLICT-MEMORY-ONLY-FOR-CURRENT-NAMED-NEED` | old deconflict proof can be used as scoped memory, not as a public dossier or automatic fault history | recall only the minimum prior proof needed for a current owner, recipient, protected route, appeal, record, redesign, or route-choice decision; keep sensitive proof local-only or redacted |
| `YN3-PUBLISH-CURRENT-PROOF-AGE-OWNER-AND-LEARNER-SAFE-ACTION` | relapse handling depends on current proof, not stale screenshots or old operation closure alone | publish whether proof is current, aged, mismatched, source-only, search-only, archive-only, owner-confirmed, recipient-confirmed, protected/local-only, unresolved, or insufficient; publish no-action, one-safe-route, dual-route-recognition, longer-window, wait, or owner-only action accordingly |
| `YN4-PUBLISH-POST-RELAPSE-DISPOSITION-REMINIMIZATION-AND-REOPEN-TRIGGERS` | a relapse should end, split, escalate, reopen, or minimize on named facts instead of lingering as route-pair history | publish fresh first-cycle handling, repeat-conflict threshold, reopened deconflict operation, redesign handoff, route split, retired-route residue, no-active-route residue, ordinary lag, non-material close, reminimized memory, or reopen only on material new route, owner, proof, clock, recipient, protected-route, search, archive, or official-record facts |

## Field values that now travel together

When this layer is used, the shell should publish only six concrete fields:

1. `post_deconflict_relapse_signal_token` — `none`, `same route pair reappeared`, `revived route reappeared`, `replacement route changed`, `recipient portal split`, `protected route conflict`, `official-record conflict`, `source page reappeared`, `Google result reappeared`, `Bing or partner-search result reappeared`, `custom search reappeared`, `image result reappeared`, `archive or mirror reappeared`, `proof object aged`, `clock contradiction`, `owner silence after exit`, `ordinary lag only`, `unrelated new path`, `none inherited`, or `not published`;
2. `prior_deconflict_exit_and_scope_token` — `ordinary activation restored`, `route pair reconciled`, `replacement route controlled`, `revived route controlled`, `dual-route recognition retained`, `route split retained`, `protected route retained`, `recipient path controlled`, `route redesign handoff`, `retired-route residue`, `no-active-route residue`, `ordinary lag only`, `operation closed without learner action`, `prior exit not found`, `none inherited`, or `not published`;
3. `deconflict_memory_recall_token` — `no recall needed`, `current owner recall`, `successor owner recall`, `recipient-of-record recall`, `protected owner recall`, `appeal or complaint route recall`, `official-record owner recall`, `redacted public pointer`, `local-only proof recall`, `aggregate memory only`, `screenshot-only not enough`, `expired status row not enough`, `stale proof not enough`, `no authority to recall`, `none inherited`, or `not published`;
4. `current_relapse_proof_and_age_token` — `current owner proof`, `current reciprocal proof`, `current recipient proof`, `current source proof`, `current search status`, `current archive status`, `current protected proof local-only`, `proof aged but usable`, `proof aged and insufficient`, `proof mismatched`, `proof partial`, `proof expired`, `proof disappeared`, `proof contradicted`, `proof unavailable`, `none inherited`, or `not published`;
5. `learner_safe_action_after_relapse_token` — `none current`, `information-only notice`, `wait for owner confirmation`, `use replacement route`, `use revived route`, `submit once with dual-route recognition`, `do not duplicate filing`, `use more protective route until resolved`, `use longer current window until resolved`, `protected local-only submission`, `manual local support only`, `owner-only action`, `formal appeal route only`, `none inherited`, or `not published`;
6. `post_relapse_disposition_and_memory_token` — `fresh first-cycle conflict`, `repeat-conflict threshold candidate`, `reopen deconflict operation`, `redesign handoff`, `route split retained`, `dual-route recognition retained`, `replacement controls again`, `revived route controls again`, `retired-route residue`, `no-active-route residue`, `ordinary lag only`, `non-material close`, `reminimized memory`, `local-only memory retained`, `reopen only on material new fact`, `none inherited`, or `not published`.

## Minimal publication sentence

A learner-facing or owner-facing shell can stay compact:

> This route pair was previously deconflicted as `[prior_deconflict_exit_and_scope_token]`. The current signal is `[post_deconflict_relapse_signal_token]`. Prior memory is `[deconflict_memory_recall_token]`; current proof is `[current_relapse_proof_and_age_token]`. Learner action now is `[learner_safe_action_after_relapse_token]`. Current disposition is `[post_relapse_disposition_and_memory_token]`.

If a public notice would expose protected, privacy-sensitive, accommodation, appeal, security, or record-controlled proof, publish only the owner, action-now truth, and a redacted or local-only memory token.

## Default interpretation rules

1. **Same route pair is not automatic re-watch.** A later recurrence only reopens operation if it is material to a current owner, recipient, proof object, clock, protected route, official record, or learner action.
2. **Prior exit is not erased.** Ordinary activation restored, route-pair reconciliation, dual-route recognition, route split, redesign handoff, retired-route residue, and no-active-route residue remain the starting memory until current proof supersedes them.
3. **Memory recall must be justified.** Minimized proof can be recalled only for a named current need and only at the smallest scope that preserves the current route decision.
4. **Learners should not pay for owner ambiguity.** Duplicate filing, wrong-route fault, adverse clock movement, and route-choice penalty require current proof and a route-native authority; otherwise publish no-action, one safe filing, dual-route recognition, longer-window, protected local support, or owner-only action.
5. **Relapse disposition must end or move.** A shell should close as ordinary lag, fresh first-cycle conflict, repeat-threshold candidate, reopened deconflict operation, redesign handoff, split, residue, or reminimized memory rather than remain a public route-pair warning forever.

## Worked examples

### Example A — old route appears again only in search

A replacement route was confirmed and the revived route was retired. Six weeks later, the old URL appears in a search snippet, but the source page is gone, the replacement owner is current, and the recipient portal accepts the replacement route.

Publish:

- `post_deconflict_relapse_signal_token = Google result reappeared`;
- `prior_deconflict_exit_and_scope_token = replacement route controlled`;
- `deconflict_memory_recall_token = redacted public pointer`;
- `current_relapse_proof_and_age_token = current search status`;
- `learner_safe_action_after_relapse_token = use replacement route`; and
- `post_relapse_disposition_and_memory_token = ordinary lag only`.

Do not reopen the operation merely because a downstream result lags.

### Example B — recipient portal again accepts the wrong route

A deconflict operation previously ended with dual-route recognition for one cycle, then minimized. In the next cycle, the recipient portal again accepts the older route while the official record owner publishes a different clock.

Publish:

- `post_deconflict_relapse_signal_token = recipient portal split`;
- `prior_deconflict_exit_and_scope_token = dual-route recognition retained`;
- `deconflict_memory_recall_token = recipient-of-record recall`;
- `current_relapse_proof_and_age_token = proof mismatched`;
- `learner_safe_action_after_relapse_token = submit once with dual-route recognition`; and
- `post_relapse_disposition_and_memory_token = repeat-conflict threshold candidate`.

Do not make the learner file twice unless a current authority requires duplicate action and names the protection for both filings.

### Example C — protected route relapse with sensitive proof

A protected accommodation route was split and kept local-only. A public replacement page later contradicts the protected route. The proof needed to resolve the conflict includes sensitive accommodation facts.

Publish:

- `post_deconflict_relapse_signal_token = protected route conflict`;
- `prior_deconflict_exit_and_scope_token = protected route retained`;
- `deconflict_memory_recall_token = protected owner recall`;
- `current_relapse_proof_and_age_token = current protected proof local-only`;
- `learner_safe_action_after_relapse_token = protected local-only submission`; and
- `post_relapse_disposition_and_memory_token = route split retained`.

Do not move protected proof into the public route-pair memory layer.

## Non-goals

This layer does **not** create:

- a permanent route-pair relapse dashboard;
- an automatic re-watch after any later recurrence;
- a public proof vault for minimized deconflict memory;
- a duplicate-filing duty for learners;
- an adverse wrong-route fault rule;
- a no-memory reset that treats prior deconflict work as nonexistent;
- a global replacement-failure or restored-trust certificate;
- a search-engine, archive, portal, source, recipient, or protected-route winner by default; or
- a duty to monitor all old route pairs after deconflict exit.

## Why this matters for the larger archive

The archive's education-with-AI program is not only about resolving conflict once. It is also about preventing old conflict from becoming either permanent stigma or invisible repetition.

This layer matters because both extreme defaults are bad. One bad default says a later recurrence proves that the route pair is permanently unstable and that learners must refile, reprove, or avoid the route. Another bad default says exit minimization means no memory can be used, so every recurrence must be treated as new even when the same recipient portal, proof object, protected route, or clock has failed before. The portable answer is narrower: preserve a small, scoped memory of the prior exit; recall only what a current named need justifies; publish current proof age and learner-safe action; and move the relapse to fresh handling, repeat threshold, reopened deconflict operation, redesign, split, residue, ordinary lag, or reminimization on named facts.

## Boundary conditions

This layer should not be used when only one of the following is true:

- `YO0-YO4` has not previously exited, minimized, split, handed back, redesigned, retired, or become residue;
- the later event is visibly unrelated to the earlier route pair or affected surface;
- the current signal is ordinary search/cache/crawl/archive lag with no learner-facing owner, proof, clock, recipient, protected-route, or live dependency effect;
- the route-native process already names relapse handling, memory recall, proof age, learner-safe action, and reopen rules;
- the only signal is an unrelated mirror, screenshot, expired history row, stale search result, or downstream copy with no current owner or learner dependency;
- protected accommodation, privacy, safety, legal, records, appeal, or recipient-of-record rules already control proof handling and should stay local-only; or
- no current learner, owner, recipient, proof object, clock, protected route, or official-record dependency remains.

In those cases, publish `ordinary lag only`, `unrelated new path`, `route-native rule controls`, `protected local-only route`, `no learner action now`, `no active owner`, `fresh first-cycle conflict`, or `none inherited` rather than creating a post-deconflict relapse memory layer.

## What this closes

This closes `FT-0149`.

The archive no longer stops at "activation deconflict operation exited". It can now publish a minimal post-deconflict relapse / route-pair memory layer: relapse materiality, prior exit state, route-pair scope, recall authority, current proof age, learner-safe action, disposition, reminimization, and reopen triggers when a learner again sees two official-looking paths, old proof ages, minimized memory must be recalled, or the same route pair relapses after an operation had already exited.

It also opens one narrower seam.

After a post-deconflict relapse has been classified as fresh first-cycle handling, repeat-threshold candidate, reopened operation, redesign handoff, split, residue, ordinary lag, or reminimized memory, the archive may still need a tiny repeat-relapse / rewatch-threshold layer for cases where route-pair relapse itself repeats after memory recall — without making every relapse an automatic re-watch, every repeat a permanent stigma label, or every minimized memory object a public dossier.
