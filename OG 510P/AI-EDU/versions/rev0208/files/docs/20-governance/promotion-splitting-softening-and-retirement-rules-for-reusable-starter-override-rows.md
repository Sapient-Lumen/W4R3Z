# Promotion, splitting, softening, and retirement rules for reusable starter override rows

This document closes the archive's next governance gap about **when a provisional starter override row has really earned stronger inheritance, when it should split into child rows, when it should soften back toward protected default, and when it should retreat to local-only publication or manual review**.

The archive's current bet is:

> keep the tiny starter row set, but add one small disposition rule and one first set of row-state judgments so “provisional” does not become a permanent vague status and “reusable” does not silently turn into overhardening.

The point is to avoid five predictable failures at once:

- **immortal provisionality** — rows stay published forever without ever becoming stronger, splitting, softening, or retiring;
- **premature hardening** — one plausible row gets treated as sector-wide truth before age band, stakes, or construct variation have been surfaced;
- **construct drift hidden as accessibility** — a row continues to inherit the language of support even after it is altering what the task is supposed to measure;
- **anti-access overreaction** — institutions use one construct-sensitive row to justify broad bans where the support should often remain protected access or bounded exploration help;
- **burden inflation** — substitute proof surfaces grow from short confirming checks into routine heavy documentation, oral-defense queues, or case-by-case bureaucracy.

Current public signals point in the same direction. College Board's current AP AI guidance is now explicitly domain-specific rather than universal: AP Art and Design prohibits AI across the creative process, AP Capstone allows limited use but requires checkpoints and teacher authenticity affirmation, AP Computer Science Principles permits AI-assisted coding but still requires students to understand and explain the code, and AP world-language course projects allow AI for inquiry and target-language source finding while keeping final learner-owned language performance central. NCEO and WIDA continue to hold the accessibility line that accommodations should preserve valid measurement and should not change what is being measured. ETS continues to frame fairness and validity around construct, content, predictive, consequential, and external validity rather than convenience alone. AAMC's current medical-education guidance keeps human-centred judgment, equal access, data privacy, and ongoing monitoring in view across assessment, simulation, advising, and program evaluation. Together those signals support a tighter archive rule: starter rows should travel only while the construct claim, access logic, and proof burden remain reviewably stable. See `B195`.

It adds two things only:

- a **small disposition rule** for deciding when a starter row may harden, must split, should soften, or should retire;
- a **first row-state judgment table** so the archive says something concrete about the current starter set instead of leaving every row equally provisional.

The starter-row canon still answers the first question:

- which repeated construct-sensitive cases are portable enough to publish centrally at all.

This document answers the next question:

- what should happen after those rows have actually been used for a while.

## The disposition rule

| Disposition | What it means | Archive action |
|---|---|---|
| **harden** | the row keeps describing the construct-sensitive boundary truthfully across ordinary reuse without hidden accessibility conflict or burden creep | publish the row as a stronger inherited default for the named scope |
| **split** | the row is real, but one recurring age, stakes, or construct-stage difference now changes the truthful default outcome | keep the parent only as a family shell and publish the child rows |
| **soften** | the row remains useful, but its current default outcome is too hot; more of the work should return to protected default, bounded exploration help, or first-unaided-then-supported handling | cool the default outcome and publish the narrower trigger that still keeps the construct visible |
| **retire / local** | apparent reuse is too uneven, too rare, or too dependent on special staffing / local doctrine for a shared row to help | remove the row from the inherited starter set or demote it to local-only publication / manual review |

## Five tests before a starter row hardens

A provisional starter row should harden only when all five tests are substantially met.

### 1. The construct claim stays the same across ordinary reuse

The row should harden only if the same thing is still being protected or measured across the reuse scope. If one site is really checking first-pass decoding, another is checking comprehension-with-support, and a third is checking persistence under scaffolded reading, the row is not hardening — it is hiding a split.

### 2. The support status remains accommodation-like rather than modification-like

If the ordinary support under the row now starts changing what the task is supposed to measure, the row should split or retreat rather than harden. The archive continues to treat that boundary as central, not technical residue.

### 3. The substitute proof surface stays short, reviewable, and educationally plausible

A row that requires long viva queues, universal draft archives, or dense case memos in ordinary use has probably not found the right stable surface. Hardening is only plausible if the confirming proof stays small enough to belong to ordinary educational practice.

### 4. Local departures cluster cleanly rather than scattering everywhere

A row should harden only if local departures are either rare or patterned. If many sites keep making different age, stakes, language, or programme exceptions, the row likely needs child branches or retirement rather than stronger inheritance.

### 5. The row does not depend on one unusually capable team, teacher, or office

If the row only works because a local champion can run live checks, explain edge cases, or absorb hidden labor, then the archive should not treat it as a hardened reusable default yet.

## What counts as a split trigger instead of hardening

The archive now treats six recurring changes as presumptive split triggers for starter rows:

1. **age band changes the construct boundary itself** — especially where early foundational skill differs from later supported participation;
2. **exploration support and final learner-owned performance stop sharing one honest default**;
3. **gateway, licensure, or readiness stakes change the proof surface from short educational check to supervised or safety-bearing performance**;
4. **the row starts depending on a protected-access carveout that is not stable across sites**;
5. **tool ecology changes the construct claim** — for example, symbolic procedure, coding, or writing settings where ordinary tool expectations diverge materially;
6. **the same row requires materially different human review tempo or expertise across sectors**.

## What counts as soften or retire pressure

The archive now treats four recurring signals as evidence that a row should soften or retire rather than harden:

1. **most local departures broaden the row back toward protected default** rather than tightening it further;
2. **the substitute proof surface costs more labor or learner burden than the construct gain justifies**;
3. **the row is repeatedly bypassed in favour of ordinary local explanation or manual review**;
4. **the row begins functioning mainly as a broad deterrent or ban instead of a narrow construct-sensitive exception**.

## What these judgments mean in practice

The archive is now making four tighter claims explicit:

1. **not every starter row should mature the same way** — some are ready to harden, some clearly need child rows first, and some should stay provisional longer;
2. **hardening a row is not the same thing as eliminating accessibility review** — especially for writing and other domains where protected access must stay distinct from surrogate production;
3. **the archive prefers stage splits and stakes splits to universal bans** where inquiry support and final construct performance are still meaningfully separable;
4. **a row that keeps requiring local exceptions in different directions is evidence for branching or retreat, not for pretending the row is already a sector default**.

## What institutions should publish when a row changes state

When a local or sector owner promotes, splits, softens, or retires a starter row, publish only six extra fields beyond the ordinary row table:

1. the row ID and prior state;
2. the new state (`harden`, `split`, `soften`, or `retire/local`);
3. the reason family (`construct drift`, `age split`, `stakes split`, `tool-ecology split`, `protected-access conflict`, `burden inflation`, or `low reuse`);
4. the scope of the change (course family, age band, stakes band, or programme type);
5. the substitute proof surface or protected-default rule now in force;
6. the next review point if the new state is still provisional.

That is enough to make state changes legible without turning the override table into a giant policy codebook.

## What counted as a real archive gain

The archive previously had a tiny starter row set, but it still lacked a disciplined answer to the next operational question: **when does a provisional row stop being just plausible and become hard, split, softened, or retired canon?**

This document answers that with a bounded disposition rule plus one first state-judgment table. It keeps the starter-row set small, but it now makes the archive more honest about what is already stable and what is not.

## Current archive bet

The archive's current best guess is that a **tiny starter row set plus one compact promote / split / soften / retire rule** will outperform both extremes:

- leaving every construct-sensitive row permanently provisional and vague;
- or hardening rows broadly without enough evidence about age, stakes, and construct-stage variation.

That claim is now canon, but still live. The next narrower problem is no longer whether starter rows need any state-change rule at all, but which of the still-live rows deserve the **first named child splits** by age band, stakes, or construct stage. See `OQ-0005`.
