# First repeat post-deconflict relapse and rewatch-threshold defaults for hot-exam recipient followup shells

The archive can now publish one still smaller layer for the hottest exam-like learner-request routes.

It can already say:

- when a revived or replacement route first activates and exposes route-choice conflict;
- when repeated activation-cycle conflict crosses a named route-stability threshold;
- when that threshold opens bounded deconflict work and exits;
- when an exited deconflict operation later relapses; and
- how minimized deconflict memory may be recalled only for a current named need.

That is still not enough.

A single post-deconflict relapse can be handled as a current event. The shell can ask whether the recurrence is material, what the prior exit state was, who may recall minimized memory, how old the proof is, what the learner safely does now, and whether the disposition is ordinary lag, fresh first-cycle handling, repeat-threshold candidacy, reopened operation, redesign, split, residue, or reminimization.

But the same relapse can happen again. A recipient portal may repeatedly accept the older route after memory has been reminimized. A protected accommodation or records route may repeatedly contradict a public replacement page. A route pair may repeatedly produce clock conflicts across cycles. Search, archive, image, custom-search, source, or official-record surfaces may repeatedly revive the same ambiguity after the deconflict operation closed. The old proof may be too aged to serve as current proof, but too relevant to ignore. The shell needs to know when repeated relapse crosses a threshold for bounded rewatch, redesign, split, local-only protected handling, or no-active-route residue — and when it remains ordinary lag or fresh handling.

This document adds one thing only:

- a **tiny repeat post-deconflict relapse / rewatch-threshold field set** for hot-exam recipient followup shells after `YN0-YN4` has classified at least one post-deconflict relapse, but before the archive opens a bounded rewatch operation, redesign handoff, route split, protected-route-only handling, recipient-record correction, or no-active-route residue.

That means the archive now asks a narrower question than before. It no longer asks only **how to handle one later relapse after deconflict exit**. It now asks **when repeated relapse after memory recall or reminimization crosses a named rewatch threshold — without making every relapse an automatic re-watch, every repeated signal a permanent route-pair stigma label, every learner duplicate-file, or every minimized proof object become a public dossier**.

Current official signals support a deliberately narrow answer. Google Search Console's Removals tool remains property, URL, current/expired-history, temporary-removal, cancellation, about-six-month, Google-Search-only, and source-side-permanent-method based rather than a standing rewatch command. Google's Refresh Outdated Content route remains exact page/image URL, changed/gone-content, queue/status, and 180-day-expiry based rather than a durable relapse-pattern monitor. Google's personal-content routes distinguish Search removal from source-page removal and keep screenshots, notifications, sensitive proof, and new-result handling bounded. WiscWeb, Princeton, and Rowan separate local source control, CMS ownership, accessibility/accommodation support, cache/search/archive persistence, content redesign, and support-ticket work. Internet Archive and Bing expose URL-specific, time-specific, temporary, or source-proof-dependent routes rather than all-copy route-pair closure. Together those signals support a tighter archive rule: **the next truthful portability gain here is one tiny threshold layer for repeated-relapse count, scope, materiality, threshold owner, memory limit, learner-safe action, threshold disposition, minimization, and reopen triggers — but not one automatic rewatch, one public route-pair stigma label, one duplicate-filing duty, one permanent proof vault, or one all-surface relapse certificate.** See `B264`.

## Small field set for repeat post-deconflict relapse and rewatch thresholds

| Code | Meaning | Default archive action |
|---|---|---|
| `YT0-NO-AUTOMATIC-REWATCH-PERMANENT-STIGMA-PUBLIC-DOSSIER-OR-REPEAT-BY-ANECDOTE` | repeated relapse can matter, but repetition alone does not create surveillance, stigma, public proof retention, or a pattern label | require repeat count, affected scope, current materiality, threshold source, memory limit, learner-safe action, and threshold disposition before widening beyond ordinary relapse handling |
| `YT1-PUBLISH-REPEAT-RELAPSE-COUNT-SCOPE-AND-MATERIALITY` | the shell must say what repeated, where, and why it matters now | publish whether the repeat involves the same route pair, same recipient portal, same proof object, same protected route, same clock, same source/search/archive surface, same official-record dependency, or a different path that should not be counted together |
| `YT2-PUBLISH-REWATCH-THRESHOLD-SOURCE-OWNER-AND-MEMORY-LIMIT` | a rewatch threshold needs a named owner and a proof boundary, not just accumulated unease | publish whether the threshold comes from route-native rules, recipient-record owner, protected-route owner, local redesign owner, source owner, search/archive provider, formal appeal body, or archive-local portability; state what prior memory may be recalled and what remains local-only or redacted |
| `YT3-SEPARATE-REWATCH-OWNER-WORK-FROM-LEARNER-FAULT-DUPLICATE-FILING-AND-PROOF-VAULTING` | repeated route-pair relapse is usually owner-stability work before it is learner fault | publish no-action, one safe route, dual-route recognition, longer current window, protected local-only submission, or owner-only rewatch work unless a current route-native authority names a learner duty |
| `YT4-PUBLISH-THRESHOLD-DISPOSITION-MINIMIZATION-AND-REOPEN-TRIGGERS` | repeated relapse must end, narrow, or open a bounded next posture on named facts | publish ordinary lag, fresh first-cycle handling, repeat-threshold not met, bounded rewatch candidate, reopened deconflict operation, redesign handoff, route split, protected local-only route, recipient-record correction, retired-route residue, no-active-route residue, reminimized memory, or reopen only on material new facts |

## Field values that now travel together

When this layer is used, the shell should publish only six concrete fields:

1. `repeat_post_deconflict_relapse_pattern_token` — `none`, `same route pair repeated`, `same revived route repeated`, `same replacement route repeated`, `recipient portal repeated`, `protected route repeated`, `official-record route repeated`, `clock conflict repeated`, `proof object aged repeatedly`, `source page repeated`, `Google result repeated`, `Bing or partner-search result repeated`, `custom search repeated`, `image result repeated`, `archive or mirror repeated`, `owner silence repeated`, `ordinary lag repeated`, `different surface not counted`, `unrelated new path`, `none inherited`, or `not published`;
2. `repeat_relapse_count_scope_token` — `first relapse only`, `second material relapse`, `third material relapse`, `same cycle duplicate not counted`, `same route pair only`, `same recipient only`, `same protected route only`, `same proof object only`, `same clock only`, `same source surface only`, `search-only repeat`, `archive-only repeat`, `mixed surface split`, `no countable pattern`, `route-native count controls`, `none inherited`, or `not published`;
3. `rewatch_threshold_owner_and_basis_token` — `threshold not met`, `route-native threshold`, `recipient-record owner threshold`, `protected-route owner threshold`, `official-record owner threshold`, `local redesign owner threshold`, `source owner threshold`, `search or archive provider status threshold`, `formal appeal or complaint threshold`, `archive-local portability threshold`, `owner threshold disputed`, `no current owner`, `none inherited`, or `not published`;
4. `repeat_memory_limit_token` — `no recall needed`, `aggregate memory only`, `redacted public pointer`, `local-only prior proof`, `protected proof local-only`, `current proof required before recall`, `screenshot-only insufficient`, `expired status row insufficient`, `stale proof insufficient`, `recall limited to threshold owner`, `recall limited to recipient`, `recall limited to appeal or record owner`, `no authority to recall`, `none inherited`, or `not published`;
5. `learner_safe_action_under_threshold_token` — `none current`, `information-only notice`, `wait for owner confirmation`, `use current replacement route`, `use revived route only if current owner confirms`, `submit once with dual-route recognition`, `do not duplicate filing`, `use more protective route until resolved`, `use longer current window until resolved`, `protected local-only submission`, `manual local support only`, `owner-only rewatch work`, `formal appeal route only`, `none inherited`, or `not published`;
6. `repeat_relapse_threshold_disposition_token` — `ordinary lag only`, `fresh first-cycle handling`, `repeat-threshold not met`, `bounded rewatch candidate`, `reopen deconflict operation`, `redesign handoff`, `route split retained`, `dual-route recognition retained`, `recipient-record correction`, `protected local-only route retained`, `retired-route residue`, `no-active-route residue`, `reminimized memory`, `local-only memory retained`, `reopen only on material new fact`, `none inherited`, or `not published`.

## Minimal publication sentence

A learner-facing or owner-facing shell can stay compact:

> Repeat relapse is `[repeat_post_deconflict_relapse_pattern_token]` with count/scope `[repeat_relapse_count_scope_token]`. The threshold basis is `[rewatch_threshold_owner_and_basis_token]`; memory limit is `[repeat_memory_limit_token]`. Learner action now is `[learner_safe_action_under_threshold_token]`. Current disposition is `[repeat_relapse_threshold_disposition_token]`.

If the threshold would require protected, privacy-sensitive, accommodation, appeal, security, or official-record proof, publish the threshold owner, learner-safe action, and redacted memory posture while keeping the actual proof local-only.

## Default interpretation rules

1. **Repeat means same material dependency, not same vibe.** Count repeated relapse only when the same route pair, recipient, proof object, protected route, official record, clock, source/search/archive surface, or learner dependency recurs; unrelated mirrors or stale snippets do not create a pattern.
2. **A threshold is not a watch.** Crossing the threshold only authorizes the next bounded decision posture. It does not itself create a permanent dashboard, public route-pair stigma, or indefinite proof vault.
3. **Prior memory stays minimized unless current need justifies recall.** The shell may recall only the minimum proof needed for the named threshold owner or route decision, and must keep protected or sensitive proof local-only.
4. **Learner safety comes before owner repair.** Duplicate filing, wrong-route fault, adverse clock movement, or proof reburdening requires a current route-native authority; otherwise publish one safe route, dual-route recognition, longer window, protected local-only support, or owner-only work.
5. **The threshold must dispose of itself.** The shell must either stay ordinary, handle as a fresh first-cycle conflict, reopen deconflict operation, hand to redesign, split, correct the recipient record, retain protected route, publish residue, or reminimize memory.

## Worked examples

### Example A — search-only repeats do not cross the threshold

A replacement route controls. Twice after deconflict exit, an old Google result reappears for the retired URL. The source page is gone, the recipient portal accepts the replacement route, and no learner action depends on the old search result.

Publish:

- `repeat_post_deconflict_relapse_pattern_token = Google result repeated`;
- `repeat_relapse_count_scope_token = search-only repeat`;
- `rewatch_threshold_owner_and_basis_token = threshold not met`;
- `repeat_memory_limit_token = aggregate memory only`;
- `learner_safe_action_under_threshold_token = use current replacement route`; and
- `repeat_relapse_threshold_disposition_token = ordinary lag only`.

Do not open a rewatch merely because downstream search reflection repeats.

### Example B — recipient portal repeats after reminimization

A deconflict operation ended with dual-route recognition for one cycle. The shell reminimized memory. In two later cycles, the recipient portal again accepts the older route while the official record owner publishes a different current clock.

Publish:

- `repeat_post_deconflict_relapse_pattern_token = recipient portal repeated`;
- `repeat_relapse_count_scope_token = second material relapse`;
- `rewatch_threshold_owner_and_basis_token = recipient-record owner threshold`;
- `repeat_memory_limit_token = recall limited to recipient`;
- `learner_safe_action_under_threshold_token = submit once with dual-route recognition`; and
- `repeat_relapse_threshold_disposition_token = bounded rewatch candidate`.

Do not make the learner file twice unless the current recipient-record owner names that duty and protects the learner against duplicate-clock harm.

### Example C — protected route conflict repeats

A public route and a protected accommodation route disagree. The prior relapse stayed local-only because the proof was sensitive. A later cycle repeats the same contradiction for the same learner-facing window.

Publish:

- `repeat_post_deconflict_relapse_pattern_token = protected route repeated`;
- `repeat_relapse_count_scope_token = same protected route only`;
- `rewatch_threshold_owner_and_basis_token = protected-route owner threshold`;
- `repeat_memory_limit_token = protected proof local-only`;
- `learner_safe_action_under_threshold_token = protected local-only submission`; and
- `repeat_relapse_threshold_disposition_token = protected local-only route retained`.

Do not move protected proof into a public threshold packet.

### Example D — aged proof forces current confirmation before rewatch

The same route pair has relapsed twice, but the only prior proof is an expired status row and a screenshot from an old cycle. The current source page has changed and the owner has not confirmed present applicability.

Publish:

- `repeat_post_deconflict_relapse_pattern_token = same route pair repeated`;
- `repeat_relapse_count_scope_token = second material relapse`;
- `rewatch_threshold_owner_and_basis_token = owner threshold disputed`;
- `repeat_memory_limit_token = current proof required before recall`;
- `learner_safe_action_under_threshold_token = wait for owner confirmation`; and
- `repeat_relapse_threshold_disposition_token = repeat-threshold not met`.

Do not treat old deconflict proof as current authority merely because the pattern resembles the earlier case.

## Non-goals

This layer does **not** create:

- a standing rewatch for every post-deconflict relapse;
- a public route-pair stigma label;
- an automatic duplicate-filing duty;
- a permanent proof vault for minimized deconflict memory;
- a universal repeat count for all surfaces;
- an all-engine or all-archive relapse certificate;
- a learner wrong-route fault rule;
- a protected-proof publication duty;
- a no-memory reset that ignores prior deconflict work; or
- a duty to monitor every old route pair after reminimization.

## Why this matters for the larger archive

The archive's education-with-AI program is not only about resolving route conflict once or remembering it once. It also has to decide when repeated recurrence shows an owner-stability problem and when it is only the ordinary noise of distributed web, recipient, archive, and record systems.

This layer matters because both extreme defaults are harmful. One bad default says every repeat proves permanent instability and opens surveillance. Another says reminimization makes every recurrence new, even when the same recipient, protected route, proof object, or clock has failed repeatedly. The portable answer is narrower: count only material repeats by affected scope; name the threshold source and owner; keep memory limited and privacy-aware; protect learner action from duplicate-filing and wrong-route fault; then either stay ordinary, reopen bounded deconflict work, split, redesign, correct the recipient record, retain protected local-only handling, publish residue, or reminimize.

## Boundary conditions

This layer should not be used when only one of the following is true:

- `YN0-YN4` has not yet classified a post-deconflict relapse;
- the current event is the first material relapse after deconflict exit;
- repeated signals are unrelated to the same route pair, proof object, owner, recipient, protected route, clock, source, search, archive, or official-record dependency;
- the route-native process already defines repeat-relapse counting, threshold, owner, learner action, proof-recall, and exit rules;
- all repeated evidence is stale, expired, screenshot-only, search-only, archive-only, or mirror-only with no current owner or learner dependency;
- protected accommodation, privacy, safety, security, legal, records, appeal, or recipient-of-record rules already control proof handling and should remain local-only; or
- no current learner, owner, recipient, proof object, clock, protected route, or official-record dependency remains.

In those cases, publish `ordinary lag only`, `fresh first-cycle handling`, `threshold not met`, `route-native rule controls`, `protected local-only route`, `no learner action now`, `no active owner`, `reminimized memory`, or `none inherited` rather than creating a repeat-relapse / rewatch-threshold layer.

## What this closes

This closes `FT-0150`.

The archive no longer stops at "post-deconflict relapse memory exists". It can now publish a minimal repeat post-deconflict relapse / rewatch-threshold layer: repeated-relapse count, scope, materiality, threshold source and owner, memory limits, learner-safe action, disposition, minimization, and reopen triggers when the same route pair, recipient, protected route, proof object, clock, source/search/archive surface, or official-record conflict recurs after memory recall or reminimization.

It also opens one narrower seam.

After repeated post-deconflict relapse crosses a bounded rewatch threshold, the archive may still need a tiny rewatch operation / repair-proof / dewatch-exit layer for cases where threshold status opens owner reconciliation, route-pair repair, recipient-record correction, protected-route handling, redesign, split, retired-route residue, or no-active-route residue — without turning threshold status into permanent surveillance, public stigma, duplicate learner filing, or an indefinite proof vault.
