# First post-dewatch relapse and redesign-memory defaults for hot-exam recipient followup shells

The archive can now publish one still smaller layer for the hottest exam-like learner-request routes.

It can already say:

- when a restored or minimized surface materially recurs;
- when repeated recurrence crosses a bounded standing-watch threshold;
- how an active standing watch runs;
- what owner-repair proof is needed before de-watch; and
- what minimal memory remains after the watch exits.

That is still not enough.

After de-watch, the operational temptation changes again. A later recurrence can be treated as proof that the learner, owner, or route is permanently suspect. The opposite error is just as dangerous: because the watch label was removed and the proof was minimized, the shell can pretend the prior repair never happened. A source owner can regress after one clean cycle. A search-provider temporary block can expire after the watch closes. A mirror, archive, image, or recipient record can recur on a surface that was never inside the watch. A local redesign can have been opened but never verified. Or a later relapse can be ordinary maintenance lag rather than the same failure coming back.

This document adds one thing only:

- a **tiny post-dewatch relapse / redesign-memory field set** for hot-exam recipient followup shells after an active standing watch has de-watched, handed back, minimized proof, or returned a surface to ordinary status.

That means the archive now asks a different question than before. It no longer asks only **how the watch runs or exits**. It now asks **when a later relapse may recall minimized repair memory, when thresholding must restart, when local redesign history matters, and when the shell must avoid both permanent watch stigma and fresh-start amnesia**.

Current official signals support a deliberately narrow answer. Google Search Console exposes current and expired removal histories for limited windows, temporary-removal expiry, cancellation, and eligibility for a page to appear again rather than permanent watch closure. Google's Refresh Outdated Content route exposes request queues, statuses, 180-day approval expiry, exact result-URL handling, image/container-page proof, and additional per-URL refresh needs rather than one all-copy relapse certificate. Google personal-content routes can involve URL, screenshot, status, notifications, and source-site persistence, which supports privacy-aware proof recall only when a current personal-result dependency exists. Princeton distinguishes local deletion, access control, Google/Bing, custom search, cache, and Wayback persistence, and warns that public web copies can outlive the source action. WiscWeb distinguishes local emergency edits, primary-contact follow-up, campus directory/search/lookahead surfaces, major search-engine limits, and normal-hours constraints. Rowan separates project/operation categories, project closeout/post-implementation review, content/accessibility monitoring, contributor support, and web-support requests rather than one central all-surface redesign owner. Internet Archive requires URL, time-period, control-period, and review context and gives no guaranteed outcome before review. Bing exposes temporary blocks and up-to-90-day expiry / extension / permanent-removal boundaries rather than one durable all-engine clean slate. Together those signals support a tighter archive rule: **the next truthful portability gain here is one tiny post-dewatch relapse layer for materiality, memory recall, classification, disposition, and minimization — but not one permanent penalty box, automatic re-watch rule, public repair dossier, or fresh-start fiction that erases needed redesign memory.** See `B253`.

## Small field set for post-dewatch relapse and redesign memory

| Code | Meaning | Default archive action |
|---|---|---|
| `XY0-NO-PERMANENT-PENALTY-BOX-AUTOMATIC-REWATCH-OR-FRESH-START-AMNESIA` | de-watch removes the active watch label; it does not create either permanent suspicion or total erasure of the repair history | require any later relapse to be tied to current material facts, affected surface, and live dependency before memory is recalled or a watch reopens |
| `XY1-PUBLISH-RELAPSE-MATERIALITY-AND-PRIOR-WATCH-SCOPE` | a post-dewatch event must say whether it is the same surface/owner/route returning, a different surface, a route-native expiry, a recipient or record effect, or ordinary maintenance lag | publish what recurred, what had been watched before, and whether the learner has any action now |
| `XY2-PUBLISH-MINIMIZED-MEMORY-RECALL-AUTHORITY-AND-NEED` | minimized repair proof may be recalled only by a named owner or route for a current dependency | label the recalled memory as local-only repair summary, public as-of pointer, privacy-redacted marker, recipient confirmation marker, official-record correction marker, or redesign handoff marker; do not revive old screenshots or tickets publicly without a live need |
| `XY3-PUBLISH-FRESH-CASE-VS-REPEAT-PATTERN-VS-REDESIGN-FAILURE` | later relapse must be classified before it becomes re-watch, redesign, or ordinary casework | distinguish fresh-case restart, same-surface repeat, same-owner repeat, threshold-preserved re-watch, redesign failure, split-surface new shell, no-active-route residue, and non-material lag |
| `XY4-PUBLISH-POST-RELAPSE-DISPOSITION-AND-REMINIMIZATION` | the shell must publish what happens after the relapse is classified | publish ordinary case opened, bounded re-watch reopened, redesign review opened, owner repair requested, recipient/record correction opened, privacy/safety event trigger, no-active-route reclosure, reminimized false alarm, or post-redesign proof needed |

## Field values that now travel together

When this layer is used, the shell should publish only six concrete fields:

1. `post_dewatch_relapse_state_token` — `same exact surface relapsed`, `same owner workflow relapsed`, `route-native expiry reappearance`, `different surface relapsed`, `linked mirror archive or social relapse`, `recipient or record relapse`, `privacy or safety relapse`, `redesign area relapsed`, `crawler lag only`, `ordinary maintenance reflection`, `no material relapse`, `none inherited`, or `not published`;
2. `prior_dewatch_memory_basis_token` — `local-only repair summary`, `as-of public pointer`, `privacy-redacted marker`, `recipient confirmation marker`, `official-record correction marker`, `redesign handoff marker`, `watch exit summary`, `no memory retained`, `memory missing or expired`, `none inherited`, or `not published`;
3. `minimized_memory_recall_token` — `no recall needed`, `local-only recall by current owner`, `recall for route-native refile`, `recall for recipient dependency`, `recall for official-record dependency`, `recall for privacy or safety dependency`, `recall for redesign review`, `recall denied no live dependency`, `proof unavailable residue`, `none inherited`, or `not published`;
4. `relapse_classification_token` — `fresh case restart thresholding`, `same-surface repeat below threshold`, `same-owner repeat below threshold`, `threshold already met re-watch allowed`, `redesign failure suspected`, `redesign failure confirmed`, `split-surface new shell`, `no-active-route residue`, `non-material lag`, `ordinary maintenance`, `none inherited`, or `not published`;
5. `post_relapse_disposition_token` — `ordinary case opened`, `bounded re-watch reopened`, `owner repair requested`, `redesign review opened`, `recipient or record correction opened`, `privacy or safety event trigger opened`, `route-native refile opened`, `reclosed no active route`, `reminimized false alarm`, `post-redesign proof needed`, `none inherited`, or `not published`;
6. `redesign_memory_publication_token` — `no learner-facing penalty label`, `retain local redesign marker`, `publish current redesign owner only`, `publish repair status not old proof`, `publish affected surface only`, `retain privacy-redacted relapse marker`, `expire after clean verification`, `purge public watch stigma`, `reopen only on material recurrence`, `none inherited`, or `not published`.

That is deliberately small. It is enough to show whether a later event is the same failure returning, which minimized memory may be recalled, whether thresholding restarts or a redesign history matters, and how the shell exits again. It is not enough to create a permanent penalty box, one automatic re-watch rule, one public repair dossier, one all-copy relapse certificate, or one fresh-start fiction that hides a real redesign failure.

## What this layer now makes portable

Hot-exam recipient followup shells may now publish one tiny `XY0-XY4` layer after `XW0-XW4` when the archive needs to say not merely that **a standing watch exited**, but that **a later event either materially relapsed, restarted thresholding, reopened a bounded watch, triggered redesign memory, or stayed ordinary/non-material**.

That means a shell may now truthfully say things like:

- `the same exact Google-visible URL reappeared after the route-native expiry period; recall only the local repair summary and reopen the route-native refile path`;
- `a different archive time slice appeared after source-page de-watch; split a new archive surface rather than relabeling the source owner as unrepaired`;
- `the source owner workflow relapsed after one clean cycle; open redesign review, but do not publish old learner screenshots or ticket IDs`;
- `recipient confirmation failed again after de-watch; recall the recipient confirmation marker, not the public search proof`; or
- `the old request row expired and a crawler lag remains; keep the shell minimized because no material relapse exists`.

It still may not pretend:

- that de-watch creates permanent suspicion;
- that de-watch creates total amnesia;
- that any later related copy automatically reopens the prior watch;
- that minimized proof becomes public again by default;
- that one route-native expiry proves owner fault;
- that a redesign history can be used as learner-facing stigma;
- that all related surfaces relapse together; or
- that ordinary maintenance lag restarts the entire hot-shell chain.

## Why this matters for the larger archive

The archive's education-with-AI program is not only about building watch states and exits. It is also about governing what happens after a watch has honestly ended.

This layer matters because both errors are institutional defaults. A repaired route can become a hidden permanent mark: every later recurrence is blamed on the learner, treated as proof of bad ownership, or used to justify public evidence retention. Or repair history can disappear so thoroughly that a repeated owner workflow failure must be rediscovered from scratch. The point here is narrower: publish **what materially relapsed**, **which minimized memory may be recalled and by whom**, **whether this is a fresh case, repeat pattern, or redesign failure**, **what state opens next**, and **how proof is minimized again**. Everything else remains ordinary maintenance, route-native casework, local-only redesign memory, privacy-aware proof handling, or no-active-route residue.
