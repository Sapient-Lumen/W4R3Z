# First trigger-class and visible-effect defaults for reopened hot-exam final-ordinary shells

This document closes the archive's next narrower governance gap after **named-trigger and reopened-settled-shell publication defaults**.

Three overclaims matter here:

- **every-reopen-looks-equally-adverse drift** — once a settled shell reopens, the archive publishes every later trigger as if it had the same learner-facing seriousness, score-risk posture, and ordinary-shell effect;
- **route-local-versus-live-review blur** — the archive correctly distinguishes sample requests, integrity/security review, and custody exceptions at the trigger level, but still lacks a tiny shared way to say what each one actually does to the ordinary shell; and
- **action-now confusion** — the archive leaves it unclear whether the person who must act now is the learner, the retained-artifact owner, the AP coordinator / security owner, or no one yet, even when current official materials make that distinction visible.

Current official signals support a tighter answer. Bluebook's current AP answer-submission guidance still keeps ordinary digital closure tied to the same device and the submitted status, and it still tells coordinators to act quickly while recognizing that Test Day Toolkit status can be out of date. Current AP incident guidance still routes required incident reports through the AP coordinator within 48 hours and before returning shipments. Current AP security policy and AP Exam Terms and Conditions keep integrity/security review visibly different from route-local quality work because suspected security issues must be reported, invalid scores may trigger written notice and review, and testing irregularities or misconduct can lead to cancellation or other measures. Current AP Capstone policy keeps later quality-sample requests distinct from integrity review because retained presentation/oral-defense videos may be requested for scoring quality or scoring training, while evidence of inappropriate generative AI use or other integrity concerns may trigger investigation and interim-work requests. Current AP coordinator-manual materials also keep one more distinction visible: hybrid/paper artifacts remain under coordinator / authorized-staff custody, students are not permitted to handle those materials, and all used and unused hybrid digital free-response booklets move through the return chain rather than through a learner self-submit path. Together those signals support a narrower archive rule: **the reopened hot final-ordinary shells may now share one tiny trigger-class / visible-effect field set, but they still do not justify one universal late-review disposition, one universal adverse banner, or one universal action-now rule.** See `B216`.

This document adds one thing only:

- a **tiny trigger-class / visible-effect field set** for those already reopened-or-still-settled shells.

That means the archive now asks a different question than before. It no longer asks only **which late named trigger may reopen which shell**. It now asks **what that trigger should visibly do to the shell, whether score-risk is actually live yet, and who must act now without the archive inventing one universal late-review script**.

## Small field set for trigger-class / visible-effect defaults

| Code | Meaning | Default archive action |
|---|---|---|
| `FX0-NO-UNIVERSAL-LATE-DISPOSITION` | no one universal post-settlement disposition, adverse banner, or action script governs every reopened shell | keep the field set descriptive and shell-bounded rather than collapsing late triggers into one generic review outcome |
| `FX1-PUBLISH-TRIGGER-CLASS` | publish the later trigger as one of a tiny number of truthful classes | name the trigger as `quality-sample request`, `integrity/security review`, or `artifact-custody exception` rather than leaving a vague `review` badge |
| `FX2-PUBLISH-VISIBLE-EFFECT` | publish what the trigger actually does to visibility | say whether the event stays route-local, reopens the ordinary shell, or reopens only the affected artifact shell |
| `FX3-PUBLISH-SCORE-RISK-ONLY-WHEN-OFFICIAL` | publish score-risk posture only when the official trigger actually puts scoring or validity in question | keep nonadverse quality work nonadverse, publish live score-validity / cancellation risk only when official integrity/security review has actually opened, and keep artifact-only uncertainty artifact-bounded until wider official effect exists |
| `FX4-PUBLISH-ACTION-NOW-OWNER` | publish who actually has to act now | name the retained-artifact owner, AP coordinator / authorized materials owner, official security owner, learner, or `no learner action now` only when that owner is genuinely the next actor |

## Field values that now travel together

When this layer is used, the shell should publish only four concrete fields:

1. `trigger_class` — `quality-sample request`, `integrity/security review`, or `artifact-custody exception`;
2. `visible_effect` — `route-local only`, `ordinary shell reopened`, or `affected artifact shell reopened`;
3. `score_risk_now` — `none published`, `official score-validity review live`, or `artifact completeness/custody unresolved`;
4. `action_now_owner` — `retained-artifact owner`, `AP coordinator / authorized materials owner`, `official review owner`, `student if officially contacted`, or `no learner action now`.

That is deliberately small. It is enough to say what the later trigger is doing without pretending the archive already has one universal late-review disposition menu.

## `FX1` and `FX2` — name the trigger and its shell effect separately

The archive now separates **what happened** from **what changed visibly**.

That matters because the same word `review` can hide three different truths:

- a nonadverse retained-artifact sample request that stays route-local;
- an integrity/security process that reopens the ordinary shell because score validity or authenticity is now in question; and
- an artifact-custody exception that reopens the affected artifact shell first without automatically widening to every adjacent shell.

So the archive now requires both `trigger_class` and `visible_effect`. A named trigger is not enough by itself.

## `FX3` — score-risk must be official, not inferred from anxiety

`FX3-PUBLISH-SCORE-RISK-ONLY-WHEN-OFFICIAL` is the archive's smallest anti-panics rule.

It blocks two opposite mistakes:

- treating a nonadverse sample request as if it already threatened score validity; and
- treating a real integrity/security inquiry as if it were just quiet back-office follow-up.

Current AP Capstone policy makes that distinction visible by separating scoring-quality sample requests from investigations requesting interim work. Current AP Exam Terms and Conditions make it visible again by describing invalid-score, misconduct, and testing-irregularity processes that can lead to score cancellation or other measures. So the archive now publishes score-risk only when the official route has actually opened that question.

## `FX4` — who acts now depends on the trigger, not the archive's mood

`FX4-PUBLISH-ACTION-NOW-OWNER` is the archive's smallest anti-handwaving rule.

It stops the archive from saying only `review in progress` while concealing who is actually holding the work or what the next truthful action is.

Current official materials make at least three distinct action-now owners visible:

- for retained-video quality requests, the retained-artifact owner is the next actor;
- for hybrid/paper custody exceptions, the AP coordinator / authorized materials owner is the next actor because students do not handle the materials and the return chain remains controlled; and
- for integrity/security review, the next actor is the official review owner, with learner action only if the official process actually requests information, interim work, or another response.

That is enough for a tiny cross-shell owner field. It is not enough for one universal late-review workflow.

## What the archive now publishes when using this layer

When an institution or assessment family publishes one of these reopened hot final-ordinary shells, it should now add only the following where truthful:

1. the trigger class;
2. the visible shell effect;
3. whether score-risk is officially live yet; and
4. who has to act now.

That is enough to make later-trigger handling legible without pretending the archive already has one universal disposition menu.

## What counted as a real archive gain

The archive already knew which later named triggers could stay route-local, reopen the ordinary shell, or reopen only the affected artifact shell. It still lacked the next tighter answer: **what later trigger class should be published, what that trigger visibly does to the shell, whether score-risk is truly live yet, and who actually has to act now.**

This document answers yes, but only barely.

It now allows the archive to publish one thin field set that distinguishes:

- nonadverse quality-sample requests from live integrity/security review;
- artifact-specific custody exceptions from wider ordinary-shell reopening;
- official score-risk from mere anxiety; and
- learner action, retained-artifact action, and coordinator/security action.

That is a real operating gain because it blocks four opposite mistakes at once:

- treating every later trigger as equally adverse;
- concealing which shell has actually changed state;
- publishing score-risk before the official route has actually made it live; and
- leaving reopened settled shells legible about *what happened* but opaque about *who must act now*.
