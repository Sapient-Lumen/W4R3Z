# Availability, acknowledgement, and action-now fields for after-hours split-lane branches

This document closes the archive's next implementation gap about **what an after-hours or delayed-owner child branch must actually say once it remains visible outside the main owner's live decision window**.

The archive already has:

- a generic split-lane display grammar (`DL0-DL3`, `LD1-LD7`, `PX0-PX3`);
- a starter profile layer for higher-ed teach-out, workforce routing, civic first-contact, licensure-sensitive routes, and protected support channels; and
- a branch / retreat layer (`BR0-BR3`, `AT0-AT3`, `OF0-OF4`) for when inherited packet defaults stop being truthful.

What it still lacked was the next narrower answer:

> **once a child branch survives after-hours variation, what minimum availability, acknowledgement, and action-now fields must travel so visible intake does not impersonate live decision ownership, preserved position, waived rights, or 24/7 adjudication?**

The archive's answer is now:

> **every after-hours or delayed-owner child branch must publish one tiny service-truth shell naming what is actually live now, what acknowledgement is owed, whether any queue or clock protection starts now, what the learner should do right now, and which owner or urgent channel actually acts next.**

Current public signals support that move. OIA's current good-practice framework says providers should tell students what actions they need to take to preserve their position while matters are being considered, should direct them to sources of advice, and should update them when timeframes extend. OIA's glossary also says a Completion of Procedures Letter should issue as soon as possible and within 28 days once internal procedures are finished. Federal Student Aid currently says FAFSA Submission Summary amounts are estimates while each school's aid offer is the final determination and best source of truth. SAMHSA's current 988 materials say the line offers 24/7 call, text, and chat access to immediate crisis support. Together those signals support a sharp packet distinction between **visible now**, **received now**, **position preserved now**, **final owner decision later**, and **live urgent help now**. See `B184`.

## Core rule

When a split-lane profile is operating under `BR1` or `BR2` with `AT1` or `AT2`, the packet must say five things explicitly:

1. what is live **right now**;
2. what acknowledgement, if any, is owed **right now**;
3. whether any queue, hold, pause, or position-preserving effect starts **right now**;
4. what the learner should do **right now**;
5. which owner or urgent channel actually acts next.

The archive's anti-slippage claim is now explicit:

> **visibility is not service, receipt is not decision, and an after-hours intake shell is not a 24/7 front desk unless the branch can truthfully say so.**

## Three tiny code families the archive now adds

### Service-truth posture (`TV0-TV4`)

| Code | Meaning | What the packet may truthfully imply |
|---|---|---|
| `TV0 pointer only` | the shared packet may name the lane or channel, but the lane itself is not currently running as an intake surface here | orientation only; the packet must point outward rather than imply active handling |
| `TV1 browse only` | the learner may read guidance, compare options, or prepare materials, but no submission or preserved place begins now | the packet may inform, but may not imply the owner has received or queued anything |
| `TV2 intake now / owner later` | the learner may submit now, but the branch only records receipt; no queue priority, pause, or decision ownership begins until the next staffed owner window unless separately stated | the packet may say "sent now" but not "being decided now" |
| `TV3 intake now / protection now / owner later` | the learner may submit now and doing so truthfully preserves a place, starts a pause, or keeps a no-loss temporary protection while the named owner acts later | the packet may say "your position is preserved" or equivalent, but must still separate that from live adjudication |
| `TV4 live staffed route now` | the learner is reaching a genuinely staffed decision, urgent-transfer, or crisis/protected channel that is live now | the packet may say a live owner or urgent channel is available right now |

### Acknowledgement duty (`AY0-AY4`)

| Code | Meaning | What the packet must show |
|---|---|---|
| `AY0 no acknowledgement owed` | nothing was submitted because the branch is pointer-only or browse-only | no receipt promise is implied |
| `AY1 receipt confirmation only` | the system owes only confirmation that a submission was received | the packet must say receipt is not yet queue start, owner review, or final action |
| `AY2 receipt plus next-owner window` | the system owes receipt plus the next staffed owner window or review start window | the packet must name when the owner next acts or reviews |
| `AY3 receipt plus protection statement` | the system owes receipt, the next owner window, and a clear statement of what place / pause / temporary protection began immediately | the packet must name what was preserved and what still waits |
| `AY4 live handoff confirmation` | the branch is live now and owes immediate handoff or staffed confirmation | the packet must name the live route and how the learner knows the handoff succeeded |

### Action-now posture (`AN0-AN4`)

| Code | Meaning | What the learner should understand |
|---|---|---|
| `AN0 review / prepare only` | read, compare, gather documents, or return later; no immediate submission is needed to preserve position | missing the after-hours window does not itself cause loss |
| `AN1 submit request now` | send the intake or question now if you want the owner to review it in the next staffed window | useful for getting into the ordinary queue, but not yet for preserving rights or route position |
| `AN2 submit now to preserve position` | send the intake now because doing so truthfully preserves a hold, pause, place, or temporary protection | immediate submission matters, but the packet must say exactly what it preserves |
| `AN3 use urgent or protected channel now` | leave the ordinary packet and use the named urgent/protected route immediately | the ordinary branch must stop pretending it owns the live next step |
| `AN4 wait for named owner update` | no further learner action is needed now beyond monitoring the named next update point | the packet must say who updates next and when |

## Minimum extra fields that now travel with after-hours child branches

When `BR1` or `BR2` remains visible outside the main owner's live decision window, publish six extra learner-facing fields beyond the ordinary `LD1-LD7` lane shell:

1. **service-truth code** (`TV0-TV4`);
2. **acknowledgement code** (`AY0-AY4`);
3. **action-now code** (`AN0-AN4`);
4. **next staffed owner window** in local time, or explicit statement that the channel is live now;
5. **immediate effect field** saying whether submission starts nothing, receipt only, queue placement, temporary hold, pause, or urgent transfer;
6. **separate urgent/protected route field** when a different live channel exists.

These fields are intentionally thinner than a full case-management manual. They are just enough to stop fake all-hours ownership.

## Combination rule

The archive keeps the combination rule narrow.

### `AT1` usually means `TV1` or `TV2`, not `TV3`

If the branch is after-hours browse/intake only, the packet should usually publish `TV1 + AY0 + AN0` or `TV2 + AY1/AY2 + AN1`.

Use `TV3` only if the institution can truthfully say that immediate submission preserves a place, pause, or no-loss temporary protection before the next staffed owner window.

### `AT2` often needs `AY2` or `AY3`

If the learner may submit now but the owner acts later, the packet should usually publish:

- `TV2 + AY2 + AN1` where receipt matters but does not yet preserve position; or
- `TV3 + AY3 + AN2` where submission truthfully preserves place, pause, or protected interim status.

### `AT3` should usually leave the ordinary packet operationally

If the lane is urgent or protected in a genuinely live way, the ordinary packet should usually retreat under `BR3`. Where the shared packet still mentions the lane, it should do so only as a pointer with `TV0 + AN3` unless the live channel itself is the packet being used.

## What the packet must never imply

1. **receipt-is-decision failure** — a confirmation email or form receipt reads like a live owner decision has started.
2. **receipt-is-protection failure** — the packet thanks the learner for submitting but never says whether place, pause, or rights were preserved.
3. **false-24/7 failure** — the packet stays visible all night and therefore seems to promise all-night adjudication.
4. **silent-wait failure** — the learner is told only "we'll be in touch" with no next owner window or live alternative.
5. **ordinary-packet capture failure** — the packet leaves an urgent or protected route buried as one more ordinary row instead of saying "use this channel now."

## Starter examples

| Pattern | Typical truthful shell |
|---|---|
| higher-ed teach-out FAQ remains visible overnight but route decisions resume in business hours | `TV1` or `TV2`, `AY0` or `AY2`, `AN0` or `AN1` |
| after-hours aid-question intake that merely logs receipt for the aid office | `TV2`, `AY2`, `AN1` |
| continuity form that really preserves a provisional place or pauses an internal expiry if filed before midnight | `TV3`, `AY3`, `AN2` |
| crisis or urgent welfare lane mentioned from an ordinary route packet | `TV0`, `AY0`, `AN3` in the ordinary packet, with the live route handled separately |
| genuinely staffed urgent/protected live channel | `TV4`, `AY4`, `AN3` or route-specific live instructions |

## Current archive bet

The archive's current best guess is that **one tiny service-truth layer (`TV0-TV4`, `AY0-AY4`, `AN0-AN4`)** is enough to keep after-hours child branches honest without turning the split-lane chain into a full service-desk manual.

That claim is now canon, but still live. The next narrower question is no longer what an after-hours child branch must minimally say, but **which of these service-truth defaults can harden across sector profiles and when queue-preserving or rights-preserving intake must split further by stakes, office family, or protected support type.**
