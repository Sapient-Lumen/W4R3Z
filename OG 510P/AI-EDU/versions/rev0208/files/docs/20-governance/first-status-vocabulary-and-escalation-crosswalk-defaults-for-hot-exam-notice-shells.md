# First status vocabulary and escalation-crosswalk defaults for hot exam notice shells

This document closes the archive's next narrower governance gap after **receipt / handback / owner-notice minima**.

Three overclaims matter here:

- **state-word laundering** — once shell-specific notice minima exist, the archive acts as if each route should still use fully local prose forever and cannot share any portable state language at all;
- **report-form collapse** — the moment a tiny cross-route vocabulary becomes possible, it gets mistaken for permission to invent one universal incident form or one universal incident actor; and
- **escalation inflation** — every unresolved submission, booklet-custody problem, retained-record issue, and security concern gets treated as if it should enter the same report path at the same urgency.

Current official signals support a tighter answer. Bluebook's current in-school answer-submission guidance says coordinators should identify students with unsubmitted answers, protect answers on shared devices until submission is complete, keep submission on the same testing device, and complete AP answer submission within **3 days**. Test Day Toolkit guidance adds that for AP Exams proctors should verify submission before dismissal and let the **AP coordinator** know about any incidents. College Board's incident-report page then makes the next escalation layer explicit: when a testing incident requires an incident report, the **AP coordinator** submits it through AP Registration and Ordering **within 48 hours of the exam and before returning shipments**. The current coordinator manual and technical troubleshooting guide also keep route families distinct while still admitting a narrow crosswalk: Bluebook-related incidents, paper-related incidents including hybrid digital materials, and unresolved technical failures may all rise to the coordinator / incident-report path, while security issues use a separate report channel and AP Research/AP Capstone local defense videos are retained because College Board may later request them for scoring-quality review. Together those signals support a narrower archive rule: **one tiny shared status vocabulary and one tiny escalation crosswalk may now travel across the hot notice shells, but one universal incident form, universal owner, or universal report clock still remains fiction.** See `B209`.

## Small grammar for shared status vocabulary

| Code | Meaning | Default archive action |
|---|---|---|
| `SV0-LOCAL-ONLY` | no shared status word currently travels honestly for this family | keep status publication fully shell- or owner-local |
| `SV1-ACTION-OPEN` | the authoritative artifact still requires a named learner or owner action before the route handoff is complete | publish what action remains, by whom, and under what deadline or constraint |
| `SV2-NAMED-CUSTODY` | the authoritative artifact is protected in a named device, booklet, or local-record custody state, but the route is not yet universally closed | publish who now holds the artifact and what they must not change or discard |
| `SV3-HANDOFF-COMPLETE` | the required submission, collection, or checkpoint handoff for this shell is complete, so the learner no longer owes the next ordinary operational action for that shell | publish closure truth for the shell without implying scoring is finished |
| `SV4-UPSTREAM-REVIEW-OPEN` | the issue or artifact has crossed into a coordinator, incident-report, security, or requested-review path beyond ordinary local handling | publish the named upward path rather than pretending the shell is still only local |

## Small grammar for escalation crosswalks

| Code | Meaning | Default archive action |
|---|---|---|
| `ER0-NO-PORTABLE-UPWARD-PATH` | no shared upward reporting path is yet honest for this shell | keep escalation/report logic local |
| `ER1-LOCAL-TO-COORDINATOR` | proctor or local route actor must hand the issue to the AP coordinator or named route owner | publish coordinator ownership rather than direct learner self-cure fiction |
| `ER2-COORDINATOR-IR-48H` | if the incident requires formal reporting, the AP coordinator submits an incident report through the official system within the published window | publish the IR path and timing without pretending all incidents require it |
| `ER3-SECURITY-UPWARD` | suspected security or missing-material issues move into the dedicated security/report channel rather than ordinary route repair | publish the separate security path explicitly |
| `ER4-RETAIN-FOR-POSSIBLE-REQUEST` | the ordinary duty is local retention because College Board may later request the artifact for review | publish retention owner and request-contingent production rather than an immediate incident form |

## `SV1` — action remains open

`SV1-ACTION-OPEN` is the archive's smallest honest way to say that the route is not closed yet because some named action still must happen.

The crucial restraint is that `SV1` does **not** imply the same actor in every shell.

- In unresolved post-end fully digital submission, `SV1` means same-device submission or coordinator-owned remedy still remains open.
- In checkpointed portfolio-plus-local-record continuity, `SV1` means a student paper submission, teacher scoring step, or checkpoint/authenticity affirmation still remains open.

The archive publishes only the open action, the actor, and the deadline/constraint. It does **not** pretend those are the same workflow.

## `SV2` — named custody is now portable across three different artifact realities

`SV2-NAMED-CUSTODY` is the strongest shared state word the archive can now harden without fiction.

Across the three shells, `SV2` names three different but still comparable truths:

- a shared testing device is set aside and protected until digital submission is completed;
- a hybrid free-response booklet has been identified, collected, and moved into the secure return chain; or
- a local defense video is retained by the teacher for at least one academic year because College Board may request it later.

The common gain is not one common storage method. The common gain is simply that **the authoritative artifact is now in named custody and must not be casually altered, discarded, or treated as if the learner still owns the next operational step**.

## `SV3` — handoff complete is stronger than receipt, weaker than scoring finality

`SV3-HANDOFF-COMPLETE` is the archive's anti-overclaim middle state.

It lets the archive publish that the shell's required operational handoff has happened:

- answers have been submitted in Bluebook;
- the hybrid booklet has been collected into the secure chain; or
- the required portfolio/checkpoint handoff for the shell is complete.

But `SV3` does **not** claim the student's score is final, that every downstream review is over, or that no later audit/security/review path exists.

That narrower wording prevents the archive from laundering collection or submission into false closure.

## `SV4` plus `ER1-ER4` — a crosswalk exists, but it is not one universal incident form

`SV4-UPSTREAM-REVIEW-OPEN` means the shell has crossed out of ordinary local handling and into a named upward path. The crosswalk is tiny on purpose:

- `ER1-LOCAL-TO-COORDINATOR` covers the ordinary AP Exams rule that proctors hand incidents to the AP coordinator.
- `ER2-COORDINATOR-IR-48H` covers the formal incident-report path when a testing incident actually requires it.
- `ER3-SECURITY-UPWARD` covers separate security reporting, including missing materials or suspected cheating/security breaches.
- `ER4-RETAIN-FOR-POSSIBLE-REQUEST` covers the different AP Research / AP Capstone truth that some artifacts are kept locally because College Board may later request them for scoring-quality review.

That is a real crosswalk, but it is still not one universal form. A retained local video is not the same thing as an answer-submission incident report, and a security breach is not the same thing as an unresolved same-device submission.

## What the archive now publishes when using this layer

When an institution or assessment family publishes one of the hot exam notice shells, it should now add only the following where truthful:

1. the shell-specific receipt / handback / owner-notice minimum from `RC1-RC3`;
2. the applicable `SV` status word(s);
3. the applicable `ER` crosswalk code(s), if any;
4. the named next actor and deadline/constraint when `SV1` applies;
5. the named custodian and non-alteration / non-disposal truth when `SV2` applies.

That is enough to make the shell more legible without publishing one universal incident packet.

## What counted as a real archive gain

The archive already knew that hot exam continuity shells needed artifact-specific notice minima. It still lacked the next tighter answer: **can any tiny state words or upward-path labels travel across those shells without flattening them into one route?**

This document answers yes, but only barely.

It now allows the archive to publish a small shared language for:

- action still open;
- named custody;
- handoff complete; and
- upstream review/report path open.

And it pairs that language with a still smaller crosswalk for:

- local handoff to the coordinator;
- coordinator-filed incident reports where officially required;
- separate security reporting; and
- retain-for-possible-request review paths.

That is a real operating gain because it blocks three opposite mistakes at once:

- pretending shell-specific notice minima can never share any status language;
- pretending a tiny shared vocabulary authorizes one universal incident form; and
- pretending every hotter shell climbs into the same escalation/report path.
