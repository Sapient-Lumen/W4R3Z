# First post-window exception and owner-caused late-petition-relief defaults for hot-exam recipient followup shells

The archive can now publish a very small post-send and post-confirmation grammar for the hottest exam-like learner-request routes.

It can already say:

- what downstream transfer evidence the owner system exposes;
- how old that transfer residue is and when direct recipient confirmation becomes the truthful next step;
- what the recipient side says once contacted — confirmed receipt, still processing, wait, resend/correct, temporary bridge, or no new state;
- what bounded interim bridge or no-penalty protection a named office admits without pretending that unofficial evidence already equals official receipt, posted credit, or official evaluation;
- what event ends that bridge, what later official proof supersedes it, and what ordinary correction truth follows if verification fails; and
- what named correction window still protects the learner if official verification lands late enough to change the route.

That is still not enough.

The archive still lacked the next tighter answer: **once a named no-fault correction window has already closed, when does a current office still admit a distinct exception path because the delay, wrong state, or missed timing was owner-caused; what relief actually travels there — waived late fee, non-counting late action, direct correction, retroactive add/drop, or refund/removal; which owner, proof bundle, and deadline govern that exception; and when do ordinary petition burdens still stand?**

This document adds one thing only:

- a **tiny post-window exception / owner-caused late-petition-relief field set** for those already named hot-exam recipient followup shells.

That means the archive now asks a different question than before. It no longer asks only **what protected correction window exists before ordinary late-change risk resumes**. It now asks **whether, after that window closes, there is a named fault-based exception path that displaces ordinary fee, petition, documentation, or count-against-cap burdens, and where that exception still stops**.

Current official signals support a deliberately narrow answer. UCLA says late registration, processing, and penalty fees are waivable only if they were incurred through University fault or because a student suffered a sudden and debilitating injury or accident. Washington says students may request a refund of change-of-registration or late-registration fees if those fees were assessed due to University error. Berkeley L&S says that when a late change is due to departmental error or delay outside the student's control, the student may submit a departmental-error letter so the request does not count toward the ordinary late-action cap and the late fee is waived, but the request is still due by the Late Change of Class Schedule deadline. Buffalo says exception registration should be used only for administrative error, advisement error, or swapping sections/courses, and not for students who simply missed add/drop deadlines. George Mason says a retroactive add after the end of the semester is only allowed for documented university error, not student registration mistakes. Colorado Boulder says retroactive class adds or variable-credit adjustments after the term are for university error, and some other post-deadline grading changes also admit no exceptions unless the cause is university error. Arizona says some administrative errors do not belong in the general-petition route at all and should instead be corrected directly by Registration, Residency & Transcripts. UCF says a documented administrative error by the university can support a late-drop petition and, if approved, leads to a full refund of tuition fees and complete removal of the course from the academic record. Together those signals support a tighter archive rule: **the next truthful portability gain here is one tiny post-window exception / owner-caused late-petition-relief layer, but not one universal registrar amnesty, one universal guaranteed seat-repair workflow, or one universal late-fee-forgiveness rule.** See `B228`.

## Small field set for post-window exception / owner-caused late-petition-relief defaults

| Code | Meaning | Default archive action |
|---|---|---|
| `PW0-NO-UNIVERSAL-POST-WINDOW-AMNESTY-OR-GUARANTEED-REPAIR-RULE` | no one universal post-window exception, guaranteed seat-repair workflow, or automatic fee-forgiveness rule governs every hot recipient followup shell once the named correction window has closed | keep post-window relief route-bounded instead of implying `the system must still fix this the same way everywhere` |
| `PW1-PUBLISH-NAMED-OWNER-CAUSED-OR-ADMINISTRATIVE-ERROR-TRIGGERS-ONLY-WHEN-CURRENT-PAGES-EXPLICITLY-NAME-THEM` | publish a post-window exception trigger only when a current office explicitly says university fault, administrative error, departmental error, advisement error, or comparable owner-caused conditions open a distinct path | distinguish real fault-based exception triggers from sympathetic guesswork |
| `PW2-WHEN-NAMED-PUBLISH-WHAT-RELIEF-THE-EXCEPTION-ACTUALLY-DISPLACES` | if current materials say the exception waives a fee, keeps the action from counting against an ordinary cap, permits direct correction, admits retroactive add/drop, or yields refund/removal, publish that bounded relief directly | distinguish concrete post-window relief from a general promise that late rules no longer matter |
| `PW3-PUBLISH-WHICH-OFFICE-PROOF-BUNDLE-AND-DEADLINE-OWN-THE-EXCEPTION` | publish which office, petition, letter, documentation bundle, or direct-contact route owns the exception and whether the ordinary late deadline still governs | distinguish a real exception path from vague `appeal if needed` language |
| `PW4-OUTSIDE-THE-NAMED-FAULT-PATH-ORDINARY-LATE-PETITION-FEE-OR-DENIAL-TRUTH-STILL-STANDS` | once the current page stops naming owner-caused fault, ordinary late-fee, missed-deadline, approval-not-guaranteed, or denial rules remain visible | distinguish bounded fault-based exception relief from indefinite amnesty |

## Field values that now travel together

When this layer is used, the shell should publish only four concrete fields:

1. `exception_trigger_token` — `university-fault fee-waiver path`, `departmental-error late-change exception`, `documented university-error retroactive add`, `administrative-error direct correction`, `administrative-error late-drop refund path`, `none inherited`, or `not published`;
2. `relief_scope` — `late fee waived or refunded`, `late action does not count toward ordinary cap`, `direct correction outside general petition`, `late or retroactive add may still be approved`, `full refund and record removal if approved`, `none inherited`, or `not published`;
3. `exception_owner_proof_and_deadline` — `assessing office written waiver request`, `registration-fee refund petition after payment`, `departmental-error letter plus late-change petition by named deadline`, `registrar or college form plus documentation and instructor verification`, `direct registration-office correction contact`, `academic services petition within named submission deadline`, `none inherited`, or `not published`;
4. `outside_exception_truth` — `ordinary late fee still applies`, `missed deadline alone is not enough`, `student error is not a legitimate reason`, `late submission still denied after named deadline`, `financial matters handled elsewhere`, `none inherited`, or `not published`.

That is deliberately small. It is enough to distinguish a real fault-based exception from an ordinary late petition, to distinguish fee waiver from record correction, to distinguish direct correction from approval-based retroactive repair, and to distinguish a named post-window exception from the stricter late-change regime that still surrounds it.

## `PW1` — post-window exception triggers must be named, not inferred

`PW1-PUBLISH-NAMED-OWNER-CAUSED-OR-ADMINISTRATIVE-ERROR-TRIGGERS-ONLY-WHEN-CURRENT-PAGES-EXPLICITLY-NAME-THEM` is the archive's smallest anti-fake-exception rule.

It blocks two opposite mistakes at once:

- acting as if every late-arriving official score, bad handoff, or confusing local state automatically becomes institution-fault once the ordinary correction window closes; and
- acting as if current institutions never admit owner-caused post-window relief at all.

Current official pages now make several named triggers visible enough to publish:

- UCLA names University fault;
- Washington names University error;
- Berkeley names departmental error or delay outside the student's control;
- Buffalo names administrative error and advisement error;
- George Mason and Colorado Boulder name university error; and
- Arizona names administrative error that should be corrected directly.

That is enough for one tiny exception-trigger field. It is not enough for one universal `late but understandable` amnesty.

## `PW2` — post-window relief can be fee waiver, non-counting action, direct correction, retroactive add, or refund/removal, but only when named

`PW2-WHEN-NAMED-PUBLISH-WHAT-RELIEF-THE-EXCEPTION-ACTUALLY-DISPLACES` is the archive's smallest anti-fake-remedy rule.

Current official pages now make several different relief scopes visible enough to distinguish:

- a late fee may be waived before or after payment if the institution caused the lateness;
- a departmental-error late change may stop counting against an ordinary late-action cap and may also carry a fee waiver;
- a direct administrative correction may bypass the general petition route entirely;
- a documented university-error path may still admit late or retroactive add after the ordinary window; and
- a documented administrative-error late drop may repair both bill and record through refund and removal.

That is enough for one tiny `relief_scope` field. It is not enough for the archive to pretend every owner-caused case guarantees seat repair, successful late add, or total retroactive cure in the same way.

## `PW3` — the exception owner, proof bundle, and deadline must stay visible

`PW3-PUBLISH-WHICH-OFFICE-PROOF-BUNDLE-AND-DEADLINE-OWN-THE-EXCEPTION` is the archive's smallest anti-vagueness rule.

Current official pages now make it visible that post-window exception ownership really differs:

- some institutions require a written waiver request to the assessing office;
- some require a fee-refund petition after the charge has already been paid;
- some require a departmental-error letter plus the ordinary late-change petition before the named deadline;
- some require registrar or college forms, documentation, and sometimes instructor verification; and
- some direct the learner to the registration office because the error is administrative correction, not general-petition business.

That is enough for one tiny owner/proof/deadline field. It is not enough for one universal `file an appeal` instruction.

## `PW4` — outside the named fault path, ordinary late-change truth still stands

`PW4-OUTSIDE-THE-NAMED-FAULT-PATH-ORDINARY-LATE-PETITION-FEE-OR-DENIAL-TRUTH-STILL-STANDS` is the archive's smallest anti-infinite-exception rule.

Current official pages now make both sides visible at once:

- Berkeley softens ordinary cap and fee burdens for departmental error, but still says late submissions after the named deadline will not be considered even if the delay came from getting permissions;
- Buffalo says exception registration is not for students who simply missed the add/drop deadlines;
- George Mason says student registration errors are not legitimate reasons for retroactive add; and
- Arizona says tuition refunds or other financial matters live on a different path even when some administrative record errors are corrected directly.

So the archive now requires an `outside_exception_truth` field instead of letting a real fault-based exception drift by implication into indefinite waiver, guaranteed repair, or universal late-petition forgiveness.

## What the archive now publishes when using this layer

When an institution or assessment family publishes one of these hot recipient followup shells, it should now add only the following where truthful:

1. whether a current office names a post-window exception trigger tied to university fault, administrative error, departmental error, advisement error, or a comparable owner-caused condition;
2. what concrete relief that exception actually displaces — fee, cap-counting, ordinary petition route, retroactive add barrier, or refund/removal boundary;
3. which office, proof bundle, and deadline own the exception path; and
4. what ordinary late-change truth still stands outside that named fault path.

That is enough to make post-window fault-based exception relief legible without inventing one universal registrar amnesty.

## What counted as a real archive gain

The archive already knew what protected correction windows could still soften late-arriving official verification and when ordinary late-change risk resumed. It still lacked the next tighter answer: **what current institutions say once that named window has already closed but the remaining lateness is still owner-caused**.

This document answers yes, but only barely.

It now allows the archive to publish one thin field set that distinguishes:

- a real named owner-caused exception trigger from generic sympathy for any late request;
- waived fee, non-counting late action, direct correction, retroactive add, and refund/removal from each other;
- the office, proof bundle, and deadline that actually own the exception path from vague `submit an appeal` language; and
- a bounded fault-based exception from the ordinary late-fee, missed-deadline, student-error, or denial rules that still remain visible around it.

That is a real operating gain because it blocks four opposite mistakes at once:

- treating every late-arriving official score as if institution fault were automatically presumed after the correction window closes;
- treating every current university-error carveout as if it guaranteed the same repair outcome;
- treating direct administrative correction and approval-based retroactive repair as if they were the same path; and
- treating a real fault-based exception as if it erased every remaining deadline, fee, or proof burden.
