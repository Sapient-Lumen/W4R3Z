# AI-EDU: start here

This archive is for careful long-run work on **education with AI**.

Non-negotiables:

- Do not optimize for novelty over learning.
- Do not treat teacher time savings as sufficient evidence of educational value.
- Do not assume that general-purpose chatbots are automatically good pedagogical tools.
- Do not pretend that one answer-release posture travels unchanged across age bands, subject families, accessibility conditions, and task modes; publish the branch conditions instead.
- Do not preserve assignment formats whose evidentiary value has collapsed under ordinary AI use.
- Do not let AI literacy collapse into “prompting” instead of judgment, disclosure, and responsibility.
- Do not treat repeated answer-dependence, looping confusion, or relational stickiness as a cue for faster answers or deeper learner profiling; publish a named recovery path, a tiny temporary packet, aggregate-only service signals, a visible sector/context starter profile where minors, credit-bearing higher education, professional-practice training, or public adult-route support already need cooler or earlier-human-owned recovery defaults, a compact rule for when those starter profiles may truly harden, must branch, or should cool back toward `RP0` or direct human handback, a small portability layer for which recovery branches really carry shared review-window bands, substitute-path expectations, and publication floors rather than hiding them in local process notes, and a tiny treatment mini-code layer for the hotter branches so non-worsening, minimal-loss, and authority-sensitive handback promises stay truthful and legible, plus one still smaller authority-family map so the archive says which of those commitments truly harden across record owners, supervisor/safety owners, and route-case owners and which still remain branch-bound, plus a still narrower owner-facing packet-field rule so portable handback metadata stops at branch, authority, interim posture, review anchor, and a few family-conditioned fields rather than turning into hidden merits preparation, and a low-threshold ratchet so repeated packet departures cannot sit forever as merely published local residue, plus a still narrower recovery / reopen / watch rule so repaired packet defaults re-harden only on monitored comparable reuse, reopen on rights-shell loss or serious same-path relapse, reset when the governed path materially changes, and stop inheriting expired watch evidence once several individually non-reopening packet-shell edits accumulate into a fresh packet reset cluster, while allowing recurring same-basket calendar, route, or label upkeep to batch prospectively only inside a tiny pre-declared maintenance envelope with published shell invariants and explicit breach resets, and now saying that only label/plain-language harmonisation usually travels as a branch-portable envelope default, calendar housekeeping only for record and route owner families, while route/contact upkeep still remains local, and now saying that only label cleanup usually carries one shared `QC-3 + QW-14D` band while record-owner calendar cleanup carries only a shared `QC-2` cap and keeps the window local, plus one still narrower renewal-portability layer so promoted label cleanup may usually carry one shared fresh-cycle republication + pass-then-reopen package while record-owner calendar upkeep usually carries only the fresh-cycle republication floor and keeps recurrence admission local, plus one still narrower first-post-repromotion watch layer so only re-promoted label cleanup usually carries one shared watched re-entry cycle + immediate re-cooling package while record-owner calendar upkeep, route calendars, and safety calendars keep relapse handling local after re-entry, plus one still narrower post-restoration caution layer so only restored-to-ordinary label cleanup usually carries one shared recent-repair-sensitive first ordinary cycle + accelerated re-cooling package while record-owner calendar upkeep, route calendars, and safety calendars keep that first ordinary-cycle caution local, plus one final-settling layer so only post-restoration label cleanup usually carries one shared recent-repair-expiry + fully settled ordinary-status package while calendar families keep that last settling boundary local.
- Do not let silent model changes, persistent learner modeling, or service outages alter educational treatment without review, bounded memory rules, a visible starter profile layer where minors, formal assessment, professional gatekeeping, or public-route services already need cooler defaults or earlier human-owned rails, first child branches where support continuity and consequence-bearing memory should stop sharing one ceiling, a further rule that cooler branches harden only while memory stays function-bounded and non-portable and hotter branches usually retreat to named `M3` rails or human-only handling, fallback, continuity protection, a visible change-governance rule, and hotter inherited defaults where those same contexts already need them — and do not let a useful governed service silently harden into background infrastructure without a fresh branch-or-cap judgment, or let a named `M3` rail hide behind generic “case history” language without publishing its owner, allowed downstream effects, challenge path, no-travel boundary, the difference between a portable rights floor and a merely local merits rule, and any local rebuttal packet when a family presumption is being overridden.
- Do not permit high-stakes educational decisions to disappear into opaque automation.
- Do not let the archive sprawl; summarize, link, and ratchet.
