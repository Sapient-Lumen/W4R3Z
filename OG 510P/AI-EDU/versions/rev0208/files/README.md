AI-EDU is a compact, cumulative archive for designing an education system that treats AI neither as a ban-worthy novelty nor as an excuse to automate schooling into emptiness, and that now treats official study surfaces as requiring a small learning-first branch-and-recovery map, a bounded recovery-packet and aggregate-signal rule, a tiny sector-and-context recovery profile layer, a compact harden / branch / retreat rule with first child branches, and a tiny portability layer for shared review-window bands, substitute-path expectations, and publication floors, plus three very small treatment mini-codes for non-worsening holds, minimal-loss continuity, and authority-sensitive handback, and now one still smaller authority-family map for which of those commitments really harden across record owners, supervisor/safety owners, or route-case owners, plus an owner-facing packet-field rule that lets only branch, authority, interim-posture, review-anchor, and a few family-conditioned fields travel, together with a tiny departure-publication rule for local packet additions, withholdings, or family-default untruthfulness claims, plus a low-threshold ratchet so repeated packet departures force default revision, bounded field promotion, branch split, or local retirement rather than lingering forever as published residue, and now a still narrower recovery / relapse / watch rule so repaired packet defaults re-harden only on monitored comparable reuse, reopen on same-path structural relapse or rights-shell loss, reset when the governed path materially changes, stop inheriting expired watch evidence once several individually non-reopening packet-shell edits accumulate into a fresh packet reset cluster, and allow recurring same-basket calendar, route, or label upkeep to batch prospectively only inside a tiny pre-declared maintenance envelope with published shell invariants and explicit breach resets, while now saying that only label/plain-language harmonisation usually travels as a branch-portable envelope default, calendar housekeeping travels only for record and route owner families, and route/contact upkeep still stays local, with only label cleanup usually carrying one shared `QC-3 + QW-14D` maintenance band and record-owner calendar cleanup carrying only a shared `QC-2` cap while its real window stays local, and now saying that only promoted label cleanup usually carries one shared post-window checkpoint / breach package while record-owner calendar upkeep carries only the breach family and keeps the checkpoint anchor local, plus one still narrower post-restoration caution layer so only restored-to-ordinary label cleanup usually carries one shared recent-repair-sensitive first ordinary cycle + accelerated re-cooling package while record-owner calendar upkeep, route calendars, and safety calendars keep that first ordinary-cycle caution local, plus one final-settling layer so only post-restoration label cleanup usually carries one shared recent-repair-expiry + fully settled ordinary-status package while calendar families keep that last settling boundary local, rather than one universal answer posture, one generic telemetry habit, or one hidden merits packet. The archive is built around six commitments:

1. **Learning over task completion.** AI should increase understanding, transfer, agency, and access—not just help students finish work faster.
2. **Teacher-centred institutions.** Teachers remain the primary accountable adults for instruction, judgment, care, and escalation, so teacher-facing AI use needs its own compact delegation defaults and sign-off triggers rather than a quiet slide from planning help into grading, risk labeling, or official communication; and some of those defaults need a tiny sector-and-age profile layer because teaching minors, running credit-bearing higher-ed courses, and supervising live professional practice do not start from the same risk floor. Institutions also need a separate compact rule for internal AI systems that rank, queue, flag, or allocate cases, because learners can be affected by those systems even when no chatbot is visible; and some of those internal uses need starter profile splits by sector and office type rather than one generic operations rule.
3. **Assessment redesign, not denial.** Once capable AI is normal, many legacy take-home tasks stop functioning as reliable proxies for learning, so institutions need explicit proof-of-learning bundles, clear intensity bands, sampling ceilings, a small set of subject-family defaults, and a tiny sector-and-age profile layer so minors, ordinary higher education, professional-practice training, and public adult routes do not all inherit the same proof burden.
4. **Curricular AI literacy, not prompt fashion.** Students and teachers need staged competence in how to use, inspect, disclose, and govern AI across the lifespan. That competence should cash out in subject-embedded, mode-tagged routines and a light course-level use/disclosure grammar rather than abstract framework language alone.
5. **Evidence, equity, and safety by default.** Access, privacy, bias, disability inclusion, cultural responsiveness, and anti-manipulation safeguards are first-order design requirements; accommodation/access support should not be collapsed into the same disclosure rail as ordinary authorship, institutions should pre-clear ordinary access supports while publishing narrow override rules only where the construct being assessed would otherwise be replaced, recurring institutional AI support should move from tolerated general-purpose use toward wrapped or purpose-built tools as dependence, data sensitivity, and rights stakes rise, with published starter defaults and human handoff triggers for FAQ, study help, tutoring, advising, accessibility routing, and well-being functions, plus a tiny sector-and-age profile layer where minors, credit-bearing higher education, professional-practice training, or public adult-route systems already need stricter learner-facing defaults, recurring teacher-facing AI use should publish where draft assistance ends and accountable sign-off begins for planning, materials, feedback, marking support, analytics, and communication, with a tiny sector-and-age profile layer where minors, credit-bearing higher education, professional-practice training, or public adult-route teaching already need stricter defaults, and recurring institution-facing AI use should publish where clerical or descriptive support ends and contestable human review begins for queues, risk flags, allocation, and formal decisions, with stricter inherited starter profiles where minors, professional gatekeeping, or benefits-linked public routing make one generic internal default misleading, institutions should also publish a visible pilot-to-scale gate so exploratory wins do not quietly become default infrastructure, plus a tiny sector-and-function rollout profile layer where minors, formal assessment, professional gatekeeping, or public-route services already need a hotter scale burden or a lower default ceiling than the generic ladder, together with a compact rule for when those inherited profiles may harden unchanged, must branch, or should remain capped below `RG4`, plus first child branches inside those hotter rollout parents so minor-facing tutoring, candidate-facing assessment controls, readiness signalling, and queue-shaping public-route systems do not inherit the same scale path as lower-consequence support uses, and recurring educational-AI services should also publish a small observability/retention profile so safety logging, proof review, and appeal handling do not quietly become ambient learner surveillance or cross-function trace reuse, with a tiny sector-and-function overlay where minors, formal test monitoring, professional gatekeeping, or public-route coordination already need different default rails or stronger modality limits, and recurring services should also publish a small failure-escalation and manual-fallback rule so harmful drift, silent updates, or outages do not become learner-borne disruption, plus a compact memory/personalisation rule so institutions distinguish stateless help, learner-controlled preferences, bounded course memory, human-owned record rails, and predictive learner models before “personalisation” turns into quiet profile-building or cross-function nudging, plus a tiny sector-and-function memory profile layer so minors, formal assessment, professional gatekeeping, and public-route services do not inherit one generic tolerance for remembered state or one generic path toward predictive learner models, plus a tiny sector-and-context recovery profile layer so minors, credit-bearing higher education, professional-practice training, and public adult-route services do not inherit one generic packet-and-signal default once repeated dependence handling is being normalized, plus a tiny portability layer so the named recovery child branches publish shared review-window bands, substitute-path expectations, and publication floors where those really travel, plus a tiny treatment mini-code layer so hotter recovery branches can publish the strongest truthful non-worsening, minimal-loss, and handback rules without pretending one full interim package fits all cases, plus one still smaller authority-family layer so record owners usually harden at handback-plus-non-worsening, supervisor/safety owners usually harden only at handback, and route-case owners harden at handback plus a conditional continuity split, plus a still narrower owner-facing packet-field rule so portable recovery metadata stops before transcripts, predicted outcomes, queue nudges, or welfare narratives start smuggling merits into handback, plus a low-threshold ratchet so repeated owner-facing packet departures cannot indefinitely protect a false portable default once the same gap keeps recurring, plus a compact change-classification rule so model, prompt, tool, memory, cohort, or workflow changes cannot quietly ship as “maintenance” when they really require fresh review, shadowing, notice, or a freeze window, together with a tiny sector-and-function overlay where minors, formal assessment, professional gatekeeping, or public-route services already need hotter inherited change defaults before local evidence accumulates.
6. **Lifelong public routes, not school-only AI adoption.** Community colleges, VET, workforce systems, libraries, and learning-city/community spaces are part of the educational system AI will reshape; the archive therefore treats public first-contact points, adult transition routes, a small cross-node handoff standard, a typed portability/recognition rail, sector-specific recognition gates, reviewable standing-equivalency lists, and a tiny machine-readable publication profile with family-specific freshness windows, plus a bounded exception grammar for local overrides and partial equivalencies, a privacy-light maintenance rule for learning from appeals and false matches over time, and a thin public maintenance-history layer that publishes state, dates, scope, and short reasons without raw counts or case traces, plus a partner-consumption / grandfathering rule that defaults most maintenance changes to future-use effects rather than retroactive churn, and a no-fault continuity-cost rule with a small `P0` / `P1` / `P2` payer ladder, a tiny `CSP-CASE / CSP-RESERVE / CSP-ENTITLEMENT` graduation rule, and a still smaller published activation shell so system-caused bridges, challenge steps, substitute-equivalent routes, continuity supports, and repeated cycle-loss burdens are absorbed, reserved against, or backstopped through visible trigger facts, short proof minima, and real claiming windows rather than quietly billed back to the learner or left forever to ad hoc hardship exception handling, as core infrastructure rather than side cases.

The archive is intentionally small. It prefers ratcheted syntheses, open questions, and explicit ledgers over large dumps of literature.
