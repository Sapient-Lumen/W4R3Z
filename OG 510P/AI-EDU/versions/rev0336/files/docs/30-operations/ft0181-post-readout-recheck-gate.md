# FT-0181 post-readout recheck gate

Use this after a `post-readout-action.json` dispatch reaches its `due_or_recheck_date`. Do not treat the dispatch due date as a prose reminder.

In `rev0303`, run the router first. On or after the due date, it now emits a scratch-only recheck brief before the human recheck command:

```bash
make owner-post-readout-recheck-brief \
  ACTION=scratch/path/to/post-readout-action.json \
  AS_OF_DATE=YYYY-MM-DD
```

The brief validates the source action and due-date firebreak, then prints bounded `owner-post-readout-recheck` command skeletons. It is not the recheck, not context receipt, not evidence, and not closure.

## Preferred route

```text
post-readout-action dispatch
→ wait until due_or_recheck_date
→ owner-post-readout-recheck-brief
→ human-recorded owner-post-readout-recheck
→ if new context exists, route actual returned context through owner-field-next CSV=... and context receipt
```

## Source rule

Open a recheck only from one scratch-local `post-readout-action.json` generated by `make owner-post-readout-action`. The recheck records the source dispatch path, SHA-256 hash, dispatch lane, owner action class, source-truth class, due date, check date, and bounded outcome. It must not be opened from a copied summary, a live-window readout, a service-record edit, or a public-language draft.

## Allowed outcomes

| Outcome | Meaning |
|---|---|
| `no_new_owner_context` | The owner-held action or recheck produced no new owner context. Stop and keep `FT-0181` live. |
| `new_owner_context_available` | New real owner context exists outside the archive. Do not copy it into the recheck. Restart through `owner-field-next CSV=...`; the router must record `owner-post-readout-context-receipt` before intake. |
| `owner_action_complete_no_closure` | The owner-held action completed locally but does not authorize closure or public/service/lifecycle movement. |
| `route_blocked_no_owner` | The next owner route is blocked or unavailable. Preserve the block and keep `FT-0181` live. |

## Firebreaks

Every recheck must confirm no expansion, no public-claim upgrade, no service-record edit, no lifecycle movement, and no closure from recheck. The artifact may contain only class labels, counts, hashes, dates, and next-action routing. It must not copy owner answers, raw CSV rows, live-window notes, contact details, public claim text, or new owner context.

## Scratch-state firebreak

When the router decides whether this gate is current, it ignores checker/lint scratch subtrees such as `scratch/check-*` and helper artifacts that provenance-link back to those subtrees. A synthetic check fixture must not make a maintainer believe a real post-readout action, recheck, or owner context path exists.

## Boundary

A post-readout recheck is not evidence, not accepted `SRC2+`, not custody, not a service-record edit, not a lifecycle decision, not public-summary support, and not `FT-0181` closure. It only prevents a dispatch due date from disappearing or being mistaken for completion.
