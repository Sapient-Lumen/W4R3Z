# Portable local-repair / republication defaults for repeat-retreated after-hours service-truth profiles

This document closes the archive's next after-hours governance gap: **once a promoted callback-only
after-hours branch has already suffered repeated misses, carried a shared automatic retreat package,
and cooled back to local publication, can portable callback publication ever be regained under one
shared local-repair / republication package, or should portability re-entry stay fully local even
across the tiny callback-only reuse scope?**

The archive's answer is narrower again:

> only a very small class of low-consequence, callback-only `OV1 + AQT-CALLBACK + ABP-BOTH +
RFP-BOTH` branches may usually inherit one shared **local-repair / fresh-republication** package.
Consequence-bearing re-entry stays local.

That asymmetry is deliberate. The archive is trying to avoid four opposite errors at once:

- **forgiveness laundering** — one quiet local interval is treated as though it automatically
  restores the old portable callback promise even when the real repair evidence is owner-specific or
  staffing-specific;
- **permanent de-portabilisation** — a branch whose repair-to-portability truth really is stable
  enough to travel never earns one small re-entry package and therefore has to rebuild the same
  republication logic locally forever;
- **silent restoration** — the shared callback band quietly reappears after retreat without any
  fresh learner-facing republication that explains the promise is back and why;
- **fake-live recovery** — a branch that merely repaired an ordinary callback promise is made to
  look like it now has stronger owner-window or urgent-route truth.

Current public signals support this thinner move. HLC's current teach-out policy still requires
governed communications around applicability period, credit treatment, fees, records, and related
student-facing protections. OIA says providers should tell students what they need to do to preserve
position while matters remain live and should issue a Completion of Procedures Letter promptly once
internal procedures end. Federal Student Aid still says FAFSA Submission Summary amounts are
estimates while the school's aid offer is the final source of truth. ALA still frames libraries as
low-barrier public access infrastructure rather than downstream decision owners. SAMHSA still treats
988 as a genuinely live 24/7 crisis route. Together those signals support a small archive rule: **a
cooled callback-only branch may sometimes regain a thin portable callback band, but only after one
locally kept cycle and explicit fresh republication — not by elapsed time alone, and not by quietly
drifting back into stronger wording.** See `B190`.

## Three re-entry portability tiers

The archive now distinguishes three re-entry portability tiers.

| Tier | Meaning | What travels | What stays local |
|---|---|---|---|
| `ARP-LOCAL` | no shared re-entry package travels | only the earlier promoted, quantitative, miss, and retreat tiers | both the local repair floor and the republication gate |
| `ARP-FLOOR` | one shared local-repair floor travels but the actual republication gate stays local | the minimum fact that portability may not return immediately after retreat | the exact review evidence, owner sign-off, and republication gate |
| `ARP-BOTH` | one shared local-repair floor and one shared fresh-republication gate travel | the minimum kept-local cycle and the minimum conditions for republishing the callback band as a fresh re-entry | any stricter local review, any stronger local evidence bundle, and any first-post-re-entry watch rule |

The archive is deliberately asymmetric again:

> re-entry portability is harder to earn than first-promotion portability. A branch can carry one
shared callback band, one shared first-miss cure package, and even one shared repeat-failure retreat
package while the truth about **getting portability back** still remains local.

## Five tests for whether repair-to-portability truth really travels

A repeat-retreated after-hours branch may harden above `ARP-LOCAL` only when all five tests
substantially hold.

### 1. Same-repair-object test

The cooled local cycle must be repairing the same practical object across the reuse scope: the
ordinary callback promise itself. If one regime is really repairing queue fairness, rights
preservation, licensure timing, or protected-support handling rather than a simple callback promise,
re-entry stays local.

### 2. Same-kept-local-cycle test

The same minimum local repair floor must mean the same thing across the reuse scope. A portable
re-entry floor is only plausible where one **locally published kept callback cycle** still tells the
same truth everywhere: the branch has actually demonstrated that the previously missed callback
promise can now be kept under ordinary local conditions.

### 3. No-hidden-consequence-drift test

The shared re-entry package must not conceal that consequence shape changed while the branch was
cooled. If the cooled branch has drifted toward queue preservation, aid timing, complaint position,
licensure consequence, or protected support, portability re-entry stays local.

### 4. No-fake-forgiveness test

The shared package must not make elapsed time, silence, or one unpublished workaround look like
genuine repair. The callback promise should return only after a locally kept cycle and explicit
fresh republication.

### 5. Same-first-republished-cycle test

The first cycle after re-entry must begin with the same bounded trust story across the reuse scope.
If one context needs a stricter watched first cycle, extra owner sign-off, or narrower wording on
return, only the local repair floor may eventually travel, or the whole re-entry package stays
local.

## The starter local-repair / republication package

The archive now names one shared local-repair floor and one shared fresh-republication gate.

| Code | Meaning |
|---|---|
| `LR-CB1BD-1KEPT` | after `RT-CB1BD-LOCAL-REVIEW`, at least **1 full locally published callback cycle** must actually be kept within the would-be `CB-1BD` promise before portable callback status may return |
| `RG-CB1BD-FRESH-REENTRY` | portable `CB-1BD` publication may return only after that kept local cycle closes cleanly: the callback was actually delivered inside the local promise, no unresolved repeat-failure review or owner-scarcity question remains open, no new queue / rights / protected-route consequence has emerged, and the next portable band is republished as a **fresh re-entry** rather than as silent restoration |

The archive deliberately keeps the shared package thin. In the starter canon `LR-CB1BD-1KEPT +
RG-CB1BD-FRESH-REENTRY` does **not** include:

- automatic restoration of any stronger owner-window promise;
- automatic queue-preservation, deadline extension, compensation, or rights-preserving cure;
- automatic return after elapsed time alone;
- automatic return for branches that changed sector meaning while cooled;
- automatic first-post-re-entry trust without any watched-cycle question.

Those outcomes remain local unless a separate local regime already publishes them truthfully.

## The archive's starter re-entry answers

### `ST-HE-TEACHOUT` may sometimes harden as `ARP-BOTH`

Where a teach-out branch had previously truthfully hardened only to a **callback-only** `OV1 +
AQT-CALLBACK + ABP-BOTH + RFP-BOTH` promise, then cooled under `RT-CB1BD-LOCAL-REVIEW`, the archive
will usually allow one shared local-repair / republication package.

The starter default is therefore:

> when `ST-HE-TEACHOUT` has already truthfully hardened only to callback-only portability and then
retreats under `RM-CB1BD-2CONSEC + RT-CB1BD-LOCAL-REVIEW`, it may usually also inherit `ARP-BOTH`
with `LR-CB1BD-1KEPT + RG-CB1BD-FRESH-REENTRY`.

Why the archive allows this:

- the repaired object is still usually the same thing across the reuse scope — an ordinary
  orientation / teach-out callback promise, not a rights-bearing decision window;
- one locally kept callback cycle usually means the same thing here: the branch demonstrated that
  the cooled promise can now be kept again under ordinary staffing;
- fresh republication matters in the same way too: the learner should see that the callback band has
  **returned** rather than infer that it was never withdrawn.

What still stays local:

- any rights-preserving or complaint-preserving remedy;
- any compensation or fee-waiver decision;
- any watched first cycle after re-entry if the local owner believes renewed trust is still fragile.

### `ST-LIB-CIVIC-FIRST` may sometimes harden as `ARP-BOTH`

Where a civic or library first-contact branch had previously truthfully hardened only to
callback-only portability and then cooled under the shared retreat package, the archive will usually
allow the same small re-entry package.

Why the archive allows this:

- the repaired object usually still means only the ordinary navigator / orientation callback
  promise;
- one locally kept callback cycle usually gives enough truthful evidence that the front door can
  republish that thin promise again;
- fresh republication helps stop a civic front door from quietly drifting back into callback wording
  after a period when that wording had been withdrawn.

What still stays local:

- any downstream eligibility, seat, aid, or complaint effect;
- any stronger substitute route or emergency response;
- any first-post-re-entry watch rule if the local service still doubts stability.

### `ST-HE-AID-CREDIT` stays `ARP-LOCAL`

Aid, credit, registration, transfer, progression, and complaint-adjacent branches keep re-entry
fully local.

Why the archive stops here:

- once those branches have already repeated-missed and retreated, the meaning of a "clean" local
  cycle is too entangled with deadlines, queue place, evidence submission, and consequence-bearing
  ownership;
- a shared re-entry package would too easily hide that the branch has moved too close to
  rights-bearing or money-bearing timing to republish a portable callback band comfortably.

### `ST-WF-PUBLIC-ROUTE` stays `ARP-LOCAL`

Public-route branches also keep re-entry local.

Why:

- route integrity, scarce appointment meaning, and public-duty ordering still vary too much across
  workforce and public-service regimes;
- one kept local callback cycle does not necessarily carry the same fairness or queue meaning across
  those regimes.

### `ST-PRO-LICENSURE` stays `ARP-LOCAL`

Licensure-sensitive branches keep re-entry local.

Why:

- one locally kept cycle may still conceal regulator, practicum, or partner timing differences that
  make republished callback promises materially unlike one another;
- a shared re-entry package would too easily understate the consequence-bearing nature of the
  branch.

### `ST-PROTECTED-SUPPORT` stays `ARP-LOCAL`

Protected-support routes also keep re-entry local.

Why:

- once a protected-support-adjacent branch has already repeat-failed and retreated, any path back
  toward visible callback promises should be governed by local protected-route, safeguarding, or
  crisis logic rather than a reusable generic re-entry shell;
- the archive does not want an ordinary callback recovery package to blur into genuine urgent or
  protected support readiness.

## What the archive is refusing for now

The archive is intentionally declining five stronger claims:

1. any shared re-entry package that allows portable callback publication to return with **zero**
   locally kept cycles;
2. any shared re-entry package that treats elapsed time alone as sufficient repair evidence;
3. any shared re-entry package for aid / credit, public-route, licensure-sensitive, or
   protected-support branches;
4. any shared re-entry package that silently restores the callback band without fresh learner-facing
   republication;
5. any claim that a branch regaining a portable callback band has therefore also regained ordinary
   trust without a separate watched-first-cycle question.

## Why this counted as a real archive gain

The archive already knew:

- which after-hours starter profiles begin from different service-truth postures;
- when repeated after-hours demand has earned qualitative promotion;
- which promoted branches may carry one coarse shared callback band at all;
- which of those branches may share one thin first-miss cure package;
- and which of those branches may share one thin repeat-failure retreat package.

But it still lacked the next tighter answer:

- whether a cooled callback-only branch can ever regain portable callback publication under one
  shared repair-to-portability package;
- and whether the archive should distinguish the tiny reuse scope where that truth travels from the
  larger set of branches where re-entry still depends too heavily on local review.

This revision now answers that narrower question with one small ratchet:

- three re-entry portability tiers;
- five tests for whether repair-to-portability truth really travels;
- one tiny starter package, `LR-CB1BD-1KEPT + RG-CB1BD-FRESH-REENTRY`;
- and a starter judgment that only some callback-only teach-out and civic first-contact branches
  usually carry it.

That is a real operating gain because it blocks three opposite mistakes at once:

- treating one cooled interval or one quiet local workaround as automatic forgiveness for a failed
  portable callback promise;
- making low-consequence callback-only branches permanently local after retreat even when their
  repair-to-portability story is actually stable enough to travel;
- and letting the callback band quietly reappear without any fresh learner-facing republication that
  says the promise has returned.

## Current archive bet

The archive's current best guess is that **after-hours portability should become harder at each
stage: starter service truth first, then sector-specific overnight defaults, then qualitative
promotion, then at most one coarse callback band, then at most one first-miss cure package, then at
most one repeat-failure retreat package, and only after that may a very small repair-to-portability
package sometimes travel — with only some low-consequence callback-only teach-out and civic
first-contact branches usually carrying one shared `LR-CB1BD-1KEPT + RG-CB1BD-FRESH-REENTRY` package
while all consequence-bearing re-entry handling stays local.**

That claim is now canon, and the archive now answers that next probation question in

The next narrower question is whether any watched re-entered callback-only branch can also carry one
shared **probation-expiry / ordinary-status restoration package** after a clean watched portable
cycle, or whether restoration-to-ordinary trust should still stay local because callback-band return
has not yet become fully settled ordinary truth. See `OQ-0053`.
