# Late-relapse and ordinary-reset defaults for fully settled after-hours service-truth profiles

This document closes the archive's next after-hours governance gap: **once a callback-only
after-hours branch has already repeat-retreated, regained portable callback publication under one
shared local-repair / fresh-republication package, survived its watched returned cycle, restored
ordinary portable callback status, completed its recent-return-sensitive first ordinary cycle
cleanly, and truthfully rejoined fully settled ordinary portable status, does it still need one
distinct shared late-relapse / ordinary-reset package after a materially quiet settled cycle, or
should later misses simply fall back to the ordinary promoted callback canon?**

The archive's answer is now the same kind of closure move it already made on the packet-maintenance
side, but only after the after-hours chain has actually earned it:

> a callback-only after-hours branch that has truthfully rejoined **fully settled ordinary portable
status** should usually not carry any further special late-relapse / ordinary-reset package. In the
starter canon, fully settled ordinary callback-only `ST-HE-TEACHOUT`, `ST-LIB-CIVIC-FIRST`,
`ST-HE-AID-CREDIT`, `ST-WF-PUBLIC-ROUTE`, `ST-PRO-LICENSURE`, and `ST-PROTECTED-SUPPORT` branches
all fall back to the ordinary promoted callback-band / missed-window / retreat / re-entry canon
rather than carrying a distinct post-settlement relapse layer.

The point is to avoid three opposite errors at once:

- **duplicate-canon clutter** — a service republishes an ordinary promoted callback reset rule under
  a new late-relapse label even though the ordinary promoted after-hours canon already says
  everything the post-settlement path needs;
- **fake settlement** — a branch is publicly described as fully settled ordinary again while a
  hidden “recently repaired” or fast-collapse rule still governs later misses;
- **infinite callback residue** — a low-consequence callback path that has truthfully settled never
  gets to stop carrying post-repair caution because the archive keeps inventing one more downstream
  state.

Current public signals support this thinner move. HLC's current teach-out policy still treats
communications, applicability periods, credit treatment, fees, and records as governed
student-facing commitments. OIA's current Completion of Procedures guidance still turns completion
of internal procedures into a real end-of-process boundary rather than an endlessly residually open
state. Federal Student Aid still says the school's aid offer is the best source of truth rather than
earlier estimates. ALA still frames civic/library access as low-barrier public access infrastructure
rather than downstream decision ownership. SAMHSA still treats 988 as a genuinely live 24/7 crisis
route. Together those signals support a small archive rule: **once an ordinary callback path has
truthfully become fully settled ordinary again, later misses should usually return to the ordinary
promoted callback canon rather than carry a second special repaired-state layer.** See `B194`.

## Three post-settlement relapse tiers

The archive now distinguishes three post-settlement relapse tiers.

| Tier | Meaning | What travels | What stays local |
|---|---|---|---|
| `LRO-CB-BOTH` | the fully settled ordinary callback branch carries one shared late-relapse trigger family and one shared ordinary-reset rule | the minimum fact that certain later misses count as a special post-settlement relapse and the minimum fact about what reset follows | any stricter local watch, any owner-local review packet, and any stronger local publication or challenge route |
| `LRO-CB-FLAG` | the branch carries only one shared late-relapse flag floor | the minimum fact that some later misses should be named as post-settlement relapse events | whether those events produce any reset beyond the ordinary promoted callback canon |
| `LRO-CB-NONE` | the fully settled ordinary callback branch carries no special post-settlement relapse layer | only the ordinary promoted callback-band / missed-window / retreat / re-entry canon that already governs settled callback portability | both late-relapse labeling and any extra reset package |

The archive is deliberately asymmetric again:

> once a callback branch has truthfully earned `FS-CB1BD-SETTLED`, the burden shifts sharply against
any new special layer. A distinct post-settlement relapse package is presumptively evidence that
fully settled ordinary portable status was overstated or that the ordinary promoted callback canon
is still under-specified.

## Five tests for whether any post-settlement relapse layer is really needed

A fully settled ordinary callback-only after-hours branch may harden above `LRO-CB-NONE` only when
all five tests hold.

1. **non-duplication test** — the proposed late-relapse layer adds a real truth not already carried
   by the ordinary promoted callback-band / missed-window / retreat / re-entry canon.
2. **same-settled-meaning test** — “fully settled ordinary portable status” really means the same
   thing across the reuse scope rather than some owners quietly preserving a latent recent-return or
   repaired-state shadow.
3. **same-late-relapse trigger test** — the kinds of later misses that are supposed to count as a
   special post-settlement relapse can actually be described in one reusable way rather than
   collapsing back into the ordinary missed-window / repeat-miss / retreat grammar.
4. **same-reset-consequence test** — once the late-relapse trigger fires, the reset consequence is
   genuinely different from the ordinary promoted callback canon and remains stable across the reuse
   scope.
5. **no-shadow-probation test** — the proposed post-settlement layer does not merely smuggle back an
   unpublished probation, recent-return stigma, or hidden fast-collapse rule underneath the label
   “fully settled ordinary portable status.”

Failing the first, fourth, or fifth test keeps the branch at `LRO-CB-NONE`. Failing only the fourth
may someday point to `LRO-CB-FLAG`, but the starter canon does not yet use that middle tier.

## The starter post-settlement answer

The archive now makes one compact starter claim:

| Code | Meaning |
|---|---|
| `NO-CB-LRO-LAYER` | once a callback path has truthfully earned `FS-CB1BD-SETTLED`, later misses should fall back to the **ordinary promoted callback-band / missed-window / retreat / re-entry canon** rather than carrying any distinct post-settlement relapse package |

The starter canon is deliberately small:

- no fully settled ordinary callback-only after-hours branch currently carries one shared
  late-relapse trigger family beyond the ordinary canon;
- no fully settled ordinary callback-only after-hours branch currently carries one shared
  ordinary-reset rule beyond the ordinary canon;
- if a service believes a later miss still needs a special repaired-state package after supposed
  settlement, the archive treats that as evidence that the path was not yet truthfully fully settled
  ordinary or that the ordinary promoted callback canon needs repair upstream rather than one more
  post-settlement layer.

## The archive's starter post-settlement answers

### Fully settled ordinary callback-only `ST-HE-TEACHOUT` stays `LRO-CB-NONE`

Fully settled ordinary callback-only teach-out branches should currently carry **no** distinct
late-relapse package.

Why:

- once the branch has truthfully earned `OV1`, `AQT-CALLBACK`, `ABP-BOTH`, `RFP-BOTH`, `ARP-BOTH`,
  `RWP-WATCH`, `AOS-BOTH`, and `AFS-BOTH`, the path has already demonstrated that special
  recent-return residue has cleared and that later misses can be governed honestly through the
  ordinary promoted callback canon;
- a special late-relapse layer here would usually duplicate the existing ordinary missed-window /
  repeat-miss / retreat / re-entry logic rather than add a new truthful governance fact;
- if a teach-out callback path still seems to need a distinct “recently repaired” fallback after
  settlement, that is usually evidence that `FS-CB1BD-SETTLED` was claimed too early.

The starter default is therefore:

> when callback-only `ST-HE-TEACHOUT` has already earned `RRX-CB1BD-CLEAN-1ORDINARY +
FS-CB1BD-SETTLED`, it should usually fall back to `LRO-CB-NONE` with `NO-CB-LRO-LAYER` rather than
carrying any distinct post-settlement relapse package.

What this means in practice:

1. a later missed callback after a materially quiet settled cycle is handled as an ordinary promoted
   missed-window, repeat-miss, retreat, or re-entry event;
2. the service should not revive a hidden “recently repaired” label merely because the path once
   passed through callback retreat and recovery;
3. any institution that cannot tell that story truthfully should reopen the earlier final-settling
   claim instead of inventing a new post-settlement layer.

### Fully settled ordinary callback-only `ST-LIB-CIVIC-FIRST` stays `LRO-CB-NONE`

Fully settled ordinary callback-only civic/library first-contact branches also stay `LRO-CB-NONE`.

Why:

- once civic first-contact callback truth has already settled, a special post-settlement relapse
  package would usually duplicate the ordinary promoted callback canon rather than add any new
  truthful public distinction;
- where later civic misses still seem to need a hotter local rule, that is usually evidence that the
  branch is not truly fully settled ordinary or that the downstream office boundary was misdescribed
  earlier.

### Fully settled ordinary callback-only `ST-HE-AID-CREDIT` stays `LRO-CB-NONE`

Aid / credit callback branches also stay `LRO-CB-NONE`.

Why:

- aid / credit branches never earned shared final-settling portability in the first place, so there
  is no honest shared post-settlement relapse package to add on top;
- where an aid / credit path has settled locally, later misses are still handled through the
  ordinary local or promoted canon that already governs that owner-bound path.

### Fully settled ordinary callback-only `ST-WF-PUBLIC-ROUTE` stays `LRO-CB-NONE`

Public-route routing branches likewise stay `LRO-CB-NONE`.

Why:

- route branches keep final-settling truth local, so a shared post-settlement relapse package would
  only compound a portability claim the archive never made;
- later route misses should therefore keep using the ordinary route-owned callback and retreat logic
  already in force.

### Fully settled ordinary callback-only `ST-PRO-LICENSURE` stays `LRO-CB-NONE`

Licensure-sensitive callback branches also stay `LRO-CB-NONE`.

Why:

- licensure-sensitive paths keep final-settling truth local and remain tightly coupled to regulator
  windows and consequence-bearing timing;
- a distinct shared late-relapse package here would either duplicate ordinary licensure-governance
  logic or reintroduce a shadow repaired-state story the archive is trying to avoid.

### Fully settled ordinary callback-only `ST-PROTECTED-SUPPORT` stays `LRO-CB-NONE`

Protected-support callback branches also stay `LRO-CB-NONE`.

Why:

- protected-support branches keep final-settling truth local and remain coupled to live
  urgent-support separation, protected evidence handling, or genuine crisis-route staging;
- a distinct shared late-relapse package here would either duplicate ordinary protected-support
  governance or hide that the branch was never fully settled ordinary in the first place.

## What the archive is refusing for now

The archive is intentionally declining four stronger claims:

1. any shared post-settlement relapse package for fully settled ordinary callback-only
   `ST-HE-TEACHOUT` or `ST-LIB-CIVIC-FIRST` branches;
2. any shared post-settlement relapse package for aid / credit, public-route, licensure-sensitive,
   or protected-support callback branches;
3. any claim that fully settled ordinary portable callback status may truthfully coexist with a
   hidden repaired-state or “recently returned” post-settlement layer;
4. any attempt to use a late-relapse package to patch what should really have been a stricter
   earlier final-settling judgment.

## Why this counted as a real archive gain

The archive already knew which after-hours branches can begin from different honest overnight
postures, when repeated overnight use can promote into a published callback-slot promise, which
promoted branches can carry one coarse portable callback band, which of those can share one
missed-window cure package, which can share one repeat-failure retreat package, which can later
regain portable callback publication under one shared re-entry package, which first returned cycle
can carry one shared watched package, which clean watched returned cycle can restore ordinary
portable callback status, and which clean first restored ordinary portable cycle can sometimes end
recent-return sensitivity and restore fully settled ordinary portable status. But it still lacked
the last tight answer:

- whether any callback path that has truthfully rejoined fully settled ordinary portable status
  still needs one more special layer after settlement;
- and whether a distinct late-relapse package clarifies governance or merely hides that settlement
  was overstated.

This revision now answers that last narrow question with one small closure move:

- three post-settlement relapse tiers;
- five tests for whether any post-settlement relapse layer is really needed;
- one tiny starter rule, `NO-CB-LRO-LAYER`;
- and a starter judgment that every currently named fully settled ordinary callback class stays
  `LRO-CB-NONE`.

That is a real operating gain because it blocks three opposite mistakes at once:

- declaring callback paths fully settled and then quietly keeping a shadow probation alive;
- bloating the archive with a redundant post-settlement reset layer that just restates the ordinary
  callback canon;
- and hiding an earlier final-settling mistake by papering it over with one more downstream package.

## Current archive bet

The archive's current best guess is that **after-hours callback portability should become harder at
each stage and then stop: qualitative promotion travels first, then at most one coarse callback-slot
band, then at most one thin first-miss cure package, then at most one thin repeat-failure retreat
package, then at most one shared repair-to-portability package, then at most one watched
returned-cycle package, then at most one restoration-to-ordinary package, then at most one very
small final-settling package, and after truthful settlement later misses should simply fall back to
the ordinary promoted callback canon rather than spawning a new special relapse layer.**

That claim is now canon, but still revisable. The after-hours callback chain is provisionally closed
here: it should be reopened only if evidence shows that some class can truthfully be both **fully
settled ordinary portable status** and yet still needs a distinct post-settlement relapse package
that is neither redundant nor a disguised shadow probation.
