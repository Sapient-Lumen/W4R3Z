# Portable repeat-miss / retreat / de-portabilisation defaults for promoted after-hours service-truth profiles

This document closes the archive's next after-hours governance gap: **once a promoted after-hours
branch already carries a truthful shared callback band and has even been allowed one shared
missed-window / cure package, what happens if that portable callback promise is missed again?**

The archive's answer is narrower again:

> only a very small class of low-consequence, callback-only `OV1 + AQT-CALLBACK + ABP-BOTH` branches
may usually inherit one shared **repeat-miss / automatic retreat / de-portabilisation** package.
Consequence-bearing repeat-failure handling remains local.

That asymmetry is deliberate. The archive is trying to avoid four opposite errors at once:

- **promise persistence laundering** — a portable callback band keeps being published even after
  repeated misses have made the shared promise visibly untruthful;
- **fake-stability repair** — the service responds to repeated misses with one warm apology and a
  fresh callback target every time, instead of admitting that the portable band has failed and must
  cool;
- **over-portable discipline** — one cross-sector repeat-failure script gets pasted onto contexts
  where queue position, rights preservation, aid timing, or protected support semantics differ too
  much for shared retreat to stay honest;
- **fake-live escalation** — repeated failure of an ordinary callback branch is used to imply that
  the branch has now become a live protected route rather than a cooled local service requiring
  named owner review.

Current public signals support this thinner move. HLC's current teach-out policy still requires
student-facing clarity around applicable period, credit treatment, fees, records handling, and
discharge/refund information. OIA says providers should tell students what they need to do to
preserve position while matters remain live, update them if timeframes extend, and issue a
Completion of Procedures Letter when internal procedures end. Federal Student Aid still says FAFSA
Submission Summary amounts are estimates while the school's aid offer is the final source of truth.
ALA still frames libraries as low-barrier public access infrastructure rather than downstream
decision owners. SAMHSA still treats 988 as a genuinely live 24/7 crisis route. Together those
signals support a small archive rule: **when a thin portable callback promise is missed repeatedly,
the truthful shared move is usually to withdraw that portable promise and force named local review,
not to keep republishing the same band or simulate a live route.** See `B189`.

## Three repeat-failure portability tiers

The archive now distinguishes three repeat-failure portability tiers.

| Tier | Meaning | What travels | What stays local |
|---|---|---|---|
| `RFP-LOCAL` | no shared repeat-failure package travels | only the earlier promoted, quantitative, and first-miss tiers | the repeat-miss trigger, the cooling move, the owner review, and any re-entry logic |
| `RFP-RETREAT` | one shared repeat-miss trigger travels but the actual retreat package stays local | the basic repeat-failure definition | the de-portabilisation mechanics, owner review, rights handling, and any future re-entry |
| `RFP-BOTH` | one shared repeat-miss trigger and one shared automatic retreat package travel | the repeat-failure definition and the minimum de-portabilisation move | any rights-preserving remedy, queue protection, owner-window substitute, compensation, or re-entry to portability |

The starter canon grants only `RFP-LOCAL` and `RFP-BOTH`. `RFP-RETREAT` is reserved for a future
case where repeat-failure semantics might travel more easily than the actual retreat package does.

## Five tests before a repeat-failure package travels

A promoted after-hours branch may harden above `RFP-LOCAL` only when all five tests substantially
hold.

### 1. Same-repeat-trigger test

The same practical event must count as repeat failure across the reuse scope. If one office treats a
second miss as mere inconvenience while another treats it as queue loss, rights jeopardy, or
evidence of owner scarcity, the repeat-failure package stays local.

### 2. Same-honest-retreat test

The same minimum retreat must still be truthful across the reuse scope. A portable retreat is easier
to justify only where the honest shared move is simply to stop publishing the shared callback band,
restate that the branch is not a live route, and force named local owner review before the
portability claim can return.

### 3. No-rights-obscurity test

The shared retreat package must not hide whether any live position, deadline, or rights effect
changed because repeated misses occurred. If repeat failure interacts with complaint position, aid
timing, regulated route access, or protected support status, the retreat handling stays local.

### 4. No-fake-upgrade test

The retreat package must not quietly convert repeated ordinary callback failure into a stronger
promise, same-day owner-window claim, or implied 24/7 route. If the truthful answer is that the
branch has failed and must cool, the package must publish that cooling move rather than simulate a
hotter service.

### 5. Same-review-floor test

The same minimum post-retreat review truth must hold across the reuse scope. A shared repeat-failure
package is only plausible where the archive can truthfully say that a named local owner must review
the branch before any portable callback claim is republished, while the exact review evidence and
re-entry path remain local.

## The starter shared repeat-miss and retreat families

The archive now names one shared repeat-miss family and one shared automatic retreat family.

| Code | Meaning |
|---|---|
| `RM-CB1BD-2CONSEC` | the branch records **2 consecutive** `MW-CB1BD-CORE` misses while still publishing the shared `CB-1BD` band, with no clean kept `CB-1BD` callback in between |
| `RT-CB1BD-LOCAL-REVIEW` | immediately withdraw the shared `CB-1BD` claim, de-portabilise the branch back to `AQT-LOCAL + ABP-LOCAL`, publish one clear local service-truth update plus the next staffed owner route, and require named local owner review before any portable callback band is republished |

The archive deliberately keeps the shared retreat family thin. In the starter canon
`RT-CB1BD-LOCAL-REVIEW` does **not** include:

- automatic queue preservation;
- automatic deadline extension;
- automatic compensation, waiver, or rights-preserving cure;
- automatic same-day owner-window publication;
- automatic re-promotion back into `AQT-CALLBACK` after elapsed time alone.

Those outcomes remain local unless a separate local regime already publishes them truthfully.

## The archive's starter repeat-failure answers

### `ST-HE-TEACHOUT` may sometimes harden as `RFP-BOTH`

Where a teach-out branch has already truthfully hardened only to a **callback-only** `OV1 +
AQT-CALLBACK + ABP-BOTH` promise, the archive will usually allow one shared repeat-failure retreat
package.

The starter default is therefore:

> when `ST-HE-TEACHOUT` has already truthfully hardened only to `OV1 + AQT-CALLBACK + ABP-BOTH` with
`CB-1BD`, it may usually also inherit `RFP-BOTH` with `RM-CB1BD-2CONSEC + RT-CB1BD-LOCAL-REVIEW`.

Why the archive allows this:

- the repeat-failure event usually still means the same thing across the reusable scope — the
  learner did not receive the promised comparison / orientation callback twice in a row;
- the truthful shared retreat is still small — withdraw the shared band, admit that the portable
  callback promise is not currently holding, and send the branch back to named local owner review
  rather than pretending the promise is still trustworthy;
- the branch is still not claiming that aid, complaint, discharge, or regulator-facing consequences
  were preserved just because the callback branch previously carried a portable band.

What still stays local:

- any rights-preserving or complaint-preserving remedy;
- any compensation or fee waiver;
- any exact review timetable for regaining a portable callback promise.

### `ST-LIB-CIVIC-FIRST` may sometimes harden as `RFP-BOTH`

Where a civic or library first-contact branch has already truthfully hardened only to `OV1 +
AQT-CALLBACK + ABP-BOTH`, the archive will usually allow the same small repeat-failure retreat
package.

Why the archive allows this:

- the repeat failure usually still means only that the promised navigator / orientation callback did
  not happen twice in a row;
- the shared retreat helps stop a civic front door from continuing to publish a callback promise
  that ordinary staffing is not currently keeping;
- the shared retreat still preserves the boundary that the civic front door is not the downstream
  aid, complaint, licensure, or protected-support owner.

What still stays local:

- any downstream eligibility, seat, aid, or complaint effect;
- any stronger substitute route or emergency response;
- any timetable or evidence package for re-entering portable callback publication.

### `ST-HE-AID-CREDIT` stays `RFP-LOCAL`

Aid, credit, registration, transfer, progression, and complaint-adjacent branches keep
repeat-failure handling local.

Why the archive stops here:

- repeated callback misses can interact with deadlines, queue place, evidence submission, and
  external complaint position;
- the truthful retreat may need context-specific explanation about whether any live protection was
  lost, preserved, or had to be replaced locally;
- a shared repeat-failure package would too easily hide that the branch was already close to
  rights-bearing or consequence-bearing ownership.

### `ST-WF-PUBLIC-ROUTE` stays `RFP-LOCAL`

Public-route branches keep repeat-failure handling local too.

Why:

- route integrity and scarce-appointment meaning still vary too much across workforce and
  public-service regimes;
- repeated callback misses may implicate queue fairness, partner capacity, or public-duty ordering
  in ways a shared retreat package would conceal.

### `ST-PRO-LICENSURE` stays `RFP-LOCAL`

Licensure-sensitive branches keep repeat-failure handling local.

Why:

- repeated misses can interact with regulator, partner, or practicum timing in ways that are not
  safely abstractable into one cross-sector retreat package;
- a shared retreat could hide the fact that the branch was already too close to external-gate
  consequence to support portable callback promises comfortably.

### `ST-PROTECTED-SUPPORT` stays `RFP-LOCAL`

Protected-support routes also keep repeat-failure handling local.

Why:

- repeated missed callback promises near protected support should trigger local protected-route,
  safeguarding, or crisis-response logic rather than a reusable generic retreat shell;
- the archive does not want ordinary callback-failure grammar to blur into protected-support triage
  or to mimic a genuinely live urgent route.

## What the archive is refusing for now

The archive is intentionally declining five stronger claims:

1. any shared repeat-failure package for owner-window, queue-preserving, or rights-preserving
   branches;
2. any shared repeat-failure package that upgrades the branch into a hotter service promise instead
   of cooling it;
3. any shared repeat-failure package for aid / credit, public-route, licensure-sensitive, or
   protected-support branches;
4. any shared repeat-failure package that carries compensation, waiver, or preserved-position
   promises by default;
5. any claim that repeated misses can regain a shared callback band automatically without explicit
   local review and republication.

## Why this counted as a real archive gain

The archive already knew:

- which after-hours starter profiles begin from different service-truth postures;
- when repeated after-hours demand has earned qualitative promotion;
- which promoted branches may carry one coarse shared callback band at all;
- and which of those branches may share one thin first-miss cure package.

But it still lacked the next tighter answer:

- whether repeated misses of that portable callback promise should force one shared cooling move
  across the very small reuse scope;
- or whether even repeat failure remained too local to carry any shared retreat logic.

This revision now answers that narrower question with one small ratchet:

- three repeat-failure portability tiers;
- five tests for whether repeat-failure truth really travels;
- one tiny starter pair, `RM-CB1BD-2CONSEC + RT-CB1BD-LOCAL-REVIEW`;
- and a starter judgment that only some callback-only teach-out and civic first-contact branches
  usually carry it.

That is a real operating gain because it blocks three opposite mistakes at once:

- leaving a portable callback band in place after repeated misses have made it visibly untrue;
- forcing even low-consequence callback-only branches to reinvent the same de-portabilisation move
  locally forever;
- and treating repeat failure as permission to simulate a hotter service rather than admit that the
  portable band has failed.

## Current archive bet

The archive's current best guess is that **after-hours portability should get narrower at each
stage: starter service truth first, then sector-specific overnight defaults, then qualitative
promotion, then at most one coarse callback band, then at most one first-miss cure package, and only
after that may a very small repeat-failure retreat package sometimes travel — with only some
low-consequence callback-only teach-out and civic first-contact branches usually carrying
`RM-CB1BD-2CONSEC + RT-CB1BD-LOCAL-REVIEW` while all consequence-bearing repeat-failure handling
stays local.**

That claim is now canon, but still live. The next narrower question is whether any repeat-retreated
branch can later reclaim portable callback-band status under one shared local-repair /
re-publication package or whether portability re-entry should stay local even across the tiny
callback-only reuse scope. See `OQ-0051`.
