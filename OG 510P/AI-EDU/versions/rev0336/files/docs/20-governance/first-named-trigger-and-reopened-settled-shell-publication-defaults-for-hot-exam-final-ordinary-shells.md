# First named-trigger and reopened-settled-shell publication defaults for hot-exam final-ordinary shells

This document closes the archive's next narrower governance gap after **residual-review and
final-settled ordinary defaults**.

Three overclaims matter here:

- **every-late-trigger-reopens-everything drift** — once a shell has truthfully returned to settled
  ordinary status, the archive treats every later scoring-quality request, security concern, or
  chain exception as if it must reopen the whole ordinary shell in the same way;
- **nonadverse-sample-equals-investigation confusion** — the archive treats later requests for
  retained video or other scoring-quality samples as if they were already academic-integrity or
  misconduct findings rather than route-specific quality review; and
- **artifact-exception-goes-global drift** — the archive treats a missing-materials or return-chain
  exception as if it automatically reopens every adjacent learner-facing shell rather than the
  affected artifact shell first.

Current official signals support a tighter answer. Bluebook's current AP answer-submission pages
still keep ordinary digital closure tied to the same device, the 3-calendar-day submission window,
and the ordinary submitted token, while unresolved failures route into coordinator / incident
handling instead of a standing universal late-review owner. Current AP incident guidance still
requires the AP coordinator to submit required incident reports within 48 hours of the exam and
before returning shipments. Current AP security policy and AP Exam Terms and Conditions keep a
different later trigger visible: suspected security issues must be reported to Test Security, and
College Board may cancel scores when testing irregularities are found. Current AP Capstone policy
keeps two later portfolio triggers sharply distinct from each other: teachers must retain
presentation/oral-defense videos for at least one academic year because College Board may request
them to review scoring quality or identify samples for scoring training, while evidence of
inappropriate generative AI use or other academic-integrity concerns may trigger investigation and
requests for interim work. Current AP coordinator materials also keep missing exam materials or
other security issues involving hybrid digital or paper materials as an identified security/custody
exception requiring immediate escalation and instructions, rather than a generic review badge.
Together those signals support a narrower archive rule: **the hot final-ordinary shells may now
share one tiny named-trigger / reopened-settled-shell publication layer, but they still do not
justify one universal late-review owner, one universal reopened banner, or one universal
late-trigger workflow.** See `B215`.

This document adds one thing only:

- a **tiny named-trigger / reopened-settled-shell publication layer** for those already settled
  shells.

That means the archive now asks a different question than before. It no longer asks only **whether a
named later trigger may reopen settlement at all**. It now asks **which named later triggers should
reopen the ordinary shell visibly, which should stay route-local even after settlement, which should
reopen only the affected artifact shell rather than every adjacent shell, and what final disposition
returns the shell to settled ordinary truth**.

## Small grammar for named-trigger / reopened-settled-shell publication defaults

| Code | Meaning | Default archive action |
|---|---|---|
| `TG0-NO-UNIVERSAL-LATE-REVIEW-OWNER` | no one universal owner, banner, or workflow governs every later reopened settled shell | keep late-trigger publication shell-specific rather than inventing one generic post-settlement review office |
| `TG1-NONADVERSE-QUALITY-SAMPLE-STAYS-ROUTE-LOCAL` | a later scoring-quality or training-sample request does not by itself reopen the ordinary learner-facing shell as adverse review | keep sample-request handling inside the route-local retained-artifact layer unless the request turns into a score-affecting or integrity review |
| `TG2-INTEGRITY-OR-SECURITY-TRIGGER-REOPENS-ORDINARY-SHELL` | when an official integrity or security trigger reaches the named artifact/submission, the ordinary shell reopens as live review rather than pretending settlement still stands unchanged | publish reopened ordinary-shell review when score validity or authenticity is now officially in question |
| `TG3-CUSTODY-EXCEPTION-REOPENS-THE-AFFECTED-ARTIFACT-SHELL` | a later chain, missing-materials, or identified-custody exception reopens the affected artifact shell first rather than every neighboring shell | reopen the specific artifact/custody shell and escalate there before widening outward |
| `TG4-OFFICIAL-DISPOSITION-RETURNS-TO-SETTLED-OR-UPSTREAM` | once the named trigger resolves, the shell returns either to settled ordinary status or to whatever route-specific upstream-review / partial-closure state the official disposition actually supports | do not keep a resolved late trigger permanently visible once the official route has actually settled again |

## `TG1` — nonadverse sample requests stay route-local

`TG1-NONADVERSE-QUALITY-SAMPLE-STAYS-ROUTE-LOCAL` is the archive's smallest anti-paranoia rule.

Its point is not that later scoring-quality requests are trivial. Its point is that they are not the
same thing as a score-validity accusation.

Current AP Capstone policy says teachers must retain presentation/oral-defense videos for at least
one academic year because College Board may request them to review scoring quality, identify samples
for scoring training, and provide release-form instructions when needed. That is a real later
trigger. But it is not the same as an academic-integrity finding. So the archive now lets
retained-artifact sample requests stay inside the route-local shell unless they actually become
score-affecting review.

## `TG2` — integrity and security triggers do reopen the ordinary shell

`TG2-INTEGRITY-OR-SECURITY-TRIGGER-REOPENS-ORDINARY-SHELL` is the archive's smallest
anti-minimization rule.

Some later triggers genuinely do change the status of the ordinary shell:

- AP security policy requires suspected test-security issues to be reported to Test Security;
- AP Exam Terms and Conditions say College Board may cancel scores when testing irregularities are
  found; and
- AP Capstone policy says evidence of inappropriate generative AI use or related integrity concerns
  may trigger investigation and requests for interim work.

Those are not passive-retention facts. They are official late triggers that can affect score
validity, authenticity, or comparability. So the archive now lets them reopen the ordinary shell
visibly.

## `TG3` — custody exceptions reopen the affected artifact shell first

`TG3-CUSTODY-EXCEPTION-REOPENS-THE-AFFECTED-ARTIFACT-SHELL` is the archive's smallest anti-contagion
rule.

It stops one artifact problem from spreading farther than the official trigger actually reaches.

Current coordinator/security materials treat missing exam materials and related security issues as
identified exceptions requiring immediate instructions. That supports a narrower archive rule:
reopen the affected booklet / material shell first, not every neighboring shell automatically.

## `TG4` — official disposition decides whether the reopened shell settles again

`TG4-OFFICIAL-DISPOSITION-RETURNS-TO-SETTLED-OR-UPSTREAM` is deliberately modest.

It does not promise one universal cure. It says only this:

- if the late trigger resolves without leaving a live official defect, the shell may return to
  settled ordinary status;
- if the trigger resolves only partially, the shell should return to partial-closure or
  upstream-review truth instead; and
- if the trigger matures into score cancellation, replacement testing, or another route-specific
  official outcome, the shell should publish that outcome instead of silently snapping back to
  ordinary.

So `TG4` gives the archive a small way to end late-trigger publication honestly without inventing a
universal late-review owner.

## What the archive now publishes when using this layer

When an institution or assessment family publishes one of the hot final-ordinary shells, it should
now add only the following where truthful:

1. whether the later event is merely a retained-artifact quality-sample request, an
   integrity/security trigger, or an artifact-specific custody exception;
2. whether the ordinary shell stays settled, reopens visibly, or only the affected artifact shell
   reopens;
3. which route-specific owner or office now holds the reopened shell; and
4. whether the final official disposition returned the shell to settled ordinary truth or moved it
   into some other already-named state.

That is enough to make late-trigger handling legible without inventing one universal reopened-review
regime.

## What counted as a real archive gain

The archive already knew that settled shells could later reopen on named formal triggers. It still
lacked the next tighter answer: **which later named triggers should actually reopen the ordinary
shell, which should stay route-local even after settlement, and when a later exception should reopen
only the affected artifact shell instead of spreading everywhere.**

This document answers yes, but only barely.

It now allows the archive to publish a small shared layer for:

- nonadverse quality-sample requests that stay route-local;
- integrity/security triggers that reopen the ordinary shell;
- artifact-specific custody exceptions that reopen the affected shell first; and
- official disposition that either settles the shell again or leaves it in some other already-named
  state.

That is a real operating gain because it blocks four opposite mistakes at once:

- treating every possible later request as a visible reopened review;
- treating nonadverse scoring-quality requests as if they were misconduct findings;
- letting one identified custody problem contagiously reopen every neighboring shell; and
- leaving reopened settled shells without any truthful way to become settled again once official
  disposition arrives.
