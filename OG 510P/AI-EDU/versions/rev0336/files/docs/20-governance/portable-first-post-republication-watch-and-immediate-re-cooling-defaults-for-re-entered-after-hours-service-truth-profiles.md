# Portable first-post-republication watch and immediate re-cooling defaults for re-entered after-hours service-truth profiles

This document closes the archive's next after-hours governance gap: **once a repeat-retreated
callback-only after-hours branch has already regained portable callback publication under one shared
local-repair / fresh-republication package, can that first newly republished callback cycle itself
carry one shared watch / immediate re-cooling package, or should first-cycle relapse handling remain
local even though portable status has technically returned?**

The archive's answer is narrower again:

> only a very small class of low-consequence, callback-only `OV1 + AQT-CALLBACK + ABP-BOTH +
RFP-BOTH + ARP-BOTH` branches may usually inherit one shared **first-post-republication watch /
immediate re-cooling** package. Consequence-bearing first-cycle relapse handling stays local.

That asymmetry is deliberate. The archive is trying to avoid four opposite errors at once:

- **instant-normalisation drift** — a branch treats regained portable callback publication as though
  it were already ordinary settled trust even though the first returned cycle is where relapse is
  most likely;
- **shadow-watch laundering** — the archive publishes one shared re-entry package, but the first
  returned cycle is still being governed by unpublished local caution, owner doubt, or extra relapse
  triggers that the portable story conceals;
- **permanent probation** — a branch whose first returned callback cycle really can carry one small
  shared watch package never earns it and therefore has to rebuild the same temporary caution layer
  locally forever;
- **fake-live rebound** — the first returned callback cycle is described in a way that makes a thin
  callback promise sound like same-day owner action, rights preservation, or 24/7 readiness.

Current public signals support that thinner move. HLC's current teach-out policy still treats
communications, credit treatment, time period, fees, and records as governed student-facing
commitments. OIA's current good-practice materials still expect providers to tell students what they
must do to preserve position while matters remain live, to keep them updated if timeframes extend,
and to issue a Completion of Procedures Letter promptly once internal procedures end. Federal
Student Aid still says the school's aid offer is the best source of truth rather than earlier
estimates. SAMHSA still treats 988 as a genuinely live 24/7 crisis route. Together those signals
support a small archive rule: **portable callback publication may return before ordinary trust
returns, so the first republished cycle may need one explicit watched-probation layer rather than
silent normalisation.** See `B191`.

## Three first-post-republication watch portability tiers

The archive now distinguishes three first-post-republication watch portability tiers.

| Tier | Meaning | What travels | What stays local |
|---|---|---|---|
| `RWP-BOTH` | the re-entered branch carries one shared watched-cycle floor and one shared immediate re-cooling trigger family | the fact that the first republished callback cycle is still probationary and the minimal trigger family that collapses it back to local cooling before a second portable cycle begins | any stricter local reviewer, any extra local checkpoint, and any stronger local warning or challenge route |
| `RWP-WATCH` | the re-entered branch carries only one shared watched-cycle floor | the fact that renewed callback portability is still watched for one cycle | the actual relapse / re-cooling trigger family and any local watch record |
| `RWP-LOCAL` | the re-entered branch carries no shared first-post-republication watch package | only the earlier promotion, quantitative, miss, retreat, and re-entry tiers | both the watched-cycle floor and the immediate re-cooling package |

The archive is deliberately asymmetric again:

> first-post-republication watch portability is harder to earn than re-entry portability. A branch
can carry one shared `LR-CB1BD-1KEPT + RG-CB1BD-FRESH-REENTRY` package while the truth about the
**first returned callback cycle** still remains local.

## Five tests for whether first-post-republication probation truth really travels

A re-entered after-hours callback-only branch may harden above `RWP-LOCAL` only when all five tests
hold.

### 1. Same-first-cycle-object test

The watched cycle must still be repairing the same practical object across the reuse scope: an
ordinary callback promise, not queue preservation, rights protection, complaint timing, or
protected-support response.

### 2. Same-probation-meaning test

Saying that the first republished callback cycle is still watched must mean the same thing across
the reuse scope: portable callback wording is live again, but not yet ordinary settled trust.

### 3. Same-immediate-re-cooling-truth test

The minimal relapse family for collapsing the first returned cycle back to local cooling must be
describable in one reusable way without concealing local queue effects, owner-family caution, or
rights-bearing side conditions.

### 4. No-shadow-watch test

The shared package must not make one owner's unpublished caution, staffing fragility, or extra
sign-off look like ordinary portable monitoring when the real first-cycle scrutiny still differs
materially by branch family.

### 5. Same-second-cycle-admission boundary test

Clearing the watched cycle must mean the same thing for admission to a second portable callback
cycle across the proposed scope rather than still depending on local sign-off, local consequence
review, or local owner-confidence evidence that the shared package would hide.

Failing the first, third, fourth, or fifth test keeps the branch at `RWP-LOCAL`. Failing only the
third may eventually point toward `RWP-WATCH`, but the starter canon does not yet use that middle
tier.

## The starter first-post-republication watch package

The archive now names one shared watched-cycle floor and one shared immediate re-cooling package.

| Code | Meaning |
|---|---|
| `PW-CB1BD-1RETURN` | the **first cycle after portable `CB-1BD` publication returns** runs as a watched portable cycle rather than as ordinary settled trust |
| `RC-CB1BD-LOCAL` | during that watched cycle, any missed callback against the republished band, fresh owner-window inflation, new queue/rights/protected-route consequence, or unresolved owner-scarcity relapse immediately collapses the path back to local cooling before a second portable callback cycle may begin |

The starter canon stays intentionally thin:

- no re-entered after-hours branch currently becomes fully ordinary on the same cycle that portable
  callback publication returns;
- no re-entered after-hours branch currently carries one shared "second chance inside the watched
  cycle" rule;
- where the archive refuses a shared first-post-republication watch package, services must still
  publish a **local** watched-cycle or post-re-entry relapse rule, or say plainly that renewed
  callback portability remains owner-local after return.

## The archive's starter first-post-republication watch answers

### `ST-HE-TEACHOUT` may sometimes harden as `RWP-BOTH`

Where a teach-out branch has already truthfully returned to portable callback publication under
`LR-CB1BD-1KEPT + RG-CB1BD-FRESH-REENTRY`, the archive will usually allow one shared watched first
cycle.

The starter default is therefore:

> when `ST-HE-TEACHOUT` has already truthfully re-entered portable callback publication under
`ARP-BOTH`, it may usually also inherit `RWP-BOTH` with `PW-CB1BD-1RETURN + RC-CB1BD-LOCAL`.

Why the archive allows this:

- the watched object is still usually the same thing across the reuse scope — an ordinary
  orientation / teach-out callback promise rather than a rights-bearing decision clock;
- the difference between "portable again" and "ordinary again" usually means the same thing here
  too: the callback band is back, but the first returned cycle still has to prove the repair holds;
- the minimal relapse family is also still thin enough to travel: if the republished callback is
  missed again, inflated into hotter owner timing, or drifts back toward consequence-bearing
  routing, portability should cool immediately rather than coast into a second cycle.

What still stays local:

- any compensation, fee-waiver, or complaint-preserving remedy;
- any stronger owner-window or queue-preserving promise;
- any rule for when post-watch ordinary status fully returns.

### `ST-LIB-CIVIC-FIRST` may sometimes harden as `RWP-BOTH`

Civic or library first-contact branches may usually inherit the same small watched-cycle package
after callback portability returns.

Why the archive allows this:

- the watched object usually still means only a navigator / orientation callback promise;
- the first returned cycle usually carries the same thin risk story across the reuse scope — renewed
  callback wording may be live again, but it is not yet ordinary settled trust;
- immediate re-cooling truth also remains narrow enough to travel: another miss, silent drift toward
  downstream ownership, or unexpected consequence-bearing use means the callback band should cool
  locally again.

What still stays local:

- any downstream eligibility, seat, aid, complaint, or protected-support effect;
- any stronger substitute path or urgent route;
- any later restoration-to-ordinary rule once the watched cycle ends.

### `ST-HE-AID-CREDIT` stays `RWP-LOCAL`

Aid, credit, registration, transfer, progression, and complaint-adjacent branches keep
first-post-republication watch local.

Why the archive stops here:

- once those branches have already repeat-failed, retreated, and then re-entered, the meaning of a
  "watched first returned cycle" is still too entangled with deadlines, queue place, evidence
  windows, and consequence-bearing ownership;
- a shared watch package would too easily hide that renewed callback wording may still be sitting
  next to rights-bearing timing.

### `ST-WF-PUBLIC-ROUTE` stays `RWP-LOCAL`

Public-route branches also keep first-post-republication watch local.

Why:

- the watched-cycle meaning still varies too much with public queue fairness, scarce appointment
  exposure, and cross-agency owner scarcity;
- one shared relapse family would overstate how much first-cycle trust really travels here.

### `ST-PRO-LICENSURE` stays `RWP-LOCAL`

Licensure-sensitive branches keep first-post-republication watch local.

Why:

- regulator timing, practicum dependency, and partner approval exposure still make a watched first
  returned cycle materially unlike the same cycle in low-consequence callback-only contexts;
- a shared watch package would understate how close the branch remains to consequential error.

### `ST-PROTECTED-SUPPORT` stays `RWP-LOCAL`

Protected-support routes also keep first-post-republication watch local.

Why:

- once a protected-support-adjacent branch has already repeat-failed and cooled, any callback
  restoration still sits too close to safeguarding, crisis, or protected-route readiness to reuse
  one generic watched first cycle;
- the archive does not want a temporary callback return package to blur with genuine live support
  readiness.

## What the archive is refusing for now

The archive is intentionally declining five stronger claims:

1. any shared watch package that treats fresh republication itself as full restoration to ordinary
   trust;
2. any shared watch package that allows a second portable callback cycle to begin automatically
   after one returned cycle without an explicit watched boundary;
3. any shared first-post-republication watch package for aid / credit, public-route,
   licensure-sensitive, or protected-support branches;
4. any shared package that treats another callback miss during the watched cycle as compatible with
   staying portable;
5. any claim that a watched first returned cycle already settles when ordinary post-repair trust
   should expire, relax, or fully normalize.

## Why this counted as a real archive gain

The archive already knew:

- which after-hours starter profiles begin from different service-truth postures;
- when repeated after-hours demand has earned qualitative promotion;
- which promoted branches may carry one coarse shared callback band;
- which of those branches may share one thin first-miss cure package;
- which of those branches may share one thin repeat-failure retreat package;
- and which of those branches may later regain portable callback publication under one shared
  kept-local-cycle plus fresh-republication package.

But it still lacked the next tighter answer:

- whether the first cycle **after** callback-band return could itself carry one shared watch /
  immediate re-cooling package;
- and whether the archive should distinguish the tiny reuse scope where that probation truth travels
  from the larger set of branches where first-cycle relapse handling still depends too heavily on
  local review.

This revision now answers that narrower question with one small ratchet:

- three first-post-republication watch portability tiers;
- five tests for whether watched first-cycle truth really travels;
- one tiny starter package, `PW-CB1BD-1RETURN + RC-CB1BD-LOCAL`;
- and a starter judgment that only some callback-only teach-out and civic first-contact branches
  usually carry it.

That is a real operating gain because it blocks three opposite mistakes at once:

- treating callback-band return as though ordinary trust had already returned;
- making low-consequence callback-only branches carry bespoke first-cycle caution forever even where
  the probation story is actually stable enough to travel;
- and letting a republished callback band drift silently back into consequence-bearing or fake-live
  meaning before the archive has one explicit re-cooling rule.

## Current archive bet

The archive's current best guess is that **after-hours portability should get stricter at each
stage: starter service truth first, then sector-specific overnight defaults, then qualitative
promotion, then at most one coarse callback band, then at most one first-miss cure package, then at
most one repeat-failure retreat package, then at most one kept-local-cycle plus fresh-republication
package, and only after that may a very small first-post-republication watch package sometimes
travel — with only some low-consequence callback-only teach-out and civic first-contact branches
usually carrying one shared `PW-CB1BD-1RETURN + RC-CB1BD-LOCAL` package while all
consequence-bearing first-cycle relapse handling stays local.**

That claim is now canon, and the archive now answers the next step in
[`portable-probation-expiry-and-ordinary-status-restoration-defaults-for-re-entered-after-hours-service-truth-profiles.md`](portable-probation-expiry-and-ordinary-status-restoration-defaults-for-re-entered-after-hours-service-truth-profiles.md).
The next narrower question is which restored-to-ordinary callback-only branches, if any, can safely
carry one shared **recent-return sensitivity-expiry / fully-settled ordinary-status package** after
a clean first ordinary portable cycle, and which should keep the final settling boundary local. See
`OQ-0054`.
