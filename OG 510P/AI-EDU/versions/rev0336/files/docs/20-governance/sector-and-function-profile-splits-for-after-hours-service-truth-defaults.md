# Sector-and-function profile splits for after-hours service-truth defaults

This document closes the archive's next implementation gap about **which after-hours service-truth
defaults already start from different honest postures across sectors and function families**.

The archive now has a small service-truth shell for after-hours or delayed-owner child branches:

- `TV0-TV4` for what is truly live now;
- `AY0-AY4` for what acknowledgement is owed now;
- `AN0-AN4` for what the learner should do now.

What it still needed was a **starter profile layer** for contexts where the same visible after-hours
branch should already begin from a different honesty floor because route closure, aid timing, queue
protection, licensure separation, or protected support intensity are knowable in advance.

The archive's current bet is:

> a generic after-hours service-truth shell is not enough; teach-out, aid / credit help,
public-route routing, civic first contact, licensure-sensitive guidance, and protected support
should not all begin from the same overnight promise.

Current public signals point the same way. HLC's current teach-out policy still requires distinct
learner-facing fields about applicability period, credit treatment, tuition and fees, records
retention, and communications. Federal Student Aid still says FAFSA Submission Summary amounts are
estimates while each school's aid offer is the final determination and best source of truth. The
public workforce system still combines employment, education, training, and support services under
WIOA. ALA still frames libraries as public access infrastructure serving people across language,
income, education, disability, and geographic barriers. The U.S. Department of Education still
describes professional licensure as state-specific rather than automatically implied by ordinary
programme completion. SAMHSA still treats 988 as a genuine 24/7 live crisis route. Together those
signals support a small archive rule: **different sectors should start from different after-hours
truth defaults before local packet custom begins**. See `B185`.

## Relationship to the generic after-hours service-truth shell

This document does not replace
[`availability-acknowledgement-and-action-now-fields-for-after-hours-split-lane-branches.md`](availability-acknowledgement-and-action-now-fields-for-after-hours-split-lane-branches.md).

It adds one thing only:

- a **starter profile layer** for places where the archive already knows the generic `TV` / `AY` /
  `AN` shell should begin hotter, cooler, or more separate.

The generic shell still answers the first question:

- is the branch pointer-only,
- browse-only,
- intake-now / owner-later,
- intake-now with immediate protection,
- or genuinely live now?

This document answers the second question:

- in this sector-and-function context, which combination should the archive treat as the honest
  starting posture before local branching or promotion?

## The starter profile table

The archive keeps this table intentionally small. These are **starter inherited profiles**, not full
local procedures.

| Profile | Scope | Typical starting posture | May rise to | Should usually avoid | Why the split exists |
|---|---|---|---|---|---|
| `ST-HE-TEACHOUT` | higher-ed teach-out, closure, continuity, and substitute-route packets that remain visible after hours | usually `TV1 + AY0 + AN0` for reading/comparison, or `TV2 + AY2 + AN1` where after-hours submission only starts receipt plus next-owner-window truth | `TV3 + AY3 + AN2` only where the institution has already published a truthful hold, pause, or no-loss continuity effect that begins on receipt | `TV4` unless a genuinely staffed after-hours owner exists; any packet that implies money, complaint, or regulator lanes are live just because the continuity notice is visible | teach-out packets often need to stay visible outside office hours, but HLC still treats credit, fee, records, and communications facts as distinct governed commitments rather than one vague continuity promise |
| `ST-HE-AID-CREDIT` | higher-ed aid, registration, transfer, and progression help inside live windows | usually `TV2 + AY2 + AN1`; the learner may submit now and should be told when the accountable office next reviews | `TV3 + AY3 + AN2` only where published local policy says receipt now preserves queue place, pending status, or deadline protection until staffed review | generic `TV3` by default, because FAFSA summaries, aid offers, transfer monitoring, and complaint clocks often have different owners and anchors | the overnight truth here is usually "received now, reviewed later" rather than "decision started now" or "rights preserved now" unless a specific protected rule exists |
| `ST-WF-PUBLIC-ROUTE` | workforce, adult-route, funded-seat, referral, or public-route packets spanning intake, training, and support services | usually `TV2 + AY2 + AN1`; where funded-seat, mandated-participation, or queue-integrity rules are already published, the profile may start at `TV3 + AY3 + AN2` | `TV4 + AY4 + AN3/AN4` only for a named live public or crisis route that is truly staffed now | pointer-only treatment for services that actually require timely place-holding, and false unified ownership where different agencies or funders act next | WIOA deliberately joins education, training, employment, and support services, so overnight routing may matter materially even when final owner action waits until the next staffed window |
| `ST-LIB-CIVIC-FIRST` | public-library, civic, and low-barrier first-contact routes used for orientation, digital access, and warm transfer | usually `TV0 + AY0 + AN0` or `TV1 + AY0 + AN0`; at most `TV2 + AY1 + AN1` for a simple callback or contact request | narrow `TV2` where a library or civic node truthfully accepts a request for later follow-up | `TV3` or `TV4` for benefits, aid, complaint, licensure, or sanctions handling that the civic node does not own | civic first-contact routes should stay welcoming and low-barrier, but they should not impersonate the downstream office that owns eligibility, money, or formal remedy |
| `ST-PRO-LICENSURE` | licensure-sensitive educational routes where programme completion, approval, and state-board treatment can diverge | usually `TV1 + AY0 + AN0` for reading/comparison or `TV2 + AY2 + AN1` for owner-routed questions | narrow `TV3` only where a named owner can truthfully preserve a local filing position or internal review place without implying state-board rights are preserved | broad `TV3` or `TV4` inherited by default, because licensure obligations often sit outside ordinary programme ownership and may vary by state | state-specific licensure means after-hours packets should usually cool or split before they imply that one campus-facing intake preserves every downstream licensing consequence |
| `ST-PROTECTED-SUPPORT` | crisis, acute wellbeing, immediate safety, or protected support routes | the ordinary shared packet should usually retreat to `TV0 + AY0 + AN3`, pointing to the genuinely live protected route; where the protected route itself is the visible branch, start at `TV4 + AY4 + AN3/AN4` | no hotter ordinary packet; the growth path is route separation, not richer imitation | `TV2` or `TV3` as a substitute for live urgent/protected help | protected support is the place where the archive most strongly rejects fake overnight ownership; either the route is really live, or the ordinary packet should say where the live route is |

## How to read these starter profiles

These profiles are **overlays**, not replacements.

The generic after-hours shell still answers the first question:

- what is live now,
- what receipt is owed now,
- what action the learner should take now?

This document answers the second question:

- in this sector or function, does the archive already know that the honest starting combination
  should be cooler, more receipt-bound, more queue-protective, or more separate?

That means superficially similar after-hours forms may inherit different defaults:

- a higher-ed continuity packet may honestly accept receipt now while keeping later aid and
  complaint ownership separate;
- a public-route intake may sometimes preserve queue position on receipt because the route itself is
  a scarce public pipeline;
- a library first-contact form should usually stay pointer/browse-first even if it sits on the same
  website as deeper public services;
- a licensure-sensitive path should usually cool or split before implying one campus intake
  preserves state-board consequences;
- and protected support should usually retreat to the genuinely live route rather than simulating
  it.

## Cross-sector interpretation rules the archive now treats as knowable in advance

### 1. `TV3` is scarce and should be evidence-bearing

Immediate queue, hold, pause, or rights protection should not be the generic overnight default. Use
`TV3 + AY3 + AN2` only where a published rule already says receipt itself starts that protection.

### 2. Public-route queue integrity is different from ordinary office courtesy

The archive now treats `ST-WF-PUBLIC-ROUTE` as the most likely ordinary context to begin at or rise
quickly to `TV3`, because funded-seat or mandated-route timing can turn overnight intake into real
continuity protection.

### 3. Civic first contact should stay warm without impersonating authority

A library or civic node may orient, translate, or warm-transfer, but should not quietly inherit the
service-truth posture of aid, eligibility, complaint, licensure, or sanction owners merely because
it is the learner's first visible door.

### 4. Licensure-sensitive routes should split early when state or external-board facts matter

Where the next consequences depend on a state board, regulator, or external practice rule, the
archive now prefers cooling or lane separation over generic overnight protection promises.

### 5. Protected support should separate rather than simulate

Where the honest next step is a live crisis or protected channel, the ordinary packet should usually
point there directly or become that route. It should not publish `TV2` or `TV3` merely to avoid
visible retreat.

## What institutions should publish

Where a visible after-hours branch inherits one of these profiles, publish one extra line with only
six additions beyond the generic `TV` / `AY` / `AN` shell:

1. profile identifier (`ST-HE-TEACHOUT` through `ST-PROTECTED-SUPPORT` or local equivalent);
2. whether the profile is inherited unchanged or locally cooled / heated;
3. which starting `TV` / `AY` / `AN` combination is in force;
4. what fact lets the branch claim any immediate queue, hold, pause, or rights-preserving effect;
5. which office, agency, or protected route acts next;
6. what visible retreat happens if that promise can no longer be kept.

This keeps the packet layer small while stopping the common failure where one generic after-hours
shell is pasted onto contexts that actually owe different overnight truths.

## What counted as a real archive gain

The archive previously knew how any after-hours child branch should name service truth in the
abstract. It still lacked a compact answer to a harder operational question: **which contexts should
already begin from different truth defaults before local packet custom starts improvising?**

This document answers that with a bounded starter layer. It keeps the generic `TV0-TV4` / `AY0-AY4`
/ `AN0-AN4` grammar, but it now makes the archive more deployable across higher-ed continuity, aid /
credit windows, public-route routing, civic first contact, licensure-sensitive educational routes,
and protected support without pretending those contexts share one honest overnight promise.

## Current archive bet

The archive's current best guess is that a **generic after-hours service-truth shell plus a tiny
sector-and-function starter profile layer** will outperform both extremes:

- one universal overnight script for all visible child branches;
- and bespoke packet writing for every office with no inherited defaults.

That claim is now canon, but still live. The next problem is narrower: which repeated `TV2` / `TV3`
starter-profile branches have earned promotion into published callback-slot, same-day owner-window,
or hotter `HC` coverage expectations, and when repeated overnight protection claims should instead
cool back, split further, or retreat to separate live service routes. See `OQ-0047`.
