# First post-dewatch relapse and repaired-route memory defaults for hot-exam recipient followup shells

The archive can now publish one still smaller layer for the hottest exam-like learner-request
routes.

It can already say:

- when route-pair relapse after deconflict exit crosses a bounded rewatch threshold;
- what the opened rewatch is actually doing;
- what owner, recipient, protected-route, source, search, archive, proof-object, clock, or redesign
  repair proof is current;
- what learners can safely do while the rewatch operates; and
- how the rewatch exits, de-watches, splits, redesigns, becomes residue, or minimizes repair memory.

That is still not enough.

After dewatch, the temptation changes again. A later recurrence can be treated as proof that the
repaired route pair was never trustworthy. The opposite error is just as dangerous: because the
rewatch label ended and the public proof was minimized, the shell can pretend no repair history
exists. A recipient correction can reverse. A protected-route correction can reappear only inside a
local accommodation or appeal channel. A search result or archive slice can reappear after
route-native expiry. A redesign handoff can fail silently. A retired-route residue can revive. A
no-active-route residue can expose a current owner. Or the apparent relapse can be only ordinary
downstream lag with no learner-facing dependency.

This document adds one thing only:

- a **tiny post-dewatch relapse / repaired-route memory field set** for hot-exam recipient followup
  shells after `YV0-YV4` has exited, de-watched, split, redesigned, retired, become no-active-route
  residue, or minimized repair memory, but before the archive treats a later event as automatic
  rewatch, fresh first-cycle conflict, repeat relapse, redesign failure, recipient-record
  correction, protected-route reopening, retired-route revival, or ordinary lag.

That means the archive now asks a narrower question than before. It no longer asks only **how a
rewatch operation proves repair and exits**. It now asks **what happens after dewatch if the same
route pair or affected surface later relapses, if repair proof ages, if minimized rewatch memory
must be recalled, or if a learner again faces ambiguous action — without making every later
recurrence automatic rewatch, permanent route-pair stigma, duplicate filing, public repair-vault
revival, or total fresh-start amnesia**.

Current official signals support a deliberately narrow answer. Google Search Console's Removals tool
exposes property-owner, exact-URL, current/expired-history, temporary-removal, cancellation,
about-six-month, Google-Search-only, and source-side-permanent-method boundaries rather than a
durable dewatch certificate. Google's Refresh Outdated Content route is exact page/image URL,
changed/gone-content, queue/status, and 180-day-expiry based rather than a permanent all-copy repair
memory. Google's personal-content routes keep Search removal, source-page removal, screenshot proof,
notifications, new-result handling, and sensitive proof separate. WiscWeb separates local source
edits, emergency edits, primary-contact follow-up, campus-search and lookahead ownership,
redirection, caching, and major-search-engine non-control. Princeton separates local deletion,
document/media cleanup, access control, cache behavior, Google/Bing/custom-search handling, and
Wayback persistence. Rowan separates CMS ownership, Web Services support, Siteimprove/accessibility
monitoring, contributor training, content-audit/redesign work, support tickets, and accommodation
routing. Internet Archive asks for URL, time-period, control-period, and review context before
exclusion. Bing distinguishes temporary block, up-to-90-day expiry, cached/outdated-content
handling, exact URL submission, extension or permanent-removal prerequisites, and source-side
methods such as 404/410 or noindex. Together those signals support a tighter archive rule: **the
next truthful portability gain here is one tiny repaired-route memory layer for dewatch-exit basis,
relapse signal, scoped memory recall, current proof age, learner-safe action, disposition,
reminimization, and reopen triggers — but not one automatic rewatch, one public repaired-route
dossier, one duplicate-filing duty, one all-engine repair certificate, or one no-memory reset.** See
`B266`.

## Small field set for post-dewatch relapse and repaired-route memory

| Code | Meaning | Default archive action |
|---|---|---|
| `YW0-NO-AUTOMATIC-REWATCH-PERMANENT-STIGMA-DUPLICATE-FILING-PUBLIC-VAULT-OR-AMNESIA` | a later recurrence after dewatch can matter, but it does not automatically reopen watch, publish stigma, force duplicate filing, revive the public proof vault, or erase repair memory | require a current relapse signal, prior dewatch basis, affected repaired-route scope, recall authority, current proof age, and learner action-now truth before widening beyond ordinary post-dewatch publication |
| `YW1-PUBLISH-DEWATCH-EXIT-BASIS-RELAPSE-SIGNAL-AND-REPAIRED-SCOPE` | the shell must say what the rewatch had repaired or minimized, and what has now changed | publish the prior `YV0-YV4` exit state, affected route pair or surface, current relapse signal, materiality, and whether the event is same-route relapse, repaired proof aging, protected or recipient correction recurrence, retired-route revival, no-active-route owner discovery, or ordinary lag |
| `YW2-RECALL-REPAIRED-ROUTE-MEMORY-ONLY-FOR-CURRENT-NAMED-DEPENDENCY` | old repair proof can be used as scoped memory, not as a public dossier or automatic learner fault history | recall only the minimum prior repair summary needed for a current owner, recipient, protected route, appeal, official record, redesign, source/search/archive route, clock, or learner-remedy decision; keep sensitive proof local-only or redacted |
| `YW3-PUBLISH-CURRENT-PROOF-AGE-OWNER-STATUS-AND-LEARNER-SAFE-ACTION` | post-dewatch handling depends on current proof, not stale screenshots, expired request rows, or old dewatch closure alone | publish whether proof is current, aged, mismatched, source-only, search-only, archive-only, owner-confirmed, recipient-confirmed, protected/local-only, unresolved, or insufficient; publish no-action, one-safe-route, dual-route-recognition, longer-window, protected local-only action, wait, or owner-only action accordingly |
| `YW4-PUBLISH-POST-DEWATCH-DISPOSITION-REMINIMIZATION-AND-REOPEN-TRIGGERS` | a post-dewatch relapse should close, split, reopen, redesign, become residue, or minimize on named facts instead of lingering as repaired-route history | publish ordinary lag, non-material close, fresh first-cycle handling, repeat-relapse threshold candidate, reopened rewatch, repair refresh, route split retained, redesign handoff, protected-route retained, recipient-record correction, retired-route revival, no-active-route residue, reminimized memory, local-only memory retained, or reopen only on material new route, owner, proof, clock, recipient, protected-route, source, search, archive, or official-record facts |

## Field values that now travel together

When this layer is used, the shell should publish only six concrete fields:

1. `post_dewatch_relapse_signal_token` — `none`, `same repaired route pair relapsed`, `repaired
   route proof aged`, `repair proof contradicted`, `recipient correction reappeared`,
   `official-record correction reversed`, `protected route reappeared`, `source page reappeared`,
   `Google result reappeared`, `Bing or partner-search result reappeared`, `image result
   reappeared`, `archive or mirror reappeared`, `redesign handoff failed`, `retired-route residue
   revived`, `no-active-route residue gained owner`, `ordinary lag only`, `unrelated new path`,
   `none inherited`, or `not published`;
2. `prior_dewatch_exit_and_repair_scope_token` — `ordinary route pair returned`, `route pair
   repaired`, `recipient-record correction completed`, `official-record correction completed`,
   `protected route retained`, `route split retained`, `dual-route recognition retained`, `redesign
   handoff completed`, `retired-route residue`, `no-active-route residue`, `rewatch closed after
   clean cycle`, `rewatch closed after repair proof`, `operation closed without learner action`,
   `prior dewatch not found`, `none inherited`, or `not published`;
3. `repaired_route_memory_recall_token` — `no recall needed`, `current repair owner recall`,
   `successor owner recall`, `recipient-of-record recall`, `protected owner recall`, `appeal or
   complaint route recall`, `official-record owner recall`, `redesign owner recall`, `source owner
   recall`, `search or archive route recall`, `redacted public pointer`, `local-only proof recall`,
   `aggregate memory only`, `screenshot-only not enough`, `expired status row not enough`, `no
   authority to recall`, `none inherited`, or `not published`;
4. `current_repair_proof_and_age_token` — `current owner proof`, `current reciprocal owner proof`,
   `current recipient proof`, `current official-record proof`, `current protected proof local-only`,
   `current source proof`, `current search status`, `current archive status`, `current redesign
   proof`, `proof aged but usable`, `proof aged and insufficient`, `proof mismatched`, `proof
   partial`, `proof expired`, `proof disappeared`, `proof contradicted`, `proof unavailable`, `none
   inherited`, or `not published`;
5. `learner_safe_action_after_dewatch_relapse_token` — `none current`, `information-only notice`,
   `wait for owner confirmation`, `use repaired route`, `use replacement route`, `use revived
   route`, `submit once with dual-route recognition`, `do not duplicate filing`, `use more
   protective route until resolved`, `use longer current window until resolved`, `protected
   local-only submission`, `manual local support only`, `owner-only action`, `formal appeal route
   only`, `none inherited`, or `not published`;
6. `post_dewatch_disposition_and_memory_token` — `ordinary lag only`, `non-material close`, `fresh
   first-cycle conflict`, `repeat-relapse threshold candidate`, `reopen bounded rewatch`, `repair
   refresh requested`, `recipient or record correction opened`, `protected route retained`, `route
   split retained`, `dual-route recognition retained`, `redesign handoff`, `retired-route revival
   review`, `no-active-route residue`, `reminimized memory`, `local-only memory retained`, `reopen
   only on material new fact`, `none inherited`, or `not published`.

## Minimal publication sentence

A learner-facing or owner-facing shell can stay compact:

> This route pair de-watched as `[prior_dewatch_exit_and_repair_scope_token]`. The current signal is
`[post_dewatch_relapse_signal_token]`. Repair memory is `[repaired_route_memory_recall_token]`;
current proof is `[current_repair_proof_and_age_token]`. Learner action now is
`[learner_safe_action_after_dewatch_relapse_token]`. Current disposition is
`[post_dewatch_disposition_and_memory_token]`.

If public publication would expose protected, privacy-sensitive, accommodation, appeal, security, or
record-controlled proof, publish only the owner, action-now truth, and a redacted or local-only
memory token.

## Default interpretation rules

1. **Dewatch is not a permanent certificate.** It records that a bounded operation ended on named
   proof or a clean cycle. It does not prove that every source, search, archive, recipient,
   protected-route, or official-record surface can never relapse.
2. **Relapse is not automatic rewatch.** A later event reopens watch only when it is material to a
   current owner, recipient, proof object, clock, protected route, official record, or learner
   action.
3. **Repair memory is scoped memory, not public stigma.** Minimized proof can be recalled only for a
   named current need and only at the smallest scope needed to preserve the current decision.
4. **Aged proof must be labelled.** Expired request rows, stale screenshots, old owner assertions,
   and disappeared status pages can support an as-of memory pointer, but they do not become current
   repair authority without a current owner or route-native proof basis.
5. **Learners should not pay for owner ambiguity.** Duplicate filing, wrong-route fault, adverse
   clock movement, and route-choice penalty require current proof and route-native authority;
   otherwise publish no action, one safe filing, dual-route recognition, longer window, protected
   local support, or owner-only action.
6. **The relapse must dispose of itself.** A shell should close as ordinary lag, fresh first-cycle
   handling, repeat-threshold candidate, reopened rewatch, repair refresh, redesign, split, residue,
   recipient correction, protected-route retention, or reminimized memory rather than remain a
   public repaired-route warning forever.

## Worked examples

### Example A — dewatched search reflection only

A rewatch closed after the source owner removed an old page and the replacement route controlled.
Five weeks later, a Google result briefly shows the retired URL again. The source page remains gone,
the recipient portal accepts the repaired route, and no learner action depends on the old result.

Publish:

- `post_dewatch_relapse_signal_token = Google result reappeared`;
- `prior_dewatch_exit_and_repair_scope_token = route pair repaired`;
- `repaired_route_memory_recall_token = redacted public pointer`;
- `current_repair_proof_and_age_token = current search status`;
- `learner_safe_action_after_dewatch_relapse_token = use repaired route`; and
- `post_dewatch_disposition_and_memory_token = ordinary lag only`.

Do not reopen rewatch merely because a downstream search reflection lags.

### Example B — recipient correction reverses after dewatch

A rewatch exited after the recipient-of-record confirmed that one route and one clock controlled. In
the next cycle, the recipient portal again accepts the retired route while the official record owner
still publishes the repaired clock.

Publish:

- `post_dewatch_relapse_signal_token = recipient correction reappeared`;
- `prior_dewatch_exit_and_repair_scope_token = recipient-record correction completed`;
- `repaired_route_memory_recall_token = recipient-of-record recall`;
- `current_repair_proof_and_age_token = proof mismatched`;
- `learner_safe_action_after_dewatch_relapse_token = submit once with dual-route recognition`; and
- `post_dewatch_disposition_and_memory_token = repeat-relapse threshold candidate`.

Do not force duplicate learner filing unless a current recipient authority names that duty and
protects the learner against duplicate-clock harm.

### Example C — protected route reappears with sensitive proof

A protected accommodation route was retained locally and the public route was repaired. After
dewatch, a public replacement page again contradicts the protected local route. The proof needed to
resolve the conflict includes sensitive accommodation facts.

Publish:

- `post_dewatch_relapse_signal_token = protected route reappeared`;
- `prior_dewatch_exit_and_repair_scope_token = protected route retained`;
- `repaired_route_memory_recall_token = protected owner recall`;
- `current_repair_proof_and_age_token = current protected proof local-only`;
- `learner_safe_action_after_dewatch_relapse_token = protected local-only submission`; and
- `post_dewatch_disposition_and_memory_token = protected route retained`.

Do not move protected proof into the public repaired-route memory layer.

### Example D — no-active-route residue gains an owner

A rewatch exited as no-active-route residue because the route owner had disclaimed control and no
successor existed. Later, a new owner publishes a support path for the same affected surface.

Publish:

- `post_dewatch_relapse_signal_token = no-active-route residue gained owner`;
- `prior_dewatch_exit_and_repair_scope_token = no-active-route residue`;
- `repaired_route_memory_recall_token = successor owner recall`;
- `current_repair_proof_and_age_token = current owner proof`;
- `learner_safe_action_after_dewatch_relapse_token = wait for owner confirmation` or `use repaired
  route`; and
- `post_dewatch_disposition_and_memory_token = repair refresh requested`.

Do not treat the old no-active-route label as permanent once a current named owner and action path
exist.

## Non-goals

This layer does **not** create:

- a permanent repaired-route relapse dashboard;
- an automatic rewatch after any later recurrence;
- a public proof vault for minimized rewatch memory;
- a duplicate-filing duty for learners;
- an adverse wrong-route fault rule;
- a no-memory reset that treats prior rewatch repair as nonexistent;
- a global repaired-route, replacement-route, source, search, archive, or recipient certificate;
- a protected-proof publication duty;
- a search-engine, archive, portal, source, recipient, or protected-route winner by default; or
- a duty to monitor all old route pairs after dewatch.

## Why this matters for the larger archive

The archive's education-with-AI program is not only about repairing route conflict once. It is also
about ensuring that repaired routes do not become either permanent suspicion or invisible
repetition.

This layer matters because both extreme defaults are harmful. One bad default says later recurrence
proves the route pair is permanently unstable and that learners must refile, reprove, or accept
wrong-route fault. Another says dewatch minimization means no memory can be used, so every
recurrence is treated as new even when the same recipient portal, protected route, proof object,
clock, source, search, or archive dependency has failed before. The portable answer is narrower:
preserve a small, scoped memory of the prior dewatch exit; recall only what a current named need
justifies; publish current proof age and learner-safe action; and move the relapse to ordinary lag,
fresh first-cycle handling, repeat threshold, reopened rewatch, repair refresh, redesign, split,
residue, recipient correction, protected-route retention, or reminimization on named facts.

## Boundary conditions

This layer should not be used when only one of the following is true:

- `YV0-YV4` has not previously exited, de-watched, split, redesigned, retired, become residue, or
  minimized repair memory;
- the later event is visibly unrelated to the repaired route pair or affected surface;
- the current signal is ordinary search/cache/crawl/archive lag with no learner-facing owner, proof,
  clock, recipient, protected-route, or live dependency effect;
- the route-native process already names post-dewatch relapse handling, memory recall, proof age,
  learner-safe action, and reopen rules;
- the only signal is an unrelated mirror, screenshot, expired history row, stale search result, or
  downstream copy with no current owner or learner dependency;
- protected accommodation, privacy, safety, legal, records, appeal, or recipient-of-record rules
  already control proof handling and should stay local-only; or
- no current learner, owner, recipient, proof object, clock, protected route, or official-record
  dependency remains.

In those cases, publish `ordinary lag only`, `unrelated new path`, `route-native rule controls`,
`protected local-only route`, `no learner action now`, `no active owner`, `fresh first-cycle
conflict`, `reminimized memory`, or `none inherited` rather than creating a post-dewatch
repaired-route memory layer.

## What this closes

This closes `FT-0152`.

The archive no longer stops at "rewatch operation exited or de-watched". It can now publish a
minimal post-dewatch relapse / repaired-route memory layer: prior dewatch basis, current relapse
signal, repaired-route scope, scoped memory recall, current repair proof age, learner-safe action,
disposition, reminimization, and reopen triggers when a dewatched route pair later relapses, repair
proof ages, protected or recipient corrections reappear, redesign handoff fails, retired-route
residue revives, or no-active-route residue exposes a current owner.

It also opens one narrower seam.

After a post-dewatch relapse has been classified as ordinary lag, fresh first-cycle handling,
repeat-relapse candidate, reopened rewatch, repair refresh, redesign handoff, split, protected-route
retention, recipient correction, retired-route revival, no-active-route residue, or reminimized
memory, the archive may still need a tiny repeat post-dewatch relapse / repaired-route
rewatch-threshold layer for cases where the same repaired route pair or affected surface relapses
again after memory recall — without making every relapse an automatic rewatch, every repeat a
permanent stigma label, every duplicate-filing demand learner fault, or every minimized repair
object a public dossier.
