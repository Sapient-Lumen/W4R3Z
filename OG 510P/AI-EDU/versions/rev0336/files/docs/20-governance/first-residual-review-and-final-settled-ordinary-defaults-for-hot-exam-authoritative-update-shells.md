# First residual-review and final-settled ordinary defaults for hot-exam authoritative-update shells

This document closes the archive's next narrower governance gap after **superseded-proof and
authoritative-update defaults**.

Three overclaims matter here:

- **permanent-review-banner drift** — once ordinary closure truth returns, the archive treats every
  hot shell as if it must remain visibly review-open for as long as any record is retained, shipment
  continues, or possible-request authority exists;
- **passive-retention-equals-live-review** — the archive treats secure return chains, locally
  retained defense videos, or possible interim-work requests as if they were already an active
  reopened review rather than dormant route-specific residue; and
- **settled-without-reopen-trigger silence** — the archive restores ordinary closure but leaves no
  compact rule for when a later formal request, investigation, or route-specific exception may
  truthfully reopen that settled shell.

Current official signals support a tighter answer. Bluebook's current AP answer-resolution guidance
says ordinary digital closure is restored when the student submits on the same device and reaches
the **Congratulations** page or sees **“Your answers have been submitted”** on **Past**. The current
in-school answer-submission page keeps unresolved digital review route-specific: only if staff could
not resolve issues before dismissal do coordinators protect the device, help the student submit
later, or continue local incident handling. Current AP administration materials keep hybrid digital
custody distinct again: proctors close booklets and collect them at dismissal, and the AP Program
must receive exam materials by **June 1, 2026**. That ongoing secure return chain is real, but it is
not itself a learner-facing open-review state. Current AP Research and AP Capstone materials make
the portfolio route sharper still: students submit the Academic Paper as final by **April 30, 2026,
11:59 p.m. ET**; teachers score presentation components by **May 10, 2026**; AP Capstone performance
tasks and the AP Seminar end-of-course exam are **not rescored**; yet teachers must retain
presentation/oral-defense videos for at least one academic year because College Board may request
them for scoring-quality review, and College Board may also request interim work when
academic-integrity concerns arise. Together those signals support a narrower archive rule: **the hot
authoritative-update shells may now share one tiny residual-review / final-settled ordinary layer,
but they still do not justify one universal post-closure audit phase, one universal always-open
review badge, or one universal late-review owner.** See `B214`.

This document adds one thing only:

- a **tiny residual-review / final-settled ordinary layer** for those already updated shells.

That means the archive now asks a different question than before. It no longer asks only **what
current update wins and what stale proof should disappear**. It now asks **when leftover review
residue should still remain visibly open, when passive retention or secure return is merely
route-local background, and when the shell has truthfully rejoined final ordinary status until a
named later trigger reopens it**.

## Small grammar for residual-review / final-settled ordinary defaults

| Code | Meaning | Default archive action |
|---|---|---|
| `RV0-NO-UNIVERSAL-POSTCLOSURE-REVIEW-PHASE` | no one universal post-closure audit or review phase travels across these hot shells | do not keep every restored shell visibly review-open just because some deeper route-specific residue still exists |
| `RV1-LIVE-REVIEW-ONLY-ON-NAMED-TRIGGER` | visible residual review belongs on the ordinary shell only when a named formal review, request, investigation, or unresolved exception is actually open | do not publish review-open merely because the route retains records or ships materials later |
| `RV2-PASSIVE-RETENTION-OR-RETURN-CHAIN-IS-NOT-ORDINARY-REVIEW` | secure return, mandatory retention, or possible-request authority alone does not make the ordinary shell actively open | keep passive custody / retention route-local unless a named review is actually activated |
| `RV3-FINAL-SETTLED-ORDINARY-WHEN-CURRENT-CLOSURE-STANDS-AND-NO-LIVE-REVIEW` | once the current authoritative closure stands and no named live review remains, the ordinary shell should rejoin settled ordinary status | publish ordinary settled status rather than an indefinite maybe-under-review posture |
| `RV4-REOPEN-ONLY-ON-FORMAL-REVIEW-TRIGGER` | a later settled shell may reopen only when a named formal review trigger actually arrives | allow late reopen on actual request / investigation, not on generic possibility alone |

## `RV1` — review residue is visible only when an actual named review exists

`RV1-LIVE-REVIEW-ONLY-ON-NAMED-TRIGGER` is the archive's smallest anti-permanent-review rule.

Its point is not that review never exists. Its point is that the ordinary shell should show
review-open only when there is a real named trigger still alive:

- an unresolved or formally escalated digital AP incident after submission trouble;
- a named hybrid booklet custody or security exception; or
- a College Board scoring-quality or academic-integrity request in the AP Capstone route.

So `RV1` blocks vague “still maybe under review” language from lingering after ordinary closure has
already returned.

## `RV2` — passive retention and secure return do not keep the ordinary shell open

`RV2-PASSIVE-RETENTION-OR-RETURN-CHAIN-IS-NOT-ORDINARY-REVIEW` is the archive's smallest
anti-ambient-review rule.

It matters most where route-specific custody continues after ordinary closure:

- hybrid digital booklets may still travel through secure return to the AP Program;
- AP Seminar / AP Research videos must still be retained locally for one academic year; and
- interim work may still be requestable later in academic-integrity review.

But passive custody or potential request alone is not the same thing as an active review-open shell.

So `RV2` lets the archive keep real retention and return-chain duties without turning them into a
universal ongoing learner-facing warning state.

## `RV3` — settled ordinary status may return even while route-local residue remains elsewhere

`RV3-FINAL-SETTLED-ORDINARY-WHEN-CURRENT-CLOSURE-STANDS-AND-NO-LIVE-REVIEW` is the archive's
smallest anti-never-settled rule.

It says the ordinary shell may become settled again when two things are true:

1. the current owner-of-record closure still stands; and
2. no named live review remains open.

That means:

- same-device digital AP submission may become settled once Bluebook shows ordinary submitted status
  and no live incident path remains;
- hybrid digital custody may become settled once the identified booklet has re-entered ordinary
  counted return-for-scoring handling and no live mismatch remains; and
- portfolio-plus-local-record continuity may become settled once the currently governing portfolio
  and checkpoint legs stand closed, even though route-local retained materials still exist.

So `RV3` is what keeps the archive from confusing route-local residue with unfinished ordinary
closure.

## `RV4` — later reopen belongs to named formal triggers, not to generic possibility

`RV4-REOPEN-ONLY-ON-FORMAL-REVIEW-TRIGGER` is deliberately narrow.

It does **not** create one universal late-review authority. It says only that once a shell has
rejoined settled ordinary status, it should reopen again only when a named later trigger actually
appears, such as:

- a formal incident/security review that survives or arrives after ordinary digital closure;
- a later named secure-materials exception in the hybrid chain; or
- a direct College Board request for retained video or interim work in AP Capstone integrity /
  scoring-quality review.

So `RV4` lets settled ordinary status remain truthful while preserving the ability to reopen the
shell when an actual late trigger arrives.

## What the archive now publishes when using this layer

When an institution or assessment family publishes one of the hot authoritative-update shells, it
should now add only the following where truthful:

1. the shell-specific notice minimum from `RC1-RC3`;
2. the applicable `SV`, `ER`, `HF`, `MR`, `PR`, and `AU` fields, if any;
3. any `RV1` review-open state only when a named formal trigger is actually alive;
4. any `RV2` rule that keeps passive retention or secure return out of the ordinary shell; and
5. any `RV3` / `RV4` rule that restores settled ordinary status until a named formal trigger later
   reopens it.

That is enough to make post-closure review residue legible without inventing one universal
post-closure audit phase.

## What counted as a real archive gain

The archive already knew how to restore current truth after mismatch and how to withdraw stale proof
from the ordinary shell. It still lacked the next tighter answer: **when leftover review residue
should still remain visibly open, when passive retention or secure return is merely background
route-local residue, and when the shell has truthfully rejoined settled ordinary status.**

This document answers yes, but only barely.

It now allows the archive to publish a small shared layer for:

- no universal post-closure review phase;
- visible review-open residue only on named live triggers;
- passive retention / secure return that does not itself keep the ordinary shell open;
- final settled ordinary status once current closure stands and no live review remains; and
- later reopen only on actual formal review triggers.

That is a real operating gain because it blocks four opposite mistakes at once:

- leaving every restored shell under a vague permanent “still under review” banner;
- treating passive retention or secure return as if it were already an active review state;
- suppressing settled ordinary status just because deeper route-local residue still exists; and
- reopening ordinary shells on generic possibility rather than on actual named review triggers.
