# rev0325 pedagogy-forward execution refactor

## Refactor target

The cube had become safe enough to act but still too easy to browse. The rev0325 refactor reduces the operator path from many remembered commands to one scratch handoff bundle before human action.

## Hot path after rev0325

1. Run `make field-handoff-bundle OVERWRITE=1`.
2. Open `scratch/field-handoff/rev0325/FIELD-HANDOFF.md`.
3. For the owner rail, send/adapt the bounded owner request or record the route block.
4. For the teacher/tutor rail, complete the equality-one-step owner plan, run one local aggregate cycle, and then use readiness/next-action routing.
5. Only after real owner review, record the owner-review stop and result receipt.

## What this replaces

The operator should not need to manually gather:

- owner first-contact message;
- owner reply template;
- owner send checklist;
- micro-pilot owner plan;
- measure card;
- session log;
- final readout;
- readiness and next-action commands.

The bundle prepares those together under scratch/external storage.

## Boundary

The field handoff bundle is not evidence and not an execution result. It does not send, run, review, record, import, publish, authorize, or close anything. It only makes the next human actions easier to complete without growing the governance tail.
