# rev0317 pedagogy-forward execution refactor

## Refactor target

Rev0316 added the teacher/tutor augmentation micro-pilot. Rev0317 makes it easier to execute and
harder to avoid by hiding behind the archive. The target is not more doctrine. The target is a real
owner plan, a daily aggregate log, and a stop/continue decision.

## Refactor performed

- Converted the owner-contact boundary into a durable send pack instead of leaving it only in
  scratch output.
- Added a first-contact message template with explicit data exclusions and an eight-row aggregate
  ask.
- Added a teacher/tutor run card that defines one concept, one owner, one fallback, one no-AI
  transfer check, daily stop rules, and four end-of-cycle decisions.
- Added owner-plan and session-log templates that avoid raw learner traces and protected facts.
- Audited the governance tail so startup attention stays on the owner send and micro-pilot run.

## Refactor rule carried forward

Do not add another pre-import control until one of these happens:

- a real owner packet exposes a concrete uncovered failure;
- a real micro-pilot readout exposes learner harm, access harm, privacy leakage, or false-claim risk
  that existing controls cannot block;
- a release check demonstrates a reproducible packaging or source-truth defect.

Otherwise, spend the next cycle on human contact, bounded learning evidence, consolidation, or
deletion.

## Claim boundary

This refactor supplies execution materials. It does not send email, accept owner evidence, run a
micro-pilot, authorize service use, upgrade public language, or close `FT-0181`.
