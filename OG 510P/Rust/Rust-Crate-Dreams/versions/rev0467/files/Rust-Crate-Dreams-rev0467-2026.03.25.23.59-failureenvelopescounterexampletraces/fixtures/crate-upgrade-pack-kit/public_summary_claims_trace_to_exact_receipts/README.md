# Scenario — public summary claims trace to exact receipts

A frozen public pack already names the summary, warning register, and supporting receipts, but the reader still lacks one compact answer to a simpler question:

- which specific public summary claims are being made,
- which receipts or reports back each one,
- and which section id or fallback path should a downstream reader follow when the summary alone is not enough.

This scenario demonstrates that a public upgrade summary should ship with a bounded claim register instead of asking readers or tools to reverse-engineer claim provenance from prose.
