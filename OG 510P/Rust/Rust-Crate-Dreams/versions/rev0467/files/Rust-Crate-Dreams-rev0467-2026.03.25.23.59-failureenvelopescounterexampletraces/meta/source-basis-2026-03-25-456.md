# Source basis note — 2026-03-25 (entry 456)

## Scope of this pass

This pass did not try to find a new top-ranked fantasy crate.
It asked what the current top lanes would have to look like **operationally** to deserve near-term build attention.

## Facts imported directly from sources

- The 2025 State of Rust survey still reports non-trivial productivity problems around resource usage and debugging, while online documentation remains the preferred canonical reference.
- The March 2026 Rust challenges post says the Vision Doc team heard recurring high-level pain and now carries an explicit retraction note about the wording and LLM-assisted drafting of the original version.
- The debugging survey explicitly describes debugger/OS/version variance, visualizers, async debugging, and expression evaluation as important gaps.
- crates.io now exposes Security-tab data, Trusted Publishing enhancements, SLOC, and `pubtime`.
- The February 2026 malicious-crate policy update says most malicious-crate removals will be announced through RustSec advisories rather than individual blog posts.
- The March 2026 Cargo advisory distinguishes crates.io protections from alternate-registry exposure.
- docs.rs builds docs from crates.io releases, uses nightly in a sandbox, exposes build metadata knobs, stores documentation ZIP archives, and hosts rustdoc JSON with `format_version` caveats.
- The October 2025 docs.rs target update changed the default target list.
- Current Cargo/project-goals work includes build analysis, programmatic test output work, public/private dependency work, and other machine-usable substrate.
- Rust-for-Linux, build-script sandboxing, and safety-critical reporting all emphasize stable tooling, deterministic behavior, and stronger evidence surfaces.
- Community ecosystem hubs still show broad sector activity in web, GUI, game dev, IDE tooling, geospatial, and local-first work.

## Main inferences made in this pass

1. The archive’s strongest missing crates are still mostly cross-domain control-plane and evidence/contract kits.
2. The sharper missing layer is no longer just what artifacts a crate emits, but what **operating loop** lets another team keep trusting those artifacts.
3. That makes scenario corpora and recheck discipline part of the worthiness bar, not mere implementation polish.
4. The strongest near-term build slice is still the front door plus frozen basis plus minimal lifecycle loop, because official substrate already supports that shape unusually well.

## Open questions

- How much of the operating spine should be one cohesive crate family versus loosely coupled crates with shared packet conventions?
- How large should a `0.1` scenario corpus be before it becomes maintainability debt instead of trust infrastructure?
- Which recheck triggers should remain human-reviewed even after better machine imports arrive?
- How much debugger/OS/version variance can `P-0486` productize without becoming mostly a large matrix maintenance burden?

## Claim-level changes in this pass

- No broad salience reset.
- One practical upgrade: the archive now treats **operating models** and **scenario corpora** as first-class criteria for worthiness.
- One hygiene upgrade: the archive now tightens anti-amnesia rules around operational claims, not only citation and continuity claims.
