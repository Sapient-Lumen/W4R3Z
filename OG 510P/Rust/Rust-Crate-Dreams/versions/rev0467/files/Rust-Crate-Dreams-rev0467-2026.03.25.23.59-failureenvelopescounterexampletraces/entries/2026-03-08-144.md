> **P-0505 Cargo Host/Target Scope Contract Kit**

## Main judgment

Cargo’s host/target configuration split is no longer just an obscure documentation gotcha.

The docs, tracking issues, and internal implementation notes now make it clear that:

- `RUSTFLAGS` / `build.rustflags` behave differently depending on `--target`,
- rustdoc belongs to the same scope family,
- `host-config` and `target-applies-to-host` remain unstable and open,
- and same-triple builds can still change scope materially.

So the missing crate is best understood as a **portable scope incident bundle**:
policy, snapshot, observation receipt, diagnosis report, and diff.

## New planning stance

Read **P-0505** as a product with three minimal bundle layers:

1. intended policy,
2. observed receipt,
3. diff/diagnosis.

That is the right theory/practice split:
- let Cargo own the underlying config behavior,
- let this crate own the reviewable support artifact.

## Archive-level lesson

When Cargo exposes confusing-but-real host/target behavior, the best downstream crate may not be a new wrapper or launcher.
It may be the crate that captures **what actually applied, to which artifact kinds, under which command shape**, and makes that portable to CI, docs builders, and support threads.
