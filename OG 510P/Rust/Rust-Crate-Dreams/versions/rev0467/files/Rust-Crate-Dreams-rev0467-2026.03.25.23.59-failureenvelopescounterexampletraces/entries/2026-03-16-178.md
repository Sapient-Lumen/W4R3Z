# Entry 178 — publish-surface truth sharpened around trusted-publisher rehearsal and joined release receipts

This pass again avoided adding another top-level proposal.
The stronger move was to sharpen two already-worthy crates whose value became much more concrete after recent crates.io changes:

- **P-0175 Trusted Publishing Tooling Kit**
- **P-0477 Cargo Publish Receipt Join Kit**

## Why these moved now

The crates.io substrate is now materially more explicit than it was even a short time ago.

Recent official signals that changed the shape of the gap:

- crates.io trusted publishing now supports **GitHub Actions and GitLab CI/CD**,
- crates can enable **trusted-publishing-only mode**,
- crates.io blocks some especially risky GitHub triggers from trusted publishing,
- crates.io has **publish notifications**,
- and crates.io’s February 2026 malicious-crate policy clarifies that **RustSec / public incident communication** is still a separate lane from routine release artifacts.

That means the archive did not need another fuzzy “publish security tool”.
It needed better boundaries and more implementation-shaped artifacts for two distinct jobs:

1. **before release** — can we rehearse and explain trusted-publishing eligibility?
2. **after release** — what joined receipt proves what was released and how?
