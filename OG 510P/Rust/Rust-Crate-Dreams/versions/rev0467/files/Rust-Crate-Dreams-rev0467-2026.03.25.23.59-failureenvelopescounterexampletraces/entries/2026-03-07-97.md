# Entry 97 — Rust workflow kits: sanitizers, single-file packages, target-dir coordination, and backend matrices

Added four proposals after another pass over places where Rust is making meaningful progress but ordinary users still lack a boring workflow layer.

New proposals:

- P-0434 Sanitizer Profile & Evidence Kit
- P-0435 Cargo Script Workbench Kit
- P-0436 Target-Dir Lease & Shared Cache Coordination Kit
- P-0437 Codegen Backend Matrix Workbench Kit

Why these rose:

- **P-0434** rose because Rust sanitizer support is now a live project-goal area and the docs already encode real workflow traps (`build-std`, `--target`, symbolizer expectations, partial instrumentation). The sharper missing crate is a **profile/receipt/report-bundle layer**, not another wiki page or shell script.
- **P-0435** rose because official cargo-script work turns single-file packages into a first-class shape, but ordinary users still lack a **lock/bundle/doctor/export layer** for bug reports, tutorials, and one-file handoff.
- **P-0436** rose because Cargo itself is explicitly targeting build-dir units, finer-grained locking, GC, and shared caches. The sharper missing crate is a **lease/receipt/cleanup coordination layer** that helps people use target dirs deliberately without scraping internals or blindly deleting them.
- **P-0437** rose because Cranelift is now explicitly being pushed toward production-ready local-dev use, while GCC remains strategically important for other architectures and backend diversity. The missing crate is a **matrix/diff/fallback workbench**, not another backend.

What changed in archive judgment:

- The archive now has a stronger pattern for crates that sit above **package shape**, **artifact residence**, **instrumentation mode**, and **backend choice**.
- A worthy crate contribution does not have to be a parser, runtime, or giant framework; it can be the coordination layer that makes an upstream capability socially and operationally usable.
- This pass broadens the archive’s Rust-internal coverage beyond Cargo planning and public-IR work into **workflow maturity** for higher-level scripting, security testing, caching, and compiler-backend choice.

Archive hygiene added in this pass:

- Added an amnesia resistor reminding future passes not to confuse “the feature exists” with “normal users now have a boring default workflow.”
- Added notes to keep future workflow proposals honest about **inference, caveats, leases, fallback policy, and review artifacts** rather than pretending raw flags or config snippets are enough.
