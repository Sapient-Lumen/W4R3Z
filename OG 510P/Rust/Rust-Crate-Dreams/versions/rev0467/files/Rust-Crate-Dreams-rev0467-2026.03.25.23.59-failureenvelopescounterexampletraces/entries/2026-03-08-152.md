# Entry 152 — resolver why-bundles also need feature-unification policy and participant-scope truth

This pass again did **not** add another top-level proposal.

Instead, it sharpened **P-0468 Cargo Resolver Explanation Kit** where the archive still had unusually high leverage: the crate now has a clearer plan for **feature-unification policy and participant scope** above today’s mixed Cargo surfaces.

## Main judgment

The important missing crate is not another dependency graph explorer.
It is a **receiver-facing resolver bundle** that can tell another person:

- which `resolver.feature-unification` mode was active,
- which packages were selected for the command,
- which packages were allowed to participate in feature unification,
- whether an out-of-selection workspace member still influenced the answer,
- whether package mode intentionally preferred duplicate builds,
- and whether a diff should be read as “policy changed” rather than “manifest changed”.
