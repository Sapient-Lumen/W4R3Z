# 2026-03-01 (05): build-time sandboxing + OS sandbox kits + ML inference unification

This entry records evidence that three areas remain *high-leverage missing “default paths”* in the Rust ecosystem:

1) **Build-time sandboxing** (build scripts and procedural macros) as a practical, adoptable workflow.
2) **Cross-platform process sandboxing** as a reusable library primitive (not every project rolling their own).
3) **A stable ML inference interface** that unifies the growing Rust inference ecosystem.

## Signals & evidence

### Build-time sandboxing is an active Rust goal, but not “done”
- Rust Project Goals explicitly describe an opt-in approach to running build scripts in a sandbox with constrained access to OS resources, motivated by both security and determinism/caching benefits.
  - https://rust-lang.github.io/rust-project-goals/2024h2/sandboxed-build-script.html
- There are also concrete proposals for sandboxing proc macros via Wasm, emphasizing determinism and limited host interaction.
  - https://internals.rust-lang.org/t/pre-rfc-sandboxed-deterministic-reproducible-efficient-wasm-compilation-of-proc-macros/19359

### “Per-crate capabilities” keep resurfacing — but OS/Wasm isolation is seen as the reliable boundary
- A 2024 thread proposes a compile-time capability system; replies argue the security boundary is fundamentally OS-level or Wasm/process isolation, not crate/module boundaries.
  - https://internals.rust-lang.org/t/compile-time-sandbox/21139

### Practical tool prior art exists, but is incomplete / fragmented
- cargo-sandbox aims to allow fearlessly running Cargo builds against untrusted projects, including build scripts and proc macros, but is currently incomplete across platforms.
  - https://github.com/madsmtm/cargo-sandbox
- cargo-task-wasm explores sandboxed project-local tasks compiled to Wasm Components as a secure xtask-like workflow.
  - https://github.com/yoshuawuyts/cargo-task-wasm

### Cross-platform sandboxing remains “roll your own”
- OpenSSF discussions suggest Landlock as a first step for sandbox implementations, with seccomp as the next layer; this is a sign that “how to sandbox well” is still not a commodity.
  - https://github.com/ossf/wg-best-practices-os-developers/issues/631
- Concrete Rust sandboxes exist for individual mechanisms (Landlock, seccomp wrappers), but a consistent *cross-platform* abstraction is still rare:
  - Landlock crate: https://docs.rs/landlock
  - extrasafe (seccomp + Landlock wrapper): https://crates.io/crates/extrasafe
  - nanosandbox (cross-platform sandbox primitive): https://crates.io/crates/nanosandbox
  - Windows sandbox boundary docs in real projects (Job objects + AppContainer): https://github.com/wilsonzlin/fastrender/blob/main/docs/windows_sandbox.md

### Rust ML inference is growing, but API fragmentation persists
- tract is a pure-Rust inference toolkit that can read and run ONNX models.
  - https://github.com/sonos/tract
- ort is a modern ONNX Runtime wrapper (based on now-inactive onnxruntime-rs) and supports alternative backends.
  - https://crates.io/crates/ort
  - https://ort.pyke.io/backends
- Community discussions continue to ask for an abstraction layer across ONNX runtimes and platforms.
  - https://www.reddit.com/r/rust/comments/186plbx/onnx_libraries_in_rust/
