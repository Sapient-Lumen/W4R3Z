# Entry 407 — Cargo SBOM precursor work now needs capture-route truth, artifact-coverage reports, and claim ceilings

This pass stayed inside an already-promising supply-chain lane rather than adding another emitter, policy engine, or provenance stack.
It deepened:

**P-0125 Cargo SBOM Precursor Workbench Kit**.

## Why this lane earned another serious refresh now

Fresh official substrate makes one support gap much sharper than before:

- the 2026 Rust flagships explicitly keep **stabilizing Cargo SBOM precursor support** on the secure-supply-chain path;
- the current unstable Cargo docs say SBOM precursor files are generated only for **executable and linkable outputs** that are **uplifted into the target or artifact directories**;
- the same docs say Cargo sets `CARGO_SBOM_PATH` so crates can discover generated precursor paths;
- the current external-tools docs say `compiler-artifact` messages expose filenames, executable paths, enabled features, and whether a step was **fresh**;
- and the unstable `--artifact-dir` docs make copied promoted outputs a first-class output lane rather than an implementation accident.

Together those sources say the missing value is no longer only:

> “Did we ingest some `*.cargo-sbom.json` files and turn them into CycloneDX/SPDX?”

It is now also:

> “Which outputs were actually eligible for precursor generation, how were precursor files discovered, and where does the honest claim ceiling stop when the bundle came from copied or imported artifacts instead of one direct build capture?”

## Main judgment after the refresh

**P-0125** is now stronger as a **capture-route and coverage-honesty lane**.

That means a worthy crate in this lane should explicitly own:

- `capture-route.receipt.json`,
- `artifact-coverage.report.json`,
- `coverage-ceiling.report.json`,
- and a portable `sbom-workbench-bundle.manifest.json`.

It should **not** try to own:

- general sidecar shipping policy,
- publish identity or registry protection claims,
- full provenance attestation,
- or a universal SBOM-policy engine.

## What should count as a worthy crate contribution in this lane now

A worthy Cargo SBOM precursor crate should hand other people:

1. **one capture-route receipt** that says whether evidence came from a direct build, imported target/artifact tree, or manual bundle,
2. **one artifact-coverage report** that says which outputs were eligible, observed, missing, or out of scope,
3. **one coverage-ceiling report** that says where copied artifacts, imported trees, fresh-cache reuse, or non-uplifted outputs prevent stronger claims,
4. **one portable bundle manifest** another team can reopen later,
5. **one exactness story** instead of pretending every `*.cargo-sbom.json` file proves same-invocation completeness.

If a candidate crate cannot do those things, the archive should usually treat it as an emitter, adapter, or local review script — not the missing Cargo-native support-contract layer.
