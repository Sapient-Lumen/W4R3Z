# Entry 76 — frontier pass: digital publishing, neuroimaging datasets, geospatial catalogs, lidar interchange, and library-metadata migration

Added five proposals after a new pass focused on standards ecosystems where Rust now has at least *some* substrate or obvious adapter points, but still lacks the **missing middle**: profile lockfiles, official-validator wrapping, semantic diffs, replay, and portable evidence bundles.

New proposals:

- P-0332 EPUB 3.3 + EPUBCheck + OPDS 2.0 Interop & Evidence Kit
- P-0333 BIDS + NIfTI Conformance & Dataset Evidence Kit
- P-0334 STAC 1.1 + STAC API Validation & Replay Kit
- P-0335 LAS 1.4/1.5 + LAZ 1.4 + COPC Interop & Evidence Kit
- P-0336 MARC 21 + BIBFRAME Conversion Workbench Kit

Pass notes:

- **EPUB / OPDS** rose because EPUB 3.3 and EPUBCheck make conformance explicit while Rust now has enough package/catalog substrate to justify a profile-pinned evidence layer; the important seam is **publication package ↔ catalog distribution ↔ validator output**.
- **BIDS / NIfTI** rose because the official validator surface is active, Rust has real NIfTI substrate, and the expensive failures still sit between **dataset layout semantics and image-header reality**.
- **STAC** was promoted because Rust now has both document and server substrate, so the sharper missing contribution is **validation + query replay + semantic diffs**, not another catalog server.
- **LAS / LAZ / COPC** rose because Rust can already parse these formats, but the operational pain is still **CRS/VLR/header drift and partial-read behavior**, which are better served by a conformance/evidence layer than by yet another reader.
- **MARC / BIBFRAME** was promoted because the transition seam is full of official conversion specifications and real institutional pain, but Rust still lacks a boring-default **round-trip, explainable-diff, replayable migration workbench**.
