# 2026-03-17 (231) — crate runtime-handoff productization pass

This pass did **not** add a new lane.
It sharpened **P-0513 Crate Runtime Handoff Pack Kit** into a more implementation-ready `0.1` shape.

## Main judgment

The missing value is still **not** another pretty error renderer, another tracing stack, another hosted crash collector, or another one-off panic hook.
The sharper missing layer is a **crate-authored runtime handoff contract** that records:

- which runtime facts are exact captures versus maintainer summaries or heuristics,
- which fields are safe to share, hashed, truncated, omitted, or manual-review-only,
- which parts came from ordinary error paths versus panic paths,
- how complete a given handoff bundle really is,
- and where a blocked user should go next.

## Why this lane looks sharper now

- Rust’s current vision work explicitly argues that crates need more **supportive interfaces**, not only more power or flexibility.
- The 2025 State of Rust survey still says **debugging remains a notable productivity problem** and that **online documentation** plus **studying the code** are the main learning surfaces.
- `std::panic::set_hook` makes panic-path handoff a real, customizable surface with payload and location information.
- `error-stack` already models context plus attachments, which means the missing value is increasingly the handoff contract above the substrate rather than the substrate itself.
- `tracing-error` explicitly argues that span traces can be more useful than raw stacks in noisy async systems, and `SpanTraceStatus` already distinguishes `UNSUPPORTED` from `EMPTY`.
- `human-panic` and `color-eyre` show that user-facing panic/error handoff hooks, report files, and support-oriented sections are already practical.

## What to keep separate

- Keep **P-0513** separate from compile-time guidance (**P-0512**).
- Keep **P-0513** separate from generic report rendering.
- Keep **P-0513** separate from tracing / observability platforms.
- Keep **P-0513** separate from hosted crash-report collection.
- Keep **P-0513** separate from domain-specific incident or replay bundles.

## Preferred proving grounds

- CLI tools with panic hooks or user-submittable report files
- async services where logical span context matters more than raw executor stacks
- library crates using `error-stack` or similar attachment-heavy error propagation
- framework crates with public runtime error classes and recurring support-template issues
- privacy-sensitive systems where raw config/env/user identifiers must not leak into shared bundles
