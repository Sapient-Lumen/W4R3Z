# Entry 271 — crate upgrade support sharpened around review queues and cross-register consistency

This pass came from refusing to stop once the pack had many honest receipts.
A donor sweep showed that a pack can still fail in two ordinary ways even after source lineage, arbitration, follow-through, import truth, source heads, and pack readiness are all explicit.

## What moved this time

Two donor patterns kept surviving scrutiny:

- **VHK + EvidenceVault** made the strongest case that pack maturity should expose **queued review work**, not just a fused hold/candidate/freeze verdict.
- **The Election Stack + DeriveBSD** made the strongest case that a multi-artifact bundle needs a bounded **cross-register consistency** surface so already-typed lanes stay exact and contradictions fail loudly.

Both moves apply directly to **P-0514 Crate Upgrade Pack Kit**.

## Main planning move

The previous passes already established:

- source-lineage truth,
- hazard arbitration,
- native import truth,
- fixup posture,
- source-head truth,
- package-scope truth,
- active follow-through state,
- and fused pack readiness.

This pass adds two sharper review objects above them:

1. **review-queue truth** — the exact queued work still needed before the pack can advance,
2. **cross-register consistency truth** — whether the pack’s own receipts still agree well enough to support its public verdict.

## Why this matters

Without **review-queue truth**, the crate can still say `hold` and offer one polite `next_safest_step` while hiding:

- which source pinning work is actually next,
- which arbitration or scope checks are blocked versus ready,
- and which follow-through or approval steps must close before `candidate` or `freeze_ready`.

Without **cross-register consistency truth**, the crate can still emit individually honest files that combine into a dishonest story, such as:

- `pack-readiness = freeze_ready` while `source-heads` still says `citation_head_missing`,
- `freeze_ready` while `followthrough-state` still has active steps,
- or a broad workspace-sounding verdict while `package-scope` still records a narrower checked subset.

## Main judgment after the pass

A worthy upgrade-support crate should now provide **more than honest component receipts and one fused maturity verdict**.
It should also provide:

- a **review queue** that makes remaining work explicit, ordered, and blocker-aware,
- a **cross-register consistency report** that rejects impossible combinations across the pack’s own artifacts,
- and exact downgrade rules when a polished summary would otherwise over-claim what the bundle really knows.

That makes the lane more honest in two more places where migration support usually starts bluffing: it hides remaining work in prose, and it lets a contradictory bundle pose as a freeze-ready contract.
