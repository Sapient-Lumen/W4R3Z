# 2026-03-17 (220) — cfg availability ledger productization pass

This pass did **not** add a new lane.
It sharpened **P-0451 Cfg Availability Ledger Kit** into a more implementation-ready `0.1` shape.

## Main judgment

The missing value is still **not** another rustdoc renderer, another raw rustdoc-JSON helper, or another generic public-API diff tool.
The sharper missing layer is a **maintainer-facing availability ledger** that records:

- which public items are available under which target / feature / docs assumptions,
- what *kind* of availability claim that is,
- where that claim came from,
- and how much of the matrix is directly observed versus inferred.

## Why this lane looks sharper now

- rustdoc’s conditional-availability substrate is now strong enough that the missing value is increasingly the review artifact above it;
- docs.rs makes several important distortions explicit (`cfg(docsrs)` scope, hosted-vs-local differences, hosted rustdoc JSON provenance);
- Cargo feature rules still make conditional drift easy to miss in release review;
- and Cargo now passes `--check-cfg` to rustc and rustdoc, which makes origin/fidelity checking more realistic.

## Preferred proving grounds

- feature-heavy crates with optional-dependency indirection
- platform-heavy crates with `unix` / `windows` / `wasm32` surfaces
- crates using `#[cfg(doc)]` or `#[cfg(docsrs)]` to improve docs discoverability
- docs.rs metadata profiles with custom features or rustc cfgs
- releases where public items quietly move behind features
