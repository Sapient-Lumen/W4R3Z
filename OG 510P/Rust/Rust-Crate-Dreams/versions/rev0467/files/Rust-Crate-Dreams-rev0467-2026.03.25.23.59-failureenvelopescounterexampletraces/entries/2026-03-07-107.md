# Entry 107 — Cargo release handoff surfaces: package review and artifact manifests

This pass stayed on the archive’s strongest current frontier: **Cargo-adjacent crates that turn existing substrate into boring release/integration contracts**.

New proposals:

- P-0470 Cargo Package Review Kit
- P-0471 Cargo Artifact Handoff Kit

Why these rose:

- **P-0470** rose because Cargo already gives us the packaged `.crate`, path listing, VCS snapshot file, and dry-run workflow, but maintainers still mostly review publishes by hand. The sharper missing layer is a **publish-readiness receipt** that explains package shape, size-budget risk, and package-surface drift.
- **P-0471** rose because Cargo already emits produced artifacts in JSON and even has an unstable `--artifact-dir` to make outputs easier to consume, yet downstream tools still end up scraping logs or adopting larger release frameworks than they need. The sharper missing layer is a **stable artifact handoff manifest** for CI, packagers, and external build systems.

What changed in archive judgment:

- The archive now treats **Cargo packaging and build outputs** as two distinct workflow seams:
  1. **what source bundle are we actually publishing?**
  2. **what build outputs are we actually handing downstream?**
- A worthy crate contribution here may be a **review bundle** or **handoff manifest** rather than another build accelerator or publish orchestrator.
- This pass also tightened the distinction between **Cargo’s raw outputs** and **the compact contracts other humans/tools need**.

Archive hygiene added in this pass:

- Added an amnesia resistor warning future revisions not to confuse `cargo package --list`, `.cargo_vcs_info.json`, `--message-format=json`, or unstable `--artifact-dir` with a boring review/handoff workflow.
- Added known-existing notes for Cargo packaging docs, external-tools JSON, unstable artifact-dir, `cargo-dist`, and SBOM-sidecar direction so later passes do not rediscover the same false gap.
