# Entry 175 — support-surface truth refresh (toolchain contracts + docs.rs parity)

This pass deliberately avoided adding another top-level proposal.
The stronger move was to sharpen two already-worthy crates whose value became more concrete after official 2025–2026 docs.rs and rustup changes:

- **P-0484 Toolchain & Target Support Contract Kit**
- **P-0472 Docs.rs Build Parity & Evidence Kit**

## Why these moved now

Two official changes made support drift feel less theoretical than before.

First, docs.rs changed its default target list in October 2025.
That means a project can change its published docs posture simply by leaving target choice implicit.
That is exactly the kind of drift a support-contract crate should make visible.

Second, current docs.rs docs now give unusually specific hosted facts:

- the current nightly toolchain,
- the `#[cfg(docsrs)]` versus `DOCS_RS` split,
- the rule that non-`x86_64-unknown-linux-gnu` targets are cross-compiled,
- and the current resource limits.

That makes the docs.rs parity lane more concrete than “run cargo rustdoc and hope.”

Rustup 1.29 strengthened the toolchain-support lane too.
It added official Solaris hosts and continued to make environment/tooling reality more plural.
Combined with rustup’s documented override/profile/path-toolchain rules, that makes “one boring support artifact” look more valuable than another clever implementation library.

## Current judgment

The archive should keep rewarding crates that turn scattered support folklore into **reviewable artifacts**:

- a toolchain intent snapshot,
- an environment receipt,
- a support-surface report,
- a docs.rs config/limit bundle,
- or a parity diff.

This still looks more valuable than adding another protocol-specific one-off crate right now.
