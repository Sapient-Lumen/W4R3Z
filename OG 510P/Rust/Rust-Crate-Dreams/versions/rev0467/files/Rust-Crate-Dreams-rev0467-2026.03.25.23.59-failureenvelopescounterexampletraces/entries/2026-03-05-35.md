# 2026-03-05 (35): OHTTP deploy & interop kit + OID4VC interop workbench + chunked privacy gateway ops kit

This entry deepens the archive’s *interop-first, artifact-first* theme in the privacy/identity lane:

- OHTTP/BHTTP move beyond “implementation exists” into deployable, testable *privacy gateways* with reproducible incident bundles.
- OID4VC (OID4VP/OID4VCI + Presentation Exchange) gets a conformance and transcript/bundle-first workbench so wallet/verifier teams can debug interop without leaking PII.

## Added proposals

- **P-0194 — OHTTP Deploy & Interop Kit** — a batteries-included ops layer for deploying OHTTP gateways/relays in Rust, with `*.ohttpbundle.zip` reproducible artifacts. Evidence: RFC 9458 (OHTTP), RFC 9292 (Binary HTTP), and existing Rust crates (`ohttp`, `bhttp`).  
  Sources: https://www.ietf.org/rfc/rfc9458.html ; https://datatracker.ietf.org/doc/rfc9292/ ; https://crates.io/crates/ohttp ; https://crates.io/crates/bhttp

- **P-0195 — OID4VC Interop Workbench** — profile-driven conformance suites and redacted `*.oid4vcbundle.zip` transcripts spanning OID4VP/OID4VCI + Presentation Exchange.  
  Sources: https://openid.net/specs/openid-4-verifiable-presentations-1_0.html ; https://openid.net/specs/openid-4-verifiable-credential-issuance-1_0.html ; https://identity.foundation/presentation-exchange/spec/v2.0.0/

- **P-0196 — Chunked OHTTP & Privacy Gateway Ops Kit** — streaming/chunking semantics, rate limiting, privacy-invariant “doctor” tooling, and `*.pgbundle.zip` incident bundles for gateway operators.  
  Sources: https://datatracker.ietf.org/wg/ohai/ ; https://crates.io/crates/ohttp-gateway ; https://divviup.org/blog/ohttp-now-available/
