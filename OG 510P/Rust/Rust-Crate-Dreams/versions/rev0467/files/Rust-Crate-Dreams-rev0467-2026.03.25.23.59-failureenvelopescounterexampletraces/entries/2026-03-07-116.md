# Entry 116 — lower-bound dependency witnesses and build-dir consumer transitions

This pass stayed with the same discipline that has been paying off in the archive: when Rust already has meaningful substrate, the sharper missing crate is often the **reviewable workflow contract above it**, not another engine or wrapper.

New proposals:

- P-0488 Cargo Minimal-Version Witness Kit
- P-0489 Cargo Build-Dir Consumer Transition Kit

Why these rose:

- **P-0488** rose because Cargo now already has real lower-bound substrate — `direct-minimal-versions`, `minimal-versions`, explicit dependency-version semantics, a new `implicit_minimum_version_req` lint, and FAQ guidance on the kinds of conflicts users hit — but ordinary maintainers still lack a boring **policy / blame / waiver / diff bundle** for dependency-floor truthfulness.
- **P-0489** rose because Cargo now says more explicitly that intermediate build-dir layout is internal, `build.build-dir` is stable, `-Zbuild-dir-new-layout` is active work, and the user-wide-cache / build-dir-layout goals explicitly call for a transition path for tooling that accesses intermediate artifacts. The sharper gap is a **consumer audit + path-contract + transition receipt**, not another cache manager.

What changed in archive judgment:

- The archive now separates **dependency lower-bound truthfulness** from both **toolchain/MSRV validation** and **dependency update policy**. A worthy crate here does not update dependencies; it proves what lower bounds were actually checked and why they moved.
- The archive now treats Cargo’s evolving build-dir layout not only as a cache-performance story, but also as a **tooling transition** story. A worthy crate may help other tools stop scraping internal paths rather than touching build performance directly.

Archive hygiene added in this pass:

- Added an amnesia resistor warning future revisions not to mistake `direct-minimal-versions` or a Cargo lint for a complete maintainer-grade lower-bound workflow.
- Added an amnesia resistor warning future revisions not to treat stable `build.build-dir` or nightly new-layout work as proof that Cargo-adjacent tools already have a safe migration path off internal directory assumptions.
