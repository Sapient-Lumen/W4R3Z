# Entry 104 — Crate slicing, libtest JSON interop, sizedness readiness, and BorrowSanitizer evidence

Added four proposals after a pass focused on a seam the archive was still under-serving: **workflow crates above active Rust mechanisms that are real enough to experiment with but not yet boring enough for normal teams**.

New proposals:

- P-0462 Crate Slicing Soundness & Adoption Kit
- P-0463 Libtest JSON Interop Kit
- P-0464 Sized Hierarchy & Extern-Type Readiness Kit
- P-0465 BorrowSanitizer Workflow & Evidence Kit

Why these rose:

- **P-0462** rose because the 2026 crate-slicing goal is explicit that `cargo-slicer` and PRECC-Rust are proof-of-concept evidence, not production workflow, while maintainers still lack a **slice-eligibility / fallback / predicted-benefit receipt**.
- **P-0463** rose because libtest JSON now has an explicit goal and RFC path, while Cargo, nextest, and custom harnesses still lack a **schema-lock / suite-aware interop bundle** that ordinary CI and IDE tooling can safely exchange.
- **P-0464** rose because the refined `Sized` hierarchy is now a concrete stabilization target tied to unblocking extern types, yet maintainers still have no **sizedness-surface audit / opaque-type readiness receipt** above current FFI tooling.
- **P-0465** rose because BorrowSanitizer is now an explicit 2026 effort for practical aliasing-bug detection across language boundaries, but ordinary teams still lack a **profile / FFI-boundary / minimized finding bundle** for unsafe review and issue filing.

What changed in archive judgment:

- The archive now remembers another sharp pattern: when Rust has a **research prototype, unstable feature, or accepted project goal with real substrate**, the missing crate may be the one that turns experimentation into a **reviewable adoption artifact**.
- A worthy crate contribution here may be a **soundness ledger**, **schema lock**, **readiness audit**, or **finding bundle**, not another engine.
- This pass also broadens the archive’s internal-Rust seam further across **compile-time optimization**, **test-tool protocol**, **type-system/FFI migration**, and **unsafe runtime evidence**.

Archive hygiene added in this pass:

- Added an amnesia resistor reminding future passes not to confuse “there is already a prototype or goal page” with “ordinary teams already have a boring workflow around it.”
- Added known-existing notes so later revisions do not mistake `cargo-slicer`, libtest JSON experiments, FFI/binding generators, or BorrowSanitizer/Miri themselves for proof that the maintainer-facing coordination layer already exists.
