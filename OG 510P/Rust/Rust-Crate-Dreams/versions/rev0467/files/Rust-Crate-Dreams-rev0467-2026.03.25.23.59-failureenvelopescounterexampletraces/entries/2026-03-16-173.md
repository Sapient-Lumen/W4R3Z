# Entry 173 — Build-dir transition lanes + debug support refresh

This pass did **not** add another top-level proposal.
Instead, it strengthened two already-promising workflow crates with fresh official 2026 signals and sharper fixture packs:

- **P-0489 Cargo Build-Dir Consumer Transition Kit**
- **P-0486 Debuggability Support Contract Kit**

## Why these moved now

Cargo's March 2026 Build Dir Layout v2 call for testing is unusually useful archive fuel because it names concrete downstream failure modes instead of only warning that internals may change.
That made **P-0489** much more implementation-shaped: the crate can now organize its first scenario pack around known failure families like bin-path inference, target-dir recovery from `OUT_DIR`, and user-requested artifact lookup.

At the same time, the 2026 debugging survey reinforces that Rust still needs better cross-debugger / cross-OS support posture, while Cargo's clearer target-dir vs build-dir split makes it even more obvious that **artifact location** is not the same as **debug support truth**.
That made **P-0486** stronger as a support-contract crate rather than a debugger-wishlist crate.

## Current judgment

The archive should keep preferring crates that hand **other maintainers** something small and reviewable:

- a migration receipt,
- a support posture report,
- a symbol-layout manifest,
- an adapter plan,
- or a conservative diff.

This is still where a lot of the highest-value “missing crate” territory lives in Rust right now.
