# Entry 157 — broad portfolio rebalance, with deeper planning for conformance and local-first

This pass did **not** add another proposal.

Instead, it did the higher-value thing for the archive at this moment: it re-ranked the repository as a **portfolio** and upgraded two proposals that look increasingly like genuine ecosystem multipliers.

## Main judgment

The archive had started to overfit to a very sharp Cargo frontier.
That frontier is still real, but the healthier question is now:

> which missing crates would actually count as **epic** contributions to Rust as a whole?

The answer is increasingly:

- crates that produce **shared coordination artifacts**,
- crates that turn recurring pain into **portable bundles, receipts, or ledgers**,
- and crates that sit above real substrate instead of waiting for language miracles.

## Why these changes were the right ones

### 1. P-0264 was under-specified relative to its leverage

A shared **conformance harness toolkit** could lower the cost of many future standards/interop crates in this archive.
It now has a sharper plan around:

- publishable suites as dependencies,
- runner contracts,
- machine-readable results,
- and `*.conformbundle.zip` failure artifacts.

### 2. P-0076 was still too thin for a genuinely important gap

Local-first remains one of the biggest “Rust has pieces but not a boring kit” opportunities.
The updated proposal now treats the missing value as:

- a stable document-repo contract,
- a golden-path default stack,
- supportable sync bundles,
- conformance fixtures,
- and explicit security/access-control lanes.

### 3. The archive needed a broad salience checkpoint

The new broad frontier scan records a top tier that is more faithful to the actual opportunity surface:

2. P-0242 Reproducible Build Evidence Kit

10. P-0469 Cargo Rebuild Explanation Kit

## New planning stance

For the next few passes, the archive should prefer:

- strengthening **artifact-first multipliers**,
- strengthening **shared suite / bundle / receipt / ledger** vocabulary,
- and only adding new proposals when they clearly beat the current broad top tier.

It should **not** drift into:

- narrow protocol count inflation,
- another generic wrapper crate,
- or proposals that cannot say what they hand to another person.
