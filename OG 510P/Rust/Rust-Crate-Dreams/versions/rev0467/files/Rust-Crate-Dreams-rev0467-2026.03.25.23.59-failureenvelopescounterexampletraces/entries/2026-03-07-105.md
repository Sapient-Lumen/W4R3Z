# Entry 105 — Python wheel shipping, Apple SDK release contracts, and a tighter salience map

This pass did **less indiscriminate expansion** and more ranking.

New proposals:

- P-0466 Python Wheel ABI & Free-Threading ShipKit
- P-0467 Apple XCFramework & SwiftPM ShipKit

Why these rose:

- **P-0466** rose because Rust now has real Python substrate (`PyO3`, `maturin`, `abi3`) while the actual maintainer pain has shifted upward into **wheel-matrix policy, repair receipts, and free-threading split contracts**.
- **P-0467** rose because Rust now has real Apple substrate (`UniFFI` Swift bindings, `cargo swift` adjacency, `xcframework` tooling), while Apple distribution expectations now clearly include **slice accounting, SwiftPM binary-target integrity, origin verification, and privacy-manifest discipline**.

What changed in archive judgment:

- The archive now treats **cross-language distribution** as a sharper seam than generic “FFI exists / bindings can be generated” claims.
- A worthy crate contribution may be a **release contract** rather than another SDK, bridge, or code generator.
- The archive also now has a dedicated salience scan so future passes can rank the frontier instead of reflexively widening it.

Archive hygiene added in this pass:

- Added a new amnesia resistor warning future revisions not to confuse **binding generators / packagers** with **boring ship contracts**.
- Added known-existing substrate notes for PyO3/maturin/Python free-threading and for UniFFI/XCFramework/SwiftPM/Apple distribution guidance.
- Added an explicit salience map that favors build/test/debug/distribution multipliers over marginal narrow protocol expansion.
