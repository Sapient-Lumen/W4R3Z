# 2026-03-01 (10): Fast installs, binary trust, and sandboxed installers

## Signals observed (with sources)

### Cargo binary installation is becoming a “default expectation”, but trust is the missing layer
- Rust tooling discussions increasingly treat **prebuilt binaries** as the ergonomic norm because `cargo install` from source is slow for many tools. (Internals thread proposing cargo-binstall-by-default: https://internals.rust-lang.org/t/feature-request-add-cargo-binstall-by-default/23876)
- `cargo install` has a real policy dilemma around lockfiles: `--locked` improves predictability but can conflict with platform-specific needs; users are asking for a “middle ground”. (Internals thread: https://internals.rust-lang.org/t/cargo-install-locked-or-not-locked-middle-ground/23893)
- Binary installers inevitably inherit a **supply-chain trust problem**. Community reports include antivirus flagging / “trojan” alarms on downloaded release artifacts (which may be false positives, but still illustrates the trust gap). (Reddit discussion: https://www.reddit.com/r/rust/comments/1n1gelr/cargobinstallquickinstall_distributing/)

### Sandboxing isn’t just for build scripts: people want to sandbox *install scripts*
- A recent Rust forum thread describes building a **user-space macOS sandbox** to run third-party “curl | sh” install scripts safely, by redirecting/isolating side-effects. (Rust forum: https://users.rust-lang.org/t/exploring-user-space-sandboxing-for-third-party-install-scripts-macos-rust/138456)

### Upstream context: verification/mirroring and sandboxing are explicit Rust directions
- Rust project goals for “verification and mirroring” aim at **secure chain-of-trust** and the ability to verify downloads from a mirror. (Project goal: https://rust-lang.github.io/rust-project-goals/2025h1/verification-and-mirroring.html)
- Program management updates reiterate that crates.io mirroring/verification is motivated by bandwidth/firewalls and reliability constraints. (Inside Rust update: https://blog.rust-lang.org/inside-rust/2026/02/11/program-management-update-2026-01/)
- Sandboxing Cargo workloads is already being prototyped (macOS-first) as `cargo-sandbox`, highlighting both demand and incomplete coverage. (Repo: https://github.com/madsmtm/cargo-sandbox)

## Implications for “missing crates”
1) There is room for a **trust layer for binary installs** (verification, provenance, policy, explainability) that composes with existing installers rather than replacing them.
2) There is room for a **sandboxed installer runner** that applies “build-jail” ideas to the broader ecosystem of third-party installers (curlbash, homebrew formula scripts, etc.) with auditable policies and reproducible artifacts.
