# Entry 272 — crate upgrade support sharpened around export posture and exact public surface

This pass came from noticing that the pack could now be internally honest in many ways and still lie at the export boundary.
A donor sweep showed that a pack can be mature enough for maintainers while still being dishonest as a public downstream contract.

## What moved this time

Two donor patterns kept surviving scrutiny:

- **EvidenceVault** made the strongest case that a stable public contract should have one exact exported surface instead of implying the whole working tree is public.
- **DeriveBSD + Radical-Governance** made the strongest case that audience/exposure scope and redaction posture should stay exact rather than collapsing into vague “shareable” language.

Both moves apply directly to **P-0514 Crate Upgrade Pack Kit**.

## Main planning move

The previous passes already established:

- source lineage and source heads,
- hazard arbitration and native import truth,
- fixup posture,
- package-scope truth and active follow-through state,
- pack readiness,
- review queues,
- and cross-register consistency.

This pass adds two sharper review objects above them:

1. **export-posture truth** — whether the lane stays private/internal, what sensitivity flags still exist, and whether redaction is still required before public export,
2. **publication-surface truth** — the exact summary/recipe/receipt subset that forms the stable public contract.

## Why this matters

Without **export-posture truth**, the crate can still say a lane is coherent enough to freeze while hiding that it still contains:

- local filesystem paths,
- internal package aliases,
- private example context,
- or working notes that should never ship to downstream users.

Without **publication-surface truth**, the crate can still publish one summary and quietly imply that the whole working tree is the contract, including:

- floating source imports,
- raw tool dumps,
- advisory-only notes,
- and other internal review material that should stay off-surface.

## Main judgment after the pass

A worthy upgrade-support crate should now provide **more than an internally coherent migration bundle**.
It should also provide:

- an **export posture** that says whether the lane is only private/internal or actually public-shareable,
- an exact **publication surface** that says what the public contract really exports,
- and explicit off-surface reasons for raw imports, floating notes, or private evidence that remain useful only to maintainers.

That makes the lane more honest in two more places where support artifacts usually start bluffing: they export half-private working material as if it were public contract, and they leave the actual public surface implicit.
