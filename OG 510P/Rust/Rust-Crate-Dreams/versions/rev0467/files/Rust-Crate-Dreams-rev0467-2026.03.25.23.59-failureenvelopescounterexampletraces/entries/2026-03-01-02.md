# 2026-03-01 (02) — more ecosystem signals: supply-chain transparency, embedded testing, HPC

This entry adds a few strong “missing crate” signals discovered via fresh web research:

## Supply-chain transparency is converging but still fragmented
- Existing tools cover pieces: SBOM generation (`cargo-sbom`, CycloneDX cargo plugin), embedding dependency graphs into binaries (`cargo-auditable`), and signature/attestation ecosystems (Sigstore + SLSA provenance spec).
- What still feels *missing* is a coherent, ergonomic **bundle + verification workflow** that makes it easy for producers to emit and for consumers to verify: “this binary corresponds to these sources, dependencies, and build inputs”.

Links:
- `cargo-sbom` (SPDX/CycloneDX): https://docs.rs/crate/cargo-sbom/latest
- CycloneDX cargo plugin: https://crates.io/crates/cargo-cyclonedx
- `cargo-auditable`: https://github.com/rust-secure-code/cargo-auditable
- SLSA build provenance: https://slsa.dev/spec/draft/build-provenance
- crates.io Trusted Publishing docs: https://crates.io/docs/trusted-publishing
- sigstore crate: https://docs.rs/sigstore/latest/sigstore/
- pre-RFC sigstore integration: https://internals.rust-lang.org/t/pre-rfc-using-sigstore-for-signing-and-verifying-crates/18115

## Release engineering is a real ecosystem “shipping cliff”
- cargo-dist is explicitly positioning itself as the place where release planning/building/distribution steps get unified.
- Proposed shipping-related crates should likely integrate with cargo-dist rather than compete.

Links:
- cargo-dist docs: https://axodotdev.github.io/cargo-dist/

## Embedded Rust is maturing around stable interfaces, and testing remains a practical pain
- embedded-hal 1.0 is stable and focuses on drivers, including async traits; this invites a stronger “conformance + semantics test kit” story.
- The ecosystem has important tools (embedded-hal-mock, defmt-test, embedded-test), but they don’t fully standardize **behavioral conformance** for HAL implementations.

Links:
- embedded-hal v1.0 announcement: https://blog.rust-embedded.org/embedded-hal-v1/
- embedded-hal-mock: https://github.com/dbrgn/embedded-hal-mock
- defmt-test: https://crates.io/crates/defmt-test
- awesome-embedded-rust (catalog incl. embedded-test): https://github.com/rust-embedded/awesome-embedded-rust

## HPC / MPI: Rust bindings exist, but stronger type-safety ergonomics are being researched
- rsmpi provides bindings; research proposes typed abstractions to reduce mismatches and UB.
- A “typed MPI” crate could be both impactful and well-scoped.

Links:
- rsmpi: https://github.com/rsmpi/rsmpi
- arXiv (typed safety for MPI built on RSMPI): https://arxiv.org/html/2509.10803v1
