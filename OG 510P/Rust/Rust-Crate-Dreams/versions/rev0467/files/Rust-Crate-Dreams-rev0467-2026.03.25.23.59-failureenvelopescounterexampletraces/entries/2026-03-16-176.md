# Entry 176 — cargo script handoff sharpened + source parity honesty refreshed

This pass again avoided adding another top-level proposal.
The stronger move was to sharpen two already-worthy Cargo-adjacent crates whose value became more concrete after fresh 2026 official signals:

- **P-0435 Cargo Script Workbench Kit**
- **P-0496 Cargo Vendor & Source Parity Kit**

## Why these moved now

Cargo script is no longer just a third-party convenience story.
The Rust project is now actively highlighting it as a near-stable workflow for minimal reproducers, tutorials, and quick prototypes, while Cargo’s docs spell out unusually concrete semantics for single-file packages:

- disabled auto-discovery,
- inferred manifest defaults,
- disallowed fields,
- hashed Cargo-home target dirs,
- and target-dir lockfile placement.

That made the missing value much more specific.
The right crate is not another launcher.
It is the **receipt / doctor / export-plan / bundle** layer that makes single-file packages handoff-friendly.

At the same time, the crates.io mirroring push made source parity feel sharper, not broader.
The Rust project is explicitly talking about secure mirror verification and chain-of-trust work.
That is valuable, but it does not eliminate workspace-local questions like:

- which logical source IDs actually resolved,
- whether sparse/git aliases collapsed onto one physical root,
- whether path/git spillover still sits outside the trusted boundary,
- and what external verification evidence does **not** prove.

That made **P-0496** stronger as a parity and coverage crate rather than a pseudo-mirror implementation.
