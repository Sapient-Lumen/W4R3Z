# 2026-03-05 (06) — cargo sandboxing, durable-exec interop, and workspace policy doctor

This entry adds three proposals that aim to **turn recurring ecosystem pain into stable contracts** (policies, artifacts, conformance suites) that many projects can reuse.

## Added proposals

- **P-0107 Cargo Sandbox & Capability Policy Kit** — a versioned capability policy format + `cargo sandbox` runner + conformance corpus for sandboxing build scripts / proc macros, informed by Rust’s sandboxed build-script project goal, and existing tools like `cackle` and `cargo-sandbox`.  
  Sources: Rust project goal on sandboxed build scripts; `cackle`; `cargo-sandbox`; Cargo sandboxing issue history.  
  - https://rust-lang.github.io/rust-project-goals/2024h2/sandboxed-build-script.html
  - https://github.com/cackle-rs/cackle
  - https://github.com/madsmtm/cargo-sandbox
  - https://github.com/rust-lang/cargo/issues/5720

- **P-0108 Durable Execution Interop & Conformance Kit** — a small, stable workflow-history schema + replay harness + adapters (Temporal / durable / Flawless) + test vectors, grounded in the durable execution concept and current Rust engine landscape.  
  Sources: Temporal durable execution explainer; Temporal core + prerelease Rust SDK; `durable`; `flawless`.  
  - https://temporal.io/blog/what-is-durable-execution
  - https://github.com/temporalio/sdk-core
  - https://crates.io/crates/temporalio-sdk
  - https://github.com/iopsystems/durable
  - https://crates.io/crates/flawless

- **P-0109 Cargo Workspace Policy Doctor Kit** — a “policy bundle” + `cargo policy` orchestrator that normalizes outputs from RustSec/cargo-audit, cargo-deny, cargo-vet, and vendoring into stable CI artifacts.  
  Sources: RustSec; cargo-deny; cargo-vet; Cargo vendoring docs; ongoing config-sprawl discussions.  
  - https://rustsec.org/
  - https://github.com/EmbarkStudios/cargo-deny
  - https://mozilla.github.io/cargo-vet/
  - https://doc.rust-lang.org/cargo/commands/cargo-vendor.html
  - https://internals.rust-lang.org/t/is-it-possible-to-standardize-additional-config-file-naming/23900

## Notes

These proposals share an “artifact-first” bias: if we can make a workflow produce a **portable bundle** (policy, report, history, corpus), collaboration and debugging get dramatically easier — and the ecosystem can converge on shared contracts without waiting for a single upstream decision.
