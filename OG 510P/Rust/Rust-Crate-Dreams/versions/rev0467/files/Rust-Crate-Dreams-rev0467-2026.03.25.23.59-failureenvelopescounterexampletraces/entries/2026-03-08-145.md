# Entry 145 — Cargo resolver why-bundles need MSRV and exactness boundaries

This pass again did **not** add another top-level proposal.

Instead, it sharpened **P-0468 Cargo Resolver Explanation Kit** where the archive still had the most leverage left: the crate now has a clearer plan for **mixed-MSRV version-choice receipts** and **manual-review boundaries** when Cargo’s available views are useful but not exact.

## Main judgment

The important missing crate is not a better graph browser.
It is a **receiver-facing why-bundle** that can tell another person:

- which command scope was captured,
- which resolver/MSRV policy was in force,
- which facts came from Cargo directly,
- which facts came from unstable or third-party enrichments,
- and where the explanation is only approximate or requires manual review.

## New planning stance

**P-0468** should now be read as a crate that hands other people:

- one frozen capture lock,
- one feature-cause report,
- one version-choice receipt with MSRV influence,
- one receipt that states whether the explanation is exact, approximate, or manual-review-required,
- and one diff report when command selection or policy changed the answer.

That is a much sharper contract than “Cargo graph tooling.”
