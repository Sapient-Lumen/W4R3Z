# Entry 366 — Cargo lock-contention witness work deepened around root authority, actor command lanes, wait windows, and mitigation cost for P-0490

This pass deepened **P-0490 Cargo Lock Contention Witness Kit** instead of adding another generic build profiler, another cache policy crate, or another rust-analyzer tips page.

## Why this lane earned another pass now

Fresh official and primary-source signals line up unusually well:

- the March 13, 2026 build-dir-layout-v2 call for testing says the rework is explicitly meant to unblock **more granular locking** so `cargo test` and rust-analyzer do not block on each other;
- the 2025H2 Cargo build-dir-layout goal says Cargo currently locks the entire build cache, calls out rust-analyzer versus manual Cargo contention as a common user pain, and says the “shiny future” is finer-grained caching and locking with a user-wide cache;
- Cargo’s build-cache docs now directly distinguish **target-dir** from **build-dir** and document distinct configuration routes for each;
- rust-analyzer’s current configuration docs make `cargo.targetDir`, build-script/check override commands, invocation strategies, and wrapper behavior explicit enough to model as first-class receiver-facing facts;
- Cargo’s unstable docs keep `--compile-time-deps` and build-analysis sessions alive as real tool-facing substrate;
- and the Cargo 1.93 development notes explain that finer-grained locking work had to split **build-dir** versus **artifacts-dir** locking first, especially for `cargo check`-style overlap.

Together these make one conclusion stronger: the worthy crate here is not just “detect that Cargo waited.”
It is a crate that helps other people inspect **which roots were authoritative, which actor command lane actually ran, what wait window was truly observed, how strong blocker identity is, and what each mitigation would cost**.

## Main judgment after the pass

The strongest near-term contribution in this lane is still **not** another scheduler or killer of competing processes.
It is a **stable support-contract layer** above Cargo config/env, rust-analyzer configuration, Cargo stderr/process observation, and optional imported build-analysis context.

This pass promotes five P-0490 review objects into first-class status:

1. **root-authority receipt** — how each root path claim was determined;
2. **actor-command-lane receipt** — what command family/scope/invocation shape each actor actually used;
3. **wait-window receipt** — the bounded timeline and exactness of the wait claim;
4. **mitigation-cost report** — what each mitigation costs in artifact duplication, cache reuse, workflow disruption, and volatility;
5. **contention support-bundle manifest** — the compact handoff artifact joining those truths.

## Why these objects matter

Current substrate now makes several mistakes easier to commit unless the archive models them explicitly:

- `target-dir` and `build-dir` can be different even when a human says “the target directory”;
- rust-analyzer can avoid some contention by using its own target-dir, but the docs explicitly say that duplicates artifacts;
- a role label like `editor_check` is weaker than knowing whether that actor ran the default workspace-wide `cargo check --all-targets`, an override command, or a compile-time-deps-only lane;
- a build-analysis session can corroborate context without proving blocker identity;
- and build-dir-layout-v2 improves some contention classes without meaning “parallel Cargo is solved.”

## New archive-level stance

For Cargo blocking / lock-contention work, the archive should now prefer this layering:

1. **P-0490** for root authority, actor command lanes, wait windows, blocker-identity exactness, and mitigation cost;
2. **P-0469** for rebuild causality once actual waiting is understood;
3. **P-0508** for delegated build-script topology and override authority;
4. **P-0489** for build-dir consumer migration off internal assumptions;
5. Cargo and rust-analyzer official docs for the moving upstream substrate.

That keeps the portfolio from minting another crate that merely says “use a separate target dir” without clarifying what is really shared, what was actually observed, and what the workaround buys or costs.

## What should count as a worthy crate contribution after this pass

A worthy Cargo lock-contention-facing contribution should now be able to answer all of these cleanly:

1. **Which roots are actually in play, and who says so?**
2. **Which actor command lane actually ran?**
3. **What wait window was directly observed?**
4. **How exact is blocker identity?**
5. **What does the recommended mitigation cost?**
6. **Which upstream-moving assumptions still require manual review?**

If a candidate crate cannot answer those questions, the archive should usually treat it as contention folklore rather than a serious support contract.
