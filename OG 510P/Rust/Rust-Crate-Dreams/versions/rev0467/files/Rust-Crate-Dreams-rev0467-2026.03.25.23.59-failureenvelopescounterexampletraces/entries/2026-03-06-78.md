# Entry 78 — frontier pass: open 3D scenes, 3D city models, science-data conventions, emergency alerting, and music notation interchange

Added five proposals after a fresh pass focused on standards families where the ecosystem already has an official validator, profile, or conformance surface **and** Rust now has at least enough substrate to build the missing middle layer.

New proposals:

- P-0342 OpenUSD Core Spec 1.0 + USDZ Conformance & Evidence Kit
- P-0343 CityGML 3.0 + CityJSON 2.0 Conformance & Conversion Workbench Kit
- P-0344 netCDF + CF Conventions + OPeNDAP Interop & Evidence Kit
- P-0345 CAP 1.2 + IPAWS Interop & Evidence Kit
- P-0346 MusicXML 4.0 + MEI Interop & Evidence Kit

Pass notes:

- **OpenUSD / USDZ** rose because AOUSD has made compliance more explicit while Rust now has real parser/loader movement. The gap is **validator-aware evidence and semantic diffs**, not just another reader.
- **CityGML / CityJSON** rose because Rust now has both an official validator (`cjval`) and early CityGML 3.0 substrate, but still lacks **conversion-loss reporting and subset-pinned conformance bundles**.
- **netCDF / CF / OPeNDAP** was promoted because the pain sits at the boundary between local file semantics and remote subset behavior; the missing crate is **CF-aware validation + replay + semantic diffs**.
- **CAP / IPAWS** made the cut because Rust has CAP type/model substrate, but still lacks a boring-default **profile lock + explainable findings + redactable support bundle** story.
- **MusicXML / MEI** was promoted to keep the archive broad: the key missing value is **semantic loss reporting across notation encodings**, not “yet another parser”.
