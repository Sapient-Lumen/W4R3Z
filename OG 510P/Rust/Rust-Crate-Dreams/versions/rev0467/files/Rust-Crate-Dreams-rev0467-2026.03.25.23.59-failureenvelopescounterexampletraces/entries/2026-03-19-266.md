
# Entry 266 — crate ecosystem pathfinder sharpened around starter-set readiness, lock-in cost, and scope-split honesty

This pass did **not** add another popularity ranker, another façade crate, or another “blessed list”.
It sharpened **P-0509 Crate Ecosystem Pathfinder & Decision-Pack Kit** into a more implementation-ready product.

## Why this moved now

Rust’s crate-choice substrate is stronger than it was even a year ago, but the receiver-facing decision layer is still thin.

- The December 2025 Rust vision-doc work explicitly says users still struggle to know **which crates to use**, calls crate discovery “undiscoverable”, and says the ecosystem lacks a clear **starter set**.
- The 2025 State of Rust survey still says online documentation and code remain the main learning surfaces, which means default choices and migration posture matter a great deal.
- Cargo now gives teams more small signals than before — `cargo search`, `cargo add`, and `cargo info` all help — but they still assume the crate has more or less already been chosen.
- Cargo’s external-tools surfaces (`cargo metadata`, stable JSON outputs, custom subcommands) make it realistic to build reviewable decision tooling *above* Cargo rather than replace it.
- Cargo manifests already expose `keywords`, `categories`, `rust-version`, features, and other importable hints, but those hints still do not tell another maintainer when a starter set is mature enough to freeze.
- crates.io has added more review signals such as the Security tab, Trusted Publishing visibility, SLOC metrics, and `pubtime`, which improves evidence import but does not by itself yield a task-lane decision pack.
- docs.rs has also made target-visibility posture more explicit, especially after its default-target changes and continued metadata support, which makes “visible support story” more legible but still does not tell a team whether the starter answer is scoped to teaching, production, or a narrower runtime/target lane.

That combination means the gap is no longer just “finding crates is hard”.
The sharper gap is that teams still lack one small artifact that can say:

- **is this starter set ready to freeze yet?**
- **what hidden companion crates or runtime choices still prevent freezing?**
- **what lock-in cost are we buying if we accept this stack?**
- **are the teaching and production defaults intentionally different?**

## Main planning move

This pass promoted three review objects to first-class status for **P-0509**:

1. **starter-set readiness** — whether a proposed default is mature enough to freeze, still hides companion requirements, or still needs manual review,
2. **lock-in cost** — what escape cost the stack buys through runtime coupling, pervasive macros, trait surface adoption, or ecosystem gravity,
3. **scope split** — whether teaching, production, org-policy, and niche-target defaults intentionally diverge.

That matters because the archive already had the right general center of gravity — task profiles, role coverage, interop surfaces, decision weights, starter-set locks, and evidence-origin reports.
But it still did not make the difference between:

- “this crate ranks highly today”,
- “this stack is boring enough to freeze as a starter set”,
- “this stack is easy to teach but expensive to leave later”,
- and “we are deliberately publishing two defaults because they serve different goals”.

This pass fixes that.

## Main judgment after the pass

A worthy crate-discovery / starter-set contribution for Rust should now provide **more than ranked candidates**.
It should provide:

- explicit **starter-set readiness truth**,
- explicit **lock-in cost truth**,
- explicit **scope-split truth**,
- explicit **evidence-origin truth**,
- explicit **freshness and freeze-boundary truth**,
- and one compact **decision bundle** another maintainer can inspect without reverse-engineering Cargo, crates.io, docs.rs, blog posts, and team folklore.

That is more believable and more ecosystem-multiplying than either:

- “just search crates.io better”,
- “just use `cargo add` on the popular crate”,
- “just write a wiki page of blessed crates”,
- or “just bundle everything into one façade crate”.
