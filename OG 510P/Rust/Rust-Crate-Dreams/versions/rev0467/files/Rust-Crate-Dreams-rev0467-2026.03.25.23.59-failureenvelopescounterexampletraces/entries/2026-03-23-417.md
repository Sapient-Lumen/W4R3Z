# Entry 417 — compile-iteration deepened around edit-scope receipts, fast-path barriers, and invalidation honesty

This pass chose to **deepen P-0537 Compile Iteration Feedback Kit** again instead of opening a fresh lane.

The sharper question was:

> when a team says “this edit should have stayed on the fast path,” what exact kind of edit was it, and what concrete barrier pushed it off that path?

## Why this deepening pass earned a full revision

Fresh official and primary sources make that missing layer concrete:

- the March 2026 Rust challenges write-up still calls compile performance the universal productivity tax, explicitly names hot reloading, fast debug builds, and faster linking as outsized leverage, and gives GUI examples where even padding tweaks can cost 8–10 seconds;
- the 2025 compiler-performance survey still says small-change rebuild latency is the most common complaint, and specifically calls out workspace-triggered rebuild cascades plus linking as separate bottlenecks;
- the active **Relink don’t Rebuild** goal now states plainly that comment changes, implementation-only edits, and other public-interface-preserving changes still rebuild reverse dependencies today, even though the desired future is to reuse outputs and only relink;
- Dioxus 0.7 now documents both “what still requires a full rebuild” and the `--hotpatch` ceilings around globals, static initializers, component signatures, import/module changes, and dependency/workspace edits;
- current `subsecond` docs make the remaining hotpatch ceilings even sharper by documenting tip-crate-only patching, thread-local reset risk, unsupported struct hot reloading, and the need for framework-level reinstancing;
- Tauri’s current develop docs still show that `tauri dev` usually sits beside a frontend dev server route via `devUrl` and `beforeDevCommand`, so browser-visible change and Rust-ready change are still mixed but not identical;
- and cargo-leptos / Trunk still provide useful browser reload and CSS-only update routes that are fast, but are not themselves proof that a Rust-logic fast path held.

That means **P-0537** is now strongest when it can export not only:
- reload surface,
- restart ceiling,
- readiness class,
- linker route,
- and latency budget,

but also:
- **edit-scope receipts**,
- **fast-path barrier reports**,
- and scenario packets that show why a change stayed visual-only, fell out of hotpatch, or should have been interface-preserving-but-relink-only in theory even when today’s substrate still rebuilds more than users expect.

## Main judgment after this pass

The top frontier should still begin:

1. **P-0537 Compile Iteration Feedback Kit**
2. **P-0509 Crate Ecosystem Pathfinder & Decision-Pack Kit**
3. **P-0535 Dependency Lifecycle Transition Kit**
4. **P-0536 Crate Knowledge Pack Kit**
5. **P-0538 Concurrency Contract Kit**

But **P-0537** is stronger now because the repo no longer stops at “what route updated the app?”
It now has a clearer product shape for:

- what the edit actually touched,
- whether that scope was interface-preserving, layout-affecting, or frontend-only,
- what barrier stopped the strongest fast path,
- and what fallback or claim ceiling remains honest afterward.

## What should count as a worthy crate contribution in this lane now

A worthy compile-iteration crate should provide other people:

1. **one edit-scope receipt** that says whether the edit was markup, CSS/static asset, function body, public-interface surface, type layout, global/static/TLS state, build/config route, or dependency/workspace code;
2. **one fast-path barrier report** that says why the strongest fast route was unavailable: outside tip crate, interface change, layout/alignment hazard, global initializer caveat, TLS reset risk, workspace rebuild cascade, or frontend-only route ceiling;
3. **one honest separation between current substrate and desired future substrate** so an interface-preserving edit can still be recorded as “should be relink-only in theory” even if today’s Cargo/rustc stack still rebuilds more than that;
4. **one clear fallback class** — visual-only update, relink-only, restart with reinstancing, full rebuild/restart, or manual review;
5. **one portable bundle** that keeps edit scope, barrier cause, surface route, restart ceiling, and readiness class separate.

If a candidate crate cannot say **what changed** and **why the stronger fast path was unavailable**, it is probably still just a watcher, linker tweak, frontend HMR route, or hotpatch anecdote.
