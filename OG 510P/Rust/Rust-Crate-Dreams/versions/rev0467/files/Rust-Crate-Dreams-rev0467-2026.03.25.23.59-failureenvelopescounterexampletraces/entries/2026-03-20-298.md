# Entry 298 — cargo-publish-receipt-join-kit sharpened around capture basis, receipt authority, and publication visibility

This pass returned to **P-0477 Cargo Publish Receipt Join Kit** because the archive still left one release-support simplification too cheap:

> a crate could be “published” and even have a checksum somewhere, while another maintainer still lacked one compact answer to **what local artifact the receipt was actually based on**, **which observation was authoritative**, and **which public surfaces had or had not caught up yet**.

## What moved this time

Several current Cargo / crates.io / docs.rs signals make that blur more expensive now than it used to be:

- `cargo publish` still creates a `.crate`, uploads it, and then polls the index, but the command docs explicitly say that polling may timeout and manual completion checks may still be needed;
- the publishing guide still points maintainers at `cargo package --list` and inspection of the generated `.crate` as the boring pre-publish source bundle review path;
- Rust 1.93.1 release notes now say `cargo publish` no longer keeps `.crate` tarballs as final build artifacts when `build.build-dir` is set, and recommend `cargo package` when a final tarball artifact is required;
- the Cargo index format now documents `pubtime` and explicitly says index JSON should not change after insertion except for `yanked`;
- docs.rs still automatically builds docs for released crates, but its builds are queued and may take a while, which means “the release exists” and “the docs surface has converged” are not the same fact;
- and recent crates.io updates made publish identity more explicit through trusted publishing, trusted-publishing-only mode, and publish notifications.

## Main planning move

This pass promoted three more first-class review objects for **P-0477**:

1. **capture basis truth** — what concrete local artifact or imported bundle the receipt actually came from;
2. **receipt authority truth** — which observations are authoritative for checksum / publish time / identity / public visibility, and which are merely lagging or advisory;
3. **publication visibility truth** — whether Cargo-facing registry observation is complete, and whether docs/public surfaces are still pending.

## Why this matters

Without those objects, the archive still permits a very ordinary lie:

- a maintainer can truthfully say “Cargo accepted the publish,”
- a reviewer can truthfully see a checksum or `pubtime` later in the index,
- docs.rs can still be queued or failed,
- and the original `.crate` used for local review may no longer be sitting where the team assumes it is.

That is not just operational trivia.
It is the difference between “a release probably happened” and “another team can inspect one honest receipt that says what was captured, what is authoritative, and what public surfaces are still catching up.”

## Main judgment after the pass

A worthy post-publish release-support contribution for Rust should now provide more than:

- one local tarball digest,
- one later index checksum,
- or one label saying the publish used trusted publishing.

It should also provide:

- one explicit **capture-basis receipt**,
- one explicit **receipt-authority report**,
- one explicit **publication-visibility report**,
- and one honest way to keep “Cargo accepted the upload” separate from “the authoritative index facts are present” and from “downstream public surfaces like docs.rs have converged.”
