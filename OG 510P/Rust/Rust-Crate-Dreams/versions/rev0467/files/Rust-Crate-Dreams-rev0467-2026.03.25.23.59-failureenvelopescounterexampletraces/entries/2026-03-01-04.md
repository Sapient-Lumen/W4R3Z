# 2026-03-01 (04): more signals (TUF, text input/IME, lakehouse formats, audio tooling)

This entry adds four proposal candidates grounded in recurring pain signals across *very* different domains:
supply-chain security (TUF), GUI text input (IME/composition), data lakehouse table formats, and audio/DSP tooling.

## Signals & sources

### TUF adoption is converging for Rust releases and crates.io (but integration is missing)
- The Rust Foundation reports movement toward consensus on implementing **TUF** for Rust releases and crates.io, with an out-of-tree experimental deployment expected to start in 2026.
  That suggests a near-future need for **client-side tooling and mirror workflows** that can speak TUF and integrate with Cargo/rustup-style flows.
  - https://rustfoundation.org/2025/
- There are Rust TUF clients/libraries (e.g., `tuf`, `tough`), but they remain “raw building blocks” for many teams:
  - https://docs.rs/tuf
  - https://crates.io/crates/tough
- Community/author RFC drafts discuss TUF as the model for crate/release signing and trust chains:
  - https://hackmd.io/%40cWcJa4-JQNOtacfKywdqxA/ByrMv8JH0

### IME/composition support remains a chronic GUI pain point
- egui tracks IME support and explicitly attributes “no IME for much of Rust GUI” to upstream gaps (winit tracking issue).
  - https://github.com/emilk/egui/issues/248
  - https://github.com/rust-windowing/winit/issues/1497
- Web/WASM IME still has sharp edges (canvas can’t receive CompositionEvent; hidden input hacks are common).
  - https://github.com/rust-windowing/winit/issues/4424

### Lakehouse “open table formats” are arriving in Rust, but interoperability + ergonomics are fragmented
- There are official/active Rust implementations for major table formats:
  - Iceberg: https://crates.io/crates/iceberg and spec: https://iceberg.apache.org/spec/
  - Delta: https://delta-io.github.io/delta-rs/ and deltalake crate docs: https://docs.rs/deltalake
  - Hudi: https://hudi.apache.org/docs/0.15.0/python-rust-quick-start-guide/ and crate: https://docs.rs/hudi
- Delta Kernel’s stated goal is a cohesive, pluggable API surface for interoperability—but adoption challenges remain.
  - https://brokenco.de/2026/01/12/delta-kernel-challenges.html

### Audio ecosystem remains fragmented; “golden path” real-time DSP + graph tooling is still hard
- RustAudio explicitly describes the ecosystem as fragmented and “limited in capabilities,” and maintains an overview effort.
  - https://github.com/RustAudio/audio-ecosystem
- vst-rs deprecation discussions highlight how platform/plugin format shifts can strand users and tooling.
  - https://github.com/RustAudio/vst-rs/issues/193
- Longstanding commentary suggests there’s still “a lot of scope to make audio infrastructure better.”
  - https://raphlinus.github.io/synthesizer/2018/09/19/synth-update.html

## New proposal candidates
- P-0026: `cargo-tuf-mirror` — TUF-aware mirrors + verification for Rust artifacts and registries
- P-0027: `text-input-kit` — reusable text input engine (IME/composition/selection) for Rust GUI toolkits
- P-0028: `open-table-format-kit` — common traits + adapters across Iceberg/Delta/Hudi (Arrow/DataFusion-friendly)
- P-0029: `audio-graph-kit` — real-time safe DSP graph primitives + adapters (a unifier, not a monolith)
