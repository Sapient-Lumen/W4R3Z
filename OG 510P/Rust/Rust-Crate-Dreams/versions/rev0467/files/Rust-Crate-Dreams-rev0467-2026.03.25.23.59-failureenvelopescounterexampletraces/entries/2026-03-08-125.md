# Entry 125 — Cargo explainability stack sharpening, fixture stubs, and an incubation order

This pass intentionally did **not** add another top-level proposal.

Instead, it treated the current top Cargo-facing frontier as a **stack** that deserves sharper planning and more buildable artifacts.

## Main judgment

The repo is broad enough that the best next move is often to deepen one of the strongest existing ideas rather than invent a new one.

This pass therefore promoted a stronger archive judgment:

- **P-0469 Cargo Rebuild Explanation Kit** is now the best next incubation target,
- **P-0468 Cargo Resolver Explanation Kit** remains extremely strategic but should share vocabulary and fixture style with P-0469,
- and **P-0494 Cargo Compile-Time-Deps Workflow Kit** is best understood as the tool-invocation parity layer above the same Cargo explainability stack.

## Why P-0469 was favored for a concrete-planning pass

- The 2025 State of Rust survey still points to compile-time/resource pain.
- Cargo’s build-dir-layout work still names Cargo/Rust-Analyzer lock contention and cache-layout pain as current goals.
- Cargo issue history still contains a long-standing request for better “why did this rebuild?” diagnostics.
- There are recent reports of `cargo check` / rust-analyzer interaction causing unexpectedly broad rebuilds.

That combination makes P-0469 unusually **fixtureable** and easy to explain to other people: the crate should provide one boring artifact for “why did this rebuild?”
