# Entry 259 — Crate resource support sharpened around admission order, backlog ownership, capacity shrink, and acquire fate

This pass did **not** add another pool, another queue, another cache, another rate limiter, or another runtime-metrics helper.
It sharpened **P-0521 Crate Resource Surface Pack Kit** into a more implementation-ready support crate.

## Why this moved now

The current Rust resource story is no longer empty.
That changes the shape of the missing value.

- The December 2025 Rust vision-doc work explicitly says crates need more **supportive interfaces**.
- The 2025 State of Rust survey still says online docs and code remain the main learning surfaces, and resource usage is still among the recurring productivity problems.
- Tokio already documents that unbounded `mpsc` channels can buffer arbitrarily and can abort the process if memory is exhausted.
- Tokio already documents that `spawn_blocking` keeps spawning threads until the configured upper limit is reached and then queues more work.
- Tokio `Semaphore` already documents wait-for-permit semantics, while `SemaphorePermit::forget` can permanently reduce available permits.
- Tower already documents that `buffer` + `concurrency_limit` layer order changes how many requests can be in flight.
- SQLx and Deadpool already publish real pool semantics for waiting, timeouts, closure, and graceful pool shutdown.

That combination means the missing crate is no longer “Rust needs backpressure primitives” or “Rust needs more metrics.”
The sharper missing crate is a **crate-authored resource contract** above today’s substrate.

## Main planning move

This pass promoted five review objects to first-class status for **P-0521**:

1. **admission path** — which queue, permit gate, pool, or layer decides first,
2. **backlog ownership** — whether waiting work is owned by the crate, upstream, downstream, or an external service,
3. **capacity shrink** — what can permanently or temporarily reduce effective capacity,
4. **acquire fate** — whether callers wait, time out, error, or wake closed at the boundary,
5. **pressure evidence** — which signals and scenario receipts actually prove the claimed posture.

That move matters because the archive had already named the lane, but it had not yet made the **review objects** and **scenario fixtures** concrete enough to survive real product planning.
This pass fixes that.

## Main judgment after the pass

A worthy resource-support crate contribution for Rust should now provide **more than numeric defaults**.
It should provide:

- explicit **admission-path truth**,
- explicit **backlog-ownership truth**,
- explicit **capacity-shrink truth**,
- explicit **acquire-fate truth**,
- explicit **pressure-evidence truth**,
- and one compact **resource-surface diff** another maintainer or downstream user can inspect without reconstructing resource behavior from builder docs, layer ordering, and production incidents.

That is more believable and more ecosystem-multiplying than either:

- “just document your pool limits”,
- “just expose metrics”,
- or “just use a queue with backpressure” with no receiver-facing support contract attached.
