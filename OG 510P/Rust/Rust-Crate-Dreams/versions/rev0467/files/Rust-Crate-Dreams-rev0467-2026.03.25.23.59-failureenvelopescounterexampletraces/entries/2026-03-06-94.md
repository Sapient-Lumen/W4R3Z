# Entry 94 — expression portability, robot-description loss accounting, media-package receipts, agent transcripts, and quantum lowering evidence

Added five proposals after a pass aimed at ecosystems where the missing Rust value is **not another parser or SDK**, but a boring default for **environment locks, expansion receipts, profile diffs, transcript bundles, and explainable lowering reports** above already-real external contracts.

New proposals:

- P-0422 Common Expression Language (CEL) Conformance & Portability Kit
- P-0423 URDF + SDFormat + xacro Loss-Aware Interop Workbench Kit
- P-0424 SMPTE IMF Package + OPL Validation & Evidence Kit
- P-0425 A2A Protocol Conformance, Transcript & Capability Kit
- P-0426 OpenQASM 3 + QIR Interop & Evidence Kit

Pass notes:

- **CEL** rose because Rust now has a credible interpreter and the official conformance ecosystem is active, so the sharper gap is a **pinned environment and explainable evaluation receipt**, not raw expression execution.
- **URDF + SDFormat + xacro** made the cut because robotics pain is still mostly **authoring-expansion and conversion-loss drift**, not absence of XML parsing.
- **SMPTE IMF + OPL** rose because Rust now has meaningful validation substrate, but the operational gap is still a **package/application/deliverable evidence bundle**, not yet another one-off validator log.
- **A2A** made the cut because the protocol ecosystem now includes validator/TCK work and multiple Rust implementations, so the missing crate is a **capability/transcript artifact layer** that can outlast SDK churn.
- **OpenQASM 3 + QIR** rose because the hard boundary is now **source-language semantics versus target-profile-constrained IR lowering**, and Rust still lacks a portable evidence layer for that handoff.

Archive hygiene added in this pass:

- Added a reminder that some of the best crate opportunities live at the boundary between a **language/spec surface** and the **runtime/profile/tooling state required to interpret it safely**.
- Strengthened the archive’s memory that “interop” often really means **normative core + extension packs + profile overlays + receipts for loss or replay**, not one homogeneous contract.
