# Entry 190 — build insights promoted into a fixture-first historical warehouse lane

This pass did not add a new proposal.
It upgraded **P-0035 cargo-build-insights** into a more implementation-shaped lane with stronger warehouse artifacts, comparability receipts, and a broader fixture corpus.

## Why this moved now

Several official Cargo signals line up unusually well.

### 1. Cargo's recorder is finally real enough that downstream crates can stop pretending they need to invent one

The build-analysis goal explicitly says Cargo is recording build metadata across invocations.
The current unstable docs then go further and describe persisted JSONL logs in `$CARGO_HOME/log/`, unique session ids, and the `cargo report sessions` / `timings` / `rebuilds` command set.

### 2. Cargo 1.94 made the report surface more concrete

The 1.94 Cargo development-cycle update says `cargo report sessions` was added to find ids, `cargo report timings` gained missing features, and unstable `--timings=FMT` was removed because `cargo report timings` covers that role better.
That makes “freeze imported sessions into one smaller stable warehouse bundle” much more plausible than it was before.

### 3. Historical analysis is explicitly part of the upstream story

The build-analysis goal is not just about a nicer one-run report.
It explicitly says external tooling should be able to analyze historical trends and identify performance bottlenecks.
That is almost a direct invitation for a crate like P-0035 — but only if it stays above the recorder and below dashboards.

### 4. Long build pain is still real enough to justify a boring warehouse layer

The relink-don't-rebuild goal keeps broad rebuild fanout in scope, and the 2025 State of Rust survey still says resource usage remains a major productivity problem.
So a crate that can tell teams when regressions began, which series are still comparable, and what remains manual-review-only still fills a real gap.

## Current judgment

The worthy crate here is not:

- another dashboard-first analytics toy,
- another unstable JSON parser pretending Cargo wording is fixed forever,
- or another giant Cargo doctor that claims to explain every build mystery.

The worthy crate is the boring warehouse layer that can hand another person:

1. a **session-series index**,
2. a **comparability report**,
3. one or more **normalized session records**,
4. an **import receipt**,
5. an **exactness ledger**,
6. and a **small diffable ZIP** that survives CI, PR review, and longer-term performance triage.
