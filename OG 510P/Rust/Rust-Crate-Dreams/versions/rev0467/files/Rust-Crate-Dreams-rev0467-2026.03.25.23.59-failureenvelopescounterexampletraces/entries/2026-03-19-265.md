# Entry 265 — crate guidance support sharpened around message-stability classes and guidance-channel honesty

This pass did **not** add another diagnostic renderer, another proc-macro helper, or another compile-fail harness.
It sharpened **P-0512 Crate Guidance Pack Kit** into a more implementation-ready support crate.

## Why this moved now

Rust’s compile-time support story is no longer missing raw substrate.
That changes the shape of the missing value.

- The December 2025 Rust vision-doc work explicitly says crates need more **supportive interfaces** and calls out better diagnostics and guidance from crates.
- The 2025 State of Rust survey still says online docs remain the preferred canonical reference, followed by studying the code itself.
- The Rust Reference now makes the diagnostic namespace concrete: `#[diagnostic::on_unimplemented]` can supplement trait errors with custom `message`, `label`, and `note`, while `#[diagnostic::do_not_recommend]` can suppress misleading blanket-impl recommendations.
- rustdoc `compile_fail` examples are real and useful, but the rustdoc book still warns that code failing today may compile in the future.
- rustdoc’s unstable features page still says nightly-only error-number checks for `compile_fail` doctests are unlikely to stabilize, because emitted error codes are not guaranteed to be the only thing a snippet emits from version to version.
- `trybuild` remains a real compile-fail harness, but its docs still warn that compiler output can vary depending on whether `rust-src` is installed locally.
- `ui_test` remains a real “how your library shows up when used wrongly” harness, but its output is still fundamentally an output-file comparison workflow.
- `proc-macro-error2` remains a valuable migration path away from `panic!`-based proc-macro errors, while also explicitly saying that warnings are nightly-only and that panics display no errors.
- `miette::Diagnostic` still offers structured `code`, `help`, and `url` metadata, and the project changelog still records URL-linking support and automatic docs.rs link generation.

That combination means the missing crate is no longer “Rust needs compile-fail tests” or “Rust needs better proc-macro errors”.
The sharper missing crate is a **crate-authored guidance contract** that distinguishes:

- **this misuse is caught**,
- **this exact message/help/url is part of the supported surface**,
- **this recovery recipe was actually checked**,
- and **this wording is only shape-stable or environment-sensitive**.

## Main planning move

This pass promoted five review objects to first-class status for **P-0512**:

1. **message stability** — whether the crate claims exact wording, code-only stability, shape-only stability, failure-only stability, or manual review,
2. **guidance channel** — whether the user-facing help comes from compiler diagnostics, snapshot-tested stderr, proc-macro `compile_error!`, `miette` metadata, docs anchors, or a mixed path,
3. **environment sensitivity** — which parts of the guidance surface depend on toolchain, `rust-src`, nightly-only features, proc-macro panic avoidance, or docs parity,
4. **recipe witness** — what smallest-good-path was actually checked,
5. **release drift** — whether the failure is still caught even though message/help/url or channel behavior changed.

That move matters because the archive had already made **guidance authority**, **recovery origin**, and **recipe fidelity** explicit, but it still did not make the difference between:

- “this doctest still fails”,
- “this UI fixture still snapshots stderr”,
- “this proc-macro still avoids panic and emits guidance”,
- and “this exact wording/help/url is a supported contract another team may rely on”.

This pass fixes that.

## Main judgment after the pass

A worthy compile-time / early-failure support crate contribution for Rust should now provide **more than a list of failure recipes**.
It should provide:

- explicit **message-stability truth**,
- explicit **guidance-channel truth**,
- explicit **environment-sensitivity truth**,
- explicit **recovery-origin truth**,
- explicit **recipe-witness truth**,
- and one compact **guidance-surface diff** another maintainer can inspect without reconstructing the story from compiler stderr snapshots, rustdoc caveats, proc-macro internals, and scattered docs links.

That is more believable and more ecosystem-multiplying than either:

- “just add `trybuild`”,
- “just add `ui_test`”,
- “just add `miette` URLs”,
- “just use `proc-macro-error2`”,
- or “just trust that the compiler output will stay exactly the same forever”.
