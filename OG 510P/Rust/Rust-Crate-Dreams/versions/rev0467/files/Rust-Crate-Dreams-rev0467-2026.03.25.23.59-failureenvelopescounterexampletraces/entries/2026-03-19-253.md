# Entry 253 — crate off-ramp planning sharpened around successor intent, stopgap horizons, and recipe witnesses

This pass did **not** add another advisory scanner or another maintenance-score dashboard.
It sharpened **P-0515 Crate Off-Ramp Pack Kit** into a more believable, implementation-ready product.

## Why this moved now

The current Rust crate-sunset story is no longer empty.
That changes the shape of the missing value.

- Rust’s current lint docs still say deprecations should usually include what to use instead.
- Cargo’s SemVer guidance still treats deprecations as part of the downstream update experience.
- Cargo’s yank behavior still removes versions from new resolution without deleting the crate or telling downstream users where to go.
- `cargo update` still says users should try non-yanked versions or seek maintainer help.
- crates.io now has a Security tab with RustSec-backed affected version ranges, and the crates.io team says RustSec advisories remain the always-on path for removed malware crates.
- Docs.rs now shows live renamed-crate redirect patterns such as `sello-crypto` → `txgate-crypto`, which proves maintainers already improvise off-ramp surfaces today.

That combination means the missing crate is no longer “Rust needs better deprecation notes.”
The sharper missing crate is a **shared off-ramp contract** above today’s warnings, yanks, advisories, and ad hoc rename notes.

## Main planning move

This pass made the crate more concrete by promoting three first-class review objects that were still too implicit in the older proposal:

1. **successor intent map** — what is being sunset and what replacement class really applies,
2. **stopgap-horizon receipt** — whether a shim or last-safe pin is temporary and what sunset phase is in force,
3. **exit recipe witness** — what migration recipe actually ran and under which matrix.

That move matters because the archive had not yet separated:

- “deprecated” as a signal,
- “safe for now” as a stopgap,
- and “here is the checked path out” as a receiver-facing promise

into one implementation-ready `0.1` plan.
This pass fixes that.

## Main judgment after the pass

A worthy off-ramp crate contribution for Rust should now provide **more than a warning string**.
It should provide:

- explicit **successor intent truth** for what is being left and what replacement class applies,
- explicit **stopgap horizon truth** for shims, last-safe pins, and “migrate now” boundaries,
- explicit **recipe witness truth** for what path was actually checked,
- and one compact off-ramp bundle another maintainer or downstream team can inspect without reading a blog post archaeology stack.

That is more believable and more ecosystem-multiplying than either:

- “just another advisory client”,
- or “just another maintenance badge” with no successor plan attached.
