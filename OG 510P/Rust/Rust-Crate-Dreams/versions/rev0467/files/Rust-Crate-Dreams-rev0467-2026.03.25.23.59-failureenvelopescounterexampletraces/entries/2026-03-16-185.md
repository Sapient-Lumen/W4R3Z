# Entry 185 — future-incompat triage promoted into a fixture-first release-truth lane

This pass did not add a new proposal.
It upgraded **P-0478 Cargo Future-Incompat Triage Kit** into a more implementation-shaped lane with schema files, scenario packs, and a sharper explanation of what the crate should actually hand other people.

## Why this moved now

Several official signals now line up unusually well.

### 1. Cargo already has real report capture and recall substrate

Cargo’s future-incompat docs say dependency warnings are checked and can be shown in a full report.
The `cargo report` docs say Cargo can later display the latest report or a chosen report id, and can filter by package.

That means the missing crate is no longer detection or display.
It is the memory and policy layer above those surfaces.

### 2. Cargo itself already treats future-incompat reports as persisted build-adjacent state

The build-analysis project goal explicitly says Cargo does not persist much build information **other than build artifacts and future-incompatibility reports**.
That is a strong clue that the missing crate should treat report identity and report acquisition mode as first-class inputs.

### 3. The report surface can change across compiler eras

Rust release notes already record that const-eval errors entered future-incompatibility reports.
So a real crate needs a state like `reclassified_by_toolchain`, not just `new` versus `resolved`.

### 4. Cargo history already shows report-surface evolution and data-integrity concerns

The Cargo changelog records the move from `cargo describe-future-incompatibilities` to the `cargo report` surface and later fixes for duplicate saved reports.
That is another reason to freeze evidence-source receipts and capture locks instead of assuming the report substrate is timeless.

## Current judgment

The worthy crate here is not:

- another renderer for Cargo’s report text,
- another dependency updater,
- or another generic warning dashboard.

The worthy crate is the boring shared layer that can hand other people:

1. a **capture lock**,
2. a **finding snapshot**,
3. an **owner / waiver / release ledger**,
4. an **evidence-source receipt**,
5. and a **release-gate diff bundle**.
