# Entry 433 — broad frontier rerank favors horizontal ecosystem kits over narrow novelty crates

This pass deliberately **did not add another new proposal**.

The archive is now large enough that the more valuable move was to re-check the whole frontier against:

- current official Rust project goals and 2026 flagship themes,
- fresh 2025 survey/perf pain signals,
- current docs.rs build and target constraints,
- and the newer crates.io security surface.

The conclusion is that the most worthy missing crates are still the ones that **reduce repeated ecosystem decision cost** or **publish support-contract truth** across many domains.
They are not mostly new protocol wrappers, one-off adapters, or novelty abstractions.

## Why this rerank mattered

Fresh evidence reinforced a portfolio pattern the archive already suspected:

- build performance and iteration speed remain a major Rust pain point;
- Cargo itself is actively pursuing build analysis, build-dir layout reform, relink-don't-rebuild work, and faster dev-codegen paths;
- async complexity remains a live Rust challenge;
- online documentation remains the preferred reference surface;
- docs.rs remains a constrained, target-sensitive build environment rather than a magical canonical truth machine;
- crates.io now exposes more security signal, but that still does not answer “which crate should I choose?” or “what support posture am I accepting?” by itself;
- 2026 flagship themes strongly favor supply-chain clarity, safety-critical evidence, async usability, target/toolchain support, and higher-level workflow tooling.

That combination should push the archive toward **horizontal crates that help people choose, trust, explain, prove, and iterate**, not toward an endless tail of narrow wrappers.

## What should count as an epic crate contribution now

A worthy crate contribution should usually satisfy most of these tests:

1. it cuts a recurring decision cost felt across many domains, not one niche;
2. it exports **portable review artifacts** another team can inspect later;
3. it keeps adjacent truths separate instead of flattening them into one fake status word;
4. it composes with existing Rust/Cargo/docs.rs/crates.io substrate rather than replacing them;
5. it remains useful even before any language-team or compiler change lands;
6. it gives downstream users one sharper answer than today’s README / issue / blog / docs spelunking;
7. it has a plausible path to doctor checks, manifests, bundles, and receipts rather than vibes-only guidance.

## Stronger portfolio view after this pass

The archive should now prefer deepening existing horizontal lanes when a new pass can add:

- one new portable evidence artifact,
- one new lane boundary that stops cargo-cult comparisons,
- one new reusable doctor check,
- or one better bundle that other tools can import.

It should be **harder** from here to justify adding:

- another narrow format bridge,
- another single-runtime helper,
- another protocol/client wrapper,
- another AI shell without source-grounded receipts,
- or another “best crate” rubric without replayable decision bundles.
