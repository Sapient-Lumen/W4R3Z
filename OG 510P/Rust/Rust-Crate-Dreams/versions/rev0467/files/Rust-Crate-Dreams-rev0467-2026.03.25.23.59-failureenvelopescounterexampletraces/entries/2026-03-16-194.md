# Entry 194 — build-std lane promoted into a fixture-first stage-aware sysroot workbench

This pass did not add a new top-level proposal.
It upgraded **P-0430 Build-Std Workbench Kit** into a more implementation-shaped lane by freezing the next missing support-bundle layer: **stage-posture reports, evidence-source receipts, and a real fixture/schema corpus**.

## Why this moved now

Several current official Rust/Cargo signals line up unusually well.

### 1. The build-std roadmap is now explicitly staged

The July 2025 project-goals update split the work into a staged plan:

- Stage 1a: manual controls for enabling build-std
- Stage 1b: explicit `core` / `alloc` / `std` dependencies
- Stage 2: target-modifier / codegen support
- Stage 3: automatic std rebuild behavior

That means a worthy crate should stop acting as if every sysroot bundle is the same kind of evidence.
A future reader needs to know which stage posture the bundle assumes.

### 2. The Rust project has now named the RFC lanes

The October 2025 program-management update says build-std RFCs were posted for:

- context,
- always-on rebuild configuration,
- and explicit std dependencies.

That makes a **stage-aware recipe/lock/receipt crate** much more compelling than another thin helper wrapper.

### 3. Cargo already has enough raw substrate to capture today’s workflows

Cargo’s unstable docs already define today’s operational constraints:

- nightly Cargo,
- nightly rustc,
- `rust-src`,
- `-Z build-std`,
- and `-Z build-std-features`.

Cargo’s changelog also shows continuing investment in the area, including `build-std-features`, comma-separated parsing, and target-spec probing via `metadata.std`.

So the missing value is not “Cargo can do nothing here.”
The missing value is the boring capture/diff/review layer above it.

## Current judgment

The worthy crate here is not:

- another unstable-flag wrapper,
- another target JSON helper,
- another ABI-policy crate,
- or another debugger/source-support bundle.

The worthy crate is the boring stage-aware workbench that can hand other people:

1. one **sysroot recipe**,
2. one **sysroot lock**,
3. one **direct build receipt**,
4. one **stage-posture report**,
5. one **sysroot diff report**,
6. and one **evidence-source receipt**.
