# Entry 422 — compile-iteration deepened around generation witnesses, mixed-generation risk, and route-level code-epoch honesty

This pass again chose to **deepen P-0537 Compile Iteration Feedback Kit** instead of opening another hot-reload helper, watcher wrapper, or framework-specific live-coding lane.

The sharper question was:

> once a dev-loop bundle can describe edit scope, patch eligibility, activation boundaries, and stale-code residency, how does it also say **which generation of code a given route is actually running now**, **where mixed-generation execution is still possible**, and **what kind of witness backs that claim**?

## Why this deepening pass earned a full revision

Fresh sources made the next missing layer concrete:

- the March 2026 Rust challenges write-up still treats compile performance as a universal productivity tax and explicitly names hot reloading and faster linking as important mitigation routes;
- the 2025 compiler-performance survey still says incremental rebuild pain remains sharp and warns that hot-patching systems are exciting but still limitation-heavy;
- current `subsecond` docs say calls are detoured through a jump table to the latest version, but they also say **pointer versioning is not implemented yet**, `ptr_address` always reports the most up-to-date function, and nested `call` boundaries decide where patch application occurs;
- those same `subsecond` docs still document layout-triggered re-instancing, thread-local reset risk in the tip crate, and framework-local disposal strategies;
- current Chaud docs still say hot code becomes active only when a `#[chaud::hot]` function is called, and old code can continue via function pointers or trait objects;
- current `hot-lib-reloader` docs expose reload events, explicit serialize/deserialize handoff, and a `loaded_lib_name_template` with a `load_counter`, which shows that library generations exist but still does not tell another engineer which callbacks/tasks/routes are now on which generation.

That means the next worthy move for **P-0537** is not merely more state-continuity or activation prose.
It is to make **generation witnesses** and **mixed-generation-risk reports** first-class review artifacts.

## Main judgment after this pass

The top frontier still begins:

1. **P-0537 Compile Iteration Feedback Kit**
2. **P-0509 Crate Ecosystem Pathfinder & Decision-Pack Kit**
3. **P-0535 Dependency Lifecycle Transition Kit**
4. **P-0536 Crate Knowledge Pack Kit**
5. **P-0538 Concurrency Contract Kit**

But **P-0537** is stronger now because the archive no longer stops at:

- reload surface,
- restart ceiling,
- latency budget,
- edit scope,
- fast-path barriers,
- state continuity,
- activation boundaries,
- and stale-code residency.

It now has a clearer product shape for:

- **generation-witness reports**,
- **mixed-generation-risk reports**,
- **jump-table / dylib-load / entrypoint witness basis**,
- **route-level code-epoch honesty**,
- **generation cutoff vs activation cutoff distinctions**,
- and portable bundle inventory that keeps code-epoch truth separate from continuity, activation, and stale-code reachability.

## What should count as a worthy crate contribution in this lane now

A worthy compile-iteration crate should now provide other people:

1. **one generation-witness report** that says what code epoch a route is believed to run, what witness backs that belief, and how coarse or precise that witness really is;
2. **one mixed-generation-risk report** that says whether callbacks, tasks, trait objects, function pointers, or stored framework state may still hit older code while other routes have switched;
3. **one distinction between activation and generation** so “fresh code became reachable” is not mistaken for “every active route is now on the same epoch”;
4. **one distinction between witness precision and witness convenience** so jump-table latestness, dylib load counters, and pointer addresses are not over-read as precise route-level proofs;
5. **one separation between state continuity and code-generation truth** so preserved state does not imply homogeneous execution generation;
6. **one portable bundle** that keeps edit scope, barrier class, continuity, activation, stale-code risk, generation witness, mixed-generation risk, and restart fallback distinct.

That is closer to an ecosystem-worthy crate than another hot-reload demo, timing table, or framework-local wrapper.
