# 2026-03-05 (37): WebAuthn/passkeys device lab + secure email interop shipkit

This entry adds two “missing middle” kits where Rust already has components, but lacks shared **interop + diagnostic** defaults:

- **Passkeys are integrating fast**: WebAuthn + CTAP are standardized and widely deployed, but failures are notoriously device/browser dependent, and Rust teams lack a conformance runner with portable repro artifacts.
- **Secure email is still hard**: Rust has crypto and mail primitives, but end-to-end MIME + S/MIME/OpenPGP composition/verification and client-interop diagnostics remain fragmented.

## Added proposals

- **P-0200 — WebAuthn & Passkeys Interop + Device Lab Kit** — scenario DSL + browser-runner + virtual authenticator profiles, emitting `*.webauthnbundle.zip` evidence bundles with stable transcripts and verdicts.
  Sources: https://www.w3.org/TR/webauthn-2/ ; https://www.w3.org/TR/webauthn-3/ ; https://fidoalliance.org/specs/fido-v2.2-rd-20230321/fido-client-to-authenticator-protocol-v2.2-rd-20230321.html ; https://crates.io/crates/passkey ; https://github.com/pando85/soft-fido2

- **P-0201 — Secure Email Interop ShipKit** — deterministic MIME normalization + DKIM/SPF/DMARC/ARC verification + S/MIME (CMS) and OpenPGP/MIME workflows, emitting `*.mailbundle.zip` diagnostic artifacts for CI and investigations.
  Sources: https://datatracker.ietf.org/doc/html/rfc8551 ; https://github.com/stalwartlabs/mail-auth ; https://crates.io/crates/sequoia-openpgp ; https://crates.io/crates/cms ; https://docs.rs/openssl/latest/openssl/cms/index.html
