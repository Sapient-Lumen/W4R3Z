# Entry 323 — local-first sync deepened for presence posture, history retention, and branch-claim honesty

This pass deepened **P-0076 Local-first Sync Kit** instead of opening another collaboration engine, cursor/presence framework, or transport runtime.

## Why this lane earned another serious pass

The archive already had sharper answers for:

- repo identity and durable sync-state receipts,
- transport/bootstrap/session truth,
- membership/key-epoch receipts,
- and portable sync bundles.

What it still needed was a more disciplined answer to two common but under-specified questions:

> “Is this live collaboration state actually durable or only session-scoped?”

> “Does this profile still support full history/branch comparison, or only current-state sync after export or compaction?”

Current local-first substrate now makes those questions concrete enough to standardize.

## What moved this time

The main planning move was to stop treating all collaboration-state as one kind of truth.

This pass elevated two more review objects into first-class status for **P-0076**:

1. **presence-surface truth** — whether awareness/cursor/session metadata is best-effort, persisted, identity-strong, and exportable;
2. **history-retention truth** — whether the selected profile still supports full history, branch/time-travel claims, and direct comparison after compaction or shallow-snapshot export.

## Why this matters now

The ecosystem evidence is no longer ambiguous:

- Automerge markets local-first state with old-version comparison, branching, and merging.
- Automerge Repo also documents `DocHandle.broadcast()` as **ephemeral**, **not persisted**, with **no delivery guarantee**, and says its `PeerId` is not a useful user identifier.
- Yrs models sync protocol handling in the context of an `Awareness` structure and can send/receive awareness updates separately.
- Loro now exposes version control, checkout/time-travel, and export modes including shallow snapshots that keep current state while narrowing older-history reach.

That means a worthy local-first crate should not let “sync works” quietly over-claim durable presence or full historical comparability.

## Main judgment after the pass

A worthy local-first contribution should now provide more than a durable sync receipt plus a relay/bootstrap note.
It should also provide:

- one explicit **presence-surface receipt**,
- one explicit **history-retention receipt**,
- and one conservative rule for when current-state sync is still true but branch/history claims have narrowed.
