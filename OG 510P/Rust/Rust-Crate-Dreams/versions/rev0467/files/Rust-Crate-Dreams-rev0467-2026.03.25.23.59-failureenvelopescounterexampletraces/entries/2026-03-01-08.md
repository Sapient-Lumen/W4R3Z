# 2026-03-01 (08) — Cargo event streams, Web IME, eBPF packaging, and reproducibility prior art

## Signals (with sources)

- **Cargo still lacks a stable JSON event stream for its own messages**, even though IDEs and tools consume rustc JSON; this is tracked as a long-running Cargo feature request.  
  Source: “Provide Cargo messages as JSON messages” — https://github.com/rust-lang/cargo/issues/8283

- **Proc macros can break `--message-format=json` consumers by printing non-JSON lines**, which causes tooling (rust-analyzer, cargo_metadata consumers, jq) to fail parsing.  
  Source: “Proc macros can cause non-json output … despite message-format=json” — https://github.com/rust-lang/cargo/issues/8179

- **Rustc JSON is documented and widely used**, but Cargo-level messages still leak as text; there’s a mismatch between what rustc can provide and what Cargo forwards.  
  Source: rustc book “JSON Output” — https://doc.rust-lang.org/beta/rustc/json.html

- **IME/composition support is still incomplete in the Rust GUI stack, and Web (WASM) is a current pain point**: canvas cannot receive CompositionEvent, leading to hacky hidden-input workarounds and tricky fullscreen behavior.  
  Source: winit issue “Add IME support for Web (WASM)” — https://github.com/rust-windowing/winit/issues/4424  
  Related: winit tracking issue — https://github.com/rust-windowing/winit/issues/1497

- **Rust eBPF has multiple viable toolchains (Aya, libbpf-rs, redbpf)**, but the “app packaging + deploy + test harness” story is still mostly bespoke per project.  
  Sources: eBPF Foundation projects list — https://ebpf.foundation/projects/ ; awesome-aya — https://github.com/aya-rs/awesome-aya

- **Reproducibility tooling is appearing as Cargo subcommands**, e.g. `cargo-reproduce` (2025) which normalizes the build environment and verifies bit-for-bit reproducibility. This affects our own reproducibility proposals: we should integrate, not reinvent.  
  Sources: lib.rs page for cargo-reproduce — https://lib.rs/crates/cargo-reproduce ; Cargo issue on reproducible `.crate` archives — https://github.com/rust-lang/cargo/issues/8612  
  Background: reproducible-builds definition — https://reproducible-builds.org/

## Repo implications

- Add proposal: **Cargo Event Stream** (P-0042) — stable NDJSON events for Cargo + rustc, with explicit handling of build-script/proc-macro stdout pollution.
- Add proposal: **Winit Web IME Kit** (P-0043) — a shared, well-tested hidden-input bridge + composition model for canvas-based apps.
- Add proposal: **eBPF ShipKit** (P-0044) — packaging + deployment + integration-test harness for eBPF apps across kernels, bridging Aya/libbpf-rs.
- Update prior-art lists and existing proposals (`cargo-repro-pack`, `text-input-kit`) to acknowledge current tooling and sharpen scope.
