# Entry 120 — vendored-source truthfulness and CPU support promises

This pass stayed disciplined by promoting two seams that sit above already-real substrate but still do not have a boring maintainer workflow.

First, it separated **vendored/source-replaced dependency truthfulness** from broader mirroring, air-gap, or package-review work. Cargo already has source replacement, directory sources, local registries, `cargo vendor`, and offline-preparation substrate. But maintainers still cannot hand one another one compact artifact that says **which source roots actually resolved the graph, how close to registry-equivalent the result remained, and whether the claimed offline posture is honest**.

Second, it separated **CPU support promises** from both compiler-flag coherence and generic performance tuning. Rust already has `target-cpu`, `target-feature`, `cfg(target_feature)`, and runtime feature detection. But maintainers still cannot hand one another one compact artifact that says **what hardware baseline a release actually promises, which optimized paths are runtime-guarded, whether fallbacks exist, and how plausible an illegal-instruction failure really is**.

New proposals:

- P-0496 Cargo Vendor & Source Parity Kit
- P-0497 CPU Baseline & Runtime Dispatch Contract Kit

Why these rose:

- **P-0496** rose because Cargo’s source-management substrate is now rich enough that the sharper gap is no longer “some way to vendor crates.” The sharper gap is a **source-origin / registry-equivalence / offline-readiness** bundle above source replacement, `cargo vendor`, and mixed source configurations.
- **P-0497** rose because Rust’s CPU-feature substrate is now rich enough that the sharper gap is no longer “some way to write SIMD or tune builds.” The sharper gap is a **hardware support promise / dispatch manifest / illegal-instruction risk** artifact above `target-cpu`, `target-feature`, and runtime detection.

What changed in archive judgment:

- The archive now draws a cleaner line between **mirrors and air-gap transfer**, **package/publish review**, and **source-root truthfulness for vendored builds**.
- The archive now draws a cleaner line between **ABI coherence**, **toolchain/target support policy**, **foreign-SDK release promises**, and **CPU baseline support contracts**.

Archive hygiene added in this pass:

- Added an amnesia resistor warning future revisions not to confuse `cargo vendor` or source replacement with an already-boring answer to “what source roots really resolved this graph and is our offline claim honest?”
- Added an amnesia resistor warning future revisions not to confuse `target-cpu`, `target-feature`, or runtime feature detection with an already-boring answer to “what hardware baseline does this release promise and how are optimized paths guarded?”
