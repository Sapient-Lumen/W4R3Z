# Entry 278 — crate upgrade support sharpened around lane-selection origin and ambient workspace-default drift

This pass came from noticing that the upgrade pack had become honest about scope, capture context, sparse matrix coverage, export posture, and public trace routes while still carrying one quiet bluff:

> the reviewed lane could still sound deliberately scoped even when Cargo ambient defaults were the real reason sibling members or gated targets stayed outside it.

## What moved this time

Two donor patterns kept surviving scrutiny:

- **Rust-Needs-and-Dreams** kept insisting that invocation subject, manifest walk, workspace attachment, and selection causes are their own seam instead of noise around the “real” report.
- **SlopOS** kept insisting that once a family gets wide enough, membership/exclusion needs one compact explicit map instead of ambient repo structure and reader inference.

## Main planning move

The previous passes already established:

- package-scope truth,
- exact capture-context truth,
- sparse coverage-matrix truth,
- and public/export/readiness honesty surfaces.

This pass adds one sharper review object above them:

1. **lane-selection origin truth** — each upgrade lane can now say what the invocation subject was, how the manifest walk resolved, how the workspace attached, which package/feature/target selection mode produced the lane, and which omissions still come from ambient Cargo behavior rather than deliberate maintainer scope.

## Why this matters

Without **lane-selection origin truth**, the lane still permits an ordinary lie:

- a workspace-root run that inherited `default-members` can read like an explicit maintainer choice to omit sibling members,
- and a gated target can read like it was reviewed cleanly when it simply never entered the selected lane.

That is not cosmetic.
It is the difference between “this pack checked exactly what maintainers intended to check” and “this pack checked the lane Cargo ambient defaults happened to select.”

## Main judgment after the pass

A worthy upgrade-support crate should now provide more than exact package scope and exact observed cells.
It should also provide:

- one compact **lane-selection receipt** for how the reviewed lane was actually chosen,
- one bounded warning surface for ambient workspace/default-member/gated-target omissions,
- and one explicit separation between “not selected into the lane” and “selected and reviewed clean.”

That keeps the lane from quietly borrowing deliberate-scope authority from Cargo ambient behavior.
