# Entry 101 — Rust transition-helper kits: parallel parity, cfg availability, EII adoption, and safety-contract consumption

Added four proposals after another pass over places where Rust is making language/compiler progress, but ordinary maintainers still lack a compact artifact layer for reviewing what changed and how to adopt it.

New proposals:

- P-0450 Parallel Front-End Parity Lab Kit
- P-0451 Cfg Availability Ledger Kit
- P-0452 Externally Implementable Item Adoption Kit
- P-0453 Safety Contract Consumer Kit

Why these rose:

- **P-0450** rose because parallel front end is clearly moving toward stabilization, with explicit work on Cargo/rustc-perf/tool support, but ordinary teams still lack a **single-vs-parallel parity receipt** they can attach to CI or upstream reports.
- **P-0451** rose because `doc_cfg` and rustdoc JSON now make conditional API visibility much more tractable, but maintainers still do not have a **feature/target availability ledger** for semver and release review.
- **P-0452** rose because externally implementable items are becoming a real language direction for panic handlers, allocators, and other customization points, but crate authors still lack a **migration-and-diagnostics kit** for exposing those hooks in a boring, reviewable way.
- **P-0453** rose because contract attributes and std-verification work are creating real machine-readable specification substrate, but users still lack a **consumer-layer snapshot/diff/runtime-receipt kit** above compiler work and individual verification tools.

What changed in archive judgment:

- The archive now remembers a slightly sharper rule: when Rust turns something into **first-class metadata or substrate**, the missing crate may be the one that makes that metadata reviewable for maintainers.
- A worthy crate contribution here may be a **parity lab**, **availability ledger**, **customization-point adoption kit**, or **contract consumer** rather than another core engine.
- This pass also improves distinctness from nearby proposals: these are not raw compiler goals, not verification engines, and not alternate docs renderers.

Archive hygiene added in this pass:

- Added an amnesia resistor reminding future passes not to confuse “Rust can now expose this information” with “maintainers already have a boring workflow for using it.”
- Added known-existing notes so later revisions do not mistake rustc-perf, rustdoc badges/JSON, current runtime attributes, or existing verification tools for proof that the coordination layer is already solved.
