# Entry 193 — lock-contention lane promoted with exactness receipts and optional imported-session context

This pass did not add a new proposal.
It upgraded **P-0490 Cargo Lock Contention Witness Kit** into a more implementation-shaped lane by freezing the next missing support-bundle layer: **evidence-source receipts, exactness reports, and optional build-analysis session links**.

## Why this moved now

Several current official Rust/Cargo signals line up unusually well.

### 1. Shared target-dir is no longer the whole coordination story

Cargo’s build cache docs now explicitly distinguish **target-dir** (final artifacts) from **build-dir** (intermediate artifacts).
The March 13, 2026 build-dir-layout-v2 call-for-testing says teams should run tests, release processes, and anything else that may touch `build-dir` / `target-dir` with the new layout enabled, and says Cargo 1.91 already lets users separate intermediate build artifacts from final artifacts.

That means a worthy contention crate should stop acting as if “use a different target dir” is the complete receiver-facing explanation.

### 2. rust-analyzer still documents a real blocking trade-off

The rust-analyzer FAQ still says rust-analyzer’s background Cargo activity can block manually executed Cargo commands from making progress (or vice-versa), and may cause unnecessary recompilations from cache thrashing.
Its config docs still present `cargo.targetDir` as the mitigation, explicitly trading duplicated artifacts for independent progress.

That keeps live contention real enough that a support bundle is still missing value, even as Cargo evolves.

### 3. Cargo build-analysis creates a good optional support seam

Cargo’s unstable docs now expose persisted sessions plus `cargo report sessions`, `cargo report timings`, and `cargo report rebuilds`.
That gives **P-0490** a useful new receiver-facing artifact: a conservative way to attach one Cargo session as supporting context.

But it does **not** mean a session id proves which process held the lock.
That is exactly why this lane needed explicit **exactness** and **evidence-source** artifacts.

## Current judgment

The worthy crate here is not:

- another build profiler,
- another scheduler,
- another build-history warehouse,
- or another editor wrapper framework.

The worthy crate is the boring incident bundle that can hand other people:

1. one **root-sharing report**,
2. one **lock-wait receipt**,
3. one **collision diagnosis**,
4. one **mitigation plan**,
5. one **evidence-source receipt**,
6. one **exactness report**,
7. and one **optional build-analysis session link**.
