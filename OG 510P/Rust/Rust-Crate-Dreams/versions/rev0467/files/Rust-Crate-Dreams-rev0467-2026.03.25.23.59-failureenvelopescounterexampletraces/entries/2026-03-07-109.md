# Entry 109 — Cargo config receipts and rustdoc doc.parts handoff bundles

This pass stayed on the archive’s strongest recent pattern: **Rust already has more substrate than ordinary teams can comfortably explain or hand around**.

New proposals:

- P-0474 Cargo Config Layer Receipt Kit
- P-0475 Rustdoc Mergeable Info Handoff Kit

Why these rose:

- **P-0474** rose because Cargo configuration is now a serious workflow surface: hierarchical probing, include graphs, environment-variable precedence, `--config` overrides, credential providers, and an unstable `cargo config` viewer all exist. But teams still do support/debugging by folklore. The sharper missing layer is an **effective-config / origin-trace / redacted support bundle**, not another parser.
- **P-0475** rose because rustdoc and Cargo now have explicit mergeable cross-crate documentation substrate (`doc.parts`, merge/finalize modes, and nightly Cargo support), especially for large workspaces and non-Cargo build systems. But there is still no boring **manifest / compatibility / finalize receipt** for handing those parts between CI stages or debugging drift.

What changed in archive judgment:

- The archive now treats **configuration** as one of Cargo’s most underrated missing artifact seams.
- The archive also now treats **cross-crate docs handoff** as distinct from docs portals or docs.rs parity: the missing value is a compact handoff contract for `doc.parts`, not another way to browse docs.
- A worthy crate contribution here may be an **origin trace**, **redacted receipt**, **compatibility report**, or **finalize bundle** rather than a new executor or UI.

Archive hygiene added in this pass:

- Added an amnesia resistor warning future revisions not to confuse Cargo’s config docs, includes, env precedence, or unstable `cargo config` command with an already-boring effective-config workflow.
- Added an amnesia resistor warning future revisions not to confuse rustdoc’s mergeable-info substrate with a maintainer-grade handoff workflow for split or distributed docs pipelines.
