# Entry 414 — crate-knowledge deepened around item witnesses, opaque rustdoc IDs, and anchor-drift discipline

This pass chose to **deepen P-0536 Crate Knowledge Pack Kit** again rather than open a fresh docs/search/tooling lane.

The sharper question was:

> if a compact crate-knowledge pack resolves citations, how does it keep those citations attached to the *same conceptual item* when rustdoc JSON IDs are blob-local, docs.rs pages can be floating or target-sensitive, and rendered documentation surfaces are not themselves a stable identity contract?

## Why this deepening pass earned a full revision

Fresh primary sources made the next missing layer concrete:

- the rustdoc JSON RFC says item IDs in JSON are opaque, happen to be compiler `DefId`s, and are **not guaranteed to be stable across compiler invocations**;
- the same RFC says rustdoc HTML is explicitly not stabilized and should not be treated as a scraping contract;
- docs.rs shorthand URLs intentionally float across `latest`, semver ranges, and page redirects;
- docs.rs hosted builds remain target-aware, with configurable default targets and multiple built targets;
- docs.rs download archives are helpful fallback materials, but they are not the same thing as durable public item anchors;
- and RFC 3662 says rustdoc `doc.parts` cross-crate information is unstable and not compatible across disparate rustdoc versions.

That means the next worthy product move for **P-0536** is not only “resolve a citation URL.”
It is to make the pack’s **item identity witnesses** reviewable.

## Main judgment after this pass

The top frontier still begins:

1. **P-0537 Compile Iteration Feedback Kit**
2. **P-0509 Crate Ecosystem Pathfinder & Decision-Pack Kit**
3. **P-0535 Dependency Lifecycle Transition Kit**
4. **P-0536 Crate Knowledge Pack Kit**
5. **P-0538 Concurrency Contract Kit**

But **P-0536** is stronger now because the archive no longer stops at:

- material basis,
- export policy,
- excerpt lineage,
- query support,
- claim traces,
- citation locators,
- and citation-capability ceilings.

It now has a clearer product shape for:

- **item-witness manifests**,
- **identity-fidelity reports**,
- **cross-blob opaque-ID handling**,
- **same-item versus same-locator separation**,
- and doctor rules that reject fake “stable identity” stories built from raw rustdoc JSON IDs or floating docs.rs pages.

## What should count as a worthy crate contribution in this lane now

A worthy crate-knowledge pack should provide other people:

1. **one item-witness manifest** that binds exported excerpts/claims to exact crate, version, target, path, kind, and source-span context without pretending a raw rustdoc JSON ID is durable;
2. **one identity-fidelity report** that says whether a reused witness is exact, path-derived, target-bound, approximate, or manual-review-only;
3. **one separation between item identity and citation route** so a changed docs.rs route does not silently imply a different API item;
4. **one rule for blob-local opaque IDs** that forbids cross-version or cross-build identity reuse based only on the JSON item ID;
5. **one doctor path** that warns when a pack claims stable identity without witness coverage.

That is closer to an ecosystem-worthy crate than a generic “LLM pack for docs.”
