# Entry 235 — cfg availability-ledger deepening pass

Today’s pass did not promote a new crate lane.
It made **P-0451 Cfg Availability Ledger Kit** more reviewable.

## Main judgment

The archive already had a decent story for availability classes, origin receipts, docs-only drift, docs.rs-only slices, and fidelity reports.
But the next sharpener was still missing:

- **which slice was actually witnessed**,
- **how a human-facing gate summary was normalized**, and
- **whether a public item’s effective gate was inherited through re-export lineage rather than declared locally**.

Those are the review objects that keep “rustdoc showed a gate badge” from masquerading as “downstream users can rely on this item in that slice”.

## Why this was worth a pass

The current web scan made the boundary clearer:

- RFC 3631 and rustdoc’s `doc(auto_cfg)` work improve how conditional APIs are shown, but they do not themselves publish a release-review ledger.
- rustdoc’s advanced-features docs say `cfg(doc)` can widen documentation visibility and that this cfg is not passed to doctests.
- docs.rs says `cfg(docsrs)` applies only to the final crate being documented, not dependencies.
- docs.rs metadata can add features, targets, and custom `rustc` / `rustdoc` args that change what a user sees.
- Cargo build scripts and `cargo::rustc-check-cfg` make custom cfgs more disciplined, but still do not answer which public item is genuinely available in which slice.

That means the missing value is increasingly not another one of those pieces.
It is the joined, reviewable artifact that tells a downstream user what was actually observed, how the visible gate was simplified, and where lineage matters.

## Working rule after this pass

Do not invent another nearby crate until **P-0451** proves too cramped to hold:

- availability classes,
- origin receipts,
- slice-witness receipts,
- gate-normalization reports,
- re-export-lineage reports,
- fidelity reports,
- and release diffs for conditional drift.

If those still fit cleanly, the right move is to deepen **P-0451**, not split it prematurely.
