# Entry 118 — registry-auth diagnosis receipts and source-path hygiene contracts

This pass stayed disciplined in two ways.

First, it separated **registry-auth diagnosis** from both publish provenance and registry implementation. Cargo now clearly has credential providers, authenticated sparse-registry substrate, and trusted-publishing-adjacent identity flows. But maintainers still cannot hand one another a boring artifact that says **which registry, which provider chain, which stage, and why it failed**.

Second, it separated **source-path hygiene and source lookup** from broader debuggability posture. Rust now has real remap/trim-path substrate and explicit `rust-src` / `rustc-dev` components, but maintainers still cannot hand one another a boring artifact that says **what paths were sanitized, which virtual `/rustc/...` paths remain, and what source components are needed for debugging**.

New proposals:

- P-0492 Cargo Registry Auth Doctor Kit
- P-0493 Source Path Hygiene & Debug Source Kit

Why these rose:

- **P-0492** rose because Cargo’s registry-auth world now has real provider-chain, protocol, and authenticated-registry substrate, but the support workflow is still mostly raw logs and tribal knowledge. The sharper gap is a **provider-chain / operation-stage / redacted diagnosis bundle**, not another token store or registry server.
- **P-0493** rose because remap-paths, trim-paths, virtual `/rustc/<hash>/...` paths, and installable `rust-src` / `rustc-dev` components now make source-path behavior a real release/support surface. The sharper gap is a **path-hygiene / virtual-source / component-hint receipt**, not another generic debugger tool.

What changed in archive judgment:

- The archive now draws a cleaner line between **publish receipts**, **trusted-publishing enablement**, and **registry-auth diagnosis**.
- The archive now draws a cleaner line between **broad debuggability posture**, **visualizer compatibility**, and **source-path/source-lookup contracts**.

Archive hygiene added in this pass:

- Added an amnesia resistor warning future revisions not to confuse Cargo’s documented credential-provider protocol and authenticated sparse-registry substrate with an already-boring maintainer support workflow.
- Added an amnesia resistor warning future revisions not to confuse `--remap-path-prefix`, trim-paths, and installable source components with an already-boring answer to “why can’t this debugger find the source?”
