# Entry 156 — resolver why-bundles also need dependency identity and rename-surface truth

This pass again did **not** add another top-level proposal.

Instead, it sharpened **P-0468 Cargo Resolver Explanation Kit** where the archive still had unusually high leverage: the crate now has a clearer plan for **dependency identity, rename surfaces, and registry truth** above today’s mixed Cargo surfaces.

## Main judgment

The important missing crate is not another manifest linter.
It is a **receiver-facing resolver bundle** that can tell another person:

- which local dependency key referred to the dependency in the subject manifest,
- which original package name Cargo was actually requesting,
- which token belongs in manifest feature references,
- how `cargo metadata` represented the rename,
- how registry / publish surfaces represented the same rename,
- and whether inheritance or registry publication kept the answer conservative or manual-review-required.
