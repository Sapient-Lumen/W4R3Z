# Entry 115 — debuggability contracts and foreign-SDK consumer diagnosis

This pass kept the archive on the same sharpened rule: when Rust already has meaningful substrate, the better missing crate is often the **boring workflow contract above it**, not another builder or another giant platform.

New proposals:

- P-0486 Debuggability Support Contract Kit
- P-0487 Foreign SDK Consumer Doctor Kit

Why these rose:

- **P-0486** rose because Cargo, `rustc`, and the language now already expose a meaningful debugging-support surface — debug levels, split debuginfo, strip modes, debugger visualizers, and path-sanitization work — while the survey still says debugging remains a top productivity problem. The sharper gap is a **support posture / symbol-sidecar / visualizer / drift receipt**, not another general debugger wishlist.
- **P-0487** rose because Python packaging, PyO3, and Apple SDK distribution now already define a lot of artifact-side rules — wheel tags, wheel format, `abi3`, free-threaded caveats, XCFramework packaging, checksums, privacy manifests, and signatures — but downstream users still lack a compact **consumer environment / artifact intake / mismatch diagnosis bundle**.

What changed in archive judgment:

- The archive now distinguishes more sharply between **producer-side release promise drift** and **consumer-side adoption diagnosis** for foreign SDKs. A worthy crate may not build or publish anything at all; it may instead make adoption failures explainable.
- The archive now treats **debuggability** as a support contract with several distinct postures (`interactive debugger`, `backtrace only`, `symbolication only`, `manual review`) instead of one vague “debug build versus release build” story.
- The archive continues to favor joined artifacts that make support and review portable across teams, CI runs, and operating systems.

Archive hygiene added in this pass:

- Added an amnesia resistor warning future revisions not to mistake existing debuginfo knobs or debugger visualizers for a boring maintainer-grade debugging-support workflow.
- Added an amnesia resistor warning future revisions not to collapse foreign-SDK **release promises** and foreign-SDK **consumer diagnosis** into one undifferentiated tool idea.
