# Entry 88 — frontier pass: MCP evidence, Sigma↔OCSF mapping receipts, WoT profile/binding replay, GA4GH portability bundles, and Frictionless package locks

Added five proposals after a pass aimed at **coordination-layer crates** above ecosystems that already have meaningful standards or substrate. The pattern held again: what many downstream Rust users need is not another implementation of the whole stack, but a **boring default for version pinning, semantic diffs, replay traces, and shareable evidence bundles**.

New proposals:

- P-0392 MCP Protocol Conformance, Transcript & Capability Kit
- P-0393 Sigma + OCSF Detection Interop Workbench Kit
- P-0394 WoT Thing Description, Binding & Profile Interop Kit
- P-0395 GA4GH DRS + TES + WES Portability Evidence Kit
- P-0396 Frictionless Data Package + Table Schema Workbench Kit

Pass notes:

- **MCP** rose because the protocol and official Rust SDK now exist, but the sharper missing crate is still a **transport-neutral transcript and capability-evidence layer** rather than yet another SDK.
- **Sigma + OCSF** made the cut because the real coordination pain is at the **rule/taxonomy/schema mapping seam**, especially once correlations and normalized event schemas enter the picture.
- **WoT** rose because Rust has enough TD/server substrate to matter, while the missing contribution is a **profile-aware affordance replay and binding-diff workbench**.
- **GA4GH DRS/TES/WES** made the cut because the standards stack is real and deployed, but Rust still lacks a **portable run/object receipt layer** that survives cross-institution handoff.
- **Frictionless Data Package** rose because the standards remain widely useful and Data Package v2 has revived the need for a **small, well-scoped core workbench** in ecosystems that still lack a boring Rust default.

Archive hygiene added in this pass:

- Added a reminder to separate **official SDK maturity** from **protocol coordination gaps**. When a spec already has an official SDK, future proposals should say clearly whether the missing crate is an implementation, a validator, or an evidence layer above it.
- Added a reminder to separate **base specifications** from **profiles, patterns, and house conventions**. Many good crates in this archive are really profile/pattern workbenches, not generic parsers.
