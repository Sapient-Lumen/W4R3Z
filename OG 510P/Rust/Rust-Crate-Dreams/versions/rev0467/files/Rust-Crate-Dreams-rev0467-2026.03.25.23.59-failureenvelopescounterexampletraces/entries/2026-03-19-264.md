# Entry 264 — crate authority support sharpened around authority origin, fallback order, and refusal posture

This pass did **not** add another sandbox runtime, another capability-based replacement for `std`, or another static authority scanner.
It sharpened **P-0519 Crate Authority Surface Pack Kit** into a more implementation-ready support crate.

## Why this moved now

Rust’s authority story is no longer missing raw substrate.
That changes the shape of the missing value.

- The December 2025 Rust vision-doc work explicitly says crates need more **supportive interfaces**.
- The 2025 State of Rust survey still says online docs and code remain the main learning surfaces.
- `ambient-authority` still makes one crucial support boundary explicit: ambient power should be an intentional opt-in, not an invisible default.
- `cap-std` still says `open_ambient_dir` is **not sandboxed** and may access any path the host process can access.
- `cap_directories::ProjectDirs::from` still makes another subtle truth explicit: “where should I put cache/config data?” is itself an ambient-authority choice.
- `cap-tempfile` now makes the temp-path boundary concrete by exposing both ambient `tempdir(...)` and capability-oriented `tempdir_in(&Dir)` variants.
- `getrandom` now makes entropy-origin ownership unusually explicit: a custom backend should ideally be defined in the **root crate**, must be defined only once, and upstream library crates should not define it outside tests and benchmarks.
- Cargo still exposes a large environment/build-script surface, and build scripts are still compiled and executed before the package build with environment-variable inputs.
- `cargo_capsec` now exists as a real static-scanning prior art lane, which makes the missing value look even less like “another scanner” and more like “the maintainer-authored contract above the scan”.

That combination means the missing crate is no longer “Rust needs capability APIs” or “Rust needs authority scans”.
The sharper missing crate is a **crate-authored authority contract** above today’s capability, tempdir, project-dir, entropy, environment, and static-scan substrate.

## Main planning move

This pass promoted five review objects to first-class status for **P-0519**:

1. **authority origin** — where a power comes from: injected handle, caller path, host-supplied capability, ambient directory discovery, ambient tempdir, OS entropy, or manual-review territory,
2. **fallback order** — what the crate tries first, second, and last before it widens into more authority,
3. **refusal posture** — whether denied authority causes a hard error, degraded mode, silent fallback, retry, or manual review,
4. **profile witness** — whether the claimed offline/sandbox/deterministic profile was actually exercised under denial/restriction,
5. **release drift** — whether origin, fallback, or refusal behavior changed across versions.

That move matters because the archive had already made **authority budget** and **injection boundary** explicit, but it still did not make the difference between:

- “a capability-oriented path exists somewhere”,
- “the crate actually prefers that path before ambient fallback”,
- and “the crate fails honestly when ambient access is denied”.

This pass fixes that.

## Main judgment after the pass

A worthy authority-support crate contribution for Rust should now provide **more than a map of suspicious imports**.
It should provide:

- explicit **authority-origin truth**,
- explicit **fallback-order truth**,
- explicit **refusal-posture truth**,
- explicit **injection-boundary truth**,
- explicit **profile-witness truth**,
- and one compact **authority-surface diff** another maintainer can inspect without reconstructing the story from source spelunking, environment variables, platform-directory helpers, or ambient temp/entropy defaults.

That is more believable and more ecosystem-multiplying than either:

- “just use `cap-std`”,
- “just use a static scanner”,
- “just grep for `std::fs` and `env::var`”,
- or “just assume offline/sandbox-ready means the same thing everywhere”.
