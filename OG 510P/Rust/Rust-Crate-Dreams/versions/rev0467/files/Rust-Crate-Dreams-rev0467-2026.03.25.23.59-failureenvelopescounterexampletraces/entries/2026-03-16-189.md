# Entry 189 — rebuild explanation promoted into a fixture-first support-bundle lane

This pass did not add a new proposal.
It upgraded **P-0469 Cargo Rebuild Explanation Kit** into a more implementation-shaped lane with sharper boundaries, stronger exactness receipts, and a broader fixture corpus.

## Why this moved now

Several official Cargo signals line up unusually well.

### 1. Cargo’s build-analysis substrate is now real enough that downstream crates can stop pretending they must invent the recorder

The build-analysis goal explicitly says Cargo is recording build metadata across invocations and introducing report commands for rebuild reasons and timings.
The current unstable docs go further and describe persisted JSONL logs in `$CARGO_HOME/log/`, unique session ids, and the `cargo report sessions` / `timings` / `rebuilds` command set.

### 2. Cargo 1.94 made the user-facing report surface more concrete

The 1.94 Cargo development-cycle update says `cargo report timings` kept gaining missing features, `cargo report rebuild` / `rebuilds` was added for rebuild diagnosis, and `cargo report sessions` exists to find the ids needed for the other commands.
That makes “freeze one imported session into one stable bundle” much more plausible than it was before.

### 3. Rebuild fanout is still a live upstream pain point

The relink-don’t-rebuild goal is explicitly about avoiding reverse-dependency rebuilds after changes that users intuitively expect to be private.
So a crate that can hand someone a conservative, reviewable answer to “what rebuilt, and how sure are we?” still fills a real gap.

### 4. Locking and shared-cache pain remain adjacent, but separate

The build-dir-layout goal keeps lock contention and shared-cache interference squarely in scope.
That means a good rebuild bundle has to preserve when a story is really about *waiting on a root* rather than *proving a rebuild cause chain*.

## Current judgment

The worthy crate here is not:

- another profiler UI,
- another unstable JSON parser pretending Cargo wording is fixed forever,
- or another giant Cargo doctor that claims to solve every build mystery.

The worthy crate is the boring support layer that can hand another person:

1. a **session-freeze receipt**,
2. a **per-unit rebuild explanation bundle**,
3. an **evidence-source receipt**,
4. an **exactness ledger**,
5. a **timings pointer**,
6. and a **small diffable ZIP** that survives CI, bug reports, and internal support threads.
