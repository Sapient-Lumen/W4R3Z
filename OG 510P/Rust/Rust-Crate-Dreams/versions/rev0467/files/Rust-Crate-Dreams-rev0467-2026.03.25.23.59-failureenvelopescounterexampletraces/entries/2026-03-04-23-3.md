# 2026-03-04 (late-3): debugger UX kit + memory observability kit + GPU compute interop kit

This update targets a “developer throughput” trio that keeps biting Rust teams:

1) **Debugger UX regressions** (pretty printing and formatters drifting across LLDB/GDB/IDEs).  
2) **Memory observability workflows** (capture → attribute → diff → CI gate) that are still fragmented.  
3) **GPU compute ergonomics** (CUDA/ROCm/wgpu compute) that are ingredients, not a unified kit.

## New epic proposals

- **P-0083 Debugger UX Kit** (`proposals/debugger-ux-kit.md`)  
  A versioned pretty-printing pack + `cargo debug-doctor` + CI conformance goldens.  
  Evidence: community stopgaps for LLDB pretty printing and reported pain when IDE formatters regress.

- **P-0084 Memory Observability Kit** (`proposals/memory-observability-kit.md`)  
  Cargo-native memory capture bundles (`.memz`), allocator-based tracing by default, optional eBPF backend, plus diffs and CI exit codes.  
  Evidence: allocator tracing crates and production writeups that highlight the “stitch it together” reality.

- **P-0085 GPU Compute Interop Kit** (`proposals/gpu-compute-interop-kit.md`)  
  A backend-agnostic core with cargo-native kernel packaging and optional CUDA/ROCm/wgpu backends + conformance vectors.
