# Entry 84 — frontier pass: feature-flag behavior, protobuf/gateway seams, notebook protocol evidence, remote-build digests, and 3D tileset structure

Added five proposals after a fresh pass aimed at **ecosystem variety plus high practical leverage** while staying honest about where Rust already has substrate. This pass favored places where the missing value is **not** “another engine/server/runtime”, but instead:

- profile locks,
- descriptor or protocol traces,
- replayable scenarios,
- semantic diffs,
- validator/capability normalization,
- and compact evidence bundles that other teams can actually exchange.

New proposals:

- P-0372 OpenFeature + OFREP Conformance & Incident Replay Kit
- P-0373 Protobuf Editions + ProtoJSON + gRPC Transcoding Conformance Workbench Kit
- P-0374 Jupyter Notebook Format + Messaging + Kernel Replay Workbench Kit
- P-0375 Remote Execution API (REv2) + CAS + Remote Asset Interop & Evidence Kit
- P-0376 3D Tiles 1.1 + Implicit Tiling + Metadata Conformance & Evidence Kit

Pass notes:

- **OpenFeature + OFREP** made the cut because Rust now has official SDK and provider momentum, but the operational gap is still the **portable incident artifact** for evaluation-context drift, fallback behavior, and provider disagreement.
- **Protobuf + ProtoJSON + transcoding** rose because the real pain is now at the **descriptor/edition ↔ JSON ↔ gateway** seam, not at raw protobuf wire support alone.
- **Jupyter notebook + messaging** was promoted because Rust has enough notebook/protocol/kernel substrate that the sharper missing crate is a **session replay and bug-bundle workbench**, not yet another notebook UI.
- **REAPI + CAS + Remote Asset** rose because remote-build incidents still lack a boring default artifact for **digest graphs, capability snapshots, and cache/execution disagreement**.
- **3D Tiles 1.1** made the cut because implicit tiling and metadata turned “supports 3D Tiles” into a much fuzzier claim; Rust now needs a **tileset/subtree evidence layer**, not a fresh renderer.

Considered but not promoted in this pass:

- **FIDO Device Onboard** — still promising, but too adjacent to existing LwM2M/Uptane/Matter device-management territory to win this pass.
- **A generic Jupyter frontend or protobuf runtime rewrite** — repeatedly downgraded. In both spaces the sharper value is evidence, replay, and compatibility artifacts above existing substrate.

Archive hygiene added in this pass:

- Added an LLM-hygiene rule that future passes must **separate existing Rust substrate from the missing coordination artifact**. This is meant to resist the recurring archive failure mode of claiming “Rust has nothing here” when the real gap is lockfiles, replay, evidence, and validator normalization.
