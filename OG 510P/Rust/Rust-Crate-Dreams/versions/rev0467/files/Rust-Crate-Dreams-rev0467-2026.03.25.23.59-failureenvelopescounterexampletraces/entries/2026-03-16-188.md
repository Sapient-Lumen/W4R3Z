# Entry 188 — artifact handoff promoted into a fixture-first produced-output lane

This pass did not add a new proposal.
It upgraded **P-0471 Cargo Artifact Handoff Kit** into a more implementation-shaped lane with schema files, scenario packs, and a sharper statement of what the crate should actually hand other people.

## Why this moved now

Several official signals line up unusually well.

### 1. Cargo already emits enough machine-readable build output to support a handoff bundle

Cargo external-tools JSON emits `compiler-artifact`, `build-script-executed`, and `build-finished` messages.
That means a downstream crate can freeze promoted-artifact facts and their origin instead of forcing every consumer to reimplement streaming JSON handling.

### 2. Cargo still needs explicit copied-output help because final artifact lookup is awkward

The unstable `--artifact-dir` feature exists precisely because determining the final filename and location can be annoying for downstream consumers.
That does not solve handoff by itself, but it is strong evidence that the seam is real.

### 3. Build-dir churn makes “final artifact handoff” more important, not less

The March 2026 call for testing build-dir-layout-v2 explicitly tells people to run tests and release processes that touch build-dir / target-dir against the new layout.
That is a reminder that many consumers still need a cleaner escape hatch toward final-artifact handoff.

### 4. Upstream custom-final-artifact work surfaced the hard exactness questions

Cargo’s current design discussion around custom final artifacts says build scripts cannot simply write directly into artifact-dir because Cargo still needs collision reporting and concurrent-access safety.
That means a worthy downstream crate must preserve whether an artifact fact is exact, copied-output exact, conservative, or still manual-review-only.

### 5. Build-analysis work gives the handoff layer a new optional join key

Cargo’s build-analysis work is adding build identifiers and `cargo report` session queries.
That does not replace handoff manifests, but it makes session-linked receipts newly plausible.

## Current judgment

The worthy crate here is not:

- just another release workflow,
- just another raw Cargo JSON adapter,
- or just another copy-files helper.

The worthy crate is the boring shared layer that can hand other people:

1. an **artifact-handoff lock**,
2. an **artifact manifest**,
3. an **artifact-origin receipt**,
4. a **native-output report**,
5. a **handoff receipt with optional session linkage**,
6. and a **diffable layout/output bundle**.
