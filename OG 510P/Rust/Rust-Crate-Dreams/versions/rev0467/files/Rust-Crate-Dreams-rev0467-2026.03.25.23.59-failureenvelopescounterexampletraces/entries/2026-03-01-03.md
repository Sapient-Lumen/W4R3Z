# 2026-03-01 (03): more signals (privacy metrics, audit UX, data contracts, chaos testing)

This entry adds four proposal candidates grounded in recurring pain signals.

## Signals & sources

### Privacy-respecting telemetry/metrics remains unresolved
Rust has strong cultural pressure against opaque telemetry; discussions emphasize *trust but verify* and privacy expectations, especially for developer tools.
- Source: https://internals.rust-lang.org/t/no-telemetry-in-the-rust-compiler-metrics-without-betraying-user-privacy/19275

This suggests an ecosystem need for a reusable, transparent, privacy-preserving metrics kit (opt-in, auditable, with DP options).

### cargo-vet adoption pain points include workflow/UX gaps
cargo-vet aims to minimize friction, but there are explicit requests for better tooling such as a web frontend for certify and dealing with “violations” ergonomically.
- Source: https://github.com/mozilla/cargo-vet/issues/554
- Source: https://github.com/mozilla/cargo-vet/issues/552
- Source: https://mozilla.github.io/cargo-vet/how-it-works.html

This motivates an “audit workbench” that composes with cargo-vet (and effect-based approaches like Cargo Scan).

### Schema evolution/data contracts are a cross-language reality, but Rust ergonomics are scattered
Schema registries define concrete compatibility modes (backward/forward/full), but Rust projects tend to re-implement local versioning rules ad hoc.
- Source: https://docs.confluent.io/platform/current/schema-registry/fundamentals/schema-evolution.html
- Source: https://yokota.blog/2025/04/16/using-data-contracts-with-the-rust-schema-registry-client/
- Source: https://lib.rs/crates/schema-registry-validation

A crate that makes compatibility checks and contract tests easy would unlock safer distributed systems and streaming apps.

### Deterministic chaos/fault injection for async Rust is emerging but still fragmented
Recent work describes deterministic chaos testing and the need to patch runtimes to affect dependency trees, and other crates focus on injecting failures/latency at the service layer.
- Source: https://www.reddit.com/r/rust/comments/1p3e8or/fracture_deterministic_chaos_testing_for_async/
- Source: https://docs.rs/tower-resilience-chaos
- Source: https://pierrezemb.fr/posts/writing-rust-fdb-workloads-that-find-bugs/

This points to a missing “unified lab” story: deterministic scheduling + fault models + artifact reproducers.
