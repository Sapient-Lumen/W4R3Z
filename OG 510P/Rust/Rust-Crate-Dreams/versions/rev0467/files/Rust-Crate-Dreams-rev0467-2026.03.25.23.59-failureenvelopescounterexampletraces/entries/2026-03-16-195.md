# Entry 195 — crate ecosystem pathfinder promoted as a task-first decision-pack lane

This pass added a new top-level proposal: **P-0509 Crate Ecosystem Pathfinder & Decision-Pack Kit**.
It also added the lane-boundary and fixture scaffolding needed to stop future passes from collapsing crate discovery, health, trust, façade crates, and “official blessing” debates into one fake curation story.

## Why this moved now

Several current official Rust signals line up unusually well.

### 1. The Rust project is now naming crate selection as a supportiveness problem

The December 2025 vision-doc post says users still experience crate choice as tacit knowledge:

- crate choice feels undiscoverable,
- crates.io metadata is not enough to answer “what crate should I use for X?”,
- and there is no clear, recorded starter set for common third-party choices.

That is unusually direct guidance for this archive.
A worthy crate here should not pretend the problem is solved by “better search” alone.

### 2. The latest surveys reinforce the need for better ecosystem orientation

The 2024 and 2025 State of Rust surveys show a language that is increasingly used in real work, taught through official docs and source code, and still shaped by productivity/supportiveness constraints.
The 2025 survey also notes users increasingly leaning on LLM tooling when learning or troubleshooting.

That means a good crate in this lane should not just rank packages on a website.
It should produce a **portable decision artifact** that teams, docs, educators, and tools can hand around.

### 3. Official Cargo/crates.io substrate is helpful but deliberately thin

Cargo’s docs still describe:

- small manifest metadata surfaces (`keywords`, `categories`),
- a textual `cargo search` flow,
- and a `cargo add` command whose “best effort” source choice is about where to fetch a dependency from, not which crate best fits a task.

Meanwhile, crates.io maintainers continue to describe search/ranking improvement as real but non-trivial work, with current ranking built from name/keyword/description/readme weighting and unresolved popularity/order questions.

So the missing value is not a registry fork.
It is the **reviewable decision layer above today’s generic search substrate**.

## Current judgment

The worthy crate here is not:

- another registry frontend,
- another global “blessed crates” list,
- another generic trust score,
- or another dependency-minimal façade crate.

The worthy crate is the boring decision-pack layer that can hand other people:

1. one **task profile**,
2. one **candidate import report**,
3. one **interop-surface report**,
4. one **ranked decision pack**,
5. one **starter-set lock**,
6. and one explicit **manual-review boundary** when the evidence is not strong enough.
