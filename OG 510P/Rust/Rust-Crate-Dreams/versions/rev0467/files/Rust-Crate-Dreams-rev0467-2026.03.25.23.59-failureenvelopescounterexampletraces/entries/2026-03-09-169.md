# Entry 169 — text layout stack clarified and conformance kit made fixture-first

This pass again chose **not** to add another narrow proposal.

The better move was to strengthen an already high-salience frontier that still lagged behind the repo’s newer best proposals in handoff quality.

**P-0197 Text Layout & Shaping Conformance Kit** already had the right instinct.
It still needed a much clearer stack model and a much deeper fixture pack.

## Main judgment

The sharper missing crate here is **not** another text engine or another renderer.

It is a crate that gives another person a compact answer to:

- what the layout case actually was,
- which Unicode/corpus inputs were pinned,
- which fonts and fallback order were in play,
- which backend lane produced the output,
- what semantic layout result came back,
- and whether the difference is really comparable or only advisory.

That is a more plausible and more ecosystem-shaped contribution than trying to crown a universal backend winner.

## Why these changes were the right ones

### 1. The proposal had become important but still underbuilt
`P-0197` was already one of the archive’s stronger non-Cargo bets, but it still looked more like a strong essay than a handoff-ready crate.
This pass rewrote it into a clearer artifact-first proposal.

### 2. Current Rust substrate makes the missing value clearer
The ecosystem signals are now stronger than they were when this proposal first landed:

- `parley` is real layout substrate.
- `cosmic-text` is real layout/fallback substrate.
- ICU4X 2.0 makes the Unicode/i18n layer more mature.
- `rustybuzz` is already close to HarfBuzz on the published shaping corpus.
- Unicode and WPT expose real importable test material.
- backend churn in the ecosystem is evidence that comparison artifacts matter.

That means the sharper crate opportunity is now the **portable case / receipt / IR / diff / diagnosis layer above backend diversity**.

### 3. The archive needed stack boundaries, not another blurry text idea
Without a boundary note, future revisions were likely to keep mixing together:

- Unicode data and default algorithms,
- shaping engines,
- layout engines,
- font/fallback policy,
- raster overlays,
- and correctness-lab bundle work.

That would make the archive larger while making the ideas less implementable.
The new note should help resist that drift.

### 4. The fixture pack now answers a receiver-facing question
The strongest recent passes in this archive have made proposals concrete by freezing the artifacts they would hand another person.
This pass brings the text layout frontier closer to that standard.

The new minimal pack is now explicit:

- layout case,
- fontset lock,
- corpus import receipt,
- backend capability receipt,
- layout output,
- semantic diff report,
- diagnosis report,
- and bundle manifest.

## New planning stance

For the next few passes, the archive should prefer:

- treating **P-0197** as the cross-backend text correctness **artifact and adapter** story,
- treating Unicode data and shaping engines as substrate rather than as the missing crate,
- connecting **P-0197** upward to **P-0264** and **P-0256**,
- and only adding another text proposal if the repo can show that a truly separate layer is still missing.

It should **not** drift back into a fuzzy “Rust needs one text crate to do everything” framing.
