# Entry 117 — live lock-contention witnesses and debugger visualizer compatibility receipts

This pass stayed disciplined in two ways.

First, it separated **live blocking facts** from broader cache/build explanations. Rust users often know that Cargo is “slow,” but the sharper missing crate here is sometimes the one that says **who blocked whom, on which cache root, and what the least-bad mitigation is**.

Second, it separated **visualizer compatibility** from both broad debugger support and broad formatter-pack ambitions. Rust now has stable embedded visualizer substrate, but maintainers still lack one compact artifact that says which debugger families their assets actually support and whether that changed.

New proposals:

- P-0490 Cargo Lock Contention Witness Kit
- P-0491 Debugger Visualizer Compatibility Kit

Why these rose:

- **P-0490** rose because official Rust and rust-analyzer materials now make the blocking seam unusually explicit: the compiler-performance survey calls out IDE/Cargo blocking and target-directory contention; rust-analyzer documents the separate-target-dir workaround; Cargo’s own cache-lock internals and build-dir-layout work show that locking is real substrate, not folklore. The sharper gap is a **lock-wait / collision-diagnosis / mitigation bundle**, not another generic cache manager.
- **P-0491** rose because `#[debugger_visualizer]` is now stable and officially documents embedded NatVis and GDB visualizer assets, but that still does not give maintainers a boring **backend matrix / render-golden / drift receipt**. The sharper gap is narrower than P-0083 and P-0486: it is specifically the compatibility story for visualizer assets already being shipped.

What changed in archive judgment:

- The archive now draws a cleaner line between **rebuild explanation**, **cache policy/GC**, **build-dir consumer migration**, and **live lock contention witnesses**. Those are adjacent, but they are not the same worthy crate.
- The archive now draws a cleaner line between **debuggability support posture**, **formatter-pack UX**, and **visualizer-asset compatibility receipts**. A crate can be valuable just by making embedded visualizer support honest and reviewable.

Archive hygiene added in this pass:

- Added an amnesia resistor warning future revisions not to confuse Cargo’s richer cache/build-dir substrate with an already-boring answer to “what is blocking me right now?”
- Added an amnesia resistor warning future revisions not to confuse stable embedded visualizer syntax with an already-boring debugger compatibility workflow across backend families and releases.
