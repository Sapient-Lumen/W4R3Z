# Entry 276 — crate upgrade support sharpened around exact capture context and sparse coverage matrices

This pass came from noticing that the upgrade pack had become honest about sources, readiness, export posture, warnings, freshness, and summary-claim traceability while still carrying two quiet bluffs:

> imported evidence could still outgrow the exact command/session that produced it, and dimension lists could still sound like whole-matrix coverage.

## What moved this time

Two donor patterns kept surviving scrutiny:

- **Rust-Needs-and-Dreams** kept insisting that native imports should stay bound to an explicit session or replay posture instead of floating as generic report truth.
- **DeriveBSD + Micromax** kept insisting that exact scope and typed misses are more honest than one broad “covered” claim.

## Main planning move

The previous passes already established:

- source lineage, source heads, native import truth, and hazard arbitration,
- fixup posture, package-scope truth, active follow-through, readiness, and review queues,
- export posture, public surface exactness, deviations, warnings,
- freshness/supersession, and summary-claim traceability.

This pass adds two sharper review objects above them:

1. **capture-context truth** — each imported fix/check/report can be tied to the exact package/target/feature/toolchain/lockfile context that produced it;
2. **coverage-matrix truth** — each exact sparse matrix cell can be marked observed, hazard-bearing, recipe-only, manual-review-only, unsupported, unrequested, or unknown.

## Why this matters

Without **capture-context truth**, the lane still permits an ordinary lie:

- a `cargo fix`, `cargo metadata`, or SemVer import can be read as if it covered the whole workspace or all targets when it only covered one exact selection.

Without **coverage-matrix truth**, the lane still permits another ordinary lie:

- listing touched features or targets can sound like whole-lane coverage even when a `required-features` binary, alternate target triple, or runtime/config profile was never actually observed.

That is not cosmetic.
It is the difference between “we checked something nearby” and “this exact upgrade cell was really reviewed”.

## Main judgment after the pass

A worthy upgrade-support crate should now provide more than exact receipts, exact summaries, and honest public posture.
It should also provide:

- one compact **capture-context receipt** for each imported evidence family that could otherwise outgrow its exact selection,
- one explicit **coverage matrix** so exact feature/target/profile cells stay visible,
- and one bounded rule that a broader lane may not borrow authority from a narrower capture without saying so.

That keeps the lane from quietly turning nearby observations into whole-migration authority.
