# Entry 77 — frontier pass: genomics delivery, learning telemetry, model-driven network management, event contracts, and research-software citation metadata

Added five proposals after a fresh pass focused on domains where standards are active, Rust has at least some substrate or strong adapter points, and the missing value still looks like the **boring middle layer**: lockfiles, semantic diffs, replay, crosswalks, and portable evidence bundles.

New proposals:

- P-0337 GA4GH htsget + refget + Crypt4GH Interop & Evidence Kit
- P-0338 xAPI 2.0 + cmi5 Conformance & Replay Kit
- P-0339 NETCONF + YANG + RESTCONF Conformance & Evidence Kit
- P-0340 AsyncAPI 3.0 + CloudEvents Interop & Evidence Kit
- P-0341 DataCite 4.7 + CodeMeta + CITATION.cff Crosswalk Workbench Kit

Pass notes:

- **GA4GH htsget / refget / Crypt4GH** rose because Rust now has real protocol substrate and even compliance/demo momentum, but the practical pain is still at the seam between **streaming semantics, reference integrity, and privacy-aware evidence**.
- **xAPI / cmi5** rose because Rust now has an actual xAPI 2.0 implementation path, but the ecosystem still lacks a boring-default **profile lock + session replay + explainable statement diff** workbench.
- **NETCONF / YANG / RESTCONF** was promoted because Rust has credible protocol/model substrate, yet firmware and module drift still create expensive failures that want **capability lockfiles, semantic diffs, and replay bundles**, not one more raw client.
- **AsyncAPI / CloudEvents** made the cut because the important problem is not “parse another spec file”; it is **keeping logical event contracts stable across transport bindings** and making those failures reproducible.
- **DataCite / CodeMeta / CFF** was promoted because Rust has useful fragments for citation and metadata extraction, but still lacks a deterministic **crosswalk + loss-reporting + release/deposit evidence** workflow for research software.
