# Entry 329 — Verification Campaign Workbench Kit deepened for obligation inventory, lane semantics, trust ledgers, policy gates, and comparability truth

This pass deepened **P-0485 Verification Campaign Workbench Kit** instead of adding another verifier, another sanitizer lane, or another assurance-case wrapper.

## Why this lane earned another serious pass

The archive already knew Rust had meaningful verification substrate.
What it lacked was a build-shaped answer for *which truths actually belong in one reviewable cross-tool verification contract*.

Current substrate is now strong enough to make that precise:

- Rust’s 2026 flagship themes now explicitly include **Safety-Critical Rust** with certified tooling, specifications, and evidence;
- the January 2026 safety-critical Rust post is explicit that verification and evidence demands rise with criticality;
- the Rust Foundation’s Safety-Critical Rust Consortium is explicitly interested in guidelines, static analysis tools, and formal methods;
- Miri, Kani, Creusot, Prusti, Flux, and Verus now form a real spread of verification lanes;
- Kani contracts/stubs, Creusot replay, Prusti trusted functions, Flux compile-time refinements, and Verus trusted/external components make it obvious that trust surface and lane semantics must stay visible.

That means a worthy crate here should not simply say “supports verification”.
It should say what obligations existed, what each lane really meant, what trust surface existed, what policy decided, and whether a campaign diff is even comparable.

## What moved this time

The main planning move was to stop treating “verification campaign” as one blob.

This pass elevated five review objects into first-class status for **P-0485**:

1. **obligation-inventory truth** — what needed to be checked and what evidence classes count;
2. **lane-semantics truth** — dynamic execution, bounded proof, deductive proof, refinement check, theorem proof, or manual review;
3. **trust-ledger truth** — trusted functions, externals, stubs, axioms, waivers, and review obligations;
4. **policy-evaluation truth** — why the campaign is green, yellow, or red;
5. **comparability truth** — whether tool/version/target/trust drift still permits a meaningful diff.

## Why this matters now

The evidence is sharp enough that the missing layer is no longer vague:

- Miri is real UB-detection substrate, but its results remain executed-path evidence;
- Kani’s contracts and `stub_verified` flow prove modular proof reuse matters, but also add explicit trust surface;
- Creusot’s `prove` / replay workflow proves proof context and replay state matter to campaign comparability;
- Prusti makes trusted functions and assumptions first-class enough that the trust ledger can no longer stay implicit;
- Flux and Verus show that compile-time refinements and theorem-style proofs can each be strong but still partial.

That means a worthy crate should not let “we ran some verifiers” quietly over-claim whole-campaign closure.

## Main judgment after the pass

A worthy verification campaign crate should now provide more than tool adapters and one bundle file.
It should also provide:

- one explicit **obligation inventory**,
- one explicit **lane-semantics import model**,
- one explicit **trust ledger**,
- one explicit **policy-evaluation report**,
- one explicit **comparability / drift report**,
- and one conservative rule for when useful raw verification output is still too partial, too trust-heavy, or too drifted to bluff a whole-campaign green result.
