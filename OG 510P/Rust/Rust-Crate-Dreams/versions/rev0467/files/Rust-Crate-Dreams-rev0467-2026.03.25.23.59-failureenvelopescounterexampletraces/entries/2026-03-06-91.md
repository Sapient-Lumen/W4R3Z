# Entry 91 — host-mediated grants, immutable policy state, scan-model loss, and long-lived open document layers

Added five proposals after a pass aimed at ecosystems where the missing Rust value is **not another parser, binding, or full stack**, but a boring default for **lockfiles, request/session receipts, conversion loss reports, and portable evidence** above already-real standards or substrate.

New proposals:

- P-0407 ISO 15118 Plug & Charge + V2G PKI Interop & Evidence Kit
- P-0408 XDG Desktop Portal Capability Portability Kit
- P-0409 OpenFGA Authorization Model + Tuple Replay Kit
- P-0410 E57 + LAS/LAZ + COPC Loss-Aware Interop Workbench Kit
- P-0411 OpenDocument ODF + OpenFormula Conformance Workbench Kit

Pass notes:

- **ISO 15118** rose because public ecosystem guidance now clearly treats Plug & Charge and V2G as critical interop surfaces, while Rust still lacks a compact session/PKI artifact that can survive vendor handoff.
- **XDG Desktop Portal** made the cut because Rust already has meaningful substrate (`ashpd`, `zbus`), but still lacks a portable backend-capability and request/session evidence layer.
- **OpenFGA** rose because immutable models, contextual tuples, and store-file tests now form a real operational surface, while Rust still lacks a replay artifact for authz regressions.
- **E57 + LAS/LAZ + COPC** made the cut because the sharper missing layer is not parsing but **loss accounting** across point-cloud families with different structural assumptions.
- **OpenDocument** rose because ODF 1.4 is current again, Rust support remains partial and modality-skewed, and the missing crate is a family-aware package/formula workbench rather than one more format-specific helper.

Archive hygiene added in this pass:

- Added a reminder that some of the most important crate opportunities live at the boundary between **persisted state and live, host-mediated, or request-scoped state**.
- Strengthened the archive’s memory that ecosystems with one family name may still contain **multiple layers with materially different contracts**: package, schema, formula, session, tuple state, backend capability, or conversion-loss surfaces.
