# 2026-03-01: ecosystem signals + new epic proposals (expanded)

## Signals (with sources)

### Offline / air-gapped workflows remain a recurring pain (toolchain + crates)
Community threads keep describing offline mirrors as fragile and under-documented, especially for air-gapped environments.
Separately, toolchain mirroring (components like clippy/rustfmt/targets) is a distinct pain point.

Evidence:
- https://users.rust-lang.org/t/alternate-crates-io-index-repo/133959
- https://users.rust-lang.org/t/cargo-with-local-crates-io-mirror/135132
- https://users.rust-lang.org/t/how-to-transfer-crates-to-a-private-registry/121156
- https://www.reddit.com/r/rust/comments/v889xy/offlineish_installation_mirroring_of_rust/
- https://users.rust-lang.org/t/proper-offline-install/116256
- https://github.com/panamax-rs/panamax

### Supply-chain security: publishing is improving, but provenance is still fragmented
crates.io is expanding Trusted Publishing (OIDC), which reduces leaked-token risk, but does not on its own provide artifact-level attestations/provenance.

Evidence:
- https://blog.rust-lang.org/2026/01/21/crates-io-development-update/
- https://crates.io/docs/trusted-publishing
- https://internals.rust-lang.org/t/idea-a-small-crate-for-verifying-crates-generating-sboms-future-proof-for-signing/23574

### Auditing burden: new research suggests a path to “audit less code”
Cargo Scan research reports large reductions in the amount of code auditors need to inspect by focusing on effects and context, complementing audit-tracking workflows like cargo-vet.

Evidence:
- https://arxiv.org/abs/2602.06466
- https://mozilla.github.io/cargo-vet/
- https://github.com/google/rust-crate-audits

### Licensing/compliance: “bundle the real texts” still isn’t a solved golden path
Users report that existing tools don’t reliably produce the exact license texts/notices they need to ship, and workspace packaging quirks often lead to missing license files.

Evidence:
- https://users.rust-lang.org/t/missing-good-tools-for-bundling-third-party-licenses/93172
- https://github.com/EmbarkStudios/cargo-about
- https://github.com/sstadick/cargo-bundle-licenses

### Typosquatting and “trust signals” are becoming first-class concerns
There is ongoing discussion about confusable names, and research tools like Cargo Sherlock propose quantifying trust assumptions (“trust cost”) over dependency graphs.

Evidence:
- https://users.rust-lang.org/t/etiquette-of-flagging-crates-as-typos-confusables/113624
- https://arxiv.org/abs/2512.12553
- https://github.com/DavisPL/supply-chain-trust

### Connector ecosystems: connector roadmaps are exploding
Some projects track 100+ connector targets; there’s clear demand for a connector authoring/runtime “kit” with testing and observability baked in.

Evidence:
- https://github.com/apache/iggy/issues/2753
- https://iggy.apache.org/blogs/2025/06/06/connectors-runtime/

## New proposals added today
- P-0014: `license-bundle-kit` — deterministic third‑party license + notice bundles for Rust artifacts
- P-0015: `cargo-attest` — build provenance + in-toto attestations for crates and binaries
- P-0016: `audit-lens` — effect-focused auditing artifacts that compose with cargo-vet
- P-0017: `trust-lens` — typosquatting + trust-cost scoring for dependency graphs
- P-0018: `airgap-sdk` — one verified bundle for rustup toolchains + Cargo dependencies
