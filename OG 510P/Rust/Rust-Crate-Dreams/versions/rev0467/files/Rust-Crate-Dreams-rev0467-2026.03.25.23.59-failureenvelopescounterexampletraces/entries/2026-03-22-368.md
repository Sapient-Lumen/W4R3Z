# Entry 368 — Broad frontier rerank deepened around ecosystem guidance, sustainability, build friction, and machine-consumable crate knowledge

This pass was a **broad archive rerank** rather than another narrow deepening pass.
The goal was to re-check the latest archive, refresh it against current official Rust/Foundation/docs.rs/crates.io signals, and ask a harder question:

> what crate contributions would still count as truly worthy — even epic — now that so many obvious wrapper ideas are already taken?

## Why this lane earned a broad pass now

Fresh official signals now line up across multiple fronts:

- the 2025 State of Rust survey says online docs remain the preferred canonical reference, while resource usage and compile-time friction remain major productivity problems;
- the March 2026 Rust challenges write-up says experts still hit async complexity, certification gaps, embedded ecosystem-maturity problems, and ecosystem-navigation pain;
- the compiler-performance survey says incremental rebuilds and “understanding why builds are slow” remain central workflow pain;
- the debugging survey makes debugger-family support, visualizers, async debugging, and expression evaluation explicit project concerns;
- the 2026 goals page elevates supply-chain, safety-critical, and Cargo-facing work into flagship themes;
- and the Rust Foundation’s 2026–2028 strategy makes stable infrastructure and sustainable maintenance first-class ecosystem priorities.

Together these make a broad archive lesson clearer:

The next worthy Rust crates are disproportionately **boring support contracts** above already-real substrate.
They are less likely to be “yet another runtime / runner / portal / dashboard” and more likely to be **diffable receiver-facing artifacts** that remove tacit knowledge.

## Main ranked takeaways from this pass

After the reread + fresh-source scan, the current strongest archive lanes are:

1. **P-0484 Toolchain & Target Support Contract Kit**
2. **P-0011 Crate Health Contract Kit**
3. **P-0535 Dependency Lifecycle Transition Kit**
4. **P-0120 Unsafe Contract Auditor Kit**
5. **P-0532 Async Runtime Assurance Profile Kit**
6. **P-0486 Debuggability Support Contract Kit**
7. **P-0536 Crate Knowledge Pack Kit** *(new proposal added in this pass)*
8. **P-0490 Cargo Lock Contention Witness Kit**
9. **P-0469 Cargo Rebuild Explanation Kit**
10. **P-0431 Public Dependency Boundary Kit**

This pass therefore did **not** explode the archive with many new crates.
It reranked the territory, tightened synthesis rules, and added exactly one new lane where the archive still had a real gap.

## What changed conceptually

### 1. Sustainability is now a front-rank crate-design concern

This pass promoted **crate health**, **continuity**, and **dependency lifecycle** from “important ecosystem meta” to first-rank crate opportunities.

The archive should now treat these as real product lanes, not as social afterthoughts, because downstream adopters increasingly need portable stewardship truth rather than popularity folklore.

### 2. Build friction is still the universal tax, but the right answer is support truth

The build-performance and challenge material reinforced that the missing value is not one mega-optimizer crate.
It is a family of boring support contracts:

- what target lane is actually supported,
- what caused this rebuild,
- who blocked the shared build root,
- and what Cargo really did for this script-like invocation.

### 3. Docs-facing work needed one joined handoff lane

The archive already had strong docs pieces:

- rustdoc JSON normalization,
- docs.rs parity evidence,
- doctest/support truth,
- docs coverage review.

But it still lacked one lane for **canonical crate knowledge handoff**.
That gap is sharper now because docs remain canonical while more learning/support work is clearly machine-mediated.

This pass therefore added **P-0536 Crate Knowledge Pack Kit** instead of adding another docs portal, another rustdoc wrapper, or another “chat with your crate” fantasy.

## New archive-level stance

For future broad scans, the archive should usually do one of three things:

1. **rerank a structural lane**,
2. **deepen a support-contract lane**,
3. or **add exactly one new joined lane** where the missing value is a receiver-facing artifact above existing substrate.

The archive should increasingly reject:

- another generic docs portal when P-0051 + P-0472 + P-0476 + P-0536 already explain the stack;
- another generic Cargo-performance crate when P-0490 + P-0469 + P-0484 already own the sharpest review objects;
- another generic crate-trust score when P-0011 + P-0535 already frame the more honest stewardship questions.

## What should count as a worthy crate contribution after this pass

A worthy contribution should now usually provide other people with:

1. **one compact artifact or contract**,
2. **a reusable vocabulary for a messy truth**,
3. **separate authority classes instead of one flattened verdict**,
4. **diffable release-to-release evidence**,
5. **a maintenance story that does not assume heroics**.

If a proposal does not clearly improve another engineer’s ability to review, trust, diff, adopt, or hand off the result, it is now more likely to be convenience than frontier.
