# Entry 154 — resolver why-bundles also need workspace-inheritance and manifest-origin truth

This pass again did **not** add another top-level proposal.

Instead, it sharpened **P-0468 Cargo Resolver Explanation Kit** where the archive still had unusually high leverage: the crate now has a clearer plan for **workspace dependency inheritance, manifest origin, and inherited default-feature policy** above today’s mixed Cargo surfaces.

## Main judgment

The important missing crate is not another dependency graph explorer.
It is a **receiver-facing resolver bundle** that can tell another person:

- whether an effective dependency policy came from `[workspace.dependencies]`, a member manifest, or both,
- whether default features were disabled, neutralized, or re-enabled,
- whether a target-specific inherited dependency changed the story,
- and whether the answer is directly observed, conservative, or still manual-review-required.

That is a sharper contract than “Cargo feature explanation tool”.
