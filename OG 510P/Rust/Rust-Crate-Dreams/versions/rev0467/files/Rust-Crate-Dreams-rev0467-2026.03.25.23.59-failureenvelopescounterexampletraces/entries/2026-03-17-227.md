# 2026-03-17 (227) — crate configuration-scenario productization pass

This pass did **not** add a new lane.
It sharpened **P-0516 Crate Configuration Scenario Pack Kit** into a more implementation-ready `0.1` shape.

## Main judgment

The missing value is still **not** another feature-doc macro, another feature-powerset runner, another generic Cargo config explainer, or another docs portal.
The sharper missing layer is a **maintainer-facing scenario contract** that records:

- which setup lanes are officially intended,
- what *kind* of scenario each lane is,
- where each important fact came from,
- and how much of the advertised matrix was actually observed.

## Why this lane looks sharper now

- Cargo’s target docs now make `required-features` explicit enough that the missing value is increasingly the review artifact above raw target tables;
- docs.rs now makes feature/target/custom-build knobs and hosted-vs-local drift explicit enough that the missing value is increasingly the scenario contract above documentation build metadata;
- RFC 3416 and `document-features` make it clear that feature vocabulary and feature docs matter, but they still do not name official setup lanes;
- and combinatorial tools like `cargo-feature-combinations` and `cargo-hack` make checking real enough that the missing value is increasingly **which scenarios matter and how honest the evidence is**, not whether Cargo can run commands.

## What to keep separate

- Keep **P-0516** separate from task-first crate choice (**P-0509**).
- Keep **P-0516** separate from docs.rs parity / hosting work (**P-0472**).
- Keep **P-0516** separate from feature-doc renderers and powerset executors.
- Keep **P-0516** separate from generic Cargo config-precedence explanation.

## Preferred proving grounds

- crates with rustls-vs-native-tls or runtime-backend choices
- crates with `no_std` / `alloc` support whose examples or docs skew `std`
- crates whose docs.rs surface uses `all-features` or special cfgs
- workspaces where official recipes depend on `required-features`-gated examples or bins
- crates where the honest default differs from the broadest technically buildable combination
