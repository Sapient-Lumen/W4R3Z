# Entry 371 — Unsafe contract auditing deepened around authority imports, obligation drift, witness comparison, and callback-boundary honesty

This pass continued the archive’s current strategy of **deepening one top lane until it looks buildable** instead of minting another adjacent verifier, lint pack, or proof dashboard.

The lane chosen here was **P-0120 Unsafe Contract Auditor Kit**.
The archive already had a solid thesis, core schemas, and a few scenario fixtures for P-0120.
What it still lacked was a sharper answer to a harder review question:

> when unsafe evidence changes across revisions, toolchains, or imported authority sources, what exactly should another engineer receive and compare?

This pass answers that more concretely.

## Why this lane deserved more work now

Fresh official signals still pull in the same direction:

- the 2026 Rust flagships page explicitly names **normative unsafe documentation** as part of the Safety-Critical Rust agenda;
- the std-contracts goal keeps pushing toward **contract as code**, contract attributes, and machine-retrievable safety conditions;
- the unsafe-fields goal keeps reminding us that many important safety invariants live outside the visible boundary of `unsafe` blocks;
- Miri remains very valuable, but its own public docs are explicit that it does **not** define the full Rust spec and cannot catch every possible violation;
- and the January 2026 safety-critical write-up keeps pointing toward tooling that is reviewable, transportable, and honest about boundary limits.

That combination makes one archive lesson sharper:

**A worthy unsafe-audit crate is not just “run Miri and save logs.”
It is a reviewable contract for where unsafe obligations came from, how they changed, which witnesses are comparable, and where the witness boundary stayed partial even when the run looked green.**

## Main repo judgment from this pass

The strongest next move for **P-0120** was to make three more review objects first-class and to sharpen one existing scenario family:

1. **`authority-import.receipt.json`** — imported authority should be explicit about exactness, freshness, and local-manual gaps.
2. **`obligation-drift.diff.json`** — unsafe-site inventory changes should be diffable without pretending that a site move automatically changes the semantic obligation.
3. **`witness-comparison.report.json`** — two green runs are only meaningfully comparable when claim scope, target/toolchain meaning, and boundary semantics still line up.
4. **callback-focused boundary fixtures** — FFI callback lanes should remain partial even when the local witness succeeds.

The repo also now states a sharper boundary against adjacent lanes:

- future std-contracts / contract-attribute work can become an **imported authority source** for P-0120;
- unsafe fields remain a language surface for denoting invariants;
- but **P-0120** owns the receiver-facing workflow for comparing obligation/evidence posture over time.

That separation matters.
Otherwise the archive would quietly confuse “the language can express more invariants” with “another team can review what our unsafe evidence really means.”

## What a worthy crate in this lane should provide other people

The archive now has a tighter answer:

1. **One authority trail** that distinguishes local prose, machine contracts, imported upstream contracts, and manual local patch-ups.
2. **One obligation inventory** that stays reviewable even when unsafe sites move around in a refactor.
3. **One drift report** that says whether the obligation set changed, only the site layout changed, or the semantic story is still manual-review territory.
4. **One witness comparison object** that says whether two runs can honestly be compared at all.
5. **One boundary receipt** that keeps FFI callbacks, symbols, platform hooks, and other foreign behavior from being flattened into “green test = covered.”
6. **One portable audit bundle** that a downstream adopter, auditor, or release reviewer can actually diff.

If a crate idea in this territory cannot supply those review objects, it is still probably substrate, logging, or local experiment orchestration.

## New repo-level lesson

The archive is stronger when it refuses to flatten **green evidence** into **stable meaning**.

Future passes should therefore keep asking:

1. what authority source defined the obligation,
2. what changed in the obligation map,
3. whether two witnesses are genuinely comparable,
4. and which boundaries stayed partial despite a successful run.

That is a better use of repo time than inventing another nearby unsafe-analysis lane.
