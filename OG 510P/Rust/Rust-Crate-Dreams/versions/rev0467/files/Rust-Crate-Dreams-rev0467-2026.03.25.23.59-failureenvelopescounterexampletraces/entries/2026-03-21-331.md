# Entry 331 — Evidence Bundle Core Kit deepened for container basis, entry lineage, attestation lanes, publication routes, and share-safety posture

This pass deepened **P-0256 Evidence Bundle Core Kit** instead of adding another domain-specific evidence bundle, another private zip grammar, or another generic signing helper.

## Why this lane earned another serious pass

The archive already knew evidence bundles mattered.
What it still lacked was a build-shaped answer for *which truths belong in one reusable bundle substrate contract* rather than being silently copied into every downstream kit.

Current substrate is now strong enough to make that precise:

- in-toto keeps **predicate**, **statement**, **envelope**, and **bundle** explicitly distinct;
- Sigstore now documents a concrete bundle format for verification material rather than just detached signature folklore;
- OCI/ORAS now make `subject` / referrer publication routes concrete enough that local validity and publication path should not be conflated;
- SCITT is clarifying the external transparency/publication lane rather than replacing local portable bundles;
- and the archive itself now has enough bundle-first proposals that grammar drift is a larger risk than shortage of ideas.

That means a worthy crate here should not simply say “supports signed evidence bundles”.
It should say **what deterministic container basis was used, how entries are typed by lineage, which attestation lane is present, whether any publication route exists, and whether the pack is actually safe to share**.

## What moved this time

The main planning move was to stop treating “bundle” as one blob.

This pass elevated five review objects into first-class status for **P-0256**:

1. **container basis** — archive format, ordering, timestamps, path rules, compression, digest policy, and reproducibility posture;
2. **entry lineage** — whether an entry is raw, projected, generated, imported, copied, or redacted;
3. **attestation lane** — unsigned, DSSE, COSE, Sigstore bundle, or mixed;
4. **publication route** — local-only, flat-file export, OCI subject/referrers attachment, or transparency/publication preparation;
5. **share-safety posture** — private-only, redacted-shareable, encrypted-shareable, or manual-review-only.

## Why this matters now

The ecosystem evidence is now sharp enough that the missing layer is no longer vague:

- in-toto and DSSE make attestation layering explicit;
- Sigstore bundles make verification material concrete;
- OCI referrers make publication attachment concrete;
- SCITT makes it easier to keep external transparency/publication separate from local portable bundles.

That means a worthy crate should not let one green verification bit quietly over-claim local validity, publication state, or share-safety.

## Main judgment after the pass

A worthy evidence-bundle substrate should now provide more than a manifest plus detached signatures.
It should also provide:

- one explicit **container-basis receipt**,
- one explicit **entry-lineage report**,
- one explicit **attestation-lane receipt**,
- one explicit **publication-route receipt**,
- one explicit **share-safety receipt**,
- plus the already-needed manifest, redaction, verification, and diff surfaces.
