# Entry 343 — crate health deepened for work-routing, response channels, and continuity backstops

This pass deepened **P-0011 Crate Health Contract Kit** instead of adding another ranking layer, another funding dashboard, or another trust/security score.

## Why this lane earned another pass now

Fresh Rust and ecosystem signals line up unusually well:

- the January 2026 maintenance post says maintenance is not just releases but issue triage, bug fixing, CI failures, security incidents, performance regressions, dependency updates, documentation freshness, review, and contributor enablement;
- the 2025 State of Rust survey says concern about **developer and maintainers support** ticked upward while online docs remain the preferred canonical reference;
- the Rust Foundation’s 2026–2028 strategic plan now makes **Sustainable Maintenance** one of its core pillars;
- the open-infrastructure stewardship statement says today’s ecosystems must move from invisible dependence to shared responsibility;
- and crates.io now exposes richer support-adjacent signals such as the Security tab, Trusted Publishing Only Mode, SLOC, and `pubtime`.

That combination makes one gap harder to ignore: downstream users can increasingly see *signals* about a crate, but they still often cannot see **where maintenance work is supposed to go** or **what happens if the obvious maintainer disappears for a while**.

## Main judgment after the pass

The sharper missing contribution is not another `is_this_crate_healthy()` score.
It is a **stewardship routing contract** above today’s badges, issue folklore, owner counts, CODEOWNERS files, security settings, and registry signals.

A worthy crate-health contribution should now tell other people, in a reviewable way:

1. **which route** different work classes are supposed to take,
2. **which channels** are public versus private,
3. **who or what class of owner** is expected to respond,
4. **what backup / backstop** exists when the primary route is unavailable,
5. and **which parts of the story are declared, imported, inferred, or still manual-review-only**.

## What moved this time

This pass promoted three new first-class review artifacts for **P-0011**:

- `work-routing.report.json`
- `response-channel.receipt.json`
- `continuity-backstop.report.json`

## Why these three artifacts matter

Current substrate is now strong enough that the archive should stop flattening it:

- GitHub CODEOWNERS gives a real way to declare path responsibility, but that is not the same thing as saying where CI breakages, release orchestration, or security reports go;
- GitHub private vulnerability reporting is separate from `SECURITY.md`, which means “a private route exists” and “the public instructions say what to do” are distinct truths;
- crates.io Security / Trusted Publishing / SLOC / `pubtime` help consumers reason about a crate, but they still do not answer who will triage docs drift next week or who can keep the crate responsive during maintainer absence.

## What should count as a worthy crate contribution after this pass

A worthy crate-health contribution should now be able to answer all of these cleanly:

1. **Where should ordinary bugs, docs fixes, CI failures, release breaks, and security reports go?**
2. **Which routes are public and which must stay private?**
3. **What routes rely on one named maintainer, and what routes have a backstop?**
4. **Which routes are real declarations versus inferred from repository substrate?**
5. **What continuity story exists when the primary maintainer is away, overloaded, or exiting?**

If a candidate crate cannot answer those questions, the archive should usually treat it as incomplete health folklore rather than a real stewardship contract.
