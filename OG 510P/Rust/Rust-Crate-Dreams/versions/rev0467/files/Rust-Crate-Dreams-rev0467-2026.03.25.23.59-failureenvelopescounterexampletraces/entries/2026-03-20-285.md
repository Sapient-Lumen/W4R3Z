# Entry 285 — crate upgrade support sharpened around baseline-state truth and pristine-versus-drift disclosure

This pass came from noticing that the upgrade pack had become exact about lane selection, config basis, capture context, session honesty, replay bridges, export posture, and public traceability while still leaving one ordinary bluff available:

> a lane could still sound like a clean release-to-release contract even when the checked subject was already a dirty, unpublished, or partially migrated local workspace.

## What moved this time

One donor pattern kept surviving scrutiny:

- **Radical-Governance** kept insisting that consequential review should run from a named approved baseline instead of a silent moving target.

## Main planning move

The previous passes already established:

- exact command/config/session truth,
- exact scope and replay truth,
- and exact readiness/export/public-trace truth.

This pass adds one sharper review object above them:

1. **baseline-state truth** — the pack can now say whether the checked subject came from a pinned published release, a reconstructible package extract, a git checkout, or a mutable local workspace, whether it was pristine, dirty, partially migrated, or generated, and what claim posture still remains honest.

## Why this matters

Without **baseline-state truth**, the lane still permits one ordinary lie:

- package/feature/target scope can be exact,
- config basis can be explicit,
- replay bridges can be reviewable,
- yet the bundle can still omit whether the checked subject was already a locally drifted workspace rather than a clean published baseline.

That is not cosmetic.
It is the difference between “we checked *something nearby*” and “we checked the real release-pair baseline we are now asking downstream adopters to trust.”

## Main judgment after the pass

A worthy upgrade-support crate should now provide more than exact command/config/session truth.
It should also provide:

- one compact **baseline-state receipt** for which subject was actually checked,
- one explicit distinction between **published release**, **reconstructible extract**, **git checkout**, and **mutable local workspace**,
- and one consistency failure when public release-pair claims still pretend the baseline was pristine when it was already drifted or partially migrated.

That keeps the lane from quietly turning “nearby local workspace” into “trusted published release pair.”
