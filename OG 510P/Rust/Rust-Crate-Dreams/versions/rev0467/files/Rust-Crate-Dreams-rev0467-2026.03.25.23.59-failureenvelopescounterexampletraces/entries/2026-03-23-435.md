# Entry 435 — deepen the repo around a cross-domain demand matrix, pathfinder lane templates, and a debuggability capability stack

This pass again chose **deepen** over **append**.

The archive already has enough raw proposals.
What it needed next was a more implementation-ready answer to:

1. which archive lanes matter across the widest variety of real Rust use cases,
2. what a high-value crate should actually provide **other people** in those use cases,
3. and which top-frontier proposals deserve more concrete product planning before any new sector lane is added.

## Main judgment

The current top control-plane frontier still stands.

1. **P-0537 Compile Iteration Feedback Kit**
2. **P-0509 Crate Ecosystem Pathfinder & Decision-Pack Kit**
3. **P-0535 Dependency Lifecycle Transition Kit**
4. **P-0536 Crate Knowledge Pack Kit**
5. **P-0538 Concurrency Contract Kit**
6. **P-0486 Debuggability Support Contract Kit**
7. **P-0484 Toolchain & Target Support Contract Kit**
8. **P-0011 Crate Health Contract Kit**
9. **P-0532 Async Runtime Assurance Profile Kit**
10. **P-0431 Public Dependency Boundary Kit**

But the **repo-building order** inside that frontier should now tilt toward:

1. **P-0509 Crate Ecosystem Pathfinder & Decision-Pack Kit**
2. **P-0486 Debuggability Support Contract Kit**
3. **P-0535 Dependency Lifecycle Transition Kit**
4. **P-0484 Toolchain & Target Support Contract Kit**
5. **P-0536 Crate Knowledge Pack Kit**

Why?
Because current official Rust signals span a very wide map at once:

- async parity remains a flagship concern,
- build/test/tooling work remains central,
- safety-critical Rust is now explicit,
- Wasm Components are an active flagship,
- C++ interop and Rust-for-Linux remain real strategic seams,
- reference/FLS upkeep keeps specification and long-lived support work live,
- and docs.rs / crates.io still improve visibility without solving receiver-facing choice, debug, migration, or support truth.

That combination makes the next strong repo move less “invent another niche crate” and more “turn the top frontier into buildable product plans that work across many sectors.”

## New portfolio stance

### 1. Use a demand matrix before adding another sector proposal
A broad scan should now map prospective work against real user/use-case families first:

- teaching / newcomer stacks,
- backend and async services,
- GUI / game / creative tools,
- embedded / edge / device stacks,
- kernel / low-level systems work,
- safety-critical / regulated delivery,
- Wasm browser + component/plugin work,
- C++ / FFI / mixed-language systems,
- data / numerics / GPU / scientific pipelines,
- build / test / platform tooling.

If the best answer for several rows is still a shared control-plane crate, do **not** open another narrow lane.

### 2. Pathfinder now deserves explicit lane templates
The pathfinder lane is strong because many people need help choosing crates.
But a real product needs **task-lane templates**.
This pass therefore defined a lane-catalog plan so P-0509 can ship named starter profiles for varied tasks instead of vague “crate ranking”.

### 3. Debuggability now deserves an explicit capability stack
Debugging is broad enough that “debugging support” is too blurry.
A real product now needs a capability-stack model that separates:

- symbol/material presence,
- source lookup,
- breakpoints/stepping,
- async stack/task visibility,
- expression evaluation,
- pretty-printer / visualizer help,
- remote/container/embedded session families,
- and post-mortem symbolication.

That keeps P-0486 wide **without** letting it turn into one fake support score.

## Why this matters for worthy / epic crates

The archive’s best crates keep looking epic for the same reason:
they provide other people with a **portable answer** they can inspect later.

That answer might be:

- a decision pack,
- a capability witness,
- a lifecycle receipt,
- a support contract,
- a migration/off-ramp bundle,
- or a machine-usable knowledge pack.

The archive should still resist:

- another narrow wrapper,
- another parser/client bridge,
- another popularity scoreboard,
- another generic “LLM for crates” shell,
- or another sector-specific lane when the sharper missing seam is still horizontal.
