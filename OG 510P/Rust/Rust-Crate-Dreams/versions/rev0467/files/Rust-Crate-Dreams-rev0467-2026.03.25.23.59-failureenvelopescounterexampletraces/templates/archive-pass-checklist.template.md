# Archive pass checklist template

Use this before closing a revision.

## Pass summary
- **Entry number:**
- **Date:**
- **Dominant mode:** deepen / rerank / append / eliminate / hygiene
- **One-sentence change:**

## Current-source check
- [ ] I checked current official Rust sources when freshness mattered.
- [ ] I checked at least one ecosystem/domain source if the pass touched sector variety.
- [ ] I recorded the sources in the entry and relevant meta notes.

## Archive-shape check
- [ ] I did not promote a broad umbrella without a sharper seam.
- [ ] I left at least one practical artifact behind (plan, schema, scenario, delivery card, template, etc.).
- [ ] I stated what the crate should provide other people.
- [ ] I stated what the crate refuses to do.

## Frontier check
- [ ] I considered **need** separately from **buildability now**.
- [ ] I stated whether the pass changed salience, build order, both, or neither.
- [ ] I named any proposals that should be merged, held, or not re-inflated.

## Memory-spine check
- [ ] README updated if the latest pass changes how the repo should be entered.
- [ ] INDEX updated.
- [ ] prioritization updated if ranking/build order changed.
- [ ] roadmap updated if the next proving ground changed.
- [ ] research-ledger updated.
- [ ] decision-log updated.
- [ ] archive-memory-anchor updated.
- [ ] llm-hygiene updated if archive behavior changed.

## Finish check
- [ ] The latest entry explains what changed in plain language.
- [ ] A new reader could tell what to read first.
- [ ] The revision zip name matches the new archive state.
