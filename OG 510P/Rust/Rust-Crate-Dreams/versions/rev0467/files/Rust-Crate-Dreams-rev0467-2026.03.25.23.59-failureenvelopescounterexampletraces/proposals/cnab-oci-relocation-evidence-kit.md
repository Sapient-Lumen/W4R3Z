# Problem

CNAB now has a mature-enough shape to matter operationally: CNAB Core 1.2.0 is final, the spec family includes registry/security/claims/dependencies chapters, and the community has real compatibility knowledge for storing bundles in OCI registries. Rust also has solid OCI image/distribution substrate.

But the painful failures still happen at the seam between:

- **the `bundle.json` someone authored and the OCI artifact layout that actually got pushed**,
- **relocation maps and the digests people think were moved together**,
- **registry claims of OCI compatibility and the quirks a bundle installer really encountered**,
- **thin/thick/air-gap expectations and what a support team can actually hand off**,
- and **supply-chain/security metadata that exists in theory but never lands in one portable incident bundle.**

The missing Rust contribution is not another installer runtime. It is a **relocation-and-evidence kit** for CNAB locks, OCI push/pull receipts, registry-quirk overlays, and air-gap handoff artifacts.

# What it provides

- `cnab.lock` — pins bundle identity, invocation images, dependency/claims/security overlays, and expected OCI media-type/layout assumptions.
- `relocation-receipt` — normalized record of digest rewrites, repository moves, and artifact attachment state.
- `registry-capabilities.json` — explicit registry behavior notes rather than vague “OCI compatible” claims.
- `airgap-pack` — deterministic handoff artifact for disconnected scenarios.
- `cargo cnab-evidence` — emits `*.cnabbundle.zip` with locks, receipts, manifest/index views, and notes.

# What the crate should provide other people

1. **A boring artifact for “what exactly got pushed/pulled?”**
2. **Deterministic relocation receipts** across repositories and registries.
3. **Registry-quirk evidence** for support and CI diagnostics.
4. **Air-gap/disconnected handoff bundles** that stay honest about what was included.
5. **A Rust-native coordination layer above existing OCI crates and non-Rust CNAB tooling.**

# Persona / who it’s for

- platform and release engineers
- CNAB / application-bundle maintainers
- registry and artifact-platform teams
- support/operations teams handling disconnected installs

# Users & user stories

- **Release engineer**: “Capture the exact OCI index/manifests and relocation outcomes for this bundle push.”
- **Support engineer**: “Show me which registry quirk broke the install, with one compact receipt.”
- **Air-gap operator**: “Build a deterministic handoff artifact for a disconnected environment.”
- **Security reviewer**: “See the bundle, digest movement, and attached metadata in one place.”

# Prior art (and why it’s insufficient)

- CNAB already has a real spec family.
- `cnab-to-oci` demonstrates a reference approach for packaging bundles into OCI registries.
- Rust already has OCI spec and distribution client crates.

What Rust still lacks is a **portable evidence layer** for bundle locking, relocation receipts, registry capability overlays, and air-gap bundle generation.

# Design goals

1. **Bundle-explicit** — pin `bundle.json` semantics and invocation images directly.
2. **Digest-honest** — every relocation must be inspectable and replayable.
3. **Registry-aware** — capture quirks and fallbacks explicitly.
4. **Disconnected-friendly** — make air-gap handoff a first-class use case.
5. **Tool-neutral** — interoperate with existing CNAB/OCI tooling rather than replace it.

# MVP surface

- Minimal types: `CnabLock`, `RelocationReceipt`, `RegistryCapabilityMatrix`, `AirgapPack`, `CnabBundle`
- Minimal functions:
  - `capture_bundle()`
  - `capture_relocation()`
  - `probe_registry()`
  - `build_airgap_pack()`
  - `write_bundle()`
- Feature flags:
  - `registry-probe`
  - `airgap`
  - `claims`
  - `security`

# Compatibility story

- Works above existing OCI crates and artifacts.
- Accepts bundles or receipts generated by non-Rust CNAB tooling.
- Treats registry behavior as explicit overlays, not hidden assumptions.
- Does not require a new installer runtime.

# Conformance & fixtures

- Goldens for digest relocation, missing invocation image, thin/thick bundle mismatch, and registry annotation quirks.
- Synthetic registry-capability fixtures.
- Air-gap pack fixtures that prove included versus omitted artifacts.
- Public redacted bundles for issue reports and CI.

# Path to boring stability

- Stabilize locks and relocation receipts before deep installer integration.
- Keep registry probing narrow and evidence-oriented.
- Treat air-gap packs as deterministic bundles, not ad hoc tarballs.
- Resist drift into becoming a full deployment platform.

# Minimum lovable MVP

A Rust library and CLI that pin a CNAB bundle and its OCI assumptions, capture relocation outcomes and registry quirks, optionally build a deterministic air-gap pack, and emit compact `*.cnabbundle.zip` artifacts.

# De-risk plan

1. Start with offline bundle/index capture and relocation receipts.
2. Add registry probing only after the receipt model is stable.
3. Keep claims/security attachments optional overlays at first.
4. Pilot with synthetic registries and redacted sample bundles.

# Non-goals

- Not a fresh CNAB installer/runtime.
- Not a general OCI registry server.
- Not a universal artifact-signing platform.
- Not a full application deployment orchestrator.

# Architecture & API sketch

```rust
pub struct CnabLock {
    pub name: String,
    pub version: String,
    pub invocation_images: Vec<String>,
    pub oci_layout_profile: String,
}

pub fn capture_bundle(path: &std::path::Path) -> Result<CnabLock>;
pub fn capture_relocation(before: &str, after: &str) -> Result<RelocationReceipt>;
pub fn build_airgap_pack(lock: &CnabLock) -> Result<AirgapPack>;
```

Bundle draft: `cnab.lock`, `bundle.json`, `oci-index.json`, `relocation-receipt.json`, `registry-capabilities.json`, `airgap-manifest.json`, `notes.md`.

# Security / safety model

- Preserve digest integrity and provenance of moved artifacts.
- Redact registry credentials and private repository names when needed.
- Distinguish observed registry behavior from inferred compatibility notes.
- Avoid silently rewriting bundle semantics during capture.

# Maintenance & governance plan

- Track CNAB and OCI revisions explicitly.
- Keep registry capability overlays versioned and reviewable.
- Publish tiny synthetic bundles for regression tests.
- Avoid embedding vendor-specific deployment logic in the core.
