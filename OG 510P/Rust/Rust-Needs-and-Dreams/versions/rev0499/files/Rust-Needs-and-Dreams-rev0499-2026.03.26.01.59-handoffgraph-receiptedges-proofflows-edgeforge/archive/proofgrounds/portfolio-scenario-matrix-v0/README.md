# Portfolio scenario matrix v0

This is the archive's first thin proving-grounds matrix.

It is intentionally small.
It does **not** try to enumerate every Rust domain or every worthy seam.
It exists to force explicit answers to:
- which recurring Rust reality did a pilot exercise,
- what artifacts should it emit there,
- and what conclusions remain forbidden if it skipped other realities?

Primary file:
- `scenarios.json`

Typical use:
1. choose one or more scenario IDs for a pilot;
2. bind the pilot scorecard to those scenario IDs;
3. declare any skipped expected scenarios with reasons;
4. keep scenario coverage separate from seam ranking.
