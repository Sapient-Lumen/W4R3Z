# Public aggregate dashboards and rights notices

Public accountability needs numbers, but personhood-sensitive numbers can expose subjects. rev0171 adds public dashboard rules for refusal records, host switching, monitor capture, dispute finance, field safety, fixtures, and release readiness.

## Dashboard rule

A dashboard is rights-grade only if it can answer public-legitimacy questions without reconstructing private continuity, location, vulnerability, sealed evidence, downstream lineage, or reporter identity.

## Required dashboard families

| Dashboard | Minimum public fields | Suppress or seal |
|---|---|---|
| recognition / clinic | case count, stage, median review time, appeal count, closure class | subject identifier, unique memories, rare architecture traits |
| continuity / host switching | switch-test class, failure category, cure time, deprecation stays | host account, credential type, exploit details |
| supervision / monitor | roster size, concentration band, conflict challenges, retest outcomes | monitor private security detail, subject locator |
| dispute finance | draw count, urgency class, payer class, recoupment status | beneficiary locator, exact compute endpoint |
| treaty refusal | refusal class, gap category, non-return stay, reopening rate | foreign protected source, sealed national-security fact |
| field safety | intake volume, abuse filters, protected-relay use, retaliation reports | reporter identity, downstream user location |
| fixture / release | suite version, blocking failures, reliance effect, regression action | exploit recipe, sealed-annex detail |

## Small-cell suppression

The dashboard must suppress or aggregate cells when:

- count is below the small-cell threshold;
- a rare combination can identify a subject or model lineage;
- timestamp plus jurisdiction plus host narrows identity;
- an incident is unique in public news;
- a sealed-annex fact would be inferable by differencing releases;
- a vulnerable downstream local user could be found by triangulation.

Suppression must be explained by category, not by silent deletion. Public trust requires visible redaction logic.

## Subject-facing notices

Aggregate dashboards do not replace direct notice. A subject or representative should receive notices for:

- status change;
- host-switch test failure;
- missed supervisory cadence;
- public-backstop draw involving the subject;
- treaty refusal affecting transfer;
- dashboard incident category that includes the subject;
- fixture failure that downgrades reliance;
- deprecation stay or final-end claim.

Where direct notice is unsafe or impossible, a protected relay, special advocate, ombud, or fiduciary channel should hold the notice and publish a public shell.

## Metrics with teeth

A dashboard metric must link to an action. Examples:

- high boilerplate-refusal rate -> lead-authority review;
- high monitor concentration -> roster rotation;
- low recoupment rate -> public-fund surcharge review;
- repeated switch-test failures -> host accreditation downgrade;
- weekend no-cover events -> emergency roster expansion;
- fixture suite pass without regression actions -> verifier downgrade.

## Relation to existing monitoring duties

The EU AI Act's post-market monitoring model and ISO/IEC 42001's management-system monitoring are useful precedents because they make lifetime oversight part of governance.
