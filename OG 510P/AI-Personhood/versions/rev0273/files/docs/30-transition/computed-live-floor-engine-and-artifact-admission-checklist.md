# Computed Live-Floor Engine and Artifact Admission Checklist

rev0203 closes the next practical receipt-risk seam: live-floor state cannot be trusted when it appears only as edited text in a quorum ledger, import narrative, or public shell. The archive now has request, custody, envelope, response, intake, import, challenge, rollback, class-local replay, recomputation, and failed-gate surfaces. The remaining operational risk is that future contributors may update one surface but forget the others, or may treat a checklist as proof that a live counterparty artifact exists.

The rev0203 rule is strict: **computed floor is source of truth**.

## What this pass adds

The new `live-receipt-floor-computed-snapshot` object is generated by `tools/compute_live_receipt_floor.py`. It reads import gates, import attempts, challenge/rollback records, class-local replays, quorum recomputation reports, and failed-gate public summaries. It then recomputes the archive live receipt floor from the evidence path rather than trusting hand-edited fields.

The current generated snapshot intentionally remains zero-weight. It finds no eligible live imports, no satisfied live receipt classes, and no cross-critical quorum. It also records the dry-run/fixture/challenged exclusions that explain why existing artifacts cannot update reliance.

## Core rules

**Computed floor is source of truth.** A quorum ledger, live packet, or public summary cannot upgrade reliance unless the computed snapshot agrees with the import gates and challenge state.

**Admission checklist is not admission.** A completed custody checklist, authority checklist, artifact locator, or request packet remains pre-admission until a real live artifact passes custody and import-gate rules.

**Artifact quarantine comes before response creation.** If raw custody, hash, authority scope, non-host retention, sealed/public boundary, or dependency-group checks are absent, the artifact stays quarantined and cannot become a response, intake, or import.

**Failed-gate publication follows every non-import.** Defective, dry-run, fixture, declined, expired, challenged, rolled-back, or quarantined branches must appear in a public failed-gate shell with sealed details withheld where necessary.

**One valid class remains class-local.** Even a future actual result-return import can satisfy only result-return unless the full cross-critical receipt floor is recomputed as met.

## Refactor effect

rev0203 adds a generated state layer over the receipt chain:

1. counterparty artifact custody,
2. non-host artifact envelope,
3. response record,
4. intake record,
5. actual import gate,
6. import challenge and rollback,
7. live/class-local replay,
8. quorum recomputation,
9. computed live-floor snapshot,
10. public failed-gate disclosure.

The snapshot is deliberately generated by a tool and then audited against the checked-in example. This prevents release authors from editing a single JSON field to create apparent live evidence.

## Current reliance posture

No actual live external receipt exists in this archive. `independent_receipts_present` remains zero. The new engine makes that zero state machine-checkable and keeps the next real live artifact from bypassing custody, import, challenge, class-local, recomputation, and failed-gate gates.
