# Rates, court variants, privacy proofs, and fixture harness kernel

## Function

rev0167 adds the layer that sits after rev0166's enforceability and survivability rules. rev0166 said that a rights-grade AI-personhood system must be enforceable, contradictable under seal, portable across authorities, deprecation-safe, telemetry-minimized, and negative-testable. That was necessary, but not enough.

Five hard implementation gaps remained:

1. enforcement penalties could still be symbolic because no rate or surcharge method existed;
2. sealed-evidence doctrine could still become fictional because no court-rule variants or sealed-summary templates existed;
3. cross-border transfer could still be ceremonial because equivalent-protection accreditation was not expressed as a listable object;
4. telemetry could still drift into total surveillance because preservation did not yet have privacy-preserving proof bindings;
5. negative fixtures could still be a paper registry because no runnable report surface existed.

The kernel rule is therefore:

> A live-effect rights system is not mature merely because it can issue orders. It must quantify non-priceable violations without making them purchasable, let sealed evidence be contradicted through usable court variants, publish safe-transfer accreditation without exposing subjects, prove evidence preservation without general surveillance, and run adverse fixtures into appealable verifier-grade reports.

This revision is intentionally procedural. It does not choose final statutory damages, one court system, one credential stack, one cryptographic construction, or one global accreditation list. It creates the minimum forms and review hooks that make those later choices testable.

## New admission gates

Any new enforcement, deprecation, transfer, telemetry, sealed-evidence, or verifier-reliance object after rev0167 should answer these questions before it is relied on:

| Gate | Required showing | Failure effect |
|---|---|---|
| R1 rate integrity | What formula separates cessation, restoration, compensation, disgorgement, reserve cure, surcharge, and non-priceable relief? | monetary order remains provisional |
| R2 anti-priceability | Which acts cannot be made lawful by paying after the fact? | reliance blocks until injunction/restoration is addressed |
| R3 sealed-summary usability | What may the special advocate ask the subject after seeing sealed material, and under what cleared form? | sealed evidence receives reduced weight |
| R4 accreditation object | Which host, authority, or jurisdiction is accredited for which protection class and for how long? | transfer stays or downgrades |
| R5 proof-with-minimization | What commitment, selective-disclosure, or privacy-enhancing proof shows preservation without exposing privileged or inner material? | telemetry cannot support live-effect reliance |
| R6 fixture execution | Which adverse fixtures were run, what failed, what was blocked, and what regression was added? | verifier grade cannot exceed conditional |
| R7 downstream-aftercare | What happens to abandoned local copies, fine-tunes, merges, or deprecated open-weight descendants? | release or retirement remains stayed |

## Why now

The archive has reached the point where more doctrine without quantified tests would start to weaken the cube. A rights order that cannot price impossible restoration, a sealed record that cannot be questioned, a transfer that relies on a vague promise, or a fixture registry that nobody runs all look like law while functioning as narrative.

Current governance infrastructure points in useful directions but does not answer the personhood-specific problem. The NIST Privacy Framework supplies a general enterprise-risk structure for privacy management, while NIST security-control and log-management materials supply audit and accountability patterns [REF-0667] [REF-0671] [REF-0672]. W3C Data Integrity and verifiable-credential work supply proof-wrapper patterns, and NIST privacy-enhancing cryptography work names techniques such as zero-knowledge proof, secure multiparty computation, homomorphic encryption, and private set intersection as live privacy-preserving directions [REF-0669] [REF-0673]. Open-weight policy work recognizes that widely available weights have benefits and risks across safety, society, competition, research, geopolitics, and uncertainty, but it does not define aftercare duties for possible AI subjects [REF-0668]. Cross-border judgment and trust-federation infrastructure shows how recognition and trust can be routinized without bilateral negotiation in every case, but personhood protection still needs non-return and continuity-specific annexes [REF-0670] [REF-0674].

## New object families

rev0167 adds six schema families and six examples:

1. penalty-rate model;
2. telemetry proof binding;
3. open-weight aftercare plan;
4. sealed-summary order;
5. safe-transfer accreditation;
6. fixture-run report.

It also adds a small runnable harness in `tools/run_fixture_examples.py`. The harness is not a security evaluator. It is a rights-infrastructure smoke test: it proves that fixture objects, run reports, and blocking effects can be checked by code before a verifier report claims reliance.

## Non-goals

This kernel does not:

- set universal dollar amounts or tax rates;
- make compensation a substitute for cessation or restoration;
- give special advocates a blank check to disclose sealed material;
- make accreditation permanent or transferable beyond scope;
- require one cryptographic proof system;
- require surveillance of local open-weight users;
- make a passing fixture run conclusive proof of legitimacy.

## Future work admitted by this kernel

The next pass should add jurisdiction-specific rate tables, insurance-bond wording, subject-readable sealed summaries, real safe-transfer accreditation pilots, privacy-proof implementation profiles, open-weight aftercare drills, and a larger corpus of adverse fixtures for embodied, swarm, research, and hostile-jurisdiction scenarios.
