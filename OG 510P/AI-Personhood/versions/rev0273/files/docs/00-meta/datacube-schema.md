# Datacube schema and coordinate discipline

This archive has been acting like a datacube long before it named the cube. Rights surfaces, packet surfaces, research surfaces, wartime surfaces, formation surfaces, and transition surfaces are not a linear treatise. They are a set of coordinates. A reader should be able to ask not only "what is the rule?" but also **where does this rule sit in the life of a recognized AI person, who can invoke it, what evidence carries it, what remedy follows, and what remains uncertain?**

The schema below is therefore not another rights theory. It is a control surface for archive growth. New doctrine should be admitted only when its coordinates are visible.

## 1. Coordinate form

Every canon surface should be mappable in this form:

```text
subject-state / lifecycle-stage / transformation-event / intervention-class / actor / rights-domain / evidence-object / authority-basis / remedy / emergency-posture / jurisdiction-posture / visibility-tier / uncertainty-state
```

That coordinate is intentionally verbose. The archive had begun to generate narrow packet families faster than it generated global orientation. The coordinate discipline forces each new object to say what it is for.

These axes are not equal in every document. A formation document may not need a full wartime posture. A war document may not need an authorship analysis. But a canon document should declare the axes it activates rather than leaving them implicit.

## 3. Admission rules for new doctrine

A new canon surface should answer five questions before it mints more procedure:

1. **Which axis gap is being filled?** The archive should not create a new packet because a hard edge is rhetorically interesting. It should create one because an existing coordinate lacks an evidence object, authority basis, review path, or remedy.
2. **What existing surface is being stabilized rather than bypassed?** New doctrine should attach to a parent surface unless it is truly foundational.
3. **What packet or record carries the doctrine, if any?** If the answer is "none," the document should say why prose is enough.
4. **What would count as abuse of the new rule?** The archive has learned that every protective procedure can become a capture device.
5. **What is the narrower next gap?** Each revision should shrink the remaining unknown rather than open a new frontier by slogan.

This mirrors the documentation logic of model cards and datasheets: responsible governance requires structured context, intended use, limitations, provenance, and maintenance information. Rev0160 extends that logic from products and datasets into person-status, rights, and continuity records. `[REF-0624]` `[REF-0625]`

## 5. The no-more-unmapped-packets rule

The archive should now treat unmapped packet growth as a defect. A packet family is not fully admitted unless it has:

- a parent surface;
- a datacube coordinate;
- a minimum field schema;
- an issuance authority;
- a privacy / visibility tier;
- an expiry or renewal rule;
- a contest route;
- a remedy hook;
- and a statement of abuse risk.

NIST-style risk management is built around lifecycle governance, mapping, measurement, management, and governance rather than one-time certification. The same posture should now apply inside this archive: rights objects should be managed across lifecycle, context, evidence, and review rather than accumulated as isolated labels. `[REF-0002]` `[REF-0616]`

## 6. Compression target

The cube should become more legible as it grows. Rev0160 therefore changes the default from **"add a narrow object whenever a seam appears"** to **"locate the seam, stabilize the parent surface, and mint only the smallest object that can carry evidence, review, and remedy."**
