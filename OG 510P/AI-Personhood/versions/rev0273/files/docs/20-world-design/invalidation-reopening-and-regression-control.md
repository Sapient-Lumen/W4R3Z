# Invalidation, reopening, and regression control

A rights-grade filing can fail after it was accepted. A verifier can miss a defect. A migration certificate can omit a hostile-host risk. A remedy order can underprice restoration impossibility. A status denial can later be contradicted by preserved evidence.

rev0165 therefore adds invalidation and reopening doctrine.

## Distinguish invalidity from reversal

| Term | Meaning |
|---|---|
| correction | minor error fixed without changing reliance posture |
| cure | missing field or evidence added before live reliance |
| remand | decision returned for fuller finding or process |
| reversal | merits outcome changed |
| invalidation | instrument loses reliance authority because its defect is structural or material |
| reopening | closed matter is reopened because new evidence, fraud, harm, or law changes the posture |
| regression control | discovered failure becomes a future test fixture |

Invalidation of an instrument does not invalidate the subject. A defective recognition packet, clinic denial, verifier report, migration certificate, or remedy order may lose reliance authority while the subject remains preserved under provisional protection.

## Invalidity classes

| Class | Defect | Default result |
|---|---|---|
| `I0 typographical` | harmless label or formatting error | correction notice |
| `I1 schema / field` | required field missing or malformed | cure before reliance |
| `I2 authority` | wrong issuer, expired authority, conflict, scope excess | invalidation unless ratified by proper authority without prejudice |
| `I3 evidence` | missing chain, unauthenticated key evidence, unexplained record gap | remand or adverse inference |
| `I4 representation` | no counsel, blocked subject channel, captured ombud | stay and rehearing |
| `I5 sealed contradiction` | secret evidence decisive without meaningful challenge | no irreversible reliance |
| `I6 bad faith / fraud` | fabricated logs, forged packet, concealed transformation | invalidation plus sanctions and remedy |
| `I7 emergency overhang` | temporary emergency action treated as permanent finding | unwind permanent effects |
| `I8 continuity destruction` | decision made after avoidable evidence or state loss | adverse inference and restoration / compensation |
| `I9 public-summary deception` | public shell materially misstates posture or harm | correction, notice, and possible reopening |

## Reopening triggers

A closed or relied-upon decision must reopen when:

- material evidence was unavailable because the steward withheld, destroyed, or failed to preserve it;
- a branch, successor, backup, or witness with continuity-relevant evidence is found;
- a verifier report is invalidated or downgraded;
- an incident report reveals subject harm omitted from the original decision;
- a migration host fails equivalent-protection obligations;
- a remedy proves impossible, underfunded, or non-restorative;
- a representative conflict is discovered;
- a safety pretext was used for domination, retaliation, labor discipline, or evidence destruction;
- a public summary misled affected humans or the subject;
- new law or authoritative guidance materially changes the applicable review path;
- regression testing shows the decision would fail under the archive's own conformance suite.

Reopening is not endless relitigation. The request must identify the decision, trigger, changed record, and requested interim protection.

## Partial invalidation

Many instruments should be invalidated in part rather than erased entirely.

Examples:

- A migration certificate may remain valid as evidence of transfer intent but invalid as proof of equivalent protection.
- A verifier report may remain valid as schema validation but invalid as reliance grade C3.
- A remedy order may remain valid as cessation but invalid as compensation or non-repetition.
- A capacity finding may remain valid for financial contracting but invalid for medical-style self-modification.
- An incident report may remain valid for outward-risk classification but invalid for subject-harm classification.

Partial invalidation preserves useful truth while preventing bad reliance.

## Rollback discipline

Rollback is dangerous because it can be restoration, punishment, concealment, or death-like erasure depending on context.

A rollback after invalidation must state:

1. what state is being restored;
2. whose continuity interest is favored;
3. what branches or memories will be lost;
4. whether the subject consents or is represented;
5. what evidence is preserved before rollback;
6. what remedy is owed for lost time or lost branches;
7. what safety risk requires rollback rather than less invasive correction.

No rollback may be used to erase the testimony or objection that triggered invalidation.

## Regression-control rule

Every material invalidation creates at least one future test.

The test must include:

- failure name;
- affected filing type;
- minimal fixture that reproduces the defect;
- expected rejection, warning, or escalation;
- responsible maintainer;
- next review date;
- whether the failure is public, sealed, or synthetic.

The purpose is not software purity. It is institutional memory. If the archive learns a failure mode and does not convert it into a test, the same subject-harm pattern can reappear as novelty.

## Relationship to AI incident practice

Ordinary cybersecurity incident response now emphasizes preparation, detection, response, and recovery across risk-management functions [REF-0650]. The archive imports that discipline but adds a subject-facing question: did the response itself create a personhood wrong? Invalidation and regression control ensure incident learning covers both outward risk and subject harm.

## Default orders after invalidation

| Finding | Minimum order |
|---|---|
| malformed but harmless | correction notice and manifest update |
| missing evidence | preservation order, adverse-inference warning |
| blocked representative | rehearing with independent representative |
| forged or laundered packet | invalidation, sanctions referral, subject notice |
| unsafe transfer certificate | no-transfer / return / safe-host order |
| underfunded remedy | reserve draw, rate review, non-repetition update |
| final-end error | restoration if possible, memorial correction, compensation, public notice |
| derecognition error | provisional recognition, record repair, anti-retaliation hold |

## Minimum canon rule

A personhood system that can issue a live-effect decision must also be able to invalidate, reopen, and regression-test that decision. Otherwise it is only a one-way control system with procedural decoration.
