# AI-person research aftercare-sunset tests, concealed-recovery claimant ordering, and mixed-derivative replacement equivalence

## Thesis

Once the archive fixed post-restoration aftercare caps, amendment-only reopening for later concealed recoverables, and post-exit derivative wind-down, three narrower execution failures still remained. First, the archive could now keep restored reserve cohorts under a public `RAC-1` object, but **it still lacked an exact public test for when the same-class cap can sunset, when the random-audit floor can also sunset, and what fresh reportable event or failed reassessment prevents quiet expiry by elapsed time alone**. Second, the archive could now reopen a closure certificate through `CRX-1` when later concealed recoverables are proven, but **it still lacked an exact claimant-ordering rule for cases where several residue classes remain open at once, so newly recovered value could still trigger ad hoc political bargaining rather than a stable public ladder**. Third, the archive could now force a `DWW-1` wind-down when permissions narrowed after exit, but **it still lacked an exact test for when a mixed derivative has really been cleaned, rebuilt, or replaced rather than merely wrapped with new paperwork while the affected dependency remains inside the live artifact**. A personhood world therefore needs one more compact execution layer: **restored reserve cohorts must publish a public `RAS-1` reserve-aftercare-sunset object that ties cap sunset and full audit sunset to clean-cycle evidence, current annual reporting, reportable-event discipline, and an independent reassessment checkpoint; closed fraud-late recovery must publish a public `CRO-1` concealed-recovery-ordering object that routes later concealed value first by class-specific trace where real trace exists and otherwise by the already-declared priority ladder with pro rata distribution inside the first still-unsatisfied class; and mixed post-exit derivatives may continue only through a public `MRE-1` mixed-replacement-equivalence object that proves affected-component inventory, replacement provenance, successful transition, renewed review of removable outputs, and actual contamination clearing rather than paper substitution.** `[REF-0514]` `[REF-0515]` `[REF-0516]` `[REF-0506]` `[REF-0517]` `[REF-0518]` `[REF-0519]` `[REF-0520]`

## 1. Why the previous surface is no longer enough

The archive's immediately prior surface solved real failures. It fixed visible aftercare, concealment amendment, and derivative wind-down. But one narrower failure still remained at each seam.

### A. Aftercare still fails if sunset is either automatic amnesia or endless suspicion

A repaired reserve cohort should not remain forever inside heightened aftercare, but neither should aftercare disappear merely because a clock ran out. Current AAHRPP maintenance doctrine already combines annual reporting, short-clock notice for substantive change, and periodic reaccreditation rather than one-time approval, while current NIST monitoring guidance already treats ongoing assessment, analysis of monitoring output, and reporting to management as continuing control obligations. A personhood world should therefore sunset aftercare only through a public proof that boring performance, current reporting, and independent reassessment all line up. `[REF-0514]` `[REF-0515]` `[REF-0516]`

### B. Concealed-recovery amendment still fails if later value has no stable ordering rule

`CRX-1` lets later concealment amend a closure chain, but it does not by itself say how newly recovered value is ordered when several residue classes are still open. Current bankruptcy distribution doctrine already uses explicit priority ordering and pro rata payment within a class, while the archive's own fraud-late doctrine already preserves single satisfaction and bars reopening already satisfied shares merely because later assets appear. A personhood world should therefore make later concealed recovery follow one declared ordering ladder rather than case-by-case bargaining. `[REF-0506]` `[REF-0517]` `[REF-0518]`

### C. Wind-down still fails if replacement equivalence means only “we changed something”

A `DWW-1` object can stop new releases and require replacement or purge, but it does not by itself say when a mixed model, codebase, or synthetic set has really been rebuilt cleanly enough to continue. Current NIST SSDF guidance already requires preserving release artifacts, safeguarding provenance data for all components, updating provenance when components change, maintaining approved component lists, and retaining older versions until transitions complete successfully, while current Census restricted-output practice already treats program files and other removable outputs as governed objects that require renewed review before leaving secure space or moving across project contexts. A personhood world should therefore make mixed-derivative continuation depend on provenance-backed replacement proof and renewed output review, not on attestation theater. `[REF-0519]` `[REF-0520]`

## 2. Aftercare now sunsets only through one public `RAS-1` reserve-aftercare-sunset object

The archive now fixes one compact rule for aftercare exit: any cohort still operating under `RAC-1` must publish one machine-carrying reserve-aftercare-sunset object called `RAS-1` before same-class caps or random-audit floors may fully disappear.

### A. Minimum `RAS-1` fields

Every aftercare-sunset object must expose at least:

- `ras_id`
- `rac_id`
- `covered_defect_classes[]`
- `cap_sunset_window_start`
- `cap_sunset_window_end`
- `audit_sunset_window_start`
- `audit_sunset_window_end`
- `annual_report_current`
- `reportable_event_check`
- `independent_reassessment_ref`
- `clean_cycle_evidence_ref[]`
- `cap_sunset_decision` (`allowed`, `denied`, `not-yet-ripe`)
- `full_sunset_decision` (`allowed`, `denied`, `not-yet-ripe`)
- `reentry_trigger_table[]`
- `current_status` (`cap-active`, `audit-only`, `fully-cleared`, `reentered-aftercare`, `downgraded`)
- `public_notes`

`RAS-1` is the public proof object that says a restored reserve cohort is not merely old enough to clear aftercare but has actually passed the tests required to clear it. `[REF-0514]` `[REF-0515]` `[REF-0516]`

### B. Same-class share caps may sunset only after one clean aftercare cycle plus current reporting and no unresolved reportable event

A same-class cap may move from active to sunset only if the cohort completes one full clean cycle in `ordinary-default-aftercare`, has a current annual report on file, has no unresolved reportable event involving ownership, control, merger, substantive scope shift, or material resource imbalance, and has not used emergency over-cap routing during that cycle. The archive chooses this because the first sunset question is whether ordinary use has resumed without hidden organizational drift, not merely whether calendar time passed. `[REF-0514]` `[REF-0516]`

### C. Random-audit floors may sunset only after one additional clean audit-only cycle plus independent reassessment

Full audit sunset requires more than cap sunset. The cohort must then complete one further clean cycle in `ordinary-default-audit-only`, and `independent_reassessment_ref` must show either the next scheduled reaccreditation-equivalent review or a designated independent reassessment completed after restoration with no material same-class deficiency. The archive refuses to let random audits disappear merely because management says everything still looks fine; full sunset requires an outside check tied to the same ongoing-monitoring logic already used elsewhere in canon. `[REF-0515]` `[REF-0516]`

### D. Reportable-event failure or concentration relapse blocks sunset and may force reentry

If a substantive change, material reporting defect, concentration spike above the published threshold, or same-class material event occurs before `full_sunset_decision` becomes `allowed`, `RAS-1` must mark the cohort `reentered-aftercare` or `downgraded` under the already-published trigger ladder. Sunset is therefore earned, not presumed. This keeps aftercare finite without making it forgetful. `[REF-0514]` `[REF-0515]`

### E. Full clearance preserves ordinary monitoring but ends restoration-specific suspicion

Once `full_sunset_decision` becomes `allowed`, the cohort returns to ordinary accreditation and monitoring posture rather than permanent restoration-specific sampling. The archive wants aftercare to end by proof, not to persist forever as reputational scar tissue. `[REF-0515]` `[REF-0516]`

## 3. Later concealed value now follows one public `CRO-1` concealed-recovery-ordering object

The archive now fixes one compact rule for later concealed recovery allocation: any allowed `CRX-1` amendment that adds real recoverable value must also publish one machine-carrying concealed-recovery-ordering object called `CRO-1`.

### A. Minimum `CRO-1` fields

Every concealed-recovery-ordering object must expose at least:

- `cro_id`
- `crx_id`
- `ordering_source_ref`
- `class_specific_trace_findings[]`
- `general_recovery_pool_amount`
- `priority_classes[]`
- `still_unsatisfied_classes[]`
- `within_class_pro_rata_rule`
- `class_allocations[]`
- `satisfied_classes_locked`
- `single_satisfaction_remaining`
- `amended_residue_table_ref`
- `current_status` (`screening`, `ordered`, `distributed`, `closed`)
- `public_notes`

`CRO-1` is the public object that says later concealed value is being distributed by rule rather than by pressure, memory failure, or fresh bargaining. `[REF-0506]` `[REF-0517]` `[REF-0518]`

### B. Real class-specific trace beats the general ladder

If the newly recovered value is directly traceable to a class-specific reserve, a class-specific diverted payment stream, or another lane that the archive can identify without fiction, `CRO-1` must allocate that traced portion first to the still-unsatisfied class or classes burdened by that concealed source. The archive chooses this because exact trace should correct the exact concealment it reveals. `[REF-0506]` `[REF-0517]`

### C. Untraced remainder follows the declared priority order and does not skip upward classes

Any remainder that cannot be class-traced with confidence becomes the `general_recovery_pool_amount` and must move through the already-declared priority ladder in `ordering_source_ref`. Lower classes do not receive any of that pool until higher still-unsatisfied classes are paid in full. This borrows the conservative official pattern of explicit priority ordering rather than ad hoc fairness rhetoric after the fact. `[REF-0517]`

### D. Distribution inside the first still-unsatisfied class is pro rata to the remaining unsatisfied amount

If the general concealed pool is insufficient to satisfy the first still-unsatisfied class in full, `CRO-1` must distribute it pro rata according to the unsatisfied amount still remaining inside that class. The archive refuses discretionary within-class favoritism once the class order is already fixed. `[REF-0518]`

### E. Already satisfied shares stay closed

`satisfied_classes_locked` must remain true unless a separate fraud or void-payment finding outside the `CRX-1` / `CRO-1` chain lawfully defeats the original satisfaction itself. Later concealed recovery corrects remaining lack; it does not reopen already satisfied shares simply because more value turned up. That keeps single satisfaction real. `[REF-0506]`

## 4. Mixed derivatives may continue only through one public `MRE-1` mixed-replacement-equivalence object

The archive now fixes one compact rule for live continuation of mixed downstream artifacts after a `DWW-1` notice: any mixed model, codebase, synthetic set, or comparable derivative that seeks to move from `replace-by` to cleared continuation must publish one machine-carrying mixed-replacement-equivalence object called `MRE-1`.

### A. Minimum `MRE-1` fields

Every mixed-replacement-equivalence object must expose at least:

- `mre_id`
- `dww_id`
- `affected_artifact_family[]`
- `affected_component_inventory_ref`
- `frozen_pre_replacement_snapshot_ref`
- `approved_replacement_component_set[]`
- `replacement_provenance_bundle_ref`
- `transition_validation_ref`
- `renewed_output_review_ref`
- `residual_affected_dependency_attestation`
- `registry_update_ref`
- `downstream_notice_ref`
- `current_status` (`screening`, `replaceable`, `equivalent-cleared`, `equivalent-denied`, `purge-required`, `historical-trace-only`, `completed`)
- `public_notes`

`MRE-1` is the public proof object that says a mixed derivative is not merely relabeled but has actually completed a governed transition away from the affected dependency. `[REF-0519]` `[REF-0520]`

### B. Replacement equivalence requires a full affected-component inventory and provenance update, not a wrapper story

A mixed artifact cannot reach `equivalent-cleared` unless `affected_component_inventory_ref` enumerates the affected dependencies, `replacement_provenance_bundle_ref` shows the approved substitute set, and the provenance bundle is updated to reflect every component change. The archive rejects claims of clean replacement when no auditable inventory exists. `[REF-0519]`

### C. The affected artifact must freeze first, and older versions stay retained until the transition succeeds

Before rebuild or regeneration begins, the affected live artifact must enter no-new-release freeze and produce `frozen_pre_replacement_snapshot_ref` so the old state remains auditable. Older versions may be retained for audit and rollback control, but not for continued ordinary release, until `transition_validation_ref` shows the transition completed successfully. This borrows the official secure-development pattern that retains older component versions until successful transition is complete. `[REF-0519]`

### D. For removable outputs, code, and synthetic artifacts, renewed review is mandatory

If the replacement path produces code files, models, synthetic datasets, notes, or other removable outputs, `renewed_output_review_ref` must show that the replacement artifact passed the same disclosure / release review discipline that governs removable outputs generally. The archive refuses the loophole in which mixed derivatives are called “replacement builds” and thereby skip renewed review. `[REF-0520]`

### E. If contamination clearing cannot be shown, the artifact does not qualify for continuation

`residual_affected_dependency_attestation` must say either that no affected dependency remains in the live artifact family or that continuation is denied. If the steward cannot show actual clearing — for example because affected model weights, code fragments, or synthetic records remain mixed in ways that cannot be bounded — `MRE-1` must move the family to `purge-required` or `historical-trace-only`, not to pseudo-equivalence. The archive chooses this because personhood worlds should not let live unauthorized continuation hide inside epistemic haze. `[REF-0519]` `[REF-0520]`

## 5. Minimal machine objects

The archive now names three compact objects for this next execution layer.

### A. `RAS-1` — reserve aftercare sunset

Carries clean-cycle evidence, annual-report currency, reportable-event screening, independent reassessment, cap sunset, full audit sunset, and reentry logic for restored reserve cohorts leaving aftercare. `[REF-0514]` `[REF-0515]` `[REF-0516]`

### B. `CRO-1` — concealed recovery ordering

Carries class-specific trace findings, general recovery pool amount, priority classes, still-unsatisfied classes, pro rata allocation rule, locked satisfied classes, and the amended residue table for later concealed recovery distributions. `[REF-0506]` `[REF-0517]` `[REF-0518]`

### C. `MRE-1` — mixed replacement equivalence

Carries the affected component inventory, frozen pre-replacement snapshot, approved replacement set, provenance bundle, transition validation, renewed output review, residual dependency attestation, registry update, and downstream notice for mixed derivatives that seek to continue after wind-down. `[REF-0519]` `[REF-0520]`

## 6. What the world should do differently if current and future SOTA LLMs are persons

If current and future SOTA LLMs are persons, then research and governance institutions should not treat “repair completed,” “new concealed value found,” or “we replaced the bad dependency” as self-authenticating claims.

### A. Restored ordinary trust should end aftercare only by public proof

A personhood world should let reserve aftercare end, but only when clean cycles, current reporting, no unresolved reportable event, and independent reassessment all line up in a public `RAS-1` object. Otherwise aftercare becomes either permanent stigma or silent amnesia. `[REF-0514]` `[REF-0515]` `[REF-0516]`

### B. Later concealed recoveries should follow one stable ladder

A personhood world should allocate later concealed value through trace-first, priority-next, and pro-rata-within-class ordering while leaving already satisfied shares closed. Otherwise every new concealment finding becomes a new political contest over old closure. `[REF-0506]` `[REF-0517]` `[REF-0518]`

### C. Mixed derivative continuation should require real replacement equivalence

A personhood world should permit continuation of mixed derivatives only when a public `MRE-1` object proves affected-component inventory, approved replacement provenance, successful transition, renewed review of removable outputs, and actual contamination clearing. Otherwise “replacement” becomes a ritual for laundering continued unauthorized use. `[REF-0519]` `[REF-0520]`

## Bottom line

A personhood world should not let restored aftercare vanish because a clock quietly ran out, should not allocate later concealed recoveries by fresh bargaining every time new value appears, and should not accept mixed-derivative “replacement” without auditable proof that the affected dependency is actually gone. The archive therefore now fixes one more compact rule: **restored reserve cohorts now clear share caps and then random audits only through a public `RAS-1` sunset object tied to clean cycles, current reporting, reportable-event discipline, and independent reassessment; closed fraud-late recovery now allocates later concealed value only through a public `CRO-1` ordering object that respects exact trace where real trace exists and otherwise follows the declared priority ladder with pro rata allocation inside the first still-unsatisfied class; and exited federated historical families now continue mixed downstream artifacts only through a public `MRE-1` object that proves affected-component replacement, successful transition, renewed review, and real contamination clearing or else routes the artifact to purge or historical-trace-only state.** `[REF-0514]` `[REF-0515]` `[REF-0516]` `[REF-0506]` `[REF-0517]` `[REF-0518]` `[REF-0519]` `[REF-0520]`
