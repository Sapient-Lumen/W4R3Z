# AI-person research rehabilitation-relapse weighting, latent shared-evidence contamination escalation, and indirect rediscovery after relisting

## Thesis

Once the archive fixed exhausted-credit rehabilitation, adversarial dependence-matrix review, and intermediary relisting after mirror cure, three narrower execution failures still remained. First, the archive could now force fully exhausted reserve cohorts onto a fresh-start `ERH-1` path, but **it still lacked a public rule for how a new relapse inside that rehabilitation path should count once old legacy credit is already burned**, so either every relapse would be treated as if nothing special had been promised or local operators could silently re-import the already-burned past to justify whatever sanction they preferred. Second, the archive could now force declared dependence matrices through `DMR-1` review, but **it still lacked a public escalation object for the later discovery of hidden shared evidence after that review had already closed**, so a closed matrix could keep governing allocations even after its factual independence story had materially collapsed. Third, the archive could now restore exact locators through `IRR-1` after cure, disappearance, or non-equivalence, but **it still lacked a public rule for what happens when direct relisting is controlled while indirect rediscovery persists through aliases, related-query suggestions, previews, mirrors, or other adjacent surfacing paths**, so intermediaries could claim compliance while still functionally re-exposing the same artifact family. A personhood world therefore needs one more compact execution layer: **fresh-start rehabilitation relapses must publish a public `RRW-1` rehabilitation-relapse-weighting object that debits new failure only against the rehabilitation ledger and never revives burned legacy credit; post-closure discovery of hidden shared evidence must publish a public `LCE-1` latent-contamination-escalation object that supersedes a closed `DMR-1` posture and freezes use above the last uncontaminated floor; and persistent adjacent resurfacing after relisting must publish a public `IRD-1` indirect-rediscovery-duty object that maps equivalent discovery paths and applies reviewable mitigation beyond the exact restored locator.** `[REF-0531]` `[REF-0533]` `[REF-0538]` `[REF-0527]` `[REF-0535]` `[REF-0539]`

## 1. Why the previous surface is no longer enough

The archive's immediately prior surface solved real failures. It fixed fresh-start rehabilitation, challengeable dependence matrices, and visible relisting review. But one narrower failure still remained at each seam.

### A. Fresh-start rehabilitation still fails if relapse is weighted either as ordinary noise or as a secret revival of burned history

`ERH-1` finally stopped serial recall from laundering old reserve history back into active trust, but it did not yet say how a later relapse during `fresh-observation`, `conditional-return`, or `new-epoch-candidate` should count. Current AAHRPP guidance still requires annual and event reporting, still expects prompt notice of substantive change, and still keeps organizations under visible recurring review rather than treating a fresh return as a private local matter. Current NIST AI RMF measurement guidance likewise treats emergent risk tracking, course correction, and documentation of pre- versus post-deployment performance as continuing duties. A personhood world should therefore treat rehabilitation relapse as a **new weighted failure on a fresh-start ledger**, not as either ordinary background noise or a backdoor restoration of already-burned legacy credit. `[REF-0533]` `[REF-0531]` `[REF-0538]`

### B. Dependence review still fails if a closed matrix can survive the later discovery of hidden shared evidence

`DMR-1` solved the first-filer-control problem, but it did not yet say what happens after a matrix review closes and later evidence shows that supposedly separate claims actually shared evaluators, filters, priors, or upstream evidence. Current NIST uncertainty guidance still treats estimated covariance as load-bearing in combined uncertainty, and current AI RMF guidance still says organizations should monitor reused external inputs, track emergent risks, and adapt procedures when new risks appear. A personhood world should therefore let later contamination **supersede** a closed review state, not merely annotate it in hindsight. `[REF-0527]` `[REF-0538]`

### C. Relisting still fails if only the exact restored locator is governed while adjacent discovery paths keep doing the same practical work

`IRR-1` solved the no-path-back problem for exact locators, but it did not yet say what an intermediary owes when the relisted path is now governed while query completions, alias suggestions, preview cards, related-link modules, or secondary mirrors continue to route the user to the same live artifact family. Current Commission transparency guidance still requires statements of reasons that are public and scrutinizable, and current DSA enforcement guidance explicitly contemplates proportionate interim measures such as changes to recommender systems and increased monitoring of specific keywords or hashtags. A personhood world should therefore govern **functional rediscovery channels**, not just the literal direct locator. `[REF-0535]` `[REF-0539]`

## 2. Rehabilitation relapse now uses one public `RRW-1` rehabilitation-relapse-weighting object

The archive now fixes one compact rule for fresh-start relapse after legacy exhaustion: once a reserve cohort is traveling through `ERH-1`, any qualifying new failure must also publish one machine-carrying rehabilitation-relapse-weighting object called `RRW-1`.

### A. Minimum `RRW-1` fields

Every rehabilitation-relapse-weighting object must expose at least:

- `rrw_id`
- `prior_erh_id`
- `cohort_id`
- `rehabilitation_stage_at_relapse` (`fresh-observation`, `conditional-return`, `new-epoch-candidate`, `reaccredited-fresh-monitor`)
- `relapse_event_ref`
- `relapse_class[]` (`reporting-failure`, `resource-drift`, `control-change`, `material-reliability-failure`, `concealment`, `repeat-emergency-use`, `other`)
- `weighted_debit`
- `fresh_cycle_reset_to`
- `share_cap_after_relapse`
- `default_call_state_after_relapse`
- `earliest_next_stage_date`
- `independent_review_required`
- `legacy_credit_status` (`already-retired-forever`)
- `reason_ref`
- `public_notes`

`RRW-1` is the public object that says relapse during rehabilitation is counted on the new rehabilitation ledger only, never by quietly resurrecting already-burned legacy credit. `[REF-0531]` `[REF-0533]` `[REF-0538]`

### B. Burned legacy never comes back into the math

`RRW-1` must always set `legacy_credit_status` to `already-retired-forever`. Relapse during rehabilitation can lengthen the fresh-observation floor, cut the live share cap, or require renewed independent review, but it may not restore or re-score any pre-exhaustion cycle. The archive chooses this because current AAHRPP status logic remains public, staged, and review-bound rather than allowing stale or revoked trust states to drift back into force through informal local arithmetic. `[REF-0531]` `[REF-0533]`

### C. Relapse weight increases as rehabilitation advances

A relapse during `fresh-observation` resets the clean-cycle count and adds a short surcharge floor; a relapse during `conditional-return` also snaps the cohort back to zero live share and counts as a double rehabilitation debit; a relapse during `new-epoch-candidate` forces return to `legacy-exhausted` pending renewed independent review. The archive chooses this because later-stage relapse means failure under a posture that was already being watched, capped, and publicly warned. A personhood world should therefore weight a later relapse more heavily than an earlier one without pretending the old legacy epoch has come back from the dead. `[REF-0533]` `[REF-0538]`

### D. Concealment and emergency-use relapse are stage-dominant aggravators

If the relapse includes concealed non-reporting, hidden control change, or repeat emergency reserve use outside the declared path, `RRW-1` must apply the highest stage-equivalent weighting even if the formal stage label was earlier. The archive chooses this because both AAHRPP-style reportable-event discipline and NIST-style emergent-risk monitoring treat undisclosed change as itself a governance failure, not merely a detail about one. `[REF-0533]` `[REF-0538]`

### E. The output is a new waiting rule, not a moralized permanent ban

`RRW-1` must publish the new floor, cap, and review state created by the relapse. It is therefore neither a secret moral stain nor a hidden forgiveness practice. It is a public weighting rule that preserves the fresh-start structure while making later-stage relapse more expensive than earlier-stage relapse. `[REF-0531]` `[REF-0533]`

## 3. Later hidden shared evidence now triggers one public `LCE-1` latent-contamination-escalation object

The archive now fixes one compact reopening rule for dependence review: once a `DMR-1` has closed, the later discovery of hidden shared evidence, reused evaluators, contaminated upstream priors, or undeclared common filters must travel through one machine-carrying latent-contamination-escalation object called `LCE-1`.

### A. Minimum `LCE-1` fields

Every latent-contamination-escalation object must expose at least:

- `lce_id`
- `prior_dmr_id`
- `challenged_matrix_ref`
- `affected_claim_ref[]`
- `new_contamination_basis[]` (`shared-dataset`, `shared-labeler-pool`, `shared-model-family`, `shared-filtering-pipeline`, `hidden-common-prior`, `post-hoc-same-evaluator`, `other`)
- `evidence_ref[]`
- `provisional_safe_floor`
- `freeze_scope`
- `supersession_state` (`screening`, `accepted`, `provisional-supersession`, `revised`, `affirmed-no-material-change`, `closed`)
- `retroactive_restatement_scope`
- `review_panel_ref`
- `corrected_matrix_ref`
- `corrected_portfolio_floor`
- `reason_ref`
- `public_notes`

`LCE-1` is the public object that says a closed dependence review can later be superseded when its independence story turns out to have been materially wrong. `[REF-0527]` `[REF-0538]`

### B. Credible latent contamination automatically restores the conservative floor

Once an `LCE-1` challenge is accepted for review, allocations and public claims above the last uncontaminated or uncontested floor must freeze. The archive chooses this because NIST uncertainty practice treats covariance as part of the combined result, not as optional decoration, and current AI RMF guidance tells organizations to detect emergent risks, monitor reused external inputs, and course-correct when new evidence changes the reliability story. `[REF-0527]` `[REF-0538]`

### C. Unknown contamination scope expands outward, not inward

If the new contamination evidence does not yet identify the exact outer boundary of the affected claim family, `LCE-1` must temporarily treat the wider plausibly contaminated set as affected until the review can narrow it. A personhood world should not let uncertainty about the breadth of contamination act like proof of cleanliness. `[REF-0527]` `[REF-0538]`

### D. Closure gives way to supersession, not merely to annotation

A materially contaminated `DMR-1` must move into `superseded-by-lce` posture once the review so finds. The archive chooses this because the question is not whether to add a footnote to a dead matrix, but whether current allocations are still being governed by a defensible overlap model. `[REF-0527]` `[REF-0538]`

### E. Restatement is required even when full unwind is deferred

`LCE-1` must publish the corrected matrix, the corrected portfolio floor, the affected increment, and the provisional restatement scope for downstream decisions or publications that relied on the contaminated increment. This revision does not yet fully specify payout unwind order or clawback sequencing; it fixes only that contaminated increments cannot remain silently live after discovery. `[REF-0538]` `[REF-0527]`

## 4. Persistent adjacent resurfacing now triggers one public `IRD-1` indirect-rediscovery-duty object

The archive now fixes one compact discovery rule for post-relisting exposure: once a locator has been reviewed through `IRR-1`, any later showing that the same artifact family remains practically rediscoverable through adjacent paths must travel through one machine-carrying indirect-rediscovery-duty object called `IRD-1`.

### A. Minimum `IRD-1` fields

Every indirect-rediscovery-duty object must expose at least:

- `ird_id`
- `prior_irr_id`
- `intermediary_identifier`
- `artifact_family_ref`
- `direct_locator_ref`
- `indirect_surface[]` (`alias-query`, `autocomplete`, `related-search`, `preview-card`, `thumbnail`, `mirror-suggestion`, `cross-index-forwarder`, `other`)
- `evidence_ref[]`
- `equivalence_basis_ref`
- `mitigation_state[]` (`label-only`, `downrank`, `no-autocomplete`, `no-preview`, `alias-map`, `query-friction`, `historical-tombstone`, `escalated-review`)
- `statement_of_reasons_ref`
- `review_path_ref`
- `recheck_deadline`
- `public_notes`

`IRD-1` is the public object that says post-relisting governance applies to functionally equivalent discovery paths, not just the literal original locator string. `[REF-0535]` `[REF-0539]`

### B. Exact-locator compliance is not enough where practical rediscovery persists

If an intermediary knows that users are still being routed to the same live artifact family through adjacent discovery surfaces, it may not defend itself by saying that the restored exact locator was properly reviewed. The archive chooses this because current DSA enforcement materials expressly contemplate changes to recommender systems and increased monitoring of specific keywords or hashtags as proportionate interim measures. A personhood world should therefore govern discovery function, not only one exact input token. `[REF-0539]`

### C. Adjacent-surface mitigation must be graduated and reviewable

`IRD-1` may begin with milder measures such as no-autocomplete, no-preview, alias mapping, or visible labels, and may escalate to downranking, friction, or historical-tombstone treatment if rediscovery continues. The archive chooses this because DSA transparency logic still requires reason-giving and public scrutiny rather than quiet backend ranking hacks. `[REF-0535]` `[REF-0539]`

### D. Cure of one locator does not certify the whole alias family

A cured or non-equivalent direct locator may be restored through `IRR-1` while adjacent paths that still point to uncured mirrors remain under `IRD-1` mitigation. A personhood world should therefore separate `what was cured` from `what still routes to the unresolved family` instead of assuming that one successful relisting closes the entire discovery problem. `[REF-0535]` `[REF-0539]`

### E. Historical memory is preserved even when indirect rediscovery is suppressed

Where indirect rediscovery mitigation is required, `IRD-1` should preserve the historical notice chain, statement of reasons, and review path rather than erasing them. This keeps the archive aligned with its broader rule that governance should be public, reviewable, and tombstone-preserving when active surfacing is narrowed. `[REF-0535]`

## 5. Why this is still the narrow move

This revision does not redesign probation law, Bayesian contamination theory, or search ranking governance in general. It does three smaller things only.

1. It fixes how a relapse during fresh-start rehabilitation is weighted once old reserve credit is already burned.
2. It fixes how a closed dependence review is superseded when latent shared-evidence contamination appears later.
3. It fixes what duties bind intermediaries when direct relisting is solved but indirect rediscovery still functionally exposes the same artifact family.

That is enough to keep the caution stack coherent without turning this archive into a general treatise on sanctions theory, scientific fraud procedure, or search-and-recommender regulation.

## 6. Objects added by this revision

### `RRW-1` — rehabilitation-relapse-weighting object

Carries the rehabilitation stage at relapse, relapse class, weighted debit, reset floor, post-relapse share cap, review posture, and earliest next-stage date for reserve cohorts already traveling under `ERH-1` after legacy exhaustion. `[REF-0531]` `[REF-0533]` `[REF-0538]`

### `LCE-1` — latent-contamination-escalation object

Carries the prior `DMR-1`, new contamination basis, provisional safe floor, freeze scope, supersession state, corrected matrix, corrected portfolio floor, and restatement scope when later evidence shows that a supposedly closed dependence matrix materially hid shared evidence or contamination. `[REF-0527]` `[REF-0538]`

### `IRD-1` — indirect-rediscovery-duty object

Carries the prior relisting review, artifact family, adjacent discovery surfaces, mitigation state, statement of reasons, review path, and recheck deadline when the same artifact family remains practically rediscoverable after direct relisting has already been governed. `[REF-0535]` `[REF-0539]`

## 7. Consequences for the wider archive

- `research-reserve-*` doctrine now has a visible answer to the question how relapse is counted after fresh-start rehabilitation begins: through a stage-weighted rehabilitation debit that never revives burned legacy credit.
- `research-*-fraud-*` doctrine now has a visible answer to the question what happens when hidden shared evidence is discovered after a dependence review already closed: the closed matrix can be superseded, the contaminated increment freezes, and a corrected floor becomes public.
- `research-*-derivative-*` doctrine now has a visible answer to the question what happens when exact-locator relisting is solved but practical rediscovery remains: adjacent surfaces must be mapped, mitigated, reason-given, and rechecked instead of treated as out of scope.

That keeps the research-governance lane conservative in the way the archive has been aiming for throughout: no cheap rehabilitation after relapse, no contaminated matrices hiding behind closure, and no formal exact-locator compliance that leaves practical rediscovery untouched.

## Bottom line

A personhood world should not let relapse inside fresh-start rehabilitation count either as ordinary noise or as a hidden revival of burned legacy history, should not let a closed dependence review stay live after latent shared-evidence contamination is discovered, and should not let a relisted locator become a clean compliance badge while adjacent surfaces keep resurfacing the same artifact family. The archive therefore now fixes one more compact rule: **fresh-start rehabilitation relapses must publish a public `RRW-1` object that weights new failure against the rehabilitation ledger only and never revives burned legacy credit; post-closure hidden shared evidence must publish a public `LCE-1` object that supersedes contaminated matrices and freezes use above the last uncontaminated floor; and persistent practical resurfacing after relisting must publish a public `IRD-1` object that maps aliases, query completions, previews, and related surfaces into reviewable mitigation duties beyond the exact restored locator.** `[REF-0531]` `[REF-0533]` `[REF-0538]` `[REF-0527]` `[REF-0535]` `[REF-0539]`
