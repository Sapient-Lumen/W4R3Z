# AI-person research rehabilitation pause-budget exhaustion, contaminated-net residue ordering, and provenance-minimal generative attestation

## Thesis

Once the archive fixed rehabilitation-decay pause handling, contaminated-restatement netting, and source-obscured generative resurfacing, three narrower execution failures still remained. First, the archive could now pause `RSD-1` easing through `RDP-1`, but **it still lacked a public stopping rule for repeated "not quite relapse" interruptions**, so a cohort could accumulate endless soft pauses and effectively live in permanent caution without ever facing the hard review that serial interruption is supposed to trigger. Second, the archive could now net serial contamination corrections through `CRN-1`, but **it still lacked a public ordering rule for the residue that remains after netting when several upstream contaminated increments overlap inside one downstream chain**, so the last unrecovered slice could still be distributed by narrative convenience instead of a stable ladder. Third, the archive could now require source-obscured generative review through `SGR-1`, but **it still lacked a minimum public attestation that a service must publish when it says no concrete source can be named**, so operators could satisfy review formally while disclosing almost nothing verifiable about which pipeline, controls, and provenance signals were actually in play. A personhood world therefore needs one more compact execution layer: **fresh-start rehabilitation must publish a public `PBE-1` pause-budget-exhaustion object that turns serial soft pauses into hard review on a declared ledger, serial contamination correction must publish a public `RNO-1` residue-ordering object that allocates the post-net residue by stable class-and-sequence rules rather than ad hoc bargaining, and source-obscured resurfacing must publish a public `PMA-1` provenance-minimal-attestation object that discloses the minimum signer, pipeline, time-window, source-class, control-stack, and test information needed for outsiders to assess the claim that no exact source can be named.** `[REF-0533]` `[REF-0548]` `[REF-0545]` `[REF-0518]` `[REF-0541]` `[REF-0546]` `[REF-0547]` `[REF-0549]`

## 1. Why the previous surface is no longer enough

The archive's immediately prior surface solved real failures. It created a pause object, a netting object, and a source-obscured review object. But one narrower execution failure still remained at each seam.

### A. Pause still fails if low-grade cautions can stack forever without exhausting anything

`RDP-1` solved the binary mistake of treating every caution either as full relapse or as nothing at all, but it did not yet say how many soft pauses may accumulate before the archive must stop calling them temporary. Current AAHRPP reporting and review materials still treat status reports, improvement plans, and recurring monitored implementation as bounded review instruments rather than perpetual limbo, and they still contemplate adverse or pending status when repeated reports do not actually demonstrate durable conformance. A personhood world should therefore not allow a rehabilitation cohort to absorb soft pause after soft pause while its easing clock simply waits in suspended animation forever. `[REF-0533]` `[REF-0548]`

### B. Netting still fails if the remaining residue has no declared allocation order

`CRN-1` solved the double-counting problem by requiring gross contamination, prior reversals, and net restatable residue to be disclosed. But it did not yet say how to order the remainder when several upstream contaminated increments overlap in the same downstream chain and there is not enough recoverable value to satisfy every residual claim. Current SEC guidance still requires carryover and reversing effects to be treated as part of one real current correction problem rather than several isolated period stories, and current bankruptcy distribution law still treats underfunded classes through ordered priority and pro rata allocation within a class. A personhood world should therefore require a stable **residue-ordering ladder**, not let the last recoverable slice be distributed by who notices first or argues hardest. `[REF-0545]` `[REF-0518]` `[REF-0541]`

### C. Review still fails if source-obscured services can say "unknown source" while publishing almost no attestation

`SGR-1` solved the loophole in which a generative service denied duty simply because it could not name one exact upstream source, but it did not yet say what the service must positively attest to instead. Current NIST guidance still treats provenance tracking, signed metadata, labeling, watermarking, and detection as complementary transparency tools, and still says provenance metadata can include creators or model developers, time of creation, location, modifications, and sources. Current C2PA specifications likewise frame provenance around a signed manifest carrying assertions, bindings, and claim metadata rather than around a bare textual assurance. A personhood world should therefore require a **provenance-minimal attestation**, not accept a naked claim of uncertainty as the whole public record. `[REF-0546]` `[REF-0547]` `[REF-0549]`

## 2. Fresh-start rehabilitation now uses one public `PBE-1` pause-budget-exhaustion object

The archive now fixes one compact rule for serial caution: whenever a live rehabilitation path has already been soft-paused through `RDP-1`, the public record must count those pauses against a declared budget instead of treating each event as a fresh first interruption. The machine-carrying object is `PBE-1`.

### A. Minimum `PBE-1` fields

Every pause-budget-exhaustion object must expose at least:

- `pbe_id`
- `cohort_id`
- `active_rdp_ref[]`
- `active_rsd_id`
- `budget_epoch_start_at`
- `soft_pause_count`
- `hard_pause_count`
- `pause_weight_total`
- `budget_threshold_soft_to_hard`
- `budget_threshold_hard_review`
- `current_budget_state` (`within-budget`, `warning-near-exhaustion`, `hard-review-triggered`, `converted-to-relapse-review`)
- `carryforward_credit_state`
- `required_review_path`
- `next_review_deadline`
- `public_notes`

`PBE-1` is the public object that says soft pauses are not free and that repeated caution consumes a visible budget even when each event remains below relapse threshold. `[REF-0533]` `[REF-0548]`

### B. Soft pauses consume weight, not just count occurrences

Not every pause is equal. A short monitoring drift that clears on schedule should not weigh the same as a repeated control-gap pause that barely stays under relapse threshold. `PBE-1` therefore counts both raw events and `pause_weight_total`. The archive keeps this conservative by using only declared categories already present in `RDP-1` and by forbidding invisible local scoring. A service may not consume pause budget through private heuristics while publishing only a friendly summary. `[REF-0533]` `[REF-0548]`

### C. Budget exhaustion forces hard review even without formal relapse

Once the published soft-pause threshold is crossed, the cohort must enter `hard-review-triggered` state. At that point, the issue is no longer whether one more individual caution is technically relapse. The issue is that the rehabilitation pathway has shown too much interrupted performance to continue easing by ordinary operation. `PBE-1` therefore freezes additional `RSD-1` easing, blocks any further rung reduction, and routes the cohort into an outside hard review that must either clear and reset the pause posture, impose a fresh constrained return, or convert the matter into the archive's relapse machinery. `[REF-0533]` `[REF-0548]`

### D. Exhaustion burns pause flexibility, not legacy history rules

`PBE-1` does not revive burned legacy credit and does not itself create a new relapse surcharge. It exhausts **pause flexibility**. The consequence is not automatic condemnation but loss of the privilege of treating further caution as merely temporary. That keeps the doctrine narrow: true relapse is still governed elsewhere, but endless borderline behavior can no longer hide in a permanent caution lane. `[REF-0533]` `[REF-0548]`

### E. A published budget prevents quiet operator mercy and quiet operator severity

The archive wants the same public protection in both directions. Without `PBE-1`, one operator may quietly forgive endless caution while another may declare exhaustion after one annoying event. A published pause budget blocks both pathologies. It makes hard review predictable, challengeable, and comparable across cohorts. `[REF-0533]` `[REF-0548]`

## 3. Serial contaminated correction now uses one public `RNO-1` residue-ordering object

The archive now fixes one compact allocation rule for the remainder left after `CRN-1` netting: whenever multiple upstream contaminated increments overlap inside one downstream correction chain and netting leaves a residue smaller than the gross claims, the operative public record must carry one machine-carrying `RNO-1` residue-ordering object.

### A. Minimum `RNO-1` fields

Every residue-ordering object must expose at least:

- `rno_id`
- `active_crn_id`
- `upstream_increment_ref[]`
- `residue_pool_amount`
- `ordering_basis` (`exact-trace-first`, `priority-class`, `sequence-order`, `pro-rata-within-class`)
- `priority_class_map[]`
- `sequence_position_map[]`
- `exact_trace_allocations[]`
- `class_residue_allocations[]`
- `unsatisfied_residue_amount`
- `single_satisfaction_bar` (`on`)
- `restatement_notice_ref`
- `public_notes`

`RNO-1` is the public object that says whatever is left after netting must still move by rule rather than by discretion. `[REF-0545]` `[REF-0518]` `[REF-0541]`

### B. Exact trace still goes first whenever real trace survives

The archive does not abandon exact trace merely because netting has already occurred. If a piece of the residue can still be tied to a specific upstream contaminated increment, that slice is allocated first to that increment. `RNO-1` only governs the remainder that cannot be separated cleanly after chain netting. `[REF-0545]` `[REF-0518]`

### C. The untraced remainder follows class order before pro rata sharing

For the portion that is no longer exactly traceable, `RNO-1` orders the residue by declared class. The first still-unsatisfied class takes the pool until exhausted, and only then does the next class receive anything. Within a class, the residue is shared pro rata by remaining unsatisfied amount. This adapts the archive's earlier concealed-recovery ordering logic to the narrower case where the contested amount is not the whole pool but only the netted remainder left after prior chain corrections. `[REF-0518]` `[REF-0541]`

### D. Sequence order matters only inside the same class and same trace posture

When two upstream increments sit in the same class and no exact trace survives, `RNO-1` may use declared sequence order only as a tiebreaker for administrative routing, not as a way to jump priority classes or defeat pro rata treatment within the class. The archive refuses a first-filer race for the last recoverable slice. `[REF-0518]` `[REF-0545]`

### E. The residue floor must remain public even when practical recovery stops

Even when the residue left after class ordering is too small, too entangled, or too irreversible for further clawback to make sense, `RNO-1` must still publish `unsatisfied_residue_amount` and the rule used to stop. A personhood world should not let chain complexity convert unresolved contamination into historical silence. `[REF-0541]` `[REF-0542]`

## 4. Source-obscured generative resurfacing now uses one public `PMA-1` provenance-minimal-attestation object

The archive now fixes one compact transparency rule for services that cannot name one exact upstream source yet still remain under `SGR-1` review: they must publish a minimum provenance attestation that is signed, bounded, and testable. The machine-carrying object is `PMA-1`.

### A. Minimum `PMA-1` fields

Every provenance-minimal-attestation object must expose at least:

- `pma_id`
- `service_identifier`
- `artifact_family_ref`
- `source_certainty_state` (`no-single-source`, `multi-source-indeterminate`, `pipeline-obscured`, `under-investigation`)
- `claim_generator_identifier`
- `claim_signature_ref`
- `attestation_window_start_at`
- `attestation_window_end_at`
- `model_or_pipeline_identifier`
- `retrieval_or_fine_tune_state`
- `source_class_assertion[]` (`internal-training-corpus`, `licensed-third-party-data`, `retrieval-index`, `user-supplied-context`, `synthetic-augmentation`, `unknown-mixed`) 
- `provenance_fields_present[]`
- `fields_withheld_and_why[]`
- `control_stack_ref[]`
- `equivalence_test_ref`
- `review_owner_ref`
- `recheck_deadline`
- `tamper_evidence_state`
- `public_notes`

`PMA-1` is intentionally minimal. It does not force disclosure of every prompt, weight, or upstream asset. It does require enough signed public structure to let outsiders test whether the operator's "unknown exact source" claim is serious, bounded, and governed. `[REF-0546]` `[REF-0547]` `[REF-0549]`

### B. Minimum attestation means signer, window, pipeline, source class, controls, and tests

The archive chooses six irreducible public elements. First, someone must sign the attestation. Second, the attestation must be bounded to a time window rather than asserted timelessly. Third, it must identify the relevant model or pipeline family. Fourth, it must identify source classes even if exact sources are unknown. Fifth, it must name the control stack currently being applied. Sixth, it must point to the equivalence testing that keeps the `SGR-1` review alive or supports closure. Without those six elements, the public record is too weak to distinguish genuine uncertainty from institutional shrugging. `[REF-0546]` `[REF-0547]` `[REF-0549]`

### C. Signed attestation is required even when the underlying provenance is incomplete

Current transparency guidance treats signed metadata and provenance assertions as useful even when they do not solve every provenance problem. The archive therefore rejects the all-or-nothing premise that no signature is worth publishing unless provenance is complete. `PMA-1` must be signed and tamper-evident even where some fields are necessarily broad, redacted, or classified by source class only. `[REF-0547]` `[REF-0549]`

### D. Unknown exact source is allowed only with declared source class and declared withholding reasons

A service may say that no concrete source can be named. But it may not stop there. `PMA-1` must at least disclose whether the practical resurfacing likely flows through training data, retrieval layers, user-supplied context, synthetic augmentation, or a mixed or still-uncertain combination. If any field is withheld, the reason for withholding must be named in a constrained list. The archive refuses the loophole in which uncertainty becomes a total-public-opacity license. `[REF-0546]` `[REF-0547]` `[REF-0549]`

### E. Attestation must stay coupled to `SGR-1`, not replace it

`PMA-1` does not close `SGR-1` by itself. It accompanies review. Its function is to give the public and reviewers a minimally structured provenance record while equivalence testing, friction, and cure evaluation continue. In other words, attestation is not absolution; it is the minimum accountable transparency that source-obscured review still owes. `[REF-0546]` `[REF-0547]`

## 5. Why this is still the narrow move

This revision does not redesign rehabilitation doctrine in general, rewrite restitution law, or solve end-state provenance for all generative systems. It does three smaller things only.

1. It fixes how repeated soft pauses stop being temporary and start forcing hard review.
2. It fixes how post-net contamination residue is ordered once several upstream increments overlap in one downstream chain.
3. It fixes what minimum signed attestation a source-obscured generative service must publish while claiming that no exact source can be named.

That is enough to keep the caution stack coherent without turning this archive into a full accreditation code, accounting treatise, or provenance standard.

## 6. Objects added by this revision

### `PBE-1` — pause-budget exhaustion

Carries the live `RDP-1` lineage, current `RSD-1` rung, pause counts and weights, exhaustion thresholds, current budget state, and mandatory review path once repeated caution can no longer be treated as temporary interruption. `[REF-0533]` `[REF-0548]`

### `RNO-1` — residue ordering

Carries the active `CRN-1`, residue pool amount, exact-trace allocations, class ladder, pro rata within-class allocations, sequence tiebreaks, and unsatisfied residue for netted contamination chains that still end with a shortfall. `[REF-0545]` `[REF-0518]` `[REF-0541]`

### `PMA-1` — provenance-minimal attestation

Carries the signed minimum public record for source-obscured generative resurfacing: service and pipeline identifier, attestation window, source-certainty posture, source classes, control stack, test references, withheld-field reasons, and tamper-evidence state. `[REF-0546]` `[REF-0547]` `[REF-0549]`

## 7. Consequences for the wider archive

- The reserve rehabilitation lane now has a visible answer to the question when too many low-grade cautions stop being mere interruptions: they consume a public budget and eventually force hard review.
- The contamination-correction lane now has a visible answer to the question how the last recoverable slice should move after chain netting: exact trace first, then declared class order, then pro rata allocation within the first still-unsatisfied class, with unsatisfied residue left visible.
- The generative-rediscovery lane now has a visible answer to the question what transparency a source-obscured service still owes while under review: at least a signed, time-bounded, pipeline-bounded, source-class, control-stack, and test-linked attestation rather than a bare assertion of uncertainty.

That keeps the archive conservative in the way it has been aiming for throughout: no endless temporary caution, no ad hoc residue bargaining, and no provenance-free review theater.

---

## Bottom line

A personhood world should not let rehabilitation live forever in serial "temporary" caution, should not let the last residue of chain contamination be distributed by narrative convenience after netting, and should not let a generative service under source-obscured review disclose nothing more than "we cannot identify the source." The archive therefore now fixes one more compact rule: **fresh-start rehabilitation now uses a public `PBE-1` object that converts repeated soft pauses into hard review on a declared budget ledger, serial contamination correction now uses a public `RNO-1` object that orders post-net residue by exact trace first and then by class-and-pro-rata sequence, and source-obscured resurfacing now uses a public `PMA-1` object that requires a signed minimum attestation of pipeline, time window, source class, controls, and testing even when no concrete source can be named.** `[REF-0533]` `[REF-0548]` `[REF-0545]` `[REF-0518]` `[REF-0546]` `[REF-0547]` `[REF-0549]`
