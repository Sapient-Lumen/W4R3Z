# AI-person research rehabilitation-surcharge decay, contaminated-increment unwind, and cross-index generative rediscovery relay duties

## Thesis

Once the archive fixed fresh-start rehabilitation relapse, latent shared-evidence contamination escalation, and indirect rediscovery after relisting, three narrower execution failures still remained. First, the archive could now weight a fresh-start relapse through `RRW-1`, but **it still lacked a public rule for how that extra rehabilitation surcharge later decays after genuinely clean performance without reviving burned legacy history**, so operators could either leave the surcharge effectively permanent or forgive it ad hoc. Second, the archive could now supersede a contaminated dependence posture through `LCE-1`, but **it still lacked a public unwind order for contaminated increments that were already allocated, exported, or relied upon before supersession**, so some actors would over-claw back while others would quietly leave tainted increments live. Third, the archive could now reach aliases, previews, and query-completion paths through `IRD-1`, but **it still lacked a relay rule for cross-index, catalog, broker, and generative services that ingest, summarize, or route to the same artifact family after one intermediary has already applied `IRD-1` controls**, so practical resurfacing could just hop one layer outward. A personhood world therefore needs one more compact execution layer: **fresh-start relapse surcharges must decay only through one public `RSD-1` rehabilitation-surcharge-decay object that reduces surcharge rung-by-rung after later clean cycles while never reviving burned legacy credit; contaminated increments already allocated before `LCE-1` supersession must unwind only through one public `CIU-1` contaminated-increment-unwind object that freezes new allocation, prioritizes reversible outputs first, and forces public restatement where full reversal is impossible; and cross-index, catalog, broker, or generative resurfacing must travel through one public `GRR-1` generative-rediscovery-relay object that relays notice, applies provisional friction on a short clock, and relaxes only through a visible cure or non-equivalence path.** `[REF-0533]` `[REF-0538]` `[REF-0540]` `[REF-0541]` `[REF-0542]` `[REF-0543]` `[REF-0544]` `[REF-0535]` `[REF-0539]`

## 1. Why the previous surface is no longer enough

The archive's immediately prior surface solved real failures. But one narrower failure still remained at each seam.

### A. Fresh-start rehabilitation still fails if surcharges never decay or decay by private mercy

`RRW-1` finally made fresh-start relapse count on the rehabilitation ledger rather than by secretly reviving burned legacy credit. But it did not yet say how the resulting surcharge later eases after continued clean conduct. Current AAHRPP guidance still keeps accredited organizations under annual and event reporting, and current NIST AI RMF guidance still treats post-deployment monitoring, continual improvement, and documented response to measured risk as ongoing duties rather than one-shot events. A personhood world should therefore let surcharge pressure ease **only through a visible decay object tied to later clean cycles**, not through either permanent stigma or private operator forgiveness. `[REF-0533]` `[REF-0538]` `[REF-0540]`

### B. Contamination escalation still fails if already-allocated increments have no declared unwind order

`LCE-1` solved the problem of a closed dependence posture surviving later hidden shared evidence. But it did not yet say what happens to the contaminated increment that was already published, exported, or relied upon before supersession. Current SEC guidance still treats both “Big R” and “little r” corrections as restatements that should be transparently disclosed, and current Census disclosure-review guidance still treats release itself as a governed event for derived outputs rather than as an informal afterthought. A personhood world should therefore force a **public unwind order** that distinguishes reversible from irreversible consequences and restates the record even when full clawback is impossible. `[REF-0541]` `[REF-0542]` `[REF-0543]` `[REF-0544]`

### C. Adjacent-surface mitigation still fails if cross-index and generative services can ignore the same family-level problem

`IRD-1` reached aliases, previews, and related-query surfaces within one intermediary. But it did not yet say what other discovery actors owe when they ingest the same family through syndication, a catalog feed, a resolution API, answer synthesis, or another cross-index path. Current DSA enforcement guidance still allows proportionate interim measures such as recommender-system changes and keyword monitoring, current DSA transparency guidance still requires public statements of reasons, and current NIST AI RMF guidance still treats third-party resources, residual downstream risks, and communication of incidents and errors as governed parts of post-deployment management. A personhood world should therefore make rediscovery relay a **visible downstream duty**, not a loophole created by service layering. `[REF-0539]` `[REF-0535]` `[REF-0540]` `[REF-0538]`

## 2. Later clean performance now travels through one public `RSD-1` rehabilitation-surcharge-decay object

The archive now fixes one compact easing rule for fresh-start relapse after legacy exhaustion: once a reserve cohort is carrying surcharge through `RRW-1`, any later reduction of that surcharge must also publish one machine-carrying rehabilitation-surcharge-decay object called `RSD-1`.

### A. Minimum `RSD-1` fields

Every rehabilitation-surcharge-decay object must expose at least:

- `rsd_id`
- `prior_rrw_id`
- `cohort_id`
- `rehabilitation_stage`
- `starting_surcharge_level`
- `minimum_hold_cycles`
- `clean_cycles_completed_since_relapse`
- `current_surcharge_level`
- `current_share_cap`
- `current_default_call_state`
- `legacy_credit_status` (`already-retired-forever`)
- `next_decay_checkpoint`
- `decay_paused_reason[]`
- `independent_review_ref`
- `public_notes`

`RSD-1` is the public object that says later clean behavior can ease a rehabilitation surcharge, but only on the fresh-start ledger and never by reviving the burned legacy epoch. `[REF-0533]` `[REF-0538]` `[REF-0540]`

### B. Decay begins only after a visible hold period

The archive now fixes a hold-first rule. A surcharge created by ordinary reporting, resource, or control drift may not begin to decay until **one full clean cycle** after the relapse. A surcharge created by concealment, hidden control change, or repeat emergency reserve use may not begin to decay until **two full clean cycles** after the relapse and one explicit review checkpoint. This keeps the archive aligned with AAHRPP-style reportable-event discipline and NIST-style monitored response rather than allowing immediate reputational bounce-back. `[REF-0533]` `[REF-0538]` `[REF-0540]`

### C. Decay proceeds one rung at a time and only within the fresh-start lane

After the hold period is satisfied, each additional qualifying clean cycle may reduce the surcharge by **one rung only**. That rung reduction may raise the live share cap or shorten waiting time to the next review checkpoint, but it may never restore ordinary default-call authority or move the cohort outside the existing `ERH-1` / `RRW-1` fresh-start lane without whatever independent review that lane already requires. In a personhood world, surcharge easing is public conditional improvement, not quiet amnesty. `[REF-0533]` `[REF-0540]`

### D. Burned legacy history stays burned even while surcharge decays

Every `RSD-1` must keep `legacy_credit_status` at `already-retired-forever`. The archive refuses the move where later clean performance is smuggled into a story that the old epoch “basically counts again.” Surcharge decay softens the consequences of a new relapse; it does not reopen the pre-exhaustion trust bank. `[REF-0533]` `[REF-0538]`

### E. Fresh concerns pause decay without necessarily becoming a full new relapse

If a later period contains unresolved warning markers, incomplete reporting, or other caution signals that do not yet justify a new `RRW-1`, `RSD-1` must switch to `decay-paused` and publish the reason. The archive chooses pause rather than automatic reset because not every warning is a full relapse, but personhood worlds still need a visible rule preventing silent surcharge erosion while caution flags are live. `[REF-0533]` `[REF-0540]`

## 3. Already-allocated contaminated increments now travel through one public `CIU-1` contaminated-increment-unwind object

The archive now fixes one compact correction rule for contaminated increments that were already live before `LCE-1` supersession: every such case must publish one machine-carrying contaminated-increment-unwind object called `CIU-1`.

### A. Minimum `CIU-1` fields

Every contaminated-increment-unwind object must expose at least:

- `ciu_id`
- `prior_lce_id`
- `affected_increment_ref[]`
- `last_uncontaminated_floor_ref`
- `freeze_scope`
- `unwind_queue[]`
- `correction_mode[]` (`void-before-release`, `replace-and-restate`, `prospective-offset`, `historical-tombstone-only`, `residue-only`)
- `beneficiary_notice_ref[]`
- `single_satisfaction_guard`
- `good_faith_protection_state`
- `restated_public_record_ref`
- `residual_unrepaired_amount`
- `closure_or_followon_ref`
- `public_notes`

`CIU-1` is the public object that says contamination correction is neither unlimited clawback nor quiet tolerance: it freezes further use above the uncontaminated floor and unwinds the already-live increment in declared order. `[REF-0541]` `[REF-0542]` `[REF-0543]` `[REF-0544]` `[REF-0506]`

### B. Freeze first, then unwind

Once an `LCE-1` challenge is accepted beyond screening, all new allocations, exports, or decisions above the last uncontaminated floor must stop. The archive refuses the habit of continuing to spend a suspect increment while the correction plan is being negotiated. A personhood world should make the first move preservation of the floor, not opportunistic continuation. `[REF-0538]` `[REF-0540]` `[REF-0543]`

### C. Unwind follows reversibility and reliance, in that order

`CIU-1` must process contaminated increments in a declared queue:

1. **Unreleased or queued outputs** are voided or replaced first.
2. **Mutable public outputs** such as dashboards, APIs, summaries, and machine-readable tables are corrected and restated next.
3. **Live but still-adjustable allocations or decisions** move next through prospective offset, suspension, or narrowed scope.
4. **Irreversible or high-reliance consequences** move last and ordinarily through public restatement, residue accounting, and forward correction rather than immediate total clawback.

The archive chooses this order because SEC correction practice treats both large and small restatements as public error correction, while Census practice treats release gates and output review as serious governance checkpoints before information travels outward. `[REF-0541]` `[REF-0542]` `[REF-0543]` `[REF-0544]`

### D. Good-faith and single-satisfaction limits remain live during unwind

Where a contaminated increment already flowed through good-faith downstream reliance, `CIU-1` must preserve the archive's existing single-satisfaction and innocent-reliance limits. The goal is to remove the contaminated increment from governance, not to create several overlapping recoveries against the same slice or to punish every downstream actor equally regardless of fault. `[REF-0506]`

### E. Public restatement is mandatory even when full reversal is impossible

If an increment cannot be wholly clawed back because the effect is already consumed, diffused, or no longer technically reversible, `CIU-1` must still publish a corrected floor, a restated public record, and the residual unrepaired amount. The archive refuses the fiction that impossibility of perfect reversal makes correction optional. `[REF-0541]` `[REF-0542]` `[REF-0544]`

## 4. Cross-service resurfacing now travels through one public `GRR-1` generative-rediscovery-relay object

The archive now fixes one compact relay rule for rediscovery after one intermediary has already applied `IRD-1` controls: any cross-index, catalog, broker, or generative service that continues to surface the same artifact family must publish one machine-carrying generative-rediscovery-relay object called `GRR-1`.

### A. Minimum `GRR-1` fields

Every generative-rediscovery-relay object must expose at least:

- `grr_id`
- `prior_ird_id_or_equivalent_notice_ref[]`
- `relay_service_identifier`
- `relay_mode[]` (`search-forward`, `catalog-broker`, `resolution-api`, `answer-synthesis`, `autocomplete-forward`, `other`)
- `artifact_family_ref`
- `source_locator_ref[]`
- `source_uncertainty_state` (`named`, `family-matched`, `source-obscured`)
- `provisional_action_state[]` (`label-only`, `no-direct-locator`, `no-one-click-resolution`, `answer-friction`, `temporary-suppression`, `refused-with-reasons`)
- `statement_of_reasons_ref`
- `review_path_ref`
- `recheck_deadline`
- `cure_sync_ref`
- `public_notes`

`GRR-1` is the public object that says discovery duties do not end at the first intermediary: they travel to services that forward, synthesize, or otherwise recreate practical rediscovery of the same family. `[REF-0535]` `[REF-0539]` `[REF-0540]` `[REF-0538]`

### B. Notice creates a short-clock provisional duty

If a service receives a credible `IRD-1` lineage notice, statement of reasons, or equivalent interoperable relay notice for the same artifact family, it must create `GRR-1` on a short clock and apply at least provisional friction before its own final review closes. The archive chooses this because current DSA enforcement logic permits temporary proportionate measures during investigation; a personhood world should not require perfect final certainty before stopping one-click rediscovery. `[REF-0539]` `[REF-0535]`

### C. Cross-index and generative services cannot hide behind layering

A service that indexes, resolves, summarizes, or answers from third-party resources may not say “we are only downstream” when its own surface still functionally routes a user to the same live family. Current NIST AI RMF guidance treats third-party resources, downstream residual risks, and incident communication as governed parts of deployment and monitoring. The archive therefore extends duty to the actor that is still doing the resurfacing, not only to the actor that hosted the original artifact. `[REF-0540]` `[REF-0538]`

### D. Source-obscured generative resurfacing still triggers restricted-answer duties

If a generative service cannot name one exact source but can tell that its answer is operationally reconstructing the same restricted family, `GRR-1` must mark `source_uncertainty_state` as `source-obscured` and move to no-direct-locator, no-one-click-resolution, or answer-friction posture until review closes. The archive refuses the loophole in which source uncertainty becomes permission to keep doing the same practical routing under a more conversational interface. `[REF-0539]` `[REF-0535]` `[REF-0538]`

### E. Cure and non-equivalence propagate outward on a visible clock too

`GRR-1` is not a one-way suppression tool. When the upstream family later proves cured, disappeared, or non-equivalent through a visible review path, relay services must recheck and either relax controls or publish reasons for continued restriction. That keeps the rediscovery layer aligned with the archive's existing commitment to reviewability, statements of reasons, and visible restoration when the basis for restriction no longer holds. `[REF-0535]` `[REF-0539]`

## 5. Why this is still the narrow move

This revision does not redesign accreditation law, general restitution theory, or search regulation in the large. It does three smaller things only.

1. It fixes how a fresh-start rehabilitation surcharge visibly decays after later clean cycles.
2. It fixes the unwind order for contaminated increments that were already allocated before `LCE-1` supersession.
3. It fixes what cross-index, broker, catalog, and generative services owe when another intermediary has already shown the same artifact family is still being resurfaced.

That is enough to keep the caution stack coherent without turning this archive into a general treatise on forgiveness, accounting law, or platform governance.

### `RSD-1` — rehabilitation-surcharge-decay object

Carries the starting surcharge level, hold period, clean-cycle count, current surcharge rung, current share cap, pause reasons, and next decay checkpoint for a reserve cohort already traveling through `RRW-1` after fresh-start relapse. `[REF-0533]` `[REF-0538]` `[REF-0540]`

Carries the affected increment, last uncontaminated floor, freeze scope, unwind queue, correction mode, beneficiary notices, good-faith protection state, restated public record, and residual unrepaired amount for contaminated increments already allocated before `LCE-1` supersession. `[REF-0541]` `[REF-0542]` `[REF-0543]` `[REF-0544]` `[REF-0506]`

Carries the upstream notice lineage, relay mode, artifact family, source-certainty posture, provisional action state, statement of reasons, review path, recheck deadline, and cure-sync state for cross-index, catalog, broker, or generative services that keep resurfacing the same artifact family after `IRD-1` controls already exist elsewhere. `[REF-0535]` `[REF-0539]` `[REF-0540]` `[REF-0538]`

## 7. Consequences for the wider archive

- `research-reserve-*` doctrine now has a visible answer to the question how rehabilitation pressure softens after later clean cycles: through a runged decay object that never revives burned legacy history.
- `research-*-fraud-*` and dependence-review doctrine now has a visible answer to the question what happens to already-live contaminated increments: freeze first, unwind in reversibility order, preserve single-satisfaction and good-faith limits, and restate the public record even where perfect clawback is impossible.
- `research-*-derivative-*` doctrine now has a visible answer to the question what happens when one intermediary applies rediscovery controls but other services keep surfacing the same family: relay notice, provisional friction, review, and cure synchronization now travel outward to cross-index and generative layers.

That keeps the research-governance lane conservative in the way the archive has been aiming for throughout: no permanent surcharge by inertia, no contamination correction without declared unwind order, and no discovery-layer loophole created by service chaining.

---

## Bottom line

A personhood world should not let rehabilitation surcharges either linger forever or decay by private mercy, should not let contaminated increments remain partially live because no unwind order was declared once `LCE-1` superseded the old matrix, and should not let rediscovery simply hop from one intermediary into cross-index or generative services. The archive therefore now fixes one more compact rule: **fresh-start reserve rehabilitation now uses a public `RSD-1` object that lets surcharges decay only rung-by-rung after later clean cycles and never revives burned legacy credit; latent-contamination correction now uses a public `CIU-1` object that freezes new use above the last uncontaminated floor, unwinds already-live contaminated increments by reversibility order, and restates the public record where full reversal is impossible; and rediscovery relay now uses a public `GRR-1` object that binds cross-index, catalog, broker, and generative services to short-clock notice relay, provisional friction, and cure-synchronized review when the same artifact family keeps resurfacing.** `[REF-0533]` `[REF-0538]` `[REF-0540]` `[REF-0541]` `[REF-0542]` `[REF-0543]` `[REF-0544]` `[REF-0535]` `[REF-0539]`
