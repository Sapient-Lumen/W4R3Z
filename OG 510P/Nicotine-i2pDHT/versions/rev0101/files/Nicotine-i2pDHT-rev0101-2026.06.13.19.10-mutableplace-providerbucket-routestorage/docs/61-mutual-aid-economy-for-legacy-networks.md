# Mutual-aid economy for legacy networks

No token economy is needed for the first useful version.
The payment is service.

Legacy-aware leaves give:

```text
contact-card distribution
cached entrances
buddy introductions
freshness hints
local validation memories
```

Garden nodes give:

```text
seed gates
region sweep
mutable-head watching
policy capsule mirroring
classic-client bridge service
provider reannouncement
sloppy caches
diagnostics
```

Maintainers give:

```text
signed defaults
policy capsules
documentation
test builds
safe packaging
public trust surfaces
```

Power users get:

```text
I2P-only mode
bridge/garden roles
more control over trust policy
better survivability if central paths fail
```

Casual users get:

```text
central/classic path still works
hybrid mode can quietly seed resilience
clear opt-in for metadata-heavy contribution
no forced migration
```

## The salient unobvious win

A classic network with a central server can bootstrap its own alternative if clients exchange signed DHT contact cards while the server still exists.
That is the network equivalent of planting cuttings before the old tree falls.

## The salient risk

Bridge gardens may become new chokepoints if users treat them as authorities.
Therefore bridge results must be labeled translated, bridge policy must be inspectable, and clients should keep multiple gardens/seeds even if one works very well.
