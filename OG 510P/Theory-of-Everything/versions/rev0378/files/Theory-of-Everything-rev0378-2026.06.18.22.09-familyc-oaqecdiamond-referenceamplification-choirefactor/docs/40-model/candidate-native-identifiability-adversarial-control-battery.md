## Compression verdict

The candidate-native identifiability stack can now say what a route must declare, how field-local credit is scored, how route promotion avoids compensation, how new evidence enters, how stale credit decays, how dependent cells propagate, how conflicts are adjudicated, how decisions are traced, how traces are replayed, how challenges are answered, and how challenge cases close.
That is still not enough to prevent a positive-only route from inflating.
A lane can pass through the lifecycle while only being tested against the data, dictionary, public carrier, prior, code subspace, or observer frame that made the original success visible.

The remaining corruption mode is **unopposed success**:

**a route identifies the target in the friendly package, but the archive never asks whether a wrong target, surrogate recoverand, gauge / frame relabeling, boundary dictionary, acquisition channel, regularizer, simulator ecology, abstention blind spot, public-carrier fragility, or witness import would have produced the same apparent win.**

That is not a bookkeeping gap.
It is a falsification gap inside the identifiability claim.
Candidate-native identifiability is contrastive: it must say not only why the positive target is recoverable, but why nearby non-targets, empirical collapses, surrogate explanations, borrowed witness packages, and hostile reruns do not receive the same credit.

The correct adversarial-control posture is:

**no future `S4` or `S5` candidate-native identifiability claim should be accepted unless the route survives a declared hostile-control battery against target decoys, equivalence relabelings, acquisition spoofing, inverse / prior leakage, margin collapse, abstention failure, public-bridge fragility, and witness-borrowing substitution; failure narrows, freezes, retags, or bars promotion rather than becoming a vague caveat.**

This battery is deliberately not another lifecycle stage for every edit.
Use it when:
- an `E5` promotion attempt is made;
- an `E4` readiness change would move a row toward `S4`;
- a previously traced `S4` or `S5` row is reused as current support;
- a challenge alleges that a positive route would also pass under a decoy, surrogate, borrowed, or publicness-failed control;
- a family-C, completion-bid, lab / simulation, frame / observer, or cosmological row claims candidate-native identification rather than field-local progress.

A battery pass is not witness-package closure.
It only says that the claimed candidate-native route has survived the declared adversarial controls for its stated target, regime, record class, public carrier, and abstention boundary.
Witness-package credit remains routed through `docs/40-model/witness-package-burden-router.md`.

## Adversarial-control state codes

Use these codes when a promotion attempt, readiness move, replayed high-state row, or route-bearing challenge needs adversarial controls.
They are not evidence-intake states, not supersession states, not propagation states, not adjudication states, not trace states, not replay states, not challenge-response states, not challenge-closure states, and not promotion states.
They say whether the adversarial battery was absent, mis-owned, locally passed, locally damaging, coupled-field passing, coupled-field damaging, conditionally public, or promotion-barring.

| Code | Control state | Meaning | Required archive action | Blocked overclaim |
|---|---|---|---|---|
| `NC0` | no battery required | The update is `E0`/`E1`, a prose repair, a source-sieve change, or a field-local note with no route-promotion implication. | Leave route posture unchanged; do not create a fake control row. | Turning every edit into a promotion stress test. |
| `NC1` | required battery missing | The claim seeks `E4`, `E5`, `S4`, `S5`, or reused high-state credit, but no adversarial controls are declared. | Bar promotion language; return to route ledger / evidence intake with missing controls named. | Treating a positive route as identified because nobody ran hostile decoys. |
| `NC2` | wrong-owner control | The hostile test targets witness custody, local-law credit, cosmological selection, method quality, or bibliography support rather than `OQ-0057` identifiability. | Retag the control to the correct owner and preserve the identifiability cap. | Letting a non-identifiability stress test promote or demote the candidate-native route. |
| `NC3` | field-local controls pass | A hostile control for one field passes without changing the target quotient, field vector, readiness state, or dominant blocker. | Preserve field-local credit; do not promote the route unless coupled controls and the promotion gate also pass. | Promoting the whole row because one field survived a local null. |
| `NC4` | field-local control damage | A control exposes a decoy, surrogate, spoofed acquisition, prior leak, margin collapse, abstention blind spot, or fragile public carrier in one field. | Narrow, freeze, retag, or route through supersession and challenge response as appropriate. | Keeping a damaged field as if the hostile test merely reduced confidence. |
| `NC5` | coupled-route controls pass | Multiple hostile controls pass together for a named target, record, quotient, regime, inverse, margin, abstention rule, and public bridge. | Allow the promotion gate to consider `S4` or retain a bounded `S3` / candidate `S4` row; record the remaining blocker. | Treating coupled pass as automatic `S5` or witness closure. |
| `NC6` | coupled-route control damage | A hostile control breaks compatibility between fields, exposes same-package stacking, or shows that the route identifies a surrogate / package rather than the candidate target. | Recompute route state; likely narrow to `S3`, freeze, retag, witness-separate, or bar promotion. | Averaging surviving fields after a coupled negative control invalidates the route. |
| `NC7` | public adversarial pass with condition | The route survives outside challenge only while a custody, replay, independence, replication, or challenge-procedure condition is maintained. | Carry the condition with the public-bridge and closure rows; reopen if the condition fails. | Treating a maintained public-control pass as permanent publicness. |
| `NC8` | promotion-barring open control | The adversarial battery cannot be replayed, has unclear owners, lacks decoys, fails under a required control, or leaves surviving scope unclear. | Do not spend high-state credit; route through conflict, replay / rollback, challenge response, or challenge closure before reuse. | Calling unresolved hostile controls mere caution while using the target credit. |

## Required hostile controls

A promotion attempt does not need every possible adversarial experiment.
It does need a battery that matches the claimed target and regime.
If a control is impossible, the row should say whether the impossibility is a justified abstention boundary or a promotion bar.

### 1. Target-decoy control

Ask whether a nearby wrong candidate target, parameter choice, geometry, history, vacuum, growth rule, fixed point, frame, or ontology would receive the same positive score.
If the answer is yes, the route has not identified the target; it has identified a broader equivalence class or surrogate.

Failure mode: target richness or reconstruction success is really class-level compatibility.
Default result: `NC4` if local, `NC6` if the target quotient collapses.

### 2. Equivalence / gauge / frame relabeling control

Ask whether the same record can be redescribed by a gauge choice, dual dictionary, boundary map, frame selection, observer split, or empirical-collapse relation without changing public outcomes.
If so, the route must either collapse the variants explicitly or stop claiming same/different identification.

Failure mode: inverse uniqueness is asserted before equivalence is fixed.
Default result: `NC4` or `NC6`, with retag through the equivalence-collapse protocol.

### 3. Acquisition-spoof control

Ask whether the record exists only inside the formal model, simulator, boundary dictionary, training data, hosted dashboard, or measurement preparation that assumes the target structure.
If the access channel imports the answer, the route has not acquired candidate-native evidence.

Failure mode: formal observability, simulator observability, or lab preparation is spent as acquired public evidence.
Default result: `NC4` and evidence-intake / supersession review; `NC6` if the whole route depended on the spoofed channel.

### 4. Inverse / prior-leakage control

Ask whether regularization, architecture, prior, gauge fixing, dictionary choice, benchmark ecology, likelihood family, or reconstruction policy carries the inverse result.
A route that works only because the inverse engine already encodes the target is not candidate-native identification.

Failure mode: recoverand, prior, or training ecology does the identifying work.
Default result: `NC4` for a field-local repair; `NC6` when coupled inverse / stability credit collapses.

### 5. Margin / perturbation control

Ask whether the target remains separated under finite-resource noise, nuisance variation, regime transport, out-of-distribution perturbation, public rerun, and known hard cases.
A route that wins only at zero noise, one tuned regime, or one benchmark ecology is not stable identification.

Failure mode: apparent uniqueness is a thin tie or overfit margin.
Default result: `NC4` if the margin narrows; `NC6` if the route cannot preserve the target quotient.

### 6. Abstention / hard-negative control

Ask whether the route refuses or returns no-verdict when it receives no-acquisition, no-inversion, empirical-collapse, underdetermined, out-of-regime, adversarially similar, or public-carrier-failed cases.
A route that must always name a best target is not safe identifiability.

Failure mode: calibrated confidence, posterior spread, or policy deferral hides forced-answer behavior.
Default result: `NC4` with an abstention-row update; `NC6` if forced answers are route-wide.

### 7. Public-bridge fragility control

Ask whether an outsider can possess, replay, challenge, and preserve the native-to-public bridge without relying on private infrastructure, privileged access, unverifiable preprocessing, disappearing custody, or one lab's tacit procedure.
A route that survives internally but not publicly may be native competence without public identifiability.

Failure mode: publicness is borrowed from publication, code release, hosted replay, or ordinary lab access.
Default result: `NC7` if conditioned public control survives; `NC6` or `NC8` if it does not.

### 8. Witness-borrowing substitution control

Ask whether the route's strongest support actually belongs to a witness-package owner, public-reference owner, lab / simulation owner, local-law owner, cosmological-package owner, or completion-bid target owner rather than candidate-native identifiability.
If so, preserve the surviving work but keep the identifiability cap.

Failure mode: witness-package progress or target-side formal progress erases a candidate-native identifiability debt.
Default result: `NC2`, `NC4`, or `NC7`, with witness separation when appropriate.

## Promotion use

A future `S4` proposal must show at least:

1. a complete eight-field route row;
2. no `NC1`, `NC6`, or `NC8` result on any decisive field;
3. any `NC4` damage narrowed into the route state rather than left as a caveat;
4. any `NC7` public condition carried into the public-bridge and challenge-closure rows;
5. a promotion-gate row stating why the earliest dominant blocker changed.

A future `S5` closure proposal must show more:

1. all `S4` requirements;
2. coupled-route controls passing for the full claimed target class, not only one benchmark or regime;
3. no surviving hidden witness-borrowing substitution;
4. replayable adversarial-control rows;
5. public challenge procedure sufficient for hostile outside reruns;
6. an abstention boundary that refuses empirical-collapse and no-inversion cases rather than forcing a target.

A route can pass the adversarial battery and still fail witness-package closure.
That is expected.
This surface only protects the candidate-native identifiability claim from positive-only inflation.

## Current-row guidance

### Family C

Family C should be stress-tested first against target-decoy, boundary-dictionary, inverse / prior-leakage, margin, abstention, and public-bridge controls.
The likely honest result remains bounded `S3` unless a route survives outside a fixed boundary / code-subspace / dictionary / simulator / replay package.
A successful local control is `NC3` or `NC5`, not automatic promotion.
A boundary- or regularizer-dependent failure is normally `NC4` or `NC6`.

### Completion bids

Completion bids should be stress-tested first against target-decoy, acquisition-spoof, inverse / prior-leakage, and witness-borrowing controls.
Formal uniqueness, fixed-point seriousness, worldsheet consistency, spin-foam convergence, causal-order minimalism, or amplitude selection can survive as target-side credit while still failing the public target-to-record battery.
The default result remains `NC2`, `NC3`, or `NC4` unless an acquired public record route is supplied.

### Laboratory and simulation routes

Lab and simulation routes should be stress-tested first against target-decoy, acquisition-spoof, inverse / prior-leakage, and witness-borrowing substitution.
They may pass publicness and acquisition controls better than completion bids while still identifying only an effective-model contrast, benchmark ecology, emulator behavior, or named discriminator class.
The default result remains bounded `S2` or named-class `S3` unless the candidate target quotient changes.

### Witness-side frame and observer routes

Frame, observer, asymptotic, and relational routes should be stress-tested first against equivalence / frame relabeling and public-bridge fragility.
A special access map can be real progress and still fail same-public-fact transport.
The default result remains access-discipline credit unless the public reference-standard route passes hostile frame changes.

### Cosmological proposal classes

Vacuum-energy, measure, population, typicality, anthropic, relaxation, and global-selection proposals should be stress-tested first against witness-borrowing and local-law / cosmological-package substitution.
A burden-reduction or selection story is not candidate-native identifiability unless it supplies a local target-to-record route and survives decoys that reshuffle the same burden.
The default result is `NC2` unless a local record-bearing route is declared.

## Anti-patterns blocked

- A route passes on one friendly benchmark and is retold as a candidate-native target identifier.
- A reconstruction succeeds only under the boundary dictionary that supplied the target, but the route is credited as independent inverse evidence.
- A prior, architecture, gauge choice, or simulator ecology carries the inverse while the output is reported as native recovery.
- A target is separated only at zero noise or under one tuned regime, while finite-resource margins remain untested.
- A route always returns a best answer and calls low confidence an abstention rule.
- A hosted replay, publication, or source release is treated as public challengeability after custody, independence, or rerun conditions fail.
- A witness-package or lab gain is remembered as candidate-native identifiability progress because it survived a public-control test.
- A promotion attempt says “robust to controls” without naming decoys, owners, surviving scope, damaged scope, and re-entry triggers.

## Minimal update policy

- If the battery returns `NC0`, do not change route posture.
- If it returns `NC1`, bar promotion until controls are supplied.
- If it returns `NC2`, retag to the correct owner and preserve the identifiability cap.
- If it returns `NC3`, preserve field-local credit without route promotion.
- If it returns `NC4`, narrow, freeze, or supersede the damaged field credit.
- If it returns `NC5`, allow promotion-gate consideration but do not skip readiness, trace, replay, challenge, or witness-package checks.
- If it returns `NC6`, recompute route state and likely freeze, narrow, retag, or witness-separate.
- If it returns `NC7`, carry the public condition into public-bridge, replay, and challenge-closure rows.
- If it returns `NC8`, do not spend high-state credit until the open control is answered or closure-barred.
