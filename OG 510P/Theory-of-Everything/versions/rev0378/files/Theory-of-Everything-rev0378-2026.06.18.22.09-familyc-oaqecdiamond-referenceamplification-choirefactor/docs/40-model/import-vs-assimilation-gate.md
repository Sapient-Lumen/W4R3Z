# Import versus assimilation gate

A completion bid should not earn the same archive-governance credit merely because a preserved fragment has been **imported** into a recipient lane or the shared spine and because that fragment has become **recipient-native or spine-native explanatory credit**.

Shared family scaffolding and ordered routing live in `docs/40-model/completion-bid-comparison-gate-family-frame.md` and `docs/40-model/completion-bid-comparison-stack.md`; this file keeps only the pair-specific split between import-grade transfer and assimilation-grade domestication.

**Pair-specific split:** a fragment may cross the border cleanly enough to be reused without yet becoming native property of the new home.

## What this gate separates

A completion bid can currently earn:
1. **import-grade transfer** — a salvaged fragment may be reused inside another lane or the shared spine with provenance, transfer mechanism, carried debt, and credit routing stated explicitly;
2. **assimilation-grade domestication** — that imported fragment may now be treated as recipient-native support or shared-spine property rather than as a tracked dependency whose foreign origin still matters.

This surface exists only to block the inflation from (1) to “the recipient now owns the achievement.”

## Why the distinction matters

Imported fragments often remain foreign modules.
A recipient lane can borrow a mathematical device, effective structure, benchmark map, or constraint relic and still depend on donor-lane scaffolding in ways that matter for explanatory credit.
The shared spine can also mention a fragment as common overlap while still lacking grounds to treat it as native canon.

Without an assimilation gate, the archive can make three opposite mistakes.
It can let a recipient lane narrate imported leverage as if it were generated by the recipient's own commitments.
It can let the shared spine absorb a fragment before the archive knows whether the fragment is really common structure or just portable borrowed machinery.
Or it can overreact in the other direction and treat every imported fragment as permanently foreign even after the recipient has genuinely re-supported it.

The archive therefore needs one more honesty layer:
**import-grade transfer is not yet assimilation-grade native credit.**

## What assimilation-grade domestication would have to cash out

### 1. Native-support disclosure

The archive should not treat an imported fragment as domesticated until it says how the recipient lane or shared spine now supports it.
At minimum, it should ask:
- whether the recipient re-derives the fragment from its own commitments or only calls it as external machinery,
- whether the fragment is now constrained by the recipient's native invariants,
- whether the fragment's explanatory role survives without appeal to donor-lane prestige,
- and whether the recipient can state the fragment in its own canonical language rather than only in donor notation.

Import without native support is still useful.
It is just not yet domestication.

### 2. Dependency-ledger disclosure

A fragment should not become native property while its foreign dependencies remain invisible.
At minimum, the archive should ask:
- which donor assumptions, approximations, or benchmark choices remain load-bearing,
- whether the recipient still depends on donor-side ontology, boundary data, or calibration conventions,
- which parts of the imported fragment would fail if the donor lane weakened further,
- and whether the archive can say exactly what remains borrowed rather than merely “inspired by” the donor.

A tracked dependency can still be import-grade successful.
But invisible dependency is assimilation fraud.

### 3. Host-robustness disclosure

The archive should not let one recipient lane monopolize a fragment too early.
At minimum, it should ask:
- whether multiple rival lanes can host the same fragment with comparable success,
- whether the fragment is now better scored as shared infrastructure than as proprietary recipient credit,
- whether the recipient adds any distinctive explanatory gain beyond merely being one admissible host,
- and whether the fragment's portability weakens rather than strengthens the case for recipient-native ownership.

If several lanes can host the same fragment equally well, that usually points toward common infrastructure rather than lane-native achievement.

### 4. Withdrawal and failure-isolation disclosure

The archive should not treat an import as domesticated until it knows what happens if donor support is withdrawn.
At minimum, it should ask:
- whether the fragment would still survive if the donor lane lost more global prestige,
- whether the recipient can preserve the fragment when donor-specific scaffolding is stripped away,
- whether downstream claims in the recipient lane break if the imported module is removed,
- and whether the fragment's success is resilient or merely loaned.

Domestication should survive a bounded donor-withdrawal thought experiment.

### 5. Spine-admission discipline

The shared spine should be stricter still.
A fragment deserves spine-level assimilation only when:
- it has been re-supported in a way that does not depend on one donor lane's prestige alone,
- or more than one serious lane can recover it under explicit correspondence conditions,
- or the fragment is honestly recoded as neutral shared infrastructure rather than as any lane's native triumph.

Shared-spine admission is not just a stronger import.
It is a claim about what the archive now treats as common capital.

### 6. Assimilation-grade domestication

An imported fragment earns assimilation-grade domestication only when:
- native support is explicit enough that the recipient or spine can state why the fragment now belongs there,
- a dependency ledger names what remains borrowed and what no longer does,
- host robustness is checked so common infrastructure is not mistaken for proprietary recipient credit,
- withdrawal / failure-isolation checks show the fragment is not merely surviving on donor reputation,
- and explanatory credit is rerouted honestly: recipient-native, shared infrastructure, or spine-level common capital.

A fragment may deserve import while still failing assimilation.
That is not a problem; it is border honesty.

## Common failure modes

1. **Import-to-native laundering** — a recipient lane narrates borrowed leverage as if it had generated it internally.
2. **Dependency erasure** — donor assumptions remain load-bearing but disappear from the story once the fragment crosses lanes.
3. **Shared-infrastructure capture** — a fragment several lanes can host gets narrated as one lane's proprietary achievement.
4. **Spine over-compression** — the archive treats a transported fragment as common canon before it has checked whether it is actually neutral shared capital.
5. **Prestige relay** — donor-lane authority quietly persists through the imported fragment even when the donor lane itself remains demoted.

## Compact current readout

| Assimilation question | What the archive should ask | Failure mode if skipped |
| --- | --- | --- |
| **Native support** | Can the recipient or spine now state and support the fragment in its own language? | borrowed machinery retold as native success |
| **Dependency ledger** | Which donor commitments still remain load-bearing after import? | foreign debt hidden inside new ownership language |
| **Host robustness** | Could multiple rival lanes host the same fragment equally well? | shared infrastructure captured as proprietary credit |
| **Failure isolation** | Does the fragment survive bounded donor withdrawal? | domestication claimed on reputation loans |
| **Spine admission** | Is this really common capital rather than one lane's imported asset? | premature unification rhetoric |

## Immediate archive rules

1. **Do not convert import-grade transfer directly into recipient-native or spine-native credit.**
2. **Require native-support and dependency-ledger disclosure before imported fragments affect recipient ranking, spine compression, or canon language.**
3. **If multiple serious lanes can host the same fragment comparably, route it first to shared infrastructure rather than proprietary recipient credit.**
4. **Keep donor provenance visible until bounded withdrawal checks show the fragment no longer survives only on donor reputation.**
5. **Keep this gate subordinate to the salvage-versus-import gate and upstream of any claim that a transferred fragment now counts as recipient-native achievement, shared-spine capital, or evidence of deep convergence.**

## Net result

The archive now has a smaller and more honest sentence available:

> a completion bid may import a fragment cleanly enough for reuse while still failing assimilation-grade domestication until native support, dependency ledger, host robustness, withdrawal resilience, and spine-admission debt are faced honestly.

That blocks one more route by which portable fragments can be mistaken for native unity or recipient-owned explanatory closure without widening the archive.
