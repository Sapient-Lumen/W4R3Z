# Frame transport and public-record equivalence

## Purpose

Frame dependence is not only a warning label. A candidate that uses observer-relative, relational, or quantum-reference-frame records needs an explicit transport law saying when two frame-relative descriptions count as the same public fact.

## Anchors

`REF-0120` anchors the need for operationally defined reference frames, relational observables, and explicit relational reference-frame transformations in generally covariant settings. `REF-0197` anchors operational quantum reference-frame transformations and operational equivalence. Existing archive anchors such as `REF-0119`, `REF-0182`, and `REF-0187` keep the brake sharp: same-looking frame stories can still fail counterpart identification, commutation, or public-portability conditions.

## Equivalence classes

| Claim | Required transport result |
|---|---|
| same event | counterpart convention or relational transformation preserves event identity under the claimed target quotient |
| same measurement | readout effects and public-access mode are operationally equivalent |
| same geometry | geometric observables commute or are jointly comparable in the relevant frame domain, or the noncommutation is carried as a cap |
| same record | persistence, rereadability, custody, and challenge route survive the frame change |
| same candidate state | inverse map remains stable after frame transport |

## Promotion consequence

One frame's sharp record is access credit. Two frames' translated descriptions are portability credit only if the transformation rule and equivalence test are declared. A public reference standard requires more: stable custody, reproducible challenge, and no hidden frame-owner asymmetry.

## Speculative pressure

The archive may need to treat publicness as an equivalence class of frame-relative records rather than as a single observer-independent object. That move is admissible only if the equivalence relation is operational and challengeable.
