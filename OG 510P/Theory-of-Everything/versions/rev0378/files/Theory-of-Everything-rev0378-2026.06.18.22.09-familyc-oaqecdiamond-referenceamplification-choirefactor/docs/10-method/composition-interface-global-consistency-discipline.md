# Composition, interface, and global-consistency discipline

## Purpose

This surface blocks a common authority leak: several route-local successes are placed next to one another and then described as a unified, modular, compositional, or globally consistent theory.

The archive now treats composition as a separate denominator. A route must declare the local components, the composition law, the interface objects, the overlap/descent conditions, and the global obstruction tests before local support can travel into global-language credit.

## Rule

```text
local success
+ matching vocabulary
+ adjacent sectors
+ a gluing diagram
+ package consistency
≠ unified candidate
≠ local-to-global closure
≠ all-sector recovery
≠ ToE support
```

The route must instead pay three debts:

1. `COMPOSITION-LAW-LEDGER.json` declares the composition rule and associativity/functoriality or factorization check.
2. `INTERFACE-COMPATIBILITY-LEDGER.json` declares overlap, boundary, seam, threshold, shared-variable, dictionary, detector/source, or public-record compatibility.
3. `GLOBAL-CONSISTENCY-LEDGER.json` declares the local-to-global target, obstruction search, and global integrability test.

## Non-promotion rule

Composition rows can cap, freeze, demote, or roll back support. They cannot promote a route beyond the candidate-identifiability state machine, public-record custody, observed-sector recovery, gauge/observable quotient, regularization/matching, or residual-cap limits.

## Forbidden moves

- Treating a list of locally successful sectors as a global theory.
- Treating factorization, tensor-product, or cluster language as global consistency without an interface test.
- Treating a cospan, gluing diagram, or descent metaphor as an actual route-level composition law.
- Treating package metadata, generated summaries, or clean manifests as scientific local-to-global consistency.
- Treating modular compatibility as candidate-native identity.
