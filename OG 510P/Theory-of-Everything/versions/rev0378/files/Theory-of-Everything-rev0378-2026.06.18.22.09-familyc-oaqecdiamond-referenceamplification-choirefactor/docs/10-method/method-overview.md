# Method overview

This archive treats theory-of-everything research as a problem of **disciplined compression under cross-scale pressure**.

The job is not to collect every idea. The job is to preserve the smallest set of distinctions that keeps the live scientific problem visible.

## Method commitments

1. **Baseline before novelty.** Any candidate must answer to established low-energy success.
2. **Invariants before metaphors.** Track what must be recovered before debating what the world “really is.”
3. **Bridge claims before worldview claims.** A bridge claim says how one successful regime connects to another.
4. **Quarantine before inflation.** Keep bold ideas live without laundering them into canon.
5. **Compression with replayability.** Reduce text while preserving the ability to reconstruct the next good move.
6. **State machines over docket sprawl.** When a control stack grows, compress its semantics into one state machine and leave older dockets as worksheets.
7. **Negative controls before closure.** Positive route success should be tested against decoys that mimic the same surface pattern but lack the target property.
8. **Decision outcomes before route updates.** Forecasts, protocols, records, benchmarks, and null results must state what route field they change before posture changes.
9. **Carriers before public-record claims.** Public-record language must name a carrier, acquisition protocol, replay/challenge path, and claim binding before it can affect authority.
10. **Defeaters before repromotion.** Once support is attacked, rollback and repair must follow executable dependency edges rather than summary-level optimism.
11. **Severity before positive-evidence spending.** A positive result must say which alternatives or negative controls would probably not have passed the same test.
12. **Evidence units before aggregation.** Multiple artifacts count as independent support only when evidence-unit, independence-assumption, and credit-allocation rows permit aggregation.
13. **Contrast classes before update language.** Route support must name the alternatives, likelihood/update object, prior-stress test, and maximum route effect before it can be described as confirmation, evidence, or model-selection pressure.
