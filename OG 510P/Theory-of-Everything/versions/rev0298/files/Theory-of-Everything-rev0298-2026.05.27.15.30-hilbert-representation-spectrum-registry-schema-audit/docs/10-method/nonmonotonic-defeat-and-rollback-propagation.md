# Nonmonotonic defeat and rollback propagation

Purpose: make authority loss as explicit as authority gain.

The route stack now distinguishes four things that previous prose could blur:

1. **Support** — a carrier, protocol, proof, benchmark, empirical delta, or route row supplies bounded credit.
2. **Attack** — a defeater undercuts or rebuts that support, or collapses the target quotient the support needed.
3. **Rollback** — an activated defeater changes which downstream route, claim, carrier, protocol, or summary language remains licensed.
4. **Repair** — a later correction restores only the support it actually demonstrates; it does not silently restore every prior sentence that once depended on the broken support.

This is a nonmonotonic rule: new information can make a previously acceptable route sentence no longer acceptable without making the original public record disappear. A catalog may remain public while the model-class inference drawn from it is rolled back. A theorem may remain true in a narrower regime while the earlier broad route use is withdrawn. A successful benchmark may remain a benchmark success while losing candidate-native inverse credit.

## Defeater classes

`EPISTEMIC-DEFEATER-LEDGER.json` separates source-integrity loss, carrier custody breaks, acquisition replay failure, negative-control survival, quotient collapse, observed-sector conflict, lab-mediator confounding, proof gaps, benchmark surrogate failure, survey/model misspecification, frame-transport failure, gravitational subsystem obstruction, forecast realization failure, and regulator/truncation portability failure.

The separation matters because the same public result can survive one kind of attack while losing another kind of authority. A DESI-like likelihood can remain a public carrier while losing a dark-energy route update. A GIE-like result can remain a lab record while losing mediator-attribution credit. A holographic decoder can remain useful inside a code space while losing candidate-native public-bridge credit.

## Propagation rule

Rollback follows `AUTHORITY-DEPENDENCY-GRAPH.json`, not rhetorical proximity. If a failed protocol supports a route and a claim binding supports a public summary through that route, the summary must be recomputed even if the markdown sentence that mentioned the claim did not directly mention the protocol.

The default rule is most-restrictive survival:

```text
surviving authority = minimum(route state, carrier max, protocol max, severity max, rollback floor, residual cap)
```

This is not arithmetic averaging. A strong public carrier cannot compensate for a failed quotient. A severe test cannot compensate for a broken acquisition protocol. A repaired carrier cannot compensate for a still-surviving negative control.

## Repair rule

A repair must name exactly what it repairs:

- source integrity,
- carrier custody,
- acquisition replay,
- negative-control separation,
- quotient map,
- observed-sector crosswalk,
- nuisance/model class,
- proof scope,
- benchmark target,
- frame transport,
- subsystem witness class,
- forecast realization,
- regulator/truncation portability.

A repair reopens review. It is not restoration by default.
