# Negative-control discipline

## Purpose

A candidate route is not strong merely because it passes a positive pattern. It should also fail against hostile decoys that mimic the same surface success while lacking the claimed target property.

This surface turns negative controls into a required companion to candidate-native identifiability promotion.

## Control schema

```yaml
control_id:
route_id:
positive_pattern_mimicked:
missing_target_property:
borrowed_support_or_surrogate:
expected_failure_mode:
public_record_similarity:
candidate_native_difference:
required_discriminator:
state_machine_effect:
```

A control that only says "try a different model" is too weak. The control should be close enough to pass the same easy test and fail only at the distinction the archive claims to care about.

## Default control classes

| Control class | Mimics | Should fail because |
|---|---|---|
| Dual-description decoy | empirical equivalence or same boundary data | candidate-native target quotient is not fixed |
| Reconstruction decoy | impressive bulk / geometry reconstruction | inverse map is code-subspace-, cutoff-, state-, or prior-dependent |
| Publicness decoy | publication, hosted code, dashboard, or boundary access | public bridge is borrowed from outside the candidate |
| Lab-discriminator decoy | quantum-versus-classical or mediator-class signal | full ToE candidate remains underdetermined |
| Frame decoy | frame-relative agreement | no same-fact transport or public reference-standard rule exists |
| Package-selection decoy | string compactification, vacuum choice, or bootstrap consistency | target is selected post hoc or inside a special package |
| Simulator decoy | faithful execution of an assumed equation | simulator inherits the target equation rather than identifying it |

## Required placement

Negative controls should be cited in three places when a route is being strengthened:

1. the route ledger row or candidate-family stack;
2. the promotion gate / readiness matrix entry;
3. the worked-example battery if the control class is reusable.

If a proposed promotion has no negative control, its promotion ceiling is `S2` unless the reason for exemption is explicitly stated and replayable.

## No-promotion clause

This discipline is stricter than the current archive. It does not demote existing route rows by itself, but future `S4` or `S5` spending should be blocked until the relevant negative-control class is named and survived.
