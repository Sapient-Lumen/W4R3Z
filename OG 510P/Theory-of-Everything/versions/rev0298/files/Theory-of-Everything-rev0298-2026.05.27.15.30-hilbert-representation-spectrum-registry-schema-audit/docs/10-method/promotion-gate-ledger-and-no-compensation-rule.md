# Promotion-gate ledger and no-compensation rule

## Purpose

`PROMOTION-GATE-LEDGER.json` is the executable companion to the candidate-identifiability state machine. It prevents a route from being promoted because several impressive partial fields are averaged together.

The rule is simple: **a route is capped by its weakest decisive non-optional field.** Target, record, equivalence, acquisition, inverse, stability, abstention, public bridge, observed-sector obligations, and negative controls are not exchangeable currencies.

## Gate chain

- `PG-S1-TO-S2` turns a clue into a structured route only when the denominator is real.
- `PG-S2-TO-S3` turns a structured route into bounded partial-identification or discriminator credit only when quotient, residual cap, and hostile decoys are explicit.
- `PG-S3-TO-S4` requires replayable candidate-native operational closure in the claimed regime plus observed-sector obligation accounting.
- `PG-S4-TO-S5` requires full observed-sector recovery, cross-family countermodel collapse, public witness portability, and target-quotient closure.
- `PG-ANY-TO-Q` and `PG-ANY-TO-AR` route contaminated re-entry or failed authority transitions into quarantine / rollback instead of summary-driven revival.

No current route row clears `PG-S3-TO-S4` or `PG-S4-TO-S5`.

## No-compensation table

| Missing decisive field | Cannot be compensated by |
|---|---|
| target quotient | more public data, prettier reconstructions, or stronger catalog fits |
| record object | formal proof, framework prestige, or internal consistency |
| equivalence relation | inverse-map sharpness |
| acquisition map | formal observability |
| inverse/stability | one successful reconstruction or benchmark |
| abstention/no-verdict rule | calibrated confidence or selected examples |
| public bridge | publication, release slug, or private native confidence |
| observed-sector recovery | consistency in one sector or one successful lab discriminator |
| negative controls | prose caveats or friendly examples |

## Use

A future route update should name the gate it is trying to cross. If it cannot name the gate, the update is a field-local delta, not a route-state update.
