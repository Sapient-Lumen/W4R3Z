# Operational record language

## Purpose

This archive needs a record language that can be stated before choosing a final ontology. Operational probabilistic theories provide a useful neutral grammar: systems, states, transformations, tests, effects, processes, and public comparison rules can be described without first deciding whether the underlying candidate is QFT, GR, string / M-theory, causal set dynamics, amplitudes, or something else.

This is a constitution surface, not a promotion claim.

## Minimal objects

| Object | Archive meaning |
|---|---|
| System | the bounded target of a preparation / transformation / readout claim |
| State | operational equivalence class of preparations under the allowed tests |
| Transformation | candidate-native or public operation that maps states to states or records |
| Effect / test | declared readout event with a stability and publicness condition |
| Process | composed preparation, transformation, and readout history |
| Record | persistent, rereadable, causally generated trace inside a public or candidate-native process |
| Public record | record with declared access mode, custody, replay condition, equivalence rule, and challenge route |
| Candidate-native record | record whose production and equivalence are defined in the candidate's own language rather than borrowed entirely from an external witness substrate |

## Record denominator

Every public-record claim should state:

```yaml
record_id:
system_or_target:
preparation_or_source:
transformation_history:
readout_effects:
persistence_condition:
rereadability_condition:
public_access_mode:
custody_chain:
equivalence_rule:
challenge_route:
candidate_native_components:
borrowed_components:
residual_cap:
```

This denominator is the record-side version of the identifiability route denominator. It is deliberately ontology-light.

## Purification and process caution

Purification-based operational theories show that powerful quantum-like structure can be derived from operational principles such as purification and reversible realization of processes (`REF-0196`). The archive should use that as a neutral grammar, not as a new ToE candidate. Operational elegance is not candidate-native identifiability.

## Public bridge rule

A public bridge is not the same as an ordinary public artifact. A paper, dataset, code release, dashboard, boundary correlator, detector log, or generated bundle becomes a public bridge only when the record denominator identifies what is public, what is candidate-native, what is borrowed, what is equivalent, and how challenges can be replayed.

## Placement

Use this surface when a claim crosses from physics into record language. Use `docs/10-method/candidate-identifiability-state-machine.md` when the same record language is being used to score candidate identifiability.
