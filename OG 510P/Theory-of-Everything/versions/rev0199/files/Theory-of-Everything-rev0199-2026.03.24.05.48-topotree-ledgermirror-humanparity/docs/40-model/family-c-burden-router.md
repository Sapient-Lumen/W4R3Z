## Shared rule

Family C should be scored in order:
- first by preserving its real bounded geometric / reconstruction surplus,
- then by keeping the witness-ceiling question explicit rather than quietly promoting `WB-2` to later closure,
- then by routing remaining identifiability debt through the ordered post-partial-identification screen chain,
- and only then by asking what the current strongest cross-family readout actually earns.

Restricted inverse progress is real progress, not candidate-native identifiability closure.
A tighter inverse interface is not yet a native same/different rule.
A witness-ceiling check is not the same thing as a cross-family closure verdict.

Stable, restart, and program surfaces should therefore name this router when they only need the established family-C control route.
Do not replay the witness-ceiling gate, identifiability stack, and cross-family readout separately unless the revision is actually changing one of those subordinate surfaces.
If the issue is integrated broad ToE credit rather than family-C pressure specifically, route through `docs/40-model/broad-toe-credit-router.md` instead.
