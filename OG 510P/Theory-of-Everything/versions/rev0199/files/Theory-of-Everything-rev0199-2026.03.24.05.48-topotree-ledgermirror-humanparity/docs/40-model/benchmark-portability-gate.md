# Benchmark-portability gate

Purpose: split the **parameter-fixation** layer inside `docs/40-model/parameter-fixation-gate.md` one step further.
A completion bid should not earn the same observed-parameter credit merely because it can exhibit **one successful benchmark construction** and because it can show **portable structural fixation** across an admissible neighborhood of its own package space.
Shared family scaffolding and ordered routing live in `docs/40-model/completion-bid-comparison-gate-family-frame.md` and `docs/40-model/completion-bid-comparison-stack.md`; this file keeps only the pair-specific split between benchmark fixation and portable fixation.

## Compression verdict

The archive should now score the strongest layer of observed-parameter cash-out in **three distinct sublayers**:

1. **benchmark fixation** — one explicit construction, compactification, truncation, or worked point reproduces some observed pattern with nontrivial structure;
2. **portable fixation** — the same success survives a bounded neighborhood, or is carried by a lane-level mechanism rather than one isolated corner;
3. **rarity / search disclosure** — if the success still lives in a narrow corner, the lane should say so explicitly: how much search, tuning, conditioning, vacuum choice, truncation choice, or phenomenological filtering is still doing the work?

A lane may earn real credit on layer 1 while still being weak on layers 2 and 3.
That is still progress.
It is just not portable closure.

## Why this gate exists

`docs/40-model/parameter-fixation-gate.md` already blocked one inflation move:
**architecture recovery or texture language pretending to be observed-parameter closure.**

A further inflation move remained too easy:
**one successful benchmark point pretending to be lane-level explanation.**

That confusion appears whenever a completion bid is praised because it:
- can display one realistic compactification or benchmark,
- finds one parameter point after a large search,
- shows one truncation with attractive low-energy relations,
- or reaches one rare but striking match to observed masses and mixings,

and that local success is then narrated as though the lane had explained the observed pattern in a structurally portable way.

This gate keeps those credits separate.

## The three-step portability test

### 1. Benchmark success

A lane earns **benchmark-fixation** credit when it can show one worked construction or bounded setup that really reaches part of the observed parameter pattern with nontrivial internal structure.
Examples include:
- a compactification with realistic gauge / flavor data,
- a modular-flavor benchmark with low effective fit freedom,
- a truncation with sharp critical-surface restrictions,
- or another explicit worked point that does more than restate the target.

This is stronger than merely naming a texture.
But it is not yet portable closure.

### 2. Neighborhood robustness

A lane earns **portable-fixation** credit only when the success is not obviously confined to one fragile corner.
At minimum, the archive should ask whether:
- nearby vacua, compactifications, or stabilization choices preserve the gain,
- nearby truncations / regulator choices preserve the gain,
- the explanatory mechanism survives modest model-class variation,
- and the result looks lane-level rather than point-level.

One worked point may still be valuable.
But a lane should get more credit for a mechanism that transports than for a rare point that merely exists.

### 3. Rarity and search disclosure

If the lane does **not** yet show portability, it should say what is still carrying the burden.
Typical carriers include:
- a massive search over candidate vacua or constructions,
- a narrow viable corner of compactification or stabilization space,
- truncation- or scheme-selected windows,
- phenomenological filters imposed after the fact,
- or an unknown measure over the surviving candidate set.

The archive should not punish honest disclosure.
It should punish silent corner-hunting.
An isolated success may still earn benchmark credit, but it is different from structural explanation. Use `docs/40-model/fit-vs-prediction-gate.md` when the question becomes whether the fitted observables were also the ones consumed during benchmark selection.

## Common failure modes

1. **Benchmark inflation** — one realistic worked point is narrated as if the lane had explained the observed pattern generically.
2. **Search opacity** — an enormous search, conditioning pipeline, or post-selection filter is hidden behind the final benchmark.
3. **Neighborhood inflation** — small deformations, nearby vacua, or nearby truncations have not been tested, but the result is narrated as stable.
4. **Rarity smuggling** — the success lives in a narrow corner, yet the rarity or measure question is left implicit.

## Immediate archive rules

1. **Do not let one benchmark fit count as lane-level closure.**
2. **Do not let large search effort disappear behind one surviving example.**
3. **Do not let portability be assumed unless nearby package or truncation changes have been checked explicitly.**
4. **Require rarity / search disclosure whenever success still lives in a narrow corner.**
5. **Keep this gate subordinate to the parameter-fixation gate and the main completion-bid sieve.**
   This surface sharpens only the top layer of observed-parameter cash-out; it does not replace the separate debts on package disclosure, observables, witness closure, or cosmological burden.

## Net result

The archive now has a smaller and more honest sentence available:

> a completion bid may earn benchmark-level observed-parameter credit and still be weak on portable structural fixation.

That sentence blocks another common prestige inflation move without widening the archive.
