# Current-family readout router

Purpose: canonical broad router for the archive's strongest live-family readouts. Use this when stable, restart, program, witness-side, or broad-credit surfaces need the bounded family-B control lane and the strongest current family-C readout without separately naming `family-b-burden-router.md` and `family-c-burden-router.md`. Use `docs/40-model/cross-family-pressure-router.md` when the issue is the full bridge-family snapshot across A–D rather than the current leading readouts, and use `docs/40-model/broad-toe-credit-router.md` when the issue is integrated broad ToE credit rather than live-family burden specifically.

## Shared rule

Current-family readout should be scored in order:
- first by preserving family B as a bounded thermodynamic clue under explicit trace-discipline and no-climb pressure,
- then by preserving family C as the strongest current partial inverse-interface lane under explicit witness-ceiling and identifiability pressure,
- and only then by asking what the current live-family readout actually changes for broader witness or ToE scoring.

A bounded family-B clue is not yet a promoted bridge winner.
A strongest current family-C partial case is not yet candidate-native identifiability closure.
A strongest current live-family readout is not yet integrated broad ToE credit.

Stable, restart, program, witness-side, and broad-credit surfaces should therefore name this router when they only need the archive's current live-family burden architecture.
Do not replay `family-b-burden-router.md` and `family-c-burden-router.md` as separate broad-surface obligations unless the revision is actually changing one of those subordinate family routes.
If the issue is only one live family rather than the current-family readout architecture, deepen only that subordinate family router instead.
