# Fit-versus-prediction gate

Purpose: split the **claimed observed-parameter success** layer one step further.
A completion bid should not earn the same observed-parameter credit merely because it can **fit or accommodate the observables already used to tune, select, or condition the construction** and because it leaves **additional risky relations, exclusions, or forecast windows genuinely exposed** after that accommodation.
Shared family scaffolding and ordered routing live in `docs/40-model/completion-bid-comparison-gate-family-frame.md` and `docs/40-model/completion-bid-comparison-stack.md`; this file keeps only the pair-specific split between accommodated fit and exposed risky surplus.

## Compression verdict

The archive should now score claimed observed-parameter success in **three distinct test-sequencing layers**:

1. **accommodated fit** — the lane matches observables that were directly or effectively consumed in benchmark construction, parameter tuning, truncation choice, vacuum selection, or phenomenological filtering;
2. **exposed surplus** — after that fit, the lane still leaves additional nontrivial relations, exclusions, or forecast windows genuinely exposed rather than reusing the same target data as both input and output;
3. **input / test disclosure** — the lane states plainly which observables were used as inputs, soft priors, filters, or post-selection criteria, and which observables remain real tests.

A lane may earn real credit on layer 1 while still being weak on layers 2 and 3.
That is still progress.
It is just not the same thing as risky predictive closure.

## Why this gate exists

`docs/40-model/parameter-fixation-gate.md` already blocked one inflation move:
**architecture or texture language pretending to be observed-parameter closure.**

`docs/40-model/benchmark-portability-gate.md` blocked a second:
**one successful benchmark point pretending to be lane-level explanation.**

A further inflation move remained too easy:
**the same data serving as both training target and advertised prediction.**

That confusion appears whenever a completion bid is praised because it:
- selects a benchmark using already measured masses, mixings, or couplings,
- scans a large construction space with phenomenological cuts already tied to the target pattern,
- tunes a truncation or compactification against known low-energy data,
- or narrates a successful global fit as if the fitted observables themselves were still risky predictions,

and that accommodated success is then retold as though the lane had left substantial new low-energy structure exposed.

This gate keeps those credits separate.

## The three-step fit / prediction test

### 1. Input accounting

A lane earns **accommodated-fit** credit when it reproduces real observed quantities, but the archive should first ask what was already consumed to get there.
Relevant inputs may include:
- direct parameter fitting,
- vacuum / compactification selection using the target pattern,
- truncation or regulator choices made to retain the target behavior,
- phenomenological filters imposed after scanning,
- or soft priors that already encode part of the desired low-energy structure.

Using data is not illegitimate.
Hiding that use is.

### 2. Exposed surplus

A lane earns **risky predictive-surplus** credit only when something materially interesting remains exposed after the fit.
At minimum, the archive should ask whether the lane leaves behind any of:
- nontrivial relations among observables not already used as inputs,
- excluded windows or sign restrictions,
- cross-sector transport from one fitted block to another unfitted block,
- or future-sensitive forecast windows that could genuinely fail.

A lane should get more credit for exposed surplus than for the accommodated fit alone.
Matching the data you already used is not yet the same as predicting more data. Then use `docs/40-model/prediction-vs-discrimination-gate.md` when the question becomes whether that exposed surplus would actually separate the lane from nearby rivals.

### 3. Test-path disclosure

If the lane does **not** yet leave substantial surplus exposed, it should say so explicitly.
The archive should ask for:
- which observables were fit,
- which were only checked afterward,
- which filters were hard requirements versus soft preferences,
- and which advertised consequences remain genuinely vulnerable to future failure.

The archive should not punish honest disclosure.
It should punish input laundering.

## Common failure modes

1. **Input laundering** — measured targets used during model selection are later advertised as predictions.
2. **Postdiction inflation** — an accommodated benchmark is narrated as if it had risked failure on the same observables.
3. **Filter opacity** — phenomenological cuts and scan criteria are hidden behind the final surviving point.
4. **Pseudo-surplus** — the remaining “predictions” are just reformulations of already used inputs.

## Immediate archive rules

1. **Do not let fitted observables be re-advertised as predictions without input disclosure.**
2. **Do not let a global fit or benchmark scan count as risky surplus by itself.**
3. **Require explicit separation between used inputs, post-selection filters, checked observables, and genuinely exposed tests.**
4. **Give extra credit only for relations, exclusions, or forecasts that remain vulnerable after the fitting / selection path is named honestly.**
5. **Keep this gate subordinate to the parameter-fixation and benchmark-portability gates.**
   This surface sharpens test sequencing inside claimed observed-parameter success; it does not replace the separate debts on package disclosure, observables, witness closure, or cosmological burden.

## Net result

The archive now has a smaller and more honest sentence available:

> a completion bid may achieve an impressive accommodated fit and still be weak on genuinely exposed risky predictions.

That sentence blocks another common prestige inflation move without widening the archive.
