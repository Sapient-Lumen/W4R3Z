# Archive policy

## Purpose

Keep the archive small enough to survive, structured enough to re-enter, and sharp enough to make real progress on unification.

## Rules

1. Prefer **citations, ids, and compact summaries** over long quotation.
2. Keep **no PDFs or other bulky source artifacts** in release bundles.
3. Preserve only what changes the continuation state: invariants, claims, open questions, bridge tests, and load-bearing references.
4. When a concept appears in more than one document, pick one canonical home and link to it.
5. Separate `accepted`, `inferred`, `speculative`, and `adversarial-countermodel` material.
6. Distinguish **baseline constraints** from **candidate explanations**.
7. Distinguish **local low-energy success** from **global fundamental explanation**.
8. New documents must be wired into `docs/README.md`, `ARCHIVE_INDEX.md`, and at least one registry or workstream.
9. If a revision adds citations, record the load-bearing reason each source matters.
10. If a revision adds a bold idea, either attach a promotion basis or place it in quarantine.
11. If a document can be merged without loss of operative state, merge it.
12. Keep every release inspectable in one sitting.

## Salience budget

A salient archive is not the one that stores the most literature. It is the one that stores the smallest set of distinctions that still lets the next session:
- recover the real problem,
- see what is already constrained,
- see what is still live,
- and choose the next best discriminating move.

## Release discipline

Each release should preserve:
- a stable bundle name,
- a revision receipt,
- a context pack,
- a docs index,
- a machine-readable status surface,
- and a bounded next-task queue.
