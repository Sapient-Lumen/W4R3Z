## Preferred revision pattern

1. Reopen the current state.
2. Decide which move class applies.
3. Add or refine one canonical surface.
4. Update the affected registry.
5. Add a bibliography entry only if it materially changed the archive.
6. Rebuild index, run lint, emit revision receipt, package.

## Hard constraints

- No retained PDFs in release bundles.
- No giant quotes.
- No duplicate conceptual homes.
- No promotion of a claim without explicit basis.
- No pretending a framework label explains anything by itself.

## Research posture

When uncertain, prefer:
- sharper invariants,
- clearer bridge tests,
- smaller summaries,
- and more honest abstention.
