# Lessons from old cubes

The uploaded cubes were read as structural prior art, not as content sources.

## Parables

Parables shows the value of a simple accretive surface: one main corpus file, one scratchpad, one already-searched log. It preserves taste, rejected candidates, search memory, and narrative feel. DeathVocab should learn from this by keeping rejected/held source notes and not letting JSON erase texture.

## TriKEM

TriKEM is strong at release posture: explicit non-claims, evidence debts, public-surface boundaries, fail-closed status, and guard artifacts. DeathVocab needs the same discipline because a sensitive observation can easily masquerade as medical advice, universal truth, or permission to publish.

## Theory-of-Everything

Theory-of-Everything emphasizes route state, defeaters, rollback, dependency, and severity. DeathVocab needs this because later evidence, consent withdrawal, source-chain pollution, cultural restriction, or clinical harm can invalidate not only one record but every summary and search alias derived from it.

## DelayBasin

DelayBasin is strong at long-run continuity: receipts, surface status, re-entry packs, transfer ledgers, validation maps, and open-question queues. DeathVocab should use compact re-entry surfaces so a future turn can resume without rereading thousands of records.

## DeathVocab-specific synthesis

The archive should combine:

- Parables' narrative texture and search-memory humility;
- TriKEM's nonclaim/evidence-debt posture;
- Theory's defeater and rollback discipline;
- DelayBasin's re-entry and revision continuity.

The result should be a corpus that is intimate but not loose, structured but not dead, and safe without becoming sterile.
