# Hot substrate watch protocol

## Purpose
Use this protocol when a revision is mainly about **fast-moving imported truths**: evolving upstream surfaces, service-side operator truth, machine-readable export caveats, or live stewardship/institutional-readiness signals.

The point is to capture drift honestly without collapsing it into packets, charters, or broad ranking changes.

Read with:
- `design/epic-contribution-hot-substrate-watchcards-2026Q1.md`
- `design/epic-contribution-portfolio-control-loop-2026Q1.md`
- `meta/PORTFOLIO_CONTROL_LOOP_PROTOCOL.md`
- current `evidence/hot-substrate-*.md` files

## Required moves
1. Re-open the nearest canon before inventing a new hot-watch story.
2. Decide explicitly whether the revision is really a hot-substrate move.
3. Emit or refresh a watchcard with lane, truths, non-claims, triggers, affected assets, and unchanged posture.
4. Prefer primary sources that actually carry moving truth.
5. Keep imported truth bounded.
6. Separate service truth, tool truth, and policy truth.
7. Update packets, charters, or canon only if the watchcard clearly justifies it.
8. Refresh continuity rails in the same revision.

## Default interpretation rules
- do not let hot drift impersonate a canon rewrite;
- do not let one service or prototype surface become a fake universal contract;
- do not let a watchcard replace packets, charters, or broad design notes;
- do not let assistant synthesis erase version/format caveats.

## Failure modes
### Failure mode 1: memo-shaped drift
A giant “latest update” summary with no bounded watchcard, no reissue triggers, and no explicit non-claims.

### Failure mode 2: packet inflation
Using hot substrate movement as an excuse to change verdict posture automatically.

### Failure mode 3: service truth overreach
Treating a registry or docs-host feature as if it solved policy, governance, or universal compatibility semantics.

### Failure mode 4: caveat amnesia
Quoting JSON or structured-output surfaces without preserving format-version, opacity, or instability warnings.

### Failure mode 5: canon by repetition
Letting a repeatedly paraphrased hot source become “obvious canon” without naming the drift lane that supported it.
