# Installed incident signatures

VHK now keeps one compact incident-signature verdict on the installed lane.
This sits beside session readiness, runtime health, runtime-health drift,
startup handoff, and startup-handoff drift.

## Why this matters

Linux support work often starts with the question "what just happened?" A lane
may be healthy now but still have a recent start-limit incident. Another lane
may be inactive because the session was not ready, not because the service
failed.

The incident-signature layer keeps those cases separate.

## Current verdict families

- `healthy_no_recent_incident`
- `stopped_no_recent_incident`
- `clean_session_skip`
- `condition_skip`
- `start_limit_churn`
- `service_failure`
- `missing_unit`
- `probe_error`
- `no_owned_service`
- `journal_unavailable`
- `unavailable`
