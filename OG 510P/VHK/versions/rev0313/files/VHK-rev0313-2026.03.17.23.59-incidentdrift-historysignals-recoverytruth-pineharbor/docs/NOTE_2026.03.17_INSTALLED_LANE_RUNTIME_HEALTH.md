# Note — installed-lane runtime health verdicts

Session readiness is necessary, but it is not sufficient.

A real Linux operator still wants to know:

- is the owned lane actually healthy right now?
- is it being skipped cleanly because the session is not ready?
- is it stopped even though the session looks ready?
- is it looping through restarts or hitting a start limit?
- does this lane even own a long-lived unit, or is it mostly launcher/userland?

This revision teaches VHK to answer those questions directly from the installed
status bridge instead of forcing every support interaction into raw unit-state
interpretation or a full dossier capture.
