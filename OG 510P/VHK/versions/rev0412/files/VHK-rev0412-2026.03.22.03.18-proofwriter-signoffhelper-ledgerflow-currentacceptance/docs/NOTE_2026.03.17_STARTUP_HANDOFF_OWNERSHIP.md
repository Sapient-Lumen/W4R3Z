# Note — startup handoff ownership

A Linux-native automation project should not casually install every available
startup hook for the same service lane.

For VHK session-service exports, three related but different truths now stay
visible together:

- activation environment sync
- graphical-session lifetime binding
- startup ownership

That last layer matters because one pack can easily generate both a
`graphical-session.target`-bound user unit and an XDG autostart bridge. Both can
be useful, but they should not silently become co-equal default owners for the
same lane.

This revision keeps the systemd target path primary when VHK already has a
strong first-party session-bound unit lane, and leaves the XDG autostart bridge
as a deliberate fallback for desktops/sessions that still need it.
