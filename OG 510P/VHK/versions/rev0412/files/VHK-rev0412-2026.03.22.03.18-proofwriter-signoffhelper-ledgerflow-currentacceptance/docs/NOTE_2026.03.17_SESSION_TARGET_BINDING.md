# Session target binding

VHK now treats **graphical-session lifetime binding** as a first-class Linux
service concern.

The service handoff already knew how to ship user units, environment exports,
and activation-sync helpers. But those artifacts still left a practical Linux
question too fuzzy: is the VHK-owned watcher/runtime lane supposed to survive as
an ordinary user daemon, or stop when the graphical session ends?

The generated service pack now therefore includes:

- a reviewable `session_target_policy` in `VHK_SERVICE_COMPOSE_PLAN.json`
- a human guide in `VHK_SESSION_TARGETS.md`
- `verify_session_targets.sh`
- explicit `BindsTo=graphical-session.target` wiring in the generated user
  units when the service lane is graphical-session-bound

This keeps session lifetime visible as a separate concern from both authority
ownership and activation-environment sync.
