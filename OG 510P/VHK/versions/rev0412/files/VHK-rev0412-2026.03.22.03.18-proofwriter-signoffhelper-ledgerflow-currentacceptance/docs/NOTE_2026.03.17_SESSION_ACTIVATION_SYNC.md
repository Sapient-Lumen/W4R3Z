# Session activation sync

VHK now treats session activation as a distinct Linux-native concern.

`environment.d` remains the right place for stable exports like `PATH` and VHK-
specific variables, but graphical-session variables often still need to be
bridged into D-Bus and `systemd --user` activation environments at login time.

The generated service handoff now therefore includes:

- a reviewable policy in `VHK_SERVICE_COMPOSE_PLAN.json`
- a human guide in `VHK_SESSION_ACTIVATION.md`
- `sync_session_activation_env.sh`
- an autostart bridge that runs that helper before starting the VHK-owned unit

This keeps startup reality closer to how Linux desktops actually behave without
pretending VHK owns portal consent or privileged helper boundaries.
