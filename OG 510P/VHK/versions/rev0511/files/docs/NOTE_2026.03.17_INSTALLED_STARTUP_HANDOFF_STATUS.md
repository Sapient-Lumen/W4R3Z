# Note — installed startup handoff status

VHK already knew three adjacent truths:

- whether the session looked ready
- whether the owned lane looked healthy
- what the reviewed startup policy was supposed to be

What was still missing was the installed-lane answer to:

> who actually owns startup on this host right now?

That question matters on Linux because user-unit enablement and XDG autostart
presence are not interchangeable. A lane may have:

- one primary user-unit owner
- one XDG autostart fallback owner
- both at once (duplicate-start risk)
- neither (startup drift)

This revision makes that state reviewable from the everyday launcher status and
support surfaces instead of forcing operators into raw `systemctl` and desktop
file archaeology.
