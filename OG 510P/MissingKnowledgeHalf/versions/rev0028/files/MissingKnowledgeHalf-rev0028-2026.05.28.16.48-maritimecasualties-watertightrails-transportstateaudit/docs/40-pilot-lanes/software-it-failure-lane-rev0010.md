# Rev0010 pilot lane: software and IT failures

Rev0010 chooses software because it is a missing-half problem inside the missing-half project. Software failures are common, consequential, and often richly discussed in postmortems, yet the public record is fragmented across regulators, vendors, incident blogs, vulnerability databases, litigation, journalism, and outage dashboards.

The first slice deliberately mixes four kinds of case:

1. Knight Capital — a deployment/stale-code automated trading failure.
2. Northeast Blackout 2003 — a control-room EMS alarm and situational-awareness failure within a larger grid event.
3. Equifax — a known-vulnerability, patch-verification, asset-visibility, and monitoring failure.
4. CrowdStrike — a privileged endpoint-security content update that caused global outage and recovery stress.

The infrastructure records are equally important. CVE, NVD, and CISA KEV make vulnerabilities more visible. They do not make all software failures visible. That gap is itself an object for the cube.

Rev0010 should be read as lane-opening, not lane-completion.
