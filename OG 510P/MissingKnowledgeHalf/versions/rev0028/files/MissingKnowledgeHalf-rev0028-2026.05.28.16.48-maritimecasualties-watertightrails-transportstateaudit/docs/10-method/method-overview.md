# Method overview

## Basic unit

The basic unit is a **record**, not a story. A record is a structured object with sources, status, uncertainty, ethical handling, and links. Stories can be written later from records; records should not be inferred from stories without sources.

## Record lifecycle

1. **Seed mention** — a candidate appears in a seed document, prior queue, conversation, or source search. It is useful memory, not corpus fact.
2. **Candidate** — the archive chooses it as worth sourcing.
3. **Source located** — at least one relevant source exists, but extraction is not complete.
4. **Primary-source backed** — a primary or high-grade source supports the basic record existence.
5. **Extracted** — fields are populated: claim/incident/influence, dates, people, method/system, result, source, status.
6. **Reviewed** — a second pass checks source dependence, status, ethics, and overclaiming.
7. **Synthesized** — record links to claims, practice, patterns, replications, genealogy, or consequences.
8. **Maintained** — later evidence can contest, narrow, revive, supersede, or retire the record.

## Cross-corpus posture

- A failed replication can be a negative result, but it needs replication-specific fields.
- An engineering failure is an empirical disconfirmation in practice, but it needs timeline/causal-chain fields.
- A genealogy record is interpretive, but it can explain why claims persisted, recurred, or were resisted.
- A pattern record is earned only by recurrence across records.

## Archive growth rule

Grow by small ratchets. Each revision should make one future action easier without making current status less honest.
