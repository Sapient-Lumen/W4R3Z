# Flight-deck state and crew-resource legibility

Aviation human-factors records must not collapse into operator blame. The useful grain is state conversion: what the aircraft was doing, what the crew could see or infer, which automation or warning mode was active, which crew member held which observation, whether challenge/communication turned observations into shared state, and what training/procedures made action likely or unlikely.

The cube should distinguish:

- actual aircraft state;
- displayed or interpreted state;
- automation mode and warning mode;
- communication, challenge, and command gradient;
- training/procedure/memory rails;
- fatigue, professionalism, supervision, and oversight;
- survivability and evacuation;
- safety-investigation status versus legal status.

CRM is a rail, not a magic fix. It can be absent, inadequate, present-but-insufficient, or a positive-control resilience surface.
