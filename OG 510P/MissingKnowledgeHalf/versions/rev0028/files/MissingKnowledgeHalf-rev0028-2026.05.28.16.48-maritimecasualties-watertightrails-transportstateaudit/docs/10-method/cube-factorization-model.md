# Cube factorization model

The current record types are containers, not destiny. They are useful because they make records readable, but they are not the deepest ontology of the cube.

## The core mistake to avoid

Do not let every new phenomenon become a new record type. A medical reversal, a failed replication, a software outage, a regulator inquiry, a post-publication correction, a confidential near-miss channel, and a genealogy scene can share factor axes even when their record containers differ.

## Current container types

- `ENG`: engineering, software, system, and accountability failures.
- `NEG`: negative result, hard-endpoint reversal, program audit, or practice-lag case.
- `REP`: replication program or replication-qualified claim.
- `GEN`: genealogy, scene, anti-genealogy, or transmission record.
- `INF`: infrastructure that makes missingness, warning, reporting, correction, or action visible.
- `MET`: meta-research audit of missingness, reporting bias, reversals, or evidence production.
- `PAT`: pattern candidate.
- `SRC`: source record.

## Factor axes

Use factor axes to ask what analytic work a record is doing:

1. object role;
2. evidence surface;
3. status motion;
4. denominator visibility;
5. correction surface;
6. transmission edge;
7. practice status;
8. harm and ethics;
9. pattern maturity;
10. review depth.

These axes make it possible to query across lanes without flattening domains. For example, a NASA accident report, a sham-controlled medical trial, and a Retraction Watch record are very different sources, but all may participate in correction surfaces and status motion.

## Migration principle

Readable case records should remain. But future structured layers should extract first-class claims, edges, status transitions, locators, and practice surfaces from those records.
