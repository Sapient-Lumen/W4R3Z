# Pattern red-team controls

Pattern records are useful only if they do not become loose analogies.

Rev0016 adds `red_team_controls` to every current pattern candidate. The field does not upgrade any pattern. It does the opposite: it makes upgrade harder and more explicit.

## Required control surfaces

A pattern candidate needs:

- supporting records currently in the cube;
- positive controls: additional fitting cases not used in first promotion;
- negative controls: similar-domain cases that should not fit the pattern;
- counterexamples to seek;
- rollback triggers;
- split/merge watch;
- a maturity gate.

## Candidate versus mature pattern

A candidate pattern preserves a possible recurrence. A mature pattern has earned stronger status by surviving controls and counterexamples. Current patterns are candidates only.

No pattern may make frequency claims, universal causal claims, or mature-theory claims merely because it has several support records.

## Why this matters

The cube's premise is recurrence across the missing half of knowledge. Recurrence is powerful but dangerous. Without controls, every interesting story starts to resemble every other interesting story. Red-team controls are how the cube prevents pattern intoxication.
