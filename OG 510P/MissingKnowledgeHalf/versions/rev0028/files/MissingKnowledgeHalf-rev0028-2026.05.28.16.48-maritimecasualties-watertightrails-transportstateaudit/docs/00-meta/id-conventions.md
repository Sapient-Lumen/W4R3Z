# ID conventions

## Revision IDs

Use four-digit revision IDs: `rev0001`, `rev0002`, … `rev9999`, then expand only if necessary.

Package filename pattern:

`MissingKnowledgeHalf-rev####-YYYY.MM.DD.HH.MM-summary-highlight-codename.zip`

## Record IDs

Use prefix `MKH-` plus type family:

- `MKH-NEG-0001` — negative result / file drawer
- `MKH-REP-0001` — failed replication / replication qualification
- `MKH-ENG-0001` — engineering failure / incident / near-miss
- `MKH-GEN-0001` — genealogy / anti-genealogy / scene / influence
- `MKH-SRC-0001` — source record
- `MKH-PAT-0001` — recurring pattern
- `MKH-CLA-0001` — claim record

The candidate queue currently uses provisional IDs in this style. Do not reuse retired IDs.

## Ledger IDs

- `AS-####` assumptions
- `FT-####` followthrough items
- `FP-####` foreign pressure items
- `TL-####` datacube transfer items
- `ETH-####` ethics principles
- `SRC-####` source records once source acquisition starts
- `STAT-####` claim-status entries once claims exist

## Slugs

Slugs should be lowercase, hyphenated, and descriptive. They should not imply factual promotion. Good early slugs: `source-permanence`, `first-eng-record`, `candidate-queue-taxonomy`, `status-history-model`.
