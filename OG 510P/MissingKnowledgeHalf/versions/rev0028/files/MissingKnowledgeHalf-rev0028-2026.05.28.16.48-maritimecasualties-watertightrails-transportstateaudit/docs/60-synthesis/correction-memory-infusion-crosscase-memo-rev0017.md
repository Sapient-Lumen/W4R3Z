# Correction memory and correction infusion

Revision: rev0017

The cube has been accumulating visibility rails: ASRS, CHIRP, CIRAS, REPCON, NTSB recommendations, registries, Registered Reports, Retraction Watch/Crossref, PubPeer, Choosing Wisely, Cochrane, GRADE, NICE, EBI, and now NASA LLIS.

Rev0017 names a risk that applies across all of them: preserving a warning, lesson, registration, recommendation, or correction is not the same as transferring it to the future decision that needs it.

For 10k+ revisions, the cube should separate these surfaces:

- **Capture**: did the signal enter a durable record?
- **Index**: can it be found by the next person who needs it?
- **Interpretation**: is it framed with enough context to be applied correctly?
- **Authority**: can it force a change, stop, redesign, guideline, or warning?
- **Infusion**: did it enter process, checklist, policy, training, procurement, code, protocol, or textbook practice?
- **Follow-through**: did anyone verify that the change worked?
- **Decay**: did the lesson become stale, forgotten, ritualized, or too generic?

`MKH-PAT-0014` is deliberately candidate-level because the cube has only one infrastructure-audit pair in this lane. The point is not to criticize NASA; it is to protect the cube from confusing memory with uptake.
