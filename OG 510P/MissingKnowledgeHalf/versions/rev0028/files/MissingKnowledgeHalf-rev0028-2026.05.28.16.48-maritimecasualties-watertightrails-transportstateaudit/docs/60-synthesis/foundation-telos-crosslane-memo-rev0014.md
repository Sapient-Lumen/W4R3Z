# Foundation telos cross-lane memo — rev0014

Rev0014 pauses after thirteen revisions of scaffolding and case work. The pause reveals several cross-lane lessons.

## 1. Infrastructure is not auxiliary

The source-infrastructure lane began as support: registries, reporting channels, databases, recommendation systems, retraction metadata, and guidelines. It now appears foundational. The missing half of knowledge is visible only where some institution captures it.

Without ASRS-like, ClinicalTrials.gov-like, NTSB-like, Retraction-Watch-like, Cochrane-like, or inquiry-like surfaces, failure memory remains private, decays, or survives only as anecdote.

Future implication: each domain should be assessed not only by its failures but by the maturity of its failure-memory infrastructure.

## 2. Practice status is a separate world-state

Medical reversal and practice-lag records make clear that evidence can update before practice updates. The same will be true in engineering standards, software deployment cultures, textbooks, classroom examples, journalism, public belief, regulation, and procurement.

Future implication: every mature claim may need at least two statuses: literature status and practice status.

## 3. Pattern candidates are valuable precisely because they are not mature

The current pattern records should not be read as theories. They are prompts for disciplined recurrence research. Their value is in making a hypothesis visible while preserving the work required to earn it.

Future implication: pattern surfaces need support maps, negative controls, counterexamples, and scope boundaries before promotion.

## 4. Genealogy is underbuilt but essential

The first genealogy records are scene-level and cautious. That is appropriate. But without genealogy, the cube can say what failed without explaining why certain claims, methods, standards, or corrections traveled.

Future implication: build influence edges slowly, evidence-graded, and linked to claims or correction practices when possible.

## 5. Software needs special handling

Software appears in engineering, medicine, finance, law, regulation, security, and public administration. Its failures often involve hidden internal state, rapid deployment, opaque vendor records, and attribution surfaces that outsiders cannot inspect.

Future implication: software records need to distinguish outage, exploitability, breach, hidden state, regulatory evasion, deployment failure, monitoring failure, and machine testimony.

## 6. The cube needs reviews as much as additions

The early records are good seed records, but record count has outpaced second-review depth. This is normal. It should become explicit rather than embarrassing.

Future implication: review passes are first-class revisions.

## 7. The telos is correction memory

The best current description is: build the durable, source-backed memory of how knowledge fails, corrects, travels, lags, revives, and teaches.

That sentence should be allowed to evolve, but it captures the center better than “negative results database.”
