## Goal

Produce one finite FreeBSD handoff that can be copied back to the cloudtainer and imported without any checker-simulation, refusal, or failed-proof flags.

## Preconditions on the FreeBSD host

Run from the repository root on a real FreeBSD host. `PREFLIGHT_ON_FREEBSD.sh` verifies the copied work-order kit, then runs the root-required preflight either directly when uid 0 or through `sudo env PYTHON=...`; this fixes the collection/preflight split where `RUN_ON_FREEBSD.sh` could use sudo for collection but fail preflight as the invoking user. The preflight must observe FreeBSD, uid 0 at the actual preflight boundary, Capsicum feature sysctls enabled, `python3`, `cc`, `makefs`, `mdconfig`, `fstyp`, `mount`, `umount`, and `sha256` or `sha256sum` before media authority is used. A passed receipt records `host_target_tier`; `primary-production` is the desired target, while `supported-legacy-floor` is accepted only for the current supported 14.x floor because real host proof is scarce and must be labeled honestly. Do not collect new proof on the previous 14.3 floor; keep older 14.3 evidence historical.

## Concrete work order

The checked-in real-host proof work order at `validation/freebsd-real-host-proof-work-order/current` contains `PREFLIGHT_ON_FREEBSD.sh`, `RUN_ON_FREEBSD.sh`, `IMPORT_IN_CLOUDTAINER.sh`, `VERIFY_WORK_ORDER.sh`, and `real-host-proof-work-order.json`. It is generated by `tools/freebsd/stage_real_host_proof_work_order.py` and verified by `tools/freebsd/verify_real_host_proof_work_order.py`. The manifest binds the runnable work-order script digests plus repo proof-tool digests, so stale copied kits fail before scarce host time or returned proof is spent. The standalone preflight script can be run before collection and `RUN_ON_FREEBSD.sh` invokes it before the collector. The cloudtainer script runs sealed import preflight before publishing and passes `--reuse-existing-import`, so target-tier failures fail before writing an import and an interrupted rerun can verify/reuse the already-published matching sealed digest import. The sealed importer also holds an exclusive sibling import-root lock during publish/reuse/replace decisions, so two cloudtainer sessions cannot interleave scarce proof publication.

## Preferred cloudtainer handoff path

```sh
cd /path/to/DeriveBSD
handoff_dir=${DERIVEBSD_HOST_PROOF_HANDOFF_DIR:-/tmp/derivebsd-host-proof-handoff.$(date -u +%Y%m%dT%H%M%SZ)}
sudo env PYTHON=${PYTHON:-python3} \
  tools/freebsd/collect_removable_media_local_fallback_host_proof.sh \
  "$handoff_dir/receipt.json" \
  "$handoff_dir/bundle.json" \
  "$handoff_dir"
archive=derivebsd-freebsd-host-proof-handoff.zip
python3 -B -S tools/freebsd/seal_removable_media_local_fallback_host_proof_handoff.py \
  "$handoff_dir" --output "$archive"
```

Bring back either the handoff directory with exactly the required files `SHA256SUMS, bundle.json, receipt.json` or the deterministic sealed handoff archive. `README.import.txt` is optional, but if it is present then `SHA256SUMS` must cover it too. Do not add loose notes, logs, screenshots, or renamed files to the handoff directory; the verifier and sealer reject loose files and path drift. Do not point the handoff directory or import root at symlinks; the collector and strict wrapper refuse those paths before host proof collection/import. Do not reuse a handoff directory unless the deliberate replacement environment is set. The collector also has a handoff overwrite guard: if `receipt.json`, `bundle.json`, `SHA256SUMS`, or `README.import.txt` already exists in the handoff directory, it refuses before FreeBSD preflight unless `DERIVEBSD_HOST_PROOF_HANDOFF_REPLACE=1` is set for a deliberate replacement.
The deterministic sealer rejects a symlinked handoff, copies the handoff through a finite nofollow staging snapshot before archive write, enforces finite size limits, writes canonical sorted stored ZIP members with exact regular-file mode metadata, and the unseal/import tail rejects noncanonical ZIP metadata before atomic publish and audit.

## Cloudtainer import commands

Use the sealed preflight first, then the sealed one-command importer when the handoff comes back as the deterministic archive:

```sh
python3 -B -S tools/freebsd/preflight_sealed_removable_media_local_fallback_host_proof_import.py \
  /path/to/derivebsd-freebsd-host-proof-handoff.zip \
  --import-root validation/freebsd-host-proof-imports \
  --require-primary-target \
  --reuse-existing-import
python3 -B -S tools/freebsd/import_sealed_removable_media_local_fallback_host_proof_handoff.py \
  /path/to/derivebsd-freebsd-host-proof-handoff.zip \
  --import-root validation/freebsd-host-proof-imports \
  --require-primary-target \
  --reuse-existing-import
python3 -B -S tools/freebsd/report_removable_media_local_fallback_host_proof_imports.py --json
python3 -B -S tools/check_removable_media_local_fallback_freebsd_host_proof_checked_import_gate.py
python3 -B -S tools/check_freebsd_real_host_proof_theatre_gate.py
```

If the sealed archive needs inspection before import, unseal it to a scratch handoff directory first:

```sh
python3 -B -S tools/freebsd/unseal_removable_media_local_fallback_host_proof_handoff.py \
  /path/to/derivebsd-freebsd-host-proof-handoff.zip \
  --output-dir /path/to/handoff
```

If the handoff comes back as a loose directory already, skip unseal and point `/path/to/handoff` at that directory, then run the explicit verify/import/audit/report tail:

```sh
python3 -B -S tools/freebsd/verify_removable_media_local_fallback_host_proof_handoff.py /path/to/handoff
python3 -B -S tools/freebsd/import_removable_media_local_fallback_host_proof_handoff.py /path/to/handoff --import-root validation/freebsd-host-proof-imports
python3 -B -S tools/freebsd/audit_removable_media_local_fallback_host_proof_imports.py validation/freebsd-host-proof-imports
python3 -B -S tools/freebsd/report_removable_media_local_fallback_host_proof_imports.py
```

The preflight predicts the full copied-snapshot import identity without publishing; `--reuse-existing-import` is allowed only to verify and reuse an audit-clean matching sealed digest import during an operator retry. The importer itself serializes publish/reuse/replace behind an exclusive sibling import-root lock. Those commands run in default real-host-proof mode. They intentionally pass no non-proof allowance flags. The proof status reporter is observational: in this cloudtainer it should say `status=blocked-no-real-host-proof-import` and `proof_complete=false` until a primary-production real host proof has been imported. Use `--fail-if-incomplete` only when intentionally gating a proof-completion milestone.

## Refusal boundary

A Linux cloudtainer refusal receipt, a checker-only success simulation, a failed receipt, or an empty import-root proof status is useful regression evidence, but it is not a real host proof and is not an importable `real-host-proof`.
