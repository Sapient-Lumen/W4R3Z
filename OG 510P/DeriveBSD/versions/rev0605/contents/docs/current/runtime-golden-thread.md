# Runtime golden thread

The r630 runtime gate keeps the v0 mission spine executable while reducing the next product lie after fixture-payload truth: a hand-authored catalog can still pretend to be the admitted repository. The runtime now loads `validation/runtime-package-repository/current/snapshot.json` before accepting `validation/runtime-package-catalog/current/catalog.json`; the snapshot binds checked-in fixture package bytes by material sha256/size, payload digest, platform, origin, version, runtime dependencies, offline/no-network posture, fixture-only truth flags, and cube cut. Lock rejects stale snapshot bytes, catalog/snapshot package-set drift, snapshot/payload dependency drift, catalog/payload drift, missing dependency targets, dependency cycles, mutable `:latest` workload closures, and material-byte mismatch before issuing evidence. It still makes `nginx` pull checked-in `openssl` and `pcre2` fixture bytes into the lock/build path, carries the snapshot policy/digest through lock, plan, artifact, activation, explanation, and sealed artifact inputs, and retains the r629 payload projection repair, r628 transitive closure repair, r627 material-byte verification and digest-pinned workload closure guard, r626 transaction-spine repair, r625 precommit journal, r624 no-clobber generation receipts, r623 sealed artifact tree, r622 finite package-catalog resolver, r621 symlink authority-path guards, and r620 proof/preflight binding before any future authority-changing FreeBSD step. Run it locally with:

```sh
python3 -S tools/derive_runtime.py run-golden-thread \
  --spec spec/examples/microvm.spec.json \
  --workspace /tmp/derivebsd-golden-thread \
  --out /tmp/derivebsd-golden-thread/run.summary.json
```

The checked-in current evidence is `validation/runtime-golden-thread/current/run.summary.json`, with the full dry-run workspace under `validation/runtime-golden-thread/current/workspace/`. It proves the archive can execute:

`Spec → Lock → Plan → Artifact → Activate → Explain → Rollback`

The current backend is intentionally narrow and honest:

- The runtime lock uses an offline fixture resolver and records `truth_claim = finite-offline-fixture-repository-snapshot-plus-catalog-projection-plus-payload-verified-closure-and-bytes-not-a-package-index-resolution`.
- The runtime lock verifies each closed package material file from `validation/runtime-materials/current/packages/` against the snapshot/catalog-bound size and sha256, validates the admitted repository snapshot against fixture-payload metadata before accepting the catalog projection, records `package_repository_snapshot_policy`, `package_repository_snapshot_digest`, `package_payload_metadata_policy`, and records `package_closure` with requested, dependency, and resolved package IDs.
- The runtime plan records `bhyve_execution = false`, `freebsd_system_mutation = false`, and an empty host-file blast radius.
- The runtime artifact materializes a local sealed artifact tree with copied package fixture bytes for the full closed dependency set, `inputs/package-materials.json` carrying repository-snapshot and payload-policy evidence, an rc.conf-style fragment, and a non-executed microVM launch intent.
- The activation receipt mutates only a local generation pointer under the requested state directory and binds the precommit journal digest.
- The rollback receipt restores the prior local pointer and binds the precommit journal digest.
- The explanation binds the live spec, lock, plan, artifact, and activation receipt digests.

The r630 repair adds release-critical runtime regressions for stale repository-snapshot bytes and snapshot/payload dependency drift: if the catalog points at bytes whose sha256 no longer matches the admitted snapshot reference, lock fails before producing evidence; if the admitted snapshot claims dependency metadata different from the checked-in fixture package payload, lock also fails before evidence. `tools/gen_runtime_fixture_repository.py` now regenerates the fixture repository snapshot and projected catalog from package payload bytes, reducing hand-maintained resolver drift while keeping the gate executable. The r629 repair remains active: catalog/payload dependency drift fails before lock; the missing-target and cycle regressions mutate package payloads and refresh repository/catalog projections so they test resolver behavior rather than stale hand-authored catalog lies. The r628 repair remains active: a closed dependency edge whose target package is absent must fail before lock creation, and a dependency cycle such as `nginx -> pcre2 -> nginx` must be rejected before it can become lock or artifact evidence. The r627 material-byte regressions remain active: a catalog whose material digest does not match the checked-in package fixture bytes must fail before lock creation, and a microVM closure such as `services/nginx:latest` must be rejected before it can become evidence.

The r626 repair adds four executable regressions to keep the cube moving on transaction substance: rebuilding identical content in the same store must preserve the original CAS tree inode and digest, a fault-injected current-pointer writer must fail with a readback mismatch instead of issuing success, a replaced state lock must remain in place rather than be unlinked by the old owner, and `state-status` must classify malformed pending journals as quarantine-required.

The r616 repair added `runtime_identity_profile = derive-runtime-v0-content-identity-no-local-locators`. Runtime digests are computed from a path-independent identity view that drops local workspaces, receipt locators, and wall-clock metadata while preserving the semantic spec, resolver truth, authorities, blast radius, targets, artifact manifest, state transition, and upstream digest chain. The release gate runs the same spec and timestamp in two different workspaces and requires identical runtime digests; it also mutates a lock and a plan without updating their stored digests and requires downstream planning/building to fail.

The r625 repair added a precommit state journal; the release gate proves stale-journal activation and rollback refusal, journal preservation on refusal, and journal cleanup after successful commits. The r624 repair added an exclusive state mutation lock and no-clobber generation receipts; the release gate proves locked activation, locked rollback, duplicate-generation refusal, and lock release after success/failure. The r623 repair seals local artifacts and proves that writable file mode, writable directory mode, hardlink aliases, symlink members, and post-build byte tamper fail before activation writes local state. The r622 repair replaces the unlimited offline resolver stub with a finite checked-in fixture catalog: unknown packages fail closed before lock creation, catalog bytes changed without `catalog_digest` refresh are rejected, and the same catalog content at a different local path produces the same runtime digests. The r617 repair hardened mutation order: rollback verifies the activation receipt digest and current-generation precondition before state changes; repeated or stale rollback attempts fail closed; tampered activation receipts cannot write forged `state_before`; activation refuses post-build artifact-tree mutation; and explain validates activation → artifact → plan → lock digest links before trusting each next local locator. The r618 repair added `host-preflight`: real-backend activation refuses missing preflight evidence, denied host posture, and digest-tampered preflight receipts before local state mutation. The r619 repair made digest-valid preflight insufficient: runtime admission rechecks semantic host facts, primary-production target tier, root posture, required command rows, cube cut, and denial list; then `activate --mode freebsd-real` requires the checked import root to contain an imported primary-production real-host proof. The r620 repair binds that imported proof to the admitted preflight: release, machine, OSRELDATE, target tier, and target matrix must match before the runtime can reach the explicit backend-not-implemented refusal. Artifact digest and materialized-tree verification now happen before the `freebsd-real` admission branch, so proof admission cannot mask a stale or mutated artifact. The r621 repair adds a local symlink guard: build refuses symlinked artifact stores, activation/rollback refuse symlinked state directories, and activation/explain reject symlink members in materialized artifact trees before trusting bytes or writing state. On this cloudtainer the expected real-backend result is refusal, not FreeBSD proof.

This is not a product claim that DeriveBSD has activated a FreeBSD boot environment or launched bhyve. It is the smallest release-critical executable seam that can now be replaced from the inside: first replace fixture material bytes with an authoritative FreeBSD package/base-byte resolver, then implement the FreeBSD activation backend, then add `derive-vmmd` launch/stop receipts while preserving the same runtime identity chain.
