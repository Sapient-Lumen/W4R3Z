# SLSA levels and DeriveBSD goals (pragmatic roadmap)

SLSA provides a language for “how strong is our build pipeline?”
DeriveBSD can use SLSA as an external yardstick while keeping BSD-native constraints.

## SLSA framing
SLSA distinguishes:
- provenance generation
- build platform hardening
- hermetic builds
- two-person review / tamper resistance

## DeriveBSD mapping (rough)
- **SLSA L1**: provenance exists and is signed (baseline)
- **SLSA L2**: provenance is generated by the build system (not hand-written)
- **SLSA L3**: isolated build environment (jails, no network) + stronger controls
- **SLSA L4**: highly hardened, hermetic, strongly reviewed pipeline (long-term)

## v1 realistic posture
Aim for:
- L2-like guarantees for most artifacts (generated provenance, signed)
- L3-like isolation for high-value targets (builders hostile, no network, pinned toolchains)

Keep this *policy-expressible* so organizations can tighten over time.
