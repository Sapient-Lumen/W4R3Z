# LLM runbook (amnesia-resistant workflow)

This archive is designed to be edited by humans *and* automation. When using an LLM in the loop, treat this file as the
**operational contract** that prevents “design drift.”

## Non-negotiable invariants

DeriveBSD must preserve **all** of these pillars:

1. **Reproducible / derivation-first** builds and upgrades (explicit inputs; content-addressed identity; deterministic-by-default; impurity is policy-controlled and receipted).
2. **Strong runtime isolation** (jails + microVMs; least authority; capability-brokered operations; bounded interop).
3. **Supply-chain integrity / provenance** (signatures; trust roots; quarantine→promote; transparency lanes where applicable; long-term rebuildability & availability).
4. **Operability + forensics UX** (receipts everywhere; explainability; queryable evidence; deterministic exports / support bundles).

DeriveBSD must remain viable for all product shapes **without forks**:

- **A:** secure fleet host
- **B:** secure workstation
- **C:** general-purpose OS
- **D:** appliance factory / regulatory

Letters A–D are shorthands; canonical profile ids are in `spec/examples/product.profiles.json` (mapping in `spec/product.profile_aliases.json`).

If something only fits a subset, implement it as a **profile**, **tiered feature**, **optional lane**, or **adapter**.

## Editing rules (keep it tight)

- Prefer **small, composable changes**. One concept per doc.
- Docs >=397 must include a tiny metadata block near the top: **Tier / Profiles / Pillars / Patterns** (enforced by `tools/check_doc_metadata.py` and `tools/check_doc_patterns.py`).
- New work must fit an existing **pattern** (see `docs/397-pattern-catalog.md`), or add *exactly one* new pattern and justify the entropy cost.
- Every change must declare:
  - **tier** (A/B/C/D/E from `docs/401-v0-cutline-and-feature-tiers.md`)
  - **profile applicability** (A/B/C/D from `docs/411-product-profiles-as-compilation-target.md`)
- Any interop / compatibility must follow **Adapter → Shadow → Replace** and remain *killable* (`docs/402-adapter-lanes-and-strangler-discipline.md`).
- In `docs/266-open-questions-and-risk-register.md`, tag decided items with **[DECIDED]** and pin them to an ADR (guardrail: `tools/check_open_questions_decisions.py`).
- MicroVM Plan→Receipt examples must be mechanically consistent: receipt `plan_digest` is `sha256(JCS(plan))` (guardrail: `tools/check_microvm_example_plan_digests.py`).
- MicroVM lifecycle receipts must include stable reason codes on non-success outcomes (guardrail: `tools/check_microvm_receipt_reason_requirements.py`).
- MicroVM receipt example reason codes must be drawn from the central registry (guardrail: `tools/check_microvm_reason_code_registry.py`; registry: `docs/456-microvm-receipt-reason-code-registry.md`).
- Multi-origin userlands must normalize through `stratum.manifest` → `stratum.stack` → `mount.view`; every stack has exactly one ABI anchor, host-library fallback stays forbidden, foreign/incompatible userlands stay in bounded `compat_view` or `microvm` lanes, and `runtime.manifest` / runtime evidence must carry `stratum_stack_digest` + `mount_view_digest` (guardrail: `tools/check_strata_contract.py`).
- Component runtime authoring must stay crisp: `derive.unit` is the reviewed source, it names runtime bytes via exactly one authored field (`rootfs` xor `strata`), `runtime.manifest` is compiled launch authority and carries `derive_unit_digest` + runtime-composition digests, and `derive.unit.compile.receipt` stays evidence-only (guardrail: `tools/check_derive_unit_contract.py`).
- Product-profile defaults must stay a flat allowlisted vocabulary: `product.profiles.defaults` only uses keys explicitly declared in `spec/product.profile.schema.json`, values stay symbolic strings rather than nested policy objects, vocabulary changes require an ADR plus registry-doc update, observability posture must stay factored across `evidence` + `evidence_exports` + `network_egress` rather than a separate `telemetry` key, and DNS receipt detail/export posture stays a compiled consequence of those existing surfaces rather than a new profile key (guardrail: `tools/check_profile_default_vocabulary.py`; see `docs/501-product-profile-default-vocabulary-boundary.md`, `docs/503-telemetry-is-not-a-product-profile-default-boundary.md`, and `docs/504-dns-receipt-detail-and-export-posture-by-profile.md`).
- Network learn/audit must stay a bounded convergence lane: `net-flow-summary` is the compact evidence-only review surface, learn sessions carry explicit time + event bounds, `policy-suggestion` stays reviewable proposal only, and `net-egress-policy` remains the only authoritative enforcement object (guardrail: `tools/check_learn_net_contract.py`; see `docs/328-learned-network-policies-from-flow-receipts.md` and `docs/505-network-learn-audit-convergence-contract.md`).
- Temporary service sharing must stay on the relay-backed publish-session lane: use `net.publish.session` for bounded B/C sharing, keep the source listener local-first, join authority + transport evidence, and do not let durable host ingress drift back into tunnel folklore (guardrail: `tools/check_publish_session_contract.py`; see `docs/562-relay-backed-publish-sessions-for-temporary-service-sharing.md`).
- Relay-backed publish sessions must keep audience/publicness explicit: human sharing should stay audience-bound by default (`organization-users`, `named-recipients`, `support-session-peer`), while `public-webhook` and `public-link` remain explicit exception postures rather than the meaning of `internet` (guardrail: `tools/check_publish_session_access_posture_contract.py`; see `docs/563-publish-session-audience-binding-and-publicness-posture-boundary.md`).
- Relay-backed publish sessions must also stay reboot-cleared and no-auto-resume: require explicit lifecycle end conditions on `net.publish.session`, keep `resume_policy = new-session-with-fresh-authority`, and do not let relay/provider daemon state become ambient restart-persistent publication authority (guardrail: `tools/check_publish_session_lifetime_contract.py`; see `docs/564-publish-session-end-conditions-and-no-auto-resume-posture-boundary.md`).
