# Proof obligations — rev0043

Before this can become production design, the cube owes:

- a real key hierarchy proposal for leaf, garden, and bridge profiles;
- a private-key storage and migration story;
- exact rules for when dual-use keys are allowed, if ever;
- binding between I2P Destination identity and DHT node identity;
- recovery paths after operator compromise that do not erase hard-negative history;
- metadata analysis for public key rotation, succession, and compartment announcements.
