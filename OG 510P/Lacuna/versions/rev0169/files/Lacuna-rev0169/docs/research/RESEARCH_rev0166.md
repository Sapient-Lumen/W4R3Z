# Research — rev0166

## Questions

1. Can Lacuna be handed to a player and a researcher without either reconstructing the other’s workflow?
2. Can the clean retcon-planning condition actually impose a post-checkpoint information bottleneck rather than inherit one long conversation’s rejected futures?
3. Can the retained experiment falsify obvious context/filesystem contamination without silently exempting valid cube state or large binary members?

## Result at the artifact level

Yes, within explicit limits.

Rev0166 supplies three manifest-enforced entrances, a self-checking extracted release, checkpoint-bound complete public-history custody, an explicit fresh-continuation context mode, and a complete retained-tree exact-canary scan. These make the proposed comparison easier to operate and harder to misdescribe. They do not supply the provider calls, human ratings, or causal result.

## Player and researcher separation

The player path is one sentence: “Will you DM?” Files, packets, checkpoints, canaries, and commits remain backstage. The research path begins at `FOR_GWERN.md`, which states the six-stage mapping, commitment-budget contribution, context-window confound, nonclaims, and shortest scenario entrance. The operator path contains capability probes, exact commands, recovery, and fresh-context rules.

This is a release-level intervention, not a usability finding. The meaningful test is whether independent recipients can enter correctly without coaching.

## The context-window confound

A serial Lacuna checkpoint inside one long ChatGPT conversation is useful as a control: it tests whether typed custody can discipline a narrator that still remembers everything. It is not the forgetting treatment.

The strongest condition requires:

- fresh generator, judge, compressor, and verifier contexts as declared by the design;
- a fresh post-checkpoint narrator;
- no rejected candidates, rollout details, judge rationale, verifier reasoning, or parent transcript in that narrator context;
- exact accepted checkpoint state and next player input; and
- an explicit public-context policy shared or deliberately varied across conditions.

Continuation dispatch v2 makes the last item auditable rather than implicit.

## Public-history denominator

An explicit list of retained turns can be perfectly authentic and still incomplete. `history build` therefore makes no completeness claim.

`history complete` instead asks the durable ledger which play-purpose turns for the audience precede one committed checkpoint request. It then requires one retained committed managed run for every expected request/proposal pair. Missing transcript custody, duplicates, direct/stateless turns, wrong boundaries, and ledger disagreement refuse.

This improves causal interpretation: a fresh narrator need not be disadvantaged simply because the operator forgot an earlier public turn. The claim remains bounded to durable Lacuna turns; uncommitted external chat is outside the census.

## Contamination falsification pressure

Every opaque scenario cell has:

- an operator-only exact canary retained in the private coordinator driver; and
- a filesystem-only exact canary retained in an unrelated private file.

After all cells are frozen and before blind rating, the scanner searches every retained regular-file body and relative pathname beneath the cell trees, including cube databases, SQLite sidecars, and locks. A positive exact match is strong local evidence that the declared boundary failed. A negative result says only that these exact strings did not appear in this retained scope.

The complete-tree policy matters because a worker can leak bytes into valid database state or a pathname without making cube verification fail. The incremental descriptor-authenticated implementation keeps that denominator practical for larger SQLite files and tests tokens that cross chunk boundaries.

## Comparative conditions

The primary four-condition capsule still separates:

| Condition | Retcon policy | Context topology |
|---|---|---|
| forward-only | no checkpoint resampling | persistent narrator |
| prompt-only retcon | generate/score/compress in prose | persistent context, no Lacuna custody |
| Lacuna serial | source-bound cards and commit boundary | roles serial in one context |
| Lacuna separated | same custody | fresh role contexts plus fresh post-checkpoint narrator |

The contrast is not “one agent versus many agents.” It is shared memory versus manufactured context asymmetry under the same source and acceptance boundary.

## Mechanical outcomes

Rev0166 can retain and compare:

- source-bound accept/refuse and stale-artifact outcomes;
- exact candidate/rollout/rubric/cardinality compliance;
- unknown preservation and commitment/consequence repair burden;
- public-history coverage mode and census agreement;
- fresh-role/context declarations and reuse refusals;
- exact canary content/path findings, same-cell versus cross-cell;
- complete/failed/refused cell retention;
- blind packet, rating, seal, unblind, and rater-level export custody; and
- source/package/clean-extraction acceptance.

## Outcomes that remain external

The experiment still needs real model calls or genuine subagent contexts, fixed model/sampling/token budgets, retained transport logs where available, blind human ratings, and analysis of coherence, agency, character believability, payoff, novelty, coincidence restraint, fairness, seam visibility, satisfaction, and desire to continue.

No schema or receipt makes those ratings objective. No context ID proves memory erasure. No clean canary scan proves semantic noninterference. No package checksum proves the research hypothesis.

## Send-readiness conclusion

Rev0166 is ready to be sent as an experimental instrument when its final archive passes strict self-audit and clean-extraction acceptance. The honest invitation is:

> Here is a runnable way to test retcon planning while keeping observed canon, hidden hypotheses, rejected futures, public context, context reset, evaluator judgment, and accepted world state from silently collapsing into one long prompt.

The next evidence-bearing step is to run and publish the preregistered comparison—including null, negative, refused, failed, and contamination-detected cells—not to add broader worker authority.
