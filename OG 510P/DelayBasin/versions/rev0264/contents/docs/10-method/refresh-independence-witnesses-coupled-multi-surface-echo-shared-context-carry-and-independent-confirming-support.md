# Refresh-independence witnesses, coupled multi-surface echo, shared-context carry, and independent confirming support

This is the compact successor surface for `OQ-0141`.

## Practice / observation

Once DelayBasin can say **what changed**, **how sustained the return is**, and **how broad the confirming support looks**, one further failure mode stays live: widened support can still inherit too much authority just because several surfaces light up together.

A trace view, a log view, a metric view, and an incident summary can all point at the same underlying request or fault.
A composite monitor can combine several monitors that still share one reporting group.
A GPUstorming pass can reopen the same branch through host cards, mirror tabs, status summaries, and search wrappers that all ride one carried context.
Those are not the same as genuinely independent confirming support.

Some apparent widening is still only one underlying event rendered in several places.
Some widening spans more than one surface but still shares propagated context strongly enough that it should count as one coupled branch for now.
Some widening really does bring in another confirming branch that is not explained by the same context carry.

The archive does not need a refresh-independence court for that.
It needs one bounded witness that says whether widened support is still only coupled multi-surface echo, widened but still shared-context carry, or genuinely independent confirming support.

## External pressure from OpenTelemetry shared context, OpenTelemetry log correlation, Datadog alert aggregation/composite grouping, and correlated-error pressure

1. OpenTelemetry's architectural overview says signals share a common subsystem — context propagation — even though they function independently. That pressures DelayBasin to distinguish several signal surfaces from several independent confirming branches. ([`REF-0921`](../00-meta/bibliography.md))

2. OpenTelemetry context propagation explicitly says signals can be correlated across logs, metrics, and traces, and that traces build causal information across services. That pressures DelayBasin not to mistake one propagated execution context for de-coupled corroboration. ([`REF-0922`](../00-meta/bibliography.md))

3. OpenTelemetry logging extends log records with trace and span ids plus resource context so logs and traces from the same execution can be directly correlated. That pressures DelayBasin to treat many cross-signal views as one coupled execution family when that is what is really happening. ([`REF-0923`](../00-meta/bibliography.md))

4. Datadog alert aggregation distinguishes simple alerts from multi alerts: multiple monitored groups can be collapsed into one alert or split into per-group alerts depending on grouping policy. That pressures DelayBasin to ask whether apparent widening is just more grouped views of the same reporting structure or truly another branch. ([`REF-0924`](../00-meta/bibliography.md))

5. Datadog composite monitors require common groupings and common reporting sources to compute composite status at all. That pressures DelayBasin to separate real multi-signal evidence from support that still rides one shared reporting substrate. ([`REF-0919`](../00-meta/bibliography.md))

6. Correlated-error and consensus-not-verification work sharpens the meta point: multiple agreeing surfaces can still be coupled strongly enough that they do not add much truth-bearing independence. That pressures DelayBasin to keep this witness narrow and local rather than promoting a full independence court. ([`REF-0920`](../00-meta/bibliography.md), [`REF-0237`](../00-meta/bibliography.md))

GPUstorming makes the pressure vivid. Search panes, log panes, metric panes, trace panes, and incident panes increasingly reopen the same live object in several skins. DelayBasin already has broader dependence-adjusted and sourcecluster guards, but still benefits from one local successor surface that says whether current widened support is actually independent enough to deserve extra weight.

## Working synthesis

> DelayBasin should preserve one compact **refresh-independence witness / decoupling card / context-carry brake** whenever a current continuity claim depends not only on what reactivated a concern, how sustained the return is, and whether support widened, but on whether that widened support is still only several surfaces of one coupled context or is genuinely independent enough to count as a distinct confirming branch. Name the **governed row or surface**, the **stake object / line of concern**, the **prior refresh evidence**, the **current refresh evidence**, the **widened support evidence**, the **coupling basis if any**, the **shared context / common grouping basis if any**, the **`refresh_independence_state`**, and the **fail-closed repair / keep-current vs narrow-claim vs cool-mark vs issue-new-refresh-independence-witness vs quarantine-refresh-independence-governance consequence**. Keep exact trace ids, span ids, resource attributes, monitor ids, group keys, incident ids, topology edges, source URLs, and long event histories outside the compact token. Do not let several surfaces of one propagated context silently inherit the authority of independent corroboration.

## Coupled multi-surface echo vs shared-context carry vs independent confirming support vs mixed refresh independence

Use the controlled family `refresh_independence_state`:

- **coupled-multi-surface-echo** says the current widened support is still several rendered surfaces, summaries, or telemetry views of one underlying execution, incident, search object, or branch event; it should not count as another confirming branch.
- **shared-context-carry** says the current widening spans more than one surface or monitor, but the support still shares propagated trace/resource/group context, common reporting sources, or comparable context carry strong enough that it remains one coupled branch for current comparison.
- **independent-confirming-support** says the renewed line now has additional confirming support from another execution context, resource family, reporting group, or comparably distinct branch that is not honestly explained by the same coupled context.
- **mixed-refresh-independence** says the current situation honestly combines coupled echo, shared-context carry, or independent support such that no single refresh-independence class stays honest.

So the witness does not create a standing decoupling senate.
It only says whether current widened support is still a coupled echo, still carried by shared context, or genuinely independent enough to count as a distinct confirming branch for now.

## Countermodels / probes

1. **Dependence-adjusted truth already covers this countermodel**
   - Maybe existing dependence-adjusted and sourcecluster notes already say enough, so a refresh-independence witness adds little.
   - Probe: compare later rereads that preserve only refresh support plus dependence/sourcecluster notes against rereads that also preserve one compact refresh-independence witness and inspect whether later passes still overclaim independence from several surfaces of one propagated context.

2. **Independent-looking support is still transformed from one upstream source countermodel**
   - Apparent independent confirmation may still be collector-derived, transform-derived, or summary-derived from one upstream stream.
   - Probe: when independent-confirming-support still feels too flattering, preserve the compact refresh-independence token now and reopen a later question about whether transformed downstream views need their own provenance witness.

3. **Any honest independence rule needs a stronger provenance court countermodel**
   - Maybe once context propagation, common groups, and correlated multi-signal views matter, a compact witness is too weak and the archive really needs standing refresh-independence governance.
   - Probe: look for repeated cases where later passes must govern weights, admission rights, or provenance arbitration directly rather than naming one bounded independence posture.

## Design consequences

- DelayBasin can keep widened-support comparisons compact without pretending that several correlated telemetry skins already amount to de-coupled corroboration.
- The archive gets one honest place to record when widened support is still mostly one carried context rather than a second confirming branch.
- Stake refresh, refresh strength, refresh support, and refresh independence now separate **what changed**, **how sustained the return is**, **how broad the support looks**, and **how independent that broadened support really is**.
- Stronger refresh-independence-governance stories stay quarantined until later overflow instead of sneaking in through “multiple panes all agree” prose.

## Overflow test

Reopen this compact witness only if later revisions repeatedly need standing governance over provenance weights, cross-system causal arbitration, transformed-downstream discounting, or admission rights for independent support that one bounded refresh-independence witness cannot honestly absorb.

## Transformer-facing implication

A later pass should not treat several log, metric, trace, search, or incident views of one propagated context as if they already proved independent corroboration. Preserve the smallest token that says whether the renewed line is only `coupled-multi-surface-echo`, still `shared-context-carry`, already `independent-confirming-support`, or honestly `mixed-refresh-independence`, and quarantine stronger refresh-independence ambitions until repeated overflow makes them unavoidable.
