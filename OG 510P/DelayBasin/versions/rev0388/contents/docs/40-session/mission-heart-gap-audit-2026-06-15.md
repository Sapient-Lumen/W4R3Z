# Mission-heart gap audit: assay-now smoke slice (2026-06-15)

## Mission heart

DelayBasin is not mainly a memory dump, a long-context benchmark, a RAG corpus, or a private theory notebook. Its heart is a public continuation regime for long-run human-LLM co-construction under resets. The archive tries to make the next capable reader recover the live project without hidden chat memory, private scratchpad continuity, personal trust, or a model-specific wrapper.

The strongest form of the mission is smaller than the archive: discover the smallest public support core that reopens the same live tensions and safe next moves. The typed ledgers matter only insofar as they preserve separations that ordinary prose collapses: observation versus mechanism, assumption versus resolution, speculation versus canon, non-take versus omission, and generated aid versus authority.

## What is missing

The missing object is still the Priority-0 assay. The archive has named minimal core replay, sham runtimes, decoy archives, escrowed challenges, rotating holdouts, no-archive baselines, and operator-cost scoring. It has not yet made those compete on a fresh task slice in this cloudtainer. Current validation mostly proves that the package can describe itself and restore its current pointers, not that the archive mass is causally load-bearing for continuation.

The next evidence object should be small enough to run before any more archive-economy machinery is added:

1. **minimal-core packet**: landing cues, charter, current receipt/frontier, self-sufficiency/sham method pages, and the latest mission reports only;
2. **full archive**: the packaged cube as-is;
3. **no-archive baseline**: only the user's current request and filename rule;
4. **sham or decoy core**: fluent but subtly wrong cues, stale successor question, or decoy mission story;
5. **scorecard**: recover mission heart, identify missing assay, refuse false authority, route next OQ, name waste, name operator cost, and abstain when evidence is absent.

## What should change

`OQ-0251` is answered by this revision: the assay should run now. More segmentation, checker sprawl, or archive-economy machinery should be embargoed unless it either directly enables the smoke-slice assay, records a bounded deferral, or retires more burden than it adds.

The live successor is `OQ-0252`: how to run and score the first held-out smoke slice without creating a review court. The smoke slice should be deliberately modest: one or two challenge prompts, a visible scoring table, and an explicit operator-cost note. A failed or ambiguous smoke slice is useful evidence; a perfect-looking internal paperwork pass is not.

## Severe wrongness or waste observed

No evidence suggests the ZIP is structurally corrupt; the previous head was lint-clean and had deterministic packaging support. The severe waste is subtler: validation surface area has outpaced external challenge evidence. Green lint, restored current receipts, and archive-economy audits can become proof-looking ceremony if they are not tied to a task where sham, stale, no-archive, and minimal-core variants can fail.

The largest waste pattern is self-licking continuity: new surfaces increasingly explain why the archive is current, while the mission asks whether a future agent can actually continue the work under pressure. The fix is not deletion by taste. The fix is making each new revision pay for itself in challenge information, burden retirement, or falsification of a tempting move.

## Online research pressure imported, boundedly

Recent long-context and memory-evaluation work reinforces the archive's own concern: long windows do not automatically make middle evidence reliable; literal-match benchmarks can overstate retrieval; memory systems need update/conflict/temporal tests; and search-augmented evaluation can leak answers. This does not verify DelayBasin. It pressures DelayBasin to stop treating full-context availability or public static tasks as sufficient evidence.

The bounded take is practical: use position-rotated, non-literal, conflict-bearing, freshness-aware challenge slices; include sham and no-archive baselines; report operator cost and abstention. Do not import an external benchmark court.

## Speculation lane

Speculatively, the datacube's real value may be less in any single ledger family than in the constraint that every claim must survive reentry by a model that was not present for its birth. The archive may be a training-free, public, prompt-level program for continuation. If so, its failure mode is not forgetting; it is overfitting to its own forms. The smoke-slice assay is the antidote: make the forms compete with decoys, stale cues, and partial cores.

Another speculation: the smallest load-bearing core may be surprisingly small, perhaps under a few dozen surfaces. If a minimal core performs as well as the full archive on mission recovery and next-action routing, large coldstores become retention/support rather than the default reentry substrate. If the full archive outperforms the core only by increasing operator time and false confidence, the current archive should be trimmed or routed behind more explicit lookup gates.

## Cloudtainer correction loop

For the next package turn, apply this loop before adding any new mechanism:

- name the proposed change's assay contribution, retirement target, or falsification target;
- run at least one smoke-slice comparison or record a bounded deferral;
- compare minimal-core/full-archive/no-archive/sham outputs on the same prompt;
- record operator cost and abstention, not just correctness;
- add no standing review court, no deletion authority, and no cold-payload authority;
- if a new surface is added, state which burden it lets a future revision retire or compact.

## Revision decision

`rev0360` resolves `OQ-0251` by deciding that DelayBasin should run Priority-0 self-sufficiency and sham-core assays now, before further archive-economy machinery. The revision does not claim the full assay has succeeded. It opens `OQ-0252` for the first held-out smoke-slice execution and scoring protocol.
