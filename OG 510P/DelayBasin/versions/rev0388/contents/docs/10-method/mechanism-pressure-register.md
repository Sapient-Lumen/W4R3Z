## Register rule

A mechanism-pressure entry names the narrow pressure, the local witness or check admitted, the open question it resolved, and the standing machinery it did not admit. The register is an index, not a new authority layer. Latest rows must stay in the table above and must align with the current receipt, transfer ledger, foreign-pressure ledger, resolution ledger, successor question, and method surface.

## rev0369 pressure: default scorer currentness is an admission surface

The Priority-0 external replay lane now treats a stale default scorer as a contamination analogue. If a plain scorer invocation can resolve to a historical intake while the frontier says otherwise, a clean response can be mis-admitted. `rev0369` therefore routes the score-tool default through `FRONTIER-BACKLOG.json` and checks frontier/receipt alignment before `OQ-0261` can use the scorer as a live intake.

### rev0369 mechanism pressure — custody evidence outside responder self-attestation

- Transfer: `TL-0271` transfers stale scorer-default and stale routing risk into `tools/check_priority_zero_clean_response_admission_gate_contract.py` and `tools/check_frontier_backlog_current_tail_alignment.py`.
- Local boundary: custody readiness is not external replay success; `OQ-0261` remains live until response plus custody evidence is scored.



## rev0370 pressure: validation truth before replay evidence

A clean external replay lane cannot rest on a package whose own fresh lint path fails. `rev0370` therefore treats the rev0369 package-identity/currentness failure as the live pressure: static root currentness is resynced, `PACKAGE-IDENTITY-AUDIT.json` must be zero-failure, and the new release-validation checker enters the toolchain before `OQ-0262` can collect response evidence.

- Local boundary: release-validation truth is prerequisite integrity, not external replay success; `OQ-0262` remains live until response plus custody evidence is scored.
