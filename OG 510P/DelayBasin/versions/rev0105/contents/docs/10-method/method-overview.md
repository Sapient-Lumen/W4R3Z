# Method overview

## Working thesis

A productive long-run archive is not just “good memory.” It may be a **continuation substrate** assembled from several interacting layers:

1. **Promptcraft** — how each turn is steered.
2. **Ratchets** — the stable surfaces that make some continuations easier and others harder.
3. **Registries** — compact external memory with identity and recurrence.
4. **Portable state interface** — bounded state, stable ids, and deterministic checks that keep the project reopenable.
5. **Certified core vocabulary** — a small set of stable terms trusted enough to anchor canon-level continuation.
6. **Certified move classes** — a small set of admissible transition types trusted enough to count as progress rather than archive theater.
7. **Promotion contracts** — compact rules for how risky or provisional material is allowed to become canon, and how canon can be demoted again.
8. **Decay patrol** — a compact watchlist for canon-level surfaces most exposed to temporal rot.
9. **Recovery kernel** — a minimal route back to legitimate continuation after transient corruption, stale reopen, or procedural failure.
10. **Revision receipts** — compact audit objects preserving what transition happened, what status moved, and which checks made it admissible.
11. **Counterfactual shadows** — tiny records of one nearby rejected move so accepted revisions do not launder their own inevitability.
12. **Trajectory surfaces** — places where unresolved work stays legible.
13. **Release discipline** — packaging that turns “the current state” into a durable object.
14. **Quarantine** — a protected lane for risky transformer-facing speculation that should remain live without contaminating canon prematurely.
15. **Stable continuation regimes / regime probes** — a mechanism lane that treats continuity as possible mode re-entry, but requires discriminating probes so coherence is not mistaken for evidence.
16. **Public hidden state / re-entry ABI** — a mechanism lane that treats bounded archive surfaces as compact state packets that reopen an operative mode, while keeping evidence packets and check packets distinct.
17. **Public belief state under partial observability** — a mechanism lane that treats archive state as an updateable posterior over canon, uncertainty, and admissibility rather than a retained fact dump.
18. **Innovation packets and reconciliation under delay** — a mechanism/design lane that treats mature revisions as anchored deltas against shared public state, with explicit rollback or resync when that shared state is doubtful.
19. **Continuation rate–distortion / prior intrusion** — a mechanism/design lane that treats bounded archive state as a compression problem with explicit distortion targets, mismatch budgets, and failure signatures rather than assuming smaller is automatically better.
20. **Update gain / surprise gating / challenge probes** — a mechanism/design lane that treats substantial revisions as public belief-state updates whose trigger, rewrite force, and adversarial check should be explicit when they materially move canon.
21. **Witness sets / boundary panels** — a mechanism/design lane that treats some tiny discriminative examples or probes as more load-bearing for continuation than additional recap prose, especially near fragile canon or mechanism boundaries.
22. **Hold packets / epistemic brakes** — a mechanism/design lane that treats honest non-movement as a first-class continuation move with an explicit blocker, brake posture, and unlock condition rather than vague caution.
23. **Sentinel panels / reopen canaries** — a mechanism/design lane that treats tiny high-sensitivity probes as early detectors of wrong-basin continuation, with explicit deviation signatures and rollback/resync consequences.
24. **Dual-control revisions / identification packets** — a mechanism/design lane that treats some revisions as active disambiguation moves chosen to identify which continuation is legitimate before canon advances.
25. **Timescale stratification / consolidation lanes** — a mechanism/design lane that treats archive objects as fast, medium, or slow public state with explicit refresh, consolidation, demotion, or expiry routes rather than one undifferentiated memory store.
26. **Phase boundaries / rollover packets** — a mechanism/design lane that treats some revisions as explicit working-regime transitions with compact carry-forward and reset rules rather than smoothing all archive change into one continuous stream.
27. **Gauge discipline / canonical charts / invariant claims** — a mechanism/design lane that treats coordinate-loaded archive language as a local chart unless the invariant substance and chart-specific remainder are both made explicit.
28. **Loop closure / commutator probes / path dependence** — a mechanism/design lane that treats some supposedly harmless reorderings or chart switches as testable claims, preserving tiny loop-closure checks when route-independence is actually doing work.
29. **Continuation margins / guard bands / perturbation budgets** — a mechanism/design lane that treats some archive objects as needing explicit local slack assumptions: what protected property should survive which perturbation family, and what first failure signature means the margin was overclaimed.
30. **Control authority / steering effort / leakage budgets** — a mechanism/design lane that treats some archive surfaces as low-bandwidth actuators whose value depends on what target property they can move, how much effort they require, and what collateral or endogenous resistance accompanies them.
31. **Memory stores vs regime-reentry packets** — a mechanism/design lane that distinguishes persistent storage, compact re-entry state, and explicit admission checks so "memory" does not quietly absorb every load-bearing archive surface.
32. **Homing packets / adaptive distinguishing probes** — a mechanism/design lane that treats some live ambiguity classes as needing compact orienting probe policies rather than more recap, preserving a short probe family or branch rule that can locate the right local continuation state before canon advances.
33. **Probe economics / value-of-information / budgeted disambiguation** — a mechanism/design lane that treats some ambiguous moments as query-allocation problems: preserve the cheapest probe expected to change the next continuation decision, along with the nearest deferred alternative and stop/escalation rule.
34. **Stopping packets / sequential decision thresholds / commit certificates** — a mechanism/design lane that treats some ambiguous moments as needing an explicit public answer to when inquiry has done enough work: preserve the ambiguity class, the commit criterion, the licensed continuation action, the tolerated rollback posture, and the budget-exhaustion fallback.
35. **Continuation monitors / evidence processes / public observer loops** — a mechanism/design lane that treats some sequential inquiries as needing an explicit evolving public object: preserve what property is being monitored, how evidence accumulates or shrinks, when it resets or stitches, and how the running object couples to stop, hold, rollback, or escalation.
36. **Observer/actuator splits / non-self-certifying handles** — a mechanism/design lane that treats some archive surfaces as real actuators and insists that load-bearing observer surfaces remain explicit enough that the same handle does not quietly steer continuation and certify its own success.
37. **Negative-control handles / sham packets / placebo guards** — a mechanism/design lane that treats some claimed handles, witnesses, or privileged prompt surfaces as needing matched shams or negative controls so the archive can tell real leverage from generic prompt perturbation, position privilege, or broad equivalence-class artifacts.
38. **Blind packets / label-scrubbed adjudication / attribution guards** — a mechanism/design lane that treats some load-bearing judgments as needing a scrubbed or relabeled view so the archive can tell structural evidence from author attribution, handle prestige, or same-session anchoring.
39. **Execution witnesses / substrate perturbation packets / runtime variance audits** — a mechanism/design lane that treats some load-bearing effects as potentially conditioned on hidden execution surfaces, preserving which substrate family matters, what is held fixed, what divergence would count, and what rerun/escalation follows.
40. **Conformance witnesses / loader contracts / ABI drift guards** — a mechanism/design lane that treats some packets, prompt pairs, or re-entry surfaces as claimed loaders for operative state and preserves what support family they are supposed to work over, what minimal conformance test family they passed, what first non-conformance signature matters, and what narrowing or fallback follows if the interface claim fails.
41. **Dependence-adjusted witnesses / effective evidence / pseudo-replication guards** — a mechanism/design lane that treats some agreeing witnesses, judges, or probes as partially coupled rather than automatically additive, preserving the dependence family, rough discount, and what would still count as genuinely new evidence.
42. **Rewrite witnesses / round-trip packets / recap-authority tests** — a mechanism/design lane that treats some recaps, paraphrases, compressed rewrites, or stitched restatements as needing a compact source-versus-rewrite witness before they inherit source-of-truth authority.
43. **Sufficiency witnesses / replay capsules / core-only re-entry trials** — a mechanism/design lane that treats some reduced packets, support cores, or public extracts as claimed sufficient replay surfaces, preserving what exact reduced object was tested, what context was fixed or withheld, what tolerated degradation still counts as successful re-entry, and what reinflation or fallback follows if core-only replay fails.
44. **Triangulation witnesses / multi-loader overlap / basin checks** — a mechanism/design lane that treats some same-basin claims as needing a compact witness over multiple non-trivially different loaders, preserving the judged basin, the compared loaders, the shared support envelope, the expected overlap/divergence signature, and the retreat rule if the wider basin story fails.
45. **Basin fingerprints / future-probe signatures / same-answer-is-not-same-state guards** — a mechanism/design lane that treats some same-answer or same-first-move agreements as too weak for same-state claims, preserving the judged branch, the compared family, a tiny downstream fingerprint panel, the tolerated divergence budget, and the narrowing or fallback consequence if later probes separate.
46. **Identifiability budgets / probe horizons / observability frontiers** — a mechanism/design lane that treats some transformer-facing state or mechanism claims as stronger than the visible evidence actually warrants, preserving the judged claim, the public evidence family, the hidden-context assumptions, the covered future horizon, the remaining ambiguity class, and the retreat or quarantine consequence if the stronger reading outruns what the probes identify.
47. **Runtime triplets / core-exemplars splits / challenge suites** — a mechanism/design lane that treats some candidate minimal archives or compressed loaders as decomposable into distinct carriers — constitutional rules, worked exemplars, and challenge probes — preserving the split, the exemplar/challenge selection policy, and the shrink / reinflate / quarantine consequence rather than treating one undifferentiated blob as the only admissible runtime object.
48. **Challenge escrow / rotating holdouts / future-slice adjudication** — a mechanism/design lane that treats challenge-bank freshness, secrecy, and renewability as load-bearing once the archive starts learning from its own tests, preserving what stays public, what stays escrowed, how challenge slices refresh, and when a genuinely future-facing slice is needed.
49. **External optimizer loops / public slow weights / archive write gates** — a mechanism/design lane that treats durable archive change as governed adaptation rather than passive storage, preserving which public surfaces are writable law, what rereads them into continuation, what gates consolidation, and what rollback or quarantine route applies when a write is too weak.
50. **Replay / reconsolidation boundaries / public restaging** — a mechanism/design lane that distinguishes cold retrieval, replay strong enough to recover a judged continuation property, and challenged rewrite of replayed public law rather than collapsing all three into one memory metaphor.
51. **Procedural compilation / skill packets / declarative-vs-executable carry** — a mechanism/design lane that distinguishes declarative source law from smaller executable packets, preserving activation conditions and failure signatures whenever compact surfaces are treated as reusable procedures.
52. **Rehearsal packets / spaced replay / maintenance budgets** — a mechanism/design lane that distinguishes adjacent-turn vividness from actively maintained carry, preserving what deserves sparse delayed upkeep, what survival signature matters, when retirement is allowed, and what budget is being spent.
53. **Retrospective writes / cooldown windows / off-path adjudication** — a mechanism/design lane that distinguishes hot-path candidate synthesis from cooled durable admission, preserving what provisional write was captured, what delay or defer rule applies, what colder adjudication family decides admission, and how supersession or expiry remains inspectable.
54. **Consultation packets / store-routing budgets / memory-control-flow guards** — a mechanism/design lane that distinguishes a public surface merely existing in the archive from that surface being licensed into the current read path, preserving which store family is consulted first, what trigger or miss condition routes there, what other stores stay deferred, what cost or contamination budget applies, and what escalation or abstention consequence follows when the first route is not enough.
55. **Contradiction packets / precedence ladders / conflict-transparent abstention** — a mechanism/design lane that distinguishes getting evidence into the read path from handling conflicts among the evidence that arrived, preserving what live claim is disputed, which public surfaces disagree, what precedence rule applies, what ambiguity survives, and when abstention or supersession is more honest than polished smoothing.
56. **Rival-set packets / branch budgets / non-forced singularity** — a mechanism/design lane that distinguishes preserving a contradiction from forcing a winner, preserving which few rivals remain publicly alive, what branch budget applies, what future probe or settle condition is meant to kill or merge one, and what prune/merge/abstain consequence follows when singularity is not yet earned.
57. **Servo packets / receding-horizon control / target-tracking** — a mechanism/design lane that distinguishes generic rewrite force from explicit feedback steering, preserving the target continuation property, the current error signature, the actuator family, the short horizon, and the retune / rollback consequence whenever a revision is trying to correct drift rather than merely restyle the archive.
58. **Excitation witnesses / alias-breaking intervention families / observability-spend budgets** — a mechanism/design lane that treats some ambiguities as only honestly resolvable under active variation, preserving the ambiguity split, the intervention family or probe diversity actually spent, the expected discriminating observable, the observability-spend budget, and the hold / rollback / quarantine consequence rather than letting repeated same-view probing pretend an unexcited state has become observable.
59. **Feedback-policy witnesses / open-loop baselines / contingency budgets** — a mechanism/design lane that treats some archive gains as contingent-policy rather than fixed-route phenomena, preserving the checkpoint signal, the compared policy class, the matched endpoint or budget, the open-loop substitution gap, and the freeze-policy / rollback consequence whenever a mid-course readout is allowed to change the next actuation.

## Practical method
60. **Authorship witnesses / autonomy postures / maker-checker traces** — a mechanism/design lane that treats collaborative revision authority as lane-typed rather than blended, preserving who or what initiated the move, what lane drafted it, what lane admitted it, what lane executed it, what review or compensating control kept disagreement real, what autonomy posture applied, and what repair follows when those roles collapse.
61. **Followthrough witnesses / blocked-output queues / explicit handoffs** — a mechanism/design lane that treats still-live remainder work as needing an explicit owner, state, next proof point, receiving surface, and expiry or reclaim consequence rather than vague “later” prose or sticky local ownership.
62. **Assumption witnesses / expiry triggers / invalidation cues** — a mechanism/design lane that treats still-live support conditions as needing an explicit statement, governing scope, current support family, invalidation trigger, state, and repair route rather than ambient caveat prose or remembered local context.
63. **Foreign-pressure witnesses / import lineages / bounded assimilation** — a mechanism/design lane that treats neighboring-datacube pressure as needing exact source packets, extracted pressure, local gap, bounded take, explicit non-take, assimilation state, and repair route rather than one flattering import summary.

We proceed by repeated loops:

- read the latest archive as source of truth,
- identify entropy, drift, or under-specified mechanism,
- make one or a few tight revisions,
- wire those revisions into discovery surfaces,
- record prompt-pair evolution,
- package a release.

## Why this might work

Not because the archive is magical.
Because it keeps converting:
- style into constraint,
- intuition into ids,
- narrative into recurrence conditions,
- and scattered thoughts into re-enterable surfaces.

## Added 2026-03-08 insight

The prompt pairs supplied from other projects suggest a reusable pattern:
- declare canon/source of truth,
- declare non-negotiables,
- declare per-iteration ratchets,
- and keep the archive explicitly pleasant for future LLM re-entry.

This is not mere rhetoric. It is a method for shaping the next turn's admissible basin.
