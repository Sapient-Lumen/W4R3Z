## Why this change

The archive already had a strong deeper note on turnover-aware systems, but it still lacked one joined front-door canon for a timing question that keeps reappearing in real programmes:

**how should ideal solutions use the moments when the decision is actually live — sale, rental, replacement, procurement, renovation, refinance, and rebuild — without mistaking timing discipline for passive delay?**

The new note compresses that answer into one place: ideal solutions should attach themselves to trigger points where stock is already changing, make the cleaner and safer option win by default or near-default at those moments, and override natural turnover where waiting would lock in too much harm.
