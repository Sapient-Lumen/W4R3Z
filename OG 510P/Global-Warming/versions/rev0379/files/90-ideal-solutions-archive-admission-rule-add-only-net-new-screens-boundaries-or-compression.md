# 90 — Ideal Solutions: Archive Admission Rule — Add Only Net-New Screens, Boundaries, or Compression

## Claim

The archive is now strong enough that its main failure mode is no longer under-theorizing climate solutions.
Its main failure mode is **growing by restatement**.
So the archive should make one more rule explicit:

**do not add a new main-canon note unless it changes the archive's screening power, boundary clarity, or navigation cost in a meaningful way.**

This is a canon-maintenance note.
It introduces no major new factual claims about climate science or technology.
It compresses what the archive already implies through `59-ideal-solutions-fast-screen-promote-demote-quarantine.md`, `88-ideal-solutions-compact-canon-core-screens-in-one-place.md`, and `89-ideal-solutions-compact-negative-canon-red-flags-and-recurring-failure-modes.md`.
For the shortest joined workflow that tells a future researcher when to use those screens, when to route a proposal, and only then when to consider archive growth, see `91-ideal-solutions-operating-protocol-fail-fast-screen-route-and-admit.md`.

## Default posture

The default answer to a proposed new note should now be **no** unless at least one of the following is true:

1. it adds a **net-new screen** the archive could not previously apply
2. it clarifies a **boundary** that changes promote / demote / quarantine disposition in practice
3. it creates a real **compression** that lowers navigation cost or joins scattered logic into one reusable screen
4. it repairs a meaningful **structural defect** in the archive such as stale metadata, broken mapability, duplicated doctrine, or missing cross-links that block use

If a proposal does none of those, the archive should usually prefer:
- one light cross-link
- one paragraph added to an existing file
- one wording clarification
- or no change at all

## The archive admission tests

A candidate addition should usually pass most of these.

### 1. Delta test
Does the proposed note say something the archive cannot already say with one existing file plus one sentence of guidance?

If not, it is probably restatement.

### 2. Disposition-change test
Would the note actually change how future proposals get promoted, demoted, quarantined, or routed?

If not, it is probably elaboration without decision value.

### 3. Compression test
Does the note reduce hops across the archive by bundling several already-valid pieces into one smaller reusable screen?

If yes, that can justify growth even without major new doctrine.

### 4. Boundary test
Does it resolve a confusion the archive keeps encountering — for example between enabling measures and core physical lanes, between residual tools and main-path tools, or between justified exceptions and loopholes?

If yes, it may earn admission even if it is short.

### 5. Non-paraphrase test
Is the note more than a renaming of a nearby file with slightly different labels?

If not, merge or cross-link instead.

### 6. Surface-area test
Will the note reduce net user effort to navigate the archive, or will it increase lookup burden more than it increases clarity?

If it mostly increases lookup burden, do not add it.

### 7. Maintenance test
Will this addition create future obligations — more cross-links, more summary burden, more map complexity — that exceed its value?

If yes, it should face a higher bar.

## Preferred actions by case

### Case A: clearly net-new
Add a new main-canon note when the archive truly gains a screen, boundary, or synthesis it did not have before.

### Case B: useful but not net-new
Edit one existing note, add a short paragraph, or strengthen the README / compact canon instead.

### Case C: same idea, better shape
Refactor: merge duplicate material, tighten wording, or redirect the reader toward the stronger file.

### Case D: no real gain
Do nothing.

## Strong reasons to refuse a new main-canon note

Refuse when the proposal:
- merely restates the same doctrine in slightly different language
- produces another fragment where a synthesis would be better
- adds moral emphasis without changing screening power
- adds examples better kept as one sentence under an existing rule
- creates a new navigation burden larger than its conceptual gain

## Strong reasons to admit a new main-canon note

Admit when the proposal:
- creates a reusable screening question the archive previously lacked
- resolves a recurring ambiguity that changes actual judgments
- compresses several scattered rules into one smaller front-door screen
- repairs a structural archive defect that blocks correct use

## Working rule for future revisions

For each proposed change, ask in order:

1. **What exact decision becomes easier after this addition?**
2. **What existing file is insufficient on its own?**
3. **Why is this better as a new file rather than a sentence, cross-link, merge, or rewrite?**
4. **Will the archive be sharper, or merely larger?**

If the best honest answer to the last question is **merely larger**, the default should be **no new main-canon file**.

## Compression

The archive is not trying to maximize the number of true things it contains.
It is trying to maximize **usable judgment per page**.

That means future growth should now be selective:
- add new notes only for net-new screens, boundaries, or compressions
- otherwise merge, tighten, cross-link, or refuse

This note exists so the archive can stay ambitious without becoming baggy.
