# 125 — Ideal Solutions: Whole-Archive Minimal Spine

## Claim

The archive now has:
- a shortest front-door answer (`58`)
- a compact package note (`57`)
- an acceptance-tests note (`97`)
- a design-directives note (`98`)
- an action-verbs note (`99`)
- a readiness compact canon (`122`)
- an off-normal compact canon (`123`)
- and a governing-kernel compact canon (`124`)

That is now enough material that the archive benefits from one more compression move:

**a single smallest reading spine for people who want to internalize the whole archive without reopening the full tree.**

This note is not a new doctrinal branch.
It is a navigation / compression note.
Its job is to reduce the mature archive to the fewest files that still hold the answer together.

## Fast rule

**If you want the whole archive in the fewest stops, read in this order: answer, package, acceptance tests, design grammar, governing kernel, readiness state machine, and off-normal state machine. Stop there unless a concrete question still survives.**

## Why this note is not redundant

- `94-ideal-solutions-archive-topology-layers-best-first-stops-and-preferred-reading-order.md` answers **which archive layer to start in**
- `95-ideal-solutions-question-router-common-prompts-to-best-first-files.md` answers **which file matches a concrete natural-language prompt**
- `122-ideal-solutions-readiness-state-machine-compact-canon.md` answers **how to hold the readiness cluster in one place**
- `123-ideal-solutions-off-normal-state-machine-compact-canon.md` answers **how to hold the off-normal cluster in one place**

- this note answers **what the smallest whole-archive reading spine now is**

## The minimal spine

### 1. Start with the shortest answer
Open `58-ideal-solutions-one-page-answer.md`.

That file gives the archive’s shortest answer to the main question:
ideal solutions are not one technology, one tax, one market tweak, or one future cleanup promise.
They are a physical-first portfolio that cuts emissions fast, protects people directly, reduces lock-in, and can actually be delivered.

If this file already answers the question in the needed resolution, stop there.

### 2. Add the compact package
Open `57-ideal-solutions-reference-portfolio-2026-2035.md`.

This is the shortest operational package note in the archive.
It turns the answer into a concrete portfolio rather than a slogan.

Use it when the question is:
- what the programme actually contains
- what must happen in parallel
- what a serious package looks like in applied form

### 3. Add the acceptance tests
Open `97-ideal-solutions-design-spec-ten-acceptance-tests-for-a-serious-climate-package.md`.

This is the archive’s shortest seriousness filter for proposed packages.
It says what a climate programme must satisfy before it deserves serious attention.

Use it when the question is:
- is this package actually serious
- what must an ideal solution pass
- what makes a proposal fail fast

### 4. Add the positive design grammar
Open `98-ideal-solutions-seven-design-directives-for-the-whole-archive.md` and `99-ideal-solutions-seven-action-verbs-for-a-serious-climate-program.md`.

These two files give the shortest reusable design grammar in the archive:
- what ideal solutions should generally look like
- what ideal solutions mostly do

Use them when the task is design rather than screening.

### 5. Add the governing kernel
Open `124-ideal-solutions-governing-kernel-compact-canon.md`.

This is the smallest joined note for how a serious climate state runs the programme:
- lanes
- levers
- clocks
- roles
- rights
- precedence

Use it when the question becomes:
how is the programme actually governed rather than merely described?

### 6. Add the readiness state machine
Open `122-ideal-solutions-readiness-state-machine-compact-canon.md`.

This is the smallest joined note for readiness before the bad day:
- keep readiness live
- classify status honestly
- operate by the current status
- promote only on current proof
- demote quickly when the stronger claim no longer governs
- suppress flapping
- resolve disputes conservatively

Use it when the question becomes:
are we actually ready, or only saying so?

### 7. Add the off-normal state machine
Open `123-ideal-solutions-off-normal-state-machine-compact-canon.md`.

This is the smallest joined note for what happens when routine governance is no longer enough:
- readiness before stress
- visible tripwires
- response modes
- proof gates
- live detour discipline
- return-to-routine tests
- after-action hardening

Use it when the question becomes:
what happens when the system is under strain, failing, or temporarily off the clean mainline?

## Preferred stopping rule

For most readers, the archive can now be held in **seven first stops**:

1. `58`
2. `57`
3. `97`
4. `98`
5. `99`
6. `124`
7. `122`
8. `123`

But this is better understood as **five layers**:
- answer
- package
- acceptance / design grammar
- normal governance
- readiness and off-normal governance

So the actual stopping rule is simple:

- stop after `58` if only the shortest answer is needed
- stop after `57` if a compact package is enough
- stop after `97`–`99` if the task is design or evaluation
- stop after `124` if the question extends into state operating design
- stop after `122` and `123` if the question extends into readiness, failure, stress, or detour governance

Only descend into the deeper tree when one of those compact notes leaves a live unresolved question.
