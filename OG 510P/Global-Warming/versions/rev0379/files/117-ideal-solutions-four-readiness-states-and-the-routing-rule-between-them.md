# 117 — Ideal Solutions: Four Readiness States and the Routing Rule Between Them

## Claim

The archive already has:
- a readiness note (`111`)
- a live-discipline note (`112`)
- a rehearsal-discipline note (`113`)
- a readiness-assurance note (`114`)
- a partial-readiness note (`115`)
- and an unknown-readiness note (`116`)

What it still lacked was the shortest **readiness-status ladder** for the question:

**Which readiness state are we actually in right now, and which note should govern next?**

That gap matters because institutions often ask the wrong question.
They ask **“Are we ready?”** as though readiness were a simple yes-or-no property.
But the archive now distinguishes several materially different states:
readiness that is currently evidenced, readiness that is known to be partial, readiness that is unknown because proof is stale, and situations where off-normal operation is already live.
Without a short ladder, readers must infer that structure by triangulating across several notes.
A compact archive needed one short bridge that compresses the cluster into a single front door.

This note is a **compression note**, not a new doctrinal branch.
Its job is to reduce the readiness cluster to four states and a conservative routing rule: classify honestly, route immediately, and when uncertain choose the more conservative state [S34][S55][S73][S83][S102][S103][S108][S109][S111][S112][S113][S114][S115][S145][S147].

## Fast rule

**Do not ask only “are we ready?” Ask which readiness state governs right now: proven ready, partial readiness, unknown readiness, or live detour. Then route to the governing note for that state, and if the classification is unclear choose the more conservative state.**

## The four readiness states

### 1. Proven ready
This is the state a serious climate institution may claim only when current evidence supports the claim.

What this means in practice:
- the core readiness duties are in place
- the critical joins, tools, contacts, and protection paths have current evidence behind them
- rehearsal and assurance are recent enough that the readiness claim is not inherited from old proof [S55][S83][S111][S113][S114][S145][S147]

Default route:
- keep `111` live as the standing readiness base
- use `113` to keep drills real
- use `114` to keep the claim evidentiary rather than ceremonial

### 2. Partial readiness
This is the state where important gaps are known, but they are known clearly enough that compensations can be declared and repair can be driven on a live clock.

What this means in practice:
- readiness is not being overclaimed
- the gaps are identified rather than hidden
- operating ambition, exposure, or complexity is reduced while repair is underway [S83][S103][S111][S114][S115][S147]

Default route:
- govern by `115`
- keep `114` as the truth test for what may still be claimed
- keep `111` and `113` as the repair target, not as the current description of reality

### 3. Unknown or stale readiness
This is the state where the institution cannot honestly tell whether readiness is still real, because checks are missing, evidence is stale, ownership drifted, or the critical path has not been verified recently.

What this means in practice:
- the problem is not yet a known gap but a loss of proof
- the correct default is not confidence but downgrade
- the first job is to verify the highest-consequence joins and protection paths [S73][S83][S102][S111][S113][S114][S116][S145]

Default route:
- govern by `116`
- downgrade status to not proven
- move quickly either toward `114` if proof is restored or toward `115` if meaningful gaps are confirmed

### 4. Live detour
This is the state where a tripwire has fired or a fallback, exception, or escalation path is already open.
Readiness classification still matters, but the governing task is now live discipline rather than readiness description.

What this means in practice:
- the system is already operating off-normal
- containment, protection, proof discipline, and closure conditions matter more than abstract status language
- the question is no longer whether the institution was ready enough in theory, but how the detour is being governed in fact [S34][S83][S103][S104][S108][S109][S110][S112][S147]

Default route:
- govern immediately by `112`
- use `108` to police dirty delay, fallback, or exception claims
- use `109` for closure discipline and `110` for learning and hardening afterward

## Routing rule

Use the smallest honest classification and route immediately:

1. **If proof is current and the critical path is evidenced, treat the state as proven ready.**
2. **If meaningful gaps are known, treat the state as partial readiness.**
3. **If evidence is stale or missing and status cannot be honestly stated, treat the state as unknown readiness.**
4. **If an off-normal path is already open, treat the state as a live detour.**

If the classification is contested or blurry, choose the **more conservative** state until evidence earns the upgrade.
That means:
- choose **unknown** over presumed ready
- choose **partial** over confident overclaim
- choose **live detour** over polite language that hides an already-open exception or fallback [S34][S83][S102][S108][S114][S115][S116][S147]

## Minimal status ladder

The smallest serious readiness ladder is:

- **proven ready** → governed mainly by `111`, `113`, `114`
- **partial readiness** → governed mainly by `115`
- **unknown readiness** → governed mainly by `116`
- **live detour** → governed mainly by `112`, then `109` and `110`

This is enough to stop the archive from collapsing several materially different situations into the vague phrase **“readiness concern.”**

**The archive now has a shortest readiness-status ladder: stop asking only “are we ready?” and instead classify the situation as proven ready, partial readiness, unknown readiness, or live detour. This compresses the growing readiness cluster into one front door without adding a new doctrinal branch.**
