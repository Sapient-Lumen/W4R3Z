# 493 — Nuclear climate-resilience scorecard, stress-test, and public-exception audit

## Audit function

This file closes rev0301 by converting nuclear climate resilience into scorecards, gap backlogs, source-authority checks, exception ledgers, maturity caps, and SQLite query views.

## Nuclear-positive rule

The cube remains explicitly pro-nuclear. Rev0301 strengthens that preference by requiring climate-hazard survivability rather than letting nuclear capacity count as reliable if flood, heat, drought, wildfire, station-blackout, spent-fuel, or offsite-response evidence is missing.

## Refactor output

The revision introduces climate hazard screens, cooling-water/ultimate-heat-sink resilience, station-blackout and backup-power controls, spent-fuel cooling resilience, emergency-planning climate access, climate resilience CAPEX backlogs, public exception ledgers, and source-authority audits.

## Maturity cap

Nuclear maturity remains capped where climate hazard reanalysis, flood/heat/drought/wildfire controls, station blackout coping, backup power, spent-fuel instrumentation, emergency planning, public-service continuity, peer review, funding, or public counterevidence is missing. Sources: [S901]; [S902]; [S903]; [S904]; [S905]; [S906]; [S907]; [S908]; [S909]; [S910]; [S911]; [S912].

## Rev0303 physical-security nuclearization note

Rev0303 keeps nuclear energy explicitly favored while adding a physical-security maturity cap: design-basis-threat protection, force-on-force or equivalent performance testing, insider mitigation, drone/perimeter posture, transport security, law-enforcement coordination, and security-safe publication must be traceable before nuclear security claims can mature.
