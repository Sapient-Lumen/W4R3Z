# 549 — Nuclear emergency preparedness: capture command board, go/no-go gates, loss caps, and post-exercise evidence triage

Revision: rev0342  
Status: compact canon / operational refactor  
Scope: Beaver Valley public-only pilot and generic nuclear-emergency-preparedness readiness machinery.  
Claim boundary: no real-site readiness, unreadiness, pass, fail, green, safe, sufficient, reasonable-assurance-ready, or closure claim is made.

## Why this revision exists

The cube now has strong branch proof spines: alert authorization, delivery, field receipt, protective-action uptake, CRC/decon, first receivers, dose/PAR, ingestion controls, recovery, responder sustainment, cyber/data continuity, lifelines, COP/handoff, exercise realism, finding/CAP closure, and an integrated claim kernel.

The remaining near-term risk is operational: the June 2026 exercise window can pass while the cube has a long list of desired packets but no short command path that says who captures which fragile evidence, when, what happens if it is missing, and which public claims remain frozen until adjudication.

Rev0342 turns the broad claim kernel into a time-boxed capture command board.

## Hard rule

A public notice, public meeting, preliminary finding statement, AAR paragraph, evaluator summary, controller note, MSEL event, extent-of-play statement, PI page, dashboard, source ID, duplicate URL, redacted surrogate, or complete-looking local packet can demand, cap, route, contradict, or reopen a claim. It cannot automatically close local emergency-readiness evidence.

## Operational route

```
exercise clock
→ pre-exercise go/no-go gate
→ capture command board
→ minimum evidence-bag cutline
→ owner/backup capture roster
→ loss cap if missing or late
→ preliminary finding / public meeting shield
→ final AAR/IP diff and finding parser
→ CAP/redemonstration/verifier queue
→ integrated claim kernel release gate
```

## Minimum capture cutline

The new capture command board ranks must-capture evidence by fragility and claim consequence. The highest-priority artifacts are raw alert logs, PAD/PAR decision logs, originator authority records, IPAWS ACK/ERROR evidence, EAS/WEA/local-channel evidence, field receipt/nonreceipt probes, public-message diffs, evaluator observations, controller/simcell intervention logs, action-uptake evidence, CRC/first-receiver observations, dose/model/field-monitoring traces, sampling/lab custody, lifeline status, cyber/data continuity proof, COP/handoff packets, and finding/CAP/redemonstration lineage.

If a P0 capture packet is missing, the default is not neutral. The default is a claim cap.

## Public meeting and preliminary findings

The June public meeting is treated as a lockbox and capture clock. It can provide a transcript, audio/video hash, preliminary statement, Q&A, correction, or contradiction. It cannot close a finding or readiness row.

## Refactor value

Earlier revisions produced many branch-specific proof requirements. Rev0342 compresses them into owner-actionable capture work. It answers: what must be collected during the exercise window, what breaks if it is absent, who owns it, and which claim phrases remain forbidden.

## Remaining hard gap

No real or anonymized June 2026 exercise packet has been imported. The next material step is to run real/anonymized packets through the rev0342 command board and classify each as rejected, held, context-only, reopen, or candidate-for-adjudication.
