# 102 — Ideal Solutions: Four Governing Clocks for a Serious Climate State

## Claim

The archive already has:
- a one-page answer (`58`)
- a compact package note (`57`)
- an action-grammar note (`99`)
- an execution-lanes note (`100`)
- and a steering-levers note (`101`)

What it still lacked was the shortest **time-structure note** for the question:

**What recurring clocks should a serious climate state actually run on if it wants the programme to keep moving without living in permanent improvisation?**

That matters because many readers do not first need more sectors, more verbs, or more levers.
They need the smallest reusable picture of **how the programme stays live over time**.

This note is a **compression note**, not a new doctrinal branch.
Its job is to reduce the archive to four governing clocks that public authority should keep running at once.

## Fast rule

**A serious climate state runs on four clocks at once: a fast incident clock, a pipeline clock, a ratchet clock, and a turnover clock.**

## Four governing clocks

### 1. Fast incident clock
Run a rapid-response clock for failures, shocks, and fast-moving harms that cannot wait for the next budget cycle or standards review.

What this usually includes:
- methane super-emitters, routine venting and flaring, and other fix-now operational leakage
- heat, fire, smoke, flood, drought, outage, and public-health stress
- interconnection bottlenecks, delivery failures, and obvious underperformance that can be corrected quickly once visible [S103][S104][S106][S111][S133][S147]

Why it matters:
- some climate gains and protections are short-latency, and serious institutions should capture them fast rather than treating everything as a slow planning exercise
- visible fast correction also protects trust while slower backbone work is still being built [S101][S106][S133][S134]

### 2. Pipeline clock
Run a quarterly or otherwise regular pipeline clock for the buildout machinery that has to keep moving even when there is no headline emergency.

What this usually includes:
- procurement rounds, grid and interconnection queues, permitting backlogs, training intakes, retrofit pipelines, finance windows, and project connection calendars
- visible backlogs, queue discipline, and standard operating cadences that turn climate ambition into investable and trainable signal [S55][S103][S117][S180][S181][S182]

Why it matters:
- climate programmes fail when the workstream exists only as aspiration and not as a maintained delivery pipeline
- supply chains, labour, local government, and finance institutions scale more readily around predictable calendars than around sporadic announcement bursts [S117][S180][S181]

### 3. Ratchet clock
Run an annual or scheduled review clock for tightening standards, budgets, targets, and programme rules in light of real performance.

What this usually includes:
- code updates, appliance and vehicle standards, methane rules, procurement volumes, public-finance terms, retirement schedules, and other reviewable defaults
- scoreboards, measurement, remedy, and correction loops that let the state tighten what is working and fix what is not [S34][S65][S111][S113][S114][S181][S183]

Why it matters:
- without a ratchet clock, early gains plateau, weak rules stay weak, and programmes drift into ceremony or subsidy habit
- the point of measurement is not only to observe but to trigger correction and upward revision [S34][S111][S113][S114]

### 4. Turnover clock
Run a standing capture clock for natural replacement, sale, rebuild, and renewal moments when dirty or fragile capital stock is already about to change.

What this usually includes:
- heating-system replacement, vehicle and fleet renewal, roof and equipment replacement, building renovation, rental turnover, industrial reinvestment, and post-disaster rebuilding
- codes, procurement rules, standard offers, and finance structures that make the cleaner replacement win at the moment when capital is already turning over [S50][S81][S82][S83][S84][S161][S162][S163][S164]

Why it matters:
- many climate failures come from simply missing the moment and locking in another dirty cycle
- turnover capture is often cheaper and more durable than trying to reverse a fresh dirty investment after the fact [S50][S161][S162]

## What this note changes in practice

When a proposal claims to be an ideal climate solution, ask not only what lane it belongs to or which steering lever moves it.
Ask **which governing clock is supposed to keep it live**.

If it depends only on the annual budget clock, it is probably too slow.
If it has no pipeline clock, it is probably theatre.
If it has no ratchet clock, it will probably stall.
If it ignores turnover moments, it will probably miss the cheapest durable wins.
If it cannot survive fast incident pressure, it is not robust enough for the world it is entering.

The best programmes therefore assign for each clock:
- an accountable owner
- a visible cadence
- a small scoreboard
- and an escalation rule when performance slips

This note therefore sits in a distinct place:
- `100` says how the programme is best split into parallel **execution lanes**
- `101` says what public authority mostly **uses to steer those lanes**
- `102` says on what recurring **clocks** the programme must keep running so those lanes and levers do not decay into one-off campaigns
