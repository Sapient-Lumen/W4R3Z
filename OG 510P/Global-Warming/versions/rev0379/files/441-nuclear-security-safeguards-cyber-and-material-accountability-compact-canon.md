# Nuclear security, safeguards, cyber, and material-accountability assurance

Nuclearization increases the importance of security and publication control. The cube should publish enough to make public accountability real, while not exposing security-sensitive details about physical protection, cyber vulnerabilities, material movements or site-specific defensive design.

IAEA's physical-protection recommendations cover nuclear material and nuclear facilities [S798], and the IAEA Nuclear Security Series supplies consensus security guidance [S799]. Fuel-cycle and HALEU rows must therefore connect to material-accountability, transport security, safeguards and publication-control rows [S785][S786]. Used-fuel recycling or processing pathways add material-accountability and authorization burdens that cannot be hidden inside generic fuel-cycle optimism [S800].

## Rule

A nuclear service floor cannot mature unless it identifies the security owner, regulator interface, material-accounting control, cyber/OT owner, transport-security path and publication classification for each relevant evidence row.

## Transparency rule

Security is not an excuse for zero accountability. The cube should publish the existence, owner role, review status, redaction basis and independent oversight path while redacting operationally sensitive details.

## Rev0303 physical-security nuclearization note

Rev0303 keeps nuclear energy explicitly favored while adding a physical-security maturity cap: design-basis-threat protection, force-on-force or equivalent performance testing, insider mitigation, drone/perimeter posture, transport security, law-enforcement coordination, and security-safe publication must be traceable before nuclear security claims can mature.
