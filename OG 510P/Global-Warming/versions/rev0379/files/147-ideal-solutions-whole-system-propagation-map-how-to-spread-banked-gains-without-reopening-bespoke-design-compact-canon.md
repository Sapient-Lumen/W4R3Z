# 147 — Ideal Solutions: Whole-System Propagation Map — How to Spread Banked Gains Without Reopening Bespoke Design Compact Canon

## Claim

The archive already has a mature whole-system set:
- a static layer map (`136`)
- a feedback map (`137`)
- a scoreboard map (`138`)
- a control-surface map (`139`)
- a sequencing map (`140`)
- a boundary map (`141`)
- a diagnosis map (`142`)
- a remedy map (`143`)
- a verification map (`144`)
- a second-pass map (`145`)
- and a stabilization map (`146`)

That is now enough architecture, causality, signals, leverage, order-of-attack, boundary structure, failure-location logic, first-correction logic, correction-check logic, failed-correction logic, and gain-banking logic that the next clean gain is **not** another narrow sector note.
What it still lacked was the shortest joined note for the next practical scaling question:

**if a correction works and is banked into routine in one place, asset class, agency, utility, or programme lane, how should a serious climate programme spread that gain across similar contexts without reopening bespoke design from zero every time?**

This note is a compression note, not a new doctrinal branch.
Its job is to gather the archive’s copyability rule, place-sensitivity rule, routinization rule, design-kernel rule, physical-portfolio rule, delivery rule, truth rule, governing-kernel rule, stabilization rule, and scoreboard rule into one first-stop propagation map [S47][S53][S55][S71][S73][S122][S124][S128][S130][S132][S133][S138][S146][S150][S151][S172][S173][S180][S181][S182][S183].

## Fast rule

**Do not spread anecdotes; spread stabilized patterns. Once a correction has been verified and banked, translate it into a reference design, standard offer, default contract, operating checklist, metric set, and delivery package that similar places can adopt with minimal reinvention. Copy the core, adapt the edges, pre-clear the bottlenecks, and keep the same proof gates so propagation increases speed without diluting truth.**

## The compact propagation map

### 1. Propagate only after the gain is stabilized, not after the first encouraging anecdote
A serious programme should not treat one calm month, one successful pilot, or one charismatic site as proof that a correction is ready for broad copying.
Propagation should start **after** the archive’s verification and stabilization tests are met:
- the targeted weak signal has actually improved in the governed data
- the gain has been locked into routine standards, budgets, contracts, and accountability
- the improvement looks durable enough that copying it will not merely multiply noise [S124][S133][S138][S144][S146].

### 2. Spread the pattern, not the story
The thing to propagate is not the tale of a good project.
It is the **copyable unit** that made the result possible:
- the reference design
- the standard operating rule
- the default contract form
- the eligibility rule
- the metric set
- the commissioning checklist
- the remedy path when performance drifts [S47][S71][S73][S124][S133][S150][S151].

Propagation gets cheaper when institutions can pick up a usable package rather than a case study that still has to be reinterpreted from scratch.

### 3. Keep the invariant core, adapt the place-sensitive edges
A propagated correction should travel with a stable causal core but should not pretend every place is identical.
The archive’s place-sensitive rule still governs:
- copy the causal mechanism
- adapt the siting, interface, financing mix, staffing path, user pathway, and fallback provisions to local conditions
- keep the proof standard and performance expectation stable enough that propagation does not become a cover for quality drift [S53][S130][S132][S133][S172][S173].

In practice:
- a clean-heating standard offer can travel, but building archetypes and labour mixes will vary
- a grid-upgrade playbook can travel, but topology, queue rules, and regulatory venue will vary
- an early-warning package can travel, but hazard mix, communication channels, and institutional owners will vary

### 4. Move bottlenecks and proof together
Propagation fails when the archive copies the offer but not the enabling conditions.
A serious programme should therefore propagate:
- the delivery package
- the finance or tariff path
- the procurement or interconnection rule
- the workforce and supplier assumptions
- the measurement protocol
- the recourse and correction path [S71][S73][S124][S132][S133][S150][S180][S181].

If the first site had unusual staff attention, extra grant support, bespoke analytics, or heroic troubleshooting, the propagated package should either reproduce those supports honestly or redesign the package so it no longer needs them.

### 5. Insert propagation into existing cadences instead of treating it as another special campaign
The cheapest way to spread a working correction is to put it into rhythms institutions already have:
- regular procurement rounds
- recurring standards updates
- rate cases and planning cycles
- maintenance windows
- capital-replacement decisions
- training intakes
- NDC, utility, or budget cycles [S55][S124][S140][S180][S181][S182][S183].

Propagation should therefore prefer **calendarized uptake** over another burst of ad hoc enthusiasm.

### 6. Score propagation by outcome quality, not by adopter count alone
A copied correction is not a success merely because many jurisdictions, agencies, or sites now claim to use it.
The archive’s scoreboard and truth rules still govern:
- are the targeted weak signals improving in the new sites
- are service gains holding
- are bottlenecks shrinking
- are burdens being shifted onto weaker actors
- is the copied package still passing the same proof gates [S133][S138][S141][S144][S146].

If diffusion increases nominal adoption but weakens outcome quality, the programme should slow, re-diagnose, and tighten the propagated package rather than celebrating scale for its own sake.

## One-paragraph compression

**Once a correction has been verified and banked into governed routine, the next ideal move is to spread the stabilized pattern across similar contexts without reopening bespoke design from zero: copy the causal core, package it as a reference design and default offer, adapt the edges to place, propagate delivery conditions and proof with the offer, embed uptake in ordinary institutional cadences, and judge diffusion by outcome quality rather than raw adopter count.**
