# Nuclear assurance traceability matrix and preference red-team audit

A nuclear-positive cube needs a red team. The point is not to make the cube neutral again; the point is to make the preference honest. A declared preference should have a traceability matrix showing which source, file, service floor, claim, gate, owner, evidence item, public challenge path and maturity cap supports each nuclear decision.

Rev0291 adds that audit surface. General sources that support nuclear as a clean-firm technology cannot be misused as certification of a particular reactor, site, fuel contract, emergency plan, security posture or host-community agreement. Regulatory and public-participation sources must be tied to project-specific evidence before they lift maturity [S793][S794]. Waste-consent and security sources set hard constraints rather than public-relations talking points [S796][S798][S799].

## Rule

Every nuclear-favored floor should be traceable across:

- policy preference;
- service floor;
- assurance gate;
- claim;
- evidence class and source;
- owner role;
- public challenge/redress path;
- exception or unresolved counterargument;
- maturity cap.

## Red-team default

A nuclear pathway with no counterargument row is not more mature; it is less audited.
