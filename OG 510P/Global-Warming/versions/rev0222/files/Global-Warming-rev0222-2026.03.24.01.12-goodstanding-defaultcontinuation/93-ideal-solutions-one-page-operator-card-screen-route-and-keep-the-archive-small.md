This note adds that card.
It is a compression note, not a new doctrinal branch.
If the remaining question is simply where to start in the archive at all, go next to `94-ideal-solutions-archive-topology-layers-best-first-stops-and-preferred-reading-order.md`.

## Fast rule

**Screen the object, assign a disposition, then choose the smallest archive action that fits.**

Do not let curiosity skip screening.
Do not let promotion automatically create a file.
Do not let refusal create clutter.

## The one-page sequence

### 1. Frame the object
Ask first what kind of thing this is:
- a core physical climate lane
- a supporting delivery or governance layer
- a context-specific tool
- or mostly noise, symbolism, or paper substitution

A badly framed object wastes the whole rest of the procedure.

### 2. Fail fast on obvious red flags
Go next to `89-ideal-solutions-compact-negative-canon-red-flags-and-recurring-failure-modes.md`.
Ask whether the proposal clearly:
- substitutes paper for physics
- delays near-term cuts behind later cleanup stories
- misuses scarce tools
- has no dirty-retirement story
- dumps burdens onto weak actors
- fragments accountability
- socializes downside while privatizing upside
- or survives mainly on loopholes, waivers, announcements, or pilot exceptionalism

If the answer is clearly yes on several of these, do **not** force a full positive-canon reading just to be polite. [S100][S101][S102][S103][S104][S106][S118][S119][S123][S143][S146][S147]

### 3. Run the core screens on survivors
Go next to `88-ideal-solutions-compact-canon-core-screens-in-one-place.md`.
Use the archive's default order:
1. physical portfolio
2. justice
3. time
4. leverage design
5. user pathway
6. trust and accountability
7. place and scarcity
8. edge conditions
9. delivery reality

Early failures matter more than late elegance.
A proposal that fails physics, justice, or time should rarely be rescued by administrative polish. [S100][S101][S102][S103][S104][S106][S118][S119][S123][S143][S146][S147]

### 4. Assign a disposition
Use the archive's shortest dispositions:
- **promote** — canon-compatible and genuinely strong
- **demote** — useful but secondary, local, or non-central
- **quarantine** — maybe important later, but unstable or weakly proved now
- **refuse** — mirage, restatement, or clear screen failure

For the archive's shortest disposition screen, see `59-ideal-solutions-fast-screen-promote-demote-quarantine.md`.

### 5. Map disposition to archive action
Use `92-ideal-solutions-routing-matrix-from-disposition-to-archive-action.md`.
The shortest defaults are:
- **promote** → edit, compress, or cross-link first; add only for true net-new value
- **demote** → clarify boundaries inside existing notes
- **quarantine** → isolate and state the promotion trigger
- **refuse** → usually do nothing

### 6. Apply the archive-growth rule last
Only after screening and routing should the archive ask whether it should grow.
Use `90-ideal-solutions-archive-admission-rule-add-only-net-new-screens-boundaries-or-compression.md`.
A new main-canon file should usually appear **only** when the proposal:
- adds a net-new screen
- clarifies a decision-changing boundary
- or creates real compression that lowers navigation cost

## Default stop rules

- stop early when red flags are already decisive
- do not mistake interest for admissibility
- do not turn refusal into a genre of archive output
- do not let quarantine drift into half-admission without a clear trigger
- do not add a file when an edit or cross-link would say the important thing

## One-paragraph compression

**The archive now has a one-page operator card: frame the object, fail fast on red flags, run the compact positive screens on whatever survives, assign a disposition, map that disposition to the smallest fitting archive action, and only then ask whether the canon should grow. That keeps future intake harsh on mirages, fair to promising ideas, and disciplined against archive growth by restatement.** [S100][S101][S102][S103][S104][S106][S118][S119][S123][S143][S146][S147]
