## The operating loop

### 1. Define the answer
Open `58-ideal-solutions-one-page-answer.md`.

Start with the archive’s shortest answer:
ideal solutions are not one technology, one offset market, one carbon price by itself, or one future removal promise.
They are a physical-first programme that cuts emissions fast, lowers overshoot risk, protects people directly, and can actually be delivered.

This keeps the loop anchored to outcomes rather than ideology.

### 2. Shape the package
Open `57-ideal-solutions-reference-portfolio-2026-2035.md`.

Turn the answer into an actual programme package.
The package should combine clean buildout, efficiency, electrification, methane cuts, industrial transition, demand shaping where useful, ecosystem protection, and protection/adaptation where harms are already arriving.

This keeps the answer from collapsing into slogan or single-instrument fantasy.

### 3. Screen and design it seriously
Open `97-ideal-solutions-design-spec-ten-acceptance-tests-for-a-serious-climate-package.md`, then `98-ideal-solutions-seven-design-directives-for-the-whole-archive.md`, then `99-ideal-solutions-seven-action-verbs-for-a-serious-climate-program.md`.

Now ask:
- does the package pass the seriousness tests?
- does it look like the archive’s preferred design grammar?
- does it mostly do the right things in verbs simple enough to remember and reuse?

This keeps the package from being merely broad instead of actually serious.

### 4. Govern routine delivery through the kernel
Open `124-ideal-solutions-governing-kernel-compact-canon.md`.

Run the programme in ordinary time through:
- execution lanes
- steering levers
- governing clocks
- accountable roles
- decision rights
- and precedence rules

This is the archive’s smallest normal-time governing picture.

### 5. Keep readiness live even when routine looks calm
Open `122-ideal-solutions-readiness-state-machine-compact-canon.md`.

Routine governance is not enough.
A serious climate state should keep readiness live, classify readiness honestly, promote only on proof, demote when stronger claims no longer govern, suppress ceremonial flapping, and resolve readiness disputes conservatively.

This keeps apparent calm from silently becoming unpreparedness.

### 6. Enter a detour only through explicit tripwires and proof gates
Open `123-ideal-solutions-off-normal-state-machine-compact-canon.md`.

When routine governance is no longer enough, do not improvise.
Tripwires should be visible.
Dirty delay, fallback, or exception should be narrow, time-bounded, and proof-gated.
The detour should exist only to protect people and restore the clean mainline.

This keeps bad-day governance from becoming a loophole machine.

### 7. Govern the detour tightly, then close it fast
Still in `123`, hold the detour to live discipline, return-to-routine tests, and after-action duties.

While the detour is open:
- keep protections live
- keep proof current
- keep scope narrow
- keep the clean mainline repair clock running

Then close the detour as soon as the return tests are satisfied.

This keeps the exception from becoming a shadow policy regime.

### 8. Convert every detour into harder routine
After the detour closes, use after-action learning to repair the mainline, tighten readiness, improve proof gates, and reduce recurrence risk.

The loop therefore does not end where it started.
It should end with a stronger normal state than before.

That is the archive’s preferred ratchet:
**bad days should teach the system how to need fewer bad-day moves next time.**

## One-paragraph compression

**The whole archive can now be held as one loop: define the answer, shape the package, screen/design it seriously, govern routine delivery through the state kernel, keep readiness honest even in calm periods, enter off-normal operation only through visible proof-gated triggers, run the detour tightly, close it quickly, and convert every incident into harder routine. That is the smallest dynamic picture that still carries the archive’s full logic.**

**If you want the archive as a system rather than a bookshelf, use this loop before reopening the deeper tree.**
