## Why this change

The archive already had strong older notes on copyable systems, standardisation, interoperability, modularity, and routinized delivery, but it still lacked one joined front-door canon for a scaling question that keeps returning in practice:

**what should ideal solutions look like if they must spread across many places fast without bespoke redesign each time?**

The new note compresses that answer into one place: prefer climate measures that can travel as repeatable forms — stable core logic, common metrics and interfaces, standard contracts and workflows, modular units where sensible, one-stop administrative paths, and visible recurring delivery cadence — while reserving bespoke design effort for the genuinely exceptional edge.
