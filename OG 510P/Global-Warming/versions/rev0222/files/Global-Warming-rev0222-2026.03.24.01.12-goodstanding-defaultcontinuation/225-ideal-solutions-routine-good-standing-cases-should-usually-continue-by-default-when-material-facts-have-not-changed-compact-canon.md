# 225 — Ideal Solutions: Routine Good-Standing Cases Should Usually Continue by Default When Material Facts Have Not Changed

## Claim

The archive already says the clean path should usually start with one informed yes (`218`), survive ordinary life events rather than reset to dirty defaults (`219`), carry the right continuity packet across handoffs (`220`), reuse existing records instead of repeated proof (`72`), and reach users as a drafted clean offer rather than a blank self-assembly task (`224`).
One more compact front-door rule belongs in the canon:

**if the case is in good standing and no material facts have changed, the clean path should usually continue by default with delta-only updates rather than expiring into full reapplication, rediscovery, and dirty reversion.**

In plain terms:
- routine renewals, recertifications, support continuations, maintenance relationships, tariff enrollments, service contracts, and other ordinary continuations should not restart from zero when the key facts are still materially the same [S72][S74][S75][S77][S118][S119][S143]
- when some update is needed, the stronger design usually asks only for the delta — what changed, not the whole story again [S72][S77][S118][S119]
- and lapse, delay, or missed routine paperwork should not quietly become a path back to the dirtier baseline when the case could have been continued, reminded, corrected, or briefly held instead [S74][S75][S79][S80][S118][S119][S143][S144]

So the shortest rule is:

**continue by default when nothing material changed; ask for deltas, not full restart.**

This note answers something narrower and later:

**what should happen at routine continuation time when the case is already live and nothing material has changed.**

## The compact canon

### 1. Expiration cliffs are usually hidden burden-shifting
A programme can look continuous on paper while behaving like a stop-start maze in practice.
If routine eligibility, service, or support expires by default and the weaker party has to rebuild the case from zero to keep the clean state alive, the burden has simply been shifted downstream again [S72][S75][S79][S118][S119][S143].

House rule: **treat arbitrary expiration cliffs as a friction cost, not as neutral administration.**

### 2. No material change should usually mean default continuation
If the person, place, account, building, tariff class, landlord relationship, or service need has not changed in a way that matters to the programme’s integrity, the stronger design is usually continuation, not restart [S72][S75][S77][S118][S119][S143].

House rule: **same case, same standing, same path — unless a real reason for review exists.**

### 3. When updates are needed, ask for the delta
Sometimes facts do change: income band, tenancy, ownership, damage state, equipment condition, account holder, or site characteristics.
Even then, the system should usually ask what changed and verify only the changed part instead of forcing the full story to be retold and re-proved [S72][S77][S118][S119].

House rule: **update the changed field, not the whole case.**

### 4. Grace, reminder, and assisted correction usually outrank hard drop
Routine steps get missed.
Mail is lost. Portals fail. Administrators change. Tenants move mid-process. Small institutions miss a date.
The stronger programme usually tries reminder, grace period, assisted correction, or temporary hold before it lets a routine miss become a hard stop that pushes the case back toward dirtier fallback conditions [S74][S75][S79][S80][S118][S119][S143][S144].

House rule: **degrade softly before you eject.**

### 5. Review triggers should be explicit and material
Default continuation is not the same as no oversight.
The archive still wants clear review triggers where integrity, cost, safety, or fit could have changed materially.
But those triggers should be published, narrow, and connected to real differences, not to administrative habit or yearly ritual for its own sake [S71][S72][S75][S118][S119][S143].

House rule: **review because something material changed, not because the calendar turned.**

### 6. The default should preserve the cleaner state, not the old fallback
If routine continuation fails, the system should still prefer interim arrangements that keep the cleaner state alive or make return easy, rather than using procedural lapse as an excuse to reinstall the dirtier default [S74][S75][S79][S80][S82][S118][S119][S143][S144].

House rule: **when continuity is in doubt, hold the cleaner state if honesty allows.**

## Preferred use

Open this note first when the live question is any of the following:
- what should happen at renewal, recertification, or routine continuation when nothing material has changed
- whether a climate programme is too dependent on repeated reapplication, annual proof loops, or hard expiration cliffs
- how the archive thinks about “good standing” once a household, tenant, school, clinic, small firm, or municipality is already inside the cleaner path
- whether a proposal still makes people retell and re-prove the same case just to keep a working clean arrangement alive
- what should distinguish a real integrity review from pointless administrative churn

Then reopen `72`, `74`, `75`, `77`, `79`, or `220` only if the deeper sub-question survives.

## Compression rule

**Ideal climate solutions should usually keep routine good-standing cases live by default when material facts have not changed. Ask for deltas, use reminder and grace before hard drop, and do not let routine continuation failures become a quiet path back to the dirtier baseline.**
