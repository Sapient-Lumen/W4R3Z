## Fast rule

**Do not grade a correction by announcement, spending, or activity. Grade it by whether the weak signal that triggered the correction is now improving at the layer you said was failing. If the failing layer was truth, proof quality and comparability should improve. If it was throughput, the choke point should loosen in the actual queue, permit, commissioning, or turnover data. If it was burden or uptake, completion, retention, and user-friction indicators should improve for the intended population. If it was protection, exposure and service-loss indicators should improve where risk was highest. If it was governance or readiness, latency, ownership clarity, drill performance, and detour discipline should improve. If it was cross-border friction, capital cost, rule alignment, supply reliability, or sector-regime compliance should improve. If the targeted weak signal does not improve, do not celebrate the correction as a success. Diagnose again, tighten the remedy, or escalate.**

## The compact verification map

### 1. If the truth layer was corrected, proof quality should improve before narrative confidence does
When the first correction targeted the truth layer, the verification question is not whether reporting volume rose.
It is whether claims became more measurable, comparable, auditable, and correctable.

Verification usually looks like:
- fewer ambiguous definitions, scope gaps, and baseline games
- shorter lag from underperformance to visible correction
- stronger agreement between dashboards, field evidence, and physical outcomes
- weaker dependence on self-serving labels, weak credits, or unaudited claims

### 2. If throughput was corrected, the choke point should actually loosen
When the first correction targeted throughput, the verification question is not whether programmes got louder.
It is whether the next binding bottleneck loosened in the real pipeline.

Verification usually looks like:
- shorter waits in queues, permits, procurement, interconnection, or commissioning
- higher share of projects reaching completion rather than recycling in delay
- more turnover at the asset classes the correction was supposed to release
- less spillback from one bottleneck into the next adjacent bottleneck

### 3. If burden or uptake was corrected, completion and retention should improve for normal actors
When the first correction targeted burden or uptake, the verification question is not whether people liked the announcement.
It is whether more normal actors actually completed the clean path and stayed on it.

Verification usually looks like:
- higher take-up and completion among the intended users, especially the previously under-served
- lower abandonment, fewer reimbursement failures, and fewer stalled handoffs
- better retention, performance, and user satisfaction after delivery
- less evidence that the weak actor is still acting as system integrator by hand

### 4. If protection was corrected, exposed people and lifelines should actually be safer
When the first correction targeted protection, the verification question is not whether adaptation plans multiplied.
It is whether exposure, outage, loss, and continuity indicators improved where risk was highest.

Verification usually looks like:
- fewer dangerous service interruptions under heat, smoke, flood, drought, or storm stress
- better continuity for water, health, cooling, communications, and power in high-risk places
- lower repeat losses or less extreme harm from similar events
- narrower dependence on brittle fallback arrangements

### 5. If governance or readiness was corrected, response quality should improve in live operation
When the first correction targeted governance or readiness, the verification question is not whether new charts were published.
It is whether the state now detects, classifies, escalates, and governs with less drift.

Verification usually looks like:
- shorter detection-to-response latency
- clearer ownership and fewer unresolved authority collisions
- more honest readiness classification and less flattering overclaim
- narrower, more disciplined detours and better return-to-routine performance

### 6. If cross-border friction was corrected, external constraints should actually ease
When the first correction targeted cross-border friction, the verification question is not whether there are more communiques.
It is whether the external binding constraint loosened in money, rules, or supply.

Verification usually looks like:
- lower cost of capital, better debt room, or faster financial close where finance was binding
- stronger standards alignment and less rule fragmentation where interoperability was binding
- more reliable cleaner supply availability where import dependence or bottlenecked components were binding
- stronger compliance in leakage-prone or international sectors where unilateral ambition alone was previously failing

## Smallest useful reading pattern from this map

If the mature programme has already launched a first correction:
1. read `142` only if the likely failing layer is still uncertain
2. read `143` to confirm that the first correction class matches the diagnosed failure layer
3. read this note (`144`) to decide what improvement would actually count as proof that the correction worked
4. reopen `138` to watch the targeted weak signal rather than the most flattering activity metric
5. reopen `141` if the apparent success depends on paper substitution, dirty convenience, or a weak exception
6. if the targeted weak signal is not improving, re-diagnose or escalate rather than relabeling the correction as success

## Boundary

**Do not score a correction by implementation theatre, administrative motion, or narrative comfort. Score it by whether the targeted weak signal improved at the layer that was supposed to be fixed.**
Do not answer failure of verification with broader claims, and do not declare the programme back on track because adjacent signals improved while the targeted weak signal stayed weak.
