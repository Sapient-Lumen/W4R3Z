## The operating sequence

### 0. Frame the object correctly
Before screening, ask what kind of thing this is.
Is it:
- a core physical climate lane
- a supporting delivery or governance layer
- a context-specific tool
- or mostly noise, symbolism, or paper substitution

Bad framing causes wasted screening effort.
A nice supporting measure should not be mistaken for a core climate lane, and a peripheral idea should not be promoted as though it were central.

## 1. Fail fast on red flags
Go first to `89-ideal-solutions-compact-negative-canon-red-flags-and-recurring-failure-modes.md`.
Ask whether the proposal is obviously weak because it:
- substitutes paper for physics
- delays near-term cuts behind later cleanup stories
- misuses scarce tools
- tells a clean-build story with no dirty-retirement story
- dumps burden onto users
- fragments accountability
- socializes downside while privatizing upside
- relies on loopholes, waivers, or temporary dirty bridges that have no real sunset
- works only in unusually affluent or pilot conditions
- or proves success mainly through announcements rather than outcomes

If **two or three strong red flags** are already present, the default should usually be **demote or quarantine** rather than full positive screening.
Do not spend large evaluation effort rescuing obvious mirages. [S100][S101][S102][S103][S104][S106][S118][S119][S123][S143][S146][S147]

## 2. Run the core screens on survivors
If the proposal survives the fast red-flag pass, run `88-ideal-solutions-compact-canon-core-screens-in-one-place.md` in order.
The archive's default screening order is:
1. physical portfolio
2. justice
3. time
4. leverage design
5. user pathway
6. trust and accountability
7. place and scarcity
8. edge conditions
9. delivery reality

Early failures matter more than late polish.
A proposal that fails the physical, justice, or time screens should rarely be rescued by elegance elsewhere.
Likewise, a proposal that sounds attractive in principle but fails user-pathway, trust, or delivery-reality screens should usually not be promoted as a serious ideal solution. [S100][S101][S102][S103][S104][S106][S118][S119][S123][S143][S146][S147]

## 3. Assign a disposition
After screening, route the proposal deliberately.

### Promote
Promote when the proposal:
- belongs clearly in a core physical lane or an indispensable delivery layer
- passes most core screens without major red flags
- is physically real, scalable, and not dependent on heroic assumptions

### Demote
Demote when the proposal:
- is useful but secondary, local, partial, or too context-bound to serve as a main-canon answer
- helps around the edges but should not carry core explanatory weight

### Quarantine
Quarantine when the proposal:
- may matter, but proof is still thin
- has high scarcity cost, high loophole risk, or weak delivery evidence
- could deserve later promotion but is not yet stable enough for strong canon treatment

### Refuse
Refuse when the proposal:
- is mostly restatement, symbolism, or paper substitution
- fails early core screens badly
- or triggers strong negative-canon warnings without a convincing rescue case

For the archive's shortest existing disposition screen, see `59-ideal-solutions-fast-screen-promote-demote-quarantine.md`. For the shortest routing bridge from disposition to archive action, see `92-ideal-solutions-routing-matrix-from-disposition-to-archive-action.md`.

## 4. Decide what to do with the archive
Only after the proposal has been routed should the archive decide whether to grow.
Go next to `90-ideal-solutions-archive-admission-rule-add-only-net-new-screens-boundaries-or-compression.md`.

The default question is not “is this interesting?”
The default question is:
**does this deserve a new main-canon file?**

Usually the answers should be:
- **add a new file** only for a net-new screen, a decision-changing boundary, or a real compression
- **edit an existing file** when the idea is useful but not net-new
- **cross-link only** when guidance already exists and the new material mainly improves findability
- **do nothing** when the archive already says the important thing

See `92-ideal-solutions-routing-matrix-from-disposition-to-archive-action.md` for the shortest joined default mapping from disposition to archive action.

## The shortest operator checklist

When reading a new proposal, ask in order:
1. What kind of object is this?
2. Does it trip obvious red flags quickly?
3. Which core screens does it pass or fail?
4. Is it promote, demote, quarantine, or refuse?
5. Even if it matters, does the archive need a new file for it?

That is the archive's shortest joined intake workflow.
If you want the same sequence compressed to a single keep-open note, go next to `93-ideal-solutions-one-page-operator-card-screen-route-and-keep-the-archive-small.md`.
