## Fast rule

**Do not stop at retirement. Once the inferior path is no longer the default, keep it from quietly returning: watch for re-entry signals, keep the better path easier and safer to stay on than the old path is to revive, treat any re-entry as an explicit off-normal event rather than silent routine, harden handoffs and turnover moments where regression usually reappears, and close new loopholes before they normalize.**

## The compact regression-prevention map

### 1. Assume regression pressure persists after retirement
A serious programme should not treat retirement as the end of pressure from the inferior path.
Old paths try to return through ordinary institutional channels:
- the budget cut that quietly restores the cheaper dirty shortcut
- the procurement reset that reopens the older spec
- the reliability scare that normalizes the old fallback
- the staffing gap that revives manual workarounds
- the hardship carve-out that becomes the ordinary route back [S46][S75][S84][S85][S131][S148].

Retirement is therefore not the finish line.
It is the beginning of a new discipline: **keep the superior path normal enough that re-entry pressure cannot easily reinstall the inferior one.**

### 2. Watch explicit re-entry signals, not only the continued growth of the better path
A programme should not assume the inferior path is gone merely because the cleaner path remains large.
The truth and scoreboard rules should watch for re-entry signals such as:
- rising waiver or exception use
- fallback being invoked more often or for weaker reasons
- dirty asset replacement share creeping back up
- queue priority, subsidy, or contract preference quietly returning to the older path
- handoffs, rebuilds, outages, or stress periods resetting users into inferior defaults [S75][S84][S85][S133][S138][S141][S148].

Regression often starts at the edges before it reappears in the centre.
A serious programme should score the return path itself, not merely celebrate continued headline adoption of the cleaner one.

### 3. Keep the better path easier to stay on than the old path is to revive
Regression prevention is not mainly rhetorical.
It is practical.
A serious programme should make the superior path easier to maintain than the inferior path is to restore:
- preserve affordability, repair, maintenance, and staffing for the better system
- keep the better contract, tariff, or default offer as the ordinary baseline
- protect spare parts, software support, service channels, and training for the cleaner path
- make any attempted return to the older path slower, more visible, and harder to justify than staying with the better one [S46][S71][S75][S82][S124][S131][S148].

If the superior path becomes fragile, expensive, or administratively awkward, retirement can reverse even without formal repeal.

### 4. Treat any re-entry as an explicit off-normal event, not silent routine
The archive’s basic rule is that a retired inferior path should not quietly become ordinary again.
If the programme believes temporary re-entry is unavoidable, it should be governed as an off-normal event:
- a named owner
- an explicit reason
- visible proof of necessity
- the least-damaging available fallback form
- a narrow scope
- and a visible sunset with a route back to the superior path [S84][S85][S86][S123][S141][S148].

The moment re-entry becomes invisible routine, retirement has failed in practice even if the formal rule still looks intact.

### 5. Harden the moments where regression usually sneaks back in
Inferior paths rarely return through open ideological defeat alone.
They usually return at weak seams:
- rebuilds and replacements
- landlord or tenant turnover
- household moves
- emergency outages
- procurement renewals
- budget squeezes
- political turnover and agency reorganization [S46][S75][S82][S124][S131][S148].

A serious programme should therefore harden continuity at those seams:
- no reset to dirty defaults at handoffs
- no automatic reinstatement of legacy subsidies or tariff treatment
- no blank-page requalification that strips away the superior path
- no stress-era fallback that survives without a closure clock [S75][S84][S85][S86][S148].

### 6. Re-tighten quickly when regression pressure appears
Regression prevention is not passive monitoring.
When re-entry signals appear, the programme should move quickly:
- classify the event visibly
- diagnose the likely failing layer
- apply the smallest fitting first correction
- verify whether re-entry pressure falls
- and, if needed, re-retire the reopened path before it regains normal status [S138][S142][S143][S144][S145][S148].

The rule is simple: **do not let small returns of the inferior path mature into a new settled compromise.**
