# 121 — Ideal Solutions: Five Dispute-Resolution Rules When Readiness Status Is Contested

## Claim

The archive now has:
- a readiness-status ladder (`117`)
- a readiness-promotion note (`118`)
- a readiness-demotion note (`119`)
- and a readiness-anti-churn note (`120`)

What it still lacked was the shortest **dispute-resolution rule** for the practical governance question:

**What should a serious climate state do when actors disagree about the current readiness status or about whether promotion or demotion is justified?**

That gap matters because readiness status is rarely contested in the abstract.
It is contested when a stronger claim protects reputation, budgets, discretion, or political calm.
Without a short rule for handling disagreement, a readiness ladder can still be captured by bargaining, hierarchy, or delay.
A compact archive needed one short note that says:
**when readiness status is disputed, the mission does not wait for rhetorical consensus.
The state should operate under the more conservative status until current evidence resolves the dispute through a named path.**

This note is a **compression note**, not a new doctrinal branch.
Its job is to connect the archive’s earlier governance notes on roles, decision rights, precedence, and burdens of proof to the newer readiness state machine [S34][S55][S73][S83][S102][S103][S105][S106][S107][S108][S114][S117][S118][S119][S120][S145][S147].

## Fast rule

**When readiness status is contested, do not protect the stronger claim by default. Shift the burden onto the actor defending that stronger claim, run the system under the more conservative status while the dispute is open, and resolve the dispute quickly through current evidence, a named decider, and a dated next check.**

## The five dispute-resolution rules

### 1. Protection beats reputation when status is disputed
If the dispute matters because a stronger readiness claim would justify looser protections, larger exposure, or delayed repair, protection should govern first.

What this looks like:
- do not preserve a stronger status merely because downgrade would be embarrassing
- do not keep a stronger label if the consequence would be weaker shielding, looser tripwires, or broader exposure
- if the dispute changes who bears risk, resolve in favour of the less harmful operating posture [S83][S103][S107][S108][S115][S116]

Default consequence:
- while the dispute is open, use the safer posture rather than the more flattering label

### 2. The stronger claim carries the burden
The actor defending the stronger readiness status should prove that the stronger state still governs.
The actor arguing for caution does not need to prove catastrophe before a downgrade is allowed.

What this looks like:
- claims of “still ready” or “safe to re-upgrade” require current evidence
- missing proof, stale proof, or proof that covers only part of the critical path does not sustain the stronger claim
- the burden stays with the actor resisting downgrade or seeking promotion [S83][S102][S108][S114][S118][S119]

Default consequence:
- if the stronger claim is not proved, the dispute resolves to the more conservative state

### 3. Current end-to-end evidence beats paperwork or memory
When actors disagree, the archive should prefer current evidence from the working path over documentation that used to be true.

What this looks like:
- fresh exercises, current joins, live contactability, recent protection checks, and recent end-to-end demonstrations outrank old certifications or inherited confidence
- a completed checklist does not outrank a failed current handoff
- localized success does not outrank a broken governing join [S55][S73][S83][S113][S114][S118][S119][S145]

Default consequence:
- resolve the dispute using the newest evidence that covers the real critical path

### 4. Disputes are governed under the more conservative status until closed
A readiness dispute is not a permission slip for ambiguity.
It is itself a reason to stop using the stronger state as the governing assumption.

What this looks like:
- if the disagreement is between **proven ready** and **partial**, govern as **partial**
- if the disagreement is between **partial** and **unknown**, govern as **unknown** unless the known-gap picture is already good enough to carry `115`
- if a real detour is already open, govern as **live detour** rather than arguing about cleaner labels around it [S103][S112][S116][S117][S119][S120]

Default consequence:
- while unresolved, the operating status is the lower or more conservative of the competing states

### 5. Every readiness dispute needs a named decider, a short evidence path, and a dated re-check
Disputes should not linger as ambient ambiguity.
They should be routed through an explicit decision path.

What this looks like:
- a named authority owns the resolution
- the missing evidence needed to resolve the dispute is stated plainly
- the resolution clock is short enough that ambiguity does not become an inherited state
- the decision leaves a trace: cause, ruling, owner, and next proof date [S34][S55][S83][S102][S105][S106][S107][S120]

Default consequence:
- if the dispute has no decider, no evidence path, or no re-check date, treat that as further reason to hold the more conservative state

## Minimal dispute map

The smallest serious readiness-dispute map is:

- **protection outranks reputation**
- **the stronger claim carries the burden**
- **current end-to-end evidence outranks stale paperwork**
- **the system runs under the more conservative state while the dispute is open**
- **every dispute gets a named decider, a short evidence path, and a dated re-check** [S83][S102][S105][S106][S107][S108][S114][S117][S118][S119][S120][S147]

## Conservative default

If a team says the archive should keep the stronger status until everyone agrees otherwise, it is usually defending optics, discretion, or calm more than it is defending the mission.
The archive should prefer:
- **conservative operation over flattering ambiguity**
- **explicit burden assignment over status bargaining**
- **short evidence clocks over unresolved drift**
- **mission protection over reputational comfort** [S83][S102][S107][S108][S114][S116][S117][S120][S147]
