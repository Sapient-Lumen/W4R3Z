# 153 — Ideal Solutions: Whole-System Queue-Discipline Map — How to Cap Active Corrections and Protect Throughput (Compact Canon)

## Claim

A serious climate programme cannot correct every weak signal at once.
After attention allocation (`151`) and triage (`152`), it still needs one more rule:
**how much correction work may be live at once, what enters now, what waits, what is batched, and what is quarantined.**

Without that rule, triage decays into overload.
Too many live corrections cause the same failures they were meant to solve:
- truth degrades because too many claims are being asserted at once
- delivery degrades because managers become systems integrators for too many exceptions
- protection degrades because stop-harm work loses focus
- verification degrades because no correction gets enough measurement time to prove or fail cleanly
- institutional memory degrades because half-finished fixes pile up faster than they can be stabilized or retired

So the archive needs a shortest joined note for **queue discipline**.
This is not a new doctrine branch.
It is a compact operating rule that sits between triage and execution.

## Fast rule

**Carry only as many live correction tracks as the programme can truthfully verify, govern, and stabilize. Rank first, then cap active work, protect emergency lanes, batch the rest, and make waiting visible instead of pretending everything is in motion.**

## What queue discipline is for

Queue discipline answers five practical questions:
1. **What must enter active work now?**
2. **What must wait, even if it matters?**
3. **How many live correction tracks can the programme carry without degrading truth, delivery, and protection?**
4. **What should be grouped into one batch or template instead of launched as bespoke parallel work?**
5. **What should be quarantined until stronger proof, clearer ownership, or a freed bottleneck exists?**

## Five queue-discipline rules

### 1. Protect a hard cap on active correction work
Do not admit more live correction tracks than the programme can actually:
- govern,
- measure,
- verify,
- stabilize,
- and either propagate or retire.

If those downstream steps are not resourced, the new correction is not truly admitted.
It is only being announced.

### 2. Reserve an emergency lane, but keep it narrow
Stop-harm and anti-lock-in work can pre-empt the queue.
But the emergency lane must stay narrow, explicit, and time-bounded.
Otherwise every claimant relabels itself urgent and the queue discipline collapses.

### 3. Prefer batchable classes over bespoke parallel fixes
If ten weak signals share one failure layer, one template correction usually beats ten special projects.
Batch by recurring failure pattern where possible:
- one permitting fix across many sites
- one tariff or interconnection reform across many queues
- one procurement standard across many agencies
- one measurement protocol across many programmes

### 4. Make waiting states explicit
Not-active is not the same as ignored.
Every non-active item should sit in a visible state such as:
- queued for next admission
- batched with related work
- awaiting proof
- awaiting ownership
- awaiting released bottleneck
- quarantined pending boundary review

Invisible waiting turns into political amnesia, duplicate work, and reputational theatre.

### 5. Exit before admitting more
If the programme wants to admit more live corrections, it should first clear space by doing one of the following:
- verify and stabilize a successful correction
- stop or redesign a failing one
- merge duplicates into one template
- retire a now-inferior workaround
- move a claim back to queue or quarantine if it lacks proof, ownership, or capacity

Admission without exit is how correction work becomes a permanent traffic jam.

## Operational shape

A serious programme should usually run four visible buckets:
- **active now** — currently governed and measured work
- **emergency lane** — narrow, time-bounded stop-harm or anti-lock-in work
- **queued / batched next** — worthwhile work that is not yet admitted to active governance
- **quarantine** — claims that need more proof, cleaner boundaries, or clearer ownership before entry

## What this note is not saying

This note is not saying “do less.”
It is saying **do only as much live correction work as can still be made real.**
The way to do more is not to carry everything simultaneously.
The way to do more is to:
- increase delivery capacity,
- improve templates,
- reuse proven fixes,
- remove duplicate effort,
- and free bottlenecks so more work can move without degrading truth or protection.
