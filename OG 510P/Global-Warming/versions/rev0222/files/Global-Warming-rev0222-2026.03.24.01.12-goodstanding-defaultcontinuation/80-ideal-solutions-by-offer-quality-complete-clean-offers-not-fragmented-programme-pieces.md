# 80 — Ideal Solutions by Offer Quality: Complete Clean Offers, Not Fragmented Programme Pieces

## Claim

The archive now has compact rules for interface form, enrolment form, eligibility form, payment form, contract form, delivery form, verification form, remedy form, continuity form, the joined user pathway, and burden shape.
Those notes explain how a strong clean pathway should work.
But the archive still lacks the shortest provider-side synthesis rule for what the intended user should actually receive:

**ideal climate solutions should usually arrive as complete clean offers, not as fragmented programme pieces that the user must discover, combine, reconcile, and carry across institutions.**

A policy system may contain subsidy, finance, contractor lists, tariffs, guarantees, standards, and customer support.
If those elements sit in separate silos, the system is still weak from the user’s point of view.
So the archive’s shortest offer-quality rule is:

**judge the climate pathway as an offer. If the intended user cannot receive a coherent clean offer from first contact to persistent benefit, the solution is still incomplete** [S69][S71][S80][S91][S96][S118][S119][S137][S140][S141][S143].

## Why this belongs in the canon

### 1. Availability is not the same as offer quality

Many climate systems are defended by saying that the parts already exist:
- a rebate exists,
- a loan exists,
- a vendor directory exists,
- an advice line exists,
- a tariff exists,
- a complaints route exists.

But a user does not live inside policy categories.
They experience one thing: whether a coherent clean offer is actually being made to them.
If the pieces are scattered across agencies, time windows, forms, vendors, and incompatible rules, the system is not offering a transition.
It is offering a scavenger hunt [S118][S119][S137][S140][S141][S143].

So this note adds a sharper rule than "low friction":

**do not confuse the existence of programme components with the existence of a good offer.**

### 2. A complete offer is the provider-side expression of the pathway rule

`78-ideal-solutions-by-user-pathway-one-sequence-from-front-door-to-persistent-clean-state.md` describes the same sequence from the user side.
This note states the matching provider-side standard:

**someone with responsibility for climate delivery should be able to say what the complete offer is, who it is for, how it starts, how it is paid for, how it is delivered, how claims are checked, how failures are corrected, and how gains persist.**

If no actor can describe that complete offer, responsibility is probably fragmented in a way that will push hidden integration work back onto weaker actors [S69][S80][S91][S96][S118][S119][S137][S141][S143].
For the archive’s companion note on **who should remain accountable for that whole joined pathway when different institutions or contractors perform different pieces**, see `81-ideal-solutions-by-orchestration-form-one-accountable-lead-and-no-user-as-systems-integrator.md`.

### 3. Offer quality is a justice and delivery issue at once

Bad offer quality sorts by spare time, literacy, liquidity, tenure security, confidence, and access to trusted intermediaries.
It also burns state capacity because local staff then spend time improvising handoffs instead of repeating a known package.
So a complete offer is not just better customer experience.
It is part of the archive’s justice doctrine, delivery doctrine, and copyability doctrine [S69][S71][S80][S118][S119][S137][S140][S141][S143].

## The archive’s complete-offer test

A proposal is stronger when the intended user can receive something that looks like a real offer rather than a puzzle.

### 1. Named-outcome test
Can the offer be stated in service terms the user can understand — lower bills, safer cooling, cleaner heat, reliable mobility, resilient power, lower risk — rather than only as a menu of measures or technologies? [S69][S71][S118][S140][S141][S143]

### 2. Joined-finance test
Does the offer already contain a workable payment route, or must the user leave the pathway and separately solve financing? [S91][S96][S118][S137][S143]

### 3. Joined-delivery test
Does the offer already contain a delivery route — provider, contractor network, utility programme, landlord obligation, municipal channel, or procurement path — or must the user build that route manually? [S80][S118][S119][S137][S141][S143]

### 4. Joined-proof test
Does the offer already know how ordinary eligibility and verification will be handled, or are those proof burdens still externalized to the user? [S118][S119][S123][S135][S136][S143]

### 5. Joined-remedy test
If the offer fails, underdelivers, or misroutes the user, is there a built-in correction path with a clear responsible actor? [S118][S119][S143]

### 6. Persistence test
After the offer succeeds once, can the resulting clean state survive ordinary handoffs, account changes, and rebuilding without being silently undone? [S69][S118][S119][S137][S143]

## What a complete clean offer usually includes

A strong offer does not need to be luxurious or bespoke.
It usually just needs to be whole.
In compact form, that means the intended user can see:
- what service or outcome is being offered,
- why they are a likely fit,
- how to start,
- what they will probably pay and when,
- who will deliver or manage delivery,
- how ordinary claims will be proved,
- what happens if something goes wrong,
- how the gain will be kept in place afterward [S69][S80][S91][S96][S118][S119][S137][S140][S141][S143].

This is deliberately close to ordinary good public-service design.
That is the point.
The climate offer should usually feel like a usable civic or utility service, not like a one-off grant hunt.

## What this rule promotes

Promote:
- climate pathways that can be presented as complete offers rather than as loose bundles of available supports [S118][S119][S140][S141][S143]
- joined-up utility, municipal, landlord, procurement, and intermediary channels that can carry a user from invitation to persistent outcome without repeated re-entry [S69][S80][S118][S119][S137][S141][S143]
- service-first designs where finance, contractor management, verification, and remedy are embedded instead of exported downstream [S91][S96][S118][S137][S143]
- programme accountability that names the actor responsible for offer integrity rather than letting each silo defend only its own fragment [S80][S118][S119][S141][S143]

## What this rule demotes

Demote:
- climate systems that can only be defended by listing parts while no one can describe the whole user offer [S118][S119][S137][S140][S143]
- designs that require the intended user to stitch together subsidy, finance, delivery, proof, and remedy across separate institutions [S69][S91][S96][S118][S119][S137][S143]
- programmes that are rich in components but poor in offer quality [S118][S140][S141][S143]
- any solution that treats user drop-off as lack of motivation when the real problem is that no coherent offer was ever assembled [S118][S137][S140][S143]

## One-paragraph compression

**Ideal climate solutions should usually arrive as complete clean offers, not as fragmented programme pieces. The intended user should be able to encounter one coherent pathway with a named outcome, a workable payment route, a joined delivery route, proportionate proof, a clear remedy path, and persistence through ordinary handoffs. If those parts exist only as separate administrative fragments, the system is still incomplete no matter how impressive the parts look on paper** [S69][S71][S80][S91][S96][S118][S119][S137][S140][S141][S143].
