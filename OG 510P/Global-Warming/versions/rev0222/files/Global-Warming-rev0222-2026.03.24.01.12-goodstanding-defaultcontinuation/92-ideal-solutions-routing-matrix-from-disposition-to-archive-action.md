## Fast rule

**Disposition answers what the proposal is worth. Archive action answers what to do with the archive. Do not confuse the two.**

A proposal can matter without deserving a new file.
A proposal can also fail core screening so clearly that the correct archive action is simply to refuse growth.

## The routing matrix

### Promote → usually edit or compress before adding
If a proposal is promoted, ask first whether the canon already has the right screen.

Default archive actions, in order:
1. **edit an existing file** if the proposal sharpens an existing screen or adds a better example, boundary, or wording
2. **cross-link** if the archive already says the important thing and only findability improves
3. **add a new main-canon file** only if the proposal adds a net-new screen, clarifies a decision-changing boundary, or creates real compression that lowers navigation cost

Promotion is therefore **not** an automatic instruction to add a file.
It is first an instruction to treat the idea as canon-compatible.

### Demote → route to conditional, local, or supporting status
If a proposal is demoted, the usual archive action is **not** new main-canon growth.

Default archive actions, in order:
1. **leave it where it is already covered** in a broader note
2. **add a sentence or short paragraph** to an existing note if the boundary needs clarification
3. **cross-link only** if the main value is navigational
4. **avoid new standalone files** unless the demotion itself clarifies an important recurring boundary

Demotion means the idea may still be useful, but it should not carry central explanatory weight.

### Quarantine → isolate, watch, and require a promotion trigger
If a proposal is quarantined, the archive should usually preserve the caution rather than half-admit it.

Default archive actions, in order:
1. **leave it in quarantine or conditional treatment**
2. **note the specific promotion trigger** required for later movement, such as stronger evidence, lower scarcity cost, clearer delivery proof, or tighter boundaries
3. **avoid canon expansion** until that trigger is met

Quarantine is for ideas that may matter later but are not yet stable enough for strong canon treatment.

### Refuse → do nothing or record the refusal briefly
If a proposal is refused, the default archive action is usually **do nothing**.

Possible archive actions:
1. **do nothing** when the archive already rejects the idea clearly
2. **add one line to an existing negative-canon or boundary note** only if the refusal closes a recurring confusion
3. **do not create a standalone refusal note** unless there is exceptional compression value

Refusal should lower archive growth pressure, not create a new genre of archive clutter.

## The operator sequence after screening

After a proposal has been screened, the archive should usually ask four action questions in order:
1. **Is this already covered?**
2. **If not, is the gap best closed by editing, cross-linking, or adding?**
3. **Does the proposal change the canon, or only help people find the canon?**
4. **Would a new file lower navigation cost, or merely create another stop?**

## One-line defaults

- **promote** → edit, compress, or cross-link first; add only for true net-new value
- **demote** → clarify boundaries inside existing notes
- **quarantine** → isolate and state the trigger for later reconsideration
- **refuse** → usually do nothing

## One-paragraph compression

**The archive now has a shortest routing matrix: promotion does not automatically mean “add a file”; demotion usually means “keep it conditional inside existing notes”; quarantine means “isolate and wait for a clear promotion trigger”; refusal usually means “do nothing.” This keeps archive actions proportionate to evaluation outcomes and helps the canon stay sharp instead of growing by procedural confusion.**
