**a single smallest canon for how a new proposal, question, or candidate note should enter the archive, be screened, be routed, and either change the canon proportionately or leave it unchanged.**

This note is not a new doctrinal branch.
It is a joining note.
Its job is to reduce the archive’s intake logic to one first stop.

## Fast rule

**Do not let proposals enter by enthusiasm, novelty, or filename pressure. Start from the actual question, fail fast on red flags, run the positive screens, assign a disposition, choose the smallest archive action that solves the problem, and only grow the main canon when the addition creates a net-new screen, a decision-changing boundary, or real compression.**

## The intake-and-admission sequence

### 1. Start from the real question
Open `95-ideal-solutions-question-router-common-prompts-to-best-first-files.md` if the incoming object is still unclear.
Open `94-ideal-solutions-archive-topology-layers-best-first-stops-and-preferred-reading-order.md` if the task is clear but the right archive layer is not.

The archive should not begin by adding or opening a deep note at random.
It should begin by naming the question and choosing the smallest layer that can answer it.

### 2. Fail fast on red flags
Open `89-ideal-solutions-compact-negative-canon-red-flags-and-recurring-failure-modes.md`.

Ask first whether the proposal is mostly a delay device, future-cleanup excuse, scarcity waste, paper-claim machine, distributional dodge, or delivery fantasy.
If a strong red flag governs, do not reward the proposal with expansive treatment.

### 3. Run the positive screens
Open `88-ideal-solutions-compact-canon-core-screens-in-one-place.md`.

If the proposal survives the red flags, ask whether it is physically real, fast enough, robust under scarcity, fair enough to last, aligned with real delivery, and likely to produce hard-world gains rather than only formal claims.

### 4. Assign a disposition
Open `59-ideal-solutions-fast-screen-promote-demote-quarantine.md`.

Every intake should land, at minimum, in one of four states:
- promote
- demote
- quarantine
- refuse

The archive should not drift from screening into editing without first naming the disposition.

### 5. Translate disposition into the smallest archive action
Open `92-ideal-solutions-routing-matrix-from-disposition-to-archive-action.md`.

Default preference order:
1. do nothing if the archive already says the important thing
2. edit an existing file if the gain is clarification
3. cross-link if the gain is findability
4. add a new main-canon file only if the gain is genuine net-new value or genuine compression

This is the archive’s proportionality rule in action.

### 6. Enforce the archive-growth rule
Open `90-ideal-solutions-archive-admission-rule-add-only-net-new-screens-boundaries-or-compression.md`.

A new main-canon file is justified only when it adds:
- a net-new screen
- a decision-changing boundary
- or real compression that lowers navigation cost

“Interesting,” “related,” or “not yet named separately” is not enough.

### 7. Use the short operator card when speed matters
Open `93-ideal-solutions-one-page-operator-card-screen-route-and-keep-the-archive-small.md`.

When working fast, keep the archive’s full intake logic on one page:
- screen
- route
- admit only if justified
- keep the archive small by default

### 8. Reopen the deeper tree only when a live question remains
If the intake survives all of the above and still exposes a live unresolved question, only then reopen deeper design rules, sector notes, or state-machine notes.

That keeps archive growth downstream of actual need rather than upstream of it.

## Compression rule

**Treat archive intake as one sequence: route the question, screen the object, assign the disposition, choose the smallest archive action, and admit only on true net-new value or true compression.**

## One-paragraph compression

**The archive now has a shortest joined canon for intake and admission: start from the actual question rather than a remembered filename, fail fast on red flags, run the positive screens, name the disposition, translate that disposition into the smallest proportional archive action, and only grow the main canon when the change adds a net-new screen, a decision-changing boundary, or real compression. That gives the mature archive one compact front-door rule for how new proposals should be handled without turning intake itself into a source of archive sprawl.**
