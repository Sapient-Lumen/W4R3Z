# Meta 0403 — archive refactor note

## Objective

Keep the Radical-Governance archive dense, interoperable, and cumulative as the revision count grows.

## Refactor move

Future additions should default to a five-part structure:

1. one-line thesis,
2. mechanism or pattern pack,
3. guardrails,
4. failure modes,
5. practical tests / metrics.

This keeps documents short enough to scan while preserving enough structure for recombination.

## Meta-engineering heuristics

### A. Govern the hinge, not the whole machine

Prefer documents about leverage points:

- interfaces,
- appeals pathways,
- budget rules,
- disclosure triggers,
- switching rights,
- review clocks,
- authority maps.

### B. Distinguish build from operate

Many governance notes blur design-time and run-time institutions. Future docs should separate:

- design / procurement,
- deployment / operation,
- monitoring / appeal,
- repair / decommission.

### C. Keep cross-scope portability visible

Every note should imply how it scales:

- municipal,
- regional,
- national,
- transnational,
- platform / protocol layer,
- non-territorial governance where relevant.

### D. Preserve anti-capture moves

Every pattern pack should include at least one anti-capture check:

- portability,
- rotation,
- public logging,
- independent review,
- open standards,
- sunset review,
- conflict-of-interest barrier.

### E. Favor verbs over abstractions

Good archive language names actions:

- route,
- log,
- publish,
- switch,
- pause,
- contest,
- sunset,
- federate,
- equalize,
- escrow.

## Suggested next additions

Promising nearby notes:
