# 278 — Worked Example System Attachment to the Governance Systems Map

**Purpose:** keep `276-worked-example-system-consolidated.md` as the canonical memo for the worked-example subsystem while explaining **where it sits inside the archive-wide systems map** introduced in `279-governance-systems-map.md`.

This memo is intentionally **not** a second full architecture write-up. It exists to stop a new duplicate from forming.

## Canonical relationship

- **Canonical worked-example architecture:** `276-worked-example-system-consolidated.md`
- **Canonical archive-wide systems map:** `279-governance-systems-map.md`
- **Worked-example → thematic routing layer:** `274-worked-example-to-domain-crosswalk.md`

## Attachment rule

Treat the worked-example layer as a module of the **Institutional Learning System**, with spillovers into:
- **Justice & Redress** when examples expose remedy failure,
- **Implementation** when examples expose service or delivery breakdown,
- **Institutional Reform / Retrofit** when examples expose design flaws that need structural change.

## What belongs in 276 vs 278

### Keep in `276`
- the subsystem’s internal components,
- the operational workflow,
- the role of evidence packets / comparison cuts / bridges / drills.

### Keep in `278`
- the subsystem’s position in the archive-wide map,
- rules for attaching future worked-example memos,
- anti-duplication guidance.

## Anti-duplication rule

If a future memo is mainly about:
1. **how the worked-example subsystem itself operates**, extend `276`;
2. **how worked examples connect to a governance system or domain cluster**, extend `278` or `274`;
3. **a new concrete example family**, create a worked-example memo and point back to `276`.

This file exists so the archive has **one canonical worked-example architecture memo, not two**.
