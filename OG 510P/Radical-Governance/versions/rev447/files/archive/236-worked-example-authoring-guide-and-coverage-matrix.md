# Worked Example Authoring Guide & Coverage Matrix

**Purpose:** keep worked examples first-class, reusable, and compact enough that they sharpen the archive instead of bloating it.

**Person served:** archive maintainers and memo authors who need a consistent way to write examples that stay tied to the governed person, not just the institution.

**From-below:** this memo exists so future examples keep showing what power feels like at the point of contact, what artifacts must appear, and what the minimum repair looks like when they do not.

---

## Minimum anatomy of a worked example

Every worked example SHOULD include:
1) **Situation** — one paragraph with a real-feeling trigger event.
2) **What the person should be able to learn quickly** — 3–5 plain-language bullets.
3) **Minimum person path / trace** — 4–6 steps with actual artifacts.
4) **Operator view** — what a clerk, reviewer, dispatcher, teacher, or project manager should see.
5) **Oversight view** — what should be inspectable at portfolio level.
6) **Red flags** — concrete anti-patterns.
7) **Smallest repair** — the minimum believable improvement.
8) **Why this example matters** — the moral stake in direct speech.

A good example should make a reader say: **I can now see what would happen, what should be visible, and where the system usually cheats.**

---

## Coverage matrix

Across the casebook, keep coverage across these power types:
- entitlement / cutoff
- queue / priority
- coercion / custody
- money / allocation
- boundary / continuity
- participation / legitimacy
- infrastructure / maintenance
- record / identity correction
- housing / displacement
- revenue / subsistence
- permissioning / livelihood
- labor / collective power

A healthy archive does not need equal numbers in each category, but it SHOULD avoid stacking all examples in one comfort zone.
