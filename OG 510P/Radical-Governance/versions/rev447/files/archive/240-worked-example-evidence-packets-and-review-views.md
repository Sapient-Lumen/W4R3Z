# Worked Example Evidence Packets & Review Views


**Purpose:** make each example legible from several positions — affected person, frontline operator, oversight body, and public.

**Person served:** implementers, auditors, journalists, ombuds staff, advocates, and supervisors who need to know what each audience should be able to inspect.

---

## Evidence-packet views

| View | What it should contain | Examples |
|---|---|---|
| person packet | consequence, reason class, next step, owner, deadline, interim protection | `WX-01`, `WX-28`, `WX-43`, `WX-48` |
| operator packet | current state, as-of facts, escalation lane, missing-artifact flags | `WX-10`, `WX-35`, `WX-45`, `WX-50` |
| oversight packet | pattern fields, comparator groups, stop-rule breaches, repeat offices/vendors | `WX-03`, `WX-29`, `WX-36`, `WX-49` |
| public packet | de-identified pattern counts, policy deltas, contractor/program signals | `WX-07`, `WX-33`, `WX-44`, `WX-51` |

## Rule of thumb
A system is probably under-specified if one audience can explain the case only by hiding what another audience needs to contest or verify.
