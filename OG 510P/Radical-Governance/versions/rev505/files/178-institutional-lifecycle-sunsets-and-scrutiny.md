# Institutional Lifecycle: Create, Operate, Evaluate, Sunset, Rebuild

**Purpose:** prevent “immortal institutions” (capture + rot) while avoiding churn. Provide a *default lifecycle* for agencies, boards, emergency powers, and major programs.

**Design target:** institutions that are *auditable, revisable, and terminable* without governance collapse.

---

## Core rule: lifecycle is a first-class interface
Every institution MUST publish:
- **Mandate + scope** (what it is for, what it is not for).
- **Owner / oversight path** (who can intervene; how fast).
- **Renewal clock** (when it must be reviewed).
- **Exit plan** (how it can be wound down without service loss).
- **Records interface** (what must be disclosed, to whom, and when).

(Connects to: `34-competence-ledger-and-mandate-registry.md`, `115-information-integrity-and-record-interfaces.md`, `71-interface-obligations-by-scope.md`.)

## The 6-phase lifecycle (default)

### 1) Charter (birth)
Charter must include:
- explicit *problem statement* + falsifiable success measures
- budget ceiling + staffing plan
- data authority boundaries (what data it can touch)
- escalation and appeal routes
- **sunset + review trigger** (see below)

### 2) Commissioning (first audit gate)
Before the institution is considered “live”:
- baseline metrics + data collection plan
- publication plan (what will be public by default)
- risk register (capture, corruption, rights, safety, failure to deliver)

### 3) Operations (steady state)
Operational invariants:
- service standards + time budgets (`108-service-standards-and-time-budgets.md`)
- grievance and remedy loop (`08-remedy-and-grievance.md`)
- procurement and contracting rails (`179-open-contracting-and-procurement-rails.md`)

### 4) Review (post-legislative / post-charter scrutiny)
A review MUST be substantive, not ceremonial:
- independent evaluation of outcomes, side-effects, and equity
- review of whether the **mandate** is still needed (not just whether it's “performing”)
- audit of emergency powers and exceptional authorities
- audit of capture indicators (see `177-governance-failure-taxonomy-and-recovery-ops.md`)

Good sunset clauses require **real review capacity**, otherwise they become placebo.

### 5) Renewal / modification (re-authorization)
Possible outcomes:
- renew unchanged (rare)
- renew with narrowed scope + new guardrails
- merge / split
- transfer to different scope (subsidiarity reassignment)
- convert from discretionary to rules-based (reduce capture surface)

### 6) Sunset / replacement (death + continuity)
If sunset triggers:
- continuity plan must transfer critical services
- records escrow + integrity locks apply
- staff transition policy reduces perverse incentives
- publish closure report (what worked, what failed)

---

## Sunset clauses: minimum viable spec
A sunset clause is only “real” if it includes:
- clear **expiry** date/condition
- explicit **renewal** procedure
- required **evidence bundle** for renewal
- a **review body** empowered to recommend termination/reshaping

Well-drafted sunset clauses + scrutiny can improve democratic control; poorly drafted ones can fail to constrain power.

---

## Emergency powers: hardening the exception
Emergency powers must include:
- narrow trigger definition
- time limit (short default)
- renewal only with evidence + recorded votes
- post-emergency audit (mandatory)
- automatic rollback of extraordinary data access

(See also: `105-institutional-circuit-breakers.md`.)

---

## Integration hooks (add to tests)
Add (or keep) these as auditable requirements:
- **Lifecycle field completeness:** charter includes renewal clock + exit plan.
- **Review reality check:** independent evaluation exists and is published.
- **Sunset enforcement:** non-renewed powers actually lapse (no silent continuation).
