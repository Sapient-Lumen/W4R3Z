**Material floor (one sentence):** If a polity uses deliberation to guide policy, it must treat deliberation as *infrastructure*—with clear mandates, selection integrity, information integrity, binding pathways, and audited follow‑through.

## Where assemblies fit (scope-agnostic)
Citizens’ assemblies / juries are one tool inside a **deliberative system**: a portfolio of participation modes with defined “handoffs” into decision authority (cf. `111-deliberation-to-decision-binding.md`, `119-selection-and-sortition-integrity.md`). OECD frames these as “innovative public participation” and provides design guidance and typologies for deliberative processes. See [BIB-OECD-INNOVATIVE-PUBLIC-PARTICIPATION], [BIB-OECD-NEW-FRONTIERS-CITIZEN-PARTICIPATION-2024].

## Minimal design pattern (assembly as a governed pipeline)
1. **Mandate & scope** (what questions; what is out-of-scope; who owns implementation).
2. **Selection** (random selection + stratification; independent sampling operator; audit trails). See `119-…`.
3. **Information integrity** (balanced briefing; adversarial “challenge” sessions; disclosure of conflicts; citation discipline). See `115-information-integrity-and-record-interfaces.md`.
4. **Deliberation** (facilitation standards; accessibility; interpretation; harassment safety).
5. **Outputs** (recommendations with confidence levels; minority reports; costings; implementation options).
6. **Binding pathway** (how outputs bite): one of
 - **Agenda-binding** (must be debated / voted with reasons),
See also: `159-civic-lottery-and-deliberation-infrastructure.md` (minimum viable deliberation infrastructure + binding response rail).

 - **Response-binding** (must accept/reject each rec with written reasons),
 - **Co-decision** (shared decision authority),
 - **Trigger/veto** (narrow, pre-defined, high legitimacy bar).
 See `111-…` for binding types.
7. **Follow-through & monitoring** (public tracker; deadlines; “why not” explanations; escalation).
8. **Evaluation** (process + outcome evaluation; participants’ experience; learning loop). See `133-evaluation-and-learning-integrity.md`.

## Failure modes (and circuit breakers)
- **Agenda capture** (pre-framed question; hidden constraints) → publish the “scope docket” + adversarial reframing session.
- **Selection gaming** (non-response bias, stratification errors) → independent selection operator + audits (`119-…`).
- **Briefing asymmetry** (one-sided experts) → balanced panels + disclosed evidence index (`115-…`).
- **Non-implementation theater** → binding response rules + public implementation tracker + escalation to oversight (`111-…`, `130-audit-and-inspection-integrity.md`).

## “Where should we deploy this?”
Use assemblies when:
- stakes are high, values conflict, and legitimacy is contested;
- policy needs *public reasoning* rather than pure expertise;
- you need durable consent for tradeoffs.

Avoid assemblies when:
- the domain is mainly technical and bounded (prefer expert panels with public review);
- coercion/violence risk is high (prioritize safety + confidential channels).

## Cross-scope note
At micro-local scales, assemblies can be standing “neighborhood juries”; at national/global scales, they are often best as **issue-specific** bodies with strong binding pathways and interoperability with legislatures/compacts. See `197-polycentric-federalism-and-overlapping-sovereignty.md`.
