# 878 — Applied generative-assistant case packet for GOV.UK Chat: RAG guidance assistant, source links, limited pilot, and no benefit, tax, or visa decision by summary

## One-line thesis

GOV.UK Chat should be classified as a source-bound public guidance assistant under staged expansion: its RAG design, algorithmic transparency record, source links, user warnings, evaluation, red-teaming, privacy controls, and app integration make it a stronger positive-control case than NYC MyCity, but its public-law safety still depends on keeping summaries below decision grade and preserving evaluation, corpus, model-change, incident, and escalation records.

## Why this matters

This packet gives `876` a positive-control case. The archive needs examples where generative public guidance is not simply condemned. GOV.UK Chat is valuable because the public record names the owner, third-party involvement, retrieval design, source corpus, user onboarding, no-decision boundary, model and hosting arrangement, evaluation methods, red-team posture, personal-data filtering, answer links, and pilot / expansion path.

The holding is deliberately bounded. GOV.UK Chat may help users navigate complex public guidance, but it must not become a benefit, tax, visa, licence, immigration, welfare, or enforcement decision by summary. A source-bound answer remains a summary. It is useful only while users can see the source, verify it, and enter the official route for action.

## Pattern pack

### 1. Trigger and dispatcher table

| Field | Finding |
| --- | --- |
| trigger | public-facing AI assistant embedded in the GOV.UK app to answer natural-language questions from government guidance |
| boundary mismatch | source corpus, GOV.UK brand, RAG retrieval, LLM generation, app onboarding, user warnings, no-decision boundary, supplier / model hosting, evaluation, and expansion decisions interact |
| first-form question | whether this is search, guidance, decision support, supplier dependency, or advice-state infrastructure |
| lower-form test | ordinary search is too thin because the system retrieves, composes, summarizes, and answers in natural language |
| heavier-form test | automated decision system is too thick while official records say no decisions are made or assisted and the tool summarizes guidance only |
| form verdict | source-bound public guidance assistant under staged expansion and evaluation |

### 2. Legal form boundary

| Wrong label | Why wrong |
| --- | --- |
| mere search | hides RAG, model output, answer composition, and reliance risk |
| legal adviser | overstates the formal authority if the tool is kept to summaries and source links |
| automated decision system | too strong unless the output affects rights, benefits, tax, immigration, enforcement, or case routing |
| safe because source-bound | too optimistic; retrieval, chunking, incompleteness, outdated content, ambiguity, and user reliance remain live |
| unsafe because generative | too pessimistic; a controlled source-bound assistant may improve access if it stays below decision grade |

The honest label is **source-bound public guidance assistant under staged expansion**.

### 3. Public record strengths

| Record | Why it matters |
| --- | --- |
| algorithmic transparency record | names owner, team, third-party involvement, model, data, operational process, and no-decision boundary |
| RAG design | constrains answers to GOV.UK content rather than free-form general advice |
| source links | gives users a route to verify and continue their official journey |
| onboarding warning | tells users the tool is AI-powered and may be inaccurate |
| limited testing / staged opening | avoids pretending that public deployment is already settled |
| hybrid evaluation | combines automated evaluation, manual expert review, red-team probing, and user research |
| privacy filtering | attempts to exclude personal data and reject user inputs with common personal-data patterns |
| model / hosting disclosure | exposes supplier and infrastructure dependency enough for review |

These strengths do not remove risk. They make the risk legible.

### 5. Generative-assistant test docket

This case activates all tests, but with a stronger initial showing than the MyCity packet:

1. **Public-owner and boundary test** — owner, team, and senior responsible owner are declared.
2. **Canonical corpus and source trace** — source grounding is central, though chunking, exclusions, and freshness remain review surfaces.
3. **Reliance and warning test** — onboarding and answer links exist; the open question is whether warnings suffice as access expands.
4. **Answer consistency and hallucination test** — pilot results report improved accuracy, but topic-specific harm classes must stay visible.
5. **Accessibility and language robustness** — conversational access helps some users but can hide ambiguity, disability, and language effects.
6. **Feedback-to-correction clock** — pilots and evaluation are promising only if correction loops remain live after wider launch.
7. **Incident disclosure threshold** — public incident rules should be explicit before high-stakes domains expand.
8. **Supplier / model-change record** — Anthropic / AWS Bedrock, Claude model, embeddings, and model updates require change records.
9. **Human / authoritative handoff** — the tool must preserve a route to official guidance, forms, and agency decisions.
10. **Withdrawal / transition receipt** — a pilot or staged opening requires public criteria for narrowing, pausing, expanding, or retiring.

### 6. Opposition and rival readings

**Rival 1: the tool is safe because it only summarizes GOV.UK.** The archive rejects overconfidence. Retrieval and summarization can omit conditions, exceptions, deadlines, devolved variation, or eligibility caveats.

**Rival 2: the tool should not exist because official brands magnify hallucination risk.** The archive rejects categorical prohibition. A source-bound, evaluated, transparent, staged assistant may reduce confusion compared with unaudited consumer AI or poor search.

**Rival 3: source links transfer responsibility to the user.** The archive partly accepts the concern. Links are necessary but not sufficient. The assistant must not issue confident instructions that ordinary users cannot verify.

**Rival 4: no-decision language is enough.** The archive rejects formalism. The tool can still shape practical access, triage, and expectations. If it begins to prefill, route, score, recommend eligibility, or affect case handling, `874` must activate.

### 7. Capture and theater channels

- **summary capture**: a short answer displaces a complex official page.
- **brand reliance capture**: GOV.UK identity makes an answer feel authoritative.
- **accuracy-percentage theater**: aggregate accuracy can hide high-stakes domain failures.
- **source-link theater**: users may see links without understanding which proposition each link supports.
- **guardrail theater**: jailbreak success/failure does not measure ordinary incomplete guidance risk.
- **model-change opacity**: model upgrades can change behavior without user-visible doctrine change.
- **pilot-to-platform drift**: a limited experiment can become infrastructure before the public knows the expansion criteria.

### 8. Repair surfaces

Keep the packet open around:

- topic-specific accuracy, completeness, and harm-class metrics;
- source / proposition traceability;
- corpus freshness and excluded-content rules;
- model and embedding version logs;
- prompt / guardrail / refusal policy records;
- user feedback and correction records;
- incident thresholds and public reporting;
- accessibility, language, and ambiguity tests;
- escalation paths for benefits, tax, immigration, health, housing, and enforcement topics;
- expansion, pause, and retirement criteria.

### 9. Holding

GOV.UK Chat is a promising positive-control case because it makes many governance records visible. The archive should praise that visibility while refusing to let a helpful summary become a public-law decision. The clean boundary is: conversational access may improve guidance, but decisions still need the ordinary public-law path.

## Anti-theater tests

This packet fails if source-bounded design becomes a blanket safety claim. The public record must keep topic-specific accuracy, source traceability, model and corpus versioning, incident thresholds, high-stakes handoff, user-comprehension evidence, and expansion / pause criteria visible as the assistant moves from limited pilot toward ordinary service infrastructure.
