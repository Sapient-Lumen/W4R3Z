# 847 — Scope-cluster consolidation pass for Radical Governance: first-citation map, supersession docket, applied-use triggers, and no more parallel answer keys

## One-line thesis

The archive should now treat the broad scope-answer cluster as consolidated: `841` is the pocket answer, `790` is the longer dispatch, `825` through `840` are live lens notes, `842` through `846` are the audit and maintenance shell, and older broad restatements should be cited only for lineage or a retained specialist detail unless a case packet proves they still carry a unique active function.

## Why this matters

The previous reconstruction created the retirement docket but deliberately stopped short of applying it. That was prudent for one pass, but a docket that never touches real notes becomes another layer of governance theater.

This note applies the docket to the archive's highest-risk cluster: repeated answers to the question **what would ideal governments of each scope be?** The answer exists, but it exists in several generations. Without a first-citation map, a reader can mistake discovery history for equal authority, and future additions can re-summarize instead of testing.

The goal is not deletion. The goal is to reduce parallel authority. A reader should know where to start, when to branch, and when an older note is being used only because it preserves a detail not yet carried by the canon waist.

## Failure modes

- Treating every historical broad-scope note as equally current.
- Adding another answer key when a citation map, case packet, or source repair would do.
- Retiring notes silently instead of preserving lineage and specialist-detail triggers.
- Freezing machine-readable status before applied packets show which labels survive use.

### 3. Supersession is a routing claim, not a truth claim

An older note can be superseded as a first citation while still being true, useful, or historically important. Supersession here says: **the archive now has a better first stop for ordinary use**.

Use an older broad-scope note only when one of these conditions is met:

- it contains a specialist concept not carried into `841`, `790`, or the lens run;
- a case packet needs to reconstruct the genealogy of a doctrine;
- an opposition brief is testing whether the new canon lost something important;
- a source repair is comparing old anchors with better current anchors;
- the note is being considered for merge, burial, or reactivation.

Otherwise cite the waist.

### 4. No more parallel answer keys

A new note should not answer **what should ideal governments of each scope be?** again unless it changes the status of the canon. Acceptable additions are narrower:

| Addition type | Acceptable form |
| --- | --- |
| case packet | tests the canon against a named real governance arrangement |
| opposition brief | strengthens the adversary, falsifier, harmed-party, or capture-channel layer |
| lens note | adds a genuinely missing dimension, not another summary |
| source repair | updates anchors without turning the source note into doctrine |
| consolidation pass | merges, routes, or demotes existing material |
| machine-readable status and case matrix | allowed after `849`–`855`, but reversible and subordinate to note text |

If a proposed note merely says the canon again in a new order, it should become a paragraph in an existing note or not be added.

### 5. Applied-use triggers before new doctrine

Before adding doctrine to the scope cluster, require one of these triggers:

| Trigger | Evidence required | Likely output |
| --- | --- | --- |
| live design problem | a real charter, statute, treaty, reform proposal, or institutional failure | case packet or design memo |
| contradiction between notes | exact notes and claims that conflict | consolidation pass or amendment note |
| current law changed | official source showing a changed legal or institutional baseline | source repair plus targeted note edit |
| repeated reader confusion | at least two locations where routing misleads | dispatcher table or glossary patch |
| serious rival theory | named alternative that would choose a different scope | opposition brief |
| missing governance dimension | cannot be handled by `825`–`840` | one new lens, with retirement review attached |

This turns growth from thematic association into accountable need.

The archive should now prefer status labels and dispatch tables over new doctrinal prose.

### 7. Canon-use checklist

When using the scope doctrine, record five facts:

1. Which scope is being assigned power?
2. Which first-citation note supports the assignment?
3. Which rival scope would plausibly claim the function?
4. What source or case evidence proves the chosen scope can actually perform?
5. What handback, override, or review clock prevents permanent overreach?

If those five facts cannot be stated, the archive is not yet designing government. It is only naming tiers.

### 8. Reconstruction verdict

The broad scope-answer cluster is now **consolidated but not closed**.

It is consolidated because ordinary readers should start with `841`, deepen through `790`, use `825`–`840` only by lens, and route criticism through `842`–`846` plus this note.

It is not closed because applied packets may show that an older note carries a missing concept, that a lens is too thin, that the pocket answer overfits one constitutional tradition, or that the cross-boundary dispatcher fails under use. In that case, the right move is not another parallel answer key. The right move is a case-tested amendment to the canon waist, a source repair, a dispatcher repair, or a status change.
