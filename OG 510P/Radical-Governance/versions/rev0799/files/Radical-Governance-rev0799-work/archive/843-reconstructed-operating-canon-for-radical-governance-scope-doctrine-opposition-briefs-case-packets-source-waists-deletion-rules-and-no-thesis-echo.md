# 843 — Reconstructed operating canon for Radical Governance: scope doctrine, opposition briefs, case packets, source waists, deletion rules, and no thesis echo

## One-line thesis

The archive should now operate through a **canon-first architecture**: use `841` for the pocket answer, `790` for the longer scope doctrine, `842` for the self-audit, this note for growth discipline, the default and threshold notes only when a specific lens is live, `844` for adversarial testing, `845` for applied case-packet selection, `846` for retirement and merge discipline, and no new numbered note unless it fills a declared gap, carries an opposition brief, has a source-index entry, and cannot be achieved by editing, merging, source repair, or retirement labeling.

## Why this matters

A governance research archive needs two opposite virtues. It must be exploratory enough to discover new institutional forms, but disciplined enough that discovery does not become unusable abundance. The Radical Governance archive now has the first virtue. This note is meant to supply more of the second.

The archive’s central answer is no longer missing. It can already say what ideal governments of each scope should normally be, which powers fit each scale, how authority should be selected, financed, reviewed, bounded, amended, and preempted, and how cross-boundary forms should be chosen and audited. The live risk is now canon drift: future work may cite whatever adjacent note happens to be memorable, add new notes for small variations, or treat defaults as if they were self-proving.

This note reconstructs the operating canon. It tells future work where to start, when to deepen, when to challenge, when to repair sources, and when to refuse a new note.

## Pattern pack

### 1. Use the canon-first reading order

When the broad question is **what would ideal governments of each scope be?**, the archive should start here:

| Reader need | First stop | Then use |
| --- | --- | --- |
| pocket answer | `841` | `790` only if the reader needs the longer dispatch |
| audit of archive quality | `842` | this note for operating rules |
| regime-form, mandate, finance, oversight, coercion, records, emergency, participation, courts, guarantees, amendment, or preemption | `825` through `840` | only the relevant lens, not the whole run |
| benchmark or scoring | `791` | `800`, `808`, and `811` when review practice is live |
| challenger rights or rebuttal | `797` | threshold and verdict notes when evidence is contested |
| threshold proof for new or changed tiers | `810` | `811` for applied verdict packets |
| cross-boundary institutional form | `812` through `824` | the specific legitimacy, fiscal, administrative, oversight, participation, information, boundary, decision, dispute, asset, contracting, or enforcement chain |
| field-specific design | domain notes from `403` onward | only after the scope and lens question are known |

This order is not decorative. It is a cost-control rule. The archive should make the first citation point obvious.

### 2. Declare the note class before adding the note

Every future numbered addition should declare one primary class.

| Note class | Use when | Do not use when |
| --- | --- | --- |
| **canon waist** | several existing notes need one authoritative first citation point | the old notes are already easy to cite |
| **lens note** | a genuinely distinct design axis is missing | the axis is a synonym for an existing lens |
| **threshold note** | the archive needs evidence rules for a boundary question | the answer is just another default |
| **case packet** | a real polity, proposal, or failure needs applied judgment | the case facts are not stable enough to preserve |
| **opposition brief** | a strong default needs adversarial testing | the note only repeats the favored view |
| **source repair** | a claim cluster needs better grounding or current replacement sources | the source does not change the archive’s usable judgment |
| **deletion or merge map** | several notes should be retired, superseded, or folded | deletion would destroy a useful discovery path |

If a proposed note does not fit a class, it is probably a thesis echo.

### 3. Install the no-thesis-echo gate

A new note should be rejected, merged, or converted to an edit if it cannot answer all of these:

1. Which existing note is insufficient?
2. Is the insufficiency conceptual, evidentiary, navigational, or applied?
3. What new decision will the archive be able to make after this note that it could not make before?
4. What older note becomes less central because this one exists?
5. What is the shortest safe version of the addition?

The answer **this makes the point clearer** is not enough by itself. Clarity matters, but repeated clarity can become archive fog.

### 4. Require a compact opposition brief for strong defaults

For any note that strengthens a default, adds a presumption, or converts a recurring pattern into a canon rule, include an opposition brief.

The compact form is:

| Opposition field | Question |
| --- | --- |
| strongest rival rule | What would a serious opponent prescribe instead? |
| embarrassing case | Where has this default failed, overreached, or been captured? |
| falsifier | What evidence would make the archive demote the rule? |
| harmed party | Who is most exposed if the rule is applied mechanically? |
| capture channel | Who can exploit the rule’s language to gain power without accountability? |

The opposition brief should not be performative balance. It is an anti-capture device.

### 5. Use claim-status labels in applied work

Applied governance work should not cite an archive note as if all claims have the same authority. Use status labels.

- **Settled holding**: the archive’s current first answer; rebuttable only by strong case evidence.
- **Strong default**: the normal design preference; rebuttable by context, capacity, legal bargain, or rights floor.
- **Threshold frontier**: a boundary question requiring evidence, comparator, and review clock.
- **Case diagnosis**: a fact-bound judgment about one polity, proposal, intervention, or failure.
- **Hypothesis**: an exploratory claim preserved for testing, not direct design authority.

This label should appear in case packets, benchmark verdicts, and any future note that applies the archive to a real government.

### 6. Make source-waist coverage complete but not bulky

The archive should keep sources in `SOURCES.md` and `SOURCES.json`, not in giant quoted blocks inside notes. A source entry should be compact but complete enough to show why the note is not self-authorizing.

The source-waist rule after this reconstruction is:

- every numbered archive note should have a source-index entry unless explicitly exempted as a pure internal tool or generated surface;
- source groups should cite official, primary, or high-quality analytical sources whenever possible;
- obsolete governance sources should be replaced or labeled rather than silently retained;
- sources should be cited, not downloaded into the archive;
- no source entry should be padded merely to look authoritative.

This revision’s backfill for `403` through `438` is the first application of that rule.

### 7. Prefer case packets over more universal doctrine once the doctrine is settled

The archive has enough universal doctrine to begin applied testing. Future progress should increasingly come from case packets, not only more defaults.

A case packet should answer:

1. What polity, proposal, or institutional failure is being judged?
2. Which scope does it claim to occupy?
3. Which archive holding or default is being applied?
4. What evidence supports the claim?
5. What evidence contradicts it?
6. What is the verdict: keep, thicken, thin, hand back, merge, split, sunset, or audit further?
7. What review clock should revisit the judgment?

This will expose whether the archive’s elegant scope theory survives empirical and political stress.

### 8. Keep deletion conservative but real

Deletion should be possible, but not impulsive. The archive is valuable partly because it preserves the path by which ideas became usable.

Use four retirement statuses:

| Status | Meaning |
| --- | --- |
| **active** | first-line or still-useful note |
| **superseded** | preserved for history but no longer first citation point |
| **merge candidate** | content should be folded into another note or canon waist |
| **burial candidate** | obsolete, duplicative, or misleading enough that preservation imposes more cost than value |

A retirement label is better than silent deletion. It lets the archive slim without pretending it never changed its mind.

### 9. Put political economy into every serious design move

A government design is incomplete until it names who can profit from failure. Future notes should include at least one sentence naming the capture channel.

Examples:

- municipal headroom can be captured by local exclusion, land hoarding, or service inequality;
- metropolitan authority can be captured by infrastructure contractors, central-city dominance, or suburban veto bargaining;
- regional autonomy can be captured by patronage machines or separatist elites;
- national guarantee can be captured by central ministries using rights language to monopolize ordinary administration;
- global narrow-waist bodies can be captured by donors, secretariats, expert panels, or dominant states.

The archive should not allow institutional beauty to hide power incentives.

### 10. Treat reconstruction as an operating loop

After this revision, reconstruction should be an ongoing loop:

1. **canon** — identify first citation points;
2. **critique** — name failure modes and opposition;
3. **source** — repair grounding and current-source drift;
4. **apply** — test doctrine on real cases;
5. **retire** — mark superseded, merge, or burial candidates;
6. **repeat** — only add new doctrine when the loop proves a real gap.

This loop should be cheaper than adding more universal notes.

## New-addition decision tree

Before creating a new numbered note, future work should ask:

1. Is the question already answered by `841`, `790`, or `825`–`840`?
2. If yes, does the proposed work apply that answer to a case rather than restating it?
3. If no, is the gap a new lens, a threshold frontier, an opposition brief, or a source repair?
4. Can an existing note be edited instead?
5. Would a source-index entry, generated-surface refresh, or retirement label solve the problem?
6. Does the proposed note contain a hardest counterexample and a capture channel?
7. Is the proposed note short enough to reduce future reading cost?

Only after passing that tree should a new note be added.

## Guardrails

- Canon first; lenses second; cases third; domain modules only when the case needs them.
- No new note by thesis echo.
- Every strong default gets an opposition brief.
- Every numbered note gets source-waist coverage.
- Generated surfaces route attention; they do not prove doctrine.
- Deletion should be labeled before it is executed.
- The archive should increasingly test its doctrine on cases rather than endlessly refine universal language.

## Failure modes

- **canon drift**: readers cite different compression layers as if all are equally first-line.
- **opposition omission**: the archive becomes persuasive but not stress-tested.
- **source padding**: source entries grow longer without becoming more probative.
- **case avoidance**: universal doctrine keeps expanding because real application is harder.
- **retirement cowardice**: nothing is ever superseded, so every note remains notionally current.
- **political-economy blindness**: capture channels are left unnamed because the institutional design sounds clean.

## Practical tests

The reconstructed archive is working when a reader can do all of the following quickly:

1. answer the headline scope question from `841` without reading the entire corpus;
2. find the correct deeper lens from the canon map;
3. tell whether a claim is settled, default, frontier, case diagnosis, or hypothesis;
4. locate structured sources for every numbered note;
5. see the strongest objection before a default becomes stronger;
6. apply the doctrine to a real government through a case packet;
7. identify which notes are active, superseded, merge candidates, or burial candidates.

## Compression rule for the archive

The archive should now grow by **necessity, not adjacency**. A new note is justified only when it reduces future confusion more than it increases future surface area. The default repair should be canon clarification, source repair, opposition briefing through `844`, case application through `845`, or retirement labeling through `846` — not another elegant restatement of a doctrine the archive already knows.
