# Rev0982 audit record

Rev0982 adds one offline, immutable primary-replica SQLite backup artifact. The shipping command acquires the deployment singleton, opens the attested source through the retained owner, captures one transactionally pinned canonical SQLite image under explicit 512 MiB and 262,144-page ceilings, brackets the capture with exact source cutpoints, publishes create-new at mode 0600, and independently reopens and re-proves the durable artifact. Detached inspection requires the deployment manifest but does not open the live primary database family.

The adjacent review corrected two authority defects. A detached deserialized SQLite image cannot be classified by `sqlite3_db_readonly()` alone, so the final verifier requires the exact in-memory journal identity, retained query-only profile, and an actual `SQLITE_READONLY` denial inside the typed nested-savepoint owner. The sanitizer product lane also exposed a completed-stop pathname race; only a validated stop response may accept exact post-response socket disappearance, while every other command still requires final owner, inode, and mode reproof.

The initial release reconstruction omitted the two stop-race files and later inventory hardening. Final sealing therefore regenerated the binary-aware patch from the frozen source and proved the actual 17-file active delta plus the complete 577-file projection byte-for-byte and by mode. The package does not claim whole-share backup, restore execution, payload completeness, trusted time, durable retention-age reset, external anti-rollback authority, or collection permission.
