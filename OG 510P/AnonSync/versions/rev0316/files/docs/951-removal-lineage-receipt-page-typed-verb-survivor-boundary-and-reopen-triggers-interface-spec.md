# Removal lineage receipt page: typed verb, survivor boundary, and reopen triggers interface spec

## Purpose

This receipt preserves the meaning of a completed or attempted remove-like action.
It exists so later operators do not need menu folklore or platform memory to answer:

> which removal family ran, which planes changed, what survived, and what could return or reconnect later?

## Required receipt fields

The receipt must preserve at minimum:

- receipt id and timestamp
- target subject or seat
- typed removal verb family
- initiating projection and platform
- affected scope / audience
- local byte effect summary
- placeholder effect summary
- seat / linkage effect summary
- remote survivor summary
- hidden service / archive residue summary
- reversibility class
- comeback / reconnect risk summary
- strongest safe sentence
- stronger rejected sentence
- reopen triggers

## Receipt body order

1. outcome header
2. changed planes summary
3. survivor and residue summary
4. comeback and branch-risk summary
5. reopen triggers

### 1) Outcome header

Show the final verb family, verdict, and proof ceiling.

### 2) Changed planes summary

Show which planes actually changed: seat roster, seat linkage, subject registration, local bytes, placeholders, archive/service residue, and remote peers.

### 3) Survivor and residue summary

Show what remained locally, what remained remotely, and which stronger deletion claim would have been false.

### 4) Comeback and branch-risk summary

Show whether the subject can reconnect, whether a hidden seat can reappear, and whether default-path reconnect can create a sibling branch.

### 5) Reopen triggers

Include triggers such as:

- hidden seat comes back online
- reconnect is attempted with a different default path
- remote full-copy witnesses disappear
- reinstall or re-add is attempted
- a later delete or unlink action supersedes this receipt

## Rules

### Rule 1 — the receipt must preserve typed meaning

`Removed` is not enough.

### Rule 2 — survivor truth must survive success wording

Later operators need to know whether remote peers, archives, or latent seats still remain.

### Rule 3 — reopen triggers are part of the contract

A removal action is not fully understood until the product records how continuity can return or drift later.
