# AnonSync rev0858

## Mission increment

AnonSync treats a validated manifest as transition authority for identity,
diff planning, chunk scheduling, staging, publication, and recovery. Rev0858
makes that authority explicitly resource-bounded before those downstream
operations can begin.

## Severe defect corrected: aliased path input was erased

`normalize_sync_relative_path()` previously began by clearing its output. Its
input is a `const std::string&`, and callers are permitted to pass the output's
own `value` as that input. In that legal aliasing case the implementation erased
the observation before checking it, then reported an empty-path failure.

The extracted owner validates the complete borrowed input before mutating the
output. Valid in-place normalization succeeds. Invalid aliased input is
rejected and leaves the output empty. Focused tests exercise both directions,
and the source audit requires the validation-before-clear ordering.

## Resource-bounded manifest owner

`sync_manifest_validation` now owns:

- portable sync identifier syntax;
- strict UTF-8 validation;
- portable relative-path validation;
- manifest-entry semantics;
- folder-manifest ordering and publisher binding; and
- typed cardinality and metadata budgets.

`SyncManifestResourceLimits` controls:

- entries;
- chunks per entry and in aggregate;
- lineage entries per entry and in aggregate;
- aggregate path bytes; and
- aggregate typed metadata bytes.

The folder validator uses a two-phase preflight. Phase one observes only vector
sizes and path string lengths. Any oversized nested vector is rejected before
an element is inspected, hashed, compared, or copied. Phase two traverses
nested values only after aggregate counts are bounded. Every `size_t` conversion
and `uint64_t` addition is checked. `SyncManifestResourceUsage` is published
only after semantic validation succeeds, so failure cannot leave apparently
authoritative partial evidence.

The single-entry validator applies the same per-entry and aggregate policy.
The existing public entry and folder validators delegate to one named default
policy, while focused tests inject exact small limits for inclusive-boundary and
one-over-boundary proofs.

## Audit/refactor result

The former domain implementation allocated a vector of path components and one
string per component. The new owner performs one component scan with
`std::string_view`. It uses explicit ASCII case folding rather than ambient
C/C++ locale. Lineage and path ordering retain borrowed prior values rather
than copying strings on every iteration.

Research against Microsoft's current Win32 naming documentation exposed a
missing portability case: ISO-8859-1 superscript digits 1, 2, and 3 participate
in reserved `COM#` and `LPT#` device names. Their UTF-8 spellings, including
extension forms such as `COM².txt`, are now rejected. The focused test and
source audit bind all three spellings.

Unknown `SyncManifestEntryKind` values now have an explicit fail-closed result.
The extracted source is separately linked, appears in the invariant-owned and
sanitizer inventories, and is not duplicated in the domain source list.

## Boundaries not crossed

The typed owner cannot undo allocation already performed by an upstream
decoder. No claim is made that every manifest construction path applies limits
before allocation. A budget-aware wire/persistence decoder remains necessary.

This revision does not prove arbitrary omission/partition healing, whole-system
convergence, protocol confidentiality or anonymity, metadata hiding, hostile
worker isolation, Windows runtime behavior, Release-mode behavior,
ThreadSanitizer coverage, or full-project sanitizer coverage.
