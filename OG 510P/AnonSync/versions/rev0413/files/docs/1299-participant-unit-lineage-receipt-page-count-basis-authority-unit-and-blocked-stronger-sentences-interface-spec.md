## Participant-unit lineage receipt

### Receipt purpose
Preserve exactly what unit the product was talking about when it made a people / peer / participant claim.

### Receipt fields
- **Claimed phrase**: the sentence the operator saw
- **Participant unit class**
- **Current display planes**: identity name, device name, row label
- **Count basis**
- **Authority basis**
- **Approval-memory scope**
- **Grouping source**: folder family, linked-identity witness, or none
- **Recent invalidators checked**: unlink, identity regeneration, regroup, device rename, surface switch
- **Strongest safe sentence**
- **Blocked stronger sentence**
- **Reopen conditions**

### Example blocked stronger sentences
- `these two rows are definitely the same approved person`
- `disconnecting this row revokes every linked device`
- `three peers means three independent authority holders`
- `same human-readable name means same trust history`

### Product requirement
Every peer-count badge, approval decision, permission edit, and disconnect action must be able to open this receipt directly from the UI.
