# Governance-plane lineage receipt page — authorship plane, override basis, and blocked stronger sentences

## Purpose

This page answers one ordinary question later:

> what plane actually governed this value, what lost, what inheritance state survived, and which stronger sentence did the product refuse to make?

## Core decision

Every meaningful governance verdict must emit one durable **Governance-plane lineage receipt**.

## Receipt fields

### Header

Show:

- value
- subject / scope target
- event type
- time
- operator intent

### Winning plane

Show:

- winning plane name
- current value
- scope
- basis of victory
- any rejected stronger or simpler plane story

### Inheritance state

Show:

- `live-inherited`, `manually-detached`, `config-pinned`, `service-world-owned`, or `unknown`
- event that created that state
- whether broader default changes still flow through

### Witness and activation

Show:

- best current witness surface
- weaker witness surfaces
- activation boundary class
- whether the winner is merely saved or proven active

### Losing planes

Show:

- losing or shadowed planes
- why they lost
- what claim they still weakly support

### Strongest safe sentence

Show:

- strongest safe sentence
- stronger blocked sentence

### Reopen conditions

Show:

- what future event invalidates this receipt
- what stronger proof would be required for a stronger claim

## Copy rules

- Use exact plane names, not fuzzy synonyms.
- Preserve blocked stronger sentences verbatim enough for later review.
- Never collapse `same shown value` into `same governance lineage`.
- Never collapse `editable on one surface` into `governing plane overall`.
- Never collapse `saved into a colder plane` into `already active winner`.
