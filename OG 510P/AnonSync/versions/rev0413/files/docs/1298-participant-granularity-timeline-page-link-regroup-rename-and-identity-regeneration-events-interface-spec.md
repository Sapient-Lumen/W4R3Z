## Participant granularity timeline

### What this timeline tracks
The timeline explains why the same underlying human relationship may appear as different counts or rows over time.

### Event classes
- **Link devices into one identity**: can collapse future approvals and regroup later views under one participant family.
- **Share through Advanced folder**: may render grouped user rows with child devices.
- **Share through Standard folder**: may render device seats separately with no user identity in the peer list.
- **Rename device**: changes one display plane without necessarily changing authority continuity.
- **Change identity name by unlink/regenerate**: breaks certificate continuity even if the human-facing name looks similar later.
- **Unlink a device**: can split a former family into separately counted units.
- **Surface switch**: desktop, mobile, or other views may emphasize different label planes.

### Timeline output
For any participant-related incident, show:
- current participant-unit class
- last regroup event
- last authority-breaking event
- label-drift events since last authority proof
- count-basis shifts caused by folder-family or surface changes
- next event that would invalidate the current safe sentence

### Safe-language examples
- `one grouped participant containing two device seats`
- `two visible device rows; same-user relationship not proven on this surface`
- `same device label, new identity generation; prior approval memory expired`
