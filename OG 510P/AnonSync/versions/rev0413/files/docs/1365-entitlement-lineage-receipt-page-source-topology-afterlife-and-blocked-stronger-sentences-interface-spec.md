# Entitlement-lineage receipt page — source, topology, afterlife, and blocked stronger sentences

## Purpose

This receipt gives one durable line-item answer to:

> why is this capability available or unavailable here, through what entitlement source and topology, under what usage lane, and what stronger entitlement sentence did the product refuse to make?

## Receipt fields

### Identity block

- subject capability
- current node / participant unit
- current version / platform lane
- current usage lane

### Entitlement basis block

- entitlement source
- topology class
- grant authority holder
- revocation authority holder
- strongest proof rung reached

### Afterlife / cliff block

- feature-afterlife class
- strongest current cliff
- recovery path
- whether current surface can cure it

### Strong-sentence block

- strongest allowed sentence
- blocked stronger sentence
- exact reason blocked

## Copy rules

- Prefer `active through revocable seat`, `active but wrong support posture`, or `trial only` over generic `licensed`.
- Prefer `owner-controlled entitlement` over `independent Pro` when business-owner topology still governs.
- Prefer `site-issued non-commercial activation` over `free` when activation remains mandatory.
- Prefer `feature cliff on entitlement loss` over `may stop working` when a specific feature is known to stop.

## Example final sentence pattern

> `This capability is currently available because <source/topology>; stronger sentence <durable / legitimate-for-this-lane / independent / server-qualified> was blocked by <missing proof>.`
