## Path-projection contract sheet

### Purpose
Make the product say **what pathname truth can actually survive this cohort** before it says `same file`, `safe rename`, `supported`, or `will sync`.

### The contract object
Each serious path-bearing subject renders these fields together:

- **Visible pathname**: the current user-facing path as shown on this seat.
- **Canonical identity handle**: the stronger identity basis, if any, that survives display rewrites.
- **Filesystem dialect class**: case-sensitive, case-folding, normalization-sensitive, symbol-rewriting, length-limited, or mixed / unknown cohort.
- **Normalization posture**: composed, decomposed, byte-preserving unknown, or normalization-mixed.
- **Case posture**: case-distinct, case-collapsing, or unknown.
- **Symbol projection class**: preserved, rewritten, blocked, or unsafe / platform-specific.
- **Length ceiling basis**: current local ceiling, tight cohort ceiling, or unknown weakest ceiling.
- **Object-kind projection**: regular file, directory, symbolic-link object, unsupported link class, placeholder representation, or unknown.
- **Loss boundary**: no loss seen, rewrite risk, conflict risk, block risk, target-detached link risk, or unknown.
- **Blocked stronger sentence**: the next stronger statement the product refuses to make.

### Default language rules
- `same path` is intentionally weaker than `same canonical identity`.
- `name preserved` is intentionally weaker than `name survived without rewrite`.
- `supported here` is intentionally weaker than `safe across this cohort`.
- `link synced` is intentionally weaker than `link target coverage survives`.
- `UTF-8-looking` is intentionally weaker than `canonical encoding compatibility proven`.

### Required persistent receipts
Any serious add, rename, preflight, reconnect, or conflict-remediation action stores one durable receipt preserving dialect class, normalization posture, symbol projection, length ceiling basis, object-kind projection, loss boundary, and the blocked stronger sentence.
