The next product problem is precise: Rev0700 can run one bounded scheduler executor pass, but it still does not own a daemon lifecycle. A production worker needs durable identity, repeated bounded passes, backpressure, terminal-review stop conditions, and real peer transport binding.

## P0 — preserve the product noun: peer-to-peer folder convergence

1. **Keep testing folder convergence, not abstract ledger machinery.** Every new primitive should explain how it moves authorized devices toward the same folder tree or preserves evidence for safe recovery.
2. **Wrap the scheduler executor in a persisted daemon loop before adding production transport.** Rev0700 proves a single bounded mutating pass; the next seam is safe repetition with stop conditions.
3. **Keep every mutation evidence-bound.** No restart executor should mutate filesystem or SQLite state unless it first reloads checkpoint integrity, root evidence, manifest rows, apply intent rows, action-router state, and the durable workorder rows it owns or safely reclaims.
4. **Do not let the scheduler become a side-channel mutator.** Scheduler execution may select complete groups and call existing mutators, but it should not write workorder rows directly or bypass claim/execution/quarantine/abandon invariants.
5. **Delay production transport until local restart truth is complete.** Real peer messages should reuse the same chunk, receipt, idempotency, workorder, lease, checkpoint, retry-at, reclaim, abandon/quarantine, reset, queue-selection, scheduler-action, scheduler-group, scheduler-executor, and cleanup transitions already proven by local fake-peer execution.

## P1 — next engineering targets

1. **Add a persisted bounded daemon worker loop.** It should keep stable worker identity, call `execute_sync_session_checkpoint_resume_transfer_workorder_scheduler_pass(...)` repeatedly with limits, and stop on empty, cooldown-only, live-other-only, terminal-review, or backpressure states.
2. **Bind real peer response acceptance to owned claims.** The production path should accept authenticated peer bytes only when they satisfy an already claimed workorder row; source-root shortcut reads must remain a test harness behavior.
3. **Build an operator/recovery workflow around terminal review and reset.** Core reset, queue-review facts, scheduler-review actions, and scheduler observation exist; the product still needs inspect/list/approve affordances and a policy boundary around who may reset abandoned versus quarantined work.
4. **Add tombstone and conflict replay branches.** Deletes and conflict copies should move through the same checkpoint/resume/workorder discipline as file fetch.
5. **Broaden quarantine reasons carefully.** Add suspicious retry-schedule/event-history cases as explicit reasons, not as generic exceptions.

## P2 — reduce review cost and strengthen release evidence

1. Split `sync_domain.cpp` and large selftests by sync trust domain: manifest/index/diff, transfer, peer/session, checkpoint, resume view, recovery executor, scheduler/workorders, and filesystem mutation.
2. Replace Boolean-manifest growth with smaller versioned schemas and a claim-to-test map tied to sync operations.
3. Rename deterministic `anonsync_fuzz_*` launchers as selftests, then add actual coverage-guided fuzz targets for manifest parsing, path normalization, chunk tables, workorder rows, and peer messages.
4. Extend product validators from phrase/package checks into stateful SQLite checks over row transitions, including complete scheduler action groups, bounded mutating daemon scheduling, and future daemon-loop repetition without silently deleting or overwriting evidence.
