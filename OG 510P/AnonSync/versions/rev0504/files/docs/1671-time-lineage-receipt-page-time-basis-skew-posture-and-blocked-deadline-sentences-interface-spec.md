# Time lineage receipt page — time basis, skew posture, and blocked deadline sentences

## Purpose

This page is the durable receipt for the strongest temporal sentence honestly in force now.
It exists so future operators can see what time basis is being relied on, which deadlines are trusted, which are degraded or adjudicated, what stronger timer sentences remain blocked, and what correction or reopen event would change the receipt next.

## Required receipt blocks

### A. Source-state block

- source time-authority contract sheet
- source time-integrity review
- source deadline-integrity proof
- source action effectivity proof if used
- current temporal posture

### B. In-force block

- authoritative time basis now
- highest trusted temporal sentence now
- decisive skew class now
- decisive timer states now
- exact stronger deadline sentences still blocked now
- exact weaker temporal truths preserved now

### C. Boundary block

- deadline families currently trusted
- deadline families running but degraded
- deadline families frozen or reset
- deadline families reopened after correction
- adjudicated overrides in force
- exact next event that would strengthen or narrow this receipt

### D. Fragility block

- remaining skew risk
- remaining timezone risk
- exact correction or drift event that would narrow this receipt
- exact completion event that would strengthen this receipt
- whether any irreversible sentence is still weaker than it appears because time trust is partial

### E. Audit block

- decisive device and peer identities
- decisive UTC-normalization evidence
- decisive skew-warning records
- decisive timer records
- decisive correction records
- decisive reopen or adjudication records

## Sentences this receipt may support

- `timestamps observed, but irreversible deadline trust is degraded by peer skew`
- `protective effect remains in force; irreversible cooling is paused pending time correction`
- `deadline trust restored after correction; cooling restarted from the corrected trigger`
- `earlier expiry claim was reopened because the original time basis became suspect`
- `manual adjudication established the trusted effective time now in force`

## Failure modes the receipt must prevent

- forgetting what time basis supports the current strongest sentence
- forgetting whether the current timer is trusted, degraded, reset, or adjudicated
- overstating irreversible maturity from a merely observed elapsed interval
- confusing clock correction with automatic validation of all older deadlines
- letting future readers believe that one displayed timestamp proved the whole temporal case

## Stronger-sentence guard

The receipt may say `trusted cooling completion is now in force after restored UTC-consistent clocks and reset timing; earlier local-wall-clock completion claims survive only as historical observations, not as valid irreversible deadlines`.
It may not say `deadline definitely elapsed` unless that exact stronger state is truly supported.
