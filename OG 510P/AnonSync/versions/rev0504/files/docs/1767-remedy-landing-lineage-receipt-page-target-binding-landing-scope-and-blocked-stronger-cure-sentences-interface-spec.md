# Remedy-landing lineage receipt page — target binding, landing scope, and blocked stronger cure sentences

## Purpose

This receipt is the durable compact proof of how a cure did or did not land as intended.
It exists so later readers can see whether the product was honest about the gap between `finished transfer` and `landed in the intended operative target for the required cohort`.

## Receipt body

The receipt must record:

- case identifier
- source remedy-flight-protection receipt identifier
- current remedy-landing posture rung
- intended repair object summary
- intended target summary
- actual landing-path summary
- landing material-class summary
- duplicate or side-path summary
- placeholder-only summary
- archive-rebind summary
- encrypted or unreadable landing summary
- `.sync` continuity summary
- cohort landing summary
- strongest honest sentence
- strongest blocked stronger sentence
- exact blocker summary

## Receipt sentence families

The receipt must support concise summaries such as:

- `the cure finished, but side-path reconnect and duplicate directory risk still block target-bound landing`
- `landing is operative for the named cohort, while required-cohort landing remains blocked by placeholder-only residue`
- `archive rebind restored the object without retransmission, but operative adoption still depends on manual duplicate-path cleanup`
- `encrypted survivorship preserved substrate, but readable landing never occurred for the required cohort`
- `landing verification collapsed because target identity and actual path diverged across cohorts`

## Invariants

- the receipt never compresses finish protection, transfer completion, and target-bound landing into one word
- the receipt never hides duplicate-path or side-path residue behind a visible folder presence claim
- the receipt never lets placeholder-only or unreadable survivorship impersonate operative landing
- the receipt always preserves the blocker that prevented the stronger landing sentence
