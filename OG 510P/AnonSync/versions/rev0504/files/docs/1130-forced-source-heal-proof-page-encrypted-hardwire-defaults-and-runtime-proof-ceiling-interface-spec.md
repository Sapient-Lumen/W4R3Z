# Forced source-heal proof page: encrypted hardwire, inherited defaults, and runtime-proof ceiling interface spec

## Purpose

This page exists for seats where destructive source authority may be effectively hardwired or inherited rather than consciously toggled at the point of pain.
It answers one ordinary question:

> is source-heal active here because I chose it now, because a default authored it earlier, or because this seat class hardwires it — and what proof do I actually have that runtime behavior matches that claim?

## When this page must appear

Trigger this page for:

- encrypted F-key / backup seats
- RO subjects inheriting `overwrite_changes` defaults
- any seat where `Overwrite any changed files` is being relied on as a standing safety story
- any seat where delete / edit repair is expected to happen automatically without a new review

## Fixed page order

1. posture-origin header
2. origin and hardwire card
3. capability ceiling card
4. runtime-proof ladder
5. receipt/export rail

### 1) Posture-origin header

Show:

- subject / seat / runtime
- origin (`seat-class hardwire`, `subject-setting`, `default-setting`, `unknown`)
- current source-heal verdict
- strongest safe sentence
- stronger rejected sentence

### 2) Origin and hardwire card

Render rows for:

- encrypted custody hardwire
- Selective Sync allowed / forbidden
- subject-level overwrite flag
- default-derived overwrite flag
- currently visible share preference

### 3) Capability ceiling card

Show consequences such as:

- `Selective Sync unavailable on encrypted seat`
- `delete on encrypted peer is expected to be re-healed from authoritative peers if bytes still exist there`
- `local decrypt unavailable on encrypted custody seat without separate recovery path`
- `this surface can expose posture but does not prove behavior has been witnessed yet`

### 4) Runtime-proof ladder

Possible rungs:

- `documented seat-class hardwire only`
- `saved default only`
- `subject option visible`
- `subject option active`
- `behavior witnessed on affected object`

### 5) Receipt/export rail

Offer:

- `Emit non-authority convergence receipt`
- `Open read-only divergence review`
- `Open empty-target purge review`

## Rules

### Rule 1 — source-heal origin must stay visible

The page must not let the operator mistake seat-class hardwire for a one-off subject choice.

### Rule 2 — capability ceiling belongs on the same page

Encrypted hardwire without Selective Sync is materially different from ordinary RO overwrite.

### Rule 3 — proof origin and proof strength are different truths

A documented default does not by itself prove the running subject is already behaving that way.
