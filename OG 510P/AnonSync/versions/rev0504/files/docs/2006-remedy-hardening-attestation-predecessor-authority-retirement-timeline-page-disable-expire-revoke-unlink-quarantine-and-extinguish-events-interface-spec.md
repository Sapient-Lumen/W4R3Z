# Remedy-hardening-attestation predecessor authority retirement timeline page — disable, expire, revoke, unlink, quarantine, and extinguish events

## Purpose

This page is the time-ordered event view for how predecessor authority is supposed to die, shrink, or persist after a successor world becomes legitimate and discoverable.
It exists so the product can separate `new world stood up`, `old references moved`, `old actors still alive`, `quarantine imposed`, and `exclusive successor control proved`.

## Required event types

The timeline must preserve at least these event types:

- successor legitimacy ratified
- canonical successor pointer chosen
- predecessor key rotated or replaced
- predecessor handle redirected or tombstoned
- predecessor device unlinked locally
- predecessor device unreachable or unknown
- predecessor peer share removed
- predecessor permission lowered
- predecessor owner or revoke authority withdrawn
- predecessor copied link observed
- predecessor off-world recipient acknowledged
- predecessor service-world fork created
- predecessor rebuilt instance detected
- quarantine for named slice imposed
- contradictory predecessor actuation observed
- named-surface disablement confirmed
- named-slice retirement confirmed
- broader exclusivity claim blocked or downgraded

## Mandatory timeline questions

The page must answer in order:

1. **When did the successor become legitimate?**
2. **When did discovery move to the successor?**
3. **When were predecessor actuation lanes explicitly disabled, if ever?**
4. **When did contradictory evidence show the predecessor was still live?**
5. **When was quarantine imposed and for which slice or surface?**
6. **When, if ever, did the strongest honest sentence become `successor exclusive for named slice only`?**

## Event rendering rules

- Every event must show whether it affects discovery only, authority only, or both.
- Every event must show whether it is local, governed-slice, or off-world in scope.
- Every event must show whether it upgrades, preserves, or downgrades exclusivity standing.
- Contradiction events must remain visible even after later repair.

## Hard rules

The timeline must never let:

- `successor announced` erase `predecessor still acted later`
- `device unlinked` erase `remote unlink impossible`
- `share removed` erase `off-world copied link survives`
- `key rotated` erase `old-key cohort remained live`
- `quarantine imposed` erase `universal retirement still blocked`
