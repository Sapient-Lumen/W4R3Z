# Remedy-flight-protection lineage receipt page — finish protection, interruption budget, and blocked stronger cure sentences

## Purpose

This receipt is the durable compact proof of how well an active cure lane was protected against ordinary interruption.
It exists so later readers can see whether the product was honest about the gap between `runnable now` and `protected strongly enough to finish`.

## Receipt body

The receipt must record:

- case identifier
- source remedy-runway receipt identifier
- current remedy-flight-protection posture rung
- required cohort summary
- current execution cohort summary
- promised finish window
- interruption-budget summary
- queue and preemption summary
- scheduler and pause summary
- source continuity summary
- runtime fragility summary
- strongest honest sentence
- strongest blocked stronger sentence
- exact blocker summary

## Receipt sentence families

The receipt must support concise summaries such as:

- `runway exists and repair started, but higher-priority arrivals still leave it interruptible`
- `finish protection holds for named desktop cohort only; required cohort still depends on fragile single-source lane`
- `scheduler stays open long enough and ordinary preemptors are bounded, so required-cohort finish protection holds`
- `repair started, then stalled under hidden-task and rediscovery pressure before safe-finish time`
- `service metadata degraded; synchronization suspended; finish protection collapsed`

## Invariants

- the receipt never compresses runway readiness, start evidence, and finish protection into one word
- the receipt never hides source continuity fragility behind current source presence
- the receipt never lets queue priority configuration impersonate bounded interruption risk
- the receipt always preserves the blocker that prevented the stronger finish sentence
