# Remedy-hardening-attestation successor reference rebinding contract sheet page — predecessor handle set, canonical pointer, and retirement budget

## Purpose

This page is the compact contract for deciding whether a legitimate successor world has also become the canonical place that dependent humans and systems are meant to reach.
It exists so the product can distinguish `successor exists`, `successor inherits standing`, `some references rebound`, `old handles still live`, `canonical pointer published for named slice`, `predecessor handles tombstoned for named slice`, and `broader discovery continuity still blocked`.

## Core fields

- successor-reference-rebinding identifier
- source successor-inheritance receipt identifier
- predecessor-world identifier
- successor-world identifier
- governed slice identifier
- predecessor handle family under review
- predecessor handle inventory
- predecessor handle exposure class
- successor canonical pointer class
- successor canonical handle set
- handle-resolution rulebook version
- bridge-authority or rebinding authority source
- internal pointer-retirement status
- external pointer-retirement status
- copied-link or copied-key outside-governance status
- share-message or bookmark propagation status
- stale-handle discovery status
- tombstone publication status
- redirect or successor-resolution status
- dependent-party rebinding notice status
- current successor-reference-rebinding class
- highest currently safe rebinding sentence
- strongest blocked stronger sentence
- next fact that upgrades rebinding standing now
- next fact that collapses rebinding standing now

## Successor-reference-rebinding classes

The page must model at least these distinct classes:

- successor legitimate, rebinding unreviewed
- successor canonical pointer chosen, predecessor handles still live
- internal references rebound, copied external references unknown
- predecessor handles tombstoned for named slice only
- successor redirect live for named slice only
- stale predecessor handles still resolving
- rebinding notice sent, acknowledgement partial
- named handle family retired and successor pointer canonical for named slice only
- broader universal discovery continuity blocked

## Minimum required comparisons

The page must force explicit comparison between:

- successor legitimacy and successor discoverability
- canonical successor pointer and surviving predecessor handles
- internal retirement and external retirement
- redirect success and tombstone success
- chosen canonical handle and actually propagated handle
- handle retirement and dependent-party rebinding acknowledgement

## Hard rules

- `the successor world is valid` must never silently upgrade to `everyone now reaches it through the right handle`.
- `we re-shared or reconnected` must never silently upgrade to `all predecessor links or keys are retired`.
- `a new key was issued` must never silently upgrade to `all old keys stopped mattering`.
- `the new world has the same name or path` must never silently upgrade to `old references now safely mean the new world`.
- `some redirects work` must never silently upgrade to `all stale discovery vectors are closed`.
