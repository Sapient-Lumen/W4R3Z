# Remedy-hardening-attestation successor reference rebinding review page — do all references now point to the successor, and which predecessor handles still remain live?

## Purpose

This page is the operator-facing review that answers the practical aftermath question after successor-world inheritance is already understood: even if the successor may legitimately carry standing, do dependent humans and systems now reach it through the correct canonical handles, or do predecessor handles still remain live, copied, or ambiguous?

## Primary review prompts

The review must answer these prompts in order:

1. **Which successor-inheritance receipt is the starting basis for this rebinding review?**
2. **Which predecessor handle families are in scope: links, keys, bookmarks, copied messages, approval prompts, user-facing names, API or export references, or local path aliases?**
3. **What handle now counts as the canonical successor pointer for the named slice?**
4. **Which predecessor handles were tombstoned, which were redirected, which were reissued, and which remain uncontrolled?**
5. **Who has been notified of the canonical successor pointer, and who still appears to rely on predecessor-era references?**
6. **What is the strongest successor-reference-rebinding sentence the product may honestly publish now?**

## Review sections

### 1. Predecessor-handle basis board

Show:

- source successor-inheritance receipt
- predecessor world identifier
- successor world identifier
- predecessor handle families in scope
- strongest honest inheritance sentence before rebinding review

### 2. Canonical-pointer board

Show:

- chosen canonical successor handle
- whether it is internal only, external only, or both
- whether it resolves for all intended audiences
- whether redirects or tombstones exist for predecessor handles

### 3. Live-stale-handle board

Show:

- predecessor handles still live internally
- predecessor handles still live externally
- copied link and copied key exposure
- same-name or same-path ambiguity exposure
- old-key continuation exposure

### 4. Rebinding-notice board

Show:

- who was told about the successor pointer
- who acknowledged the rebinding
- who still appears to act on stale handles
- who is out of governance entirely

### 5. Sentence chooser

The review must output one and only one primary sentence class such as:

- successor inheritance stands, but rebinding has not yet been reviewed
- canonical successor pointer chosen, predecessor handles still live
- internal handles rebound, external copied references uncontrolled
- predecessor handles tombstoned for named slice only
- redirects live for named slice only, universal discovery still blocked
- named handle families retired and successor pointer canonical for named slice only
- stale predecessor handles still resolve, so stronger discovery claims remain blocked

## Hard rules

The review must never let an operator hide:

- stale links behind `reshared`
- old-key continuity behind `rotated`
- copied outward messages behind `canonical pointer chosen`
- same name or same path behind `successor discovered`
- partial rebinding behind `everyone now points to the new world`
