# Remedy-hardening-attestation regime-shift lineage receipt page — transition scope, world continuity, and blocked stronger sentences

## Purpose

This page is the durable receipt for the strongest honest regime-shift sentence after reviewing one or more named transitions.
It is the page a later operator opens when they need to know whether the durable state survived a world transition, which prerequisites mattered, which forks or unsupported paths occurred, and which stronger sentence remained blocked.

## Required receipt fields

The receipt must preserve:

- regime-shift robustness identifier
- source postcondition-durability receipt identifier
- named governed slice
- named transition class or transition set
- current regime-shift robustness class
- supported path status
- principal continuity status
- identity continuity status
- storage-root continuity status
- launch-parameter continuity status
- folder-class continuity status
- control-surface continuity status
- clone-or-collision warning status
- highest honest regime-shift sentence
- strongest blocked stronger sentence
- exact blocker summary
- next evidence needed for upgrade
- next evidence that would force downgrade
- issuance timestamp
- issuer identity

## Canonical sentence families

The receipt must support at least these sentence families:

- the target state is durable in the current world, but regime-shift survival is unreviewed
- the target state survives the named transition only if the same user, storage, and launch parameters are preserved
- the target state remains durable, but service-account or storage-world fork risk blocks a stronger continuity sentence
- the target state survives the named transition for the named slice only after explicit rebind or reconnect steps
- the target state is regime-robust across the named transition set for the governed slice
- broader all-transition permanence or universal migration robustness is blocked

## Hard rules

- The receipt must never collapse `survived this transition set` into `survives any transition`.
- The receipt must never collapse `manual rebind succeeded` into `continuity was automatic`.
- The receipt must never collapse `same bytes remained` into `same governing world remained`.
- The receipt must never collapse `unsupported clone did not visibly fail yet` into `supported continuity`.
