# Resilio remedy-hardening-attestation surface-claim governance, audience-scoped publication, and stale-claim-recall fragmentation evaluation

## Why this seam now belongs on the non-clone side

Current official Resilio docs are still admirably candid that `the product knows something`, `this surface may say it`, `that export may repeat it`, and `older visible statements have stopped being authoritative` are not one flat truth.
`Sync Main View (Desktop)` still says the main UI is a particular surface with a folders list, shared-files list, a 30-day History rail, and a green checkmark meaning files are synced with all connected peers — a narrower statement than any universal completion sentence.
`Configuring WebUI` still says WebUI is the default and only UI on Linux-based machines and the default UI for Windows service installs, so the same product truth already lives behind materially different rendering surfaces.
`Updating Sync to latest version` still says `Check now` is available in desktop settings but not in WebUI.
`Power user preferences` still says at least one removal-control preference is ignored in Linux WebUI.
`Setting custom name for sync shares` still says share names can differ in Sync UI from on-disk names, do not propagate to linked peers, yet can be inserted into generated links or QR flows.
`Sync Share Dialog (Desktop)` still says links can be copied to clipboard or sent through e-mail and messenger, which turns one local sentence or label into a relayed outward artifact.
`Resilio Sync change log` still records repeated UI, WebUI, history, and wording-adjacent fixes, which is another reminder that visible calm on one surface is not a durable global claim governor.

This is strong surface candor.
It is also exactly why AnonSync should not clone the present contract.
One ordinary answer to `what may this exact surface honestly say, copy, cache, notify, or export to this exact audience right now, and what older stronger sentence must be recalled or visibly demoted?` still depends on combining desktop status semantics, WebUI differences, surface-specific feature gaps, UI-only naming, share-link relay behavior, and change-log memory.

## Concrete fragmentation still present in current Resilio

Resilio today still makes the operator reconstruct publication truth from several disconnected facts:

- the dashboard and list surfaces speak in compact status idioms such as connected-peer green checks rather than typed audience-scoped sentence budgets
- WebUI and desktop do not expose identical capabilities or controls
- some preferences or actions differ or are unavailable on WebUI
- labels can be UI-local while outbound links carry a custom outward-facing name
- clipboard, e-mail, messenger, and QR flows can externalize a sentence or label without creating one case-owned publication receipt
- change logs remain part of the operator's practical understanding of whether a visible statement or surface bug should be trusted

That means several dangerous collapses stay easy:

- `green on this surface` can be misheard as `globally settled`
- `name shown here` can be misheard as `canonical name everywhere`
- `exported once` can be misheard as `still authoritative after downgrade`
- `same product` can be misheard as `same claim rules across desktop, WebUI, service, notification, and copied-link artifacts`
- `current internal ceiling known` can be misheard as `all audience-facing surfaces already obey it`

## Hard product decision

AnonSync therefore needs first-class objects for **surface class, audience class, allowed sentence budget, mandatory qualifiers, blocked stronger phrases, stale-claim recall status, export permission, supersession banner policy, and quote-safe receipt lineage** instead of leaving operators to infer publication truth from a mix of status glyphs, surface-specific controls, UI-only labels, and relay mechanics.

## Non-clone conclusion

Borrow the candor.
Do not clone the contract shape.

Resilio's current docs still answer the key question — `what can this exact surface honestly say or export now, to whom, and what older stronger sentence must be visibly demoted?` — only by making the operator combine:

- desktop-surface status semantics
- WebUI-versus-desktop capability differences
- surface-specific ignored or missing controls
- UI-local naming versus outward link naming
- copy, e-mail, messenger, and QR relay paths
- historical UI and WebUI fix memory from change logs

That is enough to justify a harder product stance:

> AnonSync is not cloning Resilio because knowing the truth internally is weaker than governing every speaking surface, and current publication truth is still reconstructed from separate UI, WebUI, naming, sharing, and change-log surfaces instead of being owned by one stable page family that says exactly what this audience may hear, what this surface may export, and which older stronger sentence has already been recalled.
