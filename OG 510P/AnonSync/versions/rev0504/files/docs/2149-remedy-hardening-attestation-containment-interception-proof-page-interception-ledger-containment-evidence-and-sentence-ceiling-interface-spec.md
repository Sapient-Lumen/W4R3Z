# Remedy-hardening-attestation containment-interception proof page — interception ledger, containment evidence, and sentence ceiling

## Purpose

This page is the proof surface for later readers who need to verify whether relapse channels were truly contained, merely narrowed, or only noticed after spread.
It must preserve containment evidence rather than just post-hoc operator confidence.

## Proof payload

The page must preserve at least:

- outsider / audience slice identifier
- corrected replacement identifier
- named channel set
- interception verdict per channel
- maximum spread before interception per channel
- residue-after-containment class per channel
- containment evidence artifact set
- unresolved residual audience set
- strongest honest containment sentence
- blocked stronger containment sentence

## Interception ledger

The ledger must support rows such as:

- `offline comeback precedence · watched only · spread may occur on reconnect · no automatic interception proof`
- `archive restore replay · narrowed by runtime detection only · may bounce back on later rescan · archive residue remains`
- `pause window residual effects · not intercepted · deletions and indexing still move · pause badge not proof`
- `read-only divergence · backflow blocked but peer fork remains · future sync suspended · cleanup proof missing`
- `disconnect device · future updates stopped · local filesystem residue remains · audience cleanliness still partial`
- `single-file UI removal · UI cleaned · device copy remains · no recipient-side deletion proof`

## Proof principles

The page must make it impossible to confuse:

- `channel noticed later`
- `channel narrowed`
- `channel intercepted before spread`
- `spread occurred but was later remediated`
- `residue still survives after containment`
- `a stronger containment sentence collapsed`

## Hard rules

The proof page must never allow:

- a watch receipt to erase the interception ledger
- a green status indicator to stand in for containment evidence
- an operator statement to stand in for recipient-side cleanup proof
- an unqualified `contained` sentence without named channel scope and residue scope
