# Remedy-hardening-attestation predecessor authority retirement proof page — old-world capability, quarantine, and exclusivity ceiling

## Purpose

This page is the proof-facing object for showing whether the predecessor world can still act and what ceiling therefore applies to any stronger `exclusive successor control` sentence.
It exists so the product can preserve actual retirement evidence instead of collapsing rebinding, resets, and local cleanup into overclaims.

## Required proof bundles

Every proof page must preserve these bundles:

### 1. Source-basis bundle

- source successor-reference-rebinding receipt
- governing rulebook version
- predecessor world and successor world identifiers
- governed slice identifier

### 2. Predecessor-capability bundle

- evidence predecessor can or cannot still write
- evidence predecessor can or cannot still share or invite
- evidence predecessor can or cannot still revoke or interfere
- evidence predecessor can or cannot still seed, serve, or relay
- evidence predecessor can or cannot still attract new dependents

### 3. Disablement bundle

- key rotation evidence
- expiration or unlink evidence
- share removal or permission-lowering evidence
- explicit disable or revoke evidence
- rebuild, reset, or identity-regeneration evidence
- service-world or storage-world fork evidence

### 4. Quarantine bundle

- named-slice quarantine controls
- excluded surfaces still unresolved
- off-world or ungoverned authority exposure
- split-world continuation markers

### 5. Ceiling bundle

- highest justified retirement sentence
- specific missing fact that blocks broader exclusivity
- contradictory evidence that would collapse current standing

## Proof outputs

The page must output at least:

- predecessor live capability assessment
- named-slice retirement assessment
- successor exclusivity assessment
- split-world activity assessment
- off-world authority ceiling
- blocked stronger control sentence

## Strong proof classes

The page must distinguish at least these proof classes:

- no reliable predecessor capability evidence
- disablement evidence present, capability still inferential
- named surface disabled only
- named slice quarantined only
- predecessor actuation extinguished for named slice only
- broader universal retirement not proved
- contradictory evidence implies split-world still active

## Contradiction triggers

The proof page must visibly downgrade if any of these appear:

- old-key peers continue syncing
- a predecessor device cannot be remotely unlinked
- remote non-linked devices may still hold and serve bytes
- copied links or recipients remain outside governance
- a service-world fork or rebuilt instance still behaves like an independent live actor
- any stale handle still admits or routes traffic to predecessor control

## Hard rules

The proof page must never let:

- key rotation evidence impersonate full predecessor retirement
- local unlink evidence impersonate remote disablement
- reference tombstoning impersonate live capability extinction
- successor inheritance evidence impersonate exclusive successor control
- named-slice quarantine impersonate universal world extinguishment
