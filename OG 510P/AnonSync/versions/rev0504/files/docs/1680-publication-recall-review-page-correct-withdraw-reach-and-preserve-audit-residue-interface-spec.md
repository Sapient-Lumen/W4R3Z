# Publication-recall review page — correct, withdraw, reach, and preserve audit residue

## Purpose

This page is the operator workspace for deciding how to unwind or narrow an already-published claim without overstating what the system can truly take back.
It exists so the archive can distinguish `we changed the current surface` from `the old audience has actually been corrected and the stronger claim is no longer safe to rely on`.

The page must answer:

> given the original publication, the current error or dispute, and the reachable audience set, what exact recall action is honest now and what stronger erasure or clawback sentence remains blocked?

## Mandatory review sections

### A. Original-exposure section

- original audience classes
- original publication class for each audience
- original reliance class for each audience
- whether mirrored or exported copies were possible
- nearest weaker sentence already earned if full recall fails

### B. Recall-routing section

- correction route
- withdrawal route
- narrower-reliance-only route
- audit-only preservation route
- unreachable-audience route
- emergency public correction route
- adjudicator escalation route

### C. Audience-reach section

For each audience class show:

- whether the audience must be reached
- whether the audience is known, partially known, or unknown
- whether reach evidence is delivered, acknowledged, inferred, or missing
- strongest sentence honestly earned for that audience now
- stronger sentence still blocked for that audience

### D. Residue section

- surviving semantic residue risk
- surviving local-copy or export risk
- surviving linked-device mirror risk
- surviving audit / archive / history trace
- whether residue is acceptable, contested, or must freeze stronger closure

### E. Outcome section

- strongest global recall sentence honest now
- strongest per-audience recall sentence honest now
- stronger clawback or erasure sentence still blocked
- next decisive reach or expiry event expected
- exact residue that still survives

## Required route labels

- `issue correction`
- `withdraw publication`
- `narrow reliance only`
- `freeze stronger claims`
- `reach still partial`
- `audit residue only`
- `adjudicator escalation`
- `full clawback blocked`

## Required comparisons

The review must keep these comparisons explicit:

- `current UI changed` vs `past viewers corrected`
- `delivery attempted` vs `delivery completed`
- `delivery completed` vs `acknowledged`
- `trace preserved` vs `old claim still allowed`
- `withdrawn for future use` vs `forgotten by all audiences`

## Failure modes the page must prevent

- mistaking permission removal for semantic clawback
- mistaking a single corrective publication for total audience reach
- letting preserved audit trace silently impersonate ongoing public publication
- forgetting that some audiences may need only narrowed reliance while others need full withdrawal
- forgetting that unknown or unreachable audiences keep stronger closure frozen

## Stronger-sentence guard

The review may say `the participant audience was fully reached and now may rely only on the corrected deadline, while external summary viewers remain partially reached and the stronger erasure sentence stays blocked`.
It may not say `the bad publication is gone` until the reach and residue rows actually support that stronger sentence.
