# Remedy-hardening-attestation regime-shift contract sheet page — transition class, world continuity, and survival budget

## Purpose

This page is the compact contract for deciding whether a target state that is already durable in the current steady state is likely to survive a named regime shift without losing the governing world that made the sentence true.
It exists so the product can distinguish `durable in current world only`, `upgrade-path conditional`, `same-user-and-storage dependent`, `service-account-fork exposed`, `config-mode override exposed`, `product-family transition blocked`, `named transition set survived`, and `broader regime robustness blocked`.

## Regime-shift robustness classes

The page must model at least these distinct classes:

- durable in current world only, regime shift unreviewed
- named transition proposed, witness missing
- upgrade-path conditional on same user, storage, and parameters
- service-account or principal-world fork risk open
- config-mode or control-surface override risk open
- folder-class continuity blocked
- version-family or license-family transition blocked
- clone-derived transition unsupported
- named transition survived for named slice only
- named transition set survived for governed slice
- broader all-transition regime robustness blocked

## Minimum required comparisons

The page must force explicit comparison between:

- ordinary steady-state durability and named transition survival
- same-world restart and different-world migration
- same user or principal and changed service account or principal
- same storage root and relocated or auto-created new storage root
- same launch parameters and install-style-dependent new launch path
- same control surface and config-mode or WebUI surface replacement
- supported migration path and unsupported clone-like shortcut

## Hard rules

- `durable now` must never silently upgrade to `survives upgrade`.
- `files still exist` must never silently upgrade to `shares configuration survived`.
- `same binary version family` must never silently upgrade to `same governing identity or license world`.
- `service starts` must never silently upgrade to `same storage world remained active`.
- `config file present` must never silently upgrade to `prior WebUI state preserved`.
- `copying the instance worked once` must never silently upgrade to `supported transition path`.
