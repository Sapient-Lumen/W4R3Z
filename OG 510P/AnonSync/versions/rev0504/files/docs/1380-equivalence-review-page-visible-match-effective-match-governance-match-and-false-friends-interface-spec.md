# Equivalence review page — visible match, effective match, governance match, and false friends

## Review question

> what grade of sameness is actually proven here, and what nearby similarity is a false friend that must not be overclaimed?

## Mandatory review branches

### 1) Visible-value-match branch

Use when two subjects display the same human-readable value.
Required outputs:

- exact displayed values
- whether value source is inherit or explicit
- whether the same effect is current only or durable
- stronger governance-equality sentence refused

### 2) Detached-but-equal branch

Use when a detached subject currently matches the default or baseline by coincidence.
Required outputs:

- proof of detached state
- proof that visible equality is incidental rather than inherited
- next future default change that would expose divergence
- exact reattach action if desired

### 3) Parallel-mobile branch

Use when a same-looking control exists on mobile share settings or mobile general settings.
Required outputs:

- device and route
- whether lane is local-parallel rather than shared authority
- exact comparison ceiling against desktop/global baseline
- stronger cross-device sameness sentence refused

### 4) Startup-config branch

Use when config mode authors the value.
Required outputs:

- config world id
- whether only Standard folders are represented there
- whether WebUI/runtime state is overridden or disabled by config ownership
- stronger runtime-equality sentence refused

### 5) Service-fork branch

Use when the same conceptual setting is compared across interactive and service worlds.
Required outputs:

- whether the service world is migrated continuity or clean-install fork
- whether shares were preserved or re-shared
- exact equivalence ceiling across the worlds
- stronger `same environment` sentence refused

### 6) Local-alias branch

Use when labels, custom names, or route names appear to line up.
Required outputs:

- local display label
- canonical subject id
- whether alias is local-only or propagated
- stronger subject-identity sentence refused

### 7) Unknown-evidence branch

Use when any comparison field is missing.
Required outputs:

- missing witness
- highest honest equality grade available now
- evidence needed for stronger grade
- blocked stronger sentence

## False-friend cases the page must catch

- `None` on two shares when one inherits and the other is explicitly detached
- same-looking desktop and mobile control when one is only device-local
- same share title when one is a local custom alias
- same value before and after service install when the world actually forked
- same route label after config import when the config world overrode WebUI state

## Required review outputs

Every equivalence review must end with:

- canonical setting id
- canonical subject ids under comparison
- baseline id
- equality grade verdict
- nearest false-friend similarity
- safe realignment options
- blocked stronger sentence
