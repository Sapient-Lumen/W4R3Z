## Activation-boundary lineage receipt

### Receipt purpose
Preserve the exact answer to **what changed, when it became live, and what stronger immediacy sentence was refused**.

### Receipt fields
- requested change
- mutation locus
- authored-on-disk witness
- minimum honest activation rung
- higher rungs not yet reached
- surviving old-world debt
- current witness class
- strongest legal sentence now
- blocked stronger sentence
- next event that could upgrade the sentence

### Example sentence pattern
`The IgnoreList edit is saved on disk and eligible for reread, but immediate full adoption is not yet proven; the first fully honest activation rung is explicit rescan or restart, depending on the runtime witness available.`

### Archival rule
Keep this receipt whenever a setting, auth posture, route policy, or service-mode mutation could be misread as already-live merely because it was saved successfully.
