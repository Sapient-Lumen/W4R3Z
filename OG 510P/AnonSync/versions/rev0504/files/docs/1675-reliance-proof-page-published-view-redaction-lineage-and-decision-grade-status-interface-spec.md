# Reliance proof page — published view, redaction lineage, and decision-grade status

## Purpose

This page is the durable proof object for the strongest publication-and-reliance sentence honestly earned by a typed act for a named audience.
It exists so later operators can see not merely that something was visible, but what exact version was published, why it was shaped that way, and what stronger reliance remained blocked.

## Sentences this page may support

- `participant received a redacted view that is sufficient for response timing but not for final allocation review`
- `linked-device mirror received the same principal view and no separate publication adjudication was required`
- `external reviewer saw metadata only; semantic reliance remained blocked pending authorization`
- `encrypted host stored bytes and continuity state but never received semantic publication rights`
- `earlier public summary was superseded by a narrower corrective publication while audit-grade access remained continuous`

## Mandatory proof blocks

### A. Viewer proof block

- viewer identity or viewer class
- eligibility basis
- whether the view was direct, delegated, mirrored, or adjudicated
- highest publication class honestly earned
- highest reliance class honestly earned
- stronger viewer sentence still blocked

### B. View-content block

- publication version identifier
- redaction profile applied
- decisive fields shown
- decisive fields withheld
- whether evidence attachments were included, summarized, or omitted
- exact reason the chosen fidelity is honest

### C. Reliance proof block

- action or decision the viewer may rely on
- action or decision the viewer may not rely on
- whether onward citation is allowed
- whether the publication supports only awareness, workflow, participant decision, or adjudication
- strongest blocked stronger sentence

### D. Lifecycle block

- publication issue time
- notice / delivery status if required
- supersession events
- retraction events
- dispute or correction events affecting reliance
- next event that would widen, preserve, or narrow this proof

### E. Audit block

- source act identifiers
- source effectivity identifiers
- publication approver or authority chain
- viewer-delivery evidence
- redaction rationale evidence
- supersession / retraction records

## Required badges

- `published`
- `redacted`
- `metadata-only`
- `decision-grade`
- `workflow-only`
- `awareness-only`
- `encrypted-custody-only`
- `superseded`
- `retracted`
- `viewer-reliance-blocked`

Badges must stack instead of collapsing meaning.
For example, `published` may coexist with `redacted` and `workflow-only`, while `superseded` may coexist with `audit-grade continuity`.

## Proof obligations

- prove viewer eligibility separately from simple technical visibility
- prove redaction choice separately from delivery success
- prove reliance class separately from publication existence
- preserve which stronger publication or reliance sentence remained blocked
- preserve whether later supersession or retraction narrowed earlier reliance

## Stronger-sentence guard

This page may say `the public summary accurately stated that a protective freeze remains active, but the public was not entitled to rely on named-creditor amounts or settlement sufficiency`.
It may not say `the matter was fully published` unless the exact audience-and-reliance rows actually support that sentence.
