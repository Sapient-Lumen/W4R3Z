# Remedy-hardening-attestation successor beneficiary-adoption lineage receipt page — adoption summary, stale-reliance risk, and blocked stronger uptake sentences

## Purpose

This page is the portable receipt summarizing what can honestly be claimed about whether one named beneficiary actually switched to the corrected working state after a later canonical correction.
Later pages must cite this receipt instead of improvising `they acknowledged it`, `they opened it`, `they switched`, or `they are now compliant` language.

## Receipt header

The header must show:

- receipt identifier
- action identifier
- source beneficiary-notice receipt identifier
- named beneficiary identifier
- current beneficiary-adoption standing
- current strongest safe sentence
- current blocked stronger sentence

## Mandatory receipt fields

- source beneficiary-notice receipt identifier
- named beneficiary summary
- governed slice summary
- canonical correction summary
- required uptake class summary
- corrected working-artifact summary
- working-pointer summary
- stale artifact summary
- stale-retirement summary
- contradiction status
- superseding receipt identifier if any

## Standing states

The receipt must support at least these states:

- correction acknowledged, adoption still unproven
- corrected artifact fetched or opened only
- beneficiary likely switched to corrected working state
- stale reliance still plausible
- stale reliance retired for governed slice
- broader compliance sentence still blocked
- later contradiction narrowed prior adoption confidence
- receipt superseded

## Primary sentence classes

The receipt must be able to emit at least these classes:

- `later correction was acknowledged; adoption sentence still blocked`
- `corrected artifact was fetched or opened; active working switch still unproven`
- `beneficiary likely adopted the corrected working state`
- `beneficiary likely adopted the corrected working state, but stale reliance still remains plausible`
- `stale reliance was retired for the governed slice`
- `broader compliance sentence remains blocked`
- `later contradiction narrowed prior beneficiary-adoption confidence`

## Display requirements

The compact receipt view must show exactly four top chips:

- correction current / superseded
- uptake standing (`acknowledged` / `opened` / `adopted`)
- stale reliance (`open` / `retired` / `contradicted`)
- strongest sentence ceiling

Selecting any chip must reveal the evidence row that caused it.

## Hard rules

The receipt must never let later pages say:

- the beneficiary definitely switched to the corrected working state
- stale reliance definitely ended everywhere
- downstream use is definitely compliant
- all superseded material is definitely retired

unless the receipt actually carries the corresponding proof state.
