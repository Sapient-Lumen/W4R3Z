# Remedy-cutover lineage receipt page — authoritative switch, live writer state, and blocked stronger cure sentences

## Purpose

This receipt is the durable compact proof of how a landed cure did or did not become the authoritative live state.
It exists so later readers can see whether the product was honest about the gap between `repair landed` and `repair safely cut over for the required writer and reader cohorts`.

## Receipt body

The receipt must record:

- case identifier
- source remedy-landing receipt identifier
- current remedy-cutover posture rung
- intended authoritative object summary
- intended writer and reader cohort summary
- writer-freeze summary
- live lock-holder summary
- unlocked-writer exposure summary
- timestamp-rebound summary
- conflict-artifact summary
- read-only invalidation summary
- platform lock-coverage summary
- strongest honest sentence
- strongest blocked stronger sentence
- exact blocker summary

## Receipt sentence families

The receipt must support concise summaries such as:

- `the cure landed, but live lock holders and unlocked-writer exposure still block authoritative cutover`
- `the repair is authoritative for the pilot writer cohort, while required-cohort cutover remains blocked by non-covered platform writers`
- `split live state and .Conflict residue collapsed the stronger cutover sentence`
- `read-only followers reflect the fix, but authoritative writer-side cutover remains blocked by rebound risk`
- `landing verified, switch attempted, later timestamp winner rebound detected, cutover collapsed`

## Invariants

- the receipt never compresses landing, switching, and authoritative cutover into one word
- the receipt never hides writer-risk or rebound-risk behind visible file presence
- the receipt never lets follower convergence impersonate full required-cohort cutover
- the receipt always preserves the blocker that prevented the stronger cutover sentence
