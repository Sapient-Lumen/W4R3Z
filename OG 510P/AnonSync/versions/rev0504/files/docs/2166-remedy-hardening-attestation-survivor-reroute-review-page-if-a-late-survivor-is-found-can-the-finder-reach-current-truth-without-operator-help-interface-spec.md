# Remedy-hardening-attestation survivor-reroute review page — if a late survivor is found, can the finder reach current truth without operator help?

## Purpose

This review page asks the question durable closure by itself cannot answer:

**when a stale survivor resurfaces later, can the finder get from that exact surface to the current correction without bespoke operator help?**

## Mandatory review prompts

The review must force explicit answers to at least:

1. Which rediscovery carriers can identify themselves as superseded?
2. Which carriers only reopen the claim because they have no embedded or adjacent reroute?
3. Which carriers reroute only for in-lane users, and which reroute for true outsiders?
4. Which carriers still depend on a particular client, manual paste flow, or support intervention?
5. Which stronger self-routing sentence would become dishonest if a forwarded or detached copy resurfaced tomorrow?

## Review buckets

### Carrier review

For each relevant carrier, the page must show:

- carrier name
- carrier class
- finder class likely to encounter it
- whether supersession is self-explaining, merely implied, or absent
- whether the route is embedded, adjacent, or off-surface
- whether rediscovery from this carrier self-routes, operator-routes, or dead-ends

### Route viability review

For each reroute path, the page must show:

- target identifier
- trust anchor for the target
- required client or app
- manual-step burden
- approval/support dependency
- whether successful routing is enough to re-close the claim for that finder

### Re-closure review

The page must separately review at least:

- stale folder links landing on generic handoff pages
- WebUI / browser dead-end or manual-paste flows
- custom-name or link-text explanation fragility
- detached single-file copies and onward resharing
- local-share and device-local derivatives
- archived or hidden survivors with no built-in route

## Refusal rules

The review must refuse to bless a self-routing claim if:

- the carrier inventory is incomplete
- the route exists only in operator memory
- the path requires unsupported or hidden client behavior
- detached copies can resurface but the sentence still says `survivor self-routes`
- re-closure conditions are not named

## Output

The output must be one of:

- `survivor self-routing proven for named carriers`
- `reroute exists but remains operator-dependent`
- `rediscovery reopens the claim; no survivor-carried route`
- `carrier classes split; some self-route and some dead-end`
