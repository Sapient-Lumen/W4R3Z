# Action matrix review page — receive, waive, lift, reopen, and delegate routes

## Purpose

This page is the operator workspace for deciding which typed action may honestly be executed now.
It exists so the archive can distinguish `valid people present` from `this exact act is ready`.

The page must answer:

> given the current signers, objections, successor state, and residue posture, which action families are executable now, which are blocked, and what weaker protective routes remain available?

## Mandatory review sections

### A. Candidate-act section

- requested action
- nearest weaker action if requested one is blocked
- actor or coalition attempting the action
- whether the action is protective, revisable, or irreversible
- present urgency class

### B. Sufficiency section

- signer set available now
- required signer set for this action
- whether named seats are present
- whether countersign or quorum is satisfied
- whether cooling window is required before execution
- whether any conflict or objection freezes the act

### C. Residue section

- exact residue touched by the requested action
- exact residue left open after the requested action
- whether disputed residue is included or excluded
- whether probation changes
- whether future-burst posture changes

### D. Protective-fallback section

- whether a freeze is executable even if closure is blocked
- whether receipt acknowledgment is executable even if waiver is blocked
- whether provisional settlement is executable even if final release is blocked
- whether reopen is executable even if normalize is blocked
- whether successor appointment is executable even if ratification is blocked

### E. Decision section

- strongest executable act now
- blocked stronger acts now
- exact prerequisites for each blocked stronger act
- whether immediate execution is honest
- whether delay or cooling is mandatory

## Required route outputs

The review must be able to route to all of these outcomes explicitly:

- execute protective freeze only
- acknowledge funds without waiving rights
- accept provisional settlement only
- execute capped settlement while leaving residue open
- execute final waiver for a named slice only
- lift probation while future-burst normalization stays blocked
- restore future-burst eligibility only after lift-plus-cooling proof
- appoint successor without retroactive ratification
- ratify predecessor act without expanding other powers
- reopen case and freeze stronger acts

## Required comparisons

The review must keep these comparisons explicit:

- `funds arrived` vs `funds accepted as settlement`
- `settlement accepted` vs `rights waived`
- `probation relieved` vs `future burst normalized`
- `successor appointed` vs `predecessor act ratified`
- `urgent freeze allowed` vs `urgent irreversible waiver allowed`

## Failure modes the page must prevent

- mistaking urgency for permission to do an irreversible act
- collapsing receipt, settlement, and waiver into one verb
- granting case-wide effect when only one creditor slice is covered
- letting the strongest blocked act disappear once a weaker act succeeds
- failing to preserve reopen power after a narrow provisional act

## Stronger-sentence guard

The review may say `funds may be acknowledged now and collection may be frozen, but disputed-residue waiver remains blocked pending unanimity and cooling`.
It may not say `matter resolved` until the exact requested stronger act is honestly executable.
