# Remedy-runway lineage receipt page — execution readiness, runway coverage, and blocked stronger cure sentences

## Purpose

This receipt is the durable compact proof of how executable the remedy lane really was at a specific moment.
It exists so later readers can see whether the product was honest about repair readiness rather than merely optimistic about preserved bytes and favorable settings.

## Receipt body

The receipt must record:

- case identifier
- source hold-enforcement receipt identifier
- current remedy-runway posture rung
- required cohort summary
- required response window
- source-present coverage summary
- queue and priority summary
- scheduler and pause summary
- headroom floor summary
- discovery-lag floor summary
- strongest honest sentence
- strongest blocked stronger sentence
- exact blocker summary

## Receipt sentence families

The receipt must support concise summaries such as:

- `repair material preserved, but required source peer offline, so runway blocked by source absence`
- `runway exists for named desktop cohort only; required mobile cohort still manual-only`
- `priority elevated, but queue and internal-task pressure keep cure only manually runnable`
- `required cohort runway ready now within window`
- `runway missed after source disappeared before safe-start time`

## Invariants

- the receipt never compresses preservation, enforcement, and executability into one word
- the receipt never hides source absence behind placeholder visibility
- the receipt never lets priority configuration impersonate actual response-window readiness
- the receipt always preserves the blocker that prevented the stronger cure sentence
