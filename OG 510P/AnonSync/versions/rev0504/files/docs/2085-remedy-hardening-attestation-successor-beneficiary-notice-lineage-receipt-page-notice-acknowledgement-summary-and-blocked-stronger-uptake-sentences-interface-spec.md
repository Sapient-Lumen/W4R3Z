# Remedy-hardening-attestation successor beneficiary-notice lineage receipt page — notice acknowledgement summary and blocked stronger uptake sentences

## Purpose

This page is the portable receipt summarizing what can honestly be claimed about whether one named beneficiary noticed and acknowledged a later canonical correction.
Later pages must cite this receipt instead of improvising `the beneficiary was informed`, `the warning was seen`, or `they acknowledged the correction` language.

## Receipt header

The header must show:

- receipt identifier
- action identifier
- source beneficiary-authority receipt identifier
- named beneficiary identifier
- current beneficiary-notice standing
- current strongest safe sentence
- current blocked stronger sentence

## Mandatory receipt fields

- source beneficiary-authority receipt identifier
- named beneficiary summary
- governed slice summary
- canonical correction summary
- notice policy summary
- acknowledgement requirement summary
- carrier summary
- surfaced / seen / acknowledged summary
- reminder / expiry summary
- contradiction status
- superseding receipt identifier if any

## Standing states

The receipt must support at least these states:

- correction published, notice still unproven
- surfaced to beneficiary environment only
- beneficiary likely saw the correction
- acknowledgement required and completed
- acknowledgement optional and absent
- acknowledgement required and overdue
- later contradiction narrowed prior notice confidence
- receipt superseded

## Primary sentence classes

The receipt must be able to emit at least these classes:

- `later correction exists; beneficiary notice sentence still blocked`
- `later correction surfaced in beneficiary environment; seen state still unproven`
- `beneficiary likely saw the later correction`
- `beneficiary acknowledged the correction under current policy`
- `beneficiary acknowledgement remains overdue`
- `later contradiction narrowed prior beneficiary-notice confidence`
- `stronger uptake sentence remains blocked`

## Display requirements

The compact receipt view must show exactly four top chips:

- correction current / superseded
- notice unproven / surfaced / seen
- acknowledgement none / optional / required-complete / required-overdue
- strongest sentence ceiling

Selecting any chip must reveal the evidence row that caused it.

## Hard rules

The receipt must never let later pages say:

- the beneficiary was definitely informed
- the beneficiary definitely saw the correction
- the beneficiary definitely acknowledged the correction
- the beneficiary accepted or acted on the correction

unless the receipt actually carries the corresponding proof state.
