# Remedy-hardening review page — has this case actually been hardened against recurrence?

## Purpose

This page is the operator's adjudication surface for whether a case that already requalified for guarded ordinary life has also been hardened against repeating the same cause family.
It exists so the operator can answer one typed question instead of reconstructing hardening truth from scattered settings, permissions, ignore rules, and rollout memory.

## Primary review question

`After honest re-entry, is this case actually hardened against recurrence of the same cause class, or are we just seeing weaker post-incident cleanup and narrower risk?`

## Required review panes

### 1. Cause-to-control pane

Show:

- triggering cause family
- control family intended to prevent recurrence
- temporary workaround still relied on
- durable control now present or absent
- strongest blocked stronger sentence from missing durable control

### 2. Cohort-rollout pane

Show:

- required hardening cohort
- named-lane-only deployment still present
- current rollout coverage
- future-carry-forward surface still outside coverage
- current rollout ceiling for recurrence-safe language

### 3. Topology-and-authority pane

Show:

- linked-device spread exposure
- Standard versus Advanced folder implications
- owner and resharing exposure
- read-only or one-way fallback posture
- strongest honest recurrence-hardening verdict ceiling

### 4. Activation-and-proof pane

Show:

- config and preference activation status
- restart or rescan still required
- ignore-list or rule propagation timing still relevant
- proof that the control is active in the risky lane
- final honest hardening sentence ceiling

## Required review outcomes

The page must support outcomes such as:

- `cause fixed once; no durable hardening yet`
- `durable hardening drafted; rollout not started`
- `named-lane hardening only; required-cohort hardening still blocked`
- `required-cohort rollout complete; carry-forward surface still exposed`
- `required-cohort hardening deployed and proven active`
- `recurrence budget narrowed; stronger recurrence-safe sentence still blocked`
- `hardening collapsed; case remains requalified but not recurrence-hardened`

## Review discipline

The review must forbid these shortcuts:

- one config change equals recurrence hardening
- one permission edit equals cohort-wide hardening
- one ignore rule equals proven activation everywhere
- one safer folder type equals topology fully hardened
- one quiet week equals durable prevention
- one rescan or restart equals hardening proven active
