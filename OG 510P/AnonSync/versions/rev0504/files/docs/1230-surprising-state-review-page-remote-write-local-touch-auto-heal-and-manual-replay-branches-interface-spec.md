# Surprising-state review page — remote write, local touch, auto-heal, and manual replay branches

## Purpose

This page exists so `why did this file look different when I came back?` stops sending the operator into warning archaeology.
It must review the strongest current branches for a surprising state and explain which class the product is actually willing to stand behind.

## Operator question

> This file, folder, or permission posture surprised me. Was it changed by another peer, reverted from source, replayed manually, inherited from a parent/source class, or merely re-noticed after a touch-like induction?

## When this page must appear

Render whenever:

- local edits appear to vanish or revert;
- an old path or old bytes reappear;
- a file becomes newly `updated` after a `touch`/mtime induction or rescan-based intervention;
- a local share or derived seat changes posture because its source changed;
- an encrypted or other hard-wired seat follows source delete / overwrite behavior;
- a manual Archive extraction or older-byte replay is attempted or has just landed.

## Fixed page order

1. **What surprised the operator**
2. **Candidate origin branches**
3. **Branch eliminators**
4. **Winning branch and confidence**
5. **Non-equivalent next actions**

## 1) What surprised the operator

Show one or more typed surprise classes:

- `my local edit disappeared`
- `a deleted file came back`
- `the old name reappeared`
- `this seat changed posture underneath me`
- `the file changed only after touch / rescan`
- `older bytes returned`
- `surprise class unresolved`

The operator must be able to answer: **what exact phenomenon are we reviewing?**

## 2) Candidate origin branches

Render the active candidates separately, not blended:

- **remote publish branch**
- **automatic source-heal branch**
- **derived-source cascade branch**
- **encrypted hard-wire follow branch**
- **manual archive replay branch**
- **detection-induction-only branch**
- **local-only survivor branch**

For each branch show:

- why it could explain the current state
- what evidence supports it
- what evidence still weakens it

The operator must be able to answer: **which origin classes are genuinely in play?**

## 3) Branch eliminators

The page must show the facts that collapse possibilities, such as:

- seat was Read Only with overwrite-heal active
- seat was encrypted and delete-following
- parent local share was downshifted from source
- Archive extraction happened manually at a known time
- `touch`/mtime induction happened without direct content-edit witness
- local addition remained unsynced by posture design

The operator must be able to answer: **what facts remove the wrong explanation?**

## 4) Winning branch and confidence

Show:

- winning origin branch
- confidence class: `high`, `medium`, `low`, `unresolved`
- strongest safe sentence
- blocked stronger sentence

The operator must be able to answer: **what explanation is the product actually willing to own?**

## 5) Non-equivalent next actions

Show next actions separated by branch class, for example:

- inspect or change overwrite-heal posture
- open parent-source derivation review
- inspect archive replay consequences
- treat touch as detection remediation, not authorship proof
- move from local-only survivor to explicit publish path
- open chronology / recovery review instead of repeating the same fix

The operator must be able to answer: **what is the next action that matches this origin class rather than a different one?**

## What this page must never imply

It must never imply that these are the same:

- touch-induced detection and authored content change
- automatic source-heal and manual replay
- derived-source cascade and direct actor mutation
- local-only survivor and shared truth
- old-name replay and simple rename authorship proof

## Receipt consequence

Completing this review must write a provenance receipt preserving surprise class, winning branch, confidence, and blocked stronger sentence.
