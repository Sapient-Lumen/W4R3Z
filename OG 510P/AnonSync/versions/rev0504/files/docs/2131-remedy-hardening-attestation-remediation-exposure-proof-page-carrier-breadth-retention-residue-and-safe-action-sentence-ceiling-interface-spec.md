# Remedy-hardening-attestation remediation-exposure proof page — carrier breadth, retention residue, and safe action sentence ceiling

## Purpose

This page is the evidence-heavy surface for proving what exposure budget a late outsider's remediation path actually consumed.
It exists to preserve carrier breadth, resharing rights, delivered-copy residue, and blocked stronger sentences instead of collapsing everything into a vague `self-service remediation succeeded` claim.

## Core proof question

The page must answer:

**what is the strongest evidence-backed sentence we can honestly make about bounded outsider remediation now, and what stronger bounded-exposure sentence is still blocked?**

## Minimum evidence sections

The proof page must contain:

- receipt header
- carrier and reach ledger
- permission-widening ledger
- retention-residue ledger
- budget-exception ledger
- strongest honest sentence / blocked stronger sentence panel

## Receipt header

The header must show:

- action identifier
- stale artifact identifier
- corrected replacement identifier
- proof freshness timestamp
- current remediation-exposure standing

## Carrier and reach ledger

For each named carrier show:

- carrier class
- intended outsider set
- effective audience breadth
- reuse ceiling
- expiry or click ceiling
- same-surface versus forwarded use
- exclusions

The ledger must make it impossible to merge `carrier exists`, `carrier works`, and `carrier is bounded`.

## Permission-widening ledger

For each path show:

- can recipient reshare copy
- can recipient reshare key or link
- can recipient invite others
- can recipient widen to owner-level control
- what topology makes that widening possible

## Retention-residue ledger

Track at least:

- delivered bytes remain after UI removal
- delivered bytes remain after disconnect
- already forwarded copies untracked
- previously approved peer still present elsewhere
- residue retirement proven elsewhere

Every residue item must carry:

- why it remains open
- what sentence it blocks
- whether it is carrier-specific or universal

## Budget-exception ledger

Track at least:

- unlimited-use bearer download
- no device restriction
- onward forwarding allowed
- owner-right widening possible
- expiration absent or disabled
- click budget absent or exceeded
- revocation stops updates only
- local residue survives revocation

## Hard rules

The page must never allow:

- successful outsider remediation to erase exposure exceptions
- expired carrier to erase delivered-copy residue
- approval history to erase onward rights already granted
- one bounded path to hide another uncontrolled path
