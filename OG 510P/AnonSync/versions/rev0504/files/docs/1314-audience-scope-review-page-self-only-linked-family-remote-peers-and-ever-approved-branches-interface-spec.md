## Audience-scope review

### What this page prevents
This page prevents one friendly row label, one peer count, or one `all devices` phrase from hiding which counterpart set the action or promise really ranges over.

### Review branches

#### 1. Self-only derived branch
Use this branch when the visible row is a local share or another self-derived branch.
The UI must say the subject is **self only**, that it only pulls from the parenting share, and that peer-count growth does not imply independent remote redundancy.

#### 2. Linked-family scope
Use this branch when a sentence only ranges over devices linked with the same private identity.
The UI must say that linked-family scope is **not** the same as all remote holders or all devices that ever received the folder.

#### 3. Remote nonlinked peers
Use this branch when the folder is also present on devices outside the linked family.
The UI must preserve that these peers are outside linked-family removal and outside identity-wide convenience claims.

#### 4. Ever-approved authorities
Use this branch when approval memory or certificate retention matters.
The UI must say whether the remembered set is `only new peers require approval` or whether `all peers` must re-ask for this folder.

### Required outputs
Every branch publishes:

- the active subject set
- the excluded counterpart set
- the strongest honest human sentence
- the stronger sentence that remains blocked
