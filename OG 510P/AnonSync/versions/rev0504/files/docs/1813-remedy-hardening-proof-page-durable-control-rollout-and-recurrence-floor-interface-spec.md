# Remedy-hardening proof page — durable control, rollout evidence, and recurrence floor

## Purpose

This page is the proof bundle behind the claim that a case which already re-entered guarded ordinary life has also been hardened against recurrence of the same causal class.
It exists so later readers can inspect control choice, rollout scope, activation evidence, and carry-forward closure instead of inferring them from configuration folklore alone.

## Proof bundle

The proof page must preserve evidence for:

- source remedy-reaccreditation result
- triggering cause family
- chosen hardening strategy
- durable-versus-temporary control evidence
- config-mode or preference rollout evidence
- folder-preference rollout evidence
- permission or owner-topology hardening evidence
- ignore-rule or exclusion-rule evidence, if relevant
- required hardening cohort
- rollout coverage evidence
- restart, rescan, or activation dependency evidence
- active-in-risk-lane proof
- future carry-forward surface closure evidence
- strongest honest current hardening sentence
- strongest blocked stronger recurrence-safe sentence

## Proof sentence families

The page must support concise summaries such as:

- `the immediate cause was repaired, but the durable guardrail is still local-only, so recurrence-hardened discharge remains blocked`
- `the durable policy rolled out across the required cohort, but linked-device carry-forward still kept the stronger sentence blocked until authority surfaces were narrowed too`
- `required-cohort hardening is now active in the exact risky lane, and recurrence-hardened discharge is honest`
- `read-only fallback narrowed the risk, but durable prevention is still weaker than the blocked stronger recurrence-safe sentence`
- `one folder type is hardened while another topology path remains open, so hardening debt survives re-entry`

## Stronger-sentence blockers

The page must explicitly name blockers such as:

- workaround only
- durable control missing
- required-cohort rollout incomplete
- carry-forward surface still open
- linked-device spread still exposed
- owner or resharing surface still open
- activation depends on restart or rescan not yet completed
- active-lane proof missing
- evidence basis too weak

## Evidence handling rules

The proof page must never let these substitute for stronger proof:

- one safer preference without cohort rollout evidence
- one permission change without topology coverage evidence
- one ignore rule without proof it is active where the recurrence risk lives
- one quiet period without durable-control evidence
- one restarted client without proof the guardrail remained active afterward
