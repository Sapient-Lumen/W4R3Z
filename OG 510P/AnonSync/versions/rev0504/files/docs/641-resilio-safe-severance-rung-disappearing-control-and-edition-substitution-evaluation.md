# Resilio safe-severance rung, disappearing controls, and edition-substitution evaluation

## Why this pass exists

The archive already had strong doctrine for severance, entitlement loss, and capability provenance.
What it still lacked was one direct current Resilio evaluation for another ordinary seam:

> when the operator wants the gentlest exit or least-strong local severance, does the product keep that rung visible, or can licensing / subject posture erase it and leave only a stronger verb?

Current official Resilio docs still show a useful, living product, but they also still show that one everyday answer still leaks across several different article families at once:

- `Disconnecting and Removing Folders`
- `Selective Sync`
- `Synchronization Modes`
- `Folder Types and Management`
- the current `I'm using Sync Free and there is no "Disconnect" button...` article

## Current official Resilio evidence that matters here

Current official docs still show an active v3 line through `3.1.2.1076`.
They also still say all of the following:

- `Disconnecting and Removing Folders` still describes `Disconnect` as a one-device action and `Remove` as the broader linked-identity action.
- `Selective Sync` still says v3 fully supports selective materialization, while v2 availability was licensed-only; it also still warns that removing a Selective-Sync share removes placeholders from the file system on that device.
- `Synchronization Modes` and `Folder Types and Management` still describe `Disconnected`, `Selective Sync`, and `Synced` as materially different postures with different local-byte and path consequences.
- The current desktop Free help article still says Sync Free has no `Disconnect` button and only allows `Remove`, explicitly bypassing the disconnect stage because Free offers only `Synced` mode.

So current Resilio still contains a real but scattered answer to `is the safer rung absent because it is semantically impossible here, or only because this edition / posture does not expose it?`

## What Resilio still gets right

### 1) It is candid that control availability is not universal

The docs do not pretend every seat always has the same severance verbs.
That honesty matters.

### 2) It still distinguishes weaker and stronger action consequences

Resilio still treats `Disconnect` and `Remove` as different things rather than flattening them into one generic `stop syncing` action.
That distinction is valuable.

### 3) It preserves the idea that local-byte posture affects which exits are meaningful

`Disconnected`, `Selective Sync`, and `Synced` still matter.
That is good product candor.

## Why this is still a good reason not to clone them

### 1) The safer rung can disappear without the product owning the gap

Current docs are candid that desktop Free lacks `Disconnect` and only exposes `Remove`.
But the product contract still makes the operator reconstruct whether the gentle exit is truly impossible or merely absent in this edition.
AnonSync should not inherit that action-floor collapse.

### 2) Control absence can silently push the user toward a stronger verb

If the softer severance action is missing, the visible alternative can look like the intended substitute even when its blast radius is stronger.
A serious sync product should never let entitlement or posture silently rewrite the user's action intent.

### 3) Feature availability and action meaning still live on different pages

Current Resilio still spreads one ordinary answer across mode docs, Selective Sync docs, folder-management docs, and a troubleshooting-style Free article.
The operator still has to reconstruct: `what I wanted`, `what is missing`, `why it is missing`, and `what is now the least-strong safe substitute`.

## The tighter AnonSync conclusion

AnonSync should borrow the following from Resilio more boldly:

- candid admission that controls can genuinely differ by posture
- explicit distinction between gentler and stronger severance verbs
- typed byte-presence consequences for each rung

But AnonSync should refuse the exact page contract whenever one ordinary answer still depends on:

- edition archaeology
- missing-button folklore
- mode-specific action disappearance
- substitution by stronger visible verbs without a typed review

## The replacement pages this evaluation justifies

This pass therefore makes four page-shaped obligations concrete:

1. **Action availability** — which control is present, absent, or impossible, and on what basis?
2. **Severance ladder review** — what gentler and stronger exits exist for this subject right now?
3. **Capability substitution** — when the requested action is unavailable, what is the least-strong safe substitute and what gets worse?
4. **Control-absence receipt** — what was requested, what was unavailable, why, and what substituted action actually committed?

## Bottom line

The tighter no-clone reason is now this:

> Resilio is still good evidence that weaker and stronger severance actions should stay distinct, but it is also current evidence that a missing safer rung can still be explained only by hopping across edition notes, mode docs, and folder-action help. AnonSync should copy the candor and refuse the disappearing-control contract.
