# Remedy-hardening-change-gate timeline page — propose, review, approve, bypass, and reseal events

## Purpose

This page is the ordered event surface for how a case moved from retained recurrence hardening into governed future change or back into regression debt.
It exists so later readers can see change proposals, approvals, bypasses, applications, and reseal timing directly rather than reconstructing them from scattered permission or config history.

## Event types

The timeline must support at least these event kinds:

- retained hardening achieved
- future change gate review opened
- proposed change registered
- change initiator identified
- required review cohort set
- approval threshold changed
- proposed change rejected as outside safe envelope
- proposed change approved pending reseal
- proposed change bypassed
- change applied under regression debt
- linked-device or onward-share surface expanded
- manual override detached lane during change
- peer-local rule divergence detected during change
- reseal review opened
- reseal proof achieved
- hardening-change-gated discharge achieved
- change gate collapsed or suspended

## Timeline queries

The page must answer:

- when did future change governance actually begin?
- when did one proposed change first threaten the original cause family?
- when was the approval threshold met?
- when did a change go live before reseal finished?
- when did bypass or unauthorized mutation reopen review?
- when did recurrence-hardened-retained-and-change-gated discharge become honest, or collapse again?

## View modes

The page must provide:

- all-events view
- proposal-only view
- approval-only view
- bypass-and-regression-debt view
- reseal-only view
- collapse-only view
