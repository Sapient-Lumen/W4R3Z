# Action effectivity proof page — notice completion, effective time, and surviving sub-truths

## Purpose

This page is the durable proof object for the strongest lifecycle state honestly earned by a typed act.
It exists so later operators can see not merely that something was executed, but when it became effective, for whom, under which timers, and which narrower truths survive any later withdrawal.

## Sentences this page may support

- `final waiver executed; effectivity not yet earned because notice is incomplete`
- `protective freeze effective immediately; irreversible closure still cooling`
- `notice completed and cooling satisfied; final waiver effective for undisputed core only`
- `act effective but contest window remains open`
- `later reopen withdrew case-wide effect while preserving earlier receipt acknowledgment and provisional settlement lineage`

## Mandatory proof blocks

### A. Lifecycle block

- action family
- highest lifecycle state honestly earned
- execution time
- effectivity time if different
- current contest state
- stronger lifecycle state still blocked

### B. Notice proof block

- required notice cohort
- proof of delivery for each required recipient
- proof of acknowledgment where required
- unresolved delivery disputes
- whether notice failure narrows scope or blocks effect entirely
- exact notice-completion time if achieved

### C. Timer proof block

- cooling requirement
- cooling start evidence
- cooling completion evidence
- contest window opening evidence
- adjudication override evidence if used
- exact event that would suspend or reset the timer

### D. Scope-and-survivor block

- affected creditor slice or case scope
- narrower truths earned at execution but surviving after later withdrawal
- stronger truths earned only after effectivity
- stronger truths never earned
- superseded truths and their successor act
- reopen consequences if triggered later

### E. Audit block

- decisive signatures
- decisive execution event
- decisive notices sent
- decisive notices delivered
- decisive objections or contests preserved
- decisive supersession or withdrawal references if any

## Required badges

- `executed-only`
- `notice-incomplete`
- `notice-complete`
- `cooling-unsatisfied`
- `cooling-satisfied`
- `effective-for-slice`
- `effective-case-wide`
- `contest-open`
- `superseded-effect`
- `withdrawn-effect`
- `surviving-subtruth`

Badges must stack instead of collapsing meaning.
For example, `notice-complete` may coexist with `cooling-unsatisfied`, and `withdrawn-effect` may coexist with `surviving-subtruth`.

## Proof obligations

- prove execution separately from effectivity
- prove notice completion separately from notification existence
- prove cooling satisfaction separately from mere passage of wall-clock time
- preserve exact narrower truths that survive supersession or withdrawal
- preserve the strongest still-blocked lifecycle state even after a weaker state is fully proven

## Stronger-sentence guard

This page may say `execution occurred on March 23, notice completed on March 25, cooling satisfied on March 28, and case-wide finality never attached because disputed residue remained outside scope`.
It may not say `binding from March 23 onward` unless the effectivity rule actually made it so.
