# Remedy-landing timeline page — start, write, rename, rebind, side-path, and adoption events

## Purpose

This page shows the event chain that turned an in-flight cure into an actual landing result — or failed to do so.
It exists so later readers can see where landing weakened: duplicate-path creation, placeholder-only stop, archive rebound, merge, unreadable backup, or adoption debt.

## Required event classes

The timeline must support events such as:

- landing requested
- source write began
- transfer pieces completed
- final rename into place
- `.sync` continuity warning
- reconnect path proposed
- duplicate directory created
- non-empty target accepted
- side-path landing observed
- placeholder-only arrival observed
- archive-backed rebind observed
- encrypted survivorship confirmed
- operative adoption completed
- landing misbind detected
- landing verification collapsed

## Timeline rules

- every event must record actor, cohort, object, target, and observed landing class
- the timeline must separate `bytes finished` from `final rename into intended place`
- the timeline must preserve whether the landing was readable, placeholder-only, unreadable, duplicate, or archive-rebound
- the timeline must keep manual adoption actions explicit rather than hiding them inside a final verdict

## Output sentence family

The timeline summary must support statements such as:

- `the cure finished transferring, but reconnect proposed a different path and duplicate-path review remained open`
- `landing completed for the named desktop cohort through archive-backed rebind, then waited on manual adoption for the required cohort`
- `one cohort received only placeholders, so bytes-finished success never upgraded into required-cohort landing`
- `encrypted survivorship stayed intact, but readable operative landing never occurred before the deadline`
