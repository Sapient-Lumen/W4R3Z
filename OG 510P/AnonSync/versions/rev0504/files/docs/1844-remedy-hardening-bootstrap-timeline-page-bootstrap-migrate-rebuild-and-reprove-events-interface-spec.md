# Remedy-hardening-bootstrap timeline page — bootstrap, migrate, rebuild, and re-prove events

## Purpose

This page is the ordered event surface for how a case moved from future-arrival-safe baseline into partial bootstrap recipe, fresh-world proof, supported-version coverage, or later reproduction regression.
It exists so later readers can see rebuild timing directly rather than reconstructing it from service restarts and install notes.

## Event types

The timeline must support at least these event kinds:

- baseline receipt imported
- bootstrap review opened
- startup-config recipe recorded
- clean-install path recorded
- migrate-settings path recorded
- service-principal target recorded
- storage-root fork detected
- manual rebind required
- manual rebind completed
- Standard-lane reproduction proven
- Advanced-lane reproduction denied
- version-lane risk declared
- version-lane reproduction proven
- supported-world reproduction claimed
- supported-world reproduction denied
- bootstrap scar recorded
- reproduction regression detected
- bootstrap reproducibility collapsed or suspended
- reproduction requalification completed

## Timeline queries

The page must answer:

- when did current-world safety stop being the strongest honest sentence?
- when was clean-world reproduction first formally reviewed?
- when did service or storage-world rebirth first block the stronger sentence?
- when did supported-version reproduction first become honest?
- when did later drift, upgrade, reinstall, or world fork collapse the bootstrap claim?

## View modes

The page must provide:

- all-events view
- bootstrap-source view
- service-and-storage view
- version-lane view
- proof-only view
- regression-only view
- requalification-only view
