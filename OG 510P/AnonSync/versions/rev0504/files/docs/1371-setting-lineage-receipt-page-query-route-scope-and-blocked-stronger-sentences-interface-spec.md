# Setting-lineage receipt page — query, route, scope, and blocked stronger sentences

## Purpose

This receipt gives one durable line-item answer to:

> what setting was asked for, what canonical object the product matched, where the real edit route lived, what scope it governed, what activation rung applied, and what stronger settings sentence the product refused to make?

## Receipt fields

### Query block

- operator query text
- alias matched
- canonical setting id
- current viewing surface

### Route block

- winning surface
- exact edit route
- witness-only surfaces
- rejected false-friend route

### Scope / authority block

- scope class
- override class
- winning authority
- strongest proof rung reached

### Activation / verification block

- activation rung
- current verification class
- strongest missing witness
- whether current surface can cure it

### Strong-sentence block

- strongest allowed sentence
- blocked stronger sentence
- exact reason blocked

## Copy rules

- Prefer `visible here, edited elsewhere` over generic `go to settings`.
- Prefer `share-local override` over `global setting changed` when detachment exists.
- Prefer `startup-owned config` over `currently set` when the runtime has not adopted it.
- Prefer `service route required` over `not available` when the setting exists but belongs to a colder world.

## Example final sentence pattern

> `This query resolved to <canonical setting>; the real edit route is <surface/path> for <scope>, and stronger sentence <same-surface editable / global authority / active now> was blocked by <missing proof>.`
