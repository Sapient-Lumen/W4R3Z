# Remedy-discharge review page — is it safe to release this repair case back to ordinary mutation and admission policy?

## Decision question

This page answers one operational question:

**Has this repaired case become safe enough to release from special quarantine and remedy fences, or are remembered approvals, linked-device spread, resharing rights, pending participants, or unreviewed admission paths still keeping ordinary-life restoration blocked?**

## Review sections

### 1) Convergence versus discharge

The review must begin by comparing the already-proven convergence result with the stronger discharge claim actually available now.
It must show:

- what converged
- which special fences remain active
- which ordinary rights are being considered for restoration
- what stronger discharge sentence is still blocked

### 2) Mutation-right restoration audit

The page must separate:

- named writer cohort requesting restoration
- required writer cohort
- currently restored write rights
- currently restored delete or rename rights
- read-only fallback posture
- unresolved write-surface exclusions

### 3) Admission-surface audit

The page must show what can still re-open the case unintentionally, including:

- remembered approvals across linked devices
- pending folders that may auto-connect later
- linked-device automatic folder availability
- Owner-level onward sharing power
- Standard-folder resharing exposure
- disconnected but still visible participants awaiting later action

### 4) Quarantine release scope

The page must model which cohorts are intentionally inside or outside discharge.
It must separate:

- named cohort granted restored mutation rights
- named cohort granted restored admission rights
- still-quarantined participants
- auto-approved but not yet re-reviewed participants
- future joiners kept outside ordinary policy
- rearm triggers that would reclose the case

### 5) Highest honest sentence

The page must always conclude with one highest honest sentence from this family:

- `future-joiner-safe convergence pending discharge review`
- `discharge blocked by remembered approval surface`
- `discharge blocked by linked-device owner spread`
- `discharge blocked by broad onward-sharing exposure`
- `discharge blocked by pending or disconnected participant outside review`
- `discharge partial for named writer cohort`
- `ordinary mutation restored for named cohort`
- `ordinary mutation restored for required cohort`
- `ordinary admission restored for required cohort`
- `quarantine released with rearm conditions`
- `discharge collapsed and quarantine reclosed`
- `discharge verification collapsed`

It must also name the blocked stronger sentence and why it remains blocked.

## Review invariants

- the review never lets convergence impersonate discharge
- the review never lets restored write rights impersonate restored admission rights
- the review never lets remembered approval impersonate fresh discharge
- the review always names the exact blocker that prevents the stronger discharge sentence
