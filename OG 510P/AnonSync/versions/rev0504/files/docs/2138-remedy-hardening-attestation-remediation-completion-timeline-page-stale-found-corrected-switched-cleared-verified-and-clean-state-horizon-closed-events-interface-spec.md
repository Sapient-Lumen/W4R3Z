# Remedy-hardening-attestation remediation-completion timeline page — stale found, corrected, switched, cleared, verified, and clean-state horizon closed events

## Purpose

This page gives the operator and later reader one chronological view of how outsider remediation moved from stale reliance toward a self-verifying clean state.

## Event families

The timeline must support at least:

- stale artifact found
- corrected replacement reached
- correction opened or downloaded
- working state switched
- stale local residue cleared or placeholderd
- disconnected copy retired
- archive checked or restored
- portable proof artifact issued
- clean-state verified
- clean-state horizon closed
- relapse or re-open event

## Timeline rules

The timeline must make visible:

- the gap between first seeing the correction and actually switching
- the gap between switching and retiring stale residue
- the gap between residue retirement and portable clean-state proof
- every later event that re-opened stale state or weakened the proof

## Timeline warnings

The page must visibly flag when:

- completion was inferred from activity rather than direct switch evidence
- residue retirement was partial or limited to one device / slice
- verification depended on transient history or a currently online peer
- later archive restore, reconnect, placeholder hydration, or forwarded-copy events reopened stale reliance risk
