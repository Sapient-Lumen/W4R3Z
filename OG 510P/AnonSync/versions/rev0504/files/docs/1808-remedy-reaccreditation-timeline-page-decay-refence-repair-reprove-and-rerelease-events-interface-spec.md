# Remedy-reaccreditation timeline page — decay, re-fence, repair, re-prove, and re-release events

## Purpose

This page is the ordered event surface for how a case moved from uncertainty or re-fence into remediation, proof refresh, and honest re-entry or continued fencing.
It exists so later readers can see requalification timing directly rather than reconstructing it from support steps and quiet-looking recovery surfaces.

## Event types

The timeline must support at least these event kinds:

- uncertainty declared
- fail-safe narrowed permissions
- automatic re-fence fired
- manual re-fence completed
- signal path restored
- restart performed
- rescan requested
- force rescan executed
- reconnect or re-add performed
- cause remediation declared
- required-cohort proof refreshed
- post-recovery drill passed
- manual re-entry requested
- manual re-entry granted
- automatic re-entry executed
- sticky scar assigned
- tighter budget armed
- guarded ordinary life re-entered
- requalification collapsed

## Timeline queries

The page must answer:

- when did requalification actually begin?
- when was the original uncertainty cause judged remediated?
- when did required-cohort proof return?
- when did re-entry authority become available?
- when did guarded ordinary life become honest again?
- what scar and tighter-budget settings survived re-entry?

## View modes

The page must provide:

- all-events view
- remediation-only view
- proof-refresh view
- authority-and-release view
- scar-and-budget view
- collapse-only view
