# Remedy-hardening-attestation catastrophe-recovery contract sheet page — catastrophe class, anchor retention, and reconstitution budget

## Purpose

This page is the compact contract for deciding whether a governed state that survived ordinary churn and named regime shifts can still be honestly recovered after catastrophic loss, corruption, theft, or control-world collapse.
It exists so the product can distinguish `catastrophe unreviewed`, `bytes salvage only`, `anchor-dependent recovery possible`, `reconstitution blocked`, `safe re-foundation only`, `named catastrophe recovered for named slice`, and `same-world recovery ceiling blocked`.

## Core fields

- catastrophe-recovery identifier
- source regime-shift receipt identifier
- governing durable sentence before catastrophe
- named catastrophe class under review
- governed slice identifier
- preserved-bytes witness status
- preserved-share-instance witness status
- preserved-identity witness status
- preserved-storage-root witness status
- preserved-database-lineage witness status
- preserved-secret-or-key anchor status
- preserved-control-surface receipt status
- `.sync` capsule integrity status
- clone-or-image-restore exposure status
- forced-reset or forced-regeneration status
- safe successor-world identifier
- reconstitution budget summary
- current catastrophe-recovery class
- highest currently safe catastrophe-recovery sentence
- strongest blocked stronger sentence
- next fact that upgrades catastrophe-recovery standing now
- next fact that collapses catastrophe-recovery standing now

## Catastrophe-recovery classes

The page must model at least these distinct classes:

- catastrophe class unreviewed
- bytes salvage only, governing continuity unknown
- anchor-dependent recovery possible, witness missing
- encrypted-backup or retained-database path conditionally recoverable
- `.sync` or instance capsule lost, same-instance continuity blocked
- clone-derived restoration unsupported
- safe re-foundation required, prior world continuity severed
- named catastrophe recovered for named slice only
- same-world reconstitution proven for named slice only
- broader all-catastrophe recovery robustness blocked

## Minimum required comparisons

The page must force explicit comparison between:

- ordinary migration and catastrophe recovery
- preserved bytes and preserved governing anchors
- same-world reconstitution and successor-world re-foundation
- retained database lineage and regenerated share instance
- retained identity and newly generated identity
- supported recovery path and unsupported clone-like shortcut

## Hard rules

- `the files came back` must never silently upgrade to `the same governed world came back`.
- `the storage folder exists` must never silently upgrade to `the right anchors survived inside it`.
- `re-added and syncing again` must never silently upgrade to `same share instance recovered`.
- `new identity is active` must never silently upgrade to `prior identity continuity preserved`.
- `image restore booted` must never silently upgrade to `supported same-world recovery`.
