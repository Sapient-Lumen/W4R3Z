# Remedy-hardening-attestation successor action-plan lineage receipt page — chosen actuator, blast radius, and blocked stronger least-harm sentences

## Purpose

This page is the compact receipt a product can carry forward after reviewing whether the chosen successor-world execution plan was the narrowest legitimate way to achieve the intended result.
It exists so downstream users can quote one durable object instead of reconstructing proportionality from linked-device defaults, share-dialog options, and manual detours.

## Receipt body

Every successor-action-plan receipt must contain:

- receipt identifier
- successor-action-plan case identifier
- source successor-action-authorization receipt identifier
- successor world identifier
- governed slice identifier
- named action identifier
- purpose basis
- beneficiary slice identifier
- chosen actuator family and identifier
- expected spread set
- persistence horizon class
- forwardability class
- auto-expansion exposure
- reversibility class
- narrowest known rejected alternative if any
- least-harm assessment state
- highest honest public sentence
- strongest blocked stronger sentence
- specific contradiction set that blocks the stronger sentence
- next evidence needed for upgrade
- downgrade trigger set
- receipt issue time
- receipt expiry or mandatory re-review horizon

## Allowed highest honest public sentences

The receipt may expose sentences such as:

- action authorized, actuator family not yet reviewed
- one-time transfer sufficient, broader sync blocked
- read-only narrow lane available, broader write lane blocked
- local-only actuator sufficient, remote share blocked
- broader actuator justified by named necessity only
- emergency broader actuator tolerated pending narrowing
- chosen actuator proportionate for named slice only
- stronger least-harm sentence still blocked

## Forbidden upgrades

The receipt must never allow:

- `least harmful` without naming the actuator family or slice
- `no safer alternative` when narrower lanes were not reviewed
- `temporary` when the chosen actuator is non-expiring or effectively durable
- `minimal spread` when linked-device or broad share effects remain live
- `future planning precedent established` from one one-off proportionate plan

## Receipt downgrade triggers

The receipt must automatically become stale or downgraded when:

- a narrower feasible actuator is discovered later
- the chosen actuator's blast radius broadens beyond the named slice
- a supposedly temporary or limited lane becomes durable or forwardable beyond review
- the beneficiary need narrows so the original actuator is now broader than required
- new evidence shows convenience rather than necessity drove the broader choice
- a rulebook revision raises the least-harm burden for this action class
