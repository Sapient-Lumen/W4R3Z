# Remedy-hardening-baseline review page — has this bounded rollout actually become the safe baseline for future arrivals?

## Purpose

This page is the operator's adjudication surface for whether a case that already achieved bounded rollout may now claim that the hardened behavior became the ongoing safe baseline.
It exists so the operator can answer one typed question instead of reconstructing baseline truth from linked-device defaults, Standard-versus-Advanced semantics, default folder paths, config-mode behavior, and folder-preference fragments.

## Primary review question

`Did this case merely achieve a bounded rollout for the present cohort, or has that hardened state actually become the safe baseline for future arrivals without depending on temporary rollout scaffolds?`

## Required review panes

### 1. Arrival-surface pane

Show:

- named future-arrival surfaces
- linked-device future-arrival inheritance status
- Standard-folder, key, and onward-share exposure
- link-based admission posture
- strongest blocked stronger sentence caused by future-arrival surface

### 2. Baseline-source pane

Show:

- configuration-mode coverage status
- default path and arrival-binding status
- per-folder preference inheritance status
- whether the claimed baseline is global, per-folder, desktop-only, startup-only, or otherwise partial
- strongest blocked stronger sentence caused by baseline-source fragmentation

### 3. Scaffold-and-exception pane

Show:

- temporary rollout scaffold inventory
- manual one-way or pilot detour inventory
- remembered-approval dependence
- explicit carry-forward scars or exceptions
- whether retirement is real, partial, or merely assumed

### 4. Future-cohort pane

Show:

- named current protected cohort
- required future-arrival cohort
- synchronization-mode inheritance map
- whether Disconnected, Selective Sync, or Synced lanes inherit the same baseline honestly
- final honest baseline-assimilated sentence ceiling

## Required review outcomes

The page must support outcomes such as:

- `the rollout remained bounded, but baseline assimilation is still blocked`
- `the baseline is honest only for the current cohort, not for future arrivals`
- `future arrivals are safe through one lane, but Standard-key or linked-device semantics still block the stronger sentence`
- `the hardened state is future-arrival safe, but one rollout-era scaffold still prevents ordinary-baseline language`
- `the hardened state has now become the safe baseline for the required arrival surfaces and cohorts`

## Review discipline

The review must forbid these shortcuts:

- bounded rollout equals baseline assimilation
- default path equals safe future admission
- linked-device availability equals safe baseline inheritance
- one manual detour equals ordinary one-way baseline
- remembered approval equals fresh safe baseline
- one desktop preference equals whole-baseline absorption
- current cohort calm equals future-arrival safety
