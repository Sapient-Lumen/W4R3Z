# Remedy-hardening-attestation successor reference rebinding lineage receipt page — canonical successor pointer, retired handles, and blocked stronger discovery sentences

## Purpose

This page is the durable receipt for the strongest honest successor-reference-rebinding sentence after reviewing whether predecessor-era handles still remain live or ambiguous.
It is the page a later operator opens when they need to know which handle now canonically represents the successor, which predecessor handles were retired or redirected, who was told, and which stronger discovery sentence remained blocked.

## Required receipt fields

The receipt must preserve:

- successor-reference-rebinding identifier
- source successor-inheritance receipt identifier
- predecessor world identifier
- successor world identifier
- named governed slice
- current successor-reference-rebinding class
- predecessor handle families in scope
- canonical successor handle set
- predecessor handles tombstoned status
- predecessor handles redirected status
- predecessor handles still live status
- external copied-reference status
- dependent rebinding notice and acknowledgement status
- bridge-authority or rebinding-authority source
- rulebook version
- highest honest successor-reference-rebinding sentence
- strongest blocked stronger sentence
- exact blocker summary
- next evidence needed for upgrade
- next evidence that would force downgrade
- issuance timestamp
- issuer identity

## Canonical sentence families

The receipt must support at least these sentence families:

- the successor world is legitimate, but rebinding has not yet been reviewed
- a canonical successor pointer is chosen for the named slice, while predecessor handles still remain live
- predecessor handles are retired internally for the named slice, while copied external references remain uncontrolled
- redirects to the successor are active for the named slice only
- stale predecessor handles still resolve, so stronger discovery claims remain blocked
- named handle families are retired and the successor pointer is canonical for the named slice only
- broader universal discovery continuity remains blocked

## Hard rules

- The receipt must never collapse `successor inherited standing` into `everyone now reaches the successor through the right handle`.
- The receipt must never collapse `reissued` into `same reference still valid`.
- The receipt must never collapse `old key replaced here` into `old key stopped mattering everywhere`.
- The receipt must never collapse `same name` into `same canonical pointer`.
- The receipt must never collapse `named handle family retired` into `all predecessor discovery vectors closed`.
