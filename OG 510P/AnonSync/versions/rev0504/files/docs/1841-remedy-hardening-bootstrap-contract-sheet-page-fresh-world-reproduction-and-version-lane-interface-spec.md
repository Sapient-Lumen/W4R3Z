# Remedy-hardening-bootstrap contract sheet page — fresh-world reproduction and version-lane safety

## Purpose

This page is the operator's compact contract for whether a case that already achieved recurrence-hardened-retained-change-gated-rollout-bounded-and-baseline-assimilated discharge may honestly claim that the same safety posture is reproducible on a fresh or rebuilt world.
It exists so the product can distinguish `the current world is safe` from `a clean bootstrap, rebuild, or migration will reproduce the same safe baseline without silent downgrade`.

## Core fields

- case identifier
- source remedy-hardening-baseline receipt identifier
- triggering cause family
- current remedy-hardening-bootstrap posture rung
- current hardening or baseline class
- named current world
- named fresh-world target class
- required reproduction cohort
- supported platform lane set
- supported version lane set
- service principal or runtime mode target
- storage-root continuity status
- identity carry-forward or rebirth rule
- migrate-settings path status
- clean-install path status
- Standard-folder reproduction coverage
- Advanced-folder reproduction coverage
- per-folder preference reproduction status
- startup-config reproduction status
- linked-device inheritance dependence status
- manual rebind or re-share requirement status
- reproduction scar or carry-forward exception status
- highest honest current bootstrap-reproducible sentence
- strongest blocked stronger bootstrap-reproducible sentence
- next strengthening trigger
- next weakening trigger

## Remedy-hardening-bootstrap posture rungs

The page must model at least these distinct rungs:

- baseline safe only in current world
- bootstrap recipe present but partial
- clean-world reproduction pending
- startup-config reproduces named defaults only
- Standard-folder lanes reproducible; Advanced or special lanes unresolved
- service or storage-world migration pending manual rebind
- version-lane compatibility blocked
- clean-install reproduction proven for named cohort
- rebuild-safe for required world class
- recurrence-hardened-retained-change-gated-rollout-bounded-baseline-assimilated-and-bootstrap-reproducible discharge achieved
- bootstrap reproducibility collapsed, stale, or suspended

## Required distinctions

The page must keep these truths separate:

- safe current world versus reproducible fresh world
- startup recipe present versus clean-world reproduction proven
- settings migration versus invariants re-proven
- Standard-lane reproduction versus full-lane reproduction
- service principal continuity versus storage-world continuity
- supported version lane versus merely nearby version
- linked-device repopulation versus honest hardening reproduction
- one successful rebuild versus required-cohort reproduction

## Operator promises

The contract sheet must let the operator say things like:

- `the current world is safe, but a clean rebuild would not yet reproduce the same safety posture`
- `the bootstrap recipe reproduces named Standard lanes only`
- `service-account or storage-root change still blocks the stronger fresh-world sentence`
- `settings migration exists, but the safety invariants have not yet been re-proven`
- `the hardened baseline is now reproducible through the required clean-world, rebuild, and supported-version lanes with scars preserved`

## UI behavior

The page must visually scar any blocked stronger sentence with the exact blocker class:

- startup config too narrow
- folder-type reproduction incomplete
- per-folder preference reproduction missing
- service-principal or storage-root fork unresolved
- clean-install path requires manual rebind not yet proven
- version-lane compatibility blocked
- linked-device auto-spread hiding missing bootstrap proof
- evidence basis too weak to claim fresh-world reproduction
