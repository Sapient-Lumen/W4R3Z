# Remedy-hardening-attestation successor reference rebinding proof page — handle ledger, resolution map, and rebinding ceiling

## Purpose

This page is the evidence-heavy proof surface for determining whether predecessor-era references have actually been retired, redirected, or rebound to the legitimate successor world.
It proves the ceiling on any claim that tries to say the successor is not only valid, but also the canonical target reached through the right handles.

## Required evidence blocks

### 1. Predecessor-handle ledger

Preserve:

- predecessor world identifier
- predecessor handle families
- handle issuance source
- handle propagation surfaces
- handle current live or copied status

### 2. Successor-pointer ledger

Preserve:

- successor world identifier
- chosen canonical successor handle set
- handle audience scope
- handle publication channels
- handle reissue events

### 3. Retirement and redirect ledger

Preserve:

- predecessor handles explicitly tombstoned
- predecessor handles redirected to successor
- predecessor handles still resolving as predecessor
- predecessor handles outside governance
- redirect or tombstone effective-scope witnesses

### 4. Dependent rebinding ledger

Preserve:

- dependent humans and systems notified
- acknowledgements received
- stale-handle hits detected
- successful successor-handle resolutions observed
- still-ambiguous consumers

### 5. Contradiction and downgrade ledger

Preserve:

- old-key peer continuity exposure
- non-expiring shared-link exposure
- copied message or bookmark exposure
- same-name alias ambiguity exposure
- conflicting resolution witnesses
- resulting downgrade class

### 6. Claim ceiling

Render:

- highest honest canonical-pointer sentence
- highest honest tombstone sentence
- highest honest redirect sentence
- highest honest dependent-rebinding sentence
- blocked stronger sentence and exact blocker

## Evidence classes

The page must distinguish at least:

- successor legitimate only
- canonical successor pointer chosen only
- internal handles rebound only
- predecessor handles tombstoned for named slice only
- redirects active for named slice only
- old handles still live
- dependent rebinding partial
- external copied references uncontrolled
- universal discovery continuity blocked

## Hard rules

The proof page must never treat:

- re-share success as proof all predecessor handles are retired
- key rotation as proof old keys stopped resolving
- same visible folder name as proof that stale references now mean the successor
- redirect for one channel as proof that every audience reaches the successor
- calm after rebuild as proof that predecessor discovery vectors disappeared
