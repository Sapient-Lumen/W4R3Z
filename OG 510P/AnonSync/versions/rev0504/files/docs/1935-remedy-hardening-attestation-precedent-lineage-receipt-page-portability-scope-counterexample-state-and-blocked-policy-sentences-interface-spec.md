# Remedy-hardening-attestation precedent lineage receipt page — portability scope, counterexample state, and blocked policy sentences

## Purpose

This page is the durable one-receipt summary for precedent claims after closure.
It lets a later operator read one artifact and know exactly whether the source case stayed case-specific or became portable for a named future-case class, a pilot cohort, or a ratified policy scope.

## Receipt fields

- receipt identifier
- case identifier
- source affected-party-closure receipt identifier
- current precedent-portability class
- target classes currently in scope
- target classes explicitly out of scope
- required invariants summary
- unresolved similarity gaps summary
- pilot reuse summary
- counterexample summary
- ratification owner and state
- review or sunset summary
- highest honest portability sentence
- blocked stronger policy sentence
- evidence bundle references
- issued-at timestamp

## Primary sentence block

The receipt must begin with exactly two lines:

- **Highest honest portability sentence**
- **Blocked stronger policy sentence**

## Required sections

1. **Why the source case was or was not fit for reuse**
2. **Which future-case classes are actually in scope**
3. **Which invariants must match and which differences are excluded**
4. **What pilot reuses and counterexamples changed the rule**
5. **Why the next stronger policy sentence is still blocked**

## Hard rules

The receipt must never let:

- `case closed` impersonate `precedent established`
- `one successful reuse` impersonate `policy ratified`
- `same label` impersonate `same topology class`
- `no current counterexample` impersonate `portable everywhere`
- `rule once ratified` impersonate `immune to sunset, narrowing, or revocation`
