# Remedy-hardening-attestation successor beneficiary-authority lineage receipt page — canonical authority summary and blocked stronger legitimacy sentences

## Purpose

This page is the portable receipt summarizing what can honestly be claimed about which authority set governs future beneficiary-facing changes now.
Later pages must cite this receipt instead of improvising `the right owner controls it`, `this lane is canonical`, or `future supersessions are definitely legitimate` language.

## Receipt header

The header must show:

- receipt identifier
- action identifier
- source beneficiary-continuity receipt identifier
- named beneficiary identifier
- current beneficiary-authority standing
- current strongest safe sentence
- current blocked stronger sentence

## Mandatory receipt fields

- source beneficiary-continuity receipt identifier
- named beneficiary summary
- governed slice summary
- intended canonical authority-set summary
- actual empowered authority-set summary
- lane architecture summary
- governance-aperture summary
- linked-device spread summary
- approval-memory summary
- onward-share / delegation summary
- contradiction status
- superseding receipt identifier if any

## Standing states

The receipt must support at least these states:

- beneficiary continuity proved, authority still unproven
- canonical authority set for named seat only
- canonical authority plus revocation power for named slice only
- multi-owner governance present
- approval carry-forward widened future admission scope
- onward-share or delegation widened legitimacy surface
- later contradiction narrowed prior authority confidence
- receipt superseded

## Primary sentence classes

The receipt must be able to emit at least these classes:

- `beneficiary remains on a live lane; canonical-authority sentence still blocked`
- `beneficiary is governed by the reviewed sovereign set for named seat only`
- `future beneficiary updates remain live, but authority aperture is wider than reviewed`
- `shared owner set governs this beneficiary-facing result`
- `approval carry-forward widened the future admission surface`
- `later contradiction narrowed prior beneficiary-authority confidence`
- `stronger exclusive-canonical-authority sentence remains blocked`

## Display requirements

The compact receipt view must show exactly four top chips:

- lane live / lane detached
- authority exclusive / authority shared / authority widened
- delegation closed / delegation open
- strongest sentence ceiling

Selecting any chip must reveal the evidence row that caused it.

## Hard rules

The receipt must never let later pages say:

- only the reviewed sovereign can still bind this beneficiary
- every future supersession is guaranteed to come from the reviewed canonical set
- approval scope remains as narrow as originally reviewed
- onward sharing cannot widen legitimacy surface

unless the receipt actually carries the corresponding proof state.
