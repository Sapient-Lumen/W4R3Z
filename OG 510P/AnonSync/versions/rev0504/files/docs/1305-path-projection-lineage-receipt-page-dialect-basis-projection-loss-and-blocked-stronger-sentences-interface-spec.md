## Path-projection lineage receipt

### Receipt purpose
Preserve one durable ordinary-language record for any serious path-bearing action.

### Required fields
- **Subject handle**
- **Visible pathname at action time**
- **Reviewed cohort scope**
- **Filesystem dialect class**
- **Normalization posture**
- **Case posture**
- **Symbol projection class**
- **Length ceiling basis**
- **Object-kind projection**
- **Observed outcome**: intact, rewritten, conflicted, blocked, or link-only
- **Loss boundary**
- **Evidence basis**
- **Safer alternative offered**
- **Blocked stronger sentence**

### Example receipt sentence
`This rename fit the currently reviewed cohort's weakest known path ceiling and no rewrite or conflict was witnessed on reviewed seats, but future seats with tighter case, normalization, symbol, or link-class rules remain outside this proof.`

### Product consequence
A later operator should never have to rediscover whether a bad surprise came from human rename intent, filesystem dialect mismatch, unsupported symbols, path length, or link-object projection ambiguity.
