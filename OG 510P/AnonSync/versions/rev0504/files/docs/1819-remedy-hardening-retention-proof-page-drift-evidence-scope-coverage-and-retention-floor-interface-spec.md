# Remedy-hardening-retention proof page — drift evidence, scope coverage, and retention floor

## Purpose

This page is the proof bundle behind the claim that a case which already claimed recurrence hardening has also retained that hardening across later drift, overrides, carry-forward, and world changes.
It exists so later readers can inspect retained control presence, divergence evidence, cohort coverage, and continuity proof instead of inferring them from operational memory.

## Proof bundle

The proof page must preserve evidence for:

- source remedy-hardening result
- triggering cause family
- original hardening strategy
- current retained-versus-drifted control evidence
- global-default evidence, if relevant
- manually altered share divergence evidence
- peer-local rule or IgnoreList coherence evidence
- linked-device or later-admission carry-forward evidence
- required retention cohort
- retained scope coverage evidence
- lower-permission or sync-mode retention evidence, if relevant
- service or storage-world continuity evidence
- strongest honest current retained-hardening sentence
- strongest blocked stronger recurrence-retained sentence

## Proof sentence families

The page must support concise summaries such as:

- `the case hardened once, but one manually overridden lane detached from current defaults, so retained hardening remains blocked`
- `the original cohort still carries the control, but future carry-forward remains outside retained scope`
- `peer-local rule divergence reopened ambiguity, so required-cohort retained hardening is not yet honest`
- `service-world continuity broke and the hardened state had to be re-proven before retained-hardening language could return`
- `required cohort and future carry-forward both remain aligned, so recurrence-hardened-and-retained discharge is now honest`

## Stronger-sentence blockers

The page must explicitly name blockers such as:

- retention unreviewed
- manual override detached lane
- global default no longer authoritative for all lanes
- peer-local rule divergence still open
- linked-device carry-forward still exposed
- later-admission scope not yet audited
- service or storage-world discontinuity unresolved
- evidence basis too weak

## Evidence handling rules

The proof page must never let these substitute for stronger proof:

- one default value without lane-by-lane exception evidence
- one folder preference without carry-forward scope evidence
- one peer's IgnoreList without peer-set coherence evidence
- one healthy restart without continuity proof across storage world
- one old hardening receipt without new retained-hardening evidence
