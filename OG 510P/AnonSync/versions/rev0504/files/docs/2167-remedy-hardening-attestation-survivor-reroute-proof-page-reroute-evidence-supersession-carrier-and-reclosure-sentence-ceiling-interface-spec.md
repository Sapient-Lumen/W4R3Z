# Remedy-hardening-attestation survivor-reroute proof page — reroute evidence, supersession carrier, and re-closure sentence ceiling

## Purpose

This proof page preserves the evidence bundle for survivor self-routing and automatic re-closure.
It exists so the archive can distinguish `we know rediscovery would reopen` from `the rediscovered thing can route the finder to current truth and help restore closure`.

## Minimum evidence families

The page must preserve at least these evidence families when applicable:

- survivor carrier inventory evidence
- supersession-explanation evidence
- canonical-target evidence
- reroute viability evidence
- client / app handoff evidence
- manual-step burden evidence
- operator-dependency evidence
- re-closure evidence

## Evidence grading

Each evidence item must be graded as one of:

- proves self-routing and re-closure
- proves routing only for named in-lane users
- proves operator-mediated reroute only
- proves only generic handoff or landing-page visibility
- proves detached survivor with no route
- contradicts self-routing claim

## Required summary fields

The proof page must summarize at least:

- highest-risk carrier class
- self-routing carrier count
- operator-dependent carrier count
- dead-end carrier count
- maximum honest re-closure lag
- strongest honest self-routing sentence
- blocked stronger self-routing sentence

## Sentence ceiling rule

The page must never allow a stronger self-routing sentence than the weakest unresolved carrier fact permits.
For example:

- a landing page that shows only basic info must not justify `self-explaining supersession`
- a route that works only through manual WebUI paste must not justify `operator-free reroute`
- custom names that do not propagate must not justify `durable survivor-carried explanation`
- a reshared single-file copy must not justify `all survivors self-route`
