# Remedy-hardening timeline page — cause fix, rollout, activation, and collapse events

## Purpose

This page is the ordered event surface for how a case moved from honest re-entry into durable recurrence hardening or back into hardening debt.
It exists so later readers can see hardening timing directly rather than reconstructing it from scattered config edits and permission history.

## Event types

The timeline must support at least these event kinds:

- cause family identified
- temporary workaround armed
- durable hardening drafted
- config rollout started
- folder-preference rollout started
- permission topology narrowed
- ignore rule added or revised
- required-cohort deployment reached
- restart required
- rescan required
- activation proven in risky lane
- carry-forward surface closed
- linked-device spread narrowed
- recurrence-hardening achieved
- hardening debt assigned
- hardening collapsed or rolled back

## Timeline queries

The page must answer:

- when did hardening actually begin?
- when did the case move beyond one-off repair into durable prevention?
- when did required-cohort coverage become true?
- when did the risky lane become actively protected rather than merely configured?
- when did future carry-forward exposure close?
- when did recurrence-hardened discharge become honest, or collapse again?

## View modes

The page must provide:

- all-events view
- cause-to-control view
- rollout-only view
- topology-and-authority view
- activation-proof view
- collapse-only view
