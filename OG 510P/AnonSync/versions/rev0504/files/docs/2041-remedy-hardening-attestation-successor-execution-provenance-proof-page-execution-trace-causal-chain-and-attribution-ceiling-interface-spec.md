# Remedy-hardening-attestation successor execution provenance proof page — execution trace, causal chain, and attribution ceiling

## Purpose

This page is the durable proof artifact that preserves what exact run fired, which actor and subsystem initiated it, which reviewed lane matched or diverged, which automatic behaviors remained plausible, and what stronger attributable-execution sentence therefore stayed blocked.

## Minimum proof bundle

The proof page must preserve at least:

- source preview/commit-binding receipt identifier
- source action-envelope receipt identifier
- execution-run identifier
- commit token identifier
- reviewed actuator identifier
- observed start timestamp
- observed first-effect timestamp
- initiating actor evidence
- initiating subsystem or process evidence
- execution-world evidence
- reviewed-lane versus actual-lane comparison
- background hazard status by family
- substitution or widening evidence
- observer quality for attribution
- strongest safe sentence at proof time
- strongest blocked stronger sentence at proof time

## Proof sections

### 1. Claimed causal chain summary

Show:

- what run was supposed to fire
- who or what was supposed to fire it
- what lane was supposed to be used
- what visible effects were expected first

### 2. Observed execution trace

For each trace component show:

- event time
- source actor or process
- source world
- actuator or mechanism used
- before state
- after state
- observer quality
- pass / fail / unknown for reviewed-lane match

### 3. Hazard ledger

For each attribution hazard show:

- why it matters
- whether it was still live
- whether it remained only hypothetical or became evidenced
- whether it widened, substituted, or merely shadowed the reviewed run
- whether it alone blocks the stronger sentence

### 4. Attribution ceiling statement

The page must end with a bounded statement such as:

- `run attributable to reviewed actor and reviewed lane for named slice only`
- `manual commit evidenced, but background widening hazard remained live`
- `visible outcome observed; causal source ambiguous between reviewed lane and rescan lane`
- `execution world ambiguous; stronger attributable-execution sentence blocked`
- `substitute actuator produced comparable outcome; reviewed-run sentence contradicted`

## Evidence grading

The proof page must support at least these grades:

- planned run only, not yet observed
- run started, actor source observed, lane still partial
- run attributable to named actor and named subsystem only
- run attributable to reviewed actor and reviewed actuator for named slice only
- run happened with unresolved automatic-behavior ambiguity
- run later contradicted by substitute-lane evidence
- attribution receipt superseded by stronger or weaker proof

## Hard rules

The page must never:

- treat outcome existence as causal proof
- treat missing subsystem evidence as manual proof
- erase live automatic hazards from the record
- treat ambiguous source worlds as equivalent worlds
- upgrade to `reviewed run fired exactly as reviewed` merely because the result looks compatible
