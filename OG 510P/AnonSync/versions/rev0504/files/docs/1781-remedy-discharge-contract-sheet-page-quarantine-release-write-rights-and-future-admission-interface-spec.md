# Remedy-discharge contract sheet page — quarantine release, write rights, and future admission

## Purpose

This page is the operator's compact contract for whether a repaired case can safely leave special remedy fences and return to ordinary mutation and admission policy.
It exists so the product can distinguish `the cure converged` from `the case is safely discharged back to ordinary life`.

## Core fields

- case identifier
- source remedy-convergence receipt identifier
- current remedy-discharge posture rung
- intended authoritative object identifier
- current quarantine scope
- remembered-approval surface posture
- linked-device owner-spread posture
- current write-right restoration scope
- current onward-sharing restoration scope
- current pending or auto-connect participant posture
- disconnected-but-still-visible participant posture
- Standard-folder resharing exposure posture
- Advanced-folder owner exposure posture
- ordinary mutation restoration scope
- ordinary admission restoration scope
- rearm condition set
- strongest blocked stronger cure sentence
- next strengthening trigger
- next weakening trigger

## Remedy-discharge posture rungs

The page must model at least these distinct rungs:

- future-joiner-safe convergence pending discharge review
- discharge blocked by remembered approval surface
- discharge blocked by linked-device owner spread
- discharge blocked by broad onward-sharing exposure
- discharge blocked by pending or disconnected participant outside review
- discharge partial for named writer cohort
- ordinary mutation restored for named cohort
- ordinary mutation restored for required cohort
- ordinary admission restored for required cohort
- quarantine released with rearm conditions
- discharge collapsed and quarantine reclosed
- discharge verification collapsed

## Required distinctions

The page must keep these truths separate:

- convergence versus discharge
- restored write rights versus restored admission rights
- Owner convenience versus case-authorized discharge
- remembered approval versus fresh case-specific admission
- linked-device visibility versus safe ordinary-lane release
- disconnecting a participant versus proving that future auto-reentry is fenced
- named-cohort restoration versus required-cohort restoration

## Operator promises

The contract sheet must let the operator say things like:

- `the repair converged, but remembered approvals still block discharge because future peers could connect without fresh case review`
- `ordinary mutation was restored for the named maintenance cohort, while onward sharing remained fenced`
- `linked-device owner spread still makes automatic re-expansion plausible, so quarantine release is not yet honest`
- `all required writers were restored, but standard-folder resharing still blocks ordinary admission restoration`
- `the case was discharged with rearm conditions, so any newly pending peer or widened sharing surface automatically reopens quarantine review`

## UI behavior

The page must visually scar any blocked stronger sentence with the exact blocker class:

- remembered approval surface still live
- linked-device owner spread still live
- broad resharing or onward admission still live
- pending or disconnected participant outside review
- write rights restored more broadly than admission rights
- discharge rearm condition still unsatisfied
