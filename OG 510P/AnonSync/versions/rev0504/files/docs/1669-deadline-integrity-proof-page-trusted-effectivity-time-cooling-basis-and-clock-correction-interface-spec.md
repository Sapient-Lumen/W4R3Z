# Deadline-integrity proof page — trusted effectivity time, cooling basis, and clock correction

## Purpose

This page is the durable proof object for the strongest time-based sentence honestly earned by a typed act.
It exists so later operators can see not merely that time passed, but that the relevant clock basis was strong enough, what corrections happened, and whether any stronger timer conclusion stayed blocked.

## Sentences this page may support

- `execution time observed, but deadline trust degraded by peer skew`
- `protective effect active on degraded time basis; irreversible cooling frozen`
- `notice completion and cooling both trusted after clock correction and renewed timer start`
- `expiry claimed earlier was reopened because the original clock basis became suspect`
- `manual adjudication accepted a trusted effectivity time after irreconcilable device clocks`

## Mandatory proof blocks

### A. Time-basis block

- authoritative time source
- clock-health class at decisive moments
- tolerated skew budget
- actual observed skew
- whether timezone mismatch was decisive
- highest temporal sentence honestly earned

### B. Timer proof block

- decisive trigger event
- timer start time
- timer pause or reset events
- cooling or expiry completion evidence
- exact reason completion is trusted, degraded, or blocked
- stronger timer sentence still blocked

### C. Correction proof block

- clock correction event
- whether correction was automatic or manual
- whether earlier timer progress was preserved, paused, or reset
- reopen consequences after correction
- adjudication evidence if used

### D. Scope-and-effect block

- which protective effects survived despite degraded time
- which irreversible effects were blocked
- which irreversible effects later matured after trusted time was restored
- which temporal claims remain contested
- exact next event that would strengthen or narrow this proof

### E. Audit block

- decisive device identities
- decisive UTC-normalization records
- decisive file-mtime references if admitted
- decisive notice and completion records
- decisive corrections and overrides
- decisive reopen records if any

## Required badges

- `trusted-deadline`
- `degraded-deadline`
- `suspect-deadline`
- `clock-corrected`
- `timer-reset`
- `timer-preserved`
- `protective-only`
- `irreversible-blocked`
- `adjudicated-time`
- `temporal-reopen`

Badges must stack instead of collapsing meaning.
For example, `clock-corrected` may coexist with `timer-reset`, and `protective-only` may coexist with `degraded-deadline`.

## Proof obligations

- prove time-source trust separately from raw timestamp presence
- prove timer start separately from timer validity
- prove clock correction aftermath separately from the correction event itself
- preserve which stronger deadline sentence remained blocked during degraded time
- preserve whether later correction reopened an earlier irreversible claim

## Stronger-sentence guard

This page may say `72 nominal hours elapsed, but only 31 trusted hours accrued before skew exceeded tolerance, so final waiver cooling did not mature until the corrected timer later completed`.
It may not say `deadline passed on schedule` unless the time basis actually supports that sentence.
