# Remedy-hardening-baseline timeline page — rollout, defaultize, exception retire, and regress events

## Purpose

This page is the ordered event surface for how a case moved from bounded rollout into provisional baseline, future-arrival-safe baseline, scaffold retirement, or later regression.
It exists so later readers can see baseline absorption timing directly rather than reconstructing it from folder defaults, device linking, or remembered rollout detours.

## Event types

The timeline must support at least these event kinds:

- bounded rollout receipt imported
- baseline review opened
- named future-arrival surfaces set
- required future-arrival cohort set
- linked-device inheritance risk declared
- Standard-key or onward-share risk declared
- default path or arrival-binding reviewed
- configuration-mode coverage reviewed
- per-folder preference inheritance reviewed
- temporary rollout scaffold declared
- scaffold retirement opened
- scaffold retired
- baseline scar recorded
- future-arrival-safe baseline claimed
- future-arrival-safe baseline denied
- baseline regression detected
- baseline assimilation collapsed or suspended
- baseline reassimilation completed

## Timeline queries

The page must answer:

- when did bounded rollout stop being the strongest honest sentence?
- when was future-arrival inheritance first formally reviewed?
- when were rollout-era scaffolds retired, and for which surfaces?
- when did the stronger baseline-assimilated sentence first become honest?
- when did drift, new admission, or scaffold return collapse the baseline claim?

## View modes

The page must provide:

- all-events view
- arrival-surface view
- scaffold-only view
- defaultization-only view
- regression-only view
- reassimilation-only view
