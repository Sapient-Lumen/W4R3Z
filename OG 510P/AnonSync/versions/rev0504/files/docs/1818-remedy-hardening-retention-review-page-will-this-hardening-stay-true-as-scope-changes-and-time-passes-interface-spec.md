# Remedy-hardening-retention review page — will this hardening stay true as scope changes and time passes?

## Purpose

This page is the operator's adjudication surface for whether a case that already claimed recurrence hardening has actually retained that hardening under later drift, overrides, carry-forward, and onboarding.
It exists so the operator can answer one typed question instead of reconstructing retained-hardening truth from scattered defaults, per-folder settings, linked-device behavior, and service/storage changes.

## Primary review question

`Did this case merely achieve recurrence hardening once, or has that hardening actually stayed retained as new folders, new devices, overrides, restarts, and storage-world changes accumulated afterward?`

## Required review panes

### 1. Drift-and-override pane

Show:

- original hardening control family
- later manual override exposure
- default-versus-effective divergence
- share-specific exception persistence
- strongest blocked stronger retained-hardening sentence from drift

### 2. Cohort-and-carry-forward pane

Show:

- required retention cohort
- original cohort retained or not
- later-admitted or later-created scope outside retention
- linked-device auto-spread exposure
- current retention ceiling for recurrence-safe language

### 3. Rule-and-topology pane

Show:

- IgnoreList or rule divergence across peers
- folder-type or permission-type asymmetry
- lower-permission retention still intact or not
- sync-mode or placeholder participation relevance
- strongest honest retained-hardening verdict ceiling

### 4. World-continuity pane

Show:

- service principal changes
- storage-path or service-world fork status
- re-add or re-share dependence
- evidence that the retained guardrail survived the world change
- final honest retained-hardening sentence ceiling

## Required review outcomes

The page must support outcomes such as:

- `recurrence hardening achieved once; retention not yet reviewed`
- `retained for named lane only; stronger retained-hardening still blocked`
- `manual override detached one share from the current guardrail`
- `peer-local rule divergence blocks required-cohort retention`
- `original cohort retained; future carry-forward still exposed`
- `required-cohort retained and future carry-forward retained`
- `retention collapsed; case remains requalified but not retained-hardened`

## Review discipline

The review must forbid these shortcuts:

- one unchanged default equals retained hardening
- one calm UI equals no drift
- one linked identity equals future carry-forward retention
- one matching peer equals rule coherence everywhere
- one restart equals same hardened world
- one prior hardening receipt equals current retained-hardening truth
