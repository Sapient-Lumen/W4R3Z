# Remedy-hardening-attestation successor-world inheritance contract sheet page — predecessor scope, carry-forward budget, and bridge authority

## Purpose

This page is the compact contract for deciding whether a recovered or re-founded successor world may legitimately inherit standing from a predecessor world whose continuity is partial, severed, or catastrophe-bounded.
It exists so the product can distinguish `successor world exists`, `bytes-only carry-forward`, `policy carry-forward only`, `obligation carry-forward only`, `named receipt inherited for named slice`, `trust-handle inheritance blocked`, and `same-world continuity still blocked`.

## Successor-inheritance classes

The page must model at least these distinct classes:

- successor world present, inheritance unreviewed
- bytes only inherited, governance unknown
- policy or precedent inherited, trust handles blocked
- obligation carry-forward required, execution basis partial
- remediation and revocation duties inherited for named slice only
- approval memory or trust-handle inheritance blocked
- named receipt inherited for named slice only
- named receipt reissued rather than inherited
- successor world ratified with bounded carry-forward budget
- same-world continuity still blocked despite bounded inheritance

## Minimum required comparisons

The page must force explicit comparison between:

- same-world continuity and successor-world inheritance
- bytes carry-forward and governance carry-forward
- policy inheritance and trust inheritance
- inherited obligation and inherited proof of fulfillment
- inherited receipt and reissued replacement receipt
- predecessor-bound authority and successor-ratified authority

## Hard rules

- `the new instance works` must never silently upgrade to `the old world's standing carried forward`.
- `some peers reconnected` must never silently upgrade to `old approvals or trust handles remain valid`.
- `we re-shared the folders` must never silently upgrade to `the old receipt was inherited`.
- `the successor is safer` must never silently upgrade to `all predecessor obligations are discharged`.
- `same bytes or names appeared again` must never silently upgrade to `same-world continuity restored`.
