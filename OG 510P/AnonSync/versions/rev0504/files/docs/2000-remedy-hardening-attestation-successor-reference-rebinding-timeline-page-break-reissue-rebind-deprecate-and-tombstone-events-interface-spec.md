# Remedy-hardening-attestation successor reference rebinding timeline page — break, reissue, rebind, deprecate, and tombstone events

## Purpose

This page is the ordered timeline for understanding how predecessor-era references were handled after a world break, successor ratification, or forced re-foundation.
It exists so later operators can see whether the successor merely became legitimate, or whether the surrounding reference ecosystem was actually repaired.

## Required event families

The timeline must be able to render at least these event families:

- predecessor handle issued
- predecessor handle propagated outward
- catastrophe or world break detected
- successor world created
- inheritance bridge ratified
- canonical successor pointer selected
- replacement key or link issued
- predecessor handle marked stale
- predecessor handle tombstoned
- predecessor handle redirected to successor
- dependent rebinding notice sent
- stale-handle hit observed
- acknowledgement of successor pointer received
- old-key or old-link continuity detected
- handle family declared outside governance
- canonical-pointer sentence upgraded or downgraded

## Event cards

Every event card must preserve:

- event identifier
- event class
- timestamp
- affected governed slice
- predecessor handle family
- resulting successor-reference-rebinding class
- rebinding effect
- blocker created or removed
- manual step required
- resulting stronger sentence blocked or unlocked

## Fixed rendering order

Every successor-reference-rebinding timeline must render the same sections in the same order:

1. **Predecessor handle basis**
2. **Break and successor-world basis**
3. **Canonical-pointer selection and handle reissue**
4. **Retirement, redirect, and stale-hit outcomes**
5. **Dependent rebinding status and final sentence**

## Hard rules

- The timeline must never hide predecessor-handle survival behind later successor legitimacy.
- The timeline must never hide reissue behind `same reference`.
- The timeline must never hide stale-handle hits behind `mostly migrated`.
- The timeline must never let later calm erase the fact that old references remained live for some horizon.
