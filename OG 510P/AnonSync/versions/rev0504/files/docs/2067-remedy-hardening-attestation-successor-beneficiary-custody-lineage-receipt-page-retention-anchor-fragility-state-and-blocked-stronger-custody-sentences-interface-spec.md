# Remedy-hardening-attestation successor beneficiary-custody lineage receipt page — retention anchor, fragility state, and blocked stronger custody sentences

## Purpose

This page is the portable receipt summarizing what can honestly be claimed about whether the named beneficiary now holds a durable copy under their own control.
Later pages must cite this receipt instead of improvising `they have it`, `it was downloaded`, or `the recipient now owns a copy` language.

## Receipt header

The header must show:

- receipt identifier
- action identifier
- source beneficiary-usability receipt identifier
- named beneficiary identifier
- current beneficiary-custody standing
- current strongest safe sentence
- current blocked stronger sentence

## Mandatory receipt fields

- source beneficiary-usability receipt identifier
- named beneficiary summary
- intended custody summary
- intended retention horizon summary
- current byte-possession summary
- retention-anchor summary
- self-sufficiency versus upstream-dependency summary
- source-withdrawal sensitivity summary
- placeholder-reversion or local-eviction sensitivity summary
- app-sandbox, license, or topology fragility summary
- export or handoff summary if any
- contradiction status
- superseding receipt identifier if any

## Standing states

The receipt must support at least these states:

- beneficiary can use result, custody still unproven
- source-dependent or placeholder-recoverable only
- local bytes present, but easy reversion or eviction risk remains
- local bytes present only in sandbox or topology-bound anchor
- beneficiary holds durable bytes for named seat only
- beneficiary holds self-sufficient custody for named slice only
- later contradiction narrowed prior custody confidence
- receipt superseded

## Primary sentence classes

The receipt must be able to emit at least these classes:

- `beneficiary can use result now; durable-custody sentence still blocked`
- `beneficiary depends on upstream availability or placeholder reversibility`
- `beneficiary has local bytes, but retention anchor remains fragile`
- `beneficiary has local bytes only inside app storage or fragile topology`
- `beneficiary holds self-sufficient custody for named seat or slice only`
- `later contradiction narrowed prior beneficiary-custody confidence`
- `stronger beneficiary-custody sentence remains blocked`

## Hard rules

The receipt must never let later pages say:

- the beneficiary has an independent durable copy
- the beneficiary can retain the copy regardless of upstream withdrawal
- the beneficiary now governs the copy fully
- the beneficiary has portable custody settled and final

unless the receipt actually carries the corresponding proof state.
