# Remedy-watch-uncertainty proof page — coverage loss, freshness decay, and fail-safe evidence

## Purpose

This page is the proof bundle behind the claim that a discharged case remains honest even when watch confidence decays.
It exists so later readers can inspect uncertainty triggers, budget use, and fail-safe evidence instead of inferring them from quiet operational surfaces.

## Proof bundle

The proof page must preserve evidence for:

- source remedy-watch-health result
- required guarded cohort
- uncertainty-declared cohort
- freshness-decay evidence
- signal-path degradation evidence
- notification-loss evidence
- rescan-only or restart-only detection evidence
- platform blind-spot evidence
- runtime blind-spot evidence
- configured uncertainty-budget evidence
- automatic fail-safe policy evidence
- automatic fail-safe execution evidence
- manual fail-safe completion evidence
- strongest honest uncertainty sentence
- strongest blocked stronger ordinary-life sentence

## Proof sentence families

The page must support concise summaries such as:

- `watch health had been current, but Android background-priority loss declared uncertainty for the required cohort and blocked stronger ordinary-life sentences before the grace budget expired`
- `Linux stayed an in-UI-only blind lane, but that lane was outside the required cohort so stronger ordinary-life claims remained honest`
- `watcher fallback moved detection to periodic rescan, uncertainty exceeded budget, and automatic narrowing fired on schedule`
- `service-side notification loss forced restart or rescan discovery, so the case remained discharged only under uncertainty-pending-fail-safe warning`
- `fresh required-cohort proof later resolved uncertainty and restored the stronger guarded sentence`

## Stronger-sentence blockers

The page must explicitly name blockers such as:

- uncertainty not yet classified
- uncertainty budget missing
- uncertainty budget exceeded
- required cohort affected
- automatic fail-safe missing
- automatic fail-safe not executed
- manual fail-safe incomplete
- platform blind spots too broad
- runtime blind spots too broad
- evidence basis too weak

## Evidence handling rules

The proof page must never let these substitute for stronger proof:

- one recent healthy probe without later uncertainty accounting
- one quiet bell or notification drawer
- one available rescan path without budgeted fail-safe behavior
- one log toggle without fresh captured evidence
- one named-cohort recovery when required-cohort uncertainty remains active
