# Kernel Kit guided tour frontier — rev0054

The Kernel Kit demo is now useful enough to need a guided-tour surface. The tour is not another runtime primitive; it is a human and future-session handoff layer that says what to click, what evidence should appear, what exact commands verify it, and what not to claim.

The guided tour runs through the same narrow wedge as the workbench: success path, reload readback, trace/export receipt, controlled failure, trace comparison, diagnostic runbook, support bundle, and non-claims. It makes the demo evaluable by a maintainer who has not been watching every revision.

## Why this belongs

Future sessions see less context than the current session. A guided tour reduces the chance that they will mistake the page for a production runtime, or miss why the support bundle/import reader matters. The tour keeps the broad release browser-light while preserving explicit browser spending through `browser:kernel-kit-demo-proof`.
