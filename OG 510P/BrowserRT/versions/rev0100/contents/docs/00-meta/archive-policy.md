# Archive policy

BrowserRT is allowed to be ambitious, but the archive must stay small enough for
fast reentry.

## Add a new surface only when

- it has a stable reader;
- it removes ambiguity that an existing surface cannot remove;
- it can be validated by `tools/check_cube.py` or a named future check;
- it is marked canon or derivative;
- it has a deletion or consolidation condition.

## Prefer

- editing an existing contract over adding a sibling;
- compact receipts over long logs;
- synthetic fixtures over external datasets;
- one manifest over many package summaries;
- one validation index over scattered command lore.

## Avoid

- ledgers without active operators;
- duplicate currentness fields;
- unchecked generated files;
- performance adjectives without measurement context;
- copying the example cubes' scale before BrowserRT has their need.
