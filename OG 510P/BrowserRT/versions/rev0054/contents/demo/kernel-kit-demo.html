Kernel Kit Demo Observatory + Failure/Export/Comparison/Diagnostic/Support Bundle/Handoff Import/Readiness Contrast workbench

One small browser-runtime workflow, made visible.

This page is the human-facing companion to browser:kernel-kit-demo-proof. It can be clicked by a person and driven by the managed Chromium/CDP harness. The demo composes runtime boot, bounded control, Worker compute, transfer object refs, admission control, OPFS storage-lane write/read, and trace receipts, a controlled failure-mode receipt, a Chrome-trace-shaped export bundle, and a side-by-side success/failure trace comparison, and a diagnostic runbook with exact next commands, and a portable support bundle plus support-bundle and handoff-Markdown import validators plus a readiness gate and a degraded-readiness contrast for future sessions.

Worker agentSpawn a browser Worker, send a BRT envelope, and compute over transferred bytes.
Object refMove an ArrayBuffer through the data plane and prove sender-side detachment.
Admission gateAccept valid work and reject oversized background work without mutation.
OPFS storage laneWrite/read an object through an OPFS block-store adapter and reload in the same profile.
Trace receiptProject runtime events into stage cards, lane timeline, and non-claim boundaries.
Trace/export workbenchEmit a BrowserRT receipt plus a Chrome-trace-shaped JSON envelope. No Chrome DevTools trace-format compatibility claim.
Failure-mode workbenchDeliberately trigger a missing-handoff failure and show that BrowserRT reports it without provider mutation.
Support bundleCollect success, reload, failure, comparison, diagnostic runbook, exact commands, and non-claims into one future-session handoff.
Guided tourRun the useful path, reload handoff, export, bounded failure, comparison, runbook, and support bundle in one ordered walkthrough.
Import validatorPaste a support bundle back into the page and validate its sections, commands, and non-claim boundaries.
Support-bundle diffCompare a pasted bundle against the current run to surface revision skew, missing commands, proof regressions, and non-claim drift before trusting a handoff.
Handoff MarkdownConvert the workbench state into a human-pasteable next-session brief with proof booleans, exact commands, and non-claims.
Handoff readerPaste the generated Markdown back into the page and validate its sections, commands, proof booleans, and non-claim boundaries.
Readiness gateTurn the whole workbench into persona-specific acceptance gates so future sessions know whether to continue or fix missing evidence first.
Readiness contrastIntentionally degrade a ready handoff and prove the gate reports missing evidence instead of pretending the weaker bundle is safe.

What rev0054 improves

Rev0042 proved the narrow Kernel Kit wedge could run. Rev0043 made the proof legible as a human-runnable observatory page. Rev0044 added a trace/export receipt and local reload handoff. Rev0046 added a side-by-side success/failure trace comparison. Rev0047 added a diagnostic runbook so future sessions can see what changed, what stayed bounded, exact commands to run next, and which non-claims still apply without widening production claims. Rev0048 added a portable support bundle so those facts could travel as one object. Rev0050 added a support-bundle diff reader so an imported handoff can be compared against the current run before a future session trusts it. Rev0052 adds a handoff Markdown reader so that the generated brief can be pasted back into the workbench and checked for sections, commands, proof booleans, and non-claim drift. Rev0054 adds a degraded-readiness contrast so the workbench teaches what a weaker handoff fails and why.

Usefulness scorecard

The rendered report now includes a Usefulness scorecard and Who benefits most section. This is deliberately not market validation; it is a local evidence ledger for browser-heavy builders deciding whether the narrow Kernel Kit wedge is worth polishing.
