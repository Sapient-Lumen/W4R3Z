Living Christ Figures datacube rules — current rev0102

Christ figure is a severe metaphor for costly mercy, not a theological claim and not an identification of divinity.

Rule 113 — Source backfill coverage / action-ledger ambiguity. The Source-Metadata-Backfill ledger is cumulative action history, but every Source Registry row must be covered by Source-Backfill-Coverage-Audit-current.* as covered or intentionally missing. Missing coverage fails the release gate; duplicate action rows must not be misread as source-registry coverage.

Rule 114 — Pacific GBV service-capacity quarantine. Pacific survivor-service, GBV, counselling, crisis-line, safe-house/refuge, family-protection, and legal-framework evidence may support aggregate internal institutional shape only. It must not be exported as a public directory, contact/helpline path, shelter/refuge cue, legal advice, protection-order-as-safety claim, referral/intake route, current-capacity statement, staff/site surface, case/client detail, image reuse, or route/support path.

Rule 115 — Suicide/crisis operational-detail redaction. Suicide, crisis-line, lifeline, and postvention evidence may support aggregate internal office shape only. Hotline shortcodes/contact digits, service-hour or availability statements, call-volume/caller-category fragments, method detail, triage, referral/contact paths, current-capacity claims, case/caller stories, minor-story extraction, suicide-training instructions, and suicide-linked legal/medical case detail must not be rendered as public or handoff-facing operational copy. Gate 075 enforces this through `META/Suicide-Crisis-Operational-Boundary-Audit-current.*`.

Rule 116 — Stale-mirror operational-detail regression. Operational-detail redaction gates must scan generated/current META mirrors and retained historical root ledgers when those surfaces carry candidate names, work summaries, or claim/status copy. A current-ledger-only scan is insufficient for hotline, refuge, route, memorial-intake, legal/medical, crisis, or survivor-service boundaries.

Rule 117 — Machine descriptor identity. `datapackage.json`, `manifest.json`, the public export manifest, and the package release contract must carry current package identity/counts or be explicitly labeled historical. Stale machine descriptors are release defects even when human front-door files are correct.

Rule 118 — Handoff digest freshness. `META/Handoff-Review-Digest-current.*` is gate-safe only when its revision and export name match `manifest.json`; a table of all-pass rows is insufficient if it describes an older package.

Rule 119 — Build-provenance baseline coherence. `BUILD-PROVENANCE-current.json` must agree with the current manifest for current revision/export and with `META/Previous-Release-Fingerprint-current.json` for previous revision/export. Previous-release identity belongs in baseline/fingerprint fields, not in current package fields.

Rule 120 — QA report freshness. `QA-REPORT-current.txt` must be regenerated after late-gate, checksum, and report-provenance changes. A stale fail/pass transcript is itself a release defect even when a fresh rerun would pass.

Rule 121 — Preservation envelope is not public permission. BagIt, PREMIS-style preservation events, RO-Crate, DataCite, PROV-O, DCAT, or similar external-transfer descriptors may improve fixity and interoperability, but they must preserve the cube's closed public posture unless a later governance decision explicitly changes public-release boundaries.

Public layer remains closed: no public URLs, archive URLs, contact paths, referrals, helpline details, route maps, support/service/housing/shelter/refuge locations, capacity claims, legal advice, protection-order-as-safety wording, case/client details, images, family stories, testimony, event details, memorial-map details, legal/medical guidance, or memorial submissions are released.

Rule 123 — Current-surface freshness gate. `META/Current-Surface-Freshness-Audit-current.*` must have zero high failures before release. Current identity/proof surfaces must match `manifest.json` revision/export and must not pass by carrying stale handoff, descriptor, front-door, or QA state.

Rule 124 — Closed preservation-transfer readiness. `META/Preservation-Transfer-Readiness-current.*` may describe fixity, transfer metadata, PREMIS-lite/PROV-style evidence surfaces, and an external BagIt-style transfer helper, but it must not convert the datacube into public release permission, a source URL catalog, referral routing, contact publication, or service-capacity guidance.

Rule 125 — Controlled-code overlay coverage. Candidate status/capacity, permission-state authority, public tier, source harm-proximity, and claim evidence-status codes must have a row-level companion overlay in `META/Normalized-Code-Overlay-current.*`. The overlay is governance-support metadata only: it must not alter core ledger headers, promote candidates, add public sources, create referral routes, or turn closed evidence into public release permission. Gate 079 fails the release if the overlay or its audit is stale, missing required code fields, or carries high failures.
Rule 126 — Release-change review and signature-proof freshness. Signature readiness/status are current-surface proof surfaces, and release deltas must be triaged for reviewer burden and payload risk before a gate-pass export is published. Gate 080 fails the release if changed stable files are unclassified, core payload movement appears in this refactor pass, or signature proof documents advertise an older current key/revision.

Rule 127 — Ledger relationship integrity gate. `META/Ledger-Relationship-Audit-current.*` must have zero high failures; current qclaim/release pointers, source/claim/candidate joins, discovery/source references, refresh paths, and normalized-code overlay targets cannot drift silently.


Rule 128 — Evidence-debt work packets. `META/Evidence-Debt-Work-Packet-current.*` must group every critical/high execution-queue row exactly once into reviewer-sized packets with a first manual step, acceptance criteria, completion evidence slot, reviewer role, and explicit no-public-expansion boundary. Gate 084 fails the release if critical packets are buried, execution rows are lost or duplicated, packet criteria are missing, or URLs/contact/phone-like details leak into the packet surface.


Rule 129 — Critical-path work order traceability. `META/Evidence-Debt-Critical-Path-Work-Order-current.*` and `META/Evidence-Debt-Work-Packet-Trace-current.*` must convert every critical/high work-packet execution row into an ordered, traceable, manual-only work order. Gate 085 fails the release if packets are lost or duplicated, execution rows do not trace to a work order, critical work is not first, completion targets leave the future manual ledger, or URL/contact/phone-like operational details leak into the work-order surface.
