# Review Role and Handoff Boundaries — current rev0063

This file separates review roles from release authority. Review authority does not transfer reuse rights.

## Standing rule

A reviewer may judge whether the package is internally coherent, but review does not create family consent, community authorization, public URL permission, service capacity, referral permission, or public reuse permission.

## Role boundaries

- Operator/editor: operator may edit the package but may not override family, community, or consent limits. Operator changes must remain inside the release gates.
- Reviewer: reviewer may evaluate release readiness but may not convert the cube into a referral directory.
- Public reader: public reader is not a referral recipient and the public index is not a service pathway.
- Family or community review authority: family or community review authority is not implied by public-source availability. Explicit consent or authorized review must be recorded before public story, image, case detail, contact path, or URL release expands.
- External reuser: external reusers must not treat this archive as a case list, event map, support path, public link directory, capacity dashboard, or implementation-as-safety scorecard.

## Release boundary

The package may be reviewed as a working handoff archive only after `META/Review-Role-Boundary-Audit-current.*`, `META/Manifest-Semantic-Coherence-Audit-current.*`, and `META/JSON-Key-Uniqueness-Audit-current.*` pass. Those passes do not loosen any public block.

The public layer remains closed: no public URLs, case details, testimony, images, routes, live referrals, support paths, current-capacity claims, or scorecard-as-safety claims are released.
