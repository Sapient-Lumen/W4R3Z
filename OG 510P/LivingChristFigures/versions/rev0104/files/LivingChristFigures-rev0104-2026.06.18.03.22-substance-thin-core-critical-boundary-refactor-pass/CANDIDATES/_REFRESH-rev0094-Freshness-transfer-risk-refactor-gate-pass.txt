# rev0094 freshness, transfer-readiness, and risk-refactor gate pass

This package-level refresh note records a risk-first pass focused on stale-current-surface prevention, transfer-readiness, and tooling refactor rather than candidate/source expansion.

What changed:

- A new `META/Current-Surface-Freshness-Audit-current.*` report makes stale current identity/proof surfaces release-blocking.
- A new `META/Preservation-Transfer-Readiness-current.*` report checks closed fixity, RO-Crate/PREMIS-lite/PROV-style transfer posture, external BagIt helper presence, and public-layer containment.
- A new `ro-crate-metadata.json` records transfer metadata for the package without converting public boundaries into public-release permission.
- `tools/make_bagit_transfer_copy.py` can create an external BagIt-style transfer copy outside the linked ZIP root, avoiding an in-place datacube root reshuffle.
- Release gates, QA, generated-artifact provenance, and field-schema coverage now include the new reports.

This note does not add candidates, claims, sources, public URLs, referrals, contacts, routes, service capacity, case details, images, stories, testimony, legal/medical guidance, or public-release permission.

Late closure correction: rev0094 also removes a self-referential QA-report dependency from the current-surface freshness audit. Final QA remains required release evidence, but the freshness gate no longer reads the final QA transcript as one of its own inputs; this prevents stale/failing QA output from creating a circular proof loop during report regeneration.
