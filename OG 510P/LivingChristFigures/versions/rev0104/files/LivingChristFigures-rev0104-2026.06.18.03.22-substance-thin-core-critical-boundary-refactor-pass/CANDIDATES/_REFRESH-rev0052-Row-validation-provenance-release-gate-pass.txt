# rev0052 — row validation / provenance / release-gate pass

CENTRAL SENTENCE: A report is not current unless its rows, revision surface, and generator inputs can prove it.

## Why this pass exists

rev0051 made the public surface safer, but the package still had a deeper handoff risk: generated reports and front-door files could pass ordinary QA while carrying stale current-revision text, stale package-revision metadata, or unvalidated row values.

rev0052 treats that as a release defect. It adds row-level validation, generated-artifact provenance, a front-door revision-surface audit, and a release-gate attestation. The goal is not more public content. The goal is making the non-release posture mechanically harder to bypass.

## Changes made

- Added `tools/row_validate.py` plus `SCHEMA/Row-Validation-Contract-current.json` and `SCHEMA/Row-Validation-Report-current.*`.
- Added `tools/generated_artifact_provenance.py` and `META/Generated-Artifact-Provenance-current.*`.
- Added `tools/revision_surface_audit.py` and `META/Revision-Surface-Audit-current.*`.
- Added `tools/release_gate_attestation.py` and `META/Release-Gate-Attestation-current.*`.
- Added field schemas for the new reports.
- Updated QA and schema validation to enforce the new gates.
- Fixed stale front-door revision strings and stale `package_revision` metadata.
- Completed rule-coverage text for rules 51 and 52 and added rules 53-56.

## Public release effect

No new public prose, public URL, live referral, case detail, testimony, image, route, support path, current-capacity claim, or implementation-as-safety claim is released. This is an integrity and handoff-gating pass only.
