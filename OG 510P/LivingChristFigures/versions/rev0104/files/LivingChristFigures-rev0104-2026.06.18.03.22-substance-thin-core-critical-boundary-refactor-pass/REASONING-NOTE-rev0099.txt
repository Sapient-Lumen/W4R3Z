Reasoning note rev0099

Priority target: accidental public over-export. The package had strong linting for files under PUBLIC/, but its legacy public export manifest still used a broad `included_files` list that mixed actual PUBLIC files with internal reviewer-support evidence. That ambiguity is a practical risk: a human or tool could treat a review-support envelope as a public payload list.

This pass therefore adds a separate PUBLIC-only bundle manifest and a release-blocking audit proving that public payload files are PUBLIC/ allowlisted files only. The change is substantive but narrow: it refactors the boundary and does not add candidates, sources, claims, URLs, contacts, routes, referrals, images, testimony, case detail, legal/medical guidance, capacity claims, or public-release permission.
