# TimeSync rev0089 audit — 2026.06.09

## Executive summary

The archive is conceptually strong: the six-field TimeState model stays small, the rev0088 mixed-layer scope-composition guard addresses a real cross-layer interpretation risk, and the semantic vector suite is broad. The most important missing semantic work is temporal coherence across guard inputs. The most important immediate repository failure was lower-level: several schema documents were not valid Draft 2020-12 schemas, one example fixture had fallen out of the semantic-vector corpus, and the validator could pass or fail for environmental reasons.

rev0089 fixes the mechanical issues that made future semantic work less trustworthy. It does not close the temporal-coherence frontier.

## Severe or high-leverage findings

1. Four schema documents contained empty `allOf: []` arrays. JSON Schema Draft 2020-12 requires `allOf` to be a non-empty array. These arrays were no-op authoring residue, but they made the schema documents invalid as schemas. rev0089 removes them and adds schema meta-validation so the problem cannot recur silently.

2. `examples/semantic-version-negotiation-rev0086.json` was a current example file but was absent from `tests/semantic-test-vectors.yaml`. Under the current schema it fails because `negotiation_version` must be `rev0087`. rev0089 keeps the file as a historical legacy fixture and adds an explicit `fail_schema` vector.

3. `tools/validate_archive.py` used `jsonschema.Draft202012Validator(schema)` without calling `check_schema(schema)`. That validates instances against a schema object, but it does not prove the schema document itself is valid. rev0089 adds `check_schema_documents()`.

4. The validator previously returned no schema errors if `jsonschema` could not be imported. That made an underprovisioned environment look cleaner than it was. rev0089 fails closed.

5. The `fail_schema` expected-error check accepted any schema error whenever an `expected_error_contains` value was present, because every schema error contains the word `schema`. rev0089 requires the stated substring to actually appear and updates the three stale expectations this exposed.

6. One schema `$id` used `example.org` while the rest used `example.invalid`. This would not break the local file-based validator, but it is a portability hazard for resolvers, generated clients, and cache keys. rev0089 normalizes it.

7. Running the Python validator can create `__pycache__` files. The manifest check then saw generated bytecode as unlisted content. rev0089 excludes `__pycache__` and `.pyc` files from manifest validation.

## What is missing next

The next semantic revision should define timestamp roles and ordering constraints for mixed-scope guard composition:

- `guard_evaluated_at`
- `artifact_created_at`
- `lifecycle_checked_at`
- `revocation_checked_at`
- `notification_observed_at`
- `discovery_negotiated_at`
- `reference_observed_at`
- `profile_digest_observed_at`
- `decision_matrix_generated_at`

The key rule should be that a guard cannot claim a current composition result if the component surfaces were evaluated at mutually incompatible times or outside their validity horizons. Some privacy-preserving surfaces may expose bounded freshness classes instead of exact timestamps, but the validator still needs executable stale-composition negatives.

## Waste and maintainability debt

- `tools/validate_archive.py` is a large monolith. Split it by concern once temporal-coherence helpers are introduced.
- `CHANGELOG.md` contains duplicated historical headings and a duplicate rev0084 section. Normalize it into one current timeline plus archived legacy fragments.
- The example corpus is intentionally explicit, but many negative examples duplicate large JSON objects. Add a fixture-rendering tool later while keeping rendered fixtures checked into the archive.
- Digest canonicalization should be revisited. Where TimeSync claims RFC8785/JCS semantics, the implementation should use a real JCS canonicalizer or constrain input enough that the current serializer is provably equivalent.
- Add dependency metadata such as `requirements.txt` or `pyproject.toml` for `jsonschema` and `PyYAML`.

## Suggested rev0090 shape

Add a temporal-coherence helper, a `scope-composition-temporal-coherence` schema fragment, and negative vectors for stale lifecycle, stale revocation, stale discovery negotiation, and guard evaluation after source posture expiry. Keep exact incident or notification timestamps optional by allowing freshness classes, but require enough ordering evidence to block unsafe composition.
