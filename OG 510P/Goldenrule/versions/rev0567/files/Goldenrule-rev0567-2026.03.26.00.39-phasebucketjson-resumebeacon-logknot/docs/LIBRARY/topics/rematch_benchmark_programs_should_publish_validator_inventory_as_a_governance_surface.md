# Rematch benchmark programs should publish validator inventory as a governance surface

Once a benchmark publication depends on a known validator set, that validator inventory is part of the governance surface rather than throwaway operator scratch.
A future inheritor should be able to see, in one compact place, which checks define readiness and which ones remain open.

The compact rule is to publish validator inventory as explicit governance metadata instead of scattering readiness across logs and ad hoc summaries.
