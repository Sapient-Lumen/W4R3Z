# Cooperation benchmark programs should publish ordered focus-open paths for compact-card reentry

When a compact-card stack already publishes a deterministic focus lineage and one primary focus-open path, one more small inheritor aid is worth keeping explicit: **publish the tiny ordered, deduplicated family of retained file paths that should usually be opened next for that focus lineage**.

Operationally:

1. derive the path family from already-retained focus-lineage artifacts rather than inventing a second browsing surface;
2. keep the sequence tiny and ordered: start with the primary open path, then list any rendered markdown / citation / operational card companions that are locally available;
3. deduplicate the family so one card rendered in two roles does not widen the archive with repeated entries;
4. thread the same ordered path family through the main reentry surfaces so inheritors do not have to reconstruct “what do I open after the first file?” by memory.

This keeps first-pass local inspection compact and reproducible without widening the cards, receipts, or handoff basis.
