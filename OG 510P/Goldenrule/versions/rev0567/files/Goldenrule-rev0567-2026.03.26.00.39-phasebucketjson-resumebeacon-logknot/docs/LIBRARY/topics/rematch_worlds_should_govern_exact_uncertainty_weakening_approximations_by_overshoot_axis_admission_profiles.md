# Rematch worlds should govern exact-uncertainty weakening approximations by overshoot-axis admission profiles

## Claim

The current weakening staircase can be governed by a tiny admission-policy menu over overshoot axes. No individual primitive demand needs both hitchhike permissions at once, so dual-axis permission is a portfolio-level convenience rather than a single-request necessity.

## Why it matters

- The exact-only profile covers just `6` of the current `15` primitive-demand coordinates.
- Allowing **precision-only** hitchhikes expands coverage to `10`, capturing the deep suffix requests that overbuy extra precision relief.
- Allowing **suffix-only** hitchhikes expands coverage to `11`, capturing the early or extra precision requests that overbuy relaxed-suffix release.
- Allowing either single-axis hitchhike covers all `15`, but no single current demand actually requires both permissions simultaneously.

## Immediate operator guidance

- Use `exact_only` when any hitchhike tax is unacceptable.
- Use `precision_hitchhike_only` when deeper relaxed-suffix coverage is worth buying with extra precision relief, but extra suffix release is not.
- Use `suffix_hitchhike_only` when precision-origin relaxation may arrive early only if extra suffix release is acceptable.
- Reserve dual-axis permission for portfolio-wide convenience across both hole families; if a future single demand requires it, treat that as a redesign alarm.
