# Cooperation benchmark programs should publish a deterministic focus lineage for compact-card reentry

Once the archive already has a fused compact-card control plane, inheritors still need one answer to the first practical question after opening the stack: **which lineage should I inspect first?**

A compact benchmark program should therefore publish one tiny deterministic focus-lineage digest that:

1. derives from the already-retained control-plane fields rather than inventing a second lineage-priority semantics;
2. uses one stable selector order, so the answer stays auditable across sessions;
3. names the chosen lineage together with its current operational/citation heads;
4. adds one short summary sentence explaining why that lineage is first under the selector.

This keeps first-pass inheritance legible without widening cards, receipts, or handoff packs. It also matches the provenance lesson that end-user consumption benefits from abstraction, summary, and multiple levels of description instead of raw lower-level traces alone (`docs/RESEARCH_SOURCES.md`, `RS-GR-131`).
