# Cooperation benchmark programs should publish role-annotated focus-open targets for compact-card reentry

When a compact-card stack already publishes a primary focus-open path and a tiny ordered `focus_open_paths` family, one more compact inheritor aid is worth keeping explicit: **publish the same retained paths with small role codes explaining why each path belongs in the family**.

Operationally:

1. derive the targets from already-retained focus-lineage artifacts rather than inventing a second browsing surface;
2. keep the target family tiny, ordered, and path-stable, matching the published `focus_open_paths` sequence exactly;
3. attach only a small deduplicated `role_codes` set per path, so the inheritor can tell whether a file is the primary open target, a rendered markdown companion, or a machine-readable citation / operational card;
4. thread the same role-annotated target family through the top-level reentry surfaces so future sessions do not have to infer file purpose from suffixes or builder code.

This keeps first-pass inspection self-explanatory without widening the compact cards, receipts, or handoff basis.
