# Cooperation benchmark programs should ship a scope surface for compact-card subsystem boundaries

Once a compact-card stack grows past one schema and one receipt, inheritors stop needing only the current citation head — they also need one exact answer to **which files constitute the compact-card subsystem at all**.

A compact benchmark program should therefore ship one tiny generated scope surface that:

- lists the exact compact-card examples, schemas, tools, builders, validators, generated reports, generated docs, and doctrine files that belong to the subsystem,
- distinguishes **source** members from **generated** members,
- keeps generated peers path-addressable without turning the scope manifest into a recursive hash knot,
- and gives the subsystem one stable boundary digest so future sessions can tell when the compact-card control plane itself has widened or narrowed.

This keeps compact-card maintenance from turning into repo-memory folklore: inheritors can see the subsystem boundary directly instead of inferring it from filenames, prior agent prose, or partial handoff packs.
