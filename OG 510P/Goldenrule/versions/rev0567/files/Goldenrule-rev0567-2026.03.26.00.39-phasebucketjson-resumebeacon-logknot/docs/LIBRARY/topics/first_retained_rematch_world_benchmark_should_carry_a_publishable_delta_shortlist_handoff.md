# The first retained rematch-world benchmark should carry a publishable delta shortlist handoff

The archive already has proxy-era results for delta frontiers, budget frontiers, hazard bands, persistence ladders, and publishability filters. But without one compact **benchmark-facing handoff**, a future inheritor still has to reopen several reports just to answer the first practical implementor question: **which delta anchors are actually benchmark-worthy enough to try first?**

A retained benchmark seed should therefore carry one tiny copied handoff extracted from the strict publishability profile, not the whole proxy report family.

For the current proxy, the strict shortlist is the `family4_width0p0010_hazard1000_sub0p01` profile:

- it requires coverage across at least four declared budget caps,
- it requires shared-core width at least `0.0010`,
- it excludes overlap with the existing `>1000` extra-seed hazard bands,
- and it keeps only sub-`0.01` anchors.

That leaves only two first-line benchmark constants:

- `TTTMMMMMU` anchored at `0.00602` over `0.00538..0.00666`, and
- `TTTMMMMUU` anchored at `0.00744` over `0.00667..0.00822`.

Those rows are much smaller and more actionable than the wider ladder tables, and they make the inheritor's next move obvious without pretending that proxy results are native world evidence.

So the retained benchmark should keep exactly one frozen shortlist handoff with:

1. the source report digest,
2. the strict guardrail profile,
3. the declared budget family,
4. the two shortlist rows,
5. and an explicit upgrade note saying that native endogenous rematch runs should replace this copied proxy-era shortlist once real SESOI-band outputs exist.
