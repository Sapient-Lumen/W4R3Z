# Cooperation benchmark programs should publish a typed selected command ladder for compact-card next-action surfaces

When compact-card next-action surfaces expose more than one command, inheritors should not have to reopen builder code to learn what each rung touches.

Compact-card next-action surfaces should therefore publish one ordered selected command ladder that, for each rung, carries:

1. the exact command string;
2. the machine target, intent summary, outcome summary, and effect code for that rung; and
3. the retained document path/object to open immediately after that rung completes, plus small local audit witnesses.

This keeps escalation legible as a bounded, citation-ready object instead of a flat list of shell strings.
