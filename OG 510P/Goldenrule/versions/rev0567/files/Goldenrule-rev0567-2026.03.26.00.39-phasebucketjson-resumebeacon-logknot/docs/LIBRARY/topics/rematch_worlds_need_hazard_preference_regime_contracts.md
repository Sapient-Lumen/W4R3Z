# Rematch Worlds Need Hazard Preference Regime Contracts

Once a rematch archive has reduced the live choice to two anchors and exposed an explicit preference inequality, it should not leave the hazard term as a loose “sensitivity” footnote.

If the hazard budget is discrete and the binding hazard panels can change with added seeds, then the hazard contribution itself lives in regimes. Those regimes should be published directly.

For the current family `10/20/50/100` rematch proxy inside the certified policy box, the residual hazard term is not one stable coefficient.

It breaks into three exact cap regimes:
- caps `10..14`: hazard clearance still favors `TTTMMMMUU`,
- caps `15..19`: hazard clearance favors `TTTMMMMMU` even before any binding-panel switch,
- caps `20+`: hazard clearance still favors `TTTMMMMMU`, but now because `TTTMMMMMU` binds against a different and much closer hazard panel.

That matters because it changes the handoff language.

The inheritor no longer has to say “hazard matters a little.” They can say exactly this:
- the full shortlist first appears at cap `10`,
- hazard helps the stability anchor only for `10..14`,
- it flips against the stability anchor at `15`,
- and from `20` onward it remains only weakly material-favoring, approaching a tiny asymptotic edge rather than exploding.

That is the contract worth archiving: not a large table of sampled caps, but the exact discrete regime boundaries that explain when the hazard term changes role.
