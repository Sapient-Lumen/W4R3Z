# First Retained Rematch-world Benchmark Should Carry a Matching-state Interpretation Handoff

The archive already had the raw ingredients for `SQ-013`, but the retained benchmark spine still made the inheritor reopen both the proxy matching-friction and occupancy-accounting reports to answer one practical question:

> How should the first retained rematch-world benchmark talk about delay/search dead-time without overclaiming matching-market efficiency?

The new compact handoff in `examples/snapshots/rematch_world_benchmark_matching_state_interpretation_handoff.json` collapses that seam into one frozen packet.

## What it keeps

- the proxy-wide monotone delay-tax headline across all `15` tested policy/extortion cells,
- the ranked mean delay-tax order from largest (`DCECC`) to smallest (`courteous_firm`),
- the occupancy decomposition headline showing that mean delay-loss is mostly matched-share loss (`0.985842`) while max in-match drift stays tiny (`0.005788`),
- and the minimal engine-facing guidance that a native matching-state section must expose both search-state fields and matched-state fields.

## Why this is worth retaining

This handoff directly encodes the standing publication-contract boundary for `SQ-013`:

- exogenous-pool rematch-delay sweeps are delay-tax diagnostics,
- not full matching-efficiency claims,
- and comparable welfare claims need matched-vs-searching state to be explicit.

That is exactly the sort of interpretation rule future sessions would otherwise keep re-deriving from larger proxy-era artifacts.

## Boundary

This is still a copied proxy-era interpretation packet.
It should stay frozen and citation-first until endogenous rematch worlds can emit native matching-state sections directly from real runs.
