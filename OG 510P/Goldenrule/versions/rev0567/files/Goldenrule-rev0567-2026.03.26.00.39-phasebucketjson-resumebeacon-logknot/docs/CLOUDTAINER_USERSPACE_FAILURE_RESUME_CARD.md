## Why this is worth preserving

- This card closes the operational gap between the offline proof ladder and the first real later-machine failure: instead of reopening the whole comeback stack, the inheritor now gets one small phase-scoped resume map.
- The resume commands stay narrow on purpose: network trouble resumes from warm-cache, compile/codegen trouble resumes from offline compile, and semantic test failures stay pinned to the exact witness or the wider probe_run smoke phase.
- The emitted JSON capture variants are optional but useful because Cargo can emit line-delimited JSON messages with compiler diagnostics, artifacts, and build-script results before any later plain test-binary output begins.

## Resume details

### `bootstrap_command_missing`

- phase that failed: `bootstrap`
- resume from: `env`
- rerun command: `curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- --default-toolchain none -y`
- interpretation: The later machine does not yet have the repo-local rustup/Cargo toolchain on PATH.
- next step: Re-export the repo-local env roots, bootstrap rustup again, then continue to toolchain install before retrying Cargo.
- capture hint: No JSON rerun needed yet; this is still a bootstrap/path failure before Cargo itself can emit structured diagnostics.
- marker set: `rustup: command not found`, `cargo: command not found`, `no such file or directory (os error 2)`, `command not found`

### `toolchain_unresolved`

- phase that failed: `toolchain`
- resume from: `toolchain`
- rerun command: `rustup toolchain install stable --profile minimal --component rustfmt`
- interpretation: rustup exists, but the repo-pinned toolchain/components are not fully installed or selected yet.
- next step: Resume from the toolchain-install phase rather than from fetch or patch apply.
- capture hint: Run `rustup show` immediately after reinstalling to confirm the override resolved before spending another fetch attempt.
- marker set: `toolchain`, `is not installed`, `no default toolchain configured`, `override toolchain`, `component`, `rustfmt`

### `warm_cache_transport_or_registry`

- phase that failed: `warm_cache`
- resume from: `warm_cache`
- rerun command: `cargo fetch --locked`
- interpretation: The brief egress window failed during dependency staging.
- next step: Spend the next egress window on `cargo fetch --locked` again before trusting any offline compile or test output.
- capture hint: If the failure text is noisy, rerun the exact warm-cache command with `-vv` and keep the log with the later-machine note.
- marker set: `spurious network error`, `failed to download`, `could not resolve host`, `timed out`, `failed to get`, `updating crates.io index`

### `offline_cache_incomplete_or_lock_drift`

- phase that failed: `offline_compile`
- resume from: `warm_cache`
- rerun command: `cargo fetch --locked`
- interpretation: The offline compile/test step is still asking for network access or wants to rewrite the lockfile.
- next step: Treat this as a return to warm-cache or lockfile reconciliation, not as a semantic test failure.
- capture hint: Prefer the structured rerun `cargo test --locked --offline --no-run -p gr_engine --test probe_run --message-format=json-render-diagnostics` if you want Cargo/rustc diagnostics separated from later test output.
- marker set: `attempting to make an http request, but --offline was specified`, `failed to load source for dependency`, `lock file cargo.lock needs to be updated but --locked was passed`, `unable to update registry`, `but --offline was specified`

### `patch_apply_mismatch`

- phase that failed: `apply_quick_foothold`
- resume from: `apply_quick_foothold`
- rerun command: `git apply artifacts/patches/rust_external_test_shards/01_fsm_grim_trigger_probe.patch`
- interpretation: The quick-foothold patch no longer applies cleanly to the checked-out tree.
- next step: Refresh the comeback execution card on that later machine, inspect branch drift, and re-evaluate whether the quick foothold is still the right shard.
- capture hint: Keep the raw `git apply` stderr; this failure is branch-state drift, not Cargo drift.
- marker set: `patch failed`, `does not apply`, `corrupt patch`, `error: patch fragment without header`, `rejected hunk`

- capture hint: For machine-readable triage, rerun `cargo test --locked --offline --no-run -p gr_engine --test probe_run --message-format=json-render-diagnostics` and feed that log to `scripts/tools/classify_cloudtainer_userspace_failure.py --command-key offline_compile`.
