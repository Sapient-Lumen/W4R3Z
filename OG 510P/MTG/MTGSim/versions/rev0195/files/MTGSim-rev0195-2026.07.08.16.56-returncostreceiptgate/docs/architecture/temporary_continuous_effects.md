# Temporary continuous effects

rev0029 adds the first temporary continuous-effect seam generated by resolving spells or abilities. It is deliberately narrow and metadata-only: fictional cards can carry an `EffectKind::CreateContinuousEffect` payload plus a `StaticEffectDefinition`-shaped payload, and resolution creates a `ContinuousEffectDefinition` stored on `GameState::continuous_effects`.

## Scope

The implemented duration is `ContinuousEffectDuration::UntilCleanup`, which is MTGSim's current stand-in for “until end of turn” / “this turn” behavior. Cleanup calls `expire_continuous_effects(...)` before damage and regeneration cleanup finish, so derived characteristics return to their pre-effect values at the same observed duration boundary as damage cleanup.

The effect payload can currently express the same narrow derived-characteristic operations as the static-effect scaffold:

- P/T modifiers;
- ability grants and removals;
- add/remove type payloads;
- color set/add/remove payloads;
- base P/T setting.

These feed `object_type_mask(...)`, `object_color_mask(...)`, `object_has_ability(...)`, `effective_power(...)`, and `effective_toughness(...)` so combat, actions, SBAs, protection/source checks, and scenario expectations observe one derived view rather than scattered mutations.

## Locked target snapshots

Resolved spell/ability continuous effects that modify object characteristics lock to their target set when the effect begins. The current scaffold stores a locked target as object id plus `zone_change_index`. If that object leaves and returns, the old locked target record no longer matches. This is only a single-target fixture seam, but it catches a class of bugs where a later object incarnation accidentally inherits an old temporary effect.

## Timestamp seam

Temporary continuous effects receive `next_continuous_effect_timestamp` values. rev0029 applies temporary ability grants/removals in timestamp order after the older static scaffold semantics. This is not a full layer engine, but it gives us a stable testable seam for later timestamp/dependency refactors.

## Tests

Covered by C++ cases for temporary pump, temporary flying, temporary ability grant/removal timestamp order, temporary land animation, target-lock break on zone change, and malformed-record validation. Scenario fixtures cover temporary pump cleanup, temporary flying cleanup, and temporary land animation cleanup.

## Limitations

This is not a complete continuous-effect engine. Missing pieces include full duration grammar, “for as long as” duration handling, multiple-object snapshots, timestamp ordering across all static/generated effects, dependency ordering, characteristic-defining abilities, copy/text layers, full type/subtype/supertype changes, switch P/T effects, continuous effects from unusual zones, rule-changing effects, player-affecting effects, cost-changing effects, and Oracle-text parsing.

Note: docs use the phrase until-cleanup to describe the current `UntilCleanup` duration boundary.

## Interaction with rev0030 copy effects

Temporary continuous effects now share the same derived-characteristic projection path as static effects and copied-definition snapshots. In this revision, copy selection happens first, then type/color/ability/base-P/T/modifier projections are queried through the same helpers. This is a foothold for future timestamp/dependency work, not a full layer engine.

## rev0031 shared timestamp domain

Temporary continuous effects now receive timestamps from `GameState::next_layer_timestamp`, the same monotonic domain used for battlefield static sources. The derived-characteristic helpers collect both static and generated applications and sort them before applying narrow layer payloads. This upgrades the rev0029 temporary-effect seam from "temporary after static" to a testable timestamp-order scaffold.
