# Transition trace handoff seal — rev0130

rev0130 audits the seam between the immediate `TransitionResult` API and exported replay traces. A committed transition already proved the proposal state, adopted state, causal `ActionReceiptRecord`, selected `LegalAction`, choice proofs, preflight evidence, and boundary hash; the missing link was a compact proof that this exact transition result projects to the exact `ActionTraceEntry` that replay consumers will later verify.

The new public surface is `kTransitionTraceHandoffSealSchemaVersion`, `TransitionResult::transition_trace_handoff_schema_version`, `TransitionResult::transition_trace_handoff_hash`, `has_transition_trace_handoff_seal()`, and `committed_with_trace_handoff_seal()`. `commit_action_transition(...)` computes `transition_result_trace_handoff_hash(...)` only after the staged receipt is checked and before `seal_transition_result_boundary(...)`, so the boundary seal binds the handoff hash instead of leaving it as a side-channel.

The replay projection is explicit. `action_trace_entry_from_transition_result(...)` creates the same `ActionTraceEntry` shape as receipt export, `action_trace_entry_hash(...)` gives both receipt-exported and transition-projected rows a stable `MTGSim.ActionTraceEntry.v1` digest, and `transition_result_matches_action_trace_entry(...)` rejects action, choice, page-proof, APNAP queue-proof, schema, state-hash, or applied-status drift before replay callers trust the row.

The boundary diagnostics now include `expected_transition_trace_handoff_hash` and `observed_transition_trace_handoff_hash`, with stable failure kinds `TraceHandoffSealMissing` and `TraceHandoffSealMismatch`. That lets replay, fuzz, search, and agent callers distinguish a stale trace projection from checkpoint drift, preflight drift, boundary hash drift, or causal receipt drift.

The small refactor behind the seal routes `export_action_trace(...)` through `action_trace_entry_from_receipt_record(...)`, so the receipt-exported trace row and the transition-projected trace row share one field mapping instead of two hand-maintained copies. The regression `test_commit_action_transition_projects_exact_action_trace_entry` proves that a committed pass transition exports one receipt-backed row, projects the same row from `TransitionResult`, hashes both rows identically, replays the projected row from the original checkpoint, and rejects APNAP queue-location tampering.
