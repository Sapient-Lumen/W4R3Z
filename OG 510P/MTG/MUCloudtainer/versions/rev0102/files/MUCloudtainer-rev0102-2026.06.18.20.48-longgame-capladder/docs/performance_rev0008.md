# rev0008 simulator performance notes

The user flagged a likely future bottleneck: once construction search, self-play, payoff tables, PSRO, or neural training begin, simulator throughput will matter.

rev0008 does not rewrite the engine. It adds measurement and two low-risk speed seams.

## New code

```text
src/muc5/perf.py
scripts/profile_simulator_rev0008.py
```

## Refactor: trusted legal-action application

Before rev0008, the hot loop often did this:

```text
agent asks legal_actions(state)
agent chooses one action
apply_action asks legal_actions(state) again to validate
```

rev0008 keeps safe validation as the default for external callers:

```python
apply_action(state, action, rng, validate=True)
```

but hot loops can now call:

```python
apply_action(state, action, rng, validate=False)
```

Only use `validate=False` when the action came directly from `legal_actions(state)` for that exact state.

`play_agent_game` now exposes:

```python
validate_actions: bool = False
record_log: bool = True
```

The fast arena path uses trusted legal actions. Tests still exercise both safe and trusted paths.

## Refactor: optional log suppression

`GameState` now has:

```python
record_log: bool = True
```

`start_game(..., record_log=False)` avoids most event-log string construction in high-throughput simulations. External gametable and debugging paths can keep logs on.

One subtle fix was needed: `f"...{action.compact()}"` is evaluated before entering a helper function, so the action log now checks `state.record_log` before constructing the compact action string.

## cProfile top cumulative hotspots

The current profile says the big costs are still:

```text
HeuristicAgent.choose_action
GameState.observation
legal_actions
PlayerState.public_dict
HeuristicAgent.score_action
```

That means the next optimizations should not be C++ or Numba yet. They should be structural:

```text
1. Avoid rebuilding full observation dictionaries for simple heuristic scoring.
2. Let built-in agents consume precomputed legal action lists.
3. Add an arena runner that reuses agent instances and avoids extra factory calls.
4. Add batch payoff generation with process-level parallelism only after the single-process hot loop is clean.
5. Keep logs off for training/payoff runs and on for gametable/debug runs.
```

## What not to do yet

Do not prematurely rewrite the engine in Cython/Numba/Rust. The engine is still changing, and cProfile shows ordinary Python object/dictionary work as the current cost. The correct near-term target is less allocation and fewer repeated conversions.
