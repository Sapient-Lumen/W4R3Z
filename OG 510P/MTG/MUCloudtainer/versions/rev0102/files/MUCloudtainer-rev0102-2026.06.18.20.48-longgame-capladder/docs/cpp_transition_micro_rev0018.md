# rev0018 C++ transition expansion: stack and choice coverage

rev0018 expands the staged C++ transition microkernel. Python is still the semantic reference; C++ earns authority only through differential tests.

The important change is that transition records now carry **ordered library state** and **pending-choice state**. Earlier transition signatures only compared public counts, which was enough for play/cast/block microcases but too weak for these transitions:

```text
Overlord resolves -> draw two -> discard one
Jace 0 resolves -> draw three -> choose two putbacks
Jace +2 choice -> leave or bottom exact top card
cleanup discard -> possibly advance to next turn and draw
response PASS -> maybe resolve top of stack
```

The C++ bridge can now compare these exact post-state signatures:

```text
ordered libraries, bottom-to-top
pending choice player/kind/resume payload fields
stack ids/controllers/cards/modes/targets
combat pending state
hand/graveyard/exile/library counts
Jace loyalty/use flags
Overlord creature/impending buckets
```

## Why this matters

The fastest dangerous mistake would be to port the whole engine and then debug strategy results against two subtly different games. rev0018 keeps the safer ladder:

```text
Python reference state
  -> flat exact transition record
  -> C++ one-action transition
  -> exact post-state signature comparison
  -> only then consider batching/rollout acceleration
```
