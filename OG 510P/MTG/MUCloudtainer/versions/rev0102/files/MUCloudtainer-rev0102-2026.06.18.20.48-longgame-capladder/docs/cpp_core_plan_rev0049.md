# C++ core plan, rev0049

The doctrine remains:

```text
Python = semantic reference, hidden-information boundary, replay/gates, analytics
C++    = stable hot kernels, segment/batch acceleration, future rollout core after parity proof
```

rev0049 does not add a new C++ kernel.  It routes the new yield-collector branch
traffic and the terminal-clean payoff panel through the existing C++ transition
shadow path.  That is deliberate: before C++ becomes authoritative for larger
chunks of tournament execution, every new policy/collector surface should keep
passing parity checks.

Near-term C++ priorities remain:

```text
1. keep transition shadow checks attached to branch-heavy data collection
2. use no-choice segment batching when branch collection is demonstrably speed-limited
3. avoid full C++ rollout authority until Python pre/post fingerprints remain stable
```
