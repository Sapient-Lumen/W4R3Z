# Product shape and access posture

This rev0002 surface sketches possible product forms without selecting a deployment model.

## Core product identity

PoliceMisconduct should be a **commons substrate with careful views**, not a single undifferentiated public database.

The archive layer may preserve more detail than any public interface should expose. Public display is a separate decision from lawful acquisition, source custody, and internal normalization.

## Likely views

### Source inventory view

A public map of record carriers by jurisdiction and department:

- court dockets and filing availability;
- settlement ledgers;
- POST/decertification sources;
- policy archives;
- union contracts;
- consent decrees and monitor reports;
- FOIA portals and known request routes;
- official dashboards and their limitations.

This is a high-value, low-person-risk first view.

### Department accountability view

A department page that foregrounds institutional context:

- jurisdiction and agency type;
- policy timeline;
- union-contract accountability provisions;
- settlement totals and denominators;
- consent-decree / monitor state;
- public complaint/discipline data availability;
- source gaps and disclosure barriers.

This lets community members and officials reason about the institution before the project turns into person lookup.

### Lawsuit and settlement view

A normalized view of cases and settlements that preserves procedural posture:

- allegations;
- claims;
- defendant classes;
- disposition;
- settlement amount and admission language;
- linked source documents;
- appeal/correction/rollback state.

Officer names can be delayed, minimized, or role-gated until identity and display rules mature.

### Officer mobility / wandering detector

The mature high-impact view. It should identify mobility patterns only under strict thresholds:

- strong identity evidence;
- employment timeline support;
- separation reason support;
- source-visible misconduct/adjudication state;
- appeal/reinstatement state;
- correction/right-of-reply route;
- no name-only linkage.

The purpose is to prevent disappearance across jurisdictional seams, not to create a harassment surface.

### Defense disclosure / Brady-Giglio research view

A specialized view for defense attorneys, journalists, researchers, and possibly court-supervised access contexts. It should preserve source and procedural language exactly enough to avoid overstating credibility findings.

### Family / incident record packet

A dignified record packet for deaths, serious injuries, and major incidents. This should be built with special privacy and narrative ownership constraints, especially when relatives, minors, survivors, or vulnerable witnesses are involved.

## Access model questions

- Which fields are always public?
- Which are public only in aggregate?
- Which are available only to vetted civic users?
- Which are retained for source integrity but not displayed?
- Which are never stored because the harm exceeds the accountability value?
- What does a correction request pause, annotate, or roll back?
- How does the archive prevent use against civilians while still enabling public accountability?

## First-access recommendation

Start with public source inventories and department-level pages. Delay broad officer lookup until the cube can prove its evidence state machine, unmerge workflow, right-of-reply route, privacy display classes, and legal review loop.
