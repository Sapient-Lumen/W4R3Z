# Earned capability ladder — rev0015

The ladder is not a schedule. It is a way to keep future ambition legible while preventing premature promotion.

The basic rule is: **value does not equal readiness**.

A public defender Brady/Giglio view is valuable. A wandering-officer detector is valuable. A settlement-per-officer cost ledger is valuable. A family incident packet is valuable. But each becomes safe only when the lower layers are strong enough.

The machine-readable ladder is `EARNED-CAPABILITY-LADDER.json`.

## How to use it

When proposing a future revision, name the capability rung it is trying to earn. Then name the evidence, privacy, due-process, freshness, and correction gates that remain closed.

A revision may work on a high rung speculatively, but it must mark that work as horizon/design/synthetic until lower gates pass.

## What this prevents

- treating a dream as a claim;
- treating a product mockup as release permission;
- treating a pilot as the whole project;
- treating a useful alert as safe because it is useful;
- treating no-person scaffolding as a permanent refusal to build the core entity graph.
