# Trajectory map

## Phase 0 — scaffold discipline

- reentry surfaces;
- source carrier taxonomy;
- claim state ladder;
- privacy/due-process rules;
- entity-resolution thresholds;
- schemas;
- synthetic fixtures;
- correction route.

## Phase 1 — pilot selection

Possible pilot shapes:

1. record-type-first: public settlement ledgers for a small set of cities;
2. record-type-first: state POST decertification lists;
3. jurisdiction-first: one city/county with settlements, lawsuits, policies, and discipline where public;
4. consent-decree-first: departments with federal monitor reports;
5. court-first: RECAP/PACER §1983 docket mapping for a bounded district.

## Phase 2 — acquisition protocols

Create acquisition and custody protocols for selected carrier types. Add source locks and extraction templates.

## Phase 3 — synthetic and then live fixtures

Test schemas on synthetic examples first. Admit live records only after privacy, source, correction, and rollback gates are operational.

## Phase 4 — entity linkage and aggregation

Only after field-level records are stable should officer/department aggregation begin.

## Phase 5 — public access model

Public access needs threat modeling, role-based display, correction workflow, and community consultation.

## Rev0002 trajectory refinement

Before selecting a pilot, build the distinction between source graph, claim graph, entity graph, civic views, and wandering-prevention layer. Early public value should come from source inventories and department-level pages; officer-level lookup remains late-stage until identity, privacy, correction, and rollback gates mature.
