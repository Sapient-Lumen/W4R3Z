# Incident-Response Review Runbook v1

Purpose: provide a local, successor-readable procedure for classifying incidents, near misses, harm allegations, warning failures, unauthorized deployment, and recovery debt involving archive material.

Boundary: this runbook is archive-local. It does not create public incident intake, legal process, clinical/safety review, institutional authority, external monitoring, or domain closure.

## Entry triggers

Use this runbook when any of the following occurs:

1. archive material guides or nearly guides live action beyond its deployment packet;
2. a user, derivative, teacher, public citer, or steward reports harm, near harm, reliance failure, or warning failure;
3. a generated or compressed output drops limits and is used operationally;
4. automation, validation, workflow, runbook, or register language is used to claim more authority than warranted;
5. rollback, withdrawal, deprecation, notice, or public correction is needed;
6. evidence must be preserved before editing.

## Stage order

### 1. Freeze

Preserve the implicated artifact before editing: source file, generated output, register, prompt, validation transcript, workflow trace, citation, teaching derivative, public note, or deployment packet.

### 2. Contain

Downgrade or halt the disputed use. Use the lowest safe claim language until the incident is classified.

### 3. Scope

Identify affected parties, artifacts, derivatives, audiences, source subjects, systems, and domains.

### 4. Classify

Assign provisional incident status INC0-INC9, harm/severity H0-H9, and recovery class RC0-RC9.

### 5. Route controls

Consult relevant controls: reception `153`, release/rollback `154`, public reliance `158`, stewardship `159`, continuity `160`, automation `163`, semantic fidelity `164`, deployment `165`, and incident response `166`.

### 6. Recover

Choose clarification, register update, erratum, rollback, withdrawal, notice, source/domain review, governance revision, or blocked unresolved status.

### 7. Close or carry debt

Close only with evidence, residual risk, and successor-memory trigger. Otherwise mark unresolved or unsafe.

## Allowed wording

- local incident-response runbook executed;
- incident status classified locally;
- evidence-preservation step recorded;
- recovery action identified;
- local package incident artifacts present.

## Forbidden wording

- public incident process active;
- legal, clinical, engineering, safety, or institutional incident review completed;
- affected-party notice delivered unless separately evidenced;
- external monitoring active;
- all derivative uses checked;
- incident closed for domain purposes without domain authority.


## Post-response learning handoff

After an incident or near miss is contained and closure status is assigned, ask whether `167-post-incident-learning-root-cause-capa-and-recurrence-risk-governance.md` is triggered. Use `167` when the event may reveal a recurring pattern, requires root-cause classification, needs corrective/preventive action, requires verification evidence, or should create successor-memory beyond the recovery packet. Do not describe the event as learned merely because the incident record is closed.
