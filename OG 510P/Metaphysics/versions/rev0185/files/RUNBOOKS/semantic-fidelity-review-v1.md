# Semantic Fidelity Review Runbook v1

Purpose: provide a local procedure for checking whether generated, compressed, translated, tabulated, diagrammed, excerpted, or derivative archive outputs preserve the meaning and limits of their source material.

Scope: local summaries, teaching artifacts, prompt answers, release notes, generated drafts, derivative files, source digests, diagrams, tables, and public handoff text. This runbook does not create independent philosophical review, source currency, domain authority, public CI, public derivative monitoring, or automated semantic certification.

## Ordered procedure

1. **Identify source and output**
   - Name the source version, source files, output type, audience, intended use, and compression level.
   - Stop if the source version is unknown.

2. **Classify automation involvement**
   - If a tool or model helped produce the output, record automation status and permission class under `163`.
   - Do not let authorized tool use become semantic warrant.

3. **Check target and route fidelity**
   - Confirm that the output preserves the target question and the route through operator, method, or control file.

4. **Check basis and rival fidelity**
   - Confirm that the output preserves the basis for the verdict and at least the nearest rival, defeater, hostile variation, or appeal trigger when material.

5. **Check status and non-verdict fidelity**
   - Confirm that commitment status, maturity, precedent status, public-use status, review warrant, and non-verdicts are not silently upgraded or deleted.

6. **Check source and version fidelity**
   - Confirm that source-bound claims, version identity, lineage relation, migration rule, supersession, and source-currency limits are visible where relevant.

7. **Check warning retention**
   - Assign WR0–WR8. Keep the specific warning that matters rather than hiding it in generic disclaimer noise.

8. **Check visual and table implications**
   - For diagrams or tables, inspect arrows, hierarchy, ordering, grouping, blanks, and labels for unintended causation, grounding, endorsement, containment, or sequence claims.

9. **Assign semantic-fidelity status**
   - Use SF0–SF9. Downgrade if the output is useful but not faithful enough for its intended use.

10. **State allowed and forbidden reuse**
   - Record what the output may support, what it may not support, and what review or correction trigger applies.

11. **Create or update the semantic-fidelity record**
   - Use `REGISTERS/schemas/semantic-fidelity-record-v1.yml` for current-version release-level records or for high-risk outputs.

12. **Escalate or quarantine**
   - Quarantine if warnings, source boundaries, non-verdicts, status limits, or high-stakes boundaries are materially missing.

## Minimum evidence

- source version and files,
- output type and audience,
- compression level,
- automation involvement if any,
- fidelity dimensions checked,
- warning-retention class,
- semantic-fidelity status,
- omissions and known risks,
- human-review boundary,
- allowed and forbidden reuse,
- next review trigger.
