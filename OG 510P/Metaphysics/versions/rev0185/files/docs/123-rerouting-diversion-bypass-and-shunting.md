# Rerouting, Diversion, Bypass, and Shunting

## Why this file exists

The archive now has explicit files on **circulation / throughflow**, **bottlenecks / congestion / chokepoints**, **gating / coupling**, **compartmentalization / firebreaks**, **repair / resilience / adaptive reorganization**, and **sequestration / release / leakage**, but it still lacks one direct file saying what to do when a case is described as **rerouted**, **diverted**, **sent around an obstruction**, **bypassed**, **shunted into another channel**, **detoured**, **reassigned to another corridor**, or **kept alive by an alternate path**.

That omission matters because the archive still risks nine opposite mistakes:

- treating every **reroute** as if it were already a new bearer rather than the same bearer under path-change,
- treating every **bypass** as if it erased the blocked or damaged segment rather than going around it,
- treating every **shunt** as if it were just leakage or accidental loss rather than directed alternate passage,
- treating every **diversion** as if it were only blockage, delay, or congestion rather than path-selection,
- treating every alternate route as if it were mere **duplication** rather than reassignment of live traffic,
- treating every **detour** as if it were only descriptive travel language with no ontological import,
- missing the difference between **same continuing bearer under rerouted passage** and **replacement, fission, or successor substitution**,
- missing the difference between **adaptive alternate routing** and **mere release, leakage, or uncontained escape**,
- or smuggling the difference between **rerouting**, **diversion**, **bypass**, **shunting**, **detour**, and **load-balancing across paths** into neighboring files without typing it.

This file gives the archive a compact **rerouting / diversion / bypass / shunting profile** so future revisions can say whether a case is chiefly about detour around a local obstruction, bypass of a compromised segment, shunting into an alternate channel, protective rerouting under disturbance, or distributed redirection across several available paths.

## Working default

The archive should now say explicitly:

> **Some real systems remain the same continuing bearers while passage changes path.**

In compressed form:

> **Not every altered path is a new bearer. Some persistence is reroute-shaped.**

And more carefully:

> **Rerouting, diversion, bypass, and shunting are best understood as typed ways in which one real route, organism, mechanism, corridor, institution, or network remains the same continuing bearer while material, signals, cases, or authority are redirected through an alternate path, side-channel, detour, or substitute conduit rather than through the default or previously preferred one.**

This fits the archive's wider commitments:

- **circulation / throughput / organized throughflow** still matter because rerouting changes the path of passage within a continuing routed bearer,
- **bottlenecks / congestion / backpressure** still matter because rerouting is often a response to local constriction or overload,
- **gating / selective responsiveness** still matter because some reroutes are actively selected rather than passively forced,
- **compartmentalization / firebreaks** still matter because alternate paths can localize disturbance and preserve wider continuity,
- **repair / resilience / adaptive reorganization** still matter because some systems survive damage by shifting traffic to backup routes,
- **sequestration / release / leakage** still matter because rerouting is directed alternate passage, not mere holding or uncontrolled escape,
- and **organization / mechanism** still matter because valves, switches, grafts, detour plans, routing tables, approval chains, and handoff rules often determine where the alternate path actually is.

## Core distinctions

### 1. Rerouting is not the same as blockage or ending

A blocked path may stop local passage, but rerouting means passage continues by another route. The continuing bearer may therefore survive constraint without the blocked path being unreal.

So the archive should distinguish:

- **same bearer with one route impeded**,
- **same bearer with traffic redirected elsewhere**,
- **total blockage or ending only in harder cases**,
- **same flow now taking another path**,
- and **mixed cases only where local blockage and alternate-route continuation coexist**.

Otherwise it will keep mistaking altered path for vanished process.

### 2. Bypass is not the same as repair

A bypass can preserve function without restoring the original path. That matters because a system may remain itself while its damaged segment is still damaged.

So the archive should distinguish:

- **restored original path**,
- **same wider bearer preserved by going around the damaged segment**,
- **same function under alternate conduit**,
- **replacement or successor formation only in stronger architectural change**,
- and **mixed cases only where repair and bypass are jointly present**.

Otherwise it will keep flattening workaround and restoration into one continuity verdict.

### 3. Shunting is not the same as leakage

A shunt is directed redirection into another channel, cavity, line, or branch. Leakage is uncontrolled escape. Both involve flow leaving one corridor, but only one is organized alternate routing.

So the archive should distinguish:

- **directed alternate passage**,
- **uncontrolled escape or loss**,
- **same system under channel reassignment**,
- **same source under failed containment**,
- and **mixed cases only where a shunt itself later leaks or degrades**.

Otherwise it will keep mistaking deliberate side-routing for broken containment.

### 4. Diversion is not the same as duplication

A diverted stream is reassigned, not necessarily doubled. The same cases, people, fluid, or packets may now go elsewhere without any increase in total stock.

So the archive should distinguish:

- **same traffic reallocated across paths**,
- **parallel duplication or branching**,
- **same bearer with alternate route choice**,
- **same bearer with newly multiplied copies only in stronger branching cases**,
- and **mixed cases only where rerouting and duplication jointly occur**.

Otherwise it will keep treating traffic reassignment as if new traffic or new bearers had appeared.

### 5. Detours can preserve continuity while changing cost, exposure, and timescale

An alternate path may be longer, slower, riskier, or more resource-intensive while still preserving the same wider bearer and same directed task.

So the archive should distinguish:

- **same task under longer or costlier route**,
- **same bearer under changed exposure or dwell time**,
- **same corridor with altered path geometry**,
- **new bearer only in harder redesign cases**,
- and **mixed cases only where repeated detouring transforms organization more deeply**.

Otherwise it will keep treating path-cost change as ontological replacement.

### 6. Stable rerouting can preserve a bearer through local damage or overload

Many organized systems survive not by freezing the original path but by redistributing passage across alternatives, backups, or substitute corridors.

So the archive should distinguish:

- **same bearer preserved by alternate routing**,
- **same bearer preserved by redundancy or failover more generally**,
- **same bearer under emergency detour or adaptive reorganization**,
- **deeper replacement only where the route-change also changes the bearer-kind or identity conditions**,
- and **mixed cases only where rerouting shades into rebuilding or succession**.

Otherwise it will keep missing continuity-through-redirection.

## Typology of rerouting cases

### A. Detour or diversion around a local obstruction

The key feature is that traffic is sent around a local blockage, closure, or incident while the wider corridor remains operative.

**Examples:** road detour around a crash site, administrative case diversion away from one overloaded office, emergency logistics routed around a closed hub.

### B. Bypass around a compromised segment

The key feature is that function is preserved by adding or using an alternate conduit around a damaged or narrowed segment.

**Examples:** coronary bypass graft, temporary plumbing bypass around a failed section, software or workflow bypass around a broken subsystem.

### C. Shunting into an alternate channel

The key feature is that flow is intentionally redirected into another chamber, branch, or low-resistance route.

**Examples:** cerebrospinal-fluid shunt, portal-system shunt, current routed through a shunt path, fluid diverted into a relief or return line.

### D. Load-balancing or distributed rerouting

The key feature is that traffic is redistributed across several available paths to reduce local overload or preserve service.

**Examples:** packet rerouting across network paths, aircraft or vehicle diversion across parallel corridors, support tickets redistributed among teams.

### E. Protective rerouting and damage isolation

The key feature is that redirection helps localize damage or maintain viability while one segment is offline, contaminated, or overloaded.

**Examples:** collateral circulation, bypass valves, work routed around a compromised production stage, ecological or institutional traffic shifted away from a damaged zone.

## Cross-domain pressure

### Surgery, circulation, and physiological shunts

These cases pressure the archive because one organism can remain the same while blood or cerebrospinal fluid is directed through newly established or substitute passages.

### Traffic, logistics, and detours

These cases pressure the archive because one continuing corridor or supply system can remain real while passage is sent along alternate roads, hubs, lanes, or schedules.

### Circuits, pipelines, and channel redirection

These cases pressure the archive because one system can remain itself while current, pressure, or fluid is sent through side-channels, bypass loops, or relief paths.

### Institutions, workflows, and delegated path-change

These cases pressure the archive because one continuing organization can preserve function by reassigning cases, approvals, or authority routes without thereby becoming a new institution.

## False moves to avoid

- Do **not** infer new bearer from every reroute.
- Do **not** infer repair from every bypass.
- Do **not** infer leakage from every shunt.
- Do **not** infer duplication from every diversion.
- Do **not** infer disappearance of the old path from the fact that it is presently not used.
- Do **not** infer that the preferred route was metaphysically privileged just because it was earlier or more familiar.
- Do **not** infer pure costless preservation from every detour.
- Do **not** infer that rerouting always solves the deeper problem rather than temporarily working around it.
- Do **not** infer one flat relation from **rerouted**, **diverted**, **detoured**, **bypassed**, **shunted**, **sent around**, or **moved onto an alternate path**.

## Default diagnostic questions

When a case is described as **rerouted**, **diverted**, **detoured**, **bypassed**, **shunted**, **sent through another corridor**, or **kept going by an alternate path**, ask:

1. What exactly is the **target** — one vessel, one fluid stream, one circuit, one corridor, one pipeline, one workflow, one office-structure, one institution, or one mixed organization?
2. Is the case chiefly about **detour / diversion**, **bypass**, **shunting**, **load-balancing rerouting**, **protective rerouting**, or a mixed architecture?
3. What is actually **doing the rerouting work** — graft, valve, switch, routing table, detour plan, alternate corridor, approval reassignment, pressure differential, or mixed?
4. What remains **real underneath the path-change** — same bearer under alternate passage, same institution under reassigned cases, same organism under new conduit, same route-system with one segment avoided, stronger replacement or branching only in harder cases, or mixed?
5. What is the nearest **comparison class** — blockage, leakage, release, duplication, circulation, repair, failover, or artifact?
6. What is the relevant **path / cost / stock profile** — same stock on another path, partial diversion with residual primary traffic, complete bypass of one segment, short emergency detour, chronic alternate routing, or mixed?
7. What is the relevant **timescale profile** — transient incident response, medium-term workaround, chronic bypass dependence, scheduled redistribution, or mixed?
8. What is the relevant **artifact-risk profile** — route labels changed without real traffic change, proxy path inferred from sparse data, diversion counted without stock accounting, hidden simultaneous leakage, or mixed?
9. Is the best verdict **typed detour / diversion**, **typed bypass**, **typed shunting**, **typed distributed rerouting**, **typed protective rerouting**, **apparent reroute / proxy artifact**, or **still unsettled**?
