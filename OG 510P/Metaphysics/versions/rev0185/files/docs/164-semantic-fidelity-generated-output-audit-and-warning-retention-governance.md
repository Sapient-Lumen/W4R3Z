# Semantic Fidelity, Generated-Output Audit, and Warning-Retention Governance

## Why automation boundaries are not enough

`163-automation-boundaries-agent-delegation-scheduled-execution-and-tool-permission-governance.md` says which tool-mediated actions may occur and which claims those actions may support. That layer is necessary, but it is not sufficient. A tool can remain inside its permission boundary and still produce an output that is semantically unsafe.

The danger is **semantic-fidelity laundering**. A summary may preserve the headline while dropping the non-verdict. A table may make live rivals look defeated because the cells are too compact. A teaching handout may retain the example but lose its version, status, appeal trigger, or source boundary. A generated answer may quote the archive's vocabulary while silently upgrading orientation into doctrine. A derivative file may preserve the route but omit the defeater. A diagram may draw arrows that imply causation, grounding, containment, flow, or control when the archive only licensed comparison. A source digest may compress an external anchor into archive commitment. A public note may keep the conclusion but lose withdrawal, review-expiry, or high-stakes warnings.

This file adds a layer after automation governance: **semantic fidelity, generated-output audit, and warning retention**. Its question is not merely "was a tool allowed to act?" but **did the resulting output preserve the meaning, limits, warnings, status, and return path that made the source responsible?**

The rule is simple:

> **A bounded tool action can still produce an unfaithful output. Generated or compressed material must be audited for target, basis, status, warning, source, version, and non-verdict retention before it is reused, taught, published, or treated as a faithful artifact.**

## Compressed default

The archive should now say:

> **Do not call an output faithful merely because it was authorized, validated, or well formatted. Check what it preserved, what it dropped, what it upgraded, what it ambiguated, and what warnings must travel with it.**

In shorter form:

> **A good-looking summary can still be a bad transfer.**

And more carefully:

> **Every generated, compressed, translated, tabulated, diagrammed, excerpted, or derivative output that carries archive authority should state its source version, output type, intended audience, compression level, target preserved, basis preserved, warnings retained, statuses retained, source boundaries retained, non-verdicts retained, omissions, review boundary, allowed reuse, forbidden reuse, and next fidelity trigger.**

This file therefore shifts the archive from **automation-boundary governance** to **semantic-output governance**.

The difference between `163` and this file is crucial. `163` asks: **what was the tool allowed to do, and what authority did its action not have?** This file asks: **after the tool or human produced the output, did the meaning survive the transfer?**

## What counts as a generated or transformed output

This file applies to any artifact that presents archive material in a new form, even if no machine model was involved:

1. compact answers, glosses, summaries, abstracts, or executive notes,
2. teaching handouts, slides, diagrams, rubrics, tests, or classroom examples,
3. tables, matrices, flowcharts, decision trees, checklists, or dashboards,
4. prompt outputs, generated drafts, rewritten sections, translations, style transfers, or Q&A responses,
5. source digests, literature notes, citation packets, or source-bound examples,
6. derivative public pages, forks, imported excerpts, migrated files, or adapted packets,
7. validation summaries, release notes, README claims, handoff messages, or package descriptions,
8. semantic indexes, embeddings, retrieval snippets, search summaries, and chunked views.

The common feature is not automation. The common feature is **representational transfer**: something that had one context is now being used in another.

## Semantic-fidelity status classes

### SF0 — no fidelity claim

The output makes no claim to preserve archive meaning. It may be a brainstorming note, private scratch, or informal orientation. It should not be cited as faithful.

### SF1 — loose orientation

The output gives a rough orientation and may omit technical limits. It must not be used as doctrine, precedent, source interpretation, or public reliance. The return path to the archive should be visible.

### SF2 — caveat-retaining summary

The output preserves the main target, conclusion, and at least the most important caveat or non-upgrade warning. It is suitable for local orientation but not for high-stakes, source-bound, public, or derivative use.

### SF3 — warning-retaining teaching output

The output preserves version identity, target, status, compression level, key warnings, and nearest-rival cautions. It may be used pedagogically if students or readers can see what has been simplified.

### SF4 — dossier-faithful applied output

The output preserves enough of the `150` dossier structure to support applied use: target, route, basis, rivals, hostile variants, defeaters, non-verdict, status, review trigger, and future-use permission.

### SF5 — precedent- and transfer-faithful output

The output preserves precedent status, transfer limits, appeal triggers, supersession rules, and do-not-reuse boundaries from `151`. It may travel across contexts only within those limits.

### SF6 — source- and version-faithful output

The output preserves source role, source currency limits, source-bound examples, version lineage, migration status, review warrant, and public-use restrictions. It is required for source-dependent public handoffs.

### SF7 — independently reviewed semantic-fidelity output

A distinct reviewer has checked that the output preserves target, basis, limits, warnings, non-verdicts, source role, version status, and permitted claim language. This supports semantic-fidelity review only, not general philosophical certification.

### SF8 — public-use fidelity-warranted output

The output has a public-use packet, stewardship assignment, continuity path, dispute route, withdrawal rule, and semantic-fidelity review appropriate to its audience. This is rare and should not be inferred from a polished summary.

### SF9 — failed, unsafe, or fidelity-laundered output

The output is being presented as faithful while it drops, reverses, upgrades, or obscures essential limits. Use when warnings disappear, source-bound claims become archive doctrine, live rivals vanish, examples become precedents, or validation/automation language becomes semantic warrant.

## Warning-retention classes

### WR0 — no warning retained

No warning, limit, or non-verdict travels with the output. This is acceptable only for private scratch or clearly marked orientation.

### WR1 — return-path warning retained

The output tells the reader where the fuller treatment lives and warns against treating the output as complete.

### WR2 — status warning retained

The output preserves whether the claim is kernel, working default, diagnostic, calibrated precedent, source-dependent, provisional, deprecated, quarantined, or open debt.

### WR3 — non-verdict retained

The output explicitly states what the source did not decide.

### WR4 — rival/defeater retained

The output preserves at least the nearest rival, appeal trigger, hostile variation, or defeater class.

### WR5 — source/version boundary retained

The output preserves source role, source currency limits, version identity, lineage relation, migration status, and review-expiry boundary where relevant.

### WR6 — public-use and stewardship boundary retained

The output preserves public-use permission, citation form, reliance limits, dispute path, correction path, stewardship duty, and withdrawal/retraction rule where relevant.

### WR7 — high-stakes/domain boundary retained

The output preserves the rule that this archive does not provide legal, medical, clinical, engineering, financial, safety-critical, institutional, or operational advice without current source review and domain authority.

### WR8 — warning failure

The output presents itself as faithful while warnings, statuses, source boundaries, non-verdicts, or review limits are missing or misleading.

## Fidelity dimensions

A semantic-fidelity audit should check at least these dimensions:

1. **Target fidelity** — does the output preserve what question, case, object, process, relation, or claim was actually under discussion?
2. **Route fidelity** — does it preserve which operator, family, method rule, or control layer routed the answer?
3. **Basis fidelity** — does it preserve the evidence, argument, contrast class, source role, or package check that actually supported the answer?
4. **Status fidelity** — does it preserve maturity level, commitment class, precedent status, review warrant, public-use status, and stewardship duty where relevant?
5. **Non-verdict fidelity** — does it preserve what the source refused to decide or held open?
6. **Warning fidelity** — does it preserve caveats, do-not-upgrade instructions, high-stakes exclusions, source limits, appeal triggers, withdrawal rules, and review-expiry triggers?
7. **Rival fidelity** — does it preserve the nearest rival interpretation or at least acknowledge that rivals remain live?
8. **Version fidelity** — does it preserve version identity, lineage relation, migration status, supersession, deprecation, or historical-only status?
9. **Source fidelity** — does it preserve whether a claim came from archive reasoning, external source interpretation, source-bound example, or current-source review?
10. **Compression fidelity** — does the output's compression level match the amount of omitted reasoning and warning material?
11. **Visual fidelity** — if the output is a diagram, table, or flowchart, do arrows, boxes, hierarchy, and sequence imply relations the archive did not license?
12. **Audience fidelity** — does the output fit its intended audience without hiding limits needed for that audience's use?

## Generated-output audit record

A semantic-fidelity record should minimally include:

- record ID,
- artifact and version,
- source material and source version,
- output artifact or output type,
- intended audience and intended use,
- compression level under `152`,
- automation status and tool-permission class under `163` if any,
- semantic-fidelity status SF0–SF9,
- warning-retention class WR0–WR8,
- target, route, basis, status, non-verdict, source, version, and public-use items checked,
- warnings retained,
- warnings omitted with justification,
- transformations performed,
- known fidelity risks,
- human-review boundary,
- allowed reuse,
- forbidden reuse,
- correction or withdrawal trigger,
- open semantic-fidelity debt,
- next fidelity review trigger.

## Common failure patterns

### Headline preservation with basis loss

The output keeps the conclusion but drops the contrast class, hostile variant, source role, or method route that made the conclusion responsible.

### Status bleaching

The output preserves a distinction but removes whether it is kernel, working default, provisional, source-bound, deprecated, appeal-pending, or do-not-reuse.

### Non-verdict deletion

The output omits what the archive deliberately left undecided. This is especially dangerous in tables, short answers, and public summaries.

### Example supremacy

A teaching example becomes the doctrine. Fix by reintroducing target, family, status, and transfer limit.

### Diagrammatic overclaim

A visual arrow implies causation, grounding, generation, containment, hierarchy, flow, endorsement, or one-way dependence when the source only licensed comparison or diagnostic order.

### Source-boundary collapse

A source-dependent claim is rewritten as archive doctrine, or a current-source need is hidden behind source-neutral governance prose.

### Version ghosting

The output cites a conclusion without saying which version, whether it was superseded, whether migration is required, or whether a later release narrowed the claim.

### Automation-to-fidelity jump

A tool was authorized and validation passed, so the generated prose is treated as faithful without semantic review.

### Warning overload followed by warning deletion

The output includes so many generic disclaimers that readers cannot see the specific warning that matters; later summaries delete all warnings as boilerplate.

### Public-use upgrade

A locally faithful summary is treated as public reliance, domain authority, or operational guidance without `158`, `159`, and `160` support.

## When semantic fidelity should block reuse

Block or quarantine the output when:

- the source version cannot be identified,
- the output changes the target question,
- status, warning, or non-verdict information is missing and material,
- a source-bound claim becomes archive-wide doctrine,
- a public-use or high-stakes boundary disappears,
- a diagram/table implies stronger metaphysical relations than the source licenses,
- a generated output cannot distinguish summary from review, validation, or certification,
- a derivative artifact cannot provide a return path to the controlling version,
- or a reviewer cannot state what was preserved and what was omitted.

## When a lighter record is enough

Not every short answer needs a full packet. A compact semantic-fidelity note is enough when the output is local, source-neutral, non-public, non-precedential, non-high-stakes, and does not purport to settle doctrine. Even then, the output should avoid stronger wording than its source permits and should provide a return path for fuller treatment.

Use a full record when the output is public, source-dependent, derivative, teaching-facing, precedent-like, cross-version, generated at scale, high-risk, or likely to be reused without the archive nearby.

## Interaction with existing governance layers

Semantic-fidelity governance does not replace earlier layers.

- `152` states how much compression is allowed.
- `153` classifies how an output is received.
- `158` states whether public reliance is permitted.
- `159` assigns duties after reliance or derivative use.
- `161` validates structure and manifest invariants.
- `162` records workflow execution.
- `163` binds tool permissions and automation claims.
- `164` asks whether the resulting output actually preserved the meaning, warnings, statuses, and limits that earlier layers required.

## Safety and domain boundaries

No semantic-fidelity record may convert an archive output into legal, medical, engineering, clinical, financial, safety-critical, institutional, or operational advice. A semantically faithful output is faithful to the archive; it is not automatically true in the world, current with external sources, domain-authorized, or safe for operational reliance.

If a future output touches such a domain, the archive should require current source review, domain authority, explicit public-use rules, and high-stakes warnings before allowing more than orientation.
