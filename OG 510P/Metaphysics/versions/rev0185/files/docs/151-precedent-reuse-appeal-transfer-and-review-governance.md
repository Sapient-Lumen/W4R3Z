# Precedent Reuse, Appeal, Transfer, and Review Governance

## Why this file exists

`150-application-dossier-decision-record-and-verdict-report-protocol.md` made applied verdicts portable. That was necessary, but it is not yet sufficient. A dossier can be well written and still be misused later.

The next danger is **precedent drift**: a bounded verdict travels into a new case, classroom summary, synthesis paragraph, source interpretation, or revision argument, and the limits that made it responsible are quietly dropped. The archive then begins to learn from its own summaries rather than from the dossiered basis. It can inherit a result without inheriting the target, grain, rivals, defeaters, status, source role, non-verdict, and review trigger.

A second danger is **appeal blindness**: once a verdict has a dossier, later users may treat it as closed even when new cases, source anchors, hostile variants, terminology conflicts, status changes, or failed transfers should reopen it.

A third danger is **transfer inflation**: a verdict that was safe in one family, grain, source-domain, or teaching context is exported across domains as if precedent meant universal permission.

This file adds a post-dossier governance layer: **precedent reuse, appeal, transfer, and review control**. Its job is not to create another first-order metaphysical operator. Its job is to govern what happens after a verdict has been recorded and begins to move.

## Compressed default

The archive should now say:

> **A dossier is not a license for unlimited reuse. Every reused verdict must carry its permission, scope, transfer conditions, appeal triggers, and supersession rule.**

In shorter form:

> **Portable verdicts need travel rules.**

And more carefully:

> **A case result may be reused only in the form allowed by its dossier and precedent status: illustration, controlled precedent, calibration, regression warning, source-bound example, live rival, open pressure, deprecated caution, or do-not-reuse. If the new use changes target, basis, grain, family, source role, status, or failure mode, the result must be re-dossiered or appealed rather than silently exported.**

This file therefore shifts the archive from **application-auditable classification** to **reuse-governed classification**.

## Place in the control sequence

The intended hard-case sequence is now:

1. **Route** the case or proposed addition with `144`.
2. **Stress-test** the routed verdict with `145`.
3. **Ledger** reusable or precedent-setting cases with `146`.
4. **Propagate** accepted changes with `147`.
5. **Register terminology** with `148`.
6. **Assign commitment status** with `149`.
7. **Write the application dossier** with `150` when the result must travel.
8. **Govern reuse, transfer, appeal, and review** with this file when the result is cited, taught, exported, challenged, superseded, or used as precedent.
9. **Govern transmission and compression** with `152-transmission-excerpt-compression-and-pedagogical-governance.md` when an allowed use becomes a summary, excerpt, diagram, table, teaching module, prompt answer, paper section, rubric, or derivative artifact.

The difference between `150` and this file is simple. `150` asks: **what exactly was decided, and how was it earned?** This file asks: **what may later users do with that decision, and when must they stop, reopen, narrow, supersede, or refuse the transfer?** `152` then asks: **what must remain visible when an allowed use is compressed or transmitted?**

## The basic unit: the precedent packet

A **precedent packet** is the smallest portable bundle that allows a verdict to be reused without upgrade drift.

A precedent packet should contain:

1. **Dossier pointer** — which application dossier, decision record, or verdict report is being reused.
2. **Precedent status** — local answer, illustration, controlled precedent, calibration precedent, regression warning, source-bound precedent, live-rival precedent, deprecated caution, appeal-pending item, or do-not-reuse item.
3. **Allowed uses** — teaching example, comparison case, method demonstration, family-routing precedent, calibration control, source interpretation, synthesis support, demotion warning, or revision trigger.
4. **Forbidden uses** — identity inference, parthood inference, grounding inference, causal inference, source export, kernel promotion, cross-family analogy, continuity upgrade, or universalization.
5. **Transfer conditions** — what target, basis, grain, family, source role, failure mode, and terminology status must be preserved for reuse to be legitimate.
6. **Appeal triggers** — what new evidence, hostile variant, source conflict, domain shift, failed reuse, or status change should reopen the verdict.
7. **Supersession rule** — what happens if a later dossier narrows, defeats, absorbs, or replaces the precedent.
8. **Citation form** — how the precedent should be named so later readers know whether it is illustration, calibration, live rival, caution, or controlling comparison.

The point is not to make every application bureaucratic. The point is to stop a successful application from becoming a free-floating slogan.

## Precedent-status categories

### 1. Local answer only

A verdict may solve the immediate question but should not be reused. This is appropriate when the case was too context-specific, under-specified, low-stakes, or not stress-tested enough to travel.

Reuse permission: none, except as a private example.

Typical warning: **Do not cite as precedent.**

### 2. Teaching illustration

The case can help explain a distinction, but it has not earned calibration or precedent status.

Reuse permission: explanatory use only.

Forbidden upgrade: treating memorability as evidential force.

### 3. Controlled precedent

The case may guide new cases that preserve the relevant target, basis, grain, family, and failure mode.

Reuse permission: comparison and routing under stated transfer conditions.

Forbidden upgrade: exporting the verdict beyond its matched structure.

### 4. Calibration precedent

The case functions as a positive control, negative control, hard positive, hard negative, boundary case, or regression case under `146`.

Reuse permission: benchmark use.

Forbidden upgrade: treating calibration success as kernel commitment.

### 5. Regression warning

The case marks a mistake the archive must not repeat: a false promotion, false compression, source smuggling, terminology drift, or status inflation.

Reuse permission: cautionary and adversarial use.

Forbidden upgrade: treating the warning as a positive doctrine.

### 6. Source-bound precedent

The case may be reused only within a source-defined domain, practice, legal regime, technical standard, scientific model, historical vocabulary, or institutional rule.

Reuse permission: source-local or domain-local use.

Forbidden upgrade: archive-wide metaphysical export without new routing and status assignment.

### 7. Live-rival precedent

The case preserves a strong rival diagnosis that the archive has not defeated.

Reuse permission: pressure-testing and comparison.

Forbidden upgrade: treating the rival as either accepted doctrine or refuted error.

### 8. Deprecated caution

The case records a once-used distinction, term, or verdict that has been narrowed, absorbed, superseded, or retired.

Reuse permission: history and warning.

Forbidden upgrade: reinstating the old use without appeal.

### 9. Appeal-pending item

The precedent is provisionally frozen because a review trigger has fired.

Reuse permission: cite only as contested.

Forbidden upgrade: using the verdict as stable support while the appeal is open.

### 10. Do-not-reuse item

The case is too misleading, contaminated, under-specified, source-dependent, metaphorical, or defeated to travel.

Reuse permission: none, except as an example of what not to use.

Forbidden upgrade: all doctrinal, teaching, precedent, and calibration use.

## Transfer test

Before reusing a dossiered verdict in a new context, ask the following questions.

### 1. Target preservation

Is the new case about the same kind of target: object, process, relation, role, status, fact, power, structure, representation, event, system, institution, source term, or mixed target?

If not, do not reuse without rerouting through `144`.

### 2. Basis preservation

Does the new case preserve the basis that made the original verdict non-accidental?

If the word remains while the basis changes, the precedent fails.

### 3. Grain compatibility

Is the new case at the same grain: token, type, role, system, lineage, model, institution, regime, source practice, or mixed?

If the grain changes, reuse is at most analogical until re-dossiered.

### 4. Family compatibility

Does the new case belong to the same operator family, or has it moved from identity to support, support to evidence, evidence to status, status to source interpretation, passage to control, or application to governance?

If the family changes, the precedent must be treated as a prompt rather than a ruling.

### 5. Rival preservation

Are the nearest rivals the same? A precedent against `hosting` may not settle a later case whose live rival is `embedding`, `support`, `enclosure`, or `source-bound classification`.

If the rival set changes, reuse requires a new nearest-rival challenge.

### 6. Failure-mode preservation

Would the same breakdown reveal the same relation or misclassification?

If the failure mode changes, the precedent is probably not controlling.

### 7. Terminology preservation

Do the canonical terms, aliases, source terms, metaphors, and unsafe shortcuts have the same status under `148`?

If a term is being translated into a new domain, perform terminology audit before reuse.

### 8. Commitment-status preservation

Does the original status under `149` still hold: kernel commitment, working default, diagnostic distinction, calibrated precedent, domain-local rule, live rival, provisional probe, source-dependent commitment, deprecated item, or open debt?

If the status changes, the precedent must be narrowed or appealed.

### 9. Source-role preservation

If the original verdict depended on a source, is the same kind of source role present: constitutive, evidential, classificatory, historical, illustrative, or absent?

If a source-bound precedent is exported to an archive-wide metaphysical claim, the transfer fails.

### 10. Non-verdict preservation

Does the later use preserve what the original explicitly did not decide?

If the non-verdict is dropped, the precedent is being laundered into a stronger claim.

## Appeal triggers

A precedent should be appealed, frozen, narrowed, or re-dossiered when any of the following occurs.

### New case pressure

A new case preserves the vocabulary and apparent family but defeats the original basis, grain, failure mode, or rival set.

### Failed transfer

A precedent that worked in one domain produces contradictions, misclassifications, or forced overcommitment in another.

### Source change

A relevant source anchor changes, is reinterpreted, is superseded, or turns out to have been merely illustrative rather than constitutive or evidential.

### Terminology conflict

A canonical term, alias, source-specific term, metaphor, or unsafe shortcut changes status under `148`.

### Commitment-status change

A claim is promoted, demoted, deprecated, narrowed, source-bound, or marked as open debt under `149`.

### Dossier defect

A later reader cannot reconstruct the target, basis, grain, rivals, hostile variants, non-verdict, review trigger, or future-use permission from the original dossier.

### Regression failure

A future revision accidentally reverses a hard positive, hard negative, negative control, boundary case, or regression warning from `146`.

### Teaching drift

A simplified example becomes the remembered doctrine and begins to override the dossier.

### Package drift

The file map, index, revision note, manifest, source note, or control sequence no longer agrees with the actual archive.

### Live-rival strengthening

A preserved rival gains new support, exposes a hidden assumption, or better explains the case at the relevant grain.

## Appeal procedure

When an appeal trigger fires, use this sequence.

### Step 1. Freeze uncontrolled reuse

Mark the precedent as **appeal-pending**. Do not use it as teaching precedent, calibration, source interpretation, or synthesis support until review is complete.

### Step 2. Reconstruct the original dossier

Identify the original target, diagnostic question, route, rivals, basis, grain, source role, hostile variants, artifact risks, defeaters, status, maturity, non-verdict, future-use permission, and review trigger.

### Step 3. State the appeal question

An appeal should not ask vaguely whether the old verdict was wrong. It should ask a precise question:

- Did the target change?
- Did the basis change?
- Did the grain change?
- Did the rival set change?
- Did the source role change?
- Did terminology status change?
- Did commitment status change?
- Did a calibration case fail?
- Did a teaching summary overrun the dossier?

### Step 4. Rerun the relevant controls

Use only the controls that the appeal actually implicates, but do not skip the implicated ones:

- reroute with `144` if target or family changed,
- rerun `145` if hostile variants or rivals changed,
- update `146` if calibration or regression consequences changed,
- run `147` if the appeal changes any file dependencies,
- use `148` if terminology changed,
- use `149` if commitment status changed,
- update `150` if the dossier was defective or the verdict must be rewritten.

### Step 5. Decide the appeal

The appeal result should be one of:

- **affirm** — precedent remains valid under original scope,
- **affirm with narrower scope** — transfer conditions become stricter,
- **split** — one case family remains valid and another gets a new verdict,
- **demote** — precedent becomes illustration, live rival, source-bound example, open pressure, or local answer only,
- **quarantine** — precedent becomes do-not-reuse until repaired,
- **supersede** — new dossier replaces old verdict,
- **absorb** — precedent is compressed into a broader family map or method rule,
- **deprecate** — old use remains in history but should not guide new work,
- **reopen** — archive records open debt because the appeal cannot be settled yet.

### Step 6. Publish the review result

A review result should update the precedent packet, the original dossier, the case ledger if applicable, the status register, the terminology register if terms changed, the propagation map, and the source note if a source role changed.

## Teaching and exposition discipline

Teaching examples are especially dangerous because clarity often comes from simplification.

The archive should distinguish:

- **introductory illustration** — helps a reader grasp a distinction but carries no precedential force,
- **worked example** — shows how to apply a file but does not calibrate future cases,
- **controlled comparison** — contrasts two or three neighboring files under fixed basis and grain,
- **calibration case** — serves as a positive/negative/hard/boundary/regression case,
- **appeal case** — shows when a previously safe verdict must be reopened,
- **anti-example** — shows how misuse happens,
- **source-bound example** — teaches a source-local distinction without exporting it.

Every teaching use should include one sentence beginning: **This example does not show that...** That sentence is the teaching version of the dossier's non-verdict.

## Family-specific transfer prompts

### Identity and continuity cases

Before reusing an identity or continuity precedent, ask whether the later case preserves the bearer, role, material basis, organization, lineage, records, recognition conditions, and grain. A precedent about substitution does not automatically settle migration, turnover, duplication, fusion, or office continuity.

### Dependence and grounding cases

Before reusing a dependence precedent, ask whether the same dependence relation is in play: grounding, constitution, realization, enabling background, scaffolding, hosting, support, source-local classification, or evidential support. A precedent about dependence should not become a flat priority claim.

### Access and evidence cases

Before reusing an evidence precedent, ask whether the same access route, instrument, proxy, robustness profile, source role, and target/vehicle distinction are preserved. A precedent about reliable detection should not become an ontological promotion without new status assignment.

### Process and temporal cases

Before reusing a process precedent, ask whether the later case preserves onset, maintenance, interruption, dormancy, return, cessation, irreversibility, history-trace, or regime-shift structure. A precedent about resumption should not settle survival after replacement.

### Stock, flow, passage, and control cases

Before reusing a flow or control precedent, ask whether the stock, passed target, route, aperture, valve, gate, support, leakage, bottleneck, and failure mode remain matched. A precedent about valving should not settle sealing, guiding, throttling, bottlenecking, or generic gating without renewed contrast.

### Interface, support, and attachment cases

Before reusing an interface precedent, ask whether contact, attachment, support, enclosure, embedding, wrapping, joining, articulation, clamping, latching, threading, meshing, gripping, guiding, and hosting have the same basis and failure profile. A precedent about being attached should not settle parthood or fusion.

### Social, normative, institutional, living, and conscious cases

Before reusing a high-level domain precedent, ask whether recognition conditions, rules, enforcement, embodiment, life-process, first-personal organization, agency, normativity, and source practices transfer. These domains are especially prone to source-bound and status-bound precedent misuse.

## Common mistakes this file is designed to block

1. **Precedent laundering** — citing a dossiered verdict while dropping its scope, non-verdict, and review trigger.
2. **Analogy inflation** — treating similarity of image, metaphor, or example as preservation of basis and grain.
3. **Teaching fossilization** — allowing the classroom summary to become more authoritative than the dossier.
4. **Appeal evasion** — refusing to reopen a verdict because it was once carefully recorded.
5. **Universalization drift** — exporting a domain-local or source-bound precedent as archive-wide doctrine.
6. **Calibration overreach** — treating a positive control as a kernel commitment.
7. **Regression amnesia** — forgetting why a hard negative or deprecated caution was recorded.
8. **Status bypass** — using precedent to promote a claim without explicit `149` status assignment.
9. **Term bypass** — using precedent to stabilize an alias or metaphor without `148` registration.
10. **Supersession fog** — allowing old and new verdicts to coexist without saying which governs which cases.

## Minimal reuse checklist

Before citing a previous verdict as precedent, confirm:

- [ ] The original dossier or decision record is identifiable.
- [ ] Precedent status is known.
- [ ] Allowed and forbidden uses are explicit.
- [ ] Target, basis, grain, family, and failure mode transfer.
- [ ] Nearest rivals remain comparable.
- [ ] Terminology status still holds.
- [ ] Commitment status and maturity still hold.
- [ ] Source role has not changed.
- [ ] The non-verdict is preserved.
- [ ] Appeal triggers have not fired.
- [ ] Supersession or deprecation has been checked.

## Relation to earlier control files

### Relation to `144`

`144` routes a case. This file decides whether a past routed case can guide a new one. Reuse is not routing; it is a claim that routing conditions are preserved.

### Relation to `145`

`145` attacks a verdict. This file says when later reuse or new pressure requires the attack to be rerun. Stress-test survival is not permanent immunity.

### Relation to `146`

`146` records calibration cases. This file governs when those cases may be used as calibration, when they are only illustrations, and when a failed transfer should become a new regression warning.

### Relation to `147`

`147` propagates accepted changes. This file adds a post-propagation question: after a change has propagated, how may its results be reused, appealed, narrowed, or superseded?

### Relation to `148`

`148` governs terms. This file prevents precedent from laundering an unsafe term into canonical use. A reused verdict must carry term status forward.

### Relation to `149`

`149` assigns commitment status. This file prevents precedent from becoming a hidden status promotion. A precedent cannot be stronger than the status of the claim it reuses.

### Relation to `150`

`150` writes the dossier. This file governs the dossier's later life: citation, teaching, transfer, appeal, supersession, and review. A well-written dossier can still be misused if it has no travel rules.

## Future expansion rule

Before adding another control or application file after this one, ask whether the pressure is really new. A new file is warranted only if the archive lacks a reusable answer to one of these questions:

- Where does the case route?
- Does the verdict survive attack?
- Should the case become calibration?
- Where must the change propagate?
- What terms are safe?
- What status does the claim have?
- How should the result be reported?
- How may the reported result be reused, transferred, appealed, superseded, or taught?
- How should permitted material be summarized, excerpted, diagrammed, taught, or exported without losing its limits?
- How should downstream uptake, misunderstanding, criticism, errata, and operational failure be classified before correction?

If the pressure is a variant of one of those questions, amend `144` through `161` rather than adding another governance file.

## Closing formulation

The archive's current applied sequence can now be compressed as:

> **Route the case. Attack the route. Ledger the hard result. Propagate the accepted change. Register the words. Assign the commitment level. Write the auditable verdict. Govern its reuse and appeal. Control its transmission. Audit its reception. Gate the release.**

The point is not to make metaphysics imitate law. The point is to keep the archive honest about memory. A verdict that travels without its limits is no longer the verdict the archive earned. A precedent that cannot be appealed is not mature; it is brittle.
