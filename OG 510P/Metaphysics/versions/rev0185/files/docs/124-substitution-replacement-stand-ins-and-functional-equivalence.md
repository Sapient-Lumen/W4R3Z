# Substitution, Replacement, Stand-Ins, and Functional Equivalence

## Why this file exists

The archive now has explicit files on **constitution / coincidence**, **identity over time**, **sortals and persistence**, **multiple realization**, **repair / resilience**, **delegation / proxying**, **turnover / renewal**, and **rerouting / bypass**, but it still lacks one direct file saying what to do when a case is described as **substituting**, **swapping out**, **replacing**, **standing in**, **acting as the substitute**, **plug-compatible**, **functionally equivalent**, **hot-swapped**, or **kept going by an alternate component or occupant**.

That omission matters because the archive still risks twelve opposite mistakes:

- treating every **successful substitution** as if it preserved **the same bearer**,
- treating every **part replacement** as if it forced **a numerically new thing**,
- treating every **stand-in** as if it were just **delegated proxy performance**,
- treating every **proxy** as if it were a **substitute occupant**,
- treating every **prosthetic or graft case** as if it were already **wholesale replacement**,
- treating every **function-preserving swap** as if it settled the deeper question of **sortal identity**,
- treating every **different realizer** as if it were either obviously **the same kind** or obviously **a different kind**,
- treating every **fungible stock replacement** as if that logic transferred automatically to **nonfungible individuals**,
- collapsing **component substitution**, **stand-in occupancy**, **prosthetic supplementation**, **realizer substitution**, **fungible replacement**, and **successor replacement** into one flat story,
- missing the difference between **same organization under altered components** and **same role with a different occupant**,
- missing the difference between **same function preserved differently** and **same bearer preserved**,
- or smuggling the difference between **replacement**, **repair**, **rerouting**, **turnover**, **proxying**, **duplication**, and **succession** into neighboring files without an explicit rule.

This file gives the archive a compact **substitution / replacement / stand-in / functional-equivalence profile** so future revisions can say whether a case is chiefly about component substitution within one continuing bearer, stand-in occupancy of a role, prosthetic supplementation, realizer substitution under one higher-level function, fungible replacement inside a stock, or stronger successor replacement.

## Working default

The archive should now say explicitly:

> **Some real things persist through typed substitution, but substitution is never self-interpreting.**

In compressed form:

> **Same function is not yet same bearer, and replacement is not yet loss of identity.**

And more carefully:

> **Substitution, replacement, stand-ins, and functional equivalence are best understood as typed ways in which one real bearer, role, function, organization, route, or stock may preserve some operative profile through changed components, occupants, realizers, or supports without thereby automatically implying strict numerical identity, obvious nonidentity, mere proxying, or unrestricted fungibility across domains.**

This fits the archive's wider commitments:

- **sortals / persistence** still matter because what counts as identity-preserving replacement is kind-sensitive,
- **constitution / coincidence** still matter because material continuity and bearer continuity can come apart,
- **multiple realization** still matters because the same higher-level function may be realized by different lower-level configurations,
- **repair / resilience / rerouting** still matter because some substitutions preserve one target by workaround rather than restoration,
- **delegation / office enactment** still matters because one role can be occupied by another without literal identity of performer,
- **turnover / renewal** still matter because gradual constituent exchange differs from explicit substitution decisions,
- **artifact and teleology files** still matter because designed function and origin history can affect what counts as the same artifact,
- and **fungibility / stock reasoning** still matters because reserves, inventories, and role-slots often allow replacement more easily than organisms, persons, or historically individuated artifacts.

## Core distinctions

### 1. Functional equivalence is not the same as numerical identity

Two things can do the same job, fill the same role, or preserve the same output profile without thereby being one and the same bearer.

So the archive should distinguish:

- **same function under different bearer**,
- **same bearer under changed component**,
- **same service under different substrate**,
- **same role under different occupant**,
- and **strict numerical identity only where the kind and continuity basis support it**.

Otherwise it will keep reading operational sameness as metaphysical sameness.

### 2. Part replacement is not the same as whole replacement

A ship, organism, device, or institution can survive some component substitution without thereby becoming a numerically new whole.

So the archive should distinguish:

- **local component substitution**,
- **distributed maintenance replacement**,
- **same wider bearer preserved across part-change**,
- **whole-target replacement only in stronger cases**,
- and **mixed cases only where enough structural change accumulates to threaten identity**.

Otherwise it will keep treating every swap as either trivial or catastrophic.

### 3. Stand-in occupancy is not the same as proxying

A substitute teacher, interim officer, or backup operator may temporarily occupy a role rather than merely transmit or execute the will of the original occupant.

So the archive should distinguish:

- **proxy enactment on behalf of another**,
- **temporary substitute occupancy of one role**,
- **same office with changed occupant**,
- **same organization under role continuity**,
- and **same original individual only in no cases at all**.

Otherwise it will keep flattening office continuity and performer continuity into one story.

### 4. Prosthetic supplementation is not the same as simple repair

A prosthesis, graft, scaffold, or substitute module can preserve or restore function without restoring the original material path.

So the archive should distinguish:

- **restoration of original part or route**,
- **supplementation by substitute support**,
- **same organism or mechanism under altered implementation**,
- **same capacity under prosthetic aid**,
- and **stronger replacement only where the bearer-conditions shift more deeply**.

Otherwise it will keep confusing repair, support, and replacement.

### 5. Fungible replacement is not the same as replacement of a nonfungible individual

Inventory units, budgeted supplies, and role-slots may tolerate replacement much more readily than historically individuated artifacts, organisms, or persons.

So the archive should distinguish:

- **fungible item replacement within one stock**,
- **nonfungible individual replacement**,
- **same reserve with different units**,
- **same slot with a different occupant**,
- and **same individual only where history and kind permit it**.

Otherwise it will keep overextending stock logic into person and artifact cases.

### 6. Realizer substitution is not the same as unrestricted kind identity

The same higher-level power or function may be realized in multiple ways, but that does not mean every different realization supports the same metaphysical kind at every grain.

So the archive should distinguish:

- **same higher-level function with different realizers**,
- **different realizers that still support one explanatory kind**,
- **different realizers that instead reveal different kinds at the relevant grain**,
- **organizational continuity across implementation change**,
- and **kind-splitting only where the explanatory and modal profile really changes**.

Otherwise it will keep turning multiple realization either into lazy anti-reductionism or into forced lower-level identity.

### 7. Origin and history can still matter under replacement

An artifact, office, institution, or organism may preserve one continuity basis while losing another. Replacement therefore has to be typed historically, not read off present function alone.

So the archive should distinguish:

- **spatiotemporal continuity**,
- **material-origin continuity**,
- **organizational continuity**,
- **role or legal continuity**,
- and **historical or origin-sensitive nonidentity even under excellent present fit**.

Otherwise it will keep treating present performance as the only continuity basis that matters.

## Typology of substitution cases

### A. Component substitution within one continuing bearer

The key feature is that a local part is swapped while the wider organized whole is treated as continuing.

**Examples:** replaceable ship plank; hot-swapped server drive; valve replaced within one hydraulic assembly.

### B. Stand-in or substitute occupancy of a continuing role

The key feature is that one role, office, or slot persists while the occupant changes temporarily or permanently.

**Examples:** interim chair; substitute teacher; backup controller taking an active seat.

### C. Prosthetic supplementation or grafted replacement

The key feature is that function is preserved or restored through a substitute component or support that is not simply the original part returned.

**Examples:** joint prosthesis; vascular graft; assistive communication device integrated into an ongoing activity-system.

### D. Realizer substitution under one higher-level function

The key feature is that one higher-level kind, role, or operation appears to persist through differing lower-level implementations.

**Examples:** one computational service across different hardware; one control function across changed circuitry; one cognitive or institutional role under reorganized implementation.

### E. Fungible stock replacement

The key feature is that one reserve, inventory, or slot-system remains the same while particular units are swapped, replenished, or rotated.

**Examples:** replacement bulbs in one supply stock; swapped cartridges in one inventory; rotating crew slots in one maintained shift structure.

### F. Successor replacement or re-founded continuation

The key feature is that replacement has gone deep enough that the best verdict may no longer be same bearer under substitution, but successor continuity, re-founding, or new-bearer formation.

**Examples:** rebuilt institution after charter rupture; complete artifact reconstruction under contested identity; staged system replacement marketed as the same service.

## Cross-domain pressure

### Artifacts and the Ship of Theseus family

Artifact cases pressure the archive because gradual part replacement can preserve one continuity basis while reassembly of the original parts seems to preserve another.

### Organisms, prostheses, and grafts

Organismic cases pressure the archive because one living bearer can persist through prosthetic aid, tissue substitution, or grafted support without making simple material continuity the only criterion.

### Institutions, offices, and role occupancy

Institutional cases pressure the archive because one office or organization can continue while occupants change, deputies substitute, or interim holders take over.

### Computation, infrastructure, and service continuity

Computational and infrastructural cases pressure the archive because one service can remain stable across hardware swaps, mirrored implementations, and changing local routes or modules.

## False moves to avoid

- Do **not** infer same bearer from every successful substitute.
- Do **not** infer new bearer from every local replacement.
- Do **not** infer proxying from every stand-in.
- Do **not** infer role continuity from every same-output case.
- Do **not** infer unrestricted fungibility from inventory-like cases.
- Do **not** infer same kind from every case of multiple realization.
- Do **not** infer that present function outranks all historical or origin-sensitive continuity constraints.
- Do **not** infer one flat relation from **substituted**, **replaced**, **swapped out**, **stand-in**, **surrogate**, **plug-compatible**, **functionally equivalent**, **hot-swapped**, or **same role with different material**.

## Default diagnostic questions

When a case is described as **substituted**, **replaced**, **swapped**, **standing in**, **plug-compatible**, **functionally equivalent**, **hot-swapped**, or **kept going by another component or occupant**, ask:

1. What exactly is the **target** — one artifact, one organism, one office, one institution, one service, one inventory, one person, or one mixed organization?
2. Is the case chiefly about **component substitution**, **stand-in occupancy**, **prosthetic supplementation**, **realizer substitution**, **fungible replacement**, **successor replacement**, or a mixed architecture?
3. What is actually **doing the continuity work** — sortal persistence, organizational constraint, role continuity, spatiotemporal continuity, material origin, legal designation, or mixed basis?
4. What is actually **doing the substitution work** — local part swap, graft, plug-compatible module, new occupant, reserve-unit replacement, alternate substrate, or mixed?
5. What remains **real underneath the replacement** — same bearer under changed part, same role with different occupant, same higher-level function under new realizer, same stock with different units, stronger successor only in harder cases, or mixed?
6. What is the nearest **comparison class** — repair, turnover, replenishment, rerouting, proxying, duplication, succession, or artifact?
7. What is the relevant **history profile** — gradual maintenance exchange, sudden substitution, staged migration, legally designated replacement, reassembly from originals, or mixed?
8. What is the relevant **fungibility profile** — nonfungible individual, partially interchangeable component, role-slot, reserve unit, or mixed?
9. What is the relevant **artifact-risk profile** — same label masking new target, same output hiding changed grain, marketing continuity, bookkeeping substitution, or mixed?
10. Whether the best verdict is **typed component substitution**, **typed stand-in occupancy**, **typed prosthetic supplementation**, **typed realizer substitution**, **typed fungible replacement**, **typed successor replacement**, **apparent substitution / label artifact**, or **still unsettled**.

## Compression rule

Future revisions should normally treat **substitution / replacement / stand-ins / functional equivalence** as one operator-family whenever the explanatory burden is: **changed component, occupant, or realizer; preserved or contested function; unresolved bearer-identity question; kind-sensitive continuity basis; and the need to distinguish same function, same role, same organization, same stock, and same individual rather than letting one of them settle the rest.**
