# CloudtainerML

## A small experiment should make a smaller, clearer claim

The early CloudtainerML snapshot is a collection of tiny transformer, memory and cache experiments. Its questions are more interesting than a generic promise of faster AI: when does selective verification erase a lossy-cache advantage, when is a reasoning boundary real rather than typographic, and what should persistent memory carry besides a belief?

Those questions invite a reader to examine the unit of inference. A symbolic probe, a trained model, a captured trace and a timing result on named hardware are not interchangeable evidence.

## What changes between the snapshots

The later revision’s dry-run, wheelhouse and cache-duplication work is largely about making that evidence path viable in an actual constrained environment. It should not be mistaken for a new model-quality or speed result simply because it makes a command easier to run.

The archive’s description of itself as a claim compiler is useful when read strictly: it should make the basis and limits of a claim inspectable, not upgrade a miniature experiment by giving it a larger packet. A reader should keep asking what measurement is present and which next measurement is still absent.

This reading edition did not download a model, execute a capture kit, rerun a probe or promote an archived next-action instruction. Hardware and performance claims remain those of their supplied evidence.

Read beside [DelayBasin](../DelayBasin/README.md) on continuity and experimental inference, and [TimeSync](../TimeSync/README.md) on the difference between a clean interface and trustworthy underlying support.
