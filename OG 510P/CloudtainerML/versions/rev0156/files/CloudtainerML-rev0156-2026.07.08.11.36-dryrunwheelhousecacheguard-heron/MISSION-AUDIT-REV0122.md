## Heart of the mission

CloudtainerML is still best understood as a **claim compiler**: it should convert an architecture claim into a cheap hostile falsifier, exact trace/provenance receipt, selector/evaluation receipt, portable reviewer handoff, named-hardware timing, and a promote/kill/pivot decision. Sparse attention is a test lane, not the product itself. If the sparse lane dies, the reusable product is the evidence discipline.

## What is missing

1. **A real immutable TinyLlama trace.** The active lane still has no accepted public NPZ/provenance pair from the intended runtime.
2. **An authenticated local snapshot proof.** Rev0121 checks structure well, but hash verification was optional and partly unwired; a local/mounted snapshot could be structurally plausible without proving it is exactly the pinned `model.safetensors`.
3. **Named-hardware end-to-end timing.** No performance promotion should happen without a named GPU/device/dtype/cache/kernel timing packet against dense and KV-management baselines.
4. **A baseline bracket strong enough to kill the sparse claim.** The minimum bracket should include exact IO-aware attention, paged/KV-cache serving systems, flexible compiled attention masks, and dynamic sparse long-context methods.
5. **A pivot/stop rule.** The cube needs an explicit point at which the answer becomes “claim compiler product” rather than another gate around absent evidence.

## What went severely wrong or wasteful

### 1. Evidence-lane gravity: gate craft is outrunning evidence

Rev0115 through rev0121 made real improvements, especially no-write reviewer verification, fail-fast prerequisite handling, phase separation, and snapshot structural integrity. But the deeper failure pattern remains: the project can spend many turns becoming a better gate machine while the decisive public trace is still absent. That is the core waste risk.

### 2. Snapshot hash semantics were not strong enough

`hf_snapshot_integrity.inspect_snapshot(..., include_hashes=False)` accepted structural integrity without digest proof. More importantly, `public_trace_snapshot_intake_audit.py --hash-weights` exposed a flag but did not pass it into `inspect_snapshot`, and the rev0121 prepare wrapper had no operator surface for requesting hash verification. Rev0122 wires this path so `HASH_WEIGHTS=1 bash artifacts/capture-kit/PREPARE_CURRENT_PUBLIC_TRACE_SNAPSHOT.sh` actually requests model weight hashing in the materializer/intake path.

This does not make hashing mandatory for the cheap fast gate; it makes the slower authenticity check real and available. The next policy change should be: **promotion acceptance requires a matching model.safetensors SHA-256 or a Hub/Xet content proof that is equivalently pinned.**

### 3. Metadata coherence checks are too narrow

The current metadata audits correctly catch stale `revision`, `package_name`, and core artifact fields, but stale lower-salience fields persisted in rev0121-era top-level JSONs, including old codenames/highlights and historical package labels. This is not promotion-fatal, but it erodes operator trust. Rev0122 records this as metadata-drift debt and updates the current metadata fields.

### 4. Generated bytecode was packaged and checksummed

Rev0121 included tracked `tools/__pycache__/*.pyc` files. That is small in bytes but bad in principle: generated interpreter artifacts should not be part of immutable evidence unless they are intentionally part of a binary toolchain proof. Rev0122 removes them from the working revision and regenerates checksums.

### 5. Fixture archaeology still taxes the reader

Many handoff fixture trees intentionally duplicate tools and receipts, which is useful for tamper tests but expensive cognitively. The cure is not blind deletion; it is content-addressed fixture storage plus generated latest/current views so reviewers see the active lane first and can expand history only when needed.

## What should change next

1. Run snapshot preparation with `HASH_WEIGHTS=1` after a complete snapshot is mounted or downloaded.
2. Make hash/authenticity proof a public-trace acceptance requirement, not merely an optional intake enrichment.
3. Keep the fast gate cheap, but split readiness language into three terms: `structurally_complete_snapshot`, `authentic_digest_checked_snapshot`, and `capture_runtime_ready`.
4. Add a metadata-drift audit that scans **all** top-level current JSON fields, not only the current identity whitelist.
5. Refuse doctrine-only turns: every future revision should either unblock snapshot/runtime/hardware, produce the trace, run a named-hardware baseline, or formalize the pivot.

## Speculation

My strongest speculation is that CloudtainerML's durable value will be higher as a falsification harness than as a sparse-attention claim. Sparse attention can still win, but probably only in a narrow systems-shaped lane: block/page-aligned layout, cheap selector metadata, GPU-friendly kernels, and workload-specific long-context retrieval/prefill behavior. If it cannot beat exact IO-aware attention plus modern KV-cache systems on named hardware, kill the sparse claim and keep the claim compiler.
