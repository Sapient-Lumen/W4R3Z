# Baby datacube shape notes — rev0002

This cube is not yet an implementation cube. It is a scouting cube with enough structure to survive handoff without calcifying too early.

## Lessons retained from example cubes

- Put a porch at the root: start, readme, current status, reentry contract, receipt.
- Keep machine ledgers beside human notes.
- Carry a validation command, even when the package is mostly research notes.
- Do not let archive structure become more important than the experimental surface.
- Prefer current-slice clarity over encyclopedic accumulation.

## Proposed minimum cell contract

Each experiment cell should have:

- one sentence question;
- source IDs;
- cheap first run;
- baselines;
- metrics;
- falsifier / demotion condition;
- status.

## Current axes

See `BABY-DATACUBE-CANDIDATE.json` for machine-readable axes.

The current axes are:

- architecture/memory mechanism;
