# Cross-case decision path

## What this note is for

The archive already has a compact **single-case** operator bridge in [`case-work-decision-path.md`](case-work-decision-path.md).
It now also has a fairly complete **cross-case** stack:
choose a comparison set, extract a recurring pattern, separate confidence burdens, name live rivals, confront the hardest deviant case, screen portability, stop when another case is no longer the most verdict-moving next move, handle null or mixed results honestly, and route any surviving consequence to the smallest honest target.

What it still lacked was the same thing the single-case path solved earlier:
**one short order of operations for multi-case work.**

That gap matters because a tight archive can fail in two opposite ways:
- it can re-explain the whole cross-case sequence in every memo preface until the front door regrows into the archive,
- or it can assume future readers will reconstruct the order from many thin bridge notes and quietly accept route drift, skipped burdens, or fake pattern confidence.

This note gives the archive one compact **cross-case operator path**.
It is not a new doctrine note and not a new dashboard.
It is a **routing bridge** for the comparison stack.
For the retained memo shape to use after this path is run, use [`cross-case-application-protocol.md`](cross-case-application-protocol.md).

## The archive's nine cross-case questions

A thin retained comparison should usually answer these questions in order:

1. **Which cases actually belong in the same retained comparison set?**
2. **What recurring pattern, if any, survives on the shared operator spine?**
3. **How much confidence belongs to the pattern, the mechanism story, portability, and any wider consequence?**
4. **What is the strongest live rival explanation or measurement rival?**
5. **What is the hardest deviant case, and what kind of anomaly is it?**
6. **What part of the lesson actually travels beyond the compared cases?**
7. **Would another case still be the most verdict-moving next move?**
8. **If no stable positive pattern survives, what is the smallest honest archive action?**
9. **If a lesson does survive, where should its consequence actually land?**

That sequence is the cross-case version of the archive's recurring workflow rule:
future comparison work should not have to rediscover the order of operations every time it moves from several memos to one retained lesson.

## Step 1. Build the comparison set before comparing

Start with [`comparison-set-selection-and-non-comparability.md`](comparison-set-selection-and-non-comparability.md).
Do not compare cases merely because they are vivid, famous, or all plausibly relevant.
The archive should first name one shared comparison question, one comparison level, and which candidate cases are excluded or postponed.

Output four short lines:
- **comparison question**
- **cases included**
- **cases excluded or postponed and why**
- **comparison level**

If those lines cannot be written cleanly, the archive usually does not need a retained comparison note yet.
It usually needs fresher memos, narrower cases, or a different question.

## Step 2. Extract the smallest real recurring pattern

Now use [`cross-case-comparison-and-pattern-extraction.md`](cross-case-comparison-and-pattern-extraction.md).
Keep the comparison on the archive's ordinary operator spine rather than inventing a bespoke mini-dashboard.
The aim is to identify the smallest recurring pattern that actually survives the compared cases.

Output three short lines:
- **shared pattern candidate**
- **shared mechanism candidate**
- **comparison consequence candidate**

At this stage the archive should still treat the pattern as provisional.
The point is to name what appears to recur, not to export it yet.

## Step 3. Separate the confidence burdens

Next use [`pattern-confidence-and-export-burdens.md`](pattern-confidence-and-export-burdens.md).
Do not let smooth prose or repeated appearance do the work of confidence.
Keep the burdens separate.

Output four labels:
- **pattern-existence confidence**
- **mechanism confidence**
- **portability confidence**
- **doctrine-consequence confidence**

This step protects the archive from a common false move:
writing as though a recurring pattern, a correct mechanism story, a portable lesson, and a doctrine consequence are all the same burden.
They are not.

## Step 4. Name the strongest live rival

Use [`pattern-rival-explanations-and-disconfirmation.md`](pattern-rival-explanations-and-disconfirmation.md).
A recurring pattern that never names its strongest rival is usually just coasting on elegance.

Output four short lines:
- **main live rival**
- **main measurement rival**
- **cleanest disconfirmation trigger**
- **next discriminating proof burden**

The archive should prefer the rival that would most shrink the claimed pattern if true, not the easiest rival to dismiss.

## Step 5. Confront the hardest deviant case

Use [`pattern-deviant-cases-and-anomaly-handling.md`](pattern-deviant-cases-and-anomaly-handling.md).
The archive should not export a pattern that survives only because its hardest contrary case was treated as a footnote.

Output four short lines:
- **hardest deviant case**
- **why it strains the pattern**
- **anomaly type**
- **archive consequence of the anomaly**

A deviant case does not automatically kill a pattern.
But it must be diagnosed before the pattern is allowed to travel.

## Step 6. Screen portability before wider reuse

Now use [`pattern-portability-and-transfer-limits.md`](pattern-portability-and-transfer-limits.md).
The archive should say what part of the lesson actually travels and what remains local, rail-dependent, or blocked.

Output four short lines:
- **portable core**
- **required rails for transfer**
- **local dependence**
- **transfer posture**

This step matters because recurrence alone is not yet transport.
A pattern may be real and still be case-family only.

## Step 7. Decide whether more cases would still move the burden

Use [`pattern-saturation-and-stopping-rules.md`](pattern-saturation-and-stopping-rules.md).
Cross-case work should not keep expanding merely because more plausible cases exist.
It should expand only when another case would still be the most verdict-moving next move.

Output four short lines:
- **saturation posture**
- **why enough / not enough yet**
- **next most verdict-moving case, if any**
- **archive consequence of that saturation posture**

This is the archive's anti-warehouse step for comparison work.

## Step 8. Handle nulls, mixed results, and parking honestly

If no stable positive pattern survives, or only a narrow local family survives, use [`pattern-null-results-and-parking-rules.md`](pattern-null-results-and-parking-rules.md).
The archive should not force signal from a comparison merely because the comparison already exists.

Output four short lines:
- **null-result posture**
- **what failed to survive**
- **smallest next discriminating move**
- **retention decision**

This step protects the archive against two opposite mistakes:
forced pattern confidence and needless retention of dead comparisons.

## Step 9. Route any surviving consequence to the smallest honest target

Only after the comparison has survived the earlier burdens should it use [`pattern-consequence-routing-and-revision-targets.md`](pattern-consequence-routing-and-revision-targets.md).
A real recurring lesson does not automatically belong in doctrine.

Output four short lines:
- **primary revision target**
- **why that target and not a larger one**
- **explicit non-consequence**
- **next governed route**

This is the archive's anti-spill step.
It stops every successful comparison from drifting upward by momentum.

## The one-screen output

A thin retained cross-case pass should usually be reducible to these nine blocks. When the archive retains an actual comparison memo, use [`cross-case-application-protocol.md`](cross-case-application-protocol.md) for the stable memo shape and keep this note as the order-of-operations bridge:

- **Comparison question / set / level**
- **Shared pattern candidate**
- **Confidence burdens**
- **Strongest rival and disconfirmation trigger**
- **Hardest deviant case and anomaly result**
- **Portability posture**
- **Saturation posture**
- **Null-result / parking posture, if relevant**
- **Consequence routing target, if relevant**

If the archive cannot state those blocks cleanly, it usually does not need more rhetorical confidence yet.
It needs a narrower set, a fresher memo, a cleaner rival test, a more honest portability screen, or a smaller consequence claim.

## False moves this note is meant to stop

### 1. Re-explaining the whole comparison stack in every memo

The archive already has the notes.
This path exists so future work can point through them rather than re-summarize them badly.

### 2. Treating multi-case work as if pattern extraction were the only burden

A pattern that has not survived rivals, anomalies, portability, and stopping discipline is not yet ready for consequence routing.

### 3. Letting successful comparison drift upward by momentum

A surviving lesson may still belong only in a case-family bridge, a package-routing note, or an evidence rule.
This path is built to keep consequences small until larger motion is actually earned.

## Fast use rule

When several live or exemplar cases seem to teach one shared lesson:

1. **Choose the comparison set.**
2. **Extract the smallest recurring pattern.**
3. **Separate the confidence burdens.**
4. **Name the strongest rival.**
5. **Confront the hardest deviant case.**
6. **Screen portability.**
7. **Decide whether another case still matters.**
8. **Handle nulls or parking honestly if no stable pattern survives.**
9. **Route any surviving consequence to the smallest honest target.**

## Bottom line

The archive now has the same thing for **cross-case** work that it already had for **single-case** work:
one compact order of operations.
Choose the set, extract the pattern, separate confidence, test rivals, confront anomalies, screen portability, stop when more cases would not really move the burden, handle nulls honestly, and route any surviving consequence to the smallest target that actually deserves revision.
