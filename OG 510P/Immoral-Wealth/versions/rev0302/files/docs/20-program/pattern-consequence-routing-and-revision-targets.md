# Pattern consequence routing and revision targets

## What this note is for

The archive can now choose a comparison set, extract a recurring pattern, state separate export burdens, name live rivals, confront the hardest deviant case, screen portability, and stop when another case is no longer the most verdict-moving next move.
What it still lacked was the thinner bridge **after** those steps:
**if a cross-case pattern survives, what part of the archive is actually supposed to move?**

That gap matters because multi-case work can still fail in two opposite ways:
- a recurring pattern gets promoted too far, too fast, and starts rewriting doctrine, package choice, or source priority all at once,
- or a real surviving lesson never changes anything because the archive has no compact rule for where the consequence properly belongs.

This note gives the archive a compact **consequence-routing rule**.
It is not a new doctrine note and not a replacement for promotion or doctrine-repair governance.
It is the bridge that says **which surface should move, which surface should stay put, and what burden is still missing** before anything larger is revised.[S15][S18][S19][S20][S21][S22][S23][S31][S32][S33]

## Minimum rule

A surviving cross-case pattern should usually move the **smallest archive surface that honestly fits the earned consequence**.
Do **not** start by asking whether doctrine moves.
Ask instead:

1. **what is the narrowest consequence the pattern has actually earned?**
2. **what archive surface carries that kind of consequence?**
3. **what larger surface explicitly does *not* move yet?**

If that third line cannot be stated, the archive is usually about to overreact.

## The archive's main consequence targets

A serious cross-case note should usually route its consequence to **one primary target**.
A named secondary target is allowed only when it is truly downstream of the same earned lesson.

### 1. No revision yet — keep the lesson inside the comparison note

Use this when the pattern is interesting but still too thin, too rival-exposed, too anomaly-strained, too local, or too unsaturated to justify any retained archive motion beyond the comparison itself.

Archive consequence:
- **retain as comparison output only**
- maybe add one narrow evidence debt
- **do not** rewrite package, doctrine, or source priorities yet

### 2. Case-family handling rule

Use this when the pattern mainly changes how a **family of cases** should be selected, grouped, compared, or read, without yet justifying wider doctrine motion.
This often means the lesson belongs in comparison-set discipline, portability screening, anomaly handling, or case-portfolio triage.

Archive consequence:
- **update a case-work bridge or family rule**
- keep doctrine still
- keep package guidance still unless the pattern clearly changes routing, not just description

### 3. Package-routing or tie-break consequence

Use this when the pattern most clearly teaches that, under a named breach / washout / rail profile, one opening package or tie-break cue should rank differently than before.
This is narrower than doctrine and should usually stay in the program-routing layer.

Archive consequence:
- **update opening-package routing or tie-break guidance**
- keep constitutional doctrine still unless the pattern really changes what counts as failure or near-pass

### 4. Evidence / measurement / source-priority consequence

Use this when the pattern mostly reveals that the archive is repeatedly misled by the same missingness, visibility regime, lag, or source architecture.
Then the right consequence is not yet a substantive rule but a sharper evidence demand or source-function priority.

Archive consequence:
- **update evidence-pack, scoreboard, or source-governance surfaces**
- keep doctrine and package layers still until the stronger evidence burden is met

### 5. Doctrine-motion candidate

Use this when the pattern is strong enough that the live question is no longer only case handling or package routing, but whether some archive-wide rule should be promoted, clarified, repaired, or demoted.
That does **not** mean doctrine moves automatically here.
It means the pattern has earned a governed doctrine question.

Archive consequence:
- route through [`../00-meta/case-to-doctrine-promotion-and-quarantine.md`](../00-meta/case-to-doctrine-promotion-and-quarantine.md) if the pattern seems to support a new or stronger live rule
- route through [`../00-meta/doctrine-revision-and-demotion-under-case-pressure.md`](../00-meta/doctrine-revision-and-demotion-under-case-pressure.md) if the pattern strains an already-live rule

The discipline is strict:
this note names the **target** of possible doctrine motion.
It does not itself rewrite doctrine.

## What a cross-case note should output about consequence routing

Keep this block to four short lines:

1. **primary consequence target** — one of the five targets above
2. **why this target, not a larger one yet** — one sentence only
3. **explicit non-consequence** — what surface does *not* move yet
4. **next governed route** — the exact note or surface that should receive the consequence

That is enough.
Do not turn consequence routing into a second doctrine essay.

## How this block should change nearby archive calls

### If the consequence stays inside the comparison note

Stop there.
Do not create a bridge just because the pattern sounds elegant.
The archive may only owe a sharper evidence debt or one next decisive case.

### If the consequence is case-family only

Patch the smallest relevant case-work bridge.
Do not let a case-family lesson masquerade as a universal rule.

### If the consequence is package-routing only

Move the consequence to program routing, not constitutional doctrine.
The archive should not let repeated implementation lessons quietly redefine what morally acceptable distribution means.

### If the consequence is evidence or source priority

Say so plainly.
Sometimes the real lesson is that the archive keeps asking a substantive question with the wrong evidence architecture.

### If the consequence is a doctrine-motion candidate

The archive should still route through governance.
A strong pattern can earn a doctrine question without yet earning a doctrine rewrite.

## What this note is meant to stop

### 1. Letting every real pattern rewrite doctrine

Not every recurring lesson is a constitutional rule.
Some lessons only sharpen package choice, evidence burden, or case-family boundaries.

### 2. Letting no pattern change anything

If a pattern has clearly earned a narrower archive consequence, the archive should state where it lands instead of quarantining every lesson as atmosphere.

### 3. Revising too many surfaces at once

A clean cross-case lesson should usually move one primary surface first.
If several surfaces seem to move together, the archive should say which one is primary and why the rest are downstream or still unchanged.

### 4. Confusing doctrine pressure with route pressure

Sometimes a pattern only shows that a bridge note, package router, or evidence rule is badly tuned.
That is not the same as a constitutional revision.

## Fast use rule

When a cross-case pattern survives comparison:

1. **Name the smallest consequence it has honestly earned.**
2. **Route that consequence to one primary archive target.**
3. **State what does not move yet.**
4. **If doctrine seems implicated, open a governed doctrine question instead of rewriting doctrine here.**
5. **Stop after the smallest honest motion.**

## Bottom line

The archive now has a thinner answer to a question that appears **after** pattern confidence, rivals, anomalies, portability, and stopping rules:
**where should the consequence of a surviving cross-case pattern actually land?**
Move the smallest surface that fits the earned lesson, name what stays still, and let doctrine move only through its own governed repair or promotion path.
