# Case-portfolio caps and retirement

## What this note is for

The archive now has a rule for **which candidate cases deserve memo work first**.
What it still needs is the follow-on discipline:
**how many full retained case memos should remain live at once, when should one be downgraded, and what should survive after retirement?**

Without that rule, the archive can make a good choice at the front of the queue and still drift into a warehouse later.
A case that once earned a memo can keep occupying bytes long after it stopped carrying live routing value.
This note is therefore about **portfolio waist control after selection**, not about forgetting cases or pretending they never mattered.

## Minimum rule

The archive should keep only a **small active case portfolio**.
A new retained case memo should usually either:

1. fill an empty portfolio slot,
2. displace a weaker live case,
3. replace several near-duplicate cases with one cleaner exemplar,
4. or prove that an older memo now belongs in a shorter stub.

If it does none of those, the default answer should usually be:
**do not retain another full case memo yet.**
Use a citation, a ledger line, temporary scratch, or a paragraph inside a current memo instead.

## The active-portfolio cap

Treat this as the archive's default retained shape:

- **1-2 urgent live cases**
- **1 exemplar case**
- **0-1 proof-building case**
- **0-1 transition/watch case** only when it is genuinely teaching something the archive cannot otherwise see

That means the archive should usually tolerate **no more than 4 or 5 full retained case memos** at once.
The cap is soft, not sacred.
But going above it should require an explicit reason in the revision receipt because the archive's danger is not merely missing cases.
It is quietly turning into a casebook.

## The four retained case statuses

A real-case memo should usually sit in one of four portfolio statuses.

### 1. Live active case

Use this when the memo is still doing real present work:
- ongoing harm is high,
- delay still matters,
- the watch posture is live,
- or the memo is still anchoring a current routing problem.

A live active case earns fuller retained detail because the archive may need to revisit it soon.

### 2. Live exemplar

Use this when the memo is not the main urgent case anymore but still teaches a recurring pattern especially well.
The exemplar should remain because later work can route through it.
It should not remain merely because it once consumed effort.

### 3. Proof-building support case

Use this when the memo remains useful mainly because it resolves a repeated evidence, measurement, or routing uncertainty.
This bucket should stay small.
If the proof question is now resolved elsewhere, the memo usually loses its claim on full retained status.

### 4. Retired stub

Use this when the memo once mattered but no longer deserves full retained detail.
A retired stub keeps only the minimum memory needed to avoid confusion and accidental reinvention.
It is **not** a live routing anchor.

## What a retired stub should keep

A retired stub should usually keep only five things:

1. **case name / scope**
2. **last certification or review date**
3. **why the case once mattered**
4. **what safely carries forward, if anything**
5. **what note or newer memo now supersedes it**

If more than that is needed, the case may not be ready for retirement.
If less than that is kept, later readers may not know whether the case was forgotten, disproved, merged, or merely parked.

## Retirement triggers

A full retained case memo should usually be downgraded when one or more of these conditions hold.

### 1. The pattern is already covered by a cleaner exemplar

If the memo no longer teaches anything distinct and a shorter, cleaner exemplar now does the same job, retire the duplicate.
The archive does not need four versions of the same lesson.

### 2. The case is stale beyond safe soft reuse

If the memo now fails the reuse screen in [`case-staleness-and-recertification.md`](case-staleness-and-recertification.md), it should not remain in the portfolio pretending to be live.
Either recertify it or retire it.

### 3. The watch posture is no longer live

If the case no longer has an active build / reroute / ratchet / reopen burden, and its main value is only historical memory, a stub often does the job better than a full memo.

### 4. The memo lost routing value

A case can still be morally important yet stop teaching the archive anything reusable.
When that happens, keep a short reference if needed, not a full retained anchor.

### 5. The portfolio is crowded by a stronger entrant

If a new candidate has higher present harm, higher delay cost, better generalizable routing value, or fixes a portfolio blind spot, an older weaker memo should be the first place to recover bytes.

### 6. The theory has absorbed the lesson

Sometimes a case memo matters because it forces a new doctrine or bridge. Route that promotion question through [`../00-meta/case-to-doctrine-promotion-and-quarantine.md`](../00-meta/case-to-doctrine-promotion-and-quarantine.md) instead of letting the case silently become doctrine by reuse. Once that lesson has been cleanly absorbed into the archive's stable notes, the full memo may no longer earn its old weight.

## When retirement should not happen yet

Do **not** retire a case memo merely because:
- it is old,
- the politics around it cooled,
- a new case is more fashionable,
- or the archive feels guilty about file count.

Retain the memo when it still does any of the following:
- anchors a live monitoring burden,
- remains the cleanest exemplar for a recurring pattern,
- carries a proof-building problem the archive has not yet solved elsewhere,
- or provides the best safe route through a still-active case family.

## How to decide between recertify, trim, and retire

When an older case comes up for review, ask these questions in order:

1. **Is the case still live enough to justify recertification?**
2. **If not, does it still teach a recurring pattern better than current alternatives?**
3. **If not, what five-line stub would preserve the archive's memory without keeping a full memo alive?**

That gives three ordinary outcomes:
- **recertify** when the case is still live,
- **trim to exemplar** when the case still teaches but no longer needs full operational detail,
- **retire to stub** when its main value is memory rather than routing.

## The displacement rule

A new retained memo should usually name its displacement cost.
It should answer one of these questions explicitly:

- **Which current active memo becomes redundant because of this one?**
- **Which current memo drops to exemplar or stub status because this one now teaches the pattern better?**
- **Which empty portfolio slot is this filling, and why was the slot genuinely empty?**

If a new memo cannot answer one of those, it usually has not yet earned permanent space.

## The main false moves this note is meant to stop

### 1. Mistaking retention for seriousness

A case does not become more morally serious because the archive keeps a long memo about it forever.
Retention should follow current routing value, not archival sentiment.

### 2. Confusing retirement with forgetting

Retirement means the archive no longer needs the full memo active.
It does not mean the case no longer mattered.
That is why the stub rule exists.

### 3. Letting every active case become an exemplar

An exemplar should be rare and clean.
If every finished memo becomes an exemplar, exemplar has stopped meaning anything.

### 4. Keeping stale memos alive as soft authority

An unrecentified memo should not linger in the live portfolio if later readers can mistake it for current judgment.
Either refresh it or demote it.

### 5. Building a parking lot of mini-memos

The archive should not respond to the cap by keeping many almost-full "retired" memos under another name.
A retired stub should really be short.

## Fast use rule

Use this note in six moves:

1. **Keep the active portfolio small.**
2. **Classify each retained case as live active, live exemplar, proof-building support, or retired stub.**
3. **Require new full memos to fill a slot, displace a weaker memo, or collapse duplicates.**
4. **Use recertification when the case is still live; otherwise prefer trim or retirement.**
5. **Keep retired stubs to five lines of memory, not mini-memos.**
6. **Treat portfolio crowding as a reason to recover bytes, not a reason to normalize sprawl.**

## Bottom line

The archive now has a compact answer to a question that sat just downstream of case selection:
**once case memos exist, how many should remain active, and what happens to the rest?**
Keep a small live portfolio, make new memos pay their displacement cost, and retire old cases into honest stubs once they stop carrying live routing value.
That preserves memory without letting case work quietly become the archive.
