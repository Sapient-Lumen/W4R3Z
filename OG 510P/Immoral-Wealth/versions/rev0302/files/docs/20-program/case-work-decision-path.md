# Case-work decision path

## What this note is for

The archive now has a strong set of case-work parts: evidence discipline, source-order discipline, verdicts, breach selection, package routing, confidence labels, reroute rules, ratchet rules, and reopen rules.
What it still lacked was one **short operator bridge** that says what order to use those parts in before drafting a memo.

This note is that bridge.
It is not another theory branch and not another memo template.
It is a **decision sequence** for moving from raw case evidence to a governed next move without re-synthesizing half the archive each time.
When the archive is deciding whether a candidate case deserves a retained memo at all—or whether an older memo still deserves a live slot—route that upstream portfolio question through [`case-portfolio-triage-and-memo-selection.md`](case-portfolio-triage-and-memo-selection.md) and [`case-portfolio-caps-and-retirement.md`](case-portfolio-caps-and-retirement.md) rather than bloating the case path itself. When the archive instead has several live or exemplar cases already on the table, route that work through [`cross-case-decision-path.md`](cross-case-decision-path.md) so the comparison stack stays in one stable order instead of being reassembled by hand in every memo preface.

## The archive's shortest case-work path

A serious real-case pass should usually answer these nine questions in order:

1. **Do we have enough evidence to judge without pretending?**
2. **What is the verdict right now?**
3. **Which breach is doing the most constitutional damage now?**
4. **Which washout channel would erase visible gains fastest?**
5. **Which governing mode fits the case?**
6. **Which opening package follows from that diagnosis?**
7. **How much confidence belongs to the verdict, the package, the rails, and any softer reading?**
8. **What watch posture follows now: build, reroute, ratchet, or reopen?**
9. **How often should the case be reviewed again, when should continued miss force reroute, and what ordinary pressure must any softer reading still survive?**

That sequence is the archive's compact answer to a recurring workflow problem:
future case work should not have to rediscover the order of operations every time it tries to move from diagnosis to action.

## Step 1. Evidence gate: enough to judge, not enough to fantasize

Start with [`minimum-evidence-pack-for-case-work.md`](minimum-evidence-pack-for-case-work.md).
Then use [`source-order-and-conflict-resolution.md`](source-order-and-conflict-resolution.md) to sort missingness, undercapture, timing mismatch, and real disagreement.

Output one short line:
- **evidence posture:** sufficient / thin but usable / too thin for a clean package call.

The archive's standing rule is strict here:
missing top-tail visibility, weak group disaggregation, or household-only balance-sheet comfort should usually harden certification rather than soften concern.
If the evidence is too thin for a strong package comparison, the case may still be thick enough for a failing verdict and for lower-regret corrective moves.

## Step 2. Verdict first

Before choosing instruments, classify the case with [`../10-framework/constitutional-verdicts-for-wealth-orders.md`](../10-framework/constitutional-verdicts-for-wealth-orders.md).
Do not start from the package.
Start from the constitutional reading.

Output one short line:
- **verdict:** structurally failing / correction-required / provisional near-pass / near-ideal.

The archive's discipline here is simple:
shares are first-screen evidence, not the whole judgment.
A case can still fail near the numbers when the floor is thin, control remains concentrated, circulation is too inherited, public counterweight is too weak, or proof is too incomplete.

## Step 3. Name the dominant breach

Use [`dominant-breach-and-fastest-washout-selection.md`](dominant-breach-and-fastest-washout-selection.md) to choose the one failure doing the most mass constitutional damage now.
At most one genuine secondary breach should survive this cut.

Output one short line:
- **dominant breach:** floor failure / late footholds / dynastic closure / rent-washout / control concentration / wealth-to-rule conversion / thin public counterweight / another clearly named archive surface.

If this step is skipped, future work usually drifts into policy-shopping.
The package starts reflecting taste rather than diagnosis.

## Step 4. Name the fastest washout

Choose the channel that would erase visible gains fastest if left open.
This is often housing and land, debt and carrying costs, monopoly tolls, opacity, or public downside absorption.
It is related to the dominant breach, but it is not always the same thing.

Output one short line:
- **fastest washout:** the channel most likely to reabsorb progress first.

This step matters because the archive does not count all improvements as equally durable.
A package that helps on paper while leaving the main washout channel open is usually missequenced.

## Step 5. Place the case in a governing mode

Now use [`mode-selection-and-escalation-heuristic.md`](mode-selection-and-escalation-heuristic.md).
The question is not just how bad the distribution looks.
The question is what posture the case now requires: ordinary prevention, active correction, or harder anti-oligarchy response.

Output one short line:
- **mode:** prevention / correction / anti-oligarchy response.

This prevents a common false move: treating the same instrument as if it means the same thing across a still-governable case and a capture-heavy one.

## Step 6. Route to one opening package

Only after verdict, dominant breach, washout, and mode are clear should the archive pick a package.
Use [`opening-package-router.md`](opening-package-router.md) first.
If more than one plausible lane mix survives, use [`package-choice-and-tie-break-rules.md`](package-choice-and-tie-break-rules.md).

Output two short lines:
- **opening package:** the one lane mix nearest-real for this case.
- **rail / gating posture:** what can begin now, what must build rails while moving, and what remains gated.

The archive should prefer the package that most cleanly hits the breach, closes the washout channel, improves lower-half or entrant position earlier, fits actual rails more honestly, and creates the least new proof debt.

## Step 7. State confidence separately

Now add confidence using [`confidence-labels-and-action-under-proof-debt.md`](confidence-labels-and-action-under-proof-debt.md).
Keep four questions separate.

Output four short labels:
- **verdict confidence**
- **package confidence**
- **rail confidence**
- **pass / de-escalation confidence**

This protects the archive from a familiar drift.
It can be highly confident that a case is still failing while only moderately confident that one package is best and weakly confident that softer certification is warranted.

## Step 8. Choose the watch posture that follows

After the package call, the archive still needs to know what happens next.
Use one of four postures, then use [`next-scoreboard-and-evidence-debt-selection.md`](next-scoreboard-and-evidence-debt-selection.md) to keep the case close narrow rather than re-pasting the whole dashboard.
Then use [`review-cadence-and-durability-window-selection.md`](review-cadence-and-durability-window-selection.md) to say how often the case should be re-read, how long continued miss is allowed before reroute, and what ordinary reversal channel a softer reading still has to survive.


### A. Build

Use this when the package is chosen but not yet launched or too early to narrate.
End with the next scoreboard and the main evidence debt.

### B. Reroute

Use [`package-monitoring-and-reroute-triggers.md`](package-monitoring-and-reroute-triggers.md) when the package is underway but missing on passage, retention, closure, skew, capture, or rail strain.

### C. Ratchet

Use [`hardening-gains-into-ratchets.md`](hardening-gains-into-ratchets.md) when the package is landing and the main question is how to make the gain harder to reverse before speaking too softly.

### D. Reopen

Use [`provisional-passes-and-reopening-triggers.md`](provisional-passes-and-reopening-triggers.md) when the case is being read more softly and the archive must state what would automatically reopen correction.

Output one short line:
- **watch posture:** build / reroute / ratchet / reopen.

This is the step that keeps case work from stopping too early.
A package choice is not the end of the archive's job.

If the memo will later be reused rather than freshly rewritten, the archive should then run [`case-staleness-and-recertification.md`](case-staleness-and-recertification.md) before carrying its softer language, package call, or rail reading forward as if still current. If several memos now seem to teach a wider recurring lesson, first route that question through [`cross-case-decision-path.md`](cross-case-decision-path.md) and then through [`pattern-consequence-routing-and-revision-targets.md`](pattern-consequence-routing-and-revision-targets.md) so the archive names whether the earned motion belongs in a case-family bridge, package-routing surface, evidence rule, or only as a governed doctrine question. If the memo also seems to teach a wider rule after that routing step, use [`../00-meta/case-to-doctrine-promotion-and-quarantine.md`](../00-meta/case-to-doctrine-promotion-and-quarantine.md) rather than letting one live case become archive-wide doctrine by momentum. If the memo instead repeatedly strains an already-live archive rule, route that doctrine-repair question through [`../00-meta/doctrine-revision-and-demotion-under-case-pressure.md`](../00-meta/doctrine-revision-and-demotion-under-case-pressure.md) rather than forcing future readers to keep the caveat in their heads.

## Step 9. Add the timing burden

After the watch posture is chosen, add the case's timing burden with [`review-cadence-and-durability-window-selection.md`](review-cadence-and-durability-window-selection.md).
Keep three questions separate.

Output three short lines:
- **review cadence**
- **reroute horizon**
- **durability window**

The archive should usually review earliest, reroute next, and certify last.
That keeps it from waiting too long to correct a missing package while also blocking one good interval from doing the work of a real durability window.

## The one-screen output

A thin real-case pass should usually be reducible to these twelve lines:

- **Case and date**
- **Evidence posture**
- **Verdict**
- **Dominant breach**
- **Fastest washout**
- **Mode**
- **Opening package**
- **Rail / gating posture**
- **Confidence labels**
- **Watch posture**
- **Next scoreboard / evidence debt**
- **Review cadence / reroute horizon / durability window**

If those lines cannot be filled honestly, the archive usually does not need more rhetoric yet.
It needs better evidence, a cleaner breach choice, a more honest rail reading, a tighter next scoreboard, or a less theatrical package claim.

## The main false moves this note is meant to stop

### 1. Starting with favorite instruments

The archive should not begin from a preferred tax, fund, ownership form, or emergency stance and then reverse-justify the diagnosis.

### 2. Collapsing verdict, package, and confidence into one feeling

A case can be clear on the verdict and unclear on the best package.
It can be clear on the package and unclear on rail readiness.
It can improve without earning softer certification.
The archive should keep those judgments separate.

### 3. Letting uncertainty soften the reading by default

Thin visibility at the top, poor group breakdowns, or household masking should usually block comfort, not grant it.

### 4. Stopping at package choice

The archive should not act as if naming an opening package finishes the work.
The real next step may be build, reroute, ratchet, or reopen.

## Fast use rule

Use this note in seven moves:

1. **Gate on evidence.**
2. **Set the verdict before naming instruments.**
3. **Choose one dominant breach and one fastest washout.**
4. **Choose the mode, then the package, then the rail posture.**
5. **Label confidence separately across verdict, package, rails, and softer readings.**
6. **End with a watch posture: build, reroute, ratchet, or reopen.**
7. **Add the timing burden: review cadence, reroute horizon, and durability window.**

## Bottom line

The archive now has a thinner answer to a practical question that kept showing up between notes:
**in what order should a real case be judged and routed?**
The answer is: evidence first, verdict first, breach first, washout first, mode before package, confidence kept separate, watch posture named explicitly, and timing attached before the memo closes.
That is the shortest path the archive now offers from raw case evidence to a governed next move.
