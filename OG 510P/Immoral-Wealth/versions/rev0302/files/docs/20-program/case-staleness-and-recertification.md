# Case staleness and recertification

## What this note is for

The archive now has a compact rule for choosing a case's **next scoreboard**, **review cadence**, **reroute horizon**, and **durability window**.
What it still lacked was the equally thin rule for a different problem:
**when an already-written case memo has gone stale enough that it should not be casually reused as if nothing important has changed.**

That matters because future archive work will accumulate real-case passes over countries, cities, sectors, and cohorts.
Without a recertification rule, those memos can quietly become cached authority: reused after asset repricing, policy reversal, new controller visibility, or stronger group evidence without saying which parts are still live and which parts are not.[S04][S05][S06][S15][S17][S20][S23][S31][S32][S33]

This note gives the archive a compact way to decide whether an older memo is still usable, partly salvageable, or in need of fresh recertification.
It is not another full memo template.
It is a **reuse discipline**.

## Minimum reading rule

Do not reuse an old case memo just because no single dramatic event happened.
Reuse should depend on whether the memo's **verdict, package call, rail reading, or softer certification** still rests on live enough evidence and a still-recognizable institutional situation.
When the underlying case has materially moved, the memo should be refreshed, narrowed, or recertified rather than casually cited forward.[S04][S05][S06][S15][S17][S20][S23][S31][S32][S33]

In compact form:

- treat **verdict reuse** as the easiest claim to preserve,
- treat **package reuse** as harder,
- treat **rail reuse** as harder still,
- and treat **soft certification reuse** as strictest.

The archive should usually be able to salvage some of an older memo.
But it should salvage only the part that still has a live factual and institutional footing.

## The four different things that can go stale

### 1. Verdict staleness

A verdict becomes stale when the case's constitutional reading may have moved: for example after a major floor shock, large asset repricing, new inheritance channel evidence, newly visible controller concentration, new excluded-group evidence, or meaningful strengthening or weakening of public/common counterweight.[S05][S06][S15][S17][S18][S19][S20][S23][S31][S32][S33]

### 2. Package staleness

A package call becomes stale when the memo's chosen opening package may no longer be the nearest-real move because the dominant breach changed, the fastest washout changed, the package already launched and missed, or a formerly gated lane became newly feasible.[S04][S07][S12][S15][S20][S21][S22][S23][S31][S36][S39][S40]

### 3. Rail staleness

A rail reading becomes stale when the case's delivery, visibility, enforcement, or anti-capture capacity materially changed.
That can happen through registry improvement, enforcement degradation, fiscal retrenchment, political capture, administrative simplification, or the opposite.[S04][S15][S23][S31][S32][S33][S36][S39][S40]

### 4. Soft-certification staleness

A provisional near-pass, de-escalation, ratchet, or near-acceptable reading becomes stale fastest whenever the durability window has not yet been passed, was passed only under one unusually calm interval, or has been broken by ordinary pressure that the earlier memo had not yet faced.[S05][S06][S13][S20][S23][S31][S32][S33]

## The standing recertification triggers

A memo should usually be recertified, not merely recopied, when one of these things is true.

### 1. A main moral surface materially moved

Recertify when one of the memo's main relied-on surfaces materially changed:
- floor reality,
- lower-half footholds,
- housing / debt washout,
- top-tail visibility or concentration,
- wealth-to-rule conversion,
- public/common counterweight,
- or excluded-group access.[S07][S13][S15][S17][S18][S19][S20][S21][S22][S23][S31][S32][S33][S36]

### 2. The source picture changed enough to move confidence

Recertify when a source refresh, new registry, new disaggregation, revised national accounts, better inheritance evidence, or stronger controller visibility materially raises or lowers confidence in the memo's verdict, package, rail reading, or softer language.
Use [`../00-meta/source-refresh-and-citation-compression.md`](../00-meta/source-refresh-and-citation-compression.md) and [`source-order-and-conflict-resolution.md`](source-order-and-conflict-resolution.md) here.[S04][S15][S16][S20][S23][S31]

### 3. The watch posture changed

A **build** memo that now needs **reroute** should not be reused as a build memo.
A **ratchet** memo that now needs **reopen** should not be reused as if the case were still on the ratchet path.
The watch posture is part of the memo's live meaning, not a decorative epilogue.

### 4. The governing mode changed

If the case crossed from ordinary **prevention** into **correction** or **anti-oligarchy response**, or moved back the other way, recertify.
Mode shifts change what the same instrument means and what kind of confidence or coerciveness is warranted.[S15][S23][S31][S32][S33]

### 5. The timing burden expired or was broken

If the memo's stated review cadence has plainly passed without refresh, its reuse should already become more cautious.
If the reroute horizon has passed with continuing miss, or if the durability window was broken by ordinary pressure, the memo should be recertified before being cited as if still current.[S05][S06][S20][S23][S31][S32][S33]

## The archive's four memo-status labels

When reusing an older case memo, add one short status line.

### A. Live

Use **live** only when the memo's core surfaces, sources, mode, posture, and timing burden are still recognizably current.
This is the strongest status and should be used sparingly for anything softer than a failing verdict.

### B. Live but refresh due

Use this when the memo is still directionally usable, but its stated review cadence has arrived or its evidence support is aging enough that a refresh should happen before the next major soft claim.
This status is often acceptable for hard verdicts and rough package posture, but not for comfortable certification.

### C. Partly stale; salvageable

Use this when some parts still stand but others do not.
The archive should then say what can still be carried forward:
- verdict only,
- verdict plus mode,
- or verdict plus narrow watch posture.
Do not carry forward the old package, rail confidence, or softer language unless those parts were actually re-read.

### D. Recertify before soft reuse

Use this when the memo would otherwise be used to justify a softer verdict, de-escalation, or a claim that the case is now safer than before.
This should be the default label whenever the durability window has not clearly held or the evidence picture materially improved or worsened since the memo was written.

## What a thin reuse block should output

When an older case memo is reused, add four short lines:

- **memo status** — live / live but refresh due / partly stale; salvageable / recertify before soft reuse
- **stale surface** — what changed or aged enough to matter
- **safe carry-forward scope** — verdict only / verdict plus mode / verdict plus watch posture / full memo still live
- **next recertification trigger** — the event, source refresh, or timing point that would force a fresh pass

This keeps archive memory usable without letting memory impersonate present judgment.

## The four main false moves this note is meant to stop

### 1. Treating silence as stability

A memo does not stay live just because nobody rewrote it.
A quiet period can still hide repricing, capture, drift in claiming, deteriorating rails, or new controller visibility.

### 2. Letting one old package call keep ruling after the diagnosis moved

Once the dominant breach or fastest washout changes, the old package should no longer enjoy automatic authority.
That is how case work turns into favorite-instrument inertia.[S15][S18][S19][S20][S21][S22][S23]

### 3. Confusing review cadence with recertification discipline

Review cadence tells the archive **when to look again while a live posture is underway**.
Recertification discipline tells the archive **whether an already-written memo is still safe to reuse as current authority**.
Those are related but different burdens.

### 4. Reusing soft language more casually than hard language

The archive should usually be more willing to carry forward a still-failing verdict than a comforting near-pass, de-escalation, or near-ideal reading.
Soft language should expire faster than hard caution.[S05][S06][S15][S20][S23][S31][S32][S33]

## Fast use rule

When an older case memo is about to be cited forward:

1. **Check whether its review cadence, reroute horizon, or durability window has already matured or been broken.**
2. **Ask whether the dominant breach, fastest washout, mode, or rails still look like the same case.**
3. **Ask whether source refreshes or new visibility would move confidence materially.**
4. **Carry forward only the narrowest part that is still honestly live.**
5. **Require fresh recertification before using old work to justify softer language.**

## Bottom line

A good archive should accumulate judgment without pretending that old judgment stays current forever.
This note gives the archive a narrow middle path between two bad extremes:
**rewriting every case from zero whenever anything changes, and casually recycling stale memos as if they were still fresh authority.**
The archive should preserve what still stands, narrow what no longer does, and recertify before comfort travels farther than the evidence or the case itself will bear.[S04][S05][S06][S15][S20][S23][S31][S32][S33]
