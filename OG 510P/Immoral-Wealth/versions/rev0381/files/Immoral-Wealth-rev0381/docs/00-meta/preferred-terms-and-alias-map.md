# Preferred terms and alias map

## What this note is for

[`term-discipline-and-synonym-control.md`](term-discipline-and-synonym-control.md) gives the archive the rule.
This note is the **short reusable map** of recurring terms that now deserve stable wording across revisions, routes, and case memos.

It is not a second authority layer.
Each parent anchor remains the place where the concept is actually defined and tightened.

## Working map

- **immoral wealth inequality** — keep for the archive's root object; avoid rotating among plutocratic inequality, pathological concentration, or extreme inequality when the archive means the same thing. Anchor: [`../10-framework/immoral-wealth-inequality.md`](../10-framework/immoral-wealth-inequality.md)
- **near-ideal / constitutionally acceptable** — keep for the archive's soft-positive verdict; avoid multiplying near-enough, acceptable order, or good-enough order as separate verdict labels. Anchor: [`../10-framework/constitutional-verdicts-for-wealth-orders.md`](../10-framework/constitutional-verdicts-for-wealth-orders.md)
- **dominant breach** — keep for the main live failure; avoid main failure, lead breach, or primary defect. Anchor: [`../20-program/dominant-breach-and-fastest-washout-selection.md`](../20-program/dominant-breach-and-fastest-washout-selection.md)
- **fastest washout** — keep for the channel that would erase visible gains fastest; avoid rebound channel or reabsorption path. Anchor: [`../20-program/dominant-breach-and-fastest-washout-selection.md`](../20-program/dominant-breach-and-fastest-washout-selection.md)
- **opening package** — keep for the first serious lane mix; avoid starter bundle, first bundle, or initial platform. Anchor: [`../20-program/opening-package-router.md`](../20-program/opening-package-router.md)
- **rail / gating posture** — keep for what can begin now, what must build rails while moving, and what stays gated; avoid implementation mood or readiness stance as rival categories. Anchor: [`../20-program/minimum-viable-implementation-stack.md`](../20-program/minimum-viable-implementation-stack.md)
- **proof debt** — keep for the missing proof that still blocks a cleaner action claim; do not collapse it into evidence debt. Anchor: [`../20-program/confidence-labels-and-action-under-proof-debt.md`](../20-program/confidence-labels-and-action-under-proof-debt.md)
- **evidence debt** — keep for the missing proof that could still move the next judgment; do not collapse it into proof debt. Anchor: [`../20-program/next-scoreboard-and-evidence-debt-selection.md`](../20-program/next-scoreboard-and-evidence-debt-selection.md)
- **watch posture** — keep for build / reroute / ratchet / reopen; avoid follow-up mode or monitoring stance as fresh doctrine. Anchor: [`../20-program/case-work-decision-path.md`](../20-program/case-work-decision-path.md)
- **reroute horizon** — keep for how long continued miss is allowed before reroute; avoid tolerance window or package grace period. Anchor: [`../20-program/review-cadence-and-durability-window-selection.md`](../20-program/review-cadence-and-durability-window-selection.md)
- **durability window** — keep for how long improvement must survive ordinary pressure before softer language hardens; avoid settlement window or proof-of-stickiness period as separate categories. Anchor: [`../20-program/review-cadence-and-durability-window-selection.md`](../20-program/review-cadence-and-durability-window-selection.md)
- **canonical anchor** — keep for the main note in a cluster; avoid lead note or primary file as standing archive vocabulary. Anchor: [`canonical-anchors-and-bridge-note-discipline.md`](canonical-anchors-and-bridge-note-discipline.md)
- **active bridge** — keep for a helper note that closes one recurring gap without becoming a rival anchor; avoid sidecar or satellite note as permanent categories. Anchor: [`canonical-anchors-and-bridge-note-discipline.md`](canonical-anchors-and-bridge-note-discipline.md)
- **superseded stub** — keep for an old note retained only as a redirect or memory aid; avoid dead note or legacy shard unless a real status distinction is needed. Anchor: [`note-status-and-supersession-discipline.md`](note-status-and-supersession-discipline.md)

## Use rule

When a future revision wants a new phrase for one of these concepts, the default move should be:

1. reuse the preferred term,
2. mention the alias only once if clarity really requires it,
3. then fold back to the preferred term immediately.

If the new phrase would change the decision, proof burden, route, or boundary between concepts, tighten the parent anchor first.

## Refactor trigger

Update this map only when:

- a recurring concept has become stable enough to deserve a preferred term,
- a real confusion has appeared across routes or case memos,
- or an alias has become common enough that the archive now needs to suppress it explicitly.

## Bottom line

The archive should not make future revisions rediscover its working vocabulary by feel.
This note keeps the short reusable map of terms that now do enough work to deserve deliberate stability.
