# Pattern null results and parking rules

## What this note is for

The archive can now choose a comparison set, extract a recurring pattern, separate confidence burdens, name live rivals, confront the hardest deviant case, screen portability, and stop when another case would no longer be the most verdict-moving next move.
What it still lacked was the compact bridge for a different but common outcome:
**what to do when a comparison does not support a stable positive pattern yet.**

That gap matters because multi-case work can fail in two opposite ways:
- it can **force a positive pattern** out of thin or mixed comparison work because the archive feels pressure to “learn something larger,”
- or it can **warehouse every inconclusive comparison** as if each one deserved permanent memo weight.

This note gives the archive a thin rule for handling **null, mixed, collapsed, or not-yet pattern findings** without treating them as either empty noise or hidden doctrine.
It is not a null-results warehouse.
It is a **parking and retention discipline**.

## Minimum rule

A retained cross-case pass should usually say **one of four things** before it routes any wider consequence.

1. **A stable positive pattern survives.**
2. **No stable pattern survives yet.**
3. **A narrow local or case-family pattern survives, but wider export does not.**
4. **The comparison is not worth retaining as a live comparison note right now.**

If the comparison cannot state which of those postures it is in, it is usually still too blurry, too stale, or too mixed to deserve consequence routing.

## The archive's null-result classes

### 1. Too thin or too stale to learn much yet

Use this when the comparison set still looks promising but memo freshness, evidence quality, or claim-level mismatch is too weak for an honest recurring lesson.
This is not a positive pattern and not a negative pattern.
It is a **not-yet**.

### 2. Mixed comparison with one unresolved splitter

Use this when a recurring pattern partly appears but one unresolved splitter still does too much work.
Typical splitters are:
- a rail difference the archive has not yet isolated,
- a measurement mismatch still doing too much explanatory work,
- or a deviant case that may be repairable but has not yet been diagnosed cleanly.

This posture means:
**do not export the pattern yet, but do not throw the comparison away either.**

### 3. Positive pattern collapses under rival, anomaly, or portability pressure

Use this when the comparison first looked like a stable recurrence but fails after the archive names the strongest rival, the hardest deviant case, or the actual transfer burden.

This is a real learning outcome.
The archive should keep a small record of the collapse so later work does not keep rediscovering and re-arguing the same overreach.

### 4. Local or case-family pattern only

Use this when there really is a recurring lesson, but it survives only inside a narrower family of cases.
That is **not** a null comparison.
But it is a null result for any broader portability or doctrine claim.

### 5. Comparison no longer earns retained memo space

Use this when the compared set is too stale, too thin, too mismatched, or too weakly verdict-moving to deserve a live retained comparison.
In that case the archive should usually keep only a tiny stub or changelog memory rather than carrying a full comparison note forward by inertia.

## What a null or mixed comparison should usually output

Keep the close narrow.
A null or mixed cross-case pass should usually end with only these four lines.

1. **null-result posture** — not-yet / mixed unresolved / collapsed after stress / local-only / retire
2. **what failed to survive** — pattern / mechanism story / portability / doctrine consequence / retention burden
3. **smallest next discriminating move** — the next case, refresh, rail distinction, measurement repair, or proof burden that would most cleanly move the posture
4. **archive retention decision** — keep thin null note / narrow comparison set and rerun / park / retire to stub

That is usually enough.
Do not turn null handling into a second comparison memo.

## When to keep a thin null note

Keep a small retained null note when at least one of these is true:
- the archive is likely to face the same tempting overclaim again,
- the collapsed pattern teaches a reusable limit on portability or doctrine motion,
- one clean discriminating next move is visible,
- or the comparison explains why a still-live candidate case should **not** be added yet.

A thin null note should usually be shorter than a positive retained comparison note.
It exists to prevent repeated overreach, not to preserve every dead end.

## When to park instead of retain

Usually park the comparison when:
- the memos are too stale for honest comparison and no quick refresh is coming,
- the claim-level mismatch is doing most of the apparent disagreement,
- the comparison does not move queue choice, doctrine pressure, or package routing,
- or the next real discriminating move is far enough away that a retained comparison note would mostly be shelf weight.

Parking is not failure.
It is how the archive refuses to grow around unresolved maybe-patterns.

## When a null should still move doctrine **not at all**

A null or mixed comparison should usually block doctrine motion unless the archive can say something stronger than “the pattern did not survive this round.”

Most null results should move doctrine **not at all**.
They usually belong to one of these smaller consequences instead:
- narrower case-family caution,
- stronger burden before portability claims,
- stronger rival-testing discipline,
- or simple comparison retirement.

If a null result seems to pressure doctrine anyway, route that question through [`../00-meta/doctrine-revision-and-demotion-under-case-pressure.md`](../00-meta/doctrine-revision-and-demotion-under-case-pressure.md) rather than treating absence of a stable pattern as a doctrine rewrite by mood.

## False moves this note is meant to stop

### 1. Forcing a positive pattern because the archive compared several cases

Comparison effort is not itself evidence of recurrence.

### 2. Treating a null as proof of the opposite rule

Failure to establish one recurring pattern is not yet proof that the opposite story is true.

### 3. Warehousing every inconclusive comparison

The archive should remember reusable failed overclaims, not preserve every mixed comparison as a standing object.

### 4. Letting a null result do secret doctrine work

A mixed or collapsed comparison may justify caution, a narrower family, or a stronger export burden.
It should rarely rewrite doctrine by implication.

## Minimal checklist

Before closing a mixed or null comparison, the archive should usually be able to say:

1. **What exactly failed to survive?**
2. **What is the smallest next move that would discriminate further?**
3. **Does this deserve a thin retained null note, a parked comparison, or retirement to stub?**
4. **What, if anything, does not move because the pattern did not survive?**
