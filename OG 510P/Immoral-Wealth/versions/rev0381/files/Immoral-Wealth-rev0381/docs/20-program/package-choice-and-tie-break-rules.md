# Package choice and tie-break rules

## What this note is for

This note gives the archive a **thin choice rule for moments when several packages survive first diagnosis**.
It is not a replacement for [`opening-package-router.md`](opening-package-router.md).
The router says how to build a serious opening package out of the dominant breach, the fastest washout channel, the governing mode, and current rails. The new selection note says how to choose that breach and that washout when several plausible candidates are live.
This note answers a narrower question that future case work would otherwise keep improvising:
**when two or three candidate packages still look plausible, which one should the archive prefer first?**

The standing answer is that the archive should not choose by headline drama, gross fiscal size, or ideological familiarity.
It should choose by which package most cleanly **hits the dominant breach, closes the fastest washout channel, routes the next durable gains toward entrants and the lower half, survives the current rails, and leaves the least room for quick reversal or quiet capture**.[S07][S15][S18][S19][S20][S21][S22][S23][S27][S28][S29][S30][S31][S32][S33][S36][S39][S139][S54]

## Minimum operating rule

When several packages are plausible, prefer the one that does **six things better at once**:

1. **Hits the dominant breach and the mandatory closure together.** A package that helps on one side while leaving the live reabsorption path open usually counts less, even when its headline promise is larger.[S07][S10][S17][S20][S31][S32][S33][S36]
2. **Routes the next durable gains toward entrants, excluded groups, younger adults, and the lower half.** The archive cares about who gets the next real footholds, not just who benefits eventually in a broad macro sense.[S18][S19][S27][S28][S29][S30][S47][S52]
3. **Creates person-level, portable, claimable footholds sooner.** Packages count more when they reduce household masking, gatekeeper dependence, and administrative attrition rather than adding new layers of expert-managed access.[S21][S22][S27][S28][S29][S30][S39][S139][S41]
4. **Fits the current rails while building stronger ones.** A package should count more when it can begin honestly now and less when its moral force depends on valuation, visibility, or integrity capacities that do not yet exist.[S04][S15][S23][S31]
5. **Creates less obvious washout, capitalization, or sabotage risk.** Packages count more when gains are harder to price away, charge away, refinance away, or politically claw back.[S07][S15][S20][S23][S31][S32][S33][S36]
6. **Leaves less proof debt.** When two packages look similar, prefer the one that depends on fewer optimistic assumptions about take-up, enforcement, future politics, or later compensating fixes.[S15][S23][S31][S32][S33][S39][S139]

So the standing tie-break rule is:
**prefer the package that delivers the next real footholds earlier, with cleaner closure, lower claimant burden, lower proof debt, and less room for rapid reconcentration.**

## The six main false passes

### 1. The biggest list is mistaken for the strongest package

A package should count less when it wins only because it includes more instruments, more spending lines, or more future promises.
The archive wants the **smallest governable package that changes the case**, not the thickest shopping list.[S20][S23][S31][S32][S33]

### 2. A higher gross transfer is mistaken for a better package

A package counts less when it looks larger in headline value but leaves housing, debt, monopoly tolls, or claim friction positioned to take the gain back.
Gross size is not the same thing as durable incidence.[S07][S10][S17][S20][S21][S22][S31][S36][S39][S139]

### 3. Household reach is mistaken for person-level foothold quality

A package counts less when it reaches many households but leaves control inside households, employers, local gatekeepers, or administrative chokepoints rather than with the person who needs the foothold.[S27][S28][S29][S30][S41]

### 4. A later hard fix is used to excuse a weaker opening

A package counts less when its defenders say the floor can stay thin now, or the washout lane can stay open now, because a harder redistribution or public-wealth move might arrive later.
The archive discounts backloaded rescue stories.[S20][S23][S31][S32][S33]

### 5. Political elegance is mistaken for a better first move

A package counts less when it is chosen because it sounds principled, universal, or bold while easier lower-half, tenant, wage, registry, or claimability moves are more governable and more urgent in the live case.[S04][S15][S21][S22][S23][S31][S39][S139]

### 6. Cheapness is achieved by off-loading burden back onto households

A package counts less when it looks administratively or fiscally light only because households must self-insure more, navigate more, borrow more, wait longer, or absorb more interruption risk on their own.[S17][S21][S22][S24][S25][S39][S139][S41][S50]

## The standing tie-break stack

### 1. Breach-and-closure beats headline breadth

If Package A hits the dominant breach but leaves the fastest washout lane open, while Package B hits the same breach and closes the washout channel at the same time, the archive should usually prefer **Package B** even when its gross distributive surface looks smaller.
This is the archive's anti-fantasy rule in practical form.[S07][S10][S17][S20][S31][S36]

### 2. Earlier entrant footholds beat later incumbent rebalancing

If two packages are similar in aggregate promise, prefer the one that moves the next durable units of wealth or security **earlier** toward entrants, younger adults, excluded groups, and the lower half.
The archive gives special weight to timing because late footholds often arrive after housing, family formation, or compounding opportunities have already been sorted by inherited position.[S18][S19][S27][S28][S29][S30][S47][S52]

### 3. Person-level portability beats household or sponsor dependence

If two packages create similar apparent reach, prefer the one that gives the individual a clearer, cheaper-to-defend, more portable claim.
A package should count more when it can survive separation, job change, mobility, provider churn, or ordinary administrative interruption.[S27][S28][S29][S30][S139][S41]

### 4. Lower-friction, lower-claimant-load design beats formally equal but harder access

If two packages aim at the same population, prefer the one that asks less repeated proof, less expert help, fewer renewals, fewer gatekeepers, and less involuntary household pooling.
The archive counts claimant burden as a real moral cost rather than a side issue.[S39][S139][S43][S45]

### 5. Begin-now realism beats heroic readiness theater

If two packages are morally attractive, prefer the one that can **begin now** under current rails while honestly building the rails for harder tools next.
The archive does not confuse rail honesty with timidity.
It rejects both maximal delay and fake readiness.[S04][S15][S23][S31]

### 6. Harder-to-capture and easier-to-ratchet packages beat softer gains

If two packages look similar in the short run, prefer the one that is easier to harden into defaults, durable public/common support, visible enforcement, and anti-capture protections.
The archive should bias toward gains that are more likely to survive a colder political season.[S15][S20][S23][S31][S32][S33][S54]

## Four recurring choice patterns

### A. Bigger transfer versus cleaner closure

When one package offers a visibly larger transfer or subsidy while another offers a smaller gain plus direct closure of the live rent or debt washout channel, the archive should usually prefer the **cleaner closure package first**.
Otherwise the larger transfer often becomes a brief pass-through to landowners, creditors, or other incumbents.[S07][S17][S20][S31][S36]

### B. Public/common build-out versus citizen-side foothold now

When one package invests mainly in public or common vehicles while another also creates direct lower-half footholds, the archive should usually prefer the package that does **both**, or at least the one that does not leave ordinary people waiting entirely on later public translation.
Public wealth matters, but it should not become a reason to postpone person-side security indefinitely.[S02][S12][S20][S21][S22][S23]

### C. Elegant top-tail tool versus ordinary lower-half repair

When one package leads with a visibility-heavy, valuation-heavy top-tail instrument while another begins with tenant protection, floor repair, wage room, or registry-linked claimability that current rails can actually carry, the archive should usually **begin with the governable lower-half repair while building the rails for the harder top-tail tool**.[S04][S15][S21][S22][S23][S31][S39][S139]

### D. Broad household inclusion versus person-level title

When one package broadens asset holding mainly at the household level and another gives clearer person-level title, portability, or non-forfeiture, the archive should usually prefer the **person-level variant** unless the cost is genuinely prohibitive and temporary.[S27][S28][S29][S30][S41]

## Fast use rule

Use this note when a case memo has **two or three serious package candidates left**:

1. **Check breach and closure first.** Which package hits the dominant breach and closes the fastest washout channel at the same time?
2. **Check marginal incidence second.** Which package sends the next durable gains sooner toward entrants, excluded groups, younger adults, or the lower half?
3. **Check foothold quality third.** Which package gives clearer person-level, portable, low-friction claims?
4. **Check rail honesty fourth.** Which package can begin now without pretending missing capacity already exists?
5. **Check durability fifth.** Which package is easier to ratchet, defend, and keep from being captured or washed out?
6. **If still close, prefer the smaller governable set.** The archive should rather do one serious package that changes the case than a larger package that mostly enlarges proof debt.

Default shortcut:
- **bigger headline vs cleaner closure** -> prefer cleaner closure;
- **later broad promise vs earlier entrant foothold** -> prefer earlier entrant foothold;
- **household reach vs person-level title** -> prefer person-level title;
- **heroic tool vs rail-fit starter** -> prefer rail-fit starter while building the rails for the heroic tool;
- **similar short-run gains** -> prefer the package easier to ratchet and harder to capture.[S04][S07][S15][S18][S19][S20][S21][S22][S23][S27][S28][S29][S30][S31][S32][S33][S36][S39][S139][S41][S54]

## Handoff to case work

A future case memo does not need a new essay for this note.
If it is weighing more than one serious opening package, it can usually add one short line after the opening-package block:
- **why this package won the tie-break,**
- **which apparently plausible package lost,**
- and **what feature decided it**.
If package confidence is only action-grade or directional, the memo should say that plainly using [`confidence-labels-and-action-under-proof-debt.md`](confidence-labels-and-action-under-proof-debt.md) rather than speaking as if the tie-break were already settled beyond reasonable dispute.

That keeps the archive thin.
The purpose of this note is not to multiply options.
It is to stop future work from pretending that every plausible package is equally good once it clears the first screen.

## Bottom line

The archive now has a cleaner answer to a recurring design question:
**what should we do when several packages all look defensible?**
Prefer the one that hits the dominant breach, closes the fastest washout channel, routes the next durable gains toward entrants and the lower half, creates lower-friction person-level footholds, fits real rails, and is easiest to harden against reconcentration and capture.
That is the archive's compact tie-break rule for turning plural plausibility into a real choice rather than another shopping list.[S07][S15][S18][S19][S20][S21][S22][S23][S27][S28][S29][S30][S31][S32][S33][S36][S39][S139][S41][S54]
