# Case-portfolio triage and memo selection

## What this note is for

The archive now has a tight rule for how to judge **one** real case.
What it still lacked was the thinner upstream rule:
**when several countries, cities, sectors, or cohorts could be studied, which ones actually deserve memo work first?**

That matters for archive discipline as much as for research discipline.
Without a portfolio rule, every plausible case becomes a tempting branch.
The archive then starts growing by **case accumulation** rather than by decision value.

This note gives the archive a compact way to decide:

1. which candidate cases deserve active memo work now,
2. which should stay visible but parked,
3. which should be used as **exemplars** rather than treated as universal representatives,
4. and how many live case tracks the archive should tolerate at once before the queue itself becomes bloat.

## Minimum reading rule

Choose cases by **decision value per retained byte**, not by fame, rhetorical vividness, or data prettiness.

A case should move toward the front of the queue when it scores strongly on four questions:

1. **How much constitutional harm is concentrated here now?**
2. **How much would a memo on this case change archive judgment, package choice, or route confidence more generally?**
3. **How tractable is the case to read honestly with the evidence and rails we can actually carry?**
4. **How costly is delay if the case is left unworked for now?**

In compact form:

- prioritize cases with **mass harm**, **generalizable routing value**, **usable evidence**, and **high delay cost**;
- demote cases that are mainly vivid, prestigious, weird, or convenient;
- and keep only a **small live queue** so case work does not become the archive.

## The six tests for case priority

Run candidate cases through these tests in order.

### 1. Harm test

Ask where the archive is most likely to find **large present constitutional damage**:
thin floors, high forced private exposure, rapid washout, entrenched dynastic closure, active wealth-to-rule conversion, or weak public counterweight.

This test is first because a case with minor marginal importance should not leap the queue merely because its data are elegant or its politics are fashionable.

### 2. Decision-movement test

Ask whether working this case would likely improve the archive beyond the case itself.

A candidate rises when it would likely:
- sharpen a recurring verdict surface,
- reveal a package-routing pattern that will travel,
- clarify a rail or gating dispute that appears across many cases,
- or expose a repeatable washout channel the archive should treat more seriously elsewhere.

A case falls when it is mostly idiosyncratic and unlikely to teach the archive anything beyond itself.

### 3. Tractability test

Ask whether the archive can read the case **honestly enough** without pretending it knows more than it does.

A case is more tractable when:
- minimum evidence is likely reachable,
- source conflict can be sorted without heroic speculation,
- ordinary watch surfaces are visible enough to monitor,
- and a real package comparison is possible rather than purely theatrical.

A case is less tractable when almost everything important is opaque, lagged, legally hidden, or so politically exceptional that the memo would mostly narrate unknowability.

### 4. Delay-cost test

Ask what is lost by waiting.

Some cases should move forward even under proof debt because delay is expensive:
the washout is fast, the distribution is still hardening, the anti-capture window may close, or an actionable debate is live now.
Other cases can stay parked longer because the memo would mostly be calibration work rather than missed protection.

### 5. Archive-reuse test

Ask whether this case can serve as one of three useful roles:

- an **urgent live case** whose harm and delay cost are both high,
- an **exemplar case** that future work can reuse as a stable pattern,
- or a **proof-building case** that resolves a recurring evidence or routing problem.

If the case serves none of those roles, it usually should not become a full retained memo.

### 6. Queue-discipline test

After the case looks worthwhile, ask one more question:
**does the queue already have too many live cases of the same type?**

The archive should not keep multiple near-duplicate live cases when one exemplar plus shorter citations would do.
A new case earns priority more easily when it adds a missing type, missing geography, missing institutional mode, or missing washout pattern.
It earns priority less easily when it is only the fifth version of a case family the archive already understands well enough.

## The four standing portfolio classes

Every candidate should usually end in one of four classes.

### A. Urgent live case

Use this for cases with high present harm, high delay cost, and enough tractability to support an action-guiding memo now.

These cases justify:
- a fresh memo,
- faster review expectations,
- and more active watch posture once the memo exists.

The archive should keep this bucket small.
If too many candidates qualify, choose the ones with the highest combined harm and delay cost first.

### B. Exemplar case

Use this for cases that are especially good at teaching a pattern the archive expects to reuse:
rent-washout, late footholds, top-tail rule conversion, thin public counterweight, claimant friction, or another recurring archive surface.

An exemplar does **not** have to be the worst case.
It has to be a **clean teaching case** whose memo can carry weight later without pretending to be universal.

### C. Proof-building case

Use this for cases chosen mainly because they help the archive solve a recurrent evidence, measurement, or routing problem.
These cases are often valuable even when they are not the most morally urgent cases in the queue.

But proof-building work should stay narrow.
The memo should be honest that the case was selected to resolve a repeated reading problem, not because it is the only place where injustice matters.

### D. Parked / citation-only case

Use this when the case is interesting, rhetorically tempting, or maybe important later, but does not yet beat the current queue on harm, tractability, delay cost, or archive reuse.

A parked case should remain visible in a ledger or short note if needed.
It does **not** automatically earn a full retained memo.

## The default queue shape

The archive should usually resist running many full cases at once.

A good default queue is:

- **one or two urgent live cases,**
- **one exemplar case,**
- **at most one proof-building case,**
- and the rest parked.

This is a discipline rule, not a metaphysical claim.
Its purpose is to stop the archive from quietly becoming a casebook.
For the next downstream question—how many full retained case memos should remain active at once, when older memos should shrink to stubs, and how a new memo should recover bytes rather than only add them—use [`case-portfolio-caps-and-retirement.md`](case-portfolio-caps-and-retirement.md).

If a new candidate enters the queue, the archive should ask what it displaces.
A case that displaces nothing usually has not yet earned its bytes.

## How to break ties between candidate cases

When two candidate cases look similarly worthy, prefer the case that offers more of the following:

1. **cleaner moral clarity** — the verdict is less likely to dissolve into atmosphere,
2. **cleaner routing value** — the case teaches a decision rule that will travel,
3. **higher washout visibility** — success or failure will become legible sooner,
4. **better evidence carry** — the archive can monitor the case without building a new data warehouse,
5. **broader future reuse** — later work can cite the memo as an anchor rather than only as a curiosity.

When those are still tied, prefer the case that most directly corrects the current portfolio's blind spot:
missing geography, missing class of institution, missing mode, missing group stratification surface, or missing washout type.

## The main false moves this note is meant to stop

### 1. Choosing cases by fame

Highly discussed countries, sectors, or scandals often attract memo work because they are already visible.
That is not enough.
The archive should not let prestige, notoriety, or discourse volume choose its queue.

### 2. Choosing only data-rich cases

Data-rich cases can be useful exemplars.
But an archive that chooses only the prettiest data will systematically underread opaque but morally important cases.

### 3. Choosing only the hardest opaque cases

The opposite mistake is also real.
If every chosen case is so opaque that verdict, package, and watch posture all remain vaporous, the archive stops producing decision value.
It should keep some proof-building work, but not let opacity monopolize the queue.

### 4. Letting every interesting case become a memo

A visible case can still fail to earn retained bytes.
Sometimes the right move is a citation, a ledger line, or a paragraph inside another note.

### 5. Confusing exemplar with representative

An exemplar memo is a teaching anchor, not a claim that all cases of that broad family behave identically.
The archive should reuse exemplars for routing help, not to erase local differences.

### 6. Using case work to smuggle new theory

A case memo should usually apply the archive.
If working a candidate would mostly require inventing new doctrine, the archive should say that the real work needed is theory repair first, not pretend the case queue solved it. If a case later seems to teach a wider recurring rule, route that promotion question through [`../00-meta/case-to-doctrine-promotion-and-quarantine.md`](../00-meta/case-to-doctrine-promotion-and-quarantine.md) rather than letting one vivid memo quietly generalize itself into archive doctrine.

## What a portfolio-triage block should output

Before drafting a new case memo, the archive should be able to write six short lines:

- **candidate case**
- **portfolio class** — urgent / exemplar / proof-building / parked
- **why now**
- **why not later or not at all**
- **what this case is supposed to teach or decide**
- **what current queue item it displaces, if any**

If those lines cannot be written honestly, the case probably is not ready for retained memo status.

## Fast use rule

Use this note in seven steps:

1. **Screen for harm first.**
2. **Ask whether the case will move archive judgment beyond itself.**
3. **Check whether the evidence is tractable enough for an honest memo.**
4. **Ask what delay would cost.**
5. **Classify the case** as urgent, exemplar, proof-building, or parked.
6. **Keep the live queue small** and make every new case displace something.
7. **Only then** run the chosen case through [`case-work-decision-path.md`](case-work-decision-path.md) and [`case-application-protocol.md`](case-application-protocol.md).

## Bottom line

The archive now has a compact answer to another growth problem:
**which candidate cases deserve memo work first?**

Choose cases by harm, decision movement, tractability, delay cost, and future reuse.
Keep the live queue small.
Let exemplars teach, let proof-building cases solve repeated reading problems, and let many plausible cases remain parked without apology.
That is how the archive can accumulate real case knowledge without turning into an undisciplined case warehouse.
