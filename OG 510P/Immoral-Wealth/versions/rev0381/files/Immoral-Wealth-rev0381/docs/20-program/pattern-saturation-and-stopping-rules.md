# Pattern saturation and stopping rules

## What this note is for

The archive can now choose a comparison set, extract a recurring pattern, separate confidence burdens, name live rivals, confront the hardest deviant case, and screen portability.
What it still lacked was the compact bridge for a different pressure point:
**when is the comparison already strong enough for archive purposes, and when is adding another case still the most verdict-moving next move?**

That gap matters because cross-case work can fail in two opposite ways at once:
- it keeps adding cases long after the next case is unlikely to move the real claim,
- or it calls a pattern "established" too early just because two or three cases look elegant together.

This note gives the archive a compact rule for **provisional saturation**.
It is not a counting rule, not a doctrine note, and not a license to keep building a warehouse until every imaginable case is gathered.
It is a **stopping-rule bridge**.

## Minimum rule

A cross-case comparison should usually stop growing when the **next comparable case is unlikely to move** one or more of these four things:

1. **pattern-existence confidence**
2. **mechanism confidence**
3. **portability confidence**
4. **doctrine-consequence confidence**

If a genuinely comparable next case would still likely move one of those four burdens, the pattern is **not yet saturated enough for archive purposes**.
If the next comparable case is unlikely to move them much, the pattern may be treated as **provisionally saturated for the current claim level**.

This is why the archive should not ask "how many cases do we have?"
It should ask:
**what is the next case most likely to change?**

## What should usually count as the next most verdict-moving case

If another case is still worth adding, it should usually be the one that would do the most to change the pattern claim.
That is often one of four things:

### 1. Strongest missing comparable case

A case that belongs inside the same comparison family but is not yet represented.
This matters when the current set is too narrow or too self-reinforcing.

### 2. Strongest rail contrast

A case that keeps the same apparent pattern question but changes the rail environment sharply.
This matters when portability is the live uncertainty.

### 3. Strongest live deviant candidate

A case likely to be the hardest genuine anomaly if it survives freshness and comparability checks.
This matters when the pattern still looks too comfortable because its hardest contrary case has not yet been tested.

### 4. Strongest measurement discriminator

A case whose evidence architecture would help separate a real mechanism from a measurement artifact or from a rival explanation.
This matters when the pattern is still too dependent on one data style or one visibility regime.

If the archive cannot name a next case that would matter in one of those ways, that is already evidence for stopping.

## The archive's saturation postures

A serious cross-case note should usually classify itself into one of five postures.
Use one only.

### 1. Too thin to talk about saturation

Use this when the comparison set is still so small, stale, or non-comparable that asking whether the pattern is saturated is premature.
The archive consequence is usually **repair or expand before export**.

### 2. Expansion still clearly warranted

Use this when the next most verdict-moving case is easy to name and would likely move at least one of the four burdens above.
The archive consequence is usually **add one more case, not many**.

### 3. Provisionally saturated for local or case-family claim

Use this when the current set is strong enough to support a local or case-family lesson, but not strong enough for portable-core or doctrine consequence claims.
The archive consequence is usually **retain the pattern narrowly and stop case accumulation for now**.

### 4. Provisionally saturated for portable-core claim

Use this when further near-term case addition is unlikely to change the portable-core claim much, though named rails and transfer limits still apply.
The archive consequence is usually **allow narrow export without pretending doctrine has moved**.

### 5. Pattern may be saturated, doctrine still is not

Use this when the archive has enough cross-case confidence to treat the pattern as real and fairly portable, but the doctrine consequence is still too uncertain, too normatively loaded, or too thinly discriminated to justify promotion or repair.
The archive consequence is usually **hold the doctrine where it is and stop pretending more similar cases are what is missing**.

## What a cross-case note should output about stopping

Keep this block to four short lines:

1. **saturation posture** — one of the five postures above
2. **why not yet / why enough for now** — one sentence only
3. **next most verdict-moving case** — name it, or say none obvious
4. **archive consequence** — expand one case / hold narrow / allow portable-core export / no doctrine motion yet

That is enough.
Do not turn stopping discipline into a second dashboard or a pseudo-formal sample-size ritual.

## How this block should change nearby archive calls

### If the pattern is still too thin

Do not speak about saturation yet.
Repair set selection, freshness, or evidence architecture first.

### If one more case is clearly warranted

Add **one** case of the most verdict-moving kind.
Do not grow a queue of vaguely relevant additions.
If a second additional case is immediately proposed, the archive should say why the first added case would still not answer the live burden.

### If the pattern is saturated only locally

Stop accumulating broad comparison rhetoric.
Keep the lesson at local or case-family level and let portability stay narrow.

### If the pattern is saturated for portable-core claim

The archive may export the smallest honest core, but it should still say what named rails remain required and what doctrine has **not** yet moved.

### If doctrine still is not saturated

More like-with-like cases are often not the missing ingredient.
The missing work may instead be normative clarification, better rival discrimination, or stronger transfer limits.
Route that question through promotion or doctrine-repair governance rather than using more case accumulation as a substitute.

## What this note is meant to stop

### 1. Endless case accumulation

The archive should not keep adding cases because another plausible case exists somewhere.
It should add another case only when that case is likely to move the live burden.

### 2. Counting cases instead of naming the next decisive one

A pattern is not stronger merely because the archive has more examples.
It is stronger when the best remaining counterpressure has already been faced or is unlikely to change the call.

### 3. Confusing saturation with certainty

Provisional saturation is a stopping rule for archive growth, not a guarantee that the pattern is universally true.
It still sits under the archive's confidence, portability, and doctrine-burden rules.

### 4. Letting doctrine move just because the pattern is repeated

Sometimes the pattern is real and the doctrine consequence is still not ready.
This note is meant to preserve that difference.

## Fast use rule

When a cross-case pattern seems to survive:

1. **Ask what the next most verdict-moving case would be.**
2. **If no clear next case exists, treat that as evidence for stopping.**
3. **If one clear next case exists, add one case rather than a new warehouse.**
4. **Classify the saturation posture.**
5. **State what level of claim is saturated enough for now, and what still is not.**

## Bottom line

The archive now has a thinner answer to a question that appears after portability and anomaly handling:
**when is a cross-case pattern strong enough for archive purposes, and when is adding another case still the most verdict-moving next step?**
Stop when the next comparable case is unlikely to move the real burden, keep the supported claim level narrow, and prefer one decisive next case to endless accumulation.
