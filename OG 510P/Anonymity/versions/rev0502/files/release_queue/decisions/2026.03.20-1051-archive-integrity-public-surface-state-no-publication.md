## What changed

This pass did not review or promote a paper.
It instead hardened the archive's wake-up and integrity surfaces.

Added or refreshed:

- `release_queue/QUEUE_INDEX.json` as a machine-readable summary of Candidate / Hold / Published-ready / Published queue state,
- `published/CITATION_HEADS.md` and `published/citation_heads.json` as a compact register of what is actually citable right now versus merely frozen in-repo,
- `published/PUBLIC_SURFACE.json` as a machine-readable description of the stable published-facing surface,
- `MANIFEST.sha256` as an exact file-level checksum manifest for the shipped archive, and
- `REVISION_RECEIPT.json` as a compact reentry object explaining what this revision changed and why.

Repo guidance was then updated so future turns consult those compact surfaces before improvising public-link or queue-state claims.

## Why this decision

Several comparison archives converged on the same useful pattern: keep the human-facing prose, but also ship one compact machine-readable state surface and one compact integrity/provenance receipt so a future operator does not have to rediscover archive state by crawling the tree.

For this repository, the highest-value transfer was not a new release mechanism.
It was a stricter separation among:

- what is currently public and citable,
- what is merely frozen in-repo,
- what is only queue state, and
- what exact bytes this revision shipped.
