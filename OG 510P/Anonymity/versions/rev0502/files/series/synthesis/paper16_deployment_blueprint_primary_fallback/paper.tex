\begin{abstract}
This note is a capstone assembly: it states a minimal, referee-friendly deployment blueprint that composes the series' contract objects into a single operational story.
The blueprint is \emph{tiered}: a primary, cryptographic path carries most queries; a DHT fallback handles residuals and is made \emph{honest} by publishing explicit repetition/observation budgets and by recertifying when parameters drift.
The note is intentionally non-redundant: definitions and interfaces are imported from their owners and this paper provides only the checklist glue.
\end{abstract}

\section{Goal and scope}

The series is primarily \emph{provider- and auditor-facing}: it specifies how a deployment can make reader-privacy claims precise, checkable, and updateable.
End-user verification is optional and minimal: we target \emph{receipt discovery and anchoring validation} (not full behavioral attestation), via a small client-side interface.

A single theme motivates the blueprint: repeated use turns ``one lookup privacy'' into a \emph{Boss Fight} budgeting problem.
Dummy cover / equalization mechanisms can be formally sound yet practically inadequate under realistic query horizons $Q$; therefore, the privacy boundary is architectural:
push strong privacy into a small primary path, and treat the DHT as residual capacity whose leakage is explicitly budgeted and published.

\section{Blueprint: what a deployment ships}

\subsection{Tiered paths}
The architectural motivation, mixture bound, and honest-fallback semantics are owned by Synthesis~10 and should not be restated here.\cite{series:tieredpattern}
This blueprint therefore treats the path design as an imported prerequisite:
\begin{itemize}[leftmargin=*]
\item \textbf{Primary path:} a small cryptographic or strongly mediated surface with an explicit threat-window declaration and published receipt semantics.
\item \textbf{Fallback path:} a DHT path whose repeated-use, observation, and path-selection costs are published honestly in the receipt chain.
\end{itemize}
What this note adds is the \emph{operational packaging}: what artifacts, records, and role-specific checks a deployment should ship once it has adopted the tiered pattern.

\subsection{Receipt chain: from build to public record}

A deployment SHOULD ship a receipt chain with the following structure, each element expressed as a contract object \cite{series:contractobjects}.

\begin{enumerate}[leftmargin=*]
\item \textbf{Manifest + canonicalization.} A stable manifest over source and configuration inputs, using the series' canonicalization/digest binding conventions (imported by the transparency interface \cite{series:transparency}).
\item \textbf{ABOM/OINL declaration.} An ABOM/OINL object describing what is claimed and what is not claimed (owner: \cite{series:abomoinl}).
\item \textbf{Receipt line items + replay hooks.} A receipt record carrying the minimal tuple in \cite{series:receiptitems}, including the declared TW and observation model (scalar or tiered). Each line item SHOULD include a \texttt{replay\_hook} with \texttt{plan\_id} and digest-bound \texttt{plan\_spec\_id}, so a third party can tell what replay workflow the receipt promises (and so drift triggers replay vs.\ recertification are well-defined).\cite{series:planstateequiv}
\item \textbf{Anchoring.} Append-only log anchoring, with inclusion (and, when relevant, consistency) proofs under the transparency interface \cite{series:transparency}.
\item \textbf{Optional UVI record.} A user-verifiable discovery/validation record, enabling clients to find the relevant receipt and validate anchoring mechanically \cite{series:userminiface}.
\end{enumerate}

\begin{remark}[Non-goal: shipping all artifacts by default]
The archive's ``source-only'' policy is compatible with referee-grade defaults as long as the \emph{argument-bearing evidence} is present in the papers and receipts.
Scripts, datasets, and auxiliary tooling can remain on-request, but the published receipt chain must be sufficient to reproduce the stated bounds.
\end{remark}

\section{Checklist by role (minimal MVP)}

This section is the main export of the blueprint: a concise role-based checklist.
It is phrased so a referee can audit it without reading the whole series.

\subsection{Deployer checklist}

\begin{enumerate}[leftmargin=*]
\item \textbf{Declare the TW.} Publish a TW declaration object (threat window, adversary class, query budget conventions) \cite{series:threatwindows}.
\item \textbf{Choose tiering.} Specify the primary path (cryptographic) and fallback path (DHT) policy \cite{series:tieredpattern}.
\item \textbf{Publish fallback honesty.} Decide whether fallback usage is secret-/state-independent; if not, publish the trigger model interface and selection-tax bound \cite{series:selectiontax}.
\item \textbf{Publish observation semantics.} Choose scalar $p_{\mathrm{obs}}$ or a tiered vector model and publish it in the receipt \cite{series:tieredobsvec}.
If a relay/stub-mix is used, record the attenuation assumptions \cite{series:obsatten}.
\item \textbf{Budget repeated use.} Provide a Boss Fight dial-sheet slice or sufficient parameters for an auditor to reproduce the same bound \cite{series:bossfightdial}.
\item \textbf{Emit the receipt chain.} Emit manifest, ABOM/OINL, receipt line items (including \texttt{plan\_id}/\texttt{plan\_spec\_id}), and anchoring proofs \cite{series:receiptitems,series:releaseledger,series:transparency,series:planstateequiv}. If any line item relies on schedule-only trace auditing, publish a plan certificate and log inclusion proof as part of the replay-plan evidence (Operational~B).\cite{series:operationalB}
\item \textbf{Recertify on drift.} Bind receipts to the evaluation workflow and define recertification triggers (config changes, observed deviations, or policy changes) \cite{series:evalnotary,series:advantagecontracts}.
\end{enumerate}

\subsection{Auditor/referee checklist}

\begin{enumerate}[leftmargin=*]
\item \textbf{Check anchoring.} Verify inclusion (and consistency when required) under the transparency interface \cite{series:transparency}.
\item \textbf{Check ownership.} Ensure claims are made only by the paper/object that owns the definition; imported semantics should cite their owners \cite{series:contractobjects}.
\item \textbf{Check TW match.} Confirm the receipt's TW matches the paper claims and that the adversary/query-horizon conventions are coherent \cite{series:threatwindows}.
\item \textbf{Recompute bounds.} Verify each line item's \texttt{plan\_spec\_id} resolves to a replay workflow you understand (Synthesis~18), then recompute the stated repeated-use budget from the published line items:
Boss Fight tables \cite{series:bossfightdial}, observation vector semantics \cite{series:tieredobsvec}, selection tax when applicable \cite{series:selectiontax}.
\item \textbf{Check change control.} Ensure the receipt chain is linked to release receipts (ABOM/OINL + property ledger) \cite{series:releaseledger,series:abomoinl} and that recertification triggers exist \cite{series:advantagecontracts}.
\end{enumerate}

\subsection{Client/user checklist (minimal, optional)}

\begin{enumerate}[leftmargin=*]
\item \textbf{Discover.} Obtain the UVI record (or equivalent discovery pointer) for the deployment \cite{series:userminiface}.
\item \textbf{Validate anchoring.} Validate inclusion/consistency against published log checkpoints under the transparency interface \cite{series:transparency}.
\item \textbf{Interpret.} Read the published receipt tuple (TW, observation model, $Q$ budget conventions) \cite{series:receiptitems} and, if needed, consult the Boss Fight dial-sheet slice \cite{series:bossfightdial}.
\item \textbf{Compare.} If the deployment publishes a watch policy or compare-profile adjunct, use it to compare the current claim surface against the last release without treating those adjuncts as new core receipt fields \cite{series:workedexample}.
\end{enumerate}

\section{Minimal disclosure rules (to stay tight)}

This note is ``tight by construction'' and therefore states what \emph{must not} be duplicated:
\begin{itemize}[leftmargin=*]
\item Do not restate the beacon/VRF/log interface outside Synthesis~9 \cite{series:transparency}; cite it.
\item Do not invent new receipt fields ad hoc; add them only via Synthesis~12 \cite{series:receiptitems}.
\item Do not restate Boss Fight accounting in deployment papers; cite the dial sheet and publish parameters \cite{series:bossfightdial}.
\item Do not restate plan/state drift semantics; cite Synthesis~18 \cite{series:planstateequiv}.
\item Do not hide core evidence behind build flags (the series now uses explicit addenda when needed).
\end{itemize}

\section*{Exports}
This note exports a single object: the role-based blueprint checklist and the claim that a deployment is referee-auditable when it publishes the receipt chain and supports the role checklists above.
It does \emph{not} export new math, new metrics, or new receipt primitives; those remain owned by the cited synthesis notes and series papers.
For a concrete worked instantiation of the receipt chain, UVI record, and evaluation handoff, see the worked-example micro-note (Synthesis~17).\cite{series:workedexample}
