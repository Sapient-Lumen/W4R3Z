\begin{abstract}
This note is a non-redundancy aid.
The One-True-Archive relies on five already-published mathematics notes (canonical wiki links) for core mechanism design and lower bounds.
Downstream papers should not repeatedly re-explain that machinery.
We therefore record a compact crosswalk: what each backbone note exports as an interface, which series papers depend on it, and how to chain the exports into receipt-grade line items and endpoint sizing.
This is not a survey and does not introduce new primitives.
In particular, it distinguishes the theorem root, the receipt-facing landing zone, and the maintained replay/release stop that should be consulted once a certified claim changes.
\end{abstract}

\paragraph{Concrete landing zone.}
The worked example (Synthesis~17) now ships \texttt{artifacts/example\_line\_item\_owner\_map.json}, a digest-bound crosswalk from receipt line items to owner notes and, where relevant, to the canonical \texttt{wiki:*} backbones listed above.
It also ships \texttt{artifacts/example\_release\_spine.json}, which turns the same import graph into a stable release-maintenance chain once a receipt has already been published. The newer theorem-to-review bridge in Synthesis~55 and the companion worked artifact \texttt{example\_series\_spine.json} let later papers cite that whole chain without restitching it from prose.
Use this note for the mathematical/root-side rule, Synthesis~55 for the cross-series bridge, and Synthesis~17 only when a paper needs one concrete end-to-end instantiation rather than another prose summary of the same import graph.\cite{series:workedexample,series:seriesspines}

\paragraph{Four stable audit stops.}
A terse downstream paper usually needs to answer only four questions: which theorem or lower bound justifies the claim, where that claim lands on the public receipt surface, which maintained replay/release object becomes the next audit stop if that line item changes, and what the smallest maintained referee handoff should be if the question turns into review rather than mechanism explanation. This crosswalk owns the first question and the math-side landing of the second. Synthesis~17 gives one concrete instantiation of the second, Synthesis~32 owns the release-local stage cuts for the third, and Synthesis~55 owns the cross-series bridge to the fourth.\cite{series:workedexample,series:releasespine,series:seriesspines}

\paragraph{Later-terse-paper citation posture.}
Later terse papers should cite the relevant legacy \texttt{wiki:*} entry when the live issue is the theorem, lower bound, or mechanism itself; cite this crosswalk only when they need one compact routing sentence saying which mathematical export lands at which receipt-facing owner; cite Synthesis~17 only when a concrete end-to-end instantiation or owner-map artifact is itself the live object; and widen to Synthesis~32 or Synthesis~55 once the question is already about replay-local stage cuts, successor maintenance, or referee handoffs rather than the mathematics export boundary. That division is the main reason this note is better treated as a maintained crosswalk than as a first-wave theorem, certificate, or release unit.\cite{series:workedexample,series:releasespine,series:seriesspines}

\section{What each backbone note exports (as an interface)}
We treat each backbone note as exporting a small set of reusable objects.
Downstream papers should cite the relevant backbone note for the 
\emph{mechanism/lower-bound} content and cite the synthesis layer for the \emph{receipt surface}.

\subsection{2026-01-22: Scheduling/compiler techniques}
\textbf{Exports.}
(i) public-schedule and stop-time-padding models; (ii) compiler-oriented constraints (calendar/poset feasibility); (iii) TV-style privacy certificates for termination-time / deadline-hiding mechanisms.
\textbf{Receipt-facing touchpoints.} threat-window declarations (Synthesis~4), termination-time/stop-time exposure normal forms (Synthesis~3), and TV/dual-certificate accounting (published 2026-01-29; Congestion-EQ).\cite{series:threatwindows,series:traceifaces,wiki:knapsack}

\subsection{2026-01-23: Spectral anonymity for delegation}
\textbf{Exports.}
Random-walk delegation distinguishing bounds expressed via spectral witnesses (including directed overlays), and a clean ``per-step leakage'' packaging that can be attached to a receipt as evidence.
\textbf{Receipt-facing touchpoints.} Anonymity~D packages the spectral witness as a receipt-grade MaxL/odds-inflation budget; Synthesis~21 provides the conditional-certificate shape when the bound is assumption-qualified.\cite{series:spectral2budget,series:condcert}

\subsection{2026-01-25 and 2026-01-26: Prefix capacities and stop-time normal forms}
\textbf{Exports.}
A termination-time hiding frontier under shared-kernel constraints: prefix-capacity bounds, separation cuts, and normal forms for deadline distributions.
\textbf{Receipt-facing touchpoints.} These results justify which termination-time witness families are actually equalizable under an operational kernel constraint; the exposure IDs for those families live in Synthesis~3 and the repetition/window handling lives in Synthesis~4.\cite{series:traceifaces,series:threatwindows}

\subsection{2026-01-29: Optimal poset-feasible padding (knapsack/transport + dual certificates)}
\textbf{Exports.}
A TV-privacy optimization stack for padding under feasibility constraints (knapsack/transport) together with dual certificates that can be published as replayable evidence.
\textbf{Receipt-facing touchpoints.} Use this note when you want a termination-time hiding claim to be accompanied by a dual certificate (proof-carrying budget style) rather than only a point estimate.\cite{wiki:knapsack,series:pcbudgets}

\section{Minimal pipeline sketch (how the pieces compose)}
This section is intentionally short: it is here so downstream papers can cite a single paragraph rather than re-stitching the same chain.

\paragraph{Delegation slice (spectral $\Rightarrow$ endpoint).}
A spectral witness bound from 2026-01-23 yields a per-step leakage bound (Anonymity~D) that can be published as a receipt line item bound $b$ in bits (MaxL or odds inflation), possibly conditional on a state/separation guard.
For a horizon $n$ (or a declared retry window), compose using the checkpoint accountant (Anonymity~A / Synthesis~19) and translate to endpoint sizing using the bridge rule (Synthesis~5).\cite{series:spectral2budget,series:oddsinflation,series:receiptacct,series:endpointbridge}

\paragraph{Stop-time padding slice (TV $\Rightarrow$ receipt-grade evidence).}
A stop-time padding mechanism (2026-01-22/26) yields a TV-style guarantee on a declared termination-time witness family.
If the deployment uses feasibility constraints (calendar/poset), 2026-01-29 provides an optimization and a dual certificate that can be committed via ABOM/OINL and replayed (proof-carrying budgets).
Receipt-facing objects are: the exposure normal-form id (Synthesis~3), the threat-window id (Synthesis~4), and the replay hook binding the certificate plan spec (Synthesis~12/18/20).\cite{series:traceifaces,series:threatwindows,series:receiptitems,series:planstateequiv,series:auditorreplay,wiki:scheduling,wiki:stopadd,wiki:knapsack}

\paragraph{Backbone $\to$ receipt $\to$ release spine.}
For later maintenance, the import chain should stay explicit: backbone mathematics justifies a witness family or bound; the synthesis layer turns that export into a receipt line item and replay promise; the worked example's owner map says \emph{which note owns which field}; the worked example's release spine says \emph{how a published claim should evolve across releases}; and Synthesis~31 owns the final downstream sentence-normalization suffix once the task becomes stable public wording rather than new evidence. That separation is the main anti-redundancy gain: papers can cite the backbone for the theorem, the synthesis layer for the receipt interface, Synthesis~55 for the maintained theorem-to-review bridge, the release spine for successor-maintenance order, and Synthesis~31 only when they need reusable public wording that still resolves leftward to the narrower verdicts.\cite{series:receiptitems,series:planstateequiv,series:workedexample,series:downstreamnormalforms,series:seriesspines}

\section{Research prompts (where more work seems warranted)}
The backbone notes provide strong local results; several cross-paper ``glue'' problems remain worthwhile:
\begin{itemize}[leftmargin=1.2em]
\item \textbf{End-to-end composition across heterogeneous witnesses.} Provide a single receipt-grade theorem that composes a delegation bound (spectral) with a stop-time padding bound (TV) under one threat-window declaration.
\item \textbf{Directed/weighted overlays in deployment.} The spectral note treats directed overlays; the series would benefit from a deployment-facing canonicalization of ``what graph object is committed'' when the overlay is dynamic.
\item \textbf{Certificate compression and witness minimization.} Dual certificates can be large; connecting the routing-signature compression work to padding/TV certificates is a practical next step.\cite{series:routingcompress}
\item \textbf{Separation/failure modeling.} For separation-qualified primary paths, publishing a credible $\rho$ remains operationally hard; the probabilistic separation note (Synthesis~23) lists evidence shapes, but calibrating them against modern reconnaissance and compromise rates is an open deployment discipline problem.\cite{series:probsep}
\end{itemize}
