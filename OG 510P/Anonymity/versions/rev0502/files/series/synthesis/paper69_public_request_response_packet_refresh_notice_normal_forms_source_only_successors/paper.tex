\begin{abstract}
The source-only successor branch can now say which exact bounded response packet should travel for one concrete follow-up about a visible public-request notice, whether that packet survives a successor release, which packet-local field families refresh when it is reused, and what exact outward-facing sentence may describe that reissued handoff slice. One smaller publication question still remained. Which sentence family is canonical for that visible packet-refresh notice, so later terse papers can reuse the reissue wrapper without treating each emitted sentence as bespoke prose? This note gives that owner one home. It defines compact \emph{public request response packet refresh notice normal forms}: maintained template-and-slot objects factoring one emitted packet-refresh notice into a canonical sentence family plus explicit slot bindings, without re-owning the emitted wrapper sentence, the packet-local delta ledger, or the exact bounded packet slice it summarizes.
\end{abstract}

\section{Why packet-refresh-notice normal forms deserve their own note}
A later terse note may want to cite not merely the exact emitted reissue sentence for one maintained packet, but the canonical wrapper family that such sentences must realize when the packet is reusable.
Without one maintained normal-form owner, neighboring notes either quote one concrete sentence as if it were the whole canonical family or silently drift in wording while claiming to say the same thing.
That is a different question from who owns the emitted wrapper sentence itself.
The emitted refresh notice owns the exact sentence and reader-pointer order for one release cut.
The normal form owns the canonical family that emitted sentence is allowed to realize.

\begin{definition}[Public request response packet refresh notice normal form]
Fix one emitted public request response packet refresh notice $N$ whose basis is one public request response packet delta ledger $\Delta$.
A \emph{public request response packet refresh notice normal form} is a tuple
\[
F=(\tau,\Theta,\Lambda,\rho,\sigma)
\]
consisting of one notice kind $\tau$, one allowed delta-token set $\Theta$, one ordered literal-and-slot template $\Lambda$, one realization map $\rho$ sending each slot to an already-owned field in the imported emitted notice or its delta-ledger basis, and one rendered sentence $\sigma$ produced by substituting those slot values into $\Lambda$.
The normal form does not own the emitted notice instance.
It owns only the canonical family and the explicit slot map making that visible reissue sentence auditable.
\end{definition}

\begin{definition}[Delta-compatibility rule]
A public request response packet refresh notice normal form satisfies the \emph{delta-compatibility rule} if its allowed delta-token set agrees with the imported packet-refresh notice and its imported delta-ledger basis.
For a refresh-in-place form, the allowed delta token must match the imported packet delta ledger's \texttt{refresh\_fields} verdict and the visible changed-field phrase must be computed only from the imported refresh instructions. Reusing the same changed-field-family phrase across multiple notices is allowed only through that imported packet-local vocabulary.
For a reopen form, the normal form may name no unchanged-slice claim.
So the normal form may not authorize a visible reissue family for a delta verdict the imported basis object does not actually certify.
\end{definition}

\begin{definition}[Slot-realization rule]
A public request response packet refresh notice normal form satisfies the \emph{slot-realization rule} if every non-literal semantic phrase in its rendered sentence is carried by an explicit slot whose source field is named in the realization map, and if substituting those slot values into the template produces the emitted refresh-notice sentence exactly.
One slot may realize a maintained field-family list only through an explicit render map or join rule declared in the slot binding.
So the normal form may compress wording, but it may not hide successor-maintenance semantics in undeclared glue text.
\end{definition}

\begin{definition}[Emitted-notice inheritance rule]
A public request response packet refresh notice normal form satisfies the \emph{emitted-notice inheritance rule} if every emitted packet-refresh-notice key it names already exists in the companion packet-refresh-notice ledger and if the normal form changes neither the emitted notice's reader-pointer order nor the narrower packet-delta owner artifacts that emitted notice already imports.
So the normal form may factor the sentence family, but it may not replace the concrete emitted wrapper instance.
\end{definition}

\begin{lemma}[Canonical refresh-notice families reduce wording drift without replacing emitted-notice ownership]
If a public request response packet refresh notice normal form satisfies the delta-compatibility, slot-realization, and emitted-notice inheritance rules, then a later terse paper may cite the normal form when it needs the canonical successor-facing wrapper family for a reusable source-only response packet, while still citing the emitted packet-refresh notice when it needs to say which exact visible sentence and pointer order were actually shipped.
\end{lemma}

\begin{proof}
The delta-compatibility rule prevents the normal form from licensing a packet-refresh sentence family for a reuse verdict or changed-field set that the imported delta ledger does not certify.
The slot-realization rule ensures that the visible reissue sentence is reconstructed exactly from declared literals and owned delta-ledger or emitted-notice fields rather than from hidden prose drift.
The emitted-notice inheritance rule prevents the normal form from silently taking over the concrete emitted wrapper sentence or its pointer order.
Therefore the normal form contributes one reusable sentence family, not a new packet-delta owner and not a replacement for the emitted refresh notice.\qedhere
\end{proof}

\begin{remark}[Minimal citation rule]
Cite the packet-refresh-notice normal form when the claim is about \emph{which canonical successor-facing wrapper family or template was used}.
Cite the packet-refresh notice when the claim is about \emph{which exact visible reissue sentence and pointer order were actually emitted}.
Cite the packet delta ledger when the claim is about \emph{which exact packet-local field families refreshed or whether the packet reopened}.
\end{remark}

\section{Worked example pointer}
The maintained worked bundle now ships \nolinkurl{example_public_request_response_packet_refresh_notice_normal_forms.json}.\cite{series:workedexample}
It contains one maintained normal-form entry for each emitted worked packet-refresh notice, and each such entry reuses the same explicit literal-and-slot schema for the refresh-in-place case: successor release, rendered request-class label, rendered notice-kind label, and the joined changed-field-family phrase.
That gives later terse papers one citeable owner for the canonical reissue-wrapper family without confusing that family with the concrete emitted packet-refresh notice or the narrower packet-local delta ledger. But later terse papers that are not disputing the canonical wrapper family itself should usually cite Synthesis~73--75 instead of re-narrating this family layer. The worked note now also makes explicit that the shared changed-field-family vocabulary still comes from the packet-local delta owner, while the reusable wrapper family here remains notice-kind/request-class scoped. In the maintained worked bundle, the same refresh-notice normal-form keys are now imported directly onto the shipped audience/question routes, and the companion route/spine refresh-family-mode map says directly that repeated canonical refresh-family labels recur there only as imported packet-local delta vocabulary rather than as new route-owned wrapper policy, so the canonical visible reissue family is recoverable from the route object itself without blurring that ownership split.
