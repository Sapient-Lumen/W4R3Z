\begin{abstract}
Challenge answer capsules already solve the one-piece problem.
They let a later note hand one audience one auditable bundle for one certified semantic piece.
But many downstream questions are not one-piece questions: a public-status challenge may need both continuity and closure, while a compact-diff challenge may need numeric deltas, changed-family identity, and an off-surface recomputation witness.
This note gives that next aggregation one home.
It defines a compact \emph{challenge answer sheet}: one audience-question handoff that lists the piece-complete capsule set, in declared stop-profile order, without restating branches, witness cores, terminal owners, or surface hooks inline.
\end{abstract}

\paragraph{Non-redundancy note.}
Synthesis~36 owns audience-keyed start paths and escalation order, Synthesis~37 owns question-keyed semantic pieces and approved terminal fields, Synthesis~45 owns one-piece answer capsules, Synthesis~47 owns the final emitted answer cards built from a sheet plus a sentence lock, Synthesis~54 owns the answer-side terminal citation normal form, Synthesis~74 owns the paired terminal citation discipline, Synthesis~75 owns the paired cutover rule, and Synthesis~17 owns the concrete worked instantiation.
This note owns only the audience-question handoff that later notes should reopen when the exact whole-question piece-complete bundle is itself live; it deliberately stops before the final emitted answer object.

\paragraph{Scope.}
This is not a new route map, stop profile, coverage certificate, branch map, witness core, witness slice, or answer capsule.
It is a narrow publication-interface note about grouping already-certified capsules into one piece-complete audience-question handoff.

\section{Why answer sheets deserve their own note}
A later note often needs the whole answer to one downstream question, not just one piece of it.
That is a different packaging problem from Synthesis~45.
The stop profile already says which semantic pieces the question contains, and the capsule ledger already says how to answer each one piece-by-piece.
But if a release note, referee memo, or audit handoff keeps rebuilding the same multi-piece bundle by hand, the archive either repeats the same capsule keys everywhere or quietly drifts into prose like ``for this question, gather these two or three capsules.''
So the series benefits from one small object whose only job is to say: for this audience and this question family, here is the piece-complete capsule set in the declared order, with the surfaced and support-only parts explicitly separated.

\begin{definition}[Challenge answer sheet]
Fix one concrete base$\to$successor comparison, one audience key $a$, and one downstream question key $q$.
A \emph{challenge answer sheet} is a tuple
\[
G(a,q)=(a,q,f,r,s,\mathbf{p},\Gamma,\Gamma_{\mathrm{surf}},\Gamma_{\mathrm{sup}})
\]
containing the audience key $a$, question key $q$, sentence family $f$, one route key $r$, one stop-profile key $s$, an ordered nonempty list $\mathbf{p}$ of semantic piece keys for that audience-question pair, an ordered nonempty list $\Gamma$ of challenge answer-capsule keys, a list $\Gamma_{\mathrm{surf}}\subseteq \Gamma$ of surface-carried capsule keys, and a list $\Gamma_{\mathrm{sup}}\subseteq \Gamma$ of support-only capsule keys.
\end{definition}

\begin{definition}[Audience-question piece-completeness rule]
A challenge answer sheet satisfies the \emph{audience-question piece-completeness rule} if the ordered piece list $\mathbf{p}$ matches exactly the semantic-piece order declared by the companion stop profile for $(a,q)$, and if the ordered capsule list $\Gamma$ contains exactly one imported answer capsule for each listed piece and no others.
\end{definition}

\begin{definition}[Capsule-factorization rule]
A challenge answer sheet satisfies the \emph{capsule-factorization rule} if it references imported answer capsules rather than restating their branch keys, coverage entries, witness cores, witness slices, terminal-witness keys, or surface-hook keys inline.
The sheet may name the audience route and the stop profile it serves, but the proving payload stays in the imported capsules.
\end{definition}

\begin{definition}[Surface/support partition rule]
A challenge answer sheet satisfies the \emph{surface/support partition rule} if $\Gamma_{\mathrm{surf}}$ and $\Gamma_{\mathrm{sup}}$ partition $\Gamma$ according to the coverage modes of the imported capsules.
In particular, every surfaced piece appears in $\Gamma_{\mathrm{surf}}$, while every support-only piece appears in $\Gamma_{\mathrm{sup}}$.
\end{definition}

\begin{lemma}[Answer sheets keep whole-question handoffs compact without changing certification content]
Assume every answer sheet satisfies the audience-question piece-completeness rule, the capsule-factorization rule, and the surface/support partition rule.
Then a later note may hand one sheet to one audience as the whole auditable answer to one downstream question without changing the certification content already carried by the imported routes, stop profiles, and answer capsules.
\end{lemma}

\begin{proof}
The audience-question piece-completeness rule prevents the sheet from omitting one semantic piece of the declared question or from silently mixing in pieces from another question family.
The capsule-factorization rule keeps ownership where it already belongs: the sheet groups capsules but does not rewrite their proving payload.
The surface/support partition rule preserves the visible/off-surface boundary already certified by those capsules.
So the sheet changes only packaging: it gives one piece-complete audience-question handoff, but it does not alter the underlying certification facts.\qedhere
\end{proof}

\section{Worked example pointer}
The maintained worked bundle now ships \path{example_successor_challenge_answer_sheets.json}.\cite{series:workedexample}
It records four answer sheets for the canned Case-B successor: one each for the release-note and referee public-status question, and one each for the release-note and auditor compact-diff question.
Concrete keys already in the ledger include \path{release_note_public_status_sentence_answer_sheet} and \path{auditor_compact_diff_summary_answer_sheet}.
Each sheet binds one audience, one question family, one route, one stop-profile order, the piece-complete ordered capsule set for that question, and the surfaced/support-only partition induced by those capsules.
That keeps Synthesis~45 about one-piece bundles and lets later notes cite one compact whole-question handoff only when they truly need the entire audience-question answer rather than one semantic piece at a time.\cite{series:challengeanswercapsules}

\paragraph{Why this helps the series.}
The archive is now cleaner at both scales.
A terse note can still cite one capsule when only one piece is disputed.
A fuller referee or audit handoff can cite one answer sheet when the whole downstream question must travel together.
That is a better stable spine for future release-evolution notes than repeatedly improvising a multi-piece bundle in prose. When a later note also wants the shipped sentence and the inherited visible-provenance mode, it should import Synthesis~47 rather than widening the sheet object here.\cite{series:challengeanswercards}
