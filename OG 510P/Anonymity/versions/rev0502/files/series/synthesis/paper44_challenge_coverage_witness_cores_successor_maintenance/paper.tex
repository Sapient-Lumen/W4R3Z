\begin{abstract}
A challenge coverage witness pack can already bind one coverage claim to the exact audience routes and route-specific branches that certify it.
A companion witness-slice ledger can already project that claim down to one audience at a time.
But both objects still rely on the same piece-local terminal witnesses and the same surface hooks whenever those dependencies do not vary by audience.
This note isolates that common layer.
It defines a compact \emph{challenge coverage witness core} that binds one coverage entry to the exact audience-invariant proving keys: the piece-local terminal witnesses that must always be available and, when the claim is surface-carried, the exact surface hooks that realize it.
\end{abstract}

\section{Why witness cores deserve their own note}
When one coverage claim is certified for several audiences, the varying part of the proof burden is usually just the route key and the route-specific branches.
The piece-local terminal witness is often identical for every audience, and if the claim is surface-carried the exact surface hooks are identical too.
If those audience-invariant dependencies are repeated inside every audience slice, later notes either overstate what one audience actually contributes or carry avoidable duplication in every compact certification object.
So the archive benefits from one small object whose only job is to say which proving keys remain fixed no matter which certified audience is using the claim.

\begin{definition}[Challenge coverage witness core]
Fix one concrete base$\to$successor comparison and one already-declared coverage entry $e$ from a companion coverage certificate.
A \emph{challenge coverage witness core} for $e$ is a tuple
\[
K(e)=(e,f,p,m,W,H)
\]
containing the coverage-entry key $e$, the sentence family $f$, the semantic piece key $p$, the coverage mode $m\in\{\textsf{surface},\textsf{support-only}\}$, a finite nonempty set $W$ of piece-local terminal-witness keys, and a finite set $H$ of exact surface-hook keys.
\end{definition}

\begin{definition}[Audience-invariance rule]
A witness core satisfies the \emph{audience-invariance rule} if every listed terminal-witness key and every listed surface-hook key resolves to the same sentence family and piece key, independent of audience route.
\end{definition}

\begin{definition}[Surface/support-only core rule]
A witness core satisfies the \emph{surface/support-only core rule} if $m=\textsf{surface}$ implies $H\neq\varnothing$, while $m=\textsf{support-only}$ implies $H=\varnothing$.
In either case the listed terminal-witness keys in $W$ remain mandatory.
\end{definition}

\begin{definition}[Factorization rule]
Let $\Pi(e)$ be the companion aggregate witness pack for $e$ and let $\Sigma_a(e)$ range over the companion audience-specific witness slices.
The family satisfies the \emph{factorization rule} if the audience-varying route and branch keys are carried by $\Pi(e)$ and the $\Sigma_a(e)$ objects, while the audience-invariant terminal-witness and surface-hook keys are carried once by $K(e)$ and referenced rather than restated by those companions.
\end{definition}

\begin{lemma}[Witness cores remove duplicate proving burden without changing certification]
Assume every coverage entry is paired with a witness core satisfying the audience-invariance rule, the surface/support-only core rule, and the factorization rule.
Then later notes may cite one audience-specific proving slice or one aggregate proving bundle without restating the same terminal/surface dependencies each time, while preserving the exact certification content of the original coverage claim.
\end{lemma}

\begin{proof}
The audience-invariance rule keeps the core tied to one sentence family and one semantic piece rather than letting it float across audiences.
The surface/support-only core rule preserves the boundary between visible realization and off-surface support hooks.
The factorization rule then says that route- and branch-dependent obligations stay with packs and slices, while common terminal/surface obligations stay in one shared core.
So the proving content is unchanged, but the repeated audience-invariant keys no longer need to be restated in every audience-specific object.\qedhere
\end{proof}

\section{Worked example pointer}
The maintained worked bundle now ships \path{example_successor_challenge_coverage_witness_cores.json}.\cite{series:workedexample}
It records five witness cores for the canned Case-B successor: one for each coverage entry.
Each core names the same piece-local terminal witness already declared elsewhere, and for surface-carried claims it also names the exact surface hooks shared by every certified audience of that claim.
That keeps Synthesis~42 about aggregate route-and-branch bundles, Synthesis~43 about audience-specific route-and-branch deltas, and this note about the audience-invariant proving keys both of those objects reuse.\cite{series:challengecoveragewitnesspacks,series:challengecoveragewitnessslices}

\paragraph{Why this helps the archive.}
The series can now cite the common proof burden once, then let compact aggregate packs and audience-specific slices state only what actually varies with audience.
That is the right next tightening for brief referee-grade notes.

\paragraph{One tiny witness-core drill.}
For the worked continuity claim, \nolinkurl{public_status_sentence_continuity_piece_witness_core} still forces the same shared proving burden while the same continuity coverage entry, the same \nolinkurl{continuity_piece}, the same terminal witness, and the same realized surface hook still agree for every certified audience. If the live question widens from ``is this still the shared proving core for the continuity claim?'' to ``what is the route-and-branch delta for the release-note user?'' the honest stop is no longer this note but Synthesis~43. If the live question stays audience-invariant but the support posture flips, the shared hook set changes, or the maintained core no longer factors the same companion pack and slices, the matrix has gone stale and a later terse paper must reopen the exact witness-core owner rather than keep quoting the old shared proving burden. Only once the shared core is fixed and the remaining issue becomes the maintained answer-side handoff or paired terminal cutover should the paper leave this note for Synthesis~54 or Synthesis~74--75.\cite{series:workedexample}
