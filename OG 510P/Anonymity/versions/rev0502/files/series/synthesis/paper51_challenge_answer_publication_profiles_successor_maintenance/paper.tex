\begin{abstract}
The series now has enough late-stage answer structure that two different choices can drift if they are left implicit: which maintained answer object should be cited, and how much visible provenance should travel beside the emitted sentence when space is tight. Citation dockets already solve the first choice. Sentence locks already solve the second. But later papers still tend to re-pair those two policies ad hoc. This note isolates that publication-level pairing. It defines a compact challenge answer publication profile: one audience/question map from common publication budgets to one emitted answer card under one declared inline-provenance mode, together with the exact-location and full-audit escalation objects to cite when the terse form is no longer enough. The profile does not create a new semantic stage. It keeps publication choices brief, auditable, and inherited from already-maintained answer and reuse objects.
\end{abstract}

\section{Why answer publication profiles deserve their own note}
Once the late-stage answer stack is in place, later papers still face a smaller but recurrent publication question.
Suppose the author already knows which audience/question answer is relevant.
Now the real question is: under the current space budget, should the note print the emitted answer silently, print it with the visible-provenance floor, print it with the full visible capsule, point to the exact shipped carrier slot, or send the reader all the way to the full audit trail?
Those are not semantic disagreements.
They are publication-policy choices drawn from already-maintained objects.
If they remain implicit, terse papers drift between inconsistent visible-provenance practice and inconsistent escalation targets.
So the archive benefits from one thin publication object whose only job is to say: for this audience and this downstream question, these are the allowed brief, expanded, exact-location, and full-audit publication forms.

\begin{definition}[Challenge answer publication profile]
Fix one concrete base$\to$successor comparison, one audience key $a$, and one downstream question key $q$.
A \emph{challenge answer publication profile} is a tuple
\[
P(a,q)=(a,q,C,D,E_{\mathrm{def}},E_{\mathrm{exp}},K,T)
\]
containing one imported answer-card key $C$, one imported answer-citation-docket key $D$, one default-inline publication entry $E_{\mathrm{def}}$, one expanded-inline publication entry $E_{\mathrm{exp}}$, one exact-location escalation entry $K$, and one full-audit escalation entry $T$.
The two inline publication entries both reuse the same emitted answer card but under different already-declared inline-provenance modes from its imported sentence lock.
The escalation entries import the exact-location and full-audit choices from the citation docket rather than inventing new ones.
\end{definition}

\begin{definition}[Budget-local publication rule]
A challenge answer publication profile satisfies the \emph{budget-local publication rule} if its default-inline entry is the smallest declared inline form later notes should inherit for brief publication, while its expanded-inline entry keeps the same emitted answer card but switches to a strictly larger declared inline-provenance mode from the same sentence lock.
The profile may therefore choose among already-declared publication sizes, but it may not create new sentence text, new answer semantics, or new citation owners.
\end{definition}

\begin{definition}[Inherited-visibility rule]
A challenge answer publication profile satisfies the \emph{inherited-visibility rule} if every inline entry names exactly one declared inline-provenance profile from the imported sentence lock and its visible field list agrees exactly with that profile.
So publication profiles may choose among declared visible-provenance modes, but they may not improvise new visible fields or suppress declared ones while claiming to use the same mode.
\end{definition}

\begin{definition}[Escalation-companion rule]
A challenge answer publication profile satisfies the \emph{escalation-companion rule} if its exact-location escalation entry agrees exactly with the citation docket's exact-carrier entry and its full-audit escalation entry agrees exactly with the citation docket's full-audit entry.
So the profile may package common publication escalations, but it may not replace the docket's smallest-sufficient selection logic.
\end{definition}

\begin{lemma}[Publication profiles keep brief reuse consistent without changing answer ownership]
Assume every challenge answer publication profile satisfies the budget-local publication rule, the inherited-visibility rule, and the escalation-companion rule.
Then a later note may cite one publication profile as the common publication guide for one audience/question pair without changing the ownership of emitted-answer identity, visible-provenance policy, exact carrier location, or full audit.
\end{lemma}

\begin{proof}
The budget-local publication rule keeps the profile on the publication side of the series: it only chooses among already-declared brief and expanded forms of the same emitted answer card.
The inherited-visibility rule prevents the profile from silently inventing a new visible-provenance bundle while pretending to reuse the same sentence-lock discipline.
The escalation-companion rule then prevents the profile from replacing the citation docket when later notes need exact location or full audit.
So the profile changes only packaging: it makes publication choices stable and compact, but it does not alter answer semantics, sentence-lock policy, exact-location ownership, or the full audit walk.\qedhere
\end{proof}

\section{Worked example pointer}
The maintained worked bundle now ships \texttt{example\_successor\_challenge\_answer\_publication\_profiles.json}, and the newer spine/routing adjuncts mirror each shipped profile as one compact publication-budget map on the corresponding answer route.\cite{series:workedexample}
It records four publication profiles for the canned Case-B successor.
Each profile follows one audience/question pair and names one emitted answer card, one answer-citation docket, one default-inline publication entry, one expanded-inline publication entry, one exact-location escalation entry, and one full-audit escalation entry. The mirrored route-side publication-budget map does not create a second owner; it only makes those four already-owned choices directly visible at the same place where the archive already records the public anchor, stop profile, sentence lock, and review menu for that answer.
Concrete keys already in the ledger include \texttt{release\_note\_public\_status\_sentence\_answer\_publication\_profile} and \texttt{auditor\_compact\_diff\_summary\_answer\_publication\_profile}.
For the release-note public-status profile, the default-inline entry reuses the emitted answer card under the declared floor profile, the expanded-inline entry switches to the capsule profile from the same sentence lock, the exact-location entry points at the lineage-notice carrier slot, and the full-audit entry points at the matching public-status audit trail.
For the auditor compact-diff profile, the same pattern reuses the compact-diff answer card under the floor and capsule profiles, then escalates to the clause-pack carrier slot or the full compact-diff audit trail when more detail is needed.

\paragraph{Why this helps the series.}
Citation dockets already answer which late-stage object is smallest sufficient for a given reuse goal.
Sentence locks already answer which visible-provenance modes are allowed beside unchanged wording.
A publication profile is the missing glue for brief papers: it says how to combine those two policies once per audience/question pair, so later notes can stay terse without letting publication practice drift sentence by sentence. The new route-side publication-budget map then makes that same glue directly reusable at the theorem-to-review bridge without moving publication ownership away from the profile itself.
But once the live question has already reached the checked-answer stop, later terse papers should usually cite the answer-side terminal citation normal form and paired cutover rule instead of reopening the profile; the profile reopens only when the exact brief-versus-expanded inline provenance budget is itself the issue.\cite{series:challengeanswerreviewmenus,series:pairedterminalcitationdiscipline,series:pairedterminalcutoverrules}
The further question of which exact deeper audit slice should be handed over on request is intentionally left to the disclosure-packet note, so this note stays about inline publication rather than archive handoff.
