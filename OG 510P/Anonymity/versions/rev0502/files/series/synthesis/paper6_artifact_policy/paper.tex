\begin{abstract}
This archive is designed for short, referee-grade papers that remain readable and checkable without shipping a large companion repository.
Accordingly, the public release is \emph{source-only} (one \texttt{.tex} file per paper), while artifacts that are useful for deeper auditing
(e.g., scripts, logs, simulations, certificates/keys, measurement traces, and raw data) are distributed on request.
This micro-note standardizes the disclosure language used throughout the series and clarifies what is available, under what conditions, and how it is indexed.
\end{abstract}

\paragraph{Scope.}
Define the disclosure contract for this source-only public release: what is shipped publicly, what is held back, and how on-request artifacts are indexed to the public papers. This is intentionally a one-paragraph policy note plus canonical boilerplate, kept standalone for citation convenience.

\paragraph{Imports.}
None.

\paragraph{Exports.}
Canonical boilerplate and a manifest-indexing rule used by every paper in this archive when referring to artifacts, tooling, certificates, or raw evidence. This note owns only the archive-wide source-only policy. Exact paper-facing packet cuts, request menus, and omitted-support family names belong to later successor-maintenance notes when needed.

\paragraph{Artifact policy.}
This note \emph{is} the archive-wide artifact policy; it is the canonical citation target \cite{series:artifactpolicy}. When a later paper needs the exact paper-level public-on-request cut rather than only the archive-wide boilerplate, it should cite the maintained public-request-contract note as well. If it also needs a stable name for the omitted-support family that cut is promising, it should cite the requestable-evidence-classes note.\cite{series:publicrequestcontracts,series:requestableevidenceclasses}

\paragraph{Later-terse-paper citation posture.}
Later terse papers should cite this note only for the archive-wide source-only boilerplate itself: that the public release ships one \texttt{.tex} file per paper plus a manifest, and that deeper artifacts may be furnished on request under that archive-wide policy. Once the live question becomes the exact paper-level packet/menu/validator cut promised behind one paper's ``available on request'' sentence, widen to Synthesis~56--58 instead. Once the live question is already about ABOM/OINL packaging or cross-release lineage of the public claim object, stop at Anonymity~C / Release~A rather than asking this note to own release-facing details.\cite{series:publicrequestcontracts,series:requestableevidenceclasses,series:requestfulfillmentcertificates,series:abomoinl,series:releaseproperty}



\section{Policy statement (canonical)}
\paragraph{Public release.}
The public archive contains only referee-facing \LaTeX{} sources (one file per paper) plus a manifest of file hashes.
When a paper refers to paths such as \texttt{tools/}, \texttt{scripts/}, \texttt{evidence/}, or \texttt{certs/}, these refer to an \emph{artifact bundle}
that is not included in the public release.

\paragraph{On-request artifacts.}
On request, we can provide an archive containing the referenced artifacts, including (as applicable):
(i) build scripts and dependency locks;
(ii) raw and processed data;
(iii) simulation code and seeds;
(iv) evaluation harnesses;
(v) certificates/keys for proof-carrying plans and logs;
(vi) transparency-log checkpoints and witnesses; and
(vii) any auxiliary notes needed to reproduce plots or tables.

\paragraph{Disclosure control.}
Each paper may state additional disclosure constraints (e.g., what portions of logs or measurements can be shared publicly).
Absent an explicit restriction, artifacts are available to referees/auditors under a standard confidentiality assumption.

\paragraph{Indexing.}
The artifact bundle is indexed to this public release by the SHA256 manifest included at the archive root. Later notes may additionally maintain a paper-facing public request contract saying which exact packet/menu/validator slice corresponds to one short paper's public ``available on request" sentence; that narrower ownership does not belong here. Reusable omitted-support family names likewise belong one note later still, and exact completion criteria for satisfying such a request belong in Synthesis~58 rather than here.\cite{series:publicrequestcontracts,series:requestableevidenceclasses,series:requestfulfillmentcertificates}

\section{Recommended boilerplate (non-redundant)}
Papers in this archive may include the following short paragraph:
\begin{quote}
\emph{Artifact policy.} This archive is source-only; supporting artifacts are available on request. See \cite{series:artifactpolicy}. If this paper cites a maintained public request contract, that contract fixes the exact packet/menu cut behind this sentence. If this paper also cites a requestable evidence class, that class names the omitted-support family behind the cut without expanding the boilerplate itself. If it further cites a request-fulfillment certificate, that certificate says when the promised cut has actually been satisfied.\cite{series:publicrequestcontracts,series:requestableevidenceclasses,series:requestfulfillmentcertificates}
\end{quote}
