\begin{abstract}
The late-stage answer stack now has enough narrow objects that later notes face a new repetition problem: for one audience and one downstream question, should a citation point at the one-piece capsule, the whole-question sheet, the emitted answer card, the exact carrier slot, or the full leftward audit trail? This note isolates that selection problem. It defines a compact challenge answer citation docket: one audience/question map from common downstream reuse goals to the smallest sufficient already-maintained answer object. The docket does not create a new semantic stage. It imports the existing answer layers and records which one is sufficient for piece-local citation, whole-question handoff, emitted-answer identity, exact shipped location, or full audit. That keeps later papers brief without letting answer-layer citation practice drift ad hoc.
\end{abstract}

\paragraph{Exports.}
This note exports (i) challenge answer citation dockets, (ii) a smallest-sufficient answer-selection rule, (iii) a piece-order preservation rule for piece-local citation entries, and (iv) a late-stage selection locality rule saying that later notes may cite one maintained selection object only when the live question is which answer-layer object is smallest sufficient for one piece-local citation, one whole-question handoff, one emitted-answer identity claim, one exact shipped location, or one full leftward audit. \section{Why answer citation dockets deserve their own note}
The series now has a clean late-stage answer stack.
A capsule handles one semantic piece.
A sheet handles one whole audience/question handoff.
A card handles one released audience/question answer object.
A carrier slot handles the exact shipped field or reusable clause carrying that answer.
An audit trail handles the full leftward reader walk from that carrier location to the narrow terminal owners.
That stack is narrow and useful, but later notes still repeat a smaller operational choice: for this audience and this question, which of those already-maintained objects is the smallest sufficient citation target for the current downstream purpose?
Without a maintained answer-selection object, that choice drifts back into prose.

\begin{definition}[Challenge answer citation docket]
Fix one concrete base$\to$successor comparison, one audience key $a$, and one downstream question key $q$.
A \emph{challenge answer citation docket} is a tuple
\[
D(a,q)=(a,q,\Pi,S,C,K,T)
\]
containing an ordered family $\Pi=(\pi_1,\dots,\pi_m)$ of piece-citation entries, one imported answer-sheet key $S$, one imported answer-card key $C$, one imported answer-carrier-slot key $K$, and one imported answer-audit-trail key $T$.
Each piece-citation entry $\pi_i$ names exactly one imported answer-capsule key for the $i$th semantic piece of the imported answer sheet, together with the downstream use condition under which that one-piece capsule is the smallest sufficient citation target.
\end{definition}

\begin{definition}[Smallest-sufficient answer-selection rule]
A challenge answer citation docket satisfies the \emph{smallest-sufficient answer-selection rule} if it chooses:
\begin{enumerate}[leftmargin=*]
\item one imported answer capsule when the downstream need is one semantic piece only,
\item one imported answer sheet when the need is the whole audience/question handoff,
\item one imported answer card when the need is the released answer object itself,
\item one imported answer carrier slot when the need is the exact shipped location of that answer, and
\item one imported answer-audit trail when the need is the full leftward walk to the narrow terminal owners.
\end{enumerate}
So the docket changes only citation choice; it does not collapse the imported answer layers into one larger semantic object.
\end{definition}

\begin{definition}[Piece-order preservation rule]
A challenge answer citation docket satisfies the \emph{piece-order preservation rule} if its ordered piece-citation entries agree exactly with the semantic-piece order declared by the imported answer sheet and if each such entry points at the matching imported one-piece answer capsule.
So a later note that wants only one piece can still recover the whole-question ordering discipline rather than citing a detached capsule out of context.
\end{definition}

\begin{definition}[Late-stage selection locality rule]
A challenge answer citation docket satisfies the \emph{late-stage selection locality rule} if every imported object key in the docket belongs to the same audience/question pair and if the docket records no new semantics, coverage, branch walk, carrier location, or audit path beyond what those imported objects already own.
The docket may select among late-stage answer objects, but it may not become a substitute answer object itself.
\end{definition}

\begin{lemma}[Citation dockets keep answer-layer reuse brief without changing ownership]
Assume every challenge answer citation docket satisfies the smallest-sufficient answer-selection rule, the piece-order preservation rule, and the late-stage selection locality rule.
Then a later note may cite one docket as the answer-layer selection guide for one audience/question pair without changing the ownership of piece semantics, whole-question assembly, emitted-answer identity, exact carrier location, or full audit walk.
\end{lemma}

\begin{proof}
The smallest-sufficient answer-selection rule ensures that each downstream reuse goal resolves to one already-owned late-stage answer object and no larger one.
The piece-order preservation rule prevents piece-local citation from drifting away from the declared whole-question ordering discipline.
The late-stage selection locality rule then prevents the docket from silently re-owning semantics, carrier location, or proof walks.
So the docket changes only packaging: it keeps late-stage citation choice stable and auditable, but it does not create a new answer stage or replace any narrower answer object.\qedhere
\end{proof}

\section{Worked example pointer}
The maintained worked bundle now ships \texttt{example\_successor\_challenge\_answer\_citation\_dockets.json}.\cite{series:workedexample}
It records four citation dockets for the canned Case-B successor.
Each docket follows one audience/question pair and names five late-stage citation choices: one ordered piece-citation list of imported answer capsules, one imported answer sheet, one imported answer card, one imported answer carrier slot, and one imported answer-audit trail.
Concrete keys already in the ledger include \texttt{release\_note\_public\_status\_sentence\_answer\_citation\_docket} and \texttt{auditor\_compact\_diff\_summary\_answer\_citation\_docket}.
For the release-note public-status docket, the piece-level entries point at the continuity and closure capsules, the whole-question entry points at the release-note public-status answer sheet, the emitted-answer entry points at the matching answer card, the exact-location entry points at the lineage-notice carrier slot, and the full-audit entry points at the release-note public-status audit trail.
For the auditor compact-diff docket, the same pattern selects three piece capsules, the whole-question compact-diff sheet, the compact-diff answer card, the clause-pack carrier slot, and the full compact-diff audit trail.

\paragraph{Why this helps the series.}
The late-stage answer stack is now stable enough that the next failure mode is not missing semantics but ad hoc citation choice.
A docket fixes that choice once per audience/question pair.
Later papers can stay brief by citing the docket when the real question is ``which answer-layer object should I cite here?'' The worked question-routing catalog now mirrors that docket key beside the emitted-answer and publication-budget bindings, so terse downstream notes do not have to recover the exact citation owner indirectly through the review menu first.
But once the live question has already reached the checked-answer stop, later terse papers should usually cite the answer-side terminal citation normal form and paired cutover rule instead of reopening the docket; the docket reopens only when the exact piece-local / whole-question / emitted-answer / exact-location / full-audit choice is itself the disputed issue.\cite{series:challengeanswerreviewmenus,series:pairedterminalcitationdiscipline,series:pairedterminalcutoverrules}
When the real question is instead piece semantics, whole-question completeness, emitted-answer identity, exact location, or full audit, the series still points leftward to the narrower note that actually owns that content.
