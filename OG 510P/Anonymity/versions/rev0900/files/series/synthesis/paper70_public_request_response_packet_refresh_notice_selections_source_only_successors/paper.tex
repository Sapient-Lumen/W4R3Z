\begin{abstract}
The source-only successor branch can now say which exact bounded response packet should travel for one paper-facing follow-up, whether that packet survives a successor release, which packet-local field families refresh when it is reused, what exact visible reissue sentence may be emitted, and what canonical template-and-slot family sits behind that sentence. One selector-sized question still remained. When the emitted refresh sentence is factored into a maintained canonical family, which such family is the right one for the actual packet-local delta token and notice kind in force here? This note gives that choice one home. It defines compact \emph{public request response packet refresh notice selections}: token-keyed selectors choosing one already-owned canonical visible reissue family for one emitted packet-refresh notice.
\end{abstract}

\section{Why packet-refresh-family choice deserves its own note}
Once a reusable source-only response packet has been refreshed, the archive already has two maintained objects: the exact emitted visible sentence and the canonical template family behind that sentence. Those still leave one small but real audit task. A referee may ask why that particular family was the right one for the actual successor-facing token basis. Without a selector owner, later notes either turn the canonical-family note into a hidden decision table or improvise prose about which family ``obviously'' applies. Selection is different from family definition. In the worked route/spine bridge it is also the first reopened owner when a visible-refresh closure fails because the emitted sentence has rebound to a new packet-local delta family.

\begin{definition}[Public request response packet refresh notice selection]
Fix one emitted public request response packet refresh notice $N$, one canonical packet-refresh-notice normal form family $F$, and one imported packet-local delta token basis $b$. A \emph{public request response packet refresh notice selection} is a tuple
\[
\Sigma(N,F,b)=(N,F,b,d)
\]
containing the emitted notice key, the selected canonical family key, the explicit selector-input token basis, and one recorded selection decision $d$.
The selection may import packet-local delta tokens, notice kind, and request class from narrower owners, but it may not redefine them.
\end{definition}

\begin{definition}[Basis-token rule]
A packet-refresh-notice selection satisfies the \emph{basis-token rule} if every selector input is imported from already-owned packet-refresh objects: the delta token from the packet-delta ledger or emitted refresh notice, the notice kind from the emitted refresh notice, and the request class from the same emitted notice. So the selector never invents a new successor-facing basis for visible reissue choice.
\end{definition}

\begin{definition}[Family-choice rule]
A packet-refresh-notice selection satisfies the \emph{family-choice rule} if it selects exactly one canonical packet-refresh-notice normal form whose allowed delta-token set contains the imported delta token and whose notice kind and request class match the emitted refresh notice. Shared changed-field-family vocabulary alone never selects a family; the licensed family is still fixed by the full notice-scoped basis. So canonical visible reissue families remain maintained reusable owners, while this note records which one applies here.
\end{definition}

\begin{definition}[Emitted-agreement rule]
A packet-refresh-notice selection satisfies the \emph{emitted-agreement rule} if the rendered sentence attached to the selector is byte-identical to both the imported emitted refresh sentence and the rendered sentence of the selected canonical normal form. So the selector cannot drift away from either narrower owner while pretending only to justify family choice.
\end{definition}

\begin{definition}[Packet-refresh-selection sentence normal form]
A public request response packet refresh notice selection \((N,F,b,d)\) exports a \emph{packet-refresh-selection sentence normal form} if it supplies exactly one clause:
\begin{quote}\small
For this visible refresh wrapper, selector \texttt{d} fixes canonical family \texttt{F} for emitted notice \texttt{N} under imported selector basis \texttt{b}.
\end{quote}
The clause is only a rendering of the already-owned family-choice judgment. It does not replace the emitted notice sentence, the canonical family realization, or the later successor-facing handoff that may follow once that family choice is fixed.
\end{definition}

\begin{lemma}[Packet-refresh-family selections make canonical reissue choice auditable without replacing sentence or family ownership]
Assume every public request response packet refresh notice selection satisfies the basis-token, family-choice, and emitted-agreement rules. Then a later terse paper may cite one maintained selector to justify why one canonical visible reissue family applies to one successor-facing source-only response-packet handoff, without re-owning either the emitted sentence or the canonical family itself.
\end{lemma}

\begin{proof}
The packet-delta ledger still owns which successor-facing field families refresh. The emitted packet-refresh notice still owns the exact outward-facing sentence. The packet-refresh-notice normal form still owns the canonical template-and-slot family behind that sentence. The basis-token rule prevents the selector from inventing a new basis. The family-choice rule prevents it from acting like a new canonical-family note. The emitted-agreement rule prevents it from restating a different visible sentence under the guise of selection. So the selector adds only one narrow contribution: a maintained explanation of why this already-owned canonical visible reissue family is the one licensed by the imported successor-facing token basis.\qedhere
\end{proof}

\section{Worked example pointer}
The maintained worked bundle now ships \nolinkurl{example_public_request_response_packet_refresh_notice_selections.json}.\cite{series:workedexample}
It contains one selector entry for every emitted packet-refresh notice in the canned successor comparison. In the present cut, every entry selects the refresh-in-place canonical visible reissue family from the imported \texttt{refresh\_fields} delta token, notice kind, and request class. That gives later terse papers one citeable owner for ``why this canonical visible reissue family?'' without widening either the emitted-sentence note or the canonical-family note. But later terse papers that are not disputing that family-choice judgment itself should usually cite Synthesis~73 for the maintained request-side terminal stop, drop to Synthesis~17 for one concrete checked-answer/request-tail seam, and widen to Synthesis~74--75 only for the abstract paired-tail discipline or abstract cutover judgment instead of narrating this selector layer. In the maintained worked bundle, those selector keys remain route-visible beside the imported refresh-notice and refresh-normal-form maps, while the companion route/spine refresh-family-mode map says directly that repeated canonical refresh-family labels recur there only as imported packet-local delta vocabulary rather than as new route-owned wrapper policy, so audit-focused later papers can still recover the whole visible successor-facing wrapper ladder from one maintained route object.
