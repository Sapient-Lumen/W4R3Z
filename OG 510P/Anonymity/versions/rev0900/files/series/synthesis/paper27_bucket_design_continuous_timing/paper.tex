\begin{abstract}
Many anonymity mechanisms expose timing (request latency, retry spacing, refresh cadence).
In this archive, deployable claims are expressed through an \emph{equalization contract} on declared
\emph{interface projections} that can be audited from logs.
Synthesis~25--26 provide conservative discrete log-audit certificates and anytime change-control for expanding audit menus.
This note fills one narrow gap: how to turn a continuous timing signal into a \emph{declared discrete projection} (a finite ``bucket'' alphabet)
that is (i) compatible with the receipt schema, (ii) statistically audit-friendly, and (iii) non-redundant with the rest of the series.
\end{abstract}

\section{Why buckets are the contract surface}
Trace interfaces in this archive treat a projection as part of an exposure normal form (ENF): a deployment declares
what is observed and what is forbidden/absent. \cite{series:traceifaces}
A continuous timing variable $T\in\mathbb{R}_{\ge 0}$ is generally \emph{not} auditably equalized from finite logs without further structure.
Accordingly, the recommended receipt-grade surface is a \emph{bucket map}
\[
b:\mathbb{R}_{\ge 0}\to\{1,\dots,m\},\qquad X \coloneqq b(T),
\]
and the equalization contract is stated for the discrete $X$ (not the raw $T$). \cite{series:profiling,series:stataudit}

\begin{remark}[Scope]
If an adversary (or an internal observer) sees the raw $T$, then equalizing $X=b(T)$ alone does not control leakage from within-bucket variation.
Receipt-grade claims should therefore be read as: \emph{the ENF forbids retaining or exposing finer timing information than $X$}.
This is the same ``interface discipline'' assumption used throughout the receipt series. \cite{series:receiptitems,series:receiptrulebook}
\end{remark}

\section{Statistical effect of alphabet size}
Let $n$ be the number of samples available for a given class/policy $k$ and menu item $\mu$.
Synthesis~25 provides a conservative radius bound for the multinomial empirical distribution on $\{1,\dots,m\}$. \cite{series:stataudit}
Inverting the (approximate) dependence on $m$ yields a simple design inequality.

\begin{lemma}[Bucket budget from the Weissman tail bound]\label{lem:mbudget}
Fix a per-item failure probability $\delta\in(0,1)$ and a target TV radius $\tau\in(0,1)$
for the empirical-to-true deviation $\TV(\widehat P,P)\le \tau$ on an $m$-bucket alphabet.
Under the Weissman-type bound used in Synthesis~25,
\[
\Pr[\TV(\widehat P,P)>\tau]\le (2^m-2)\,e^{-2n\tau^2},
\]
so a sufficient condition for failure probability at most $\delta$ is
\[
m\;\le\;\log_2\!\bigl(2+\delta\,e^{2n\tau^2}\bigr).
\]
In the common ``large-$m$'' regime where $2^m\gg 2$, this simplifies to the rule of thumb
\[
m \lesssim \frac{2n\tau^2-\log(1/\delta)}{\log 2},
\]
which is meaningful only when the right-hand side is positive.
Menu-level budgets $\delta_{\mathrm{stat}}$ are allocated across items either by a static union bound (Synthesis~25)
or an anytime spending schedule over audit events (Synthesis~26).\cite{series:anytimespend}
\end{lemma}

\section{Bucket design patterns}
This note is intentionally conservative: its goal is a clean, publishable bucket declaration and a predictable audit cost.

\paragraph{Equal-width buckets (engineering-first).}
Choose boundaries $0=t_0<t_1<\dots<t_m=\infty$ with fixed widths in a region of interest
(e.g., milliseconds up to a deadline, then a catch-all tail bucket).
This is simplest to implement and review, but can waste alphabet on rarely used regions.

\paragraph{Quantile buckets (audit-first).}
If a stable baseline exists (per class/policy), choose boundaries so that buckets have roughly equal mass under a reference distribution.
This reduces sampling noise in thin tails.
Because the boundaries depend on data, deployments should separate a \emph{pilot/estimation} phase from the \emph{frozen-audit} phase:
publish the frozen boundaries in the receipt and treat boundary changes as a new menu item (or a new audit event) with its own spending. \cite{series:anytimespend}

\paragraph{Deadline + tail-sign normal forms (mechanism-first).}
When the mechanism already enforces deadline-like behavior (padding, stop-time policies),
choose buckets aligned to those normal forms:
pre-deadline resolution, deadline bucket, and post-deadline tail buckets (often geometric in time).
This keeps the bucket map consistent with the padding feasibility analyses in the published mathematics notes. \cite{pub:stopnormal, pub:prefixcaps}

\section{Receipt-facing declaration checklist}
A bucketed timing projection should be publishable in a single place (ENF + receipt evidence), without repeating statistics:
\begin{itemize}[leftmargin=*]
\item The bucket map $b$ (explicit boundaries and the tail convention).
\item The declared projection id (used by receipts to refer to the alphabet).
\item A statement that finer timing telemetry is absent/forbidden by the ENF. \cite{series:traceifaces}
\item The log-audit certificate reference (Synthesis~25) and, if repeated, the spending rule reference (Synthesis~26). \cite{series:stataudit,series:anytimespend}
\end{itemize}

\paragraph{How later papers should cite this note.}
This note owns the \emph{bucket-map design rule}: why continuous telemetry must be turned into a declared finite alphabet, which bucket families are audit-friendly, and which receipt fields freeze that map for review. Later terse papers should cite this note when the exact timing discretization or bucket-family choice is live. If the live question is instead how the chosen projection is certified or maintained over time, cite Synthesis~25--26 for the statistical surface and cite the worked example / series spine for the maintained replay/review handoff rather than re-narrating bucket design locally.\cite{series:workedexample,series:seriesspines}
