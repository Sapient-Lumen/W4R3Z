\begin{abstract}
Anonymous DHT lookups sit at the intersection of query privacy, metadata-hiding transport/scheduling, and deployment discipline.
This note is a compact map of the literature to reduce redundancy across the One-True-Archive series.
It is not a survey; it is a \emph{reference index}: a minimal taxonomy, a few representative exemplars per branch, and a ``what-to-cite-where'' map for this archive.
\end{abstract}

\paragraph{Scope.}
We organize prior work on DHT lookup privacy (including IPFS/libp2p content routing) into a minimal taxonomy and give a short internal citation map.

\paragraph{Imports.}
We treat the series' internal primitives as imported: posterior-mass/PML and endpoint sizing (Anonymity~A; Synthesis~5), profiler/equalization contracts (Anonymity~B), ABOM/OINL (Anonymity~C), schedule-only retry wrappers (Operational~A), and separation guard objects for primary-path claims (Synthesis~22--23).\cite{series:oddsinflation,series:endpointbridge,series:profiling,series:abomoinl,series:operationalA,series:primarysepmanifest,series:probsep} For the five published math backbones (scheduling, spectral delegation bounds, stop-time padding, and TV/knapsack certificates), this note treats the crosswalk (Synthesis~24) as the canonical pointer and does not re-explain those results.\cite{series:mathcrosswalk}
\paragraph{Exports.}
Exports (i) a minimal taxonomy, (ii) representative references per branch, and (iii) a compact ``what-to-cite-where'' table for the rest of the series.

\subsection{Delegation and random-walk based lookup}
The ``anonymous lookup'' line keeps a structured DHT (e.g., Kademlia\cite{kademlia}) and adds delegation: split queries, cover traffic, and random-walk relaying.
Octopus is an archetype: it delegates queries along a random walk and adds mechanisms to resist adversarial nodes.\cite{octopus,wangborisovLookupCCS2010}
Work analyzing information leaks in structured P2P anonymity systems motivates explicit leakage accounting.\cite{mittal_tissec}

Earlier work also treated the overlay itself as privacy-critical.
Salsa and ShadowWalker build anonymity systems around structured overlays and random walks with neighbor verification.\cite{salsa,shadowwalker}

\subsection{DHT-backed relay selection and directory distribution (Tor-style low latency)}
A closely related line uses DHT lookups not to hide a DHT query, but to scale the \emph{directory/relay selection} service of a low-latency anonymity network.
AP3 selects random forwarders via secure lookups; NISAN distributes network information over a DHT to sample relays uniformly; Torsk uses ``secret buddy'' proxies to perform lookups on behalf of the initiator.\cite{ap3,nisan,torsk}
These designs motivated follow-on leakage and active-attack analyses and reinforce a core editorial rule of this archive: retry/fallback/state behavior must be treated as first-class adversarial handles, not implementation details.\cite{wangborisovLookupCCS2010,mittal_tissec,tran2009failure}

\subsection{Cryptographic query privacy (PIR / OT / PSI)}
A second line tries to cryptographically hide query contents/targets.
Backes et~al. add query privacy to robust DHTs using PIR-style techniques.\cite{backesQueryPrivacy2012}
Peer2PIR explores PIR for IPFS content routing with a different engineering and cost profile.\cite{peer2pir2024}

In this archive, we treat PIR/OT-style approaches as one point on a design frontier.
For series-internal baselines situating destination equalization (MC-EQ/CoverSketch) against PIR, delegated routing, and obfuscation/cover approaches, see Release~\&~Destination Paper~B.\cite{series:mceq}

\subsection{Obfuscation, cover distributions, and compatibility-first privacy}
Some systems approximate privacy by obfuscating query patterns (decoys, widened prefix fetching, altered termination behavior) while preserving compatibility with existing deployments.
Daniel et~al. study practical query obfuscation for Kademlia-style lookups.\cite{danielQueryObfuscationSAC2025}
Iris provides privacy-preserving search for authenticated Chord while staying compatible with vanilla Chord nodes.\cite{irisNDSS2025}

In this archive, these techniques are treated as instances of a \emph{projection-level contract surface}: identify what is actually observed, define a transcript projection, and export a budgeted equalization claim (Anonymity~B; Certified~A).\cite{series:profiling,series:certmenus}

\subsection{Deployed mitigations and evolving specs (IPFS / libp2p)}
In live systems, lookup privacy is often pursued as incremental deployment hardening: delegated routing endpoints, shared caches, AutoConf-based endpoint discovery, and privacy-relay upgrades (OHTTP).
These are not footnotes: they determine \emph{who} can see queries, and they can silently drift the observable surface across time.
To keep this note non-redundant, the deployed-surface taxonomy and ``what-to-pin'' checklist live in Synthesis~30.\cite{series:deployedsurfaces}
For measurement context (centralization pressure and request visibility), see Trautwein et~al. and Balduf et~al.\cite{trautweinIPFS2022,balduf_cloud_strikes_back}

\section{Attacks, measurement, and operational threat surfaces (selected)}
Even if the lookup layer is ``anonymous,'' deployment can re-introduce leakage through retries, downgrade fallbacks, and timing patterns.
Classic failure-mode analyses of DHT-based anonymity schemes motivate treating retries and state as first-class adversarial handles.\cite{tran2009failure,odonnell2004chord}

Operationally, P2P overlay nodes are also recon targets: large-scale scanning and exploitation attempts raise the ambient observation/compromise rate and can interact with ``privacy via delegation'' assumptions.\cite{seidenbergerMaitiRecon2024}
IPFS deployments face active attacks (e.g., Sybil/eclipse strategies) and censorship pressure that interact with routing privacy.\cite{cholezSybilIPFSARES2024,nettoSybilIPFSDHT2025,sridharIPFSCensorshipNDSS2024,matterTranIPFSCensorship2025}

\section{Where this series fits}
This archive is not an attempt to out-survey the literature.
Its contribution is an \emph{interface discipline}:
\begin{itemize}[leftmargin=1.2em]
\item Express privacy in a small number of composable budgets (posterior-mass/PML / max-divergence / TV tiers) that propagate to endpoint sizing.\cite{series:oddsinflation,series:endpointbridge}
\item Identify the few observable features that dominate profiling (e.g., stop-time buckets, committee-contact sets) and turn them into equalization contracts.\cite{series:profiling}
\item Require that retries, fallbacks, and downgrade surfaces are treated as first-class leakage events (schedule-only wrappers).\cite{series:operationalA}
\item Treat role-separation assumptions for primary paths as explicit guard objects committed by digest (separation manifests).\cite{series:primarysepmanifest}
\item Make claims checkable in source-only releases by committing artifacts via ABOM/OINL and notarized receipts.\cite{series:abomoinl,series:releaseproperty}
\end{itemize}
