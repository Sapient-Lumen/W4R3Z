\begin{abstract}
A challenge coverage certificate can say which semantic pieces count as covered for which audiences.
A witness core can say which terminal-witness keys and surface-hook keys are shared across every certified audience for one such coverage claim.
One compact question remains anyway: which exact \emph{route-and-branch} dependencies certify that claim as a whole once the audience-invariant core has already been fixed?
This note isolates that aggregate route-and-branch layer.
It defines a compact \emph{challenge coverage witness pack} that binds one certified coverage entry to the exact audience routes and piece-keyed branches needed collectively across all audiences certified for that claim, while importing shared terminal and surface keys from the companion witness core.
\end{abstract}

\section{Why witness packs deserve their own note}
A coverage certificate should answer a semantic question: does this sentence family count as covering this piece for these audiences, or only preserve it as a support-only hook?
A witness core should answer the audience-invariant dependency question: which terminal-witness keys and surface-hook keys are shared by every certified audience for that coverage entry?
Neither object should also be forced to carry the exact \emph{aggregate} route and branch set for the coverage claim as a whole.
Conversely, if those route/branch dependencies are left implicit, later maintainers are forced to reconstruct them from several audience-specific slices.
So the archive benefits from one small object whose only job is to say which existing route and branch keys discharge one coverage claim as a whole, with common terminal/surface keys imported from the witness core and per-audience minimization left to companion witness slices.

\begin{definition}[Challenge coverage witness pack]
Fix one concrete base$\to$successor comparison and one already-declared coverage entry $e$ from a companion challenge coverage certificate.
Let $\Gamma(e)$ be the companion witness core for $e$.
A \emph{challenge coverage witness pack} for $e$ is a tuple
\[
\Pi(e)=(e,f,p,m,\gamma,R,B)
\]
containing the coverage-entry key $e$, the sentence family $f$, the semantic piece key $p$, the coverage mode $m\in\{\textsf{surface},\textsf{support-only}\}$, the witness-core key $\gamma$, a finite nonempty set $R$ of audience-route keys, and a finite nonempty set $B$ of branch keys.
\end{definition}

\begin{definition}[Route-union rule]
A witness pack satisfies the \emph{route-union rule} if every route key in $R$ belongs to an audience certified by the companion coverage entry, and the set of audiences induced by $R$ is exactly the audience set certified for that entry.
\end{definition}

\begin{definition}[Branch-union rule]
A witness pack satisfies the \emph{branch-union rule} if every branch key in $B$ witnesses one of the route-plus-piece pairs induced by $R$ and the semantic piece $p$, and every such certified route contributes at least one matching branch to $B$.
\end{definition}

\begin{definition}[Pack-vs-slice rule]
Let $\Sigma_a(e)$ range over the companion audience-specific witness slices for coverage entry $e$.
A witness pack satisfies the \emph{pack-vs-slice rule} if the union of the route keys and branch keys carried by all certified audience slices recovers exactly the route set $R$ and branch set $B$ up to order, while every such slice points back to the same witness-core key $\gamma$.
\end{definition}

\begin{lemma}[Witness packs prevent hidden aggregate route drift]
Assume every coverage entry is paired with a witness pack satisfying the route-union rule, the branch-union rule, and the pack-vs-slice rule.
Then later notes may reuse the coverage certificate and witness core without silently changing the aggregate route-and-branch bundle that makes one coverage claim auditable as a whole.
\end{lemma}

\begin{proof}
The route-union rule prevents one audience from disappearing from the aggregate certification bundle once coverage has already been declared for that audience.
The branch-union rule prevents the coverage claim from drifting away from the exact route-plus-piece walks already declared elsewhere.
The pack-vs-slice rule keeps the aggregate pack synchronized with its audience-specific decompositions while leaving terminal/surface proving keys in the shared witness core.
So the witness pack records the aggregate route/branch bundle for one coverage claim without forcing the semantic certificate or the witness core to carry that content inline.
\end{proof}

\section{Worked example pointer}
The maintained worked bundle now ships \path{example_successor_challenge_coverage_witness_packs.json}.\cite{series:workedexample}
It records five witness packs for the canned Case-B successor: two for the public-status sentence and three for the compact numeric diff sentence.
Each pack names the common witness core for that coverage entry together with the exact audience routes and route-plus-piece branches needed collectively across all certified audiences.
The support-only recomputation pack uses the same factorization: its surface/terminal proving keys live in the shared core while its aggregate route/branch burden lives here.
That keeps Synthesis~39 about \emph{what} is covered, Synthesis~44 about the \emph{common audience-invariant proving core}, Synthesis~43 about \emph{which audience-minimal route/branch delta one audience needs}, and this note about \emph{which aggregate route/branch bundle certifies the coverage claim as a whole}.\cite{series:challengecoverage,series:challengecoveragewitnesscores,series:challengecoveragewitnessslices}

\paragraph{Why this helps the archive.}
The series can now keep the semantic certificate small, the common proving core reusable, and the aggregate route/branch burden explicit without letting any one ledger silently do two jobs.
That is a useful tightening for terse referee-grade notes.
