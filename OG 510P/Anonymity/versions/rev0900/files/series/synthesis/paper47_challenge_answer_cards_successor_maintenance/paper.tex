\begin{abstract}
Challenge answer sheets already solve the whole-question semantic handoff.
Sentence locks already solve sentence reuse, recheck versus regeneration, and visible inline provenance.
But a later note that wants the actual emitted audience/question answer still has to pair those two objects by hand.
This note gives that last pairing one home.
It defines a compact \emph{challenge answer card}: one released audience/question answer object binding one piece-complete answer sheet to one shipped sentence lock, its mirrored current sentence-reuse posture, and one default visible-provenance mode, without turning either imported layer into a new release stage.
\end{abstract}

\section{Why answer cards deserve their own note}
A release note or referee memo often wants to cite the answer that is actually shipped to one audience.
By that point the semantic content is already organized by the answer sheet, and the reuse policy for the emitted sentence is already organized by the sentence lock.
Yet without one final wrapper, later papers must keep saying some variant of ``take this sheet, pair it with that lock, inherit the default inline profile, and remember which pieces are only support-only.''
That is a real maintained object, not decorative prose.
So the archive benefits from one thin layer whose only job is to say: for this audience and this downstream question, here is the released answer object exactly as later papers should cite it.

\begin{definition}[Challenge answer card]
Fix one concrete base$\to$successor comparison, one audience key $a$, and one downstream question key $q$.
A \emph{challenge answer card} is a tuple
\[
C(a,q)=(a,q,f,G,L,p,\Phi,\tau,\mathbf{p}_{\mathrm{surf}},\mathbf{p}_{\mathrm{sup}})
\]
containing the audience key $a$, question key $q$, sentence family $f$, one imported challenge-answer-sheet key $G$, one imported sentence-lock key $L$, one selected inline-provenance profile key $p$, the visible-provenance field list $\Phi$ induced by that selected profile, one emitted surface text $\tau$ imported from the sentence lock, an ordered list $\mathbf{p}_{\mathrm{surf}}$ of surfaced piece keys, and an ordered list $\mathbf{p}_{\mathrm{sup}}$ of support-only piece keys.
\end{definition}

\begin{definition}[Sheet-lock factorization rule]
A challenge answer card satisfies the \emph{sheet-lock factorization rule} if it references exactly one imported answer sheet and exactly one imported sentence lock for the same audience/question sentence family, rather than restating capsule order, branch keys, witness keys, or recheck policy inline.
The sheet continues to own the whole-question semantic handoff; the lock continues to own sentence reuse policy.
\end{definition}

\begin{definition}[Default-profile import rule]
A challenge answer card satisfies the \emph{default-profile import rule} if its selected inline-provenance profile is exactly the default profile declared by the imported sentence lock and its visible-provenance field list agrees exactly with that profile.
So the card inherits a checked visibility policy rather than improvising one.
\end{definition}

\begin{definition}[Surfaced/support-only piece-partition rule]
A challenge answer card satisfies the \emph{surfaced/support-only piece-partition rule} if its surfaced and support-only piece lists are induced by the imported answer sheet and the coverage modes of that sheet's ordered answer capsules.
In particular, the card may not silently promote a support-only piece to surfaced status or hide a surfaced piece inside support-only prose.
\end{definition}

\begin{lemma}[Answer cards preserve semantic content and reuse policy]
Assume every answer card satisfies the sheet-lock factorization rule, the default-profile import rule, and the surfaced/support-only piece-partition rule.
Then a later note may cite one answer card as the released answer to one audience/question pair without changing either the semantic content already carried by the imported answer sheet or the reuse policy already carried by the imported sentence lock.
\end{lemma}

\begin{proof}
The sheet-lock factorization rule keeps ownership separated: the imported sheet continues to say which semantic pieces answer the question, while the imported lock continues to say whether and how the sentence may be reused.
The default-profile import rule prevents a later paper from silently changing visible-provenance policy while claiming to cite the same released answer.
The surfaced/support-only piece-partition rule preserves the visible/off-surface boundary already fixed by the imported sheet and its capsules.
So the answer card changes only packaging: it provides one released answer object for one audience/question pair, but it does not alter the underlying semantic or reuse facts.\qedhere
\end{proof}

\section{Worked example pointer}
The maintained worked bundle now ships \path{example_successor_challenge_answer_cards.json}.\cite{series:workedexample}
It records four answer cards for the canned Case-B successor: one each for the release-note and referee public-status question, and one each for the release-note and auditor compact-diff question.
Concrete keys already in the ledger include \path{release_note_public_status_sentence_answer_card} and \path{auditor_compact_diff_summary_answer_card}.
Each card binds one imported answer sheet, one imported sentence lock, the inherited default inline-provenance profile, the visible-provenance fields induced by that profile, the shipped sentence text, the cite path for that sentence, and the surfaced/support-only piece partition induced by the ordered capsules in the imported sheet.
That gives later notes one object to cite when they want the emitted audience/question answer itself rather than only the semantic handoff or only the reuse policy.

\paragraph{Why this helps the series.}
The stack is now cleaner at three distinct publication scales.
A narrow note can cite one answer capsule when only one semantic piece is disputed.
A fuller handoff can cite one answer sheet when the whole question must travel.
And a release-facing or referee-facing note can cite one answer card when it wants the final shipped answer object with inherited sentence policy already attached.
