\begin{abstract}
Challenge routes can already say where one audience should start.
Challenge stop profiles can already say which semantic pieces one downstream question carries and which narrow fields may discharge them.
Challenge branches, coverage certificates, witness cores, and witness slices can already say how one piece is certified.
But later notes still face a repetitive assembly problem: to answer one audience's one question about one emitted piece, they must keep re-gathering the same route key, approved stop fields, exact branch, coverage entry, shared witness core, audience-specific witness slice, and realized surface hooks.
This note gives that final assembly one home.
It defines a compact \emph{challenge answer capsule}: one auditable bundle for one audience, one question family, and one certified semantic piece.
\end{abstract}

\section{Why answer capsules deserve their own note}
A later paper often does not want the whole proving lattice.
It wants one minimal answer bundle for one reader and one question: where should this reader begin, which semantic piece is actually at issue, which exact branch reaches an approved narrow stop, which coverage entry says the piece is carried, which proving keys are shared across audiences, which proving keys are specific to this audience, and where on the emitted surface that covered piece lives.
If those imports are always reassembled ad hoc, the series either grows repetitive or lets a friendly wrapper sentence obscure which object owns which part of the answer.
So the archive benefits from one tiny object whose only job is to say: for this audience, this question family, and this semantic piece, here is the exact answer bundle and nothing else.

\begin{definition}[Challenge answer capsule]
Fix one concrete base$\to$successor comparison, one audience key $a$, one downstream question key $q$, and one semantic piece key $p$ that is already certified for that audience/question context.
A \emph{challenge answer capsule} is a tuple
\[
A(a,q,p)=(a,q,p,f,m,r,s,b,e,K,\Sigma,W,H)
\]
containing the audience key $a$, question key $q$, piece key $p$, sentence family $f$, coverage mode $m\in\{\textsf{surface},\textsf{support-only}\}$, one route key $r$, one approved stop profile $s$, one route-plus-piece branch key $b$, one coverage-entry key $e$, one shared witness-core key $K$, one audience-specific witness-slice key $\Sigma$, a finite nonempty set $W$ of exact terminal-witness keys, and a finite set $H$ of exact surface-hook keys.
\end{definition}

\begin{definition}[Question-piece minimality rule]
A challenge answer capsule satisfies the \emph{question-piece minimality rule} if it answers exactly one audience/question/piece bundle.
In particular, it may not merge several question families, several semantic pieces, or several audience routes into one capsule merely because they share some proving keys.
Common proving keys belong in imported witness cores, not in a widened capsule.
\end{definition}

\begin{definition}[Surface/support-only capsule rule]
A challenge answer capsule satisfies the \emph{surface/support-only capsule rule} if $m=\textsf{surface}$ implies $H\neq\varnothing$, while $m=\textsf{support-only}$ implies $H=\varnothing$.
In either case the listed terminal-witness set $W$ remains mandatory and must agree with the imported stop profile and branch endpoint for that semantic piece.
\end{definition}

\begin{definition}[Assembly rule]
A family of challenge answer capsules satisfies the \emph{assembly rule} if every capsule references exactly one imported route, one imported stop profile, one imported branch, one imported coverage entry, one imported witness core, and one imported witness slice, and if its terminal-witness and surface-hook sets agree with those imported companions rather than restating altered copies.
\end{definition}

\begin{lemma}[Answer capsules keep downstream answers compact without changing certification content]
Assume every answer capsule satisfies the question-piece minimality rule, the surface/support-only capsule rule, and the assembly rule.
Then a later note may hand one capsule to one audience as a minimal auditable answer bundle without changing the certification content already carried by the imported routes, stop profiles, branches, coverage entries, witness cores, and witness slices.
\end{lemma}

\begin{proof}
The question-piece minimality rule prevents one capsule from silently becoming a mixed audience or mixed semantic object.
The surface/support-only capsule rule preserves the boundary between visible realization and off-surface support.
The assembly rule then says that every field in the capsule is imported from already-owned companion objects rather than rewritten in a new wrapper.
So the capsule changes only packaging: it makes one downstream answer bundle compact, but it does not move ownership or alter the underlying certification facts.\qedhere
\end{proof}

\paragraph{Three auditable capsule shapes.}
The worked archive already exhibits three distinct capsule shapes.
A release-note capsule for the public-status continuity piece binds one release-note route, one continuity branch, one continuity terminal owner, and one realized surface hook.
A referee capsule for the changed-family basis binds the same shared witness core together with the referee-specific witness slice for the changed-family piece.
An auditor capsule for the recomputation basis is support-only: it binds one auditor route, one recomputation branch, one off-surface terminal owner, and no surface hooks at all.
These three shapes are enough to show that the capsule layer is not decorative; it simply packages whichever imported proving objects are already required for that audience/question/piece triple.
