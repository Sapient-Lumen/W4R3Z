## Evidence found

The base verifier surface was no longer thin after rev0802, but its public-object list was still a list of filenames. That left one avoidable trust hop: a reader had to look outside the verifier row to know that each named public object was the current in-archive object. At the same time, the optional profiling variants already had current-cut receipt, owner-map, replay-plan, support-bundle, and series-spine rows, but no verifier-facing row set that kept them separate from the base `plans_checked` list.

## Change made

The maintained Synthesis~17 materializer now emits `public_object_digest_entries` into each base `plans_checked` row. The digest entries bind every row-local `public_objects` path to the current in-archive SHA-256 digest.

The verifier report now also emits `optional_variant_plans_checked` for:

- `profiling_equalization_prefixfetch` / `eval-profiling-prefixfetch-v1`,
- `profiling_equalization_prefixfetch_statecond` / `eval-profiling-prefixfetch-statecond-v1`,
- `profiling_equalization_contact_coarsened` / `eval-profiling-contact-coarsened-v1`.

Each optional row mirrors `receipt_variant_file`, `evidence_id`, `plan_spec_id`, `support_bundle_id`, `support_consumed_by`, `support_required_artifacts`, `support_pointers`, `public_objects`, and `public_object_digest_entries`; the contact-coarsened row also mirrors `coarsening_map_id`.

## Validator hardening
