## Evidence found

The archive-level manifest and manifest-verification report could be internally correct while the Synthesis~17 artifact-local `support_manifest.json` contained stale per-file SHA-256 claims. The maintained worked-example validator was strong on resolver semantics, but it did not previously verify every support-manifest file row against the current shipped bytes.

The quick-check path was also not fully side-effect-free: direct `python3` invocations documented in the compact startup surfaces could create `__pycache__` files, which then failed transient-surface hygiene and could push the archive over its hard file budget.

## Change made

Added `publishing/check_support_manifest_integrity.py`, integrated it into `make verify-surfaces`, `publishing/rebuild_archive_surfaces.py`, `reports/support_manifest_integrity.json`, and `reports/archive_surface_coherence.json`. The checker scans nested `support_manifest.json` files, resolves every file row from explicit base semantics, checks the repo-relative binding, verifies existence, and compares SHA-256 digests.

Synthesis~17 support-manifest rows now carry `base` and `repo_relative_path` fields. The local validator now includes `support manifest full file digest integrity`, raising the maintained worked-example validation count to 95 checks.

## Release-boundary hardening

`publishing/release_preflight.py` now records the source hash, rejects already-published sources, verifies queue presence unless an explicit exception is passed, performs static citation/reference closure, reports placeholder markers, and can run a clean LaTeX build in a temporary copy.

`PUBLISHING.md` and `publishing/RELEASE_FLOW.md` now state that papers making artifact-governance claims need a minimal evidence pack rather than source-only publication.

## Research-object metadata and provenance

Added root-level citation, CodeMeta-style, RO-Crate-style, notice/license, and in-toto/SLSA-shaped provenance surfaces. These metadata surfaces do not publish any new paper and do not grant a new public reuse license; they describe the archive boundary and the rev0805 hardening action.

## Archive budget

The flat exact 700-file cap is replaced by a category-aware cap. The zero-transient rule remains strict, while reports, schemas, and root research-object metadata are now tracked as explicit categories.

## Publication action

None. This is a release-hardening and integrity-control revision. Queue posture remains unchanged.
