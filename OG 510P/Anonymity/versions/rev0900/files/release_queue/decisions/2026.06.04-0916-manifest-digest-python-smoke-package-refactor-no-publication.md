## Subject

Distribution-byte integrity and executable Python automation smoke.

## Decision

No publication is authorized. No queue item is moved.

## Reason

rev0829 made release-lane TeX evidence materially stronger, but the next high-risk seam was the handoff from the working tree to the distributable zip and the trustworthiness of the Python automation used to verify it. A filename-parity package check is not enough if current bytes can drift from `MANIFEST.sha256`, and stored reports should not be trusted if shipped Python no longer compiles or exposes guarded entrypoints.

## Changes accepted

- Hardened `publishing/build_archive_zip.py` so dry-run and real zip emission fail unless package inputs match both `MANIFEST.json` and `MANIFEST.sha256`.
- Added a stale-hash negative control to `publishing/check_archive_packaging_recipe.py`.
- Added `publishing/check_python_entrypoint_smoke.py`, `schemas/python_entrypoint_smoke.schema.json`, and `reports/python_entrypoint_smoke.json`.
- Wired Python smoke into rebuild, verification, schema validation, coherence, and invariant checks.
- Retired `reports/deep_read_assessment.json` to keep the report count flat.
- Added `-no-shell-escape` to queue compile-smoke `pdflatex` runs.

## Follow-up

The next useful risk-reduction pass should make long evidence-producing gates resumable and cache-aware rather than adding another registry surface.
