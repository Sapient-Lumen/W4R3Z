\begin{abstract}
Several papers in this archive parameterize a ``Boss Fight'' budget by an \emph{observation model} $p_{\mathrm{obs}}$.
In practice, deployments have \emph{multiple} partially observed witness surfaces: e.g., (i) which contacts were queried, (ii) timing/packetization metadata, and (iii) congestion witnesses.
If receipts publish only a single scalar, this structure is lost and cross-release comparisons become ambiguous.
This note centralizes a minimal, receipt-ready interface: publish an \emph{observation vector} of tiers, each with its own observation probability and per-lookup MaxL (or odds-inflation) bound, together with a conservative rule for combining tiers.
\end{abstract}

\paragraph{Scope.}
This is a short interface note.
It does not propose new mechanisms; it standardizes how \emph{multiple witness tiers} are published and combined in receipts.

\section{Tiered observation vectors (definition)}
A deployment rarely exposes ``the transcript'' as a monolith.
Instead, different adversaries (or the same adversary at different vantages) observe different projections.
We model this using tiers.

\begin{definition}[Tiered observation vector]
Fix a secret $C$ (e.g., queried content label) and a mechanism that induces witness projections $Y^{(1)},\dots,Y^{(m)}$ as in the trace-interfaces vocabulary.\cite{series:traceifaces}
For each tier $i$, declare:
\begin{itemize}[leftmargin=1.2em]
\item a \emph{tier name} and witness definition (what projection is meant),
\item a \emph{per-lookup} bound $b_i$ on $\MaxL(C\to Y^{(i)})$ (or an equivalent odds-inflation label), and
\item an \emph{observation probability} $p_i\in[0,1]$ indicating how often that tier is actually observed (or an auditable upper bound).
\end{itemize}
Let $Z^{(i)}$ be the thinned observation of tier $i$ with parameter $p_i$ (Synthesis~11).\cite{series:obsatten}
The \emph{tiered observation vector} is $\mathbf{Z} := (Z^{(1)},\dots,Z^{(m)})$.
\end{definition}

\paragraph{Receipt hook.}
In the line-item schema, this vector lives inside \texttt{obs\_model}: instead of a single $p_{\mathrm{obs}}$, publish a list of tiers with $(p_i, b_i)$ and the combination rule below.\cite{series:receiptitems}

\section{A conservative MaxL composition rule}
To keep receipts referee-grade without overfitting to a specific adversary, we adopt a conservative composition rule under a clear, checkable condition.

\begin{definition}[Conditional-independence condition]
We say tiers are \emph{conditionally independent given $C$} if, for all $c$,
\[\Pr[\mathbf{Z}=\mathbf{z}\mid C=c] = \prod_{i=1}^m \Pr[Z^{(i)}=z_i\mid C=c].\]
This condition is natural when tiers correspond to distinct vantages with independent compromise/visibility events, or when the published tier definitions already condition on shared public side information.
\end{definition}

\begin{lemma}[MaxL subadditivity under conditional independence]\label{lem:maxl-add}
If $Z^{(1)},\dots,Z^{(m)}$ are conditionally independent given $C$, then
\[\MaxL(C\to \mathbf{Z}) \;\le\; \sum_{i=1}^m \MaxL(C\to Z^{(i)}).\]
\end{lemma}
\begin{proof}
By definition, $2^{\MaxL(C\to \mathbf{Z})}=\sum_{\mathbf{z}}\max_c \Pr[\mathbf{Z}=\mathbf{z}\mid C=c]$.
Under conditional independence, this equals $\sum_{\mathbf{z}}\max_c \prod_i \Pr[Z^{(i)}=z_i\mid C=c]$.
For each $\mathbf{z}$,
\[\max_c \prod_i a_i(c) \;\le\; \prod_i \max_c a_i(c),\]
so
\[\sum_{\mathbf{z}}\max_c \prod_i \Pr[Z^{(i)}=z_i\mid c] \;\le\; \sum_{\mathbf{z}} \prod_i \max_c \Pr[Z^{(i)}=z_i\mid c]
= \prod_i \sum_{z_i} \max_c \Pr[Z^{(i)}=z_i\mid c].\]
Taking $\log_2$ yields the claim.
\end{proof}

\begin{corollary}[Receipt-ready tier aggregation]\label{cor:receipt-agg}
If tier $i$ has an unthinned bound $\MaxL(C\to Y^{(i)})\le b_i$ and thinning parameter $p_i$, then Synthesis~11 gives
\[\MaxL(C\to Z^{(i)}) \le \log_2\big((1-p_i)+p_i\,2^{b_i}\big).\]
If tiers are conditionally independent given $C$, then
\[\MaxL(C\to \mathbf{Z}) \;\le\; \sum_{i=1}^m \log_2\big((1-p_i)+p_i\,2^{b_i}\big).\]
\end{corollary}

\begin{remark}[If independence is not defensible]
If a deployment cannot justify the conditional-independence condition, the receipt should publish a joint bound for the combined witness surface (treating $\mathbf{Z}$ as a single tier) rather than using Corollary~\ref{cor:receipt-agg}.
The schema still applies; only the accountant changes.\cite{series:receiptitems}
\end{remark}

\section{Canonical tier names (recommended)}
To keep cross-paper citations stable, we recommend three canonical tier classes (a deployment may add others).
\begin{itemize}[leftmargin=1.2em]
\item \textbf{CSET (contact-set tier):} which overlay contacts were queried / delegated to / responded.
\item \textbf{TIME (timing tier):} timestamps, packetization/length classes, and timeout/abort surfaces.
\item \textbf{CONG (congestion tier):} RTT/queueing/loss witnesses governed by the congestion series.
\end{itemize}
Each tier must map to a trace projection owned by the trace-interfaces note.\cite{series:traceifaces}

\section{How this is used elsewhere in the archive (one paragraph)}
Boss Fight dial sheets usually publish a single $p_{\mathrm{obs}}$ for the CSET tier.
Tiered deployments (primary cryptographic path + budgeted DHT fallback) should publish distinct tier vectors per path and combine them using Corollary~\ref{cor:receipt-agg}, while treating adaptive fallback selection as an additional witness stream owned by the fallback-tax note.\cite{series:tieredpattern,series:fallbacktax}
