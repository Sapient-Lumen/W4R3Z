\title{Anytime Statistical Spending for Menu Audits:\\
\large Change-Control-Safe Confidence Budgets for Expanding Log Certificates}

\begin{abstract}
Synthesis~25 gives a conservative finite-sample recipe that turns log frequencies for a \emph{fixed} discrete projection into a simultaneous (menu-level) total-variation certificate.
Real deployments are not one-shot:
menus expand, audits repeat, and drift monitoring triggers incremental re-certification.

This note centralizes a minimal, referee-grade \emph{anytime spending} rule: how to allocate a single published statistical failure budget $\delta_{\mathrm{stat}}$ across an unbounded sequence of audit events (and across expanding menus) without invalidating earlier certificates.
The goal is non-redundancy: mechanism and contract papers can cite this note rather than re-deriving optional-stopping or ``menu growth'' bookkeeping.
\end{abstract}

\section{Problem: certificates that must survive time}
Many papers in this archive publish claims of the form
\[\TV(P_{k,\mu},P_{k',\mu})\le \tau_{\mu}\]\
for discrete projections $X_\mu$ audited from logs.
Synthesis~25 supplies the per-audit certificate surface.\cite{series:stataudit}

Operationally, audits occur at times $t=1,2,\dots$ (weekly, per-release, or when monitors fire).
At time $t$, the deployment may:
(i) add new keys/policies to an existing menu,
(ii) add a new projection (new ENF-ID),
(iii) repeat an audit with fresh logs, or
(iv) publish drift evidence that triggers a new receipt under the plan/state equivalence rules.\cite{series:planstateequiv,series:accountingrulebook}

A naive reuse of $\delta$ per audit silently violates the meaning of the published statistical confidence.
This note fixes the bookkeeping with a single device: \emph{spend} $\delta_{\mathrm{stat}}$ over time.

\section{Spending schedules}
\begin{definition}[Audit event]
An \emph{audit event} $A_t$ is the act of publishing (or internally producing) a finite set of statistical certificates at time $t$.
Each event consumes a chosen failure probability budget $\delta_t\in(0,1)$.
\end{definition}

\begin{definition}[Spending schedule]
A \emph{spending schedule} is any sequence $(\delta_t)_{t\ge 1}$ such that
\[\sum_{t=1}^{\infty} \delta_t \le \delta_{\mathrm{stat}}.\]
We treat the schedule name (e.g., \texttt{geom-1/2} or \texttt{zeta2}) as a published parameter.
\end{definition}

Two simple schedules (both easy to publish and implement):
\begin{itemize}[leftmargin=*]
\item \textbf{Geometric:} $\delta_t = \delta_{\mathrm{stat}}\,2^{-t}$.
\item \textbf{Zeta(2):} $\delta_t = \delta_{\mathrm{stat}}\,\frac{6}{\pi^2}\,\frac{1}{t^2}$.
\end{itemize}
Both satisfy $\sum_t \delta_t \le \delta_{\mathrm{stat}}$.

\begin{lemma}[Anytime validity by a union bound]
\label{lem:anytime}
Suppose audit event $A_t$ is designed so that its published certificates hold with probability at least $1-\delta_t$.
If $(\delta_t)$ is a spending schedule, then with probability at least $1-\delta_{\mathrm{stat}}$, \emph{all} certificates published across \emph{all} times hold simultaneously.
\end{lemma}

\begin{proof}
Apply a union bound over events:
$\Pr[\exists t: A_t \text{ fails}]\le \sum_t \delta_t\le \delta_{\mathrm{stat}}$.
\end{proof}

\begin{remark}[Why this is enough for this archive]
This note is intentionally conservative.
More powerful anytime-valid tools (e-values, confidence sequences) exist, but Lemma~\ref{lem:anytime} is short, transparent, and compatible with the receipt/line-item publication model.
When a paper needs stopping-safe drift tests for \emph{state} witnesses, the state-series owns that story; this note only standardizes how to publish \emph{log-audit} confidence over time.\cite{series:state1A}
\end{remark}

\section{Expanding menus inside an audit event}
Within an event $t$, the deployment may certify a \emph{finite} set of menu items and class pairs.
Write $\mathcal I_t$ for the set of audited pairs $(k,\mu)$ at time $t$.
A simple in-event allocation is Bonferroni:
\[\delta_{t,(k,\mu)} := \delta_t / |\mathcal I_t|.\]
Then Corollary~(menu-level radii) from Synthesis~25 applies inside $t$ with $\delta_t$ as the event-level confidence.\cite{series:stataudit}

\begin{corollary}[Anytime-valid menu growth]
\label{cor:growth}
Assume each audit event $t$ certifies its (finite) scope $\mathcal I_t$ with failure probability at most $\delta_t$.
Under any spending schedule, with probability at least $1-\delta_{\mathrm{stat}}$, \emph{every} menu item ever certified remains valid, even as the menu grows over time.
\end{corollary}

\paragraph{Practical interpretation.}
A deployment may publish a new key-class, add a new projection, or expand a certified menu without ``resetting'' statistical meaning, as long as it spends additional $\delta_t$ and publishes that spend.

\section{Receipt-facing publication fields (minimal)}
This archive's receipts already separate \emph{claim surfaces} (ENF-ID, TW-ID, optional state-decl id) from \emph{evidence objects}.\cite{series:receiptitems,series:contractobjects}
This note proposes a minimal set of fields for evidence objects that rely on log-audit spending:
\begin{itemize}[leftmargin=*]
\item \textbf{$\delta_{\mathrm{stat}}$} (menu-level statistical confidence budget),
\item \textbf{spending schedule id} (e.g., \texttt{geom-1/2} or \texttt{zeta2}) and its parameter(s),
\item \textbf{event index $t$} (or an event nonce) and the spent value $\delta_t$,
\item \textbf{in-event allocation rule} (e.g., Bonferroni) and per-item sample sizes.
\end{itemize}
The rest of the per-projection evidence surface (projection id, menu scope, empirical distances, derived bounds) is owned by Synthesis~25, and the interlock to receipts and bundles is exercised concretely in Synthesis~17.\cite{series:stataudit,series:workedexample}

\section{Change control and identity}
Spending does \emph{not} change claim identity.
If ENF-ID / TW-ID / state-decl id are unchanged, an audit event can be published as a new evidence object referenced by the same claim.
If any identity field changes, Synthesis~18's plan/state taxonomy should treat the outcome as a new claim object (or as an explicit coarsening) and require fresh evidence.\cite{series:planstateequiv}

\section{Research warranted (short list)}
\begin{itemize}[leftmargin=*]
\item \textbf{E-value unification:} connect the state-series stopping-safe drift tests to the log-audit spending surface so deployments can publish a single ``monitoring confidence'' parameter without mixing regimes.
\item \textbf{Adaptive projection discovery:} when the projection $X$ is discovered from logs (feature selection), the effective multiplicity can dwarf a fixed menu size; bridging to Certified~A/C selection wrappers is a natural next note.\cite{series:menus}
\item \textbf{Power-aware spending:} schedules that allocate more $\delta$ to high-impact events (e.g., major releases) while retaining a simple publication rule.
\end{itemize}
