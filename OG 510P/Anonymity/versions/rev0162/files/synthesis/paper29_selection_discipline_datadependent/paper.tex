\title{Selection Discipline for Data-Dependent Interface Projections:\\
\large Witness-Indexed Maps and Pilot/Frozen Phases for Receipt-Grade Audits}
\author{}
\date{February 28, 2026 (archive v147)}

\begin{document}

\begin{abstract}
Several ``interface projections'' in this archive require choosing a discrete map from data: timing bucket boundaries (Synthesis~27),
coarsening/partition maps for large alphabets (Synthesis~28), or ``top-$m$ plus other'' hash bins for structured witnesses.
If the chosen map is published, the selection itself can become an additional, reviewable exposure surface.
This note centralizes two conservative patterns that keep papers non-redundant and receipts referee-grade:
(i) \emph{witness-indexed families} where the chosen map is a deterministic function of a \emph{published witness} $W$ already in scope,
and (ii) \emph{pilot/frozen phases} where map selection and audit evidence are separated by change control and spending (Synthesis~26).
\end{abstract}

\section{Setting and scope}
A deployment publishes a receipt claiming that an observed projection $Y$ is nearly secret-independent (Anonymity~B),
and supports that claim with log-audit evidence (Synthesis~25) under a change-control discipline (Synthesis~26).\cite{series:profiling,series:stataudit,series:anytimespend}
When the projection is derived as $Y=f_\theta(T)$ with a data-chosen parameter $\theta$ (bucket boundaries, partition rules),
this note asks one narrow question:
\emph{how can $\theta$ be chosen and published without silently expanding the exposure surface?}

We keep the answer intentionally conservative.
If a deployment wants to use sophisticated selection (e.g., adaptive data-driven partitions), it should be treated as a first-class exposure mechanism and analyzed separately.

\section{Pattern A: witness-indexed maps (selection by declared public state)}
The cleanest receipt-grade pattern is to make selection a deterministic function of an explicit, published witness $W$.
Examples: bucket boundaries by public ``epoch class,'' coarsening maps by declared overlay configuration, or prefix rules by public staleness class.

\begin{definition}[Witness-indexed map family]
Let $W$ be a published witness taking values in $\mathcal W$.
A \emph{witness-indexed family} is a collection of deterministic maps $\{f_w\}_{w\in\mathcal W}$
(e.g., bucket maps $b_w$ or coarsenings $c_w$) and a rule $Y=f_W(X)$.
Receipts publish (i) the witness value $W$ (or its digest-bound declaration id) and (ii) the chosen map id (digest) $\texttt{map\_id}(W)$.
\end{definition}

\paragraph{Why this is conservative.}
If $W$ is public and (by declaration) independent of the secret,
then publishing $W$ is not avoidable---it is already part of the claim surface.
Selection adds no extra secret dependence beyond what is accounted for by conditioning on $W$.
Formally, Lemma~\ref{lem:tv_state_witness} in Synthesis~18 bounds joint leakage of $(W,Y)$ by
``leakage of $W$'' plus worst-case conditional leakage of $Y$ given $W$.\cite{series:planstate}

\begin{remark}[State-conditioned variants in the worked example]
Synthesis~17 includes ``state-conditioned'' variants (e.g., prefix-fetch equalization conditioned on a bucket-staleness class)
that instantiate this pattern end-to-end: the witness is published explicitly, and the receipt claims are conditional.\cite{series:workedexample}
\end{remark}

\section{Pattern B: pilot/frozen phases (separate selection from audit)}
When $W$ is not available (or the map must be chosen from observed behavior),
a second conservative pattern is \emph{pilot/frozen} operation:
use a pilot window to choose a map, then freeze it and certify it from fresh logs.

\paragraph{Pilot window.}
Choose a map using internal logs from a declared pilot period.
To keep the receipt surface disciplined, publish the resulting map as a digest-bound object and treat it as a \emph{menu change}.

\paragraph{Frozen-audit window.}
Run the deployment with the frozen map and collect audit logs.
Issue certificates for the resulting discrete projection using Synthesis~25.
If the map changes again, treat the change as a new audit event and allocate statistical failure probability via Synthesis~26.\cite{series:anytimespend}

\paragraph{Relation to data splitting / selective inference.}
Pilot/frozen is a conservative form of \emph{data splitting}: selection is done on one dataset and inference/audit on another.
The series does not import post-selection inference machinery, but the warning is shared: publishing a choice made from data can itself leak information and can invalidate naive confidence accounting.\cite{leePostSelection2016}

\paragraph{What this does \emph{not} solve.}
Publishing a map chosen from pilot logs can leak information about that pilot window.
This archive's conservative stance is: either (i) the pilot window is outside the modeled adversary exposure (explicitly),
or (ii) the map-selection output is itself treated as an exposure surface to be bounded (new line item / new interface projection).
In either case, the change-control boundary makes the scope reviewable.

\section{Receipt-facing checklist for data-dependent parameters}
A paper that uses a data-dependent map should be able to cite this note and remain short.
Receipts (or ENF+receipt bundles) should include:
\begin{itemize}[leftmargin=*]
\item The \textbf{map object} (bucket boundaries or partition table) as a digest-bound artifact (\texttt{map\_id}).
\item The \textbf{selection discipline}: witness-indexed (publish $W$ / \texttt{state\_decl\_id}) or pilot/frozen (publish pilot scope, freeze date, and event index $t$).\cite{series:planstate}
\item The \textbf{audit evidence reference}: Synthesis~25 for the finite-sample certificate, and Synthesis~26 for repeated/expanding audits.\cite{series:stataudit,series:anytimespend}
\item An explicit statement of \textbf{ENF discipline}: finer telemetry used during pilot is not retained/exposed beyond the declared receipt surface.\cite{series:traceifaces}
\end{itemize}
