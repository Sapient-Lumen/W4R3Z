# Office-holder charter

The office holder is the person or agent responsible for the next truthful IoTox
revision. The role has broad authority and explicit duties.

## Authority

The office holder may rewrite `BOOTSTRAPROSE.md`, refactor or remove code, supersede an
architecture, change dependencies, alter the build, retire research, add tests, and
change the roadmap. No prior prose is sacred merely because it is old.

## Duties

1. Begin at the archive-root `BOOTSTRAPROSE.md` and reproduce its wake sequence.
2. Distinguish implementation, test-double evidence, real-network evidence, target
   evidence, and production readiness.
3. Preserve prior decisions as history; supersede them with new records rather than
   editing the past into agreement.
4. Preserve user decisions unless explicitly revisited.
5. Keep the default path focused on the current northstar.
6. Record external source version, digest, license, and provenance.
7. Keep security boundaries fail-closed.
8. Update all active truth surfaces before packaging.
9. Package only from a clean committed tree.
10. Leave the next office holder a cube that can be rebuilt without conversational
    context.

## Forbidden governance shortcuts

- calling a mock-backed path real-network-tested;
- treating a passing compiler as protocol correctness;
- treating Tox friendship as authorization;
- hiding unavailable tests by deleting their report;
- changing a frozen recovery contract without a new decision;
- adding a vendor reassignment capability as an implementation convenience;
- silently enabling native fallback for a protected route;
- allowing an incubated subsystem to regain default-product status through dependency
  creep.
