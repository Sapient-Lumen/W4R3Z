# ADR 0317: Add a typed CLI registry and generated completion

- Status: accepted and implemented
- Date: 2026-09-03

## Context

IoTox grew to 199 accepted command spellings across Agent lifecycle, local control, Ratox terminal,
terminal administration, witness ceremonies, informational commands, and compatibility aliases.
Recognition lived in three dispatchers while the detailed help was hand-authored. The accepted CLI
plan required shell completion to come from one complete registry rather than becoming a fourth,
independently drifting command list.

The audit found two real symptoms: `transport-peer-add` and `transport-peer-reject` were accepted
compatibility spellings but absent from the detailed usage list. Command completion generated by
scraping help would preserve that omission and would not distinguish canonical verbs from aliases.

## Decision

Add a constexpr sorted `CliCommandDescriptor` registry. Every descriptor binds one exact command
name to a closed execution class: Agent, control, terminal, terminal administration, witness,
informational, or compatibility. Each compatibility descriptor also names an existing canonical
descriptor. There are no unregistered spellings recognized by the current main, terminal, or
terminal-admin dispatchers.

Terminal and terminal-admin recognition now consult the registry, as does the control dispatcher's
fail-closed command-class gate. `iotox --help` retains its detailed forms and adds an exhaustive
generated command index with classes and alias targets. The public command:

```text
iotox completion bash|zsh|fish
```

emits deterministic shell source from the same ordered registry. Bash and Zsh receive the complete
word set plus `--help` and `--version`; Fish receives one description-bearing declaration per
command. Unknown shells and extra/missing operands fail with the CLI usage status.

The generator does not inspect runtime state and emits no identities, aliases, paths, peers,
endpoints, or secrets. It completes stable command names only. Detailed operand grammar remains
owned by the existing strict command parsers and human usage forms; teaching completion about a
closed enum or positional type is a later descriptor revision, not a reason to guess today.

## Consequences

Four owned checks bring the direct registry to 825. They freeze the 199-entry sorted population,
closed name alphabet, unique spellings, valid canonical alias targets, complete help-index coverage,
all three generators, public dispatch, and invalid-shell refusal. The emitted scripts pass Bash,
Zsh 5.9.2, and Fish 4.8.1 syntax checks. Final qualification passes all 825 direct checks, all 55
GCC CTest entries, and all 70 Clang ASan/UBSan CTest entries; the five privileged cgroup/PSI cells
remain explicit host skips in both CTest presets.

Adding or removing a command now requires an intentional registry change and makes the exact-count
test fail. This catches command-level help/completion drift, but it is not a generated man page,
dynamic remote-state completion, shell installation, argument validation in the shell, or a promise
that compatibility aliases will live forever.
